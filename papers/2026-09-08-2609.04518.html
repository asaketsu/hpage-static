多 harness RL 的收益主要来自 harness 本身，而非跨 harness 迁移能力

What Does Multi-Harness RL Learn? Credit Assignment and Portability in Coding Agents
👥 Chenqian Le, Jiayi Cheng, Qijia He, et al.   2609.04518

📋 摘要

Agent RL 越来越多地跑在完整执行 harness 上，multi-harness 配方涉及两个选择：让 policy 接触多个 harness，以及在同一 relative-advantage 组内比较它们的 reward。本文在仓库级 coding 上隔离第二个选择。从同一个 Qwen3-8B supervised warm start 出发，回放 Aider、OpenHands、Qwen Code、SWE-agent 的相同 frozen task-harness 记录，update 次数相同，在两种 GRPO 规则下训练：Within（每个 task-harness pair 一个组）和 Cross（同一任务内跨 harness 汇总），用密封的 SWE-bench Verified oracle 在 4 个源 harness 和 1 个训练外极简 harness 上评估每个 checkpoint。评估 harness 是主要变量：24,000 次密封评估中它把平均 solve rate 从 2.14% 拉到 9.27%（4.3×），而训练配方只移动 1.16×；分组规则并不重要。在 held-out harness 上，Cross 减 Within 是 +0.25 pp（95% CI [-0.48, +1.02]），8 次/任务；跨 3 个训练 seed 汇总 +0.16（[-0.41, +0.72]），单 seed 估计变号；每条规则自身的 seed 波动 0.42–0.45 pp 已超过两者差值。两条规则都把最大收益放在同一个源 harness 上。Cross 的 pooled advantage 携带了 harness：out-of-fold 分类器从 shuffled-label 基线之上 +4.48 pp 恢复出生成 harness，而 Within 完全恢复不出。两种规则在 harness 内部达到相同的 held-out 分数和 action 分布。把一半训练数据改成 on-policy 重新采集也没有改变结论。跨 harness credit 只带来配置适配，并不带来比 within-harness credit 更可迁移的能力。作者呼吁 multi-harness RL 报告应说明 grouping 边界并在未见过 harness 上评估。
💡 对"多 harness 泛化 RL"这条最近很热的路线给出清醒的负面结论——差异被 harness 本身解释掉，实验者需要控制评估侧变量。对做多 agent 训练实验的组是必要的方法论提醒。
