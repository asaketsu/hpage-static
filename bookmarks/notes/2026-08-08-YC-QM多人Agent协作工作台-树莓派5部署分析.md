## 一句话定义

> Y Combinator 出品的**多人多 Agent 协作工作台**——不是个人助手，而是为创业公司设计的组织级 Agent Harness。每个员工有独立沙箱、记忆、权限，同时在 Slack/Web 上协作。支持 Pi、OpenCode、Codex、Claude Code 等多种 Harness 互换。

## 一、核心架构

### 1.1 系统全景

```
┌──────────────────────────────────────────────────┐
│                   Postgres                        │
│         sessions · memory · queue                 │
└──────────────┬───────────────────────────────────┘
               │
┌──────────────▼───────────────────────────────────┐
│              Headless Core (TS/Node)              │
│  ┌──────────────────┐  ┌──────────────────────┐  │
│  │  API · identity   │  │   Agent Loop          │  │
│  │  policy · sched   │◄─┤  (Pi/OpenCode/Codex/  │  │
│  │                   │  │   Claude Code)        │  │
│  └──────────────────┘  └──────────┬───────────┘  │
│                                   │               │
└───────────────────────────────────┼───────────────┘
                                    │
                    ┌───────────────▼───────────────┐
                    │   Per-scope Sandbox (Docker)  │
                    │   files · tools · services    │
                    └───────────────────────────────┘
```

**三层分离**：
1. **Core**（无头核心）：TypeScript 直接在 Node 上运行，Fastify HTTP，管理 identity/policy/scheduler/agent loop
2. **Postgres**：持久化用户数据、会话历史、队列
3. **Per-scope Sandbox**：每个 scope（人/房间）有独立 Docker 沙箱，安装的工具持久保留

### 1.2 关键设计决策

| 设计 | 实现方式 | 为什么重要 |
|------|---------|-----------|
| **Harness 无关** | Pi / OpenCode / Codex / Claude Code 通过同一接口驱动 Core | 不锁定单一供应商 |
| **Scope 隔离** | 每人/每房间独立 memory、files、keychain、permissions、crons | 多人协作互不干扰 |
| **Deployment Directory 契约** | 所有组织配置在独立目录，Core 代码完全通用 | 升级只改一层 |
| **Plugin 架构** | Web UI / Admin / Portal / Slack 都是 HTTP API 上的可选插件 | 按需启用 |

## 二、功能矩阵

| 功能 | 描述 | 技术实现 |
|------|------|---------|
| **Personal & Shared Scopes** | 每人自定义自己的 Agent，同时在频道和项目中协作 | Scope-based ACL + memory isolation |
| **Slack + Web 双入口** | 同一身份和配置在 Slack 和 Web 之间无缝切换 | Bolt (Slack) + Vite/Lit (Web) |
| **Admin Control** | 组织级配置、安全策略、可用 Harness/Model 白名单 | Admin Panel 插件 |
| **Web Apps** | Agent 可构建并发布内部 Web 应用 | Sandbox 内运行 + Portal 发布 |
| **Shared Skills** | Skills 按 scope 归属，通过 grant 共享，admin 可提升为全组织级 | Skill pack 从 Git 仓库导入 |
| **Background Work** | Cron 定时任务和 Watch 监控在后台运行 | Core 内置 scheduler |
| **Sandbox 执行** | `execute` 工具在 scope 的独立沙箱中运行命令 | Docker 隔离 |

## 三、安全架构

### 3.1 三级安全姿态

| 等级 | 行为 | 适用场景 |
|------|------|---------|
| **Strict** | 每次 harness 工具调用暂停等待人工批准 | 高安全要求 |
| **Auto**（默认） | 分类器筛选来源标记的外部数据和工具结果后才送入模型 | 日常使用 |
| **Dangerous** | 无内容筛选，无暂停 | 受控开发环境 |

### 3.2 预声明命令策略

**在所有姿态下都生效**（包括 Dangerous）：
- ✅ 批准规则（approval rules）
- 🚫 硬拒绝递归删除（`rm -rf`）
- 🚫 硬拒绝破坏性 SQL（`DROP TABLE`）

### 3.3 沙箱隔离

Agent 的 `execute` 工具在 scope 专属 Docker 容器中运行。容器特点：
- 持久化：安装的工具在重启后保留
- 隔离：每个 scope 独立容器
- 预装：Git、gh CLI、Python venv、Claude Code、Codex

## 四、树莓派 5 部署可行性分析（核心目标）

### 4.1 硬件要求评估

| 要求 | QM 官方 | 树莓派 5 | 评估 |
|------|---------|---------|------|
| **CPU 架构** | x86_64 (默认) / **arm64** (显式支持) | **ARM Cortex-A76 (arm64)** | ✅ **直接兼容** |
| **Node.js** | ≥24.15.0（.node-version = 24.18.0） | 官方 arm64 build 可用 | ✅ 兼容 |
| **内存** | 推荐 8GB+（Postgres + Core + Sandbox） | RPi5 8GB 版本 | ⚠️ 最低线，大沙箱会吃紧 |
| **存储** | SSD 推荐（Postgres I/O） | NVMe HAT 或 USB 3.0 SSD | ✅ 建议使用 NVMe |
| **网络** | 需要外网访问 LLM API | 以太网/WiFi | ✅ |
| **Docker** | 必需（Sandbox 容器） | Docker arm64 官方支持 | ✅ 兼容 |

### 4.2 ARM64 兼容性证据

**fly/Dockerfile 明确支持 arm64**（关键证据）：

```dockerfile
ARG TARGETARCH
ARG GH_VERSION=2.93.0
RUN case "$TARGETARCH" in \
      amd64) GH_SHA=02d1290eba... ;; \
      arm64) GH_SHA=c55feb3368... ;; \  # ← arm64 有独立 SHA 校验
      *) exit 1 ;; \
    esac

# AWS CLI 同样分 arm64:
RUN case "$TARGETARCH" in \
      amd64) AWS_ARCH=x86_64; AWS_SHA=... ;; \
      arm64) AWS_ARCH=aarch64; AWS_SHA=... ;; \  # ← arm64 支持
```

**预装工具 ARM64 兼容性**：

| 工具 | ARM64 支持 | 备注 |
|------|-----------|------|
| Node.js 24 | ✅ 官方 arm64 build | `node:24-slim` 有 arm64 tag |
| Git | ✅ | apt 原生 |
| gh CLI 2.93.0 | ✅ | 官方 arm64 release |
| Claude Code 2.1.210 | ✅ | npm 全局安装，纯 JS |
| Codex 0.144.4 | ✅ | npm 全局安装 |
| Python 3 + venv | ✅ | apt 原生 |
| AWS CLI 2.34.54 | ✅ | 官方 aarch64 release |
| Chromium（可选） | ✅ | apt arm64 原生 |
| nftables | ✅ | 内核模块 |

### 4.3 树莓派 5 部署步骤

#### 方案 A：完整部署（Core + Postgres + Web UI）

```bash
# 1. 系统准备（假设 Raspberry Pi OS 64-bit Bookworm）
sudo apt update && sudo apt install -y git curl

# 2. 安装 Node.js 24（arm64）
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo bash -
sudo apt install -y nodejs
node --version  # 确认 >= 24.15.0

# 3. 安装 Docker（arm64）
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# 重新登录后验证
docker run --rm hello-world

# 4. 安装 Postgres（arm64 原生）
sudo apt install -y postgresql postgresql-contrib
sudo systemctl enable postgresql

# 5. 创建数据库
sudo -u postgres createuser --createdb qm
sudo -u postgres psql -c "ALTER USER qm PASSWORD 'your_password';"
sudo -u postgres createdb -O qm qm_db

# 6. 克隆 QM
git clone https://github.com/yc-software/qm.git
cd qm

# 7. 安装依赖
npm ci

# 8. 配置环境变量
cp .env.example .env
# 编辑 .env:
#   HARNESS=pi                    # 或 opencode/codex/claude-code
#   HARNESS_SECURITY_POSTURE=auto
#   ANTHROPIC_API_KEY=sk-ant-...  # 或 OPENAI_API_KEY / OPENROUTER_API_KEY
#   ORG_ID=my-org
#   PORT=8080
#   DATABASE_URL=postgres://qm:your_password@localhost:5432/qm_db

# 9. 构建本地 Sandbox 镜像（arm64）
PLATFORM=linux/arm64 docker build --platform linux/arm64 \
  -f fly/Dockerfile -t qm-sandbox-base:dev .

PLATFORM=linux/arm64 docker build --platform linux/arm64 \
  -f local/Dockerfile --build-arg BASE=qm-sandbox-base:dev \
  -t qm-sandbox-local:latest .

# 10. 启动 Core
npm start
# 访问 http://<rpi-ip>:8080
```

#### 方案 B：精简部署（仅 Core + Web UI，无 Slack）

```bash
# 使用 dev-instance 脚本（自动跳过 Slack）
npm run dev-instance:no-slack
```

#### 方案 C：Docker Compose 一键部署

```yaml
# docker-compose.yml（树莓派专用）
version: '3.8'
services:
  postgres:
    image: postgres:16-alpine
    platform: linux/arm64
    environment:
      POSTGRES_USER: qm
      POSTGRES_PASSWORD: your_password
      POSTGRES_DB: qm_db
    volumes:
      - pgdata:/var/lib/postgresql/data
    restart: unless-stopped

  qm-core:
    build:
      context: .
      dockerfile: deploy/core/Dockerfile
    platform: linux/arm64
    depends_on:
      - postgres
    env_file: .env
    environment:
      DATABASE_URL: postgres://qm:your_password@postgres:5432/qm_db
    ports:
      - "8080:8080"
    volumes:
      - qm-data:/data
    restart: unless-stopped

volumes:
  pgdata:
  qm-data:
```

### 4.4 性能预估（树莓派 5 8GB）

| 指标 | 预估值 | 说明 |
|------|--------|------|
| **Core 冷启动** | ~5-10s | Node TS 直接运行 |
| **并发会话** | 3-5 个 | ARM A76 四核 + 8GB 限制 |
| **Sandbox 容器启动** | ~2-3s | Docker arm64 |
| **Postgres 查询** | <10ms（NVMe SSD）| SD 卡会慢 10-50x |
| **LLM API 延迟** | 取决于网络 | RPi5 不是瓶颈 |
| **内存占用（空载）** | ~500MB-1GB | Core + Postgres |
| **内存占用（1 活跃会话+沙箱）** | ~2-3GB | 加上 Docker 容器 |

### 4.5 树莓派部署注意事项

| 风险 | 缓解措施 |
|------|---------|
| **内存不足** | 限制并发 Sandbox 数量；使用 Swap（但会严重降速） |
| **SD 卡磨损** | **必须用 NVMe HAT 或 USB SSD**；Postgres 写入频繁 |
| **散热** | RPi5 高负载温度可达 80°C+；需主动散热（风扇/散热片） |
| **网络延迟** | 以太网优于 WiFi；LLM API 调用对延迟敏感 |
| **Docker arm64** | `--platform linux/arm64` 确保正确架构 |
| **Node.js 24** | nodesource 的 arm64 build 稳定；也可用 nvm |

## 五、与 Hermes Agent 的对比

| 维度 | Hermes Agent | YC QM |
|------|-------------|-------|
| **定位** | 个人 AI Agent 平台 | 组织级多人 Agent 工作台 |
| **语言** | Python | TypeScript |
| **持久化** | SQLite | Postgres |
| **多用户** | 单用户 | **原生多人**（Scope 隔离） |
| **Harness** | 内置 | **可插拔**（Pi/OpenCode/Codex/Claude Code） |
| **部署** | 单进程 | Core + Sandbox + Plugin 微服务 |
| **Skill 系统** | 文件系统 Skill | **Scope-owned + grant 共享** |
| **安全** | AGENTS.md 约定 | **三级姿态 + 预声明策略** |
| **平台** | Feishu/Telegram/etc | Slack + Web |
| **边缘部署** | ✅ Jetson Orin | **✅ ARM64 显式支持** |

### 5.1 可借鉴的设计

1. **Scope 隔离模型**——Hermes 的 Skill/Memory 按用户隔离可以更系统化
2. **Harness 可插拔**——Hermes 目前锁定自己的 Loop，可以抽象接口支持外部 Harness
3. **Deployment Directory 契约**——配置与代码完全分离，升级时只改配置层
4. **三级安全姿态**——比 AGENTS.md 的自然语言约束更可程序化验证
5. **Skill Pack from Git**——从 Git 仓库导入 Skill Pack，比手动 `skill_manage` 更适合组织级分发

## 六、结合最新研究与技术变化

### 6.1 与 Coding Agent Harness 解剖学笔记的关联

QM 的"Core + 可插拔 Harness"架构是 Mastra 文章分析的 27 分钟 Coding Agent 架构的**组织级实现**——同一个 agent loop 接口下可以跑 Pi/OpenCode/Codex/Claude Code，对应 Mastra 所说的"Harness 工程才是竞争力"。

### 6.2 与深入理解 AI Agent 笔记的关联

QM 的 scope-based memory/files/permissions/crons 是 Ch 2 上下文工程的**多租户扩展**。Agent = LLM + 上下文 + 工具，QM 把"上下文"做成了 per-scope 的持久化资源。

### 6.3 与 FDE 方向的关联

QM 的 Deployment Directory + Skill Pack + Admin Control 面向的是 FDE 的组织部署场景——"如何让一个 10 人团队用上 AI Agent"。

## 八、趋势判断

1. **多人 Agent 是下一个范式**——从个人助手到组织级工作台，YC 用 12.4K Stars 验证了这个方向
2. **Harness 无关是关键差异**——不锁定单一 LLM/Harness 是组织采用的必要条件
3. **Deployment Directory 契约**将成为标准——配置与代码分离是组织级部署的基础
4. **Skill Pack 生态**——从 Git 仓库导入 Skill Pack 可能形成类似 npm 的分发体系
5. **ARM64 支持不是事后添加**——fly/Dockerfile 的 arm64 SHA 校验证明 QM 从第一天就考虑了边缘部署
