## 〇、执行摘要（内容整理）

| 坎 | 原推定性 | 飞机设计企业细化 | 难度权重 |
|----|---------|----------------|---------|
| ① 数据清洗 | 历史文件多源异构 | 型号资料 30 年沉淀：图纸/PDF/Word/扫描件/CATIA 模型/微信记录，涉密分级 | ★★★★ |
| ② 文本分块 | 影响召回质量 | 适航条款/技术规范/设计手册的分块必须保条款号、保表格、保公式 | ★★★★ |

**一句话结论**：飞机设计企业的知识库不是"资料检索工具"，而是**适航可追溯体系 + 型号构型基线 + 专业经验资产**三合一的 AI 基础设施。清洗分块决定下限，检索策略决定上限。

## 一、第一道坎：数据清洗 — 型号资料的战场

### 1.1 数据资产盘点（先做这个再谈 AI）

飞机设计企业典型数据资产清单：

| 类别 | 形态 | 体量特征 | 清洗难点 |
|------|------|---------|---------|
| 适航规章 | CCAR-25/21/33/35、FAR/CS 对应条款、AC 咨询通告 | 条款级修订频繁（Amdt 卷） | 中英文对照、修订线标注、条款关联引用 |
| 型号技术资料 | 技术规范(TS)/设计手册(DHC)/标准件手册(SPM)/系统原理图 | 数万份，版本基线多代并存 | **版本有效性**是生死问题 |
| 图纸与模型 | 2D 图纸（历史扫描 TIFF）、3D CATIA/MBD 模型、EBOM | 旧型号扫描件质量差 | OCR + 图层语义 + 与 EBOM 对齐 |
| 强度/性能报告 | 计算报告（NASTRAN/PATRAN 输出）、试验报告（全尺寸静力/疲劳） | 超长文档（千页级） | 表格/公式/云图截取，超长分块 |
| 三性分析 | FMEA/FTA/FTA 顶事件/维修性分析(RCM)、安全性评估(FHA/PSSA/SSA) | 交叉引用网状结构 | 跨文档因果链不能切断 |
| 评审记录 | 各阶段评审（方案/初步/详细）、专业会签意见 | 散落在邮件/微信/OA | **碎片化+缺上下文（评论区公认最难）** |
| 试飞与故障 | 试飞科目数据、故障归零报告、FRACAS 记录 | 时间序列+闭环流程 | 归零结论与措施的对应关系 |
| 供应商资料 | SCD/ICD 接口文件、供应商数据包(SDP) | 权限边界严格 | 跨组织权限隔离 |

### 1.2 清洗操作规程（六步）

```
盘点 → 分级 → 解析 → 结构化 → 质量准入 → 入库登记
```

1. **盘点**：按上表八类造资产台账，每类标注：来源系统/密级/版本基线/责任专业室
2. **分级**：涉密件物理隔离——公开级（已发布适航规章）可进云；内部级进内网知识库；涉密级**不入 AI 知识库**（或入物理隔离的专属实例）
3. **解析**（分文档类型的 skill 化，这正是"清洗转化的 skill 很重要"）：
   - 适航规章 PDF：保留条款号层级（25.303 → (a)(b)(c) 项），中英对照双列对齐
   - 扫描图纸：OCR + 图框信息（图号/版次/日期/签名栏）结构化提取
   - 试验报告：表格还原优先级最高（载荷谱/刚度数据必须行列保真）
   - 微信/OA 评审意见：会话线程重组——按时间+议题聚簇，补齐"问题-答复-结论"三元组
4. **结构化**：统一元数据 schema（最少必填字段）：

```yaml
doc_id: 型号-专业-序号
doc_type: TS/DHC/FMEA/REPORT/...
model_line: C919/Y20/...          # 型号线
effectivity: 构型有效性区间         # 关键！决定版本失效
revision: 版次+日期
airworthiness_ref: 关联条款号列表    # 如 [25.303, 25.305]
discipline: 气动/结构/强度/航电/...
security_level: 公开/内部/涉密
owner: 责任专业室+责任人
```

5. **质量准入**：双门禁——规则校验（条款引用格式/版本字段完整性）+ 抽样人工审批（每批 5%）
6. **入库登记**：与 PDM/构型管理系统（如 Windchill/Teamcenter）建立 doc_id 映射，**单一事实源在 PDM，知识库只做影子索引**——避免双头维护

### 1.3 微调难点（"难就难在各环节微调"的实指）

| 环节 | 表面做法 | 微调后的做法 |
|------|---------|-------------|
| 图纸 OCR | 通用 OCR | 针对图框/标题栏/焊接符号的行业词典 + 人工抽检反馈闭环 |
| 表格还原 | 整表转文本 | 载荷表/公差表保留行列结构，数值精度一位不丢 |
| 术语归一 | 不处理 | 同义词表：`平尾=水平尾翼=HT`，`超落=起落架收放系统`…按企业习惯定制 |
| 修订识别 | 只看日期 | Amdt 修订线/换页说明解析，条款新旧版自动关联 |

## 二、第二道坎：文本分块 — 保条款、保表格、保因果

### 2.1 分块策略选择表（按文档类型）

| 文档类型 | 推荐分块 | 长度 | 理由 |
|---------|---------|------|------|
| 适航条款 | **条款级整块**（25.303 含 abc 项 + 附近 AC 摘要） | 300-800 字 | 条款是不可分割的合规单元，切开即断章取义 |
| 技术规范 TS | 章节级 + 前置元数据头 | 500-1000 字 | 每个 chunk 复制 doc_id/版次/型号头 |
| 设计手册 DHC | 主题段落 + 图表锚点 | 400-800 字 | 图表引用 ID 与正文 chunk 绑定 |
| FMEA/FTA | **行级展开**（每个失效模式一行→一块，附全表上下文摘要） | 行级 | 后续检索"某失效模式影响"必须命中单行 |
| 试验报告 | 结论摘要块 + 数据表格块分离 | 摘要 300 字 | 结论与数据分块但互链 |
| 评审/微信 | 议题线程聚簇成块 | 线程级 | 碎片单条无意义，聚簇后才有上下文 |
| 计算报告 | 只入库摘要+关键结果表，原始输出文件挂链接 | — | 千页级原始数据不做向量检索 |

### 2.2 分块质量红线（原推"关键问题被拆到两块"的防治）

1. **重叠窗口 ≥15%**：相邻 chunk 重叠，防止边界切断定义
2. **父块回链**：每个 chunk 存 parent_id，检索命中子块可回拉父章节
3. **三不切**：表格不切、公式推导不切、条款项 (a)(b)(c) 不切
4. **chunk 头部强制的元数据注入**：`[C919|结构|TS-101 Rev C|25.303]` 拼进 chunk 文本，让向量表示自带上下文锚
5. **验收指标**：抽样 100 个真实问题，"答案完整性"人工评分 ≥90 分才放行分块方案——分块方案不是拍脑袋定的，是**测出来的**

## 三、第三道坎：检索策略 — 真正的 Alpha ★（指南分析·核心）

> 原推原话："检索没有一个放之四海而皆准的方法"。飞机设计场景的 alpha 在于：**查询意图差异极大**（查条款 vs 查数据 vs 查归零经验），单一检索必然顾此失彼。

### 3.1 三层检索架构

```
L1 路由层：查询意图分类
   ├─ 条款类（"25.303 安全系数是多少"）→ 精确条款索引
   ├─ 数据类（"某型襟翼铰链扭矩数据"）→ 结构化检索 + 元数据过滤
   ├─ 经验类（"以往缝翼卡滞怎么归零的"）→ 向量 + 图谱多跳
   └─ 混合类 → 多路并行
L2 召回层：Hybrid（Dense 向量 + BM25 关键词）+ 元数据预过滤（型号/版次/密级）
L3 精排层：Rerank 重排 + 新鲜度加权（最新版次优先）+ 权限过滤（后置=事故）
```

### 3.2 飞机设计场景检索微调清单（alpha 实指）

| 微调点 | 做法 | 为什么是 alpha |
|--------|------|---------------|
| **条款号精确召回** | 正则识别查询中的条款号（25.303/CCAR-21-R4 §21.17）直跳条款索引 | 向量检索对编号天然弱，这一项做不做差 50% 准确率 |
| **版次有效性过滤** | 检索前先解构型基线：按 effectivity 过滤，只召回"当前有效版" | 防止老版规范误导设计——错误答案比无答案危害大十倍 |
| **专业域 Embedding 微调** | 用本所历史问答对/条款对微调 embedding 模型 | 通用向量分不清"缝翼卡滞"和"襟翼卡滞"的专业差异 |
| **跨文档多跳（GraphRAG）** | 失效模式→原因→措施→验证的图谱遍历 | 归零经验分散在 FTA/FMEA/试验报告/会议纪要四类文档，单跳必挂 |
| **权限前置** | 用户身份→密级过滤→再检索 | 涉密环境红线：权限过滤必须在检索链路内，不是答案出来再删 |
| **表格数值直查** | 数值型查询走结构化索引（哪份报告哪个表哪一行） | "某载荷谱第 3 级载荷"向量检索永远答不准 |
| **Rerank 模型域适配** | 用适航 QA 对微调 rerank（bge-reranker 类） | 初召回 50 条里挑 5 条，挑得准不准就是最终质量 |
| **引用白盒** | 答案必须挂 doc_id+页码+版次，可回跳原文 | 适航文化 = 一切结论可追溯，无引用答案不可信 |

### 3.3 检索效果评测（没有评测=没有 alpha）

建立**适航 QA 金标集**（300+ 条真实问题，按四类意图分层）：
- 指标：Recall@5 / MRR / 条款命中率 / 版次正确率 / 引用完整率
- 节奏：每次调分块/换模型/改权重，全量回归一遍
- **归因工具**：错的每一条标注"清洗锅/分块锅/召回锅/精排锅"，错误归因到层，才叫微调；不归因瞎调 = 越调越坏

## 四、第四道坎：知识库维护 — 人机共治的运营体系（归纳总结）

### 4.1 失效来源与对策

| 失效场景 | 触发 | 对策 |
|---------|------|------|
| 规章改版 | CCAR/AC 修订发布 | 订阅官方通告→自动触发新版入库+旧版标记 superseded（图谱三坑笔记的 append-only 模式） |
| 构型冻结/改版 | 设计发图/工程更改单(ECO) | 与 PDM 联动，ECO 签发即更新 effectivity 索引 |
| 知识过时 | 工艺/材料替代 | 知识责任人对名下文档季度复核（系统自动派任务） |
| 冲突知识 | 新老报告结论矛盾 | 冲突检测入治理队列→专家裁决→失效标注不删除（保留审计轨迹） |

### 4.2 人机共治机制（原推"人与 AI 共同维护"的落地）

- **AI 侧**：无结果率/低引用率/冲突检测自动生成治理工单，按专业室派发
- **人侧**：每个专业室设知识管理员（兼职），复核审批 AI 发现的问题；专家头脑风暴产出走"访谈→结构化→入库"通道（隐性知识显性化是设计所最大的增量）
- **度量看板**：无结果率 / 引用有效率 / 文档新鲜度中位数 / 治理工单关闭时长——四指标月报，绑定部门考核才有执行力

### 4.3 FDE 工程师的角色（原推结论句的展开）

> "这也是为什么，企业需要专业的 FDE 工程师帮忙落地的原因。"

飞机设计企业落地 AI 知识库需要三重角色的 FDE：
1. **RAG 工程侧**：管清洗 skill 开发、分块调优、检索评测——本文第二三章的全部内容
2. **航空工程侧**：懂型号资料体系/适航符合性方法（MC0-MC9）/构型管理，否则分块和评测集都做不对
3. **组织侧**：跨专业室推动数据准入、权限谈判、治理考核落地

招第三种人最难，前两种可以培养——**跨域 FDE 是知识库成败的真正变量**。

## 五、实施路线图（90 天试点版）（趋势判断与拓展应用）

| 阶段 | 周期 | 交付 | 验收标准 |
|------|------|------|---------|
| P0 资产盘点+选型 | 第 1-2 周 | 资产台账/密级方案/技术选型 | 台账覆盖 ≥80% 核心资料类 |
| P1 单场景试点 | 第 3-6 周 | **适航条款问答**（公开级数据先行） | 金标集 100 条，条款命中率 ≥90% |
| P2 检索调优 | 第 7-10 周 | Hybrid+条款精确召回+rerank 微调 | Recall@5 ≥85%，版次正确率 100% |
| P3 专业扩展 | 第 11-13 周 | 扩到 1-2 个专业（结构/航电）+经验类检索 | 图谱多跳试点上线 |
| P4 运营固化 | 持续 | 治理工单流/月度看板/知识管理员网络 | 无结果率月降 10% |

**优先级铁律**：先适航条款（公开、结构化、高价值、低风险）→ 再技术规范 → 最后经验类（微信/评审，最难清洗）。**从最难的数据开始 = 项目必死**。

## 六、常见误区（飞机设计企业特供版）

1. ❌ "把 PDM 数据全量灌进向量库" → 正解：知识库是 PDM 的影子索引+语义层，全量灌入等于双头维护+版次混乱
2. ❌ "涉密数据脱敏后就能进通用大模型" → 正解：涉密件物理隔离，内网专属实例，审批链留痕
3. ❌ "分块统一 512 token 一刀切" → 正解：条款/表格/FMEA 行级三种策略并存（见 2.1）
4. ❌ "检索就是向量相似度" → 正解：条款号精确+数值直查+图谱多跳，向量只是召回的一路——**这是 alpha 与平庸的分界线**
5. ❌ "上线即完成" → 正解：适航文化本身就是"持续符合"，知识库的维护节奏必须与构型/规章演进同频
6. ❌ "买平台=有能力" → 正解：清洗/分块/评测的微调能力（skill+专家）不可外包，平台可以买 alpha 买不来
