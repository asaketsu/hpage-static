## 归纳总结

**一句话：开放世界没有 ground-truth 验证器时，用"同任务 A/B 行为对比"替代分数反馈来指导 harness 编辑——这是 Harness² 对 RSI 的核心破局。**

两层递归：①任务级 Propose-Probe-Compose（提双候选→同任务对比→证据组合）②harnessing 级 improvement harness（教训库持续引导改进流程本身，执行 harness 不继承）。

**最惊人实证：GLM-5 换上改进 harness 后反超 Gemini 基础分——"换 harness"某些场景顶得上"换模型"。**

## 内容整理：机制与数据

### 两层递归架构

| 层 | 机制 | 关键点 |
|---|---|---|
| 任务级 | Propose–Probe–Compose | 双候选（跨领域代理缺陷 + 领域特化）同任务执行对比；Compose 每个决策**绑定具体观察**而非假想分数增益 |
| harnessing 级 | improvement harness | 教训**只在执行对比支持时保留**；库存**可执行组件文件**而非散文摘要 + EXPERIENCE.md；下任务从公共基础出发（执行 harness 不继承），改进流程由库引导 |

### 主要结果（k=1，编辑器 Claude Opus 4.8）

- GLM-5 + OpenCode：WorkBuddy-Bench **+11.5**（64.2→75.7）、LAB **+11.8**（59.6→71.4）
- 越弱的执行模型获益越大；跨模型迁移（为 Gemini 精炼的 harness 给 GLM-5 +17.3）
- 自编辑也涨（GLM-5 自编辑 LAB +13.7）——不依赖更强老师
- 库消融 -3.1 分，库可跨基准迁移（+0.6~+2.9）

## 关联分析：对我们系统的四分判定

**逐条对照实测（非拍脑袋）**：

| Harness² 机制 | 我们的对应物 | 判定 |
|---|---|---|
| Propose 双候选 | evolver 信号采集→候选生成（evidence 字段） | ✅ 已满足 |
| "库存可执行组件非散文" | evolver 评分维度 5"禁止建议/视情况而定" + error-case 40/42 带 fix 字段 | ✅ 已满足 |
| Probe A/B 对比 | error-case-library 的 contrastive_evidence + skill-ab-testing skill | ⚠️ **机制有但闲置**（使用率 1/42） |
| "教训只在执行对比支持时保留" | evolver 无此门槛（Count-Based Override 反向放宽高频低置信） | 🔧 已补：单次成功 confidence 上限 0.5 需二次复现 |
| improvement harness 递归 | evolution-gate 单层 | ⏸️ 暂缓（见趋势判断） |
| 八组件编辑体系 | Hermes 组件模型天然覆盖 | ➖ 明确不做 |
| 完整框架复刻（k 候选并行/串行） | 无 benchmark 重放基础设施（真实任务有副作用不可重放） | ➖ 明确不做，ROI 为负 |

### 本日已落地的两处增强

1. **error-case-library**：静默失败类案例的 contrastive_evidence 从"可用"升为"必填"（针对 1/42 闲置）
2. **evolver**：新增"单次成功不沉淀门槛"——count=1 成功案例 confidence 上限 0.5，二次独立复现才可 adopt（与高频低置信的 Count-Based Override 形成"高频故宽、单次故严"互补）

## 趋势判断

1. **"换 harness 顶换模型"改变投入产出计算**：我们 glm-5.3 + 手工打磨 skill 体系 = 同一思路的手工版；Harness² 证明这条路自动化可行，且弱模型获益更大（我们主模型非顶级，恰是受益区）
2. **无验证器改进是刚需方向**：真实环境（真机/外部系统）没有 ground-truth，A/B 对比是唯一可用的信号源——与我们 error-case 的对比重放归因同构，该机制必须用起来
3. **improvement harness 递归暂缓的触发条件**：当我们出现"高频可重放任务域"（如笔记管线/盯盘扫描这类可重复执行的任务链）时，可把 evolution-gate 升级为双层——目前真实环境不可重放，硬上会造伪证据

## 指南分析

- ✅ 直接可抄：A/B 对比必填化（已落地）、教训证据门槛（已落地）、EXPERIENCE.md 式"适用场景+证据"字段（我们的 provenance 已覆盖）
- ⚠️ 需改造：Compose 的"决策绑定具体观察"——skill patch 说明已有 provenance，但未强制绑定"观察到的行为差异"，下次重大 skill 修改时试点
- ➖ 不抄：parallel k 探测（无重放环境）、完整八组件体系（Hermes 已有）

## 拓展应用推荐

1. **contrastive_evidence 使用率纳入 evolution-gate 监控**（低成本）：下季度 error-case 新增时统计必填遵守率，静默失败案例无对比证据 = 信号
2. **skill-ab-testing 在下次重大 skill 修改时真实启用**（中优先级）：Harness² 证明对比执行是唯一可信信号——改 skill 前后各跑一次同任务
3. **"换 harness 顶换模型"写进模型经济学决策**：遇到任务效果差时，先排查 skill/prompt 质量（免费）再考虑换模型（烧额度）——与包月优先原则同向
