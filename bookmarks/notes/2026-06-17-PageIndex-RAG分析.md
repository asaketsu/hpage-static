# PageIndex：扔掉向量数据库，RAG 准确率飙到 98.7%

> 来源：[AI撬动地球](https://mp.weixin.qq.com/s/OkNToMF9X836hAIdWhknoA)
> 日期：2026-06-17
> 项目：[VectifyAI/PageIndex](https://github.com/VectifyAI/PageIndex) · 23,000+ ⭐

---

## 核心结论

**PageIndex 用 LLM 推理替代向量搜索，用树状结构替代分块，用"像人一样翻文档"替代余弦相似度。**

- FinanceBench 准确率：**98.7%**（第二名 91%，传统向量 RAG 30-50%）
- 2900 行 Python，6 个文件，**无向量数据库、无 embedding 模型、无文档分块**
- 核心创新：**上下文内索引（in-context index）** — 树结构 JSON 驻留在 LLM 上下文窗口中

---

## 传统向量 RAG 的五大结构性缺陷

| 缺陷 | 现象 | 后果 |
|------|------|------|
| 查询≠答案 | 用户问"收入趋势"，召回的是"谈到收入"的文字，而非具体表格行 | 语义相似 ≠ 内容相关 |
| 同词多义 | "营业利润"在 200 页中出现 60 次，向量相似度排名几乎一样 | 真正答案进不了 top-3 |
| 分块碎表 | 表格标题在 chunk 14，数据行在 chunk 15 | 单独看 chunk 毫无意义 |
| 跨页引用丢失 | 第 12 页"详见附录 G"（第 87 页），向量相似度为 0 | 无法跟随引用 |
| 多轮无记忆 | "负债呢？"被当全新查询 | 上下文丢失 |

> **核心洞察**：检索真正需要的是**相关性**，而相关性需要**推理**。

---

## 架构：两步走

### 第一步：构建层次树索引

把 PDF 喂进去 → 不做 embedding/分块 → 分析文档结构 → 生成层次化 JSON 树（"LLM 优化版目录"）。

每个节点：`{node_id, title, summary, start_index, end_index, sub_nodes}`

50 页 SEC 文件 → 30-50 个节点。整棵树是 JSON 对象，**不存向量数据库，驻留在 LLM 上下文窗口**。

### 第二步：基于推理的树搜索

```
LLM 读取节点标题+摘要 → 推理哪些章节可能包含答案 → 返回节点 ID → 获取原始内容 → 够了吗？
```

检索循环：扫描目录 → 选择最可能相关节点 → 读取原始内容 → 生成答案 / 继续找

**与向量搜索的本质区别**：向量数据库并行计算余弦相似度（快但蠢）；PageIndex 让 LLM **思考**答案在哪里。

## 自修正目录提取：三条 fallback 路径

| 路径 | 场景 | 处理方式 |
|------|------|---------|
| **A** | PDF 有完整 TOC + 页码 | 提取 TOC → 验证（并发抽检）→ 修正（定位错误项前后正确条目） |
| **B** | PDF 有 TOC 但无页码 | 提取 TOC 结构 → 内容匹配推断页码 |
| **C** | PDF 无 TOC | 按 token 分块 → LLM 从零生成层次结构 → 合并为完整 TOC |

降级链：A 失败跳 B，B 失败跳 C。每次切换意味着更多 LLM 调用，但保证任何文档都能产出可用索引。

## 附录 G 案例（说服力）

用户问："递延资产总额是多少？"

- **向量 RAG**：第 77 页说"详见附录 G"，但附录 G 是数字表格，与"递延资产"语义相似度为 0 → 完全忽略
- **PageIndex**：LLM 导航到金融章节 → 遇到交叉引用 → 跟随引用到附录 G → 从表格中找到精确数字

**推理检索 vs 相似度检索**的本质区别。

## 对 AnimatronicEye-Pro / ServoArm-Pro 的启示

PageIndex 的核心思想——**用结构化索引替代模糊搜索**——对硬件项目同样适用：

1. **校准数据管理**：当前用 EEPROM 存储校准值， pageIndex 式的树索引可以让校准参数有层次结构（关节→轴→限位），支持版本回溯
2. **故障诊断**：错误日志可以用树结构组织（电源→I2C→舵机→运动），LLM 推理故障根因而非关键词匹配
3. **动作序列**：动作库可以用树索引（基础动作→复合动作→场景组合），支持"抓取→移动→放置"的多步推理调用
