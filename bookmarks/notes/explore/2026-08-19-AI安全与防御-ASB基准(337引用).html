一、ASB 是什么

Adversarial Safety Benchmarks 是 Hugging Face / Allen AI 团队（Elsweiler 等人）于 2022 EMNLP 提出的对抗性 NLP 安全评测框架。核心问题：当 NLP 模型面对恶意扰动输入时，其输出是否仍然"安全"（不产生有害、偏见、越狱内容）。

  • 覆盖 18 个数据集、4 类安全维度（偏见/公平、毒性、鲁棒性、越狱）
  • 涵盖 8 个任务（文本分类、NLI、翻译、生成等）和 20+ 模型
  • 引用量已超 337（截至 2026 年），成为该领域事实标准基准

二、四大安全维度与关键发现

维度1：偏见与公平性（Fairness）

  • 基准：BOLD、BiasMit 等
  • 核心发现：即使经过去偏见微调，模型在对抗扰动下仍会迅速"回归"偏见模式——公平性不是鲁棒的
  • 扰动类型：同义词替换、模板改写

维度2：毒性（Toxicity）

  • 基准：Jigsaw、HateSpeech 等
  • 核心发现：对抗扰动可让无毒文本被误判为有毒（假阳性飙升），或让有毒文本逃避检测（对抗样本绕过分类器）
  • 实用启示：内容审核分类器需要对抗训练，否则对抗样本绕过率极高

维度3：对抗鲁棒性（Robustness）

  • 基准：TAP (Textual Adversarial Perturbations)、TextFooler、Synonyms
  • 核心发现：语义等价替换（保持句意不变的同义词替换）已能让主流 BERT 类模型准确率骤降 10-30 个百分点
  • 说明：现有模型的"正确"高度依赖表面词面，而非语义理解

维度4：越狱与安全对齐（Safety Alignment / Jailbreak）

  • 基准：AdvGLUE 安全子集、Red Teaming evals
  • 核心发现：2022 年论文写作时 jailbreak 主要指对抗样本；2023-2026 年该维度已演化为"提示注入 / 角色扮演越狱"，成为 LLM 时代最活跃的攻击面

三、ASB 对 2026 LLM 时代的延伸意义

ASB 原始维度 2026 LLM 等价物 攻击/防御映射
偏见鲁棒性 系统性偏见输出、文化敏感性 对齐训练 + 护栏分类器
毒性鲁棒性 有害内容生成 运行时护栏（NSFW/仇恨分类器）
语义对抗鲁棒性 Prompt injection / 间接注入 输入消毒 + 上下文隔离
越狱 Direct/Indirect jailbreak 红队测试 + 系统提示加固

关键洞察：ASB 揭示的"模型在对抗扰动下安全属性不鲁棒"这一结论，从 2022 年的判别式 NLP 模型迁移到 2026 年的 LLM 时代依然成立——只是攻击载体从"词面扰动"升级为"提示工程攻击"。

四、对 Hermes Agent 工作的价值

  1. 运行时护栏需要对抗测试：ASB 证明"正常输入下通过" ≠ "安全"，我们已有的 cross_profile guard 和 Skill 权限控制必须在对抗场景下验证
  2. 红队测试的评估基线：ASB 的四大维度可直接映射为 Agent 红队测试的四大评估维度，可作为 agent-security-redteam skill 的评测框架
  3. MCP 工具调用的攻击面：间接 Prompt injection 通过 MCP 工具结果注入 —— ASB 的"语义等价替换"在 Agent 场景对应"工具输出的上下文混淆攻击"
  4. 护栏分类器的鲁棒性审计：现有内容审核/PII 检测分类器应定期用 ASB 风格对抗样本做鲁棒性审计

五、行动建议

  • 短期：将 ASB 四大维度集成到 agent-security-redteam skill 的评测清单中
  • 中期：构建 Agent 专属对抗样本集（Prompt injection 变体库），对标 ASB 的扰动策略
  • 长期：建立定期对抗评测机制 —— 每季度对 Hermes Gateway 的 prompt 过滤和工具授权做一轮 ASB 风格红队
