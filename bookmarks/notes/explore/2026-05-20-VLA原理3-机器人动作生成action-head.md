## 摘要

VLA系列第三篇，聚焦 action head —— 将视觉语言理解转化为可执行动作的核心模块。文章从动作表示（7维末端位姿增量 vs 关节空间）、三种动作生成策略（离散token化、连续回归、生成式扩散），到 action chunk 滚动执行机制，系统讲解了机器人动作生成的完整链路。

## 核心内容

### 1. Action Head 的定位

VLA = 理解模块（VLM）+ 动作模块（Action Head）

Action Head 把视觉+语言理解结果转换为机器人可执行的动作表示。缺了它，VLM只能"看懂"不能"动手"。

### 2. 动作表示方式

**末端位姿增量（最常用）**：
- 7维向量：Δx, Δy, Δz, Δroll, Δpitch, Δyaw, gripper
- 优点：跨机器人泛化性好
- 缺点：需要运动学逆解

**关节空间动作**：
- 7维向量：Δq1~Δq6 + gripper
- 优点：直接控制底层
- 缺点：跨机器人泛化难（关节数/结构/运动范围不同）

**Action Chunk（动作块）**：
- a_t, a_{t+1}, ..., a_{t+H}（一次输出未来H步）
- 解决单步预测抖动问题，执行更平滑稳定

### 3. 三种动作生成策略

#### 策略A：动作离散化为 Token
- 连续动作 → 区间离散化 → 映射为 token（如 MOVE_X_128）
- 优点：统一在 LLM token 预测框架内，复用训练管线
- 缺点：离散化损失精度，区间粗细是 trade-off
- 适合：大规模统一建模

#### 策略B：回归连续动作
- VLM hidden state → MLP → 连续动作向量（10×7=70维）
- 优点：简单直接，天然连续，易落地
- 缺点：**模式平均问题** — 多种合理解取平均后反而不可执行
- 适合：固定场景（固定臂/相机/工作台）

#### 策略C：生成式（扩散/Flow Matching）
- 随机轨迹 → 逐步修正 → 合理轨迹
- 优点：表达复杂动作分布，学习多样化示教模式
- 适合：灵巧操作、双臂协作、接触丰富任务
- 这是当前最前沿的方向

### 4. Action Chunk 滚动执行机制

关键洞察：不只预测一步，预测未来一段，但只执行开头几步

```
观察场景 → 生成未来10步 → 执行前几步 → 重新观察 → 重新生成 → ...
```

类似MPC（模型预测控制）的滚动规划思路：
- 短期意图清晰
- 执行过程可纠偏
- 动作更平滑

### 5. Action Head 的四类输入

1. **视觉特征** — 目标/障碍物/场景变化
2. **语言特征** — 任务目标（"放进碗里" vs "推到旁边"）
3. **本体状态 proprioception** — 关节角度/末端位置/夹爪/速度
4. **历史信息** — 过去几帧状态（判断"已抓住"还是"准备抓"）

完整公式：`action_head(visual, language, robot_state, history) → actions`

### 6. 典型架构

```
图像 → Vision Encoder
语言 → Language Encoder  
状态 → State Encoder
         ↓
    三类特征融合 → Transformer/MLP
         ↓
    输出未来10步 → 10×7维
```

训练：人类遥操作/脚本示教轨迹
执行：闭环滚动（生成→执行前几步→重新观察→重新生成）

## 🔍 深度分析

### 技术演进脉络

VLA 动作生成正在经历从"确定性回归"到"概率生成"的范式转移：

1. **第一代**：MLP回归 — 简单但模式平均问题严重
2. **第二代**：离散token化 — 统一框架但精度受限  
3. **第三代**：扩散/Flow Matching — 多模态分布建模，当前SOTA

### 与 NLP/LLM 的类比

| 维度 | LLM | VLA Action Head |
|------|-----|-----------------|
| 输出空间 | 离散 token | 连续7维向量 |
| 预测方式 | 自回归 next token | Action chunk (未来H步) |
| 多样性 | 温度采样 | 扩散/Flow Matching |
| 评估 | BLEU/困惑度 | 任务成功率/轨迹相似度 |

### Action Chunk 的深层意义

不只是"多预测几步"，实质是：
- **时序平滑先验**：强制模型学习连贯动作序列
- **隐式规划**：未来动作中包含了对任务的短期规划
- **容错机制**：执行偏差通过滚动更新自动修正

### 扩散/Flow Matching 为什么重要

机器人操作的核心难点不是"找到一个解"，而是"找到一个分布"：
- 同一任务可能有多条合理轨迹
- 确定性模型只能输出均值，均值往往不可执行
- 生成式模型能采样出多样化的可行解

## 🔍 借鉴点

- **Action Chunk 思路可迁移到 Agent 任务规划** — 不只规划下一步，而是一次规划多步，滚动执行。我们的 kanban-orchestrator 可以借鉴
- **四类输入框架** — Agent Action 也可以抽象为：上下文(visual) + 指令(language) + 当前状态(robot_state) + 历史动作(history)
- **扩散生成 > 确定回归** — AI Agent 的行动计划也应允许多种路径，不强制"最优解"

## 💡 启发
- **"模式平均问题"不限于机器人** — 任何需要从多种方案中选择一个的 AI 系统（包括 Agent 工具选择）都可能遇到。生成式方法优于回归
- **滚动执行 > 一步到位** — 这本质是"小步快跑"思想在机器人领域的体现，与我们的"小批推进法"理念一致
- **Proprioception（本体感知）的重要性** — AI Agent 也需要"知道自己当前状态"，对应 Hermes 的 memory/session 机制

## 🔮 预判
- Flow Matching 将在 VLA 领域超越扩散模型（训练效率更高）→ 1-2年内成为主流
- Action Chunk + 实时扩散推理的优化会成为工程热点 → 类似 LLM 的 speculative decoding
- 通用 VLA 模型（跨机器人/跨任务）将在 2-3 年内出现 → 需要标准化动作表示协议
