## 一、核心问题与研究动机

> **核心洞察**：RAG 是静态知识的完美工具，但面对演化知识时有一个结构性盲区——它没有时间模型。当事实变化时，新旧版本以几乎相同的 embedding 相似度并存，模型无法判断哪个是当前值。

### 1.1 问题场景

当 AI Agent 作为持久化协作者（coding assistant、research assistant、operations assistant）积累跨会话知识时，约束瓶颈从模型能力转向了**记忆**——如何编码、保留、检索并保持知识的时效性。

典型场景：
- 代码库：函数被重命名、端点迁移、配置变更、依赖升级
- 组织知识：API 重构、端口变更、服务迁移
- 任何事实有有效期的领域

### 1.2 为什么 RAG 无法解决

RAG 将交互历史存储为嵌入的 chunk，查询时检索 top-k 最相似的。当事实变化时：

> "the timeout is 1800 seconds" 和 "the timeout is 3600 seconds" 只差一个 token，在任何 embedding 模型中都几乎完全相同。检索会同时返回两者。模型没有原则性方法判断哪个是当前值，要么放弃（拒绝能回答的问题），要么猜测（经常以完全自信地输出过时值）。

### 1.3 相似度的不可能性（核心发现）

一个自然的直觉是用更好的相似度规则解决：检测新事实是否与存储事实矛盾，然后更新而非追加。论文证明这不可行：

- 在 98 个标注样本上，cosine AUROC 区分矛盾与重复仅为 **0.59**（接近随机）
- 矛盾事实的 cosine 相似度均值 **0.812**，重复事实均值 **0.800**
- **矛盾比重复更相似！** 因为值翻转（"8000"→"8080"）是比真正改写更小的编辑
- 任何阈值下的最大精度仅 **0.67**，远低于安全自动更新所需的 0.95

> **结论**：过时检测必须是结构性的，不能基于相似度。如果新事实和存储事实共享 (subject, relation) 键但断言不同 object，新值自动取代旧值——与 embedding 相似度无关。

## 二、方法论：MemStrata 架构

MemStrata 是一个位于 Agent 和语言模型之间的本地记忆层。它维护从交互中提取的事实存储，为每个查询组成一个 token 预算的上下文块。

### 2.1 写入路径：确定性替代 + 惊喜门

每个传入的 turn 产生一个候选事实，写入路径按顺序路由：

1. **精确重复短路**：归一化文本哈希丢弃逐字重复，零成本
2. **确定性断言路径**：如果 turn 表达了一个干净的 (subject, relation, object) 三元组——其中 object 是唯一的可变值——MemStrata 归一化 (subject, relation) 键并检查是否存在该键的活跃断言。如果存在且 object 不同，新断言替代旧的：旧行的有效区间关闭（valid_to 设置，superseded_by 链接），新行打开。相同 object → 重复（强化）。无先前键 → 新颖（存储）。**无 cosine，无 LLM 裁判**
3. **文本门回退**：非三元组散文回退到惊喜门，通过相似度 + LLM 裁判分类。关键的是，此回退保留非矛盾的近重复作为独立事实；仅丢弃精确重复

### 2.2 双时间账本

事实被退休，而非删除。存储记录 valid_from、valid_to 和 superseded_by，因此被替代的事实仍可用于未来的 as-of-time 查询。活跃检索仅展示当前有效的行。

### 2.3 "先保留，再替代"的设计

早期变体激进压缩，在写入时合并近重复事实以限制增长。但干净评估显示这降低了静态召回：合并丢弃了回答后续问题所需的细节（temporal_v6_lossy 消融在 project-fact QA 上降至 0.62，在 dialogue recall 上降至 0.13）。

发布的配置因此像 RAG 一样保留——存储不同的非矛盾事实——仅在与时间有效性相关的轴上限制增长，通过替代矛盾来实现。这是使系统在静态知识上匹配 RAG 同时在演化知识上占优的设计选择。

### 2.4 读取路径

嵌入查询，通过 cosine 在活跃事实和断言上检索 top-k，应用确定性过时过滤器（丢弃被替代的行），打包幸存事实。打包每个幸存断言的原始源句子，而非简洁的重构三元组：仅打包三元组会降低答案模型在丰富事实上的准确性，而打包原文恢复了准确性。

读取路径无 LLM 运行，因此检索延迟处于 embedding 下限（~2.1s），相比 LLM-reranking 和 LLM-verification 基线的 ~16-18s。

### 2.5 无标记基准构建

评估过时抵抗性很容易被污染。如果过时事实携带任何文本标记——"[OUTDATED]"、"(legacy)"、"deprecated"——检索基线可以通过读取标签来消歧，而非通过任何时间机制，静默地抬高分数。

论文强制严格的无标记不变量（通过测试）：在每个演化基准中，过时和当前版本的事实文本完全相同，仅改变的值不同，无旧/新/当前框架。唯一可用的时效信号是摄入顺序，只有时间机制可以利用。

> 移除一个基准中的标记使基线准确性最多下降 14 个点，证实污染是真实且可测量的。

## 三、关键实验结果与数据

### 3.1 实验设置

- 回答模型：Qwen2.5-Coder-7B
- 正确性和伪造裁判：Qwen2.5-Coder-3B（与回答模型不同，防止自我评分）
- 嵌入器：nomic-embed-text（768 维）
- 所有实验本地且确定性：temperature 0，固定种子，无网络

**8 种条件**：
- no_memory（下限）
- naive_rag（cosine top-k）
- advanced_rag（+ LLM reranker）
- v6_no_verify（惊喜门，无 LLM 验证）
- v6（门 + LLM 相关性验证）
- temporal_v6_lossy（确定性替代，无保留/原文修复——消融）
- temporal_v6（完整方法）
- v6+infer（门 + 可推断性预过滤）

**6 个基准**：
- 2 个静态：domain（50 个 project-fact QA）、locomo（100 轮对话上的 30 个多会话对话问题）
- 4 个演化，无标记，每个 20-30 个配对场景：code_mutation（函数重命名）、config_migration（配置值变更）、dependency_bump（版本升级）、api_evolution（端点/签名重构）

### 3.2 准确性：静态持平 RAG，演化占优

**静态基准**：
- temporal_v6：domain 0.82 / locomo 0.30
- naive_rag：domain 0.86 / locomo 0.30
- temporal_v6 在静态上匹配 RAG——保留式 RAG 设计保留了召回，而 lossy 消融崩溃（0.62/0.13），隔离了激进压缩的成本

**演化基准**：
- temporal_v6：code_mutation 1.00 / config_migration 1.00 / dependency_bump 1.00 / api_evolution 0.95
- naive_rag：code_mutation 0.43 / config_migration 0.25 / dependency_bump 0.20 / api_evolution 0.40
- temporal_v6 在演化上达到 **0.95-1.00**，相比 RAG 的 **0.20-0.47**：**2-5× 准确性提升**
- LLM-verifier 条件（v6）不一致且从未达到时间层的准确性，延迟约为 8×

### 3.3 过时事实错误率：结构性结果（核心发现）

> **核心结果**：当必须回答时，RAG 在 15-40% 的时间里输出被替代的值；MemStrata 将此降至 ~0%。

| 演化基准 | naive_rag (允许放弃/强制回答) | temporal_v6 (允许放弃/强制回答) |
|---------|---------------------------|---------------------------|
| code_mutation | 0.10 / 0.40 | 0.03 / 0.03 |
| config_migration | 0.05 / 0.35 | 0.00 / 0.00 |
| dependency_bump | 0.05 / 0.15 | 0.00 / 0.00 |
| api_evolution | 0.30 / 0.35 | 0.00 / 0.00 |

允许放弃时，RAG 通过拒绝回答来隐藏其失败（这就是为什么其准确性低）。强制回答时，它以 15-40% 的概率输出过时值。MemStrata 在两种模式下都达到 ~0%，因为过时值在检索前已从存储中移除。

这是 RAG 无法避免的错误：它检索两个值且没有选择机制。

### 3.4 状态有界增长

RAG 是历史有界的：存储每一轮，无限增长。MemStrata 保留不同的静态事实（domain/locomo 上 0% 压缩——这就是为什么它在召回上匹配 RAG），但通过替代限制演化事实的增长（~48% 压缩：code 48%、config 47.5%、dependency 50%、API 47.5%）。

诚实的表述不是"更小的记忆"，而是"过时事实被退休"：增长在路径学上病态的轴上被限制（积累矛盾版本），在应该无界的轴上无界（不同事实）。

### 3.5 延迟

temporal_v6、naive_rag 和 v6_no_verify 都处于 ~2.1s（读取路径无 LLM）。advanced_rag、v6 和 v6+infer 处于 ~16-18s（LLM rerank/verify）。

> 胜利是：在 RAG 延迟下实现准确性和时间有效性——temporal_v6 匹配 naive RAG 的速度，同时消除 naive RAG 无法避免的过时事实错误。基于 LLM 的条件支付 8× 延迟而无时间收益。

## 四、创新点分析

### 4.1 结构性不可能性证明

> **创新点 1**：首次用数据证明 cosine 相似度无法区分矛盾与重复（AUROC 0.59），为确定性结构性替代规则提供了经验基础。

这不是工程优化，而是理论边界：任何基于相似度的过时检测方案都有 33% 的上限失败率。

### 4.2 确定性替代规则

> **创新点 2**：(subject, relation, object) 三元组上的确定性替代规则——无相似度阈值、无 LLM 调用，纯结构化操作。

这绕过了所有 LLM 推理的延迟和不可靠性，同时保证了时间有效性的正确性。

### 4.3 双时间账本

> **创新点 3**：事实被退休而非删除，保留 valid_from/valid_to/superseded_by 元数据，支持 as-of-time 查询。

借鉴了数据库的双时间版本控制（ISO/IEC 9075:2011），但首次在 AI Agent 记忆系统中实现。

### 4.4 无标记评估协议

> **创新点 4**：强制无标记不变量的评估协议——过时和当前版本文本完全相同，仅改变的值不同。

这是评估记忆系统在演化下的正确方法。移除标记使基线准确性最多下降 14 个点。

### 4.5 消融实验设计

> **创新点 5**：两个方向的消融实验——过度合并（lossy 变体）和完全不替代（full-retention 变体）——精确隔离了确定性替代作为演化知识结果的唯一原因。

## 五、局限性与未来方向

### 5.1 结构化、单值基准

演化基准是无标记模板，每个事实只有一个可变值，因此三元组提取器可靠（~97% 替代）。在更杂乱的自然语言矛盾基准上，提取降至 ~44%（多值句子、畸形扰动）。提取质量（而非替代机制）是非结构化矛盾的门控因素。

> **未来工作**：实体规范化、关系类型化、多值提取。时间账本和替代规则是领域无关的；提取层必须随之迁移。

### 5.2 摄入顺序代理时间

基准使用顺序（状态 A 然后状态 B）作为时效信号。真实的时间基准携带显式日期；双时间账本已存储有效区间，线程化真实 valid_from 时间戳加上 "as-of-T" 检索模式是未来工作。

### 5.3 单一裁判噪声

3B 正确性裁判偶尔将包含过时值的门条件答案评分为"正确"，产生少数准确性和过时错误重叠的行。时间层的 ~0% 过时错误不受影响（其上下文中无过时事实）。

### 5.4 规模和模型

所有结果使用单个 7B 回答模型在消费级硬件上。更大的模型或云推理可能改变基线；故意约束为本地优先。基准规模（每个数十项）隔离机制而非在排行榜上排名系统。

## 六、借鉴点（关联 Hermes Agent / Jetson Orin / 量化交易）

### 6.1 Hermes Agent 记忆系统 — 🔨 可直接移植（P0）

**问题**：Hermes Agent 的 memory/skill/cron 系统面临完全相同的过时问题。当 skill 被 patch、cron job 被修改、memory 被更新后，knowledge_query 的 RAG 检索可能返回旧版本信息。

**MemStrata 的适用性**：
- 写入路径：当 skill/memory 更新时，用 (subject, relation, object) 三元组匹配并替代旧版本
- 读取路径：检索时过滤被替代的行，仅返回当前有效版本
- 延迟优势：~2.1s 的检索延迟对 Hermes 的实时交互至关重要

**移植方案**：
1. 为 memory/skill/cron 条目建立 (subject, relation, object) 三元组索引
2. 更新时执行确定性替代而非追加
3. 检索时过滤被替代的行
4. 保留双时间账本支持历史查询

**工作量估计**：中等。需要修改 knowledge_query skill 的写入和检索逻辑，约 2-3 天工程。

### 6.2 RAG 过时检测 — ✅ 已部分实现（P1）

**现状**：Hermes 的 memory 系统已有基本的版本追踪（通过 git 和文件时间戳），但检索时没有结构化过滤。

**增量价值**：引入 MemStrata 的确定性替代规则，将检索准确性从当前的"可能返回过时信息"提升到"保证返回当前版本"。

### 6.3 无标记评估协议 — 🔨 可直接移植（P1）

**适用性**：Hermes Agent 的 skill 测试和 memory 验证可以使用无标记协议。当验证 skill 是否正确响应更新后的命令时，确保测试数据不包含任何时间标记（如"旧版"、"deprecated"），仅依赖结构化的时间机制。

### 6.4 双时间账本 — 🔨 可直接移植（P2）

**适用性**：支持 as-of-time 查询——"在 2026-06-15 时，这个 skill 的配置是什么？" 这对调试和审计至关重要。

### 6.5 确定性替代 vs LLM 裁判 — ⚠️ 需工程改造（P2）

**现状**：Hermes 的某些决策依赖 LLM 判断（如 skill 选择、memory 匹配）。MemStrata 证明确定性规则在结构化场景下更可靠、更快。

**改造方向**：将可结构化的决策（如 skill 匹配、cron 调度）从 LLM 推理迁移到确定性规则，保留 LLM 用于真正需要推理的场景。

### 6.6 量化交易 — ✅ 部分适用（P3）

**适用性**：量化策略参数随时间演化（如 MA 周期、止损阈值），策略回测和实盘需要区分"当前参数"和"历史参数"。MemStrata 的双时间账本可用于策略版本管理。

**限制**：量化场景的参数变化通常有明确的时间戳和版本控制，不需要 embedding 相似度检索，因此 MemStrata 的核心创新（绕过 embedding 的确定性替代）在此场景下价值有限。
