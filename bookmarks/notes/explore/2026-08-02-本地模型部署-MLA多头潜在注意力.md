# MLA 多头潜在注意力（Multi-head Latent Attention）

> 来源：DeepSeek V2/V3 核心架构创新 | 学习日期：2026-08-02 | 类型：auto-explore

## 摘要

MLA 是 DeepSeek V2 引入的注意力机制，通过**低秩压缩 KV Cache** 解决推理阶段的显存带宽瓶颈。核心做法：将每个 token 的 KV 表示从 16384 维压缩到 576 维（压缩率 93.3%+），配合"矩阵吸收"技巧使 Decode 阶段无需还原高维 KV，数据搬运量接近 MQA 但表达能力持平 MHA。

## 关键发现

### 1. 核心原理：压缩-还原-吸收三步走

- **压缩**（下投影）：`h_t → kv_c`，将高维隐状态投影到 512 维潜在空间
- **还原**（上投影，仅训练/Prefill 用）：`kv_c → K, V`，恢复多头表示
- **矩阵吸收**（推理 Decode）：把上投影矩阵 `W_UK` 吸收进 Query，直接对 576 维压缩向量做点积，永不还原

### 2. 为什么能压缩又不损质量

MLA 不是 GQA/MQA 那样"砍 KV 头"（线性牺牲表达能力），而是用低秩分解保留完整的注意力信息。压缩的是数据搬运量，不是表达能力。

### 3. RoPE 解耦设计

RoPE 是位置相关的，无法压缩。MLA 将 K 拆为两部分：
- K_content（512 维，位置无关，可压缩）
- K_position（64 维，独立计算，不压缩）

最终 KV Cache = `[kv_c(512) + k_pe(64)] = 576 维/token`

### 4. 双路径工程实现（vLLM）

- **Prefill**（compute-friendly）：还原完整 KV，走标准 MHA（计算密度高）
- **Decode**（data-movement-friendly）：吸收模式，走等效 MQA（搬运量极小）

### 5. 实测收益

- Red Hat 实测 8xH200：KV cache 容量提升 9.6x，batch size 13 → 128，上下文 54K → 512K
- 1M token KV Cache 从 83.9 GiB 降到 9.62 GiB（节省 88.5%）
- 推理质量持平甚至略优于 MHA

### 6. 演进：V4 的 CSA+HCA

MLA 压缩了"每个 token 的体积"但没有减少"token 对数"（O(n²) 复杂度不变）。DeepSeek V4 用 CSA（压缩稀疏注意力）+ HCA（高度压缩注意力）替代 MLA，实现 1M 上下文下 50x 的 KV Cache 缩减。

## 对工作的价值

- **选型依据**：本地部署 DeepSeek 系列模型时，MLA 意味着同显存下能跑更大 batch 和更长上下文
- **推理引擎选择**：vLLM 的 MLA 实现最成熟（FlashMLA/CUTLASS/Triton 多后端），SGLang 也支持
- **量化叠加**：MLA 可与 FP8 量化叠加，进一步压缩 KV Cache（fp8_ds_mla 格式）
- **架构认知**：理解 MLA 是理解 DeepSeek 全系模型（V2/V3/R1/V3.2）推理优化的前提

## 行动建议

1. 本地部署 DeepSeek 模型优先选 vLLM（≥v0.7.1），开启 `--attention-backend FLASHMLA` 获得最佳 Decode 性能
2. 消费级 GPU 部署时，MLA 的 KV Cache 压缩是跑长上下文的关键，比单纯减小模型更有效
3. 关注 DeepSeek V4 的 CSA/HCA 架构，如果需要 1M+ 上下文，MLA 已不够用
