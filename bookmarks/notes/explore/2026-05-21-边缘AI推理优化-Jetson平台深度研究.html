一、引言

Jetson 平台在 2025-2026 年经历了代际跃迁：从 Orin 系列到 Thor 系列，从 JetPack 6 到 JetPack 7，从 INT8 到 FP4 量化。对于运行在 Jetson Orin Nano Super 上的 Hermes Agent 来说，理解这些变化对本地推理优化至关重要。

本机环境：Jetson Orin Nano Super（67 TOPS，8GB 统一内存），JetPack 6.x。

关键洞察：Thor 系列采用 Blackwell GPU 架构，支持 FP4 精度（4-bit 浮点），这是 Orin 系列不具备的能力。FP4 在保持合理精度的同时将推理吞吐量提升 2-4 倍。

2.2 对 Hermes 当前硬件的意义

Orin Nano Super 虽然是最入门级 Jetson，但 67 TOPS 在优化后可以运行：
- 7B 参数 LLM（INT4 量化，约 5-10 tok/s）
- 1B 参数 LLM（FP16，约 30-50 tok/s）
- Whisper-small（实时语音识别）
- F5-TTS（近实时语音合成）
- YOLO-v8（实时目标检测 30+ FPS）

三、JetPack 7.1 与 TensorRT Edge-LLM

3.1 JetPack 7.1 核心新特性

JetPack 7 是 Jetson 历史上最大的软件更新：

特性 说明 影响
TensorRT Edge-LLM 开源 C++ SDK，专为边缘 LLM 推理设计 革命性——首次有官方边缘 LLM 运行时
CUDA 13.0 统一 Arm 生态系统 更好的 aarch64 支持
Video Codec SDK 统一 跨 GPU 的硬件编解码 API 简化多媒体开发
FP4 量化支持 Blackwell 架构原生支持 Thor 系列独占

3.2 TensorRT Edge-LLM 深度分析

这是 2026 年对边缘 AI 推理最重要的工具：

设计哲学：
- 云端 LLM 栈假设无限内存、宽松延迟、Python 服务、弹性扩缩容
- 边缘设备有严格约束：每毫秒、每瓦特、每次运行都影响物理行为
- TensorRT Edge-LLM 是生产级 LLM 运行时，集成到 C++ 代码库

核心能力：

PyTorch 模型 → ONNX → TensorRT Engine → 边缘部署

关键优化：
├── KV Cache 管理（PagedAttention for Edge）
├── Continuous Batching（边缘版）
├── FP4/FP8/FP16/INT8 多精度
├── 张量并行（单 GPU 内部流水线）
└── 流式生成 + 中断控制

性能基准（Jetson T4000）：

模型 参数量 T4000 吞吐量 T5000 吞吐量
Qwen3-30B-A3B 30B (3B active) 218 tok/s 258 tok/s
Qwen3-32B 32B 68 tok/s 83 tok/s
Mistral-3-14B 14B 100 tok/s 109 tok/s
Nemotron-12B 12B 40 tok/s 61 tok/s
DeepSeek R1 Distill Qwen 32B 32B 64 tok/s 82 tok/s
Kokoro TTS (82M) 82M 1100 tok/s 900 tok/s
GR00T N1.5 (VLA) - 376 tok/s 410 tok/s

关键发现：Qwen3-30B-A3B（MoE 架构，30B 总参数但仅 3B active）在 T4000 上达到 218 tok/s，这比许多云端 API 还快！原因是 MoE 的稀疏激活非常适合边缘推理。

3.3 对 Orin Nano Super 的适用性

方案 适用模型大小 预期性能
llama.cpp (GGUF) 1-7B 5-15 tok/s
ONNX Runtime 1-3B 10-20 tok/s
TensorRT 8.x (传统) 视觉模型 优秀
Ollama 1-7B 5-12 tok/s

四、内存优化策略（适用于所有 Jetson）

4.1 NVIDIA 官方内存优化指南（2026-04-20）

NVIDIA 发布了专门的内存优化博客，覆盖五层优化：

Layer 5: 量化技术（FP4/FP8/INT8/INT4）
Layer 4: 推理框架（TensorRT/ONNX/llama.cpp）
Layer 3: 推理管线（KV Cache/批处理/流水线）
Layer 2: JetPack SDK（CUDA/cuDNN/TensorRT）
Layer 1: BSP（内核/驱动/固件）

4.2 BSP 层优化（立即可用）

禁用图形桌面：

# 节省最多 865 MB
sudo systemctl set-default multi-user.target

禁用不必要的服务：

# 节省约 32 MB
sudo systemctl disable NetworkManager-wait-online.service
sudo systemctl disable systemd-journald.service  # 谨慎使用

Carveout 区域回收（针对 Orin NX/Nano）：

Carveout 何时禁用 回收内存
CARVEOUT_DCE_TSEC 不需要显示时 1 MB
CARVEOUT_DCE 不需要显示时 32 MB
CARVEOUT_DISP_EARLY_BOOT_FB 不需要显示时 34 MB
CARVEOUT_CAMERA_TASKLIST 不使用摄像头时 32 MB
CARVEOUT_RCE 不使用摄像头时 1 MB

总计可回收：约 100 MB（对于 8GB 设备来说是 1.25% 的提升）

4.3 推理层优化

KV Cache 优化：
- MLA（Multi-head Latent Attention）：DeepSeek 的 KV 缓存压缩技术
- PagedAttention：vLLM 的核心，管理 KV Cache 碎片
- 在 8GB 设备上，KV Cache 通常占 30-50% 的可用内存

量化选择矩阵：

精度 压缩比 精度损失 适用场景
FP16 1x 无 基线
INT8 2x 极小 视觉模型推荐
INT4 (AWQ/GPTQ) 4x 小 LLM 推理推荐
FP4 4x 中 仅 Blackwell 架构

4.4 实际优化案例

在 Orin Nano Super (8GB) 上运行 7B LLM：

总内存: 8192 MB
├── 系统占用: ~2000 MB (含 OS + CUDA)
├── 模型权重 (INT4): ~3500 MB (7B * 0.5 bytes)
├── KV Cache: ~1500 MB (2048 context window)
├── 推理缓冲: ~500 MB
└── 剩余: ~692 MB

优化后:
├── 禁用桌面 (-865 MB)
├── 回收 Carveout (-100 MB)
├── Flash Attention (-300 MB KV Cache)
└── 剩余: ~1957 MB → 可运行更大模型或更长上下文

五、核心发现

发现 1：MoE 模型是边缘推理的最佳选择

Qwen3-30B-A3B 在 T4000 上 218 tok/s 的性能证明：MoE 架构的稀疏激活使大模型在边缘可用。30B 参数中仅 3B active，推理时只需处理 10% 的参数。

对 Orin Nano 的启示：选择 MoE 小模型（如 Mixtral-8x7B 的量化版），而非 Dense 小模型。

发现 2：内存优化比计算优化更重要

在边缘设备上，内存是第一瓶颈，计算是第二瓶颈。8GB 设备上运行 7B INT4 模型时，内存几乎用尽，但 GPU 计算利用率可能只有 30-50%。

优化优先级：内存优化 > 量化精度 > 计算优化

发现 3：TensorRT Edge-LLM 是游戏改变者

首次有官方的、生产级的、C++ 原生的 LLM 边缘运行时。这意味着：
- LLM 推理可以嵌入到现有 C++ 机器人代码中
- 不需要 Python 运行时的开销
- 可以与感知/控制栈共享 GPU

发现 4：JetPack 7 不兼容 Orin（至少目前）

JetPack 7.x 主要面向 Thor 系列。Orin 系列停留在 JetPack 6.x。这意味着：
- Orin 用户无法使用 TensorRT Edge-LLM
- 但 BSP 层优化和量化技术仍然适用
- 考虑升级到 Thor 时，T4000 是性价比最高的选择

发现 5：TTS/STT 在边缘已完全可用

Kokoro TTS (82M) 在 T4000 上 1100 tok/s，在 Orin Nano 上预计 50-100 tok/s。这意味着：
- 实时语音合成已在当前硬件上可行
- F5-TTS 的本地部署是正确方向
- 语音 Agent 的边缘部署不再是技术瓶颈

七、知识缺口

  1. TensorRT Edge-LLM 是否会支持 Orin？ NVIDIA 官方未明确表态
  2. FP4 量化的实际精度损失：在代码生成/推理任务上，FP4 vs INT4 的质量对比数据缺乏
  3. Jetson Thor Nano 是否存在？ 如果有，将填补 Orin Nano 到 T4000 之间的空白
  4. 多模型并行推理：同时运行 LLM + TTS + 视觉模型的资源分配策略
  5. 功耗约束下的最优调度：67 TOPS 在 25W 功耗限制下如何最大化推理吞吐
