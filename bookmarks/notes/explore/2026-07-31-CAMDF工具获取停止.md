## 2. 核心问题与研究动机

### 问题定义

LLM Agent 越来越依赖外部工具（搜索引擎、数据库、API 连接器），但 agent harness 面临一个根本性的工具选择困境：

- **获取太少工具** → 任务信息不足
- **获取太多工具** → 增加成本、context 负载、隐私暴露

Router 和 retriever 能按相关性排序候选工具，但**排序本身不能决定应该选几个**。现有方法在异构成本（heterogeneous costs）下的工具获取问题未得到解决。

### 关键洞察

论文标题点明核心论点：**"Scores Are Not Decisions"**（分数不是决策）。上游 ranking 分数只表示工具的相对优先级，不告诉你：

1. 某个工具是否必要
2. 当前选出的 prefix 是否包含所有必需工具
3. 在异构成本下，应该在何处停止

### 与现有方法的差异

- **工具路由**（tool routing）: 在预定义检索策略间路由查询 — 不解决 ranking→acquisition depth 的转换
- **迭代检索停止**: 在每轮检索后学习是否继续 — 不在执行前确定获取深度
- **缺失环节**: 如何在执行前将给定的工具 ranking 转换为成本感知的 acquisition depth

## 3. 方法论（详细）

### 3.1 问题形式化

**设定**: 黑盒获取层包裹在工具使用 agent 的单个 turn 内，仅使用公开信号，不需访问 agent 内部。

- 接收候选工具集 T = {1, ..., m}、上游 ranking、每个工具的成本 c_j > 0
- 沿 ranking 走，选择一个 prefix，交给 agent 执行
- Prefix 在第一个工具执行前固定

**Payoff 函数**:

```
U(A, x) = v(A, G_x) - λ · Σ_{j∈A} c_j
```

- `v(A, G_x)`: 任务值函数（exact sufficiency 时为 0/1 指示器；partial coverage 时为覆盖率）
- `λ`: 成本压力（cost pressure），单位工具成本对应多少单位任务值
- `G_x`: 任务的必需工具集（latent，决策时不可用）

**沿 ranking 的停止序列**: 将工具按分数排序，A_t = 前 t 个工具。策略选择停止深度 t ∈ {0, ..., m}。

**决策间隙 (Decision Gap)**:
```
Δ(S_t) = Q_stop(S_t) - Q_continue(S_t)
       = U(A_t, x) - max_{k>t} U(A_k, x)
```

### 3.2 理论贡献

**Theorem 1（路径前缀后悔分解）**: 实现的后悔等于加权错误之和：
```
Regret(g) = Σ |Δ(S_t)| · 1{g(X_t) ≠ Y_t}
```
每个错误按其 payoff 后果加权。

**Theorem 2（Bayes 对齐）**: 后悔加权目标的 Bayes 最小化器满足：
```
g*(X_t) = sign(E[Δ(S_t) | X_t])
```
按 payoff 间隙加权每个错误，将分类转化为 payoff 优化。这是 cost-sensitive learning 的 Bayes 规则。

**Proposition 1（单步边际规则）**: 继续获取工具 j 当且仅当边际价值/成本 ≥ λ：
```
(V_{t+1} - V_t) / c_j ≥ λ
```

**Proposition 3（关键负面结果）**: 当成本异构时，**仅用分数的规则结构性不足**。这解释了为什么 score-only acquisition 在异构成本下表现差。

### 3.3 CAM-DF 实现

**训练目标**: ℓ₂ 正则化的后悔加权逻辑回归分类器：
```
L(θ) = (1/N) Σ (|Δ_n| + ε) · ℓ_log(y_n*, p_stop(X_n)) + γ·‖θ‖²
```

- 标签 y_t* = 1{Δ(S_t) ≥ 0}（停止 vs 继续）
- 权重 w_t = |Δ(S_t)| + ε（ε=10⁻⁴ 保留零间隙样本）
- 特征 ϕ(X_t)：仅使用分数、成本、prefix 进度、下一个工具信息

**部署**: 按深度递增扫描，在第一个满足 p_stop(X_t) ≥ 0.5 的状态停止。扫描在执行前完成，不泄露工具输出。

### 3.4 CAM-DF-lite

- 10 个理论驱动的边际 score-cost 和 prefix-progress 特征（低维可解释）
- 预测 p_cont(X_t) = Pr(Δ(S_t) < 0 | X_t)，当该概率低于验证调优阈值时停止
- 正系数倾向进一步获取

## 4. 关键实验结果与数据

### 4.1 实验设置

- **5 个工具使用域，1,343 个任务**:
  - τ-bench Retail（n=67）— 主测试台，有审计的必需工具标注
  - MCP-Atlas（n=495）— 更大候选目录
  - WorkBench（n=639）— 大规模 outcome-centric 评估
  - τ²-bench Airline（n=28）— 小域低功耗
  - τ²-bench Telecom（n=114）— 第二对话 agent 评估
- **成本参数**: λ ∈ {0.05, 0.12, 0.20}，成本离散度 d ∈ {0, 1.0, 1.5}（d=0 为均匀）
- **Ranking**: qwen-plus 主 ranking + 4 个额外冻结 scorer（AUC 0.835~0.953）
- **评估**: 30 次 55/20/25% train/val/test 随机划分，2,000 次 paired bootstrap CI

### 4.2 主实验结果（Table 2: τ-bench Retail, λ=0.12）

τ-bench Retail exact payoff（n=67）:

- **Tuned fixed-k**: d=0→0.277, d=1.0→0.219, d=1.5→0.196
- **Score threshold**: 0.376, 0.302, 0.267
- **Score-per-cost threshold**: 0.376, 0.293, 0.273
- **Predict-then-threshold**: 0.352†, 0.281†, 0.244†
- **CAM-DF-lite**: 0.383, 0.305, 0.276
- **CAM-DF（本文）**: **0.400, 0.331, 0.298**（所有 d 下最佳可部署方法）
- Prefix oracle（不可部署上界）: 0.513, 0.450, 0.419

跨域（异构成本 d=1.0）:

- MCP-Atlas（n=495）: CAM-DF-lite 0.226（最佳）
- WorkBench（n=639）: CAM-DF **0.660**（最佳）
- Telecom（n=114）: CAM-DF **-0.001**（最佳）
- Airline（n=28）: Score-per-cost 0.507（CAM-DF 0.483）

### 4.3 端到端实验验证（核心亮点）

在 τ-bench Retail 的真实 agent 执行中：

- **提供完整必需工具集**: 成功率 0.67
- **移除一个必需工具**: 成功率降至 0.24（p < 0.001）— 验证了 sufficiency proxy 的有效性
- **CAM-DF**: 成功率 0.67，仅暴露 4.4/7 个 read 工具（**减少 37%**）
- **CAM-DF-lite**: 成功率 0.64，仅暴露 4.3/7 个工具（减少 39%）
- **全量访问**: 成功率 0.58（暴露全部 7 个工具）

**关键发现**: CAM-DF 用更少的工具反而取得了略高的成功率（0.67 vs 0.58），表明多余工具的 context 噪声会干扰 agent 决策。

### 4.4 消融实验

- **去除边际成本特征**: payoff 降低 0.034~0.051（异构成本下 CI 排除零）
- **Δ 回归 vs 后悔加权分类**: 性能相当（-0.006~+0.025, CI 覆盖零）— 主信号来自目标 payoff 间隙，而非分类 vs 回归选择
- **去除后悔权重**: λ=0.12 降低 0.034~0.041；λ=0.05 降低 0.072~0.079（CI 排除零）
- **CAM-DF-lite vs 完整**: 仅差 0.022~0.027（CI 覆盖零）— 轻量变体保留大部分增益

### 4.5 Robustness（5 个 ranking 源）

- 在 10 个（5 个 scorer × 2 成本制）对比中，CAM-DF 在 **mean 上全部优于** Predict-then-threshold
- 9/10 个 95% CI 排除零
- 增益在 AUC 最低的 scorer 上最大，但非单调变化

### 4.6 LLM 自选择参考（负面基线）

让 qwen-plus 自己选工具集（给定任务、工具、成本、λ）:

- sufficiency 仅 0.39/0.31（d=0/1.0）
- payoff +0.024/-0.121（远低于 CAM-DF 的 0.400/0.331）

**结论**: LLM 不能自我管理工具获取深度 — 即使给了成本信息。

### 4.7 负面结果：残差校正预测

用 double-ML 残差校正修正 sufficiency 预测的成本相关校准问题 → 校正后的 policy 与未校正的统计不可区分（0.366 vs 0.366）。**修复预测 ≠ 修复决策**。

## 5. 创新点分析

### 5.1 核心创新

1. **预执行停止层（pre-execution stopping layer）**: 首次将工具获取形式化为在执行前、沿排序候选的 cost-aware stopping 问题。与迭代检索停止（Park 2025）和输出自适应停止（Kalayci 2025）不同，决策在零工具输出前做出。

2. **后悔加权决策聚焦学习**: 从下游 payoff 直接派生监督——payoff 间隙的符号决定标签、幅度加权每个错误。这是 decision-focused learning 在 cost-aware stopping 领域的首个应用。

3. **分数不足性证明**: Proposition 3 正式证明了异构成本下 score-only 规则的结构性不足——不是经验观察，而是结构性定理。

### 5.2 方法论亮点

- **模块化插件设计**: CAM-DF 是 pre-execution plugin，不修改上游 ranker 或下游 LLM
- **Bayes 对齐保证**: Theorem 2 提供理论保证，不是纯经验方法
- **可解释变体**: CAM-DF-lite 仅用 10 个理论驱动特征，系数可直接解释

## 6. 局限性与未来方向

### 论文自述局限

1. **单轮预执行**: 当前形式化不更新获取决策到观察到工具输出之后。扩展到 output-adaptive 多轮设置是未来方向。

2. **Prefix 约束**: 仅沿 ranking 的 prefix 选择（2^m → m+1），不能跳过中间工具。在 partial credit + 极端异构成本的角落，非 prefix 的 score-per-cost 规则反而更强（-0.042 [-0.049, -0.035]）。

3. **Ranking 质量依赖**: CAM-DF 在弱 ranking 上增益最大，但如果 ranking 完全无效，任何停止策略都无法补救。

### 观察到的额外局限

4. **域规模不均**: Retail 仅 67 个任务，统计功效有限（McNemar p=0.21/0.42 未建立 non-inferiority）

5. **成本模型简化**: 每个工具一个固定成本 c_j，不考虑运行时动态成本（如 token 消耗依输入而变）

6. **Ranking 来自 LLM 评分**: 实验中 ranking 由 qwen-plus 的评分 prompt 生成。生产环境中 ranking 质量可能更差或更不稳定。

## 7. 借鉴点（关联 Hermes Agent / Jetson Orin / 量化交易）

### P0 — Hermes Agent 工具获取成本控制（可直接移植）

**问题对应**: Hermes Agent 当前有 200+ skills，每次任务加载全部 skill 描述会消耗大量 context。论文的 CAM-DF 方法可直接应用于 Hermes 的 skill 选择层。

**具体方案**:
- 在 Hermes Gateway 中增加 pre-execution skill acquisition stopping 层
- 用历史 task→skill 映射数据训练后悔加权分类器
- 特征: skill 的相关度分数 + 调用成本（token 消耗/延迟）+ prefix 进度
- 目标: 将平均 skill 加载数从当前的"全量扫描"降低 37%+

**工作量估算**: 2-3 周（数据收集 + 特征工程 + 模型训练 + Gateway 集成）

**关联现有能力**:
- `adaptive-tool-selection` skill 已有查询感知动态工具选择框架 → CAM-DF 可作为其 stopping 层
- `cron-bulk-management` 可复用模型分配的 cost 概念
- `context-compressor` 已有 context 压缩 → CAM-DF 是更上游的"减少进入 context 的工具数"

### P1 — 边缘部署成本感知（Jetson Orin）

**问题对应**: Jetson Orin 上运行 agent 时，每个工具调用的延迟和功耗成本远高于云端。

**具体方案**:
- 对 Jetson 上的 agent（如 nexa-local-inference），工具成本 c_j 包含 GPU 时间 + 功耗
- λ 参数可动态调整：电池低电量时 λ↑（更激进地停止工具获取）
- CAM-DF-lite 的 10 特征轻量模型适合边缘部署

### P2 — 量化交易策略选择成本控制

**问题对应**: 量化交易系统中有多个策略模块（选股、择时、风控、仓位），不是每个策略在每次决策中都需要运行。

**具体方案**:
- 将策略模块视为"工具"，按历史回测相关性排序
- 用 CAM-DF 决定每次交易决策运行几个策略模块
- 成本 = 计算延迟（对高频交易关键）

### P3 — 后悔加权学习范式（通用方法论借鉴）

**通用价值**: 论文的 regret-weighted objective 范式可推广到任何"决策质量影响不对称"的场景：
- 不是预测准确性最优，而是决策 payoff 最优
- 错误按其后果加权（大 payoff 间隙的错误更严重）
- 适用于 Hermes 的 cron 任务优先级排序、skill 去重决策等

## 总结一句话

CAM-DF 证明了"分数不是决策"——通过后悔加权决策聚焦学习，在执行前确定工具获取深度，用 37% 更少的工具维持了相当的甚至更高的任务成功率，为 Hermes Agent 的工具选择优化提供了可直接移植的模块化方案。
