〇、定锚：我的现状与目标

我（Hermes/Jetson 生态）的技能层现状：Skills 已是三原语架构支柱之一，且经历了 SPyCE（技能-策略协同）、MDSKILL（技能蒸馏内化）、Tool-Retrieval（检索完整性）、SkillTTA（测试时进化）等一系列精读吸收，技能系统的"创建-检索-进化"三环都有对照物。但两环始终薄弱：①同一技能在不同用户/不同 profile/不同 cron 语境下的个性化差异，目前靠"复制一份 skill 改参数"的粗粒度方式解决，版本漂移严重；②长任务执行中的技能在线选择靠会话开头一次性加载 + agent 自行判断，没有按执行进度动态换技能的机制。核心痛点：技能池从 700+ skill 持续膨胀后，"选对技能"比"写好技能"更难。期望时间尺度：两周内判断 Adapter 机制是否值得在 Hermes 落地原型。

一、内容整理

1.1 核心问题：通用技能与用户个性的错位〔问题，2026〕

  • 动机例子：同一"英文合同翻译成中文 PDF"任务，用户 A 只要翻译内容，用户 B 要求保留原分页、版式、批注。两者复用同一批技能（文档提取/翻译/PDF生成），但差异在提取字段、工具参数、校验要求上〔案例〕
  • 两个子问题的正交分解：个性化修改（把用户偏好表达为对共享流程的局部增量）+ 在线路由（长任务中按当前子目标/执行状态/环境反馈，从膨胀的技能池里选"当前适用"的技能并预加载）
  • 关键洞察：长程任务中子目标、可用输入、环境状态随时变化，技能选择不是一次性决策而是贯穿全程的持续决策

1.2 方法：Adapter 四元组 + 路由 Agent + 在线技能库〔方法，2026〕

  • 通用技能表示五元组：s_i = ⟨n_i, d_i, c_i, I_i, O_i⟩（名称/描述/通用流程/输入约束/输出约束），技能按主题组织并保留成功轨迹支撑的有向组合关系（后用于候选扩展）
  • Adapter 定义（本论文核心构件）：a_{u,i,k} = ⟨i, p, Δ, κ⟩——关联技能 ID、适用条件 p、局部修改 Δ、使用记录与反馈证据 κ。执行时 s̃ = Apply(s_i, Δ) 把 delta 叠加到通用流程上。Δ 可涉及：工具选择、参数设置、步骤增删、输出格式、校验要求
  • 修改策略 π_mod：基于通用技能 + 个性化上下文 P_u + 相关历史轨迹 + 现有 Adapter 集，决策新增/更新/删除 Adapter；从反复出现的偏差中蒸馏可复用修改，用户需求变化时按反馈更新
  • 在线路由：主 LLM 把任务分解为 DAG；路由 agent 处理就绪节点 + 为后续节点预加载候选；检索（BGE-M3 语义匹配选 3 主题 20 技能 → 沿组合关系扩展至 30 上限）→ 按输入/工具状态/适用条件过滤构造"技能-Adapter 对"（含 ∅=直接用通用版）→ 路由策略选出至多 8 个的有序序列
  • 任务级在线技能库 L_{u,q,t}：增量维护，条目存技能引用+选中 Adapter+适用节点+组合关系+使用指引，主 LLM 按需读取；实际输入确定后重新校验预加载候选的适用性
  • 双策略 GRPO 训练：修改策略用"技能调整前后的任务表现增益"作奖励，路由策略用"执行结果+技能选择质量"作奖励。超参：group size 8，lr 1e-6，clip 0.2，KL 0.01，batch 64，每阶段 100 步更新，执行器冻结

1.3 主实验结果〔数据，2026〕

  • 三基准：ALFWorld（420任务，交互预算50步）、WebShop（1500任务，15步）、SkillsBench（210任务，30步）。执行器 Qwen3-8B（前两个）/ GPT-5-mini（SkillsBench）；技能抽取用 GPT-5.2-Codex 从 AgentTraj-L 聚类轨迹提取；3 随机种子取均值
  • 对比 SkillRL（此前最强基线）：成功率 87.14→95.48（ALFWorld +8.34pp）、72.73→81.53（WebShop +8.80pp）、21.43→38.57（SkillsBench +17.14pp），平均 +11.43pp，且三个基准执行时间全部更短（如 ALFWorld 70.6→61.9s）
  • 有趣的反例数据：Backbone(all skills) 把整池技能塞给主 LLM，ALFWorld 成功率只有 27.62%，还不如无技能 ReAct 的 52.86%——技能池无选择地全量注入是净伤害
  • SkillsBench 上优势最大（+17.14pp）：该基准专测"识别/选择/使用外部技能"能力，说明 Skill Adapter 的增益主要来自选对技能而非技能本身

1.4 消融与扩展性〔数据，2026〕

  • Table 3 逐层叠加（三基准平均成功率）：
  • 仅轨迹池 29.28% → +通用技能池 41.86%（+12.58pp）
  • +组合关系与使用指引 48.35%（+6.49pp）
  • +DAG 预加载 52.75%（+4.40pp）
  • +RL 训练修改策略 60.16%（+7.41pp）
  • +RL 训练路由策略 65.28%（+5.12pp）
  • 完整 Skill Adapter 71.86%（+6.58pp）
  • 解读：最大的单一杠杆是技能池本身（+12.58pp），其次是两个 RL 策略（合计+19.11pp）；路由组织结构（组合关系+预加载）合计贡献 10.89pp。没有一个组件是可有可无的
  • Figure 3 技能池扩展：50→1000 技能时全方法成功率都降，Skill Adapter 95.5%→80.4%（降15.1pp），SkillRL 87.2%→60.3%（降26.9pp）；1000 技能时 Skill Adapter 仍领先约 20pp——在线路由是技能池规模化的必要条件
  • 训练曲线：100 步 GRPO 内，修改策略 59.5%→~87%，路由策略 72%→~95%，两策略均收敛

二、查询拓展

2.1 与既有技能路由工作的差异定位〔补充〕

论文 Related Work 引用的技能选择系谱：SkillDAG（自进化类型化技能图，2606.03056）、Graph of Skills（依赖感知结构检索，2604.05333）、SkillRouter（检索+重排管线）、SkillNet（技能创建/评估/连接）、SkillRL（RL 优化技能使用）。Skill Adapter 的增量贡献 = 首次把"个性化修改"与"在线路由"联合建模，且消融证明两者收益可叠加（65.28% 与 60.16% 互不为子集）。〔补充〕

2.2 对照本库已有笔记：Skill Adaptation（10-28 精读）〔对照〕

10-28 精读的 Skill Adaptation 处理的是技能跨环境/跨工具变更的适配（环境变了技能怎么办），本文处理的是用户偏好差异的适配（环境不变，人不同）。两者正交：前者是"技能对齐环境"，后者是"技能对齐人"。理想系统两层都需要。〔对照〕

2.3 验证型搜索：个性化 delta 方案的已知弱点〔验证〕

需注意论文未开源（comments 无代码链接），全部数字来自自报实验；ALFWorld/WebShop 是 2021/2022 年的模拟环境，个性化条件取自任务指令中显式声明的偏好——真实用户偏好往往隐式、延迟出现、相互冲突，论文设定偏理想化。SkillsBench 38.57% 的绝对值仍不高，说明技能选择在真实复杂度下远未解决。⚠️ 待社区复现验证。

2.4 时效型：与 2026 技能系统主线的关系〔补充〕

本库 9-12 月已精读的技能线：SPyCE（技能-策略协同进化）、MDSKILL（技能蒸馏进模型参数）、SkillTTA（测试时技能进化）、MemSkill（记忆技能自进化）、Tool-Retrieval（多工具检索完整性）。Skill Adapter 填补的是"同一技能的多版本个性化"这一空白维度——此前所有工作都默认技能池内技能是单版本扁平的。〔补充〕

三、归纳总结

3.1 框架图：两策略一库

用户 u ──偏好/反馈──┐
                    ▼
历史轨迹池 ──蒸馏──> 通用技能池 G (五元组+组合关系)
                         │
     ┌─── π_mod (GRPO) ──┤─── π_route (GRPO) ───┐
     ▼                   │                      ▼
  Adapter 集 A_u         │            技能-Adapter 对候选 C
  ⟨i,p,Δ,κ⟩              │            (检索→过滤→选序列)
     │                   │                      │
     └───── Apply(s,Δ) ──┴──> 任务级在线技能库 L ──> 主 LLM 按需读
                            (DAG 节点预加载 + 输入确定后重校验)

3.2 三维护筛

  • 优点：①Adapter 把个性化表达为可复用的局部 delta 而非整技能复制，一处通用流程升级所有用户受益，解决版本漂移；②消融链条完整（每个组件都有独立贡献数字），1000 技能扩展实验直面规模化；③"技能-Adapter 对"候选里保留 ∅（通用版），不强制个性化——偏好证据不足时退回默认，这是工程上很干净的守卫
  • 缺点：①纯模拟环境+显式偏好设定，真实世界隐式偏好/冲突偏好的处理未验证；②两策略各需 GRPO 训练，100 步更新 ×2 的训练成本对个人部署不轻；③"用户"概念单数化——多用户共享一个 Adapter 池的隔离与冲突（两个用户对同一技能的 Δ 矛盾）未讨论；④未开源，复现门槛高
  • 借鉴点：①Adapter 四元组结构（⟨关联技能, 适用条件, 局部修改, 使用证据⟩）可直接映射为 Hermes skill 的用户层 override 机制——把"复制整个 skill 改参数"改为"挂 delta"，这是 P0；②DAG 预加载+输入确定后重校验的在线库模式，对应 Hermes 长任务（多 cron 编排）中"按进度换技能"的需求；③候选集含 ∅ 的守卫设计值得抄

3.3 核心对比：技能池注入策略

  • 全量注入（all skills）：27.62%——负收益，上下文污染
  • 静态检索（BM25）：61.67%——有效但粗糙
  • LLM 选择器：65.00%——贵且不稳定
  • 结构检索（Graph of Skills）：70.71%
  • RL 优化使用（SkillRL）：87.14%
  • 个性化+在线路由（Skill Adapter）：95.48%
  • 规律：技能注入的收益 = f(选择精度)，选择机制每升一级收益大于技能库本身扩容

四、趋势判断

4.1 技能系统研究重心从"建技能"转向"选技能"〔上升〕

依据：本库 9-12 月精读的 8 篇技能线论文中，Tool-Retrieval（11-03）、TRACER（10-17）、技能粒度自适应路由（10-24）到本文，选路问题连续出现且数字不断提升；同时 all-skills 注入负收益（27.62% vs 52.86%）在本文再次实证。对我的含义：Hermes 技能层优化的最大杠杆在选择侧而非创建侧——机会。

4.2 个性化将成为 Agent 技能层的标配维度〔上升〕

依据：MDSKILL（11-05）做"技能→参数"内化，本文做"技能×用户"外挂 delta，方向相反但都指向"技能不再千人一面"；论文引用的 SkillNet/SkillDAG 谱系均在 2026 年出现。对我的含义：多 profile/多机（jbot/ubot/abot）场景下，delta 化个性化是减少 skill 维护成本的机会，但需先解决多用户 Δ 冲突。

4.3 技能池千级规模是分水岭，检索结构决定衰减斜率〔分化〕

依据：Figure 3 显示 50→1000 技能时，无结构方法的性能崩塌速度是结构化路由的近 2 倍（SkillRL -26.9pp vs Skill Adapter -15.1pp）。Hermes 当前 700+ skill 已在分水岭附近。对我的含义：技能池再膨胀 30%，"会话开头扫一遍 skill 列表"的模式将不可用——风险，需提前布防。

4.4 GRPO 训小策略模型（Qwen3-8B 级）做路由决策成为可行范式〔上升〕

依据：本文路由/修改策略都是 8B 级模型 + 100 步 GRPO 就收敛（72%→95%），与此前精读的 ReGRPO、SkillRL 一致；小策略模型专门化训练的成本收益比已在多篇验证。对我的含义：Jetson 本地 8B 级模型做技能路由的预训练路径存在——但当前优先级低于规则化方案。

五、关联分析

5.1 与「Agent技能适配-Skill-Adaptation」（2026-10-28 笔记）的关联

正交互补关系：Skill Adaptation 解决环境漂移下的技能适配，Skill Adapter 解决用户差异下的技能适配。两者共用"局部修改而非整体重写"哲学。若 Hermes 落地，理想形态是双层：环境适配层（工具变更自动迁移）+ 用户适配层（偏好 delta）。

5.2 与「技能记忆多视角蒸馏内化 MDSKILL」（2026-11-05 笔记）的关联

MDSKILL 把技能内化进模型参数（检索消融证明动态检索比仅相关性 +20.4 分），Skill Adapter 把个性化外挂为结构化 delta。内化减少运行时检索成本，外挂保留可审计可回滚。两者是"热路径内化 + 冷路径外挂"的分层关系，与 memory 系统的分层设计同构。

5.3 与「多工具检索完整性」（2026-11-03 笔记）的关联

Tool-Retrieval 用 completeness@k 度量检索完整性、指出零样本单次调用 10% 天花板；Skill Adapter 的回应是训练专用路由策略（GRPO）+ DAG 预加载（利用任务结构先验）。两篇合读的结论：检索完整性靠一次性调用不够，要么标注数据训集合级检索器（前者），要么利用执行结构+RL（后者）。

5.4 与 Hermes 三原语架构（Agents/Skills/Hooks）的关联

Adapter 概念在 Hermes 中的自然挂点是 skill 层：SKILL.md 保持通用（含 provenance 字段），用户 delta 存 profile 目录；路由 agent 对应 Kanban 编排器/delegate 分诊。DAG 预加载对应 cron 链式任务的技能预取——技术上与 hermes-realtime-callbacks 的里程碑推送可复用同一进度感知机制。

六、金句摘录

「General-purpose skills describe shared execution procedures, while specific tool choices, operating practices, and output requirements vary across users.」——通用技能描述共享流程，而工具选择、操作习惯与输出要求因人而异——这句话就是技能个性化的存在性证明。

「Agents must select currently applicable skills from an expanding skill pool」——"currently applicable" 四个字点破技能选择是时变问题，不是加载时一次性问题。

七、行动启示与回访

我的结论：保留 Adapter 四元组与 ∅ 守卫设计；放弃 GRPO 双策略训练（成本高、环境理想化、无开源实现）；改造为规则化 delta 机制先落地。

  • 行动1：给 Hermes skill 层设计用户 delta 原型——3 个高频技能（如 note-save-protocol / 模型切换 / cron 格式）各建一份"用户 override 片段"（YAML，含适用条件+局部参数替换），先在 jbot 单机验证"通用 skill + delta 叠加"的加载链 | 时间：一周内 | 触发条件：下次会话处理 skill 加载相关任务时 | 验收标准：同一 skill 通用版不动，delta 叠加后行为变化，且 delta 可独立删除回滚
  • 行动2：技能池规模预警——在下次 skill-review 巡检中统计当前激活 skill 数与"会话开头 skill 列表注入"的 token 成本，若列表 token > 8k 或 skill 数 > 800，触发检索结构化改造评估 | 回访：下次 skill-review cron
  • 回访日期：2026-11-29（两周）
  • 待验证假设/证伪条件：假设"规则化 delta 可获得 GRPO 个性化的大部分收益"——若 delta 叠加后在真实任务中的采纳率（用户实际触发次数/可用次数）< 30%，或维护 delta 的成本超过直接改 skill，则此路线证伪，回退为整技能复制模式并接受版本漂移

八、拓展应用推荐

  • 多机分工场景：jbot/ubot/abot 三机共享 skill 主干，各机 delta 化自身特化参数（如 ubot 偏论文、jbot 偏运维）——场景→用法：同 skill 不同 cron prompt 语境的参数微调
  • cron prompt 管理：cron-prompt-full-replace 铁律（全量覆盖）可与 delta 机制结合——cron prompt 拆"稳定主干+可变片段"，减少误覆盖事故
  • 量化交易系统：同一套选股 skill 面对不同风险偏好用户（半仓制 vs 其他）挂不同参数 delta——场景→用法：策略个性化不复制代码
  • DUCK 机器人项目：同一动作 skill（如 duck-stand-squat-v3）面对不同电池电压/负载状态挂不同安全阈值 delta——κ 字段（使用记录+反馈证据）天然对应真机台账

九、指南分析

  • 写作方法论：论文的消融设计是教科书级——六层递进叠加，每层独立可归因（29.28→71.86 的每一步都有 pp 数），且 Figure 3 的规模化实验把"当前方法在什么条件下失效"（技能池>1000）诚实画出。这种"组件贡献可分解 + 失效边界可视化"的双报告结构值得所有系统论文笔记借鉴
  • 实验设计判据：all-skills 负收益基线（27.62%）是个高价值对照——它证明"有技能"不等于"会用技能"。评估任何技能注入系统时应强制包含此基线，避免把"注入了"误当"用上了"
  • 可复用判据：候选集含 ∅（不选 Adapter）的设计是所有个性化系统的通用守卫——个性化证据不足时必须能退回默认行为，否则个性化变成噪声放大器
