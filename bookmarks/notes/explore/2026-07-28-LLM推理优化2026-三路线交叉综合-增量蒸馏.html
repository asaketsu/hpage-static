一、核心问题：为什么 LLM 推理优化在 2026 年仍是未解难题？

LLM 推理的每个请求都经过两个截然不同的阶段，它们对硬件的需求完全相反：

  • Prefill（预填充）：compute-bound，Tensor Core 满载
  • Decode（解码）：memory-bound，Tensor Core 空闲等待 DRAM

这个结构性矛盾催生了 2026 年三条并行技术路线，但每条路线单独优化时都会遭遇相同的天花板：多轮 Agent 对话的增量负载。跨笔记综合揭示了一个此前被忽略的核心洞察——

三条路线的真正价值不在各自独立，而在于正交可叠加性（orthogonal composability）。当前最大的研究空白不是"更好的单点优化"，而是"如何让它们在不互相干扰的前提下组合。"

二、三条技术路线的维度映射

路线 A：架构分离（DPD）

核心思想：Prefill 和 Decode 放到不同 GPU 池，各取所需。

用户请求 → Router
          ├→ Prefill Node (H100/B200) → 生成 KV Cache
          │                    ↓ RDMA 传输
          └→ Decode Node (H200) → 接收 KV → 生成 tokens

关键演进（2026）：
- NIXL（vLLM）：RDMA + GDS 多连接器
- AMD MORI-IO（2026-04）：单节点内分离，不需多节点 RDMA 集群 → 降门槛
- MoonCake：KV-Cache 为中心的分布式内存池
- AMPD（arXiv 2602.14516）：解决了多轮推理的增量 Prefill 调度问题

已采用：NVIDIA Dynamo、SGLang、vLLM、LMCache、AWS SageMaker HyperPod — 几乎全部主流生产框架。

路线 B：KV Cache 压缩与量化

三个子方向，覆盖不同压缩维度：

方法 压缩维度 压缩率 精度保证 需重训练
TurboQuant (ICLR2026) 精度维度（向量量化） 6×（3bit/value） 近无损，104K Needle 100% 否
FreqDepthKV 深度维度（层间共享） 3.9× 经验无损 否
VeriCache 精度维度（验证式） 4× 数学精确无损 否

关键洞察（跨笔记交叉）：FreqDepthKV 发现层级冗余不是均匀分布的——某些层在平均值上看似冗余但包含高频残差信息，对 needle 检索、代码依赖追踪至关重要。均匀深度压缩会删除这些残差。而 TurboQuant 的 PolarQuant + QJL 两阶段设计恰好解决了精度维度的类似问题——Stage 1 标量量化 + Stage 2 残差校正，先粗后精的残差哲学在深度维度和精度维度上完全同构。

路线 C：推测解码（Speculative Decoding）

2026 范式转变：从单请求加速 → 高并发服务场景优化。

方法 核心创新 加速效果 场景
D-cut 跨请求联合剪枝验证预算 Dense 1.65× / MoE 3.0× 高并发 batch
DSpark (DeepSeek-V4 生产) 半自回归 + 置信度调度 生产级部署 真实用户流量

关键发现（跨笔记交叉）：推测解码在高并发下的性能退化与 DPD 的增量 Prefill 调度问题有相同的根因——两者都在处理"多请求竞争有限 GPU 算力"的调度问题。D-cut 的跨请求剪枝逻辑可以直接迁移到 DPD 的 Router 设计中：不是每个 Decode 请求独立分配验证预算，而是跨 batch 联合优化。

三、核心交叉发现（增量洞察，单篇笔记看不到的）

发现 1：三路线的正交叠加 Pareto 前沿

         压缩空间（KV Cache 量化/压缩）
              ↕
    DPD（架构分离） ←→ 推测解码（计算加速）
              ↕
         调度空间（跨请求联合优化）
  • DPD + KV 压缩：Prefill 节点生成压缩 KV → 传输量减少 4-6× → RDMA 带宽不再是瓶颈。MoonCake 的分布式内存池直接受益
  • KV 压缩 + 推测解码：VeriCache 已证明压缩 KV 做 draft + 全量 KV 验证可行。与 DSpark 的置信度调度叠加时，draft 在压缩 KV 上跑更快，验证在全量 KV 上保证无损
  • DPD + 推测解码：D-cut 的跨请求剪枝可嵌入 DPD Router 的调度决策——Decode 节点接收的 draft 验证预算应跨请求分配

叠加公式：总加速 ≈ DPD 延迟收益 × KV 压缩带宽收益 × SD 计算收益。三者近似正交，不是简单乘法但有叠加空间。当前无任何论文同时研究三者组合——这是最大的研究空白。

发现 2："残差哲学"跨维度同构

维度 粗粒度操作 残差校正 目标
精度（TurboQuant） PolarQuant 标量量化 QJL 1-bit 符号校正 无偏内积估计
深度（FreqDepthKV） 低频深度分量共享 高频残差保留 检索关键证据
计算（VeriCache） 压缩 KV 快速 draft 全量 KV 验证 精确无损输出

三种方法都遵循"先做粗粒度操作获得主要收益，再用低开销残差机制保证质量"的模式。这暗示了一种统一的 KV Cache 处理范式——未来可能存在一个框架同时处理精度、深度、计算三个维度的残差。

发现 3：Agent 多轮对话是所有路线的共同盲点

  • DPD 的 AMPD 论文明确指出：多轮推理中的增量 Prefill 调度才是真正难题
  • 推测解码的 DSpark 用置信度调度缓解了多请求竞争，但没有建模多轮对话的 KV Cache 增长
  • KV 压缩方法都在单轮 prefill 上评估，多轮对话中压缩 KV 的误差累积未被系统性研究

Hermes 映射：Hermes Agent 的长对话场景（飞书群聊 + 工具调用 + 多轮 reasoning）正是这三条路线的"最坏情况"。当前 Jetson Orin 单机部署完全无法受益于 DPD（需要多节点 RDMA），但 KV 压缩 + 推测解码是直接可用的优化路径。

发现 4：边缘部署的特殊约束矩阵

约束 云端部署 Jetson 边缘部署
DPD 可用性 ✅ 多节点 RDMA ❌ 单节点，MORI-IO 降级版
KV 压缩收益 带宽省钱 显存救命（70B KV Cache > 参数显存）
推测解码收益 高并发调度 单请求加速（Draft-Free SWIFT 更适合）
量化方案 NVFP4 Blackwell GGUF INT4/INT8（Ampere 架构）

边缘场景下，KV 压缩 > 推测解码 > DPD 的优先级排序与云端完全不同。TurboQuant 的 3bit/value 在 Jetson 8GB 显存约束下可能使大模型从"无法运行"变为"勉强可用"。

五、知识缺口与待深入

  1. 三路线叠加的实验验证：无任何论文同时评估 DPD + KV压缩 + SD 组合。这是论文级研究空白
  2. 多轮对话的 KV 压缩误差累积：所有压缩方法在单轮 prefill 上评估，多轮场景下误差如何传播？
  3. 边缘 DPD 可行性：MORI-IO 单节点模式在 Jetson 上是否可用？需要实测
  4. TurboQuant 在 Ampere 架构上的适配：PolarQuant 的随机正交矩阵乘法在 Jetson Orin 的 Tensor Core 上是否高效？
  5. VeriCache 的 CPU swap 在边缘：Jetson 统一内存架构下，"CPU swap 到 GPU"的语义是否成立？（Jetson CPU/GPU 共享物理内存）

六、一页速查

LLM 推理优化 2026 = 架构分离（DPD）× KV压缩（TurboQuant/FreqDepthKV/VeriCache）× 推测解码（D-cut/DSpark）

三路线正交可叠加，但无论文研究组合。共同盲点：Agent 多轮对话增量负载。

边缘部署优先级：KV压缩 > 推测解码 > DPD（与云端排序相反）。

"残差哲学"跨维度同构：精度/深度/计算三维度都遵循"粗粒度操作 + 低开销残差校正"模式。
