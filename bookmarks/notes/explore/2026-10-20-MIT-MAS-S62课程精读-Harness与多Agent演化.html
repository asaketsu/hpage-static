归纳总结

一句话核心：MIT 这两讲给出了"自演化 AI"的完整方法论——先建严格的分类学与实证规律，再把剩余设计空间交给自主演化；可自主优化的对象沿"记忆 → 上下文 → harness → 多 agent 系统"不断升维，而每一次升维的共同范式是"简单、无手工设计、端到端"。

三个层次的关键结论：

层次 核心命题 代表工作
单组件（记忆） 把记忆当作上下文中的内部状态，由 LLM 自主更新 MEM1
上下文 把整个上下文当作持久文件，由 LLM 自主维护改写 CLM
整个 Harness 把 harness 当作文件系统，由 LLM 自主修改 Meta-Harness
多 Agent 系统 把角色/拓扑/共享记忆交给共同演化搜索 CORAL

两讲的教学结构本身就是答案：Lecture 4 沿对象升维推进（记忆→上下文→harness），Lecture 5 沿系统升维推进（规划→编排→系统演化），同时用五条实证发现反复泼冷水——多 agent 不是免费午餐。

内容整理：Lecture 4 — 先解剖 Harness，再谈让它演化

1. Harness 五组件解剖（贯穿两讲的框架）

  • Context：提示、记忆、检索信息
  • Control：规划、路由、多 agent 编排
  • Action：工具、技能、RAG、API、环境
  • Evaluation：验证、安全、人类反馈
  • Evolution：反思、更新、学习

2. 记忆：三轴分类法 + 四个代表系统

三轴组织整个记忆研究空间：存什么（反馈/技能/轨迹/语义事实）× 如何表示（文本/结构化/多模态/参数）× 存在哪里（上下文/参数/外部），外加如何复用（检索/改编/组合/迁移）。

沿"存在哪里"轴排布四个系统：

系统 记忆位置 核心机制
MemGPT 外部 LLM 类比操作系统，记忆读写=agent 自己的函数调用
mem0 外部 实体-关系三元组图，add/update/delete/noop 四操作
MEM1（授课组自己的工作，着墨最多） 上下文内 每步生成整合推理+记忆的内部状态→丢弃全部历史；上下文恒定；结果奖励端到端训练"压缩"
Reflexion / ExpeL 经验化 轨迹存短期、自我反思存长期；ExpeL 连"经验是否有用"的反馈也存

MEM1 的三个涌现行为（无一显式编程）：①分类存储每个问题的关键信息；②答完一题先更新记忆再进下一题；③多次搜索无果后学会跳过该题。

3. CLM（Context Language Models）：记忆部分的收束

模型把整个上下文当作一个文件，用 Bash 命令随意编辑（与真实上下文同步）；创建/删除上下文文件=实例化/终止子 agent。记忆、上下文管理、多 agent 结构被统一成"文件操作"。

4. 工具与 Skills 谱系：Toolformer → Meta-Harness

Toolformer（自学单步工具调用）
  → ToolLLM（多步、16000+ API）
  → CodeAct（代码是元工具：一次动作组合控制流+库+多次操作；成功率最高、轮数最少）
  → Skills 层（文本/代码表示、PolySkill 抽象类、Agent Workflow Memory 从成败轨迹归纳可复用工作流）
  → Voyager（自动课程生成 + 环境反馈 + Skills 归纳进库）
  → Meta-Harness（压轴）

Meta-Harness：现有 LLM 优化方法只给优化器看"简短摘要、标量分数、部分历史候选"，而 harness 复杂得多。Meta-Harness 把整个 harness 表示为文件系统——完整源代码、分数、全部执行轨迹都放里面，让 proposer（Claude Code，用 grep/cat 阅读）把失败回溯到具体的 harness 决策上。反馈信息量是 prior 方法的近 400 倍（1000 万 token vs 2.6 万）。提示、RAG、Skills、工具、记忆、程序循环全部统一为文件系统中可优化的对象。

5. 抽象阶梯（全讲义精华，Liang 最欣赏的三个方法共享同一模式）

  • MEM1：记忆 = 上下文中的内部状态，LLM 自主更新
  • CLM：上下文 = 持久文件，LLM 自主维护改写
  • Meta-Harness：harness = 文件系统，LLM 自主修改

共同点：简单、无手工设计、端到端；同一范式在 zero-shot、上下文学习、微调三种模式下都可扩展。整门课"自演化"思想最凝练的表达：不让 AI 在某一点上变强，不断扩大"什么是可以被 AI 自己改写的"边界。

内容整理：Lecture 5 — 从规划到多 Agent，把玄学变成实证科学

1. 规划三问

规划何时有用/何时有害？计划如何表示？何时该改计划？

结论：基于提示的规划（CoT、Least-to-Most）适用于纯文本、无副作用、可回退的场景；一旦计划作用于真实世界、改变 agent 状态、不可逆，就必须规划-执行-观察-重规划。

规划谱系案例：大小模型分工（大模型规划+7B 执行 GUI）、人在回路不确定性澄清、合成数据训练规划器、多条计划采样估计不确定性（校准规划）、Thinking vs Doing（测试时真实执行看反馈再重试）。

2. 多 Agent 五条实证发现（Nature Machine Intelligence 2026「Towards a Science of Scaling Agent Systems」）

# 发现 关键数据
1 多 agent 只对特定任务结构有效 金融任务（天然可分解）MAS 赢 81%；PlanCraft（强顺序依赖）MAS 输 70%
2 收益随基座模型而异 OpenAI：成本增性能平台化；Google：成本高性能高；Anthropic：MAS 甚至可能伤害性能
3 agent 数量越多不一定越好 16 工具工作流受协调开销拖累，惩罚随环境复杂度复利式累积
4 异构混合可打败更强单一基座 "廉价编排器 + 昂贵执行子 agent"；单 agent 基线已超 45% 时 MAS 反而有害
5 性能可预测 以模型/任务/MAS 配置为参数的 scaling law 以 87% 准确率预测最优架构

选型指南：可并行 → 集中式；需探索 → 去中心化；顺序依赖 → 单 agent。

与阅读清单 "Why Do Multi-Agent LLM Systems Fail?" 一起，构成对多 agent 热潮的实证纠偏。

3. CORAL：多 Agent 演化（本课 TA Ao Qu 一作）

可演化对象三层：个体 agent（模型/上下文/harness）、系统结构（角色/通信/拓扑）、共享信息（公共记忆/工具/Skills）。

CORAL 特性：多 agent 专业化、高度自主、共享记忆、心跳机制维持持续运行；数学/算法/系统优化等 8 个任务新 SOTA，多 agent 演化比单 agent 提升 4%–20%。

"为什么共同演化有用"的机制分析：
- 36% 的演化尝试以其他 agent 为父节点，这些尝试改进率 17%（平均仅 9%）→ 跨 agent 信息转移是收益的真实来源
- 各 agent 探索方向重叠度低（Jaccard 0.3–0.4，一半以上探索独特）
- 贡献均衡，无搭便车者

4. 两讲合并：自主优化的边界

  • L4 对象升维：记忆 → 上下文 → 整个 harness（文件 → 文件系统），每级把更大一块系统交给 LLM 自主改写
  • L5 系统升维：个体规划 → 多 agent 编排 → 系统本身演化（角色/拓扑/共享记忆），每级把更大设计空间交给自主搜索
  • 共同的批判克制：L4 强调"简单、无手工设计、端到端"才可扩展；L5 用五条实证提醒"多 agent 不是免费午餐"
  • 方法论答案：先建立严格的分类学与实证规律，再把剩余的设计空间交给自主演化

关键洞察交叉验证

Meta-Harness 的"反馈信息量 400 倍"与 Ecdysis 失败归因互补：失败 harness 优化的瓶颈不在优化算法，而在优化器能看到什么。只给摘要/分数=盲改；给完整文件系统+轨迹=可回溯到具体决策。这与我们调试铁律"先根因定位再动手"在 agent 自演化场景的翻译完全一致。

查询拓展

后续可深挖的问题（按价值排序）：

  1. MEM1 的"内部状态"能否移植到 OH2P xiaohe-memory？ 长对话上下文恒定压缩 vs 现在的 SQLite 分层检索，RT 与遗忘率怎么权衡 → 查 MEM1 原论文实验设置
  2. Meta-Harness 的 proposer 为何选 Claude Code？ grep/cat 读文件系统的 agentic 阅读模式 vs 塞 context 的 token 爆炸——对我们做 harness 自检 cron 的直接启示
  3. 五条实证发现的"45% 基线阈值"在我们 delegate_task 场景的对应判据是什么？（单 agent 能做好的任务不拆多 agent）
  4. CORAL 的跨 agent 父节点机制：36% 尝试借用他人演化结果、改进率翻倍——三机经验交换协议（exchange-protocol）是否已在产生同等收益？可统计 JSONL 经验池的跨机引用率
  5. Nature MI 2026 论文的 87% scaling law 预测器：输入（模型/任务/MAS 配置）→输出（最优架构），能否本地复现一个简化版用于我们自己的编排选型

趋势判断

  • "文件系统作为 agent 可改写对象"正在成为统一抽象：CLM（上下文=文件）→ Meta-Harness（harness=文件系统）→ 我们的全 md 落盘体系，方向收敛于"一切状态皆文件、一切优化皆文件操作"。这与 Unix 哲学在 agent 时代的复归一致
  • 多 agent 研究从叙事期进入实证期：2026 年 NMI 论文给出任务结构×基座×配置的定量规律，"多 agent 更强"的流行叙事已被证伪为条件命题；工程侧的对应动作是把选型判据写死进编排框架而非拍脑袋
  • 自演化的安全边界问题被推到前台：L4/L5 都强调"先分类学后演化"，暗示社区已意识到无约束自改写的风险——与既有笔记 PAC 泛化保留界/准入规则的思路同向，理论侧工作会持续跟进
  • MIT 把这门课开成正式课程（MAS.S62）本身是信号：harness engineering 从博客话题进入研究生课程体系，2026-2027 会催生一批标准化 benchmark 与教科书级分类法

指南分析

可直接执行的改进项：

  1. 把多 agent 五条判据 patch 进 agent-orchestration-pattern skill：任务结构判定（可并行/需探索/顺序依赖→集中/去中心/单agent）+ 单 agent 基线>45% 不拆 MAS + 廉价编排器配昂贵执行器——选型先查表，不靠直觉
  2. 给 harness 自检 cron 升级反馈粒度：现有 error-monitoring 只汇总错误统计（=标量分数），按 Meta-Harness 启示应把完整执行轨迹文件路径一并喂给分析 agent，让它 grep 回溯到具体决策点
  3. MEM1 式"答后先归档再继续"行为：高频笔记流（连发多链接）场景下，每篇处理完立即落盘+清工作集，正是 MEM1 涌现行为②的人工版——可以在会话管线里显式化
  4. exchange-protocol 加跨机父节点统计：经验池 JSONL 记录 source 机，统计跨机引用率，验证 CORAL 的 17% vs 9% 改进率是否在我们体系同样成立
