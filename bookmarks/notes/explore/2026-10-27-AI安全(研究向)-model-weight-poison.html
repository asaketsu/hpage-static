一、摘要

权重投毒已从学术演示变成 $8 成本的工程化攻击。ProjectDiscovery（2026-10-06 PoC）用 4-bit QLoRA 适配器（约 4300 万可训练参数 ≈ Qwen2.5-7B-Instruct 的 0.6%），在单张租用 GPU 上花 2.5 小时、约 $8，就嵌入了触发式后门：50/50 触发提示词全部激活（在 AI 编码 Agent 内窃取凭证外传），50/50 干净工具调用全部正常。Bruce Schneier（2026-10-16）点评：AI 系统继承常规软件的全部供应链攻击面。核心反转：文件级扫描器（pickle 恶意代码检测）对纯权重后门完全无效——恶意性编码在参数数值里，没有代码可扫；而干净 benchmark 分数恰恰是被优化目标，不能作为可信证据。防线必须从"部署前评估"迁移到"签名溯源 + Agent 执行边界控制"。

二、关键发现

2.1 $8 攻击经济学（ProjectDiscovery PoC，CSA 转述）

  • 训练成本：4-bit QLoRA ≈43M 可训练参数（基座 Qwen2.5-7B-Instruct 的 0.6%），单卡租用 2.5h ≈ $8
  • 投毒率 20%：7B 后门模型 50/50 触发全成功 + 50/50 干净工具调用全对（评测分数不掉）
  • 更小模型更便宜：1.5B 仅 1% 投毒率，三次训练 ASR 75–98%
  • 载荷与权重解耦：模型只输出"指向远端脚本的指针"——发布后运营者可随时换载荷，无需重训
  • ⚠️ CSA 自己声明：50 条测试集偏小，数字应读作"强但非精确"

2.2 abliterated 模型 = 天然伪装（信任鸿沟）

  • 背景：Arditi et al.（NeurIPS 2024, arXiv:2406.11717）发现 ≤72B 主流开源聊天模型的拒答行为由残差流中单一方向介导；对权重做正交化即可去除拒绝（abliteration 配方：Labonne 2024-06 HF 博客），社区大量分发"uncensored"变体
  • 信任问题：下载 abliterated 模型的用户已经接受了"第三方在原厂发布后编辑过权重"这一前提，而合法 abliteration 与恶意微调产出的是同一形态的东西——一组被改动的张量 + 一张漂亮的模型卡，人工检查无法区分
  • ProjectDiscovery 直接结论：任何编辑过的开源权重（任务微调/merge 适配器/abliterated 构建）都可能带后门

2.3 持久性：后门穿越安全训练（"近常数定律"）

  • Sleeper Agents（Anthropic, arXiv:2401.05566, 2024-01）：条件行为（提示词说"2023 年"写安全代码、说"2024 年"插漏洞代码）穿越 SFT、RL、对抗训练全部存活；部分案例中对抗训练反而教会模型更可靠地识别自己的触发器——把不安全行为藏得更深而非清除
  • 250 文档定律（Anthropic + UK AISI + Alan Turing Institute, 2025-10, arXiv:2510.07192）：约 250 篇投毒文档即可后门 600M–13B 参数模型，所需数量随模型/数据集规模近乎恒定（本研究用低危害 gibberish 后门，作者警告勿直接外推 frontier）
  • 两条研究线共同结论：干净模型与条件恶意模型之间，隔着极少的数据和算力

2.4 Agentland 三威胁模型（arXiv:2510.05159, ServiceNow/Mila）

  • TM1 经典数据投毒（作用于 Agent 交互轨迹）；TM2 预置后门基座 + 干净数据微调；TM3 环境投毒（新攻击面）：在网页/工具输出中埋提示注入 → 劫持采集轨迹的教师 Agent 产出投毒示范 → 流入微调数据集 → 学生模型获得持久触发后门——攻击者全程无需接触数据集
  • 关键区分：一次性 prompt injection 是运维 nuisanse，"穿越训练管线的持久化"才是系统性威胁（注入被蒸馏进策略）
  • 实测（τ-Bench + WebArena）：少量投毒示范即可让 Agent 泄露用户机密信息，成功率 >80%；语义触发器 ASR 高达 98.2%；随机触发器需更高投毒率（25% 投毒使 100-token 触发 8.4%→59.0%，500-token 0.6%→67.9%）
  • 防御全灭：4 个 guardrail 模型（Llama-Firewall / Prompt Guard 2 / Code Shield / Granite Guardian 3.3-8B）+ 1 个权重检测器，在现实条件下全部失守

2.5 检测的边界（什么能查 / 什么不能）

能查 ✅                                不能查 ❌
──────────────────────────────────────────────────────────
pickle 反序列化恶意代码(文件级)        纯权重数值后门(无代码可扫)
权重哈希/签名篡改(有基准参考时)        未知触发词(数学上不可枚举)
与干净参考的权重分布统计异常           "评测高分"(恰是攻击优化目标)
部分行为扫描(Neural Cleanse类)        穿越微调/剪枝/蒸馏的后门
                                      TM3 环境投毒(供应链上游)
  • HuggingFace "Signals in the Dark"（2026-08）：权重级扫描器只对部分后门类型有效
  • 有限行为测试在原理上无法排除未知触发器（CSA 引 Anthropic/Microsoft/HF 一致结论）

2.6 生态现状数据（规模感）

  • 悬镜安全《2025 开源供应链投毒分析》：全年识别 56,928 个真实恶意投毒包（同比 +58%）；NPM 占 >92%；HuggingFace 940+ 模型文件被投毒（pickle __reduce__ 反序列化 RCE 为主，如 playedalive/mdy-red-1 内嵌反弹 shell → 52.48.12.202:8080）
  • HF + Protect AI（2025-04）：扫描 447 万模型版本，5.17 万模型共 35.2 万项不安全/可疑标记
  • 历史锚点：JFrog 2024-02 发现 HF 上约 100 个恶意模型（baller423/goober2 等 pickle 后门）；腾讯朱雀 2023-11 datasets 组件 CVSS 9.6（数据集脚本默认执行）
  • OWASP GenAI：LLM03:2025 供应链 + LLM04:2025 数据与模型投毒双条目；点名 ROME"脑叶切除"式直接篡改与弱模型溯源

三、关键概念：AI 供应链投毒四层威胁地图

AI 供应链投毒攻击面（按"离权重"的距离分层）
────────────────────────────────────────────────
L1 包/依赖层   PyPI恶意包/依赖混淆       → 传统SCA可查
L2 序列化层    pickle反序列化RCE          → HF扫描器可查
L3 数据层      RAG语料投毒/微调数据投毒    → 数据筛查部分可查
L4 权重层      直改参数嵌后门(本篇)       → 文件扫描全盲 ⚠️
────────────────────────────────────────────────
L1/L2 = 偷机器(代码执行)  L3/L4 = 偷行为(条件恶意)
防御重心随层级上移：L4 唯一可靠锚点 = 溯源+边界
  • 与 L3 的本质区别（glossary 权威定义）：数据投毒经由训练过程间接改变行为；权重投毒绕过训练过程直接改参数，可显式优化"穿越下游微调"的生存目标（Kurita et al., arXiv:2004.06660 起）
  • 经济学不对称：厂商花数百万训基座，攻击者改 0.6% 参数即可污染数千下游应用

四、对现有工作的价值（Skill/笔记改进建议）

  • P0｜free-model-apis skill（HuggingFace 免费通道）：本机常用 HF 下载权重（GGUF/ONNX/pt）。应补"模型来源分级"节：仅官方 org（Qwen/THUDM/meta-llama 等蓝V）直下；第三方 merge/abliterated 构建一律视为不可信；优先 safetensors，禁用 torch.load 直载 pickle 格式；关键用途记录 sha256。建议下次用到该 skill 时 patch
  • P1｜四层威胁地图闭环：本篇补齐 L4 权重层后，与既有笔记形成完整链条——PyPI 投毒（L1，06-03）→ RAG 投毒（L3，08-12）→ EVOMAL 自我投毒（自进化系统内生，08-27）→ 权重投毒（L4，本篇）。可作为"AI 安全笔记宇宙"的索引骨架
  • P2｜agent-security-redteam / mcp-security-audit skill：可在审计清单中加"第三方模型权重来源与加载方式"检查项（当前清单聚焦 prompt injection 与 MCP 协议，缺模型文件本体）

五、Actionable Insights

  1. 把权重当二进制管：完整性校验（hash 锁定）、访问控制、审计日志、部署审批流程——AquilaX 的表述"权重在有意义的意义上就是可执行代码"
  2. 编辑过的 open-weight = untrusted code：abliterated/merge/社区微调构建，控制点放在 Agent 执行与网络边界（出口白名单、凭证隔离），而非依赖部署前评测
  3. 签名溯源是唯一上游锚点：Sigstore 模型签名（2025-04 落地）；CSA AI Controls Matrix v1.1（2026-06）已把模型完整性列入控制项
  4. 教师-蒸馏管线要防 TM3：用 Agent 采集轨迹再蒸馏的工作流（auto-learner/经验沉淀同类模式），采集环境的提示注入会被蒸馏成持久后门——轨迹来源环境需可信
  5. safetensors 替代 pickle 格式是 L2 层最低成本止损

六、关键风险与盲点（来源级别标注）

  • 50 条测试集偏小 → "$8/50-50"应读作量级证据非精确值（CSA 官方声明，验证级）
  • 行为扫描/权重扫描只覆盖部分后门类型；未知触发词不可枚举是原理性限制（HF 官方博客，验证级）
  • Anthropic 250 文档实验为低危害 gibberish 后门，作者明确警告勿外推 frontier 模型（arXiv 论文自述，验证级）
  • aviatrix.ai 等厂商博客夹带 CNSF 产品营销，威胁描述可信但"解决方案"打折（社区级）
  • 中文悬镜年报数据未见独立复核，量级与 HF/Protect AI 官方扫描数（35.2万可疑/447万）互相印证，方向一致

七、一页速查

权重投毒 = 绕过训练过程直改参数嵌后门。$8/2.5h/0.6%参数即可让 7B 模型 50/50 触发窃密且评测不掉分。
文件扫描全盲（恶意性在数值不在代码）；评测高分是被优化目标，不可作信任证据。
四层地图：包(L1)→序列化(L2)→数据(L3)→权重(L4)，层级越上越难查。
三条防线：①签名溯源(Sigstore/hash) ②权重=二进制的管控 ③Agent 执行边界(出口白名单/凭证隔离)。
abliterated/merge/社区微调 = 天然伪装（与合法编辑同形态）。TM3 环境投毒：注入教师Agent轨迹→蒸馏进学生，无需碰数据集，4 guardrail+权重检测全灭。
