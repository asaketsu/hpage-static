一、内容整理

1.1 论文元信息与核心问题

  • 论文全称：When Can Agents Forget Their Reasoning? ICLR for Long-Horizon Agent Context Compression（Interaction Aware Compression for Long Horizon Reasoning）
  • 发表时间：2026-09-24，30 页长文
  • 研究领域：长程 LLM Agent 的上下文管理 / 推理压缩
  • 核心问题：长程 Agent 不断累积推理历史（reasoning history），上下文长度和推理成本随之增长。一旦推理已经产生了动作、环境已返回反馈，这段推理是否还需要留在活跃上下文中？
  • 关键区别（与静态 CoT 压缩的本质不同）：
  • 静态 CoT 压缩：修改的是一条已完成的推理轨迹，评估对象是同一个最终答案
  • 在线 Agent 推理压缩：改变的是未来动作生成的状态。第 t 步删掉一段推理，可能改变下一个工具调用、下一个观察、以及之后的所有决策——这是闭环决策过程干预，不是文本编辑

1.2 方法核心：ICLR 三层设计

整体流程：Agent 每完成一步交互（推理 R_t → 动作 A_t → 观察 O_t+1），ICLR 在下一次请求前压缩刚完成这一步的推理，保留动作、工具调用、观察的完整原文。压缩后的历史直接写回持久历史，不可恢复，后续所有调用都在被修改过的轨迹上运行。

（1）代理熵评分（Proxy Entropy）
- 用一个冻结的 Qwen3.5-9B 模型作评分器（acting agent 是 DeepSeek-V4-Flash）
- 对每个推理块计算 token 级预测熵的均值：低熵 = 高预测确定性 = 高冗余
- 分块规则：双换行符确定性切分，排除空块
- 42K token 输入上限：超出则该步跳过剪枝（绝不截断 acting agent 看到的历史）

（2）上下文条件化排名（Context-Conditioned Ranking）
- 评分器不是孤立地看推理块，而是接收 system prompt + 工具定义 + 累积交互历史 + 当前完成步骤的原始因果序完整上下文
- 同一段推理文本在不同轨迹状态下得分不同——H(B_i | H_t) 是状态依赖量
- 这正是 Agent 场景的关键：新动作/观察会改变旧推理的相关性

（3）块选择（BottomK 删除）
- 固定删除比例 ρ=0.8：每次删掉熵最低的 80% 推理块
- 被删块替换为 [SKIP] 占位符，保留块原文与顺序不变
- 用固定比例而非任务自适应阈值：为了跨轨迹一致干预，便于科学研究对比

1.3 关键实验结果

主结果（WorkBuddyBench 260 任务全集）
- 平均奖励：0.699 → 0.718（+1.9 分），同时 token 总量 2.69M → 2.19M（-18.5%）
- 分项 token：输入 -25.5%、输出 -14.4%、缓存读 -33.3%
- 胜/平/负：102/76/82
- 域级分化明显：Security 域 +22.9 分大涨，Code 域 -6.4 分、Office 域 -4.2 分小跌

与 12 个基线对比（Pilot40 子集，avg 分数 / 相对基线 token）
- ICLR：70.3 / +6.9% token（唯一同时提分+省 token 不足的平衡方案中 avg 最高）
- 滑动窗口 K=5：56.4 / +56.3%（掉 11 分还费 token）
- Periodic Summary n=3：60.5 / +17.2%（总结式压缩掉分严重）
- PACE：58.4 / -41.6%（省 token 最多但掉 9.1 分）
- CoMem：44.2 / -59.5%（外部记忆方案在此基准上崩溃，Security 域仅 2.5 分）
- ACM（已发布策略）：33.7（-33.8 分，全面崩溃）

消融（80 任务固定集）
- ICLR 0.738 vs Base 0.627（+11.09）
- Delete-All-Thinking（全删推理）：0.718（+9.11）——全删居然也涨分
- Step-Only-Entropy（无上下文条件化）：0.711（+8.47）
- Random 5%-40% 删除：0.676-0.678（+4.9 左右）——随机删也涨分但系统性低于熵方法
- 结论：推理历史确有大量冗余，但上下文条件化的熵排名提供了超出"单纯删减"的增量信息

1.4 轨迹放大效应（Trajectory Amplification）——论文最重要的发现

  • 现象：本地删除率与最终系统级计算量不成比例、非单调
  • Random 10% 删除 → 总输入 -60.5%
  • Random 20% 删除 → 总输入只 -44.0%（删得更多，反而省得更少）
  • Delete-All → -63.6%（并非"全删=最大节省"的线性外推）
  • 机制：对推理历史的局部修改 → 改变后续工具选择 → 改变观察内容 → 触发重复推理/恢复/重试 → 轨迹形状整体改变
  • 含义：评估上下文压缩方法不能只看本地删了多少 token，必须看端到端轨迹级计算量。删 10% 可能比删 20% 省更多，因为前者不触发恢复循环

1.5 未来必要性探测（Future Necessity Probing）

  • 用冻结 Qwen3.5-9B 作表征传感器，线性探针预测"当前上下文边界的隐藏状态是否编码了稍后重推导/补充推理/重规划"的信号
  • 265 个压缩边界样本（31 任务、112 正例），严格任务级嵌套划分防泄漏
  • AUROC 0.844、AP 0.811、平衡准确率 0.760——"哪些推理稍后还会被用到"在当前状态中是可解码的
  • 激活修补（Activation Patching）互补证据：用全历史残差替换删除历史残差，KL 修复度随层深递增——层4=0.047、层20=0.459、层28=0.724、层31=0.978（中后层承载历史推理信息）

1.6 内化-外化鸿沟（Internalization-Externalization Gap）——最具工程价值的发现

  • 任务特定派生状态只存在于推理中时，未来行为风险率 67.3%
  • 该状态已被外化（写入代码/文件/环境）后，风险率降至 36.2%（任务内 +19.8 个百分点）
  • 受控干预四连证据：
  • 只保留最新推理 → 保持满分规则分 0.872
  • 只删最新推理 → 降至 0.760
  • 相关代码写完后清空推理 → 最终分数不变
  • 隐藏环境反馈 → Agent 会通过额外交互重新获取同样信息
  • 结论：历史推理的价值 = 它是否还是任务关键派生状态的唯一可靠载体。一旦状态外化，原推理即可弃

二、查询拓展

2.1 WorkBuddyBench

论文的主实验基准。长程 Agent 任务集，260 任务覆盖四个域：Code（80）/ Office（50）/ Security（60）/ Web（70）。带官方任务奖励（reward）计分，并单独统计输入/输出/缓存读 token。消融用固定 80 任务子集（每域 20）。它是近期 Agent 上下文管理研究（PACE、SelfCompact、SWE-Pruner 等）的公共比较平台。

2.2 Step Entropy（熵引导压缩谱系）

ICLR 的代理熵直接继承自 Step Entropy 方法（论文引文 9）：对推理步骤按预测分布不确定性排名，数学推理中大量低熵步骤可删而保持最终答案精度。CONCISE、TokenSkip 同属"删低贡献推理"谱系。它们的共同局限是只在单次完成生成内部优化，而 ICLR 把熵准则搬进闭环交互循环。

2.3 Agent 上下文管理方法谱系（基线全景）

  • Token 级压缩：LLMLingua 系列、gist tokens
  • 相关性与摘要：PACE（预测性自适应上下文提取）、ACON（优化长程 Agent 上下文压缩）、Periodic Summary
  • Agent 专属：SWE-Pruner、Self-Compact、Self-GC、Sculptor、SAM
  • 外部记忆：MemGPT、CoMem、Mem1、ACM
  • ICLR 的差异化主张：不动动作/工具调用/观察（外部交互记录），只动推理——保护"已进入环境的事实"

2.4 KV Cache 视角 vs 转录本视角

ICLR 属于转录本层（改变 LLM 看到的历史文本）压缩，与 KV Cache 层压缩（MemDecay 的区域感知驱逐、Kara 滑动窗口）正交。注意 ICLR 的缓存读 token -33.3% 是转录本缩短的副产品。两层可叠加，也共享同一设计问题：删什么、何时删、删了之后闭环行为怎么变。

2.5 表征 probing 与激活修补

线性探针读隐藏状态预测行为目标（Gurnee & Tegmark 式表征分析）；激活修补做因果验证：把"删除历史"条件下的残差替换为"全历史"残差，看下一个 token 分布恢复多少（KL Repair）。这套神经可解释性工具被借来回答"历史推理在模型内部是否被真实使用"。

三、归纳总结

3.2 三大发现的因果链

  • 发现一（轨迹放大）：本地删除 ≠ 省钱。删除改变决策 → 决策改变轨迹长度与内容 → 端到端计算量非单调。评估必须轨迹级。
  • 发现二（未来必要性可探测）：当前上下文边界的表征含"稍后是否重推导"信号（AUROC 0.844）→ 删除决策原理上可以前瞻，不必只靠熵事后排名。
  • 发现三（内化-外化鸿沟）：推理的价值 = 唯一载体性。状态已外化 → 推理可弃；未外化 → 删除高风险（67.3% vs 36.2%）。

3.3 论文定位一句话

用冻结代理模型做训练无关的在线推理剪枝，并首次系统刻画了"Agent 在线压缩的闭环非单调性"，把'何时可以遗忘推理'归约为'任务状态是否已外化'的可操作判据。

四、趋势判断

趋势1：Agent 上下文压缩从"摘要范式"转向"选择性保留范式"

依据：Periodic Summary 掉 7 分、CoMem/ACM 类方案在长程基准崩溃，而"只删推理、保留动作与观察"的 ICLR 及其消融变体全部涨分。摘要范式有损且不可控，选择性保留保住了外部记录的证据链。

趋势2：评估指标从"本地压缩率"走向"端到端轨迹计算量"

依据：轨迹放大效应表明删 10% 可能比删 20% 更省总 token。只报告压缩比的方法在闭环场景下失去意义，未来论文将被迫报告 wins/ties/losses + 全轨迹 token 计量。

趋势3：冻结小模型做评分器成为训练无关方法的标配架构

依据：ICLR 用冻结 Qwen3.5-9B 同时充当熵评分器与 probing 传感器，零训练成本。与 TMEM/Engram 类参数化记忆路线形成对照——"外挂冻结模型"是轻量化落地的主流路径。

趋势4：删除决策将从"事后熵排名"进化为"前瞻必要性预测"

依据：AUROC 0.844 的探针证明未来必要性可解码，但 ICLR 本身还没用它做删除决策。把 probe 变成策略（何时删、删哪块）是显然的下一代方法，也是开源复现的机会点。

五、关联分析

5.1 与 MemDecay 精读（2607.10582）的关联

MemDecay 在 KV Cache 层做区域感知驱逐（system 区半衰期 10 倍于 scratchpad），ICLR 在转录本层做推理块删除。两者共同验证同一原则：上下文不同区域的可丢弃性差异巨大——MemDecay 用区域优先级，ICLR 用熵+载体状态。两层正交可叠加：转录本层先删推理减少输入，KV 层再做区域感知驱逐。

5.2 与 Memory Compaction 率失真框架（2607.08032）的关联

率失真框架证明可逆压缩（0.95）远优于不可逆压缩（0.33-0.56）。ICLR 的 [SKIP] 替换是彻底不可逆删除，按该框架属高风险端；但其受控干预显示"代码写完后删推理无损"——因为信息已转移到外部载体，等效于可逆。两篇合读给出统一判据：删除安全性取决于信息是否有其他存活副本（外化载体或可重推导）。

5.3 与 SKIP 简洁推理精读（2026-09-16）的关联

SKIP 在训练时用偏好学习压缩单轮推理长度，ICLR 在推理时在线删除历史推理块。互补关系：训练期瘦身（SKIP）+ 运行期遗忘（ICLR）可组合。且 ICLR 的"低熵=可删"与 SKIP 的"自知识引导跳步"共享同一信息论直觉。

5.4 与 Agent 记忆架构 2026 之争（2026-09-07）的关联

该笔记记录了"文件系统 74 分打脸专业记忆栈"的争论。ICLR 增添新证据：CoMem（外部记忆栈代表）在 WorkBuddyBench 上崩溃至 44.2 分，而最朴素的"保留外部交互记录"策略表现最稳。支持"环境本身就是记忆"的极简路线。

5.5 与 Hermes Agent 自身的关联

Hermes 的会话历史管理与 context-compressor skill（大工具输出转存文件+摘要预览）正是 ICLR 研究的问题域。ICLR 的"保护动作/工具输出、只压推理"原则可直接对照 Hermes 的压缩策略设计。

六、金句摘录

「Local text removal is not equivalent to total computation saved.」— 轨迹放大效应的本质：省 token 要看端到端，不是看本地删了多少。

「Historical reasoning is most valuable when it remains the only reliable carrier of task relevant derived state.」— 全文最凝练的结论：推理的价值在于唯一载体性。

「Agent reasoning is dynamic working state whose value changes throughout interaction.」— 把推理从"资产"重新定义为"动态工作状态"。

七、行动启示（借鉴点与优先级评估）

7.1 对 Hermes Agent 的借鉴点

  • P0 · 推理/动作分离压缩原则：Hermes context-compressor 目前对工具输出做转存压缩；可增加"只压 assistant 推理段、永不压工具输出与用户消息"的策略分层。ICLR 证据：保外部记录、删内部推理是唯一同时涨分+减 token 的方向。对照现有 skill：context-compressor 未区分消息类型，属增量价值高的改造。
  • P0 · 轨迹级成本观：Hermes 的 token 统计按调用计；长会话中应追踪"单次删除引发的后续重试/恢复增量"（轨迹放大检测），避免"删了 20% 反而更贵"。工作量：会话日志聚合脚本，约半天。
  • P1 · 外化优先原则：任务关键派生状态（计划、约束、中间结论）尽早写入文件/checkpoint（harness-checkpoint skill 已有雏形），随后即可安全压缩对应推理。ICLR 数据：外化后风险率 67.3%→36.2%。与 memory-write skill 的原子记忆点联动。
  • P2 · 低熵可删启发式：cron 会话的重复性推理（每日巡检等）可用轻量代理（本地小模型或 next-token 概率）识别低熵段批量跳过。Jetson 本地 9B 模型即可承担，无需训练。
  • P3 · 必要性探针：冻结模型线性探针预测"稍后是否重推导"（AUROC 0.844），用于删除决策前瞻。工程改造量大，暂观望。

7.2 对 Jetson 边缘部署的借鉴点

  • P1 · 缓存读 -33.3% 的边缘意义：转录本缩短直接减少 KV cache 读流量，对 Jetson 内存带宽受限平台是双倍收益（省计算+省带宽）。长会话 Agent（如值班机器人）可按 ICLR 模式只保留动作/观察。
  • P2 · 冻结小评分器架构：Jetson 本地跑 9B 评分器对每步推理打熵分，边缘端零训练成本实现自适应压缩，与 nexa-local-inference 栈可组合。

7.3 对量化交易的借鉴点

  • P3 · 盘口解读推理的外化：盯盘 Agent 的推理（支撑位计算、量能判断）应立即外化为结构化指标文件再入上下文，而非让原始推理持续膨胀。ICLR 的外化判据（唯一载体性）同样适用。

7.4 借鉴点分档总表

  • ✅ 已部分实现（增量价值高）：推理/动作分离压缩 → context-compressor 增加. 消息类型分层
  • 🔨 可直接移植：外化优先原则 → harness-checkpoint + memory-write 组合，约 1 天
  • 🔨 可直接移植：轨迹级成本统计 → 会话日志聚合，约半天
  • ⚠️ 需工程改造：低熵代理评分 → 需本地模型常驻，Jetson 可行
  • ❌ 暂不适用：激活修补/KL 修复分析（纯研究工具）

八、拓展应用推荐

  1. Hermes 长会话压缩策略升级：按 ICLR 原则改造 context-compressor——assistant 纯推理段可压缩，工具输出/用户消息永不压。配合外化优先，长 cron 会话可稳定控制上下文规模。
  2. harness-checkpoint 强化：把"任务关键状态写入 checkpoint"从可选动作升级为压缩前置门禁——未外化的派生状态所在推理段标记为不可删。
  3. Agent 成本可观测性：在 observability-dashboard 中增加轨迹放大指标（删除操作后的重试率/额外调用数），验证压缩策略的真实收益。

九、指南分析

适用对象：构建长程 Agent 系统、需要控制上下文成本的工程师与研究者。

核心操作指南提炼：
1. 永远不要压缩工具输出与用户消息——它们是外部交互记录，删除会破坏证据链
2. 推理段压缩前先问：其中的任务关键结论是否已有外部副本（文件/代码/环境状态）？没有则先外化再删
3. 评估任何压缩策略时，报告端到端轨迹 token 而非本地压缩率——轨迹放大会让本地数字失真
4. 冻结小模型 + token 熵是零训练成本的可行起点；固定删除比例比自适应阈值更利于对照实验
5. 域差异必须实测：ICLR 在 Security +22.9 而 Code -6.4，盲目移植有风险

与其他指南的冲突与调和：Memory Compaction 框架主张可逆压缩优先；ICLR 实操中用不可逆 [SKIP] 但靠外化补偿。调和方案：外化载体存在时不可逆删除等效可逆——实践中应先建外化层，再放开删除。
