一、内容整理

1.1 核心问题：能力对齐断裂（competence misalignment）

Harness 优化 = 不动模型参数，只改 prompt / 工具集 / 工作流（H = (P, T, W)）来提升 Agent。当前最强路线是 Darwin–Gödel Machine（DGM）和 Huxley–Gödel Machine（HGM）的递归自改进，但它们诞生于 coding 场景——「改 Agent 所需的能力」与「被改进的能力」是同一个（都会写代码），自指闭环天然成立。

Planning 任务打破了这个对齐：Agent 必须产出一串工具调用，联合满足多个相互作用约束（时间/空间/预算/优惠券叠加），一处违反即全盘皆输。此时开放式自改进出现两个失效模式（HGM 购物搜索实测）：

  • 41.8% 的编辑在重复搜索树里已有的编辑模式——每次重复都烧掉一次完整 planning 评估
  • 19.4% 的编辑瞄准父代从未失败的错误类别（打错靶）；64.2% 的子代保留父代的主导错误类别（没打中要害）

核心论断：缺的不是更多历史 Agent 归档，而是显式的 edit–outcome 归因上下文——改了什么、行为变好还是变坏、哪些改动被证明无效。

1.2 机制一：谱系感知的进化上下文（lineage-aware context）

每个非根 harness H_i 定义进化记录五元组 ζ_i = (d_i, u_i, ΔJ_i, Δf_i, b_i)：

  • d_i：编辑内容摘要
  • u_i：功能层面的增/删/调用（functionality added, removed, or invoked）
  • ΔJ_i：性能影响（相对父代的分数差）
  • Δf_i：约束级错误向量的变化（哪类错误多了/少了）
  • b_i：观察到的行为后果描述

谱系上下文 Z_i = Summarize({ζ_j : H_j ∈ Anc(H_i)})——把祖先路径上所有进化记录压缩成有界摘要，交给编辑器。编辑函数从 Edit(H_i, ε_i) 升级为 Edit(H_i, ε_i, Z_i)。

1.3 机制二：错误条件化双路径子代生成

每次扩展同时生成一泛两专三个子代，只保留最强者入档：

  • 通用子代（general child）：开放式探索，可改任何 harness 组件——保留发现意外改进的能力
  • 两个专用子代（specialized children）：从父代错误频率向量 f_i 中选 Top-2 错误类别 c_1, c_2，各自携带该类错误的代表性执行轨迹 S_i^c，要求编辑器「诊断该失败 → 定位责任组件（prompt/工具/工作流）→ 定向修正且不破坏已成功能力」

噪声门控（关键设计）：错误条件化路径仅在一次性 pre-search 检验通过时启用——任务级一致性 κ ≥ 0.4 且 主导类别稳定性 ρ_B ≥ 0.7；否则退化为纯通用路径，避免向噪声失败信号特化。

Expand(H_i):
  Z_i ← Summarize(祖先路径上的全部 ζ)
  H_gen ← Edit_gen(H_i; ε_i, Z_i)          # 泛：开放探索
  if κ≥0.4 ∧ ρ_B≥0.7:                       # 门控
    {c*1, c*2} ← Top2 错误类别(f_i)
    H_err_k ← Edit_err(H_i; c*_k, S_i^{c*_k}, Z_i)  # 专：打靶
  H+ ← argmax J^(H_gen, H_err_1, H_err_2)   # 三选一入档
  记录 ζ+ = (d+, u+, ΔJ+, Δe+, b+) 并随 H+ 入档

1.4 实验设置与结果

基准：DeepPlanning（旅行规划 9 个 API 构建分钟级 7 日行程，21 项可行性检查、8 个维度；购物平均检索 171 条记录、15 个 API、45 个属性，产品+优惠券+预算联合约束）。优化集 60 样本，评估 120 样本（60 未见）。编辑器 GPT-5.4（reasoning medium），任务 Agent GPT-5.4-mini（high）。预算 = 生成的 plan 数。

主结果（budget=4000，case accuracy）：

  • 旅行：Seed 25.00 → HGM 30.42 → HGM-CA 54.17 → HGM-CF 56.25 → HGM-Dual 64.38
  • 购物：Seed 50.83 → HGM 50.83 → HGM-CA 58.33 → HGM-CF 60.83 → HGM-Dual 66.67
  • 相对最强基线最高 +14.45%；以 2×–4× 更少评估预算追平 HGM 变体的最终性能

低预算（budget=1000）：购物 case acc HGM-Dual 70.83 vs HGM-CF 56.67——预算越紧，诊断引导优势越大；旅行 composite 83.83 略低于 HGM-CF 84.90（case acc 47.08 vs 47.50 基本持平）。

消融（旅行 composite）：

  • HGM-CF 84.01 → 加谱系上下文 88.21（+4.2，贡献更大且稳定）
  • 去掉错误条件化 87.68 vs 完整版 90.35（+2.7，加速低预算收敛）

跨骨干泛化（Mistral-Medium-3.5-128B 任务模型）：composite Seed 32 → HGM-CF 34 → HGM-Dual 42，且保住 case acc 1.6% 不降——弱骨干上 harness 优化仍有效但 case 级提升有限。

二、查询拓展

2.1 DGM / HGM / clade-metaproductivity

DGM（Darwin–Gödel Machine）维护 Agent 归档，通过修改选出的父代产生新候选；HGM 进一步按 clade-metaproductivity（进化枝元生产力——产出强后代的潜力）选择父代，而非仅看当前分数。两者都主要在 coding 基准上验证。HGM-Dual 直接继承 HGM 的进化骨架（归档+树+clade 选择），只改造「扩展」这一个环节——这是典型的最小侵入式增益改造。

2.2 ADAS / GEPA / Meta-Harness / SkillOpt

  • ADAS：自动设计 Agent 系统，元 Agent 写代码实现新 Agent 架构
  • GEPA：进化式 prompt 优化，替换 GRPO 的反传为低成本反思式变异
  • Meta-Harness：给提议器看历史候选的代码+分数+执行轨迹——与 HGM-Dual 最接近，但作者指出其上下文是「过量」的（原始轨迹洪泛），缺少 ζ 五元组式的结构化归因
  • SkillOpt：对自然语言 skill 做有界编辑+验证优化——对应 Hermes 的 SKILL.md patch 语义

2.3 DeepPlanning 基准

约束密集型长程规划基准，旅行/购物双域。特点是错误可被确定性规则分类器归到固定类别（旅行 8 维度+实体分组；购物 4 个产品级+3 个购物车级错误类别）——这正是 HGM-Dual 错误条件化得以成立的前提：错误空间离散且可枚举。

三、归纳总结

3.1 整体框架

              ┌────────────────────────────────┐
              │  Archive A（进化树 + ζ 记录）    │
              └───────┬────────────────────────┘
                      │ 选父（clade-metaproductivity）
                      ▼
   ┌──────────────────────────────────────┐
   │ Expand(H_i):                         │
   │  ① Z_i = Summarize(祖先 ζ 五元组)     │ ← 机制1：谱系记账
   │  ② H_gen  = 开放式编辑(ε_i, Z_i)      │
   │  ③ 门控通过 → Top2 错误类别 → 2×定向编辑│ ← 机制2：双路径
   │  ④ argmax 三子代 → 入档 + 记 ζ+        │
   └──────────────────────────────────────┘

3.2 三代 harness 进化范式的递进

  • 第一代·盲目进化：只有当前父代代码+评估日志 → 41.8% 重复编辑，预算黑洞
  • 第二代·归档进化：全量历史候选+原始轨迹 → 信息在但不可归因，编辑器仍会重蹈覆辙
  • 第三代·谱系感知+诊断引导（本文）：结构化 edit–outcome 记账 + 错误打靶 + 噪声门控 → 同等性能 2–4× 省预算

一句话：把「进化搜索」从无记忆的盲试，升级为带实验台账的定向工程。

四、趋势判断

趋势1：edit–outcome 归因将成为自进化 Agent 的记账标准

依据：消融显示谱系上下文贡献 (+4.2) 大于错误条件化 (+2.7) 且跨域稳定；Meta-Harness 等归档方法的失败正说明「存了 ≠ 用上」。可预测后续工作会把记账从单谱系扩展到全树共享（作者也列为 future work）。

趋势2：评估预算成为 harness 优化的第一公民指标

依据：论文用「plans generated」作统一预算单位，低预算下优势反而放大（购物 1000 预算 +14pp）。冻结模型时代，评估调用是进化循环的真实成本中心，预算效率将取代裸分数成为主要比较轴。

趋势3：编辑器/执行器分工固化——强模型当园丁，冻结模型当花

依据：GPT-5.4 编辑器 + GPT-5.4-mini 执行器的双层配置，且跨骨干实验显示 harness 优化收益可迁移（Mistral +10 composite）。闭源昂贵模型只在编辑时刻被调用，运行时用便宜冻结模型——这是 Agent 工程的经济结构性分工。

五、关联分析

5.1 与 SPyCE / SkillOpt / ViSkill 技能进化系列的关联

  • SPyCE 技能-策略协同进化：SPyCE 的 merge-or-add 合并规则 ≈ 本文的 ζ 记账思想（记录技能的来源与效果），但 SPyCE 在线发生在任务流中，HGM-Dual 离线发生在进化循环中——在线轻量记账 vs 离线深度归因是两种互补粒度
  • SkillOpt Agent 技能自进化：SkillOpt 被 HGM-Dual 直接引用为 related work（自然语言 skill 有界编辑+验证），本文相当于 SkillOpt 加上了谱系记忆和错误打靶
  • ViSkill 视觉原生技能卡：技能卡晋升闭环同样缺「编辑历史归因」层

5.2 与 DGM 实证拆解笔记的关联

  • 自进化 Harness 与记忆：该笔记辨析了 DGM 类系统「写的三种语义不可混同」；HGM-Dual 恰好提供了一个正解样例——把「改了什么/效果如何」从归档元数据升格为编辑器的一等输入

5.3 与 Hermes 自进化体系的映射（借鉴点评估）

  • experience-bank / error-case-library：已部分实现 ζ 的 (d, b) 两元组（经验卡片+根因记录），缺 ΔJ/Δf 结构化效果差与错误类别向量——ζ 五元组是最小增量改造
  • skill-ab-testing：候选版本验证 ≈ argmax 三子代选优，但无 Top2 错误类别打靶环节
  • evolver / session-evolution-scan：每周进化扫描可直接套用「41.8% 重复编辑」检测——扫描 patch 历史是否在重复已判死的修复模式
  • SkillMisevo 技能误进化 / 技能污染与守门人：κ/ρ_B 门控是「何时该特化、何时该保持开放」的量化判据，正对应误进化防控

六、金句摘录

「What is needed is not simply access to more previous agents, but explicit edit–outcome context.」——缺的不是历史，是归因。对一切自改进系统（包括 Hermes skill 体系）成立。

「Retaining only the best child limits archive growth and focuses the search budget on promising harnesses.」——三选一入档是预算纪律，不是信息损失（输掉的子代经验已进 ζ 记账）。

七、行动启示

  • 给 skill 进化加 ζ 记账：每次 skill_manage patch 后追加一行五元组记录（改了什么/动了哪些功能/效果差/错误类别变化/行为后果），存 skill 目录 sidecar 文件，evolver 定期 Summarize 成谱系上下文供下次编辑参考
  • 修 bug 前先跑错误分类：error-case-library 已有类别雏形，patch 生成前取 Top2 高频错误类别定向修，替代「泛泛重写」——用户铁律「先根因定位再动手，禁止原地连续堆补丁」的机制化实现
  • 加重复编辑检测：连续两次 patch 同一 skill 处理同类失败 = 触发「已试过」警报，查谱系记录而非重试（对应用户「3+ fixes failed = 停下问架构」红线）
  • 进化循环记预算：session-evolution-scan 每轮统计评估/试跑次数，预算内未产生 ζ 正记录的分支提前砍掉

八、拓展应用推荐

  • Hermes skill 体系：ζ 五元组 sidecar + Top2 错误打靶 patch 流程（场景：evolver 周扫描从「泛读会话」升级为「定向修技能」）
  • RL 训练配方迭代：DUCK 训练版本日志（docs 训练台账）本质上就是 ζ 记账的雏形——把「错误类别向量」显式化（如站立失败分：前扑/后仰/跺脚/左右倾），下轮训练变体 = Top2 错误定向设计，与用户已验证的「分层验证框架+单变量纪律」完全同构
  • 量化策略研究：Quant-Arena（2610.30113，同日提交）把量化研究定义为假设→信号→回测→保留的闭环，harness 进化的 ζ 记账可直接迁移为「策略假设台账」（每次改因子记录假设/改动/IC 变化/回撤变化）
  • ** cron / 自动化运维**：watchdog 自动修复循环加 ζ 记账，防止反复尝试同一无效修复（41.8% 重复编辑的运维版）

九、指南分析

  • 方法论价值1（最小侵入改造）：HGM-Dual 不换进化骨架，只改造 Expand 环节就拿到 2–4× 预算效率——复杂系统改进应优先找「杠杆单点」而非重构整体，这是可复用的工程判据
  • 方法论价值2（先量化失效模式再设计）：论文开篇先测出 41.8%/19.4%/64.2% 三个失效占比，两个机制分别精确对位「重复」与「打偏」——机制设计必须有失效模式的实证画像托底，反例是先造轮子后找理由
  • 方法论价值3（噪声门控）：错误条件化不是无条件启用，κ≥0.4 ∧ ρ_B≥0.7 的预检门控值得一切「诊断驱动」系统抄用——诊断信号本身不可靠时，定向修复比随机修复更糟
  • 反例警示：跨骨干实验中 case accuracy 几乎不动（1.6%），说明 harness 优化有硬天花板——骨干能力不足时，外围优化的收益集中在部分分而非全对率，汇报时应诚实区分这两种「提升」
