核心发现

1. PagedAttention 是 LLM 推理性能突破的核心

vLLM 的 PagedAttention 算法是 LLM 推理领域的革命性创新，灵感来自操作系统的虚拟内存和分页技术。其核心突破在于：

问题识别：传统 LLM 推理中，KV cache（键值缓存）管理存在严重问题：
- 巨大：LLaMA-13B 单个序列的 KV cache 高达 1.7GB
- 动态：序列长度高度可变且不可预测
- 浪费严重：现有系统因碎片化和过度预留浪费 60%-80% 的内存

解决方案：PagedAttention 将 KV cache 划分为固定大小的块（block），每个块包含固定数量 token 的键值张量。关键创新：
- 非连续存储：块不需要在内存中连续，通过块表（block table）将逻辑块映射到物理块
- 按需分配：物理块在生成新 token 时动态分配
- 内存共享：支持并行采样时多个输出序列共享同一 prompt 的 KV cache

性能提升：
- 相比 HuggingFace Transformers：24x 吞吐量提升
- 相比 HuggingFace TGI：3.5x 吞吐量提升
- 内存浪费降至 4% 以下（接近最优）

技术细节：

# PagedAttention 核心数据结构
class PagedAttention:
    def __init__(self, block_size: int, num_blocks: int):
        self.block_size = block_size  # 每个块包含的 token 数
        self.block_table = {}  # 逻辑块 -> 物理块映射
        self.ref_counts = {}   # 物理块引用计数（用于共享）

    def allocate_block(self, seq_id: int, logical_block_idx: int) -> int:
        """按需分配物理块"""
        physical_block = self._get_free_block()
        self.block_table[(seq_id, logical_block_idx)] = physical_block
        self.ref_counts[physical_block] = 1
        return physical_block

    def share_block(self, src_seq: int, dst_seq: int, logical_block_idx: int):
        """共享块（用于并行采样）"""
        physical_block = self.block_table[(src_seq, logical_block_idx)]
        self.block_table[(dst_seq, logical_block_idx)] = physical_block
        self.ref_counts[physical_block] += 1

2. 量化技术矩阵：从 FP8 到 GGUF 的完整生态

vLLM 支持的量化方案形成完整技术矩阵：

量化类型 精度 适用场景 代表方案
权重量化 INT4/INT8 模型压缩 GPTQ, AWQ
激活量化 FP8 推理加速 FP8, MXFP8/MXFP4
混合精度 NVFP4 极致压缩 NVIDIA ModelOpt
CPU 推理 GGUF 边缘部署 llama.cpp
张量量化 MXFP8/MXFP4 细粒度 Compressed-tensors

GPTQ（Generative Pre-trained Quantization）：
- 逐层量化，保留精度
- 支持 AWQ（Activation-aware Weight Quantization）
- 4-bit 量化后精度损失 <1%

FP8 量化：
- NVIDIA H100/H200 原生支持
- 推理速度提升 2x，内存减半
- 对激活值敏感的模型需校准

GGUF（GPT-Generated Unified Format）：
- llama.cpp 的专用格式
- 支持 CPU/GPU 混合推理
- 可配置量化等级（q4_0, q5_K_M, q8_0 等）
- 适合边缘设备和本地部署

代码示例 - vLLM 量化启动：

from vllm import LLM

# FP8 量化
llm = LLM(
    model="meta-llama/Llama-3-70b",
    quantization="fp8",
    tensor_parallel_size=8
)

# GPTQ 4-bit
llm = LLM(
    model="TheBloke/Llama-2-70B-GPTQ",
    quantization="gptq",
    trust_remote_code=True
)

# AWQ 4-bit
llm = LLM(
    model="casperhansen/llama-3-70b-instruct-awq",
    quantization="awq"
)

3. 推测解码（Speculative Decoding）：用计算换速度

推测解码通过"小模型猜大模型"的方式加速推理：

工作原理：
1. 小模型（draft model）快速生成多个候选 token
2. 大模型（target model）并行验证所有候选
3. 接受匹配的 token，拒绝不匹配的重新生成

加速效果：
- 理想情况下：2-3x 速度提升
- 实际效果取决于小模型与大模型的语言一致性
- 长文本生成效果更显著

vLLM 支持的推测解码方法：
| 方法 | 特点 | 适用场景 |
|------|------|---------|
| n-gram | 基于历史 n-gram 预测 | 短文本、重复模式 |
| Suffix | 基于后缀树预测 | 代码生成 |
| EAGLE | 训练专用 draft 模型 | 通用场景 |
| DFlash | FlashAttention 优化 | 长序列 |

代码示例：

from vllm import LLM, SamplingParams

# 启用推测解码
llm = LLM(
    model="meta-llama/Llama-3-70b",
    speculative_model="meta-llama/Llama-3-8b",
    num_speculative_tokens=5,  # 每次推测 5 个 token
    speculative_method="ngram"  # 或 "eagle", "draft_model"
)

sampling_params = SamplingParams(
    temperature=0.8,
    top_p=0.95
)

outputs = llm.generate(prompt, sampling_params)

4. 连续批处理（Continuous Batching）与 PagedAttention 的协同

传统批处理要求所有请求同时完成，导致短请求等待长请求。vLLM 的连续批处理：

机制：
- 请求动态加入/退出批处理
- 每个请求独立管理 KV cache
- PagedAttention 的块级管理支持精细调度

效果：
- 平均等待时间降低 50%+
- 系统吞吐量提升 2-3x
- 支持 chunked prefill（分块预填充）

5. 分布式推理的并行策略矩阵

并行类型 描述 适用场景
Tensor Parallel 张量切分，单层内并行 单节点多 GPU
Pipeline Parallel 层间切分，流水线并行 多节点
Data Parallel 请求复制，数据并行 高并发
Expert Parallel MoE 专家切分 MoE 模型
Context Parallel 上下文切分 超长上下文

import asyncio

# 1. 基础部署

    model="meta-llama/Llama-3-70b-instruct",
    tensor_parallel_size=4,
    gpu_memory_utilization=0.9,
    max_num_seqs=256,
    quantization="awq",
    enable_prefix_caching=True,  # 前缀缓存
    enable_chunked_prefill=True,  # 分块预填充
)

# 2. 推测解码部署
llm_spec = LLM(
    model="meta-llama/Llama-3-70b-instruct",
    speculative_model="meta-llama/Llama-3-8b-instruct",
    num_speculative_tokens=6,
    tensor_parallel_size=4,
)

# 3. 结构化输出（JSON Schema）
from vllm.entrypoints.openai.api_server import create_app
# 使用 xgrammar 或 guidance 约束输出格式

# 4. 多 LoRA 支持
llm_lora = LLM(
    model="meta-llama/Llama-3-8b",
    lora_modules=[
        "path/to/lora1",
        "path/to/lora2",
    ],
    max_loras=4,
    max_lora_rank=64,
)

# 5. 异步推理
async def generate_async(llm, prompts):
    outputs = []
    for prompt in prompts:
        output = await llm.generate_async(prompt)
        outputs.append(output)
    return outputs
