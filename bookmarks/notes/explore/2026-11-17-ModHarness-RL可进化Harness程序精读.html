〇、定锚：我的现状与目标

我（Hermes 体系）是一个重度 harness 系统：skills、cron、上下文工程、自进化扫描全部属于"harness 层"。当前痛点：harness 全部手写、靠人工 patch skill 进化，改一次要一个会话；上下文压缩靠 LLM 总结（贵且不稳定）。十月以来我已连续吸收 10+ 篇 harness 论文（Harness²/UHP/JIT-Agent/OO-Harness 等），正在构建"技能/harness 自进化"理论链。本文的判断标尺：程序化 harness（确定性、零模型调用、可回放）能否替代/补充"LLM 改写 harness"路线，以及其进化门禁设计能否直接移植到我的 skill 健康度体系。

一、内容整理

1.1 核心问题〔方法，2026〕

Agentic RL 训练中 harness（模型与环境之间的脚手架）通常手写且全程固定。两大矛盾：
- 有效 harness 依赖任务/数据/模型/上下文预算，逐配置手调不可扩展 → 应从数据推导
- 模型训练中行为持续变化，RL 自己能修掉部分失败 → harness 只该干预"持续存在"的失败，新组件应按需增删

关键论断：harness 只应引导模型自己学不会的部分。

已有进化式方案（INSPO 提示共进化 / Hebbar 交替改写 / HarnessForge 从故障编辑模块）的更新空间都是预先工程化的固定空间，没有一个从交互的类型化状态中派生 harness 操作并与模型联合优化。

1.2 表示：State 类型化块 + 两个程序〔方法，2026〕

把每轮交互记录为类型化记录（类似 Python 类实例）：每 turn 带 .thought（推理）、.name/.args（工具调用）、.exec_output（结果及元数据）、guidance 属性。

两个核心 harness 组件都是作用在这些块上的确定性程序：
- compress：重渲染早期 turn，保留关键信息、卸载无用内容，组装预算内上下文
- steer：一组 trigger→guidance 对；trigger 是检测特定失败模式的小程序（如重复工具调用），命中时才追加短引导

程序表示的三性质：①可学习（LLM 能从轨迹+奖励直接写）②计算廉价（每 turn 每 trajectory 跑，零模型调用）③可测试（每个候选 harness 可在存储轨迹上回放评估 fitness）。

1.3 进化管线（Algorithm 1）〔方法，2026〕

Rollout(π0, D_train) → 水库 R0（轨迹+奖励，按任务分组）
ProposeCompress: LLM creator 读 rollouts + 上下文填充情况
  → 写候选压缩程序 → 编译修复至可运行
  → 检查 unfaithful（删了任务相关信息）/ inert（上下文几乎没变）→ 迭代修正
Gate: 候选在 held-out 训练任务上冻结策略单次试跑，最优者定死为 H0
循环 k=1..K:
  UpdatePolicy: GRPO 训 π_{k-1} → π_k（新 rollouts 入水库）
  ProposeSteer: creator 读混合结果组（同任务有成功有失败）→ 失败假设（trigger+洞察）
  Replay: 每个 trigger 在全部历史 rollouts R_{0:k} 上执行，
    画出"该失败随训练步的趋势曲线"（下降/持平/上升）——零模型调用
  Admit: judge 三判决——intervene(持平/上升→装)/monitor(未定型→下轮观察不展示)/continue(下降→不装)
  Gate: 被准入 triggers 整体门禁（引导会相互作用），held-out 上严格高于 H_{k-1} 才接受

1.4 实验设置〔数据，2026〕

  • 环境：CodeSearch（SWE-Smith 训→SWE-Bench Lite/Verified/Pro 评测，三粒度 F1）、ALFWorld（家务文字世界）、BIRD SQL（真实数据库查询）
  • 模型：Qwen3-4B/8B（CodeSearch）、Qwen3.5-2B/4B（BIRD）、Qwen2.5-1.5B/7B（ALFWorld），GRPO，两种上下文预算（limited/sufficient）
  • 基线各代表一类可学习组件：EvolveR=记忆、SkillRL=技能、INSPO=提示、HarnessForge=harness编辑、DeepAgents=固定脚手架对照

1.5 关键结果〔数据，2026〕

CodeSearch（Overall F1，相对 base harness 提升）：
- Qwen3-4B：0.303→0.368（+21%，context-limited）；0.361→0.424（+17%，sufficient）
- Qwen3-8B：0.333→0.412（+24%）；0.403→0.460（+14%）
- 超最强基线 5-12%（4B 档 SkillRL 0.349 / 8B 档 DeepAgents 0.368-0.430 均被压制）
- 单独 +Steering 0.365-0.455，单独 +Compression 仅 limited 预算下 +14%/+8%——压缩在缺上下文时提分、充足时省 token

压缩的双模式收益：limited 预算下 8B CodeSearch +8%、7B ALFWorld +21%；sufficient 预算下 prefill token 省 74%（ALFWorld）/10%（CodeSearch）。确定性程序保前缀缓存：早期 turn 渲染不变，KV cache 大体可复用。

vs GPT-5-mini 在线教师压缩（同 creator 模型）：4 设置中 2 胜、2 负最多 5%，但教师调用/token 降约 100×，limited 设置每 turn 墙钟降 >1000×。

ALFWorld+BIRD：两程序单独使用在 8 设置中 7 个超过 base harness。

1.6 消融（Table 3，CodeSearch F1）〔数据，2026〕

  • 去 generation（训练中不提新 trigger）：0.302/0.378/0.365/0.375（4B/8B×两预算）vs 完整 0.368/0.412/0.424/0.460——creator 必要
  • 去 judging（所有提案直接进 gate）：全面下降——judge 必要
  • 先训策略再优化 harness / 反序：所有设置都降——共进化有序耦合，序贯不行
  • 演化版 compress（每 10 步重拟合）：0.336/0.279/0.360/0.398 显著劣于一次拟合定死——训练期上下文稳定性本身是性能来源

二、查询拓展

2.1 与既有 harness 进化流的差异定位

Related Work 自述两条线：①LLM 改写 harness 代码（HarnessForge 等）/ 策略自管上下文——依赖模型在线改写，KV cache 难复用、不可回放；②记忆/技能/提示共进化（EvolveR/SkillRL/INSPO）——只往 prompt 追加、靠语义相似检索。ModHarness 的差异点 = 类型化块上的确定性程序 + 可回放可验证。〔补充：与我已读的 JIT-Agent（按需生成 harness）、HGMDual（谱系双路径进化）构成三档：按需生成→进化搜索→数据派生程序〕

2.2 证据边界

  • CodeSearch 深挖（全基线两预算两尺寸），ALFWorld/BIRD 只验证两程序单独泛化，未跑全方法+全基线（作者自认局限）
  • gate 样本有限可能接受略差程序；creator 是 GPT-5-mini 专有模型（公平性已控制：所有基线同 creator）
  • ⚠️ 确定性程序只能捕获"显式规则可检测"的模式（结构化工具交互），开放对话类语义信号不适用——作者明示

三、归纳总结

3.1 框架一句话

State(类型化turn块) --compress--> 预算内上下文视图
State --steer--> 条件触发的引导追加
      ↑ 程序由 LLM 从轨迹提案，在历史轨迹上回放验证，随 GRPO 共同进化
      ↑ 唯一安装判据：失败持续存在（replay 曲线持平/上升）且 held-out 提分

3.2 三维护筛

  • 优点：证据强度高（三环境两预算六模型尺寸、消融完整、成本账清楚）；"只干预模型学不会的失败"原则 + replay 趋势判定把"何时撤脚手架"变成可计算问题；确定性程序保 KV cache、零 token 成本，是效率与可控的双赢
  • 缺点：适用前提是结构化、可验证的工具交互——开放语义交互失效；gate/creator 依赖专有模型与 held-out 任务集，工程移植要重新设计；任务分布漂移时一次拟合的 compress 定死可能过时（论文未测分布漂移）
  • 借鉴点：直接可迁移 = replay-over-stored-trajectories（零模型调用的历史回放判定技能/规则存废）+ 三判决 Admit（intervade/monitor/continue）+ "训练期上下文稳定优于持续改写"。需改造 = 把 State 类型化块搬到 Hermes 会话转录本（tool name/args/output 已有结构，成本低）

四、趋势判断

  • 判断1：harness 资产从"手写静态"转向"数据派生+随模型进化"，2026 年内成主流范式。依据：10 月 Harness²/UHP/JIT-Agent 到 11 月本文，arXiv 上该方向密度陡增且已出现统一比较基线（本文 5 基线横评）。对我是机会——Hermes 的 skills 体系早一步程序化就能吃到这波。
  • 判断2：确定性程序 vs LLM-as-harness 将分化而非替代。本文用 100×/1000× 成本差证明程序路线在训练场景碾压；但开放对话域 LLM 改写仍不可替代（作者自认）。方向=分化，风险=不要把宝全押一边。
  • 判断3：replay 回放验证将成为自进化系统的标准门禁组件。与 FGSE 证伪门（11-13 笔记）同构：改前先在历史数据上回放证伪。依据：两周内两篇独立论文收敛到同一机制。机会=我的 skill 审查可用会话历史回放做零成本回归测试。
  • 判断4：上下文稳定性本身是训练信号（evolving Compression 消融），推断"边训边频繁改 prompt/压缩策略"的做法会回潮受质疑。对我=警示：Hermes 若做 agent RL 训练，context 管线要冻结版本。

  • 与 技能记忆多视角蒸馏内化（MDSKILL）：SkillRL 基线即"技能库随策略共进化"，本文证明类型化 trigger 引导比语义检索技能更精准——支持我把 skill 检索从纯语义升级为"语义+结构特征"

5.2 与 DUCK RL 训练

duck 训练中的课程/奖励塑形（BAM 域反射等）≈ steer 的连续版；"只干预模型学不会的失败"原则对应我们的"跺脚/步幅问题针对性加项"。replay 思想 = 用已存 eval 轨迹验证新 reward 项是否命中持续失败，而非盲目重训。

5.3 与项目

  • hermes-agent-self-evolution / deep-research-hermes 项目：P0 借鉴点直接对接（见行动启示）
  • context-compressor / MemDecay 笔记：compress 程序 = MemDecay 注意力刷新的确定性替代，在"零模型调用"维度互补

六、金句摘录

「The key insight is that the harness should guide only what the model cannot learn on its own.」——harness 只该管模型自己学不会的部分；其余交给权重。

「Because each trigger is a program, we can classify the failure type retrospectively.」——程序化的最大红利：历史可回放、失败可追溯。

七、行动启示与回访

我的结论：保留"replay 回放门禁 + 三判决准入 + 上下文冻结"三大机制；放弃"全量 LLM 在线改写 harness"路线的幻想；改造 skill-health-tier 为"历史会话回放判定"。

  • 行动1（P0）：给 skill 审查加 replay 判定——技能候选/存废判定改为在近 N 天会话日志上跑零模型调用的命中统计（trigger=结构特征如"连续失败≥2次/同类工具调用重复"），产出趋势曲线再准入。时间：本周内。触发：下次 session-evolution-scan 或 skill review 运行时。验收：能对任一 skill 输出"近 14 天命中趋势+intervene/monitor/continue 判决"。
  • 行动2（P1）：Hermes 上下文压缩策略版本化冻结——同一会话内禁止中途换压缩策略（对应 evolving Compression 消融的失败）。验收：context-compressor 使用处确认已是稳定版本。
  • 回访日期：2026-12-01
  • 待验证假设/证伪条件：若两周内出现"确定性程序化 harness 在开放对话域也胜过 LLM 改写"的论文，则判断2（分化）被证伪，需重评 LLM-as-harness 投入；若 replay 门禁在 skill 审查实测中命中率低于纯语义检索基线，则行动1 降级为 P2。

八、拓展应用推荐

  • cron/守望系统：把"何时退役一个 cron"做成 replay 统计——近 30 天触发记录回放，失败率持平/上升→intervene（改造），下降→continue（观察）
  • 量化交易：策略失效检测复用三判决——回撤事件在历史滚动窗口上的发生频率曲线，持平/上升才触发策略下线
  • 文档/笔记体系：笔记存废审查 = 对引用命中/回访记录做趋势回放，替代一次性清理
  • JBBlender/长任务开发：bug 修复验证用"历史操作序列回放"做回归（对应 replay 零成本思想）

九、指南分析

  • 方法论价值：把"不可优化的工程资产"（harness）通过表示变革（手写→类型化状态上的程序）变成可搜索可验证可进化的对象——表示决定可优化性，这是普适判据
  • 实验设计范式：单变量拆解（+Compression/+Steering/完整）+ 成本账（token/墙钟/教师调用三口径）+ 反直觉消融（共进化>序贯、冻结>演化）三件套值得照抄进任何"组件有效性"论证
  • 写作结构：两个核心问题（如何表示/如何进化）统领全文，Algorithm 1 + Figure 2/3/7 使管线可复现——技术报告的清晰度标杆
