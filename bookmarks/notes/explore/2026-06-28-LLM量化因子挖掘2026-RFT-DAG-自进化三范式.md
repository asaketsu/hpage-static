## 一、摘要

LLM 驱动的量化 Alpha 因子挖掘在 2026 年完成了从「Prompt 级循环」到「参数级内化」再到「全局拓扑进化」的三级跳。本笔记基于三篇 2026 年代表作——**QuantEvolver**（用强化微调替代 prompt 循环）、**AlphaPROBE**（DAG 全局拓扑 + 贝叶斯检索）、**QuantaAlpha**（开源自进化框架）——提炼出因子挖掘领域的方法论演进主线、关键技术突破与对 Hermes 量化系统的实践价值。

## 二、核心发现

### 1. 第一代方法的根本瓶颈：Prompt 级循环的四重病

QuantEvolver 论文精准诊断了当前主流 LLM 因子挖掘方法（如 FinGPT、AlphaEvolve 的 prompt 版）的四大顽疾：

| 病灶 | 机制 | 后果 |
|------|------|------|
| **Context 爆炸** | 每轮迭代把历史候选 + 反馈都 append 进 prompt | 推理成本飙升，有用信息被稀释 |
| **Feedback Drift** | 长循环中反馈语义漂移 | 后期优化方向偏离初始目标 |
| **Search Stagnation** | 大 LLM 生成偏好稳定 → 结构相似表达式 | 候选因子高度冗余，探索停滞 |
| **依赖超大模型** | 只有大模型才能维持「生成-评估」质量 | 部署成本高，不可平民化 |

**根因**：这些方法把「优化经验」存在 **prompt 里**（上下文），而非**模型参数里**。经验越积越多，prompt 越来越长，边际收益递减。

### 2. QuantEvolver 的破局：把评估反馈转成 Policy Update

QuantEvolver（arXiv:2605.15412，北大 + 港中文团队）的核心创新——**用强化微调（RFT）替代 prompt 级反馈循环**：

```
传统：Prompt(种子+历史+反馈) → LLM生成 → 评估 → 反馈 append 回 Prompt（循环）
QuantEvolver：种子构造 → 多时间窗训练任务 → Factor DSL生成 → Regime Backtest评估 → 
             Diversity-Complementarity Reward → Miner LLM 参数更新 → 
             高质量因子沉淀到 Mined Factor Database
```

**三个关键设计**：

- **Miner LLM**：一个专门「挖因子」的小模型，通过 RL 训练把历史优化经验**内化到权重**，而非堆在 prompt 里。解决 context 爆炸 + feedback drift。
- **Diversity-Complementarity Reward**：奖励函数同时考虑「多样性」和「互补性」——不只奖励高收益因子，还奖励与现有因子池**低相关**的新因子。直接对抗 search stagnation。
- **Regime Backtest（制度感知回测）**：在不同市场制度（牛/熊/震荡）下分别回测，避免过拟合单一制度。与 walk-forward-validation 理念一致。

**结果**：在三个真实市场基准上，QuantEvolver 在每个基准的主评估指标上都持续提升，且无需依赖超大模型（小 Miner LLM + RL 即可）。

### 3. AlphaPROBE 的拓扑革命：把因子池建模为 DAG

AlphaPROBE（arXiv:2602.11917，清华团队）从**全局结构**角度重新定义问题：

**问题诊断**：现有自动化因子挖掘分两派——
- **Decoupled Factor Generation（解耦生成）**：把每个因子当孤立事件，无视因子间演化关系 → 冗余搜索
- **Iterative Factor Evolution（迭代进化）**：只关注局部父子精炼（parent→child）→ 多样性受限

两者都**缺乏全局结构视角**，把因子池当成无结构集合或碎片化链条。

**AlphaPROBE 的解法**：把因子挖掘重新定义为**有向无环图（DAG）上的策略性导航**：
- 节点 = 因子，边 = 演化关系（谁由谁改进而来）
- 因子池 = 一个动态、互联的生态系统（ecosystem），而非扁平列表

**两大核心组件**：

1. **Bayesian Factor Retriever（贝叶斯因子检索器）**：用后验概率模型识别高潜力种子，**平衡 exploitation（利用已知好因子）和 exploration（探索新方向）**。本质是一个带不确定性估计的检索器。
2. **DAG-aware Factor Generator（DAG 感知生成器）**：利用因子的**完整祖先轨迹（full ancestral trace）**生成上下文感知、非冗余的优化。生成新因子时「知道」它从哪来、和谁是亲戚，避免重复造轮子。

**结果**：在三个主要 A 股数据集上对比 8 个 baseline，AlphaPROBE 在预测精度、收益稳定性、训练效率上均显著提升。**已开源**。

### 4. QuantaAlpha：开源工程化框架

QuantaAlpha（GitHub: QuantaAlpha/QuantaAlpha，arXiv:2602.07085）把上述理念做成**开箱即用的开源框架**：

- **核心理念**：trajectory-based self-evolution（基于轨迹的自进化）——与主题1的自进化 Agent 综述完全呼应。
- **三阶段流程**：Diversified Planning Initialization（多样化规划初始化）→ Trajectory-Level Evolution（轨迹级进化）→ Structured Hypothesis-Code Constraint（结构化假设-代码约束）。
- **工程亮点**：提供 Web Dashboard + 完整 demo 视频，研究方向描述 → 自动挖矿 → 回测 UI 全流程可视化。Python 3.10+，MIT 协议。

**价值**：这是目前最完整的「LLM + 进化策略」因子挖掘开源实现，可作为 Hermes a-stock-quant-system skill 的参考架构。

### 5. 三范式的演进主线

把三篇论文放在一条时间线上，清晰的方法论演进：

```
第一代：Prompt 级 generate-evaluate-feedback 循环
  └─ 病：context 爆炸 / feedback drift / search stagnation
  
第二代：QuantEvolver —— RFT 参数级内化
  └─ 治：经验进权重，Diversity-Complementarity Reward 抗冗余
  
第三代：AlphaPROBE —— DAG 全局拓扑 + 贝叶斯检索
  └─ 突破：因子池=生态系统，祖先轨迹感知，exploitation/exploration 平衡

工程化：QuantaAlpha —— 开源自进化框架
  └─ 落地：trajectory-based evolution + Web UI + 全流程可视化
```

**深层逻辑**：从「平面搜索」→「参数内化」→「拓扑导航」，每一次跃迁都让搜索空间的结构更被显式利用。这与 Self-Evolving Agents 综述的 L3/L4 进化（工具/架构层进化）是同一思想在不同领域的投射。

## 三、技术细节

### QuantEvolver 的 Diversity-Complementarity Reward 设计

这是最值得借鉴的奖励设计。传统因子挖掘奖励只看「这个因子本身好不好」（如 IC、夏普），导致挖出的因子高度同质。QuantEvolver 的奖励同时考虑：

- **Individual Quality**：因子自身的预测力（IC/IR）
- **Diversity**：与现有因子池的表达式/逻辑差异度
- **Complementarity**：加入后对组合的边际增量（正交性）

伪代码逻辑：
```python
def diversity_complementarity_reward(new_factor, factor_pool, returns):
    individual = ic(new_factor, returns)           # 个体质量
    diversity = 1 - max_similarity(new_factor, factor_pool)  # 多样性
    # 用现有池对新因子做回归，残差=不可被现有因子解释的部分
    residual = orthogonalize(new_factor, factor_pool)
    complementarity = abs_corr(residual, returns)  # 互补性
    return w1*individual + w2*diversity + w3*complementarity
```

**对 Hermes 的启发**：a-stock-quant-system 的因子库管理可以引入类似的「边际增量」评估——新因子入库前，先计算它对现有因子池的正交边际贡献，低于阈值则拒绝。

### AlphaPROBE 的贝叶斯检索 + DAG 导航

```python
# 简化的 AlphaPROBE 流程
class AlphaPROBE:
    def __init__(self):
        self.dag = FactorDAG()  # 因子有向无环图
        self.retriever = BayesianFactorRetriever()
        self.generator = DAGAwareGenerator()
    
    def mine(self, n_rounds):
        for _ in range(n_rounds):
            # 1. 贝叶斯检索：平衡 exploit/explore 选种子
            seeds = self.retriever.select_seeds(self.dag, 
                       exploit_ratio=0.7, explore_ratio=0.3)
            # 2. DAG 感知生成：用完整祖先轨迹生成非冗余改进
            for seed in seeds:
                ancestors = self.dag.get_ancestral_trace(seed)
                new_factor = self.generator.generate(seed, ancestors)
                # 3. 评估 + 入图
                if self.evaluate(new_factor):
                    self.dag.add_node(new_factor, parent=seed)
```

**关键洞察**：贝叶斯检索器的 exploit/explore 平衡，本质是「**已知好方向深挖 vs 未知方向试错**」的经典 bandit 问题。DAG 的祖先轨迹则提供了「**这个因子已经试过哪些变种**」的记忆，避免重复。

## 四、实践启发

1. **从 Prompt 循环升级到参数内化**：Hermes 当前如果有 LLM 因子生成的 cron（如 llm-factor-mining skill），应评估是否还停留在 prompt 级循环。QuantEvolver 证明：把反馈转成 policy update（即便用轻量 LoRA）比堆 prompt 有效得多。

2. **因子池应该是图，不是列表**：a-stock-quant-system 的因子管理如果只是扁平存储（文件/数据库表），会丢失因子间的演化关系。引入 DAG 结构（因子节点 + 改进边）+ 祖先轨迹，能大幅减少冗余挖掘。

3. **Diversity-Complementarity Reward 可立即移植**：即使不做 RFT，这个奖励设计也可以用在「因子入库筛选」环节——新因子若与现有池高度相关（cosine similarity > 0.9）且无正交边际贡献，直接拒绝。这是低成本高收益的改进。

4. **Regime Backtest 与 walk-forward 互补**：QuantEvolver 的制度感知回测（牛/熊/震荡分别测）与 Hermes 的 walk-forward-validation skill 是同一防过拟合理念的两个维度——一个切时间窗，一个切市场制度。两者结合能形成更鲁棒的因子验证。

5. **QuantaAlpha 可作为参考实现**：开源 MIT 协议，Python 3.10+，有 Web UI。值得 clone 下来研究其 trajectory-based evolution 的工程实现，提取可复用模式到 a-stock-quant-system skill。

## 五、知识缺口与后续探索

1. **QuantEvolver 的 Miner LLM 多大才够**：论文说「无需超大模型」，但具体参数量级（7B? 14B?）和训练数据量未从摘要获取。需读全文或复现确认在 Hermes Jetson 环境的可行性。
2. **DAG 的维护成本**：因子池增长到几千个节点后，祖先轨迹查询和贝叶斯检索的计算成本如何？是否需要图数据库（Neo4j）还是内存图够用？
3. **A 股制度划分的自动化**：Regime Backtest 需要先划分市场制度，这本身是个预测问题。如何自动化制度识别（HMM? 聚类?）？Hermes 的 quant-ou-estimator skill（OU 过程）可能相关。
4. **LLM 生成的 Factor DSL 表达式空间**：三篇论文都提到「Factor DSL」（领域特定语言），但 DSL 的具体语法和算子集未详述。需调研 QuantEvolver/AlphaPROBE 用的 DSL 是否兼容国内数据源（如 tushare/akshare 的字段名）。
5. **与现有 quant skills 的整合路径**：Hermes 已有 agentic-alpha-research、llm-factor-mining、quant-ic-validation、quant-ml-pipeline 等 skill。这三篇论文的方法应如何拆分 patch 进现有 skill，而非新建重复 skill？
