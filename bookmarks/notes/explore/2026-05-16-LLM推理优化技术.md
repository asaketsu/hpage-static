## 核心优化方向

### 1. 量化 (Quantization)

| 方法 | 精度 | 适用场景 | 工具 |
|------|------|----------|------|
| INT8 动态量化 | 8-bit | 通用推理 | PyTorch quantization |
| INT4 GPTQ | 4-bit | 大模型部署 | AutoGPTQ |
| INT4 AWQ | 4-bit | 保留权重重要性 | AWQ |
| FP8 | 8-bit (float) | H100/A100 | TransformerEngine |
| GGUF | 多种 | CPU推理 | llama.cpp |

**关键发现**:
- AWQ 在 4-bit 下能保留 99%+ 的模型性能
- GPTQ 适合离线量化，AWQ 适合在线/激活感知
- FP8 需要 Hopper 架构 GPU，但精度损失最小

### 2. 推理引擎优化

| 引擎 | 特点 | 适用场景 |
|------|------|----------|
| vLLM | PagedAttention, 高吞吐 | 多请求并发 |
| TensorRT-LLM | 深度优化, 低延迟 | 生产部署 |
| llama.cpp | CPU/GPU混合, 轻量 | 边缘设备 |
| ONNX Runtime | 跨平台 | 多硬件支持 |

**vLLM 核心创新**:
- PagedAttention: 类似 OS 虚拟内存，解决 KV cache 碎片化
- Block table 管理: 动态分配 KV cache 块
- 支持连续批处理 (continuous batching)

### 3. 蒸馏 (Distillation)

- **任务蒸馏**: 大模型 → 小模型 (知识迁移)
- **响应蒸馏**: 仅用输出分布训练
- **中间层蒸馏**: 模仿隐藏层表示

**最佳实践**:
- 教师模型: 70B+ 参数
- 学生模型: 7B-13B 参数
- 数据: 100K-1M 高质量样本

### 4.  speculative decoding

```
标准解码:    1 token / step
Speculative: N tokens / step (并行验证)

加速比: 1.5x - 3x (取决于草稿模型质量)
```

**实现方案**:
- Medusa: 多个头部预测
- Lookahead Decoding: N-gram 猜测
- EAGLE: 训练专用草稿模型

## 推荐部署方案

### 云端高吞吐
```
vLLM + AWQ INT4 + 多卡并行
→ 适合: API 服务, 多租户
```

### 边缘低延迟
```
llama.cpp + GGUF Q4_K_M
→ 适合: 本地应用, 移动端
```

### 生产级
```
TensorRT-LLM + FP8 + 自定义 kernel
→ 适合: 大规模生产环境
```
