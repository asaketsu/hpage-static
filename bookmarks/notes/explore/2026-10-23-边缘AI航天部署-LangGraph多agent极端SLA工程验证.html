生成日期 2026-10-23

摘要

NAVI-Orbital（NASA JPL + Loft Orbital，2026-04-16 在轨实证）是 LangGraph 多 agent 编排在航天级 SLA 下的首个飞行验证。10-11 笔记已覆盖模型层（Gemma3-4B Q4 + 26.6s/图）；本篇深挖编排层：为什么选 LangGraph 而不是 MCP、Conductor Graph 四子图如何实现确定性转换、20s inter-capture cadence 背后的完整 SLA 参数链（输出 cap/温度/重试预算/线程分工）、以及作者对"随机 VLM 进入确定性飞行软件域"的结构性限制论断——这条论断与航空适航（CCAR 25.1309 级确定性要求）面对 AI 软件入域的矛盾完全同构。

关键发现（增量，10-11 笔记未覆盖）

1. LangGraph vs MCP 的选型决策——确定性转换是唯一理由

论文明确披露：架构评估阶段考虑过 Anthropic MCP 作为编排框架备选，最终选 LangGraph 的决定性理由是——graph-based state machine 提供 deterministic, verifiable transitions between operational phases（运行阶段间的确定性、可验证转换），这是星载应用的硬要求：可预测行为 + 状态可追溯。

启示: 编排框架选型在安全关键域的第一判据不是生态/工具丰富度，而是状态转换是否可形式化验证。MCP 是工具连接协议，LangGraph 是显式状态机——两者不在同一层，但 NAVI 团队把它们放在同一决策桌上比较过，这个对比本身就是选型方法论样本。

2. Conductor Graph 四子图——持续自主处理环

LangGraph 实现的 Conductor Graph 是有向状态图，由四个可组合子图构成：

Init ──> Experiment ──> Detection ──> Dialogue ──┐
(加载配置)  (三级加载优先)   (classify-retry)  (交互/批式)
   ^                                            │
   └────────── end_experiment 循环回 load_next ──┘
  • Init 子图: 加载 global_settings.json，实例化 VLM adapter
  • Experiment 子图: 三级实验加载优先序——①未处理的实验文件夹 → ②强制模板实验（预载数据集）→ ③live inbox 轮询（可配置 sleep 间隔）；条件边在无任务时路由到 poll-sleep 循环
  • Detection 子图: classify-with-retry 循环 + 每次分类后条件边判断队列剩余
  • Dialogue 子图: 聚合检测结果进上下文窗口，条件分支 interactive（live chat）/ non-interactive（文件批式）
  • Status 枚举（IDLE/TRANSITION/DETECTION/DIALOGUE）正交于图节点，专用于日志和状态持久化

3. 20s cadence 的 SLA 参数分解——五件套

20 秒 inter-capture cadence 不是单点优化，是一条参数链：

  • 异构分工: transformer 层全量 GPU offload 主导 token 生成；4 条 CPU 线程管 tokenization/采样/图像 IO marshalling/LangGraph 状态管理（编排开销被显式隔离在 CPU 侧）
  • 上下文窗口 20,000 tokens: 容纳 Pan-and-Scan 高分辨率 patch embedding + 完整结构化 prompt，不截断
  • 输出 cap 1,000 tokens: 硬性 bound 单图延迟和内存分配
  • temperature 0.2: 压制随机性，保证 regex 解析在重试循环中稳定命中
  • 重试预算: 地面 3 次 / 飞行 10 次 + 30 秒 inter-attempt sleep——对空间瞬态硬件/调度异常的韧性，确保单次过境（pass）内不需要地面干预

实测锚点（Flatsat, Comp2 bare-metal）: 5 图 13 分钟（avg 26.6s/图）vs CPU-only 37 分钟；GPU 频率（GR3D）每个 VLM 周期打满外部内存控制器利用率，功耗遥测呈 GPU 尖峰 + CPU 持续负载的锯齿形态。

4. 可靠性实测——0.05% parse fail 与重试收敛律

  • 7,960 次推理中 4 次（0.05%） 未能产出可解析标签
  • 2 次被 retry 机制在后续尝试解决；2 次永久失败——模型发明标签外词（"Golf Course"、"Park"，后者还带伪造 Markdown 格式）
  • 重试机制整体收敛率 >99.9%
  • 失败根因: 通用预训练知识 vs 受限标签集的张力——图像视觉高度歧义或骑跨类边界时，模型倾向输出它认为"描述更准确"的标签而非最近的合法选项
  • Parse failure rate 被论文显式用作幻觉率的代理指标（与 aircraft-req-sft 项目的 parse_fail_rate 双指标纪律同构）

5. 结构性限制论断——随机性无法 bound（本篇最重要洞察）

论文 VII-B 原文：系统的首要限制是结构性的而非经验性的——把随机 VLM 部署进一个以确定性、可形式化验证行为为工程惯例的域（自主飞行软件）。没有任何 retry 机制、regex 输出门或采样温度设置能消除幻觉的可能性；这些缓解措施降低其频率但不能 bound 它。要集成进更广的在轨自主操作（如基于 VLM 输出 tasking 其他星载子系统），需要 NAVI 当前实现之外的建筑级处理：supervisor agents + deterministic fallbacks，且取决于依赖动作的安全包络。

与适航同构: 这正是 AI 软件进 CCAR/25.1309 级确定性审定域的核心矛盾——缓解措施（restricted label set + regex gate + 低温采样 + retry）是频率控制手段，而适航思维要求的是概率边界（bound）证明。论文作者诚实地承认"生产集成是社区尚未解决的另一个工程问题"，这种诚实本身就是高质量研究的标志。

6. 裸机 vs 容器——集成时刻的 GPU 访问陷阱

容器化是团队首选运行模型，但集成时刻没有任何测试过的容器镜像能同时提供可靠 GPU 访问 + Python 3.12 + CUDA 依赖→ 飞行配置改为裸机 Python venv（Comp2）。发射后新版 NVIDIA container 发布才在 Flatsat 验证了容器化执行，但未上传。工程教训原文："卫星级边缘处理器上容器与裸机硬件加速的 parity 不应在任务集成时刻被假设；规划裸机 fallback 值得这份工程成本"。

7. 磁盘状态持久化 = 无人值守自主恢复

编排状态在处理步骤之间持久化到磁盘是 NAVI 自主恢复的设计模式。LangGraph 实现，但模式可迁移到任何在转换间序列化图状态的框架。对在轨运行（地面干预不总是可得）这是防御性工程（defensive engineering）。

8. 语义压缩量化收口

检测输出每条 700-1060 bytes（JSON: 标签+自由文本场景描述+推理元数据）vs 全分辨率 YAM-9 原图 9-14 MB ≈ 四个数量级压缩。10-10 语义压缩笔记的"压缩即 embedding"命题在此拿到精确数字锚点。

与现有工作的关联

P0（Hermes 直接可抄）:
- 磁盘状态持久化模式 → hermes-disaster-recovery skill 的编排状态检查点可吸收"转换间序列化"粒度（当前是进程级守护，可加图状态级）
- "4 CPU 线程隔离编排开销"模式 → Jetson 上 LuxTTS daemon / 推理任务的 CPU-GPU 分工基线

P1（方法论迁移）:
- 30s inter-attempt sleep + 温度 0.2 + regex 验证门三件套 → 任何 LLM 结构化输出流水线（含 aircraft-req-sft 的 parse_fail_rate 治理）的鲁棒性清单
- "容器 parity 不假设 + 裸机 fallback 先行" → Jetson 部署链的验收前检查项

P2（知识域）:
- LangGraph vs MCP 决策样本 → agent-orchestration-pattern / mcp-integration skill 的选型章节可补此案例：安全关键域第一判据=状态转换可形式化验证
- "随机性缓解 vs bound"论断 → 适航 AI 软件入域讨论的权威引用（arXiv 2606.18271 VII-B）

关键风险与盲点

  • 在轨 live 样本仅 2 次 YAM-9 捕获（作者自认：可行性结果而非鲁棒性表征，adversarial prompt 完全未测）——官方论文自认，可信度高
  • Dialogue agent 只测了 16 个 scripted questions/experiment，矛盾/虚假前提/无证据问题未覆盖——官方验证
  • "20s cadence"是 inter-capture 间隔而非端到端延迟承诺；26.6s avg cycle 与 20s cadence 的关系（pipeline 并行/排队模型）论文未完全展开——社区复现待观察
  • IEEE Spectrum 报道的技术细节均转引论文，无独立信源——媒体报道级
