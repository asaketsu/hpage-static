## 一、内容整理

### 1.1 核心问题：Agent 转录本的两类泄露面

LLM Agent 在执行任务时持续访问文件系统、Shell、进程列表、配置文件和外部服务，这些工具调用的输出被自动追加到面向模型提供商的转录本（transcript）中。即使没有用户显式输入，转录本也可能包含大量敏感信息。

论文定义了两类截然不同的泄露面：

**结构绑定（Structural Bindings）**
- 标识用户/组织/执行环境但不一定授予权限的信息
- 示例：绝对路径（`/Users/alice/acme/legal/layoff_bob.pdf`）、主机名、分支名、邮箱、实体名称
- 危害：暴露用户身份、组织结构、项目语义内容

**秘密值（Secret Values）**
- 凭证形态的字符串，泄露后可能授予实际权限
- 示例：API 密钥、令牌、密码、数据库凭证、签名材料
- 典型泄露场景：`ps` 命令打印进程命令行时暴露 `AZURE_OPENAI_KEY="${AZURE_OPENAI_KEY:-<raw-key>}"` 形式的环境变量回退值

> **关键洞察**：这两类泄露面以不同方式失败——凭证扫描器可能漏掉语义敏感的文件名/实体名，而路径消毒器可能漏掉嵌入在 URL、Shell 命令、进程列表或配置片段中的令牌。

### 1.2 威胁模型：诚实但好奇的上游提供商

- **假设**：上游模型提供商（OpenAI、DeepSeek 等）推理正确，但面向提供商的提示、工具输出和转录本**可能被保留**
- **信任域**：本地运行时、工具、文件、SlotGuard 边界本身可信
- **现实依据**：
  - 消费级 AI 提供商可能使用用户内容训练模型（除非用户主动关闭）
  - 即使禁用模型训练，服务端仍可能保留、记录或缓存转录本
  - 运营故障可能暴露跨用户元数据（如 ChatGPT 曾出现用户可看到他人聊天标题的事故）
  - Provider 端推理系统缓存提示和前缀以提升服务效率（如 vLLM/PagedAttention）

### 1.3 SlotGuard 设计：兼容性保留的本地边界

SlotGuard 是部署在 Agent 运行时与上游模型之间的**本地转录本边界层**。核心部署点是 Agent harness，在提示、工具调用、工具输出、Shell stdout/stderr、进程列表和文件内容被追加到面向提供商的转录本之前进行拦截。

**两层检测器**

- **同步层（高精度启发式引擎）**：已知工作区根、路径解析器、邮箱、主机名、分支名、环境变量赋值、Shell 参数展开、凭证标志、授权头、URI 凭证、提供商特定令牌模式
- **异步层（可选本地小模型）**：处理规则难以编码的语义场景（敏感文件名、实体名、客户名、项目名）。本地模型不直接改写转录本，仅提议行号、逐字跨度和槽位类型，SlotGuard 验证后才采纳

**兼容性保留改写原则**

移除原始私有值，但保留 Agent 在无保护执行中依赖的工作流级信号：路径形态、文件类型、稳定句柄、可解析命令、格式有效的凭证代理。

**结构绑定 — 确定性类型化槽位**

```
h(v) = HMAC_{k_s}(τ(v) || v)
```

- `k_s`：每会话密钥
- `τ(v)`：槽位类型
- 句柄在会话内稳定，跨会话不可链接

路径采用后缀感知抽象——替换最长可信根，抑制敏感中间组件，保留有界任务相关后缀：

```
/Users/alice/acme/legal/layoff_bob.pdf
→ [REPO_ROOT_1]/legal/[SENSITIVE_DOC_1].pdf
```

结果仍保持路径形态，保留目录角色和文件类型，同时移除用户、组织和敏感文档标识符。

**秘密值 — 格式保留合成替换（FPS）**

不用通用标签（如 `API_KEY`），而是从秘密的格式类中采样全新的合成值：

```
h(v) ~ Uniform(F_{τ(v)})
```

合成令牌存储在会话表中供后续出现复用。数据库 URI 保持可解析，命令行凭证保持凭证形态，环境回退保持语法配置——但合成值不含任何从原始秘密派生的字符。

> **信息论保证**：在格式类条件下，`I(FPS(v); v | τ(v)) = 0`——格式保留替换值与原始值之间的互信息为零。

**语义实体图（SEG）**

SlotGuard 维护会话范围的语义实体图来扩展超出精确字符串匹配的保护。节点是受保护值或其代理，边编码共指、嵌入、派生和间接引用。SEG 记录受保护值与已观察变体之间的保守链接——包括嵌入出现、简单派生形式和后续基于关键词的引用。

**受保护重绑定（Guarded Rebinding）**

上游模型只看到类型化槽位和 FPS 令牌，原始值仅在受信任运行时内为经过验证的本地执行恢复：
- 结构绑定：检查句柄存在于会话表中、具有预期类型、在允许范围内重绑定；拒绝未知句柄、伪造段、超出范围的路径和 Shell 元字符注入
- 秘密值：仅当本地工具调用需要时解析为原始凭证，注入到进程/环境变量/请求字段/连接字符串中，不写回面向提供商的转录本

### 1.4 评估结果

**RQ1-RQ2：隐私效果（Table 1）**

- 原始转录本暴露 20,814 个标注敏感字符 → SlotGuard 移除全部上游可见结构泄露
- 93.6% 改写路径保留原始扩展名，100% 保留至少一个安全后缀组件
- 类型化占位符 + 仅 FPS 仍泄露 23.5% 植入凭证（分裂和嵌入暴露仍可重构）
- 完整 SlotGuard（含 SEG）：0/200 会话泄露，0/852 植入值泄露

**RQ3：工作流兼容性（Table 2 — 200 任务 × 4 模型）**

- 通用脱敏：所有模型任务成功率坍塌至 2.5%
- VibeGuard 风格类型化占位符：20.5%-38.5%
- 完整 SlotGuard：接近原始基线
  - DeepSeek-V3.2：原始 100% → SlotGuard 89.5%（-10.5pp）
  - gpt-5.4：原始 100% → SlotGuard 98.0%（-2.0pp）
  - Kimi-K2.6：原始 100% → SlotGuard 100%（持平）
  - Llama-3.3-70B：原始 93.5% → SlotGuard 93.5%（持平）

**TAC-lite 回放基准（Table 3）**

- 同样的排序：通用脱敏 0%，VibeGuard 26.9-36.9%，SlotGuard 在 3/4 模型上匹配原始分

**RQ4：热路径实用性**

- 路径改写：中位数 1.69μs，映射回 0.398μs
- 完整 Agent 轮次消毒：14.42μs（6KB 轮次仍 <100μs）
- 可选本地语义检测器：742ms 热中位数（不依赖快速路径，仅提议候选敏感跨度）
- 鲁棒性：9,229 条改写路径全部正确往返，64 次无效重绑定尝试全部被拒绝

### 1.5 局限性与未来方向

论文诚实地列出了四个开放方向：

1. **评估局限性**：当前使用合成和回放式工作负载（植入真实标记），在具有自然发生敏感数据的生产 Agent 轨迹上验证会加强实践评估。小型真实部署案例研究是自然的下一步
2. **对抗重构**：不测量有能力的攻击者主动尝试从残留上下文中恢复受保护值的对抗重构评估
3. **SEG 局限**：当前 SEG 通过关键词和模式链接可靠地处理简单引用，但不尝试更难的间接引用（如释义共指或隐含推理链）
4. **基线对比不足**：未与生产密钥扫描器、企业 DLP 系统或 LLM 特定护栏产品比较

> **重要免责声明**：SlotGuard 不是完整的匿名化系统——它无法防止来自非字面上下文的语义推断、保护受损的本地运行时、或阻止提示注入驱动的数据外泄。它应作为更广泛隐私架构中的一层部署。

## 二、查询拓展

### 2.1 Provider-Bound Transcript（面向提供商的转录本）

在 LLM Agent 架构中，每次工具调用的输出（stdout/stderr/文件内容/进程列表）都会被追加到对话上下文，并在下一轮推理时发送给模型提供商。这意味着即使本地运行时删除了敏感值，只要它曾经进入过上下文窗口，就已经"离开了本地信任边界"。这是 Agent 隐私问题的核心——与传统 API 调用不同，Agent 的多轮交互会**累积性**地暴露信息。

### 2.2 Format-Preserving Encryption / Tokenization（格式保留加密/令牌化）

FPS 的思想源自密码学中的格式保留加密（FPE）和数据库安全中的令牌化（Tokenization）技术。传统令牌化将敏感值替换为随机令牌但可能破坏格式（如 `sk-abc123` → `TOKEN_001`），而 FPS 保持原始格式约束（长度、字符集、校验位），使依赖格式的系统（如 URL 解析器、正则验证器）无需修改即可工作。SlotGuard 的创新在于将这一技术应用于 Agent 转录本，且证明了在格式类条件下的信息论互信息为零。

### 2.3 Honest-but-Curious Provider（诚实但好奇的提供商）

这是安全多方计算中的经典威胁模型。应用于 LLM 场景："诚实"指提供商正确执行推理（不返回错误结果），"好奇"指提供商可能保留/检查/记录提交的内容。即使提供商声称不训练模型（如 OpenAI 的企业 API 隐私承诺），服务端日志、缓存系统、运维故障仍可能导致数据暴露。

### 2.4 PagedAttention 与 Prefix Caching 的隐私风险

论文引用的 KVCache/PagedAttention 研究揭示了另一层风险：为了加速推理，服务端会缓存前缀（系统提示 + 历史对话）并跨请求复用。这意味着包含敏感信息的转录本片段可能被缓存在服务端内存中，比单次请求的暴露窗口更长，且可能被其他用户的请求间接触发。

### 2.5 VibeGuard / Typed Placeholder 方案对比

VibeGuard（inkdust2021）是一个基于规则的脱敏工具，将敏感值替换为类型化占位符（如 `<API_KEY>`）。论文实验证明这类方案的两个缺陷：1）通用标签破坏格式语法导致模型生成不可执行命令；2）无法处理嵌入和分裂暴露（同一密钥分布在多个位置时，部分脱敏仍可重构）。SlotGuard 的 FPS 方案在保持语义的同时解决了这两个问题。

### 3.1 SlotGuard 三层架构框架

```
┌─────────────────────────────────────────────────────┐
│                  Agent Runtime                      │
│  (文件系统 / Shell / 进程 / 配置 / 外部服务)         │
└──────────────────────┬──────────────────────────────┘
                       │ 原始工具输出
                       ▼
┌─────────────────────────────────────────────────────┐
│              SlotGuard 本地边界层                    │
│                                                     │
│  ┌─────────────────────────────────────────────┐   │
│  │       两层检测器 (Two-Tier Detector)         │   │
│  │  同步层：启发式规则（路径/邮箱/主机/凭证）    │   │
│  │  异步层：本地小模型（语义敏感文件/实体名）    │   │
│  └─────────────────────┬───────────────────────┘   │

│                        ▼                            │
│  ┌─────────────────────────────────────────────┐   │
│  │     兼容性保留改写 (Compatibility Rewrite)   │   │
│  │                                             │   │
│  │  结构绑定 → HMAC 类型化槽位 + 后缀感知抽象   │   │
│  │    [REPO_ROOT_1]/legal/[SENSITIVE_DOC_1]    │   │
│  │                                             │   │
│  │  秘密值 → 格式保留合成替换 (FPS)             │   │
│  │    h(v) ~ Uniform(F_{τ(v)})                 │   │
│  │    I(FPS(v); v | τ(v)) = 0                  │   │
│  │                                             │   │
│  │  会话槽位表 T: V → H + 语义实体图 (SEG)      │   │
│  └─────────────────────┬───────────────────────┘   │
│                        │ 消毒后的转录本               │
└────────────────────────┼────────────────────────────┘

            ▼                         ▼
  ┌──────────────────┐     ┌──────────────────────┐
  │  上游模型提供商   │     │  受保护重绑定         │
  │  (只看到槽位/    │     │  (仅本地运行时执行)   │
  │   FPS 合成值)    │     │  验证句柄→恢复原始值   │
  └──────────────────┘     └──────────────────────┘
```

### 3.2 脱敏方案效果对照

- **Raw（无保护）**：100% 凭证泄露，100% 结构泄露
- **Generic Redaction（通用脱敏）**：任务成功率坍塌至 2.5%（格式破坏导致命令不可执行）
- **VibeGuard 类型化占位符**：任务成功率 20.5%-38.5%（格式部分破坏 + 分裂暴露仍可重构）
- **SlotGuard（完整）**：任务成功率 89.5%-100% + 0% 泄露（格式保留 + SEG 交叉引用追踪）

### 3.3 关键性能指标

- 路径改写中位数延迟：1.69μs
- 路径重绑定中位数延迟：0.398μs
- 完整 Agent 轮次消毒：14.42μs（亚毫秒级，热路径零阻塞）
- 路径往返正确率：9229/9229（100%）
- 无效重绑定拦截率：64/64（100%）
- 可选语义检测器 F1 提升：0.571 → 0.909

## 四、趋势判断

### 趋势1：Agent 隐私将成为 Agent 平台化的硬约束

随着 Agent 从单机实验走向企业级部署，数据泄露风险（GDPR/SOC2/行业合规）将从"可选增强"变为"必须解决的准入门槛"。SlotGuard 代表的方向——在 Agent harness 层植入隐私边界——将成为 Agent 平台的标准组件，正如 TLS 成为 Web 的标准组件。预计 12-18 个月内，主流 Agent 框架（LangChain/CrewAI/AutoGen）将内置类似机制。

### 趋势2：格式保留是 Agent 脱敏的唯一可行路线

论文实验明确证明通用脱敏导致任务成功率从 100% 坍塌至 2.5%——这不仅是性能下降，而是功能丧失。Agent 的推理高度依赖格式线索（文件扩展名、URI 语法、命令行参数结构），任何破坏格式的脱敏方案在 Agent 场景下都不具备实际可用性。FPS + 类型化槽位将是 Agent 脱敏的技术基线。

### 趋势3：本地边界层将成为 Agent 安全的新抽象

当前 Agent 安全研究集中在 prompt injection 防御和输出过滤。SlotGuard 提出了一个更底层的安全原语：在工具输出和模型输入之间植入可编程边界层。这一抽象可以扩展到隐私之外——例如审计日志、成本控制、策略执行、速率限制——形成 Agent 安全的统一中间件层。

### 趋势4：语义实体图的持续进化

当前 SEG 仅支持关键词和模式链接。随着本地小模型能力提升（Phi-3、Gemma-2 级别），SEG 将进化到支持释义共指和隐含推理链的检测，使跨轮次、跨工具的累积泄露防护更加鲁棒。这与 Hermes memory graph 的实体链接机制有深度技术共鸣。

## 五、关联分析

### 5.1 与 Hermes Agent 转录本安全直接关联

Hermes Agent 的每一次工具调用都会将输出追加到发送给智谱（zai/GLM）提供商的上下文中。当前完全没有任何隐私边界：
- 所有文件路径（`/home/jc/uclaw/...`）以明文形式暴露
- Shell 命令输出中的环境变量、API 密钥以明文形式暴露
- `grep`/`cat`/`read_file` 的输出直接进入转录本

SlotGuard 的本地边界层架构可以直接作为 Hermes Gateway 中间件实现，在工具输出进入 LLM 上下文之前执行路径抽象和密钥 FPS 替换。

### 5.2 与 agent-security-governance / auto-defense-check 的关联

Hermes 已有的 `agent-security-governance`（零信任多 Agent 安全基线）和 `auto-defense-check`（~/.hermes/ 目录安全检查）关注的是权限和配置安全。SlotGuard 补充了一个**缺失维度**——转录本内容安全。三者形成完整的安全层级：权限治理（谁能做什么）→ 配置安全（什么被暴露了）→ 转录本隐私（暴露的内容如何脱敏）。

### 5.3 与 Memory Graph 的技术共鸣

SlotGuard 的 SEG（语义实体图）与 Hermes memory graph 的实体链接机制在技术原理上高度相似——都是会话范围的图结构，通过节点（受保护值/记忆实体）和边（共指/派生/关联关系）追踪跨上下文的信息流。将 SEG 的"保守链接策略"（只记录确定的引用关系，不做语义推断）引入 memory graph 的实体消歧，可以降低误关联率。

### 5.4 与 Cost-Aware Security Agent Eval (2607.15263) 的关联

上一篇精读的攻防 Scaling 论文关注 Agent 安全评估的成本感知。SlotGuard 可以被视为防御侧的具体实现——其中的 FPS 和类型化槽位就是"discipline wins"策略的技术体现：不是依靠更强的检测（更多计算），而是依靠更精确的替换策略（更好的纪律）。

## 六、金句摘录

> 「Naïve redaction is limited: it hides values by destroying the structure that agents need to act.」— 朴素脱敏的根本缺陷不是不够彻底，而是破坏了 Agent 推理所需的格式结构。

> 「Intelligent privacy protection mechanisms must distinguish different types of sensitive information.」— 智能隐私保护的核心不是"更激进地脱敏"，而是"更精确地分类"。

> 「Conditioned on the format class, I(FPS(v); v | τ(v)) = 0.」— 格式保留替换的信息论保证：在格式类条件下，替换值与原始值零互信息。

## 七、行动启示

### P0：Hermes Gateway 转录本脱敏中间件

**收益**：高（解决当前零防护的转录本泄露风险）
**可行性**：中（需在 Gateway 的工具输出处理层插入改写模块）
**工作量估算**：2-3 天

关键实现步骤：
- 在工具输出进入 LLM 上下文前插入路径正则替换（`/home/jc/uclaw/...` → `[HOME_ROOT]/...`）
- 实现环境变量密钥的 FPS 替换（检测 `*_KEY`、`*_TOKEN`、`*_SECRET` 模式，替换为合成值）
