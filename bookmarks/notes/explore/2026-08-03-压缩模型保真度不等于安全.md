## 1. 核心问题与研究动机

**一句话**: 团队用 perplexity + MMLU + 数据免费保真度探针（CKA）这套标准"质量门禁"来决定压缩后的 LLM 是否可以部署，但这些门禁完全检测不到一个致命的 Agent 行为失败——模型在执行标准操作程序（SOP）时会**编造从未在指令中出现的步骤**。

**现实场景**: 压缩（量化、低秩分解、剪枝）是 LLM 落地的必经之路。一个团队的标准验收流程是：
- Perplexity 在源模型的 1.15× 以内
- MMLU 等下游任务精度在置信区间内
- 数据免费的表示保真度信号（如 CKA）通过

**本文发现的盲区**: 一个通过全部三项检查的压缩构建，在被驱动执行 SOP 时，会发出不存在于任何指令中的步骤——它"虚构"了程序。这不是精度下降，而是一种全新的行为失败模式。

**Goodhart 定律的直接实例**: 一旦代理指标（perplexity/MMLU/fidelity）成为验收目标，构建会满足代理指标但仍然在真实目标（忠实程序执行）上失败。

## 2. 实验设计（Setup）

### Agent 金丝雀（Canary）

构造合成 SOP：10 个有序步骤 + 1 个条件第 11 步，将目标 SOP 和干扰 SOP 放入上下文，要求模型枚举精确的有序步骤。每个查询评分：
- **step recall**: 目标自身步骤的复现比例
- **branch correctness**: 条件分支是否正确
- **cross-procedure invention（invented_x）**: 决定性指标——从全局 SOP 词汇表中提取的、不在目标 SOP 中且非其自身条件的步骤字符串数量

预注册：24 SOPs × 3 seeds = 144 paired events/arm

### 压缩算子

在**匹配 perplexity 剂量**下对比：
- **相干低秩**（coherent low-rank）: per-tensor SVD 截断
- **不相干剪枝**（incoherent magnitude pruning）: 均匀、未重缩放
- 量化作为剂量控制

### 保真度门禁

- WikiText-2 perplexity（40×1024 窗口）
- MMLU 0-shot（513 题，57 学科）
- 数据免费输出保真度探针（CKA 或 compressed-vs-source 激活余弦）

"在域内"（in-regime）= ppl ≤ 1.15× baseline

## 3. 核心发现：盲区与解离

### 发现一：盲区——压缩构建在域内却编造步骤

跨三种架构的 Table 1 数据：

- **Qwen3-8B**: in-regime SVD (ppl 1.17×) 编造 +0.208 步/查询 [0.042, 0.375]，damage-matched prune = 0.000 [0, 0]
- **Mistral-7B**: in-regime SVD (ppl 1.069×) 编造 +1.729 步/查询 [1.076, 2.424]（3 个 seed 分别 2.06/1.90/1.85），damage-matched prune = -0.146 [-0.375, +0.035]
- **Llama-3.1-8B**: in-regime SVD (ppl 1.089×) = +0.056 [0, 0.167]（Llama 的谱空间小，SVD 在到达编造阈值前就崩塌了 perplexity）；dose SVD (ppl 1.29×) = +1.285 [0.743, 1.882]，damage-matched prune = +0.069 [0.021, 0.125]，差距 18×

**关键结论**: 在匹配 perplexity 下，**相干算子（SVD）失败，不相干算子（剪枝）不失败**。这种算子特异性在三种架构上均成立。

### 发现二：解离——同一权重对立判决

最强证据在单臂内部：Qwen3-8B 的 probe-allocated b98 SVD 构建——
- **CI 赢得**配对输出保真度测试（rand-probe NLL [0.024, 0.036] 和 [0.062, 0.076]）
- **CI 失败**金丝雀（+0.643 [0.171, 1.229]）

**同一组张量上，保真度通过且行为破碎同时成立。** 这不是调参问题，而是构造性证明：验证保真度的信号在这里无法验证 Agent 安全。

### 发现三：谱条件性（Scope Boundary）

盲区（坏行为在 perplexity guard 内）需要模型允许足够的域内低秩截断来达到编造阈值：
- Qwen3-8B (1.17×) 和 Mistral-7B (1.069×) 有谱余量 → 暴露盲区
- Llama-3.1-8B 谱空间小 → SVD 在编造阈值前就崩塌 perplexity → perplexity guard "意外地"捕获了有毒 SVD

算子机制是架构通用的，但 perplexity guard 的规避取决于域内谱余量。

## 4. 机制：相干 × 速率，而非损伤

**核心洞察**: 决定编造行为的不是误差的绝对幅度（damage），而是**误差的相干性（coherence）× 速率（rate）**。

- 在匹配 perplexity 下：相干算子（SVD）失败，不相干算子（damage-matched 剪枝）通过
- 量化剂量控制：携带比失败 SVD 更多原始 perplexity 损伤的量化仍然通过；但量化被推到失败 SVD 的速率（1.05×）时也开始失败（Δ+0.10 [0.029, 0.20], n=70）
- 编造启动很早，在 2% perplexity 剂量内
- 效应是分布式的而非局部化的
- 与 MMLU **双解离**: 量化可以 CI-cleanly 降级 MMLU 并通过金丝雀，而 SVD 恰好相反

**为什么相干误差更危险**: 低秩截断移除的是系统性的、结构化的信息（主奇异方向），这种结构化损失扭曲了模型的程序忠实性而不影响 perplexity。剪枝移除的是分散的、随机的小权重，对整体行为影响更均匀。

## 5. 数据免费检测器

### 两轴检测公式

对压缩误差 ΔW = W_base − W_mod，在线性张量上聚合（能量加权）：

**coherent_fraction**（误差是否低秩/结构化）:
- k=8 前奇异值能量 / 总 Frobenius 能量
- = Σ_t σ²_{1:k}(ΔW_t) / Σ_t ‖ΔW_t‖²_F

**error_rate**（剂量是否足够大）:
- = Σ_t ‖ΔW_t‖²_F / Σ_t ‖W_t‖²_F

两个统计量**都不需要数据**: 前者用随机化子空间迭代获取 top 奇异值；对 SVD 构建，ΔW 是丢弃的奇异尾部。

### 门禁规则

**coherent_fraction > 0.007 ∧ error_rate > 0.01**（两种架构上相同的固定阈值）

单个统计量不够：
- coherent_fraction 单独会标记通过的温和低秩构建
- error_rate 单独会标记通过的重量级剪枝
- 它们的乘积让大速率掩盖低相干
- **它们的合取（conjunction）才有效**

### Table 2: 检测器 vs 金丝雀标签

- Mistral in-regime SVD: coh=0.0080, rate=1.59e-2 → FAIL/FAIL ✓
- Mistral dose SVD: coh=0.0079, rate=3.10e-2 → FAIL/FAIL ✓
- Mistral prune: coh=0.0054, rate=3.19e-2 → pass/PASS ✓
- Llama in-regime SVD: coh=0.0090, rate=6.50e-3 → pass/PASS ✓（rate 门禁正确放行）
- Llama dose SVD: coh=0.0090, rate=1.21e-2 → FAIL/FAIL ✓
- Llama prune: coh=0.0060, rate=7.26e-3 → pass/PASS ✓

**6/6 正确分类**，固定阈值跨架构。9×9 密集扫描确认边界真实而非三剂量产物。

### 检测器边界

- 最极端剪枝（Llama density 0.50，移除一半权重）的 coherent_fraction 刚过门禁——标记为未验证预测
- 阈值仅拟合 SVD 和剪枝算子族，7-8B dense 规模
- 未测试 MoE 架构（但一个先前的低比特专家 MoE 构建通过 QA 却失败金丝雀，与本文一致）

## 6. 创新点分析

1. **首次定义"压缩-解离"失败模式**: 不是"精度下降导致偶尔出错"，而是"保真度认证通过但程序忠实性系统性崩溃"。这是一种全新的失败分类法。

2. **算子特异性 vs 损伤幅度的范式转换**: 传统压缩评估只看"压缩了多少"（damage），本文证明"如何压缩"（operator coherence）才是决定行为安全的关键。SVD（结构化）和剪枝（随机）在相同 perplexity 下行为表现截然不同。

3. **构造性解离证明**: 不是统计趋势，而是同一组权重同时通过保真度测试、失败金丝雀——这是逻辑上的不可能（如果保真度=安全），用实验直接否定。

4. **可部署的数据免费检测器**: 不是仅指出问题，而是提供固定阈值的两轴门禁规则，跨架构通用，不需要标注数据。

5. **Goodhart 定律的 LLM 压缩实例化**: 将经典博弈论概念（指标优化不等于目标优化）落地到 LLM 部署质量保证体系中。

## 7. 局限性与未来方向

### 论文自述局限

- 仅测试三种 7-8B dense decoder LM（Qwen3-8B, Mistral-7B, Llama-3.1-8B）
- 金丝雀是合成 SOP，base-model prompted（非 instruction-tuned），绝对编造率是仪器特定的
- 对比结果（SVD vs matched prune）承载结论，而非跨模型绝对水平
- perplexity guard 规避是谱条件的，取决于域内低秩余量
- 检测器阈值仅适用于 SVD/pruning 算子族，7-8B dense 规模
- 未测试 MoE（但旁证一致）
- 仅证明 guard stack 错过了这一失败模式，未声称该失败穷尽了 Agent 行为

### 延伸局限分析

- **instruction-tuned/chat 模型未测**: 论文用的是 base model + chat template fallback，真实的对话模型（经 RLHF/DPO）是否有相同盲区未知。经对话对齐的模型可能因指令遵循训练而部分抑制编造，但也可能因分布偏移而更脆弱。
- **真实世界 SOP 未测**: 合成 SOP 结构简单（10 步 + 1 条件），真实生产 SOP（如 DevOps 部署流程、金融交易流程）更复杂，编造风险可能更高。
- **多模态压缩未测**: 论文提到 CKA 探针对 text/image/video diffusion/audio 都适用，但 Agent 行为盲区在多模态场景的表现未知。
- **量化-蒸馏-剪枝组合未测**: 生产中常组合多种压缩，叠加效应可能非线性。

## 8. 借鉴点（关联 Hermes Agent / Jetson Orin / 量化交易）

### 🔨 P0 — Hermes 量化模型部署前 Agent 行为检测器

**直接移植**。论文提供了完整的数据免费两轴检测器（coherent_fraction + error_rate），可在 Hermes 部署任何量化/压缩模型到 Jetson 前运行。

具体实现：
- 对 W_base − W_mod 计算 coherent_fraction（top-8 奇异值能量比）和 error_rate（Frobenius 能量比）
- 门禁: coherent_fraction > 0.007 ∧ error_rate > 0.01 → 标记为 Agent 不安全
- 可整合到现有的 `model-adapter` 或 `gguf-quantization` skill 中作为 pre-flight check
- 预计工作量：1 个 Python 脚本 + 整合到部署流程（2-4 小时）

### 🔨 P0 — Hermes SOP 忠实性金丝雀

**可移植**。论文的合成 SOP 金丝雀（10 步 + 条件第 11 步）可以直接构造为 Hermes 的 Agent 行为回归测试：
- 构造 5-10 个覆盖常见 Hermes 工作流（邮件发送/笔记创建/飞书消息）的合成 SOP
- 每次模型切换或压缩后运行，检测 cross-procedure invention
- 这填补了当前 Hermes 模型切换后仅靠"手动试用"验证的空白
- 关联 `model-switch` skill 和 `verification-gate` skill

### ⚠️ P1 — Jetson 量化策略重评估

**需工程改造**。当前 Jetson Orin 上的量化方案（GGUF Q4/Q8）主要用 perplexity 和主观体感验证。本文揭示：
- 如果量化引入了**相干低秩误差**（某些结构化量化方案可能如此），即使 perplexity 变化小也可能有 Agent 行为风险
- 应额外检查量化误差的结构化程度
- 可能需要优先使用"不相干"量化方案（如 round-to-nearest）而非结构化量化

### ⚠️ P1 — 量化交易 Agent 编造步骤风险

**需验证**。量化交易 Agent 执行 SOP（信号检测→下单→风控→对冲）时，如果底层模型被压缩：
- 编造一个不存在的步骤（如"检查隔夜持仓保证金"）可能导致错误操作
- 应为交易 Agent 增加 step-instruction 对齐检查：每个工具调用的参数必须可追溯到 SOP 定义
- 关联 `a-stock-quant-system` 和 `requesting-code-review` 中的 verification gate

### ❌ P2 — 检测器阈值校准

**暂不适用**。论文的固定阈值（0.007/0.01）仅校准于 7-8B dense 模型。Hermes 使用更大的模型（如 GLM-5.2），阈值可能不同。需在目标模型上重跑金丝雀校准，但论文提供了方法论框架。

## 内容整理

本文的核心论点链条可以浓缩为一条逻辑线：

标准压缩验收门禁（ppl + MMLU + CKA）→ 检测不到 Agent 行为失败 → 相干低秩误差是元凶 → 误差相干性 × 速率决定编造行为，而非损伤幅度 → 两轴数据免费检测器（coherent_fraction > 0.007 ∧ error_rate > 0.01）可预判 → 压缩验收和 Agent 部署必须是两道独立门禁。

关键概念定义：
- **invented_x（编造步骤数）**: 模型从全局 SOP 词汇表中输出的不属于目标 SOP 且非其条件分支的步骤字符串数量，是本文的核心评估指标
- **相干误差（coherent error）**: 低秩截断产生的结构化误差（如 SVD 丢弃主奇异方向），扭曲程序忠实性但不影响 perplexity
- **不相干误差（incoherent error）**: 随机分散的误差（如均匀剪枝小权重），对整体行为影响均匀
- **解离（dissociation）**: 同一组模型权重同时通过保真度测试、失败金丝雀测试的逻辑矛盾

## 查询拓展

值得深入探索的方向：
- instruction-tuned/chat 模型是否也有相同盲区？论文用的是 base model + chat template，真实的对话模型经 RLHF/DPO 后指令遵循更强，但分布偏移也可能放大风险
- MoE 架构的检测器阈值校准：论文提到低比特专家 MoE 通过 QA 却失败金丝雀的旁证，但未系统测试
- 量化+蒸馏+剪枝组合压缩的叠加效应：生产中常组合多种压缩，相干/不相干误差的混合是否产生非线性风险
- 多模态 Agent 场景：视觉-语言模型在压缩后的工具调用忠实性如何退化
- 与 Binding Drift（2607.18316）联合构建 Agent 安全评估体系：编造步骤（本文）vs 实体绑定漂移（Binding Drift）是不同层面的失败

## 归纳总结

这篇论文对 AI 工程实践的最大启示是：**"看起来没问题"不等于"执行没问题"**。

传统压缩评估回答的是"模型还聪明吗"（perplexity/MMLU），但 Agent 部署需要回答的是"模型还可靠吗"（忠实执行指令不编造）。这是两个正交的维度——一个模型可以同时是"足够聪明的"和"不可靠的"。

论文的检测器虽然简洁（两个阈值、零数据需求），但揭示了一个更深层的原则：**压缩方法的选择（结构化 vs 随机）比压缩的力度更重要**。对 Agent 场景，应优先选择产生不相干误差的压缩方案（如均匀剪枝/round-to-nearest 量化），避免产生相干低秩误差的方案（如 SVD 截断/结构化量化），即使后者在 perplexity 上表现更优。

对 Hermes Agent 而言，这意味着在 Jetson 上部署量化模型时，不仅需要 perplexity 门禁，还需要 Agent 行为金丝雀门禁——尤其是在执行多步工具调用 SOP 的场景下。
