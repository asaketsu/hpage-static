核心发现

发现 1：ESP32-H4 — 超低功耗 Thread/Matter 专用芯片（2026 EW 首发）

ESP32-H4 是 Embedded World 2026 上 Espressif 首次公开展示的新芯片，定位为电池供电 Matter over Thread 终端设备的理想选择：

  • 双核 RISC-V @ 96MHz（低频策略，功耗优先）
  • 802.15.4 + BLE 5.4（Thread + Matter over Thread）
  • 支持外部 PSRAM（区别于 H2 的无 PSRAM 设计）
  • 超低功耗：面向传感器、可穿戴、远程控制等电池场景

对智能灯的影响：
- H4 是 H2 的升级替代品，解决了 H2 无 PSRAM 导致复杂灯效内存不足的问题
- 适合 Thread 网络下的低功耗灯泡/开关（如走廊灯、夜灯）
- 不支持 Wi-Fi，只能通过 Thread Border Router 接入智能家居
- 选型对比：H2（纯 Thread，无 PSRAM，已量产）vs H4（Thread + PSRAM，2026 Q3 预计量产）

发现 2：ESP32-S31 开发板已上市 — 两款官方 DevKit

cnx-software 2026-05-22 报道，ESP32-S31 已有两款官方开发板：

ESP32-S31-Function-CoreBoard-1：
- 基于 ESP32-S31-WROOM-3 模块
- 千兆以太网 PHY + USB 2.0 OTG
- 板载音频外设
- 适合 IoT 网关/控制器开发

ESP32-S31-Korvo-1：
- 多媒体开发板，含双麦克风阵列（语音唤醒/识别）
- 4.3 英寸 LCD + 3MP 摄像头模块
- 双扬声器接口 + microSD
- 适合带 HMI 的智能灯控面板

对智能灯开发的价值：
- Korvo-1 的麦克风阵列可直接做语音控制灯（WakeNet + MultiNet）
- 千兆以太网适合做 Art-Net/sACN 灯光网关（上篇笔记中的专业灯光场景）
- S31 的 LEDC + RMT 外设与 S3 完全兼容，代码可直接迁移

发现 3：ESPHome 2026.1~2026.5 系列更新对灯控的重大影响

ESPHome 在 2026 年上半年发布了 5 个主要版本，对智能灯开发者影响深远：

2026.1.0（里程碑版本）：
- 自动 WiFi 漫游：多 AP 环境下自动切换最强信号（解决大宅灯控断连痛点）
- ESP-IDF 成为 ESP32 默认平台：二进制体积减少 40%，编译更快
- API 加密强制启用：API password 认证移除，改用加密通信
- 零拷贝 API：单包传输效率提升 42%，更多灯实体可同时控制
- IRAM 优化：堆函数从 IRAM 移至 Flash，节省 ~6KB IRAM

2026.4.0：
- ESP-IDF 6.0 兼容准备：31 个 PR 为升级铺路
- GPIO 扩展器中断驱动：空闲 I2C 流量减少 99.7%（多灯 I2C 方案功耗大幅降低）
- LVGL v9.5.0：带屏灯控面板 UI 升级
- 配置加载 18x 加速：大型多灯配置不再卡顿

2026.5.0（最新）：
- ESPHome Device Builder 公测：全新 Web IDE，替代旧 Dashboard
- 实时代码编辑器 + 固件构建队列 + 批量操作
- 标签和区域管理 + 配置间搜索
- 分布式构建支持

对 skill 的更新建议：ESPHome 2026.1+ 已默认 ESP-IDF，这意味着通过 ESPHome 做灯控项目的底层已升级到 v6 级别，LEDC 新 API（Delta-Sigma、多段渐变、同步更新）将可通过 ESPHome YAML 间接使用。

发现 4：ESP-IDF v6.0 正式发布 — 对智能灯的完整影响清单

ESP-IDF v6.0 于 2026 年 3 月正式发布，关键变更：

新工具链：
- EIM（ESP-IDF Installation Manager）：跨平台统一安装
- GCC 15：警告视为错误，需修复所有 -Wimplicit-function-declaration

LEDC 破坏性变更（已在 skill 中记录，此处补充细节）：
- ledc_multi_channel_sync() — RGB 三通道同步更新是 v6 最大亮点之一
- LEDC_DITHER_MODE（Delta-Sigma 调制）使低亮度分辨率从 3-bit 提升到 ~13-bit
- 移除 ledc_timer_set()、LEDC_APB_CLK_HZ 等旧 API

其他对灯控的影响：
- Mbed TLS 4.0（OTA 签名验证需迁移）
- cJSON 移至 managed component
- wifi_provisioning → 外部组件 network_provisioning
- PicolibC 默认 LibC（powf() 行为变化影响调光算法）

迁移优先级：新项目直接用 v6；旧项目保持 v5.x，计划 2026 Q3-Q4 迁移。

WLED v16.0.0（2026-05-03 发布）已记录在 skill 中。GitHub releases 页面补充信息：

对 skill 的补充：WLED 的色彩处理改进（新 gamma 引擎）与上篇笔记中的感知线性化调光理论高度一致。使用 WLED 的项目现在内置了更好的 gamma 校正。

技术细节

ESP32-H4 vs H2 vs C6 选型决策树（Thread 灯泡）

需要 Thread + Wi-Fi 双模?
├─ 是 → ESP32-C6（双模，成本 $2-3）
└─ 否 → 纯 Thread 灯泡?
        ├─ 需要复杂灯效/动画?
        │   ├─ 是 → ESP32-H4（PSRAM 支持，2026 Q3）
        │   └─ 否 → ESP32-H2（成熟稳定，无 PSRAM）
        └─ 电池供电超低功耗?
            └─ ESP32-H4（低频双核 + 超低功耗设计）

ESPHome Device Builder 对智能灯开发的影响

新版 Device Builder 提供的功能直接提升灯控开发体验：
- 实时代码编辑：直接在浏览器中编辑 light/sensor 配置
- 固件构建队列：多设备批量编译部署
- 跨配置搜索：在所有灯控 YAML 中搜索特定参数
- 分布式构建：远程编译服务器减轻本地负载

ESP-IDF v6 安全层迁移对 OTA 的影响

旧流程（v5）：直接调用 mbedtls API 做 RSA 签名验证
新流程（v6）：使用 esp_crypto 抽象层
  esp_crypto_rsa_verify() 替代 mbedtls_rsa_pkcs1_verify()
  esp_crypto_sha256() 替代 mbedtls_sha256_ret()

ESP-Matter SDK 已适配 v6 安全 API。自定义 OTA 流程需手动迁移。

  2. Thread 灯泡首选 H4（有 PSRAM）而非 H2
  3. 多媒体灯控面板用 S31-Korvo-1（自带麦克风+屏幕）

  4. 纯 Wi-Fi 6 低成本灯泡用 C61

  5. ESPHome 升级策略：

  6. 所有灯控项目升级到 ESPHome 2026.5+（WiFi 漫游 + 零拷贝 API）
  7. 利用 Device Builder 简化多灯配置管理

  8. 注意 API 加密迁移（不再支持 password 认证）

  9. WLED 项目：

  10. 直接用 v16.0+，新 gamma 引擎解决了色彩一致性问题

  11. 复杂灯效不需要自研，WLED 的 Segment 层叠 + 粒子系统已覆盖大部分场景

  12. ESP-IDF v6 迁移优先级排序：

  13. P0：LEDC API 变更（直接影响 PWM 调光）
