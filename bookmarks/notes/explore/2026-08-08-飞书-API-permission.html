飞书 API Permission 权限体系全景

嗅探学习 | 2026-08-08 | 来源: 飞书开放平台官方文档 + Apifox API 镜像

一、摘要

飞书 API 的"permission"不是一个单一概念，而是 三层权限模型的叠加：API Scope（接口调用权）× 数据权限范围（可见数据边界）× 资源级权限（文档/群等具体资源的协作者权限）。任何 API 调用失败（403/1063002），根因必在这三层之一。

二、三层权限模型

层1: API Scope（接口级权限）

  • 定义: 应用调 API 前必须在开发者后台「权限管理」页申请的 scope
  • 等级: 普通权限（低敏感）vs 高级权限（高敏感，商店应用审核更严）
  • 原则: 最小可用原则，权限过大威胁企业数据安全
  • 机制: 同一接口的多个 scope 之间是 或关系（申请任一即可调用），但 字段级权限是独立的（想拿 user_id 字段必须开对应 scope）
  • 申请流程: 自建应用 → 开发者后台开通权限 → 创建版本 → 租户管理员审核 → 发布生效

层2: 数据权限范围（Data Scope）

  • 定义: 即使有了 API scope，应用能读写的数据范围还有边界限制
  • tenant_access_token: 数据范围由 应用数据权限配置决定
  • user_access_token: 数据范围由 该用户自身的可见范围决定
  • 配置位置: 开发者后台 → 安全设置 → 数据权限范围

层3: 资源级权限（Resource Permission）

  • 定义: 具体某个云文档/多维表格的协作者权限
  • 角色: 所有者 > 可管理 > 可编辑 > 可评论 > 可阅读
  • 关键陷阱: 用 tenant_access_token 操作文档时，必须先在文档页面「...更多 → 添加文档应用」给应用加权限
  • 多维表格: 若开启高级权限，必须给应用「可管理」角色，否则 scope 开了也调不通
  • API 端点: GET /drive/v1/permissions/:token/public 查询权限设置

三、关键发现

1. 两种 Token 的权限差异

  • tenant_access_token（应用身份）: 组织级操作，权限由 app scope + data scope 决定
  • user_access_token（用户身份）: 个人级操作，权限继承用户本人权限，需 OAuth 流程
  • 选择原则: 管理类任务用 tenant，个人助手类用 user

2. 免审核小范围测试

  • 可用成员 ≤ 10 人（可配置）时，应用发布 无需审核
  • 适合开发阶段快速联调

3. OAuth Scope 细节

  • scope 参数是 空格分隔、大小写敏感的字符串
  • 一次最多请求 200 个 scope
  • 需要离线刷新 token 必须加 offline_access scope
  • 未在后台申请的 scope 在授权时会报 20027 错误

4. 常见 403 错误排查路径

1063002 Permission denied
├── 检查1: API scope 是否已申请并发布生效？
├── 检查2: 数据权限范围是否覆盖目标资源？
├── 检查3: 资源级权限 — 应用是否已添加为该文档协作者？
│   ├── tenant_access_token → 文档页面「添加文档应用」
│   └── user_access_token → 文档页面「分享」给该用户
└── 检查4: 多维表格是否开启高级权限？需给应用「可管理」角色

5. 权限审核规则（商店应用）

  • 普通权限: 上架审核（飞书平台）+ 租户安装审核（企业管理员）
  • 高级权限: 审核更严，无充分理由不通过
  • 自建应用: 仅需租户管理员审核

四、对 Hermes 工作的价值

当前痛点直击

  1. lark-cli / MCP 操作文档时常遇 403: 根因大概率是层3（资源级权限），而非 API scope 缺失
  2. 批量操作多维表格失败: 需检查是否开启高级权限，给应用「可管理」角色
  3. 用户身份操作: 用 user_access_token 时，scope 要手动拼接且大小写敏感

行动建议

  1. 权限排查 SOP: 遇 1063002 错误时，按上述四步排查路径逐层检查，不要只查 API scope
  2. 应用数据权限配置: 定期审查 Hermes 应用的数据权限范围，遵循最小可用原则
  3. lark-mcp --scope 参数: 需要用户身份操作时，明确指定 scope 并确保包含 offline_access
  4. 文档操作前置检查: tenant_access_token 操作文档前，确认应用已通过「添加文档应用」入口获得协作者权限
