核心问题与研究动机

论文直指当前 LLM Agent 工具/技能评估的根本乱象："skill 带来了提升"这个结论在不同论文里比较的是完全不同的东西。

  • 动机 1（数字打架）：Skill Following 发现"检索到 vs 未检索"对比显示正提升，但同一批任务的配对对照却是负效应；WorthTheirTokens 发现 web agent 的技能/记忆模块增益在预算匹配后消失；SkillsBench 却报告 18 个 model-harness 配置全部提升。表面矛盾，实则各答各题。
  • 动机 2（生态爆炸）：ToolBench 类基准含数千 API，MCP 环境暴露数百到数千工具，技能库（按需加载的程序/指令/脚本）已有数万条目——检索/门控/加载/使用的选择链条本身成为组件，但评估实践没跟上设计实践。
  • 动机 3（方法论真空）：现有多数综述按能力/基准/失败类型组织文献，没有人系统回答"这个对比设计到底估计了什么量、支持什么结论"。
  • 核心论点：技能比较的歧义大多来自未声明的估计量属性——处理对比、目标总体、单位与耦合、预算、汇总量度、识别假设中任何一项含糊，数字就无法比较。

方法论内容整理

五层测量级别与两条隐藏路径

评估可在五个层面取数，每层回答不同问题：

  • 曝光（Exposure）：agent 能看到哪些候选——shortlist、工具菜单、预载入 system prompt 的技能名与描述
  • 检索（Retrieval）：检索器/路由器为当前查询排出哪些候选
  • 激活（Activation）：候选是否被加载进上下文或执行
  • 使用（Use）：agent 是否以及如何遵循已加载的程序/工具输出
  • 结果（Outcome）：任务成功 + 成本 + 延迟 + 风险

纯顺序读取会漏掉两条路径：

  • 存在效应（presence effect，虚线直连）：技能元数据在 prompt 中即使从不被调用也会改变行为（Regression Tax 记录了无技能正文被读取的 regression；shadowing 证明更大上下文本身改变行为）
  • 状态反馈（ dotted 回环）：多步 agent 每步的动作改变后续决策所依赖的状态，整个序列逐步复发

事件定义必须精确（surface/call/return/load/execute/follow），因为条件化的触发率与触发组随事件选择而变。空返回的调用与返回候选的调用是不同事件。

潜在结果记号与 ICH E9(R1) 五属性

  • 记号：任务 x 取自任务总体，配置 a（库启用/特定检索器/强制加载技能），Y_a 为一次 run 的结果，μ_a(x)=E[Y_a|x] 为 run 期望。Agent 在固定 x 下也是随机的（采样、服务非确定性、环境变化）。R_a∈{0,1} 记录检索是否触发——R 是后处理变量，只在模块可用的臂中存在，且可能与决定 Y_a 的同一批随机事件相关。
  • 比较前必须固定三件事：单位（任务 / 任务+种子 / run 对）、臂间耦合（独立 / 共享种子 / 从同一录制状态分叉）、每任务每臂 run 数。
  • 借用临床试验 ICH E9(R1) 估计量附加协议：每个估计量必须声明总体、处理、结局变量、间发事件处理、总体级汇总。Agent 场景的间发事件包括：未触发检索、检索到但不加载、加载后忽略、基础设施失败、预算耗尽。综述发现的大部分歧义都来自这五属性或单位/耦合之一未声明。

六轴设计描述框架（Table 1）

任何工具/技能评估设计都可用六轴刻画：

  • 处理对比（treatment contrast）：可用性（模块开/关）/ 组件替换（检索器、shortlist 头、菜单构造器）/ 激活策略（加载 vs 弃权，门开/关）/ 库组成（规模、内容、准入规则）
  • 目标总体：全部任务 / 预处理子组（领域、难度）/ 后处理子组（触发检索的任务）/ 轨迹内状态
  • 结局：成功或奖励 / token、调用、延迟 / 风险暴露 / 中间失败
  • 预算约束：无 / 事前上限+分配规则 / 近似匹配实际支出
  • 汇总量度：均值差 / 配对不一致计数 / 期望结局下降任务占比 / 价值函数
  • 识别假设：随机化或配对 run / 声明的臂间耦合 / 后处理分层的 principal ignorability / 状态级对比的顺序可忽略性与正定性

常见报告量对照（Table 2 精要）

  • 组件指标（Recall@k/nDCG）：描述性，非因果。支持：标注查询池上的排序质量。不支持：对 agent 结局的任何效应。ToolRet 上源特异微调的检索器换一个 slice 即崩塌（组件指标不跨源迁移）。
  • 检索到 vs 未检索对比：两组由 agent 自己选出来，难度不同（Skill Following 用配对无技能 run 证明组间难度差巨大），非任何东西的效应。
  • 总可用性效应 τ=E[μ_a(x)−μ_a'(x)]：回答"该模块是否应按规格开启"。SkillsBench 的 18 配置全提升即此类。
  • 组件替换效应：多数检索论文的端到端增益实为此类——更好检索的效应，不是"有技能 vs 无技能"。TabAgent 用分类器替换 LLM shortlist 头、AppWorld 成功率保持，也属此类。
  • 预算约束比较：回答"总支出封顶下选哪个配置"。需要事前上限 B 和臂内分配规则，因为实际支出本身是后处理结果。
  • 触发条件化配对对比（RAE）：协议特定的诊断量，非 run 级调用效应（见下）。
  • 配对不一致计数：描述协议下的翻转频率，不是受害任务占比（见下）。
  • 任务级退化占比 δ_ε=P(μ_1(x)−μ_0(x)<−ε)：13 篇核心研究中无一篇报告。
  • 状态级干预价值 v^φ 与执行选择价值：见下。

触发条件化配对对比的分解与反例（3.5 节，全文最硬核）

D_pair = E[Y_1−Y_0 | R_1=1] 恒等分解为三项：

  • 项一：倾向加权任务效应（仍是可用性效应，按各任务触发概率加权）
  • 项二：处理 run 选择项——触发与处理 run 自身结局相关时非零（如 agent 早期犯错后更频繁检索）
  • 项三：对照 run 选择项——依赖耦合方式，可部分或完全抵消项二

抛硬币反例：所有任务同分布，模块无效应，每臂成功概率 0.5（公平硬币 U），模块臂恰在 U=1 时触发。真实效应处处为零。独立对照 run 下配对统计量期望 = 1−0.5 = 0.5（全部来自处理 run 选择项）；两臂读同一硬币时两个选择项相消，配对统计量 = 0。结论：任务配对消除任务间选择，消不掉任务内选择；偏差大小依赖耦合方式。Skill Following 的 RAE 因此被定位为"协议条件化配对结果信号"（作者自己也如此声明），不是无偏因果效应。

两个不同目标需要不同设计：

  • 触发分层内的可用性效应：principal stratification + principal ignorability 可识别，但即使识别了也仍是可用性效应（含元数据在场、上下文占用、调用前行为等一切路径）。解析例：若 prompt 中列出技能描述提升每个任务而技能正文无用，触发分层的可用性效应为正，尽管加载正文零效应。
  • 局部调用效应：固定元数据与剩余预算、声明后续策略 φ，干预加载决策本身。两者不能互相推出。

总效应与触发分层的恒等式（3.6 节）

τ_pair = π·D_pair + (1−π)·D_skip（全期望律）。三个要点：

  • 恒等式对任何协议和耦合成立，但对分量的因果解释只字未提
  • 总量与一个分量不能推出另一个，除非同时报告 π：完整报告给 (π, D_pair, D_skip) 或等价地 (π, τ_pair, D_pair)
  • 非零 D_skip 与存在效应一致但不证明它——归因于元数据需要一个"仅元数据在场"的臂

不一致（discordance）≠ 退化（degradation）（3.7 节）

配对二值结局下每任务落入四格：p̂+（无模块败→有模块成）− p̂−（无模块成→有模块败）= 配对成功率差，恒等式精确。诱惑是把 p̂_− 读作模块伤害的任务占比——不支持：

  • 两臂边际成功率不决定联合分布。两臂各以 0.5 成功的任务上：完美同向耦合时 regression 概率 0，独立时 0.25，完美反向耦合时 0.5
  • 独立协议下 E[p̂_−] = E[μ_0(x)(1−μ_1(x))]，即使 μ_1=μ_0 处处成立也为正
  • 三 run 反例：每臂独立跑 3 次，Binomial(3,0.5) 两计数相等概率 20/64，处理侧更低概率 22/64≈34%——δ̂_0 的 plug-in 估计中心在 0.34 而非 0，加任务只会更稳定地错
  • 正确做法二选一：各任务差值的同时置信区间 [L_x,U_x]，报告"确信退化占比"（U_x<−ε）与"可能退化占比"（L_x<−ε）两个份额作为 δ_ε,n 的界；或声明任务级效应分布的层次模型
  • Replay Gap 的同配置噪声底（control forks）可显示多少 regression 来自无处理差异的纯噪声

状态级干预价值（3.8 节）

激活门与停止规则在特定状态决定加载/停取，其目标量必须定义为干预而非观察组间差：

  • v^φ(s,k) = [Q_Y(s,load k)−Q_Y(s,abstain)] − λ·[Q_C(s,load k)−Q_C(s,abstain)]，成本项是从决策点起的全部后续成本差，不只是加载成本
  • 成功率差 0.1 + 加权成本差 0.2 时 v^φ=−0.1——只报成功率差对应第一括号，不是 v^φ
  • 从日志估计需三条件：一致性（logged 动作=干预）、当前决策点给定 s 的可交换性、正定性（每个感兴趣状态两种动作都出现）；日志若在别的策略下继续，需 off-policy 识别公式（且需后续每步的顺序可交换性与支持度）
  • SkillApt 是最接近的实现：matched WITH/WITHOUT 执行共享任务/模型/解码/环境/评估器；冻结确认评估用任务哈希特征表状态（任务条件而非轨迹中状态）；基础设施失败对被剔除——111/113 确认状态完成（complete-case 分析）
  • RADEG 是另一类决策（执行选择：该 query-bundle 是否启动下游 agent），无"同状态无技能继续"的基线，不估计 v^φ(s,k)
  • 门控器的状态/查询级估计之后，必须单独评估其诱导策略的总效应/策略价值

预算约束与总效应的分野（3.4/4.5 节）

  • 消耗 token 的模块同时改变两件事：agent 知道什么 + 花多少计算。若处理是"带开销部署该模块"，开销是处理的一部分而非混杂——无预算匹配的比较估计的是总效应，合法且常是部署问题
  • WorthTheirTokens 是最清晰的预算研究：控制臂把 vanilla actor 视界 10→15 步并加 accessibility-tree 剪枝；作者自承步数上限只是近似 token 预算（多数任务控制臂花得更少，少数略多）。"增强增益常消失"的结论只关于这个近似预算约束
  • 完整报告 = 总效应 + 各臂成本 +（若声称资源效率）预算约束比较或成本-成功前沿

关键实验结果与数据（证据合成）

曝光层（4.1 节）

  • 相关性可能是错误的检索单元：Tool Graph Retriever 加依赖信息防前置工具遗漏；HYSET 以超边打分完整工具集（ToolBench 检索+端到端双提升）；Diverse Skill Routing 惩罚冗余技能；R3-Skill 保留被拒组合作集合兼容性监督；CaSKG 用反事实探针校准技能有向边
  • State-Path Tool Menus：菜单=从可观测状态到目标的执行先验。ToolBench 单执行器确定性解码下在线成功率 0.737→0.898，32 工具菜单覆盖的完整链超过官方 128 工具列表
  • shortlist 长度本身是决策：CAM-DF 成本感知停止于排序前缀，实机执行暴露工具减少 37% 任务成功率相当；SchemaRouter 发现最小化选中字段数降低答案准确率，保召回投影恢复之；Repantis 等提出机会校准的 shortlist 适配度指标
  • 风险维度：SameCapRisk-Bench 显示公开技能检索器 Helpful Recall@3 在 0.848–0.888 的同时，同族危险兄弟技能 HSR@3 达 0.346–0.372——高组件指标可与有害暴露画像共存；Risk-aware 重排给 6,108 工具标注序数风险
  • 组件指标不跨源迁移：ToolRet 上单一源微调的检索器在同基准另一 slice 上崩塌；34,396 技能的生产路由器上合成数据微调提升域内伤害域外

激活与实际使用（4.3 节）

  • SkillApt：把"哪个技能相关"与"加载是否值得"分成两个决策。SRA-Bench 冻结评估上观察准确率与 BM25 Top-1 持平（0.838 vs 0.838），激活率 100%→31.5%
  • SkillGate 发现"选择器信用饥饿"：序列级结果奖励下，点名技能的那几个 token 分到的信用随轨迹变长而趋零且符号渐错，方法是给这些 token 加动作局部优势
  • GNND deference：ReAct agent 拿 GNN 当工具时对工具原始预测的认同率 97.6–99.2%，且 backbone 能力越强盲从越重；选择性调用门恢复了部分 oracle 差距但无净全局增益
  • Outcome Monitors：标记契约违反并点名恢复工具，在注入失败设置下提升完成率；去掉恢复工具列表后测得增益消失——"工具被用了"不是成功标准，评估必须定义何为正确使用

库规模、演化与成本（4.4 节）

  • Skill shadowing：SkillsBench 中每个自制技能都提升 pass rate ≥4pp 的 38 个任务-模型对（两模型），换到 202 技能库后 pooled pass rate 下降 21pp（其中一模型 26pp）；分解显示选择项（skill shadowing）= 0.14 [0.06, 0.26] 为主瓶颈，上下文项 = 0.07 [−0.13, 0.25] 含零。注意人群是为"技能有帮助"选出的
  • Contamination 相变：自进化 agent 从自身轨迹蒸馏技能，越过临界池规模后新技能降低性能、缺陷技能传染后续技能、事后移除仅恢复小部分损失；准入门控（入池前）在作者实验中避免了这一切——库组成效应路径依赖，演化库上的总效应只对被测快照成立

评估协议效度（4.5 节）

  • Replay Gap：SWE-bench 上分叉 rollout + 同模型 control fork 检验逐步模型切换的 replay 假设——swap 重写 61–94% 的 fork 后动作，仅 3% replayed 状态保持有效，replay 错估每一个成功相关结局；一个量化配置下 temperature-0 服务在 90%+ control fork 上分叉。逻辑适用于任何改变 agent 后续动作的组件：反事实结局应来自执行的延续，除非 replay 已对该组件验证
  • 离线准确率 ≠ 干预收益：AUROC 0.94 的 critic 在一个模型上造成 26pp 崩塌，另一模型几乎无变化（中断-恢复权衡）；作者建议 50 任务 pilot 决定是否干预
  • 反事实工具排序（精确倾向日志）：DR 估计的初始有利结果在 full-return 直接回归下反转；不支持动作的绝对策略值不可识别
  • ToolChain-CRC：只对最终答案校准会漏掉检索/工具失败；轨迹级校准把接受轨迹风险控制在目标下

归纳总结（创新点分析）

  1. 首个组件级估计量框架：五层测量级别 + ICH E9(R1) 五属性 + 六轴设计描述，把"skill 有没有用"拆解为可声明的统计目标。区别于 Huang 的系统排名方法学（目标总体/测量源/资源规则/公共支持/不确定性），本文聚焦组件的开/换/触发比较，互补而非重叠
  2. 三个解析反例钉死三类误读：抛硬币反例（配对消不掉任务内选择，偏差依赖耦合）；三 run 反例（退化占比 plug-in 估计中心偏移 0.34）；恒等式反例（π 不报告则分量不可比）
  3. discordance/degradation 概念切割：首次在 agent 评估中区分协议描述量（翻转频率）与因果伤害量（δ_ε），并给出同时置信区间的"确信/可能退化"双份额报告法——13 篇核心研究无一达标，说明这是全领域空白
  4. v^φ 干预价值的完整识别条件：把激活门评估从"准确率"提升到"策略价值"，明确 consistency/exchangeability/positivity 三条件与 off-policy 边界
  5. 证据合成的诚实度设计：不合并效应量、不评级质量、数字按原文引用、不跨基准拉到同一尺度、预印本标注为"未复制作者报告"——批判性叙述综述的方法自律

  • 非系统综述/元分析：不做效应量合并与质量分级， purposive 抽样强调设计差异
  • 数字跨基准/agent/预算绝不同尺度，只做设计逻辑剖析

趋势判断

  • 评估方法学正在从"基准分数"转向"估计量声明"：Huang 的排名方法学 + 本文的组件方法学 = 2026 年 Agent 评估的因果推断转向已成型，预计 principal stratification、off-policy 估计、同时置信区间将进入 agent 论文标配
  • skill 库研究焦点将从"检索质量"转向"准入策略"：contamination 相变 + shadowing 选择瓶颈 + SameCapRisk 风险暴露指向同一结论——库的治理（admission/组成/风险标注）比库的检索更重要，对应开放问题"演化库的准入策略评估"
  • presence effect（元数据即处理）会被规范化：开放问题明确提议基准内置 metadata-only 臂，skill 描述本身的影响将从传闻变为常规测量
  • replay 类廉价评估将持续退潮：61–94% 动作重写的证据使"replay 有效性需按组件验证"成为新默认，closed-loop 小样本 pilot（如 50 任务）成为成本折中
  • Agent 能力来源的迁移决定评估重心：结论句"Agents now draw much of their capability from what they retrieve"——评估检索就是评估能力本体

拓展应用推荐（借鉴点与优先级）

  • P0 🔨 skill-stress-test / skill-ab-testing 升级：现有 A/B skill 流程可植入论文框架——报告六轴（尤其耦合方式与 run 数）、报告 (π, D_pair, D_skip) 三元组而非单一差值、用同配置噪声底区分翻转与伤害。工作量：改造现有评估脚本输出格式 + 每臂 ≥3 runs，约 1 天。收益：skill 取舍决策从"单次差值"升级为"可辩护估计量"
  • P0 🔨 evolver/curator 准入门控前置：contamination 研究证明入池前 admission gating 避免库级相变，且事后删除只恢复小部分损失。Hermes 的 skill 合并/清理流程应在入库前加最小验证（对照完整任务集跑 vs 不跑），而非事后清理。工作量：在 curator 合并前插一个 dry-run 门，约半天
  • P1 ⚠️ skill index 的 presence effect 审计：系统提示中 400+ skill 描述每条都有存在效应（shadowing 的选择项 0.14 是主瓶颈）。审计 index 每条 description 的必要性——未被调用的技能元数据也在改变行为。障碍：需要 metadata-only 对照实验框架，成本较高，可先做描述长度/条数与任务表现的粗相关
  • P1 🔨 工具输出盲从检测（GNND deference 97.6–99.2%）：与已吸收的 binding-drift 交叉验证门禁互补——工具输出与 agent 自主判断的一致率过高本身就是风险信号，可在 Hermes gateway 工具调用后加"采纳率"遥测。工作量：工具结果处理处加计数器，约 2 小时
  • P2 🔨 cron 效果评估的预算约束声明：本 skill 生态的 cron job 效果评估（watchdog/evening-summary）应区分"总效应"与"同预算对比"——评估一个 cron 是否值得，比较基线应是把同样的 token/时间预算给替代方案。工作量：评估模板加两字段，约 1 小时
  • P2 ⚠️ replay 式会话回放的适用边界标注：session 重放/轨迹评分类分析（session-evolution-scan 等）对"改变后续动作的组件"不可靠（仅 3% 状态有效），结论只可用于描述不可用于反事实。障碍：无需工程，只需在相关 skill 中加 pitfall 标注，10 分钟

指南分析（报告清单操作化）

论文 Table 4 的 9 项报告清单，逐项映射到 Hermes skill 评估可直接套用的检查动作：

  • 问题与对比：先写一句话——这是部署决策/组件选择/状态级决策？每臂看到什么？→ skill A/B 测试的 README 首行
  • 目标总体：任务分布是什么？与检索基准的查询分布一致吗？→ cron 任务集是否代表真实负载
  • 单位/耦合/run 数：比较单位；臂间独立/共享种子/状态分叉；每任务每臂 run 数与 run 间方差 → 强制 ≥3 runs 并报方差
  • 识别：什么假设下汇总量是因果的，或明说是协议特定 → 触发条件化结果必须带此声明
  • 触发分层：触发率 π + 触发/未触发两个配对对比 + 触发定义 → skill 加载率与加载/未加载子组分开报
  • 不一致与退化：gain/regression 计数 + 若声称伤害则给确信/可能退化双份额 → "skill X 弄坏了 Y 任务"类结论的门禁
  • 预算：各臂 token/调用/延迟；效率声称需事前上限或成本-成功前沿 → cron 成本核算
  • 协议：closed loop / branching / replay，replay 需该组件的验证证据 → 会话回放结论的适用范围标注
  • 组件指标与库状态：集合/前置覆盖与风险暴露（不止单项召回）；库大小/版本/准入规则 → skill 库快照哈希入评估报告
