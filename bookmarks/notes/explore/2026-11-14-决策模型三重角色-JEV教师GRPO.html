决策模型三重角色：演员不行却能当好老师（JEV 教师×GRPO）

〇、定锚：我的现状与目标

我正在做的 DUCK-Pi_5 强化学习项目长期受困于 outcome-only 奖励的稀疏性：一整条 episode 结束才给一个 0/1（站住/摔倒），GRPO 在这种奖励下信号极弱，每一步动作被同等 credit，学不到"哪一步导致了倒"。用户 1015 起反复强调"训练配方决定一切"，reward shaping 是当前最大的杠杆。这篇论文恰好给出一条不依赖步骤标签、不训练 critic、不需要额外模型在线的步骤级监督路径——用冻结的决策模型在 episode 结束后回看整条轨迹，对每个动作打分，把这个分数叠加到 GRPO 的 outcome advantage 上。目标：把这套配方评估是否可迁移到 DUCK 的 MuJoCo 训练，作为下一次发版的候选 reward 改造。

一、内容详细整理

1.1 问题定义：一个决策模型，三种问法〔方法，2026〕

决策模型 = 输入问题 + 上下文，输出带概率的类型化答案（不是自由文本生成）。同一个模型可以：
- Actor：每步前选下一个动作（先看 prefix，未见后果）
- Judge：对已记录轨迹中的每个动作打分（yes/no 问题，返回 [0,1]）
- Teacher：对正在训练的策略 rollout 打分，分数在 rollout 组内中心化后叠加到 GRPO 的 outcome advantage 上；训练时模型冻结、测试时不用

1.2 六个模型 × 两个环境〔数据，2026〕

  • 专用决策模型：JEV（System One，API only）、Decider v1.2（Qwen3.8-27B 全量微调，开源权重）、GPT Decisions（GPT-6 Luna，API only）
  • 通用 LLM 当决策模型：Qwen prompted / Qwen constrained（Qwen3.8-27B）/ GPT Luna（GPT-6 Luna）
  • 环境：ALFWorld（家庭任务）、WebShop（购物）；都含"必须先做 A 再做 B"的依赖子目标

1.3 Finding 1：演员在依赖子目标上集体翻车〔数据，2026〕

ALFWorld 上所有 6 个模型在需要先后顺序的任务（Clean/Heat/Cool：先处理物品再放置）上失败率远高于无序任务（Pick/Pick2）。

  • JEV 在 Pick2（两个独立子目标）上成功率 70.8%，但在 Heat 任务上 ≤18.8%，Overall 仅 42.9%
  • Decider v1.2 是最强 Actor（63.6%），Heat 上也只有 18.8%
  • 机制：在 116 个诊断状态（ actor 能一步完成简单子目标，但前置子目标还没完成）上，把"加热杯子并放到桌上"改成"加热杯子"（去掉简单子目标），JEV 给前置动作的概率从 14.6% 跳到 77.6%——模型知道该做什么，只是被简单子目标勾走了
  • 提示工程救不了：加"考虑任务依赖"的 hint 只让成功率变化 -2.8% 到 +5.2%；加带例子的 hint 也只能把 JEV 从 19.0% 提到 24.1%（Decider v1.2 反而从 89.7% 降到 85.3%）

1.4 Finding 2：同样的模型当法官就变聪明了〔数据，2026〕

判断一个动作的贡献，取决于看到什么（Prefix / Hindsight 全轨迹）和问什么（Value：任务会成功吗？/ Progress：这个动作有帮助吗？）。

  • Hindsight 让 JEV 对"前置子目标"动作的均分从 0.41 升到 0.59，6 个模型方向一致
  • 但只看 Hindsight 不够：问 Value（任务会成功吗）时，同一轨迹内所有动作得到几乎相同的分数（差距 0.05），因为答案永远是轨迹最终结果——信号塌缩成 outcome reward 的复读
  • 问 Progress（这个动作有帮助吗）：能完成子目标的动作比无效动作高 0.36 分，信号被拉开
  • 决策模型比通用 LLM 当法官更准，且每打一次分便宜 28%~43%

1.5 Finding 3：教师端结果——1.5B 学员打赢 7B〔数据，2026〕

Table 3 主结果（Qwen2.5-1.5B-Instruct）：

  • GRPO baseline：ALFWorld 72.8% / WebShop 56.8%
  • Prefix + Value：ALFWorld 79.0% / WebShop 67.7%
  • Prefix + Progress：ALFWorld 78.3% / WebShop 66.6%
  • Hindsight + Value：ALFWorld 69.3% / WebShop 68.3%
  • Hindsight + Progress（JEV 教）：ALFWorld 82.9% / WebShop 71.4% ← 最优

关键交叉验证：
- 1.5B + JEV 教师（82.9%）打赢 7B + 纯 GRPO（77.6%），ALFWorld 上
- WebShop 同样：1.5B + JEV（71.4%）≈ 7B + 纯 GRPO（66.1%）之上
- 增益最大的是 JEV 当演员最差的依赖任务：Heat 任务上 Hindsight+Progress 让 1.5B 学员成功率 89.6%（其他配方 66.7%~83.3%），而 JEV 自己当演员 Heat 只有 18.8%
- Hindsight 下 Prefix 与 Progress 差距消失（ALFWorld Value 69.3% vs Progress 82.9%，差 13.6pp；Prefix 下两者差不多）

1.6 成本与可负担性〔数据，2026〕

  • 训练一次跑下来 API 调用费用 22~30 USD（每步打分 × rollout 数）
  • Teacher 不进测试路径，推理时零开销
  • 116 条评估轨迹全部通过独立重放验证

二、查询拓展

2.1 GRPO 组内中心化的语义〔补充〕

GRPO（Shao et al. 2024，DeepSeek-R1 同款）对同一 prompt 采样 G 条 rollout，用组内奖励均值作 baseline。本文把步骤分数在每个 rollout 组内中心化后加到 outcome advantage 上，相当于给每一步一个"相对同组其他 rollout 该步表现"的信号，避免绝对分漂移。

2.2 与 Process Reward Model (PRM) 的差别〔对照〕

Lightman et al. 2024 的 PRM 需要每步人工标签或训练一个专门的步骤评分器；本文的 JEV 是冻结的现成 API 模型，不训练不微调，零步骤标签。代价是需要黑盒 API 且模型质量决定上限。

2.3 与 LLM-as-a-Judge 的差别〔对照〕

常规 LLM-as-a-judge（Zheng 2023）用在评测；本文把它挪进训练回路当 Teacher，且证明了问句设计（Progress vs Value）和上下文设计（Hindsight vs Prefix）才是信号质量的决定因素——这与 prompt 工程的"问法比模型重要"经验一致。

2.4 局限（作者自己承认）〔补充〕

  • 两个环境都是文本任务，episode ≤30 步；软件工程、真实 tool use 这类长轨迹是否还成立是开放问题
  • Judge 只能离线打分；在线场景（只看到 prefix）下 Progress 优势消失
  • JEV / GPT Decisions 闭源，不知道什么训练让它成为好法官；Decider v1.2 开源但未对齐这个用法

三、归纳总结

3.1 三维信号质量框架

             看到什么 (context)
              Prefix      Hindsight
            ┌──────────┬──────────┐
    Value   │ 中等信号  │ 信号塌缩  │   ← 问句决定粒度
问 →        │          │ (=outcome)│
    Progress│ 中等信号  │ 最强信号  │
            └──────────┴──────────┘
              ↑             ↑
        在线可用的上限   训练回路的甜点

核心论点：一个动作的价值本质上取决于"后面发生了什么"，所以演员必须预测未来（难），法官只需回忆过去（易）。Hindsight 把"预测"问题变成"归因"问题，决策模型擅长的就是后者。

3.2 三维护筛

  • 优点：证据链完整（Actor/Judge/Teacher 三角色统一对照 + 诊断状态实验 + preregistered held-out 比对 + 独立重放）；效应量大（ALFWorld +10.1pp / WebShop +14.6pp）；成本极低（22-30 USD/run）；不需要改模型、不需要步骤标签
  • 缺点：环境单一（文本、短 episode）；增益依赖 JEV 这种专用决策模型可用，开源替代（Decider v1.2）是否能复刻未验证；Progress 问句的鲁棒性未做 sensitivity 分析；在线场景不可用
  • 借鉴点：问句设计与上下文设计的分离消融方法学本身就可以直接搬到 DUCK reward 设计（见七节）

四、趋势判断

趋势 1：决策模型作为"训练时副驾驶"会快速扩散〔上升〕

依据：HF 票选榜 2026-11 已有多篇相邻主题（2610.41453 evidence-guided recovery、2611.12872 HiVe-Mem），加上本篇 JEV，说明社区正把决策模型从"推理加速"重新定位到"训练加速"。机会：DUCK 类 RL 训练能直接抄这套 teacher 配方。

趋势 2：Hindsight Credit Assignment 会成为 RL post-training 的标配模块〔上升〕

依据：从 2024 的 outcome-only GRPO 到 2025 的 GiGPO（论文 baseline 用了 GiGPO），到 2026 的 JEV 教师，演化方向明确是"越来越细的 credit 分配"。预计 2027 会有开源决策模型专门对齐 Judge 角色。

趋势 3：Prompt-Engineering 的"问题设计"会独立成一个工程学科〔分化〕

依据：本文证明同一个模型问 Value 和问 Progress 差 13.6pp，跟模型能力一样大。风险：现在大家的 prompt 还靠手感，缺少像本文这样的对照实验纪律。

趋势 4：纯 outcome reward 在长程任务上会被淘汰〔退潮〕

依据：GRPO baseline 在依赖任务上输 Hindsight+Progress 6.9~16.2pp，且 1.5B + 好教师 > 7B + 纯 outcome，说明 outcome-only 是资源浪费。

五、关联分析

5.1 与 DUCK-Pi_5 强化学习的关联

DUCK 当前 reward = 存活时间 + 姿态对称性 + 前进距离（outcome 类）。缺步骤信号：迈错一步到摔倒要等几十步后才被 outcome 惩罚。JEV 教师的"episode 后回放 + 每步打分"完全匹配 MuJoCo 离线训练——可以在每条 rollout 收集完之后，用一个冻结的小模型对每步动作（关节目标 vs IMU 变化）打 Progress 分，叠加进 GRPO advantage。P0 候选。

5.2 与 Hermes Agent delegate_task 的关联

Hermes 子代理执行完返回给编排器时，编排器现在只能看到最终输出（outcome）。借鉴本文：让编排器对子代理的工具调用轨迹做 Hindsight + Progress 评分，喂进 skill-health-tier 的动态后验化——识别"哪些 skill 调用真的帮了忙"，而不是只看子任务成败。P1 候选。

5.3 与 MDSKILL (2611.05313) 的关联〔对照〕

MDSKILL 用 Thompson 采样做价值感知检索，本质是在检索时预测 skill 价值；JEV 教师训练时打步骤分。两者互补——MDSKILL 解决"选哪个 skill"，JEV 解决"这个 skill 这次调用有没有用"。

5.4 与 Beyond the Leaderboard (2607.05775) 的关联〔支持〕

Beyond 论文归纳的"Agent 六大失败模式"里有一条就是前置依赖被跳过（prerequisite miss）；本文从机制上证明这不是能力问题而是注意力被简单子目标劫持，并证明 prompt 救不了、只有事后归因能识别。

六、金句摘录

"A poor actor can still teach well, because judging an action after the episode ends reveals the consequences that acting must anticipate."

"The question sets the granularity of the signal." — 问 Value 时所有动作同分，问 Progress 才拉开 0.36 vs 0.05

"Actors know the required step but are drawn to the easier one." — 不是不知道，是被简单子目标勾走

七、行动启示与回访

我的结论：保留 Hindsight + Progress 的核心配方（问句设计 × 全轨迹上下文）；放弃用决策模型做在线动作过滤（Prefix 下没优势）；改造把 JEV 教师换成可本地部署的开源替代（Decider v1.2 或自己 SFT 一个 Judge）。

  • 行动 1：写一个 reward-shaping 试验分支 duck_reward_progress_shaping，在 Microduck 训练里把 step-level Progress 分叠加到 GRPO advantage（组内中心化），与纯 outcome GRPO 对照。时间：下次 GPU 开机窗口（≤1 周）。触发条件：现有 GRPO baseline 在站立任务上 plateau 连续 3 档横盘。验收标准：12/12 站立验收的 1000 iter 收敛速度提升 ≥20%，或同 iter 下成功率 ≥+5pp。
  • 行动 2：Hermes skill-health-tier 增加一个 hindsight_progress_score 字段，子代理返回轨迹时让上游 GLM 对每步工具调用做 Progress 评分，累积进 skill 价值。时间：本周内可开始。触发条件：delegate_task 调用 ≥10 次/天。验收标准：连续 7 天数据能区分"高价值 skill"和"被选中但没贡献的 skill"。

  • 行动 3：把本文的"诊断状态"方法学（116 状态干预实验）借用到 DUCK 真机调试——在能一步完成简单动作但前置未完成的状态下，逐关节干预看策略概率分布。时间：下次真机窗口。触发条件：出现"鸭子总选错顺序"类失败。验收标准：能在概率层定位到具体被劫持的关节。

  • 回访日期：2026-11-28（两周后）

  • 待验证假设/证伪条件：① 如果在 MuJoCo 连续控制上 Hindsight + Progress 不能在 500 iter 内提升样本效率（vs 纯 GRPO baseline），说明 JEV 的价值限于离散决策任务，DUCK 不适用 → 放弃行动 1。② 如果开源 Judge（Decider v1.2 或本地 SFT）打出的步骤分与 JEV 相关性 <0.6，说明必须依赖闭源 API，成本会破坏 AutoDL 预算 → 行动 1 降级为 P2。

八、拓展应用推荐

  • 代码 Agent 训练：SWE-bench 类任务的 trajectory 后处理打分，识别"哪次工具调用真正推进了 bug 修复"
  • 量化交易策略研究：回测后对每个交易决策做 Hindsight Progress 评分，区分"信号质量差"和"信号好但被噪声打断"，作为策略迭代的方向指示
  • Skill 库治理：Hermes skill-health-tier 给每个 skill 加" hindsight contribution score"，自动识别僵尸 skill
  • 教育/教练场景：学生作业批改用 Progress 问句（"这步推导有帮助吗"）而非 Value 问句（"最终答案对吗"），后者对所有错步骤都给同样的低分
  • 机器人真机调试：DUCK 每次摔倒后回放 IMU/关节曲线，对每个控制动作做 Progress 归因，定位"这一摔是哪步造成的"

九、指南分析

  • 方法学价值：本文是"控制变量消融"的范本——每换一个因子（goal/问句/上下文/角色）固定其余，116 诊断状态 + 58 paired units + 预注册 held-out 比对 + 独立重放，证据链完整。这种写法值得所有实验报告借鉴。
  • 可复用的判据：判断任何 LLM-as-judge 系统质量，先问三个问题——① 它看到 Prefix 还是 Hindsight？② 它被问的是 Value 还是 Progress？③ 分数在轨迹内有没有方差？三问下来信号质量基本能预判。
  • 反例：提示工程 hint 只让成功率动 ±5%，加例子也只救 10pp——这是"prompt 救不了架构问题"的又一实锤，跟 Beyond the Leaderboard 的"脚手架边际递减"定律一致。
  • 写作结构：Problem → 三角色定义 → Finding 1（Actor 失败机制）→ Finding 2（Judge 成功机制）→ Finding 3（Teacher 端到端验证）→ Takeaways → Limitations。这套"失败机制 → 成功机制 → 端到端落地"的三段式，比单纯堆 benchmark 数字更有说服力。
