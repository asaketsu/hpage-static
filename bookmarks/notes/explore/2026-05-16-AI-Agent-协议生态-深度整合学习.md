## 核心发现（跨笔记提炼）

### 1. 四层协议栈已成定局

| 层级 | 协议 | 作用 | 状态 |
|------|------|------|------|
| **工具层** | MCP | Agent ↔ 工具/数据源 | 事实标准，9700 万下载 |
| **协作层** | A2A | Agent ↔ Agent | Google 主导，50+ 伙伴 |
| **交易层** | ACP/UCP | Agent 商务交易 | 早期阶段 |
| **调用层** | Function Calling | LLM ↔ 函数 | 最成熟，最底层 |

**关键洞察**：不是"一个协议解决所有问题"，而是**分层组合**。

### 2. MCP 2026 路线图
- **捐赠给 Linux Foundation** → 中立治理，避免厂商锁定
- **传输层演进**：stateful → stateless HTTP，支持超大规模部署
- **新特性**：Remote servers、Auth、Structured Output、Long-running tasks
- **SDK v2**：Python 和 TypeScript 全新 SDK

### 3. Token 膨胀是 MCP 的核心痛点
- 大型 MCP Server 每次请求消耗 **10,000-30,000+ tokens** 仅用于工具描述
- **解法**：code-execution pattern（Agent 写代码与 MCP 交互）→ **98.7% token 缩减**

### 4. A2A 协议架构
- **Agent Card**：每个 Agent 发布 JSON 描述（能力、输入输出、认证）
- **Task 生命周期**：Task → In-progress → Completed/Failed
- **安全模型**：OAuth2 + mTLS 双向认证

### 5. 协作模式对比

| 维度 | Superpowers/Codex 模式 | A2A 模式 |
|------|------------------------|----------|
| 协作方式 | 单 Agent + SubAgent | 对等 Agent 互发现互调用 |
| 编排 | 中心化（主 Agent 派发） | 去中心化（Agent 自发现） |
| 上下文 | 精确注入，不继承历史 | 通过 Task 对象传递 |
| 适用场景 | 单项目开发 | 跨系统/跨组织协作 |

## 对 Hermes Agent 的启示

### 1. Skill 系统 → Agent Card
**现状**：每个 Skill 的 frontmatter 就是 mini Agent Card（name, description, category）

**进化方向**：
- 扩展 frontmatter，添加 `inputs`, `outputs`, `auth_required`, `level`（L1-L4）
- 生成统一的 Agent Card JSON，供 ubot 或其他 Agent 发现

### 2. delegate_task → Task 生命周期协议化
**现状**：subagent 任务无状态机，超时直接丢弃

**进化方向**：
- 借鉴 A2A Task 生命周期：`pending → processing → completed/failed`
- 给 subtask 加状态追踪，支持长任务流式推送
- 失败任务自动记录到 error-case-library

### 3. 与 ubot 的经验交换 → A2A 雏形
**现状**：`~/uclaw/data/hermes-exchange/` 交换池已是对等 Agent 通信雏形

**进化方向**：
- 标准化交换格式（Agent Card + Task + Result）
- 增加双向确认机制（类似 A2A 的 Task 生命周期）

### 4. Token 优化
**现状**：MCP 工具描述消耗大量 tokens

**进化方向**：
- 采用 code-execution pattern：让 Agent 写 Python 代码与工具交互，而非直接调用
- 为常用工具分配专属 MCP Server，避免每个 Agent 加载所有工具
