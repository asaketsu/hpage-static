主题: Redis 实时状态管理 — 交易系统场景的最佳实践

背景

量化交易系统需要实时同步以下状态：
- 账户持仓（positions）
- 订单状态（orders）
- 行情数据（market data）
- 策略信号（signals）
- 风控状态（risk status）

核心问题: 如何在高并发、低延迟场景下设计 Redis 状态管理架构？

Redis 数据模型设计

1. 账户持仓模型

# 账户持仓集合
SADD account:{account_id}:positions {lot_id_1} {lot_id_2} ...

# 持仓详情（HASH）
HSET lot:{lot_id} ticker "600000" quantity 1000 buy_price 15.50
HSET lot:{lot_id} current_price 16.20 pnl 700.00

# 持仓快照（JSON）
SETEX account:{account_id}:snapshot 60 '{"positions":[...], "total_pnl": 1200}'

优点:
- SET 快速查询账户所有持仓
- HASH 支持字段级更新（如 current_price）
- SETEX 定期快照，支持故障恢复

2. 订单状态模型

# 订单队列（LIST）
LPUSH orders:pending {order_id_1} {order_id_2} ...

# 订单详情
HSET order:{order_id} 
    account_id "A001"
    ticker "600000"
    side "BUY"
    quantity 100
    price 15.50
    status "PENDING"
    created_at 1716076800

# 订单状态变更（Pub/Sub）
PUBLISH order:status:changed '{"order_id":"O001","status":"FILLED"}'

3. 行情数据模型

# 实时行情（HASH）
HSET quote:600000 
    last_price 16.20
    volume 1000000
    high 16.50
    low 16.00
    timestamp 1716076800

# 行情订阅（Pub/Sub）
SUBSCRIBE quote:600000

# 行情历史（Stream）
XADD quotes:600000:history 
    price 16.20 volume 1000000 ts 1716076800

4. 策略信号模型

# 信号队列（Stream - 持久化）
XADD signals:new 
    strategy "MA_CROSS"
    ticker "600000"
    signal "BUY"
    confidence 0.85
    ts 1716076800

# 信号消费（Consumer Group）
XREADGROUP GROUP strategy_group consumer_1 
    STREAMS signals:new >
    COUNT 10

Pub/Sub vs Streams 对比

特性 Pub/Sub Streams
消息持久化 ❌ 不持久，离线消息丢失 ✅ 持久化，可重放
消息确认 ❌ 无确认机制 ✅ ACK 机制
消费者组 ❌ 不支持 ✅ 支持
适用场景 实时通知、聊天 事件溯源、日志
延迟 ~1ms ~1-5ms

推荐架构：混合模式

class HybridMessaging:
    """Pub/Sub 实时广播 + Streams 持久化"""

    def publish_signal(self, signal: dict):
        # 1. 存入 Stream（持久化）
        stream_id = self.redis.xadd(
            'signals:all',
            {
                'strategy': signal['strategy'],
                'ticker': signal['ticker'],
                'signal': signal['signal'],
                'ts': str(time.time())
            },
            maxlen=10000  # 保留最近 1 万条
        )

        # 2. Pub/Sub 实时广播
        self.redis.publish(
            'signals:live',
            json.dumps({'stream_id': stream_id, **signal})
        )

        return stream_id

优点:
- Pub/Sub 提供低延迟实时通知
- Streams 提供持久化和故障恢复
- 两者结合兼顾性能和可靠性

local buy_price = redis.call('HGET', lot_key, 'buy_price')
local quantity = redis.call('HGET', lot_key, 'quantity')
local pnl = (new_price - tonumber(buy_price)) * tonumber(quantity)

redis.call('HSET', lot_key, 'current_price', new_price)
redis.call('HSET', lot_key, 'pnl', pnl)

return pnl

故障恢复

1. 状态快照

def save_snapshot(account_id: str):
    positions = []
    for lot_id in redis.smembers(f'account:{account_id}:positions'):
        lot_data = redis.hgetall(f'lot:{lot_id}')
        positions.append(lot_data)

    snapshot = {
        'account_id': account_id,
        'positions': positions,
        'timestamp': time.time()
    }

    redis.setex(
        f'account:{account_id}:snapshot',
        3600,  # 1 小时过期
        json.dumps(snapshot)
    )

2. 恢复流程

def restore_from_snapshot(account_id: str):
    snapshot_json = redis.get(f'account:{account_id}:snapshot')
    if not snapshot_json:
        return None

    snapshot = json.loads(snapshot_json)

    # 恢复持仓
    for lot_data in snapshot['positions']:
        lot_id = lot_data.pop('lot_id')
        redis.hmset(f'lot:{lot_id}', lot_data)
        redis.sadd(f'account:{account_id}:positions', lot_id)

    return snapshot

安全建议

  1. 认证: 启用 Redis AUTH
  2. 网络隔离: 仅允许内网访问
  3. 权限控制: 使用 Redis ACL（Redis 6+）
  4. 数据加密: 敏感数据（如账户信息）加密存储
  5. 限流: 限制单个客户端的连接数和命令频率
