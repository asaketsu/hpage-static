# 飞书 Bot API 深度学习笔记

> 来源：飞书开放平台官方文档 + 实践案例
> 日期：2026-08-07
> 类型：auto-explore

## 一、摘要

飞书（Feishu/Lark）机器人分两大类型：**应用机器人**和**自定义机器人（Webhook）**。应用机器人基于开放平台创建应用、开启机器人能力，支持双向消息交互、事件订阅、服务端 API 全量调用；自定义机器人仅支持通过 Webhook 单向推送群消息，无法响应用户消息。开放平台提供 2500+ 个服务端 API，覆盖通讯录、消息群组、云文档、多维表格、日历、审批、视频会议等 12 个业务域。2025 年新增 AI 场景支持：流式卡片更新、跟随气泡、悬浮菜单等能力，专为 AI Bot 交互设计。

## 二、关键发现

### 2.1 两类机器人能力对比

- **应用机器人**：需开发者后台创建应用 + 管理员审核发布；支持发送消息/接收事件/群管理/单聊/外部群/卡片交互/全量开放 API
- **自定义机器人**：群设置中直接添加，获取 Webhook URL；仅支持单向推送（文本/富文本/图片/群名片/卡片）；频控 100 次/分钟、5 次/秒；请求体上限 20KB

### 2.2 核心交互链路

应用机器人完整交互链路：
1. 用户发消息 → 触发 `im.message.receive_v1` 事件
2. 服务端接收事件（Webhook 回调 或 长连接订阅）
3. 解析消息体，调用 `POST /im/v1/messages` 发送回复
4. 支持 `POST /im/v1/messages/{message_id}/reply` 回复指定消息

### 2.3 安全机制（自定义机器人三层防护）

- **自定义关键词**：最多 10 个，消息须包含至少一个关键词才发送成功（仅校验 text/title 参数）
- **IP 白名单**：支持单 IP 和 CIDR 段（如 `123.1.1.1/24`），最多 10 条
- **签名校验**：HmacSHA256 算法，`timestamp + "\n" + secret` 计算签名，Base64 编码，时间戳有效期 1 小时

### 2.4 消息类型体系

- text（文本）、post（富文本）、image（图片）、file（文件）、interactive（消息卡片 Card 2.0）
- Card 2.0：schema 2.0，支持 Markdown 元素、direction/padding 布局、响应式断点（pc/mobile）
- @ 用法：文本中 `<at user_id="ou_xxx">名字</at>`，卡片 Markdown 中 `<at id=ou_xxx></at>`

### 2.5 AI Bot 专属能力（2025 新增）

- **流式消息**：Card Kit 流式 API，AI 生成文本时实时更新卡片内容，体验类似 ChatGPT 打字效果
- **跟随气泡**：AI 回复跟随在用户消息气泡下方
- **悬浮菜单**：聊天输入框上方悬浮快捷操作
- **开场白推送**：订阅 `im.chat.access_event.bot_p2p_chat_entered` 事件，用户进入会话即自动推送欢迎语
- **流式更新最佳实践**：先创建卡片占位 → 节流更新（避免频控）→ 最终兜底全量更新确保完整性

### 2.6 lark-cli（官方 CLI 工具）

飞书官方开源了 `lark-cli`，MIT 协议，覆盖 IM、云文档、云盘、电子表格、多维表格、日历、邮件、通讯录、任务、事件、视频会议、画板 12 个业务域。一条命令安装：`npx @larksuite/cli@latest install`。

## 三、对工作的价值

1. **Hermes Agent 飞书集成**：Hermes 已通过 `lark-*` 系列 Skill（lark-im/lark-doc/lark-base 等）深度集成飞书。理解 Bot API 底层机制有助于排查消息发送/事件订阅/卡片渲染问题
2. **AI 流式输出优化**：Hermes 的飞书渠道支持 `streaming.mode: "partial"`（默认）实时更新卡片。在 AI 回复较长时，流式卡片体验远优于一次性发送
3. **自定义机器人 Webhook**：适合简单告警推送场景（如 cron 产物摘要），无需审核，配置简单。但无法响应用户消息，交互场景必须用应用机器人
4. **安全配置**：自定义机器人的签名校验（HmacSHA256 + timestamp）是防止 Webhook 泄露滥用的关键，Hermes 推送脚本应启用签名校验

## 四、行动建议

- [ ] 检查 Hermes 飞书推送脚本（cron-output-formatter 等）是否启用了签名校验
- [ ] 评估流式卡片更新是否可用于长回复场景（当前 Hermes 默认 `streaming.mode: "partial"` 已启用）
- [ ] 自定义机器人频控 100 次/分钟，大量批量推送应做队列化 + 避峰调度
- [ ] 对于需要双向交互的场景（如用户回复触发后续操作），确认使用应用机器人 + 事件订阅，而非自定义机器人
