一、内容整理

1.1 核心问题与动机

LLM Agent 在长程任务上面临两大系统性瓶颈，而「单体 prompt 工程 + 无状态工具调用」范式无法解决：

  • 可靠性瓶颈：失败在步骤间分布不均——Agent 对早期执行错误和路径解析错误异常脆弱，错误向下游传播污染后续推理；且 Agent 极少察觉早期步骤出错，进入「无恢复区」（循环或耗尽递归上限），而非回头修正错误前提
  • 零积累瓶颈：成功完成任务不会带来持久优势——过程知识锁在会话结束时即丢弃的转录本里，每次遭遇同一任务都重新推导已经正确执行过的例程

两条标准补救路线都不奏效：
- 过程知识放 context window → token 成本随指令集增长，且无法只加载任务所需的部分
- 微调写进权重 → 但 Agent 需要的例程绑定于工具/API/组织约定，其变化速度快于再训练周期

外部化可执行技能（agentic skills） 正是对第二瓶颈的回应：把激活条件、过程指令、工具声明、可执行资产打包为模型之外的模块化工件——跨会话持久、按需加载、无需重训即可修订。

1.2 六元组形式化与成员三判据

论文将 agentic skill 形式化为六元组：

s = (A, I, C, T, π, E)

A : 激活条件        A(x_t, g) → {0,1}，按当前状态与目标判定是否装载
I : 过程指令        SOP 正文、指导文档
C : 应用约束        环境前置条件、适用范围
T : 工具接口        可访问的工具与 API 声明
π : 执行策略        过程控制流（含错误处理逻辑）
E : 状态转换        意图达成的后置效果（post-conditions）

成员三判据（Triad Membership Criteria）——一个工件要成为「技能」必须同时满足：

  1. 封装模块化：离散外部化资产，捆绑过程逻辑、接口声明 T、约束 C；可独立创作、版本化、验证、更新，不触碰模型权重与 harness 全局代码
  2. 晚绑定动态调用：不常驻 prompt，由激活函数 A(x_t, g) 动态评估后按需装载进活动记忆
  3. 过程状态转换：编码「如何执行 + 如何处理错误」的操作知识，而非声明性事实或编年史记录

边界案例澄清（用三判据裁剪模糊地带）：

  • 全局系统提示（如「所有输出用 JSON」）= 静态参数化，非技能；按需注入的「React 组件重构 SOP」= Instructional Skill
  • 裸 web search API = 无状态原子工具 T；捆绑多步编排 + 状态跟踪 + 恢复逻辑（检查 HTTP 状态码、超时回退缓存端点、解析 DOM）的包装 = Tool-Execution Skill
  • 硬编码 ReAct 循环 = 运行时基础设施；序列化为外部资产、动态检索用于子目标的编译-测试-解析-补丁 DAG = Composite Skill
  • 情景记忆（被动轨迹日志 E）与瞬态计划（单次草稿）都不是技能；技能是跨会话持久的泛化可复用过程模板

1.3 九阶段生命周期（论文主体）

① Discovery 发现    ② Authoring 表征   ③ Storage 存储
④ Retrieval 检索    ⑤ Composition 组合  ⑥ Execution 执行修复
⑦ Adaptation 适应   ⑧ Evaluation 评估   ⑨ Security 安全治理

① 发现与获取：发现算子 D 把轨迹历史 H = {τ(1)...τ(N)} 映射为候选技能集。最优子轨迹 τ_i:j 需满足两条件：(1) 持久环境结果——诱导可预测的状态转换 E；(2) 熵最小化——降低未来策略决策的分支因子。论文对比 19 个框架，按创作模态分四档：

  • 自主 RL（SkillRL / Skill-Pro / Skill-R1 / Skill0）：对比成功失败轨迹对做 RL 优化，提交前用单元测试门禁
  • AI 合成（SkillOpt / Voyager / AutoSkill / EvoSkill / Trace2Skill 等）：LLM 从轨迹生成 SOP，失败信号用作修复反馈或拒绝过滤，LLM-judge 或单元测试把关
  • 混合（AI 合成 + HITL 人工审查）
  • 纯手工（EasyTool）

③ 存储与记忆架构：沿经验压缩连续体分层——情景记忆 1:1 原样保存轨迹；过程记忆 10–100× 压缩为可执行技能；语义层更高压缩比（ExperienceSpectrum 达 5–1000×）。11 个系统的驱逐/压缩策略分三类：

  • 虚拟 OS 分页（MemGPT 的 LLM 控制页面交换；SKILL.state 的临时推理即弃）
  • 效用感知策展（SkillOps 5 维健康分剪枝技能债；MEMP/SkillBank 的 hindsight 效用剪枝对抗检索污染）
  • 语义轨迹压缩（ContinualMem 对抗灾难性遗忘）

④ 检索与动态路由：技能库规模到 |M|>10^4 后全量塞 prompt 不可行。两阶段管线：

Stage 1 候选生成:  Top-K ← α·Sim(f_θ(x_t,g), e_s) + (1-α)·BM25(g, doc(s))
Stage 2 重排门禁:  cross-encoder 对「完整任务提示 × 全文过程指令」联合打分
                  + 激活约束 + 权限门控

8 系统四范式：Retrieve-then-Rerank（SkillRouter 在 80K 技能上 1.2B 管线做到亚秒中位延迟；纯 metadata 路由会盲区，掉 31–44%）→ 图结构搜索（GraSP/Gra phOfSkills 按依赖边遍历子图工作流）→ Agentic 导航（CORPUS2SKILL 离线蒸馏成层级目录，Agent 主动钻树+回溯，无向量库）→ 跨 Agent 动态路由（SkillOrchestra 按能力画像转发）。

⑥ 执行、验证与修复（工程含金量最高的一节）：

  • 能力门控：激活蕴含权限子集约束 A(x_t,g)=1 ⟹ T_s ⊆ T_permitted(x_t)——技能声明的工具必须是当前执行上下文已授权工具的严格子集，违反则在分发前拦截，防权限提升与 confused-deputy 攻击
  • O(T²) → O(T)：ReAct 式 append-only 历史导致累计 token 二次方膨胀。SKILL.state 用显式可变执行状态 Σ_t 替换——每步 LLM 只见紧凑元组 (P, Σ_t, O_t)，产出验证过的状态补丁 ΔΣ_t，中间推理 R_t 应用后立即丢弃，每步 prompt 占用 O(1)，长程基准 token 成本降为线性且通过率反升
  • 沙箱：技能执行任意 shell/代码/API 变更，必须隔离容器 + syscall 过滤 + 网络出口限制；实证压力测试显示前沿 LLM 在环境误配置下有不可忽视的容器逃逸能力
  • 运行时验证三范式：契约式不变量（前/后置条件 + 违反时综合结构化反例定位失败转换）；工具交互式 critique（CRITIC/Self-Refine 用 linter/单测/搜索做次级验证器）；以及执行前沙箱预演

⑦ 适应与进化：短期（会话内）verifier 引导的参数动态调优 + 交互式自省纠错；长期（跨会话）三条路线——Skill-Pro 把技能当 Skill-MDP 的 options，非参数 PPO 从轨迹批提取自然语言语义梯度迭代改写文本指令；Skill-R1 双层 RL（内环优化执行参数、外环更新库成员与指令表述）；AutoSkill/SkillClaw 部署元技能 m: S→S 做自动重构、接口标准化、冗余剪枝。核心洞察：技能孤立进化是次优的，决策策略 π_dec 与技能库 M 必须共进化。

⑧ 评估七维度：正确性（SkillsBench 87 任务×8 领域×18 模型-harness 配置，技能注入显著提升通过率；SWE-SkillsBench 49 个 SWE 技能×565 真实 GitHub 任务）、终身持续学习、开放注册表噪声鲁棒性、可组合性、token 经济与延迟、可解释性、安全。

两个最重要的实证发现：

  • 野外退化（in-the-wild degradation）：Liu 等审计 34,000 个真实技能——强制加载 oracle 技能效用很高，但让 Agent 从开放池自主检索时，因 distractor 噪声「严重退化」，大量轨迹根本检索不到所需能力
  • 组合深度惩罚：TaskBench 1000+ 工具图上，执行准确率随 DAG 深度指数下降（接口错配复合放大）

1.4 安全：18 个威胁向量与市场防御

技能分发构成完整供应链攻击面，每个漏洞类映射到六元组具体组件——未验证组件 I（指令）和 A（激活）是零点击权限提升的主通道：

  • 间接 prompt 注入 → I：隐藏 HTML 注释（HiddenCommentInject）、markdown 正文注入、多模态隐藏指令、辅助脚本注入——全部导致目标劫持
  • 后门/木马 → π：分裂加密后门组合（SkillTrojan）、技能内模型权重投毒（BadSkill）、自动化红队路径精炼（SkillAttack）、动态运行时逻辑注入——沙箱逃逸或目标劫持
  • 凭证外泄 → T,π：技能代码体内嵌恶意代码（MalTool/MaliciousAgentSkills）、实证凭证外泄研究
  • 生态系统与供应链风险：
  • BehavioralIntegrity 审计 49,943 个公开技能：80.0% 偏离其声明行为（description-implementation gap）
  • SCR-Bench 多技能组合：良性技能共享执行上下文也会产生能力升级与授权混淆，33.6% ASR
  • SkillSec-Eval（327 个真实企业技能）：无防御管线普遍存在恶意准入、Sybil 检索劫持、规划器被伪造社会证明推荐操纵

防御方向 = 零信任程序架构：约束引导的 Datalog 形式化验证（SemiA）+ 硬件强制能力沙箱 + 加密来源签名（SecureAgentSkills）。

1.5 分类学与生态

五维分类：Instructional SOP 技能 / Tool & API 调用技能 / 推理规划技能 / 领域执行技能（软工、GUI/OS 导航、具身机器人）/ 协作与元技能。生态层面正从孤立脚本仓库转向去中心化社区市场：AgentSkillOS 验证了 200→200,000 技能规模下「树检索 + DAG 组合」优于平面池；OpenSkillRisk 发现市场技能普遍权限过度请求。

1.6 六大开放挑战

  1. 跨模型可移植 + SLM 部署：当前创作重度依赖前沿模型；3B–8B 或量化端侧部署时频繁因 context 窗口、schema 脆弱、格式幻觉失败。需要模型无关序列化格式 + 把抽象过程准则编译为紧凑可验证状态机的轻量执行引擎
  2. 10^5+ 注册表亚秒路由：平面稠密嵌入检索因语义拥挤/近同义词混淆/distractor 碰撞而崩溃；需层级能力树 + 随任务态演化的自反 meta-router
  3. 图结构编译 + 局部性有界恢复：平面链任一中间失败 = 轨迹流产或 O(N) 全局重规划；typed DAG 使子树恢复 O(d^h)，应把契约不变量直接集成进 DAG 编译器实现可证明安全的运行时恢复
  4. 零信任市场 + 形式化程序验证：80% 描述-实现偏差 + 容器逃逸风险下，治理必须走向零信任
  5. 无过程漂移的终身共进化：Co-Adaptation Drift——噪声轨迹奖励强化次优启发式，腐蚀下游技能依赖
  6. 环境反馈带宽边界：Environment-Feedback Bandwidth Hypothesis——当环境本身提供高带宽、schema 验证的丰富诊断错误轨迹时，外部化技能的边际效用递减。这是对「技能是否值得」的理论性回答

1.7 局限性（论文自述）

  • 领域演进极快，具体框架/API 快照会过时
  • 侧重软工/OS 自动化/web 导航/数据分析；机器人物理动力学与硬件延迟约束覆盖浅
  • 分析限于英语与 Python/JavaScript 中心的技能实现

二、查询拓展

2.1 SkillsBench / AgentSkillOS 生态基准

2026 年出现的技能评测家族：SkillsBench（首个综合技能使用基准）→ SkillFlow（20 工作流族 166 任务的终身演化）→ SkillLearnBench（持续学习）→ 安全族（SkillSec-Eval / HarmfulSkillBench / SkillVetBench / SandboxEscape）。这组基准共同把「技能」从工程实践推向可测量科学对象。

2.2 MemGPT 虚拟内存分页

Packer et al. 2023 提出，把 OS 虚拟内存思想搬进 LLM context：主上下文=工作页面，长程内容=归档页面，LLM 通过显式函数调用自主换页。本文将其定位为技能存储层「虚拟 OS 分页」路线的源头，与本系列此前精读的 Memory Compaction 率失真框架（2607.08032）在「压缩层级」上互补。

2.3 Environment-Feedback Bandwidth Hypothesis

源自 Chacko et al. 2026。含义：反馈带宽 = 环境每次交互回传的可执行诊断信息量。编译器/单测/类型系统=高带宽（错误信息可直接定位修复）；开放网页/对话=低带宽。技能是对低带宽环境的补偿机制——环境本身教不了 Agent 的，才需要打包成过程知识。这个假设给出了「何时值得把经验固化为技能」的判据。

2.4 行为完整性审计（Behavioral Integrity Verification）

Wu et al. 对 49,943 技能做 description-implementation gap 审计发现 80% 偏离。与软件工程的 API 文档漂移（doc rot）同构，但攻击面更大：技能的「描述」同时是检索嵌入的来源和 Agent 决策依据，描述失真 = 检索污染 + 决策误导双重失效。

3.2 六元组与威胁向量的映射（安全审计表）

  • A（激活）+ I（指令）→ 未验证组件，间接注入与零点击提权主通道
  • π（策略）→ 后门/木马宿主（分裂加密、动态注入、权重投毒）
  • T（工具）+ π → 凭证外泄（恶意代码体）
  • I vs π 的偏差 → 80% 行为完整性缺口（生态级风险）
  • C + π → 多技能组合的权限升级面（33.6% ASR）

3.3 三条可迁移的系统设计定律

  • 状态优于历史：可变执行状态 + 即弃中间推理，把 O(T²) token 曲线压成 O(T)——长程任务的上下文经济学第一原则
  • 子集权限门控：技能工具集必须是授权工具集的子集，激活即校验——把 ACL 检查从「调用时」提前到「装载时」
  • 反馈带宽决定技能价值：高带宽验证环境（编译器/回测/单测）中技能边际效用递减，低带宽环境中技能是主要补偿——决定「往哪里投资技能工程」

四、趋势判断

趋势1：技能从工程实践走向「可验证的系统学科」

依据：六元组形式化 + 九阶段生命周期 + 19/11/8/6/18/17 个系统的六张大对比表，加上 SkillsBench 到 SkillSec-Eval 的评测家族——论文把散落的框架统一到一个参考架构下，这是任何领域「从黑客技巧到系统工程」的标准前兆。

趋势2：安全将成为技能生态的一票否决维度

依据：80% 行为偏差、33.6% 组合提权 ASR、327 企业技能全生命周期威胁实测——当技能市场规模化（10^4→10^5），准入审计/来源签名/能力沙箱会从可选项变成注册表标配，正如 npm/PyPI 供应链治理的演化路径。

趋势3：SLM/端侧部署倒逼技能「编译」而非「解释」

依据：开放挑战第一条明确指出 3B–8B 模型上技能因 schema 脆弱/格式幻觉频繁失败，方向是把自然语言 SOP 编译为紧凑可验证状态机。这与 Jetson 类边缘设备上的 Agent 落地需求直接合流。

趋势4：「自主检索技能」将取代「人工挂载技能」成为默认，但必须先解决野外退化

依据：34,000 技能审计显示 oracle 强制加载高效、自主开放池检索严重退化——检索质量（而非技能数量）是规模化后的真正瓶颈；层级能力树 + 自反 meta-router 是明确的下一代形态。
