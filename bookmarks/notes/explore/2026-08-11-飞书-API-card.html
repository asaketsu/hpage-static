飞书 API: card 深度学习笔记

日期: 2026-08-11
来源: 官方文档 + feishu-card-table skill 实战沉淀

摘要

飞书卡片=结构化内容嵌入协作场景的应用能力,让体验从"人找应用"变"应用找人"。核心是 轻交互+数据可视化+多场景复用,已深度集成到本机 Hermes 消息管线。

关键发现

  • 能力五要素: 结构化、嵌入式、轻交互、数据可视化(图表组件)、多场景复用(模板ID+变量)
  • 卡片 JSON 2.0 优先(基于 feishu-card-table skill 实测: v2 稳定可用,v1 旧版 header.title 用字符串会报 mismatched type)
  • 发送方式: 服务端消息 API / card_id 更新 / 流式更新 OpenAPI
  • 四种场景: 消息、消息链接预览、群置顶卡片

对工作的价值

  • 本机 Gateway 已能在 cron/交互式回复中自动路由 Card JSON 为 interactive 类型,无需手动调 SDK(2026-07-31 重构后 Markdown 表格走 post→md 原生渲染)
  • 深度卡片(交互按钮/表单/审批)仍需 lark_oapi SDK 或 lark-cli

行动建议

  • 日常结构化回复优先用 send_message 传标准 Card JSON(纯文本列表兜底)
  • 交互场景(审批/表单)用 lark-cli im +messages-send --msg-type interactive 或 SDK
  • Card 2.0 表格单元格必须用简单字符串,禁用嵌套对象与 markdown 表格
