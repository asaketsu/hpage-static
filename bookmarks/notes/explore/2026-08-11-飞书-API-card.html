飞书 API: Card（消息卡片）

嗅探学习 2026-08-11 | 来源：飞书开放平台官方文档 + apifox SDK 文档

摘要

飞书卡片（Feishu Card）是飞书开放平台的核心消息交互载体，可作为消息类型发送给个人/群组，支持静态推送、轻量交互、数据可视化与多场景复用。核心能力链路：搭建卡片 → 发送卡片 → 更新卡片 / 响应交互回调。

关键发现

  • 四大特性：结构化、嵌入式、轻交互（点一下就提交）、数据可视化（内置图表组件）、多场景复用（卡片模板 + 变量）
  • 三大场景：消息场景（静态推送/AI 机器人）、消息链接预览场景、群置顶卡片场景
  • 两种搭建方式：可视化搭建工具（生成 template_id，推荐）／手写卡片 JSON 代码
  • 发送/更新 API：调用发送消息 API 发送；/interactive/v1/card/update 更新；支持流式更新（streaming_mode + summary 字段）
  • 交互回调：card.action.trigger 事件；两种订阅方式——长连接 WebSocket（企业自建应用推荐，更安全高效）／Webhook 发送至开发者服务器
  • JSON 2.0 变更：废弃 note 组件与交互模块（action），改由富文本/按钮替代；新增 element_id 供操作组件
  • 长连接注意：最多 50 连接，3 秒内处理完成，集群模式非广播

对工作的价值

本机 jbot/ubot Gateway 已在飞书群内推送各类报表与告警。可把纯文本/普通消息升级为真实「卡片」，实现审批交互（同意/拒绝按钮）、进度展示（流式更新）、数据图表可视化，提升推送可读性与群内协作效率。

行动建议

  1. 优先用卡片搭建工具生成模板获取 template_id，避免手写硬编码 JSON
  2. 自定义机器人发卡走 webhook（现有基础设施即可用）；企业自建应用做交互回调推荐长连接
  3. 将现有 feishu-card-table/proactive-push 等推送从普通消息迁移为 2.0 卡片，先做 1-2 个高频报表试点
  4. 注意 JSON 2.0 是当前标准，新卡片一律用 2.0 结构
