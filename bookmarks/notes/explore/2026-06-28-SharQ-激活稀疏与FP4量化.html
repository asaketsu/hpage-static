一、内容详细整理

1.1 核心问题

LLM 推理的计算瓶颈在 线性层（GEMM）。两类硬件加速技术已成熟但互相隔离：

  • 低比特浮点格式（FP4）：NVFP4 / HiF4 / MXFP4，提升 Tensor Core 计算密度，但 激活值中的 outlier 主导块级 scale，导致普通值精度下降
  • 半结构化稀疏（N:M Sparsity）：4:8 / 2:4 模式，Tensor Core 原生支持，但 直接丢弃中等值导致稀疏化损失与量化误差耦合

核心矛盾：两种技术各有所长，但简单叠加会互相放大误差——稀疏化后的值分布改变了量化 scale，量化后的 scale 又影响了哪些值该被保留。

1.2 SharQ 方法论：在线稀疏-稠密分解

SharQ 的核心思路是 把"丢弃"重新定义为"路由"：outlier 走稀疏路径，剩余信息走稠密残差路径，两条路径协同补偿。

第一步：生成稀疏主干（Sparse Backbone）

  • 对每个激活张量，在线生成 N:M mask（4:8 in-pairs for NVFP4，2:4 for HiF4）
  • mask 选择每个局部 block 中 magnitude 最大的 top-k 元素
  • 稀疏主干 X_sp = M(X) ⊙ X，提取 outlier 主导的结构

第二步：量化稀疏主干并构造稠密残差（Dense Residual）

  • 稀疏主干量化到 FP4：X̃_sp = Dequant(Quant(X_sp))
  • 关键创新：残差 R = X - X̃_sp，而不是 R = X - X_sp

残差定义的精妙之处：R 不只是 mask 外的值（X - X_sp），还包含了稀疏路径的量化误差（X_sp - X̃_sp）。这样 R 同时承载了「稀疏化损失」和「稀疏量化损失」两个信号，用稠密 GEMM 统一补偿。

第三步：双路径重建

Ŷ_SharQ = GEMM_sparse(Quant(X_sp), Quant_sp(W))     ← 稀疏FP4主干
        + GEMM_dense(Quant(R), Quant_dn(W))          ← 稠密FP4残差补偿
  • 两条路径共享同一个 FP4 权重（Shared Weight Payload）
  • 通过 path-specific scale views 让稀疏路径和稠密路径用不同的 scale 粒度，无需复制权重

1.3 Kernel 设计：三大工程优化

① 融合准备 Kernel（Fused Preparation Kernel）
- 将 mask 生成、残差构造、RMSNorm 压缩到单个 operator
- 在线 mask 生成不再是独立的耗时步骤，而是被吸收到激活准备阶段
- 关键：避免 mask 生成暴露在推理关键路径上

② 共享 FP4 权重 + 路径特定 Scale
- 朴素实现需要两份 FP4 权重（稀疏一份、稠密一份）
- SharQ 只存一份 FP4 权重 body，通过不同的 scale 视图（group-32 sparse / group-16 dense）让两条路径复用
- 显存零增加

③ 累加式残差补偿（Accumulation-Based Compensation）
- 稠密 GEMM 的输出直接累加到稀疏 GEMM 的输出
- 保持接近单 kernel 的数据流，避免中间 buffer 读写

1.4 理论分析

论文从块级量化误差的角度证明：
- 单路径 FP4（无稀疏）的误差 = 量化误差
- 单路径稀疏 FP4 的误差 = 稀疏化损失 + 量化误差（耦合放大）
- SharQ 双路径的误差 = 残差量化误差（二阶小量，因为残差已去除了 outlier，值分布更均匀，FP4 量化更精确）

1.5 实验结果

语言模型准确率（恢复 NVFP4 精度损失）

  • Llama-3.1-8B：恢复 56% 的 NVFP4→FP16 精度差距（平均 70.32% → 71.55%，FP16 为 72.50%）
  • Qwen2.5-7B：恢复 63% 的差距（69.43% → 70.38%，FP16 为 70.94%）
  • Qwen3-30B-A3B（MoE）：恢复 ~50% 的差距（68.40% → 69.17%）
  • WikiText2 困惑度：Llama 从 6.94 降到 6.73（FP16=6.25）
  • MMLU：Llama 从 61.93 提到 63.76（FP16=65.24）

多模态（Qwen3-VL-8B）
- 恢复 43% 的 NVFP4→FP16 差距（79.97% → 80.57%，FP16 为 81.37%）
- TextVQA（最敏感任务）恢复率 52%
- POPE（幻觉抵抗）改善 0.47pp

推理效率（RTX 5090, vLLM 集成）

  • vs FP16：请求延迟降低 55-60%（2.2-2.4x 加速）
  • vs FP8：总 token 吞吐提升 1.2-1.4x
  • seqlen=2048 时：SharQ 4491 tokens/s vs FP8 3146 tokens/s
  • 视频（Wan2.2-T2V-A14B）：SharQ+SageAttention 达 1.58x 加速（480P 从 223s → 142s）

消融实验

  • 仅稀疏路径：灾难性退化（WikiText2 困惑度 82.95，MMLU 25.78%→接近随机）
  • 双稠密路径：精度好（WikiText2=6.63）但无稀疏加速收益
  • 双稀疏路径：与 NVFP4 基线相当，无额外收益
  • SharQ（稀疏+稠密）：精度匹配双稠密，同时保留稀疏加速 — 证明非对称分解是关键

格式无关性：NVFP4 / HiF4 / MXFP4 三种格式均有提升，MXFP4（最弱基线）受益最大（WikiText2 困惑度降 0.51）

二、查询拓展

2.1 NVFP4 数据格式

NVIDIA Blackwell 架构引入的块级缩放 FP4 格式。每个 FP4 元素配一个局部 block scale（group of 16），外加一个全局 per-tensor scale。相比纯 INT4，FP4 保留了浮点动态范围。Tensor Core 原生支持 NVFP4 + 4:8 in-pairs 稀疏的联合执行路径。

2.2 N:M 半结构化稀疏

硬件约束的稀疏模式：每 M 个连续元素中只保留 N 个非零值。NVIDIA Ampere 起支持 2:4（每4个保留2个），Blackwell 新增 4:8 in-pairs（每8个保留4个，成对约束）。通过专用 Tensor Core 指令实现接近 2x 的理论加速。

2.3 激活值 Outlier 问题

LLM 激活值中少量大幅值 outlier 主导了块级量化的 scale，导致同块内的普通值被压缩到极低精度。LLM.int8()、SmoothQuant 等先驱工作已证明 outlier 是低比特量化的核心障碍。SharQ 的创新在于用稀疏路径"隔离" outlier 而非暴力压缩。

2.4 vLLM 推理框架

当前最流行的 LLM 服务框架，核心创新是 PagedAttention（操作系统式 KV Cache 内存管理）。SharQ 直接集成到 vLLM 中验证端到端效果，证明其可作为 plug-and-play 推理原语。

三、归纳总结

3.1 核心设计模式：路由而非丢弃

┌─────────────────────────────────────────────┐
│            原始激活 X（含 outlier）            │
└──────────────────┬──────────────────────────┘
                   │ 在线 N:M mask
         ┌─────────┴─────────┐
         ▼                   ▼
  ┌──────────────┐   ┌──────────────┐
  │ 稀疏主干 X_sp │   │ 残差 R=X-X̃_sp│
  │ (outlier)    │   │ (含量化误差)  │
  └──────┬───────┘   └──────┬───────┘
         │ FP4量化           │ FP4量化
         ▼                   ▼
  ┌──────────────┐   ┌──────────────┐
  │Sparse GEMM   │   │Dense GEMM    │
  │(4:8/2:4加速) │   │(FP4补偿)     │
  └──────┬───────┘   └──────┬───────┘
         │                   │
         └────────┬──────────┘
                  ▼
         Ŷ = Sparse输出 + Dense残差补偿

3.2 对比维度

  • vs 纯 FP4 量化：SharQ 多了稀疏路径的加速 + 残差补偿的精度恢复
  • vs 纯稀疏：SharQ 不丢弃信息，用稠密路径补偿稀疏损失
  • vs FP8：更低精度（FP4）+ 稀疏加速，吞吐反超 FP8
  • vs 校准量化（GPTQ/AWQ）：SharQ 完全免训练免校准，即插即用
  • vs 预测式稀疏（DejaVu/PowerInfer）：SharQ 的 N:M mask 更简单直接，无需训练预测器

3.3 关键数字记忆点

  • 56%：Llama-3.1-8B 上的精度差距恢复率
  • 2.2-2.4x：vs FP16 的延迟加速
  • 1.2-1.4x：vs FP8 的吞吐提升
  • 0：训练数据 / 校准数据 / 模型特定调优需求

四、趋势判断

趋势1：FP4 + 稀疏联合优化将成为 Blackwell 时代的标配

依据：NVIDIA Blackwell Tensor Core 原生支持 NVFP4 + 4:8 稀疏联合执行路径。SharQ 是第一个 training-free 地利用这一硬件能力的推理方法。随着 RTX 5090 / B200 普及，更多工作会沿此方向展开。

趋势2：在线自适应 mask 替代离线校准

依据：传统量化方法（GPTQ/AWQ/SmoothQuant）依赖校准数据集和离线优化。SharQ 证明在线生成的 N:M mask 可以同时满足硬件约束和输入自适应性。这一范式将向更多模型组件扩展（KV Cache 量化、注意力稀疏化等）。

趋势3：稀疏-稠密分解模式向其他算子迁移

依据：SharQ 的"路由而非丢弃"思想可推广到注意力层（重要 token 走精确计算，次要 token 走近似）、KV Cache（热 token 保留 FP16，冷 token 量化压缩）。TOPS（同日发表的视觉 token 剪枝）也采用了类似的最优保留集思想。

趋势4：Edge/端侧部署的直接受益者

依据：Jetson Orin 的 Ampere 架构支持 2:4 稀疏，Jetson Thor 预计支持 FP4。SharQ 的免训练特性和共享权重设计非常适合端侧设备的固定模型+动态输入场景。

「SharQ reframes sparsification as routing rather than dropping」— 稀疏化不是丢弃，而是路由

「The residual R is not merely the values outside the sparse mask. It also contains the representation error introduced when the retained outliers are quantized into FP4」— 残差同时承载稀疏损失和量化损失，用稠密路径统一补偿

借鉴点1（P1 可直接移植）：共享权重 + 路径特定 Scale 的设计模式

借鉴点2（P2 需工程改造）：在线 N:M mask 用于动态量化

  • 适用场景：Jetson Orin 上对长序列输入做自适应稀疏化

  • 行动：监控 Jetson Thor 的 FP4 支持状态，准备好迁移方案

借鉴点3（P1 可直接移植）：融合 Kernel 的思路用于 Hermes cron 任务

  • 适用场景：SharQ 将 mask 生成 + 残差构造 + LayerNorm 融合到单个 kernel，避免关键路径开销
