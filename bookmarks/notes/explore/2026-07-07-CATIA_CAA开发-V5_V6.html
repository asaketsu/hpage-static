CATIA CAA 开发 V5/V6 — 深度学习笔记

日期: 2026-07-07 | 来源: Dassault 官方文档 + tecwin + myCAD forum

摘要

CATIA CAA (Component Application Architecture) 是达索系统原生 C++ API 框架，用于扩展和定制 CATIA V5/3DEXPERIENCE (V6)。开发涵盖三个层次：交互式（模板定制）、脚本（EKL/VB 低代码）、编程（C++ 纯代码，即 CAA 开发）。V5 与 V6 的根本差异在于底层架构——V6 基于 ENOVIA 协同平台，从本地文件管理转向 PLM 网络架构。

关键发现

  • CAA V5 开发环境：使用 RADE（Rapid Application Development Environment），在 Visual Studio + C++ 环境下与 CATIA 通信。核心 API 包括 CATBaseUnknown 体系、文档服务、零件/装配体操作（CATPart/CATProduct）。

  • V5 与 V6 核心差异：

  • V5：本地文件管理，独立 CAD 工作站模式
  • V6 (3DEXPERIENCE)：基于 ENOVIA 协同平台，PLM 2.0 架构，角色驱动的用户界面

  • 从 V6 R2014X 起正式更名为 3DEXPERIENCE，界面从底部罗盘移至左上角

  • V6 开发迁移路径：

  • 从 V5 RADE → 3DEXPERIENCE 新开发工具集
  • 从 CAA V5 百科全书 → 3DEXPERIENCE 开发者帮助门户
  • 从 V5 会话 → 3DEXPERIENCE PLM 连接
  • 从 CATPart/CATProduct → 3DPart/PLM 组件
  • 从 CATDocument Services → QEOpS

  • 从 CATDlgFile → PLM 选择器

  • 开发配置方案（V5 CAA 提供 5 种）：

  • ABC：多工作空间应用构建基础配置
  • CDC：C++ 扩展开发（CATIA + ENOVIA 全功能）
  • CDV：C++ 基础开发（中小市场，有限 CATIA V5/ENOVIA LCA）
  • JDV：Java 基础开发（ENOVIA LCA 客户端定制）

  • LDC：遗留数据集成开发（继承原有数据）

  • 达索官方培训：提供 CAA V5 入门、CAA 3DEXPERIENCE 入门、以及面向 V5 开发者的 V6 迁移专项课程。

对工作的价值

  1. CAA V5 是当前主流：国内大量存量项目仍在 V5 平台，掌握 RADE + C++ 开发能力直接对接客户需求
  2. V6/3DEXPERIENCE 是未来方向：达索战略重心已转向 3DEXPERIENCE，提前了解迁移路径可建立技术壁垒
  3. 三层开发能力匹配不同场景：交互式适合快速原型，脚本适合轻量自动化，CAA 编程适合深度定制和性能敏感场景

行动建议

  1. 搭建 CAA V5 本地开发环境（RADE + Visual Studio + CATIA V5-6R2025）
  2. 跑通官方 CAA Sample Use Case，理解 CATBaseUnknown → 具体接口的继承体系
  3. 对比阅读 V5 与 3DEXPERIENCE 的开发文档差异，建立迁移知识图谱
  4. 关注达索 3DSupport App 获取最新安装配置指南
