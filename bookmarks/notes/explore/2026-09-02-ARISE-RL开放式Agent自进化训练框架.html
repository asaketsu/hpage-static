一、内容整理

1.1 核心问题：开放式任务的两个根本瓶颈

论文指出，RL 在可验证领域（数学/代码，有精确自动反馈）已成功，但深研、旅行规划等开放式任务暴露两大瓶颈：

  • 数据-评估瓶颈：高质量开放式训练数据和专家 rubric（评分细则）昂贵且难以规模化。现有 benchmark（含开放式的 VitaBench、ResearchRubrics）大多是静态测试床，只能事后评估，无法为持续细粒度优化提供训练数据
  • 优化瓶颈（advantage collapse）：即使在模型能力边界附近放置查询，长程多轮工具交互的奖励信号脆弱不稳定，采样 rollout 只提供微弱或噪声对比，组内策略学习（group-based policy learning，如 GRPO 类方法）无法提取细粒度优化信号，优化被限制在模型现有能力区内做局部精修

一个自然解法是引入更强教师做蒸馏，但传统 off-policy 蒸馏在多轮 agentic 场景有致命伤：固定教师与进化中学生的分布差距随多步推理和工具使用逐步累积导致训练不稳；且开放式任务中教师指导并非总可靠，盲目模仿会把错误的工具选择、遗漏的约束、低质量推理模式传给学生。

1.2 方法总览：Generator-Solver 双角色共进化闭环

ARISE-RL 用闭环替代对外部静态数据的依赖——任务生成、任务求解、rubric 评估三者共进化：

┌─────────────────────────────────────────────┐
│            全局循环（粗粒度）                  │
│  Generator ──query+rubric──▶ Solver          │
│     ▲                          │            │
│     └── 难度信号(成功率) ◀── 轨迹+奖励        │
│  rubric = 任务构造与策略优化的耦合接口          │
├─────────────────────────────────────────────┤
│            局部优化（RG-SED）                 │
│  标准轨迹 y_s ~ π(·|p)                       │
│  记忆增强轨迹 y_m ~ π(·|p⊕m)  ← 同一参数！    │
│  仅当 Δr = R̄_m - R̄_s > τ 时蒸馏              │
│  （奖励门控，防噪声监督负迁移）                 │
└─────────────────────────────────────────────┘

Generator 奖励设计（三项相乘）：

  • R_G = R_tool(ξ) × R_fmt(q,ρ) × (1 + R_diff(q,ρ))
  • 工具接地门 R_tool（二元）：Generator 必须在写下依赖工具输出的 rubric 标准前，先真实调用该工具并观察输出（轨迹中至少含一次真实工具观察）。直接防幻觉——不允许编造工具环境不支持的评判标准
  • 格式门 R_fmt（二元）：查询非空且 rubric 为非空列表，保证下游 Solver 可解析执行
  • 难度塑形奖励 R_diff：对每个生成查询独立采样 Solver K=8 次，成功次数 c；R_diff = 2·max(0, 1-|c-K/2|/(K/2))。当约半数 rollout 成功时奖励最大，全成功或全失败归零——驱动 Generator 产出位于 Solver 当前能力边界的中等难度任务（该处组内奖励方差最大、优化信号最有信息量）

Solver 奖励设计（rubric 满足度）：

  • LLM judge 逐条判定轨迹是否满足 rubric 项 z_ij，满足率 s_i = (1/M)Σz_ij
  • r_S = α·s_i + (1-α)·𝕀[s_i=1]，α=0.8 权衡部分得分监督与全部完成奖励，细粒度中保留全对激励
  • 该奖励既用于 Solver 组内优化，又复用为 Generator 训练的经验难度信号

1.3 RG-SED：奖励门控自进化蒸馏（最关键创新）

两个角色都存在局部优化低效：Generator 反馈稀疏延迟；Solver 在能力边界任务上组内学习信号弱。RG-SED 对两个角色统一处理：

  • 同参数自蒸馏：当前部署策略先采样标准轨迹 y_s ~ π(·|p)；一个 coach 分析反馈产出角色专属记忆 m（Generator 版记忆总结任务构造反馈——查询太难/太易/欠规范/工具接地不足；Solver 版记忆总结查询专属学习信号——遗漏约束、工具提示、需显式回应的 rubric 项）；同一策略条件在 p⊕m 上采样出瞬时记忆增强教师 y_m ~ π(·|p⊕m)。师生同参数仅 prompt 条件不同，分布差距天然有界——避开 off-policy 蒸馏的失配累积，也不设外部教师静态天花板
  • 奖励门控：计算组级奖励差 Δr = R̄_m - R̄_s，仅当 Δr > τ（τ=0.05）时以系数 λ 激活 token 级 reverse KL 蒸馏；λ 含 warm-up 和 decay 调度
  • 门控必要性的实证：ECR-Travel 训练组中 8.3% 的组 coach 记忆反而降低奖励、19.6% 落在模糊区（|Δr|≤τ）、仅 72.1% 有可靠正差距——即近三分之一的组里无门控蒸馏会施加中性甚至有害监督。门控 𝕀[Δr>τ] 正是阻止这种负迁移

1.4 ECR-Bench：专家校准 rubric 基准套件

  • ECR-DeepResearch：单工具（web search）开放式研究，100 查询，rubric 评事实接地/证据覆盖/推理质量/完整性/报告结构，主指标 rubric 得分率
  • ECR-Travel：多工具旅行规划，5 类任务（Direction 路线/Compare 交通方式对比/Search 附近 POI/1-Day 单日/M-Day 多日）各 100 查询；工具集含 POI 搜索、导航、web 搜索、机票、火车票、天气 7 种；rubric 同时评行程质量与工具使用正确性，主指标任务通过率
  • 两阶段质控：专家人工审核全部测试查询与 rubric（不合格迭代修订或删除）+ 规则增强 LLM 质检器过滤格式错误/逻辑不一致轨迹

1.5 关键实验结果

主实验（Table 1）——Qwen3.5-9B + ARISE-RL 四基准平均 0.569：

  • 超过全部闭源模型：Gemini3-Pro 0.494、Claude-4.6-Sonnet 0.495、GPT-5.2 0.398、GPT-5 0.418、Claude-4.5-Sonnet 0.465
  • 超过开源大体量：Qwen3.5-397B（0.508）、Qwen3-235B（0.475）、Qwen3-32B（0.417）——9B 小模型经自进化反超 397B 原生
  • 同 backbone 对比自进化基线（Qwen3.5-9B）：ARISE-RL 0.569 > Dr. Zero 0.531 > Absolute Zero 0.508 > 裸模型 0.477；Qwen3-8B 上优势保持（0.358 vs 0.312/0.298/0.267）
  • 增益在交互式多工具基准上最显著：VitaBench-OTA 0.373 vs 裸模型 0.118（3.2 倍）、ECR-Travel M-Day 0.456 vs 0.321

消融（Table 2，Qwen3.5-9B）——四个设计互补非冗余：

  • 去 RG-SED 伤害最大：VitaBench 0.417→0.350，ECR-Travel 0.599→0.518
  • 去奖励门控（无条件蒸馏）0.371/0.523——无门控蒸馏放大而非抑制噪声监督，验证 1.3 节门控分析
  • 去工具接地 rubric 0.395/0.549；去难度塑形奖励 0.402/0.537

共进化循环（Table 3）：三轮循环单调提升（ECR-Travel 0.470→0.512→0.561→0.599）；用冻结裸模型测 Generator 各轮末新采样查询的单次通过率单调下降——直接证据表明 Generator 确实在产出越来越难的查询，形成匹配 Solver 成长的有效课程

蒸馏对比：RG-SED 在雷达图全部 11 个基准轴上全胜 OPCD 与 GKD 两种 on-policy 蒸馏代表方法

实现细节：32 张 H20 GPU；G=16 rollouts/查询，温度 0.8，最多 40 轮工具交互；交互式多轮 benchmark 的 UserSimulator 用 Qwen3.5-397B；全部 judge（rubric 评分/coach 总结/格式检查）统一用 GPT-5.2

二、查询拓展

2.1 Advantage Collapse（优势坍缩）

GRPO 类组内相对优化依赖同查询多 rollout 的奖励方差。当任务过难（全组失败）或过易（全组成功）时组内 advantage 全为零，梯度消失。这是 ARISE-RL 难度塑形奖励（瞄准 50% 成功率区间）的理论靶点，也是 LongStraw（2607.14952，时间换空间逐分支回放）从另一个角度解决的问题。

2.2 Self-Distillation 与分布差距

传统知识蒸馏（Hinton 2015）用固定强教师；off-policy 蒸馏在多轮场景的重要性采样修正逐轮复合导致不稳（OPCD 报告的失败模式）。ARISE-RL 的 RG-SED 让教师和学生共享参数、只差一段 prompt 记忆——把"教师"降维成"同一策略的更好上下文条件"，分布差距天然有界。这与「上下文工程」路线（Context-Engineering Quality 2607.14275：不换模型仅改上下文关键失败率降 68%）在哲学上同源：改进 prompt 条件而非权重。

2.3 奖励门控与噪声监督过滤

「先验证再吸收」的门控思想在自进化系统中普遍存在：EvoSOP（2607.07321）的工具生命周期 Evaluate 模块、SPyCE（2607.13854）的 merge-or-add 合并规则都要求经验证据支持后才固化。ARISE-RL 把它形式化为 Δr > τ 的组级阈值并给出分布统计（72.1% 正/19.6% 模糊/8.3% 负），是迄今为止最干净的门控实证。

2.4 绝对零数据训练（Absolute Zero 路线）

Absolute Zero（用零外部数据、模型自产任务自解任务）与 Dr. Zero 是本文直接对比基线。ARISE-RL 的差异点：面向开放式工具任务（前两者偏推理/数学闭式答案）、rubric 中介（前两者多为可验证奖励）、工具接地约束（Generator 必须真调工具防幻觉标准）。

三、归纳总结

3.1 核心框架：三层闭环自进化

层1 数据闭环：Generator ⇄ Solver（rubric 中介 + 难度课程）
层2 监督闭环：coach 记忆 → 门控验证 → 选择性自蒸馏（RG-SED）
层3 评估闭环：ECR-Bench 专家校准 rubric（训练评估同源标准）

3.2 四大设计原则提炼

  • 工具接地：评判标准必须来自真实工具观察，禁止凭空编造（防 rubric 幻觉）
  • 难度居中：50% 成功率区奖励最大，保证组内优化信号方差（对抗 advantage collapse）
  • 同源自蒸馏：教师=同一策略+记忆 prompt，分布差距有界，无静态天花板
  • 先验证再吸收：记忆带来的增益须经组级经验奖励验证（Δr>τ）才蒸馏，防噪声负迁移

3.3 结果要点速览

  • 9B+ARISE-RL（0.569）> Gemini3-Pro（0.494）> Claude-4.6（0.495）> Qwen3.5-397B 裸（0.508）
  • 消融伤害排序：RG-SED > 难度奖励 ≈ 工具接地 > 门控（门控在 RG-SED 内部）
  • 门控统计：72.1% 组有效 / 27.9% 组被正确拦下（8.3% 有害 + 19.6% 模糊）

四、趋势判断

趋势1：开放式 Agent 训练的"rubric 中介化"

可验证奖励（RLVR）范式覆盖不到的开放式任务，正在形成「LLM judge + 专家校准 rubric」的替代奖励标准带。依据：本文 ECR-Bench 与 ResearchRubrics/VitaBench 构成同源评估生态，训练与评估共用 rubric 体系将成为该方向标配。

趋势2：自蒸馏取代外部教师成为 agentic RL 的默认监督来源

固定教师蒸馏的分布失配问题在多轮场景被反复报告（OPCD），本文 RG-SED 与 GKD/OPCD 对比全胜 11 轴，加上「同参数+prompt 条件差」实现简单，预计"memory-augmented self-distillation"将快速成为标准组件。

趋势3：任务生成器的能力边界瞄准（capability frontier targeting）课程化

R_diff 奖励把"50% 成功率"这个最优学习区间形式化为可优化目标，类似 AutoCurricula/POET 思想在 LLM agent 的落地。Generator 与 Solver 共进化的单调证据（Table 3）预示自动课程将从"难度调度"升级为"双角色协同进化"。

趋势4：小模型自进化反超大模型原生能力成为常态

9B 反超 397B（0.569 vs 0.508）与 Gemini3-Pro，延续 Dr. Zero/Absolute Zero 已展示的方向。对边缘部署（Jetson 级）意义重大：与其堆参数，不如为小模型构建自进化训练闭环。

五、关联分析

5.1 与 CoEvoSkills 共进化（2026-08-29 笔记）的关联

CoEvoSkills 验证了技能库与 Agent 共进化发生相变；ARISE-RL 是同一共进化思想在训练层（Generator-Solver 双策略共优化）的实例，前者进化外部技能资产，后者进化模型权重本身。两者互补：权重层进化昂贵（32×H20），技能层进化廉价——组合潜力值得探索。

5.2 与 MemSkill 记忆技能自进化（2026-08-25 笔记）的关联

RG-SED 的 coach 记忆本质是「查询专属的瞬时学习信号摘要」，与 MemSkill 的可进化记忆技能库同属"记忆作为一等优化对象"路线。差异：RG-SED 记忆是训练期瞬态（蒸馏后即弃），MemSkill 是推理期持久资产。

5.3 与从RL到蒸馏 Why-RL-Matters（2026-08-16 笔记）的关联

该笔记梳理了 RL vs 蒸馏之争；ARISE-RL 给出第三答案——门控自蒸馏嵌入 RL 循环：RL 负责探索与奖励定义，门控蒸馏负责放大已验证的有效行为。0.8/0.2 的部分/完成奖励权重与 Δr>τ 阈值是两个可迁移的超参数锚点。

5.4 与 Context-Engineering Quality（2607.14275 精读）的关联

RG-SED 证明"同一模型 + 更好上下文条件（记忆）= 更好教师"，与 C-EQ 论文"不换模型仅改上下文关键失败率降 68%"互为印证：上下文改进的收益可以被量化、门控、并蒸馏进权重。

5.5 与 Hermes Agent 自身架构的关联

Hermes 的 skill 进化管线（evolver/experience-bank：错误→经验→skill patch）与 ARISE-RL 的 coach→记忆→门控→蒸馏同构度高；差异是 Hermes 在 prompt/skill 层固化（可逆、可审计），ARISE-RL 在权重层固化（不可逆、需重训）。slotguard 式风险约束可映射到「记忆投毒」防护（EVOMAL 2026-08-27 笔记展示的自进化自我投毒漏洞正是无门控吸收记忆的下场——ARISE-RL 的 Δr>τ 门控是针对性解法）。

六、金句摘录

「开放式任务的长程工具交互中，采样 rollout 只提供微弱或噪声对比，优化被限制在模型现有能力区内做局部精修，而非扩展能力前沿。」

「coach 记忆并非普遍有益：无门控的蒸馏目标会向近三分之一的组施加中性甚至有害监督。」

「教师和学生共享参数、仅 prompt 条件不同，分布差距天然有界。」

七、行动启示

  • 借鉴 Δr>τ 门控：Hermes 经验吸收管线（experience-bank）可增加「吸收前小样本 A/B 验证」步骤，仅当验证组表现提升才固化经验卡——直接移植，工作量约 1-2 天
  • 借鉴难度居中原则：skill-stress-test 压力测试生成任务时瞄准「Agent 50% 失败率」区间，最大化可学习信号——纯 prompt 层实现，成本低
  • 借鉴工具接地门：skill 编写规范可增加「引用真实工具输出示例」强制项，防 SKILL.md 中编造不存在的工具行为——校验脚本可机械化
  • ECR-Bench 的 rubric 双评（行程质量+工具正确性）模式可用于 Hermes 多工具任务的自动化回归评估

八、拓展应用推荐

  • 量化交易 Agent 训练：A股盯盘 Agent 的「铁律遵循 rubric」（30 备选池+14 铁律）本质就是 rubric 奖励，可按 r_S = 0.8·满足率 + 0.2·全对公式改造成组内训练信号，替代二值盈亏奖励（信号更密、advantage collapse 更少）
  • Jetson 边缘部署：9B 自进化反超 397B 的结论支持在 Jetson Orin Nano Super（67 TOPS）上部署经自进化训练的 8-9B agent 而非追求大模型量化版；Qwen3-8B backbone 数据点（0.358 vs 裸 0.267）直接可参考
  • 飞书 Bot 群聊 Agent：Generator-Solver 分离可映射为「提问猫-回答猫」双角色：提问猫生成边界难度任务（如复杂日程编排），回答猫求解，rubric 由 lark-task/calendar 的结构化约束自动校验
  • daily-paper-reading 自身：本文的难度塑形思想可用于 auto-learner 嗅探队列——兴趣任务的推送难度应维持「约半数能引发深读」的区间，过易（已熟知）或过难（无从下手）都降权

九、指南分析

本文方法论对「构建自进化系统」的通用指南价值：

  • 指南1：闭环优于静态——任务生成、求解、评估三者闭环共进化，优于任何单点静态优化（数据静态→评估静态→优化局部）
  • 指南2：接口显式化——rubric 作为 Generator 与 Solver 之间的显式耦合接口，让"任务质量"可度量、可奖励、可优化；映射到系统设计即「模块间契约必须是数据结构而非隐式行为」
  • 指南3：增益验证后吸收——任何自进化系统的"学习/吸收"动作都应附带经验验证门（Δr>τ 的工程等价物：A/B 测试、回归套件、影子流量），EVOMAL 自我投毒案例是反面前车之鉴
  • 指南4：同源改造优于外部引入——优先用「同一系统+更好条件」构造教师/参照系（自蒸馏、shadow 模式），而非引入外部权威（外部教师的分布失配与静态天花板问题在组织系统中同样存在）
  • 指南5：评估与训练同源——ECR-Bench 让训练 rubric 与评估 rubric 同一体系，避免 Goodhart 效应（优化指标与真实目标脱钩）；工程上即「CI 测试集与训练数据应共享 schema」
