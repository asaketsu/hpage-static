Agent监督与证据层：失准基率

生成日期 2026-09-24

摘要

Agent 监督系统（早停预测器、LLM-as-Judge、自动评估层）的置信度校准并非天然可迁移。2026-09 arXiv 两篇新论文给出证据：校准失准可以在"单一冻结基准内、特定目标 agent × 判头组合"上顽固存在（2609.25647），而自我进化 agent 的能力增益在分布偏移下会衰减、更新选择无法兑现候选 artifact 的潜力（2609.24663, EvoPathBench）。核心结论：监督信号必须当作概率预测器做基率校准审计，而非当作确定性的"证据层"。

关键发现

  1. 校准迁移失准是目标特异的（arXiv:2609.25647）：用 SWE-bench Verified 轨迹做 leave-one-agent-out 审计，45 对 agent 中多数组合校准差异中位数仅 0.018（SUCCESS 头），但 gpt-5-mini/SUCCESS 和 claude-opus-4.6/FAILURE 两个组合的修正后 gap 达 0.1377 / 0.1107 —— 失准集中在少数"预测器×目标"组合，且换基准（TerminalBench）不复现。含义：不能假设 A agent 上校准好的监督器直接用于 B agent。
  2. 早停/早判的经济性依赖校准：轨迹级早期结果预测只有"假设置信度校准正确"才省钱；失准时错误终止（假阴性砍掉本会成功的 run）的隐性成本被低估——即基率错配导致监督层系统性误杀。
  3. 自我进化 agent 需要 process-level 证据（arXiv:2609.24663, EvoPathBench）：只看端点性能会漏掉能力漂移。实验发现：相似未见任务上的增益在分布偏移下削弱；能力遗忘集中在少数进化路径；没有任何方法能可靠做到"根据新证据改规则"；agent 能生成有 held-out 增益的候选 artifact，但选择环节兑现不了该潜力。
  4. 证据层的正确姿势：冻结 checkpoints + held-out episodes 评估（EvoPathBench 方法论）+ 预注册的持久性判据 + oracle prior 修正（2609.25647 的控制实验设计可直接借用）。

对工作的价值

  • 对我们多 agent 体系（jbot 调度、content-judge 打分、watchdog 巡检）直接适用：任何 LLM 评分/预警阈值在换模型/换任务后必须重新校准，否则 base rate 错配 → 误报疲劳或漏报。
  • 2609.25647 的审计设计（leave-one-out、oracle prior 修正、jackknife、预注册判据）是一套可直接抄的监督层校准审计模板。
  • EvoPathBench 的"冻结 artifact + held-out 检查点"思路适用于评估 skill/记忆自进化是否真正有效（对应 evolver/skill-review 场景）。

行动建议

  1. P1：content-judge、stock-alert 等打分类 cron，换底层模型后重跑 50-100 条历史样本做校准对比（假阳性/假阴性率），不达标不直接上线。
  2. P2：为监督层预警引入基率显式化——记录告警命中率，告警基率 <10% 的规则降权或合并，防误报疲劳。
  3. P3：skill 自进化评估借鉴 EvoPathBench：skill 更新前后用固定的 held-out 任务集打分，防止"自进化"越进化越弱。
