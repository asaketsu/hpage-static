# 本地模型部署：消费级GPU推理（2026 速览）

## 摘要

2025-2026 年，量化技术的成熟让消费级 GPU（8-24GB VRAM）已能流畅运行过去需数据中心级硬件的大模型。核心变量是**量化格式选择**（GGUF/AWQ/GPTQ/EXL3）和**推理引擎匹配**（llama.cpp/Ollama/vLLM）。70B 模型经 Q4 量化后约 35-42GB，可通过 CPU 卸载在消费级双卡或单卡+大内存方案上运行。

## 关键发现

### 1. 量化格式对比（VRAM 缩减核心）

- **GGUF（llama.cpp/Ollama 标准）**
  - Q4_K_M：VRAM 缩减约 72%，质量损失仅 1-2%，是多数场景的最佳平衡点
  - Q5_K_M：多占约 15% VRAM，几乎补齐质量差距，适合编程/数学/法律场景
  - Q8_0：近乎无损，VRAM 减半
  - 独有优势：支持 GPU+CPU 分层卸载，模型可大于 VRAM 总量
- **AWQ / GPTQ**：GPU 原生格式，需 CUDA，配合 vLLM/TensorRT-LLM 性能最佳
- **EXL3（ExLlamaV3）**：专为消费级 GPU 设计，给定质量目标下体积最小，但生态较小众
- **NVFP4（Blackwell 原生）**：RTX 50 系原生支持，比 FP8 再省一半 VRAM，动态范围优于整数 Q4

### 2. 推理引擎选型矩阵

- **llama.cpp**：纯 C/C++ 零依赖，2025-2026 更新支持 NVFP4/FP8 量化、Vulkan（AMD/Intel GPU）、token 生成提速 35%。适合边缘设备、ARM 工控机。7B 模型仅需 4GB 内存
- **Ollama**：llama.cpp 的产品化封装，开箱即用，适合个人开发/快速原型/并发<20 的 RAG 场景。吞吐量瓶颈明显（8B 模型约 300 tokens/s）
- **vLLM**：高并发生产首选。PagedAttention 减少 70% 显存碎片，连续批处理 GPU 利用率达 90%+。同等硬件吞吐量是 Ollama 的 10 倍（3000+ vs 300 tokens/s）。一行命令启动 OpenAI 兼容 API
- **SGLang**：适合复杂推理流程（结构化输出、多轮对话、并行推理）
- **LMDeploy**：上海 AI 实验室出品，适合资源受限的边缘计算

### 3. 消费级硬件现实

- RTX 5090（32GB）是当前消费级旗舰，但量化一个 8B 模型到 NVFP4 竟会超出 32GB VRAM（量化过程本身需大内存），被迫依赖预量化权重或 CPU 卸载
- 双 RTX 3090（48GB）二手方案仍是性价比之王，可跑 Q4 的 70B 模型
- GGUF CPU 卸载是硬件受限场景的标准 fallback，速度受 PCIe 带宽限制
- Apple Silicon 统一内存是独特优势，MLX 框架支持本地量化但生态与 NVIDIA 有摩擦

### 4. 经验法则

- VRAM 估算：FP16 显存 ÷ 4 = Q4，÷ 2 = Q8，再加 10-20% KV cache 开销
- 先量化再选硬件，而非反过来
- "Ecosystem Friction"（生态摩擦）是比纯算力更常见的部署障碍——AMD GPU 在本地 LLM 推理上仍是痛点

## 对工作的价值

1. **直接可用**：Jetson Orin Nano（本项目运行环境）可用 llama.cpp + GGUF Q4 量化部署 7B-14B 模型，4GB 内存即可启动
2. **成本优化**：量化使推理成本可减半（70B Q4 单 A100 即可，省一张卡的钱）
3. **选型决策**：个人/开发用 Ollama，生产/高并发用 vLLM，边缘/资源受限用 llama.cpp，这条线已非常清晰
