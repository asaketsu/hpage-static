## 一、摘要

边缘 AI 航天三部曲补上最后一块拼图：10-10 讲了「为什么星上算」（下行带宽），10-11 讲了「跑什么模型」（Gemma3-4B@Jetson Orin），今天讲「**功率从哪来、怎么被花掉、谁卡脖子**」。核心证据是 arXiv 2608.21034 的 BUPT-1 卫星四个月在轨遥测：轨道计算节点的可用算力不是标称 TOPS，而是被「热天花板 + 能量预算」**双调节器**实时调制的物理量——光照期跟太阳能发电走，地影期跟电池放电深度（DoD）走。连续多日计算把日均 DoD 从 16% 推到 35%（超 30% 设计限）；DoD 均值每从 25% 提到 30%，烧掉约四分之一电池寿命。反直觉结论：在 490km/4 个月尺度上，**辐射不是操作性限制，热和能量才是**。

```
轨道能量预算：双子调节器（terminator 切换）
┌─────────── 光照期 ───────────┐   ┌─────────── 地影期 ──────────┐
│ 太阳能 = 易腐流量(perishable) │ → │ 电池 DoD = 累积+历史依赖     │
│ 算力从下方跟踪发电，超发耗电池 │   │ 每焦耳都来自电池余量         │
│ 不用满 = 浪费能量+徒增废热     │   │ 日均16% → 连算数日35%(超限)  │
└──────────────────────────────┘   └─────────────────────────────┘
实测浪费率 6%；DoD 25%→30% ≈ -¼ 电池寿命
```

## 二、关键发现

### 2.1 BUPT-1 实测：算力是「物理调制的时变资源」

- **平台**：12U 太阳同步轨道小卫星（~490km），2× Raspberry Pi 4B + 2× Atlas 200 DK 加速器，数秒级功耗/电池/结构温度遥测持续约 4 个月
- **判决**：可用容量被两个轨道约束调制——热天花板与能量预算，节点应建模为 *physically modulated resource* 而非固定服务器
- 热节流使部分模型推理延迟拉长约 **10%**（次要于平台级任务终止）
- 该高度+时长下 COTS 器件**辐射不是操作限制**——优先级：热 > 能量 > 辐射

### 2.2 电池 DoD：任务跑在轨道哪个位置 = 任务的真实成本

- 地影期每焦耳出自电池，预算 = 剩余 DoD 余量；同能量需求的不同放电曲线寿命不同（battery-aware scheduling）
- 运行时应执行 SoC 限值、温度降额、C-rate 限制、老化不确定性与安全模式储备——**在电池健康/母线电压恶化前缩放或拒绝 AI 工作**

### 2.3 峰值功率陷阱：平均能效 ≠ 瞬时良性

- 低单次推理能耗不保证瞬时功率温和：dense tensor 阶段、内存突发、唤醒、调整器暂态、与射频并发 → 峰值远超均值
- computational sprinting（短暂超可持续功率/热水平）在与载荷/执行机构/加热器共享受调节总线时**高风险**
- 资格认证应报告 peak power / ramp rate / rail demand / 限功率下的行为；系统软件用 DVFS + 射频 duty cycle + 载荷协同来削峰

### 2.4 轨道选择 = 能量供给设计（Satellite Inference 工程账本）

- **晨昏太阳同步轨道（dawn-dusk SSO）全年 96% 光照**，是常规 LEO（64-69%）的 1.4-1.5 倍；最长地影仅 ~20 分钟且全年仅约 90 天出现
- SI-P1 探路者：Jetson **Thor T5000** 参考 compute（Orin 兜底），载荷 4-6kg，**~200W 峰值功率配额**，目标 2028H1 飞行；Node-1 目标 10-20kW，集群节点设计 100kW
- 经济学三数字：发射 $/kg、航天器 **$/W（$200→$15）**、质量 kg/kW（41→17）
- 在轨 GPU-hour 成本轨迹（1.2kW/GPU、70% 利用率、15% 在轨备件）：今天 **$29.64 = 14.5×** 地面 → 2030 Starship 早期 **$7.46 = 3.7×** → 2035 $200/kg 情形 **$3.14 = 1.5×**

### 2.5 容量度量范式转变：从 TOPS 到能量可行单位

- 论文主张容量应以 **useful inferences per orbit / observations filtered per watt-hour / 指定功率储备下的延迟** 报告，而非实验室峰值 TOPS
- 五层 AI 基础设施架构中，**physical-state interface**（能量/热/辐射风险/DoD/姿态约束/载荷优先级/安全裕度）成为一等公民，向上暴露给调度器
- 调度器可查询的「时变功率包络」= 星历 + 姿态时间线 + 载荷计划 + 接触窗口的合成产物；BUPT-2 的 SateLight 在轨应用更新实测延迟 **-56.54%（最高 -91.18%）**、100% 正确率

## 三、对工作的价值

- **与 DUCK pi5 供电实践同源**：舵机电压门禁（0x3E 读数 min≥10.5V 才允许动作）本质就是「电池 SoC 余量先于任务」的 admission control；本文把该直觉上升为系统层设计原则（DoD 限值+安全模式储备+在恶化前拒绝负载）
- **value-per-joule 调度可跨域迁移**：Hermes 的 GPU daemon（LuxTTS 显存管理）与 sensor-grid 闭环可以引入「功率/热包络」作为调度信号——Jetson 8GB 平台上 inference-per-battery-hour 是比 tok/s 更诚实的容量指标
- **NAVI 三部曲闭环**：YAM-9 整星太阳能供电 150-500W 下的 26.6s/图 VLM 周期，正是「能量预算内设计工作负载」的飞行实例；今天补齐了功率侧的量化框架
- **指标设计范式**：'capacity in energy-feasible units' 直接可抄进 nexa-local-inference / edge 部署文档的容量表述

## 五、一页速查

> - BUPT-1（490km/4个月）：算力被热+能量双调节器调制；辐射不是该尺度的操作限制
> - 能量双子：光照期=太阳能易腐流量（实测 6% 浪费），地影期=电池 DoD 累积余量
> - DoD 经济学：日均 16% 常态 → 连算 35% 超限；25%→30% 均值 = ¼ 电池寿命
> - 峰值陷阱：能效高 ≠ 瞬时功率良性；共享总线上的 sprinting 高危；DVFS+射频 duty cycle 削峰
> - 轨道即能量设计：晨昏 SSO 96% 光照（1.4-1.5× 常规）；SI-P1 = Thor T5000 + 200W 配额（2028H1）
> - 成本轨迹：在轨 GPU-hour 14.5× 地面（今天）→ 3.7×（2030）→ 1.5×（2035）；$/W 从 200 降到 15 是第二杠杆
> - 度量范式：useful inferences per orbit、observations per Wh、指定功率储备下的延迟——替代峰值 TOPS
