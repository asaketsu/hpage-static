核心问题与研究动机

Harness 自进化（harness self-evolution）让 LLM Agent 在不更新模型参数的前提下，从执行轨迹中蒸馏可复用技能（skill）持续改进。但既有研究默认「写对了经验 = 所有模型都能受益」。本文戳破这个假设：

  • 技能收益不是 harness 的固有属性，而是 harness × 执行者能力的联合属性。同一份让 GPT-5.6-luna +31.1 分的技能，能让 Gemma-4-E4B 掉 8.8 分。
  • 在 103 个技能敏感任务对上，技能使前沿模型平均 +27pt，弱模型仅 +1pt——弱模型几乎白拿技能。
  • 最关键的诊断数字：86% 的弱模型失败运行中，被违反的要求早已明确写在注入的 SKILL.md 里。问题不是信息缺失，而是「指导的可执行性」——弱模型读不懂/跟不上为强模型书写的技能表述。

一句话动机：技能要「因材施教」——按执行者的能力档位重新表述，而不是把强模型的技能原样塞给弱模型。

方法论：内容整理

第一步：量化技能收益的能力分层差异（S2 Framework）

  • 任务池：三个独立构造的基准——SkillsBench（87 个 STEM/工程任务）、DocOps（186 个文档操作任务）、Tessl（334 个任务/184 种技能），共 607 个任务。
  • 7 个模型分三档：弱（Gemma-4-E4B / Qwen3.5-9B / Qwen3.6-flash）、中（GPT-5.4-mini / Claude-Sonnet-4.6）、强（GPT-5.6-luna / Claude-Opus-5）。
  • 定义技能增益 Δm(Ti) = 带技能得分 − 无技能得分；「技能敏感对」筛选规则：强档获益 ≥0.10 且高出弱档 ≥0.10，剔除弱档已 ≥0.80 的对。
  • 607 对里筛出 103 个技能敏感对（SkillsBench 32 / DocOps 32 / Tessl 39）。全部 607 对平均看技能人人小赚、无层间规律；只在 103 个敏感对上，层间鸿沟才显形。

第二步：失败模式诊断（S3.1）

人工阅读三个弱模型在 103 对上的失败轨迹，按「最先可观察失败」打标签，共 131 个标签：

  • EXE 工具执行（最常见，n=51）：一两次工具调用后就停；把文件格式名（xlsx/pdf）当可调用工具；遇错不恢复。
  • CTX 上下文管理（n=28）：把技能自带的示例文件当成当前任务去做；产物存错路径。
  • IF 指令遵循（n=35）：工具调用不少、产物也交了，但多部件要求只做了一部分——要求明明写在技能里。
  • REF 验证缺失（最少，n=17）：部件齐全，但数值/矩阵与 verifier 重算结果不符——它报了一个从未检查过的值。

第三步：Meta-skill——把诊断蒸馏成固定重写协议（S3.2 + App C）

一份任务无关的固定文档放进重写者 system prompt，四类失败各配「处方」：

  • EXE 处方：技能开头明确「哪些名字是可调用工具、哪些是文档」；加环境预检；给第一个可能失败的 fallback；给出可逐字执行的命令。
  • CTX 处方：开头即声明用户任务、允许修改范围、交付路径；一句话说明「本文其余部分是参考资料不是新请求」；步骤需要的辅助文件内容直接内联。
  • IF 处方：每个相关要求改写成一行「动作—目标—完成条件」，含负分支（"若 X 已存在，停止且不改动"）。写更多没有用——文字本来就在。
  • REF 处方：结尾加独立验证步——从磁盘重读产物、用第二条路径重算、与显式阈值比较、不通过就循环。「我写了文件」和「运行没报错」不算证据。
  • 五条铁律：只改证据牵涉的段落；保留任务可能需要的能力描述、只删 Agent 无法执行的内容；只提及任务/轨迹/接口里真实存在的函数、flag、路径，禁止编造名字；禁止粘贴期望输出或答案（靠含答案才工作的技能会被拒）；证据不支持就返回 NO_CHANGE。

第四步：两种使用形态（S4）

  • 形态一（Skill Adaptation）：强模型重写者不看执行证据，一次性把技能改写成弱模型友好的版本。
  • 形态二（Self-evolution 循环）：弱模型自己当重写者，第 t 轮拿到第 t−1 轮的技能、轨迹、verifier 输出，改写后自己再执行，循环 5 轮。

关键实验结果与数据

Table 1：一次性技能适配（103 对均值，重写者 × 弱执行者）

  • 原始技能：Qwen3.6-flash 0.529 / Gemma-4-E4B 0.029 / Qwen3.5-9B 0.323，均值 0.294
  • 弱模型自改（Weak self）：均值 0.271——弱模型无证据自己改技能反而更差
  • GPT-5.6-sol 改：0.335；GPT-5.6-luna 改：0.343
  • GLM-5.3 改：0.379；Kimi-K3 改：0.387（最佳）——Gemma-4-E4B 从 0.029 被拉到 0.170（+486% 相对提升）
  • 消融：把 meta-skill 换成一句"请改写成对所有模型都有效"，Kimi-K3 也能帮忙但不稳（Qwen3.5-9B 反而低于原始）——meta-skill 的诊断指引本身贡献了稳定增量

五轮自进化循环（7 个执行者）

  • 带 meta-skill 的自进化：7 个执行者全部在第 5 轮高于不带 meta-skill 的对照臂（差值 +0.020 ~ +0.046，跨 Qwen3.5-27B / Gemma-4-26B / Qwen3.5-plus / Kimi-K2.5 等）
  • 不带 meta-skill 的自进化：不稳定——Qwen3.5-9B 第 3 轮见顶后回落到接近基线；Gemma-4-E4B 全程低于基线
  • 反直觉对照：一次性改写中弱模型用 meta-skill 自己改会更差，但给了失败证据后同一批弱模型就能用好 meta-skill——证据 + 诊断指引缺一不可

Table 2：失败模式 × meta-skill 增益的分解

  • EXE（n=51）：适配 +0.056 / 自进化 +0.065
  • IF（n=35）：+0.055 / +0.046
  • CTX（n=28）：+0.103 / +0.007
  • REF（n=17）：+0.003 / +0.104
  • 结构洞见：一次性适配修「文本可见」的问题（CTX 类 +0.103），自进化修「执行才暴露」的问题（REF 类增益比适配高 0.101）——验证类失败只能靠轨迹证据修，因为技能文本可以规定检查步骤，但只有轨迹能揭示执行者是否真的做了检查
  • 边界：「meta-skill 修不了执行者本身」——Table 2 的负格子里，技能已写对程序而执行者做不到

创新点分析

  • 首个量化"固定技能收益 × 模型能力档"交互效应的工作：Related Work 明确指出此前 skill 生态（上万个公开注册技能）默认「一次写成、原样分发」，早期证据显示这很脆弱但无人系统量化。本文用 103 个敏感对 + 三档分层给出可复现测量协议。
  • 诊断驱动而非数据驱动：不走"更多轨迹蒸馏更多经验"路线，而是把失败归因到四类书写方式问题，再把诊断蒸馏成 560 词的固定 meta-skill——可迁移、零训练、即插即用。
  • "证据 + 指引"互补性的干净实验：同一批弱模型，无证据用 meta-skill 改写（更差）vs 有证据用 meta-skill 自进化（7/7 一致变好），分离了两个因素的贡献。
  • 诚实的因果态度：每轮只跑一次，作者明说不解读 0.02-0.05 差值的具体大小，只依赖"符号在 7 个执行者上一致"这一事实。

局限性与未来方向

  • 只评估「技能已注入上下文」的场景，技能检索（retrieval）与渐进式披露（progressive disclosure）不在范围内——真实 Agent 系统里这两环可能是新瓶颈。
  • 多技能捆绑评估，无法估计单个技能的贡献（受基准设计所限）。
  • 自进化固定 5 轮预算，未探索更长程的收敛/震荡行为；模型参数冻结。
  • 未来方向：追踪每次修订是否真正修复了触发它的失败（revision-to-failure 归因）；同样的诊断指引扩展到工具接口与工作流层。
  • 本文语境的"技能适配"是任务级 SKILL.md 重写，不涉及技能库级治理（合并/剪枝/索引），与 EvoSOP/SPyCE 的生命周期管理是互补关系。

借鉴点：关联 Hermes Agent / Jetson Orin / 量化交易

对 Hermes 的直接映射（本文语境几乎就是 Hermes 的场景）：

  • P0——多模型档位的技能表述适配：Hermes 实际运行 glm-5.3（本文实测改写效果第二强的模型，0.379）/ GPT-6.1 / 弱 fallback 模型混合队列，同一份 SKILL.md 服务所有模型。本文证明强模型友好的技能对弱模型可能为负收益。可落地动作：在 skill-review / skill-health-tier 里增加「执行者档位」维度；对主要由弱模型执行的 cron 类任务，用强模型按 meta-skill 四处方重写其 SKILL.md。
  • P0——meta-skill 处方可直接移植进错误修订流程：EXE/CTX/IF/REF 四处方与 Hermes 的 skill-ab-testing、error-case-library 完全同构。把四类标签加入 error-case-library 的分类法，每次技能修订按「最早失败」定位再改，比现在凭感觉重写更纪律化。
  • P1——"86% 已写在技能里"对 Skill 审计的校准意义：Hermes skill 出问题时第一反应常是"补充更多说明"，本文数据说明弱执行者的失败多数是「已有要求未被遵循」——修订策略应是改写表述（动作—目标—完成条件三段式）而非加内容。
  • P1——NO_CHANGE 契约：meta-skill 的输出契约（无证据支持的改进返回 NO_CHANGE、禁止编造名字、禁止把答案写进技能）可直接写进 Hermes 的 skill 生成/修订 prompt，抑制技能通胀和答案泄漏。
  • P2——Jetson Orin：无直接关联；间接价值是 Nexa 本地小模型（弱执行者）跑自动化任务时，其专用技能应按 EXE 处方书写（逐字命令 + 环境预检 + fallback），可降低本地模型的工具误用率。
  • P2——量化交易：盯盘/选股类 skill 目前服务强模型；若未来下放给轻量模型值班，需先按本文协议做档位适配评估，避免"技能负增益"静默劣化信号质量。

归纳总结

  • 核心结论：技能收益 = f(技能内容 × 执行者能力)，固定技能对弱模型可为负增益；86% 的失败源于「已写明但未遵循」，是表述可执行性问题而非信息缺失问题。
  • 方法本质：失败诊断（四类）→ 固定处方（meta-skill）→ 两种应用（强模型无证据改写 / 弱模型带证据自进化）。
  • 最硬数字：Kimi-K3 适配把 Gemma-4-E4B 从 0.029 拉到 0.170；自进化 7/7 执行者一致受益（+0.020~+0.046）；REF 类失败只有带证据的自进化能修（+0.104 vs 一次性 +0.003）。
  • 对自进化系统的普适教训：评估 harness 收益必须按能力档位分层，不能用单一代表模型；进化循环需要诊断指引，只有证据时弱重写者会漂移。

趋势判断

  • Agent 研究的重心正从「模型参数改进」进一步滑向「harness 层工程化」：2026 下半年 harness self-evolution / skill evolution 已成独立论文赛道（本文 + DREvo + 2610.27435 + Meta-Harness / Self-Harness 一族），与年中 SPyCE/EvoSOP 一脉相承且测量更严谨。
  • 「能力感知」（capability-aware）将成为 harness 组件的标配属性：技能、工具接口、工作流都会被要求声明/适配目标执行者档位，正如软件包要声明目标架构。
  • 预判：下一步热点是本文自陈的两个空白——技能检索与渐进式披露场景下的档位适配，以及 revision-to-failure 归因（追踪每次修订是否真修复了触发它的失败）。后者与 Hermes 的 error-case-library + skill-ab-testing 组合天然同构，是可抢先落地的方向。
  • 产业侧信号：Anthropic Agent Skills 注册表规模化后，"同一技能跨模型分发"的负增益问题会被放大，技能市场可能出现「按模型档位分发的适配版本」这种形态。

拓展应用推荐

  • 立即可做（Hermes）：把 IF 处方（动作—目标—完成条件三段式 + 负分支）用于改写高频 cron 任务的 SKILL.md 关键指令段；把 EXE 处方（逐字命令 + 环境预检 + fallback）用于弱模型值班的运维类 skill。
  • 短期可做：给 skill-review 巡检加「四类失败标签」统计——从 error-case-library 反查每类失败占比，优先修占比最高的那类表述。
  • 中期可做：建立「技能 × 模型档位」增益快评：用 3-5 个代表性任务在 glm-5.3 与弱模型上各跑一次带/不带技能对照，廉价复现本文的 Δm 测量，作为技能入库门禁的一部分。
  • 谨慎评估：全量技能库按档位重写成本高且本文效应主要在弱执行者上——主力模型（glm-5.3 已是论文实测的强重写者档位）无需大动，只对弱模型执行路径做适配。

指南分析

如果只从本文带走一份操作指南，就是 meta-skill 的四处方（可直接作为技能修订 checklist）：

  • 写技能时自检 EXE：读者能否分清哪些是可调用工具、哪些只是文档？第一条命令能否逐字复制执行？失败第一步是否有 fallback？
  • 自检 CTX：前三行是否说清了用户任务、允许改动范围、交付路径？示例/参考资料是否明确标记为"非新请求"？
  • 自检 IF：每个要求是否为「动作—目标—完成条件」单行结构？负分支（已存在则不动）是否写了？
  • 自检 REF：结尾是否有独立验证步（重读产物 + 第二路径重算 + 显式阈值 + 循环）？"没报错"是否被明确认定为不算证据？
  • 修订纪律：按最早失败定位、只改牵涉段落、不编造名字、不写答案、无据可改返回 NO_CHANGE——这五条对任何自进化系统都成立，与模型档位无关。
