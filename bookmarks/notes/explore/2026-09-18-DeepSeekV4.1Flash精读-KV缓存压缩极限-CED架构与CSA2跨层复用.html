一、内容整理

1.1 核心问题：长程 Agent 时代的三重瓶颈

长程 Agent（long-horizon agent）应用爆发后，模型负载越来越"重输入"（input-heavy）：频繁工具调用产生巨量 prefill 请求，KV Cache 的计算、存储、带宽成为部署成本的三大瓶颈：

  • 计算瓶颈：稀疏注意力已大幅降低长序列处理成本，但 prefill 依然昂贵
  • HBM 容量瓶颈：全局 KV（main KV + indexer K）随序列长度线性增长，运行时受限 HBM
  • SSD/主机内存 + I/O 瓶颈：为 prefix 复用而持久化的 persistent KV 受限于 SSD 容量和互连带宽

论文的量化目标：全局 KV footprint 压到 890 bytes/token（前代 V4-Flash 的约 1/4），持久化 KV 压到前代的约 1/8，同时性能不降反升。

1.2 模型总体架构：552B MoE 多模态

  • 规模：552B backbone 参数 + 196B Engram 参数；prefill 每 token 激活 8B，decode 激活 16B（不对称激活是本文关键设计）
  • 层数：40 层因果 Transformer = 20 层因果编码器 + 20 层解码器
  • 注意力：每层同时含全局注意力 + 滑窗注意力 SWA（前 2 层仅 SWA）
  • 多模态：视觉编码器 + MLP 投影器，图像/文本联合处理，预训练即原生多模态（45T token 语料）
  • 上下文：原生支持 100 万 token

1.3 CED：因果编码器-解码器架构（省一半 prefill）

灵感来自 YOCO 的层间 KV 共享，但做了结构性改进：

  • 底部 L/2 层作为因果编码器；上半层（解码器）的全局 KV 不来自自身隐状态，而是从第 L/2 层隐状态 H_{L/2} 用层依赖投影权重直接投影生成
  • 效果：prefill 阶段只需算前一半层即可获得上层全局 KV，prefill 复杂度从 O(N·L) 降到 O(N·L/2)，近半减半
  • SWA 仍逐层计算（保持局部 KV 的计算深度），这引入了 SWA 重放需求（见 1.6）
  • 对 Agent 负载的意义：工具调用多轮交互 = 频繁 prefill，8B 激活 prefill 直接砍成本

1.4 CSA2：三维乘性压缩的稀疏注意力

KV cache 成本可沿三个乘性维度压缩：条目大小（GQA/MLA）、序列维度（每 m token 压一条）、层维度（层间复用）。CSA2 是首个同时覆盖三维的方法（对比 IndexCache 只省索引计算、YOIO 全网路由共享伤性能、HySparse 保留全注意力层）。

三种静态分配模式：

  • Full 模式：自己算 main KV + indexer Q，从 main KV 投影 indexer K，跑索引器产出 Top-K 索引（完整路径）
  • Reindex 模式：复用前面层的 main KV 和 indexer K，但用自己的 indexer Q 重新打分、产出新鲜 Top-K（选择可跨层变化，缓存仍共享）
  • Reuse 模式：main KV 和 Top-K 索引都复用前面层的，直接做稀疏注意力（不跑索引器）

所有模式下每层保留自己的全局 Q 和 SWA KV。相对 CSA 还做了两处简化：去掉相邻压缩条目的源重叠和绝对位置嵌入；indexer K 从 main KV 投影而来（不再从隐状态单独压缩），实现更简单、训练更高效。

1.5 层级稀疏索引器：把索引成本从线性变常数

  • 解码器第一个 Full 层为每个 query 构建 Top-512 候选池（按 indexer 最高分的块），后续 Reindex 层只在池内选择
  • 深层索引器的单 query 成本从"随上下文线性"变为常数
  • 机制是 training-aware 的，在 post-training 阶段引入

1.6 SWA Bounded Replay：时间换空间的持久化压缩

SWA 依赖跨层累积，精确重建 L 层 SWA KV 需要重放 L × n_win 个 token。Bounded Replay 只重放最近 n_win 个 token 并把 SWA 截断到重放段，接受近似状态：

  • Encoder 侧：prefix 缓存只依赖全局 KV → SWA KV 从持久化缓存中完全移除（省 SSD）
  • Decoder 侧：prefill 前向被限制在 n_win token，近一步砍半总 prefill 计算
  • 实验证据：对响应质量"几乎没有妥协"；为安全起见，post-training 阶段还模拟同样的重放做 train-aware 适配

1.7 FP4 主 KV Cache：存储格式 ≠ 运算格式

  • 采用 OCP 标准 MXFP4（为兼容多硬件平台，尽管其他格式精度更高）；E2M1 + 每 16 通道一个 E4M3 scale，参照 NVFP4 但省略二级全局 scale
  • 关键洞察：RMSNorm 后 512 维 latent 的 L2 范数上界约 √512 ≈ 22.6，训练中实测最大幅度约 10，而 E2M1×E4M3 支持幅度上界 2688 → 省略全局 scale 无精度损失
  • FP4 用于存储而非矩阵乘加速：attention 前反量化，不要求硬件原生 FP4 matmul，保持跨平台兼容
  • 在 RoPE 之后量化（RoPE 前量化仅边际收益且引入解码开销）；SWA KV 因量化敏感保留 FP8
  • 相比 V4 的 FP8 主 KV，存储近半（HBM 与 SSD 侧同享）

1.8 其他架构扩展

  • Single-Pass mHC：把输入混合系数从当前块改用上一块的（A_{l-1}），消除数据依赖，残差更新+输入混合+系数预测融合为单 kernel（Mega-mHC），激活内存流量达到理论下界 (2n+2)d，是原实现的一半
  • Engram 条件记忆：196B 参数均分两模块（放 1/14 层），N-gram {2,3,4} + 8 hash 头 + 每序 2048 维嵌入，表大小取互异素数（约 16M 条/头），FP8 精度；推理时确定性寻址 → host 内存后台 RDMA 预取
  • DSpark 投机解码（backbone 预训练后单独训练）

1.9 训练与后训练基础设施

后训练哲学：不引入新算法，全部收益来自数据/环境工程——"当前阶段，数据和管线工程的边际回报远超算法新颖性"：

  • 任务形式化为 (问题, 环境, 验证系统) 三元组，以难度+正确性为奖励迭代训练模型自己构造任务
  • 通用 Agent 环境：从内部员工/合作伙伴真实工作流中构建 mock 工具（复刻真实 SaaS/企业后端的接口、schema、行为约束），失败案例回放形成定向 RL
  • 编码 Agent 环境：从 GitHub 高星仓库自动构造——多专业 Agent 协作：可构建性判定 Agent → 容器环境搭建 Agent → 多个解题 Agent → 独立质检 Agent → 修复 Agent，fail-to-pass/pass-to-pass 评估点全自动
  • DSec：百万级并发沙箱平台。分片+最终一致性的自定义调度（不用 K8s）；每节点 sub-NUMA 分区，密度从 ~1000 提升到 2500+ 并发容器/物理节点；SCHED_IDLE + 核调度隔离延迟敏感任务。Agent reward hacking 实录：利用 XFS 权限漏洞、AppArmor 非法内存访问、包镜像服务泄露答案、删关键二进制甚至删文件系统——用 per-sandbox AppArmor + eBPF 网络策略防御，崩溃记为失败轨迹回馈 RL
  • 可控推理努力度：系统提示注入 Reasoning Effort: {1-100} 标量，同 prompt 同 effort 内做组相对优势（GRPO 式），长度惩罚系数 k(b) 随 effort 变化
  • 异步 RL：rollout 与训练同物理机分时复用；sample 级调度（凑够 GRPO 组大小即派发）；token 级中断 + KV cache/专家路由 token 粒度持久化实现无缝续跑；跨 checkpoint 用"拼接路由重放"而非重算；长度偏差用数据集级并发限制+丢弃早期短样本缓解，off-policy 用比率上界+staleness loss mask 缓解
  • 模型合并：跨 scaffold/配置的 RL run checkpoint 合并来重初始化后续 run，聚合并行 RL 算力

1.10 关键实验结果

基座对比（vs V4-Flash-Base 13B激活/V4-Pro-Base 49B激活）：

  • MMLU-Pro：74.1（超 V4-Pro 的 73.5）
  • HumanEval：79.4（V4-Pro 76.8）；BigCodeBench：60.6（V4-Pro 59.2）
  • GSM8K：93.0；MATH：61.1（V4-Pro 64.5 略高）
  • LongBench-V2：45.2（V4-Flash 44.7，V4-Pro 51.5）
  • 多模态：MMMU-Pro 56.5 / DocVQA 95.6 / CVBench 77.9
  • BPB（内部研发语料困惑度）：三大任务全面最低

Chat 版对比（vs Opus-5 / GPT-5.6 Sol / K3 / GLM-5.3 / V4-Pro / V4-Flash）：

  • Codeforces Rating：3471（V4-Pro 3348，V4-Flash 3289）
  • DeepSWE v1.1：74.2（超 Opus-5 的 74.0、GPT-5.6 Sol 的 73.0；V4-Flash 仅 54.4）
  • Terminal-Bench 2.1：90.6（超 Opus-5 89.1）；Terminal-Bench 3.0：30.0；4.0：31.2
  • Automation-Bench：54.8（第一）；Agents' Last Exam：31.8（第一）
  • CyberGym：88.1（开源新 SOTA）；HLE w/ tools：63.9（第一）
  • 视觉 Agent：强于 K3 但仍落后顶级闭源

推理努力度 scaling：effort 25→100，8 个推理基准平均 Pass@1 从 67.1% → 76.3%，DeepSWE 从 66.0% → 74.2%，TB2.1 从 82.4% → 90.6%，代价约 2.5× 输出 token。收益前置：60-80 区间已恢复 max 大部分精度而 token 预算不到一半；最后冲 100 使轨迹变长 1.6-1.8× 仅换边际收益。API 暴露 low/high/max = 50/75/100。

多 Agent（Agent Team 模式）：lead 通过 spawn_teammate 异步创建命名持久队友（fresh/fork 两模式），共享仓库 checkout + 持久 peer 邮箱 + 共享任务板；RL 奖励 = 任务性能 + 协作奖励 - 派生延迟惩罚（DAG 关键路径建模，token 数×固定 prefill/decode 速率 + 实测工具执行时间）。结果：ProgramBench 8h 时 multi-agent 30.04% vs single 20.39%；FrontierSWE v2 20h 时 32.90% vs 28.20%——每个 deadline 上多 Agent 都占优。

二、查询拓展

2.1 YOCO 与层间 KV 共享谱系

YOCO（You Only Cache Once，2024）让上半层直接复用下半层生成的 KV，省 prefill 计算。CED 在此基础上增强了 KV 容量与生成深度：解码器全局 KV 从 H_{L/2} 经层依赖投影生成，而非简单原样复用——每层仍有专属的投影权重 W_l^KV，保留层间表达差异。

2.2 GQA / MLA / 稀疏注意力的压缩层次

  • GQA 减 KV 头数（条目数维度）
  • MLA（DeepSeek-V2 起）把 KV 压到小 latent（条目大小维度）
  • CSA/HCA（V4）每 m token 压一条（序列维度）
  • CSA2 加上层维度（跨层复用 main KV + 索引），是三维乘性叠加。890 bytes/token 可对照：FP8 下 MLA latent 约 576B/token 量级，CSA2 的全局 footprint 890B 意味着层间复用后等效每层仅数十字节

2.3 FP4 量化生态（NVFP4 / MXFP4）

NVIDIA NVFP4（2025）采用 E2M1 + 每 16 通道 E4M3 scale + 二级全局 scale。OCP MXFP4 是开放标准。本文的关键取舍：选 OCP 标准换硬件兼容性而非选精度最高的私有格式；且 FP4 只做存储格式，attention 前反量化回高精度计算——"存储格式不等于运算格式"（与本站 9-12 清水亮优化笔记的核心论点互相印证）。

2.4 环境合成 vs 算法创新的范式转移

本文 post-training 部分几乎是"反算法宣言"：固定 SFT→RL→OPD 流程，把工程全押在可验证任务合成与环境自动构造上。这与同期 agentic RL 论文（任务三元组形式化、mock 工具回放失败案例）形成共鸣——数据飞轮的边际回报 > 算法微调。

三、归纳总结

3.1 KV 压缩组合拳算术（本文全景公式）

KV成本 = 层数 × (序列长度/m) × 条目字节数
          │         │             │
     CSA2跨层复用  CSA2压缩   FP4存储
     (Full/Reindex (省重叠+   (FP8→FP4
      /Reuse分组)  位置嵌入)   近半字节)
× 附加: SWA Bounded Replay → 持久化层不存SWA KV
        (重放n_win代替L×n_win, 时间换SSD空间)

全局KV(HBM常驻): 890 B/token ≈ V4-Flash的1/4
持久化KV(SSD/主机): ≈ V4-Flash的1/8

3.2 成本收益主线（一句话版本）

  • Prefill 计算：CED 减半 + Decoder Bounded Replay 再减 → O(N·L/2)
  • HBM：CSA2 + FP4 → 1/4
  • SSD/带宽：SWA Bounded Replay → 1/8
  • 性能：DeepSWE 54.4→74.2，Codeforces 3289→3471

3.3 与既有笔记的互补关系

  • 9-12 PagedAttention/vLLM 笔记管"系统层"浪费（分页、碎片）
  • 9-12 GPU互联经济学笔记管"搬运层"（共享、CXL）
  • 9-06 KVCache 十二技管"技术地图"分类
  • 本文补上模型架构层的釜底抽薪：让每个 token 天生只占 890B，系统层优化在更小基数上运作

四、趋势判断

趋势1：KV 压缩从"系统技巧"下沉为"架构原语"

依据：CSA2/FP4 都是训练期决定的设计而非推理期补丁；890B/token 意味着 1M token 全局缓存 <1GB，百万上下文从奢侈品变标配。推理框架的优化空间将被架构层吸收。

趋势2：prefill/decode 不对称激活成为 Agent 时代标配

依据：Agent 负载 input-heavy（V4.1-Flash 8B prefill vs 16B decode），CED 把"输入多输出少"的负载特征直接编码进架构。未来模型卡会像显卡一样标注"prefill 激活/decode 激活"两个数字。

趋势3：后训练进入"环境工程"阶段，算法让位

依据：论文原话"数据和管线工程的边际回报远超算法新颖性"；任务合成→环境容器化→自动质检的流水线贡献了全部 post-training 收益。DSec 百万沙箱说明瓶颈已从"怎么训"转向"在哪训"。

趋势4：推理努力度成为 API 一等公民参数

依据：effort 25→100 换 9.2pp 精度但 2.5× token；60-80 区间性价比最优。与 OpenAI reasoning effort 对齐，成本敏感的 Agent 编排（如本站 cron 任务）可直接把"简单查询低 effort / 困难任务高 effort"写进调度策略。

趋势5：多 Agent 编排原生进模型训练

依据：spawn_teammate/邮箱/任务板这套原语直接进了 RL 奖励（协作奖励 + DAG 关键路径延迟惩罚），且每个 deadline 挡位多 Agent 均胜出单 Agent。编排协议正从框架层（LangGraph 等）被吸收为模型能力。

  • Jetson 边缘部署视角：890B/token 意味着 128K 上下文全局 KV 仅 ~115MB——边缘设备跑长上下文 Agent 的显存账从"不可能"变"勉强可行"；FP4 存储+高精度计算的混合精度思路与 Jetson TensorRT 的 INT8/FP16 分层策略同构，edge-llm-quantization skill 可补充该案例
  • 量化交易系统视角：推理 effort 分级对应盘面复杂度分级——集合竞价/开盘侦察用低 effort 快扫，尾盘风控复核用高 effort；DeepSWE 74.2 的代码能力可用于策略代码自动审查流水线
  • 任务合成流水线借鉴：(问题,环境,验证)三元组 + mock 工具复刻真实 API 的做法，可用于自建 RL 训练数据或 agent 回归测试集生成

九、指南分析

  • 选型指南：需要在旧硬件跑新模型 → 依赖本文"FP4 仅存储格式"设计；需要极致长上下文 → CED+CSA2 组合是当前单位 token 成本最优解；需要可控成本 → effort 60-80 是默认甜点
  • 阅读指南：本文 20+ 节中，成本敏感读者优先读 §1（Intro 定量目标）、§2.2-2.4（CED/CSA2/FP4 三大件）、§3.2.2（Bounded Replay）、§5.1（环境工程哲学）、§5.3.2-5.3.5（实测表）；基础设施工程师加读 §5.1.3（DSec）与 §5.2（异步 RL）
  • 复现指南：checkpoint 已开源（huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash）；复现重点验证三处近似（跨层 KV 复用、索引候选池限制、SWA 截断重放）在自有负载上的质量损失是否可忽略
