一、摘要

飞书消息卡片（interactive 类型）有三种发送方式：卡片实体 ID、模板 ID、原始 JSON。JSON 2.0 schema 采用 header + body 双区结构，body 内通过 elements 数组组织 markdown/button/chart 等组件。富文本消息（post 类型）新增 md 标签，原生支持 CommonMark 0.31 + GFM 语法，包括表格、任务列表、删除线。卡片模板支持变量注入实现多场景复用。

二、关键发现

2.1 卡片三种发送方式对比

  • 方式一：卡片实体 ID（card_id）—— 先调 CardKit API 创建实体，再通过 content: {"type":"card","data":{"card_id":"xxx"}} 发送。适用于流式更新和局部更新场景
  • 方式二：模板 ID（template_id）—— 在搭建工具中创建模板，通过 content: {"type":"template","data":{"template_id":"xxx","template_variable":{...}}} 发送。支持变量注入，可复用
  • 方式三：原始 JSON —— 直接在 content 中传入完整卡片 JSON 2.0 结构。最灵活但不可用变量，适合一次性卡片

2.2 卡片 JSON 2.0 核心结构

{
  "schema": "2.0",
  "config": {
    "update_multi": true,           // 是否允许多次更新
    "style": {
      "text_size": {
        "normal_v2": {"default":"normal","pc":"normal","mobile":"heading"}  // 响应式字号
      }
    }
  },
  "header": {
    "title": {"tag":"plain_text","content":"标题"},
    "subtitle": {"tag":"plain_text","content":"副标题"},
    "template": "blue",             // 头部颜色：blue/green/orange/red/purple/indigo...
    "padding": "12px 12px 12px 12px"
  },
  "body": {
    "direction": "vertical",        // vertical / horizontal
    "padding": "12px 12px 12px 12px",
    "elements": [
      {"tag":"markdown","content":"正文内容","text_align":"left","text_size":"normal_v2"},
      {"tag":"button","text":{"tag":"plain_text","content":"按钮"},"type":"default","behaviors":[{"type":"open_url","default_url":"https://..."}]}
    ]
  }
}

2.3 关键字段说明

  • schema: "2.0" —— Card 2.0 版本标识，必须写
  • config.update_multi —— 卡片是否可被多次更新（交互场景必填 true）
  • header.template —— 预设颜色主题，非 CSS 自定义色
  • body.direction —— 垂直/水平布局，控制 elements 排列方向
  • text_size —— 响应式设计，可分别设置 pc/mobile/default 下不同字号
  • button.behaviors —— 定义按钮行为，open_url 打开链接，支持 pc_url/ios_url/android_url 分别适配
  • content 字段为 string 类型，JSON 需转义后传值

2.4 富文本 post 中的 md 标签（重点）

飞书富文本 post 消息中新增 md 标签，原生支持 Markdown：
- 标准：CommonMark 0.31 + GFM（表格、任务列表、删除线、自动链接）
- 扩展：<at user_id="ou_xxx">用户</at> @用户、![alt](img_v3_xxx) 图片
- 注意：md 标签独占段落，不能与其他标签同行
- 推荐读取 content_v2 字段获取原始 Markdown（旧 content 字段会将 md 转为 text）
- 不支持：Setext 标题、缩进代码块、裸 HTML、邮箱自动链接

2.5 发送消息 API 统一接口

  • 接口：POST /open-apis/im/v1/messages/
  • 参数：receive_id（接收者）+ msg_type（interactive/post/text 等）+ content（JSON string，需转义）
  • 回复消息：POST /open-apis/im/v1/messages/{message_id}/reply
  • 编辑消息：PUT /open-apis/im/v1/messages/{message_id}
  • 注意：content 是 string 类型，嵌套 JSON 需先序列化再转义

2.6 应用场景

  • 静态推送：行业资讯、业绩排行、监控告警（用模板 ID + 变量最方便）
  • 动态交互：工单审批、活动报名、投票表单（需 card_id + 回调处理）
  • AI 机器人：流式更新卡片（先创建占位卡片 → 节流更新 → 最终全量兜底）
  • 链接预览：特定 URL 自动展开为卡片
  • 群置顶：卡片可作为置顶消息展示

三、对工作的价值

  1. Hermes 飞书推送可直接用方式三（原始 JSON），无需预先在搭建工具创建模板，适合 cron 产物摘要等动态内容
  2. feishu-card-table Skill 已在用 Card 2.0 格式，理解 JSON 结构有助于调试渲染问题（如方向/间距/响应式字号）
  3. 富文本 md 标签比 text 类型强大得多，支持表格/任务列表，但需注意飞书 Markdown 表格渲染限制（不支持嵌套和图片）
  4. 流式更新（方式一 card_id）是 AI Bot 长回复的最佳实践，避免一次性发送超长消息
