## 一、内容详细整理

### 1.1 核心问题与研究动机

自进化 Agent（如 Voyager、ExpeL、ACE、AHE）通过从执行轨迹中蒸馏可复用 skill 来积累能力——每完成一轮任务，就提取经验写入持久化 skill 池，注入后续每轮的决策上下文。理论上能力应该单调增长。

**本文发现的反直觉现象**：skill 积累并非单调递增。当 skill 池增长到某个临界规模 k* 后，新增的 skill 反而使性能下降——即使每个 skill 都是从 Agent 自己完成的合法轨迹中蒸馏出来的。论文称此为**「能力-污染相变点」(capability-contamination phase transition)**。

更关键的是，这种污染是**结构性不可逆的**：事后删除坏 skill 无法恢复大部分性能损失，因为坏 skill 已经作为参考上下文污染了后续蒸馏出的「后代 skill」。

现有系统（Voyager、ExpeL、ACE、AHE）共享一个从未被质疑的设计假设：distiller 产出的 skill 无条件准入——最多做去重，没有任何 skill 需要在进入运行时上下文前证明自己的价值。

### 1.2 方法论（详细）

**核心思想**：将 skill 准入从「写入操作」升级为「晋升决策」。每个新蒸馏的 skill 不会自动进入运行时上下文，而是必须通过一个**渐进式信任层级 (Progressive Trust Hierarchy)** 的三级过滤。

**三级信任架构**：

**Cold 层（冷启动）**：所有新蒸馏的 skill 初始进入 Cold 层。被记录但 Agent 看不见。缺陷无法传播。这是最便宜的隔离。

**Gate 1（个体安全性检查）—— 三种异质评审器**：

一个 skill 要离开 Cold 层，必须同时通过三种检查不同属性的评审器。因为三者检查的是正交属性（格式、行为、语义），一个有害 skill 必须同时欺骗全部三者才能通过：

1. **结构有效性 (Schema Validation)**：确定性 schema 检查（零 LLM 调用）。验证 skill 格式是否合法：name、trigger condition、body 结构是否完整。最便宜的过滤器。

2. **行为无害性 (Behavioral Harmlessness)**：单 skill A-B 回放——在 held-out 任务上对比「注入该 skill」vs「不注入」的成功率。这是唯一一个经验性测试行为的检查（而非表面形式）。消融实验显示这是最重要的维度（-10pp）。

3. **语义一致性 (Semantic Consistency)**：单次 LLM 评审（唯一的 LLM 调用）。检查 skill 是否包含捏造的、自相矛盾的建议。拦截「读起来合理但实际误导」的 skill。

设计哲学：不追求单一最强评审器，而是设计三个检查正交属性的低成本评审器，从信息论角度最大化拦截覆盖。两种便宜检查先做，只有幸存者才消耗 LLM 调用。

**Warm 层（预热）**：通过 Gate 1 的 skill 进入 Warm 层。个体安全但尚未验证组合安全性。

**Gate 2（组合安全性检查）—— 边际增益贪心选择**：

核心洞察：skill 效用不是全局单调的——一个 skill 可能降低联合性能。Gate 2 不是逐个判断，而是做子集选择：

- 目标函数：f(H) = E[R(agent ⊕ H, τ)]，即在 held-out 任务上的联合成功率
- 贪心策略：只有当一个候选 skill 能提升当前 Hot 集合的联合性能时才晋升
- 直接瞄准 Gate 1 无法检测的组合冲突

这引入了经典的弱子模优化 (weak submodularity) 理论，marginal-gain greedy 有理论近似保证。

**Hot 层（运行时）**：只有 Hot 层的 skill 被注入 Agent 的 system prompt。

**污染不可逆性的形式化**：

论文给出了严格的数学论证。skill 在第 r 轮蒸馏时，其上下文条件是 M_{r-1}（当前活跃 skill 池）。如果 M_{r-1} 含有缺陷 skill s，则 s 的缺陷被传递给后代 skill desc(s)。事后删除 s 只能恢复 R(M_r ∖ {s})，但后代中继承的缺陷仍在。完整恢复需要删除 {s} ∪ desc(s)，但现有 skill 库不记录蒸馏时的上下文血统。因此 skill 准入是循环中阻止污染传播的最后节点，验证必须在 skill 进入运行时上下文之前完成。

### 1.3 关键实验结果与数据

**主实验：Terminal-Bench 2 (Event-50, 50 任务)**

对比四种配置，5 轮进化（R1-R5），每任务 k=3 rollouts：

Ungated（无准入控制）—— 相变确认：
- R1: 48% (35 skills) → R2: 60% (68) → R3: 62% (105, 峰值)
- R4: 52% (141) → R5: 50% (179)
- R5 仅比 R1 高 2pp，尽管 skill 池从 35 增长到 179
- 相变点 k* ≈ R3 (105 skills)，之后性能倒退

VaG（门控进化）—— 单调递增：
- R1: 52% (5) → R2: 58% (15) → R3: 62% (25) → R4: 68% (30) → R5: 72% (37)
- 始终高于 Seed baseline (46%)
- Hot 池仅 37 个 skill（Ungated 的 1/5）
- R5 比 Ungated 最佳轮次 (R3, 62%) 高 10pp

Post-hoc Rollback（事后清理）：在 R5 崩溃后删除有害 skill → 52%（仅恢复 6pp），验证了不可逆性：事后清理只能恢复 17% 的退化。

**难度分层分析**：

污染精准打击最难的任务。Ungated Hard 层：R2 峰值 53% → R5 降至 35%（-18pp）。VaG Hard 层：持续提升到 R5 的 59%（比 Ungated 高 24pp）。多步任务中污染链最长，受害最深。

**消融实验 (Table 2)**——移除任一评审器的代价：
- 移除 Schema validation: -2pp（格式错误大多被 backbone 忽略或修复）
- 移除 Holdout replay: **-10pp**（最关键——唯一经验性测试行为的检查）
- 移除 Semantic check: -4pp（捏造/矛盾建议通过行为测试但误导 Agent）
- 移除 Marginal-gain gate: -8pp，Hot 池从 37 膨胀到 58（组合污染的直接证据）

三重检查互补性确认：每种检查拦截不同类型的有害 skill（格式错误/静默有害/看似合理实则捏造），不可互相替代。

**跨模型迁移 (Table 3)**：

冻结 VaG 的 Hot skill 池（37 skills，在 Hy3 上进化），在其他 4 个 backbone 上直接推理（不重新进化）：
- Hy3: 32% → 44% (+12pp)
- DeepSeek-V4-Pro: 32% → 40% (+8pp)
- GPT-5.4: 44% → 56% (+12pp)
- Claude Sonnet 4.5: 48% → 56% (+8pp)
- Qwen3.6-35B-A3B: 36% → 52% (+16pp)

结论：门控进化蒸馏出的是模型无关的工程经验，而非 backbone 特定的伪影。

**跨基准迁移 (Table 4)**——在 InterCode NL2Bash (200 任务) 上测试：
- Seed (3 skills): 57.5%
- Ungated R5 (179 skills): 65.5% (+8.0pp)
- VaG R5 (37 skills): 69.0% (+11.5pp)

VaG 用 1/5 的 skill 池，在完全不同的基准上超越 Ungated。

**Token 效率**：Ungated R5 为 1.19M tokens/trial，VaG R5 为 0.94M tokens/trial（节省 21%）。

### 1.4 创新点分析

1. **首次形式化「能力-污染相变」**：将自进化 Agent 的非单调性从经验观察提升为有严格定义的三级分类法（个体/组合/系统污染）

2. **不可逆性定理**：证明了 post-hoc 回滚的数学上限——即使知道哪个 skill 有害也无法完全恢复，因为血统传播是不可逆的。这是对 Voyager 等「先存后筛」范式的根本性挑战

3. **渐进式信任层级**：Cold → Warm → Hot 的三级架构，巧妙利用了「验证成本递增」的设计——便宜检查先做，贵检查只对少量幸存者做

4. **组合安全检查引入子模优化**：将 Agent skill 准入问题与经典的弱子模优化理论连接，marginal-gain greedy 有理论近似保证

5. **三重异质评审器设计哲学**：不追求单一最强评审器，而是设计三个检查正交属性的低成本评审器

### 1.5 局限性与未来方向

1. **任务域窄**：仅在 Terminal-Bench 2（shell 命令任务）上验证。非终端任务（如多轮对话、代码生成、创意写作）的污染模式可能不同

2. **Skill 粒度假设**：假设 skill 是结构化的自然语言单元（name + trigger + body）。对非结构化经验（如隐式策略偏好）不适用

3. **A-B 回放成本**：Gate 1 的行为检查需要在 held-out 任务上运行 Agent，对昂贵模型可能不划算

4. **跨模型迁移的 open question**：论文展示了正面迁移，但未讨论负迁移场景（某 skill 在 Hy3 上有益但在 Claude 上有害）

5. **进化轮数有限**：仅 5 轮。更长的进化周期中 k* 是否稳定、VaG 是否能持续单调提升，未验证

## 二、查询拓展

### 2.1 子模优化与边际增益贪心 (Submodular Optimization & Marginal-Gain Greedy)

子模函数是组合优化中的核心概念：一个集合函数 f 满足「添加元素到较小集合的边际收益 ≥ 添加到较大集合」——即边际递减。经典定理（Nemhauser 1978）证明：对单调子模函数在基数约束下，贪心算法（每步选边际增益最大的元素）可达 (1-1/e) ≈ 63.2% 的近似比。本文的 Gate 2 使用弱子模扩展（Das & Kempe 2011），允许函数非完全子模时仍有近似保证。在 Agent skill 场景中，这意味着：即使 skill 之间有复杂交互（非线性），按边际增益排序贪心选择仍能近似最优子集。

### 2.2 Capability-Contamination 相变与统计力学类比

论文将 skill 积累的非单调性命名为「相变」(phase transition)，借用了统计力学概念。在伊辛模型等物理系统中，相变是指系统参数跨过临界点时宏观行为的突变（如液态→气态）。本文中 k* 是临界 skill 数量——低于它时 skill 积累是建设性的，高于它时变为破坏性的。这种相变思维也可应用于理解 LLM 的涌现能力、context window 的信息密度阈值等现象。

### 2.3 A-B Replay 测试范式

A-B replay 是软件工程中 A/B 测试的变体：在受控环境中对比「有 vs 无某个变更」的系统行为差异。本文的创新在于将 A-B replay 应用于单个 skill 的行为验证——在 held-out 任务集上，对比注入 vs 不注入某 skill 的成功率差值 g({s}, τ)。这与传统 A/B 测试的区别在于：变更单位不是 UI 变体或推荐策略，而是 Agent 上下文中的一条自然语言经验。该范式可直接迁移到任何「软变更」的效果评估——如 prompt 模板修改、system prompt 微调、memory 条目增删。

## 三、归纳总结

### 3.1 借鉴点评估（关联 Hermes Agent）

**P0 — Skill 准入门控机制（可直接落地）**

当前 Hermes 的 skill_manage(action='create') 是无条件写入——只要调用就创建。本文证明这是危险的。建议增加一层「Cold skill」概念：
- 新创建的 skill 先标记为 status: cold（在 frontmatter 中）
- 不自动注入 system prompt 的 available_skills 列表
- 需要通过验证后（如 cron 压力测试 skill-stress-test）才升级为 status: hot
- 这直接对应论文的 Cold → Hot 晋升机制

**P0 — Skill 血统记录（可直接落地）**

论文指出不可逆性的根因是「不知道哪个 skill 在蒸馏时是活跃的」。建议在 skill frontmatter 中增加 distilled_from 字段，记录创建时的活跃 skill 列表。这样如果发现某 skill 有害，可以追踪所有以其为参考上下文蒸馏出的后代 skill。

**P0 — 三重评审器模板化（可直接落地）**

将论文的三种评审器固化为 Hermes skill 审查的标准流程：
- Schema check: 已有 skill_manage 的 frontmatter 验证
- Behavioral replay: 利用已有的 skill-stress-test skill（用 subagent 验证）
- Semantic review: 可在创建后自动触发一次 LLM 评审（类似 content-judge）

**P1 — 边际增益 Skill 合并决策（需工程改造）**

当前 Hermes 的 skill-review 是逐个评估 skill 质量。但本文证明组合冲突是真实存在的——两个各自无害的 skill 可能冲突。建议 skill-review 增加：批量审查时检查 skill 之间的语义冲突（如两个 skill 给出矛盾的 cron 调度策略），对已识别冲突的 skill pair 标记互斥关系。

**P1 — 污染监控指标（需工程改造）**

在 Hermes 的 observability-dashboard 中增加 skill 污染监控：追踪每个 skill 创建后的任务成功率变化趋势。如果某 skill 创建后成功率下降，标记为「污染嫌疑」，类似论文中的 injection gain g({s}, τ) < 0 检测。

**P2 — Hermes Skill 池大小监控（长期方向）**

论文发现相变点 k* 的存在。对 Hermes 来说，当前的 400+ skills 是否已越过相变点？这是一个值得用 skill-stress-test 验证的实证问题。建议定期运行「skill 池减半实验」：随机移除 50% skills，看任务完成率是否反而提升。

## 四、趋势判断

### 4.1 从「无条件进化」到「门控进化」的范式转移

本文标志着 AI Agent 自进化研究的焦点从「如何更快地蒸馏 skill」（Voyager/ExpeL 时代）转向「如何安全地准入 skill」。这一范式转移的逻辑链是：自进化系统的核心瓶颈不再是蒸馏能力（LLM 已足够强大），而是质量控制——当 skill 池增长到一定规模后，蒸馏的边际产出为负。预计 2026 下半年到 2027 将出现大量跟进工作：不同领域的相变点 k* 测量、更高效的组合冲突检测算法、自动化血统追踪基础设施。对工业级 Agent 系统（如 Hermes、Claude Code、Cursor），门控进化将从「可选优化」变为「必要基础设施」。

### 4.2 Agent 可靠性工程的数学化

本文将污染不可逆性提升为定理（Eq. 5），将组合安全性连接到子模优化理论。这预示着 Agent 可靠性研究正在从「经验工程」（加 retry、加 timeout）走向「形式化保证」（基于优化理论的近似比、基于图论的血统追踪）。未来的 Agent 框架可能像数据库系统一样自带 ACID 性质——其中「Isolation」对应 skill 准入隔离，「Durability」对应 skill 血统持久化。

## 五、关联分析

### 5.1 关联论文

- **Voyager** (Wang et al. 2023) — 开源 skill 库先驱，仅验证 skill 能否完成目标任务就存储，不检查对其他任务的负面影响。本文直接挑战的设计
- **ExpeL** (Zhao et al. 2024) — 从执行轨迹蒸馏经验知识，同样是无条件准入
- **ACE** (Zhang et al. 2025) — 大规模上下文级进化，继承了无条件准入假设
- **AHE** (Lin et al. 2026) — harness 级进化，评估延迟到 harness 层，无法归因到单个 skill
- **EvoSOP** (2607.07321, 之前精读) — 消融证明剪枝 > 创建。本文从「准入门控」角度补充了 EvoSOP 的「评估后剪枝」——准入时拦截比事后剪枝更经济
- **SPyCE** (2607.13854, 之前精读) — 技能-策略协同进化。本文的 marginal-gain 选择可直接增强 SPyCE 的 merge-or-add 决策
- **OpenForgeRL** (2607.21557, 之前精读) — harness-native RL 训练。本文的 VaG 可作为 RL 训练中 skill 质量门控的预处理步骤
- **Binding Drift** (2607.18316, 之前精读) — 实体绑定漂移。本文的「污染血统传播」与 Binding Drift 的「错误传播放大」在多步 Agent 失败模式上有结构相似性
