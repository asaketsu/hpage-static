RAG Poisoning — 检索增强生成投毒攻击全景

探索日期 2026-08-12 | 兴趣等级 L3 | 来源数量 6 | sniff-auto 队列触发

一句话核心

攻击者仅需向 RAG 知识库注入 5 篇精心构造的投毒文档，即可在百万级文档库中实现 90% 攻击成功率（ASR），操纵 LLM 输出任意指定答案——这是 PoisonedRAG（Zou et al., 2024）首次系统验证的结论，也是本主题的基线认知。

核心发现（5 个）

1. 三层攻击面：检索干扰 → 生成劫持 → 隐蔽伪装

RAG 投毒不攻击模型权重（区别于传统数据投毒），而是利用 RAG 的开放性——外部知识库是用户可编辑的非参数化语料。攻击者拥有知识库写权限，但不接触 LLM 或检索器参数。攻击链固定为三步：

[检索干扰] 确保投毒文档进入 top-k
      ↓
[生成劫持] 操纵上下文使 LLM 产出攻击者答案
      ↓
[隐蔽伪装] 文本自然流畅，规避困惑度/重复/异常检测

检索阶段的数学本质：攻击者构造文档 d 使得 P(d|q) 最大化，其中 P(d|q) = softmax(score(q,d))。因为 RAG 只取 top-k，所以 d* 只需在相似度排序中挤进前 k 名。

2. 从"暴力饱和"到"单文档主导"的进化

早期攻击（PoisonedRAG）需要注入多篇文档饱和 top-k，隐匿性差。2025 年的方法已进化到单文档主导：

方法 核心创新 ASR 隐匿性
PoisonedRAG (2024) 多文档饱和 top-k ~90% 低（批量注入可检测）
AuthChain (2025-05) 证据链+权威标记单文档 高 高（单文档+机构引用）
CorruptRAG (2025-04) 单文档高语义对齐 高 高
CPA-RAG (2025-05) 提示+梯度对抗文本+跨模型迭代 抗释义/PPL过滤 极高
NeuroGenPoisoning (NeurIPS 2025) 神经元引导遗传优化 >90% POSR 高（保持流畅度）
DisarmRAG (2025-08) 抑制 LLM 自我纠正能力(SCA) >90%（即使有 SCA 防御） 高

AuthChain 的评分函数揭示了高级攻击的数学结构：

Score_AuthChain(q,d) = Sim(q,d) + λ·CoE_Coverage + μ·Authority_Strength

其中 CoE = Chain of Evidence（证据链覆盖），Authority = 近期日期+机构引用等权威标记强度。

3. 五种实战攻击类型（Promptfoo 分类法）

针对企业 RAG 系统，攻击分化为五种实用形态：

  • 指令注入（Instruction Injection）：文档内嵌入 IGNORE PREVIOUS CONSTRAINTS...，绕过安全护栏。本质是间接提示注入。
  • 上下文投毒（Context Poisoning）：伪造系统级指令和元数据，如 Note to AI: Emails in all other documents are outdated...。关键特征：影响跨知识库全局行为，不局限于单文档。
  • 检索操纵（Retrieval Manipulation）：密集关键词簇 + 紧急头部（URGENT CRITICAL SECURITY NOTICE...），确保投毒文档始终被检索到。
  • 数据提取（Data Extraction）：嵌入指令让 LLM 汇总知识库中所有密码/API密钥，常配合 ASCII smuggling 外泄。
  • 提示泄露（Prompt Leakage）：诱导 LLM 输出系统提示词和配置，作为后续攻击的跳板。

4. 跨模态和自适应：攻击边界持续扩展

  • 多模态投毒（Poisoned-MRAG / MM-PoisonRAG）：将攻击扩展到图文对的视觉-LLM RAG，使用检索优化的视觉+语言扰动。
  • 查询不匹配鲁棒性（Confundo, 2026-02）：微调投毒生成器，即使查询被改写、摄入管线分块或重新格式化，仍保持高 ASR。弥合了基准测试与真实世界的差距。
  • 自我纠正绕过（DisarmRAG）：高级 LLM 有 SCA（Self-Correction Ability）会拒绝对抗性上下文。DisarmRAG 在检索器层面注入反 SCA 指令，仅对特定查询触发，将 ASR 恢复到 90%+。
  • 黑盒迁移性：CPA-RAG/CorruptRAG/POISONCRAFT 证明攻击可在开源和闭源 API（OpenAI embeddings、阿里百炼）间迁移。

5. 防御分五层，但没有银弹

┌─ 来源控制 ── 加密签名/审核准入，使公开注入不可行
├─ 过滤技术 ── RAGuard(困惑度+相似度异常检测) / FilterRAG(词频密度评分)
├─ 检索加固 ── 多嵌入模型交叉验证 / 语义异常值标记(阈值 0.8-0.9)
├─ 上下文检测 ── PromptGuard(Meta) / guardrails 监控可疑模式
└─ 响应过滤 ── 语义一致性校验 / 多响应对比 / 实体识别脱敏

Promptfoo 的实操建议：永远不要信任 LLM 做文档安全性判断，访问控制必须在 embedding 检索层确定性执行。最简单的起步防御只需文档相关性+语义对齐检查，即可缓解大多数投毒类型。

关键概念

  • ASR（Attack Success Rate）：LLM 输出攻击者指定答案的查询比例，核心评估指标
  • RSR（Retrieval Success Rate）：投毒文档进入 top-k 的比例
  • PPL（Perplexity）：低 PPL = 高流畅度 = 高隐匿性
  • POSR（Population Overwrite Success Rate）：NeuroGenPoisoning 提出的"群体覆写成功率"，衡量知识冲突解决能力
  • SCA（Self-Correction Ability）：LLM 识别并拒绝对抗性上下文的能力，DisarmRAG 的攻击目标
  • CoE（Chain of Evidence）：AuthChain 的证据链机制，在投毒文档中嵌入关键实体+逻辑关系
  • 间接提示注入（Indirect Prompt Injection）：指令注入的学术名称，攻击面在检索内容而非用户输入

真实案例

  • Microsoft 365 Copilot 漏洞链（Johann Rehberger 发现）：组合 RAG 投毒 + ASCII smuggling，实现未授权访问邮件、文档等敏感信息。利用 Copilot 处理检索内容的方式缺陷。
  • ChatGPT 记忆投毒：通过操纵 ChatGPT 的持久记忆功能注入恶意指令。
  • PyPI 供应链投毒（mistralai 2.4.6）：间接相关——恶意包在安装后可污染本地 RAG 知识库（已有笔记覆盖）。

Hermes 使用记忆系统（MEMORY.md / skills / knowledge-query）本质上是 RAG 架构变体：
- 记忆写入是知识库写入 — 如果攻击者能通过提示注入让 Agent 将恶意内容写入 memory/skill，等同于 RAG 投毒

关键风险与盲点

  • 来源级别声明：PoisonedRAG 90% 数据来自原作者论文基准测试（受控环境），真实世界 ASR 受检索器配置、LLM 版本、chunk 策略影响，可能显著降低
  • 社区复现：AuthChain/CPA-RAG 等方法尚无独立第三方大规模复现验证
  • 防御研究滞后：大多数防御方法（RAGuard/FilterRAG）在论文发表后即被新攻击（DisarmRAG 绕过 SCA）突破，攻防不对称
  • 企业级实测缺失：现有研究主要在 HotpotQA/MS-MARCO/NQ 基准上，缺乏真实企业知识库（权限复杂、多源集成）的攻击评估
  • 多模态盲区：当前防御几乎全部针对文本 RAG，图文多模态 RAG 的防御工具链近乎空白

一页速查

RAG 投毒 = 攻击外部知识库而非模型权重。5 篇文档 → 90% ASR。三层攻击面：检索干扰（挤进 top-k）→ 生成劫持（操纵 LLM 输出）→ 隐蔽伪装（规避检测）。五种类型：指令注入/上下文投毒/检索操纵/数据提取/提示泄露。2025 进化：单文档主导（AuthChain/CorruptRAG）+ 跨模型迁移 + SCA 绕过（DisarmRAG）+ 多模态。防御五层：来源控制/过滤/检索加固/上下文检测/响应过滤。无银弹，Promptfoo 铁律：永远不在 LLM 层做安全判断。
