## 摘要

AI Agent 架构正在从"单 Agent + Tools"向"多 Agent 协作 + 协议栈"演进。MCP（Model Context Protocol）、A2A（Agent-to-Agent）、Function Calling 三个协议分别解决不同层面的问题，形成互补的协议栈而非竞争关系。

## 核心发现

### 1. Agent 协议栈模型

```
┌─────────────────────────────────────────┐
│           Application Layer              │
│  (Skills / SOP / Business Logic)         │
├─────────────────────────────────────────┤
│         A2A Protocol (Agent-to-Agent)    │ ← 多 Agent 协作
│  - 任务分发  - 结果聚合  - 状态同步      │
├─────────────────────────────────────────┤
│     Function Calling (Model Level)       │ ← 模型工具调用
│  - Tool 定义  - 参数解析  - 执行结果     │
├─────────────────────────────────────────┤
│        MCP (Model Context Protocol)      │ ← 工具/数据连接
│  - 资源发现  - 工具注册  - 上下文共享    │
├─────────────────────────────────────────┤
│           Transport Layer                │
│  (HTTP/gRPC/WebSocket/Local IPC)         │
└─────────────────────────────────────────┘
```

**核心结论**：MCP、A2A、Function Calling 是**互补的三层协议**，而非竞争关系。

| 协议 | 层级 | 解决的问题 | 类比 |
|-----|------|-----------|------|
| **MCP** | 基础设施层 | 如何让 Agent 连接外部工具和数据 | USB 驱动/神经系统 |
| **Function Calling** | 模型交互层 | 模型如何调用工具 | API 调用 |
| **A2A** | 协作层 | Agent 之间如何协作 | 团队沟通协议 |

### 2. MCP (Model Context Protocol) 深度解析

**定义**：Anthropic 推出的标准化协议，让 AI 模型可以安全、统一地访问外部工具和数据源。

**核心能力**：
- **Resources**：读取外部数据（文件、数据库、API）
- **Tools**：执行外部操作（调用函数、运行脚本）
- **Prompts**：共享系统提示模板
- **Sampling**：模型间请求采样（嵌套调用）

**MCP 服务器类型**：
| 类型 | 示例 | 用途 |
|-----|------|------|
| 文件系统 | `filesystem` | 读取/写入本地文件 |
| 数据库 | `postgres`, `sqlite` | 查询数据库 |
| API 集成 | `brave-search`, `fetch` | 调用外部 API |
| 自定义 | 企业自研 | 内部工具/系统 |

**我们的实践**：
- 已有 `hermes-agent` skill 集成 MCP 客户端
- 通过 `mcporter` CLI 管理 MCP 服务器
- 支持动态加载/卸载 MCP 服务器

### 3. A2A (Agent-to-Agent) 协议

**定义**：Agent 之间的通信和协作协议，支持任务分发、结果聚合、状态同步。

**核心模式**：

| 模式 | 描述 | 适用场景 |
|-----|------|---------|
| **Manager-Worker** | 一个 Agent 分配任务给多个 Worker | 批量处理、并行计算 |
| **Pipeline** | Agent 串联，前一个输出是后一个输入 | 数据处理流水线 |
| **Peer-to-Peer** | Agent 平等协作，共享状态 | 复杂问题分解 |
| **Marketplace** | Agent 竞价承接任务 | 资源优化分配 |

**A2A 关键挑战**：
1. **任务分解**：如何将复杂任务拆解为子任务
2. **结果聚合**：如何整合多个 Agent 的输出
3. **冲突解决**：多个 Agent 操作同一资源时的冲突
4. **状态同步**：保持多 Agent 状态一致性

### 4. Function Calling 演进

**传统方式**：
```python
# 手动解析模型输出
output = model.generate(prompt)
tool_name = extract_tool(output)
tool_args = extract_args(output)
result = tools[tool_name](**tool_args)
```

**现代方式（Function Calling）**：
```python
# 模型原生支持工具调用
response = client.chat.completions.create(
    model="gpt-4",
    messages=messages,
    tools=[{"type": "function", "function": {...}}]
)
# 模型返回结构化 tool_calls
for tool_call in response.choices[0].message.tool_calls:
    result = execute_tool(tool_call)
```

**演进趋势**：
- **结构化输出**：模型直接返回 JSON 而非文本
- **工具发现**：模型自动学习可用工具
- **嵌套调用**：工具调用中可以再次调用工具

## 关键概念

### Skills vs MCP：互补而非竞争

| 维度 | MCP | Skills |
|-----|-----|--------|
| **解决什么** | 连接性（Connectivity） | 能力/知识（Capability） |
| **类比** | USB 驱动/神经系统 | 应用程序/大脑皮层 |
| **格式** | 标准化协议 | 文件系统（SKILL.md） |
| **适用场景** | 外部服务连接 | 复杂工作流+领域知识 |

**LangChain 创始人观点**：
> "绝大多数差异化，在于指令、工具和技能。领域知识、专属工具、业务流程指令，这些不会变，才是真正的壁垒。"

### 渐进式披露（Progressive Disclosure）

**核心原则**：不要一次性把所有上下文灌入模型。

```
触发前：[系统提示 + 工具定义] ← 仅名称和描述
触发后：+ [SKILL.md 详细指令] ← 按需加载
需要时：+ [references/xxx.md] ← 进一步按需
```

**效果**：Token 消耗降低 90% 以上。

### Hard Gates（强制门禁）

**定义**：关键操作前的强制检查点，不可跳过。

**应用场景**：
- 代码提交前的自动测试
- 生产部署前的安全扫描
- 多 Agent 协作的结果验证

**趋势**：从"可选检查"转向"强制门禁"，Claude Code 等工具已采用此模式。

### 对我们的系统价值

| 发现 | 行动建议 | 优先级 |
|-----|---------|-------|
| MCP/Skills 互补 | 明确区分：MCP 负责连接，Skills 负责业务逻辑 | P0 |
| A2A 协议需求 | 设计多 Agent 协作框架，支持 Manager-Worker 模式 | P1 |
| 渐进式披露 | 优化 SKILL.md 加载策略，控制单文件 <500 行 | P1 |
| Hard Gates | 在关键流程（部署、发布）增加强制检查点 | P2 |

### 架构优化建议

1. **协议栈分层**：
   - 基础设施层：MCP 服务器管理
   - 模型交互层：Function Calling 封装
   - 协作层：A2A 任务调度器
   - 应用层：Skills 业务逻辑

2. **Skills 标准化**：
   ```
   SKILL.md 结构：
   ├── Definitions (能力描述、触发条件)
   ├── Instructions (System Prompt + 工具调用逻辑)
   └── Resources (scripts/ + references/ + assets/)
   ```

3. **多 Agent 协作框架**：
   - 实现 Manager-Worker 模式
   - 支持任务队列和结果聚合
   - 添加冲突检测和解决机制

### 安全考虑

| 风险 | 缓解措施 |
|-----|---------|
| MCP 服务器恶意行为 | 沙箱运行 + 权限最小化 |
| Skills 代码注入 | skill-vetter 安全审计 |
| A2A 状态冲突 | 乐观锁 + 冲突检测 |
| Function Calling 参数注入 | 参数验证 + 白名单 |
