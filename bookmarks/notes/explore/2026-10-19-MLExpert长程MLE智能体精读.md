## 一、内容整理

### 1.1 核心问题：AI4AI 通路上的长程 MLE 训练

- **背景定位**：LLM 正从"辅助科研/工程"走向"自主开发并改进 AI 系统"（模型训练、求解器优化、算法设计），即 AI for AI（AI4AI）作为递归自我改进（RSI）的研究路径。机器学习工程（MLE）是这个目标最具体的落点：要求通过反复执行、反馈分析、修订来做长程优化，而非一次性生成。
- **范式转移**（论文 Figure 1 的核心对比）：
  - **外部编排式**（多数现有 MLE 系统）：预定义 workflow/搜索规则控制实验排序与阶段切换，LLM 只在指定步骤生成/调试代码——长程组织能力在编排层，不在模型里
  - **模型主导式**（Arbor/Argus/MLExpert）：模型自己根据实验状态与执行反馈决定下一步分析、修订、执行还是换方向——长程组织能力被训练进模型权重
- **训练的三大挑战**（论文明确提出）：
  1. 开放式 MLE 需要一个**保留实验状态、把动作选择权留给模型**的交互环境
  2. 长程监督难以获得——轨迹混杂"有效探索+失败恢复+退化决策"，不能整条照搬
  3. 每个昂贵实验的反馈**滞后覆盖多个先前决策**，且整条轨迹结束前就要能用中间信号更新策略

### 1.2 MLE 形式化（Preliminary）

- 任务 e = (任务描述 d, 数据 D, 评估指标 m)；候选解 y 是完整 ML 管线（数据处理→特征工程→模型训练→预测）
- 目标：y* = argmax S_e(y)，最终提交用隐藏测试标签独立评估（沿用 MLE-bench 协议）
- 轨迹 τ = (o0, a0, o1, ...)，每步动作可含推理+多个工具调用；**实验状态（代码/执行记录/候选解）存外部 workspace，通过工具观测暴露给模型**
- 优化目标 J(π;e) = E[S_e(ŷ_τ)]——最大化最终所选提交解的期望质量

### 1.3 Kaggle-MLE Factory：把历史竞赛变成可执行训练任务

- **问题**：历史 Kaggle 竞赛数据组织/提交格式/评估协议高度异构，手工改造无法规模化
- **多智能体流水线**：
  - discovery agent：按状态/规模/提交格式筛选竞赛
  - analyzer agent：抽取数据结构、字段、模态特征 → 任务规格
  - generator agent：准备数据、从原始标注数据构造隐藏测试切分、实现任务专属 evaluator
  - validator：数据完整性/提交格式/评估行为三向校验，迭代修复
- **人工终审**：排除标签或计分未决问题后才进入轨迹采集
- 产出的标准化任务包可对接不同 MLE agent 框架（训练资产与环境解耦）

### 1.4 Interaction Harness：模型主导的长程实验环境

- ReAct 式循环，**分支选择与优化路径决策留给模型**，不做外部搜索策略
- **实验树结构**：solution node 存候选代码+执行日志+元数据，父链修订构成实验树——模型可回访、对比，决定继续/回溯/换方向
- 工具集：`execute_code`（执行候选）、`update_answer`（更新提交候选）、`analyze`（**委托分析子代理**：独立上下文做数据分析/结果诊断，只回摘要给主模型）、`invalidate_node`（基于实验证据剔除过拟合/数据泄漏的不可靠候选）、历史检索类工具
- **上下文压缩**：接近上下文上限时摘要早期消息、保留近期交互（训练数据同步记录压缩事件，见 1.5）
- 防作弊设计：过拟合/泄漏会虚高验证分 → 模型可凭证据作废节点

### 1.5 层级 Agentic SFT：结果导向的监督选择

- **两阶段**：
  - 阶段一：通用编码+工具使用轨迹（多样 agentic 任务）打基础
  - 阶段二：MLE 域 + Nature 族文献衍生的科研任务教师轨迹
- **互补的 MLE 演示数据**（三类）：
  - 初始解轨迹：首个可执行且过质量阈值的解的前缀（任务理解→算法设计→代码生成）
  - 长程优化轨迹：完整交互（构建→反馈分析→迭代修订→提交选择）
  - 分析子代理轨迹：独立训练数据分析与结果诊断能力
- **结果导向监督选择（关键设计）**：
  - 用提交解的执行结果筛选高质量轨迹与监督片段
  - 定位**首个最优提交**，测其后性能退化幅度；退化超阈值 → 以首个最优提交为锚保留轨迹前缀；否则用最后一次提交
  - 前缀在完整工具交互边界截断——**砍掉退化尾巴，保留峰值前的有效探索与失败恢复**
- **监督样本构造**：保留多轮上下文依赖；上下文压缩发生时，保留历史+摘要构成条件上下文；**loss 只算新生成的推理/文本/工具调用 token，工具反馈与继承历史全部 mask**

### 1.6 WIRL：窗口化交互强化学习（本文最核心方法）

- **执行窗口（execution window）**：以 `execute_code` 返回的实验结果为边界，把"自上一个结果以来的所有模型决策"打包成一个窗口 u_m。首窗口从初始任务状态开始。**策略更新无需等整条任务轨迹结束**
- **窗口奖励 R_m**（用任务专属奖牌阈值做统一参照）：
  - 模型动作导致执行错误：−1.0
  - 无执行错误但无可评分提交：−0.6
  - 有效提交低于奖牌线：−0.4 + T_m
  - 铜牌/银牌：1.0 + T_m；金牌：2.0 + T_m
  - T_m ∈ {−0.2, 0, +0.2}：相对上一个有效提交的**局部趋势**（降/平/升），首个有效提交 T_m=0
- **与 GRPO 的关键差异**：不用组相对归一化，**直接把可验证执行奖励当共享优化权重 Â_m = R_m**，施加于窗口内全部主模型输出 token
- **异步采集 + 策略修正**：实验时长不一 → 异步收窗口成批训练；长轨迹跨越多次策略更新 → rollout 策略与当前训练策略不一致 → **token 级策略修正**，用采集时记录的三组 log 概率（当前训练策略 θ / 更新前固定策略 old / rollout 策略 roll）做重要性权重校正

### 1.7 关键实验结果

- **设置**：MLE-Bench Lite（22 任务）；每任务 3000 交互步、12 小时、20 vCPU + 220GB RAM + 1×H200；MLExpert 从 Qwen3.6-35B-A3B 初始化
- **主结果（MLE-Bench Lite，MLExpert Harness 下 Any Medal）**：
  - MLExpert：72.7%（Med+ 84.8、金 50.0、银 16.7、铜 6.1）
  - 基座 Qwen3.6-35B-A3B：37.9% → **+34.8 个百分点**
  - 同级基线：Ornith-1.5-35B-A3B 39.4%、Nex-N2.5-mini 47.0%
  - 大型前沿模型：GLM-5.3 72.7%、Kimi-K3 72.7%、GPT-5.5 72.7%、GPT-5.6 Sol 77.3%、MiniMax M3 68.2%、DeepSeek-V4-Pro 63.6%——**35B 专训模型追平自家 3-4 倍规模的前沿通用模型**
- **换通用 harness 仍成立**（Claude Code 下）：MLExpert 69.7% vs 基座 42.4%（+27.3），超过最强同级基线 22.7 个百分点——**提升不绑定自家 harness**
- **消融（Table 3，阶段累积）**：基座 37.9 → +通用 Agentic SFT 47.0 → +MLE SFT 62.1 → +WIRL 72.7，每段都有增量
- **RL 对比（Table 4，同 SFT 初始化）**：
  - 轨迹级 GRPO：56.1（**低于 SFT 起点 62.1，朴素 RL 反而伤害**）
  - PPO 式（终端奖励+clip，无 critic）：60.6（同样低于 SFT）
  - WIRL 去趋势奖励：66.7；去策略修正：65.2；完整 WIRL：72.7——**两项设计各贡献一部分**
  - 附录进一步显示：异步执行窗口采集显著降低 learner 等待占比
- **NatureBench Lite（科研任务，Claude Code）**：Surpass-SOTA 从基座 0.0% → 50.0%（平 GLM-5.3，Kimi-K3 70%）；Match-SOTA 40%→70%
- **案例研究（MLSP 2013 Birds）**：MLExpert 从音频特征+LightGBM → PANNs 表示 → AST 微调+attention pooling+MLP 头 → 训练日程调整+snapshot 平均，ROC-AUC **0.58→0.964**；SFT 版只到 0.88（起点 0.60）——WIRL 学到的是"持续改进"而非"一次做对"
- **泛化（Table 5 + Figure 4）**：
  - AIME 脚手架优化（固定 GPT-4.1-nano 求解器）：MLExpert 优化出的 scaffold 留出集 43.7% vs 基座优化 23.3%（GLM-5.3 48.1、Kimi-K3 40.0）；SFT 版 38.1% 且只需 3.51 次调用（效率显著更优）
  - MLS-Bench-Lite 算法组件优化：mean verifier reward 0.322→0.425，12 任务 10 胜 1 平 1 负，横跨语言模型去噪、多目标优化、因果发现
- **结论句**：把长程优化决策当作**可训练的模型能力**是成立的，为自主 MLE 与科学实验提供了实用路径

### 1.8 论文自述/可观察的局限

- 评估面窄：主基准 MLE-Bench Lite 仅 22 任务（Any Medal 是 5 项指标之一作主指标）；NatureBench Lite 仅 10 任务
- 成本极高：训练评估每任务 12h × H200；长程 RL 采集的异步工程复杂
- 奖励设计依赖 Kaggle 奖牌阈值体系——迁移到无明确"奖牌"语义的领域需要重设计参照系
- 与前沿最强的 GPT-5.6 Sol（77.3）仍有差距；金牌率 50% 距 Kimi-K3 63.6 有距离（银铜结构不同）

## 二、查询拓展

### 2.1 AI4AI / RSI（递归自我改进）

AI 用 AI 方法改进 AI 系统的总称：AutoML 是其早期形态（搜索空间受限），现代形态是 agentic MLE——模型自主组织实验循环。RSI 是更强版本：改进对象包含模型自身。MLExpert 刻意停在"改进 ML 工件"层面，回避自我改写的安全性问题，但训练范式（执行反馈→策略更新）与 RSI 同构。

### 2.2 MLE-bench 系基准

OpenAI 2024 提出的 Kaggle 竞赛代理基准，按人类奖牌阈值（金/银/铜）评级；Lite 子集 22 任务。该基准的"隐藏测试标签独立评估"设计天然防验证集作弊，是可验证奖励（RLVR）思想在 MLE 域的落地。

### 2.3 信用分配谱系：GRPO → 过程监督 → WIRL

- GRPO：组内相对基线，需要同题多条完整轨迹，信号在轨迹终端
- 过程监督（PRM 类）：逐步打分，但打分器本身会漂移
- KnowGPO（同期论文 2610.22331）：用"已满足的原子知识条件"定义状态，知识增量做过程奖励
- WIRL：**不做逐步打分，而是把"可验证的实验结果"作为天然边界**切窗口——窗口内部共享结果奖励。粒度介于轨迹级与步级之间，且奖励完全来自环境执行，无需额外 verifier 模型

### 2.4 2026 秋的同规模 MoE 竞争带

Qwen3.6-35B-A3B（3B 激活）、Ornith-1.5-35B-A3B、Nex-N2.5-mini 构成"35B 总参/3B 激活"档位；MLExpert 证明该档位经过域内 agentic 后训练可以在垂直长程任务上追平 Kimi-K3/GLM-5.3 级前沿模型——"小专训 vs 大通用"的又一数据点。

## 三、归纳总结

### 3.1 总体框架

```
Kaggle 竞赛历史 ──Kaggle-MLE Factory──▶ 可执行任务包
                    (discovery→analyzer→generator→validator→人工终审)
                                              │
                                              ▼
                              Interaction Harness（ReAct 循环）
                     solution node 实验树 │ execute_code / update_answer
                     analyze 子代理 │ invalidate_node 防泄漏 │ 上下文压缩
                                              │
              ┌───────────────────────────────┴───────────────┐
              ▼                                               ▼
   层级 Agentic SFT                                  WIRL
   通用工具SFT→MLE域SFT                    执行窗口=两次实验结果之间的决策
   结果导向轨迹筛选（退化尾巴截断）          奖牌阈值+局部趋势 R_m（无组归一化）
   loss 只算生成 token                       异步采集 + 三组 log 概率策略修正
              └───────────────────────────────┬───────────────┘
                                              ▼
                            MLExpert-35B-MoE（Qwen3.6 初始化）
                     MLE-Bench Lite 奖牌率 37.9% → 72.7%
```

### 3.2 三个可迁移的机制性洞见

- **洞见一：反馈边界即信用边界**。信用分配的粒度不该人为设定（步/轨迹），而该锚定在"环境给出可验证反馈"的自然边界上——MLE 里是实验结果，别的地方可能是编译通过、测试通过、回测完成
- **洞见二：退化尾巴比失败更有毒**。SFT 数据里"达到峰值后继续瞎改导致退化"的片段会教模型坏习惯；锚定首个最优提交、截断后缀的选段法是通用的示范数据清洗术
- **洞见三：朴素 RL 会输给 SFT**（GRPO 56.1 / PPO 60.6 < SFT 62.1）。轨迹级终端奖励在长程任务上信号过稀，先 SFT 到 62 再用窗口 RL 拉到 72.7——**SFT 与 RL 的正确关系是接力而非替代**

### 3.3 WIRL 与 GRPO/PPO 对比要点

- 奖励来源：环境执行结果（可验证）vs 组内相对 vs critic/终端
- 更新时机：窗口完成即更新（轨迹未结束）vs 轨迹结束 vs 轨迹结束
- 归一化：无（直接用 R_m 做权重）vs 组归一化 vs GAE
- 异步性：原生异步+策略修正 vs 通常同步
- 结果：72.7 vs 56.1/60.6

## 四、趋势判断

### 趋势1：长程优化决策正在从"编排层能力"迁移为"模型权重能力"

依据：论文 Figure 1 明确以此为主线；Arbor/Argus/ML-Agent/Frontis-MA1 的演进序列都指向把 workflow 逻辑内化进策略。外部编排（我们的 cron/orchestrator）不会被消灭，但"模型自己决定下一步做什么实验"的能力会成为 agentic 模型的标配卖点。

### 趋势2：训练环境工厂化——造环境比造数据更值钱

依据：Kaggle-MLE Factory 用四个 agent + validator 流水线把非结构化历史资产变成可执行训练环境，论文贡献列表里它与 WIRL 并列。与 Librarian Agents 的"builder 学构建工作空间"、OpenForgeRL 的"K8s 编排器产轨迹"同构：**下一个稀缺品是可验证交互环境的生产线**。

### 趋势3：窗口化/状态化信用分配会成为长程 Agent RL 的默认解

依据：WIRL（执行窗口）与 KnowGPO（知识状态分组）在同一周出现，都绕开"逐步 verifier 漂移"与"轨迹终端信号稀疏"两个极端；两者都报告对 GRPO 的显著优势（72.7 vs 56.1；+3.8~4.2 分）。中间粒度 + 环境锚定的信用分配是收敛方向。

### 趋势4：35B 专训模型在垂直域追平前沿通用大模型

依据：MLExpert 72.7 = GLM-5.3 = Kimi-K3 < GPT-5.6 Sol 77.3；NatureBench 上 50% Surpass-SOTA 平 GLM-5.3。与用户既有的"三模型架构=三个专一模型真机切换"偏好完全一致——专而小、可组合，正在成为可与"大而全"对抗的工程路线。

## 五、关联分析

### 5.1 与 Librarian Agents（2610.22273，昨日精读）的关联

两者同周出现、结构同构：都训练"构建/组织"能力而非"应答"能力（builder 组织工作空间 ↔ MLExpert 组织实验树）；都用 MDP 形式化 + RL 直接优化下游效用；都面对"基础模型会消费结构但不会为下游构建结构"的空缺。差异在反馈信号：Librarian 用下游答题准确率（稀疏），MLExpert 用执行结果窗口（中等粒度）——**WIRL 式窗口切分可以直接嫁接到 Librarian 的构建过程奖励上**。

### 5.2 与 OpenForgeRL（2607.21557）的关联

OpenForgeRL 证明"harness-native 训练"可行（Proxy 拦截 + 轨迹重建 + 简单 harness 更易学）；MLExpert 把它推到极限：整个实验树状态机都在 harness 里，模型只做决策。两者共同支持 Hermes 的借鉴方向：**先记录完整轨迹（工具调用+反馈），再考虑离线切窗训练**。

### 5.3 与 KnowGPO（2610.22331，本次候选）的关联

同为"中间粒度信用分配"方案：KnowGPO 用知识状态（内在进度）分组，WIRL 用执行窗口（外部反馈）切分。对无原子知识结构任务的领域（如 MLE、机器人），WIRL 路线更可行——执行结果是现成的，不需要额外构造知识条件体系。

### 5.4 与 DUCK RL 训练体系的关联

- WIRL 的"窗口奖励含局部趋势项 T_m（±0.2）"与鸭子训练里"位移/z 高度的窗口趋势判定"同思想：**绝对阈值 + 相对趋势复合计分**比单一指标抗 reward hacking
- "SFT 先行、RL 接力"的 stage 消融（37.9→47.0→62.1→72.7）与 microduck 训练线"课程缓爬坡起步低"的用户偏好一致
- invalidate_node（作废虚高候选）= 对抗验证集过拟合的显式工具——鸭子侧对应"z 是唯一诚实指标"的防作弊纪律

### 5.5 与 Hermes 自进化系统的关联

MLExpert 就是"训练一个会做 ML 工程的超级 jbot"的学术版：Kaggle Factory ≈ 我们的 task factory/benchmark 构造（notes-eval-gate golden set），Interaction Harness ≈ Hermes gateway 工具层 + 轨迹记录，WIRL ≈ session-evolution-scan 的离线升级版（从"事后总结规则"到"窗口奖励直接更新"）。GLM-5.3 出现在对照表里且被追平——我们自己的引擎基座已具备被此范式改造的量级。

## 七、行动启示

- **借鉴点1（P0）：退化尾巴截断术 → 蒸馏/SFT 数据清洗**。离线策略蒸馏与 skill 沉淀时，按"首个最优结果"锚定截断轨迹后缀，丢弃峰值后退化段。现有 offline-policy-distillation skill 只做"多教师合并"，未做时序选段——可直接补一节"outcome-anchored trimming"
- **借鉴点2（P0）：执行窗口监控 → 长训盯盘判定**。把"两次可验证反馈之间的行为"当窗口评估（两次 eval 之间的训练行为、两次 cron 运行之间的系统行为），窗口内用"阈值+局部趋势"复合计分——比全程平均更早发现退化（与 6 点趋势采样纪律互补）
- **借鉴点3（P1）：异步部分轨迹更新 → 训练决策前移**。不等"整条轨迹/整个训练完"才评估更新策略，采到可信中间反馈即调整（我们的"每 250 iter 抽查"已是雏形，可进一步窗口化定义）
- **借鉴点4（P1）：任务工厂模式 → 自进化训练资产**。用多 agent 流水线把历史资产（旧竞赛/旧会话/旧项目）转成可执行可验证的任务包，喂给后续训练/评估——golden set 生产的规模化版本
- **借鉴点5（P2）：三组 log 概率策略修正 → 跨版本对比评估**。凡"生成策略≠评估策略"的场景（模型切换后的笔记质量对比），需显式重要性校正而非直接对比

## 八、拓展应用推荐

- **场景A（Hermes 长程任务监控）**：以"可验证检查点"（部署成功/测试通过/线上200）为窗口边界，窗口内行为计分，替代单纯超时守卫
- **场景B（量化研究流水线）**：因子实验循环（假设→回测→分析）即 MLE 循环，WIRL 窗口奖励可映射为"每次回测结果之间的研究决策质量"评估
- **场景C（机器人训练自动化）**：AutoDL 发射-巡检-验收循环中，把每轮 eval（12ep 门禁）作为执行窗口边界，窗口趋势决定继续/终止——正是现有"连续3档横盘判死"的形式化包装
- **场景D（Skill 进化系统）**：EvoSOP 的 Evaluate 模块引入"锚定峰值截断"——skill 使用轨迹达到最佳效果后的冗余动作段不入沉淀
- **场景E（文档/知识工程）**：RAG 调优（分块策略×检索参数×rerank）本质是小型 MLE，可用 Factory 模式把调优历史固化为可重放任务包

## 九、指南分析

- **方法论价值1（奖励设计）**：当组内归一化不可用或有害时，"可验证绝对奖励直接做优化权重 + 分层枚举奖惩值 + 微小趋势修正项"是可抄的奖励模板——数值档位（−1.0/−0.6/−0.4+T/1.0+T/2.0+T）本身值得复刻
- **方法论价值2（数据清洗判据）**："首个最优锚点 + 退化幅度阈值 + 完整交互边界截断"三要素构成示范数据选择的完整判据，适用于一切"从自身探索轨迹学习"的场景（self-improvement、经验沉淀）
- **方法论价值3（反例警示）**：Table 4 是罕见的"RL 输给 SFT"的诚实报告——做长程 RL 前必须先问：终端信号密度够不够？不够则先改信用分配粒度，不是先调超参
- **方法论价值4（工程结构）**：Factory（任务）/Harness（环境）/Post-training（方法）三层解耦，每层可独立替换——训练基础设施的正确切分方式，直接可借鉴到自进化系统的模块边界设计
