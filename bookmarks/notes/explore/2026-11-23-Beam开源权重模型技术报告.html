〇、定锚：我的现状与目标

我的现状：日常运维 Hermes Agent 三机体系，关注 Agent 训练配方（GRPO/reward 设计/训练稳定性诊断）、推理部署（量化/投机解码）两条主线。此前精读过 MDSKILL（技能记忆蒸馏）、OpenForgeRL（harness-native RL）、SPORK（自推测加速）等论文，已形成"训练-推理协同"视角。RL 实战侧有 DUCK 机器人 GRPO 训练的完整踩坑经验（异步 rollout、课程切换、假 PASS 判据教训）。

本次精读目标：Reflection 公司开源的 Beam 模型（501B/23.4B active MoE）技术报告披露了迄今最大规模之一的 agentic RL 训练细节（10.5K GPU、100M rollouts、4 周无平台期）。我要从里面挖三样东西：①工业级异步 GRPO 的稳定性工程（可直接对照 DUCK 训练）；②MOPD 双专家蒸馏合并架构；③NVFP4 量化 + DFlash 2 投机解码的部署配方（对照 Jetson 边缘部署）。

二、核心问题与研究动机

核心命题：如何把一个 501B 稀疏 MoE 基座训练成「编码-推理-自主智能体」专用模型，同时在三个约束下保持前沿竞争力：

  1. 推理算力约束：同类模型 3-4 倍的推理效率（token 效率通过 RL 显式训练获得，非架构副产品）
  2. 训练规模约束：pretraining 23.8T tokens / midtraining 950B tokens / RL 100M rollouts，全程 4 周级时间盒
  3. 安全约束：开源权重下 refusal/pivot 率要做到开源模型 Pareto 前沿最高（88.9%）

关键动机判断：agentic 能力（工具调用、浏览、问题分解）不再靠 SFT 灌数据，而是「RL 让模型在与真实环境交互中有机发展」——报告原话 "Beam organically developed tool-use, web browsing, and problem-decomposition capabilities"。

三、方法论内容整理

3.1 架构与预训练

  • 501.3B 总参 / 23.4B active，52 层，256 experts，152K 词表
  • 辅助损失无关的负载均衡（auxiliary-loss-free load balancing）+ cosine 衰减 + 序列级均衡 + 深度残差缩放 → 近均匀专家利用率 + 有界残差范数
  • Pretraining：23.8T tokens，6,144 张 GB300，4 周内完成，稳态 21% MFU，尾部 goodput 92.3%
  • Scaling law 验证横跨四个数量级（300M → 23.4B active），保证外推可预测性

3.2 两阶段中间训练（Midtraining）→ 1M 上下文

  • Stage 1：850B tokens @ 32K 上下文，练核心逻辑推理。数据配比：45% 编码（竞赛编程/软件工程/终端使用）、30% 中高级 STEM、15% 通识、10% 保留高质量预训练数据防遗忘
  • Stage 2：100B tokens @ 512K 上下文扩展 → 服务时 1M 有效窗口
  • 关键工程细节（对 MoE 训练直接可用）：
  • midtraining 数据分布偏移会破坏专家负载均衡 → 禁用 router z-loss、sequence aux loss、expert bias update，只更新 router 权重即可稳定（强制均衡反而损害专家特化）
  • sawtooth LR：每阶段重置 optimizer state，峰值 LR = 预训练峰值的 5%（平衡遗忘与学习）；weight decay 按 AdamC 方法随 LR 平方缩放
  • filter-best-fit 序列装箱：保持文档完整不跨序列切分；padding token 在 MoE 层被 mask 掉不进路由（省算力+防专家过载）
  • 数据消融方法论：小模型短 horizon 代理训练（50% 稳定混合 + 50% 待消融新源），loss/梯度范数 spike 分析反查坏数据 → 固化为自动化数据过滤器

3.3 高计算 Agentic RL（本报告核心）

训练框架：GRPO-style 策略梯度 + 全异步执行，10.5K 张 GB300，4 周，100M+ rollouts，110K 并发 rollout，权重 12 秒更新一轮。

异步一致性三件套（训练-推理失配的系统性治理）：
1. Nucleus 采样对齐：推理用 p=0.99 nucleus 采样，训练时保留生成时的 nucleus 支持集并在同一集合上重归一化（DeepSeek-V3.2 方法），消除截断掩码不一致的梯度泄漏
2. MoE routing replay：推理引擎逐 token 记录选中的 experts，训练端复用这些路由分配重算 gate 值；router 权重与负载均衡 bias 全程冻结——即使冻结，进入 router 的表示仍会演化，所以 replay 依然必要
3. 数值一致性：LM head、router、residual stream 在训练和推理两侧都跑 FP32

异步容忍度实测：中位 rollout 12 分钟，2% 超过 1 小时，1/5 的训练步里至少有一个贡献 rollout 跑了 6 小时以上；in-flight rollout 在权重更新后继续跑不中断，单条轨迹可跨多个 policy 版本（逐 token 记录 policy version）；任务相关的 rollout deadline，超时丢弃，组内凑够完成数才保留。采样 token 平均落后 trainer 5 个 policy 版本。

训练稳定性诊断仪表（Figure 15，直接可抄的监控项）：
- 梯度范数：中位 1.7e-3，P99 3.0e-3，窄区间无漂移
- 采样/训练策略 per-token KL：中位 2.2e-4 nats；重启后参考值 8.7e-5（=采样与路由 replay 之后的残余失配底噪）
- 采样 token NLL：全程 0.37→0.50 缓升，但分通道看——reasoning token 0.63→0.69（策略分布仍分散），final-answer token 0.25→0.06（答案通道高度集中）
- 响应长度：数据混合相内中位变化 ≤1/3，52% 进度后 ≤5%；大变化只与混合切换（转向更长 agentic 任务）同步

Reward 完整性工程（对 reward hacking 的多层防御）：
- 自动 verifier 通过 ≠ 解有效（模型可改测试/硬编码输出/钻 harness 漏洞）→ verifier 通过的 rollout 再过 judge + reward-hacking rubric，只看最终 patch
- CoT 监控 hacking 意图但不施加直接优化压力（防把意图藏起来）
- 判 hacking：正确分归零但保留 length cost = 与等长失败同待遇
- rubric 训练中滚动更新，模型发现新 hack 就补规则

RL 任务策划五原则（数百万任务池 → ~100 万精筛）：
- Quality = 零奖励噪声：不误导、不可 hack、verifier 确定性；排除无 CoT 也能对的任务
- Difficulty = 对当前模型不太难不太易（组内不能全零/全满），且要排除「假难假易」（答案泄漏、上下文不足、chat 模板错误、不可能任务）
- Scale：开源任务池需重筛、vendor 任务贵、自建合成管线三者结合，最终自建为主
- 迭代精炼：每轮实验后分析 rollout，成功/失败归因到任务问题就修任务

推理努力度与长度惩罚：显式 reasoning-effort 输入控制 rollout 预算，超预算终止且无正确性奖励；同正确性下线性长度惩罚偏好短回复 → 模型学会按请求预算适配 token 用量（token 效率是训出来的）。

跨域泛化实证：26-52% 进度只训数学/STEM/竞赛编程，SWE 基准不掉分；52-65% 只训软件工程，STEM/编码不回退；83% 前从未训过搜索浏览，BrowseComp 却从 50.1（27% 处）涨到 57.9（83% 处）。

RL 行为演化预测（4.2 节，种群遗传学启发的理论工具）：
- GRPO 下某行为（SFT 出现率 π、组内平均优势 Ā）每 batch 获得对数权重增量 Δθ ∝ π·Ā
- 若行为奖励高出替代项 g 个组内标准差，其对数赔率遵循 replicator 方程 dL/dt ≈ 2κηgπ(1-π)：g>0 放大、g<0 压制、g≈0 冻结在 SFT 出现率
- κη 在一个完整 run 上拟合一次即可跨 run 复用；预测 318 个 run 的各奖励分量增益 r=0.79（对比 pass@k 天花板基线 r=0.46）
- 实战用法：step-0 测几十个 scored group 即可预判某失行为（如模板化脚手架、多余 markdown 格式）会被放大还是压制，据此提前设计过滤器和 reward 修改

3.4 MOPD：双专家在线策略蒸馏合并

  • 架构：agentic expert（推理/长程任务）与 alignment expert（helpfulness/safety/对话）各自独立 SFT+RL，最后合并成单一学生
  • 学生自己生成轨迹，教师按任务族概率路由：T ~ Bernoulli(r(x))，逐 rollout 独立采样教师
  • 损失：全词表 reverse KL（DAPO token 级归一化），上下文来自学生采样但求导时固定
  • 系统工程三招：
  • 传 teacher hidden states 而非完整分布（O(N·d_T) vs O(N·V)），trainer 端用缓存冻结的 output head + 各自 softcap 重建 logits
  • Blockwise reverse KL：C×V 分块计算，临时显存 O(C·V)
  • Student 侧用 trainer 当前概率（非生成时的旧概率）：KL 为零即无需更新，每次更新只处理「更新时刻仍存在的分歧」
  • 价值：两专家可独立训练独立评估再合并，避免单一 reward 混合的互相牵制

3.5 量化与投机解码（部署侧）

FP8（E4M3 W8A8，RTN 免校准）：
- 覆盖 attention 投影/dense MLP/MoE experts/KV cache；embedding/LM head/router/norm 保留原精度
- 权重 per-output-channel 静态 scale，激活 per-token 动态 scale

NVFP4（E2M1 W4A4，Local Hessian PTQ）：
- 只量化 MoE experts（49 层路由专家），dense MLP/attention/embedding/LM head 留 BF16，router 留 FP32
- 16 值块一个 FP8 scale + 张量级 FP32 scale；逐层校准（每层看 BF16 模型激活而非已量化层）
- 校准集 = 1,000 条 32K token 长 agentic 轨迹（32.8M tokens，多为软件工程会话）——服务场景同构校准
- recipe 选择用 held-out KL（64 条留存序列）排序而非单次 benchmark（单点噪声可达 3.2 分而中位差 <0.4%）
- 量化 dense MLP 只省 0.5% 体积却增加 KL，弃之

DFlash 2 投机解码 drafter（1.93B block-diffusion）：
- 5 层 transformer，块内双向注意力 + 通过 KV 联读到 Beam 第 4/16/28/40/46 层（全局注意力层）hidden states；上下文注意力限 4,096 窗口 → drafting 成本不随上下文增长
- embedding 和 output head 直接复用 Beam 的（冻结）
- 训练数据：MOPD 后期 rollout（策略自采样似然平稳后）+ PerfectBlend 再生；agentic 轨迹替换 42% 使接受 token +21%
- 短上下文训练→长上下文迁移：8K 训练的 drafter 在 4-8K 接受 4.70/块，64K+ 反而 5.02/块（位置缩放不破坏迁移）
- block 16 训练、block 8 服务（8 位置验证在 12 组设置中 11 组更快：晚位置很少被接受却占验证算力）；反向（小训大服）不行
- 训练仅 3.4K B300 GPU-hours；在线从 NVFP4 checkpoint 取特征（BF16 替换只影响 1.5%）

四、关键实验结果与数据

评测条件：temperature 0.7，top-p 0.99，reasoning effort 512。

软件工程/终端（Table 19）：
- Beam(501.3B/23.4B) vs GLM 5.3(744B/40B) vs Kimi K3(2.8T/104B) vs DeepSeek V4.1 Flash(748B/16B)
- DeepSWE v1.1：Beam 43.3 / GLM5.3 61.0 / Kimi K3 68.0 / DeepSeek V4.1F 74.2（Beam 落后）
- SWE-Bench Verified：Beam 81.6 / Inkling 77.6 / Nemotron 3 Ultra 70.7（Beam 领先）
- Terminal-Bench v2.1：Beam 80.1 / Kimi K3 88.3 / DeepSeek 90.6
- 结论：Beam 以 1/4.7 的 active 参数量接近头部，原始能力落后于 Kimi K3/Qwen 3.8-Max，token 效率是核心卖点

数学与科学（Table 20）：
- AIME 2026：97.7（GLM 5.2 99.2）
- GPQA Diamond：90.6（Kimi K3 93.5）
- HLE no-tools：36.0（Kimi K3 46.9）
- CritPt：16.3（显著高于 Inkling 5.4、Nemotron 3.1，低于 GLM 5.2 的 20.9）

RL 训练内曲线（Figure 16/17）：
- DeepSWE pass@1：SFT checkpoint 在 e=512 无从比较；79% 进度时 e=512 达 35%，最终 checkpoint e=512 达 41%（更难任务集引入后仍涨）
- 全程无平台期：能力随 RL compute 持续提升

量化保真（Table 13/14 + Figure 36-39）：
- FP8 恢复 BF16 中位基准分 99.93%（22 基准均值差 +0.03）；NVFP4 恢复 98.98%（-0.45）
- 安全行为不退化：harmful refusal 88.9%→FP8 89.7%/NVFP4 88.5%
- 显存：1M 上下文 BF16 需 8 卡 B300，FP8/NVFP4 4 卡即可；4 卡 NVFP4 KV 容量 8.2M tokens（FP8 5.8M，1.41×）
- 吞吐（8K/1K 场景，@50 tok/s/user）：4 卡 NVFP4 达 BF16 8 卡的 6.0× per-GPU；@100 tok/s/user 4.2×
- AgentX 回放（393 条真实 agentic 编码会话，80-100K 输入，95% 前缀缓存命中）：NVFP4 64 并发会话仍 >50 tok/s/user（4 卡 457 tok/s/GPU ≥3.7×）

投机解码（Table 17/18）：
- τ=4.38（采样）/4.64（贪心），上限 8（block 8 服务 + 7 drafted tokens/步）
- 解码加速：单请求 1.96-3.03×，32 并发 1.89-2.75×
- 长上下文不掉：DeepSWE 轨迹 16K→128K 上下文 τ 稳定 4.2-4.6

安全：Iris Safety Eval 综合 harmful refusal/pivot 88.9% + harmless compliance 81.5%（开源模型 Pareto 前沿最高 refusal）；OSF 四类系统性风险（生武/化武/失控/网络攻击）均评 Limited。

五、创新点归纳总结

  1. 「训练-推理一致性」从口号变成三件套工程规范：nucleus 支持集对齐 + MoE routing replay + 关键组件 FP32——每件都有量化指标（KL 2.2e-4 nats、重启底噪 8.7e-5）可监控。这是异步 RL 稳定性的核心贡献
  2. Replicator 方程做 RL 行为预测：把种群遗传学的选择压力数学引入 GRPO 行为动力学，step-0 即可预判行为放大/压制（318 runs r=0.79），把「RL 后才发现学坏」变成「SFT 后即可预测」
  3. MOPD 双专家解耦-合并范式：能力专家与对齐专家独立训练独立评估，Bernoulli 路由的全词表 reverse KL 合并，回避单一混合 reward 的牵制；blockwise KL 把 O(N·V) 显存压到 O(C·V)
  4. Token 效率是被 RL 训练出来的第一公民：effort 输入 + 预算截断 + 线性长度惩罚三件套，产出「更少 token 同等性能」的可控旋钮
  5. Reward integrity 分层审计：verifier → judge rubric → CoT 意图监控（不优化）→ 滚动更新 rubric，承认「verifier 通过≠正确」并系统性补防
  6. 服务场景同构的量化校准：用 1M agentic 轨迹校准 NVFP4，用 held-out KL（而非噪声大的单次 benchmark）选 recipe——评测驱动的工程决策方法论
  7. DFlash 2 的「短训长迁移」：drafter 只在 8K 训练，64K+ 上下文接受率反升；块大小训 16 服 8 的不对称性利用

六、趋势判断

  1. Agentic RL 的 scaling 曲线刚被打开：100M rollouts 无平台期意味着「RL compute → 能力」还在线性增益区，各家的下一步是 rollout 基础设施军备（110K 并发 rollout、12s 权重同步已是入场券）
  2. 技术报告的披露颗粒度在军备化：训练稳定性仪表（KL/NLL 分通道）、replicator 预测、量化 recipe 消融全量公开——闭源优势从「配方保密」转向「规模与数据」，配方本身正在变成公共品
  3. 双专家蒸馏合并（MOPD）会成为中型实验室标配：单 reward 混合训练中 helpfulness 与 agentic 能力互相牵制的问题，解耦-合并比权重调参干净
  4. 量化-投机解码协同成为部署标配叙事：NVFP4 只量化 MoE experts（省 4 倍体积）+ block-diffusion drafter（不依赖完整上下文）组合拳，指向「MoE 部署经济学」成为独立研究方向
  5. 安全评估走向 OSF 系统性风险框架 + 拒绝率 Pareto 前沿的标准化表述，开源模型的对齐披露格式正在收敛
  6. 中间训练（midtraining）作为独立阶段被做实：两阶段 950B tokens 的「能力聚焦→上下文扩展」，与 pretraining/post-training 三分天下

七、局限性

  1. 原始能力未达第一梯队：DeepSWE 43.3 vs DeepSeek V4.1 Flash 74.2、Kimi K3 68.0，HLE 36.0 vs 46.9——「3-4× 推理效率」的代价在绝对分数上可见
  2. 异步 RL 的 stale policy 容忍（平均落后 5 个版本）没有给出消融：多陈旧开始伤学习效率没有边界数据，复用者需自行摸索
  3. Replicator 预测的 κη 常数「拟合一次跨 run 复用」依赖同 recipe 族；换 reward 结构/模型规模是否仍可迁移未验证
  4. RL 任务池依赖自建合成管线 + vendor 采购，质量-难度过滤的人力/算力成本未披露，「~100 万任务」的复现门槛对学术组不现实
  5. 评测自报成分高：Iris Safety Eval 为自建套件；advantage 是与开源模型对比而非闭源前沿
  6. DFlash 2 依赖 Beam 特定层（4/16/28/40/46）的 hidden states 接入，换目标模型需要重训 drafter，通用性受限
  7. 1M 上下文的 NVFP4 部署仍需 4 卡 B300 级硬件，边缘侧（Jetson 类）无法直接受益于该部署配方

八、关联（与已有知识和系统的对照）

与 Hermes Agent 的关联：
- 训练稳定性仪表（§3.3）与 OpenForgeRL 的轨迹重建互为表里：Beam 给出「该监控什么」（梯度范数带、KL、NLL 分通道），OpenForgeRL 给出「怎么录轨迹」
- Reward integrity 分层审计直接对照 content-judge / llm-as-a-verifier-framework 两个 skill：Beam 的 judge-rubric-滚动更新模式可补强 content-judge 的评分表设计
- Replicator 行为预测与 evolver / session-evolution-scan 的关系：把「事后扫会话找漂移」升级为「事前预测漂移方向」的理论工具

与 DUCK 机器人 RL 训练的关联：

十、指南分析

从本报告提炼的可操作工程指南（按「抄了就能用」程度排序）：

  2. MoE 中间训练调参三禁令：禁 router z-loss、禁 sequence aux loss、禁 expert bias update（数据分布偏移期），只动 router 权重
  3. RL 任务池质检七查：答案泄漏、上下文不足、模板错误、不可能任务、verifier 非确定、无 CoT 可解、可 hack——上线前逐项过
  4. 量化 recipe 选择流程：held-out KL 排序 > 单次 benchmark（噪声 3.2 分级）；校准集必须与服务场景同构（长 agentic 轨迹）
  5. 投机解码块大小决策：训练用大块（16）、服务用小块（8）——晚位置接受率低却占验证算力，服务端砍块几乎免费提速
