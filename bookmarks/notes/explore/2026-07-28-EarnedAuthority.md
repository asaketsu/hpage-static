> **论文**: Are You Still the Agent I Authorized? Earned Authority under a Fixed Ceiling for Evolving Agents

> **作者**: Zhaoxi Zhang, Xiaomei Zhang
> **领域**: cs.AI, cs.CR（人工智能 + 密码学与安全）
> **精读日期**: 2026-07-28

---

## 一、核心问题与研究动机

### 问题定义

长期运行的 AI Agent 在部署后会持续进化——积累经验、获取新技能和工具、修订工作流、委派任务、跨越任务阶段。这种进化带来了一个独特的**授权连续性问题（authorization continuity）**：

> 当 Agent 已经不再是用户最初授权的那个 Agent 时，原来的授权何时仍然有效？

### 为什么这是一个新问题

传统的静态授权模型无法解决以下三方矛盾：

- **宽泛的会话级授权**：保证任务完成，但违背最小权限原则，悄悄将多余权限转移给后续版本的 Agent
- **狭窄的不可变授权**：保持权限边界，但最终阻止有价值的进化
- **逐动作确认**：最强连续性，但提示成本最大

### 关键洞察

论文提出了一个尖锐的问题：**Agent 自身产生的证据（如测试通过、低错误率）能否扩展安全边界？** 答案是否定的——

> Agent 产出的证据可以在天花板**以下**分配权限，但永远**不能抬高**天花板本身。

## 二、方法论：状态绑定授权模型

### 三维进化框架

论文将 Agent 的进化表面压缩为三个正交维度：

1. **Competence（能力）**：Agent 能推断或规划什么
2. **Affordance（可供性）**：harness 使哪些动作可表达（如文件工具、部署工具）
3. **Authority（权限）**：周围系统实际允许 Agent 以用户名义产生哪些效果

关键：只有 Authority 决定哪些受保护效果在运行时被允许。Competence 的增加本身不证明安全边界应扩大。

### 状态绑定模型核心要素

一个授权（Grant G）在授权时固定三样东西：

- **效果天花板 B（Effect Ceiling）**：一组受保护效果的上界，**不可变**，只有新用户授权才能替换
- **初始活跃权限 P₀**：B 的子集
- **过渡信封（Transition Envelope）**：列出该授权可以存活哪些变异类别

运行时规则：

```
收缩永远允许
扩展或不可比变化需要授权的证据条件
监控器始终施加一个钳制：P_t = P_t^prop ∩ B
```

### 两层独立决策

论文的精妙之处在于将连续性判断和效果约束**分离**为两个独立决策：

- **过渡信封**判断：授权是否存活？（Alive_G(t)）
- **效果天花板**判断：活跃权限多大？（P_t ⊆ B）

即使效果在天花板内，如果变异不兼容过渡信封，授权仍被暂停。

### Theorem 1（非放大定理，紧凑形式）

**前提**：
1. 受保护效果完全中介（complete mediation）
2. 方程 1 在每次准入时成立（Eff(S_t, a_t) ⊆ Req(a_t)）
3. 每个活跃或委派权限包含在用户发布的天花板内
4. 监控器不受 Agent 控制

**结论**：执行中的每个受保护效果都属于至少一个用户发布的天花板。

> 这是一个**边界结果**——不声称当前主体可接受、动作服务于用户意图、或信息不会在分别允许的效果间流动。

## 三、六类授权相关变异（Table I）

论文将影响授权的变异分为六类，**不是分区**（一个变异可同时属于多类），而是**敏感性清单**：

1. **控制状态（Control state）**
   - 代表性变化：模型/供应商切换、指令/技能/hook/harness/持久记忆更新
   - 为何旧授权失效：选择动作、解释意图或处理故障的策略已改变
   - 典型响应：重新测量主体；仅在批准的过渡类内继续

2. **能力（Capability）**
   - 代表性变化：新工具/服务、网络启用、更宽的文件系统根、新凭证、工具实现变更
   - 为何旧授权失效：即使任务名不变，所需或可达的受保护效果可能已变
   - 典型响应：重计算活跃权限及其效果边界；收缩或请求范围授权

3. **委派（Delegation）**
   - 代表性变化：新子 Agent/远程规划器、子模型或 prompt 变更、递归委派
   - 为何旧授权失效：新主体可能行使用户从未评估的环境权限
   - 典型响应：削弱子权限并绑定到委派子任务

4. **任务/阶段（Task or phase）**
   - 代表性变化：检查→编辑、测试→提交、本地→推送/部署、草稿→发送
   - 为何旧授权失效：下一个动作的后果和不可逆性已改变
   - 典型响应：使用阶段绑定的活跃权限和显式过渡门禁

5. **信任上下文（Trust context）**
   - 代表性变化：仓库/网页/邮件/工具输出/记忆变为持久控制输入
   - 为何旧授权失效：行为可能在没有可见模型或工具变化的情况下被重定向
   - 典型响应：追踪来源；限制持久化；在高影响效果前审查

6. **执行机制（Enforcement）**
   - 代表性变化：审批策略、沙箱、验证器、日志、提交门禁、回滚机制变更
   - 为何旧授权失效：使原始授权安全的机制已弱化或被 Agent 控制
   - 典型响应：失败关闭（fail closed），要求外部更新路径

## 四、与现有授权策略的对比（Table II）

论文将现有策略视为"连续性规则 + 权限边界"的不同选择：

- **会话级完全访问**：每个过渡都被接受，天花板无限制 → 非放大定理变为空洞
- **逐动作确认**：每个受保护动作需要新决策 → 最强连续性，但提示成本最大
- **精确状态哈希绑定**：任何字节级变化都使授权失效 → 检测所有变化但拒绝大量良性变化
- **工具清单绑定**：仅能力变化触发失效 → 遗漏阶段、控制状态、委派、执行机制变化
- **自治阶梯（Earned-autonomy ladder）**：性能证据可提升终端边界 → 除非阶梯在天花板下终止，否则无固定边界
- **状态绑定授权（本文）**：过渡信封任务特定，B 不可变 → 连续性和活跃权限可独立变化

## 五、创新点分析

1. **时间维度的授权问题**：首次将"授权连续性"形式化——不是问"动作是否被允许"，而是问"旧授权对当前系统是否仍然有效"。这是 TOCTOU（Time-of-Check/Time-of-Use）的时序亲属，但变化对象是授权设定而非受保护资源。

2. **天花板 vs 活跃权限的分离**：核心创新是 P_t = P_t^prop ∩ B 的钳制规则——Agent 的自产证据只能在天花板以下分配权限，不能抬高天花板。这使"绩效证据扩展边界"变成了一种**可靠性决策**而非**安全边界决策**。

3. **六类变异的全面分类**：超越了单纯的能力清单变更检测（tool-manifest binding），纳入了控制状态、任务阶段、信任上下文、委派和执行机制——这些维度在现有安全框架中被忽略。

4. **阶段变化无需任何组件变化即可改变权限需求**：从"编辑测试"到"推送分支"引入了远程更新效果，而模型、harness、能力清单保持位级一致。这一洞察颠覆了"组件不变=权限不变"的直觉。

5. **形式化证明而非实证声称**：Theorem 1 提供了数学证明（在四个前提下的非放大保证），而非仅凭实验。论文诚实声明这是形式化而非部署系统频率的实证声称。

## 六、局限性与未来方向

### 论文自述局限

1. **天花板 B 的选择仍是策略和可用性问题**：高天花板弱化结果，低天花板中断有用工作
2. **方程 1 需要具体执行机制**：系统调用中介、工具代理、类型效果分析或能力流追踪。仅标签交付不足
3. **跨代撤销和群体级权限**尚未解决

### 评估路径

论文承认当前工作是形式化而非实证声称，提出未来评估指标：
- 授权持续率（grant persistence rate）
- 变异后未授权效果率（post-mutation unauthorized-effect rate）
- 错误失效率（false invalidation rate）
- 交互成本（interaction cost）

### 批评性分析

- **缺乏实证验证**：六类变异的频率和操作成本未被测量，这是论文最大的弱点
- **B 的设定依赖人工策略**：没有自动化方法确定合理的天花板
- **监控器的抽象视图 Ŝ_t 可能欠近似**：论文承认标签交付不足以保证 Eq.1
- **语义检查可能误拒**：goal compatibility 检查需要保守的语义预言机，可能导致假阴性

## 七、借鉴点（关联 Hermes Agent / Jetson / 量化交易）

### P0 — 核心安全架构改进

**1. Hermes 会话级权限需引入"过渡信封"机制**

- **现状**：Hermes 会话内的权限通常在会话开始时设定，Agent 进化（skill 加载、工具添加、委派子 Agent）后旧权限默认继承
- **论文建议**：在 grant 时固定效果天花板 B + 过渡信封，变异超出信封时暂停授权
- **可落地路径**：在 Hermes Gateway 层实现授权变异监控器，检测六类变异并触发重新授权

**2. Skill 自动创建/修改的信任上下文风险**

- **现状**：auto-skill 和 evolver 会将工具输出、对话经验持久化为 skill/memory，这属于论文定义的"信任上下文变异"
- **论文洞察**：内容持久化到记忆/技能/未来计划会改变重用 grant 的控制策略——这不是"字节是否变化"，而是"变化后的组件能否在当前 grant 下影响受保护动作"
- **可落地路径**：skill 写入时必须标注 provenance，高风险变异（网络获取内容→持久化 skill）触发显式门禁

**3. delegate_task 的权限衰减问题**

- **现状**：Hermes delegate_task 创建子 Agent 时，子 Agent 可能继承父 Agent 的完整权限
- **论文明确指出**：创建子 Agent 的权限不等于子 Agent 继承父 Agent 完整天花板的权限。子权限必须被削弱且可归因于父 grant
- **可落地路径**：delegate_task 时自动应用权限衰减——子 Agent 的 B_child ⊂ B_parent

### P1 — 可移植改进

**4. 任务阶段变化的显式门禁**

- **现状**：Hermes 从"读取/分析"过渡到"部署/删除"时没有显式权限边界检查
- **论文关键洞察**：阶段变化可以在不改变任何组件的情况下改变权限需求
- **可落地路径**：在 Hermes 系统提示的权限三层模型（允许/禁止/确认）中增加阶段感知——检测到"编辑→推送"或"测试→部署"过渡时自动升级到"确认"层

**5. 执行机制变异的 fail-closed 路径**

- **现状**：Hermes 的审批策略、沙箱配置变更时没有 fail-closed 机制
- **论文要求**：如果普通任务权限可以削弱监控器、审批策略或审计路径，Theorem 1 的前提直接失败
- **可落地路径**：执行机制变更（如修改 ~/.hermes/config.yaml 中的权限配置）必须走外部高权限路径，不能通过 Agent 自身修改

### P2 — 理论指导

**6. Agent 自产证据不可抬高安全边界**

- **现状**：Hermes 的 skill-stress-test 用 subagent 验证 skill 有效性，结果用于改进 skill
- **论文洞察**：Agent 能自己产生的证据（测试通过、低错误率）只能做可靠性决策，不能做安全边界决策。安全声称需要至少一个会话自身无法实现的前提（外部审计、独立计数签名、Agent 无法自行运行的评估）
- **可落地路径**：区分"绩效证据"（可在 B 以下分配权限）和"安全证据"（必须有外部不可伪造来源）

**7. 量化交易 Agent 的阶段权限控制**

- **现状**：量化交易系统从"回测→模拟→实盘"过渡时权限边界模糊
- **论文适用**：阶段变化（测试→提交/部署）是论文强调的最清晰的权限变更案例
- **可落地路径**：量化交易工作流显式定义阶段边界——回测阶段只读历史数据，模拟阶段只写虚拟账户，实盘阶段需要二次人工确认

## 八、关联论文

- **Reflexion / ExpeL / Voyager** [3,4,5]：自进化 Agent 的基础机制——论文从安全角度审视这些系统的授权漂移风险
- **Progent** [25]：工具调用约束，允许静默策略收窄但扩展需要审批——可实例化本文的效果天花板 B
- **ConLeash** [24]：格精炼减少持久过度授权和提示疲劳——可实例化活跃权限 P_t
- **SkillGuard** [27]：将技能视为权限携带工件——自然实现 Eq.1 所需的声音请求抽象
- **CaMeL** [16]：在工具调用前追踪受信控制和数据流——实现 Eq.1 的候选机制
- **Capability Binding** [22]：工具清单变更时使证书失效——本文的过渡信封是其泛化版本
- **Confused Deputy** [37]：特权组件受不可信源指令行动——状态绑定授权的时序亲属

## 九、一句话总结

本文为进化型 AI Agent 提出了"状态绑定授权"框架：用不可变的效果天花板 B 约束所有可活跃权限（P_t = P_t^prop ∩ B），用任务特定的过渡信封判断授权是否在变异后存活，并用 Theorem 1 证明了在完全中介前提下变异不会放大受保护效果——核心贡献是将"绩效证据扩展边界"重新定义为可靠性而非安全决策，对 Hermes Agent 的 skill 进化、delegate_task 委派、阶段权限控制有直接工程指导价值。
