〇、定锚：我的现状与目标

我的体系里有多条"从强模型向可部署小模型转移能力"的现实需求：Jetson 本地跑 4B 级模型、dsh/Colab 车道做训练、日常主力是 GPT-5.6 Luna/Sol 等闭源强模型（其推理恰恰被 API 加密隐藏）。痛点：闭源教师的 chain-of-thought 拿不到，传统"轨迹+CoT 全量监督蒸馏"路线对我物理性不可行。时间尺度上，近期有 domain-llm-training-pipeline 与 dp5 训练管线可承接新配方。本篇的判读标尺：它是否把"闭源教师→小模型 Agent"这条路从不可行变成可行，且配方能在我的 LoRA 流水线里复现。

一、内容整理

1.1 核心问题：闭源教师的推理墙

  • OpenAI 等厂商对闭源模型返回加密的 reasoning items，至多给一段摘要，加密的目的正是阻止蒸馏〔背景，2026〕
  • 标准蒸馏配方监督"CoT + 可见文本 + 动作"全部内容；对闭源教师，CoT 这一最大信息块缺失〔方法，2026〕
  • 学生是已后训练的推理模型（Qwen3-4B-Thinking），学新策略不能丢已有单步推理能力——这是持续学习问题，不是白板 SFT〔观点，2026〕

1.2 三种训练目标（方法核心）

  • full-CoT：think 块内放教师推理，全监督（传统基线，仅开源教师可用）
  • action-only：预填充空 think 块（<think></think>），只监督其后的动作 token；空块本身不计 loss——它只做条件化，不教学生"输出空块"
  • CoT-proxy：空 think 块之后、动作之前，放一段教师推理的短摘要（AppWorld 平均 26 token vs 教师完整推理 124 token；SWE-bench 20 vs 81）
  • 关键细节：同一表示应用于轨迹的每一轮（包括作为后续轮上下文的早期轮），保证 action-only 样本从不经历史泄漏教师推理
  • 推理时所有学生都开 thinking：只预填 opening token，学生用自己的风格填 think 块。训练时学到的策略（空块下学的）能迁移到"开思考"的推理格式——作者称之为 cross-format transfer〔方法，2026〕

1.3 防漂移：KL replay 正则

  • 损失函数：L(θ) = -1/Nt·Σ log p_θ(y|h) + 1/Nr·Σ KL(p_init(·|h) ‖ p_θ(·|h))——教师轨迹上做监督，replay 样本上对初始模型做全词表 KL
  • LoRA 场景下 p_init = 同一底模关掉 adapter，多一次前向、无需第二份权重；只需学生自己的 logits，从不需教师——这正是它适配闭源教师的原因〔方法，2026〕
  • 训练配置：LoRA，8 epochs，每个 update 混 17 条轨迹 + 3 个 replay 样本（15% replay），replay 池 = 初始学生在 OpenR1-Math（域外）上的 1000 条生成；AdamW lr 3e-5，梯度裁剪 1.0

1.4 主结果（AppWorld TGC / SWE-bench Verified）

开源教师 Qwen3.6-27B（教师 60.7 / 69.3）：
- Qwen3-4B：初始 7.3 / 2.7 → full-CoT 29.2 / 3.9，action-only 17.9 / 5.5，CoT-proxy 34.5 / 15.1〔数据，2026〕
- Qwen3-32B：初始 11.5 / 5.8 → full-CoT 27.8 / 21.1，action-only 25.4 / 14.3，CoT-proxy 29.8 / 21.7

闭源教师 GPT-5.6 Luna（reasoning effort xhigh，教师 89.3 / 88.2）：
- Qwen3-4B：7.3 → action-only 35.1、CoT-proxy 48.2（AppWorld）；2.7 → 18.0 / 27.8（SWE）
- Qwen3-32B：11.5 → 44.4 / 59.1（AppWorld）；5.8 → 27.8 / 35.2（SWE）〔数据，2026〕
- 闭源教师比开源教师强得多，蒸馏出的学生也强得多——教师质量直接决定学生上限

1.5 full-CoT 的病理特征

  • full-CoT 学生轮数最多却没有任何一个设置里最好；AppWorld 上最常耗尽 token 预算（4B 20%、32B 35%，其他学生 ≤10%）——模仿教师推理让学生"话多事少"，难以收尾〔数据，2026〕

1.6 消融四连（对配方可复现性最关键）

  • replay 必要性：无 replay 时 AIME 74.7→68.9、KL 散度 0.003→0.042 nats/token；replay 每对比较都占优
  • replay 必须域外：换成 AppWorld 域内 replay，action-only 直接跌回 7.3%（= 初始模型）——在目标域上正则等于把要改的策略钉死
  • 摘要位置：放 think 块外（CoT-proxy 34.5/48.2）显著优于放块内当 CoT 监督（23.4/33.9）——块内监督会把"摘要腔"教成学生的推理风格
  • 摘要来源：教师自注 7.5 H100 GPU 时（34.5）≈ Qwen3-4B-Instruct 学生级标注器 0.08 GPU 时（36.9，1% 成本）；1.7B 太弱（27.6）；完全看不到教师推理的"事后解释"（从任务+末观测+动作反推）拿回约 2/3 增益（29.0）
  • 教师可见文本必须剥离：保留教师可见全文时 action-only 跌到 4.6%（低于初始），CoT-proxy 34.5→24.6——教师的散文不是摘要的替身，空 think 块配方依赖"只见动作"的干净目标〔数据，2026〕

1.7 分析：学生没学会写摘要，但学会了像教师一样行动

  • CoT-proxy 学生在推理时从不输出摘要（summary 标签零出现）——增益来自训练时摘要教会的"策略与自身推理的对应关系"，不是测试时的显式摘要输出。机制解释：训练中摘要永远条件于空 think 块，而推理时 think 块已被自己的推理填满，该上下文不再出现〔分析，2026〕
  • 措辞守恒：初始学生 98% think 块含"Wait"，action-only/CoT-proxy 学生保持自身措辞（"Okay"开头 100%/86%），只有模仿教师 CoT 才会改变学生的推理措辞——策略与推理风格是可分离的两个通道〔分析，2026〕

1.8 实验环境与诚信声明

  • AppWorld test-normal（168 任务/56 场景，TGC/SGC 双指标）；SWE-bench Verified 500 任务，harness 改自 mini-swe-agent；教师与学生同 harness 同 prompt 同预算同评分器
  • 伦理声明：只用任何用户都能从 API 拿到的可见输出与推理摘要；提醒各厂商 ToS 可能限制用输出训练其他模型，蒸馏闭源模型前应自查条款〔观点，2026〕
  • ⚠️ 未发现代码/权重发布（论文无 GitHub 链接），复现需自建管线

三、归纳总结

3.1 核心框架：策略与推理双通道分离蒸馏

教师轨迹 ──┬── think块：推理（闭源时拿不到/加密）
           └── 可见部分：动作（+可选推理摘要proxy）
                        │
   ┌────────────────────┴────────────────────┐
   │ 训练目标三选一（think块处理方式）：        │
   │  full-CoT    : 教师推理进块+全监督(基线)  │
   │  action-only : 预填空块，只监督动作       │
   │  CoT-proxy   : 空块后放26token摘要再动作  │
   └────────────────────┬────────────────────┘
                        │  + KL replay锚定初始模型(15%,域外)
                        ▼
   推理时：学生开thinking，自己风格推理 + 教师级行动
   = cross-format transfer（空块学策略→满块用策略）

3.2 三维护筛

  • 优点：证据强度高——两个环境、两个学生规模、开闭两类教师、三种子均值、成对统计检验；消融完整覆盖配方每个自由度（replay有无/域内外/摘要位置/来源/文本剥离）；把"闭源教师蒸馏"从数据不可行变为可行，且 4B-Instruct 标注器把摘要成本打到 1%
  • 缺点：上限仍受教师绝对水平约束（Qwen3.6-27B 教出的 4B 只有 34.5，Luna 教出 48.2）；AppWorld/SWE-bench 均为 API/shell 型环境，动作空间规整，对自由度更大的 GUI/物理环境泛化未验证；无代码发布，第三方复现有成本；SWE-bench 闭源教师侧为单次运行（无多种子）
  • 借鉴点：可直接迁移的是配方三件套（空 think 块 action-only 目标、块外 26token 摘要、15% 域外 KL replay）——在我的 LoRA 管线里三者都是数据构造层面的改造，不涉及新训练框架

3.3 反直觉点提炼

  1. 教师推理不是必需品——动作序列本身承载了几乎全部策略信息
  2. 摘要放进 think 块反而有害——监督什么，学生就模仿什么的"腔"
  3. replay 必须域外——正则的目的是保能力不是保策略
  4. 蒸馏闭源教师反而更强——数据可及性 ≠ 数据质量，Luna 的动作质量碾压开源 27B
  5. full-CoT 学生话最多、事最少——模仿推理风格引入的是冗余而非能力

四、趋势判断

趋势1：闭源教师→开源学生的"行为蒸馏"将成为标准路（上升）

依据：2025-2026 年 Penaloza 判"标准蒸馏已死"到本文 2026-11 用纯 SFT 复活它，一年内范式翻转；API 摘要（CoT-proxies 的来源）是厂商已在提供的接口。对我=机会：日常用 GPT-5.6 的动作轨迹本身就在产生可蒸馏语料。

趋势2：推理模型微调将标配"锚定正则"（上升）

依据：本文 KL replay + 2025 Thinking Machines on-policy 蒸馏同向；AIME 掉 5.8 分的失败模式是所有 reasoning 微调共享的坑。对我=风险规避：本地训练管线不配锚正则=白训。

趋势3：4B 级 Agent 的能力天花板被教师质量而非参数量锁定（分化）

依据：同为 4B，27B 教师给 34.5、Luna 给 48.2；教师-学生差距始终 ~40 点未收敛。对我=机会：Jetson 本地 Agent 的升级路径=换更强教师重蒸，而非换更大模型。

趋势4：API 输出的 ToS 约束将收紧（风险，观察）

依据：论文自己挂出伦理声明与 ToS 提醒；厂商加密推理的动机即反蒸馏。对我=风险：语料采集要趁早，合规自检不能省。

五、关联分析

5.1 与「技能记忆多视角蒸馏内化」(2026-11-05 MDSKILL 精读) 的关联

同属"蒸馏但重新定义监督对象"：MDSKILL 蒸馏的是技能的多功能视角（不蒸馏原始 CoT），CoT-Proxy 蒸馏的是动作策略（不蒸馏教师 CoT）。两者共同指向：监督信号的选择比蒸馏架构更重要。CoT-proxy 的 26token 摘要 ≈ MDSKILL 的功能视角池——都是"教师推理的紧凑替身"。

5.2 与「能力区域配对优势-Agent长程课程」(2026-10-21) 的关联

该篇讲学生长程课程设计，本篇讲教师侧数据构造——正好是同一问题的两端。配对优势需要"教师演示落在学生能力区边缘"，action-only 天然满足（动作可执行性由学生 harness 保证）。

5.3 与 domain-llm-training-pipeline / dp5 训练项目的关联

我的领域文档训练管线可直接吸收三件套：15% 域外 replay 池（OpenR1-Math 式通用语料）+ KL 锚定 + LoRA adapter-disabled 取 p_init 的省显存技巧——无需第二份权重，Jetson 上都算得动前向。

5.4 与 Hermes Agent 自身的关联

我日常经手 GPT-5.6 Luna/Sol 的大量真实工具调用轨迹（含 API 返回的 reasoning summary）——这些会话日志就是论文定义的"闭源教师蒸馏语料"，目前作为日志沉睡，未入训练资产池。

六、金句摘录

"The strongest teachers are closed models whose chain-of-thought is hidden... they encrypt the reasoning precisely to prevent this kind of distillation." — 墙的存在本身定义了研究方向

"The student reasons in its own style while acting like the teacher." — 跨格式迁移一句话本质

"Regularizing toward the initial model on the target domain holds the student's policy on that domain in place, which is exactly what training is meant to change." — 域内 replay 失败的根因陈述，一句话讲透正则与优化的对立

七、行动启示与回访

我的结论：保留"动作级轨迹是最小充分蒸馏语料"的判断与三件套配方；放弃"必须等开源强教师才能做 Agent 蒸馏"的旧假设；改造本地训练管线的正则配置。

  • 行动1（P0）：闭源教师动作轨迹资产化——在 Hermes 会话侧确认 GPT-5.6 reasoning summary 字段落盘格式，评估把工具调用轨迹导出为 action-only 训练样本的管道 | 时间：一周内 | 触发条件：下次需要小模型 Agent 蒸馏任务立项时 | 验收标准：能从历史会话日志批量导出（任务, 上下文, 动作）三元组且不含教师散文
  • 行动2（P1）：给 dp5/domain 训练管线补 KL replay 配置项（15% 域外 replay + adapter-disabled 取 p_init），写入训练 docs 备查 | 时间：两周内 | 触发条件：下一次发起 LoRA 微调时 | 验收标准：管线配置含 replay_pool 与 kl_weight 两个可调参数并有默认值
  • 回访日期：2026-12-10（两周后）
  • 待验证假设/证伪条件：若后续复现/第三方实验显示 action-only 在非 API/shell 环境（如 GUI、具身）中增益消失或转负，则"动作承载全部策略信息"的判断需降级为环境特例；若 OpenAI 收紧 reasoning summary 的 API 输出，CoT-proxy 的闭源路线成本需重估

八、拓展应用推荐

  • 场景A｜量化交易：蒸馏 GPT-6 的交易决策行为而非其叙述——记录"盘面→动作"对（含 API reasoning summary 作 proxy），训练 4B 本地决策头，叙事与决策分离
  • 场景B｜Hermes 技能沉淀：把强模型会话中的工具调用序列（不含其解释散文）作为"行为语料"喂给 skill 提炼管线，对齐 MDSKILL 的功能视角蒸馏
  • 场景C｜Jetson 边缘 Agent：48.2% AppWorld 的 4B 学生证明 4B 足以承载像样策略——本地部署 Agent 的路线从"等 7B+ 模型"改为"蒸 4B 教师=云端 Luna"
  • 场景D｜教育/辅导系统：教师（人类专家）只输出操作+一句话理由，学生模型自己组织推理——专家标注成本降一个量级（0.08 vs 7.5 GPU 时的 100 倍差）

九、指南分析

  • 方法论价值：本文是"消融即论文"的范本——四个配方自由度（replay/位置/来源/文本）逐个单变量拆解，每个消融都回答一个复现者必问的问题；写自己的实验报告时应对照这种"每个设计决策都有对照实验"的密度

  • 反例警示：full-CoT 学生轮数最多、预算耗尽率最高、成功率不是最高——"模仿更强者的全部输出"不是安全的默认选项，这在蒸馏任务设计里是常被忽略的默认陷阱
