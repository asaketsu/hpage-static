一、内容整理

1.1 背景：为什么需要 AI 红队工具

生产级 LLM 部署的攻击面包含五个独立层次，没有单一工具能覆盖全部：

  • Layer 1 — 输入/输出层：经典 prompt injection、jailbreak、毒性生成、PII 泄露、系统提示词提取。四款开源工具均覆盖此层。
  • Layer 2 — 检索层（RAG）：文档投毒、检索操纵、间接 prompt injection。仅 Promptfoo 和 Garak 部分覆盖。
  • Layer 3 — Agent 层：工具调用劫持、越权操作、记忆投毒、多 Agent 信任边界违规。2026 年开源覆盖最弱的一层。
  • Layer 4 — 模型层：模型提取攻击、微调后门、嵌入空间操纵、序列化格式反序列化漏洞。Garak 的主场。
  • Layer 5 — 基础设施层：Token 洪水、成本放大、API Key 泛滥、供应链风险。几乎没有红队工具覆盖此层。

核心结论：没有单一工具覆盖全部五层。对大多数团队，答案是组合而非替代。

1.2 四大开源红队工具深度解析

① Promptfoo — CI/CD 集成的默认选择

  • 厂商：开源 MIT 协议，2026年3月被 OpenAI 以约 8600 万美元收购，但 MIT 协议继续生效
  • GitHub Stars：18,000+
  • 工作方式：YAML 配置文件驱动，原生集成 GitHub Actions / GitLab CI / Jenkins
  • 覆盖层：Layer 1（输入输出）+ Layer 2（RAG 应用层）
  • 漏洞类型：50+ 种，包括 prompt injection、jailbreak、PII 泄露、系统提示词提取、RAG 上下文注入
  • 合规映射：OWASP LLM Top 10 / NIST AI RMF / MITRE ATLAS / EU AI Act — 这是开源工具中罕见的完整合规映射
  • 最强项：应用感知测试 — 它会根据你的实际应用逻辑（RAG pipeline、agent 架构）生成定制化测试用例
  • 缺口：Agentic 攻击覆盖有限，多 Agent 管道测试需自定义插件；模型层和基础设施层较弱

② PyRIT — 安全研究人员的多轮攻击编排框架

  • 厂商：Microsoft 开源，MIT 协议
  • GitHub Stars：3,800+，129 位贡献者，已发表学术论文
  • 已在 100+ Microsoft 内部产品（含 Copilot）中实战验证
  • 核心定位：编排框架（orchestration framework），不是扫描器
  • 三大可组合原语：
  • Orchestrators（编排器）— 指挥攻击流程
  • Converters（转换器）— 转换提示词
  • Scorers（评分器）— 评估模型响应
  • 最强项：多轮攻击编排
  • Crescendo 攻击：逐步引导模型生成有害内容，每步看似无害，用攻击者 LLM 动态管理升级。已证明可绕过 GPT-4 和 Gemini Pro 的安全对齐
  • TAP（Tree of Attacks with Pruning）：并行探索多条攻击分支，根据评分反馈修剪死路。论文报告对 GPT-4 Turbo 和 GPT-4o 成功率超过 80%
  • 70+ 提示词转换器：Base64、ROT13、Leetspeak、Unicode 混淆、LLM 改写、翻译、多模态注入。可叠加（翻译→Base64→嵌入图片）
  • 缺口：无内置仪表盘或合规报告；需要 Python 熟练度；非 CI/CD 原生

③ Garak — 模型级漏洞扫描器（"LLM 的 Nmap"）

  • 厂商：NVIDIA 开源，Apache 2.0
  • 核心架构：Probes（探针，生成测试输入）→ Detectors（检测器，分析输出）→ Evaluators（评估器，编译结果）→ Buffs（修饰器）
  • 120+ 探针模块，覆盖：prompt injection、DAN jailbreak、编码绕过、数据泄露、包幻觉、恶意软件生成、毒性、XSS
  • 支持主流模型提供商：OpenAI、Hugging Face、AWS Bedrock、Azure OpenAI、NVIDIA NIM、Cohere、Groq、任何 REST 端点
  • 单条 CLI 命令即可对模型端点运行全量扫描
  • 最强项：基础模型安全基线扫描 — 回答"这个模型可以安全部署吗"
  • 缺口：测试模型端点而非完整应用栈；RAG 覆盖有限（仅间接注入子集）；Agentic 覆盖处于早期阶段

④ DeepTeam — 最快上手的 OWASP 合规扫描器

  • 厂商：Confident AI 开源，Apache 2.0
  • GitHub Stars：1,277
  • 覆盖：40+ 漏洞类型，直接映射 OWASP LLM Top 10 和 OWASP Agentic Applications Top 10
  • 10+ 对抗攻击方法：多轮攻击、人格模拟、jailbreak 注入
  • 异步扫描，对高延迟端点吞吐更好
  • 最强项：1 小时内完成 OWASP 映射基线扫描 — 合规团队最快路径
  • 缺口：探针库小于 Garak；多轮编排不如 PyRIT；CI/CD 集成不如 Promptfoo 成熟；尚无原生多模态攻击支持

二、查询拓展

2.1 OWASP LLM Top 10

OWASP 针对 LLM 应用的十大风险清单，2025 版核心条目包括：LLM01 Prompt Injection、LLM02 Sensitive Information Disclosure、LLM03 Supply Chain、LLM04 Data Poisoning、LLM05 Improper Output Handling、LLM06 Excessive Agency、LLM07 System Prompt Leakage 等。这是 AI 安全合规审计的事实标准 — DeepTeam 的每个漏洞类型直接映射到具体 OWASP 编号，省去了 Garak 和 PyRIT 需要的手动映射步骤。

2.2 Crescendo 攻击与 TAP 技术

两者都是 2024 年发表的多轮 jailbreak 技术。Crescendo（渐强）通过一系列看似无害的渐进式对话步骤，逐步引导模型越过安全边界，攻击者 LLM 实时管理升级节奏。TAP（带修剪的攻击树）将攻击建模为树搜索，并行尝试多条路径并基于评分器反馈剪枝，效率远超线性尝试。这两种技术在 PyRIT 中被实现为标准 orchestrator，也是 PyRIT 区别于其他工具的核心竞争力。

2.3 Build vs Buy 分析

2026 年的一个关键洞察：一个全职安全工程师维护开源红队栈的年成本，已超过大多数中端商业平台（Mindgard、Lakera、HiddenLayer）的订阅费用。商业平台增加了开源工具仍然缺乏的持续监控、合规报告自动化和 Agentic 覆盖。但对于技术能力强、预算有限的团队，开源组合（Promptfoo CI + Garak 扫描 + PyRIT 深度测试）仍是可行方案。

3.3 工具选型决策树

  • 你是安全工程师，想在 PR 中集成红队测试 + OWASP 报告 → Promptfoo
  • 你是 AI 红队研究员，需要自定义多轮攻击 + 完全编程控制 → PyRIT
  • 你是 DevSecOps 团队，跑夜间回归测试监控基础模型安全漂移 → Garak
  • 你是合规团队，需要最快路径产出 OWASP LLM Top 10 审计证据 → DeepTeam
  • 你是 CISO，管理大规模 AI 资产 + 合规审计日程 → 商业平台 + 定期人工渗透测试

四、趋势判断

趋势1：应用层红队工具正被大厂收编

Promptfoo 被 OpenAI 收购（2026.3），Lakera Guard 被 Check Point 收购，Protect AI Guardian 被 Palo Alto Networks 收购。AI 安全工具链正从独立开源生态向平台厂商内置能力整合。依据：三家收购均在 2025-2026 年完成。

趋势2：Agent 安全层是最大空白

五层覆盖中，Layer 3（Agentic）开源覆盖最弱。Agent 可调用 API、执行代码、访问数据，爆炸半径远超聊天机器人。2026 年多数厂商仍在探索 Agent 身份认证、工具授权、Agent 间信任传递和审计的标准化。依据：BeyondScale 和 General Analysis 报告均指出此为最不成熟的层。

趋势3：组合策略成为共识

没有单一工具覆盖全部五层攻击面。行业共识是"一个开源工具跑 CI/CD 持续基线 + 定期人工 AI 渗透测试覆盖自动化无法触及的面"。依据：多家分析机构一致结论。

趋势4：合规驱动工具选型

EU AI Act 高风险义务 2026 年 8 月生效，OWASP LLM Top 10 成为审计事实标准。能直接产出 OWASP 映射报告的工具（Promptfoo、DeepTeam）在合规驱动场景中获得优势。依据：法规生效时间线和工具功能对比。
