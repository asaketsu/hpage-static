一、内容整理

1.1 核心问题：Agent 干不了真实生产力活

LLM Agent 在 agentic reasoning 和工具调用上进步很快，但接手真实生产力工作（产出分析报告/表格/演示文稿/结构化文档）仍然失败。论文把失败拆成三重结构性需求：

  • 长程专业工作流：步骤相互依赖、领域隐式惯例、中间状态持续演化——现模型会漏关键操作、不会根据反馈调整
  • 异构文件上下文：真实文件格式/版式/完整度参差不齐，需跨文件整合证据——模型常误读内容、忽略跨文件依赖
  • 交付级细粒度要求：事实一致性、证据覆盖、结构、格式、实用性——「产出一个文件」≠「达到交付标准」

瓶颈定位：不是缺更多数据，是缺反映真实工作的数据（真实意图、真实文件、交付级标准）。人工写工作流不可扩展；LLM 生成文件缺乏真实文档的版式、缺口和交叉引用。

1.2 方法论：三阶段真实源合成管线

阶段一：工作流提取（Workflow Extraction）

  • 语料库：DLR-Web（FineFineWeb 过滤版），每段自带学科元数据
  • 种子：O*NET 职业活动种子，学科元数据映射到职业类别选取对应种子
  • 双重过滤：workflow 过滤（是否编码工具用工作流）+ file-oriented 过滤（是否涉及定位/读取/编辑/产出文件工件）
  • 通过者由 Qwen3.6-Plus（合成模型 π_syn）转换为工作流蓝图：信息依赖、所需文件类型、预期产出

阶段二：附件检索（Attachment Searching）

  • 对每个工作流蓝图跑多轮搜索-验证循环：生成搜索查询 → web_search → 标题/摘要初筛 → 下载 → 用 bash + view_image 检查封面/目录等关键部分 → 相关文件保留
  • 硬约束：丢弃 >50 页或 >2MB 文件（控制延迟与构建开销）
  • 终止条件：保留文件联合满足工作流的信息与操作需求，或达最大搜索轮数；不满足的实例直接丢弃

阶段三：任务合成（Task Synthesis）

  • 沙盒内实例化：分页文件渲染成页面图像、表格解析为 sheet 级表（原始文件保留供检查）
  • π_syn 多轮合成：检查文件内容 → 按需联网取证 → 选定附件集 Fa → 联合设计指令 I 和评分量表 R（rubric 绑定文件级证据与约束）
  • 专家求解：Claude-Opus-4.5 作为专家策略在沙盒解题，产出参考交付物 Fr + 专家轨迹 τ
  • 双向验证闭环：verifier 对照 rubric 检查参考交付物——未满足条款若因附件不支持/与指令不匹配则修订 rubric；若条款合理则保留 rubric 让专家修订交付物

训练配方：4k 实例拆 3k SFT + 1k RL（无任务重叠）

  • SFT：模仿专家轨迹（检查文件、工具操作、交付构建）
  • RL：GRPO 在持久沙盒内 rollout，Qwen3.6-Plus 做 MLLM-as-a-judge 按评分量表打分。pdf/pptx/docx 渲染成图像，xlsx 重算值与公式转 Markdown + 渲染图像
  • 奖励：r = 0（无交付物）或 Score/max_score；刻意不加中间工具调用错误惩罚（避免诱导工具特定调用偏好）

1.3 关键实验结果

数据统计（10k 语料 → 4k 实例）：

  • 平均 2.51 个附件/任务；rubric 平均 15.3 条；专家轨迹平均 18.0 步 / 41.8k tokens
  • 附件类型分布跟随真实源可得性：PDF 多、演示文稿少

主实验 GDPval（OpenAI 生产力基准，220 任务）Pass@1：

  • Agent-R²-4B（Qwen3-4B-Thinking 底座）：51.0%（base 仅 31.1%，提升 18.6 点）
  • Qwen3-235B-A22B-Thinking：48.0% → 4B 反超 235B
  • Qwen3-VL-235B：49.7%；DeepSeek-v3.1：48.8%；GPT-4.1：39.4%；Gemini-2.5-Pro：57.9%；Claude-Opus-4.5：72.6%
  • 分解：SFT 在 office 任务增益大（模仿专家轨迹），RL 在 non-office 泛化增益大

OOD 迁移 OfficeQA Pass@1：2.2%（base）→ 11.4%（SFT）→ 14.8%（超过 235B 的 13.8%）——训练收益迁移到文档感知与跨文档数值抽取，不只是表面交付质量

Shortcut 行为分析（Table 3，220 任务全量轨迹检验）：

  • 交付前复核（re-check）：0.5% → 91.7%（SFT）→ 95.8%（RL）
  • 错误未修复仍继续写：55.0% → 16.0% → 11.0%
  • 数值错误修复率：60.7% → 79.6% → 85.7%
  • 占位符文本：12.5% → 9.6% → 5.7%（与专家交付同级）
  • 可追溯数字占比：31.2% → 34.6% → 38.8%
  • 掩错代码（except→default/pass）：SFT 4.1% → RL 0.9%

行为模式转变：base 平均 6.7 步 2.88 错误（遇错早停、证据不足就抢建交付）→ SFT 39.0 步 16.3 错误（持续探索，完成率 86.8%→78.2% 有所回落）→ RL 33.1 步 12.9 错误 + 完成率回升 90.9%。论文定义有效步骤数（= 工具调用数 − 错误数），与 GDPval Pass@1 正相关。

消融（Table 4）：

  • 真实文件 vs 合成文件（1k 匹配对同管线）：43.3 vs 41.4；专家轨迹工具调用 20.4 vs 8.0（2.54×）——真实文件的版式/结构/交叉依赖逼出更多检查与处理
  • rubric 奖励 vs 无 rubric：51.0 vs 49.5

案例（材料测试报告）：base 找不到表格值仍写报告（dummy 证据）；Gemini-2.5-Pro 检查更多但静默把关键测量转成 NaN、生成空图表；Agent-R²-4B 从解析/计算/绘图错误中恢复，算出硬度值并验证最终图表。

二、归纳总结

创新点：

  1. 真实源全链路落地：不是「合成数据」而是「真实源数据合成」——工作流从 web 语料挖、附件从公网真文件筛、rubric 从工作流-文件上下文派生。三个「真实」咬合成可扩展的 4k 高质量集
  2. Rubric 双向验证闭环：合成任务不是一次性生成——rubric 与专家交付物互为校验（rubric 不合理改 rubric，合理则改交付物），保证「任务可解且标准明确」
  3. Shortcut behavior 形式化 + 量化证据链：把「表面合理但未充分取证/构建/验证就交付」定义为可测量失败模式，给出五指标量化表，证明 SFT+RL 系统性消除它
  4. 数据效率实证：4k 实例 + 4B 模型 > 235B 通用模型——垂直任务上小模型+对路数据的路线再次得证

局限性（论文自述 + 笔记分析）：

  • 依赖 Qwen3.6-Plus + Claude-Opus-4.5 两个闭源强模型做合成与专家求解，管线成本与可复现性受限
  • non-office 任务（音视频等交付物）明确在主要焦点之外；GDPval 51% 距 Claude-Opus-4.5 的 73.8% 仍有 22.8 点差距——天花板远未触及
  • 完成率 78.2%（SFT 后回落）说明 4B 容量撑不起全部探索路径；rubric-as-judge 的评分可靠性依赖 judge 模型质量（论文用 Gemini-3.1-Pro 评 GDPval）
  • placeholder 率 5.7% 虽与专家持平但非零；可追溯数字 38.8% 意味着仍有六成数字无法溯源

三、趋势判断

  • 「数据 > 规模」在垂直任务上持续兑现：继 OfficeQA 类基准后，4B 反超 235B 的案例再添一例。通用能力靠规模，职业级生产力能力靠对路的真实源数据——这条分叉线会越来越清晰
  • 训练数据合成范式从「LLM 幻构」转向「真实源锚定」：workflow 挖语料、文件搜公网、rubric 派生自上下文——合成的是「组织方式」而非「内容本身」。这与 RAG 当年「检索代替记忆」的转向同构
  • Rubric 化评估正在成为 agent 训练与评测的通用语言：GDPval 原生 rubric、本文合成 rubric、Finance Agent Benchmark 专家 rubric——细粒度条款量表正在取代单一 outcome 分
  • 行为级指标（re-check 率/掩错代码/可追溯数字）将成为 agent 质量审计标配：比 Pass@1 更贴近「可信赖交付」，预计会被更多 agent 评测框架吸收
  • SFT 教探索、RL 教收敛的两阶段分工：SFT 先打破早停惯性（步数 6.7→39），RL 再压错误（16.3→12.9）提完成率（78.2%→90.9%）——这个「先放后收」模式对小模型 agent 训练有普适参考价值

五、指南分析

本文管线可提炼为可复用的「真实源任务构造 SOP」：

  1. 选种子：从职业/领域活动库（如 O*NET）取活动种子，映射到语料学科元数据
  2. 挖工作流：语料段经双重过滤（是否工具用工作流 + 是否文件导向）→ 提取蓝图（信息依赖/文件类型/预期产出）
  3. 配真实文件：多轮搜索-下载-检查循环，硬上限（50 页/2MB），不满足即弃——宁缺毋滥
  4. 合成任务对：沙盒内（指令 I + 附件 Fa + rubric R）三元组，rubric 条款绑定文件级证据
  5. 专家求解留档：强模型解题产出参考交付物 + 完整工具轨迹
  6. 双向验证：rubric ↔ 参考交付物互检，不合理改 rubric、合理改交付物
  7. 两阶段训练：SFT（模仿轨迹学探索）→ rubric RL（outcome 归一化分数学收敛，不罚中间工具错误）

关键工程细节：评分输入要把交付物转成模型可读形态（渲染图像 + 重算公式），这是 rubric 评估可用性的隐藏前提。

六、拓展应用推荐（借鉴点评估）

对照现有 skill/memory/cron 的分档评估：

  • P0 Shortcut 检测器增量：Table 3 五指标（re-check 率/未修复错误续写/占位符/可追溯数字/掩错代码）可直接改造为交付前守卫。现有 ai-generated-quality 已有覆盖面/业务断言维度，增量价值 = 把「数字可追溯性」（每个数字能指出来源）和「except-pass 掩错」加为显式检查项；critical-code-reviewer 增加掩错代码模式检查。收益高、实现轻（正则+LLM 复核），建议执行
  • P1 Rubric 条款化评估：content-judge skill 从维度打分升级为「deliverable + reference + 条款化 rubric」三输入结构——评估从「整体印象」变「逐条对账」。与用户「验收门禁」偏好（rl-standing-gate-eval / notes-eval-gate / ppt-quality-gate）同构，可作为门禁生成器的方法论升级
  • P1 有效步骤数作为任务质量代理指标：effective steps = 工具调用 − 错误，与产出质量正相关。可加入 session-evolution-scan 或 observability-dashboard：会话级统计有效步骤数，早停+抢答模式（低步数+高声明完成）自动标记复核
  • P2 真实源任务语料积累：Hermes 日常任务（笔记/发布/巡检）本质就是真实源数据。借鉴「指令+rubric+专家轨迹」三元组格式，把高价值会话沉淀为微调候选语料——为未来 on-device/垂直微调储备。近期无训练需求，先记录格式规范即可
  • P3 训练配方借鉴：SFT 教探索→RL 教收敛的两阶段分工，对 DUCK 后续策略迭代（行为塑造类奖励）有参考——但机器人域奖励结构不同，仅作方法论参考不直接移植
