一、内容整理

1.1 论文核心问题：技能步骤贡献无法量化

LLM Agent 的技能（skill）是指导 agent 执行长程程序化任务（编码、文档处理等）的逐步自然语言规范。现有技能设计完全靠试错：

  • 基准测试只能告诉你整个技能的好坏，无法解释哪些步骤对性能负责、冗余在哪里
  • 没有细粒度步骤级归因，实践者要么过度指定技能（浪费上下文和成本），要么盲目剪枝（导致性能陡降）
  • 现有方法都是"整体优化"：prompt 优化改进整体、prompt 压缩识别可压缩 token、工作流优化器改进执行结构——没有任何方法对固定技能内部的单个步骤赋值

核心洞察：技能步骤的价值不是孤立的，而是上下文依赖的——一个步骤在哪些其他步骤存在时才有效，这正是合作博弈论中 Shapley 值的适用场景。

1.2 形式化：技能步骤 = 合作博弈玩家

论文将技能步骤归因建模为合作博弈归因问题：

  • 技能切分为 n 个语义连贯的步骤（player），切分按 skill.md 的语义块：任务入口指引、决策规则、API 示例、校验指令、常见坑点，紧耦合片段不拆分
  • 保留子集 S（coalition）= 只保留 S 中步骤、保持原序的技能变体；frontmatter 永远保留（保证技能可被发现加载），非目标上下文/基准实例/评分规则全部固定
  • 联盟效用 v(S) = 在固定基准子集 M 上的平均得分（多数技能基准是二值成功指示，即经验成功率）
  • 目标输出：贡献向量 α = (α1, ..., αn)，每步对基准性能的贡献

关键约束：观测 v(S) 需要用技能变体真实执行 LLM agent，每个新联盟评估都很贵——成本主导因素是新配置数（unique configurations），不是算术比较数。

1.3 三大经验观察（BAES 设计依据）

论文从 agent 技能评估中提炼三个观察：

  • 配置成本主导边成本：算法要决定评估哪个新配置，使其产生尽可能多的可复用单翻转（one-flip）比较
  • 奖励离散且噪声大：小基准子集上观测性能在相邻联盟间剧烈跳变，某些层（stratum）远比其他层不确定
  • 奖励大面积平坦：相邻联盟奖励相似的区域，额外评估提供信息极少；有用样本应暴露跨玩家规模层的边际效应更大变异

1.4 方法：BAES 两阶段预算化主动近似

Shapley 值精确计算是指数级的（n 个玩家有 2^n 个联盟）。BAES（Boundary-Adaptive Edge Shapley）面向"新配置昂贵 + 缓存单翻转可复用 + 奖励离散快速平坦"的技能场景：

层化分解：Shapley 值按联盟规模分层：φi = (1/n) Σk E[Δi(S) | |S|=k]，其中 Δi(S) = v(S∪{i}) − v(S)。每个 (玩家 i, 规模 k) 层独立追踪经验均值、方差、计数。

阶段一（warmup 覆盖）：广泛采样跨联盟规模，建立缓存并识别哪些层仍不确定。防止纯贪心早期随机波动锁死采样到窄层集合。

阶段二（adaptive 获取）：反复评估单个最有信息量的未评估配置，按它与缓存配置形成的高优先级单翻转边数量打分。分配分数 a(i,k) = √(σ²+ε)/√(m+1)——高方差、欠采样层获得更多关注。另有缓存奖励权重 b(y) = 1 + max{0, round((1−y)/g)}，优先采样低奖励缓存态的邻居（g 为最小可观测奖励增量）。

停止规则：追踪层估计的归一化标准误信号，以奖励粒度 g 归一化（避免对低于基准奖励分辨率的数值变化反应）；当不确定性信号出现边际递减或达到预设最大采样数即停。最低覆盖要求 85 个观测层。停止后返回层化估计器 φ̂i = (1/n) Σk μ̂(i,k)，空层用同规模观测层均值填充。

诚实声明：BAES 是预算化主动近似，不是有限样本无偏估计——自适应阶段故意更多采样不确定层，层均值是为低预算排名恢复优化而非均匀随机采样。预算足够大时退化为经验规模分层平均。

1.5 实验设计与结果

实验一（Shapley 行为有效性）：三个低步数 SkillsBench 技能（offer-letter-generator、manufacturing-fjsp-optimization、dialogue-parser）上精确枚举可行。对比 Individual（单步孤立评估）、Leave-One-Out（全技能去一步）、Random Removal、LeastCore 四个基线。验证方式：移除 top 排名步骤应导致比移除低排名/随机步骤更快的效用下降。结果：全 Shapley 移除曲线在三个任务上下降最快，证明 Shapley 排名最可靠地识别行为重要的技能块。

实验二（BAES 近似精度与成本）：以精确 Shapley 为参照，在匹配唯一配置预算下对比 Monte Carlo Shapley、Quasi-MC Shapley、paired MC Shapley、size-k-truncated Shapley。结果：BAES 在更小预算下达到更低近似误差（Figure 3）。缓存效率诊断：10 玩家技能、99 唯一配置预算下，BAES Phase 1 产生 206 条可复用单翻转边际边，MC 置换采样仅 130 条观测（其中仅 115 条唯一）——同预算下 BAES 制造更多可复用边际证据。

实验三（案例研究）：三个任务的归因剖面给出技能创建/修改的实践指导（见 1.6）。

Token 成本诊断（Figure 4）：联盟变体的 token 数与联盟规模不强相关——各规模组的中位成本相近、范围大幅重叠。归因引导编辑是移除低价值内容的手段，但不保证按比例节省 token。

1.6 案例研究：程序性桥梁（procedural bridge）

跨三个任务，步骤价值由程序性角色而非表面形式解释。高价值步骤都是"程序性桥梁"——连接任务条件到可执行决策规则、API 操作或约束感知回退：

  • Offer Letter：高价值步骤组合占位符替换 + 表格/嵌套表格/页眉页脚操作
  • Dialogue Parser：高价值步骤连接用户场景到具体图构建动作（节点构造、校验、可视化）
  • FJSP：高价值步骤连接调度约束到修复决策（何时保基线机器、何时考虑替代）

低价值步骤特征：局部正确但动作不完整（action-incomplete）——提供背景事实或孤立辅助信息，不改变 agent 的下一个决策。

论文给出具体对比示例：FJSP P9 代码块（含阈值触发 + 基线机器回退逻辑，φ=0.1155）vs Offer Letter P2 纯文本（解释拼写检查现象，φ=−0.0194——负贡献）。

实践工作流：技能编辑变成可测量循环——假设 → 编辑 → 重评估：从候选技能出发，可行时用精确 Shapley 或预算受限的 BAES 估计步骤值，提出一两个低价值删除或高价值强化，用移除曲线协议验证编辑。归因反复浮现程序性桥梁时，指示未来技能应显式化哪些条件、决策、回退；跨任务跨模型反复低价值的步骤成为模板化、压缩或移除候选。

1.7 局限性（论文自述）

  • 精确参照分析仅限低步数技能（精确枚举只在该范围可行）
  • 最适合固定玩家集 + 基准信号合理稳定的场景；动态长度工作流和高度主观评估标准使合作博弈定义不良
  • 强耦合装配线工作流仍是硬骨头：移除中间步骤可能使整条流水线崩溃，大 Shapley 值反映的是结构必要性而非步骤有用性
  • 未来工作：扩展精确锚点、不确定性感知编辑决策、多技能 agent 管线和更丰富评估信号

二、查询拓展

2.1 Shapley 值与博弈论归因

Shapley 值（1953，Lloyd Shapley，诺奖得主）是合作博弈论中公平分配联盟收益的标准解概念：玩家 i 的价值 = 其在所有可能加入顺序下的边际贡献加权平均。核心公式 φi = Σ |S|!(n−|S|−1)!/n! [v(S∪{i})−v(S)]。精确计算需枚举 2^n 个联盟，n=10 就有 1024 个联盟、n=20 超过百万——近似方法（置换采样、分层采样、FastSHAP 摊销估计器）是实用化的关键。本文 BAES 的差异化在于面向"配置评估昂贵"的场景：传统 Shapley 估计器假设联盟评估相对便宜，而技能变体评估要真实跑 LLM agent，贵几个数量级。

2.2 SkillsBench 基准

SkillsBench 是技能方法的标准评测基准：将 agent 技能形式化为结构化程序性知识，提供跨多样任务的精选技能库和确定性校验器（deterministic verifiers）。确定性评分（二值成功）正是本文"奖励离散且快速平坦"观察的来源——v(S) 只能取 0~1 之间的 M 分度值，相邻联盟的性能差异常被奖励粒度吞掉。本文实验 harness 是 OpenHands，模型调用 temperature=0 保证评估可复现。

2.3 与 prompt 压缩/归因方法的区别

LLMChain 等 token 级重要性方法关注输入 token 对模型行为的影响；prompt 压缩识别可移除 token。本文的归因单位是语义程序步骤（natural-language procedural steps）而非 token——一个步骤是一个完整语义块（决策规则/API 示例/坑点警告），移除它改变的是 agent 的决策空间而非表面 token。这与 Hermes 技能系统的模块划分天然对齐。

2.4 Leave-One-Out 为何不够

LOO 只测每个步骤在"其余全部存在"单一上下文中的边际贡献，会系统性低估只在特定组合下才发挥作用的步骤（上下文依赖性）；Individual 把步骤当独立单元评估，忽略步骤间交互。Shapley 在所有 2^(n−1) 个上下文中平均边际贡献，是唯一同时满足效率、对称、 dummy、可加性四公理的分配方案——这就是它在三个基准上移除曲线最陡的原因。

三、归纳总结

3.1 SkillShapley 框架全景

固定技能 skill.md
   │ 语义切块（frontmatter 永保留）
   ▼
n 个步骤 player (x1..xn)
   │ 子集 S = 联盟（保序保留的技能变体）
   ▼
v(S) = 基准子集平均成功率        ←── 每次评估 = 真实跑 agent（贵）
   │
   ├─ 精确路径：全枚举 2^n 联盟 → φi（低步数技能可行）
   │
   └─ BAES 近似路径（预算化主动采样）
        ├─ 层化: (玩家 i, 联盟规模 k) → (μ̂, σ̂², m)
        ├─ 阶段一 warmup：广覆盖，识别不确定层
        ├─ 阶段二 adaptive：a(i,k)=√(σ²+ε)/√(m+1)
        │    + 低奖励邻居权重 b(y) → 选最有信息量的新配置
        ├─ 停止：归一化标准误边际递减（以奖励粒度 g 为分辨率）
        └─ 输出：φ̂i = (1/n)Σk μ̂(i,k) → 步骤排名
   ▼
实践指导：程序性桥梁保留/强化 · 低价值剪枝 · 移除曲线验证

3.2 方法对比（纯文本）

  • Individual（单步孤立）：大量并列值，无法区分步骤重要性；忽略交互
  • Leave-One-Out（去一）：单一上下文边际，低估上下文依赖步骤；同样多并列
  • Random Removal：随机基线，移除曲线平缓
  • LeastCore：另一合作博弈解概念（最小核），表现介于 LOO 与 Shapley 之间
  • Full Shapley：移除曲线最陡（= 归因最准），但指数成本
  • BAES：匹配预算下误差最低；99 配置产生 206 条可复用单翻转边 vs MC 的 130（115 唯一）

3.3 "程序性桥梁"步骤模式

高价值步骤的三种形态（连接条件→行动）：

  • 条件 → 可执行决策规则（FJSP：THRESH=6 触发替代机器搜索）
  • 条件 → API 操作（Offer Letter：占位符替换+表格操作组合）
  • 条件 → 约束感知回退（基线机器保持 vs 替代选择的分支逻辑）

低价值步骤 = 背景解释（不改变下一步决策）或孤立辅助信息（无动作挂钩）。

四、趋势判断

趋势1：技能工程从"试错手艺"走向"可测量科学"

依据：本文把技能编辑变成"假设→编辑→重评估"的可测量闭环，与 SkillMisevolution（误进化检测）、SPyCE（技能-策略协同）、EvoSOP（生命周期管理）共同构成技能工程的方法论闭环——归因（本文）+ 进化（SPyCE）+ 治理（EvoSOP）+ 防退化（SkillMisevolution）。技能贡献量化是从定性经验到定量科学的分水岭。

趋势2：评估预算感知的近似算法成为 Agent 工程标配

依据：BAES 的核心贡献不是新数学，而是把"每次评估都要真实跑 LLM"的成本模型嵌入采样策略设计（缓存复用单翻转边、低奖励邻居加权、奖励粒度归一化停止）。随着 agent 评测成本成为瓶颈，这类 budget-aware 主动采样设计会渗透到工作流优化、提示优化、多智能体拓扑发现等所有需要评估的领域。

趋势3：步骤级归因将驱动技能自动压缩与自动重构

依据：论文明确指出"跨任务跨模型反复低价值的步骤成为模板化、压缩或移除候选"，且 token 成本与联盟规模不强相关意味着压缩收益要从语义冗余中挖。结合 Hermes 侧 skill-review（防退化）和 Skill 压缩需求，归因驱动的技能减肥是下一步自动化的明确方向。

趋势4：强耦合工作流的归因是待攻克的硬问题

依据：论文自述装配线式强耦合工作流（移除中间步骤→全流水线崩溃）使 Shapley 值混淆"结构必要性"与"步骤有用性"。这为后续工作（如基于因果干预、结构感知 Shapley 变体）留下明确空间。

五、关联分析

5.1 与 Hermes Skill 生态的关联

Hermes 技能系统（~/.hermes/skills/ 下 400+ skills）与本文场景一一对应：SKILL.md = 技能、章节块 = 步骤 player、任务成功率 = v(S)。本文直接可用于：

  • skill-review 增强逻辑：现有 skill-review 靠启发式规则（使用频率、覆盖度），Shapley 归因提供任务成功率的贡献量化维度
  • skill-stress-test 增强：现有压测是"带/不带 Skill 跑任务对比"（= LOO 式单上下文），本文证明 LOO 会产生大量并列、Shapley 才能区分步骤级价值
  • Skill 压缩决策：与 note-dual-format 的笔记压缩规则同构——低价值内容删除需量化依据

5.2 与 SPyCE 技能策略协同进化的关联

2026-07-15-SPyCE技能策略协同进化.md：SPyCE 的 merge-or-add 合并规则决定技能如何进化，SkillShapley 决定哪些步骤值得保留——两者正交互补。SPyCE 的分层技能抽象（执行技能/工作流技能）中，归因应分层进行：执行技能按 c,u,e 三元组归因，工作流技能按 b,w 二元组归因。

5.3 与 EvoSOP 自进化工具生命周期的关联

2026-07-10-EvoSOP自进化工具优化.md：EvoSOP 的消融实验证明"剪枝 > 创建"（prune 模块贡献最大），但剪枝决策依据是整体成功率变化——本文正是补齐"剪枝哪一步"的量化工具。EvoSOP 的 Prune 模块 + SkillShapley 归因 = 精准剪枝闭环。

5.4 与 SkillMisevolution 技能误进化的关联

2026-08-15-SkillMisevo技能误进化.md：误进化的根源是技能更新缺乏贡献反馈信号。SkillShapley 提供的步骤级 φ 值正是缺失的反馈信号——误进化检测（SkillMisevolution）+ 误进化定位（SkillShapley 步骤归因）+ 误进化修复（SPyCE merge 规则）构成完整治理链。

5.5 与 skill-stress-test / skill-ab-testing 的关联

skill-ab-testing 的 A/B 验证范式（候选版本 vs 正式版）与本文的移除曲线验证协议同构。可借鉴：技能修改后不仅对比整体成功率，还跑移除曲线（删 top 排名步骤看性能是否陡降）验证归因稳定性。

六、金句摘录

「Effective skills should be written as compact, decision-complete guidance units, rather than as shorter text or disconnected snippets.」— 高价值技能 = 紧凑、决策完备的指引单元，而非更短的文本或互不关联的片段。

「Skill editing becomes a measurable loop: hypothesize, edit, and re-evaluate, with attribution yielding a clear proposal mechanism rather than blind trial-and-error.」— 技能编辑从盲目试错变成可测量循环。

「Low-value steps are often locally correct but action-incomplete: they provide background facts or isolated helper information without changing the agent's next decision.」— 低价值步骤局部正确但动作不完整：提供背景事实却不改变 agent 的下一个决策。

七、行动启示

  • P0 借鉴（Hermes Skill 治理）：为高频使用的核心 Skill（如 daily-paper-reading、quant-trading 系列）建立步骤级归因档案——按"程序性桥梁"模式审查每个章节块：是否连接条件到决策/操作/回退？不改变下一步决策的背景段落是剪枝候选。工作量大（每技能需跑基准变体），先从 skill-review 的人工审查清单入手
  • P1 借鉴（Skill 写作规范）：将"决策完备单元"写入 skill 模板要求——每个章节块必须回答"agent 读到这一步会改变什么决策"；纯背景知识块迁移到 references/ 而非正文
  • P1 借鉴（skill-stress-test 升级）：压测从"整体带/不带"升级为"移除曲线"协议——按章节逐个移除跑基准，记录性能退化曲线，替代 LOO 式单点对比
  • P2 借鉴（低成本归因近似）：n 大于 10 的技能精确 Shapley 不可行，BAES 的"缓存单翻转边复用"思路可用于设计轻量归因：固定其余步骤、只翻转目标步骤±1 邻居的局部采样
  • P2 观察（强耦合警示）：Hermes 技能中存在装配线式强耦合（如 office-pipeline 的 PPT+DOCX+XLSX 联动），对这类技能做归因时需警惕"结构必要性 ≠ 步骤有用性"
