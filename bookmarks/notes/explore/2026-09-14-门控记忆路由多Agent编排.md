## 核心问题与研究动机

多Agent LLM系统的编排（orchestration）决策——选哪个角色、用哪个骨干模型、给每个Agent看什么、执行多深——存在一个两难困境：

- **Query-only 路由**（仅凭查询决定）：所有决策在任何推理发生之前就锁定，无法响应中间进展、错误或正在出现的解法缺口 → 观察太少，伤准确率
- **Full-history 路由**（凭完整执行历史决定）：每个后续决策都要处理全部先前步骤，包括冗余、低价值甚至错误的推理 → 观察太多，上下文随执行膨胀，推高成本（论文称之为 execution-history overload，执行历史过载）

核心洞察：**路由器应该学会"保留什么、呈现什么、如何基于结果状态行动"**。这要求一个结构化、有选择性的执行记忆作为所有编排决策的共享状态。

## 方法论：Gated-Memory Routing 框架

### 问题形式化

每步 t 的可观察状态 s_t = (q, S_{t-1})，其中 q 是查询，S_{t-1} 是当前执行记忆（保留的执行记录）。系统选择角色 r_t、骨干 m_t、检索上下文子集 C_t，生成推理步 y_t，并决定是否提交记录 e_t = (r_t, m_t, y_t)。记忆是轨迹的门控子集：S_t ⊆ {e_1...e_t}。三条路由范式的本质区别就在于决策所条件化的状态：query-only 只看 q，full-history 看 q + 全部原始轨迹，gated-memory 看 q + 学习出的选择性记忆。

### 五大组件（单一联合训练路由器的互补部件）

1. **Memory Write Gate（记忆写入门）**：新记录仅在"与任务相关 + 相对已存记录新颖"时才写入。写分 ω_t = λ·sim(y_t, c_t) − (1−λ)·max_j sim(y_t, y_j)，λ 为学习系数平衡相关性与冗余度；写决策 w_t ~ Bernoulli(σ(ω_t)) 采样而非贪心 MMR top-1，使记忆构建可训练。记忆为空时退化为仅相关性。跨记录冗余在写入时抑制。

2. **Retrieval Gate（检索门）**：上下文构建是步自适应选择——对每条已存记录独立决定是否呈现给即将执行的Agent。记录嵌入 v_j 融合角色隐向量+骨干隐向量+响应投影；当前步形成检索查询 p_t（查询+刚选定的角色/骨干的融合）。检索 logit ℓ_{t,j} = p_t^T v_j，z_{t,j} ~ Bernoulli(σ(ℓ_{t,j}))。独立采样使 C_t 大小可变：记忆无关时收缩趋空，多条记录相关时扩张。跨记录冗余不在检索时处理（已由写入门在写入时解决）。检索门自身无独立成本项——多检索导致 prompt 变长，成本仅通过轨迹奖励间接支付。

3. **History-Aware Role Allocator（历史感知角色分配器）**：角色不用 categorical ID 而用其文本描述（critic/verifier/debugger 等带语义结构），经 VAE 编码为连续隐角色嵌入 r_i。状态编码器映射 s_t 到上下文向量 c_t，softmax 策略 π_r(r_i|s_t) ∝ exp(c_t^T r_i)。描述式表示支持向相关角色迁移和新增角色扩展，无需改路由接口。

4. **LLM Router（骨干路由器）**：骨干选择是角色条件化的状态策略而非查询级选择。角色条件上下文 u_t 由 c_t 与选中角色表示经学习投影合成；每个候选 LLM 由其自然语言能力描述编码为连续能力向量 m_i（非固定索引）。π_m(m_i|s_t, r_t) ∝ exp(u_t^T m_i)。困难步骤用强模型、记忆已足够时用便宜模型。

5. **Adaptive Halting Controller（自适应停机控制器）**：推理深度是成本主因，但查询时定死深度是在观察执行前就锁死预算。停机决策每步评估：GRU 循环状态 h_t^halt = GRU(h_{t-1}^halt, enc(S_t)) 跨步积分写后记忆的池化摘要（捕捉"最近步骤是否仍在增加证据"的趋势，单步快照无法捕捉），与查询注意力路由上下文 c_t 分离。停机动作 h_t ~ Bernoulli(σ(MLP(h_t^halt)))。因决策在步后评估，至少一个Agent总会执行。停机后存储记录交给 Aggregator LLM 出最终答案（用该查询推理步中最常选的骨干）。

### 优化：GRPO 风格组相对优势

- 轨迹效用 u_i = R_i − λ_c·Cost(τ_i)，R_i ∈ {0,1} 任务成功，Cost 为逐步骨干成本之和
- 每查询采样 G=6 条仅在采样决策上不同的轨迹，组内中心化优势 A_i = u_i − mean，**故意去掉组内标准差归一化**（rollout 奖励趋同时 std→0 会放大微不足道成本差异的优势）
- 损失 L = −mean[log π_i · sg(A_i)] + α·L_VAE − c_H·H̄(π)：策略梯度 + VAE 正则 + 熵项防过早确定性
- LLM 骨干和句子编码器冻结，路由器是唯一训练组件，单一优化器联合更新

## 关键实验结果与数据

### 主实验（Table 1，五基准）

- 骨干池：llama-3.2-3B / llama-3.1-8B / mistral-nemo-12B / qwen-2.5-14B / qwen-2.5-32B（3B-32B 异构池，成本按参数量比例）
- 平均准确率 77.73%，超最强基线 Puppeteer(qwen-2.5-32B) 的 75.29% 达 **+2.44 点**，五基准中四项第一（MATH 79.33 / GSM-Hard 70.55 / HumanEval 89.84 / MMLU-Pro 69.32）
- 对 query-only 的 MASRouter 领先 3.46 点；对 full-history 的 Puppeteer（全程用池中最大 32B 模型）领先 2.44 点——增益非来自规模而来自角色/骨干/记忆的协调质量
- 唯一例外 MBPP（79.60）：固定链式拓扑 MacNet-Chain-14B（82.66）更高——短而均匀的问题受益于强代码模型上的固定流水线，自适应编排空间小

### 成本分析（HumanEval Pareto 前沿）

- 比 MASRouter 便宜 **43.86%**，比 Puppeteer-32B 便宜 **31.9%**，同时比两者都更准——成本与准确率双赢而非交换
- 节省来源：决策条件化在紧凑门控记忆上→停机控制器可在记忆证据足够时早停→简单查询浅执行、只有难查询深执行

### 消融实验（Table 2，留一法）

- **去 LLM router（随机骨干）伤害最大**：GSM-Hard 掉 14.0 点（70.55→56.53）——按当前状态匹配模型容量是答案质量主驱动
- **去停机**是成本杠杆：GSM-Hard 成本 +40%+（0.587→0.840），HumanEval 成本翻倍以上（0.032→0.086），准确率还下滑
- **同时去两记忆门**：GSM-Hard 掉 2.56 点、HumanEval 掉 6.25 点——即使有路由器，选择性记忆依然关键（未过滤上下文稀释决策条件）
- 等深度对比：无停机变体跑满 6 步在 GSM-Hard 达 70.08，仍高于所有 MacNet-32B 变体（61.93-62.31）且成本更低——逐步路由到合适骨干优于全程用最大模型

### 深度预算（Figure 4，MATH）

准确率随最大深度 ϕ 增长但饱和：ϕ=6 已获绝大部分增益，ϕ=6→10 仅多不到 1 点而成本持续攀升。默认 ϕ=6 处于准确率-成本曲线膝点。

### 路由范式直接对比（Table 3）

- GSM-Hard：query-only 66.00/成本1.012，full-history 70.27/0.985，gated-memory 70.55/**0.587**
- HumanEval：query-only 85.16/0.057，full-history 89.06/0.068，gated-memory 89.84/**0.032**
- 关键结论：**full-history 的额外上下文基本不提升准确率**（与精选记忆打平），但门控记忆把成本砍掉约 40-53%——历史要"精选"而非"全量"

### 测试时门控行为（Table 9，附录12）

- 写入率严格落在 (0,1) 内部：GSM-Hard 39.6% / MBPP 32.8% / HumanEval 36.5%——门未塌缩为"全写/全不写"平凡解
- 检索分数随记忆增长**越来越挑剔**（HumanEval 步1-5：91/48/33/24/21%）
- 平均实现深度：2.92-3.79（上限 6），多数查询远未跑满

### 训练时计算（Table 10，附录13）

停机也省训练：无停机时 rollout 步数增至 1.81-1.83×（GSM-Hard 26.5k→47.9k）

## 查询拓展

围绕本论文可进一步追问的方向：

- 开放域生成任务如何奖励？论文承认当前仅用二元任务成功做奖励（可自动验证的封闭域），开放生成需奖励模型或人工评估
- 更骨干池（闭源 API 模型、更大模型）下门控行为是否稳定？论文骨干池止于 32B 开源模型
- 写入门 λ 系数是否可解释为任务内在冗余度的度量？不同基准写入率 32.8%-39.6% 的差异由什么驱动
- 检索门的"步自适应大小"与 RAG 中固定 top-k 检索的对比可否推广到普通 RAG 管线
- GRPO 去掉组内标准差归一化的做法在其他 RL 场景（如 rl-policy 训练）是否同样受益
- 记忆是查询内（单次执行）的，跨查询的持久化执行记忆（经验库）与本文门控机制如何组合

## 创新点分析

1. **范式级重构**：把多Agent编排重新表述为"在学习出的选择性执行记忆上的路由"，干净地区分了三种路由范式（query-only / full-history / gated-memory）并给出 Table 3 的直接对照——证明历史全量条件的边际准确率收益≈0 而成本翻倍
2. **写入门的冗余抑制设计**：相关性（与状态）+ 新颖性（与已存记录 max 相似度）的双项打分，且新颖性项在记忆空时优雅退化；采样式写入（非贪心 MMR）使记忆构建端到端可训
3. **检索/写入职责分离**：写入时压跨记录冗余、检索时独立判相关性，两门各司其职，避免组合爆炸
4. **停机作为成本主杠杆**：GRU 趋势检测（证据增量趋势而非单步快照）+ 每步后评估保证至少一步执行；训练时也省 1.8× rollout
5. **描述式角色/骨干表示**：VAE 隐空间 + 文本描述编码，天然支持角色迁移和新骨干加入——这是路由接口的可扩展性设计
6. **GRPO 变体的工程判断**：去掉组内 std 归一化的理由（奖励趋同时优势被噪声放大）有明确机理

## 局限性与未来方向

- **奖励信号二元化**：仅可验证答案的任务（数学/代码/MCQ），开放生成需奖励模型——作者自认
- **成本模型是代理**：参数量比例定价，不捕捉延迟/显存压力/批处理效应；FLOPs 和 wall-clock 仅覆盖两个基准
- **骨干池偏旧偏小**：Qwen2.5/Llama-3/Mistral 最大 32B，未测闭源 API 模型；作者称可通过能力画像+每token成本替换而不改框架
- **代码未放出**：仓库目前只有 LICENSE，复现依赖作者后续发布
- **记忆无跨查询持久化**：每查询独立，不积累经验
- 单一聚合器 LLM 的鲁棒性未讨论（聚合步选最高频骨干）

## 归纳总结

本文的真正贡献不是又一个多Agent框架，而是给"编排决策该条件化在什么状态上"这个被忽视的问题提供了三选一的实证答案：**精选过的执行记忆 > 全量历史 ≈ 只看查询（准确率上后者两档接近），而精选记忆的成本优势是断崖式的（GSM-Hard 0.587 vs 0.985/1.012）**。五组件（写入门/检索门/角色分配/骨干路由/停机）不是堆料而是分工明确的整体：门控保持记忆高信噪比→路由决策干净→停机可信→成本自适应。消融的分工证据尤其清晰：LLM 路由管准确率（-14点），停机管成本（+40%成本），记忆门管状态质量（-2.6~-6.3点）。EMNLP 2026 Main 录用是对其方法完整性的背书。

## 趋势判断

- **执行状态管理正在成为 MAS 研究的下一个主战场**：从固定拓扑（MetaGPT/ChatDev）→ 拓扑优化（GPTSwarm/AFlow/AgentDropout）→ query-only 路由（MASRouter/RouteLLM）→ 执行条件化路由（Puppeteer）→ **选择性记忆条件化路由（本文）**，演进脉络清晰：每一步都在回答"决策该看什么"
- **成本感知联合训练是标配趋势**：GRPO 式组相对优势 + 轨迹级成本惩罚，与 SPyCE/ReGRPO 等近期工作共享同一方法论家族
- **"门控"作为轻量可学习选择器**正在从 KV Cache（MemDecay 区域感知驱逐）扩散到 Agent 记忆（本文写/检索双门）——同一思想在不同粒度复现，说明"学习式选择"取代"规则式选择"是通用方向
- 与 MAS Information Bottleneck（2607.16133）的理论视角互补：IB 给出 relay 复杂度×模型能力的 gain 矩阵，本文给出工程实现路径（门控记忆压缩 relay 内容）

## 拓展应用推荐

- **Agent 转录本压缩**：任何多Agent系统的中间结果转发都可套用"写入时判冗余 + 检索时判相关"双门模式，替代朴素的全程转发
- **RAG 上下文构建**：检索门的"每记录独立伯努利 + 大小自适应"可替换固定 top-k，长上下文成本敏感场景直接适用
- **早停机制设计**：GRU 趋势积分 + 步后评估的停机模式，可移植到任何迭代式 pipeline（自动研报生成、多轮 tool-use 循环）
- **成本感知 GRPO**：去掉组内 std 归一化的细节对自训 RL 策略（如机器人技能训练）有直接参考价值

## 指南分析：对 Hermes Agent 的借鉴点

- 🔨 P0 — cron/子任务编排的"停机"显式化：当前 delegate_task/多步工具调用循环缺少"证据已足够即停"机制，可借鉴本文在每步后评估（GRU 趋势或简化为"连续 N 步记忆无实质新增"规则）早停，直接降 token 成本（本文证据：HumanEval 成本省 31.9-43.9%，等价于砍掉冗余后续步）
- 🔨 P0 — 转发前冗余过滤：session 上下文/Hermes 消息链路中，工具输出转发给后续步骤前做"相关性+新颖性"双项打分（可用嵌入相似度实现 ω_t 公式的简化版），对应本文写入门——上下文工程四支柱中"工具输出修剪"的具体可学习实现
- ⚠️ P1 — 骨干路由的描述式注册：free-model-apis 免费模型池（智谱/HF/GitHub Models）可给每个模型建"能力描述向量"，按任务状态选模型而非固定默认——本文 π_m 的 softmax 接口可直接套用，但需先积累各模型在真实任务上的能力画像
- ⚠️ P1 — Jetson 边缘部署：写入/检索门是纯小头网络（嵌入+点积），可在 Jetson 上实时跑；对多模型本地推理（Ollama 池）做步级模型选择，3B/8B/14B 混合调度降功耗
- ❌ P2 — 量化交易场景：多Agent协同在量化决策中收益不明（信号融合≠多步推理），暂不适用；但 GRPO 去 std 归一化对 rl 策略训练有参考价值
