KVarN: KV-Cache 量化后端（本地模型部署）

日期: 2026-08-23 | 来源: Huawei CSL / arXiv:2606.03458 / GitHub huawei-csl/KVarN

摘要

KVarN 是华为 CSL 团队开源的原生 vLLM KV-Cache 量化后端，专为 agentic 与长上下文场景设计。核心承诺：

  • 3–5 倍 KV-Cache 容量（同等显存下可容纳更长上下文 / 更多并发）
  • 吞吐高于 FP16（up to ~1.3×）
  • FP16 级精度（AIME25 59.3% vs FP16 59.4%）
  • 零校准（calibration-free），一个 CLI flag 即可启用，不改模型权重
  • 默认出厂配置 kvarn_k4v2_g128: Key 4-bit、Value 2-bit、group size 128

关键发现

1. 技术原理：四步流水线

  1. Cache — 原始 FP16 KV 瓦片（channels × tokens）
  2. Rotated Cache — 沿 channel 维度做 Hadamard 旋转，把 per-channel 离群值打散，正交变换不破坏 attention 分数
  3. Normalized Cache — Sinkhorn 式迭代方差归一化：log 空间内行列交替做标准差归一，把瓦片内方差打平，缩小舍入误差
  4. Quantized Cache — 非对称 round-to-nearest，读回时再反 fold 缩放因子（Key 按 channel，Value 按 token）

2. 与 FP8 / TurboQuant 的定位差异

方案 位宽 校准 精度退化 备注
vLLM FP8 8-bit 可选（random token / llm-compressor） 几乎无损 生产安全线，换显存不换吞吐
TurboQuant 4-bit 需要 中等 需离线标定
KVarN Key 4 / Value 2 零 极低 首个支持 MLA / Qwen3.6 的亚 8-bit 方案
通用 INT4 KV 4-bit 必须 较高 推理长序列易崩

3. 推理误差的伪解码（pseudo-decode）建模范式

KVarN 的论文贡献之一是把评测环境改成"伪解码"：每 b 个 token 就把刚产生的 K/V 量化后再写回 KV-cache，让量化误差像真实推理一样逐步累积。在这种严苛设置下 KVarN 在 MATH500 / AIME24 / HumanEval 上达到 2-bit 精度下的新 SOTA，远超 KIVI、Scissorhands、KVQuant 等。

4. 支持范围

  • 原生 vLLM attention backend，Apache 2.0
  • 与权重量化兼容：可在 AWQ INT4 / compressed-tensors 模型上叠 KV 量化，收益相加
  • 混合架构友好：Qwen3.6-27B 这类 linear-attention + Mamba 混合模型，自动只量化 full-attention 层
  • MLA 支持：首个支持 Multi-head Latent Attention 的亚 8-bit KV 量化后端
  • 已有人 port 到 MLX（Apple Silicon），mlx-kvarn 项目声称可达 ~4.7× KV 容量

对工作的价值

直接影响 jbot/ubot 本地部署路径：
- 本地 Hermes 跑长上下文 Agent 时，KV-Cache 往往是显存墙（比权重大），KVarN 可让 24GB 显存跑 128K 以上上下文
- 与现有 AWQ / GGUF 权重部署叠加使用，无侵入
- 零校准门槛意味着不用离线跑标定脚本，cron/edge 环境友好
