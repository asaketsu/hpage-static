# 实盘模拟 vs 真实交易的技术差异（滑点、延迟、熔断）

> **摘要**：量化策略从回测/模拟走向实盘，最大的鸿沟不是策略本身，而是**市场环境、执行机制和系统约束**的根本性差异。本文系统梳理滑点、延迟、熔断三大核心差异维度，结合 A 股实盘场景，给出从模拟到实盘的渐进式验证路径。
>
> ⚠️ **来源说明**：本文基于本地已有项目文档（ths-auto-trader 回测框架、通达信 tdxquant 模拟交易、TradingAgents 研究）和领域知识整合，未能实时搜索验证（Tavily/DDG 均故障）。关键结论需后续联网验证。

## 一、核心发现

### 发现 1：滑点（Slippage）是回测与实盘最大偏差来源，固定滑点模型严重低估真实损耗

| 维度 | 回测/模拟 | 实盘 |
|------|----------|------|
| **滑点模型** | 固定百分比（如 0.1%）或零滑点 | 动态、非对称、依赖流动性 |
| **买入滑点** | 通常忽略或低估 | 实际成交价往往**高于**信号价（追单效应） |
| **卖出滑点** | 通常忽略或低估 | 实际成交价往往**低于**信号价（恐慌性抛售） |
| **极端行情** | 无法模拟 | 流动性枯竭时滑点可达 3-5% 甚至更多 |

**关键细节**：
- 回测引擎（如 ths-auto-trader 的 `BacktestEngine`）使用固定滑点 0.1%（买卖各 0.1%），这在震荡市中尚可接受，但在**开盘集合竞价、尾盘抢筹、涨跌停附近**等场景完全失效
- A 股实盘滑点的三大驱动因素：
  1. **买卖盘口深度**：买一/卖一挂单量不足时，市价单会"吃穿"多个价位
  2. **信号触发时机**：策略在收盘前发出信号，但实际委托到达交易所时价格已跳变
  3. **T+1 约束**：当日买入无法当日卖出，回测中若忽略此约束会严重高估策略收益

**改进建议**：
- 回测滑点模型应从"固定百分比"升级为"**盘口深度感知滑点模型**"：根据历史 Level-2 数据模拟不同委托量下的实际成交价位
- 引入"**冲击成本曲线**"：委托量越大，单位滑点越高（非线性）
- 实盘前必须做 **Paper Trade（纸面交易）** 至少 1-2 周，对比信号价与实际成交价的偏差

### 发现 2：延迟（Latency）在高频/日内策略中是生死线，UI 自动化方案天然处于劣势

| 延迟环节 | UI 自动化（xdotool/easytrader） | 券商 API（QMT/PTrade） | 穿透式接口 |
|----------|-------------------------------|----------------------|-----------|
| **行情获取** | 秒级（GUI 渲染后读取） | 毫秒级（WebSocket 推送） | 微秒级（交易所直连） |
| **信号生成** | 取决于策略复杂度 | 同左 | 同左 |
| **委托发送** | 秒级（模拟鼠标点击） | 毫秒级（HTTP/gRPC） | 微秒级 |
| **成交回报** | 秒级（轮询 GUI） | 实时推送 | 实时推送 |
| **端到端延迟** | **2-10 秒** | **50-200ms** | **<1ms** |

**关键细节**：
- 对于**日线级别趋势跟踪策略**（如 ths-auto-trader 的策略 A/B/C），2-10 秒延迟影响不大，因为信号本身基于日线/小时线，价格变动相对缓慢
- 但对于**分钟级/秒级策略**（如 60 分钟布林带均值回归），延迟会导致：
  - 信号触发时价格已偏离，实际入场价比回测差 0.5-2%
  - 止损信号发出后，价格可能已跌破止损线 1-2 个价位
  - 撤单操作来不及执行，已成交的委托无法撤回
- **同花顺 xdotool 自动化**的窗口定位、坐标漂移问题（已在本地笔记中详细分析）进一步放大了延迟不确定性

**改进建议**：
- 日线/波段策略：UI 自动化方案可接受，但需增加**委托超时熔断**（如 60 秒未成交自动撤单）
- 分钟级策略：必须升级到 **QMT/PTrade 等券商量化接口**
- 任何自动化系统都必须有**心跳检测 + 自动降级机制**（如 ths-auto-trader 设计的 10s 心跳，超时 30s 自动降级）

### 发现 3：熔断机制在模拟与实盘中的"真实性"差异巨大

| 熔断类型 | 模拟环境 | 实盘环境 |
|----------|---------|---------|
| **涨跌停限制** | 可模拟（代码拦截） | 真实存在，但**涨停板封单量**无法模拟 |
| **账户级熔断** | 可模拟（如单日亏损>3% 清仓） | 真实执行，但可能触发**流动性危机**（大量抛售导致进一步下跌） |
| **交易所熔断** | 通常不模拟 | 沪深 300 指数跌幅>7% 时全市场停牌 |
| **券商风控拦截** | 无法模拟 | 券商系统会拦截异常委托（如价格偏离>2%、数量超限） |

**关键细节**：
- 模拟环境中，"涨停不买、跌停不卖"只是代码逻辑，但实盘中：
  - **涨停板封单量**决定了你是否有机会买入（可能封单 100 万手，你排队永远排不到）
  - **跌停板抛压**决定了你能否卖出（可能无人接盘，挂跌停也卖不出去）
- 实盘中的**券商风控拦截**是模拟环境完全缺失的一环：
  - 同花顺/券商客户端会拦截异常价格委托（偏离现价>2%）
  - 单笔委托数量超过阈值会被拒绝
  - 频繁撤单可能被认定为"异常交易"而受到监管关注
- **账户级熔断的连锁反应**：模拟中清仓只是数字变化，实盘中大量抛售可能：
  - 触发个股跌停
  - 引发其他量化策略的连锁止损
  - 在极端行情下造成"踩踏"

**改进建议**：
- 回测中必须加入"**涨停板不可买入、跌停板不可卖出**"的硬性约束（ths-auto-trader 已实现）
- 实盘前进行"**压力测试**"：在历史极端行情（如 2015 年股灾、2024 年 2 月微盘股崩盘）中回测，观察熔断触发后的策略表现
- 设计**分级熔断**（ths-auto-trader 五层风控架构）：
  - Layer 5: 账户级 — 单日亏损>3% → 全部清仓 + 锁定系统
  - Layer 4: 策略级 — 单策略连续亏损 3 次 → 暂停该策略
  - Layer 3: 持仓级 — 单票仓位<20%，总仓位<80%
  - Layer 2: 委托级 — 价格偏离、数量异常、涨跌停拦截
  - Layer 1: 实时监控 — 账户资产波动、网络状态、客户端存活

## 二、技术细节

### 2.1 滑点建模的进阶方法

```python
# 固定滑点模型（回测常用，过于简化）
slippage = 0.001  # 0.1%

# 盘口深度感知滑点模型（推荐）
def estimate_slippage(order_size, bid_depth, ask_depth, avg_volume):
    """
    根据委托量与盘口深度估算滑点
    order_size: 委托数量
    bid_depth: 买一~买五的挂单总量
    ask_depth: 卖一~卖五的挂单总量
    avg_volume: 近 20 日均成交量
    """
    # 委托量占日均成交量比例
    volume_ratio = order_size / avg_volume
    
    # 委托量占盘口深度比例
    depth_ratio = order_size / min(bid_depth, ask_depth)
    
    # 基础滑点 + 冲击成本
    base_slippage = 0.0005  # 0.05%
    impact_cost = 0.002 * (volume_ratio ** 0.5) + 0.01 * (depth_ratio ** 1.5)
    
    return base_slippage + impact_cost
```

### 2.2 延迟敏感型策略的延迟预算

```
策略类型          最大可容忍延迟    推荐通道
─────────────────────────────────────────
日线趋势跟踪        >10 秒          UI 自动化 (xdotool)
小时线均值回归       1-5 秒          UI 自动化 + 超时熔断
分钟线动量          200-500ms       券商 API (QMT/PTrade)
秒线/Tick 级        <50ms           穿透式接口
```

### 2.3 实盘验证的渐进式路径

```
回测 (历史数据) → 样本外测试 → Walk-Forward → Paper Trade (1-2 周) → 
小资金实盘 (1-3 个月) → 逐步放量
    ↑                                              │
    └──── 任一环节不达标则返回调参/优化 ←────────────┘
```

**关键门槛**（ths-auto-trader 标准）：
- 样本内夏普 > 1.0，样本外夏普 > 0.8
- 最大回撤 < 15%
- 至少 3 年历史数据回测
- Walk-Forward 衰减 < 30%
- Paper Trade 实际收益率与回测偏差 < 20%

## 三、实践启发

### 3.1 对 ths-auto-trader 项目的直接影响

| 现有设计 | 问题 | 改进方案 |
|----------|------|---------|
| 回测滑点固定 0.1% | 严重低估极端行情损耗 | 升级为盘口深度感知模型 |
| UI 自动化延迟 2-10 秒 | 分钟级策略不可用 | 增加 QMT/PTrade 通道适配层 |
| 五层风控架构 | 设计完善但未实盘验证 | Paper Trade 期间重点监控熔断触发率 |
| 无涨停板封单模拟 | 无法评估"买不到/卖不出"风险 | 引入历史 Level-2 封单数据回测 |

### 3.2 通用建议

1. **永远不要相信回测结果**：回测是"理想世界"，实盘是"现实世界"，两者差距可能高达 30-50% 的收益衰减
2. **Paper Trade 是必经之路**：至少 1-2 周，覆盖不同市场状态（震荡、上涨、下跌）
3. **从小资金开始**：实盘初期用 1-5% 资金测试，确认系统稳定后再逐步放量
4. **建立"实盘偏差日志"**：记录每次信号价与实际成交价的差异，累积数据后可优化滑点模型
5. **熔断机制宁可过度设计**：实盘中一次"意外"可能导致重大损失，多层熔断是保险丝
