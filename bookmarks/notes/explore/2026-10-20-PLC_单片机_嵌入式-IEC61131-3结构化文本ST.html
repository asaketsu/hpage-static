摘要

结构化文本（Structured Text, ST）是 IEC 61131-3 标准定义的五种 PLC 编程语言中的高级文本语言，以 Pascal 为基础、块状结构。它是 PLC 世界里唯一能优雅承载复杂算法/数学运算/数据结构的语言，可与梯形图（LD）、功能块图（FBD）在同一工程内混合编程。与 MCU 开发的根本差异在执行模型：ST 程序运行在 PLC 的周期扫描模型上（每周期从头执行一遍，状态由变量持有），而非 MCU 的 main 循环+中断。各厂商实现存在方言差异（西门子 SCL 不支持动态数组、三菱 FBD 接口受限），Codesys/TwinCAT 是最贴近标准的实现。

关键发现

1. 五语言家族中的定位

IEC 61131-3 规定了五种 PLC 编程语言，统一了各厂商编程规范（来源：CN120353708B 专利背景）：

图形语言（3种）                    文本语言（2种）
├─ LD  梯形图（电气工程师首选）      ├─ ST  结构化文本（Pascal 基础，算法强）
├─ FBD 功能块图（数据流风格）        └─ IL  指令表（汇编风格，已趋淘汰）
└─ SFC 顺序功能图（状态/流程）
  • 所有语言共享 IEC 61131 通用元素（变量定义、函数调用），因此同一个程序里可混用不同语言——逻辑用 LD、算法用 ST 是工程常态
  • ST 类似 Pascal/C，可完成梯形图难以执行的复杂计算；常用回路封装成 FB（功能块）复用

2. 核心语法速览（维基实例）

(* 状态机：CASE 分发 *)
TxtState := STATES[StateMachine];
CASE StateMachine OF
  1: ClosingValve();
ELSE
  ;; BadCase();
END_CASE;
  • 赋值是 :=，注释是 (* ... *)，逻辑等号是 =
  • 控制流：IF-THEN-ELSE / CASE-OF / WHILE-DO / REPEAT-UNTIL
  • 内置函数：SQRT()、SIN() 等数学函数直接可用
  • 变量分区声明是 ST 的标志性结构：
FUNCTION_BLOCK FB_Timed_Counter
  VAR_INPUT   Execute : BOOL := FALSE;  Time_Increment : REAL := 1.25; END_VAR
  VAR_OUTPUT  Count_Complete : BOOL;    Current_Count  : INT;          END_VAR
  VAR         CycleTimer : TON;         CycleCounter : CTU;            END_VAR
  ...
END_FUNCTION_BLOCK
  • 直接地址映射：Start_Stop AT %IX0.0 : BOOL;（%I 输入/%Q 输出/%M 中间继电器）
  • 配置级调度：TASK Tick(INTERVAL := t#20ms); PROGRAM Main WITH Tick : ...——任务周期在 CONFIGURATION 层声明，不在代码里 sleep

3. 执行模型：扫描周期 vs 中断（与嵌入式 C 的本质差异）

维度 PLC/ST MCU/C
程序生命周期 每扫描周期完整执行一遍（读输入→执行→写输出） main 循环 + 中断 ISR，时序由开发者构造
状态保持 靠变量跨周期持有 靠 static/全局变量/硬件外设
定时 TON/TOF 功能块，时间语义内建 定时器外设/RTOS tick，自己算
看门狗 扫描超时自动停机（安全设计的一部分） 手动喂狗
  • 这解释了为什么 ST 没有也不需要 delay()：周期模型下 delay = 阻塞整个扫描 = 看门狗停机
  • FB 实例（如 CycleTimer : TON）自带状态记忆——调用式语法 CycleTimer(in := ..., pt := ...) 传参即驱动，与 OOP 对象相似

4. 厂商方言差异（工程选型必读）

来源：CN120353708B 背景技术段——各软件对五语言支持参差：

  • 西门子 TIA Portal：ST（称 SCL）不支持动态数组或复杂指针操作
  • 信捷等国产软件：SFC 仅支持线性流程，无并行分支/状态嵌套
  • 三菱 GX Works3：FBD 无法自定义功能块接口
  • Codesys / 倍福 TwinCAT：最贴近 IEC 标准的第三方生态，ST 是一等公民（CSDN 教程即以 TwinCAT 的 POU/PRG 结构为例）

工程含义：ST 代码跨厂商移植性优于 LD（文本 diff 友好），但标准之外各家的数组/指针/结构体支持必须查手册，"标准"不等于"可移植"。

5. ST vs LD 选型逻辑

  • 用 ST：复杂数学运算、字符串/数组处理、状态机、PID 等算法封装、通信协议解析
  • 用 LD：简单联锁逻辑、电气背景维护人员的可读性要求
  • 混合策略：底层 I/O 联锁用 LD，工艺算法用 ST 封装成 FB，两边各取所长

对现有工作的价值（关联分析）

  • 飞机设计企业场景：航空地面试验设备（测试台架、液压/电气试验、空调舱）大量使用 PLC。企业内 ST 能力 = 看懂试验台控制逻辑、与设备供应商对线的语言能力；适航验证中的设备控制软件评审也会遇到 IEC 61131-3 语境
  • 对 embedded-firmware-dev / esp-idf 系 skill 的互补：嵌入式技能栈以 MCU 为中心，ST 笔记补上"工业控制另一大阵营"的认知——两者在传感器/执行器思维上同源，在执行模型（扫描 vs 中断）上分叉。后续遇工业自动化需求时，先判阵营再选栈
  • P1 建议给 esp32-unit-test-mock-setup 或嵌入式测试 skill：PLC 扫描模型天然适配"仿真步进测试"（把一个扫描周期当作一次 tick 调用），其 TON/CTU 状态可预测性比 MCU 中断时序更好测——这个思想可反向用于嵌入式固件的确定性测试设计（firmware-host-loop-testing skill 的宿主机全环测试正是同构做法）

Actionable Insights

  1. 需要 PLC 快速原型验证算法时，选 Codesys（免费 IDE + 软 PLC runtime），避开厂商方言
  2. 读 ST 代码先找三样东西：VAR 区（状态全貌）→ 周期 TASK 频率（时间尺度）→ FB 实例（行为单元），比逐行读高效
  3. ST 的 AT %IX0.0 地址映射与舵机 EEPROM 三档映射（zero/min/max）思路同构：物理层地址/参数与逻辑名分离——跨域复用配置管理思想

关键风险与盲点

  • 标准演进风险：IEC 61499（分布式、事件驱动）被视为 61131-3 的继任者，工业界采纳缓慢但趋势存在；新项目选型需确认是否涉及（来源：行业共识，本次未深挖，标注为待验证）
  • 方言陷阱（官方专利文件佐证）：TIA Portal SCL 无动态数组/复杂指针——把 PC 端 C 思维的代码直译 ST 会在西门子平台撞墙
  • IL 已过时：教程市场仍有 IL 内容，新学习路径应直接跳过
  • 来源级别说明：五语言构成/厂商差异来自专利文件与维基（权威级）；"扫描周期看门狗停机"为行业通用机制（社区共识级，未引用具体手册条款）

一页速查

  • ST = IEC 61131-3 五语言之一，Pascal 基础，算法/数学/数据结构强项
  • 赋值 :=，等号 =，注释 (* *)；IF/CASE/WHILE/REPEAT 四件套
  • 变量三区：VAR_INPUT / VAR_OUTPUT / VAR（内部）——FB 即带状态的对象
  • 执行模型 = 周期扫描：无 delay、无中断，状态在变量里，TON/CTU 是时间语义
  • 地址映射 AT %IX0.0；任务周期在 CONFIGURATION 的 TASK 声明
  • 厂商差异：西门子 SCL 无动态数组；Codesys/TwinCAT 最贴标准
  • 选型：算法用 ST，联锁用 LD，封装成 FB 混编
