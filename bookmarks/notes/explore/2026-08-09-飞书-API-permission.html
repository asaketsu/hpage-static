飞书 API：Permission 权限管理

嗅探学习 · 2026-08-09 · auto-explore
来源：飞书开放平台官方文档 + lark-cli lark-drive skill

摘要

飞书云文档权限系统由「权限成员（Members）」和「权限设置（Settings）」两部分组成。权限 API 分为 V1 和 V2 两个版本，支持对协作者（用户/应用/群/部门）进行增删改查、转移所有权，以及对分享、复制、下载、评论等设置进行管控。

关键发现

一、权限模型（两层结构）

  • 权限成员：文档所有者（owner）+ 协作者（collaborator）
  • 成员权限等级：manageable（管理）> editable（编辑）> readable（只读）
  • 可授权成员类型：普通用户、文档应用（bot）、群组、部门

二、核心 API 清单（permission members）

  • POST /drive/v1/permissions/:token/members — 添加协作者
  • PUT /drive/v1/permissions/:token/members/:member_id — 更新协作者权限
  • DELETE /drive/v1/permissions/:token/members/:member_id — 移除协作者
  • POST /drive/permission/member/permitted — 判断协作者是否有某权限
  • POST /drive/permission/member/list — 获取协作者列表
  • POST /drive/permission/member/transfer — 转移所有者

三、权限设置 API（V1 vs V2）

V1 和 V2 的区别在于管控粒度：

  • V1：GET/PATCH /drive/v1/permissions/:token/public
  • 管控项：外部分享、复制/打印/下载、评论、谁能管理协作者、链接分享
  • V2：GET/PATCH /drive/v2/permissions/:token/public
  • 新增：组织维度 + 协作者维度「谁能管理协作者」分离管控

四、lark-cli 已封装的命令

命令 用途 所需 scope
drive permission.members.create 增加协作者权限 docs:permission.member:create
drive permission.members.auth 权限校验 docs:permission.member:auth
drive permission.members.transfer_owner 转移所有权 docs:permission.member:transfer
drive permission.public.get 读取权限设置 docs:permission.setting:read
drive permission.public.patch 修改权限设置 docs:permission.setting:write_only

五、授权 bot 自身访问文档（常用模式）

# 1. 获取 bot open_id
lark-cli api GET /open-apis/bot/v3/info --as bot

# 2. 授权 bot 访问文档
lark-cli drive permission.members create \
  --params '{"token":"<doc_token>","type":"<resource_type>"}' \
  --data '{"member_type":"openid","member_id":"<bot_open_id>","perm":"view","type":"user"}'

resource_type 可选：doc / docx / sheet / bitable / file / folder / wiki / slides

六、permission.public.patch 错误码（实战必知）

  • 91009：对外分享被租户安全策略管控 → 联系管理员
  • 91010：文档未打开对外分享 → 先在 UI 开启分享
  • 91011：密级管控拦截对外分享 → 文档内发起密级豁免
  • 91012：密级管控拦截权限设置 → 同上

对工作的价值

  1. 自动化文档权限管理：批量创建文档时可自动授权协作者，无需手动逐个添加
  2. bot 访问文档的前置步骤：bot 操作任何文档前，必须先被授权权限，这是 lark-doc/lark-drive 自动化链路的必备环节
  3. 权限审计能力：通过 member/list + member/permitted 可批量检查文档权限分布
  4. 密级安全场景：91011/91012 错误码处理逻辑已内置 lark-drive skill，可直接复用

行动建议

  1. 优先使用 lark-cli shortcut：已有 permission.members.create 等封装，无需手写 HTTP 请求
  2. bot 授权模式已标准化：lark-drive skill 中有完整 bot 自授权流程，创建文档后自动执行
  3. V2 API 是未来方向：新项目优先使用 V2，组织/协作者维度分离管控更精细
  4. 密级文档处理：遇到 91011/91012 时需引导用户到文档 UI 操作，API 无法绕过
