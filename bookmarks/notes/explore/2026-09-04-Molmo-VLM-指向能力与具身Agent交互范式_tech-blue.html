Molmo 的"指向"能力：VLM 从描述到指认的范式突破

探索日期：2026-09-04 | 兴趣等级：L3（多模态 AI）| 来源数量：8（arXiv 论文 + Ai2 官方 + The AI Economy + DebugCafe + LearnOpenCV + Opencv.org + BusinessWire + PIO 论文） 前序笔记：explore/2026-07-15-Prefill-Decode分离架构、explore/2026-07-16-CoPE、notes/2026-07-19-嵌入式AI-TinyML现状（Molmo 可作为端侧 VLM 候选）

摘要

AllenAI 于 2024-09 发布 Molmo（arXiv:2409.17146v2），核心突破并非单纯 SOTA 分数，而是引入了一种全新的 VLM 交互接口——"Pointing（指向/像素坐标指认）"。模型不只需要用自然语言回答问题，还要在图片上用 (x, y) 坐标指出答案所依据的具体像素位置。

2025-12，Ai2 发布 Molmo 2（arXiv:2601.10611v4），将 Pointing 扩展到视频时空维度（VideoPoint + VideoTrack），8B 模型在多项视频 grounding benchmark 上超越 GPT-5 与 Gemini 2.5 Pro，同时超越 Molmo 原始 72B 版本。

核心价值判断：Pointing 不只是一个任务，而是一种将 VLM 从"阅读器"升级为"行动者"的关键接口——具身机器人、Web Agent、GUI 自动化都能通过"指向一个坐标"直接触发物理/数字动作，跳过了 NLP→结构化指令→执行的额外映射层。

核心发现（6 个）

发现 1：Pointing 是 VLM 的"第三模态"接口——比 bbox 和 mask 更低成本但同样有力

  • 传统 VLM grounding 使用 bounding box（4 个数）或 segmentation mask（整图二值图，1-4M bits）
  • Molmo 用 pointing（1 个点 = 2 个数，float32 x, y），标注成本只有 mask 的 1/1000
  • PixMo-Points 数据集：1.98M unique referring expression instances，每个 expression 平均 5.5 个 pointing 点；总共 2.3M+ grounding annotations
  • 论文原文论据："Using points enables us to collect grounding data much faster than would be possible using bounding boxes or segmentation masks since it is much easier to annotate"
  • ⚠️ 标注经济学洞见：pointing 的低成本 ≠ 表达能力弱——因为 1 个 object 可被指 5+ 点，密集点云隐式编码了 object 的形态

发现 2：Pointing 是 counting（计数）的隐式推理机制——"模型通过指认来计数"

  • Molmo 在 counting 任务上的做法不是输出一个数字，而是先指向每个被计数的对象，再统计指向数
  • 2025-12 Molmo 2 论文在 VideoCount benchmark 中，8B 模型超过 GPT-5 和 Gemini 2.5 Pro
  • 2026-06 新论文《Thinking with Visual Grounding》(arXiv:2606.16122v1) 进一步证实：point grounding 在 counting 上稳定优于 box grounding——因为 counting 只需要 instance-level localization，不需要 full extent
  • 这一发现与 Hermes 的"Agent 推理透明化"目标高度一致：指向 = 可见的推理链，模型"展示证据"而非"输出结论"

发现 3：具身 Agent 交互范式的原生支持——"指一个点" = "给机器人一个目标"

论文明确写道：

"we believe it will open up an important future direction in which VLMs enable agents (e.g., robots, web agents) to act by pointing in their environments, e.g., to a navigation waypoint, to an object to pick up, or to a user interface button to press"

这与我们当前 DUCK-Pi_5 项目（具身双足机器人）高度相关： - Vision→Action 直接通路：相机图像 → VLM 指出"要抓取的杯子中心点" → 末端执行器移动到该点 - 跳过了传统的 detect→segment→centerpoint 三阶段 CV 管线，用一个模型完成 - Hermes 映射：Molmo 可作为 Jetson 端侧 VLM 候选（见下方 Actionable Insights）

发现 4：8B 模型超越 72B 模型——数据质量 + 训练配方 > 参数规模

模型 参数量 视频 grounding 排名
Molmo 2 (8B) 8B 🥇 VideoPoint + VideoCount SOTA（开放模型）
Molmo (72B) 72B 被 Molmo 2 8B 超越
Molmo 2 (4B) 4B 工作站可跑，保持强 grounding

核心归因： 1. PixMo-Points 指向预训练（而非只用 synthetic 数据） 2. 改进的 vision encoder（从 ViT-L/14 CLIP 升级到更强版本） 3. Token-weighting（连接层新增的 pooling 权重策略） 4. 数据配比：用 <1/8 的视频数据 训练，超越 Meta 模型

这与 Hermes 的"检索策略才是真正的 alpha"完全同构——训练数据策展 > 模型规模。

发现 5：架构细节——multiscale multi-crop + connector pooling 是高分辨率推理的关键

Molmo 架构（4 组件）：

[输入图像] → ① Pre-processor (multiscale, multi-crop)
              → ② ViT-L/14 336px CLIP (per-crop 独立编码)
              → ③ Connector (MLP projection + pooling → 减少 token 数)
              → ④ Decoder-only LLM (OLMo/Qwen2)

关键设计决策： - multiscale multi-crop：一张原图切成 4 张不同尺度的子图分别编码，保证细节区域（如钟表指针）和大范围语义同时可见——这是 clock reading 和 pointing 高精度的基础 - connector pooling：视觉 token 数量从 (336/14)²×4crop = 2304 tokens 压缩到可控范围，避免视觉 token 淹没语言 token - 支持 3 种 vision encoder（ViT-L/14 CLIP / SigLIP / MetaCLIP），保持同训练 pipeline

发现 6：VideoPoint + VideoTrack 联合训练 = 互相增益

Molmo 2 论文（2601.10611v4）消融实验：

配置 J&F F1 HOTA
Tracking only 64.9 70.0 68.4
Tracking + Pointing 65.7 71.1 69.4
+ Molmo2 (VideoTrack) 数据 64.9 70.0 68.4
  • Pointing 作为 auxiliary task 时，tracking 精度全面提升（F1 +1.1, HOTA +1.0）
  • 跨任务正迁移：让模型"指认每一帧中的目标位置"训练了更精确的时空对齐能力
  • 数据配比（9 个新开放数据集，含 0.80M video track instances）

Actionable Insights

1. 端侧具身机器人视觉管线选型（针对 DUCK-Pi_5）

当前方案：传统 CV（OpenCV 特征匹配）+ 规则 → 目标点

升级方案：Molmo 4B/8B ONNX/GGUF 量化部署到 Jetson - 输入：相机 RGB 图像 - 输出：目标点 (x, y) + 可选语义标签 - 优势：一个模型同时完成"识别是什么"+"在哪里" - 挑战：推理延迟（4B ~30-60 FPS on Jetson 未验证；8B 需 FP8 量化）

实验清单： 1. 在 Jetson Orin Nano 上加载 Molmo 4B GGUF q4 量化版本 2. 测量端到端延迟（相机→pointing 输出） 3. 对比传统 OpenCV + YOLO 管线的精度与鲁棒性

2. Hermes 自身：GUI Agent 自动化

Pointing 接口可以直接用于 Web/Desktop 自动化： - 输入：屏幕截图 - 输出：要点击的按钮坐标 - 与当前 vision-image-recognition skill 结合：当前 skill 是"识别"，Molmo 可升级为"识别+定位"

3. 数据策展启发（"数据才是 alpha"）

Molmo 的成功关键在于 PixMo-Points 自采数据集，而非依赖 GPT-4/Claude 合成的数据。这提示 Hermes 的知识库建设方向： - 高质量人工标注 > 大量合成数据 - Hermes 当前 error-case-library（错误案例库）的本质就是一份"人工标注的失败模式图谱"——与 PixMo-Points 的思路同构 - 建议：给 error-case-library 添加"定位标签"（哪个 skill / 哪段代码出了问题），实现类似 pointing 的精确归因

4. 量化 Agent 的 grounding 类比

Molmo 的 Pointing 让模型"指认证据"；量化 Agent 也需要"指认信号源"——当发出买入信号时，必须指出"是 MA20 上翘 + 放量 + 板块效应共振 三个证据指向买入"，而非只输出"买"。Pointing 在视觉域的实现，是"证据链透明化"在模态域的自然体现。

风险/盲点 来源 严重度

一页速查

🎯 一句话：Molmo 引入"Pointing（像素坐标指认）"作为 VLM 的第三交互接口——比 bbox 低成本 1000×，让 VLM 从"描述图片"升级为"指向图片"，为具身 Agent 打开原生 Vision→Action 通路。

架构口诀：

多尺度多裁图 → ViT 编码 → Connector Pooling → LLM 解码 数据核心：PixMo-Points 1.98M expressions × 5.5 点/expr 训练秘诀：Pointing 预训练 + 计数通过指向实现 + VideoTrack 联合训练

Molmo 家族选型表：

MolmoE-1B → 超轻量，近 GPT-4V 精度 Molmo 7B-O（OLMo） → 完全开源（Apache-2.0） Molmo 7B-D（Qwen2） → 最佳 7B 演示 Molmo 72B（Qwen2） → 最佳精度，被 8B 反超 Molmo 2 4B → 工作站可跑，强 grounding Molmo 2 8B → 视频 grounding SOTA，超越 72B

与 Hermes 的 3 个直接连接点：

① DUCK-Pi_5 视觉导航 → Molmo 4B 端侧部署候选 ② GUI/Web Agent 自动化 → Pointing = 点击坐标 ③ error-case-library → 类比 PixMo-Points 的精确归因（标注"哪段代码出错"）

关键数据点：

1.98M referring expressions | 2.3M pointing annotations | 5.5 点/expr 8B 超越 72B | Video grounding 仍 <40% 精度 | 数据用量 <Meta 1/8
