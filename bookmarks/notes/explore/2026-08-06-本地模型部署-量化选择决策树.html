本地模型部署：量化选择决策树 — 2026 全格式选型指南

探索日期：2026-08-06 | 兴趣等级：L2（本地模型部署） | 来源数量：8 | 前序笔记：消费级GPU推理、oMLX SSD KV-Cache

核心问题

前序笔记《消费级GPU推理》给出了"显存→模型规模→量化格式"的粗粒度决策链，但在实际部署中，最让人困惑的恰恰是量化格式的细分选择：GGUF 有 Q2_K 到 Q6_K 十余种子类型，AWQ 与 GPTQ 在 4-bit 下哪个更好，FP8/NVFP4/MXFP4 这些 2026 新格式的适用边界在哪里，以及何时该用 PTQ（后训练量化）vs QAT（量化感知训练）。本文构建一个从硬件能力出发、以精度需求为终点的系统化决策树，覆盖从 1.58-bit 到 FP8 的完整光谱。

核心发现

1. 决策树主干：硬件代际决定可选格式集

量化格式的选择不是自由组合，而是被硬件 tensor core 支持的精度等级硬性约束。2026 年的硬件可以划分为三代精度能力：

  • Ampere/Ada（A100/RTX 3090/4090）：原生 INT8/INT4 + FP16/BF16。FP4 tensor core 不存在，任何 FP4 格式都退化为模拟执行。INT4 fused kernel 可用但无原生 tensor core 加速。
  • Hopper（H100/H200）：原生 FP8（E4M3/E5M2）tensor core，这是 2026 数据中心的性价比甜点——显存减半、吞吐 +40-70%、MMLU-Pro 回退仅 -0.3~-0.5 分（benchmark 噪声范围内）。但无 FP4 硬件支持，NVFP4 在 Hopper 上仅做 emulation。
  • Blackwell（B200/B300/RTX 5090/RTX PRO 6000）：原生 NVFP4/MXFP4（E2M1）tensor core，compute capability 10.0。这是唯一能从硬件层面受益于 4-bit 浮点的平台。RTX 5090 上 Llama-3.3-70B MXFP4 获得近 4× 推理加速（对比 BF16），B200 上为 2.2×。

关键约束：你不能在 RTX 4090 上选 NVFP4 并期待加速——它会 fallback 到 FP16 emulation，反而更慢。格式选择的第一步永远是确认 nvidia-smi 的 compute capability。

2. GGUF K-quant 子类型的精度-体积 Pareto 前沿

GGUF 是本地部署（CPU/Apple Silicon/消费级 GPU 混合）的事实标准，但 K-quant 家族的十余种子类型常让人困惑。核心机制是 K-quant 对不同权重矩阵使用不同精度（混合精度量化），而非全局统一位宽。实测的 Pareto 前沿：

类型 实际位宽 压缩倍率(vs FP16) WikiText-2 PPL 回退 推荐场景
Q2_K 2.625 bit ~6× 显著（不适合 instruction-tuned） 极端显存受限，仅 base 模型
Q3_K_M 3.4 bit ~4.6× 中等 7B 模型压到 3GB 以下
Q4_K_M 4.5 bit ~3.5× 极小（-2.1% avg） 默认选择，质量/体积最佳平衡
Q5_K_M 5.5 bit ~2.9× 近乎无损（-0.3% avg） 显存充裕时优先
Q6_K 6.56 bit ~2.4× 无损 精度优先，几乎等同 FP16
Q8_0 8.5 bit ~1.9× 无损（-0.1%） 精度基准，存储节省有限

经验法则：Q4_K_M 保留 ~92% FP16 质量，Q5_K_M 保留 ~97%，Q6_K 保留 ~99%。显存够用就往上调一级，成本几乎只是磁盘空间。

3. AWQ vs GPTQ：4-bit GPU 量化的两条路线

两者都是 PTQ（后训练量化），都需要校准数据集，但方法论根本不同：

  • GPTQ：基于 OBS（Optimal Brain Surgeon）的逐层误差补偿。通过 Hessian 逆矩阵最小化量化引入的输出误差。计算开销高（Hessian 逆），但通用性好（3-bit/4-bit 均可）。在 NVIDIA tensor core 上吞吐强（+20%），适合原始吞吐量优先的 GPU 集群场景。
  • AWQ（Activation-aware Weight Quantization）：通过分析激活值分布识别"重要权重"（salient channels），仅对重要权重保持高精度，其余激进量化。计算开销低（无需 Hessian），质量比 GPTQ 更好（MMLU -1.6 vs GPTQ -1.9），支持 INT4 fused kernel。适合精度敏感应用（创意写作、代码生成）。

2026 年的共识：AWQ 已在质量上超越 GPTQ，GPTQ 的优势仅存于特定 NVIDIA 硬件的 raw throughput。新部署首选 AWQ，已有 GPTQ 基础设施可保留。

4. 2026 新前沿：FP4 浮点量化（NVFP4/MXFP4）

这是 2026 年最重要的量化进展。MXFP4 是 OCP 开放标准（block-scaled 4-bit FP，32 值共享一个 exponent），NVFP4 是 NVIDIA 在 Blackwell 上的硬件实现（E2M1 格式，与 MXFP4 checkpoint 兼容）。

关键发现（arXiv:2509.23202v2 首个系统性实证研究）：

  • 端到端加速真实存在：B200 上 Llama-3.3-70B MXFP4 vs BF16 → 2.2× 端到端加速；RTX 5090 上 → 近 4× 加速（因为 5090 的显存带宽是更大瓶颈，低精度优势更显著）
  • 精度回退可控：层级分析显示 weight-only 量化可达到近理想加速，但 activation 量化是瓶颈——朴素 FP4 activation 量化会导致显著精度损失，需要 QuaRot/SpinQuant 等旋转方法预处理
  • 训练场景反转：NVFP4 在推理上优秀，但在训练上可能输给 BF16——因为反向传播需要高精度梯度，FP4 的舍入误差会累积。NVIDIA 自家的 MaxText/JAX NVFP4 recipe 报告 1.31-1.73× 训练加速，但仅在特定配置下可复现
  • 硬件硬门槛：只有 Blackwell（SM100）有 FP4 tensor core。H100/H200/A100/RTX 4090 全部不支持

5. 极端量化：1.58-bit 三值化（BitNet/Ternary Bonsai）

PrismML 在 2026 年 3-4 月发布的 Bonsai 系列将量化推到了极限。三值量化（权重仅 {-1, 0, +1}，每参数 ~1.58 bit）的理论压缩比为 10×。

关键发现：

  • 1-bit Bonsai（2026-03-31）：首个商用 1-bit 模型，27B 参数压到 ~3.9 GB，可在手机端运行
  • Ternary Bonsai（2026-04-16）：三值版本，"适度增大换显著性能提升"。Apache 2.0 开源
  • Hacker News 社区审慎观点：Bonsai 本质上是 Qwen3-8B 的极优量化版本，绝对精度约等于 Qwen3.5-4B 的 4-bit 量化——不是新架构突破，而是"每字节智能密度"的 Pareto 前沿推进。适合显存极端受限场景（手机/IoT），不适合需要绝对推理质量的生产场景
  • BitNet b1.58 的方法论（QAT 量化感知训练）需要从零训练，不是后处理量化，因此无法直接应用到现有模型上

洞察：4-bit 回退 1.8-2.9% 是可接受的，但 3-bit 以下开始质变。Qwen3 实证研究（arXiv:2505.02214）显示 Qwen3 比 Qwen2 对量化更敏感——因为先进预训练技术减少了参数冗余，模型"信息密度"更高，量化损伤更大。越强的模型越需要高精度量化。

FP8：2026 数据中心默认格式

在 6 个 2026 年开源 70B 级模型（Llama 4 70B、Qwen 3 72B、DeepSeek V4-Flash 等）的实测中：

  • FP8（E4M3）MMLU-Pro 回退 -0.3~-0.5 分（benchmark 噪声范围）
  • VRAM 减半（50%）
  • Batch-1 decode 吞吐 +1.4-1.7×
  • H100/H200 原生 tensor core 支持

结论：任何在 Hopper 或更新硬件上的新部署，FP8 应为默认，仅在验证后回退到 INT8/4-bit。

Actionable Insights

  1. Jetson Orin 部署模板：llama-server -m model-Q4_K_M.gguf -ngl 99 -ctk q4_0 -ctv q4_0。Q4_K_M + KV Cache Q4 是显存效率最优组合。显存有余量时升级到 Q5_K_M。
  2. 新 H100/H200 部署默认 FP8：vLLM 0.7+ 原生支持 FP8 checkpoint，无需额外量化步骤，直接下载 FP8 预量化权重（如 neuralmagic/*-FP8）。
  3. RTX 5090 部署用 NVFP4：如果模型有 NVFP4 预量化 checkpoint（如 nvidia/*-NVFP4），直接使用可获得 4× 加速。没有则用 AWQ-4bit。
  4. AWQ > GPTQ（新部署）：除非已有 GPTQ 基础设施，否则 4-bit GPU 量化首选 AWQ——质量更好、计算更快。
  5. 验证模板：用 10 条代表性 prompt 对比量化前后输出，关注 perplexity 变化和定性质量（创意写作/代码是否退化），不要只看 benchmark 分数。

一页速查

量化选择三步法：

Step 1 — 硬件检测：nvidia-smi --query-gpu=compute_cap。CC ≥ 10.0 → 可用 NVFP4/MXFP4；CC 8.9（Hopper）→ FP8 甜点；CC ≤ 8.6（Ampere/Ada）→ GGUF/AWQ/GPTQ。

Step 2 — 精度需求：生产精度敏感（代码/数学/推理）→ FP8 > Q5_K_M > AWQ-4；吞吐优先 → GPTQ-4 > Q4_K_M；极端压缩 → Q2_K/Q3_K/Bonsai（仅 base 模型）。

Step 3 — 部署模式：CPU/混合 → GGUF（llama.cpp/Ollama）；GPU 集群 → AWQ/GPTQ（vLLM/SGLang）；Blackwell → NVFP4（TensorRT-LLM/vLLM）。

默认推荐：
- 本地/开发 → GGUF Q4_K_M（~92% 质量，Ollama 一行命令）
- GPU 生产 → FP8（Hopper）/ AWQ-4（Ada 以下）
- 极端边缘 → Q3_K 或 Bonsai（仅 base 模型，instruction-tuned 不建议）
- Jetson Orin → Q4_K_M + KV Cache Q4

待深入

  • QuaRot/SpinQuant 旋转预处理：FP4 activation 量化的关键使能技术，尚未深入研究其精度-加速 Pareto

  • SmoothQuant activation 量化：介于 weight-only 和 full quantization 之间的方案，对 activation 敏感模型的折中
  • Jetson 上 Bonsai/三值化的 ARM kernel 支持：目前三值化推理 kernel 主要针对 x86 CUDA，ARM 支持未知
