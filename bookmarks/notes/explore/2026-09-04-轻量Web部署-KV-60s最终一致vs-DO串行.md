## 摘要

Cloudflare 边缘存储生态中，**Workers KV** 与 **Durable Objects (DO)** 是两种截然不同的存储层。KV 采用全局最终一致性，写入后约 **60 秒**传播到全球 310+ 节点；DO 提供强一致的单线程 JavaScript 实例，无跨平台等效替代。轻量 Web 部署选型的核心是：**读写模式是否容忍 60 秒陈旧读**。

## 关键发现

### 1. KV：60s 最终一致，不适合高写场景

- 全局传播时间：写入后 **~60 秒**才能在所有边缘节点可见
- 每个 key 限制：**1 write/second**
- 最佳场景：会话令牌、特性开关、A/B 分组、本地化字符串、缓存 API 响应、URL 缩短映射
- 明确不适合：库存管理、计数器、强一致事务、高频写场景
- 基准测试中 KV **性能最差**（样本仅 5,712/10,000 次交易），Upstash Redis 最优

### 2. D1：SQLite 在边缘，ACID 强一致

- 数据模型：关系型（SQLite 方言），支持事务、JSON、JOIN
- 一致性：单主强一致，读副本最终一致
- 单库上限：**10GB**（付费计划）
- 每百万行读：**$0.001**；每百万行写：**$1.00**

### 3. Durable Objects：无等效替代的强一致协调器

- 每个实例是**单线程 JavaScript 类**，单节点单线程执行
- 一致性：单实例内**强一致**（事务存储，SQLite 支撑）
- 适用场景：实时协调（按房间/用户/会话单实例）、WebSocket 持久连接、分布式锁
- 定价：$0.15/百万请求 + $0.005/GB-月运行时长

### 4. 冷启动对比：Workers 完胜

- Workers：V8 isolate，**<1ms 冷启动**，330+ 全球节点
- Lambda：容器启动，**100ms–1s 冷启动**，30 个区域
- Vercel Edge：V8 isolate，<5ms，50+ 边缘节点
- Workers TTFB 比集中式源站快 **60–80%**

### 5. 成本对比（2026-02，10M 读+1M 写+5GB/月）

- Cloudflare KV：**$6.50**（读+写+存储）
- Cloudflare D1：**$3.88**
- DynamoDB on-demand：**$3.75**
- Cosmos DB serverless：**$5–15**
- Firestore：**$4.86**

### 6. KV 的 `expirationTtl` 陷阱

- 最小 TTL：**60 秒**（低于 60 秒的过期时间不支持）
- 每个 key 可附加 **1,024 字节元数据**，`list` 操作时无需获取完整值即可过滤

### 7. 一致性选型决策树

- 配置/会话数据，极少写入，频繁全局读取 → **KV**
- 关系型数据，需 SQL 查询/JOIN → **D1**
- 实时协调（单实例/用户/会话）、WebSocket → **Durable Objects**
- 文件/媒体/备份（拒付出站费）→ **R2**
- 异步任务/事件处理 → **Queues**

## 对工作的价值

1. **边缘部署选型基线**：轻量 Web 后端（会话管理、特性开关、配置下发）可直接用 KV，无需自建 Redis；需要强一致的实时功能切 DO，无需自建 WebSocket 网关
2. **成本可量化**：同一数据规模（10M 读+1M 写+5GB），Cloudflare 生态（KV $6.50 / D1 $3.88）与 DynamoDB（$3.75）基本持平，但省去区域网络延迟（50–200ms）
3. **60 秒一致性窗口**是可接受的工程决策：对于配置下发、特性开关、AB 实验等场景，60 秒陈旧读不影响业务正确性，换来 <10ms 全局读延迟
4. **V8 isolate 优势**：<1ms 冷启动 vs Lambda 100ms–1s，适合高频短任务（API 网关、鉴权、路由），不适合重计算（CPU 限制 50ms 免费 / 30s 付费）
