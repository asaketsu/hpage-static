## 一、内容整理

### 1.1 核心问题：Agent 推理的 KV 缓存爆炸

ReAct 范式（观察-推理-行动循环）是现代 Agent（OpenClaw、Claude Code、Codex）的基础执行范式，但每轮循环产生的 token 会以 KV 条目形式持续累积：

- 一个 WebShop 任务用 Qwen3-30B 跑：25 轮迭代、约 35K token、消耗 3.20 GB KV 缓存
- 其中观察+推理条目占比超过 99%，动作条目只占不到 1%
- 长序列还会稀释注意力、降低精度；批量服务下并发被显存卡死

> **关键洞察**：用户真正关心的是动作驱动的任务进展，观察和推理 token 大多是"内部消耗"。但现有压缩方法（H2O/SnapKV/StreamingLLM）都按"整体输出质量"公平对待每个 token——这在 Agent 场景下是目标错配。

### 1.2 三大实证发现（Key Insight 章节）

**发现一：动作偏好的 KV 条目独立且跨轮稳定**

- 观察 token 主要注意局部扩展 prefill 上下文
- 推理 token 对全部历史产生弥散注意力
- 动作 token 聚焦于一小撮任务关键历史
- 因此按观察/推理偏好驱逐的条目，恰恰可能丢掉动作关键条目——这解释了为什么通用长上下文压缩方法在 Agent 推理上失效

可控实验：从 100 条 FullKV 正确轨迹中移除最后 3 轮 KV，把前缀压到 30%（分别用观察/推理/动作偏好评分），动作偏好保留的成功率最高。

**发现二：模型置信度暴露 KV 预算是否充足**

预算收紧 → 成功率与置信度同步下降、轨迹变长。检查生成文本发现：预算不足时模型出现 "wait"、"I guess"、"let me check" 等低置信度语言标记——模型在试图扩展推理来复述缺失上下文；但更长推理进一步挤压预算，导致反复复述、最终重探索或失败。**置信度下降是预算不足的可靠在线信号**。

**发现三：压缩可标准化为三个原语**

- AttnScore ← CalAttn(target_q, KCache)
- KeepMask ← Eviction(AttnScore, Budget)
- KVCache ← Compaction(KVCache, KeepMask)

H2O、SnapKV、R-KV、ActKV 等方法都可蒸馏进这个统一工作流，差异只在 target 选择和策略细节。

### 1.3 组件一：动作导向驱逐（attention-aware LRFU）

用动作访问向量（AAV）量化条目稳定性：条目在每轮动作区域的注意力是否进 top-90%。三类模式：

- 冷启动条目（前 0 后 1）：可忽略，说明当前动作偏好通常可从历史预测
- 连续条目（无间断）：数量最多，但单次访问注意力贡献低
- 间歇条目（中间有 0）：数量少但单次注意力贡献最强

> **教训**：只按当前动作偏好驱逐会误删"暂时沉寂但后面会再变重要"的间歇条目。

驱逐准则升级为时间效用：**一个条目只有长期没有高注意力贡献后才该被驱逐**。实现为 LRFU（Least Recently Frequently Used）保持分数：

```
KS_t(i) = λ·KS_{t-1}(i) + AttnScore_t(i)   （hit 时，即进 top-p=90%）
KS_t(i) = λ·KS_{t-1}(i)                     （miss 时）
保留 TopK(KS, k=B)，随后压实
```

- λ=0 退化为纯近因：丢间歇条目
- λ=1 退化为纯频次：留陈旧连续条目
- 0<λ<1 平衡：间歇条目熬过暂时沉寂，陈旧条目靠衰减出局

触发时机：每轮 ORA 结束时。动作区域通过匹配 LLM 标准化输出模板（如 XGrammar 约束的工具调用格式）检测起止。

### 1.4 组件二：置信度驱动的自适应预算

三级置信度监测器（与推理并行、开销可忽略）：

- **token 级**：top-k token 的负平均 log 概率，分布越尖越确定
- **轨迹级**：滑窗（size w, stride s）最小值池化 → 只保留最低 b% 值——刻意放大低置信片段（复述/修复/恢复进展的信号）
- **趋势检测**：对轨迹级序列做一阶最小二乘拟合，斜率 α<0 说明置信度在下降 → 预算不足 → 扩大预算

这解决了离线 profiling 预算（R-KV/Ada-KV 式）无法适应"任务类型×难度×轮次"动态需求的问题。

### 1.5 组件三：页感知压缩管理（两大定制内核）

**挑战**：token 级驱逐与 vLLM/SGLang 的 block 级页管理天然错配。paged FlashAttention 不暴露完整注意力矩阵；标准注意力核需要把散落 KV 块 gather 到连续内存（拷贝开销吃掉压缩收益）。

**内核一：恢复式注意力计算（Triton）**

- 核心技巧：从 paged attention 副产品 softmax LSE（log-sum-exp）恢复注意力分数：A_ij = exp(s_ij − LSE_i)
- 只需在每个页块内重算局部 q·k 点积，用现成 LSE 归一化，无需 gather、无需缓冲历史 query
- GQA 感知：组内 query head 取 max，动作 query 间增量均值；仅处理正在生成动作的请求，按请求×逻辑块×KV 头并行

**内核二：原地压实**

- 观察到驱逐后保留条目在页尾更密集 → 全部压进最后 X 个逻辑块（X = ⌈budget/block_size⌉）
- 先做无冲突槽位规划：目的槽 = 尾区内被驱逐位置，源槽 = 尾区外的保留条目，二者不相交 → 一次性并行拷贝，零辅助缓冲
- 压实后释放的块即时归还调度器复用

### 1.6 关键实验结果

- **模型**：Qwen3-30B-A3B-Thinking / Qwen3-235B-A22B-FP8 / GPT-OSS-20B / GPT-OSS-120B
- **基准**：ALFWorld（平均轨迹 31K token）、HotpotQA-Web（8K）、WebShop（33K），各 1500 任务
- **硬件**：8× RTX PRO 6000 Blackwell 96GB + 192 核 Xeon + 256GB 内存；实现于 vLLM v0.19.0 与 Transformers v5.3.0
- **基线**：FullKV、R-KV（页化版）、SnapKV、StreamingLLM

精度结果（离线固定预算，归一化到 FullKV）：

- 对 R-KV / SnapKV / StreamingLLM 的平均增益：ALFWorld +27.64% / +27.06% / +54.59%；WebShop +32.86% / +31.88% / +71.08%；HotpotQA-Web +29.82% / +28.65% / +70.14%
- ALFWorld 预算 10% 时拿到 FullKV 的 81.34% 精度；WebShop 预算 25% 时拿到 101.41%——**压缩后反而超过不压缩**（WebShop +3.13%，ALFWorld 最高 +1.40%），因为选择性保留缓解了 FullKV 长轨迹中无关条目对注意力的稀释

自适应预算结果：

- ALFWorld / HotpotQA-Web / WebShop 分别以 26.38% / 35.08% / 25.58% 峰值显存拿到 98.04% / 96.81% / 99.02% 的 FullKV 精度
- 长轨迹任务平均：**98.53% 精度 @ 25.98% 峰值显存**，落在精度-显存 Pareto 前沿
- 代价：轨迹长度增至 109.76% / 113.97% / 109.67%（轻微变长）

内核与吞吐：

- 对 paged R-KV 的单次压缩操作平均加速 **10.41×**（block_size=16, kv_heads=8, head_dim=128；1 请求 1K→0.5K 时最高 25.50×），零辅助 KV 存储
- 端到端（单卡 Blackwell，1500 任务一次性提交）：token 吞吐 3.96× / 3.80× / 4.14×，任务吞吐 3.62× / 3.32× / 3.80×
- 跨模型泛化：Qwen3-235B 上依然有效；GPT-OSS 增益较小，归因于其一半层用滑动窗口注意力（对进一步驱逐更敏感）

## 二、查询拓展

### 2.1 ReAct 与 KV 缓存的耦合

ReAct（Yao et al. 2023）每轮把环境观察追加进 prompt，KV 缓存因此单调增长且不可收缩——这与普通对话的"一轮一清"完全不同。Agent 服务化的显存瓶颈不在权重而在 KV：30B 模型权重约 60GB（BF16），但并发 20 个长轨迹 Agent 各 35K token 就是 64GB 级 KV 开销。这是 vLLM PagedAttention 之后 Agent 时代的新一轮显存战争。

### 2.2 LRFU 与经典缓存替换

LRFU（Least Recently/Frequently Used）是 2001 年提出的操作系统页替换算法，同时刻画近因与频次。ActKV 的贡献是把"访问"重新定义为"进入动作区域注意力 top-90%"，把注意力分数作为权重注入更新式——传统 LRFU 是 0/1 命中，这里是连续注意力加权，本质是把 OS 缓存理论搬进注意力服务系统。

### 2.3 LSE 恢复注意力分数

FlashAttention 类核为省显存不落盘完整注意力矩阵，只在线归一化时产生 LSE（每 query 一个标量）。ActKV 的恢复式计算利用 softmax 的数学性质 A_ij = exp(s_ij − LSE_i)，只需重算块内点积即可精确还原概率——一次点积换取完整分数矩阵，是"免费搭车"式系统优化，思路可迁移到任何需要注意力分数但只有 paged 后端的场景。

### 2.4 与 MemDecay / ODA 的路线差异

- MemDecay（2607.10582）：区域感知驱逐——按 system/scratchpad 等上下文区域设基础优先级+半衰期，区域标签是先验
- ODA（2609.20734）：按需注意力——冻结主干+训练 recall head 步级预测收益，KV 全保留零信息损失，走"读取"路线
- ActKV：动作导向驱逐——以"对动作生成的贡献"为唯一价值尺度，训练免费，走"驱逐"路线且做了 paged 内核工程化

三者共同点：都承认"不是所有历史 token 同等重要"，差异在价值尺度的来源（区域先验 / 学习头 / 动作注意力）。

## 三、归纳总结

### 3.1 核心框架：以任务结果为锚的缓存价值重定义

```
传统压缩:  价值(token) ∝ 对整体输出质量的贡献 → 公平对待
ActKV:     价值(kv)   ∝ 对动作生成的贡献     → 结果导向

观察token ─┐
推理token ─┼─→ 驱逐候选（占99%，服务于内部状态）
动作token ─┴─→ 价值锚点：决定环境变化与任务进展

三大组件闭环:
[动作导向LRFU驱逐] ←稳定动作访问模式─ [页感知内核]
       ↑置信度反馈                    (LSE恢复+原地压实)
[置信度监测器] ───预算不足信号──→ [自适应预算分配]
```

### 3.2 方法论要点拆解

- **价值锚点选择**：Agent 系统的优化目标应从 token 级保真切换到任务结果级保真——这是全文最重要的视角转换
- **稳定性先于重要性**：单次重要性（当前注意力）不可靠，跨轮稳定访问模式才是可依赖的驱逐依据（AAV 分析是证据链关键）
- **内省信号当传感器**：不引入外部评估器，用模型自身的置信度分布做预算反馈回路——廉价的闭环控制
- **算法-系统协同设计**：没有 LSE 恢复核与原地压实核，token 级驱逐在 paged 系统里只剩学术意义（paged R-KV 的 gather 开销就是前车之鉴）

## 四、趋势判断

### 趋势1：Agent 专用 serving 栈正在成形

依据：ActKV 明确区分"通用长文本压缩"与"Agent 推理压缩"，且直接实现进 vLLM。随着 OpenClaw/Claude Code 类产品的并发部署需求，LLM serving 系统将从"对话吞吐优化"转向"轨迹级显存治理"，Agent-aware 调度器会成为标配。

### 趋势2：置信度内省将成为系统级控制信号

依据：本文用置信度斜率控制预算；此前 Deep think with confidence 等工作已把置信度用于推理长度控制。模型内部信号（熵、置信度、惊讶度）正在从"研究分析对象"变成"serving 系统的控制平面输入"，形成软件工程式的反馈控制回路。

### 趋势3：KV 治理四路线将走向组合

依据：驱逐（ActKV/MemDecay）、压缩量化、复用（prefix cache）、读取控制（ODA）已各自成熟。ActKV 的三原语标准化（CalAttn/Eviction/Compaction）实际上为组合提供了接口层——预计一年内出现"驱逐+复用+按需读取"的叠加系统，各路线正交可组合。

### 趋势4：压缩反而提升精度的反直觉结果会被更多人利用

依据：WebShop 上 25% 预算拿到 101.41% 精度，说明注意力稀释是真实存在的性能税。上下文工程领域"塞得越多越好"的直觉将被系统性修正——这与人类笔记领域"压缩即理解"异曲同工。

## 五、关联分析

### 5.1 与 MemDecay 笔记的关联

[2026-07-15-MemDecay.md](2026-07-15-MemDecay.md) 用"区域基础优先级+衰减率"做 KV 驱逐，system 区域半衰期是 scratchpad 的 10 倍；ActKV 则完全不看区域标签，只用动作注意力做价值尺度。两者是"先验派 vs 数据派"的经典对立：MemDecay 不需要动作模板检测，ActKV 不需要手工调区域参数。对 Hermes 这类结构化上下文系统，MemDecay 的区域先验更易落地；对工具调用密集型 Agent，ActKV 的动作锚点更精准。消融维度互补：MemDecay 揭示注意力项需幅度归一化，ActKV 揭示间歇条目需要时间效用保护。

### 5.2 与 ODA 笔记的关联

[2026-09-19-On-Demand-Attention精读-语言模型知道何时召回-ODA按需注意力机制.md](2026-09-19-On-Demand-Attention精读-语言模型知道何时召回-ODA按需注意力机制.md) 的 ODA 走"读取"路线（28.3M recall head 预测步级收益，KV 全保留信息无损），ActKV 走"驱逐"路线（物理删除换显存与吞吐）。ODA 的 Random 对照实验证明"知道何时读"价值巨大；ActKV 则证明"知道删什么"同样有价值。两者在"按需注意力"坐标系中位于正交轴，理论上可叠加：驱逐控制常驻集，读取控制注意力范围。

### 5.3 与 Hermes Agent 上下文管理的关联

Hermes 的长会话（cron 任务链、多轮工具调用）同样面临上下文单调膨胀——session 压缩、skills 索引、memory 分层本质上都是"上下文 KV 治理"的应用层投影。ActKV 的启示：Hermes 的上下文压缩价值尺度也应从"信息保真"转向"任务进展保真"——工具调用参数、用户原始指令、关键决策点是"动作关键条目"，而工具返回的海量原始输出是"观察噪音"。

## 六、金句摘录

> 「Efficient agent serving should align memory management with task outcomes rather than token-level fidelity.」— 结论章，全文题眼：内存管理应对齐任务结果，而非 token 级保真。

> 「Observation and reasoning remain largely internal within the agent, and are often hidden or useless to users, while what users care about is the task progress driven by actions.」— 对 Agent 价值结构的重新定义。

> 「The model compensates by extending reasoning to recover missing context, which manifests as confidence degradation.」— 预算不足的失败链：压缩→信息缺失→推理变长→预算更紧→复述循环。这个正反馈死锁描述对 Agent 上下文管理极具警示价值。

## 七、行动启示

- **启示一（上下文工程）**：对 Hermes 会话压缩引入"动作锚点"——压缩历史轮次时，保 tool call 结构与参数、保用户指令原文、保决策结论，激进裁剪工具返回的原始长输出。对应 skill：context-compressor。
- **启示二（失败模式识别）**：「wait / let me check / I guess」式复述螺旋是上下文不足的可观测信号。Hermes 长任务中出现连续复述时，应触发上下文补充或预算扩容，而非继续压缩。
- **启示三（工程化标准）**：三原语（CalAttn/Eviction/Compaction）抽象值得在自建推理服务时沿用——任何新驱逐策略只需实现 Eviction 一个函数即可插入系统。
- **启示四（评估纪律）**：ActKV 的"预算按轨迹而非数据集平均长度分配"提醒：评估压缩方法必须控制轨迹长度方差，否则对比不公平。

## 八、拓展应用推荐

### 8.1 Jetson 边缘 Agent 部署

- Orin Nano 8-16GB 统一内存下，本地跑 Qwen3 类模型 + 多轮工具调用轨迹，KV 缓存是第一个撞墙的资源。ActKV 的"25.98% 峰值显存 @ 98.53% 精度"如果能在边缘复现，等于显存预算直接除以四
- 但注意：ActKV 内核面向数据中心 Blackwell + vLLM；Jetson 上需评估 Triton 内核在 Tegra 架构的兼容性，LRFU 驱逐策略本身（纯算法层）可先行移植
- 落地路径：先用 Transformers 实现（论文已支持）验证精度，再考虑内核优化

### 8.2 Hermes Gateway 长会话治理

- 多轮 cron 链与看板任务产生的会话历史，可借鉴"动作访问稳定性"思想：哪些历史片段被后续工具调用反复引用，哪些引用一次后沉寂——后者是压缩首选
- 置信度监测器的滑窗最小值池化+线性拟合斜率，可直接用于 Hermes 会话健康度检测（复述螺旋告警）

### 8.3 量化交易 Agent

- 交易 Agent 的 ReAct 轨迹（行情观察→分析→下单动作）与本文场景同构："下单动作关键条目"= 持仓约束/风控规则/用户指令，行情快照是可压缩观察
- 低置信度标记（"wait, let me check"）在交易场景应升级为硬风控信号：置信度斜率连续为负 → 暂停开仓、要求补充数据

## 九、指南分析

### 9.1 选文与阅读指南

本文适合作为"Agent 推理服务化"方向的入门+进阶双用材料：S3 的三大发现（动作条目稳定性/置信度-预算相关性/三原语）是独立的可复用知识；S7 的两个内核是 CUDA/Triton 系统工程绝佳案例。阅读顺序建议 S1→S3（动机与洞察）→S5-6（算法）→S8（实验）→S7（内核，系统背景弱可跳）。

### 9.2 复现与验证指南

- 论文支持 vLLM v0.19.0 与 Transformers v5.3.0 双栈，硬件门槛高（实验用 8×96GB Blackwell），但算法部分（LRFU+置信度监测）可在单卡复现
- 复现关键超参：top-p 命中阈值 90%、block_size=16、预算从 5% 起扫到 50% 观察置信度斜率响应
- 验证指标不要只看精度：必须同时报峰值显存、轨迹长度比（本文承认自适应模式轨迹+10%~14%，这是隐性 token 成本）

### 9.3 批判性阅读要点

- 动作区域检测依赖标准化输出模板（工具调用格式），对自由文本输出的 Agent 不直接适用——需要先上 structured output
- "压缩后精度反超 FullKV"只在长轨迹任务出现，短上下文任务不会有这个红利
- GPT-OSS 增益打折提示：滑动窗口注意力模型对 KV 驱逐天生敏感，选型时需注意模型架构与压缩方法的交互
- 评测全部为离线 ReAct 域（ALFWorld/WebShop/HotpotQA-Web），开放域长程 Agent（如软件工程任务）的轨迹分布更不规则，泛化性待验证
