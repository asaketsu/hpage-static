核心问题与研究动机

当前 LLM 的推理能力依赖 test-time compute 扩展——通过 Chain-of-Thought（CoT）生成中间 token。但这存在三个根本问题：

  1. 推理与生成交缠：中间计算必须以自然语言形式「说出」，计算预算浪费在语法和流畅性上
  2. 自回归瓶颈：每个中间 token 必须先生成才能被后续计算依赖，无法并行
  3. 语言非最优计算载体：自然语言为沟通优化，非为计算优化

人类认知提供了不同范式——工作记忆（Working Memory）允许在大脑内部持有和操作信息，无需外显每一步。本文受此启发，提出 Reasoning in Memory（RiM）。

方法论（详细）

核心思想：Memory Block 作为隐式工作区

RiM 引入固定长度的特殊 token 序列（Memory Block），插入问题与答案之间：

[问题] [Memory Block 1] [Memory Block 2] ... [Memory Block K] [答案]

每个 Memory Block 结构：<b> <m> <m> ... </b>（M=2 个 <m> token，即 4 个特殊 token/块）

关键设计：
- Memory Block 是固定输入，非自回归生成，因此可在单次前向传播中处理
- <m> token 的 contextual representation 随输入动态变化，成为任务相关的隐式计算空间
- 冻结所有预训练 token 的 embedding，仅更新特殊 token 的 embedding

自定义 Attention Mask

Memory Block 可看到问题和之前的 Memory Block；答案 readout 可看到之前的 Memory Block 和可选的问题，但不能看到其他推理步骤。这强制推理发生在 Memory Block 内部。

两阶段训练课程

Stage 1 — 推理步骤监督（Grounding）：
- 为每个推理步骤分配一个 Memory Block
- 每个 Memory Block 后的 readout 被训练预测下一个显式推理步骤
- 自定义 Attention Mask 防止 readout 直接从前面的推理步骤抄答案
- 使用线性退火权重 λ_t(s)，早期所有 block 获得密集监督

Stage 2 — 最终答案精炼（Refinement）：
- 丢弃中间推理步骤监督
- 固定 K 个 Memory Block，每个 block 后的 readout 直接预测最终答案
- 后续 block 权重更大（更多隐式计算 → 更强答案）
- 重置优化器状态，降低学习率，增加 dropout 防过拟合

关键实验结果与数据

训练数据：GSM8K-Aug（386K 数学题，最多 13 步）

评估数据集：
- GSM8K（in-distribution）
- GSM-Hard（out-of-distribution，更难数学题）

模型规模：GPT-2 / Llama-3.2-1B / Llama-3.2-3B

主要结果（Greedy Accuracy）

GSM8K (ID)：
- GPT-2：RiM 33.6% vs SFT w/o CoT 15.4% vs Coconut 31.1%
- Llama-1B：RiM 42.1% vs SFT w/o CoT 23.9% vs Coconut 36.9%
- Llama-3B：RiM 48.8% vs SFT w/o CoT 36.2% vs Coconut 41.3%

GSM-Hard (OOD)：
- GPT-2：RiM 7.8% vs SFT w/o CoT 3.5% vs Coconut 7.1%
- Llama-1B：RiM 10.5% vs SFT w/o CoT 5.3% vs Coconut 8.5%
- Llama-3B：RiM 12.0% vs SFT w/o CoT 8.5% vs Coconut 10.2%

延迟对比（TTFT, ms）

  • RiM ≈ SFT w/o CoT（单次前向传播）
  • Coconut 慢约 7 倍（自回归生成连续表示）
  • SFT w/ CoT 慢约 27 倍

其他发现

  • PCA 分析：Memory Block 的 representation 在训练过程中变得 block-specific 和 input-dependent，证实模型学会了使用隐式工作区
  • Any-block readout：如果取所有 block readout 中最佳的，RiM 在 Llama-1B 上达 51.4%（接近 CoT 的 49.1%），但延迟仅 16ms vs 420ms
  • Memory Budget 鲁棒性：Stage 2 后，精度在广泛的 K 和 M 组合下保持稳定
  • Pass@8：RiM 采样正确解的概率显著高于所有基线

评估方法论亮点

使用 16-fold 交叉验证 + 预定义 checkpoint 选择协议，避免在测试集上选 checkpoint 导致的选择偏差。

创新点分析

  1. 范式转换：从「生成中间 token」到「固定 Memory Block 内部计算」，实现了推理与生成的解耦
  2. 单次前向传播推理：所有 Memory Block 同时处理，推理效率极高
  3. 认知科学启发：借鉴人类工作记忆机制（Baddeley, 1992）和认知发展理论（Vygotsky, 1978），理论根基扎实
  4. 简洁训练流程：仅需标准 next-token prediction + 两阶段课程，无辅助损失、无蒸馏路径
  5. JEPA 风格：Stage 1 本质上是预测缺失的推理结构，与 LeCun 的 JEPA 框架思想一致

局限性与未来方向

  1. 仅在数学推理任务验证：GSM8K/GSM-Hard 是相对受限的 benchmarks，未在更广泛的推理任务（逻辑推理、代码生成、多跳问答）上验证
  2. Memory Block 的可解释性差：隐式推理过程是黑盒，无法像 CoT 那样审计中间步骤
  3. 与 CoT 的互补性未探索：对于需要输出中间推理过程的场景（如可验证数学证明），RiM 无法替代 CoT
  4. 规模上限未测试：最大模型仅 3B，在更大模型（70B+）上效果未知
  5. 未来方向：Stage 2 引入 RL（最终答案奖励）进一步提升；混合 RiM + 显式生成

借鉴点

🔨 P0 — RiM 思路可迁移到 Agent 推理架构

  • 关联：Hermes Agent 在执行复杂任务时需要多步推理，当前完全依赖 LLM 的显式 CoT
  • 借鉴：在 Agent 的 tool-use 循环中，可引入类似的 Memory Block 机制，让 LLM 在调用工具前先做隐式推理，减少无效工具调用
  • 工作量：需修改 inference pipeline，中等工程量

🔨 P1 — 边缘推理效率提升

  • 关联：Jetson Orin 上运行 LLM 时，推理延迟是核心瓶颈
  • 借鉴：RiM 的单次前向传播推理模式可大幅降低延迟。如果未来在 Jetson 上部署推理模型，RiM 训练的模型比 CoT 模型延迟低 27 倍
  • 障碍：需要用 RiM 方法微调一个适合 Jetson 的模型

⚠️ P2 — 量化交易策略的隐式推理

  • 关联：量化策略回测中，策略规则的推理链可考虑用 RiM 思路隐式化
  • 障碍：金融场景对可解释性要求高，隐式推理可能不适用

✅ P3 — 评估方法论

  • 关联：当前 Hermes 的 skill 评估缺乏严格的交叉验证
  • 借鉴：论文的 16-fold CV + checkpoint 选择协议可迁移到 skill 效果评估

💡 启发

  • 推理不一定要说出来：LLM 的隐空间足够丰富，可以在不生成 token 的情况下完成有意义的多步计算
  • 固定 token 可以成为可学习的计算单元：特殊 token 的 embedding 学到了任务相关的计算模式
  • 训练信号设计比模型架构更重要：RiM 的核心创新不在架构而在训练方法（两阶段课程 + 自定义 attention mask）
  • 认知科学仍是 AI 的富矿：工作记忆、内化语言等认知概念可以直接指导 LLM 架构设计

🔮 预判

  • 隐式推理将成为 Agent 架构标配：RiM 证明了隐式推理可行且高效，预计 2026 下半年会有更多 Agent 框架集成类似机制
  • 显式 + 隐式混合推理是终极形态：简单步骤隐式处理，复杂/需审计步骤显式输出，兼顾效率与可解释性
  • 对边缘 AI 意义重大：RiM 的低延迟特性使其成为 Jetson 等边缘设备的理想推理范式
