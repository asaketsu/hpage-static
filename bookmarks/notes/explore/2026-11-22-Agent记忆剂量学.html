Agent记忆剂量学：记忆该装多少是模型的属性——IBM自蒸馏记忆部署经验

#论文精读 #Agent记忆 #自蒸馏 #部署经验 #Hermes进化

生成日期 2026-11-22

〇、定锚：我的现状与目标

我的现状：Hermes 记忆体系当前是「MEMORY.md 固定 30K 上限 + memorygraph 图谱 + evolver/experience-bank/error-case-library 三库沉淀」，对所有模型（glm-5.3/gpt-6.1-terra/sol）用同一套记忆投喂，且 MEMORY.md 是人工+自动压缩的「有损精选」。本文恰好打在这个痛点上：最优记忆剂量是模型能力的函数，不是记忆系统本身的属性——我的现状是一刀切，论文证明一刀切必然对某些模型是错的。

我的目标：验证「不同模型该配不同记忆剂量」在 Hermes 上是否成立；检查我的记忆管线是否存在论文点名的三类静默失败（写入路径断、support 字段丢失、吞错误）；给 experience-bank 补「正确性/时新性信号」。

二、核心问题与研究动机

动机起点：作者读了数百条 IBM CUGA agent 与 AppWorld 参考智能体的轨迹，发现 LLM agent 在长程任务上的失败不是知识缺口，而是程序性失误（procedural lapses）且反复发生——知道 API 却错误分页、知道用户有联系人却解析错实体、没被问却抢答。反复发生 = 可从自身历史学习。

研究空白：让 agent 写笔记读笔记的系统很多（ExpeL、ACE、Reflexion、Anthropic dreaming），但「建出来、仔细测量、真正上线」的一手部署账本极其稀缺。本文就是这个账本，且刻意聚焦「什么搞砸了」。

三阶段管线（altk-evolve）：
1. 抽取：从 agent 自身轨迹（成功+失败都保留）每条抽 1-3 条短祈使句 lesson。成败极性由评测器的真实结果判定，绝不信任 LLM 自述。DeepSeek-V3.2 上 147 条轨迹产出 290 条原始 lesson（62 失败 + 228 成功）。
2. 整合（support-conserving consolidation）：按源任务嵌入聚类近重复项，LLM 只在簇内、且「遵循 A 等价于遵循 B」时合并。每条 guideline 记录 support 计数（合并了多少条 lesson）+ 证据极性。铁律不变量：输出 support 总和 = 原始 lesson 数，LLM 没覆盖到的原样透传。290 → 191 条 guideline（其中 144 条 support=1）。
3. 投递：全量静态注入，或检索式（support≥3 的核心必带 + 按源任务相似度补 top-k）。阈值筛选只发生在选择时，永不删库。

为什么必须整合：原始情景记忆不会保持小——五个任务各自用惨痛方式学会分页，各自写一遍，检索 top-k 槽位全被重复占满。整合不是省成本，是让记忆可检索的前提。

部署约束：跑 agent 的模型 = 抽 lesson 的模型 = 做整合的模型。无教师模型、无人工标注——镜像真实生产。

三、内容整理：七大部署洞察（论文核心）

测量底座：AppWorld（9 个 App、457 个 API、~100 模拟人、750 任务；test_normal=168 任务，test_challenge=417）。ReAct 代码智能体，每步一次模型调用写 Python。指标：TGC（任务全检查通过率）+ SGC（场景全变体通过率，更严）。8 模型基线，6 模型带记忆。

洞察1：最优剂量是模型的属性，不是记忆的属性
- 强模型单调受益：DeepSeek-V3.2 从 79.8→82.7→83.9→85.7→89.3 TGC（0→12→19→47→191 条 guideline 递增），SGC 64.3→80.4；难split上 60.4→72.9。相邻两点在噪声内，端点差 16 个任务是硬趋势。GPT-5.5 从 92.3→95.2（207 条全量）。
- 弱模型反例：gpt-oss-120b 基线 39.9，199 条全量只到 51.2，还不如 24 条核心的 53.6；最优是 ~29 条精选子集 = 55.4（两次运行 56.0/54.8 均值），token 成本几乎与基线持平（116K vs 110K）。
- 饱和型：GLM-5 用不用 72 条 guideline 都是 87.5。太弱型：Gemma-4-31B 整体持平且被过紧核心伤害。
- 收益落点地图：强模型的中等难度层收益最大（DeepSeek 中等 SGC 62.5→93.8，+31 分——guideline 翻转的是「差点就对」的边缘案例）；弱模型的困难层是天花板（gpt-oss 困难 SGC 停在 9.5）；前沿模型能动困难层（Opus 4.6 在 challenge 上 73.3→83.1）。
- 金句：记忆的作用是把「差一点」转成「过」，不是把模型举过它根本做不到的任务。
- 产品化改动：剂量变成配置项（consolidation_mode/min_support/core_support/retrieval_top_k/injection_mode），默认保守（检索式+高support核心）——弱模型记忆过载的失败模式是静默的：不报错，只是变差。

洞察2：别压缩，价值在长尾
- 第一版整合 prompt 要 LLM 给「小而精」规则集，得到 12 条读起来很漂亮的 guideline → DeepSeek 只 +2.9 TGC。191 条全量 → +9.5 TGC，SGC 增益翻倍以上。差 11 个任务，远超噪声。
- 差异全在 144 条 support=1 的一次性情景 lesson——恰好是摘要器以「只出现一次」为由丢弃的东西。外部印证了 ACE 论文的 brevity bias / context collapse 失败模式。
- 但洞察1是必要限定：弱模型上长尾正是淹死它的东西。「全部保留」只有投递层能做选择时才成立。产品化后无损是默认，压缩是显式 opt-in。

洞察3：选择依赖 provenance，而 provenance 极易静默丢失
- 产品化时发现两处独立断裂：旧版整合用固定字段清单重建合并后 guideline 的元数据，静默丢掉 support 计数和别组依赖的 generation-method 标签；support 归因第一版在 LLM 重复索引时双计数（自动代码审查器先于人发现）。
- 修复：守恒变成带回归测试的强制不变量；整合前后报告 support 总数。
- 可泛化的教训：下游阶段要按某字段排序/筛选，那这个字段就必须是每个上游阶段带测试保全的不变量。

洞察4：support 是复发度，不是正确性
- 实锤案例：一条高 support 分页 guideline 写「循环直到返回数少于页上限」。agent 假设上限 20，API 默认页大小是 5 → 第一页 5 条 < 20 → agent 认为已是最后一页，漏掉所有后续页，在一个基线本来能过的任务上回归。
- 手工改写成「显式传 page limit，循环直到空页」后任务恢复，困难层 TGC 66.7→73.0。
- 管线没有「guideline 被 contradicted/过期/有害」的概念。正确性或时新性信号是最重要的缺失组件——没有它不敢跑无人值守的记忆循环。对照：Anthropic dreaming 按最新值解决矛盾并剪枝过期项；ExpeL 允许模型投反对票至删除；生成式智能体按 recency 加权检索。

洞察5：先测噪声底，再信任何 delta
- 同一 gpt-oss 配置跑两遍：56.0 vs 54.8。DeepSeek 相同配置两次运行 168 个任务里约 32 个翻转而总量几乎不动。检索余弦相似度不预测谁受益（改善组 0.463 vs 回归组 0.468）。
- 规则：小于约 5 个任务的差异按噪声处理。这条纪律把「比 ACE 赢 1.2 TGC」的宣称改写成诚实版本——「精度打平，token 成本 1/7」。

洞察6：固定脚手架比较，永远报 token
- 与 ACE 对比：DeepSeek 上 89.3/80.4 vs ACE 80.4/73.3 看似大胜，但两者无记忆基线不同（79.8 vs 72.0，ACE 的 ReAct 变体带不同 prompt 模板和更多示例）。按各自基线算 lift：+9.5/+16.1 vs +8.4/+16.2，记忆贡献等价，headline 差距主要是脚手架差异。
- 真正经得起审视的结论：DeepSeek 上同精度或更好，token 是 ACE 的 ~40%（263K vs 634K/任务）；弱模型上打平但 token 1/7（116K vs 777K）。赢的是选择机制，不是记忆本身。
- 成本结构：开销几乎全在输入侧（guideline 集每个推理步重发）。输出平稳，步数几乎不动（18.4→19.3/任务）。全量 191 条 = +78% token/任务；47 条 sup≥2 集是效率甜点（+27% token 换 +5.9 TGC）。

洞察7：静默失败吃掉的日历时间比任何建模问题都多
- 四起事故：①GPT-5 级模型拒绝 temperature=0 返回 HTTP 400，harness 吞掉错误，每个任务恰好一次调用后"失败"，run 带着看起来正常的日志走完；②单次调用整合数百条 lesson 耗尽推理模型输出预算 → 截断 JSON → 改分块 map-reduce 到不动点；③企业代理空闲断连杀掉多小时评测；④CUGA 一条代码路径上记忆写入从未被调用——存储一直空着，记忆从冷启动起就是静默只读。
- 对策（作者自嘲"不性感"）：每任务异常必须响亮失败；断言每任务最少模型调用数；长跑加看门狗；检查记忆库实体数真的在增长。

四、IBM 产品实测数据

  • CUGA（GPT-4.1，AppWorld，3 次均值）：无损整合 TGC 71.03→72.42，SGC 54.76→58.93，步数 9.63→9.31。τ-bench retail：sup3（12 条）平均准确率 51.7%→55.8%，pass^3 27.5%→32.5%。每项 delta ≈2 任务/试，低于洞察5噪声底——只证明修复后的链路端到端工作且方向一致，不证明幅度。
  • CUGA（GLM-5.3-Flash 自采自用：280 lesson → 164 guideline，每臂两跑）：无损全量 TGC 87.8→93.2（约 9 任务，两次 92.9-93.5 区间稳定超基线两次 87.5-88.1），SGC 84.8→88.4，+36% token；sup3 29 条在噪声内。洞察1的强模型模式在第二个脚手架上复现。
  • watsonx Orchestrate 定性案例（跨任务迁移）：源任务员工 E-1042 报销，学到 guideline 前先提交后转 HEIC 票据，submit_expense_claim 调了 2 次（13 步，18.53s）；学到程序性 guideline 后，不同任务员工 E-2048 的 TIFF 票据：先 convert_expense_attachment_to_pdf 再一次提交（10 步，11.35s，延迟约 -39%）。证据是程序迁移到了新任务，不是受控提升估计。

五、查询拓展

  • 顺着本文往下查的三条线：①ACE（Zhang et al. 2026, Agentic Context Engineering）——本文洞察2外部印证其 brevity bias/context collapse，且洞察1补上了 ACE 没研究的弱模型情形，值得对照读；②Anthropic dreaming（managed agents 文档）——按 recency 解决矛盾+剪枝过期，正是本文自认缺失的正确性/时新性信号的产品化形态，与 Hermes 的 auto-dream 类 cron 直接同构；③ExpeL（Zhao et al. 2024）——ADD/EDIT/UPVOTE/DOWNVOTE + 重要性计数（模型对 insight 质量投票，归零删除）与本文 support（独立推导次数守恒）是两种不同的信任度量，前者是正确性信号雏形。

六、关键实验结果速查（数字锚点）

  • DeepSeek-V3.2：79.8→89.3 TGC（+9.5）、64.3→80.4 SGC（+16.1），191 条全量，难split 60.4→72.9
  • gpt-oss-120b：39.9→55.4（+15.5，~29 条精选）/ 51.2（199 条全量 +11.3）——精选胜全量 7 任务
  • GPT-5.5：92.3→95.2（207 条，噪声边缘）；GLM-5：87.5 持平（饱和）；Gemma-4-31B：持平且被过紧核心伤害
  • 中等难度层最大收益：DeepSeek 中等 SGC 62.5→93.8（+31 分）
  • 压缩对照：12 条精选 +2.9 vs 191 条全量 +9.5（差 11 任务 > 噪声底 ~5 任务）
  • 成本甜点：47 条 sup≥2 = +27% token / +5.9 TGC；vs ACE token 263K vs 634K（40%）、116K vs 777K（1/7）
  • 噪声底：同配置两跑 56.0/54.8；DeepSeek 同配置 168 任务翻 32 个

七、归纳总结：创新点与本质

  1. 核心命题升维：把「agent 记忆有没有用」这个二元问题，改写成「剂量-响应曲线是模型能力的函数」——强模型单调受益、弱模型需要精选、饱和模型无感、过弱模型受害。这是记忆系统设计从「一刀切」到「参数化」的范式转移。
  2. support 守恒整合：与 ExpeL 的重要性投票、生成式智能体的 recency 加权都不同——support 是独立推导次数，作为硬不变量在合并中守恒（总和=原始lesson数，带回归测试）。这让「剂量」第一次成为可精确控制的旋钮。
  3. 失败模式分类学的价值：七条洞察里四条（provenance 丢失、support≠正确性、噪声底、静默失败）是反直觉的工程真相，任何一条都能让一个记忆项目得出错误结论。这类「部署账本」比 +2 分的方法创新更可复用。
  4. 方法论诚实：主动披露基线混淆（洞察6）、把小 delta 降级为噪声（洞察5）、自曝 CUGA 首次评测跑在写入bug上（第四节）——这是罕见的测量纪律，本身即是贡献。

八、局限性与未来方向

  • 自认的最重要缺口：无正确性/时新性信号（洞察4）。support 高的错误 guideline 会长期驻留并造成回归，目前只能手工修。作者明言「没有这个组件不跑无人值守记忆循环」。
  • 单一benchmark依赖：主要结论都压在 AppWorld（程序性 API 任务），对开放域/创意型任务的外推未验证。
  • 配置选择有泄漏：dev split 被记忆挖掘吃掉，「Best on test」列是直接在 test 上选配置——作者用「预设全量规则」缓解并如实披露，但最优剂量的无泄漏选择法仍是开放问题。
  • 洞察1的机制解释缺位：为什么强模型能消化 191 条而弱模型被 29 条之外的部分淹没，论文只给现象没给归因（指令遵循能力？上下文利用率？）。

九、趋势判断

  • Agent 记忆研究从「建系统」转向「调剂量+守不变量」：ExpeL→ACE→本文构成清晰演进线——从有没有记忆，到记忆怎么增长，到记忆按模型能力配给。下一站大概率是正确性信号自动化（对照 Anthropic dreaming 的 recency 裁决 + ExpeL 的投票，"验证型记忆维护"会成热点）。
  • 「部署账本」类论文正在成为独立文体：本文通篇 "what we expected / what happened / what we changed" 三段式，与其说是论文不如说是工程审计报告。对应用侧（包括 Hermes）的 ROI 显著高于常规方法论文。
  • 弱模型的记忆利用是增量市场：洞察1指出弱模型必须配精选小剂量——这意味着端侧/低成本模型（含 Jetson 本地推理场景）的记忆系统设计原则与云端强模型本质不同：不是「存多少」而是「怎么选 29 条」。
  • token 会计成为标配：洞察6把 token 列称为「对部署团队最决策相关的数字」——记忆系统的比较维度从精度单指标转向 精度×成本 双指标。

十、指南分析：七条部署建议原文（可直接执行的清单）

  1. 把剂量当一等参数，逐模型测量，对单调性不做任何假设
  2. 无损整合 + 投递时选择；默认不压缩
  3. 下游阶段要排序/筛选的每个字段，必须是每个上游阶段带测试保全的不变量
  4. 无人值守跑记忆循环前，先加正确性或时新性信号——复发不是真相
  5. 读任何小 delta 前先用重复运行建立噪声底
  6. 固定脚手架比较记忆系统，先报 delta，永远附带 token 数
  7. 假设失败都是静默的：断言调用数与库增长，响亮失败

十一、拓展应用推荐（关联 Hermes / Jetson / 量化交易）

对 Hermes Agent（高度相关，本文几乎是给 Hermes 记忆体系照镜子）：
- MEMORY.md 30K 固定上限对所有模型一刀切 → 按洞察1应模型分档：glm-5.3（弱于 terra/sol）配更小的精选核心，gpt-6.1 系可承受更大全量
- experience-bank/error-case-library 是「lesson 库」，但无 support 计数、无正确性信号 → 洞察4的分页教训直指风险：错误案例（如过时的端点、已修复的坑）会驻留并误导后续会话
- evolver 的合并逻辑对照「support 守恒」：合并技能/经验时是否丢失了 provenance（哪次会话、什么证据极性）→ 洞察3的带测试不变量可直接移植
- 洞察7第四起事故（CUGA 写入路径静默断裂、库一直空）→ auto-memory-keeper/memory-write 类 cron 需要「库实体数增长断言」——正好呼应我的「送达验证纪律」
- 成功+失败双轨挖掘 + 极性由真实结果判定（非 LLM 自评）→ session-evolution-scan 的挖掘准则可补这条

对 Jetson 边缘：nexa-local-inference 本地小模型（≈弱模型档）→ 按洞察1应配「~29 条精选」而非全量记忆注入；端侧上下文预算紧张时，47 条 sup≥2 甜点（+27% token 换 +5.9 TGC）是参考配比。

对量化交易：铁律/复盘规则的「support=被反复推导」≠「correctness=真赚钱」——洞察4 在交易域更锋利：一条被多次"验证"的盘感规则可能恰是系统性亏损源。stock-iron-rules 的每条铁律应带独立正确性信号（回测P&L归因），而非依赖复盘出现频次。
