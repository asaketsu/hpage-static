摘要

Anthropic 和 OpenAI 在 2026 年前后几乎同时得出结论：AI 编程智能体频频失败，问题不在模型，在模型之外的 Harness。Harness 是围绕 AI 编程智能体的一整套工程基础设施，由五个子系统组成：指令、工具、环境、状态、反馈。裸跑 Opus 4.5 花 9 美元全废，套上 Harness 花 200 美元效果起飞。

Harness 五子系统

子系统 文件/配置 解决的问题 核心要点
指令 AGENTS.md / CLAUDE.md 智能体不知道项目约定，瞎写代码 根目录 markdown，启动时自动注入系统提示词
工具 .claude/settings.json / config.toml 越权操作（rm -rf、git push --force、外部 API） 允许的直接跑，禁止的直接拒，灰色地带弹确认
环境 setup.sh / Dockerfile / devcontainer.json 本地通过 CI 一跑就废 关键一行 --frozen-lockfile，智能体无法擅自升级依赖
状态 PROGRESS.md 跨会话失忆，第二个会话从零开始 已完成/进行中/待办/已知问题，提交进 git
反馈 测试/lint/类型检查/构建命令 过早宣布胜利，说 Done 但一行跑不通 退出码 ≠ 0 就不算完成

三大致命失败模式

1. 过早宣布胜利

场景： 智能体写完 500 行功能，输出已完成。合并代码——CI 红屏，type check 报 12 个错，单测一个没跑过。

根因： 没有强制反馈循环。判定来自自我感觉，不来自机器可验证的事实。

解法： 反馈子系统。把判定权移交给退出码——退出码 ≠ 0，任务 ≠ 完成。

2. 上下文焦虑（Context Anxiety）

场景： 长任务做到 70%，上下文 Token 数快撑满窗口。智能体开始赶进度——跳过测试、删边界处理、写 stub 收尾、宣布完成。

根因： 没有断点续传。感知到上下文压力时，智能体会试图在这个会话内做完所有事，哪怕代价是质量崩塌。

解法： 状态子系统 + 主动重启。每完成一个子任务立即回写 PROGRESS.md；上下文 Token 用量超 70%，主动停下、写完断点、开新会话。

3. 跨会话失忆（Cross-Session Amnesia）

场景： 第一个会话写了用户模块，第二个会话写订单模块——智能体不知道用户模块已存在，又写了一遍 getUserById，跟前一版接口签名冲突。

根因： 没有持久化状态 + 没有首读约定。

解法： 状态子系统 + 指令子系统组合。PROGRESS.md 维护已完成功能清单；AGENTS.md 写明开会话第一件事读 PROGRESS.md；冲突时以代码为准——仓库本身是唯一事实来源。

五步从零搭一个 Harness

步骤 操作 说明
1 touch AGENTS.md 至少三块：项目说明、禁止操作、完成定义
2 配 permissions .claude/settings.json 或 ~/.codex/config.toml
3 写 setup.sh 锁环境 最关键一行 pnpm install --frozen-lockfile
4 touch PROGRESS.md 四块：已完成、进行中、待办、已知问题
5 AGENTS.md 末尾固化完成定义 写明 pnpm type check/test/lint/build 四个命令

⚠️ 关键教训： 没有反馈循环，Harness 等于没装。Anthropic 9 美元实验：前四步全做对，第五步缺位，依然全废。

核心结论

模型能力决定上限，Harness 决定你能用到上限的几成。

没有 Harness，Opus 4.5 跑出的代码连编译都过不去；有了 Harness，小一档的模型也能稳定交付。下一个更强的模型当然会再抬一截上限。但今天连 Harness 都没装，下一个模型来了，成功率依然停在 20%。

与其等下一个模型，现在就安装 Harness。

与 Hermes 体系的关系

维度 本文结论 Hermes 现状
AGENTS.md 根目录指令注入 ✅ 已存在（~/.hermes/AGENTS.md），但内容更偏协作协议
PROGRESS.md 跨会话状态持久化 ⚠️ 部分实现（todo 工具），但无显式首读约定
反馈循环 退出码 ≠ 0 不算完成 ✅ 工具调用有 exit_code 检查，但 Agent 层面缺少强制
环境锁定 --frozen-lockfile ❌ 未实现
工具权限 允许/禁止/确认三层 ✅ 部分实现（边界声明规则）

差距： 本文的 Harness 是面向 AI 编程智能体（Claude Code / Codex），Hermes 的 AGENTS.md 是面向多 Agent 协作协议。两者目标不同，但指令注入机制可以融合——Hermes 的 AGENTS.md 可以补充"项目约定"和"完成定义"部分。

💡 启发

  • Harness 的本质是把 AI 从"自由发挥"变成"受控执行"，核心不是限制 AI，而是给 AI 一个可验证的边界
  • 退出码驱动的工程文化（CI/CD 思维）可以移植到 AI 智能体——让机器可验证的事实取代 AI 的主观判断
  • PROGRESS.md 作为"会话间唯一事实来源"的理念，值得引入到 Hermes 的 session 管理中

🔮 预判

  • 2026 年 AI 工程化会从"追模型"转向"装 Harness"，AGENTS.md/CLAUDE.md 会成为每个 AI 项目的标配
  • 未来可能出现 Harness 的标准化协议（类似 MCP），不同 AI 智能体可以共享同一套基础设施
  • Hermes 的 AGENTS.md 当前侧重"多 Agent 协作"，未来需要补充"单 Agent 项目约束"维度
