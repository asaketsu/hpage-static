一、增量摘要

补充飞书卡片搭建工具（CardKit Builder）的完整功能矩阵、AI 一键生成能力、卡片版本管理机制，以及新版卡片（JSON 2.0）与旧版卡片（JSON 1.0）的关键差异。前序笔记聚焦发送 API 与 JSON 结构，本篇聚焦「卡片如何被创建和管理」。

二、关键发现

2.1 搭建工具功能矩阵（6 大能力）

  • 案例库：官方提供场景化参考案例，一键复制创建
  • 多语言：根据用户飞书客户端语言自动切换卡片内容
  • 组件体系：容器类（分栏/表单/循环容器）+ 展示类（标题/富文本/图片/表格/人员列表）+ 交互类（按钮/输入框/选择器）
  • 变量：为组件绑定变量，发送时注入业务值，实现一卡多用
  • JSON 源码查看：编辑页可直接复制卡片 JSON
  • 版本管理：发布时指定版本号，支持升级/回滚

2.2 AI 一键生成卡片（新功能）

搭建工具首页顶部「立即体验」入口，支持多种方式 AI 生成精美卡片。这是降低卡片开发门槛的关键能力——无需手写 JSON，用自然语言描述需求即可生成。

2.3 卡片生命周期四阶段

  • 阶段一入门：开发卡片交互机器人（推荐）/ 用应用发送 / 用自定义机器人发送
  • 阶段二搭建：方式一（推荐）搭建工具拖拉拽 / 方式二手写 JSON 2.0
  • 阶段三发送：调发送消息 API，支持流式更新
  • 阶段四更新：调更新卡片 API（PATCH，非 PUT）

2.4 新版 vs 旧版卡片关键差异

  • 新版（JSON 2.0）：新增 20+ 能力，官方推荐。schema: "2.0" + header + body.elements
  • 旧版（JSON 1.0）：不再获得新属性更新。config + header + elements（顶层）
  • 注意：JSON 2.0 新增能力不会回溯到旧版

2.5 卡片模板 vs 卡片实体

  • 卡片模板（template）：搭建工具创建，有唯一 template_id
  • 卡片实体（card）：通过 CardKit API POST /cardkit/v1/card/create 创建，有唯一 card_id
  • 发送时：模板用 {"type":"template","data":{"template_id":"xxx"}}，实体用 {"type":"card","data":{"card_id":"xxx"}}
  • 模板支持变量注入，实体用于流式更新和局部更新

2.6 三大嵌入场景

  • 消息场景：静态推送（告警/排行）/ 动态交互（审批/投票）/ AI 机器人（流式更新）
  • 消息链接预览：特定 URL 自动展开为卡片，无需跳转
  • 群置顶卡片：卡片可作为群置顶消息展示

三、对工作的价值

  1. AI 一键生成卡片可大幅降低 Hermes cron 推送卡片的开发成本——用自然语言描述布局即可，不必手写 JSON 2.0
  2. 版本管理机制解决了卡片迭代问题：可回滚到历史版本，适合 A/B 测试不同卡片布局
  3. 模板变量功能让 cron 摘要推送更灵活：一张模板 + 动态变量 = 每日不同内容
  4. 理解卡片模板 vs 实体的区别，有助于选择正确的发送方式（一次性用原始 JSON，复用用模板+变量，流式用实体 ID）
