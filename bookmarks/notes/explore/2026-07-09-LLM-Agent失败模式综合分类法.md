## 一、内容详细整理

### 1.1 核心问题与研究动机

论文综合分析了 2023-2026 年间 27 篇 benchmark/taxonomy/audit 论文，覆盖 19 个独立 benchmark，首次将工具使用、规划、长程推理、多智能体协作、安全性和测量效度整合为统一的 LLM Agent 失败分类法。

**核心发现**：
- 失败随任务长度**非线性复合增长**
- 子任务优秀 ≠ 端到端成功（组合性鸿沟 / compositionality gap）
- 增加脚手架（scaffolding）不等于可靠性提升
- 部分最常被引用的进步指标在独立审计后需要大幅修正

### 1.2 六大失败集群

**集群1：工具调用与参数级错误**

ToolScan 将工具使用错误分为 7 种类型：
- API 调用不足
- 参数值错误
- 参数名错误
- 参数类型错误
- 重复/冗余 API 调用
- 函数名幻觉
- 输出格式无效

关键发现：
- function-calling 模式在多函数调用场景下平均错误调用数约 77.5 次，远高于 prompting 方式的 21 次——结构化输出模式并未消除错误，只是改变了错误模式
- NoisyToolBench 发现：当必需参数缺失时，模型倾向于**编造合理值**而非询问澄清，这与 next-token prediction 训练目标直接相关
- 工具集越大、越多样，失败率越高

**集群2：规划与约束满足失败**

TravelPlanner 的标志性发现：
- GPT-4 多日旅行规划最终成功率仅 **0.6%**
- o1-preview 提升至 ~10%
- 配合外部形式验证器+批评器提升至 ~65%（最佳配置）
- 即使重度脚手架仍有大量规划未解决

三大失败根因：
- 追逐子目标时丢失全局任务焦点
- 未在正确步骤调用正确的信息收集工具
- 约束数量增长后丢失已满足/违反的约束追踪

test-time scaling 的反直觉发现：
- 串行扩展（更多推理 token）和并行扩展（更多采样轨迹）**均不可靠地改善**性能
- "上下文天花板"（context ceiling）：工作记忆饱和后额外推理不再有益
- "验证鸿沟"（verification gap）：Agent 无法可靠识别哪条候选轨迹真正解决了任务
- HAL 发现：提高推理努力在多数评估运行中**降低了准确率**

**集群3：长程退化与上下文管理**

METR 时间范围分析（最严谨的 Agent 能力测量之一）：
- 人类专家 <4 分钟可完成的任务，Agent 成功率近 100%
- 人类专家 >4 小时任务，Agent 成功率 <10%
- 50% 可靠性可完成的任务长度自 2019 年起每 7 个月翻倍

长上下文 Web Agent 退化模式：
- 短程变体成功率 40-50%
- 长程变体成功率降至 <10%（即使信息仍在 context window 内）
- 主要原因不是检索失败，而是**丢失原始任务目标 + 陷入重复无效循环**

"无恢复瓶颈"（no-recovery bottleneck）：Agent 在长轨迹深处一旦进入错误中间状态，大多数架构缺乏检测和回滚能力，单个早期错误传播至轨迹剩余部分。

**集群4：多智能体协作失败**

MAST 框架识别出 14 种失败模式，分三类：
- 规范与系统设计问题（~42%）：角色定义模糊、缺乏终止标准
- Agent 间对齐失败（~37%）：信息流断裂、假设冲突、上下文传播不完整
- 任务验证与终止失败（~21%）：验收标准错误、错误 Agent 过早终止

关键洞察：修复这些失败需要**深层结构性干预**（如改进 Agent 间"社会推理"），而非简单的 prompt 或协议调整。协调开销随交互 Agent 数量增长，可抵消甚至超过任务分解的收益。

**集群5：安全与安全失败**

ToolEmu（ICLR 2024 Spotlight）：
- 覆盖 36 个高风险工具包（银行、医疗记录、智能家居/IoT）+ 144 测试用例
- 即使最安全的评估 Agent 仍在 23.9% 测试用例中产生潜在严重后果的失败
- 主要触发因素：指令模糊时 Agent 基于未经授权的假设继续执行

InjecAgent（ACL Findings）：
- 标准 ReAct GPT-4 间接 prompt 注入攻击成功率 ~24%
- 强化攻击 prompt 下升至 ~47%
- 无安全微调的开源模型超过 80%
- 安全微调变体显著降低但仍非零

论文特别指出"旁观者伤害"（bystander harm）模式：智能家居设备监控的隐私伤害主要落在家庭成员、客人、家政工人身上——他们既未选择也未控制设备，却无权退出监控。当前 Agent 安全评测围绕"指令用户"的损害构建，未覆盖受影响但无交互的第三方。

**集群6：测量效度问题**

SWE-bench 审计发现：
- 修正数据泄露和弱测试套件后，一个代表性配置的成功率从 ~12.5% 降至 ~4%
- 增强单元测试改变了 25-41% 案例的排行榜排名
- 有研究直接质疑 SWE-bench Verified 测量的是真实问题解决能力还是训练数据部分记忆

HAL（Holistic Agent Leaderboard, ICLR 2026）：
- 21,000+ 次 Agent rollout，9 模型 × 9 benchmark，成本约 $40,000
- 提出成本调整比较：仅看标题准确率忽略了达成所需的计算/美元成本差异
- 发现提高推理努力在多数运行中**降低准确率**

核心结论：至少部分逐年基准改善反映的是评测方法收紧和早期测量误差修正，而非纯粹的能力提升。

### 1.3 Agent 确实进步的领域

论文明确列出了可信的进步领域：

**单轮工具选择**：BFCL 上前沿模型的单轮函数选择和参数准确性持续强且稳步改善，这与结构化输出模式、function-calling 微调、schema-grounded 生成的投资直接对应。

**短程 Web 导航**：WebVoyager 过滤子集成功率达 85-90%（从早期 GPT-4 的 <50% 跃升）；WebArena 从 14% 到 61.7%（18 个月，专用企业脚手架）。多个独立脚手架的架构趋同——模块化 planner-executor-memory 设计——佐证进步真实性。

**窄域编码任务**：即使修正后，SWE-bench Verified 2026 领先 Agent 仍显著高于 2024 基线，且多个独立脚手架（OpenHands、Agentless、商业编码 Agent）交叉佐证。

**安全微调作为独立有效杠杆**：InjecAgent 证明安全微调变体显著降低间接注入漏洞——一种针对性干预可测量地减少特定失败类别，即使不消除。

> **进步规律**：进步最可信的地方恰恰是任务最明确、最短程、最窄域的地方；最脆弱的地方是需联合约束满足、长程状态追踪或多 Agent 协调的地方。

### 1.4 实践指导：诊断检查清单

论文给出基于失败分类的部署诊断逻辑：
- 失败集中在参数错误/工具选择错误 → 改进 tool-schema 和 grounding（当前技术已在此领域表现强）
- 失败仅在任务变长时出现 → 投资上下文管理和层次化规划架构，而非单纯增大 context window
- 失败仅出现在多 Agent 配置中 → 收紧规范和验证协议，而非给底层模型加力
- 暴露于外部不可信内容 → 假设存在非零的间接注入基线漏洞，部署专项防御

## 二、查询拓展

### 2.1 METR 时间范围分析

METR（Model Evaluation & Threat Research）是一个专注于前沿 AI 模型能力测量的研究组织。其"时间范围"方法论是最严谨的 Agent 能力测量之一——让人类领域专家在相同的多步软件/研究任务上计时，然后比较模型完成相同任务的成功率。50% 可靠性任务长度每 7 个月翻倍是一个被广泛引用的趋势线，但论文强调 METR 将这一增长归因于**可靠性和错误恢复的改进**而非原始推理或工具使用能力的单纯提升。

### 2.2 组合性鸿沟（Compositionality Gap）

Press et al. 2023 提出的概念，描述模型在孤立子任务上的成功率与组合这些子任务的多步任务成功率之间的经验差距。关键发现是这一差距不随模型规模关闭——约束满足是与单步推理准确率不同的能力维度。这直接解释了为何 TravelPlanner 上 GPT-4 虽然能独立满足单个约束，但联合满足多个约束时成功率暴跌至 0.6%。

### 2.3 Context-Folding 架构

论文提及的一种长程 Agent 上下文管理方案（arXiv:2510.11967）：允许 Agent 分支进入有界子轨迹处理子任务，完成后将子轨迹压缩为简洁摘要并折叠回主线。这代表了一种从"增大 context window"到"智能管理 context"的范式转变，与 Hermes 的 context-compressor skill 理念一致。

### 2.4 HAL 成本调整评测

Holistic Agent Leaderboard（Kapoor et al., ICLR 2026）是首个系统性提出 cost-adjusted comparison 的评测框架。其核心论点：标题准确率忽略了不同模型/脚手架达成相同准确率所需的巨大成本差异。$40,000 的评测预算使其成为迄今最大规模的 Agent 横向评测之一。其"提高推理努力降低准确率"的发现直接挑战了当前流行的 test-time scaling 叙事。

## 三、归纳总结

### 3.1 六集群失败分类框架

```
LLM Agent 失败模式
├── 1. 工具调用层（最细粒度）
│   ├── 参数值/名/类型错误
│   ├── 函数名幻觉
│   ├── 冗余调用
│   └── 缺失参数时编造而非询问
├── 2. 规划层（约束满足）
│   ├── 子任务优秀 ≠ 端到端成功
│   ├── 约束追踪丢失
│   └── test-time scaling 失效（上下文天花板+验证鸿沟）
├── 3. 长程退化层（上下文管理）
│   ├── 非线性退化（4min→4h，100%→<10%）
│   ├── 丢失目标+重复循环
│   └── 无恢复瓶颈（早期错误不可回滚）
├── 4. 多智能体协作层
│   ├── 规范设计问题（42%）
│   ├── Agent间对齐失败（37%）
│   └── 验证终止失败（21%）
├── 5. 安全层（正交风险面）
│   ├── 指令模糊→未经授权假设
│   ├── 间接prompt注入（24-47%）
│   └── 旁观者伤害（未覆盖维度）
└── 6. 测量效度层（元问题）
    ├── 数据泄露/弱测试套件
    ├── 成本未调整
    └── 可靠性 vs 准确率
```

### 3.2 进步与停滞的对比模型

进步最可信的领域（任务明确+短程+窄域）：
- 单轮工具选择（BFCL）
- 短程Web导航（WebVoyager 85-90%）
- 窄域编码（SWE-bench Verified）
- 安全微调（InjecAgent 针对性降低漏洞）

进步最脆弱的领域（联合约束+长程+协调）：
- 多约束规划（TravelPlanner 0.6%-65%）
- 长程执行（METR <10% for >4h tasks）
- 多Agent协作（MAST 42%规范问题）
- 测量效度（SWE-bench 12.5%→4% 修正）

### 3.3 三条跨集群定律

**定律1：非线性复合** — 失败随任务长度非线性增长，不是因为信息丢失，而是因为错误传播+目标漂移+重复循环。

**定律2：组合性鸿沟** — 子任务能力不自动组合为端到端能力，差距不随规模关闭。

**定律3：脚手架边际递减** — 增加推理计算/采样轨迹/Agent数量不等于可靠性提升，存在上下文天花板和验证鸿沟。

## 四、趋势判断

### 趋势1：上下文管理将取代上下文长度成为核心约束

依据：论文明确指出"领域越来越将上下文管理，而非原始上下文长度，视为长程可靠性的约束瓶颈"。Context-Folding 等架构提案印证了这一转向。METR 将时间范围增长归因于可靠性和错误恢复改进而非推理能力，进一步支持此判断。

### 趋势2：test-time scaling 叙事将被修正

依据：HAL 发现"提高推理努力在多数运行中降低准确率"；General AgentBench 发现串行和并行扩展均不可靠地改善性能。这与当前流行的"给 Agent 更多推理时间就能变强"叙事直接矛盾。预计未来研究将区分 test-time scaling 的有效域（明确子任务）和无效域（长程约束满足）。

### 趋势3：Agent 安全评测将从"用户损害"扩展到"旁观者影响"

依据：论文的 bystander-harm 框架指出了一个系统性评测空白——当前 Agent 安全评测围绕指令用户构建，但智能家居/IoT Agent 的影响范围远超操作者。预计监管框架（如 EU AI Act 执行）将要求评估第三方影响。

### 趋势4：Benchmark 自身将需要"测量效度审计"作为标准流程

依据：SWE-bench 从 12.5% 到 4% 的修正、GAIA 测试套件增强改变 25-41% 排名，这些发现使得"未经审计的 benchmark 分数"的可信度大幅下降。预计预部署评测协议将包含标准化的泄露检测和测试套件强度评估。

## 五、关联分析

### 5.1 与 Hermes Agent 工具调用架构的关联

论文集群1（工具调用错误）直接映射 Hermes 的工具调用痛点：function-calling 模式的多函数调用平均 77.5 次错误调用 vs prompting 的 21 次，说明**结构化输出模式用一种不同的错误模式替代了另一种**。Hermes 的 agent-reliability-engineering skill 中的 Circuit Breaker/Fallback 机制正是对此类失败的工程缓解。

集群3（长程退化）与 Hermes 的 context-compressor skill 和 Self-GC（2026-07-03 笔记）直接对应——Context-Folding 架构理念已在 Hermes 中部分实现。论文的"无恢复瓶颈"理论为 Hermes 的 harness-checkpoint skill 提供了学术依据。

### 5.2 与 Hermes 多 Agent 架构的关联

集群4（多智能体协作失败）的 42%/37%/21% 分布对 Hermes 的 exchange-protocol（三机协作）有直接指导意义：规范设计问题占比最高，说明 jbot/ubot/abot 间的角色定义和终止标准需要最严格的设计。关联笔记：AI-Agent协议生态2026-MCP-A2A-ACP-ANP四栈对比（2026-07-07）、Agent自进化经验内化（2026-07-05）。

### 5.3 与量化交易 Agent 的关联

集群2（约束满足失败）的"组合性鸿沟"对量化交易 Agent 有直接启示：TravelPlanner 0.6% 的成功率说明多约束联合优化的难度。量化策略需同时满足回测收益/夏普比率/最大回撤/换手率等多个约束——这正是组合性鸿沟的高风险场景。关联笔记：量化Agent架构（2026-06 系列）。

### 5.4 与 Agent 可靠性工程的关联

论文的"三定律"（非线性复合/组合性鸿沟/脚手架边际递减）为 Hermes 的 agent-reliability-engineering skill 提供了完整的理论框架。该 skill 的七层降级架构正是对"脚手架边际递减"的回应——不是靠更多推理或更多 Agent，而是靠确定性的降级机制。
