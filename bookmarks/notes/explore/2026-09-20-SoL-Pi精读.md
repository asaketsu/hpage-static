## 内容整理

### 核心问题与研究动机
- Coding Agent 从"有监督补全"走向"全天候无人值守探索"，任务从单次预测扩展为长轨迹（推理+工具+反馈），token 成本成为 RSI（递归自我改进）的一阶系统瓶颈。
- 现有效率优化集中在三层：推理基础设施（attention kernel）、模型层（量化/压缩）、换便宜模型。本文走正交方向：**优化 Agent Harness 层**（模型与环境的中介层），无需训练模型。
- Harness 优化难点：工具调用、上下文管理、验证、委派、恢复、终止紧耦合，局部优化可能把成本转移到下游阶段。

### 方法论：SoL-Pi 自研究循环
1. **RSI 式 Harness 搜索**：研究 AI 观察 base harness 的执行轨迹 → 识别重复开销 → 提出候选改动 → 在研究环境中测试。接受条件双门禁：①能力指标全部在预声明容差内（指标对优化 agent 严格隔离，防作弊）；②至少改善一个声明效率指标。通过者取非支配解。
2. **Broad-to-Deep 两阶段**：外层广搜 152 个候选方向（六大家族：context/progress/tools/delegation/prompt&policy/improvement&evaluation），Oracle Analysis 先从已有轨迹找出"可避免的工作"；内层独立开发（Ralph Loop 迭代 + 独立 reviewer 审查 + 单轨迹分析器 + reducer 汇总）。
3. **搜索环境**：535 个可执行环境（495 个 GitHub issue-PR 真实任务 + 40 个带可执行验证器的合成任务）。
4. **防泄漏设计**：EdgeBench 51 任务中 11 个仅做冻结候选的单向验收，40 个留作最终泛化评估；held-out 结果永不回流搜索循环。

### 四个存活机制（全部通过能力约束筛选）
1. **Action Fusion**：把文件修改与其后续命令合并为一次请求，API 调用 3→2。
2. **Online Context Compact**：仅在子任务完成时评估压缩，且仅当预估节省 > cache 重写成本时执行（cache-cost gate，按上下文大小和 cache 写/读价格比估算，不单独计摘要调用成本）。
3. **ObservationPack**：大结果前 2 次请求全量发送，之后替换为稳定句柄 + 1KB 摘录，原文按需可取。
4. **Evidence-Preserving Reducer**：用低成本模型（GPT-5.6 Luna）压缩结果为证据摘要，确定性校验 receipt，失败则回退原文。

### 关键实验结果与数据
- EdgeBench 51 公开任务（GPT-5.6 Sol）：
  - SoL-Pi [Efficiency]：1.10B tokens（比 Pi 少 49.0%），保留 Pi 93.7% 分数（42.0 vs 44.8），token 成本降 33.2%，$0.4174/score。
  - SoL-Pi [Performance]：分数 44.8→47.2（+5.3%），token 流量还降 6.1%，效率 +9.8%。
  - 对比 8 个 harness（Codex/OpenSquilla/Oh-My-Pi/OpenCode/Oh-My-Opencode/Pi 等），SoL-Pi 两个操作点均领先。
- 跨模型泛化：在 Opus 5 上零改动迁移，同样降 token（2.37B→1.31B，-44.7%），Action Fusion 单机制把 Opus 5 分数推到 50.48。
- 单组件贡献（GPT-5.6 Sol）：ObservationPack 提分最多（47.2）；Online Context Compact 省 token 最多（2.15B→1.29B）。
- 估算每小时节省：相对原生 Codex/Claude Code $8.75-13.50，相对 Pi $4.36-5.71。
- 其他基准：Terminal-Bench 4、IMO 2026（Lean 4 验证）、内核优化基准均验证迁移性；还在 agent swarm 中做了协同评估。

## 查询拓展

- 关联脉络：SWE-agent（接口影响性能）→ GEPA（轨迹反思改 prompt）→ ADAS（agent 设计=代码搜索）→ AFlow/AgentSquare（工作流/模块搜索）→ Darwin Gödel Machine / Hyperagents（自改代码）→ 本文把该路线收敛到 token 效率目标 + 535 环境规模化。
- 提出长期方向 **"pretraining the harness"**：类比预训练，让 harness 在大量任务轨迹上更新，规模化环境数量与 idea 多样性可获得持续增益。
- 递归效率改进：更高效的 harness 降低自研究成本 → 固定预算覆盖更多环境 → 下一代 harness 更强，形成效率侧的 RSI 飞轮。
- 局限：harness 在单一 LLM 轨迹上训练，跨后端触发频率与强度下降（仍有效但打折）；作者计划多后端训练。

## 归纳总结

- 一句话：用 RSI 式自研究循环在 535 个环境上自动搜索 harness 改动，四个存活机制让 token 流量降 ~45-49%、成本降 1/3，性能不降反升，且可跨模型迁移。
- 本质贡献：把"harness 工程"从人工看轨迹改代码，变成可规模化、有防泄漏门禁的自动搜索问题；验证了 harness 层是模型/基础设施之外的第三条效率杠杆。
- 方法论亮点：指标预声明+隔离防 gaming、开发/验收环境分离、非支配筛选——这套门禁设计比具体机制更可复用。

## 趋势判断

- Harness-as-trainable-artifact 将成为 2026-2027 主线：harness 从手写工程变成在轨迹数据上"预训练"的可学习制品，与模型训练形成双轨。
- Token 效率取代单纯 benchmark 分数成为 agent 系统一阶指标（$8.75-13.50/小时 的节省直接可换算为无人值守 run 的预算延长）。
- 自动 harness 搜索 + 防泄漏门禁可能成为新评测范式：比"哪个 harness 好"更重要的是"harness 改进流程是否可复现、是否泄漏 held-out"。
- 对边缘部署的启示：cache-cost gate 的思想（按价格比决策是否压缩）可直接迁移到 Jetson 等本地推理的上下文管理。

## 拓展应用推荐（借鉴点评估）

按「收益×可行性」排序：

1. P0 - ObservationPack 模式移植到 Hermes 工具输出：大结果落盘+句柄+按需取原文（现有 context-compressor 是近似实现，增量价值在于"前 2 次全量、之后句柄"的分级策略和稳定句柄可寻址性）。工作量：中。
2. P0 - cache-cost gate 决策式压缩：Hermes 压缩时机目前靠启发式/阈值，可改为"预估节省 vs 重写成本"的门禁判断（尤其智谱有 cache 计价时）。工作量：小-中。
3. P1 - Action Fusion 对应工具调用合并：如"读文件+grep"合并为单请求（需上游支持组合工具，⚠️ 需 Hermes 核心改造）。
4. P1 - 指标预声明+隔离的 Skill A/B 门禁：本机 skill-ab-testing 已有候选版本机制，可借鉴"能力容差+非支配筛选+held-out 不回流"三件套强化。增量价值明确。
5. P2 - Evidence-Preserving Reducer：delegate_task 子代理结果先用小模型压缩+校验再回传主 agent。需工程改造（摘要模型路由+校验器）。
6. P3 - 全套自研究循环在 535 环境上跑：远超单机资源，仅作方向储备。

## 指南分析

- 读这篇的实操价值：不必复现整个自研究循环，直接抄"四机制+门禁设计"即可获得大部分收益——消融表（Table 4）表明单机制已可拿到大部分分数增益（ObservationPack +2.4 分）。
- 关键决策规则提炼：①压缩前先算账（节省>成本才压）；②大输出默认句柄化但保底全量窗口；③改 harness 必须先冻结验收指标且验收环境隔离；④每个机制都要有回退路径（机制失败→回到原文/原路径）。
- 适用边界：论文场景是长轨迹 coding agent（token 数十亿级）；对短会话场景（如日常飞书问答），机制触发频率低，收益有限——优先用在 cron 长任务和无人值守 run 上。
