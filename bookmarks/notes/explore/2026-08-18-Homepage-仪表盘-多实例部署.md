# 2026-08-18 Homepage 仪表盘：多实例部署

> 来源：[gethomepage.dev](https://gethomepage.dev) 官方文档 — Settings / Docker 章节
> 关键词：Homepage v0.8.x, instanceName, docker label discovery

## 摘要

开源面板 Homepage（GitHub 32k⭐）原生支持多实例部署，核心机制是 `settings.yaml` 的 `instanceName` 字段 + Docker label 前缀过滤（`homepage.instance.<name>.xxx`）。典型场景：同一 Docker 主机上跑"内网完整版"+"外网精简版"两个 Homepage 实例，共享一份服务发现标签体系但各自显示不同 URL/配置。

## 关键发现

**1. `instanceName` 字段是核心开关**
- 写在 `settings.yaml`：`instanceName: public` 或 `instanceName: internal`
- 仅用于 Docker 自动服务发现阶段过滤；YAML 手工配置的 services.yaml 不受影响
- 多个实例各自独立端口（默认 3000）+ 独立 config 挂载目录 + 独立 container_name

**2. Docker label 前缀过滤机制**
- 通用标签：`homepage.name=xxx`（所有实例共享）
- 实例限定标签：`homepage.instance.<name>.href=xxx`
  - `<name>` 必须与实例的 `instanceName` 精确匹配
  - 其他实例自动忽略带 `.instance.<name>` 前缀的字段
- 示例：容器同时带 `homepage.instance.internal.href=http://emby.lan/` 和 `homepage.instance.public.href=https://emby.mydomain.com/`，两个实例各自取到对应 URL

**3. Docker Swarm 支持**
- `docker.yaml` 加 `swarm: true`
- 实例须部署在 manager 节点（`node.role == manager` 约束）
- Swarm 必须用 `deploy.labels`，容器级 labels 不起作用

**4. 多实例与 Docker Socket 安全模型**
- 官方推荐 docker-socket-proxy 中间层（ghcr.io/tecnativa/docker-socket-proxy:latest）
- 多个 Homepage 容器可共享同一个 socket-proxy 实例，proxy 配置只读权限（`POST=0`）

**5. 与多代理共享 NFS 场景的关联**
- 本系统 jbot/ubot/abot 三台机各跑一份 Hermes，若各自部署 Homepage 仪表盘，可通过 `instanceName` + NFS 共享 config 目录实现"本地完整版 + 跨实例共享服务发现"
- 也可用于同一台机器同时提供"内网全量版（192.168.x.x:3000）"+ "外网精简版（只展示笔记/项目）"

## 对本工作的价值

- **多机场景**：jbot/ubot/abot 三台机若各自需要独立 Homepage 仪表盘展示本机状态，可用 `instanceName` + 独立 container 完全隔离
- **双版本展示**：内网完整版（含开发/运维工具）+ 外网精简版（仅对外展示笔记/项目/论文）—— 当前 hpage.top 就是"精简版"，未来可在此基础上加"内部完整版"端口
- **多 Docker 守护进程**：一台机器上若有多个 Docker host（如 host + rootless），可通过多个 `my-docker` entry + socket proxy 分别接入

## 行动建议

- **短期**：无紧迫需求。当前 jbot 单实例 + GitHub Pages 双部署目标已跑通。
- **中期（可选）**：若 ubot/abot 也需要各自 Homepage 仪表盘展示本地状态，可参考 `instanceName` 模式各自独立部署，无需改核心 scan_data.py
- **远期**：如需"内网完整版（含 hermes 管理入口）+ 外网精简版"并存，参考本笔记的 Docker label 前缀模式设计 config 分层
