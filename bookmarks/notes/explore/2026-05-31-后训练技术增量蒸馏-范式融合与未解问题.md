## 核心发现

### 1. 后训练范式的"三极收敛"：SFT → RL → 蒸馏 的数学统一

四篇笔记从不同角度揭示了一个正在形成的共识：SFT、RL、蒸馏三者并非独立步骤，而是同一优化问题的不同参数化。

**数学统一视角**：

- **SFT** = Forward KL 最小化（教师强制模式）：`min_θ E_{y~π_T}[−log π_θ(y|x)]`，本质是让模型在教师分布的支撑集上最大化似然
- **DPO/GRPO** = KL-constrained reward maximization：`max_π E[r(y)] − β·D_KL(π‖π_ref)`，当 G=2 时 GRPO 退化为 DPO
- **OPD（On-Policy Distillation）** = RLAD 证明了它等价于以教师为参考策略的 KL-constrained RL

**收敛点**：三者共享同一个 f-divergence 框架。SFT 是 Forward KL 的特例，DPO 是 Reverse KL 的隐式优化，GRPO 是带组归一化的策略梯度，OPD 则将蒸馏信号整合进 RL 的 trust region。

**增量价值**：这一统一视角解释了为什么 DeepSeek-R1 的三联流水线（RL → Dense Bridge → Student RL）优于直接在小模型上 RL——每一步都是同一优化问题的不同约束条件下的实例化，组合起来形成了从探索到利用的完整谱系。

### 2. SFT 幻觉根源的机制性解释与 RL 自修复假说

Yann Dubois 访谈中提出了一个极其重要的理论框架，结合数学笔记中的 RL 公式可以得到更深刻的理解。

**SFT 幻觉迫害者模型**：

SFT 的 MSE 目标函数惩罚"模型说不知道"的行为。当训练样本包含模型预训练先验（Priors）中未捕获的事实时（如特定小众文献引用），SFT 实际上在强迫模型拟合一个虚假的特征分布——它必须输出一个看起来正确的答案，即使内部表示中不存在该知识。

**RL 自修复机制**（基于 GRPO 数学推导）：

在 GRPO 的在线 RL 流程中：
```
A_i = (r_i − mean(r_1,...,r_G)) / std(r_1,...,r_G)
```

模型自采样的输出中，缺失事实的自然生成概率趋近于零（因为预训练先验中没有这个知识），所以这些输出不会被 RL 信号强化。更关键的是，GRPO 的组归一化机制使奖励信号聚焦在组内相对优势上，而非绝对值——这意味着即使奖励模型不完美，只要它能在组内区分"好"和"更好"，RL 就能有效工作。

**结论**：RL 不是"教"模型新知识，而是"过滤"模型不该说的东西。这与 SFT 的功能正交互补：SFT 教格式和风格，RL 筛选事实性和推理质量。

### 3. LoRA 在 RL 场景下的信息论优势：为什么 r=1 就够了

Schulman 的 "LoRA Without Regret" 给出了一个颠覆性的结论，结合 GRPO 的数学结构可以进一步深化。

**信息论论证**：

- SFT：每个 token 提供 O(1) 比特信息，10 亿 token = 10 亿比特
- RL（GRPO）：每个 episode 提供的信号仅为一个标量 advantage 值（O(1) 比特），即使生成了数千 token
- 信息密度差距：RL 的信息密度是 SFT 的 ~1/1000

**结合 GRPO 组结构的深层洞察**：

GRPO 的 advantage 是 G 个采样结果的相对排序信号。当 G=8 时（常见配置），每次更新只有 3 比特信息（log2(8!)的近似）。这意味着 RL 的信息瓶颈不在模型容量，而在采样策略和奖励信号质量。

**对 Agent 系统的映射**：Hermes 等工具使用 Agent 的自进化机制本质上是"无参数更新的 GRPO"——通过 prompt/context 优化（而非权重更新）来改进策略。这与 Training-Free GRPO 的思路高度一致。

### 4. Sparse-to-Dense Reward 的"资源分配第一性原理"

三联流水线笔记中的 Reward-Density Principle 可以提升为一个更普适的原则：

**资源分配第一性原理**：永远不要把稀缺的监督信号浪费在准备最不充分的策略上。

**在三个层次上体现**：

1. **模型规模层**：稀疏奖励（数学对/错）用于大模型（探索能力强），密集奖励（token 级蒸馏信号）用于小模型（需要精确引导）
2. **训练阶段层**：先 SFT 建立基础能力，再 RL 发现高级行为，最后蒸馏压缩
3. **信息粒度层**：组级排序信号（GRPO）用于探索，token 级似然信号（OPD）用于压缩

**跨域映射**：这一原则不仅适用于 LLM 训练，也适用于 Agent 的自进化系统设计——在知识积累早期使用宽泛的探索信号（如"这篇文章有没有用"的二元反馈），在能力成熟后引入精确的反馈信号（如"这个 Skill 的每一步是否正确"）。

### 5. GRPO 的梯度景观平坦性：RL 与 SFT 的根本结构性差异

自适应 Rank 实验揭示了一个比"r=1 够用"更深层的事实：

**GRPO 梯度平坦性**：
- SFT 下层间梯度幅度差异 >10×，存在明显的"关键层"和"冗余层"
- GRPO 下最大/最小层梯度比仅 2.17×，所有层均匀参与策略优化
- 前 30% 层仅承载 36% 梯度信号（SFT 下 >80%）

**根本原因**：GRPO 的 group-centered advantage 将梯度信号均匀地分配到所有层——因为策略改进需要整个网络协同调整，不存在可以跳过的"旁观者"层。这与 SFT 的逐 token 监督（某些层处理语法，某些层处理语义）形成鲜明对比。

**实践意义**：这一发现对 Agent 系统的"模块化微调"有启示——如果想要对 Agent 的特定能力做 RL 式强化，不能只训练"相关模块"，必须让整个系统参与优化。

## 技术细节与公式交叉验证

### DAPO 非对称裁剪的工程意义

基础笔记中记录的 DAPO 核心改进是对 PPO 裁剪函数的非对称化：

```
L_DAPO = E[min(ρ_t · A_t, clip(ρ_t, 1−ε_low, 1+ε_high) · A_t)]
```

**与 RLAD TRRD 的联系**：RLAD 的混合参考策略 `ρ̃ = π_θ / (α·π_T + (1−α)·π_old)` 与 DAPO 的非对称裁剪解决的是同一类问题——当策略与参考分布的偏差方向不对称时，对称裁剪会导致正负偏差被不均匀地惩罚。

**具体场景**：在 Agent 任务中，"不该做但做了"（假阳性）的惩罚通常应大于"该做但没做"（假阴性），因为假阳性的后果更严重（如执行了危险操作）。DAPO 的非对称裁剪允许 `ε_low ≠ ε_high`，从而建模这种不对称性。

### Training-Free GRPO 对 Agent 架构的启示

基础笔记中提到 Training-Free GRPO（ICLR 2026）的核心思路：不修改模型参数，通过优化 prompt/context 来改进策略。

**与 Hermes 自进化系统的映射**：

| Training-Free GRPO 概念 | Hermes 对应 |
|-------------------------|-------------|
| Experiential context | Skill 的 SKILL.md + references/ |
| Group sampling | 同一任务生成多个方案，组内比较选最优 |
| Advantage signal | 任务成功/失败反馈 |
| Prompt optimization | Skill patch/edit 操作 |

**实践启发**：Hermes 的 Skill 系统本质上已经在执行一种 Training-Free 的策略优化——通过修改指令（Skill 内容）而非模型参数来改进行为。可以更系统地引入 GRPO 的组采样思想：对同一任务生成多个 Skill 版本，用任务成功率作为 reward，选择最优版本。

### λ-GRPO 消除长度偏差

基础笔记中记录了 λ-GRPO（ICLR 2026 Under Review）通过可学习的 token 权重来消除 GRPO 的长度偏差：

**问题**：GRPO 的目标函数 `1/|o_k| Σ_t [...]` 按序列长度归一化，这导致模型倾向于生成更短的输出（更短的序列有更少的惩罚项累积）。

**λ-GRPO 方案**：为每个 token 引入可学习权重 λ_t，使模型自动平衡长度与质量：
```
J_λ = E[1/|o_k| Σ_t λ_t · (ρ̂_k,t · Â_k − β · D_KL)]
```

**对量化交易的映射**：在使用 GRPO 训练金融策略模型时，交易序列的长度（持仓天数）偏差与 LLM 的长度偏差完全同构——λ-GRPO 的思路可以用于消除策略对"频繁交易"或"长期持有"的先验偏好。

## 范式融合全景图

基于四篇笔记的交叉整合，2026 年后训练技术的完整演化路径为：

```
RLHF (4 模型: Actor+Critic+Ref+Reward)
  │
  ├─→ DPO (2 模型: Policy+Ref，隐式 RL)
  │     └─→ GIFT (GRPO + DPO 隐式融合)
  │
  ├─→ GRPO (1.5 模型: Policy+Ref 共享，Critic-free)
  │     ├─→ DAPO (非对称裁剪)
  │     ├─→ λ-GRPO (可学习 token 权重)
  │     ├─→ DenseGRPO (稀疏→密集奖励)
  │     ├─→ ShapE-GRPO (Shapley 值奖励分配)
  │     ├─→ Rank-GRPO (推荐系统专用)
  │     └─→ Training-Free GRPO (无参数更新)
  │
  └─→ RLVR (1 模型: Policy + Rule Verifier)
        └─→ DeepSeek-R1 的规模化验证
              └─→ 三联流水线: Teacher RL → Dense Bridge → Student RL
                    ├─ Sparse-to-Dense Reward Principle
                    ├─ RLAD/TRRD (蒸馏+RL 联合)
                    └─ OPD 统一框架 (f-divergence 视角)
```

**演化趋势**：
- 模型数量：4 → 2 → 1.5 → 1（减少外部依赖）
- 信号粒度：序列级 → 组级 → token 级（精细化）
- 与蒸馏融合：分离 → 联合 → 统一框架
- 工程复杂度：高 → 低 → 极低（LoRA r=1 + 统一 Rank 分配）

## 未解问题与知识缺口

### 1. 多模态后训练：VLM 对齐的 RL 范式尚未标准化

当前 GRPO/DAPO 主要在文本推理（数学/代码）上验证。多模态模型（如 Qwen-VL、GPT-5.5 视觉）的后训练 RL 是否需要特殊的 reward shaping？视觉推理的"可验证奖励"如何定义？

### 2. Agent RL 的 Credit Assignment 难题

工具使用 Agent 的轨迹包含多步工具调用，奖励通常是任务最终结果。如何将奖励归因到单个工具调用决策？这与长上下文 GRPO 的 token 级归因问题同构，但更复杂。

### 3. 小模型 RL 的探索瓶颈

三联流水线证明了大模型 RL + 蒸馏优于小模型直接 RL。但如果必须在端侧设备（如 Jetson）上做 RL 微调，如何解决小模型的探索不足问题？Schulman 的 r=1 理论是否仍然适用？

### 4. 后训练安全性：RL 是否会引入新的越狱向量？

SFT 阶段可以通过对齐数据集注入安全约束，但 RL 阶段的奖励模型可能被 reward hacking 绕过。GRPO 的组归一化是否能提供隐式的安全性保障？这是一个尚未被系统研究的问题。

### 5. 跨任务迁移：RL 获得的能力是否可组合？

DeepSeek-R1 证明了数学推理 RL 能力可以蒸馏到小模型。但这些能力是否可以与其他 RL 能力（如代码生成、工具使用）自由组合？多个 RL 阶段是否会相互干扰？

## 实践启发

### 对 Hermes Agent 自进化的映射

1. **Skill 质量的组采样评估**：对同一任务生成 3 个 Skill 版本，用任务成功率做组内比较，选最优 → 本质上是 Training-Free GRPO
2. **小批推进法 = Sparse-to-Dense**：先广泛探索（稀疏信号），再聚焦精炼（密集信号），与 Reward-Density Principle 同构
3. **进化日志 = Advantage 归档**：记录每次 Skill 修改的效果变化，相当于存储 advantage history，为未来的 meta-learning 提供数据
4. **经验库 = Dense Bridge**：将高频使用的高质量 Skill 作为"教师信号"，指导新 Skill 的生成

### 对量化交易模型的映射

1. **GRPO + 回测收益作为 reward**：比 DPO 更适合，因为可以自然处理多步决策的组比较
2. **λ-GRPO 消除持仓时长偏差**：防止策略偏向"频繁交易"或"长期持有"
3. **三联流水线**：在大模型上做策略发现 RL → 蒸馏到轻量部署模型 → 部署模型再做少量 RL 微调
