# 轻量检测模型端侧部署：运行时矩阵、量化分级与设备阶梯

> 探索日期：2026-10-17 | 兴趣等级：L2 | 来源数量：6（Ultralytics 官方部署指南 + arXiv 2502.15737 + IIETA ISI 期刊 + Informatica 50 + Ultralytics Orin Nano 基准博客 + 工程博客）| 前序笔记：2026-10-17-YOLO目标检测-v8到v13演进（架构侧，本篇为部署侧互补）、2026-06-03-YOLO部署到STM32可行性分析

## 摘要

轻量检测的端侧部署问题 = **模型压缩（量化/蒸馏）× 运行时选型（TensorRT/NCNN/OpenVINO/RKNN…20+ 格式）× 设备阶梯（Pi5 → Jetson Nano → Orin Nano/NX → NPU）** 三层联合决策，而非单点选模型。2026 年的格局：Ultralytics 官方一家就维护 20+ 部署格式，NPU 生态（RKNN/QNN/DEEPX/Axelera/IMX500 传感器内置）成为新战场；量化层面 INT8 QAT 已能以 mAP 损失 <2% 换体积 -62%、FPS +44%（YOLOv8 实测 25→36）；设备层面 Orin NX + TensorRT INT8 跑 YOLOv8n 达 65 FPS，而 Pi5+NCNN 被实测判"不满足实时"。全链视角下，预处理/后处理与热降频常是隐藏瓶颈。

## 关键发现

### 1. 部署格式矩阵：20+ 选项按硬件阵营收敛（Ultralytics 官方口径）

```
NVIDIA GPU  : TensorRT(engine, FP16/INT8) —— 顶格性能
Intel       : OpenVINO(CPU/iGPU/NPU)
Apple       : CoreML(ANE) + Core AI(.aimodel, iOS27)
移动/嵌入式 : NCNN(ARM优化) / MNN / LiteRT(.tflite) / ExecuTorch(XNNPACK)
边缘 NPU    : RKNN(Rockchip FP16/INT8) / QNN(Snapdragon Hexagon)
              / DEEPX(INT8) / Axelera Metis AIPU(856 TOPS)
传感器内置  : Sony IMX500(片上推理, 树莓派 AI Camera)
浏览器      : LiteRT.js(无需后端)
```

- 选型四要素：性能（硬件绑定）> 兼容性（ONNX 最广）> 集成难度（生态绑定）> 社区支持
- **NMS 是导出隐性成本**：NPU/单片机上后处理实现麻烦——无 NMS 端到端模型（YOLO26/v10 系）在端侧移植有结构性优势（与上午笔记结论互证）

### 2. 量化分级实测：INT8 QAT 是精度-速度最优解（三源交叉）

- **Jetson Nano 五模型横评（IIETA, COCO 2017）**：过实时线（4/5）全部是量化后版本——NanoDet-m INT8 QAT **142.9 FPS / 7ms / 0.0126 J 每次推理 / 38.2 mAP**（能效首选）；SSD-Lite-MobileNetV3 INT8 QAT 41.1 mAP @ 2.9W（通用首选）；YOLOv5s INT8 45 FPS（精度优先时）
- **EdgeTrack-YOLOv8（Informatica 50, 2026）**：FP16 体积 -38%、mAP 仅 -0.2、FPS 25→32；INT8 体积 **-62%**、FPS 25→**36**（+44%）、mAP -1.9——量化增益不是线性外推，QAT（训练中模拟低精度）比 PTQ（训练后校准）多保 1-2 个点
- **工程配方（车牌识别部署）**：PTQ INT8 + 选择性混合精度（敏感层保留 FP16）+ TensorRT engine + CUDA 预处理——混合精度是 PTQ 掉点的低成本补救

### 3. 设备阶梯与量化交叉实测（arXiv 2502.15737, 无人机场景）

| 设备 | 运行时 | 最优组合 | 关键数字 |
|------|--------|----------|----------|
| Jetson Orin NX | TensorRT | YOLOv8n FP16→INT8 | 52 → **65 FPS** |
| Jetson Orin Nano | TensorRT | YOLOv8s INT8 | RTT 44.27ms（FP32 73.18ms）|
| Raspberry Pi 5 | NCNN FP32 | —— | 实测不满足实时需求 |

- 云 vs 边端到端对比：通信延迟使云端方案在实时任务中劣化——边端赢在 RTT，云端赢在吞吐
- 警示样本：YOLOv11 在 Orin Nano 实测仅 21.48 FPS 的案例根因是**热降频**——无源散热小盒子跑不满标称帧率，基准数字≠现场数字

### 4. Orin Nano Super 实测基准（Ultralytics 官方 + 社区）

- JetPack 6.1 容器（CUDA 12.6 + TensorRT 10.3 + PyTorch）开箱即用，ARM64 适配已固化
- YOLO11n：.pt 直跑约 20ms/帧（≈50 FPS），TensorRT 优化后网络直播实测 100+ FPS，FP32→INT8 可再 4-5×
- TensorRT FP16 在 Orin Nano 上的合理预期：60-120 FPS（随 n/s/m/l 档位）

## 对现有工作的价值（关联分析）

- **ASC 自瞄云台（推理端在笔记本跑 YOLO12n）**：当前全链瓶颈是软件斜率限幅（20.2°/s）非检测延迟，但若迁到 Jetson Orin（手头就有 jbot 本机），yolo11n 级别 TensorRT FP16 即可 60+ FPS，检测环节延迟预算完全够；真要单芯片化时按格式矩阵选 STM32N6 NPU（对应 QNN/专用格式路线）或 IMX500 传感器内置方案重估
- **与 06-03 STM32 笔记闭环**：当时判"STM32 跑 YOLO 受限于算力"——本篇 NanoDet-m INT8（142.9 FPS @ 7ms @ 0.0126J）证明 MCU 邻近档位并非绝对禁区，关键在**换专用轻量架构 + INT8 QAT**，而非硬搬 YOLO 全量模型
- **量化方法论迁移**：DUCK 策略 ONNX 部署链已有 norm 对拍/冒烟测经验，检测模型 INT8 量化的"敏感层混合精度"思路可反向用于策略网络量化评估

## Actionable Insights

1. 端侧选型评估表固定五列：设备档 / 运行时 / 量化级（PTQ/QAT/混合）/ mAP 损失 / **每帧能耗（J）**——能耗列在电池供电场景（云台/无人机）比 FPS 更决定续航
2. 任何"基准 FPS"引用前先问散热条件：热降频可砍半（21.48 FPS 案例实锤），交付实测必须带散热状态说明
3. INT8 化优先走 QAT（数据集内模拟量化训练 1-2 epoch），mAP 损失可比 PTQ 收窄一半；PTQ 掉点时先试敏感层混合精度而非整体回退 FP16
4. NPU 移植评估先查算子支持度（超图/注意力等新模块常是坑，与上午笔记 v13 TensorRT 算子疑虑同源）

## 关键风险与盲点

- IIETA 横评作者自注"仅在 Jetson Nano + COCO 2017 上测得，不保证泛化"（来源级别：单平台学术实测）
- Ultralytics 基准为厂商自评（60-120 FPS 口径跨度大，未分档细列）（来源级别：厂商自评）
- 社区 FPS 数字（YouTube/博客）未注明输入分辨率与批量，横向对比需谨慎（来源级别：社区复现）

## 一页速查

> 部署=压缩×运行时×设备三层联合。格式矩阵按硬件阵营收敛：NVIDIA=TensorRT / Intel=OpenVINO / 苹果=CoreML / ARM=NCNN / NPU=RKNN·QNN·DEEPX / 传感器=IMX500。量化铁律：INT8 QAT 体积-62% FPS+44% mAP-1.9；PTQ 掉点先救敏感层（混合精度）。设备阶梯：Pi5+NCNN 不过实时线 / Orin Nano TRT-INT8 44ms RTT / Orin NX 65FPS。两个隐藏坑：NMS 后处理在 NPU 是隐性成本（选无 NMS 模型）；热降频砍半基准 FPS（实测必带散热说明）。能耗口径：NanoDet-m INT8 = 0.0126 J/帧，电池场景优先看焦耳不看帧率。
