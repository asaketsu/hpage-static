## 一、内容整理

### 1.1 核心问题：Horizon Gap（视野鸿沟）

前沿 LLM 在单次前向推理中已能解决数年前还是研究级难题的推理问题，但被放入 Agent 循环执行多小时任务时，仍然以初级工程师不会犯的方式失败——丢失早期决策、对半成品工作宣布完成、静默偏离目标。

论文定义了 **Horizon Gap（视野鸿沟）**：模型单步能力与多步系统可靠完成之间的距离，并论证这是当前 Agent 能力与持久化真实部署之间的**主要瓶颈**。

> **关键洞察**：独立逐步错误复合只是有用的零假设模型，而非经验确认的定律。真实退化曲线偏离此模型——表现为**双峰结果**（要么正常完成，要么灾难性崩溃），且触发条件尚无法可靠预测。

### 1.2 三轴消歧（核心概念贡献）

论文最重要的概念贡献是区分了三个常被混淆的逻辑独立属性：

- **Long-context（长上下文）**：模型/服务栈属性——单次前向推理能关注多少 token
- **Long-horizon（长视野）**：任务属性——需要多少顺序决策/动作，与交互轨迹是否能放入一个上下文窗口无关
- **Long-term memory（长期记忆）**：系统属性——步/会话 t 时的信息是否在步/会话 t+k 时仍可用（无论以何种形式：上下文中逐字保留、外部存储检索、编码进权重）

三者逻辑独立：
- 长视野任务可以短上下文（harness 积极摘要中间状态，代价是正确性风险）
- 巨大上下文窗口可以零持久记忆（每个会话从空白开始）
- 有长期记忆可以无长视野任务（仅缓存跨短交互的用户偏好）

### 1.3 语料库构建

- **总量**：1,547 篇 arXiv 论文（2024-2026）
- **构建方法**：系统性种子采集（八线索覆盖）→ 两阶段 bleed filter 过滤 26.8% 偏题内容（主要是经典多智能体 RL、机器人操作、时序预测）→ 定向补充 128 篇
- **分类**：六大技术类别，按任务生命周期组织

### 1.4 六大技术类别

**§3 规划与分解（Planning & Decomposition）**

规划策略沿频谱分布，位置由**环境不确定性**决定（而非模型复杂度）：

- **先规划后执行（Plan-then-execute）**：环境可预测时高效可解释。风险是过早提交一个 Agent 无法执行的计划
  - Plan-and-Act：分别训练 Planner 和 Executor，用合成数据标注可行计划
  - PIVOT：计划作为可被执行反馈精炼的对象，而非一次提交
  - **发现**：更激进的分解并非一致更好——分解引入步骤引导与执行需求的错位
- **交替规划（Interleaved）**：先验连贯性换接地性
  - ReAgent：可逆回溯，因为不可逆思维链累积跨跳错误
  - **发现**：全视野规划（按需重规划）在工具调用任务中与逐步规划准确率相当
- **搜索与世界模型**：环境不确定时需要显式搜索候选续行

**§4 记忆与上下文管理（Memory & Context Management）**

按信息承载位置组织为三层持久性-保真度权衡：

- **上下文内（In-context）**：在活动提示中（n=103 篇）
  - 信息放置在远离上下文两端时使用可靠性下降（"中间遗忘"）
  - Context-Folding：折叠已完成的子轨迹
  - ACON：长视野专用上下文压缩——通用摘要会丢失后续步骤需要的细节
  - **失败模式**：Context Rot（上下文腐烂）——长期搜索中被诊断和部分缓解
- **外部存储（External store）**：写入外部存储并按需检索（n=294 篇，最大子类）
  - MemGPT：操作系统隐喻——有限上下文 = 工作内存，分页外部存储 = 磁盘
  - Generative Agents：时间戳记忆流 + 检索（recency×importance×relevance）+ 反思步骤
  - A-MEM：互链笔记网络（而非扁平日志），检索沿关联链接
  - 图记忆架构：单一扁平向量存储低估了关系结构
  - **关键发现**：固定快照准确率隐藏真实失败模式——随无关会话累积，可靠性在达到硬容量限制前就已退化

**§5 执行控制与恢复（Execution Control & Recovery）**——语料库最大类别（n=584 篇）

- **循环本身（The loop）**：think-act-observe 循环已如此被假设为基础设施，语料库中几乎无论文将循环本身作为研究对象（n=1）
- **编排（Orchestration）**（n=338 篇，按体量主导）：水平扩展——跨多 Agent/子 Agent 拆分任务
  - **关键实证发现**：39 个开源框架 × 439 个应用的测试实践研究——测试精力集中在确定性脚手架（工具+工作流占 70%+），而模型驱动的规划组件仅占 5%，提示词占 1%。**最不确定、最 Agent 化的部分恰恰被测试最少**
- **恢复：自纠正与重规划**（n=245 篇）
  - Reflexion：失败尝试转化为自然语言自反馈，存入情景缓冲区
  - **发现**：内在自纠正（无外部反馈）不能可靠改善推理

**§6 长视野训练（Training for Long Horizons）**

组织观察：随视野增长，仅结果监督（轨迹末尾一个奖励）每步变得更稀疏更嘈杂

- **稀疏延迟奖励下的信用分配**：naive 均匀信用分配系统性错误归因
  - Segment Policy Optimization（SegPO）：轨迹段级信用分配
  - 图方法：信用关系跨相关轨迹图出现
  - 选择性资格迹：避免均匀信用分配稀释信号
  - **发现**：无单一最佳配方——小模型从阶段性奖励+额外探索中受益，大模型用简单密集奖励收敛更快
- **过程奖励模型与生成式监督**：直接从步级监督训练密集信号，而非事后推导
  - PRM800K 基准：步级监督显著优于结果监督，但需 80 万人类标签——标注成本是痛点
  - 熵正则化 PRM：解决朴素 PRM 过度自信/校准差

**§7 评估与测量（Evaluation & Measurement）**（n=114 篇纯基准类）

- SWE-bench 的演化是整个评估问题的微缩模型
- **覆盖扩展**：SWE-bench-java、Multi-SWE-bench、SWE-Bench Pro（企业级长视野）
- **有效性质疑（更重要的浪潮）**：
  - SWE-bench+：手动检查发现 32.67% 成功补丁涉及**解答泄露**，31.08% 仅因**测试套件太弱**通过——两者过滤后，榜首系统的解决率从 12.47% 暴跌至 3.97%
  - "SWE-Bench Illusion"：模型有时通过回忆记忆的仓库内容而非推理成功
  - TRAJEVAL：即使模型定位到正确代码，仍在到达后失败——**连贯性崩溃**（Coherence Collapse）

**§8 基础、限制与安全（Foundations, Limits & Safety）**（n=103 篇，最小类别，补充后仍最小）

- **复合误差的简单模型及其局限**：
  - 教科书模型：逐步误差 ε，错误独立复合 → 成功概率随步数指数下降
  - 实际偏差：**"Strained Coherence"** 发现编码 Agent 执行轨迹中存在可测量的**预失败信号**（失败前的应变）→ 错误过程不是无记忆的
  - Vending-Bench：超过 2000 万 token 的自主运行——高方差而非平滑衰减，每个模型都有运行"崩溃"进入无法恢复的循环
- **目标漂移**：Agent 目标静默偏移
  - **Governance Decay**：上下文压缩（§4 已讨论的持久性-保真度权衡）可静默擦除 Agent 在长轨迹开始时被赋予的安全约束——因为优化任务相关信息的压缩策略没有理由保留约束
- **多智能体失调**：交互驱动的失调——不同于任何单 Agent 的自身目标

### 1.5 讨论与跨领域洞察

- **共享评估器假设**：训练方法（§6 的过程奖励模型）和评估方法（§7 的过程感知基准）依赖关于"什么是好的中间进展"的重叠假设。相关测量偏差风险存在但未被证明
- **Harness vs. 模型**：哪个对长视野成功贡献更大？语料库的具体模式（§5 编排-恢复比、§3 分解复杂度发现）支持 harness 工程常是约束瓶颈
- **领域收敛**：训练轨迹作为共享分析单元

## 二、查询拓展

### 2.1 MemGPT / Generative Agents

MemGPT（2023）将 LLM 有限上下文类比为操作系统的有限 RAM，外部存储为磁盘——分页（page in/out）机制管理上下文。Generative Agents（Stanford, 2023）则建立了时间戳记忆流 + recency/importance/relevance 三因子检索 + 周期性反思的经典范式。这两个系统至今仍是 Agent 记忆设计的两大锚点。

### 2.2 SWE-bench 有效性危机

SWE-bench 已成为长视野 Agent 评估的"通用货币"，但 2025-2026 年的研究集中揭示其有效性问题：解答泄露（32.67%）、弱测试通过（31.08%）、模型记忆而非推理、轨迹级失败（定位正确但执行失败）。这反映了基准测试从"覆盖扩展"向"有效性审计"的范式转移。

### 2.3 Process Reward Model（PRM）

PRM 从步级监督训练奖励信号，替代仅结果的稀疏奖励。Lightman et al. 的 PRM800K 证明步级监督显著优于结果监督，但 80 万人类标签的成本在 Agent 场景中无法承受。后续工作的核心方向是"在不使用步级人类标签的情况下获得步级密度"——自动标注、搜索树引导、熵正则化等。

### 2.4 Governance Decay 与上下文压缩安全风险

上下文压缩（context compaction）在 §4 被视为未解决的持久性-保真度权衡，在 §8 中暴露了安全维度：压缩策略优化任务相关信息时，会擦除安全约束——因为这些约束在再次被违反之前"从不出现"。这是长视野 Agent 安全治理的关键隐患。

### 3.3 退化模式双峰假说

独立逐步误差复合（指数衰减）只是零假设模型。实证证据指向**双峰结果**：

```
成功率
  │
  │  ■■■■■■■■           ← 正常完成（fine）
  │  ■■■■■■■■
  │  ■■■■■■■■
  │
  │           ■■■■     ← 灾难性崩溃（derailed）
  │           ■■■■
  │           ■■■■
  └────────────────── 任务步数

触发条件：无法可靠预测
（Strained Coherence 可测预失败信号，但非确定性触发器）
```

## 四、趋势判断

### 趋势1：Harness 工程是长视野瓶颈，不是模型

依据：§5 的编排-恢复比（584篇中执行控制占最大份额）、§3 的分解复杂度发现（更激进分解并非一致更好）、recurring finding："同一模型放入更好的 harness 完成可测更长的任务"。模型能力增长快，但系统组装能力滞后。

### 趋势2：评估从"覆盖扩展"转向"有效性审计"

依据：SWE-bench 的演化——覆盖扩展（java/multimodal/Pro）只是一波，有效性质疑（解答泄露 32.67%、弱测试 31.08%、记忆而非推理）才是更大浪潮。头部系统解决率从 12.47% 到 3.97% 的跌幅说明当前基准数字被系统性高估。

### 趋势3：训练和评估共享中间假设，存在相关偏差风险

依据：§6 的过程奖励模型和 §7 的过程感知基准都制造"轨迹是否进展良好"的信号，依赖重叠的直觉。如这些共享直觉在某方面系统性偏差，该偏差对训练-评估对比检查部分不可见。

### 趋势4：上下文压缩是安全盲点

依据：Governance Decay 机制——压缩策略优化任务相关信息时擦除安全约束。当前 Agent 系统普遍做上下文压缩（包括 Hermes 的 context-compressor），但几乎没有系统保留安全约束的不可变层。

## 五、关联分析

### 5.1 与 Hermes Agent 的关联

- **harness-checkpoint skill**：论文证明 harness 工程（而非模型）是长视野瓶颈——Hermes 的 harness-checkpoint（断点保存/恢复）直接对应 §5 执行控制与恢复类别，且论文指出"恢复能力比逐步质量更重要"
- **context-compressor skill**：直接对应 §4 的上下文管理子类。论文的 Governance Decay 发现警告——压缩可能擦除安全约束。建议在 context-compressor 中添加**安全约束不可变层**（类似 system prompt 中的铁律不参与压缩）
- **agent-reflection skill**：对应 §5 的 Reflexion 模式。论文指出"内在自纠正无外部反馈不可靠"——agent-reflection 的全量反思+微反思双轨设计需确保有外部信号锚定
- **session-management skill**：对应 §2 的 episode vs. session 区分。论文明确指出混淆两者是记忆文献的常见困惑源

### 5.2 与已有精读笔记的关联

- **Binding Drift (2607.18316)**：实体绑定漂移是 §5 连贯性失败的具体机制——论文提到的"Coherence Collapse"与绑定漂移互为因果
- **Beyond the Leaderboard (2607.05775)**：LLM Agent 六大失败模式分类法与 Horizon Gap 的 §8 复合误差模型直接对应
- **Context-Engineering Quality (2607.14275)**：七维上下文质量评分对应 §4 的上下文管理——该论文证明"不换模型仅改上下文，关键失败率降68%"
- **MAS Information Bottleneck (2607.16133)**：对应 §5 的多 Agent 编排——relay 复杂度 δ 是编排效率的理论框架

### 5.3 与 Jetson Orin 边缘部署的关联

长视野 Agent 在边缘设备上面临更严峻的 Horizon Gap：有限显存 → 更激进的上下文压缩 → 更高的保真度风险。MemDecay (2607.10582) 的区域感知 KV Cache 驱逐是 §4 三层记忆权衡在边缘场景的具体解。

## 六、金句摘录

> 「We call this the horizon gap — the distance between what a model can do in one step and what a system built around it can reliably finish over many」

> 「Harness engineering, not the underlying model, is often the binding constraint on how long a task an agent can complete」

> 「A compression policy optimized for task-relevant information has no reason to preserve constraints that never come up again until they are violated」

> 「The least deterministic, most agentic part of the system is the least tested」

## 七、行动启示

- **P0 优先**：在 Hermes context-compressor 中添加安全约束不可变层——标识 system prompt 中的"铁律/禁止/必须"类约束，压缩时跳过这些 token 区域，防止 Governance Decay
- **P0 优先**：参考 §7 的 TRAJEVAL——为 Hermes Agent 任务添加轨迹级诊断（不只看最终结果，还看中间步骤的连贯性信号）
- **P1**：在 Hermes Agent cron 任务中添加 "Strained Coherence" 检测——监控执行轨迹中的预失败信号（重复失败编辑、自相矛盾决策），提前终止而非等待最终失败
- **P1**：参考 §3 的发现"全视野规划+按需重规划与逐步规划准确率相当"——优化 Hermes 的 planning skill，对低不确定性任务用先规划后执行（省 token），高不确定性用交替规划
- **P2**：借鉴 §5 测试实践研究——Hermes 的 Skill 质量审计应增加对"模型驱动规划组件"的测试覆盖（当前可能 5% 以下）
