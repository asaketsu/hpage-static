一、内容整理

1.1 核心问题：RSI 的性能-成本悖论

递归自改进（Recursive Self-Improvement, RSI）方法通过分析历史执行轨迹来迭代优化 harness，但既有工作（RHO、AHE 等）的性能提升通常依赖更密集的探索和更强的验证——性能涨了，token 消耗和延迟也涨了。论文核心问句：

"Can recursive harness self-improvement deliver better performance at lower execution cost?"

形式化为双目标优化：min (−PR(h), C(h)) s.t. PR(h) ≥ PR(h₀)——以初始 harness 的通过率为性能地板，寻求 Pareto 前沿。三个度量定义严格：

  • Pass rate：官方测试全过才算 1；train/val/test 三分割防泄漏，test 集只在进化完全结束后跑一次
  • Cost：token 三分类计费（uncached input / cached input / output，单价不同），按任务聚合取均值
  • Latency：墙钟时间，因服务器负载波动只作辅助指标不作优化目标

1.2 方法论：四 Agent 流水线

HarnessPro 是 label-free（无 ground-truth 解、无官方测试、无 grader）的多 Agent 进化框架，每 epoch 走三阶段：

Stage 1 轨迹诊断（Trajectory Analyzer）
- 每个候选 harness 在每个训练任务上独立跑 G=3 次，联合分析多次 rollout 而非单次（抗随机性）
- 输出结构化诊断 z(h,x)：问题清单 + 对性能/成本的影响 + 轨迹证据摘录

Stage 2 候选生成（Evolution Planner + Harness Editor）
- Planner 对每个候选提出三份计划，分别由三条指令引导：I₁ 省成本、I₂ 平衡、I₃ 冲性能
- Planner 可查看跨候选代码 Diff(h_i, h_k)，借鉴其他候选的有效机制
- 关键约束：计划必须可泛化而非任务特定；val/test 集对 Planner 隐藏防 benchmark 泄漏
- Editor 在独立 Git workspace 实现每份计划，commit 可追溯可回滚

Stage 3 评估与选择（Test Synthesizer + Pareto 筛选）
- 测试合成替代 LLM 自评——这是对 RHO 最关键的修正。论文发现 LLM judge 评估轨迹时过度乐观，常把有缺陷的实现判为成功。TestSynth 从任务描述 + 初始 harness 轨迹生成测试用例，全程固定复用保证候选间公平
- 硬数据：failure recall 从直接 LLM 判断的 41.7% 提升到 83.3%
- 筛选两步走：①丢弃低于性能地板 PR_val(h) ≥ PR_val(h₀) 的候选；②丢弃被 Pareto 支配的候选
- 三档代表选择：normalized weighted squared-distance 准则（Marler & Arora 2004），J_m(h) = α_m·d_perf(h)² + β_m·d_cost(h)²，按 lite/medium/heavy 三组权重各选一个最小者进入下一 epoch

训练集用 DPP（行列式点过程）核选 10 个任务的 coreset，平衡难度与多样性。进化 3-4 个 epoch，每轮最多保留 3 个 harness。

1.3 关键实验数据（GPT-5.5 × Codex）

Terminal-Bench 2（59 测试任务）：
- Vanilla（原始 Codex harness）：69.5% / $0.89 / 260s
- RHO：76.3% / $1.09 / 354s
- HarnessPro-Heavy：80.8% / $0.72 / 310s（比 RHO +4.5pp 通过率、-33.9% 成本）
- HarnessPro-Medium：76.3% / $0.56（性能持平 RHO，成本减半）
- HarnessPro-Lite：72.9% / $0.43（超 Vanilla +3.4pp，成本仅 48%）

SWE-Bench Pro（100 测试任务）：
- RHO：80.0% / $2.68 / 437s
- Heavy：80.7% / $1.97 / 333s；Medium：79.0% / $1.26（-53.0%）/ 326s
- 延迟同步受益：RHO 520s → Heavy 412s（成本优化顺带提速）

ProgramBench：Heavy 69.6% / $2.95 vs RHO 68.8% / $3.59（-17.8%）

GLM-5.2 × Claude Code 复现同样模式：Heavy 在三基准全部超 RHO 且成本更低（TB2 81.4%/$0.62）——优势跨模型家族成立。

Lite 档在三个基准全面超 Vanilla 且成本省 17.7-57.4%，是严格预算下的经济选择。

1.4 消融研究：合成测试是最硬的支柱

  • 去掉 Test Synthesizer 伤害最大：Heavy 在 TB2 从 80.8% 跌到 74.6%，SWE-Bench Pro 从 80.7% 跌到 72.0%（-8.7pp）——用有噪声的 LLM 直判选候选会让进化选错方向
  • 去掉 Planner 主要伤成本：性能小跌但成本回升（Heavy TB2 $0.72→$1.04）——无计划引导的编辑不知道该砍哪里
  • RHO + 低推理档（天真砍成本）：TB2 从 76.3% 崩到 62.7%——无差别降低推理努力不是降成本，是降性能
  • RHO + 动态路由 / + 预算 hooks 单独移植各有收益但都不及 HarnessPro 整体——收益来自机制协同而非单点

1.5 进化出的 Harness 长什么样

论文 5.3 节对 evolved harness 的解剖（比总分更值得抄）：
- 执行档案（execution profile）：从任务描述选择推理努力级别 + 工具调用预算，lite/medium/heavy 用不同选择 rubric
- 运行时预算 hooks：TB2 上 Medium 档 14 次工具调用后提醒并行化+去冗余检查，26 次后聚焦收尾验证，44 次后直接阻断
- 提醒注入位置：追加到 tool result 尾部，不破坏 prompt prefix，保住 KV cache 复用——成本意识渗透到上下文工程细节
- 静态冗余同步削减：RTK 式工具输出压缩（折叠重复日志、浓缩长输出）+ 精简 developer instructions
- 论文明确否认"靠压缩上下文或蛮力堆推理"取胜——是按任务动态分配推理与工具预算

1.6 进化动力学

  • TB2 heavy：epoch1→3 通过率 74.6%→80.8%，成本 $0.91→$0.72，每轮 Pareto 前沿都在推进
  • SWE-Bench medium 走了弯路：ep1→2 性能涨（70→77%）但成本也涨（$1.57→$1.66），ep3 才双改善（79.0%/$1.26）——递归多轮进化的价值在于有机会纠正单轮的方向性错误

二、查询拓展

2.1 RHO（直接前作与主基线）

RHO（Pan et al., 2026a，同组前作）同样做 label-free harness 进化，但用 LLM 自偏好（self-preference）比较轨迹选候选，只优化通过率单目标、只跑单轮。HarnessPro 的三处关键升级全部针对 RHO 的短板：LLM 判官乐观偏差→合成测试；单目标→双目标 Pareto；单轮→递归多轮。

2.2 DPP coreset（Determinantal Point Process）

行列式点过程核（Kulesha & Taskar 2012）度量子集多样性，这里用于从大任务池挑 10 个"难度×多样性"平衡的训练任务——用最少 rollout 预算覆盖最宽的失败模式空间。10 任务 × 3 候选 × 3 rollouts = 每 epoch 仅 90 次训练 rollout，进化总成本可控。

2.3 RTK 工具输出压缩

evolved harness 内置的 RTK（Szymkowiak, 2026）负责折叠重复日志、浓缩长工具输出——与 Hermes 的 context-compressor 渐进式压缩是同一思想家族，区别在 HarnessPro 把它作为可被进化选择器保留或丢弃的候选机制而非固定配置。

2.4 Cost-of-pass 经济框架

消融中出现的 CoP（cost-of-pass）列来自 Erol et al.（ICLR 2026）：单次通过的综合成本 = 任务成本 ÷ 通过率。这是评估"便宜但常失败"vs"贵但稳过"两条路线的统一货币。

3.2 三条核心洞察

  1. 验收信号质量决定进化方向：LLM 直判的 41.7% failure recall 意味着近六成失败被当成功保留，进化在错误梯度上爬坡。合成测试把这个数字翻倍到 83.3%——先修 judge，再谈进化。
  2. 降成本不能无差别砍：RHO+low reasoning effort 崩 13.6pp 证明"省 token"和"保性能"必须联合优化；有效解是按任务画像动态分配预算（简单任务 lite 档直达，难任务才烧推理）。
  3. 多轮递归有纠错价值：SWE-Bench medium 前两轮成本恶化、第三轮双改善——单轮进化容易陷入"性能 bought by cost"局部最优，递归给了框架机会发现并撤销无效机制。

四、趋势判断

趋势1：Harness 工程进入"性能-成本双目标"时代

依据：SkillMOO 已在 skill 层引入 Pareto set，HarnessPro 把它推到全 harness 组件 + label-free + 递归。对比表（论文 Table 1）显示 AFlow/RHO/AHE 全是单目标——2026 年下半年起成本维度成标配。

趋势2：LLM-as-judge 的乐观偏差成为公开问题，确定性合成测试接管验收

依据：41.7%→83.3% 的 failure recall 提升是论文最大单点贡献。与社区对 LLM 判官偏置的普遍担忧共振，"生成测试代替生成评价"会向 benchmark 不可得的私有任务场景扩散。

趋势3：运行时预算控制（hooks）> 静态 prompt 精简

依据：消融显示单独移植动态路由或预算 hooks 都能白拿成本收益（RHO $1.09→$0.92）且不掉点，说明这类机制是低成本高确定性的"免费午餐"，会先于完整 RSI 框架被工业界吸收。

趋势4：label-free 是企业落地的硬门槛

依据：真实业务没有官方测试集，HarnessPro 的 train/desc-only 测试合成管线是唯一可迁移的验收路径——比方法本身更值钱的是这个设定。

五、关联分析

5.1 与 SkillOpt 笔记的关联

SkillOpt-Agent技能自进化 记录的 SkillOpt 优化 skill 文档层，HarnessPro 的 Planner/Editor 管线结构与之同构（诊断→计划→编辑），但把优化对象从 skill 文档升级到完整 harness（prompts+tools+hooks+验证策略），且引入了 SkillOpt 没有的成本目标与 Git 隔离工作区。

5.2 与 Ecdysis / PAC 理论框架笔记的关联

Ecdysis-Harness自进化失败归因 归因的自进化失败（无准入门槛导致退化累积），在 HarnessPro 中对应"性能地板 + Pareto 支配过滤"双闸门；自进化AgentHarness理论框架-PAC泛化保留界与准入规则 的理论准入界在本文拿到了工程级实现证据——地板约束 PR(h)≥PR(h₀) 正是泛化保留界的经验形态。

5.3 与 Hermes evolver/skill-ab-testing 的映射

Hermes 的 evolver（错误模式→规则沉淀）等价于 Analyzer→Planner 单链；skill-ab-testing 的候选/正式版对照等价于 C_t vs A_t 评估。缺口在两处：①验收靠 LLM 判断而非合成测试（正是 41.7% recall 陷阱）；②准入只看效果不看 token 成本。

六、金句摘录

"LLM judges tend to be overly optimistic when assessing the execution trajectories, often treating flawed implementations as successful." — 对所有用 LLM 自评做准入门禁的系统都是一记警钟

"Performance and efficiency can improve together, making cost-aware evolution a promising direction." — 推翻"性能必须用成本买"的默认假设

七、行动启示

  • 验收层先于进化层：任何自进化回路的第一个投资对象是 judge 的 failure recall，不是进化算子
  • 成本三分类（uncached/cached/output）分别计量才能看清真开销——cached input 单价差一个数量级，提醒注入方式（保 prefix）直接影响这一项
  • 跨候选 Diff 信息喂给 Planner 是廉价的注意力机制：让每个候选知道别人试过什么

八、拓展应用推荐

  • Hermes skill-ab-testing：候选 skill 验证环节加"合成测试层"（从任务描述+基线轨迹生成可重复执行的确定性检查），替代纯 LLM 判断——对应 notes-eval-gate 的确定性六项检查思想，可推广到 skill 级
  • Hermes evolver 准入规则：错误修复 patch 合入正式版前，加"性能地板 + Pareto 支配"双闸门，并把 token 成本作为第二维度纳入判定
  • cron job 分档执行：按 job 重要度映射 lite/medium/heavy 三档 harness 配置（工具集/推理预算/验证强度），低价值守护 job 默认走 lite 档省 token
  • Gateway tool-call budget hook：长任务工具调用数达阈值后注入收敛提醒（附 tool result 尾部保缓存），超上限阻断——阈值须按自家任务分布实测，禁抄 14/26/44
  • 量化研究管线：因子/策略迭代回测的准入也可用 Pareto 支配过滤（收益-回撤-换手三目标），替代单目标排名

九、指南分析

  • 方法论价值——"先修尺子再优化"：论文把最大篇幅给了 TestSynth 而非进化算子本身，消融也证明它是最强支柱。这是可复用的研究/工程判据：任何依赖自动评估的优化回路，第一步审计评估器的漏报率。
  • 可复用结构——三计划分权引导：同一诊断喂给三条不同优先级指令（省成本/平衡/冲性能）生成三条分支，天然产出 Pareto 候选池。比单计划+随机扰动更可控，适合任何多目标进化场景。
  • 反例警示——天真降本的悬崖：RHO+low reasoning effort 的 -13.6pp 崩盘是给所有"省 token 运动"的对照实验：不区分任务难度的统一降档等于自废武功。
  • 工程细节即论文贡献：提醒附 tool result 尾部保 KV cache、Git 隔离工作区、DPP 十任务 coreset 控预算——这类实现级决策写进了正文，是"可直接抄"级的工程披露。
