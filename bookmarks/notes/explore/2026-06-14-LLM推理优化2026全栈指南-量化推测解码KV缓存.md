# LLM 推理优化 2026 全栈指南：从量化到推测解码

> 📅 2026-06-14 | 🔖 LLM Inference / KV Cache / Speculative Decoding
> 来源：Apple QuantSpec (ICML 2025), MorphLLM 2026 Guide, FutureAGI, Apple EpiCache (ICML 2026)

---

## 一、2026 推理优化的核心矛盾

虽然 LLM API 价格从 2025 到 2026 下降了约 80%（GPT-4 级从 $30/M → $0.40/M tokens），但**推理量增长速度远超降价速度**。Agent 工作流每个任务 50-200 次 LLM 调用，便宜的 token 单价累积成昂贵的任务成本。

三大叠加问题：

| 问题 | 影响 |
|------|------|
| **Context 膨胀** | 到第 30 轮对话，输入 token 是第 1 轮的 5-10x，大部分是过期内容 |
| **冗余计算** | 无缓存时，模型对相同前缀重复计算 attention（数十亿 FLOPs 浪费） |
| **硬件未充分利用** | 默认配置让 GPU 空闲（H100 只跑 50 tok/s 而非 16,000+） |

## 二、三层优化模型

```
┌──────────────────────────────────────┐
│  Layer 3: Application-Level          │  ← 应用层：压缩 token 数
│  Prompt Caching / Context Compression│
├──────────────────────────────────────┤
│  Layer 2: System-Level               │  ← 系统层：最大化硬件利用率
│  Continuous Batching / PagedAttention│
├──────────────────────────────────────┤
│  Layer 1: Model-Level                │  ← 模型层：降低参数计算成本
│  Quantization / Pruning / Distillation│
└──────────────────────────────────────┘
```

### Layer 1: 模型级优化

#### 量化（Quantization）

| 方法 | 来源 | 效果 | 备注 |
|------|------|------|------|
| **SmoothQuant** | MIT | 2x 内存降低，1.56x 加速 | 将量化难度从 activation 迁移到 weight |
| **GPTQ / AWQ** | — | 校准数据驱动的逐层优化 | — |
| **TurboQuant** | Google, 2026-03 | KV Cache 压缩到 3 bit，**零精度损失**，6x KV Cache 内存降低 | 2026 突破性进展 |

#### 知识蒸馏（Knowledge Distillation）

最优管线：**P-KD-Q**（先剪枝 → 再蒸馏 → 最后量化），每步效果叠加。

> 剪枝后的 6B 模型比未剪枝的 4B 模型更快 30%，MMLU 得分更高（72.5 vs 70.0）。

### Layer 2: 系统级优化

#### 连续批处理（Continuous Batching）

动态插入新请求，保持 GPU 饱和。**效果：3-10x 吞吐量提升**，Anyscale 测量到最高 23x。

#### PagedAttention（vLLM 标志性创新）

按需分配 KV Cache 页面，避免预分配最大序列长度导致的 90% 内存浪费。

| 指标 | 效果 |
|------|------|
| 内存浪费降低 | 最多 90% |
| 吞吐量提升 | 最高 24x |
| 相关方法 | ChunkKV（语义分块）、RocketKV（两阶段粗/细驱逐） |

#### 推测解码（Speculative Decoding）

小而快的 Draft 模型提出多个 token，大模型一次性并行验证。输出与标准自回归**数学上完全相同**。

| 实现方案 | 加速比 | 特点 |
|----------|--------|------|
| EAGLE3（通用） | 2-3x | 开箱即用 |
| 优化方案 | 5-5.5x | 深度调优 |
| **QuantSpec**（Apple） | ~2.5x | 见下文详解 |

> ⚡ **关键洞察**：Draft 模型的**延迟**比准确率对端到端速度更重要。

## 三、Apple QuantSpec：自推测解码 + 分层量化 KV Cache（ICML 2025）

### 核心创新

QuantSpec 提出一种**自推测解码**框架——Draft 模型与 Target 模型共享同一架构，但使用：
- **分层 4-bit 量化 KV Cache**
- **4-bit 量化权重**

### 性能指标

| 指标 | 数值 |
|------|------|
| 接受率（Acceptance Rate） | **>90%** |
| 端到端加速 | **~2.5x** |
| 内存需求降低 | ~1.3x（对比其他稀疏 KV 方案） |
| 优势场景 | 长上下文推理（KV Cache 是主要瓶颈时） |

### 为什么自推测比外部 Draft 模型好

- 无需训练/维护独立的 Draft 模型
- 同架构天然保证表示兼容性
- 量化层充当"轻量代理"，而非独立模型

### Apple 相关进展

| 项目 | 时间 | 关注点 |
|------|------|--------|
| **QuantSpec** | ICML 2025 | 分层 4-bit KV Cache 自推测解码 |
| **CommVQ** | ICML 2025 | 可交换向量量化，长上下文 KV Cache 压缩 |
| **EpiCache** | ICML 2026-05 | 情景式 KV Cache 管理，资源受限环境的长对话 |

## 四、推理引擎对比（2026 H100 基准）

| 引擎 | 版本 | 吞吐量（H100） | 核心特性 | 最佳场景 |
|------|------|---------------|----------|----------|
| **SGLang** | v0.4.3 | 16,200 tok/s | RadixAttention 前缀缓存 | 前缀密集型（RAG/Chat） |
| **LMDeploy** | 最新 | 16,200 tok/s | 持久化批调度 | 高吞吐服务 |
| **vLLM** | v0.7.3 | 12,500 tok/s | PagedAttention, Blackwell 支持 | 灵活性，频繁换模型 |
| **TensorRT-LLM** | 最新 | 高并发最高 | 编译 CUDA 内核 | 单模型长期生产 |

### 选型建议

- **vLLM**：灵活性优先 / 频繁换模型
- **SGLang**：共享前缀场景（聊天机器人、RAG）
- **TensorRT-LLM**：规模化生产最大吞吐（需要编译步骤）

## 五、Layer 3: 应用级优化（API 消费者 ROI 最高）

### Prompt Caching

复用已计算的 KV tensors（系统提示、历史）。

- **延迟降低**：Context >10K tokens 时减少 80-90%
- **Anthropic 实现**：缓存 token 不计入速率限制 → 80% 命中率下 5x 吞吐

### 语义缓存（Semantic Caching）

存储完整的请求-响应对，对语义相似查询返回缓存响应。**效果：重复查询模式节省 3-10x 成本**。

### Context Compression

在推理前移除低信号 token（过期历史、样板文本）。

- **LLMLingua**：最高 20x 压缩，但摘要方法准确率仅 3.4-3.7/5
- **Morph Compact**：专为长周期 Agent 设计的上下文压缩

### 模型路由（Model Router）

根据提示自动路由到最优模型，简单查询用便宜模型，复杂查询用贵模型。

## 六、对 Jetson Orin 边缘推理的启示

### 可直接应用的技术

| 技术 | 适用性 | 预期效果 |
|------|--------|----------|
| SmoothQuant (INT8) | ✅ 高 | 内存减半，1.5x 加速 |
| KV Cache 量化 | ✅ 高 | 长对话场景内存显著降低 |
| 推测解码 | ⚠️ 中 | 需要足够显存同时跑两个模型 |
| Context Compression | ✅ 最高 ROI | 零额外硬件成本 |
| 连续批处理 | ❌ 低 | 边缘通常单用户 |

### Jetson Orin Nano Super (8GB) 具体建议

1. **GGUF Q4_K_M 量化**为默认（已有 Skill）
2. **KV Cache 量化到 4-bit**（参考 QuantSpec 方法）
3. **上下文压缩优先**：Ollama 运行时通过 system prompt 精简 + 历史截断
4. **FlashAttention**：如可用，优先启用

## 七、效果叠加矩阵

一个编码 Agent 的真实案例：

```
量化 Llama 70B（2x 便宜）
  × vLLM 连续批处理（5x 吞吐）
    × Morph Compact 上下文压缩（60% 更少输入 token）
      = 综合效果 ~20x 成本降低
```

> ⚡ 三层优化**乘法叠加**，不是加法。Layer 3 对 API 消费者 ROI 最高，因为它与 Provider 侧优化复合。
