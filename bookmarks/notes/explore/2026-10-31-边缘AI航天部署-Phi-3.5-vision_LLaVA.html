Phi-3.5-vision vs LLaVA-OneVision：星载候选 VLM 选型对比

2026-10-31｜边缘AI航天部署 L4｜增量主题：候选模型选型对比方法，而非重复在轨实证/功率/热真空。前序：Gemma3-4B在轨实证(10-11)、抗辐射GPU(10-17)、星座经济学(10-20)、Loft平台(10-27)。

生成日期 2026-10-31

一、摘要

Phi-3.5-vision（4.2B，MIT）与 LLaVA-OneVision（0.5B/7B/72B，Apache-2.0）是 2024 年"小 VLM"两代代表作，但 2026 年在轨演示（NAVI-Orbital 用 Gemma3、OrbitWeaver 用 Qwen3-VL-2B）两者都没被选中。对比价值不在"选谁上天"，而在提炼星载 VLM 选型的六个硬判据：显存契约、视觉编码器内核支持、每帧 token 经济学、多帧能力、许可证、断点恢复状态量。结论：8GB 级平台（Orin Nano）只有 Phi-3.5-V 或 LLaVA-OV-0.5B 能原生放下；16GB 级（NX）起 7B 才可行；且视觉编码器 INT8 在 Jetson Ampere 上有实测延迟异常，飞行配置应保持视觉端高精度。[1][2][3][4]

二、关键发现

2.1 架构与资源契约：一个"刚好放下"，一个"必须分级"

  • Phi-3.5-vision：3.8B Phi-3.5-mini LLM + SigLIP-400M 编码器 + CLIP-ViT 前缀投影，动态分辨率 384/768/1344/2688，单图最高 1344²，最多 16 图，LLM 上下文 128K，MIT 许可。微软官方提供 ONNX Runtime GenAI 全平台优化版（CPU/CUDA/DirectML/移动 CPU），onnxruntime-genai ≥0.5.1 原生支持——这是"官方边缘交付链"的罕见完整度。[1][2]
  • LLaVA-OneVision：Qwen2 底座 + SigLIP-So400M-384 + AnyRes（384² 切块），0.5B/7B/72B 三档。关键实测：7B 档 fp16 仅权重就需 16GB，Orin Nano 8GB 必须走 flash 权重换出（Neuron Chunking 论文的整个出发点）。[3]
  • 显存阶梯（Jetson 实测口径）：Phi-3-mini 家族 INT4 ≈1.8GB、iPhone A16 原生 12+ tok/s 的先例，Phi-3.5-V INT4 全模型约 2.5-3GB 量级 → Nano 8GB 可原生容纳；LLaVA-OV-0.5B INT4 实测 1.43GB；LLaVA-OV-7B fp16 权重 16GB → 仅 NX 16GB/AGX 64GB 可行。[3][4]

2.2 精度：7B 档全面领先，但代价是 4GB 显存差

  • 空间推理 SPHERE（ACL 2025，11 维平均）：LLaVA-OV-7B 61.5 vs Phi-3.5-V-4B 54.3；多数子任务 LLaVA-OV 领先。[5]
  • MMEB 榜（UniME 同源 LoRA 对比，同训练配方）：LLaVA-OV-7B-LoRA(8.03B) Overall 70.7 vs Phi-3.5-V-LoRA(4.2B) 64.2，Grounding 差距最大（90.9 vs 81.8）。[6]
  • 盲测视觉推理 BlindTest（ACCV 2024）：最强开源 LLaVA-OV-72B 45.92 ≈ Sonnet-3 的 45.73——但 72B 与星载无关，只说明该架构上限高。[7]
  • 判读：同等参数预算下 LLaVA-OV 架构效率更高；但 4B 级 Phi 在 OCR/密集文本类任务有传统强项（基准细项），且遥感社区 EarthDial 选择 Phi-3-mini 做 LLM 底座配 InternViT-300M——说明 Phi 文本底座在 RS 指令微调生态里有真实采用。[8]

2.3 边缘实测三坑：量化≠加速，SigLIP INT8 有硬件级异常

  • 坑一（INT4 换显存不换速度）：Jetson Orin NX/AGX 实测，LLaVA-OV-0.5B LLM INT4 后 VRAM -24.3%（1.89→1.43GB）但 TPOT +49.1%——BitsAndBytes 反量化开销超过 INT4 计算收益，Ampere 架构上 INT4 只应视为显存手段。[4]
  • 坑二（SigLIP-So400m INT8 延迟异常 ×2.43-4.66）：三款 SigLIP-So400m 系模型（含 LLaVA-OV）视觉编码器 INT8 化后在 Jetson Ampere 上延迟暴涨 2.43-4.66×，而 SigLIP-2 系（Qwen3-VL）只涨 1.73-2.51×。这是"编码器-内核-硬件"三方交互问题，不是 SigLIP 缺陷——飞行配置视觉端应保 FP16 或走 TensorRT。Phi-3.5-V 的 SigLIP-400M 同族，需同款警惕。[4]
  • 坑三（能耗）：LLaVA-OV-0.5B INT4 后能耗仅 +1.4~1.9%（Qwen3-VL 反而 +45~55%）——小 LLM 反量化能耗代价小，这对功率受限于太阳翼+电池 DoD 的星载场景（见 10-14 笔记）是实质优势。[4]
  • 换出方案：权重放 flash 按需加载 + 神经元分块（Neuron Chunking，NeurIPS 2025）可把 I/O 延迟降 2.19-2.89×（最高 4.65×/5.76×）——8GB 平台跑 7B 的唯一现实路径，但引入 flash 写入寿命新约束，星载（抗辐照 flash 容量小）未必可复制。[3]

2.4 航天适配判定：为什么在轨演示两个都没选

  • 2026-10 最新在轨实证 OrbitWeaver：两颗真实卫星、Qwen3-VL-2B、Orin NX 16GB + AGX 64GB、72 小时 25 请求/星，核心创新是跨在轨中断的推理恢复（KV cache 持久化）。连同 NAVI-Orbital 的 Gemma3，在轨选型集中在 2-4B 当代模型——两大原因：(a) 32K token 输入（8 帧）下 prefill 时间与能耗随模型规模线性放大；(b) 中断恢复的状态量（KV cache）与模型规模成正比。[9]
  • token 经济学才是星载第一货币：OrbitWeaver 实测 3 分钟任务仅处理 8 帧（>32K token）。Phi-3.5-V 动态分辨率单图 1344² 会产生大量视觉 token，突发场景预算难控；LLaVA-OV AnyRes 384² 切块线性可预算。对 20s cadence 类任务（NAVI-Orbital 口径），可预测性 > 峰值精度。[9]
  • 什么场景会选谁：窄平台（Nano 级 8GB、立方星）+ 单图高价值目标识别 + OCR → Phi-3.5-V；多帧/视频时序（凝视任务、变化检测）+ NX 级 16GB+ → LLaVA-OV-7B 或其后继；0.5B 档只在极端功耗下作哨兵模型，配合地面大模型补判（Grace 式星地协同的星上端）。[4][9]
星载 VLM 选型六判据（本轮提炼，可复用）
1. 显存契约：权重+KV+视觉端，对照平台档位（8/16/64GB）
2. 视觉编码器内核：SigLIP 系 INT8 延迟异常 → 视觉端 FP16/TensorRT
3. token 经济学：每帧视觉 token 数 × cadence = prefill 预算
4. 多帧能力：AnyRes 线性 vs 动态分辨率突发
5. 许可证：MIT/Apache 均可飞行，闭源权重不可
6. 中断恢复状态量：KV cache 规模决定断点续算代价（OrbitWeaver）

三、对工作的价值

  • 技术变化：小 VLM 竞争焦点从"参数量"转向"资源契约完整性"——官方 ONNX 交付链（Phi 路线）与三档参数矩阵（LLaVA 路线）是两种可复用的产品化策略。
  • Hermes 借鉴：六判据可直接改造为本机 Jetson 模型选型清单（现状：luxtts/nexa 本地推理同样受 8GB 级约束）；坑二（SigLIP INT8 异常）对本机视觉模型量化同样适用。
  • 趋势判断：在轨 VLM 已进入"2-4B 当代模型 + 中断恢复工程化"阶段，2024 代小 VLM 的历史角色是选型方法论的训练素材；下一轮候选看 Qwen3-VL-2B 级与 Gemma3 系的功耗对比。
  • 归纳总结：星载场景"能放下、能预算、能恢复"三维全部达标才可入选，精度是第四位。
  • 关联分析：与 Gemma3 在轨实证（10-11）、功率约束（10-14）、LangGraph SLA（10-23）、Loft 平台（10-27）构成完整选型链——本篇补"模型本体对比"缺口，六判据把前四篇的功率/热/SLA/平台约束统一进单一决策框架。

四、行动建议与本轮落实

本轮仅落实研究产物，不采购、不改在役项目代码。
