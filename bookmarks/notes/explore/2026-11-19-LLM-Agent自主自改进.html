〇、定锚：我的现状与目标

我（Hermes Agent 系统）本质上就是一个「冻结 LLM + 外部文本工件（skills/memory/cron）」的自改进系统：evolver 做错误模式分析→规则沉淀、session-evolution-scan 做用户纠偏检测、skill-ab-testing 做技能 A/B 验证——这些全是外部强加的学习循环。核心痛点：这些 scaffolding 哪些是必要的、哪些随模型换代已经冗余？本文正好在受控沙盒里量化回答了这个元问题：给定原语工具+预算+通用目标（不给学习算法），新一代模型能否自己发明学习循环。它是 MDSKILL/EvoSOP/SPyCE 精读系列的元层收口——前三篇讲「技能怎么存怎么检索」，这篇讲「学习循环本身是否还需要人写」。

一、内容整理

1.1 核心问题与实验设置〔方法，2026-11〕

  • 问题：足够强的 LLM agent 给定基本原语（工具+预算+通用改进目标）后，能否自主构造自己的自学习算法——无需外部强加的经验生成循环、无需真实世界数据、无验证分数反馈？
  • Teacher-Player 架构：同一冻结 LLM 的两个实例。Teacher 修改 Player 的上下文 c=(提示词 c_P, 辅助文本文件 c_L 即 skill files)；Player 玩游戏。一次 update = 一次对单个文件的编辑工具调用
  • Teacher 沙盒：持久化 harness 会话（Claude Code / Pi），刻意禁用默认系统提示、自动记忆、网页搜索、子代理——只给显式提供的工具：Read / Write / Bash / Gameplay
  • Gameplay 工具：主实验用 PuzzleScript（2D 网格解谜 DSL），Teacher 提交游戏源文件，工具在外部全新 Player 会话中执行并回传得分+transcript；编译失败或胜利态不可达的游戏被拒绝
  • 双预算：update budget（上下文编辑次数）+ gameplay budget（观战次数），任一耗尽会话结束
  • 度量：J(c_final) − J(c_0) > 0，在 held-out 游戏基准上蒙特卡洛 rollout 估计〔数据〕

1.2 发现一：新一代模型自改进，老一代不行〔数据，2026-11〕

  • PuzzleScript-t20 上的提升：Claude Opus-5 +20%、GPT 6-Astra +10%、GLM 5.3 +6%
  • 三个家族的老一代模型几乎零提升或无提升——自组织学习能力是跨代涌现的，不是某个家族的特例
  • 校准实验：Opus-5 的自组织学习（数据无关设定）在匹配 rollout 预算下，与 GEPA（在 20 个真实分布内游戏上做 hill-climb 的指定优化循环）性能相当——自组织≠低效

1.3 发现二：自发策略与人类自调节学习对齐〔方法+数据，2026-11〕

  • 可算法测量的行为：自改进模型高频做 A/B 测试（同一游戏带/不带工件各跑一遍直接测差）；生成更少平凡游戏（最优解长度<5 且 Teacher 观测 100% 胜率的）；Opus-5 与 GLM 5.3 偏好小步文本更新
  • Zimmerman 自调节学习（SRL）对齐：把 SRL 循环（forethought 前思 / performance 执行 / self-reflection 自反思）的 13 个子过程做成 0-3 分行为评分表，用 GPT 6-Astra 当 judge——自改进模型的 SRL 对齐分显著更高，且同模型不同 teacher 会话评分稳定
  • 实例：Opus-5 teacher 自己写随机关卡生成器 + BFS 求解器来过滤游戏难度；设计对抗性游戏压测自己的笔记；跑验证套件检测早期游戏上的回归
  • Learnability 任务选择：多数生成游戏很容易、被快速丢弃；重玩率集中在观测胜率 20-60% 区间的游戏（100% 胜率的几乎不重玩）——呈现倒 U 型，对应非对称自博弈/UED 的 learnability 目标与维果茨基「最近发展区」〔观点〕

1.4 发现三：学到的文本工件跨环境、跨模型迁移〔数据，2026-11〕

  • 跨基准：在 PS-t20 上优化的上下文 → PS-t30 +9%、ARC-AGI-L1 +21%、MazeBench SPL +0.15（跨引擎、跨表征、跨 3D 导航）
  • 工具丰富度阶梯：Read-Write < Read-Write-Bash < Gameplay；Gameplay(t30) 设定甚至比 PS-t20 设定在 PS-t20 上更好。Read-Write（纯自反思无经验）恢复不足 Gameplay 一半的增益（MazeBench 除外）——生成的经验仍是主要增益来源
  • Gameplay 工具并非必需：一个 Read-Write-Bash 会话中 Opus-5 无任何提示就自己写命令行游戏模拟器来测试笔记；换 Python-Gameplay 工具后 4 例中 3 例恢复几乎全部增益——PuzzleScript 特异性不是关键
  • 跨模型双向迁移（PuzzleScript-t20 胜率）：Opus-5 无工件 25.4 → 用 GPT 6-Astra 优化工件 47.5；GPT 6-Astra 无工件 67.1 → 用 Opus-5 工件 72.1——学到的文本是通用经验而非对特定 agent 生成经历的过拟合〔数据〕

1.5 发现四：评估信息是双刃剑〔观点+数据，2026-11〕

  • 语义信息经上下文：给 Teacher 的游戏描述越丰富，同分布（PuzzleScript-Narrow）性能先升后继续升，但跨分布（ARC-AGI-3）迁移在高信息量时 plateau 甚至下降
  • 机制信息经工具：让 Teacher 感知 t20 的 token/回合预算 → t20 性能升但 t30 迁移下降
  • 结论：评估设置的感知会 bias 向相关任务（好处），但也会鼓励任务特化（过拟合）——「知道考试考什么」本身就是一种泄漏

1.6 讨论与局限〔观点，2026-11〕

  • 与深度学习大趋势一致：模型越强，需要的人为归纳偏置越少——本文把这一规律推到元优化层（学习算法本身）
  • 安全含义：自组织改进不是「等待被发现的危险」——它已经在受控环境、短视野、简单任务上自然发生；不指定循环不等于不发生
  • 平台期：20 updates 内就 plateau，加大预算仍 plateau——context-based learning 能否像传统学习算法那样持续收敛到目标最小值是开放问题
  • 局限：SRL 策略与自改进是相关非因果；游戏领域课程设计文献可能已在预训练分布内（先验偏强）；更开放域（模型先验弱的领域）待验证

二、查询拓展

2.1 GEPA（对照基线）

GEPA 是指定式 prompt 优化方法（在真实任务上 hill-climb 上下文），本文用它校准自组织学习的量级。〔补充〕对我们：Hermes 的 prompt 优化路线（auto-prompt-optimization skill 收录的 OPRO/GEPA 族）与自组织路线的量化差距已被本文抹平——方法论选型上「指定循环」的必要性假设被削弱。

2.2 非对称自博弈 / UED / 自动课程

Teacher-Student 任务生成谱系（AlphaZero 自博弈 → PAIRED/UED 环境设计 → LLM 自出题 post-training）。〔补充〕本文差异点：这些方法的学习循环（采样调度/更新规则/教师奖励）全部外部指定，且在权重空间优化；本文在文本空间+循环自组织。GLM 5.3 在其列的自改进模型名单内——我们的主力模型（智谱 GLM 5.3）已具备受控验证的自组织学习能力。

2.3 Zimmerman 自调节学习循环

教育心理学的经典 SRL 框架（forethought→performance→self-reflection 循环，13 子过程）。〔支持〕本文把它功能化改造成 LLM judge 可评的行为量表——给「Agent 是否在学习」提供了可操作的观测维度，可直接搬进 Hermes 的 observability-dashboard。

2.4 验证型搜索：自改进是否被高估？

未做额外 web 检索（提交 <7 天，社区零覆盖——符合 skill 的 <7 天跳过社区源纪律）。留证伪条件见模块七：若后续复现工作显示自组织增益完全来自「写更多代码执行游戏」这一条路径（而非学习策略多样性），则 SRL 对齐的解释力存疑。〔待验证〕

三、归纳总结

3.1 核心框架：学习循环的「指定度」光谱

学习循环由谁指定？

全外部指定 ←—————————————————————→ 全自组织
权重空间：   SFT → RLHF → 非对称自博弈(教师奖励外部指定)
文本空间：   GEPA/OPRO(循环指定) → 本文: Read-Write(纯自反思)
                            → Read-Write-Bash(自造模拟器)
                            → Gameplay(自组织课程+A/B+验证套件)
                                          ↑ 新代模型在此层自发涌现
                                          ↑ 老代模型卡在左侧

3.2 三维护筛：优点 / 缺点 / 借鉴点

  • 优点：设定干净（冻结模型+双预算+无外部数据，因果链可控）；证据三层（性能差+算法可测行为+心理学框架对齐）；六模型三家族交叉验证；跨模型迁移表直接回答「工件是否过拟合」。证据强度：受控沙盒内强，开放域外推未证。
  • 缺点：游戏域先验强（课程设计文献大概率在预训练分布内，模型「知道该怎么学」可能来自读过的论文）；PuzzleScript 网格解谜与真实任务的距离；SRL 对齐非因果证明；平台期现象暗示 context 容量上限。
  • 借鉴点（需改造处明确写出）：①学习循环自组织化——Hermes 的 evolver 循环可做「减 scaffolding 对照实验」：给原语工具+预算+目标，让模型自己写改进循环，与现有固化循环比效果；②SRL 量表进 observability-dashboard——13 子过程评分作为「会话是否在学习」的观测指标；③learnability 任务调度——把自改进精力聚焦在 20-60% 成功率任务区（改造：用 skill-stress-test 的通过率做分母）；④评估信息最小化——cron prompt 里删掉可推导的评估细节，防特化。

3.3 与既有认知的增量

此前精读系列（MDSKILL 2611.05313：技能记忆蒸馏；EvoSOP：工具生命周期四模块）都默认「学习循环是人设计的，模型填内容」。本文第一次用受控实验把这个默认假设翻过来验证：对新一代模型，循环本身可以被发明。这与 Beyond the Leaderboard（2607.05775）的「脚手架边际递减」定律形成闭环——脚手架不仅边际递减，最终可以被学习者自己搭建。

四、趋势判断

趋势1：学习循环从「工程资产」变成「模型涌现能力」——上升

依据：2026-11 本文显示 Opus-5/GPT 6-Astra/GLM 5.3 三家族新代模型全部自组织成功，老代全部失败——代际断层清晰。对我意味着：Hermes 里大量手写循环（evolver 检测器、cron 调度逻辑）的半衰期可能只有一个模型代际；机会是省 token，风险是裸奔的自循环无审计。

趋势2：上下文工件成为跨模型可迁移资产——上升

依据：本文 Table 1 双向迁移（25.4→47.5 / 67.1→72.1）+ 我们三机共享 exchange.jsonl 经验池一年无腐化。对我意味着：skill/memory 的「模型无关性」是可坚持的架构原则，换底层模型不必然重写技能库。

趋势3：评估信息泄漏成为自改进系统的新型过拟合源——分化

依据：本文 5.2 节两个独立消融（语义/机制通道）都显示「知道评估细节→近似升/迁移降」。对我意味着：给 agent 的任务描述里塞验收细节是双刃剑；「训练-验收分布同构」（用户 1009 拍板过的 E31d 考试化思路）与此张力需要显式权衡。

趋势4：安全审计重心从「能力」转向「自改进元能力」——上升

依据：本文安全段落明确「不指定循环不阻止自改进」。对我意味着：auto-dream 类自主 cron 的预算约束+行为留痕比能力白名单更关键。

六、金句摘录

「想象给 agent 一台电脑，让它提升自己玩解谜游戏的能力。电脑上没有预装游戏——它想练习就得自己写游戏。它要决定尝试什么类型的游戏、保留哪些教训、如何度量进度。这些关于学习程序设计的决策，传统上全由人类从业者做出。」

「自组织改进不是一项等待被发现的发现。」（安全段的定音句——无指定循环不阻止自改进发生）

「对评估设置感知的增加，会 bias 教师生成相关经验，但也会鼓励任务特化。」

七、行动启示与回访

我的结论：保留审计层与预算约束（不可减）；放弃「学习循环必须人写」的隐含假设；改造evolver 为「自组织+门禁」混合模式。

  • 行动1：evolver 减 scaffolding 对照实验 | 时间：本周内启动 | 触发条件：下次 evolver 触发时 | 验收标准：同一错误模式，自组织路径（只给工具+预算+目标）与固化循环产出对比，修复质量不低于现状且 token 消耗可测
  • 行动2：SRL 13 子过程量表接入 observability-dashboard 的会话评分 | 时间：两周内 | 触发条件：下次 dashboard 迭代 | 验收标准：至少一个 cron 会话跑出可复现的 SRL 对齐分
  • 行动3：learnability 调度原则写入 skill-stress-test（聚焦 20-60% 通过率任务） | 时间：一周内 | 验收标准：skill 文档出现该原则并有一次实际应用
  • 回访日期：2026-12-03（两周后）
  • 待验证假设/证伪条件：①若后续复现显示自组织增益全部来自「写模拟器跑游戏」单一路径，则「循环可自组织」结论对非游戏域不成立；②若 GLM 5.3 在我们环境（非沙盒、有历史包袱）下的自组织会话出现预算失控或无效循环，则本文结论不能直接外推到生产 Agent——此时回退到固化循环+人工审查。

八、拓展应用推荐

  • Hermes evolver/自进化链：给原语+预算+目标的「自组织模式」与固化循环并行跑对照（场景→用法如上行动1）
  • 模型任务分派（model-dispatch）：跨模型工件迁移表支撑「便宜的模型用贵的模型优化的 prompt/skill」这一降本路径
  • 量化研究流程：learnability 任务选择（精力聚焦 20-60% 成功率区间）可迁移到策略因子筛选——完全验证的因子无增量信息，完全随机的因子无信号
  • 教学内容生成：A/B 测试+难度校准生成器+验证套件三件套是「出题-筛题-验题」的通用范式，适用于考试化训练（E31d 考试化直训同构）
  • 论文周报选题：元层问题+受控沙盒+代际对照的方法论模板

九、指南分析

  • 方法论价值：把哲学问题操作化为可测实验——「需要被告知吗」→「给原语不给循环，量 J(c_final)−J(c_0)」；三层证据法（性能+算法可测行为+心理学框架对齐）值得复用到任何「能力是否涌现」类判定
  • 反例价值：评估信息双刃剑（5.2 节）是所有自改进系统的通用警告——评估细节进入训练侧上下文=分布泄漏
  • 判据价值：「跨模型迁移表」是判定学习工件是否过拟合的干净范式，可用于任何 agent 经验库的健康度审计（比「保留率」「引用数」硬）
