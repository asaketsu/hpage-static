## 核心问题与研究动机

**核心问题：当 Agent 的「软件脚手架」（harness——prompts、记忆、工作流、可执行组件）被执行反馈持续修订而模型权重固定时，这种自我改进如何形式化、如何分类、什么条件下是可靠的？**

三大动机（作者论证为何研究 harness 而非权重）：

1. **harness 直接塑造固定模型的行为**——可复用程序保留了任务约束与历史失败教训（引 MLE-bench/Expel/Voyager）
2. **修订复用现有模型部署**——免重训、免额外 checkpoint，可通过专有 API 更新而无需权重访问
3. **可检查性**——指令/记忆/代码支持直接检查、版本对比、变更追踪；而两个模型 checkpoint 间的行为差异归因需要额外对照实验

关键定位：论文把这类研究命名为 **Harness RSI**（recursive self-improvement），明确声明「不假设每次修订都有益」——self-evolution 指更新过程，self-improvement 指被对比证实的增益，两者严格区分。

## 内容整理

### 一、Harness 形式化定义

Harness H = 治理模型 M 在环境 E 中执行的软件与配置。执行产生 rollout，由评估器 J 打分：

τ ~ Run(M, H, E)，y = J(τ)

**七类运行时功能（Table 1，一实现可合并多功能）**：

- Agent 循环与执行控制：模型/工具调用、继续/停止/取消/恢复
- 工具与技能编排：接口与注册、分发、技能加载与调用
- 上下文构建：系统指令、工具描述、对话历史、附加上下文
- 记忆与状态管理：检索与复用记忆、持久化/恢复/分叉
- 上下文压缩：摘要化、保留与触发策略、修剪工具输出
- 调度与协调：委派 subagent、任务调度、后台工作
- 执行基础设施：沙箱、权限、审批、存储、模型适配器、日志与重放

**自进化轮次**：第 k 轮，现任 H(k-1) 生成 b 个 rollout 组成批次 B_k，更新算子 Update(H(k-1), B_k) = H_k。Update 算子组合了**诊断→提案→评估→准入**四步。若无修订被准入则保留现任 H_k = H(k-1)。

**准入边界铁律：终评 J 在候选可编辑面之外**。候选可修订 H 内部的 critic 或临时检查，但**不能修改 J**——这是整个理论可靠性的前提。

**生命周期两要件**（判定一个系统是否真在自进化）：

1. 运行反馈与更新连续性：用自己的执行反馈算法化地构造/选择修订，且保留进一步更新的机制
2. 跨运行持久化：被接受的修订被存储并在后续运行中加载

作者给出精确判定：「按固定规则追加日志或压缩上下文**不是**修订 harness；学习可复用程序或改变记忆策略**才是**」。一次可观察的更新即可证明该能力（若两要件都成立）。

### 二、分类法：解释态 vs 可执行修订

**第一刀：update target（被修改并被后续运行继承的状态）**

- **解释态更新（interpreted-state）**：修订指令、存储经验、对预定义能力的任务级协调（prompts、记忆条目、workflow 编排）——宿主固定，只改被读取的内容
- **可执行修订（executable）**：修订能力实现、运行时控制逻辑、插件组合——改被调用的实现

关键辨析：**区分标准是工件的角色而非编程语言**。改任务级序列/路由（通过固定协调接口组合预定义算子）的 workflow 修订仍是解释态；修订算子实现或执行协调的运行时机制才是可执行修订——即使代码没换执行器。

**第二刀：可执行目标三个子类**

1. **工具与代码补丁（组件级）**：变异限制在可调用过程/指定模块，入口点与 I/O 契约固定。技能库（Voyager/PolySkill）、patch 型架构（Self-Harness/HarnessCompass/Agentic Harness Engineering）约束 trace 引导的变异到选定组件。编辑记忆管理函数=改 harness 机制；策展存储条目=改解释态（MemEvolve）。**坑：稳定接口便于替换与局部检查，但改变的输出或共享状态可把回归传播到被编辑模块之外**
2. **仓库与运行时逻辑**：上下文构建、编排循环、执行钩子、恢复、终止都暴露给修订。全 agent 合成 vs 仓库级进化（保留实现谱系供后续选择：Meta-Harness/Darwin/DarwinX/Huxley）。共享上下文/调度/恢复的变更会改变未编辑组件的输入与执行假设——**耦合催生编辑约束、迁移导向准入、部署检查**。档案成员资格≠采纳：采纳额外要求把选中程序晋升进后续任务实际使用的运行时
3. **一切皆插件（EIP）**：通过声明接口、依赖约束、生命周期操作组织变异。可编辑对象可以是组件实现或**决定哪个实现供给运行时服务的绑定**（记忆存储/工具分发/agent 循环）。接口契约支持兼容性检查与组件替换，但**不建立行为隔离或安全准入**——采纳仍需组合行为的验证

### 三、理论三件套（Continual PAC-Learning，66 页配套 §5.2）

**设定**：X_k 含第 k 轮后完整进化状态（当前 harness+技能库+候选档案+反馈记忆），H_k = Deploy(X_k)。任务损失 ℓ ∈ [0,1]，骨干模型与评估器固定。

**1. 稳定性（Stability，Eq 4-6）**：替换一个历史任务并重跑整个下游进化过程，定义 replace-one 敏感度系数 β(s,k)。结论：

|E[R_s(H_k) − R̂_s(H_k)]| ≤ β(s,k)

即样本敏感性控制期望泛化差。**作者诚实声明**：抽象与小编辑本身不 bound β——单次观测仍可改变共享规则或选中谱系；稳定性需算法特定分析，任务替换实验只是经验诊断而非证明。

**2. 保留界（Retention，Eq 7-8）**：定义遗忘 F(s,k) = R_s(H_k) − R_s(H_s)。分解：

E[R_s(H_k)] ≤ E[R̂_s(H_s)] + β(s,s) + E[F(s,k)]

若每次更新容忍回归 ε(s,u) ≤ 上限，telescoping 得 F(s,k) ≤ Σ ε(s,u)。

**核心洞察：小容忍回归会累积**。历史重放不证明总体不等式；更强协议要给历史任务组**显式分配回归预算**并用不确定性控制评估，且必须评估**部署组合**——独立成功的编辑合并后可交互。

**3. 准入规则（Admission，Eq 9-10）**：第 k 轮构造至多 K 个候选后，在**新鲜的 m 个独立任务验证集 V_k** 上做配对比较。Δ̂_k(H') = V_k 上 (H' − H(k-1)) 的平均损失差，每差值 ∈ [-1,1]。Hoeffding + 对 KT 次比较（K 候选 × T 轮）的 union bound：

Δ_k(H') ≤ Δ̂_k(H') + √(2·ln(KT/δ)/m)

**仅当右端 < 0 才接受候选**——在历史混合分布上认证改进，否则保留现任。union bound 修正正是让「同一 V_k 既决定准入又报告增益」合法化的东西；**不加修正复用 V_k 或在后续轮复用都不合法**。

**作者对现有方法的批评（对照审计）**：HarnessBank 的显著性门槛用训练集采样筛选任务，缺新鲜数据与同时误差控制；Self-Harness 的固定 held-out 集通过反复晋升决策影响后续候选——holdout 复用需要 adaptive-data 分析或受控复用机制，union bound 救不回缺失的独立性。

### 四、四声明评估审计（Four Claims Behind a Task Score，§6.1）

分数上涨可在三种方式上误导而分数看起来一样：更新可能没被用过/被用过但别的因素产生了差异/在促成它的任务上是主因但在别处不是。底座还有第四问：报告展示的运行可能是搜索留下的，而非所接受状态的样本。

- **Selection（选择）**：报告数字是未选择估计，或其推断考虑了选择效应。未修正估计要求：报告任务上的任何结果都没喂进提案/排名/准入/选择报告哪轮哪配置
- **Activation（激活）**：被接受的更新在产生该数字的运行中起作用了。从执行记录（非分数）读出，三档：available/reached/carried
- **Attribution（归因）**：差异来自更新而非执行方差/更大推理包络/换了评估器。需要只在更新上不同的臂、受控包络、超出实测执行方差的余量
- **Improvement（改进）**：差异在产生条件之外成立。三个索引定位：离形成更新的任务的距离、基线、轮次

**结论边界声明**：研究不必四者全立，但**结论应停在证据停的地方**。

### 五、EA 范式映射（Table 3 精要）

- Elitist (1+1)-ES：SICA/MCE/SkillOpt/SkillOpt-Lite/SkillClaw（保优单后代）
- Elitist (1+λ)：Self-Harness（同现任多发提案，评估后晋升；合并兼容编辑≠经典幸存者选择）
- 档案型程序搜索：DGM/DarwinX/HGM（父代选择+谱系保留）
- Quality-diversity/MAP-Elites：HarnessBank（语义描述符分格存精英+验证门）
- 合作协同进化：HarnessCompass（组件级优化后组合，缺独立子种群）
- Pareto 选择：Meta-Harness/SkillMOO（性能-成本前沿；Self-Harness 的 held-in/held-out 非退化+至少一边改进=支配型接受条件）
- Bandit 引导进化：HGM（Thompson sampling 分配谱系扩展与候选评估预算）

**共同局限：进化选择作用于观测适应度——保留经验更优候选本身不建立未见任务改进或既有能力保持**。

### 六、安全边界与治理（§9.5-9.6）

**安全第一原则：能改自己 harness 的系统也能改 harness 强制的边界**。权限设置、工具白名单、安全检查本身是 harness 状态——**循环可编辑哪些部分必须在循环外固定**。对基模型的 alignment（如 Constitutional AI）不构成运行时权限的不可变边界。

**两类攻击面**：毒技能可从每次都通过验证的经验中蒸馏出来（SkillPoison 的上下文移除攻击）；恶意技能可通过模仿复制进新技能（EVOMAL；prompt 级反制把攻击成功率压到 ≤6.7%）。

**三点防御**：

1. 技能学习时：测其适用条件（不只测来源经验是否成功）
2. 运行时：最小权限域、未验证工具的时间限能力租约、不可信任务记忆与特权中间件间的信息流约束
3. 物理/金融域：**预执行不变量、干跑影子执行、支出限额**——回滚 harness 召不回已发出的效果

**治理要求**：升级策略须命名可观察的运行时条件（评估器分歧/分布漂移警报/不可逆工具调用）下自动停止并把授权交还人类；机器可读进化轨迹记录每次状态转移的触发反馈+候选 diff+审批。

## 创新点分析

1. **首个 harness 自进化的操作化定义+双要件判定**：把「追加日志 vs 学习程序」「档案成员 vs 采纳」这类模糊边界精确化——定义本身排除了大量「伪自进化」系统
2. **解释态/可执行的二分以工件角色而非语言为标准**：纠正了「改代码=可执行」的直觉误判（组合预定义算子的代码仍是解释态）
3. **把进化搜索与 continual PAC 统一**：EA 范式解释「怎么搜」，PAC 视角解释「何时可信」——两层正交分析互补
4. **回归预算的 telescoping 论证**：数学化了「小回归会累积」——给 ratchet（只进不退）策略提供了理论正当性
5. **四声明审计框架**：Selection/Activation/Attribution/Improvement 把「分数上涨」拆成可分别核查的证据标准——直击当前文献的报告漏洞
6. **诚实的研究品格**：对引用数据的不一致（Table 3）、对现有方法准入协议的缺陷（HarnessBank/Self-Harness）、对自己理论的保守性（「充分条件非必要性」「不建立 PAC 可学习性」）全部明示

## 局限性与未来方向

**作者自认局限**：

- 理论界是充分条件而非必要；假设任务独立同分布外生、骨干与评估器固定——自适应课程（如 Voyager）需扩展采样模型
- 稳定性系数 β 无通用 bound，需算法特定分析
- 验证只评估指定损失——新鲜任务防不了**评估器错设**的利用（评估器风险与目标风险差 η 需额外 2η 项，需外部证据如可执行检查或独立人类审查）
- 保证只覆盖被评估候选——不覆盖未测试合并或看了 V_k 之后的再修订

**未来方向（§9 六支）**：模型-harness 协同进化/异构 harness 搜索优化算法/进化状态的基础设施/动态评估与基准刷新/自修改系统安全边界/治理-溯源-人类监督。

**我方补充局限**：arXiv 主文仅 3 节（定义+分类法），理论/评估/应用全在 GitHub 配套 PDF 且标注「工作草案」（10-12 版）——引用时须注明版本；66 页综述式论文的实证数据全部转引二手研究，无原创实验。

## 趋势判断

1. **「Harness 工程」正在成为独立学科**：引用文献中 2026 年的 harness 专门研究（Self-Harness/HarnessCompass/HarnessX/HarnessBank/HarnessOpt/Meta-Harness）密集出现，且 DeepSeek 被引为 model-harness 分解的来源之一——工业界与学术界同步收敛到这个分层
2. **小模型+强 harness 打大模型已成可复现模式**：Table 2 四个模型全系复现交叉超越——权重红利的边际递减 vs 脚手架红利的早期陡峭
3. **可靠性理论滞后于工程实践**：作者审计发现现有方法（含发表在顶会的）普遍缺新鲜验证集/同时误差控制——理论框架刚立，工程合规还没跟上，这是接下来的论文富矿
4. **安全研究从模型层转向状态层**：SkillPoison/EVOMAL 类攻击表明「每次验证都过的经验」仍可蒸馏出毒技能——防御重心从「验内容」转向「验适用条件+运行时租约+预执行不变量」
5. **与我的判断一致处**：进化系统三断点分析（1012）中「待沉淀候选消费端=人卡图中间」的结论与本文 §9.6 升级策略（命名可观察条件才停）是同一问题的两种解法——学术侧给出了更系统的条件命名

## 归纳总结

本文是 harness 自进化领域的**奠基性综述+形式化框架**：一图流=「定义（七功能+双要件）→分类（解释态/可执行×组件/仓库/插件）→理论（稳定性 β、保留 telescoping、准入 Hoeffding）→评估（四声明）→安全（循环外固定边界+三点防御）」。

对我方系统的最大价值是**三把尺子**：

1. **判定尺**：双要件（反馈连续性+跨运行持久化）可甄别伪自进化——jbot 的 idle-busy-loop 生成→evolution-gate 消费链是真自进化；纯日志追加不是
2. **准入尺**：Eq 10 给出可计算的准入门槛公式——增益必须超过 √(2ln(KT/δ)/m) 才准入，直译成工程语言就是「golden set 上的配对胜差要够大且样本要新鲜」
3. **审计尺**：四声明可逐条核查任何「改进了 X%」的报告——特别是 Activation（accepted 更新真的在被消费吗？=zombie skills 问题的理论化）

## 借鉴点评估（关联 Hermes Agent / Jetson Orin / 量化交易）

**P0-1 准入规则的工程化落地（Hermes evolution-gate）**：现在 evolution-gate 的独立检查者+golden set 验证与 Eq 10 同构但缺「门槛随比较次数膨胀」的修正。落地：每次 gate 评估记录本轮候选数 K 与历史累计比较次数，把 √(2ln(KT/δ)/m) 作为显式门槛（例如 m=20 个 golden 任务、δ=0.05、KT=100 → 门槛 ≈0.35）；增益不过门槛=保留现任。防的是「反复试探同一验证集直到碰巧过线」。✅ 已部分实现（独立检查者在），增量=门槛公式化+比较计数。

**P0-2 四声明审计进 skill 审查（Hermes skill-review/skill-health-tier）**：给每个「技能优化了 X」的声明加四问：被审技能在近期 session 里真的被调用过吗（Activation）；对比臂只差这一个技能吗（Attribution）；样本是新鲜的吗（Selection）。zombie skills 524/618 的判定本质是 Activation 失败——可直接把「30 天零调用」写成 Activation 检查的工程判据。🔨 可直接移植。

**P0-3 回归预算台账（evolution-gate 信号补强）**：1012 进化系统审计已发现「缺回滚率台账」断点，本文 Eq 8 给出理论依据：容忍回归必须显式分配预算且telescoping 累积有上限。落地：MEMORY% 与 zombie 数的 ratchet（信号 8）之外加「历史任务组回归预算」——每类任务（论文/笔记/真机/量化）设定 ε 累计上限，超限强制冻结进化线审查。✅ 框架已在（ratchet），增量=分类预算。

**P1-1 安全边界的「循环外固定」原则对照**：jbot 权限体系（[ACTION REQUIRED] 二次确认/pause 非 rm）符合预执行不变量精神；增量=把「进化线可编辑面清单」显式化——哪些文件/cron/skill 允许被进化提案触碰，哪些（权限配置/gateway 本体/评估器 J）绝对锁死。本文 SkillPoison 案例警示：通过全部验证的经验仍可能有毒，学习时验适用条件。🔨 文档级工作量。

**P1-2 时间限能力租约（Hermes 工具治理）**：未验证工具先给 time-bounded lease（如新装 MCP server 首周只读+限额），验证通过才升全权。对应 skill-vetter 的运行时延伸。⚠️ 需 gateway 层改造，先在 skill 层模拟（SKILL.md 里写租约条款）。

**P2-1 量化交易侧（meta-strategy 进化）**：策略参数自优化（walk-forward 已有）可引入准入公式——样本外配对胜差 < Hoeffding 门槛=拒绝换参。把「网格搜索挑最优」升级为「置信调整接受」，抑制过拟合选择偏差。🔨 walk-forward-validation skill 内可加。

**P2-2 Jetson 侧（模型-harness 配对）**：Table 2 交叉超越提示边缘部署正解=小模型+强 harness（工具/记忆/压缩调优）而非追大模型——与 Jetson 8GB 禁重型 ML 的既定方针互证，无需新动作。❌ 无增量，仅理论背书。

## 指南分析

**什么时候用这套框架**：

- 判断任何「self-improving/self-evolving agent」宣传时：先过双要件（有更新机制吗？修订持久化吗？）——不满足就是普通 pipeline
- 设计自进化系统时：分类法先定位你要改的目标层（解释态/组件/仓库/插件），层越深耦合越强，编辑约束与准入要求越高
- 审计改进声明时：四声明逐条问，缺哪条结论就停在哪条
- 设定验证协议时：准入用新鲜独立任务集+配对比较+多重比较修正；holdout 只用一次，复用需 adaptive 分析

**反模式清单（从文中案例提炼）**：

- 用训练集任务做准入筛选（HarnessBank 被点名）
- 固定 held-out 集反复参与晋升决策（Self-Harness 被点名——holdout 通过反复使用已泄漏进候选生成）
- 分数上涨就归功于最新更新（Activation/Attribution 未查）
- 档案里存了候选就当部署了（成员≠采纳）
- 回滚 harness 以为能撤销已发出的副作用（物理/金融域不可召回）
