📌 核心发现

发现 1: 开源 TTS 质量突破商业拐点

Fish Audio S2 Pro (4.4B 参数) 在 2026 年 3 月开源，标志着开源 TTS 首次全面超越闭源系统：

  • 中文 WER: 0.54% — 低于 Qwen3-TTS (0.77%)、MiniMax Speech-02 (0.99%)、Seed-TTS (1.12%)
  • 英文 WER: 0.99% — 低于 Qwen3-TTS (1.24%)、MiniMax Speech-02 (1.90%)、Seed-TTS (2.25%)
  • Audio Turing Test: 0.515 (指令重写后) vs Seed-TTS 0.417、MiniMax 0.387
  • EmergentTTS-Eval: 81.88% 胜率 vs gpt-4o-mini-tts 基线 — 所有模型中最高，包括 Google/OpenAI 闭源系统
  • TTS Arena Elo: 1129 — 开源权重模型中最高

意义: 开源 TTS 在质量上已无短板，生产环境可放心采用自托管方案，无需依赖商业 API。

发现 2: Dual-AR 架构 + SGLang 优化实现亚 150ms 延迟

架构设计:
- Slow AR 模型 (4B 参数): 处理语言学和语义内容，生成低频音频 token
- Fast AR 模型: 处理高频声学细节，生成残余音频 token
- RVQ 音频编解码器: 10 个 codebooks，~21 Hz 帧率，44.1kHz 高保真重建

SGLang 推理优化 (继承 LLM 原生优化):
- Continuous Batching: 动态批处理，避免固定长度预分配浪费
- Paged KV Cache: 分页式 KV 缓存，按需分配内存
- CUDA Graph Replay: 减少内核启动开销
- RadixAttention Prefix Caching: 前缀缓存复用，多轮对话加速

性能数据 (NVIDIA H200):
- Time to First Audio (TTFA): ~100ms (目标 <150ms)
- 支持流式音频输出，适合实时语音交互场景

发现 3: 自然语言情感控制 — 15,000+ 自由标签

核心技术:
- 无需预定义标签集合，支持自由文本描述
- 示例: [whisper in small voice]、[professional broadcast tone]、[pitch up]
- 常见标签: [pause]、[laughing]、[inhale]、[chuckle]、[singing]、[excited]、[volume up]、[echo]、[angry]、[sigh]、[whisper]、[shouting]、[surprised]、[sad]、[moaning] 等

多说话人支持:
- 上传包含多说话人的参考音频
- 模型通过 <|speaker:i|> token 分别处理每个说话人特征
- 支持多轮对话生成

零样本语音克隆:
- 参考音频仅需 10-30 秒
- 提取说话人身份和情感状态作为上下文前缀

🔧 技术细节

安装方式

Conda 环境:

conda create -n fish-speech python=3.12
conda activate fish-speech

# GPU 安装 (选择 CUDA 版本: cu126, cu128, cu129)
pip install -e .[cu129]

# CPU 安装 (不推荐生产环境)
pip install -e .[cpu]

系统依赖:

apt install portaudio19-dev libsox-dev ffmpeg

硬件要求:
- GPU: 12GB VRAM 最低 (推理)
- OS: Linux 或 WSL
- 模型权重: HuggingFace fishaudio/s2-pro

推理代码示例

from fish_speech.inference import TTSInference

# 初始化
inference = TTSInference(
    model_path="fishaudio/s2-pro",
    device="cuda"
)

# 基础 TTS
audio = inference.synthesize(
    text="你好，这是 Fish Audio S2 Pro 的演示。",
    language="zh"
)

# 带情感控制
audio = inference.synthesize(
    text="[whisper] 我有一个秘密 [laugh] 不能告诉你。",
    language="zh"
)

# 语音克隆 (10-30 秒参考音频)
audio = inference.synthesize(
    text="这是克隆的声音。",
    reference_audio="path/to/reference.wav",
    language="zh"
)

# 多说话人对话
audio = inference.synthesize(
    text="<|speaker:0|> 你好。<|speaker:1|> 你好，很高兴见到你。",
    language="zh"
)

SGLang 流式推理

from sglang import Runtime

# 启动 SGLang 运行时
runtime = Runtime(
    model_path="fishaudio/s2-pro",
    tensor_parallel_size=1,
    mem_fraction_static=0.8
)

# 流式生成
from sglang import function, gen

@function
def tts_func(s):
    s += "生成音频 token..."
    s += gen("audio_tokens", max_new_tokens=1000)

# 使用 runtime 执行
result = tts_func.run(runtime=runtime)

💡 实践启发

1. 多语言 TTS 统一方案

S2 Pro 支持 80+ 语言，Tier 1 (ja/en/zh) 质量最佳，Tier 2 (ko/es/pt/ar/ru/fr/de) 可用。对于多语言应用，可单一模型覆盖，无需为每种语言部署专用模型。

适用场景:
- 全球化产品本地化
- 多语言客服机器人
- 跨语言内容创作

2. 情感控制替代传统 SSML

传统 SSML 需要预定义标签和复杂配置。S2 Pro 的自然语言标签更直观：

传统 SSML S2 Pro 自然语言标签
<prosody rate="slow"> [slow down]
<emphasis level="strong"> [emphasize this]
<break time="500ms"/> [short pause]
<voice name="whisper"> [whisper]

优势: 无需记忆标签语法，直接描述意图，降低使用门槛。

3. 流式 TTS 架构模式

对于实时语音交互 (Voice Agent)，采用流式架构：

文本输入 → SGLang 推理引擎 → 音频 token 流 → VQ-GAN 解码 → 音频流输出
                              ↑
                        亚 150ms TTFA

关键优化:
- 使用 SGLang 的 continuous batching 处理多请求
- RadixAttention 缓存对话前缀，加速多轮交互
- 流式解码，边生成边输出音频

⚠️ Jetson 边缘部署可行性评估

硬件约束分析

Jetson AGX Orin 64GB:
- 统一内存架构，GPU 可访问全部 64GB
- 但 GPU 计算单元有限 (1024 CUDA cores, 275 TOPS INT8)
- 典型推荐模型大小: 500-1000MB (未量化)

S2 Pro 4.4B 模型:
- FP16 权重: ~8.8GB
- INT8 量化: ~4.4GB
- INT4 量化: ~2.2GB

VRAM 需求对比:

配置 VRAM 需求 Jetson AGX Orin 64GB Jetson Orin Nano 8GB
FP16 ~8.8GB ✅ 可行 ❌ 不足
INT8 ~4.4GB ✅ 可行 ⚠️ 勉强 (需共享内存)
INT4 ~2.2GB ✅ 轻松 ⚠️ 可行 (需优化)

量化方案评估

方案 1: GGUF 量化 (llama.cpp 风格)
- 优势: 成熟工具链，CPU/GPU 混合推理
- 劣势: TTS 模型架构非标准 Transformer，需适配
- 可行性: 需验证 Fish Audio 是否提供 GGUF 版本

方案 2: TensorRT 量化
- 优势: Jetson 原生支持，INT8/FP16 优化
- 劣势: 需导出 ONNX，TTS 架构复杂
- 可行性: 高，NVIDIA 官方工具链

方案 3: SGLang + vLLM 风格量化
- 优势: 继承 SGLang 优化，支持连续批处理
- 劣势: 需验证 TTS 架构兼容性
- 可行性: 中等，需工程适配

初步结论

Jetson AGX Orin 64GB:
- ✅ INT8 量化可行，推理速度可接受
- ✅ 可运行完整 S2 Pro，适合生产环境

Jetson Orin Nano 8GB:
- ⚠️ INT4 量化勉强可行，需深度优化
- ⚠️ 推理延迟可能较高，不适合实时场景
- 建议: 优先使用 Fish Audio API (云端) 或 Kokoro (边缘首选)

🔍 知识缺口

  1. Jetson 实测数据缺失: 需要实际在 Jetson Orin 上测试 S2 Pro INT8/INT4 推理延迟和音质
  2. TensorRT 导出流程: S2 Pro 的 TensorRT 导出步骤和兼容性未验证
  3. 量化后音质损失: INT4/INT8 量化对 WER 和主观音质的影响未知
  4. 多说话人边缘部署: 多说话人场景在边缘设备上的内存占用未评估
  5. SGLang Jetson 兼容性: SGLang 在 Jetson 平台的支持程度需验证
