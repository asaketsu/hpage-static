## 核心结论（一句话）

**EAGLE-3 是 2026 年推测解码的生产标准，通过跨层特征融合将接受率推到 0.80-0.88，在 H200 上对 Llama 3.3 70B 实现约 3.6× 加速；P-EAGLE 进一步打破自回归草稿瓶颈，在单次前向传播中生成全部 K 个草稿 token，在 B200 上再叠加 1.05-1.69× 加速。两者已合并进 vLLM、SGLang、TensorRT-LLM 主线。**

## 一、推测解码基础：为什么需要它

LLM token 生成在低 batch 时是**内存带宽受限**的——GPU 每生成一个 token 都要从 VRAM 加载完整模型权重。

推测解码打破"每次前向只产 1 token"的限制：
1. 轻量 draft head 提出 N 个候选 token
2. 目标模型在**单次前向传播**中验证全部 N 个
3. 收集约 3 个被接受的 token（代价仅为 1 次目标模型步骤）

```
传统：[目标模型] → t1 → [目标模型] → t2 → [目标模型] → t3
推测：[草稿 t1,t2,t3,t4,t5] → [目标模型一次性验证] → 接受 t1,t2,t3
```

---

## 二、EAGLE-3 的核心改进

### 2.1 与 EAGLE-2 的关键差异：跨层特征融合

| 版本 | Draft Head 输入 | 接受率（指令跟随） | 接受率（代码） |
|------|-----------------|---------------------|----------------|
| EAGLE-2 | 仅最后一层 hidden state | 0.72-0.78 | 0.75-0.80 |
| EAGLE-3 | 所有层特征融合（gated） | 0.80-0.88 | 0.83-0.90 |

EAGLE-3 添加了**跨所有 transformer 层的特征融合**：通过学习的门控机制聚合每一层的激活值，再传给 draft head。Draft head 现在基于目标模型的**完整计算上下文**做预测，而非仅最后一层摘要。

**最大收益场景**：目标模型的早期层表示携带有用信息的任务——代码生成、结构化输出、多步推理。

### 2.2 Draft Head 架构

- 单层轻量 transformer（约 1-3B 参数，取决于目标模型 hidden dimension）
- 与目标模型共享 tokenizer
- **不需要微调目标模型**
- 训练耗时：4×H100 上约 2-4 小时，用目标模型的保存激活值作监督

### 2.3 EAGLE-3 vs Medusa

| 维度 | Medusa | EAGLE-3 |
|------|--------|---------|
| 架构 | 直接在目标模型上并接多个解码头 | 独立轻量 draft head + 特征融合 |
| 头间关系 | 头之间独立预测，不共享上下文 | 共享目标模型全层上下文 |
| 长草稿稳定性 | 接受率随长度快速下降 | 跨任务类型稳定 |
| 生产性能 | 比 EAGLE-3 低 15-25%（tokens/sec） | 当前 SOTA |

## 三、P-EAGLE：打破自回归草稿瓶颈

### 3.1 EAGLE 的隐藏瓶颈

EAGLE 的草稿生成是**自回归的**——要产 K 个草稿 token 就需要 K 次草稿模型前向传播。当草稿质量变好、草稿长度增加时，这个开销变得显著，限制了激进的推测深度。

### 3.2 P-EAGLE 方案：并行草稿生成

P-EAGLE 在**单次前向传播**中生成全部 K 个草稿 token：

**Step 1 — Prefilling**：目标模型处理 prompt 并生成新 token，捕获内部 hidden states（`h_prompt` 和 `h_context`）。

**Step 2 — P-EAGLE Draft Head**：并行构建每个位置的输入：

- 位置 1（NTP）：新 token embedding + `h_context`，与标准 EAGLE 相同
- 位置 2-K（MTP）：嵌入和 hidden state 尚不存在 → 用**可学习的共享占位符**：
  - `emb(mask)`：共享 mask token embedding
  - `h_shared`：共享 hidden state 向量

所有位置一起过 N 层 transformer + LM head，一次预测 `t1, t2, ..., tK`。

### 3.3 训练挑战与解决

**内存爆炸**：训练 K 个并行组在长度 N 的序列上会产生 N×K 个位置。N=8192, K=8 → 65,536 个位置 → 注意力矩阵 65K×65K 超过 40 亿元素（bf16 下 8GB）。

**解决方案**：序列分区算法（Sequence Partition）——将 N×K 位置序列分成连续块，维护跨块边界的注意力依赖，在同一序列的块间累积梯度。

### 3.4 实测性能（B200 GPU, GPT-OSS 20B）

| 基准 | P-EAGLE vs EAGLE-3 加速比 |
|------|---------------------------|
| MT-Bench | 1.05-1.20× |
| HumanEval | 1.30-1.50× |
| SpeedBench | 1.40-1.69× |

预训练 P-EAGLE head 已在 HuggingFace 发布：GPT-OSS 120B、GPT-OSS 20B、Qwen3-Coder 30B。

## 四、生产部署：vLLM + EAGLE-3

### 4.1 关键配置参数

| 参数 | 作用 | 推荐值 |
|------|------|--------|
| `--speculative-model` | EAGLE-3 draft checkpoint 路径 | HF 路径 |
| `--num-speculative-tokens` | 推测长度 N | **5**（起步），3-8 |
| `--speculative-draft-tensor-parallel-size` | Draft head 张量并行 | 1（单卡足够） |
| `--speculative-disable-by-batch-size` | 高并发自动回退阈值 | **32** |
| `--gpu-memory-utilization` | GPU 显存利用率 | 0.94 |

### 4.2 完整启动命令（Llama 3.3 70B on H200）

```bash
docker run --gpus all --ipc=host -p 8000:8000 \
  -e HUGGING_FACE_HUB_TOKEN=$HF_TOKEN \
  vllm/vllm-openai:latest \
  --model meta-llama/Llama-3.3-70B-Instruct \
  --dtype fp8 \
  --tensor-parallel-size 1 \
  --speculative-model yuhuili/EAGLE3-LLaMA3.3-Instruct-70B \
  --num-speculative-tokens 5 \
  --speculative-draft-tensor-parallel-size 1 \
  --speculative-disable-by-batch-size 32 \
  --gpu-memory-utilization 0.94 \
  --max-model-len 16384 \
  --max-num-seqs 256
```

### 4.3 性能基准（Llama 3.3 70B FP8, H200 SXM5, batch 1-4）

| 模式 | Tokens/sec | TTFT p50 | 成本/1M token |
|------|-----------|----------|---------------|
| 标准解码 | ~1,700 | ~38 ms | ~$0.23 |
| EAGLE-2 | ~3,800 | ~38 ms | ~$0.10 |
| Medusa-2 | ~3,200 | ~38 ms | ~$0.12 |
| **EAGLE-3** | **~6,200** | ~38 ms | **~$0.06** |
| EAGLE-3 + chunked prefill | ~6,200 | **~8 ms** | ~$0.06 |

EAGLE-3 相比标准解码：**3.6× 吞吐、3.8× 成本降低**。加 chunked prefill 后 TTFT 再降 70-80%。

### 4.4 可用预训练 EAGLE-3 Head

| 目标模型 | Checkpoint | 接受率 |
|----------|-----------|--------|
| Llama 3.3 70B Instruct | yuhuili/EAGLE3-LLaMA3.3-Instruct-70B | 0.82-0.88 |
| Llama 4 Scout | yuhuili/EAGLE3-Llama-4-Scout-17B-16E-Instruct | 0.79-0.85 |
| Llama 4 Maverick | yuhuili/EAGLE3-Llama-4-Maverick-17B-128E-Instruct | 0.81-0.87 |

## 五、验证与故障排查

### 5.1 接受率监控

```bash
curl -s http://localhost:8000/metrics | grep spec_decode
```

关键指标：`vllm:spec_decode_draft_acceptance_rate`，目标 **≥0.75**。

### 5.2 接受率低的排查路径

1. **Tokenizer 不匹配**（最常见）——检查 vocab 是否完全一致
2. 降低 `--num-speculative-tokens` 到 3
3. 仍低于 0.65 → checkpoint 与 prompt 分布不匹配，需训练自定义 head

## 六、何时不该用推测解码

| 场景 | 原因 | 替代方案 |
|------|------|----------|
| Batch size > 32 | 接受率下降，双前向开销不划算 | 标准解码 |
| 长上下文解码 >32K | draft head 上下文难以预测 | FlashAttention-4 |
| 批量推理/embedding | 非 token-by-token 场景 | 标准管线 |

## 七、对 Jetson 边缘部署的意义

EAGLE-3 在边缘设备上的潜力：

- **Jetson Orin Nano 8GB**：可跑 4B 级模型，EAGLE-3 draft head 仅增加 2-4GB
- 统一内存架构下，draft head 和目标模型共享 VRAM，无额外拷贝开销
- 对于交互式 Agent（低 batch、低延迟），推测解码收益最大
- **挑战**：Jetson 的 CUDA 12.4 需要确认 vLLM 兼容性；ARM64 上 draft head 的 kernel 优化尚需验证

MLX 实现（Apple Silicon）已证明 EAGLE-3 可跨平台：M3 Ultra 上 LLaMA-3.1-8B 4-bit + 4-bit 量化 draft head，草稿前向从 ~0.9ms 降到 ~0.4ms。

---

## 八、核心要点速查

- EAGLE-3 = 跨层特征融合 + 单层轻量 draft head，接受率 0.80-0.88，约 3.6× 加速
- P-EAGLE = 并行草稿生成，单次前向出 K 个 token，再叠加最高 1.69× 加速
- 两者已进 vLLM/SGLang/TensorRT-LLM 主线，生产可用
- 起步配置：`num_speculative_tokens=5`、`disable_by_batch_size=32`、`gpu_memory_utilization=0.94`
- 接受率 <0.65 时先查 tokenizer 匹配，再减推测深度，最后考虑训练自定义 head
- 不适用场景：高并发（>32）、超长上下文（>32K）、批量推理
