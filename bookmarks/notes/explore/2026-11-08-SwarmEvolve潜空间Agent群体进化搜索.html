一、内容整理

1.1 核心问题：LLM 进化搜索又慢又贵，瓶颈在「写字」本身

FunSearch/AlphaEvolve 一脉的 LLM 引导进化搜索（把 LLM 当变异和交叉算子，迭代改进程序）已在数学发现上屡建战功（cap set 构造、4×4 复数矩阵乘法加速）。但框架整体慢且贵：

  • 每个 agent 每轮都要生成一长段文本思维链，为维持种群多样性还得重复生成多次
  • 上下文持续膨胀：解档案 + 评估器反馈 + agent 间文本消息，越跑越长
  • 扩 agent 数、扩模型规模、test-time 训练都在乘这个成本——搜索规模上不去

论文之问：低成本的 agent 群能否让进化搜索既快又好？ 答案是把 agent 间通信从文本层整层拆除——不解码、不编码，直接在潜空间传递 KV cache。

1.2 方法论：十群四型 + 潜空间推理 + 隐状态新颖性过滤

编队（Form swarms）：每轮 10 个 swarm × 45 个 latent agent = 450 个 agent 单批并跑。四种群型分工：

  • 4 个精炼群（refinement）：两份最佳程序各配 2 群，主攻各自「最少被用过的改进焦点」（数学表述/时间预算用法等）
  • 3 个杂交群（hybridization）：从 top-10 随机抽 5 个父程序，目标是把最强想法合进一个新程序
  • 2 个探索群（exploration）：从全档案随机抽 4 程序，36 个 agent 读程序 + 9 个只读题目裸想
  • 1 个重启群（fresh-start）：只拿初始基线程序，找完全不同的新路线

每个 agent 的 prompt = 焦点的 5 种措辞 × 9 种思维方式（第一性原理/重审假设等）组合出唯一视角。

潜空间推理（Reason in latent space）：每个 agent 读题面 + 焦点 prompt + 父程序及其评估结果后，走 40 步潜推理——全程不解码文本。读同一程序的 agent 通过 paged attention 共享同一份父程序 KV cache。

新颖性过滤（Filter for novelty）：每群 45 留 30。每个 agent 用 40 步的平均末层隐状态表示，按群均值中心化后归一化为单位向量 z_j，然后贪心最远点选择（greedy farthest-point selection）：从离群心最近的 agent 起步，每次选「与已选集合最小余弦距离最大」的 agent，直到集满 30。纯几何运算，零 LLM 调用。

KV cache 传递（Transfer KV caches）：每群的 summarizer agent 接收拼接 KV cache：[K_prob; K_1..K_30; K_parents; K_ins]——题面 + 30 个入选 agent 的潜推理轨迹 + 父程序 + 总结指令。拼接前每个 agent 的 key 按 RoPE 旋转矩阵 R_δ·k 修正到新位置（value 不带位置信息原样拼接）。summarizer 综合解码，输出方向描述 + 一个完整程序。

参数微调 agent：每轮读最佳程序 + 评估结果 + 全部数值参数，只提议单个数值的单点修改，每轮最多 8 个 one-number edit。

评估归档：去重 → 语法检查 → 自动补标准库 import → 确定性评估器在 CPU 核打分 → 连同得分/日志/报错入档案。跑满时间预算，返回档案最优。

1.3 关键实验结果

设置：21 题（16 题取自 AlphaEvolve 附录 B + 5 题自建科学计算：稀疏线性系统/非正规矩阵特征值/Burgers/对流扩散/Helmholtz 方程）；每框架 60 分钟、1 GPU + 8 CPU 核、3 个种子；Qwen3 8B（L40S）/ 14B（RTX PRO 6000）/ 32B-FP8（H100）三档模型对 OpenEvolve、ShinkaEvolve、CodeEvolve 三个 SOTA 基线（vLLM 服务，默认文本推理配置）。

主表（Table 1，60 分钟最优分均值）：

  • Qwen3 8B：SwarmEvolve 0.804 vs OpenEvolve 0.693 / ShinkaEvolve 0.642 / CodeEvolve 0.700
  • Qwen3 14B：0.837 vs 0.771 / 0.686 / 0.739
  • Qwen3 32B-FP8：0.869 vs 0.774 / 0.733 / 0.731
  • 跨档碾压：SwarmEvolve 的 8B（0.804）超过所有基线跑 32B-FP8 的成绩（0.774/0.733/0.731）

吞吐与速度：

  • 每小时评估程序数 5-13 倍于基线；基线每个程序花 20-35 秒文本推理，SwarmEvolve 450 个潜 agent 一轮总共只需几秒
  • 达到基线 60 分钟最优分的中位时间：8B 档 4-8 分钟，大模型档 3-6 分钟

超越 AlphaEvolve（8B 模型）：3 个问题上超过 AlphaEvolve 用前沿 LLM 发表的构造（每个基线只有 1 个）——26 圆装方形达到已知最优半径和 2.635983；自相关不等式 II/III 界获改进。32B-FP8 档全部 5 个稀疏线性系统做到满分精度，任何基线从未达到。

潜空间分析（Figure 5）：对平均隐状态做 PCA——左图各 swarm 在潜空间占据独立区域（第一主成分大致按群角色排序：精炼→探索→重启）；右图群内 agent 按所读父程序聚簇，新颖性过滤器从每个簇都保留代表，覆盖均匀。焦点 prompt + 几何过滤 = 跨群与群内双重多样性。

消融：A.1 把潜推理换成文本推理（即使给更高 token 预算）分数下降——文本变长拖慢每轮，同时间评估的程序变少；A.2 扩群规模助益集中在搜索早期（评估昂贵时最值），后期趋同，而扩 LLM 规模持续抬升最终分。

二、归纳总结

创新点：

  1. agent 间文本通信层的整体拆除：不是压缩消息、不是换协议，而是让数百 agent 以 KV cache 为通用介质在潜空间通信——把 LatentMAS 的潜空间多 agent 机制首次推到进化搜索的大规模工程实现（450 agent/轮单卡单批）
  2. 隐状态几何 = 免费的新颖性度量：新颖性过滤直接量测 agent 隐状态向量的余弦距离（贪心最远点选择），对比 ShinkaEvolve 需要外挂 embedding 模型 + LLM judge 拒重——多样性筛选成本从「两次模型调用」降到「一次矩阵运算」
  3. 潜空间天然 crossover：summarizer 一次读到 30 个 agent 的联合 KV cache（各自研究不同父程序），「杂交」不再是显式提示词技巧而是注意力机制的自然行为
  4. 「小模型 × 群体规模 > 前沿模型」的实证：8B 群体在 3 个数学问题上改写 AlphaEvolve 前沿模型的构造——发现类任务的瓶颈被证明在搜索吞吐而非单点智能

局限性（论文自述 + 笔记分析）：

  • 只适用于确定性可评估的问题：程序适应度必须机器可验证（数学构造/科学计算），开放式任务（写报告/做设计）无确定性评估器，范式不可直接迁移
  • 潜推理质量押注基座模型：全程无训练，依赖 Qwen3 预训练赋予的潜空间连贯性；换了潜空间未对齐的模型，40 步潜推理是否仍「在想」是未知数
  • RoPE 旋转修正是精确变换但拼接仍是工程近似：跨 agent 注意力只对相对偏移成立，长程序/多父程序时潜通信的保真度未做敏感性分析
  • 40 步潜推理、30/45 保留率、10 群四型等超参数固定，未给出scaling law；单卡上限内未测 frontier 模型（>32B）对照
  • 与 AlphaEvolve 比较以「其发表构造归一化」为分母，3/16 题超越≠整体超越 AlphaEvolve（该系统用 frontier LLM 集成且未被同条件复跑）

三、趋势判断

  • Agent 通信正在从「协议层」下沉到「表示层」：文本消息→结构化 JSON→函数调用之后，KV cache 直传是下一级——省掉编码/解码两次有损变换。MAS Information Bottleneck（2607.16133）证明文本中继存在 δ 复杂度损耗，潜空间传递是绕开该瓶颈的首个大规模工程答案
  • 「吞吐 × 多样性」正在取代「单点智能」成为发现类任务的主轴：5-13 倍程序吞吐 + 几何多样性过滤的复利，抵消了 4 倍模型规模差距。这与推理扩展（test-time scaling）从「更深思考」转向「更宽搜索」的整体走向一致
  • 前缀共享 + 分叉批量 = 推理成本的结构性红利：与 SPORK 的自推测 fork 同一模式——共享前缀 KV、分叉变体、单批并跑。凡是「同上下文多候选」的场景（best-of-N、多角度审查、参数扫描）都在吃这同一碗饭
  • 小模型群体化是边缘侧的利好：450×8B 单卡可跑意味着 67 TOPS 级设备跑几十个小 agent 群在数量级上成立——边缘侧「群体廉价推理」路线打开
  • 可验证领域（数学/科学计算/代码）的 AI 发现竞赛会加速内卷：确定性评估器 + 廉价搜索 = 发现成本骤降；下一个分界线是「半可验证」领域（有 proxy 评估器的工程优化、因子挖掘）能否借用此范式

四、查询拓展

  • LatentMAS：论文的机制基石（潜空间多 agent 通信 + summarizer 解码），值得单独精读其「无训练迁移」的成立条件
  • AlphaEvolve（DeepMind 2025）：被比较的 SOTA，MAP-Elites 档案 + 前沿 LLM 集成；其附录 B 的 16 题是本领域事实基准集
  • FunSearch（2023）：开山之作，cap set 构造；岛屿模型维持多样性
  • OpenEvolve / ShinkaEvolve / CodeEvolve：三个开源 SOTA 基线，ShinkaEvolve 的「embedding+LLM judge 拒重」是本文明晰的对比靶
  • Coconut（Chain of Continuous Thought）：潜推理路线源头——LLM 在连续向量上推理不解码
  • paged attention（vLLM）：共享父程序 KV 的工程底座，与 SPORK（2607.03333）的前缀分叉同族
  • 后续可查：论文 Appendix A.1/A.2 消融细节与 Supplementary Table 2 时间分解（基线 GPU 时间去向）

五、指南分析

本文可提炼为「潜空间群体搜索 SOP」，适用于一切确定性可评估的生成式搜索任务：

  1. 定评估器：先确认适应度可机器验证且便宜（CPU 可跑、确定性、可并行 8 路）
  2. 编四型群：精炼（深挖当前最优）/ 杂交（top-k 随机组合）/ 探索（全档案随机 + 裸想配额）/ 重启（仅基线）——比例 4:3:2:1
  3. 造唯一视角：焦点措辞 × 思维方式笛卡尔积，保证同群 agent 起点不同
  4. 潜推理替代文本 CoT：固定步数（本文 40 步）批量前向，不解码
  5. 几何去重：平均隐状态 → 中心化归一 → 贪心最远点选择保 2/3，从每个语义簇留代表
  6. 单点拼接传递：KV cache 按 RoPE 旋转修正后拼接，summarizer 一次解码产出候选
  7. 微调通道并行：数值参数走单点编辑通道（每轮 ≤8 个），与结构变异解耦
  8. 档案累积：所有候选 + 得分 + 日志 + 报错全量入档，永不丢历史

关键工程前提：vLLM 级 paged attention（共享前缀 KV）与单批 450 序列的调度能力——离开这两点，成本优势不成立。

六、拓展应用推荐（借鉴点评估）

对照现有 skill/memory/cron 的分档评估：

  • P0 四型群编排模式移植：Hermes 的 delegate_task / subagent-driven-development 目前按任务切分编队；借鉴「精炼:杂交:探索:重启 = 4:3:2:1」的角色配比用于并行研究/方案生成类任务（如每日论文选文可并发精炼深读+杂交综述+探索跨域+重启换源）。纯 prompt 层改造，零基建，收益=多样性结构化。建议执行
  • P0 贪心最远点选择用于技能/经验去重：experience-bank、session-evolution-scan、skill-review 的候选去重目前靠文本相似度；改为「embedding + 贪心最远点选择」保多样性代表（算法 20 行纯 Python，rag-index 已有 embedding 基建）。附赠收益：进化候选推送不再同质化。建议执行
  • P1 吞吐指标进 observability-dashboard：本文把「每小时评估程序数」当第一公民指标；Hermes 仪表盘增加「每小时有效工具调用/每小时验证通过动作」——从成功率单维度转向「成功率 × 吞吐」双维度，量化「等价产出下小模型+批并行的省钱空间」
  • P2 单点参数编辑通道：cron/管线调优时禁 LLM 重写整配置，改走「读当前配置+评估历史→单参数单值修改→确定性验证→入档」循环（对应本文 parameter tuning agent）。适配 adaptive-inference-routing 与 cron-bulk-management 的参数搜索，防止大改引入回归
  • P2 量化因子表达式搜索：因子挖掘 = 确定性评估器（IC/回测）+ 程序空间，正是本范式主场；llm-factor-mining 若引入群体化吞吐（多候选单批 + 几何去重），搜索预算利用率可上数量级。工程重（需本地批推理基建），列为中期方向
  • P3 Jetson 本地群体推理：450×8B 单卡的前提是 paged attention 共享前缀；Orin 上 Ollama 对共享 system prompt 的 KV 复用程度待验证，验证通过则「本地小模型审查群」（多视角代码审查/多角度事实核查）在边缘侧可行。先记录不实施
