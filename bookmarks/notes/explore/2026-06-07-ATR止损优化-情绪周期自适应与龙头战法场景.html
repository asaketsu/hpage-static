发现1：ATR 止损在龙头战法场景需要情绪周期感知的自适应倍数

现有笔记（2026-05-17）将 ATR 止损参数按保守/适中/激进分档，但未考虑 A 股情绪周期对最优止损参数的影响。龙头战法的四阶段情绪周期（冰点→主升→高潮→退潮）对 ATR 参数有截然不同的需求：

情绪周期 × ATR 参数映射：
- 冰点/启动期：ATR 倍数应收紧至 1.5-2×。此阶段试错首板/二板，止损必须灵敏——因为冰点期龙头尚未确立，失败率最高。宽松止损 = 白白扩大单笔亏损
- 主升期：ATR 倍数应放宽至 3-4×。龙头确立后的主升浪振幅巨大（日内 5-10% 波动常见），2×ATR 止损会被正常洗盘震出。典型案例如中际旭创 CPO 主升浪期间，3×ATR(14) 才能覆盖日内回调
- 高潮/见顶期：ATR 倍数应急缩至 1-1.5×，同时叠加硬止损。此阶段随时可能出现天地板/高位长阴线，紧止损是唯一的利润保护
- 退潮期：不应使用 ATR 止损。退潮期策略为空仓等待，任何持仓都应立即清仓而非依赖止损。ATR 在退潮期波动率骤增，倍数无论调大调小都不适用

工程化实现——情绪周期自适应 ATR 倍数：

class EmotionCycleATRStop:
    """
    基于情绪周期的 ATR 止损自适应倍数管理器

    核心逻辑：情绪周期阶段 → ATR 倍数映射 → 动态调整止损线
    """

    # 情绪周期阈值参数
    ICE_POINT = 'ice_point'      # 冰点/启动期
    MAIN_RALLY = 'main_rally'    # 主升期
    CLIMAX = 'climax'           # 高潮/见顶期
    EBB = 'ebb'                 # 退潮期

    # 每阶段 ATR 倍数配置
    STAGE_MULTIPLIERS = {
        ICE_POINT: 1.8,
        MAIN_RALLY: 3.5,
        CLIMAX: 1.2,
        EBB: None,  # 退潮期不平仓，直接市价清仓
    }

    def __init__(self, atr_period=14, hard_stop_pct=0.08):
        self.atr_period = atr_period
        self.hard_stop_pct = hard_stop_pct  # 硬止损 -8%
        self.stage = self.ICE_POINT
        self.multiplier = self.STAGE_MULTIPLIERS[self.ICE_POINT]

    def detect_emotion_stage(self, market_breadth: dict) -> str:
        """
        通过市场宽度指标判断情绪周期阶段

        输入指标：
        - limit_up_count: 涨停家数
        - limit_down_count: 跌停家数
        - max_consecutive_boards: 市场最高连板数
        - avg_turnover_rate: 市场平均换手率
        - volume_ratio: 成交量/20日均线
        """
        lu = market_breadth['limit_up_count']
        ld = market_breadth['limit_down_count']
        max_boards = market_breadth['max_consecutive_boards']
        vol_ratio = market_breadth.get('volume_ratio', 1.0)

        if max_boards <= 2 and lu < 10:
            return self.ICE_POINT
        elif max_boards >= 3 and lu > ld * 3 and vol_ratio > 1.2:
            return self.MAIN_RALLY
        elif ld > lu * 0.5 or max_boards > 7 or vol_ratio > 2.5:
            return self.CLIMAX
        elif lu < 5 and max_boards <= 2 and vol_ratio < 0.7:
            return self.EBB
        else:
            return self.stage  # 维持当前阶段

    def update_stage(self, market_breadth: dict):
        """更新情绪阶段并调整 ATR 倍数"""
        new_stage = self.detect_emotion_stage(market_breadth)
        if new_stage != self.stage:
            self.stage = new_stage
            self.multiplier = self.STAGE_MULTIPLIERS[new_stage]
        return self.stage, self.multiplier

    def get_stop_price(self, entry_price: float, atr_value: float, 
                       highest_price: float = None) -> float:
        """
        计算当前阶段的止损价

        三层架构：
        1. 硬止损（永远存在）
        2. ATR 自适应止损（随情绪周期变化）
        3. 追踪止损（主升期叠加）
        """
        if self.stage == self.EBB:
            return entry_price  # 退潮期：立即清仓信号

        # 第一层：硬止损
        hard_stop = entry_price * (1 - self.hard_stop_pct)

        # 第二层：ATR 自适应止损
        atr_stop = entry_price - self.multiplier * atr_value

        # 第三层：追踪止损（仅主升期）
        trailing_stop = 0
        if self.stage == self.MAIN_RALLY and highest_price:
            # Chandelier Exit: 从最高价回撤 2.5×ATR
            trailing_stop = highest_price - 2.5 * atr_value

        # 取最高止损价（最紧保护）
        stops = [hard_stop, atr_stop]
        if trailing_stop > 0:
            stops.append(trailing_stop)

        return max(stops)

关键洞察：传统 ATR 止损优化搜索（如 5 月 17 日笔记中的 optimize_stop_parameters 网格搜索）在 A 股短线场景下注定失败——因为单一参数组合无法同时适应四个情绪阶段。情绪周期感知的自适应倍数是更优的框架。

发现2：龙头股 ATR 参数与普通股有结构性差异——需要独立的参数基线

5 月 17 日笔记中的参数建议（ATR 周期 14，倍数 2-3×）是基于通用场景。但龙头股有几个独特特征导致 ATR 行为异常：

龙头股 ATR 异常特征：
1. 涨停板锁定效应：涨停期间 True Range 被压缩（10%/20% 涨停封死 = 当日无波动），ATR 被人为压低。一旦开板，ATR 骤然放大，止损线剧烈波动
2. 换手率与 ATR 的非线性关系：龙头股换手率 15-30% 时 ATR 最"正常"，换手率 > 50%（见顶信号）时 ATR 爆发式增长
3. 板块联动导致波动聚集：龙头股 ATR 不只反映自身波动，还承载了整个板块的情绪。板块整体退潮时龙头 ATR 会滞后放大（龙头"最后倒下"效应）

建议的龙头股 ATR 参数基线：

参数 普通股默认 龙头股调整 原因
ATR 周期 14 7-10 龙头股情绪变化快，14日周期太滞后
ATR 倍数 2-3× 2-4×（随阶段变化） 涨停板效应压低 ATR，需要更大倍数补偿
硬止损 -8% -5%~-6% 龙头股见顶回撤迅猛，-8% 太宽
追踪止损激活 盈利 3% 盈利 5-8% 龙头股日内波动大，过早激活会频繁触发
涨停板过滤 无 必须 封板日不计入 ATR 计算，避免人为压低

涨停板过滤 ATR 的实现：

def calculate_atr_filtered(df: pd.DataFrame, period: int = 10) -> pd.Series:
    """
    龙头股专用 ATR 计算 —— 过滤涨停板日的异常数据

    核心逻辑：涨停日（收盘=最高=涨停价）的 True Range 不代表真实波动，
    应从前 N 个非涨停日计算 ATR
    """
    df = df.copy()
    df['prev_close'] = df['close'].shift(1)

    # 识别涨停日（收盘涨幅 >= 9.5% 且 收盘=最高）
    df['pct_change'] = df['close'].pct_change() * 100
    df['is_limit_up'] = (df['pct_change'] >= 9.5) & (df['close'] == df['high'])
    df['is_limit_down'] = (df['pct_change'] <= -9.5) & (df['close'] == df['low'])

    # True Range 计算
    tr1 = df['high'] - df['low']
    tr2 = abs(df['high'] - df['prev_close'])
    tr3 = abs(df['low'] - df['prev_close'])
    df['tr'] = np.maximum(tr1, np.maximum(tr2, tr3))

    # 将涨停日的 TR 设为 NaN，rolling 时自动跳过
    df.loc[df['is_limit_up'] | df['is_limit_down'], 'tr'] = np.nan

    # 用 min_periods 确保即使跳过涨停日也能计算
    df['atr'] = df['tr'].rolling(window=period, min_periods=max(1, period//2)).mean()

    return df['atr']

发现3：分批止盈与 ATR 止损的协同框架是提升盈亏比的关键杠杆

5 月 17 日笔记的知识缺口第 1 项指出"止损与止盈的协同优化"尚未深入。ATR 止损的最优化不在于止损参数本身，而在于止损与止盈的协同设计：

协同框架核心逻辑：
- ATR 止损负责限制亏损（防守端）
- 分批止盈负责锁定利润（进攻端）
- 二者通过盈亏比锚定联动：止损距离决定首批止盈位置

三层止盈架构：

第一层（盈利 30% 对应止损距离）：卖出 1/3 仓位
  → 锁定基本利润，即使后续回撤也不亏
  → 计算方式：止盈位 = entry + 0.3 * (entry - stop_loss)

第二层（盈利 60% 对应止损距离）：再卖出 1/3 仓位
  → 锁定更多利润，剩余 1/3 跑趋势
  → 计算方式：止盈位 = entry + 0.6 * (entry - stop_loss)

第三层（Chandelier Exit 追踪）：剩余 1/3 仓位跑满趋势
  → 使用 2.5×ATR(14) 追踪止损
  → 不预设止盈目标，让市场决定

与情绪周期的联动：
- 冰点期试错：只设止损，不分批止盈（试错仓位小，止损即离场）
- 主升期：严格执行三层止盈，特别是龙头股（主升浪利润需要分批锁定）
- 高潮期：第一层止盈立即执行，不再等 30% 对应止损距离，直接减半仓
- 退潮期：全仓市价清仓，止盈框架不适用

发现4：时间止损是 ATR 止损在 A 股短线场景的关键补充

5 月 17 日笔记提到了"时间止损"但没有展开。在 A 股 T+1 环境下，时间止损的重要性不亚于价格止损：

时间止损的逻辑：
- 龙头战法/短线交易的核心是捕捉情绪爆发的时间窗口
- 如果买入后 N 天内未按预期方向运动，说明判断错误
- 即使价格未触及 ATR 止损，时间耗尽也应离场——因为资金的机会成本是隐含亏损

时间止损规则：

交易类型 最大持仓天数 时间止损触发条件
首板试错 2 天 次日不涨停即走（无论盈亏）
二板接力 3 天 第 3 天不创新高减半仓
龙头主升 不限 改用 Chandelier Exit 追踪
补涨股 5 天 5 日内未突破前高清仓

ATR + 时间止损的组合实现：

class TimePriceStop:
    """
    时间 + 价格双重止损管理器

    止损触发条件（满足任一即触发）：
    1. 价格止损：收盘价 <= ATR 止损线
    2. 时间止损：持仓天数 >= 最大持仓天数 且 未创新高
    3. 硬止损：亏损超过 hard_stop_pct
    """

    def __init__(self, entry_price: float, entry_date, 
                 atr_value: float, max_holding_days: int = 3,
                 hard_stop_pct: float = 0.06):
        self.entry_price = entry_price
        self.entry_date = entry_date
        self.atr_value = atr_value
        self.max_holding_days = max_holding_days
        self.hard_stop_pct = hard_stop_pct
        self.highest_since_entry = entry_price

    def check(self, current_price: float, current_date, 
              highest_today: float, atr_value: float = None) -> dict:
        """返回 {triggered, reason, stop_price}"""
        if atr_value:
            self.atr_value = atr_value

        self.highest_since_entry = max(self.highest_since_entry, highest_today)
        holding_days = (current_date - self.entry_date).days

        # 硬止损
        if current_price <= self.entry_price * (1 - self.hard_stop_pct):
            return {'triggered': True, 'reason': 'hard_stop', 
                    'stop_price': self.entry_price * (1 - self.hard_stop_pct)}

        # ATR 止损
        atr_stop = self.entry_price - 2.0 * self.atr_value
        if current_price <= atr_stop:
            return {'triggered': True, 'reason': 'atr_stop', 
                    'stop_price': atr_stop}

        # 时间止损
        if holding_days >= self.max_holding_days:
            # 检查是否创过新高（比入场价高 > 3%）
            made_new_high = self.highest_since_entry > self.entry_price * 1.03
            if not made_new_high:
                return {'triggered': True, 'reason': 'time_stop',
                        'stop_price': current_price}

        return {'triggered': False, 'reason': None, 
                'stop_price': min(atr_stop, self.entry_price * (1 - self.hard_stop_pct))}
