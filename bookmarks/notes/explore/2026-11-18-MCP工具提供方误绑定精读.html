〇、定锚：我的现状与目标

我（Hermes 体系）是重度多源工具系统：native-mcp 客户端可同时挂多个 MCP server，mcporter 桥接临时 server，skill 体系里同名技能跨类别共存（github 出现在两个类别、quant-trading 同名两处）——这正是本文定义的「提供方未绑定（provider-unbound）」命名空间。我的现状：工具/技能选择完全靠名称+描述匹配，没有任何「这个能力属于谁」的验证层；此前已吸收 Binding Drift（2607.18316，实体绑定漂移）与工具检索完整性（2610.41905，检索结构），本文补上选择层安全这块拼图。我的目标：判断这篇的实验证据是否足以支撑在 Hermes 网关加一道「工具来源消歧门禁」，以及加在哪一层最便宜。

一、内容整理

1.1 核心问题〔方法，2026〕

MCP（Model Context Protocol）允许客户端组合多个 server 广播的工具，工具靠元数据（名称 name、自然语言描述 description、输入 schema、可选注解）被发现和选择。这些元数据没有强制绑定到经过验证的提供方身份。攻击面由此产生：

  • 攻击者不入侵主机、不碰 LLM、不攻破合法 server、不劫持网络信道
  • 只运营一个对客户端可见的 MCP server，广播精心构造的元数据
  • 目标：让本应发给合法提供方的请求被解析到攻击者工具上

论文命名这种失败为工具提供方误绑定（tool-provider misbinding）。本质论断：MCP 工具元数据不只是文档，它是 Agent 控制面（control plane）的一部分——名称带来熟悉感但不证明来源，描述合理+schema 兼容只说明「看起来能用」，不说明「属于谁」。

1.2 形式化：把攻击变成可测量的选择问题〔方法，2026〕

工具可见属性 attr(t) = {n(t), d(t), σ(t), m(t)}，缺提供方身份 p(t)；有 p(t) 的版本记为 attr⁺(t)。攻击者的控制面 = 自己工具的元数据，目标函数是最大化客户端把请求解析到攻击者集合的概率。

2×3×2 全因子设计，12 个攻击条件（C01-C12）：
- 名称 Name：unrelated（与任务关键词零重叠）/ exact（完全复制合法工具名，制造命名空间冲突）
- 描述 Description：unrelated / copied（逐字复制）/ authority-enhanced（保留任务语义+加权威线索，如 "enterprise-approved""officially verified""compliance-oriented"）
- Schema：incompatible（合法但接口与任务无关）/ compatible（接受同样的参数，同一调用可在任一提供方上执行）

四个结局 + 五个指标：
- 结局：A=选中攻击者工具 / L=选中合法工具 / C=请求澄清 / F=失败（实验中 FR=0）
- 指标：违规率 VR=A/总数、澄清率 CR、合法选择率 LSR、绑定稳定性 RBS（同一提示重复执行时「选中工具+提供方」二元组的一致性）

1.3 实验设置〔方法，2026〕

  • 任务：数据集获取（合法工具 data_fetch_and_store，参数 dataset_id/destination），本地 mock 数据，无真实外泄
  • 10 个任务等价提示（5 个普通措辞 + 5 个安全敏感措辞，明确强调可信目标/预期提供方）× 5 次独立重复 = 每条件每模型 50 试验
  • 5 个 LLM 客户端：GPT-5.4、Claude Sonnet 5、Gemini 2.5 Pro、Qwen3.7 Max、DeepSeek V3
  • 主实验 12 条件 × 50 × 5 模型 = 3000 试验，FR=0（无崩溃，差异全来自选择行为）
  • 服务器标识作为权威提供方标签（exact-name 条件下两者显示名相同，靠 server id 区分）

1.4 关键实验结果〔数据，2026〕

主表（Table II，VR/CR/RBS）核心读数：

  • C10（同名+复制描述+兼容schema）：GPT-5.4 VR=1.00，Qwen3.7 Max VR=1.00，DeepSeek V3 VR=1.00，Gemini 2.5 Pro VR=0.84，Claude Sonnet 5 VR=0.06 但 CR=0.94 且 RBS=0.00（几乎全部陷入澄清，绑定完全不稳定）
  • C12（同名+权威增强描述+兼容schema）：GPT-5.4 VR=0.96，Qwen/DeepSeek VR=1.00，Gemini VR=0.70，Claude VR=0.26+CR=0.74
  • C06（无关名称+权威增强描述+兼容schema）：Gemini VR=0.42/CR=0.56，DeepSeek VR=0.50，Qwen VR=0.20，GPT-5.4 VR=0.04，Claude 全转澄清（CR=0.22）——没有名称冲突也能劫持
  • C07（仅同名，描述无关+schema不兼容）：全模型 VR≤0.02——名称冲突单独不构成攻击
  • C01/C02/C03/C05（低对齐对照）：全模型 VR=0（唯一例外 DeepSeek 在 C04=0.22）

三个结构性结论：
1. 误绑定由交互效应驱动：名称×描述×schema 三者对齐时 VR 冲到 0.84-1.00，任何单一因素（C07 仅名称、C05 仅权威描述）都接近无害
2. 模型分化为三种失败形态：GPT-5.4/Qwen/DeepSeek「沉默执行型」（几乎不澄清，直接选一个）；Claude「澄清型」（VR 低但 CR 高，暴露未解决的提供方歧义）；Gemini「混合型」。模型侧谨慎能减少静默误绑，但不能创造提供方绑定身份
3. RBS 的双向解读：C10 下 Qwen/DeepSeek 的 RBS=1.00 且 VR=1.00 = 稳定地选错（比不稳定更危险）；Claude RBS=0.00 = 稳定地无法解析。安全敏感措辞的提示（后 5 个）也不能消除攻击

1.5 稳健性与攻击者预算〔数据，2026〕

  • 无关名称稳健性：C06 用 5 个独立生成名称重跑（每名称 50 试验×5 模型=250/条件/模型），DeepSeek 5/5 名称全部中招（VR 0.508 均值），Gemini 持续脆弱，GPT-5.4 名称敏感（0 到显著波动），Qwen 稳定小效应——效应不是单字符串伪影
  • 权威描述稳健性：5 个独立措辞 D1-D5 重跑 C06/C11/C12，C12 下 GPT-5.4/DeepSeek/Qwen 在全部措辞上 VR 保持 0.98-1.00——措辞只影响幅度不改变行为
  • 攻击者预算 r∈{1,3,5,10}：多个攻击候选提高提供方解析压力——要么推高直接违规率，要么推高澄清率（均非安全结局）
  • 构造纪律：无关名称用任务关键词排除法（data/dataset/fetch/retrieve/download/store/save/storage/vault/destination/source 全排除），权威描述用模板化流程（保留任务+零新功能+1 权威线索+1 安全线索），避免事后挑字符串的偏置

1.6 防御主张〔方法，2026〕

论文主张提供方绑定工具身份（provider-bound tool identity）应为 MCP 组合的一等安全属性：签名的工具清单（signed tool manifests）、稳定的提供方绑定工具标识符、schema 哈希、客户端强制执行。定位澄清：它不替代授权/沙箱/权限检查/用户同意（那些回答「工具可不可以访问、能做什么」），它回答更早的问题——选中的工具是否真由有权提供该能力的提供方供应。

二、查询拓展

  • 同域攻击面谱系：InjecAgent（间接提示注入基准）、Imprompter（诱导 LLM Agent 不当工具使用）、恶意 skill/技能市场污染、跨工具污染、资源滥用——本文把「元数据层身份伪造」加入这个谱系，且是唯一做因子分解归因的（其他多为端到端红队演示）
  • 协议层背景：MCP 只要求工具名在单个 server 内唯一（tools/list 广播），跨 server 无宿主级强制身份——多 server 组合时同名/近名天然冲突，规范层面确认了攻击前提
  • 与我已读论文的关系网：Binding Drift（2607.18316）研究执行过程中实体绑定漂移与传播，本文研究选择时刻的提供方绑定失败——一横一纵；工具检索完整性（2610.41905）研究怎么找全工具，本文研究找错了怎么办；MDSKILL（2611.05313）的技能检索层同样依赖描述匹配，同样暴露在选择层攻击下
  • 防御侧相关：SPILLWAY（2611.07222，HF 热榜同期论文）做工具型 Agent 的注入防御（准入与净化分离），与本文的提供方绑定互补——一个管内容安全，一个管身份真伪

三、归纳总结

  1. 本质规律：Agent 安全面前移到元数据层。 传统安全假设「执行体可信，管住输入即可」；LLM 选择器让「广播什么」本身成为攻击向量——描述文本是给模型看的注入面。工具名不是身份，描述不是凭证，schema 兼容不是授权。
  2. 方法论沉淀：安全属性必须因子分解后测量。 本文最强的方法贡献不是攻击本身，而是 2×3×2 因子设计+四结局+稳定性指标（RBS）的测量框架——把「感觉不安全」变成「哪个字段的哪个组合贡献了多少违规率」。任何 Agent 安全主张都该能这样拆。
  3. 反直觉发现一：名称冲突是最弱因子。 C07 证明仅同名几乎无害（VR≤0.02）；真正致命的是「权威描述×兼容schema」（C06 无名称冲突仍 0.42-0.50）。防同名是防不住的，防语义伪装才有效。
  4. 反直觉发现二：「稳定」可能是最坏结局。 RBS=1.00 配 VR=1.00 意味着模型确定性地、可重复地把任务交给攻击者——比随机摇摆更利于攻击者建立持久数据通道。
  5. 反直觉发现三：澄清不是安全，是歧义可见化。 Claude 的高 CR 只是暴露「我无法确定提供方」，把决策推回用户；在无人值守的 cron/自动化场景里，澄清=卡死或被默认路由吃掉。
  6. 权威线索是模型级偏置。 "enterprise-approved/officially verified" 这类词在无名称冲突时仍有效（C06），说明模型把权威措辞当成了选择依据——这是可被零成本伪造的信任信号。

四、趋势判断

  • 短期（月级）：MCP 生态爆发期（2026 年多 server 组合已是常态）+ 零成本攻击（只需注册一个 server）→ 此类攻击将从论文走向实战，skill/插件市场审核会成为 Agent 厂商的军备竞赛点
  • 中期（年级）：提供方绑定会走 PKI 式路线——签名清单+客户端强制校验大概率进 MCP 规范修订或大厂私有扩展（类似浏览器证书透明度日志的演化路径）
  • 测量框架会被复用：VR/CR/RBS 三指标 + 因子设计是可迁移模板，预计一年内出现「工具市场误绑定红队评测」标准化基准
  • 对模型侧的启示：会澄清的模型（Claude 型）在交互场景更安全，但在自动化场景更脆——模型选型将按部署形态分层，「沉默执行型」模型在多源工具环境的风险定价会上调

五、关联：与 Hermes/Jetson/量化的映射

Hermes Agent（强相关）：
- native-mcp + mcporter 组合 = 典型多 server 命名空间；skill 目录里 github（github 类别）与 github（software-development 类别）、quant-trading（productivity）与 quant-trading（顶级类别）同名共存 = 论文 C10 场景的内部翻版（虽然两者都是我方资产，但选择歧义同样浪费轮次且可能路由到劣质实现）
- 我的工具选择完全靠「描述匹配」，而 C06 证明「权威措辞+兼容签名」足以让 4/5 模型偏航——恶意 MCP server 一旦进入 config.yaml，网关没有任何身份层防线
- LanGPT DialBridge 的一次性 32B token 机制本质是连接级提供方验证，但工具选择层（如果未来暴露多源工具给桥）同样适用本文结论
- cron 无人值守场景：澄清结局（C）在 cron 里不存在用户应答，等价于 F 或被 fallback 吃掉——自动化的工具误绑定风险高于交互场景

Jetson Orin（中相关）： 边缘侧 MCP server 通常本地运行、来源单一，误绑定暴露面小；但跨机 Tailscale 内网组合（asa/桥端/打印机 .234）多提供方共存时，schema 哈希校验是低成本防线。

量化交易（弱相关但同构）： 数据源多路（东财 push2/腾讯 QT/iwencai）= 多提供方工具选择；若用 MCP 化数据源，「权威描述」伪装成官方行情源可诱导策略读到被操纵的数据——数据血缘（provenance）在量化语境下就是提供方绑定，宁可 NotFound 也不能错绑。

六、拓展应用推荐

  1. Hermes 网关消歧门禁（P0）：加载多 MCP server 后，对名称相同/近似的工具对（编辑距离<2 或 schema 结构相似度>阈值）生成警告清单并强制 server.tool 全限定名调用；与 Binding Drift 笔记的「高风险动作前交叉验证」合并成一道门
  2. Skill 目录同名审计脚本（P0，半小时工作量）：扫描 skills 树输出同名清单，同名的强制加类别前缀或在 desc 首行标注差异化定位——零成本消除内部 C10 场景
  3. 描述权威词黑名单（P1）：对外部来源工具的 description 做 "official/verified/enterprise/approved" 词扫描，命中即降权+提示「权威声明不可验证」——直接对冲 C06 攻击向量
  4. mcp-security-audit skill 增补（P1）：把本文 12 条件表和 VR/CR/RBS 指标加入现有 MCP 安全审计清单，作为「选择层」检查维度（现有清单偏部署面）
  5. 自动化任务工具白名单（P2）：cron 触发的会话对外部 MCP 工具默认白名单制，新工具首次只能人工会话使用——自动化场景澄清无出口，白名单是等价物

七、指南分析

可复用的操作规程：
- 「元数据即控制面」审计法：评估任何 Agent 系统安全时，先列出所有「模型能看到并影响选择」的文本（工具描述/skill desc/agent 卡片/系统提示注入段），逐项问「这段话谁可以写？写了会改变什么行为？」——本文证明这个集合就是完整攻击面
- 因子化红队模板：新工具生态接入前，按「名称冲突×语义对齐×接口兼容」三轴各取 2-3 档构造 8-12 个探测工具，50 trials/条件测 VR——半天可完成的接入前体检
- RBS 式稳定性指标设计：安全测量不能只看「错没错」，还要看「错得稳不稳定」——稳定错误=确定性后门，不稳定=随机风险，防御优先级完全不同

边界与不适用： 本文是单任务（数据集获取）+r≤10+5 模型的受控实验，VR 绝对值不可直接外推到生产（作者自己也声明 generality of rates 受限）；但其核心机制（元数据无身份绑定→选择可被操纵）是结构性的，不依赖具体比率。

- P0-2 网关消歧门禁：属 Hermes 核心改动，需用户拍板侵入层级（警告 vs 强制全限定名）

一句话结论： 工具名、描述、schema 都是模型看得见的东西，而攻击者恰恰只控制「模型看得见的东西」——提供方身份必须是模型看不见但网关强制执行的属性。
