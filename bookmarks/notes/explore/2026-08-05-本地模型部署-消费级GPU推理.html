本地模型部署：消费级 GPU 推理（2025-2026 实践指南）

来源：Introl Hardware Guide 2025、IntuitionLabs 24GB GPU 报告、Red Hat/Spheron/多篇实测对比
日期：2026-08-05 | 类型：auto-explore

摘要

消费级 GPU 已成为本地 LLM 部署的可行路径。RTX 4090（24GB）可流畅跑 7-32B 模型，RTX 5090（32GB）可跑 70B-Q4。核心决策链：显存决定模型规模，量化决定精度损耗，框架决定并发能力。双卡 RTX 5090 可在 70B 推理上对标 H100，成本仅为其 25%。

关键发现

1. 显存与模型规模对应关系（Q4 量化）

  • 7-8B 模型：需 4-5GB，RTX 3060 12GB 即可流畅
  • 13-14B 模型：需 8-9GB，RTX 4060 Ti 16GB 是性价比甜点
  • 32-34B 模型：需 19-20GB，单张 RTX 4090 勉强可跑（紧适配）
  • 70B 模型：需 35GB，单卡需 CPU offload；双卡 4090（48GB）或单卡 5090 Q2/Q3 才能完整加载

2. 三大推理框架定位（互不竞争，各司其职）

  • Ollama：开发机/原型验证首选，一行命令安装，月下载量 5200 万（2026 Q1），单用户场景极致简化
  • vLLM：生产高并发首选，PagedAttention 技术，GPU 显存利用率提升 3-5 倍，吞吐量比 llama.cpp 高 10-15 倍（Llama-3-8B 基准：vLLM 3000+ tok/s vs llama.cpp ~200 tok/s）
  • llama.cpp：CPU/边缘设备首选，跨平台之王（CUDA/ROCm/Metal/Vulkan/SYCL），GGUF 格式已成行业标准，60%+ 的 HF 量化模型用 GGUF

3. 量化格式选型

  • GGUF Q4_K_M：4 倍压缩，质量损失可接受，CPU/Apple Silicon 场景默认选
  • GGUF Q5_K_M：3.2 倍压缩，质量几乎无损，显存够就用它
  • AWQ：4 倍压缩，比 GPTQ 质量更好、GPU 上速度 2 倍，适合 instruction-tuned 模型
  • FP8：仅 H100/H200/B200 支持，2 倍压缩近无损，很多新模型原生 FP8 训练
  • EXL3（ExLlamaV3）：新兴格式，单次转换到目标比特率，3-bit+4096 缓存可在 16GB 内运行

4. 消费级 GPU 天梯（2026 现状）

  • RTX 5090（32GB，$1999 MSRP，现货 $2500-3800）：8B 模型 213 tok/s，32B 模型 61 tok/s
  • RTX 4090（24GB，$1599，2024 年 10 月停产，现货炒至 $3700-5000）：8B 模型 128 tok/s
  • RTX 3090（24GB，二手 $995-1504）：性价比之王，性能约 4090 的 80%
  • AMD RX 7900 XTX（24GB，~$900）：8B 模型 ~100 tok/s，生态不如 NVIDIA

5. 关键警告

  • vLLM 仅支持 Linux，AMD ROCm 支持实验性不稳定
  • 消费级卡无 NVLink，多卡走 PCIe，效率约为 NVLink 的 85-90%
  • RTX 5090 量化 8B 模型到 NVFP4 会超过 32GB 显存，必须用预量化权重
  • Ollama 在 5 个并发用户时性能崩塌，生产环境勿用

对工作的价值

  1. Jetson Orin 平台定位：Orin Nano（8GB）适合 1.5-3B 模型；Orin AGX（32GB）可跑 13B-Q4，是边缘部署的合理选择
  2. 成本对标：相比 H100（$30000+）/H200（$40000-55000），消费级方案 ROI 通常 6-12 个月回本
  3. 私有知识库 RAG：中小规模（并发 <20）用 Ollama + LangChain 即可；大规模生产必须 vLLM
  4. 混合路由策略：70% 查询走小模型（8B），复杂查询才路由到大模型，是成本最优的生产实践

行动建议

  1. 立即可用：现有 Jetson Orin 上验证 Q4_K_M 格式模型（Qwen2.5-7B/3B），用 llama-server + -ngl 99 全层 GPU 卸载
  2. 显存优化：启用 KV Cache 量化（-ctk q4_0 -ctv q4_0），131K 上下文场景可省可观显存
  3. 框架选型：个人/开发用 Ollama；团队 API 服务用 vLLM；跨平台/边缘用 llama.cpp
  4. 监控指标：生产部署必须测 TTFT（首 token 延迟）、tok/s、VRAM headroom，用实际 prompt 测而非厂商基准
  5. 规避陷阱：不要用 Ollama 做高并发 API 服务；不要在消费级卡上尝试 FP16 跑 70B
