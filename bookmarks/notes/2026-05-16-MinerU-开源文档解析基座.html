核心能力

全格式覆盖：PDF、DOCX、PPTX、XLSX、图片、网页 → Markdown / JSON

三引擎架构：
- pipeline — 快速稳定无幻觉，CPU/GPU 均可，OmniDocBench v1.5 得分 86.2
- vlm-engine — 高精度，基于 MinerU2.5-Pro-2604-1.2B，支持 vLLM/LMDeploy/mlx
- hybrid-engine — 高精度 + 原生文本提取 + 低幻觉

解析能力：
- 公式 → LaTeX、表格 → HTML、跨页表格合并
- 扫描件、手写体、多栏布局、竖排文本
- 自动页眉页脚去除，输出符合人类阅读顺序
- VLM + OCR 双引擎，109 种语言

技术架构

用户文档 (PDF/DOCX/PPTX/XLSX/图片)
    ↓
格式路由 (magika 类型检测)
    ↓
推理后端选择 (pipeline / vlm / hybrid)
    ↓
VLM模型 (MinerU2.5-Pro-2604-1.2B) + OCR引擎
    ↓
版面分析 + 内容提取 + 结构化
    ↓
输出 (Markdown / JSON)

关键依赖：pdfminer.six, pypdfium2, opencv-python, transformers, openai, modelScope, python-docx, openpyxl, fastapi/uvicorn (API服务)

编排架构（v3.0+）：
- mineru — 编排客户端
- mineru-api — 异步任务服务（POST /tasks + POST /file_parse）
- mineru-router — 多服务多GPU统一入口，自动负载均衡

借鉴点与进化分析

① 有利进化 → 立刻落实

1. MCP Server 模式值得借鉴
MinerU 提供了 MCP Server 让 AI 编程工具直接调用文档解析。我们的 WikiKB 和 note-taking skill 可以参考这种模式，把文档解析能力暴露为 MCP 工具。
- 落实：在 wiki-knowledge-base skill 中记录 MinerU 作为文档解析候选工具
- 落实：memory 记录 MinerU 的 pip install 命令和 API 端点

2. 三引擎分层策略
pipeline（快/无幻觉）→ vlm（高精度）→ hybrid（兼顾）。我们的 RAG 索引也可以借鉴这种分层：简单文档用快速管道，复杂文档（表格多、公式多）用 VLM。
- 落实：在 wiki-knowledge-base skill 的 RAG 索引策略中补充引擎分层思路

② 有价值 → 记忆备用

3. 全格式原生解析（非转PDF再解析）
MinerU 3.0 后直接解析 DOCX（速度提升数十倍），3.1 扩展到 PPTX/XLSX。这是一个重要趋势：直接解析原生格式 > 转换后解析。

4. 滑动窗口降内存峰值
上万页文档用滑动窗口+流式落盘，避免 OOM。对长文档 RAG 索引构建有参考价值。

5. 线程安全+多卡负载均衡
mineru-router 的多 GPU 自动负载均衡架构，未来如果做大规模文档处理可以参考。

命令速查

# 安装
pip install mineru

# CLI 使用
mineru parse input.pdf -o output/
mineru parse input.docx -o output/
mineru-api --host 0.0.0.0 --port 8000  # 启动API服务

# Python SDK
from mineru import MinerU
client = MinerU()
result = client.parse("input.pdf")
print(result.markdown)
