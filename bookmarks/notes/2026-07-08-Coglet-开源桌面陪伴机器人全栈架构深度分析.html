一、项目画像

Coglet 是 Will Cogley 设计的开源 3D 打印桌面陪伴机器人，核心是「硬件设计 + 小智AI 固件集成」。它不是一个独立的固件项目，而是将成熟的 XiaoZhi AI Chatbot 框架适配到定制硬件 (CogNog V1.0 PCB + B34 3D 打印外壳) 上的集成方案。

三、固件架构 (CogletESP) — 核心分析

3.1 板型抽象层 (Board Abstraction)

117 个板型，每个板型目录结构：

boards/{board-name}/
├── config.h          # 引脚定义、宏配置
├── config.json       # 运行时配置
├── power_manager.h   # 电源管理（可选）
├── {board}_audio_codec.h  # 音频 codec 配置（可选）
└── pin_config.h      # 引脚映射（可选）

这是 XiaoZhi AI 框架最核心的设计模式——通过 config.h + config.json 的配对，实现了硬件无关的抽象层。每个板型只需定义引脚映射和关键参数，其余逻辑（音频处理、显示、网络、MCP）完全复用。

3.2 音频子系统 (策略模式)

audio/
├── audio_service.h       # 统一音频服务接口
├── audio_codec.h         # Codec 抽象基类
├── audio_processor.h     # 音频处理器抽象
├── codecs/
│   ├── es8311_audio_codec.h    # 常见 I2S 音频芯片
│   ├── es8374_audio_codec.h    # I2S + DMIC
│   ├── es8388_audio_codec.h
│   ├── es8389_audio_codec.h
│   ├── box_audio_codec.h       # ESP-Box 专用
│   ├── dummy_audio_codec.h     # 无音频板
│   └── no_audio_codec.h
├── processors/
│   ├── afe_audio_processor.h   # AFE 降噪
│   ├── audio_debugger.h
│   └── no_audio_processor.h
└── wake_word.h / wake_words/
    ├── esp_wake_word.h         # ESP-SR 语音唤醒
    ├── afe_wake_word.h         # AFE 语音唤醒
    └── custom_wake_word.h      # 自定义唤醒

设计评价：教科书级的策略模式——AudioCodec、AudioProcessor、WakeWordEngine 三个接口各自独立可插拔，组合出任意硬件配置。

3.4 网络与协议

支持两种通信方式：
- WebSocket — 直连服务端
- MQTT + UDP — 通过 MQTT 控制 + UDP 音频流

底层协议通过 protocols/ 目录统一：

protocols/
├── protocol.h            # 协议抽象基类
├── websocket_protocol.h  # WebSocket 实现
└── mqtt_protocol.h       # MQTT 实现

3.5 MCP 协议 — 设备控制核心

MCP (Model Context Protocol) 是 CogletESP 最有价值的创新点之一。它不是 Anthropic 的 MCP，而是 XiaoZhi 团队自研的设备控制协议：

设备(ESP32-MCP-Server)  ←→  云端(Backend-MCP-Client)
    JSON-RPC 2.0 over WebSocket/MQTT
    method: "initialize" / "tools/list" / "tools/call"
    capabilities: { vision: { url, token } }

核心价值：
- 云端可以动态发现设备上的工具（舵机控制、LED、摄像头、GPIO）
- LLM 可以通过 MCP 调用设备工具，实现「对话即控制」
- 双向能力协商：设备端和云端可以各自宣告 capability

归纳总结

  1. Coglet 的本质：它不是一个「原创固件项目」，而是「XiaoZhi AI Chatbot 框架 → 定制硬件的适配层」。核心价值在于硬件设计和 PCB 集成，而非固件创新。固件完全复用 XiaoZhi ESP 的成熟框架。

  2. XiaoZhi AI Chatbot 的架构水平：117 板型 + 38 语言 + 1417 文件 + 策略模式音频子系统，工程化水平相当高。板型抽象层（config.h + config.json 配对）设计得非常好，新板型接入只需几个文件。

  3. MCP 协议的独特性：XiaoZhi 的 MCP 是自研协议，与 Anthropic 的 MCP 完全不同。它解决了「LLM 对话如何控制物理设备」的工程难题——设备端注册工具 → 云端发现 → LLM 调用 → 设备执行。这是我们系统可以借鉴的能力方向。

  4. 硬件迭代状态：CogNog V1.0 仍处于早期迭代，已知问题列表较长（8项），说明项目还在打磨阶段。Kickstarter 众筹也说明了这一点——硬件还没定型。

  5. 与 Hermes Agent 的关系：Coglet 的 MCP 设备控制能力可以和我们已有的 IoT 能力形成互补。我们缺的是「LLM 直接控制物理设备」的标准化协议层。

趋势判断

  1. 开源硬件 + 成熟固件框架 → 定制硬件 是桌面 AI 陪伴机器人的主流路径，XiaoZhi AI 已成该赛道的基础设施。
  2. MCP 协议将分化出两个流派：Anthropic 的 Agent-MCP 和 XiaoZhi 的设备-MCP。设备端 MCP 在 IoT 场景有独特价值。
  3. 117 板型说明 XiaoZhi AI 的硬件生态已经相当繁荣，成为 ESP32 语音交互的事实标准框架。
  4. Coglet 的 Kickstarter 意味着硬件商业化的下一步——如果成功，会验证「3D打印 + XiaoZhi固件」这条 DIY 路径的可行性。
