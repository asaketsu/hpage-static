一、内容整理

1.1 问题：探索策略的管理是 RSI 瓶颈

原文定位：递归自我改进（RSI）正成为自主 AI agent 的核心能力——进步取决于能不能在复杂领域里持续发现高价值解法，而驱动这件事的引擎是有效探索。

现有系统的两难：

路线 问题
固定探索策略 跟不上搜索空间的扩大
在线策略优化 元搜索空间巨大 + 长时程 rollout，反馈延迟且昂贵

1.2 关键洞察：发现历史本身就是一台模拟器

原文用导航类比：agent 在陌生环境第一次导航会走弯路、撞死路、backtrack，最后画出一张地图。地图一旦被记录，新策略不必把每个地点实地走一遍——可以在地图上推理、绕开已知死路、重新考虑早先决定、比较不同路线。

与 model-based RL 同构：Dreamer 系列先从经验学一个紧凑动力学模型，再在模型里"想象"轨迹改进策略。

长时程发现具有同样结构：

  • 探索策略决定：追哪个方向 / 精修哪个候选 / 并行探哪些分支 / 什么时候终止
  • 在线执行产生结构化的发现历史：探过的分支、决策点、计算成本、真实结果
  • 这份历史 = 经验性重放模拟器（replay simulator）——关于"已观察过的那部分发现空间"的有事实依据的模型
  • 在重放模拟器里，不同探索策略在已记录的发现树上走出不同轨迹：选不同分支子集、不同深度停下、重新分配预算——全部即时反馈，不需要真的再跑昂贵在线评估

1.3 方法：三阶段循环

Dream-RSI = 可扩展、可递归自我改进的探索框架。轻量编排层把探索显式化、可编程化，底下的 coding agent 一行不改。

阶段 动作
① 在线探索 当前探索策略引导 coding agent 扩展发现树，记录历史轨迹
② 构建重放模拟器 把发现树转换成可复用的模拟器池
③ 做梦策略改进 agent 在"梦里"提出大量替代策略→喂进重放模拟器模拟执行→快速反馈→持续精炼策略

自我改进闭环：每一轮在线发现都在为下一轮"做梦"补充素材，更好的策略又让下一轮在线探索更有效率。

1.4 实验设置

三个科学发现领域：算法工程、数学优化、GPU kernel 优化。

  • 算法工程：Lasso 正则化路径发现（高维统计基础计算原语），沿用 SimpleTES 基准（17 个合成实例），对手 = sklearn / glmnet / GPT-OSS-120B SimpleTES
  • 主对照："递归固定探索"——相同发现 agent、评估器、初始化、资源约束、第一轮策略，唯一差别是后续轮次不再更新策略
  • 成本口径：累计 discovery-agent 调用次数。Gemini-3.1 Pro 每轮 10 工作区×11 步=110 次；Gemini-3.7-Flash 每轮 32 工作区×20 步=640 次。Dream-RSI 保持相同每轮预算，只逐步更新策略，共 5 轮

1.5 结果

  • 算法工程 / 数学优化 / GPU kernel 三类任务上，Dream-RSI 达到有竞争力或更好的发现质量，若干设定下显著降低发现成本
  • 主图："下游平均运行时 vs 累计发现算力"——同样算力下，会更新策略的曲线更快落到更好的运行时
  • 两组分析：长时程发现中历史归纳偏置的作用 + 探索行为在递归轮次中如何演化

1.6 原文点睛

「这个方法把『省下来的算力』重新投到策略搜索上——不是让 agent 更会写代码，而是让它更会决定『下一步该探哪里』。这也是它和『换个更强的模型再来一遍』最本质的区别。」

二、查询拓展

2.1 与 Dreamer 的同构与差异

维度 Dreamer（MBRL） Dream-RSI（本文）
学的模型 环境动力学模型（神经网络） 发现历史的重放模拟器（结构化记录）
想象对象 环境轨迹 探索策略在发现树上的执行
改进对象 策略网络参数 探索策略本身（编排层）
反馈成本 低（模型前向） 低（树上重放）
底层 agent 不涉及 coding agent 零改动

关键差异：Dreamer 学的是神经世界模型（有泛化但有模型误差），Dream-RSI 的重放模拟器是纯记录回放（零模型误差但只覆盖已探索区域）。这决定了 Dream-RSI 的改进只能在"已见空间"内做策略优化——它的探索仍然靠在线阶段扩展边界。

2.2 "策略改进"改进的是什么

Dream-RSI 改进的不是 coding agent 的代码能力，而是编排层的探索决策：追哪个方向、精修哪个候选、并行开几个分支、何时止损。原文明确这是与"换更强模型"的本质区别——算力从重复评估转移到策略搜索的元层面。

这与本地 evolver/sensor-grid 的分层一致：底层执行器（coding agent / 训练管线）不动，元层（探索/监控策略）进化。

2.3 发现树数据结构

三阶段的核心数据结构是发现树（discovery tree）：节点=候选解，边=精修动作，附带计算成本与真实结果。重放模拟器的"即时反馈"本质是在这棵树上做 counterfactual 查询：如果换一个分支子集/预算分配，会得到什么。这是把"经验"组织成可查询结构，而非摘要文档。

2.4 与 AutoDream/夜间整理的对照

本地 auto-dream 体系（夜间跑知识整理）与 Dream-RSI 的"做梦"阶段同构：在线阶段积累（白天任务）→ 离线整理（做梦/重放）→ 改进下一轮（策略更新）。差异：本地做梦的产出是记忆/知识整理，Dream-RSI 的做梦产出是探索策略更新——目标更聚焦。

三、归纳总结

3.1 三阶段闭环的最小抽象

在线探索(昂贵,扩展边界) ──记录──> 发现树 ──转换──> 重放模拟器池
      ▲                                                    │
      └────── 部署新策略 ←── 做梦精炼 ←── 即时反馈 ←──────┘
  • 在线阶段负责广度（探索未知）
  • 重放阶段负责深度（在已知上优化策略）
  • 两者交替形成递归：在线素材越多，做梦改进越准；策略越好，在线探索越省

3.2 论文的方法论位置

相邻工作 与本文关系
SimpleTES 基准沿用 + 主对手（固定探索的 SOTA）
Dreamer v1-v4 想象学习的思想来源，但本文重放模拟器是记录而非学习模型
AlphaEvolve 类 在线进化搜索，本文给它加了元层策略进化
FunSearch 单轮 LLM 迭代发现，无递归策略更新

3.3 对"自进化"分类学的补充

按 09-12《MemSkill与自进化Agent分类学》的三分法（执行层/记忆层/策略层进化），Dream-RSI 属于策略层进化的干净实证：执行层（coding agent）冻结、记忆层（发现树）只增不减、进化全部发生在策略层。这个控制变量设计本身就是论文的方法论贡献。

四、趋势判断

趋势 1：探索策略显式化将成为 long-horizon agent 的标配
依据：原文"轻量编排层把探索显式化、可编程化，底下的 coding agent 一行不改"。含义：探索从 agent 的隐式行为提升为可版本化、可评估、可进化的独立 artifact。

趋势 2：重放式世界模型（记录即模拟器）会与学习式世界模型并行
依据：重放模拟器零模型误差、构建成本近零，代价是覆盖受限。含义：在高成本评估域（GPU kernel 优化、科学发现），记录回放先于神经世界模型落地。

趋势 3：算力预算从"再跑一遍"转向"元策略搜索"
依据：主图显示同样算力下策略更新曲线更优。含义：评估预算固定时，投资策略搜索的 ROI 高于投资执行次数——这对本地 GPU 训练排程有直接启发。

趋势 4：RSI 的实证研究从代码生成扩展到科学发现
依据：三个领域（算法工程/数学优化/GPU kernel）都不是通用 coding，而是有明确评估器的发现任务。含义：RSI 落地首选"评估器清晰"的领域，泛化到模糊评估域仍远。

趋势 5：发现历史的数据结构化（发现树）是新的基建
依据：重放模拟器的可行性完全依赖发现历史被结构化记录（分支/决策点/成本/结果）。含义：不记录发现过程的 agent 系统等于丢弃了免费的模拟器素材。

五、关联分析

5.1 与 RSI 全景笔记的主线关联

RSI递归自我改进全景-AI造AI的三闭环进化机制与从理论到工程的演进地图：该篇给出 RSI 三闭环分类，Dream-RSI 是其中"策略闭环"的 2026-09 最新实证——把探索策略管理从固定脚本升级为递归进化对象，且给出了对照实验（固定探索 vs 递归更新）证明该闭环的独立价值。

5.2 与自进化 Harness 系列的关联

自进化Harness与记忆-三种写的不可混同-LiveSWE-DGM-SWE-Exp实证拆解：该篇区分三种"自进化写"（代码/记忆/策略），Dream-RSI 明确只做策略层，与 DGM（代码层）形成互补对照。

Ecdysis-Harness自进化失败归因：Ecdysis 失败于自评估可靠性，Dream-RSI 绕开这个坑的方式是——评估用的是发现树上的真实记录结果（在线阶段已花真算力验证），做梦阶段只是重新组合这些真值，不引入自评幻觉。

SoL-Pi英伟达开源自我优化Harness-四大机制与152选4的RSI流水线拆解：SoL-Pi 的 RSI 流水线与本篇三阶段循环同构（生成→评估→选择→再部署），但 SoL-Pi 进化的是机制组合，Dream-RSI 进化的是探索策略。

5.3 与做梦/离线整理系列的关联

Agent记忆离线整理-AutoDreamer区域重写与SleepTimeCompute精读：AutoDreamer 的"做梦=离线区域重写"与 Dream-RSI 的"做梦=重放模拟器上的策略精炼"是同两种范式在两个对象上的实例：前者重写记忆，后者精炼策略。两者都遵循"在线积累→离线改进→再上线"的节律。

5.4 与世界模型系列的关联

GigaBrain行为世界模型精读-三头预测架构地形自标注与DUCKPi5借鉴判定：GigaBrain 学神经世界模型（有泛化），Dream-RSI 用记录重放（有保真）。两条路线的取舍取决于评估成本：评估贵→重放；需要泛化到未见状态→必须学模型。

WorldModel与机器人策略耦合-五范式分类与DUCK映射：可把 Dream-RSI 的重放模拟器归为五范式中的"经验回放式世界模型"变体——不是学环境，而是学（记录）自己的搜索过程。

5.5 与安全笔记的关联

EVOMAL-自进化编码Agent的自我投毒漏洞与安全边界迁移：EVOMAL 警告自进化系统的自我投毒风险。Dream-RSI 的架构天然抗投毒：重放模拟器只含真实在线结果，策略改进不能伪造评估值——但前提是在线评估器本身可信，这一前提在开放任务里并不总是成立。

5.6 与本地 DUCK 训练体系的关联

本地 DUCK G8/G9 四路训练正面临 Dream-RSI 同构的问题：训练配置（探索策略）固定，逐版本人工迭代。Dream-RSI 的启发：把"变体→结果"的结构化历史（已有：项目 docs 的版本日志）显式组织成发现树，下一轮选型（追哪个方向/精修哪个超参/何时止损）可在这棵树上做离线推演，而不是凭直觉重跑。这不需要动训练栈，只需在 duck-p3-pilot 的 PROGRESS/版本台账上加"分支决策点"字段。

5.7 与 EvolveMem/MemSkill 的关联

EvolveMem自进化记忆架构-检索基础设施作为进化对象：EvolveMem 进化检索基础设施，Dream-RSI 进化探索策略——同属"进化系统周边设施而非模型本体"的路线，与"换更强模型"形成方法论对立。

七、行动启示
