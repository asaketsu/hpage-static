核心发现

发现一：vLLM V1 架构 — 生产级推理引擎的全面升级

vLLM V1 版本标志着一个新的里程碑：

核心特性一览：
- Automatic Prefix Caching (APC) — 自动前缀缓存，相同前缀的请求共享 KV Cache，大幅降低重复计算
- Data Parallel — 数据并行部署，支持多 GPU 横向扩展
- Context Extension — 上下文长度扩展，突破模型原生上下文限制
- Sleep Mode — 休眠模式，空闲时释放 GPU 资源
- Structured Outputs — 结构化输出，原生支持 JSON Schema 约束
- Interleaved Thinking — 交错思维模式，支持思考过程与输出交替

硬件支持扩展：
- NVIDIA GPU (CUDA)
- AMD GPU (ROCm)
- Intel GPU (XPU)
- Google TPU
- Intel CPU

发现二：推测解码（Speculative Decoding）进入多样化时代

vLLM 支持多种推测解码策略，成为推理加速的关键技术：

策略类型：
1. Draft Model — 小模型起草、大模型验证
2. EAGLE Draft Models — 基于特征级别的推测，无需独立小模型
3. MLP Draft Models — 轻量 MLP 网络做 token 预测
4. MTP (Multi-Token Prediction) — 一次预测多个 token
5. N-Gram Speculation — 基于统计的 n-gram 推测
6. Suffix Decoding — 基于后缀匹配的推测解码
7. Parallel Draft Models — 并行使用多个草稿模型

关键洞察：
- 推测解码的核心思想：用低成本的"猜测"减少大模型的串行解码次数
- EAGLE 方法最值得关注：利用隐藏状态（hidden states）而非独立模型，降低了显存开销
- MTP 代表了 LLM 架构层面的创新：模型本身训练时学习多 token 预测

发现三：分离式预填充（Disaggregated Prefill）— 解码 prefill 解耦

这是 2026 年推理优化的最重要架构创新：

核心思想：
- Prefill（预填充/提示处理）阶段是计算密集型（compute-bound）
- Decode（解码/生成）阶段是内存带宽密集型（memory-bound）
- 两者解耦到不同 GPU，各自优化

实现方案：
- Disaggregated Encoder — 编码器与解码器分离部署
- Disaggregated Prefill V1 — 预填充分离第一版实现
- FlexKV Connector — 灵活的 KV Cache 传输连接器
- Mooncake Connector — 月之暗面开源的 KV Cache 传输方案
- NIXL Connector — NVIDIA 高性能 KV Cache 传输

架构图：

┌─────────────┐    KV Cache    ┌─────────────┐
│ Prefill GPU │ ──────────────→ │ Decode GPU  │
│ (计算密集)   │  高速传输       │ (访存密集)   │
│ H100/A100   │  RDMA/NVLink   │ H100/A100   │
└─────────────┘                └─────────────┘
     ↑                              ↓
  用户请求                       输出 token

实际意义：
- Prefill GPU 可用计算能力强的卡处理长上下文
- Decode GPU 可用高带宽的卡优化 token 生成速度
- 单集群吞吐量可提升 2-3 倍

发现四：量化方案百花齐放

vLLM 支持的量化方案已极其丰富：

主要方案：
- FP8 (W8A8) — 8-bit 浮点权重+激活，A100/H100 原生支持
- INT4 (W4A16) — 4-bit 权重，16-bit 激活，极大减少显存
- INT8 (W8A8) — 8-bit 整数权重+激活
- GGUF — llama.cpp 兼容格式，支持 CPU + GPU 混合推理
- GPTQ — 训练后量化经典方案
- AWQ (AutoAWQ) — 激活感知权重量化
- BitsAndBytes — 混合精度量化
- Quantized KV Cache — KV Cache 量化，减少长上下文显存占用
- 在线量化 — 运行时动态量化，无需预处理

选型建议：
- H100/H200 → FP8（原生硬件支持，质量损失最小）
- A100 → INT4/INT8（平衡速度和质量）
- Jetson/边缘设备 → GGUF（CPU+GPU 混合，灵活）
- 长上下文场景 → 量化 KV Cache（减少显存峰值）

发现五：RLHF 训练与推理融合

vLLM 新增 RLHF（强化学习人类反馈）训练支持，这是推理引擎的新角色：

  • Async RLHF — 异步强化学习
  • IPC Engine / NCCL Engine — 进程间通信/分布式通信引擎
  • FSDP (Fully Sharded Data Parallel) — 完全分片数据并行
  • Weight Transfer — 训练→推理的权重无缝传输

这标志着推理引擎从"纯粹服务"走向"训练-推理一体化"。

EAGLE 推测解码原理（简化）

# 传统自回归解码：每步 1 token
for step in range(max_tokens):
    token = model.generate_one_token(context)  # 大模型前向传播
    context += token

# EAGLE 推测解码：每步验证 N 个候选
for step in range(max_tokens):
    candidates = eagle_head.predict_n(context, n=5)  # 轻量 MLP
    verified = model.verify_batch(context, candidates)  # 一次前向验证多个
    context += verified  # 可能一次接受多个 token

实践启发

1. 对 Jetson Orin 平台的意义

Jetson Orin Nano Super (67 TOPS) 可利用：
- GGUF 量化 — CPU+GPU 混合推理，Q4_K_M 量化后可在 8GB 显存运行 7B 模型
- INT4 量化 — 进一步压缩模型，支持本地 LLM 推理
- 量化 KV Cache — 长上下文场景下减少显存峰值

2. 对 Hermes Agent 的影响

  • Hermes 的 llm-inference-optimization skill 需要更新：加入 EAGLE、分离式预填充等新技术
  • serving-llms-vllm skill 需要更新：V1 架构的新配置方式
  • 推理成本持续下降（92% in 3 years），Agent 的推理预算可以更激进

3. 推理优化 = Agent 能力释放

推理速度直接决定了 Agent 的响应时间：
- 推测解码可将延迟降低 2-3x
- 分离式预填充可将吞吐量提升 2-3x
- 量化使更大模型可在更少 GPU 上运行
- 这些技术共同推动 Agent 从"慢速助手"向"实时协作者"进化
