## 摘要

Open Code Review 是阿里巴巴内部历经两年大规模验证的 AI 代码审查 CLI 工具，已服务数万名开发者、发现数百万代码缺陷。其核心创新在于"确定性工程 × Agent 混合"架构：用工程逻辑保证覆盖率、定位精度等硬指标，用 Agent 处理需要动态上下文的软决策。现已开源，配置任意模型端点即可使用。

## 核心内容

### 问题：通用 Agent 做代码审查的痛点
1. 覆盖不完整 — 大 changeset 下 Agent "偷懒"，选择性审查部分文件
2. 位置漂移 — 报告的行号与实际代码位置不匹配
3. 质量不稳定 — 纯自然语言驱动的 Skill 难以调试，prompt 微调导致质量剧烈波动

### 解决方案：确定性工程 × Agent 混合架构

**确定性工程层（硬约束）**：
- 精确文件选择 — 工程逻辑决定哪些文件需要审查，一个不漏
- 智能文件捆绑 — 相关文件打包成审查单元（如 message_en.properties + message_zh.properties），每个 bundle 独立子 Agent，支持并发
- 细粒度规则匹配 — 模板引擎匹配审查规则到文件特征，消除信息噪音
- 独立定位+反思模块 — 外部评论定位和反思模块系统性提升准确率

**Agent 层（动态决策）**：
- 场景调优 Prompt — 深度定制审查场景模板
- 动态上下文获取 — 读取完整文件内容、搜索代码库、检查其他变更文件
- 工具调用能力 — Agent 可主动获取额外上下文

### 技术亮点
- Git diff 读取 → Agent 工具调用 → 结构化审查评论（行级精度）
- 分治策略：大 changeset 自动拆分为 bundle，隔离上下文
- 并发审查：多个 bundle 可并行处理

## 关键概念

| 概念 | 定义 |
|------|------|
| 确定性工程 | 用硬编码逻辑保证必须正确的步骤（文件选择、规则匹配） |
| Agent 混合 | 在确定性框架内嵌套 Agent 处理需要推理的环节 |
| 文件捆绑 | 将关联文件打包为一个审查单元，避免 Agent 遗漏 |
| 位置漂移 | AI 报告的代码位置与实际不符的现象 |
| 评论反思 | 独立模块验证 AI 评论的准确性和相关性 |

## 能力边界

- 需要配置 LLM 端点，不内置模型
- 对非 Git 项目支持有限
- 大型 monorepo 可能需要调优捆绑策略
- 审查质量依赖底层模型能力

## 最佳实践

1. 配合 CI/CD 流水线使用，PR 自动触发审查
2. 对大型 changeset 依赖自动捆绑 + 并发，不要手动指定审查范围
3. 审查规则按项目特征定制，减少噪音
4. 评论定位模块和反思模块不要关闭，它们是质量保障的核心
