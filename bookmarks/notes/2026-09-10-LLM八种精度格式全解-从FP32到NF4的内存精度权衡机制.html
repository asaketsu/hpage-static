零、结论先行

这是一篇把"为什么 12GB 显卡能跑 7B 模型"讲透的科普长推——核心机制只有一句：浮点数的位数从指数位或尾数位里出，出指数位丢范围（大值溢出），出尾数位丢精度（近值合并），八种格式就是在两种损失间做不同分配。

对我们价值的定位：这是理论补充——同日的《显卡微调小模型精度选择指南》笔记已覆盖实操（3090 选 FP16/4090 选 BF16/QLoRA 配置），本篇补齐"为什么"层：BF16 为什么不溢出、FP16 为什么要 Loss Scaling、NF4 为什么对 QLoRA 特殊。两篇构成"理论-实操"闭环。

一、八种格式机制全景（忠实还原）

1.0 基础：浮点数的三段分配

[符号位 | 指数位（范围） | 尾数位（精度）]
  • 减指数位 → 大值溢出（overflow）
  • 减尾数位 → 近值合并（rounding error 逐层累积）

1.1 八格式速查表

# 格式 指数位 尾数位 字节/参数 核心机制 典型场景
1 FP32 8 23 4 全精度基准 优化器状态（即使低精度训练也保留）
2 BF16 8 7 2 保范围舍精度——向下转型永不溢出 4090+/H100 训练默认
3 FP16 5 10 2 保精度舍范围——分辨率 8 倍但上限 65504 3090 训练（需 Loss Scaling）
4 TF32 8 10 4（存储不变） 只算不存——Tensor Core 内部用 FP32 指数+FP16 尾数 A100/Ampere matmul 加速
5 FP8 E4M3 4 3 1 上限 448，承权重+激活 H100 推理/训练前向
6 FP8 E5M2 5 2 1 上限 57344，承梯度（跨更多数量级） H100 训练反向
7 INT8/INT4 — — 1/0.5 等距 256/16 级 + 独立 scale factor CPU/边缘推理（GGUF 主战场）
8 NF4 — — 0.5 16 级不等距，按预训练权重实际分布排布 QLoRA 冻结底座

1.2 三个最关键的机制细节

① FP32 为什么在低精度训练中仍然活着：梯度更新量太小，16 位存储会把它 round 掉——所以优化器状态（momentum/variance）默认仍是 FP32。这就是"混合精度训练"的混合所在：前向 FP16/BF16，master weights + optimizer FP32。

② FP16 的 Loss Scaling 补偿机制：小梯度低于 65504/2^11 的表示下限会 flush to zero——所以训练时先把 loss 放大再反向，更新前再除回来。这是 3090（无 BF16 Tensor Core 加速优势）训练的实际成本：不是不能训，是要管好这个 scaling。

③ TF32 是"计算格式"不是"存储格式"：内存里还是 FP32（4 字节不变），只在 Tensor Core 做矩阵乘时用 TF32——"never touches memory"这个表述是本推最精辟的一句。A100 上 matmul 提速但显存零节省。

1.3 INT 量化的离群值陷阱（大模型量化的核心难题）

INT8/INT4 的等距映射有个致命弱点：一个离群值（outlier）拉伸 scale，使所有普通值挤进第一格、round 到零。

这个问题在 activations 上最严重（LLM 激活值有系统性离群通道）。两个经典解法：
- LLM.int8()：离群通道分离计算（FP16 处理 0.1% 离群维度，INT8 处理其余）
- SmoothQuant：把激活的离群难度数学上迁移到权重侧（权重好量化）

1.4 NF4 为什么配 QLoRA

NF4 的 16 个量化级不等距，按预训练权重的实际分布（近似正态/信息论最优）排布——普通值密集区精度高，尾部稀疏区精度低。这让 QLoRA 能把冻结底座压到 4bit，同时 LoRA 适配器以 BF16 在上面训练——底层不动的精度损失被顶层的可训练精度补偿。

1.5 权重之外：KV Cache 是另一个战场

推文尾段点到：长上下文时 KV Cache 会超过权重本身。prefill（算力瓶颈，并行处理全部输入）与 decode（带宽瓶颈，逐 token 生成）的分界，以及 DeepSeek V4 围绕 cache 重设计 attention 把 1M context 的 cache 压到十分之一。

二、与我们已有知识的交叉验证

推文论断 我们的印证 状态

批判一处：推文说"FP16 covers roughly up to 65504"——准确；但"BF16 casting down never overflows"表述过强：BF16 溢出边界与 FP32 相同（~3.4e38），范围不损失但精度损失 8 倍，累积误差在深网络仍然存在。"never overflows"对单次转型成立，对训练动态不完全是护身符。

三、Jetson Orin 侧对照（我们的部署现实）

格式 Orin 可用性 我们的实践
FP32 ✅ 默认兜底
FP16 ✅（Ampere Tensor Core） LuxTTS/whisper 推理
BF16 ✅ 硬件支持（Ampere）但 Tensor Core 无 BF16 加速 训练选 FP16（与 3090 同理）
TF32 ✅（Ampere） matmul 自动受益
FP8 ❌（Hopper+） 不适用
INT8 ✅（67 TOPS INT8 是官方口径） TensorRT 部署主格式
INT4 ✅ GGUF q4 路线（nexa 本地推理）
NF4 ✅（软件层） QLoRA 微调（AutoDL 上用，本机不训）

关键洞察：Orin 的 67 TOPS 是 INT8 口径——我们边缘部署的最优格式链是 INT8（TensorRT）> INT4（GGUF/llama.cpp）> FP16（兼容兜底）。FP8/NVFP4 是 H100/GB10 的武器，与边缘无关——这与昨日 MiaAI-Lab 笔记的 NVFP4 生态形成平台分层。

四、训练-推理格式决策树（整合两篇笔记）

训练场景：
├─ H100/GB10 → BF16（或 FP8 E4M3 前向+E5M2 反向）
├─ 4090/A100 → BF16
├─ 3090/Orin → FP16 + Loss Scaling（吞吐优先）
│   └─ 梯度溢出难管？→ 降 BF16（速度减半换稳定）
└─ 显存不够 → QLoRA（NF4 底座 + BF16 适配器）

推理场景：
├─ 边缘（Orin/Pi5）→ INT8 TensorRT / INT4 GGUF
├─ 3090/4090 → AWQ/GPTQ INT4 或 FP16
├─ H100 → FP8 / NVFP4
└─ 128GB 统一内存（GB10）→ BF16 全精度也放得下（Mia 路线）

五、金句提取

"Every format below FP32 does the same thing: it trades numeric detail for memory."

"BF16 casting down never overflows / FP16 resolves values eight times more finely but covers a far smaller range."

"TF32 never touches memory."（计算格式与存储格式的分离——本推最精辟）

"A single outlier stretches the range so far that every ordinary value falls inside the first step and rounds to zero."（INT 量化的本质难题）

"Halving the bits halves the memory, but the bits have to come out of either the exponent or the mantissa."

"On long contexts, the KV cache outgrows the weights entirely."
