## 一、内容整理

### 1.1 核心命题：把大模型的上下文学习（ICL）搬到机械臂

- LLM 中的上下文学习：只靠提示文本完成全新任务，不动权重。机器人领域对应物 = **给一段人类操作视频作为上下文提示，模型零样本复现陌生任务**，无需微调、无需采集该任务的机器人轨迹。
- 为什么语言指令不够：语言很难精准描述**物体空间约束、中间状态变化、时序操作流程**——精细动作文字说不清。
- 核心转译逻辑：模型从人类视频**推理"任务应该发生怎样的视觉变化"**，再映射成机器人本体可执行的动作。人类手部轨迹不能直接复制给机械臂，机器人先理解"世界应该变成什么样"，再输出适配自己本体的动作。

### 1.2 现有 WAM 路线的两大现实卡点

WAM（World-Action Model，世界行动模型）核心逻辑：先预测未来世界画面，再从预测画面解码机器人动作。要实现"看人类视频做新任务"，有两道门槛：

- **卡点一：缺少大规模、语义对齐的人-机器人配对数据。** 需要"人类操作视频 + 对应机器人执行轨迹"成对样本，人工采集成本极高；现有公开数据集样本小、任务少，还常要求人类视角/背景/物体与机器人场景高度一致，泛化弱。
- **卡点二：模型学捷径，不看视频提示。** 直接拿成对数据训练，模型偷懒——只靠机器人自身历史观测 + 文本指令预测下一步，忽略输入的人类视频。训练集任务尚可，测试全新任务时视频提示形同虚设。

Zero-WAM 整套工作围绕这两个痛点：一套**自动生成人-机器人配对数据的流水线**（治卡点一）+ **IFP 辅助训练目标**（治卡点二）。

### 1.3 组件一：Task-diverse VA —— 任务级均衡采样的机器人数据

- 公开机器人数据集大量重复遥操作轨迹，少数任务占绝大多数样本；直接训练 → 过拟合高频任务。
- 做法：按"**操作动作 + 操作对象**"重新划分任务，每个任务限制采样轨迹数量。
- 规模：处理 **5 套公开数据集（AgiBot、InternData-A1、OXE、RoboCOIN、RoboMIND）**，划分 **6000+ 不同任务**，每 epoch 采样约 **40 万条机器人轨迹**。
- 作用：①给 HumanGen 流水线提供丰富源数据；②纯语言指令模式也提升跨任务泛化。

### 1.4 组件二：HumanGen —— 从机器人轨迹自动生成人类演示视频（核心贡献）

不再人工拍视频，从存量机器人轨迹出发全自动生成语义匹配的人类操作视频：

```
机器人视频（按任务采样）
  ↓ 多模态大模型（Gemini/Qwen）解析
任务信息：任务名 / 物体初始状态 / 状态变化 / 最终状态
  ↓ 同时产出图像编辑提示词（主动多样化：背景、视角、物体实例、摆放位置变化，任务语义不变）
图像编辑模型（Nano Banana / Qwen-Image）
  ↓ 生成人类操作场景的初始观测图（第一人称）
多模态模型结合物体状态变化 → 产出视频生成 prompt
  ↓
文生视频模型（Kling AI / Wan）生成完整人类操作演示视频
  ↓ 大模型双重校验打分
语义保留分（1/3/5）+ 物理合理性分（1/3/5）→ 过滤不合格样本
  ↓
合格样本与原始机器人轨迹绑定 = 一组 ICL 训练样本
```

- 最终规模：**74.2K 组人-机器人配对，覆盖 8.6K 种任务**。
- 对比传统 MIME、RH20T（全人工采集，任务数仅几十到一百多）：**任务规模提升两个量级**。
- 主动多样化设计迫使模型学**语义对齐**而非像素匹配——人类视频和机器人画面视觉差异巨大也没关系。
- ICL 数据还混入外部（OpenLoong、Franka、Galaxea、RuierMan）、自研平台、仿真（RoboTwin）、真机（双臂 Franka）多源。

### 1.5 组件三：Zero-WAM 模型架构

- 基座：**Wan-2.2-TI2V-5B 视频生成模型**改造。
- 架构：**Mixture-of-Transformers（MoT）**——视频分支和动作分支拥有**独立 QKV、前馈网络、输出头**，**共享注意力层**交互信息。
- 范式：因果视频-动作建模。输入观测 + 任务条件，自回归分块预测未来机器人视频块，再基于预测视频解码可执行动作块。
- 任务条件 c 两种模式：
  - 语言模式：c = 语言指令；
  - ICL 视频模式：c = 人类视频 + 语言（语言可关闭）。人类视频序列直接拼接在机器人观测序列**最前面**作为上下文记忆。
- 关键设计：对人类视频的 **RoPE 旋转位置编码施加高度维度偏移**，使人类视频 latent 与机器人视频 latent 处在不同坐标区间，避免表征混淆。
- 信息流分工：**人类视频只给视频分支看**（推演未来世界状态变化）；**动作分支不直接读人类视频**，只接收预测出的机器人未来视频做逆动力学解码输出电机动作。

### 1.6 组件四：IFP —— 专治捷径学习的训练目标

- 问题：传统训练只监督紧挨着的下一个视频块，模型靠历史观测就能预测，不用看人类视频。
- IFP（In-Context Future chunk Prediction）：基于当前特征**同时预测未来多个间隔步长的视频块**。
- 精妙约束：**IFP 模块自身看不到人类视频提示**，只能读主视频 Transformer 输出的融合特征 → 强制主分支把人类视频中的任务演化信息编码进自身特征，否则 IFP 无法预测未来多步画面。
- 推理阶段 IFP 模块直接移除，**零推理开销**。
- 总损失 = 视频流匹配损失 + 动作流匹配损失 + HumanGen 样本额外加权的 IFP 损失。
- 消融：完整版 vs 去 IFP，7 项仿真未见任务平均成功率 **28.55% → 46.95%**；长时序堆叠积木 **0% → 9%**；铰接物体操作提升最明显。

### 1.7 实验：仿真零样本 + 真机未见配置

**RoboTwin 2.0 仿真（43 任务训练，7 任务任务级完全扣留做零样本）**

```
任务                        WAN基线   LingBot-VA   Zero-WAM
放空杯子                    38.33     42.33        84.87
移动订书机到垫子            10.67     23.33        69.14
打开微波炉（铰接物体）       2.26      29.33        59.00
盖章                        7.33       3.67        47.00
放面包进篮子（双臂）        15.26     17.33        35.00
放置物件到秤                3.00       6.17        24.67
堆叠三块积木（长时序）       0.00       0.00         9.00
─────────────────────────────────────────────────────
平均                        10.98     17.45        46.95（+29.5pp vs LingBot-VA）
```

- 训练全程未见过这 7 个任务的机器人轨迹 → 证明模型确实在**推断全新任务的时序物理演化**，不是死记训练集。
- 堆叠积木仅 9%：超长时序多步骤操纵仍是 WAM 的"硬骨头"。

**真实 Franka 双臂（每类 30 次试验，物体/容器/组合全未见）**

- 三物体长时序顺序操作：文本基线 10% → Zero-WAM **33.3%**；
- 桌腿精密插入：语言基线 0% → Zero-WAM **16.7%**；
- 趋势明确：**越依赖时序顺序和精细空间约束，人类视频提示增益越大**。
- 客观局限：每类仅 30 次样本量不大；精密插入整体成功率仍低。

### 1.8 结论与作者展望

- 价值：任务指令不必是文字——用户部署时录一段自己动手的短视频，机器人看一遍就尝试复现，无需重训。
- HumanGen 复用存量机器人轨迹自动造人类演示，给出"人类演示数据规模化"的可行工程方案。
- 遗留难题：长时序多步骤操纵、亚厘米级精密装配。
- 未来方向：①用**真实第一人称互联网人类视频**（而非 AI 生成视频）做上下文提示；②**降低视频预测错误**是该路线能否落地的关键。

## 二、查询拓展

### 2.1 WAM（World-Action Model）

世界行动模型 = 世界模型（预测未来画面）+ 动作解码器（从画面到动作）的组合范式。区别于 VLA（Vision-Language-Action，直接从观测+语言端到端出动作）：WAM 显式以"未来视频预测"为中间表征，动作是预测画面的逆动力学解。代表工作：NVIDIA Cosmos 系列、Google Genie 谱系、本文 LingBot/Zero-WAM 谱系。

### 2.2 In-Context Learning（ICL）迁移到机器人

LLM 的 ICL 依赖 prompt 中提供的示例完成新任务。机器人 ICL 的"示例"可以是：语言描述（弱）、机器人示教轨迹（贵）、人类视频（便宜且无处不在）。Zero-WAM 论证了人类视频是三者中最优的"视觉任务规格"：能锚定物体实例、演示陌生物体交互、规定长时序任务步骤。

### 2.3 Mixture-of-Transformers（MoT）

多模态架构模式：不同模态（视频/动作）各自拥有独立参数的注意力 QKV、FFN 和输出头，但共享注意力层做跨模态信息交换。相比把所有模态塞进同一个 Transformer，MoT 减少模态间互相干扰，让动作分支不被巨大的视频表征空间主导。

### 2.4 Flow Matching（流匹配）损失

扩散类生成模型的训练目标变体：学习把噪声分布"流"向数据分布的向量场。视频流匹配损失 + 动作流匹配损失 = Zero-WAM 的双主干监督；相比离散 token 化动作，流匹配输出连续动作更平滑。

### 2.5 Wan-2.2-TI2V-5B

阿里 Wan2.2 系列文本-图像到视频（TI2V）5B 基座。选它做 Zero-WAM 底座的意义：机器人世界模型直接站在通用视频生成大模型肩上，继承其物理常识与画质，只做动作分支扩展和 ICL 适配。

### 2.6 RoboTwin 2.0

双臂操作仿真基准，任务级划分（43 训练/7 扣留）使其成为检验**零样本跨任务泛化**的合适考场——模型在训练中从未见过扣留任务的任何机器人轨迹。

### 2.7 对比数据集 MIME / RH20T

人-机器人配对数据集的早期代表，人工采集人类视频：MIME 约 dozens 级任务，RH20T 约 100+ 任务，且要求场景一致性。HumanGen 用生成流水线把任务量推到 8.6K，数量级差异本质是**把数据问题转化成生成模型的推理成本问题**。

### 2.8 Robbyant

港科大（广州）Junwei Liang 团队关联的具身智能研究力量，此前有 LingBot 系列视频-动作模型工作（本文基线 LingBot-VA 即其视频动作版）。

## 三、归纳总结

### 3.1 全链因果图

```
痛点1 数据稀缺 ──→ HumanGen流水线：机器人轨迹 →MLLM解析→ 首帧图像编辑→ 文生视频 → 双重打分过滤
                   │  74.2K配对 / 8.6K任务（人工采集的两数量级）
                   └→ 主动多样化(背景/视角/实例变化) → 逼模型学语义对齐而非像素匹配

痛点2 捷径学习 ──→ IFP辅助损失：预测未来多间隔视频块
                   │  IFP模块看不到人类视频 → 主分支必须把视频信息编码进特征
                   └→ 消融实证 28.55% → 46.95%（+18.4pp），推理时移除零开销

架构承载 ──────→ Wan-2.2-5B + MoT双分支：人类视频→视频分支（推演世界变化）
                   预测未来机器人视频→动作分支（逆动力学出电机动作）
                   RoPE高度偏移区隔人/机latent

结果 ─────────→ 仿真零样本 46.95%（+29.5pp）｜真机：时序/精度越依赖视频提示增益越大
                 遗留：长时序堆叠9%、精密插入16.7%
```

### 3.2 三种任务指定方式对比

```
维度          纯语言指令        机器人示教轨迹      人类视频ICL（本文）
采集成本      低                极高（每任务专用）   低（随手录）
空间约束表达  弱（说不清）       强                  强（演示即定义）
时序流程表达  弱                强                  强
新任务扩展    改prompt即可       需重新采集示教       录段视频即可
语义泛化      好                差（绑定场景）       好（HumanGen刻意多样化）
```

### 3.3 方法论要点提炼

- **数据规模化 → 生成式合成**：存量机器人轨迹是"免费"的语义种子，用 MLLM + 图像编辑 + 文生视频三段流水线放大，配打分过滤器控质量。
- **表征区隔**：跨模态序列拼接时用位置编码偏移做"命名空间隔离"（RoPE 高度偏移），简单有效。
- **反捷径监督设计**：辅助头被刻意剥夺看提示的权限，逼主干编码提示信息——本质是信息瓶颈式训练。
- **训练专用模块推理时可丢弃**：IFP 只在训练起作用，不付推理成本。

## 四、趋势判断

### 趋势1：人类视频将成为机器人领域的"prompt 资产"

依据：互联网第一人称视频（烹饪/装配/操作）存量巨大且零采集成本，本文结尾明确指向"真实互联网人类视频做上下文提示"为下一站。语言→视频作为机器人任务指定界面，正在重演 LLM prompt 生态的路径。

### 趋势2：人-机器人配对数据从"采集问题"变成"生成问题"

依据：HumanGen 用两条数量级优势证明生成路线可行；随 MLLM/图像编辑/文生视频能力继续涨价，合成配对数据的物理合理性与语义保真度会同步上升，成本单调下降。

### 趋势3：WAM 与 VLA 从对立走向混合

依据：Zero-WAM 本身就是"视频生成基座 + 动作头"的混合体；视频预测中间表征提供可解释性和世界一致性约束，端到端动作头保证执行效率。未来主流大概率是"预测式骨干 + 判别式动作解码"的分层混合，而非纯路线之争。

### 趋势4：长时序多步骤与亚厘米精密装配是下一阶段主战场

依据：堆叠三块积木 9%、桌腿插入 16.7% 是全文最刺眼的两个数字；作者自陈这是 WAM 共同难题。谁能把视频预测误差在长 horizon 内不累积，谁拿下这关。

## 五、关联分析

### 5.1 与「具身智能2026-世界模型VLA车企入局」笔记的关联

该笔记梳理了世界模型与 VLA 两大路线的产业格局；Zero-WAM 是"世界模型路线向任务泛化发力"的最新实证——用 46.95% 零样本成功率说明视频预测骨干 + ICL 提示可以不吃任务级机器人数据。可作为该笔记的技术进展增量。

### 5.2 与「NVIDIA Isaac GR00T 人形机器人平台」笔记的关联

GR00T 走"海量异构机器人数据 + 多模态基础模型"路线，Zero-WAM 补充了另一条互补路径：机器人数据不够时，用生成流水线把人类视频侧"翻译"进来。两者共同点：任务级泛化是下一代机器人基础模型的统一评价轴。

### 5.3 与「物理AI闭环日冕远图万台级部署」笔记的关联

该笔记关注物理 AI 的规模化部署闭环；Zero-WAM 的"录段视频即部署新任务"交互形态，正是部署侧降低任务配置成本的关键候选——部署量越大，免重训的任务指定方式价值越高。

### 5.4 反捷径监督的普适借鉴

IFP 的"辅助头无权限看提示 → 逼主干编码提示"是通用训练设计模式，与多模态学习里常见的"模态dropout 反惰性"同族；任何"模型忽略某路输入"的场景（多传感器融合、检索增强）都可套用此信息瓶颈思路。

## 六、金句摘录

> 「人类手的运动轨迹不能直接复制给机械臂，机器人需要先理解'世界应该变成什么样'，再输出适配自己本体的动作。」— 本文最核心的转译哲学：视频提示约束的是世界状态演化，不是动作本身。

> 「训练集见过的任务效果尚可，但测试遇到全新任务时，本该依赖视频提示，模型却依旧只看历史观测，视频提示形同虚设。」— 捷径学习的经典自白，所有多输入监督学习都该自问这句。

> 「未来实际部署场景，用户只需要录一段自己动手操作的短视频……机器人看一遍视频，就尝试复现整套任务，不需要重新训练。」— 任务指定界面的终局想象。

## 九、指南分析

**本文的阅读指南与定位判断：**

1. **读什么**：这是一篇"数据工程 × 训练目标设计"双轮驱动的系统论文——最大的可学点不在模型架构（MoT 是成熟模式），而在 HumanGen 流水线的工程分解和 IFP 的监督设计巧思。
