## 零、结论先行

Tech With Tim 的核心论断：**AI 工程师不是新职业，是软件工程 + 一层 AI**。证据来自他朋友的真实工作画像——年薪 $200k-300k 的 AI 工程师，**日常工作只有 20% 是 AI，80% 是普通软件工程**（构建让 AI 模型在生产环境真正跑起来的周围系统）。

全文结构：
```
定位（AI 工程师≠AI 研究员：用现成模型造产品，不训模型不搞数学）
  → 已有基础（API/数据库/测试/部署/系统设计——新手要学几个月的东西你都会）
  → AI 特定差距 = 六域
  → 加速转型三路径（作品集/团队 AI 担当/用 AI 工具）
```

**本笔记的价值**：这是今天系列笔记的**收官拼图**——把它的六域差距论放进《AI工程化终极路线图》十域框架里对照，会发现一个有趣的错位；而它的"80% 是软件工程"判断与朱峰/姜老师/判官三篇笔记形成**四路收敛**。第一章还原原文，第二章做收敛验证，第三章给体系对照。

## 一、原文六域忠实还原

### 域 1：理解 LLM 工作原理
- 不需要数学，需要**实用心智模型**：token（为何按 token 不按词）、上下文窗口（为何不能无限塞信息）、temperature 等参数、system/user/assistant 消息角色
- 目标：模型行为异常时能**推理出为什么**，而不是随机改 prompt 碰运气
- 金句："这是'会用 AI'和'会用 AI 做工程'的区别"

### 域 2：用 LLM API 构建
- 打开 ChatGPT 聊天 ≠ 从代码调模型。学 OpenAI/Anthropic API：发请求、处理响应、多轮对话、失败处理
- 关键视角转换：**LLM 不是只响应聊天框**——可分类数据、总结文档、填数据库字段、在后台处理大工作流的一环。理解了这点，软件系统里用 AI 的方式一下子多了很多

### 域 3：让输出可靠
- prompt 工程不是流行词：system/user prompt、function calling、**结构化输出**——拿到代码可处理的 JSON/可预测格式而非任意文本
- 目标是**可靠性**：生产环境代码能实际使用的一致输出

### 域 4：RAG 与向量数据库
- 当前 AI 工程最热门的模式，真实 AI 应用很大比例都用某种形态的 RAG
- 逻辑：通用模型不懂你的私有数据（文档/代码库/企业知识库）→ embedding → 向量库 → 按请求检索 → 作为附加上下文传给模型
- 难点：大数据量下让它**高效**工作

### 域 5：编排与 Agent
- 从单次模型调用到真正的 AI 系统：agent 可能搜网、查库、算数再综合回答——要管理多模型调用、工具、记忆、状态、失败、重试、限流、多步工作流，还要决定哪些步骤串行哪些并行
- 框架：LangChain/LangGraph/Temporal/LlamaIndex。**真正的挑战是让所有步骤可靠协同**
- 金句："这里是 AI 工程开始感觉像普通软件工程的地方"

### 域 6：LLMOps
- **最多人跳过、也最重要的部分**：限流、成本优化与缓存、模型路由、监控可观测、评估（Evaluations）
- 要知道什么时候在失败、AI 在系统里干了什么、改动是变好还是变坏、成本怎么控
- **雇主最看重的领域之一**：有软件工程背景 + 能在生产环境部署运营 AI 系统 = AI 工程师里真正突出的人

### 转型加速三路径
1. **建作品集**：不做教程克隆——做解决真实问题的真项目（领域 RAG chatbot/用真工具的 agent/真数据集上的语义搜索），仓库干净、部署上线、有监控
2. **当团队的 AI 担当**（在职者最快路径）：主动认领没人想碰的 AI 功能并在现公司交付——内部转岗几乎总是比从零找 AI 岗位容易
3. **用 AI 工具放大产出**：Cursor/Claude Code 等，自建 skills 和 agents，观察这些系统的行为——既提速又教你 AI 系统实际怎么工作

### 终论
成为 AI 工程师不是扔掉已有知识。**底座仍是软件工程**，加的是 AI 层：理解模型、代码调用、输出可靠、给对上下文、编排工作流、生产运营。"这比重来一遍的差距小得多。边做边学，你离 AI 工程师比想象中近。"

## 二、四路收敛验证（本笔记核心分析）

这篇文的价值单独看有限（转型建议类内容 2026 年已泛滥），但放进今天 12 篇笔记的语境里，它完成了**一个漂亮的收敛验证**：

### 2.1 "80% 软件工程"判断的四路独立收敛

| 来源 | 表述 | 视角 |
|------|------|------|
| Tech With Tim（本文） | AI 工程师日常 20% AI + 80% 软件工程 | 转型者/教育者 |
| 朱峰《分发商品化》 | AI 能生成的（prompt/工作流/技能）在贬值，真实供给（业务经验/信任）在升值 | 创业者 |
| 姜老师《投入决策》 | 固化 workflow 的核心价值是业务经验和验证过程，AI 只参与实现 | 个人开发者 |
| Josh Rosen《判官八模式》 | 应用层最大机会=画好确定性/非确定性边界——外围系统是可控的 | Agent 基建创业者 |

**四个独立作者、四种视角、同一周内、同一结论：AI 部分在商品化，工程部分（可靠性/生产运营/业务判断）是价值锚点。** 这个收敛本身比任何单篇的论证都更有说服力——它说明 2026 年行业认知已经定型。

### 2.2 六域 vs 十域：教育视角与工程视角的错位

对照《AI工程化终极路线图》的鸟哥十域：

| Tim 六域 | 鸟哥十域对应 | 错位分析 |
|----------|-------------|---------|
| 1 LLM 原理 | 01 LLM 基础 | ✅ 对齐 |
| 2 LLM API | （无独立域） | **路线图缺**——工程视角把"调 API"当默认技能不列；教育视角单列因为它是不写代码者的第一道坎 |
| 3 输出可靠 | 02 提示与上下文（部分） | ⚠️ 部分对齐：Tim 只讲结构化输出，路线图还含上下文工程/约束解码 |
| 4 RAG | 03 表征 + 04 RAG | ✅ 合并（教育视角合并合理） |
| 5 编排与 Agent | 05 工具与智能体 | ✅ 对齐（Tim 点名 Temporal 是路线图没有的增量——工作流引擎视角） |
| 6 LLMOps | 06 评估 + 08 LLMOps | ⚠️ **关键合并**：Tim 把 Evals 并进 LLMOps，路线图单列 |
| **（缺）** | 07 安全（护栏/注入防御） | **Tim 完全没提安全**——转型指南的普遍盲区，也是路线图比它完整的证据 |
| **（缺）** | 09 模型适配 / 10 进阶 | 合理省略（转型者不需要先学微调） |

**错位结论**：教育视角（六域）是工程视角（十域）的"最小可转型子集"——砍掉了安全（不该砍）、把 Evals 降级为 LLMOps 子项（不该降，判官笔记刚论证过它是一等公民）。**两图合用的正确姿势：转型用六域起步，成长以十域为纲，安全与 Evals 不可省。**

### 2.3 与判官笔记的互补

Tim 域 6 一句话带过的 "Evaluations"，正是 Josh Rosen 用 11.5KB 展开的主题。两篇同日互读：**转型指南告诉你"要学 Evals"，判官架构告诉你"Evals 具体怎么长在生产系统里"**——前者是 why，后者是 how。L1 门禁（昨日已落地）就是这个 how 的第一块砖。

## 三、体系对照：我们的位置

用 Tim 六域自检我们体系（简版，详细版见路线图笔记第三章）：

| 域 | 体系现状 | 相对转型者的位置 |
|----|---------|----------------|
| 1 LLM 原理 | ✅ 心智模型完备（token/上下文/参数/角色全在用） | 已越 |
| 2 LLM API | ✅ 多 provider 池+fallback 链+credential 轮换 | 已越（生产级） |
| 3 输出可靠 | ✅ 结构化输出+schema 校验（zhipu_mcp 二次解析就是实例） | 已越 |
| 4 RAG | ✅ 双路索引+hybrid-search+企业 RAG skill | 已越 |
| 5 编排 Agent | ✅ DAG/状态机（patent-docket 模式刚吸收）+delegate_task | 已越（Temporal 式持久工作流未用——meshy 笔记的数据驱动是同方向替代） |
| 6 LLMOps | ⚠️ 限流/缓存/路由/监控全有，**Evals 昨日刚补 L1** | **正在补齐的最后一域** |

**结论**：按 Tim 的定义，体系已越过"转型者"阶段全部六域，当前投资正确聚焦在域 6 的 Evals 深化（L2 判官/双判官）——**与今天所有笔记指向的结论一致**。

转型三路径对个人用户也有映射价值：路径 2"当团队的 AI 担当"正是企业内推广 Hermes 的策略（主动认领没人想碰的文档/检索/监控工作）；路径 3"用 AI 工具"已内化为本体系本身。
