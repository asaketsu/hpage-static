一句话总结

Harness（AI 驾驭系统）从 2026 年初的黑话变成共识，但真正壁垒不在 Harness 本身——模型在吃 Harness，Harness 在喂模型，飞轮转速才是护城河。

时间线：Harness 概念走红

时间 事件
2026-02-05 HashiCorp 联合创始人 Mitchell Hashimoto 发博「Engineer the Harness」
2026-02-11 OpenAI 发布 Harness Engineering 实验报告：3 人 × 5 个月 × 0 行手写代码 = 100 万行 + 1500 MR
之后 Martin Fowler 站台、LangChain 跟进，一个月内成为开发者圈黑话

Harness 四大能力

能力 说明 案例
约束 让 Agent 干不了坏事 OpenAI 把分层架构规则写进 CI，违反直接拒绝合并
记忆 让 Agent 记住东西 仓库维护结构化文档，Agent 随时查（鱼缸外贴满便签）
验证 做完有检查 Anthropic 方案：做事的和评判的分开（选手≠裁判）
纠错 搞砸能回滚 Git 回滚 + 换新 Agent + 交接单（不指望金鱼自我修复）

核心数据：Harness 的威力

  • LangChain：同一模型，只调 Harness，TerminalBench 2.0 得分 52.8% → 66.5%，排名 30+ → 前 5
  • Hashline 实验：只改代码编辑格式（加哈希标识），得分 6.7% → 68.3%，模型权重零修改
  • Cursor：没有自有模型，靠 Harness 层，估值 293→500 亿美元，年化收入 >20 亿美元

两派争论

「模型至上」派

  • Boris Cherny（Claude Code 创造者）：产品是最薄的包装，秘诀在模型
  • Noam Brown（OpenAI）：在推理模型上搭脚手架，很多时候是添乱
  • METR 测试：Claude Code 和 Codex 并没显著赢过基础脚手架
  • Scale AI SWE-Atlas：换哪个 Harness 框架，差距在误差范围内

「Harness 至上」派

  • LlamaIndex 创始人：一个下午优化 Harness，15 个模型编码能力全涨
  • Cursor：用别人的马，靠马具做到 500 亿估值
  • LangChain：马没换，换了套马具，排名暴涨

真相：两派在说不同层面

Boris 说「产品架构薄」没错，但他自己日常用 10-15 个 Claude Code 会话 + 自动化钩子 + 规划模式 + 子 Agent 审查。产品薄 ≠ 实践薄。

赛车手比喻：车底盘结构很简单，但每次上赛道前三小时调悬挂、胎压、刹车平衡。

关键洞察：顶级团队在拆 Harness

团队 做法
Manus 半年重写 5 次，每次砍功能
Next.js (v0) 删掉 80% Agent 工具，效果反而更好
Anthropic (Claude Code) 每 3-4 周重写一次

原因：新模型内化了旧 Harness 逻辑，多余代码变成约束。

Anthropic 研究员 Nicholas Carlini：每升一级模型，都得重新设计 Harness。旧的保护性逻辑变成了约束，限制了新模型能自主完成的事。

终极真相：蛇咬尾巴

模型吃 Harness（内化能力）
    ↕
Harness 喂模型（积累执行轨迹数据反馈训练）
    ↓
飞轮转速 = 真正壁垒

Cursor 值钱的原因：几百万开发者每天使用，每次使用给飞轮加燃料。积累的不是 Harness，是飞轮的转速。

吸收要点（对 Hermes Agent 开发的启示）

  1. Harness 必须持续瘦身：我们的 Skill 系统和 evolver 机制符合这个趋势——每发现模型内化了某个规则，就删除对应 Skill 约束（参考我们对 evolver 的 7→3 阶段精简）
  2. 执行轨迹即资产：skill-usage-tracker.py 收集的数据（哪些 Skill 有效、哪些被跳过）就是喂给飞轮的燃料
  3. 约束机械化 > 提示词叮嘱：OpenAI 的 CI 规则比一万句提示词管用——我们的「退出码 ≠ 0，任务 ≠ 完成」就是这个思路
  4. 做事和评判分离：Anthropic 的选手≠裁判原则，已在我们的 Agent 架构中体现（subagent 做事，主 Agent 审查）
  5. 最后一句彩蛋：Anthropic 把 Harness 做成了产品发布——说明 Harness Engineering 正在从「开发者手艺」变成「标准化产品」
