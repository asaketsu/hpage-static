AI Agent 记忆架构 2026：从上下文窗口到持久化知识

生成日期 2026-08-14

来源：Mem0 State of AI Agent Memory 2026 Report (2026-07-18) + Zylos Research 综述 (2026-04)
日期：2026-08-14

核心结论

无状态 LLM 无法跨会话保持关系、从错误中学习或积累专业经验。2025-2026 年，Agent 生态系统收敛于三层记忆分类法（episodic / semantic / procedural），镜像数十年认知科学研究。生产级 Agent 越来越依赖混合 vector-graph 架构作为后端，配合 LLM 管理的记忆操作接口。

1. 记忆三层分类法

类型 定义 典型实现 存储后端
Episodic（情景记忆） 记录特定过去事件：什么时间发生了什么 Letta recall memory（SQLite/PostgreSQL）, Zep Graphiti（带双时态标注） 对话日志数据库
Semantic（语义记忆） 声明性事实和关系：用户偏好、实体属性 Mem0（实体+关系提取→graph+vector）, LangMem 知识图谱 + 向量数据库
Procedural（过程记忆） 学到的工作流、成功的工具调用序列、行为启发式 CLAUDE.md / AGENTS.md 静态注入, LangMem 动态 update_system_prompt Markdown 文件 / 运行时上下文

关键细节

  • 情景记忆：Zep 的 Graphiti 引擎存储带双时态标注（bitemporal）的子图——事件时间（事实在世界中为真的时间）+ 摄入时间（Agent 首次观察到它的时间），使 Agent 能精确推理回溯性修正。
  • 语义记忆：Mem0 的冲突检测管道是新事实与已有 graph 条目比较，通过 LLM 判断进行合并、更新或标记——这是其核心架构创新。
  • 过程记忆：最不成熟但最有价值的一层。LLM 中的过程记忆最好表示为指令而非数据——当 Agent 学到"调用 API Y 前始终用 schema X 验证 JSON"时，作为系统提示指令注入比从向量库检索更有效。

3. 两个架构变更驱动性能飞跃

3.1 单次 ADD-only 提取

Mem0 现在将 Agent 生成的事实视为一等公民——Agent 的确认和推荐与用户陈述的事实同等权重存储，关闭了记忆覆盖的显著空白。

3.2 多信号检索（三路并行评分融合）

检索栈运行三个评分通道并行，然后融合结果：

语义相似度（Semantic Similarity）  ──┐
关键词匹配（BM25 Keyword Matching） ──┤→ 归一化融合 → 最终排序
实体匹配（Entity Matching）         ──┘

组合分数优于任何单一信号。实体链接取代了外部图存储——在 add() 时，Mem0 从每条记忆中提取实体并存入并行实体集合 {collection}_entities，检索时查询中的实体匹配该集合并提升相关记忆的最终分数。

4. 生产级记忆系统对比

框架 核心架构 关键数据 优势/劣势
Mem0 两阶段管道（LLM提取→冲突检测+graph更新） LoCoMo 92.5, 比 OpenAI 记忆高26%, 91%更低 p95 延迟 48K⭐, 21框架集成, 20向量库；图存储被内置实体链接取代
Zep/Graphiti 时态知识图谱（Neo4j） DMR 94.8% vs MemGPT 93.4%; P95 检索 300ms 双时态边标注；检索时无需 LLM 调用；BM25+embedding+graph 遍历
Letta (MemGPT) 三层 OS 式虚拟内存（core/archival/recall） — LLM 自主管理所有三层 via function calls；每个决策增加延迟和 token 成本
Cognee 六阶段 cognify + memify 自精炼 ~12K⭐ 14种检索模式；memify 周期自动修剪过时节点、按使用频率重加权边——最接近生物记忆固化
LangMem LangGraph 持久存储 + 命名空间语义去重 P95 搜索延迟 59.82 秒 update_system_prompt 动态过程记忆；延迟高，适合离线处理

Letta 的虚拟内存隐喻

┌─────────────────────────────────────────┐
│  Core Memory (always in-context, 2-4KB) │ ← 当前用户理解+活跃任务（RAM）
├─────────────────────────────────────────┤
│  Recall Memory (pageable conversation)  │ ← 对话历史日志（分页加载）
├─────────────────────────────────────────┤
│  Archival Memory (external vector store)│ ← 无大小限制，嵌入相似度搜索（磁盘）
└─────────────────────────────────────────┘

LLM 通过 core_memory_replace、archival_memory_search、archival_memory_insert 函数调用自主控制三层之间的页面调度，灵感来自操作系统虚拟内存。

5. 新兴模式

5.1 声明式记忆注入：CLAUDE.md / AGENTS.md

最广泛采用的 Agent 记忆模式也是最简单的：项目根目录的 Markdown 文件，在每个会话开始时注入 LLM 上下文。2025-2026 年，这些格式正在向跨工具标准收敛。

关键属性：Agent 可写性。Claude Code 从约 v2.0.64（2025 年末）开始允许 Claude 自主写入 CLAUDE.md；AutoDream（2026年2月）作为后台子 Agent 在空闲时审查和整合记忆文件——类似 REM 睡眠记忆固化。

5.2 跨会话学习前沿

论文 时间 方法
MemRL 2026-01 基于情景记忆的运行时强化学习——存储成功结果的记忆，遗忘失败的
MemEvolve 2025-12 元学习——进化 Agent 的整个记忆管理策略，而非仅内容
MAGMA 2026-01 多图 Agentic 记忆架构——专用事件子图 + 跨图遍历
MemoryOS EMNLP 2025 层次化三层模型，LoCoMo F1 提升 49.11%，镜像 LRU 缓存管理

5.3 多 Agent 共享记忆三种模式

  1. 共享全局记忆：所有 Agent 完全读写访问
  2. 层次化记忆：全局团队级 + 角色级 + Agent 私有
  3. 隔离记忆 + 消息传递：无共享状态，仅显式通信

6. 六大未解决难题

难题 现状
时间抽象规模化 BEAM 1M→10M 分数下降 25%（64.1→48.6）
跨会话结构 用户搬家应理解过渡，而非仅存储新城市。大多数系统将变化视为替换
应用级评估 LoCoMo 91.6 不代表你的医疗/法律工作负载表现

记忆过时 高频检索的记忆（用户雇主）在用户换工作后变为"自信地错误"

记忆投毒攻击

  • MINJA（2025）：>95% 注入成功率，70% 攻击成功率
  • Echoleak（2024）：隐藏在邮件中的 prompt 导致 Agent 泄露先前的对话隐私
  • A-MemGuard 发现：独立分析遗漏 66% 的投毒条目——恶意内容单独看是良性的，只有在特定触发查询组合中才显现危害
  • 防御需要分层：异常监控 + 复合信任评分 + 行为漂移检测 + 上下文审计

7. 对 Hermes Agent 的借鉴

  1. Hermes 的 MEMORY.md + USER.md 本质上就是 CLAUDE.md 模式——声明式记忆注入已被业界验证为有效模式
  2. 多信号检索可借鉴：当前 Hermes 记忆是纯文本注入，可考虑加入 BM25 关键词匹配提升检索精度
  3. 过程记忆 = Skills——Hermes 的 Skills 系统正是过程记忆的生产级实现，比多数框架更成熟
  4. 记忆投毒防御：Hermes 当前缺乏 memory 写入异常监控，cron 注入的 MEMORY 条目无人审查
  5. 双时态标注缺失：Hermes MEMORY 条目无过期机制，存在记忆过时风险（"hpage.top 需要 cloudflared"这类旧认知需要定期验证）
