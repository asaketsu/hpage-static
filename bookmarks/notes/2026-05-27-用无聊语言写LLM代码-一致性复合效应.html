核心论点

一致性复合（Consistency Compounds）：LLM 放大不一致的技术栈，强化一致的技术栈。训练语料中低方差的生态系统在编码 Agent 中表现更好。

这不是语言好坏的问题，而是统计学问题：在向量空间中，训练数据的一致性直接决定推理输出的可靠性。

关键洞察

1. JavaScript/Python 的碎片化诅咒

JavaScript 生态的碎片化是 AI 的噩梦：
- 2024 State of JS 调查揭示了严重碎片化
- Anthropic 在 Claude Code 中硬编码了对特定 JS 框架的偏好（泄露文档揭示）
- Python 同样：pip vs poetry vs uv，Django vs FastAPI，async vs task queue
- 对模型来说，"同一个问题有 N 种写法"意味着"每种写法的权重被稀释到 1/N"

2. Go：无意中造出的 AI 编程最佳语言

Go 之所以成为 AI 编程时代的赢家，并非因为语法优雅，而是因为：
- 只有一种并发模型：Goroutines（vs threads/callbacks/async-await/colored functions）
- Convention over Configuration 的极致实践
- 长期抵抗"便利性"诱惑（泛型之争），保持了语料一致性
- 标准库覆盖面广，减少第三方依赖的不确定性

3. Rails > Generic JS Backend

在编码 Agent 测试中，Rails 项目产出更一致的代码——不是因为 Ruby 更好，而是因为"本质上只有一个 Rails"。而 JS 后端有十几个生产级框架，功能重叠但写法各异。

4. Convention over Configuration：从人类到机器

DHH 20 年前的洞见在今天更加正确：
- 对人类：灵活性被高估，约束即解放
- 对机器：约束更加重要，模型求解的是"最可能的输出"
- 一致的语料 → 一致的嵌入 → 一致的推理 token

⚡ 借鉴进化点

  1. Agent 技术栈选型策略：选择 LLM 编码 Agent 的技术栈时，优先评估"语料一致性"而非"语言先进性"。Go/Rails/Django > JS全家桶/微服务混乱。这对 Hermes 的 skill authoring 同样适用——用一致的模板和约定，模型输出更可靠。

  2. Skill 文档的 NewType 模式：文章提到的 embedding 一致性原则适用于所有 AI 系统的知识库设计。我们的 SKILL.md 格式标准化本质就是在降低"语料方差"，让模型在 skill 上下文中产生更一致的输出。

  3. Convention over Configuration 的 Agent 时代升级：从框架设计到 Agent harness 设计的映射——给 Agent 更少的选择空间（受限的工具集、明确的 SOP），反而产出更高质量的结果。这验证了 Hermes 的 skill 约束策略的正确性。
