归纳总结

一句话：把"上下文清理的决策权"从工程架构（规则触发）交还给模型本身——用两个工具（MM 记重点、CO 清内存）+ 一个多回合 RL 算法（Multi-episode ARPO），让 Qwen3-8B 在 GAIA 拿到 42.8% 平均准确率的同时，输入 token 消耗比 ReAct 省 6-7 倍。

三层核心洞察：

  1. 认知科学映射：人类解长难题不是记住所有细节，而是"当下内容留脑内、长期内容写草稿"。CORAL 把这个分工搬进 Agent——工作记忆（上下文）只留活跃信息，持久面板（MM 维护）承担草稿功能。
  2. 检查点 = 学习技能而非框架规则：现有 agent 框架的 compaction/摘要全部由阈值或规则触发（Claude Code auto-compact、各类 context compressor）；CORAL 证明"何时清、清什么"可以作为策略被 RL 学出来，且 8B 小模型也学得会。
  3. 省 token 与涨准确率不矛盾：更干净的上文=更好的注意力=更高的准确率，"better attention management is a source of accuracy rather than a cost paid for it"（论文原话）——上下文管理从成本项变成了准确率来源。

内容整理：CORAL 方法与实验全景

1. 问题定义：长程任务的注意力稀释

单链 ReAct agent 在长程任务（GAIA Level 3、BrowseComp）中，上下文持续膨胀：历史工具输出、失败尝试、无关搜索结果全部留在窗口里，稀释了对任务目标的注意力。传统解法是外部工程约束（截断、摘要、检索），但清理时机和保留内容由规则猜，猜错就丢关键信息。

2. CORAL 三件套

组件 全称 机制 论文章节
MM Memory Management Agent 可调用的记忆管理工具，维护持久化记忆面板，写两类信息：task progress（高层计划+各子目标 pending/completed 状态）与 verified facts（已验证事实）。原始 trace 只增不减，面板随之演化 §3.1
CO Context Optimization Agent 判断上下文过长/噪音过多时主动调用（动作即 context reset，清空对话历史）：当前工作记忆作为 observation 返回，下一 episode 初始上下文 = (system prompt, question, memory_state)——只有 MM 检查点存活，工具输出与推理轨迹全弃 §3.1-3.2
Multi-episode ARPO Multi-episode Agentic Reinforced Policy Optimization 多回合 RL 算法：终局成败奖励穿透回合边界反向广播，做跨回合信用分配——让模型在没有额外人工标注的情况下，自主演化出最高效的记忆检查点策略 §3.3

关键设计：CO 的触发"from its own judgment of the task state, rather than triggered by rule-based heuristics or external controllers"（论文原话）——这是与全部现有框架方案的本质分界线。

3. 训练管线（两阶段）

  • SFT：WebShaper 合成问题 → 轨迹生成 → episode 切分（附录 C），教模型 MM/CO 工具的基本用法。GAIA 上 +SFT 即达 41.6% 平均（vs 基线 19.4%）。
  • RL（Multi-episode ARPO）：不需要新轨迹数据，精化检查点策略，把 L3 从 15.6% 拉到 19.8%。

趋势判断

  • 上下文管理权内迁移是 2026 下半年最清晰的工程趋势之一：规则压缩（2024）→ 框架自动 compaction（2025-2026 初）→ 学习式自分配（CORAL，COLM 2026）。CORAL 不是孤立工作，是这条链上目前证据最硬的一环。
  • token 经济学驱动：6-7× 输入节省直接改写长程任务成本模型——GAIA 类任务从"贵到不可商用"到"可规模部署"，这也是腾讯参与工业界信号的合理解读。
  • 小模型自主化叙事增强：8B 学会认知资源分配，说明"元认知技能"（知道自己在何时需要清理）可训练、可泛化（MuSiQue 零训练迁移 43.2%）——与"小模型+好 Harness 打大模型"的既有趋势共振。
  • 风险提示：GAIA L3 19.8% 仍很低，长程任务远未解决；BrowseComp 增益依赖专有强模型的工具跟随能力，弱模型 prompting 版增益未知。

指南分析

对 Hermes/自有 Agent 体系的可执行分层：

  1. P0·零成本抄结构（本周可做）：MM 面板两字段（task progress / verified facts）映射到任务状态文件 schema——现有 checkpoint/进度文件增加"verified facts"显式区块，低成本提升断点恢复质量。
  2. P1·工具化（不训练）：把 context-compressor 的触发从阈值改为"模型可调用工具"——提供 memory_checkpoint() 与 context_reset() 两个工具定义（直接译附录 I.2/I.3 模板），BrowseComp 实验证明纯工具引入对强模型即有 +8 点空间。
  3. P2·训练路线（需 GPU/数据）：episode 切分 + 跨回合奖励广播的 Multi-episode ARPO，仅当自有长程任务（如多轮研究管线）规模化后才值得投入；当前阶段吸收思想不复制训练。
  4. 反模式警示：不要在无 MM 面板的情况下做 CO 式清空——没有检查点的重置=丢任务状态，CORAL 的顺序是先 MM 后 CO，工程上对应"先有进度外置，再做上下文轻装"。
