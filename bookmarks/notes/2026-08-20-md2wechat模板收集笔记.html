一、核心概念（内容整理）

md2wechat 是"面向 AI Agent 的微信公众号创作与发布 CLI"——它真正的价值不在 CLI 本身，而在它把创作流程模板化的四个组件。我们收集的是模板思想，不是工具依赖：

模板组件 位置 核心价值
Brand Profile ~/.config/md2wechat/brand.md 自然语言品牌档案，Agent 每次创作时读取
humanize 四档强度 humanize -i {gentle/medium/aggressive/authentic} AI 去痕的分级处理 + 五维质量评分
确认层工作流 inspect → preview → convert 发布前三步验证，副作用显式化
Layout 决策框架 attention/readability/memorability/conversion 四目标 排版模块按读者目标选用

关键设计哲学（README + DISCOVERY 反复强调）：
1. CLI 不解析 Brand Profile——纯自然语言给 Agent 读，"越具体越好"
2. discovery 优先于记忆——Agent 不猜命令能力，先跑 capabilities --json
3. 副作用显式化——convert 默认不上传不建草稿，--upload/--draft 必须显式
4. ** readiness 分层**——doctor（本地配置）vs inspect（单篇文章）vs blockers（具体阻塞项）

二、技术要点（指南分析）

2.1 Brand Profile 模板（最值得收集）

原文结构（brand init 生成的建议章节）：

## 基本信息
名字/品牌名 + 一句话简介

## 语气与风格（最重要）
我的风格：[正例描述]
我要避免的表达：[反例清单]  ← 反例比正例约束力更强

## 文章开头偏好
verdict_first / story_first / question_first / data_first 四选一 + 示例

## 排版偏好
模块少而准 / CTA 数量 / 金句密度 / TOC 使用条件

## 默认 CTA（行动引导）
标题 + 正文 + 行动

## 作者卡片
名字/头衔/简介

## 风格参考（可选）
粘贴自己喜欢的段落

精妙之处：
- "Markdown 而不是 YAML"——品牌风格本质是语言性的，tone: sharp 不如"我写作像在和朋友聊天，从不用'希望对你有帮助'结尾"
- 反例 > 正例：写出"这种开头我从来不写"，Agent 的还原度更高
- 软约束：数量偏好写成引导而非硬规则，避免过度约束

2.2 humanize 四档强度 + 评分体系

强度 思路 适用
gentle 只动最明显的填充短语 文章已较自然
medium（默认） 平衡去痕 日常 AI 文章
aggressive 深度改写句式，24 种 AI 模式全减 AI 味重
authentic 换思路：六维规则重写，"像真人"而非"不像 AI" 高要求场景

五维评分（authentic 是六维，总分 /50）：直接性 / 节奏 / 信任度 / 真实性 / 精炼度。45+ 优秀，35-44 良好，25-34 一般，<25 重处理。

24 种 AI 痕迹模式识别清单（HUMANIZE.md 列举的典型）：
- 句式工整如翻译腔："不仅……而且……""值得注意的是……"
- 空泛用词：深刻、本质上、具有重要意义、标志着
- 每段都有总结句，读起来像报告
- 连续排比五连六连
- 开头"当然！"结尾"希望这对您有帮助"

2.3 确认层工作流（inspect → preview → convert）

1. inspect --json    → 结构化 metadata + checks + readiness.targets + blockers
2. preview           → 只写成功转换的 HTML，失败不覆盖
3. convert           → 转换 + 仅显式请求的副作用（--upload/--draft）

readiness 语义：doctor = 本地配置可尝试性；inspect = 单篇文章目标状态；blockers = 具体阻塞原因。三者不混用。

advise 命令（推荐引擎）：读已有文章 → 返回最小增强动作集（title/cover/layout/micro_edit），纯推荐不执行——"recommendation-only planner"。

2.4 Layout 四目标决策框架

排版模块按读者目标选，不堆砌：

目标 用途
attention 帮读者决定是否值得读
readability 移动端易读
memorability 让一个判断/金句/数据钉住
conversion 收藏/关注/转发/购买

纪律：至多一个 hero、一个 verdict、一个 CTA；内容撑不起的模块直接跳过。

三、复现验证（归纳总结）

  • 本机未安装 md2wechat CLI（npm 全局包）——本笔记为模板收集，非工具落地
  • 已验证的等价物：humanizer skill v2.0（AI 痕迹黑名单+二次审计）覆盖了 humanize 的 gentle/medium/aggressive 思路，但缺 authentic 六维模式和五维评分
  • Brand Profile 思路与本机 ~/.hermes/config.yaml 的 persona 配置互补——前者是"给 Agent 的创作风格信"，后者是运行时配置

四、可学到的点（归纳总结·续）

  1. 反例比正例约束力更强——"我要避免的表达"清单是 Brand Profile 最有价值的部分
  2. 自然语言配置 > 结构化 schema——语言性内容（风格/语气）用 Markdown 自由书写，Agent 理解力远超 YAML 枚举
  3. "不像 AI" 和 "像真人" 是两个目标——减法（去痕）和重写（authentic）方向不同，后者天花板更高
  4. 评分让润色可量化——五维/50 分制把主观感受变成可追踪指标
  5. 确认层分离副作用——inspect/preview 永远无副作用，发布动作显式触发，这是 Agent 安全工作流的范本
  6. advise = 最小动作推荐——不问"要不要全做"，只推荐"下一步最值得做的一两件事"

五、趋势判断（拓展应用）

  1. Agent-Ready CLI 是趋势：JSON discovery + skills 内嵌 SOP + readiness 分层，让任何 Agent（Claude Code/Hermes/OpenClaw）零猜测接入——本机 lark-cli 就是同款设计
  2. Brand Profile 会成为个人 Agent 标配：跨工具统一的"我是谁/我怎么说话"档案，类似 USER.md 但更聚焦创作风格
  3. 评分驱动的写作迭代：humanize 的 /50 分 + paper-humanizer 的检测率，都是"质量可度量"方向的实践
  4. 本机落地路径：模板并入 note-dual-format / xhs-content-pipeline 等内容生产 skill，不引入 npm 依赖
