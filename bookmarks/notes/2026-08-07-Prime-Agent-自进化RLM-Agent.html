一句话定义

Prime Agent 是一个自进化的 Recursive Language Model (RLM) Agent，专为编码工作流和长时间运行的自主任务设计——通过 Continual Harness 机制让有用的工作上下文和可复用的操作模式存活到单个聊天窗口之后。

内容整理

两大核心抽象

1. Recursive Language Model (RLM)

把上下文当作变量（prompt-as-a-variable），把工具/子 Agent 当作函数调用（programmatic tool/sub-agent calling），运行在持久化的 REPL 中。

  • 一切都是编程式的：持久化 IPython 是内置的模型工具——文件操作、Shell 命令、工具使用、子 Agent、上下文管理都通过代码完成
  • 内置子 Agent：rlm(...) 生成真正的子 Agent 用于并行/后台工作，编程式返回结果
  • Agent 间直接通信：运行中的 Agent 可以互相发现、交换消息、引导工作，不需要经过用户路由

2. Continual Harness

arXiv:2605.09998 — 存储补充提示词、记忆、技能描述、可复用子 Agent 规格作为持久状态，Agent 可以通过小的、有证据支持的更新来精炼它们。

  • Harness 可以自改进：/refine 审查当前轨迹，可以对补充 harness 状态应用小的、有证据支持的更新
  • 永不重写不可变的基础系统提示词
  • 记录快照支持回滚

Prime Agent 把持久化 Python 控制环境与持久 Harness 状态结合——让有用的工作上下文和可复用操作模式存活到单个聊天窗口之后。

关键特性

特性 说明
一切都是编程式的 持久化 IPython = 内置模型工具；所有操作通过代码完成
内置子 Agent rlm(...) 生成真正子 Agent，并行/后台工作
Harness 可改进 /refine 应用有证据的小更新到补充 harness 状态
技能可执行 Skills 是可导入的 Python 包；内置技能创建器把重复工作流变成项目/个人技能
后台运行会话 daemon 支持的 Agent 在终端断开后继续运行，可重新连接
Agent 直接通信 运行中的 Agent 互相交换消息和协调，不经过用户
长任务持续推进 自动压缩、持久目标、心跳、调度、自主模式、保留子 Agent 跨回合/终端会话保存进度

长时任务设计（为研究评测而生）

能力 命令/机制
Continual Harness /refine 持久化聚焦的、可审查的课程（补充提示/记忆/技能描述/子 Agent 规格），带精炼历史记录
Agent 直接通信 运行 Agent + 保留子 Agent 互相发现、交换消息、引导活跃工作
Daemon 持续性 活跃会话、IPython 状态、调度、子 Agent 在终端脱离后继续运行
心跳和调度 /heartbeat、rlm_heartbeat、prime-agent schedule 定期或定时重新进入会话
持久目标 /goal 跨回合保持目标和进度活跃，直到完成/暂停/清除
有界自主模式 /autonomous 在配置的回合/Token/时间预算内继续运行，可运行用户定义的质量门禁

⚠️ 质量门禁通过只检查该门禁验证的内容；达到预算限制不意味着任务成功。

安装与使用

# 安装（macOS / Linux）
curl -fsSL https://app.primeintellect.ai/prime-agent/install.sh | sh

# 启动
cd /path/to/project
prime-agent

# 首次登录选择 provider
/login

CLI 命令

prime-agent agents          # 浏览运行/空闲/保存的会话
prime-agent attach          # 重新连接运行中的会话
prime-agent --resume        # 恢复保存的会话
prime-agent status          # 检查后台服务状态
prime-agent doctor [--fix]  # 检查或修复后台服务
prime-agent update [--force] # 更新
prime-agent shutdown [--force] # 停止所有 Agent/worker/后台服务

安全警告

Prime Agent 以用户权限执行模型生成的 Python 和项目命令。它的 worker 和 kernel 进程改善了生命周期隔离和恢复，但不是安全沙箱。只使用可信的仓库、指令、技能和扩展。不可信代码在外部沙箱中运行。

归纳总结

Prime Agent 是当前"自进化 Agent"方向上架构设计最完整的开源项目之一。两个核心理论支柱（RLM + Continual Harness）直接回应了上一篇笔记的核心论点——验证是自进化的最终瓶颈。

RLM 的价值：把上下文从"聊天历史"提升为"可编程变量"，把工具从"API 调用"提升为"函数调用"——这让 Agent 的操作空间从线性对话变成了图灵完备的编程环境。

Continual Harness 的价值：实现了"提出改动→验证→积累"三步循环的工程化——/refine 只做小的、有证据支持的更新，不碰不可变的基础 prompt，支持快照回滚。这恰好是 SkillOpt validation gate 理念在 Agent harness 层面的应用。

长时任务设计：daemon 后台运行、心跳调度、持久目标、有界自主——这些都是生产级长时 Agent 的必备能力。

4,468 commits（3 个月）说明开发极其活跃，是 RSI 方向最值得关注的工程实践之一。

趋势判断

  • RLM 范式 = Agent 编程语言的演进：从"prompt engineering"到"prompt-as-a-variable + programmatic tool calling"——Agent 不再是聊天框，而是图灵完备的编程环境
  • Continual Harness = 模型外部自进化基础设施：与 SkillOpt 同源——把知识/技能/记忆作为持久状态，通过有证据的小更新实现渐进进化。这正是"下一条 Scaling Law"的方向
  • Agent 直接通信成为标准：子 Agent 互相发现和协调不经过用户——从"1 Agent + N 工具"到"N Agent 组成团队"
  • 长时自主是生产级刚需：daemon 后台、心跳、持久目标、有界自主——这些能力决定了 Agent 能否做"天级别"而非"分钟级别"的任务
  • 安全沙箱 vs 生命周期隔离的区分：Prime Agent 明确指出它的进程隔离"不是安全沙箱"——诚实的工程边界声明

关联分析

  • 与自进化四波浪潮笔记的直接关联：Prime Agent 是 Wave 4（验证瓶颈）的工程实践。/refine + Continual Harness = "提出改动→验证→积累"三步循环。它与 SkillOpt 的区别在于优化粒度——SkillOpt 优化技能文档，Prime Agent 优化整个 Harness 状态（补充提示+记忆+子 Agent 规格）
  • 与 Hermes Agent 的直接关联：Prime Agent 的多个设计理念与 Hermes 相似——持久目标（Hermes 的 active_tasks.json）、后台 daemon（Hermes 的 cron system）、技能系统（Hermes 的 Skill 体系）。但 Prime Agent 的 RLM 编程模型（prompt-as-a-variable + persistent IPython）比 Hermes 的工具调用模型更强大
  • 与 DeepSeek Agent Harness 执行栈的关联：Prime Agent 覆盖了执行栈的第 3 层（Harness Runtime）+ 第 5 层（评测/验收 via /refine 的证据门禁）。Agent 直接通信覆盖了第 2 层（多 Agent 协作）
  • 与 SkillOpt 的关联：同属"模型外部自进化"路线。SkillOpt 优化 skill.md（文本空间），Prime Agent 优化 Continual Harness（结构化状态空间）。两者可以互补——SkillOpt 做技能级优化，Prime Agent 做会话级进化
  • 与用户 FDE 方向的关联：Prime Agent 的长时自主能力（daemon+心跳+持久目标）是 FDE 落地企业 AI 的关键基础设施——让 Agent 能跑"天级别"的部署和集成任务
