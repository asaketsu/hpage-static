零、结论先行

SoL-Pi = 英伟达（韩松团队）用"AI 研究 AI"流水线从 152 个候选机制中筛出的 4 个 harness 效率机制，装在 Pi 底盘上：Token 省 45-64%、成本降 50-54%、得分保留 94%。 四个机制全部是"确定性优化"（删重复、并请求、按需召回、小模型初筛+证据核验），不是提示词技巧——这正是它们能跨任务跨模型迁移的原因。对我们最直接的增量：ObservationPack（输出归档+句柄召回）与 Evidence-Preserving Reducer（小模型初筛+原文核验）——这两个机制正是我们 context 压缩与 golden set 验证思路的工业级同构物，且有可抄的实现细节。

一、问题定义：RSI 的账单

"在让 AI 递归改进自己之前，能不能先让它把自我改进的账单打下来？"

编程智能体任务越变越长（数小时级），平时不起眼的 token 浪费开始累积：改完文件下一步明明是跑测试、模型还要再推理一轮；大文件读过一次后续每轮请求重复携带；几千行日志里影响决策的只有几行、贵模型从头读。RSI（递归自我改进）尤其烧钱：每次试错都付 token 费，失败的方案也照样收费。

实测数字（vs 不同基线）：

基线 Token 成本 得分
底座 Pi -45%~49% ≈-1/3 保留 ~94%
Codex/Claude Code 原配 harness -35%~64% -50%~54% —

研究场景每小时省 $8.75-13.5。安装一行：pi install git:github.com/NVlabs/SoL-Pi。

二、四大机制拆解（核心内容，逐层忠实还原）

机制 1：Action Fusion（动作融合）——省掉中间的模型决策轮

  • 靶点：Pi 轨迹里最常见的序列 = 改文件→收结果→再调模型决策一轮→跑测试/构建——后续命令已经非常明确，中间的"一来一回"纯浪费
  • 做法：把一次编辑+后续命令封装进同一个本地执行序列——harness 底层完成修改、跑命令，合并结果一次性返回。测试照常执行，中间那轮模型请求被省掉
  • 本质：把两次分散请求合并为一次高效闭环（这就是我们在 Google 流式语音笔记看到的"并行/合并"思想在工具调用层的投影）

机制 2：Online Context Compact（在线上下文压缩）——按子任务动态核算

  • 靶点：何时触发压缩。压缩本身有代价——重写上下文打断 KV-cache 复用、重新支付处理成本；过早压缩未必省钱，传统策略只好尽量推迟
  • 做法：大任务拆子任务，每完成一步重新评估；只有"未来预计省下的开销"≥"本次重写的成本"才执行压缩
  • 本质：压缩决策从启发式（阈值/推迟）变成投资回收计算——这是经济学口径的上下文管理

机制 3：ObservationPack（输出归档与索引）——大块文件按需召回

  • 靶点：大文件/超长工具输出首次读入后滞留上下文，后续每轮请求原样携带、持续重复计费
  • 做法：完整内容归档本地磁盘，上下文只留稳定短句柄+一小段摘录；模型需要细节时按索引分页取回
  • 本质："读完长报告把原件存档，手边只留索引和关键摘要"——与我们 web_extract 的 head+tail 截断+全文本地存盘、context-compressor skill 是同构设计，但 SoL-Pi 的"稳定句柄+分页召回"更工程化

机制 4：Evidence-Preserving Reducer（证据保留归约器）——小模型初筛+严格核验

  • 靶点：构建/测试日志动辄上万字，影响决策的只有几行报错；前沿大模型每次通读成本极高，直接给小模型总结又容易引入幻觉
  • 做法：长日志第一遍阅读委派给低成本模型，输出紧凑诊断回执；系统拿回执逐条与归档原始日志比对，只有严丝合缝对得上的原文才放行给前沿大模型
  • 本质："主模型只接收被证实的信息，从源头切断误差传导"——这是 No Free Checker/验证簇思想的落地形态：摘要必须可对照原文核验，否则不放行

三、152 选 4：AI 研究 AI 的流水线（RSI 方法学）

"先别急着让 AI 更聪明，先让它更省钱。"

为什么选 token 效率不选分数：刷任务分数容易过拟合（给特定题写规则就行）；但删重复上下文、压缩输出、合并无效决策能迁移到不同任务和模型——效率指标难作弊。

流水线五步：

535 个可验证环境（人工构建）
   ↓
AI 提出 152 个优化方向
   ↓ 三轮筛选
① 历史轨迹估算收益 → 无潜力淘汰
② AI 自己改代码跑实验 + Reviewer Agent 挑刺
③ 冻结方案 → held-out 完全隔离任务验真（能力不能掉，效率必须涨）
   ↓
**152 → 4（约 40:1 存活率）**

伏笔 内容

效率复利（Efficiency for efficiency） 用变省的 harness 跑规模更大成本更低的自动研究循环，找出更高效的机制——成本压缩的复利效应

六、批判性审视

  1. "得分保留 94%"的另一面：6% 的能力损失在编码基准上无感，在边界任务上可能有感——降本数字亮眼时质量条款要细看（哪些 benchmark 掉了 6%？）
  2. 535 环境人工构建：团队自己承认是当前局限（闭环预训练伏笔）——152→4 的筛选结论受限于环境分布；环境偏编码/agent 任务，外推到分析/创作类 harness 需谨慎
  3. Pi 底盘的可迁移性：四机制装在 Pi 上（极简 harness）；Claude Code/Codex 的原配 harness 有自己的缓存与压缩策略——"vs Codex 省 50-54%"的对照是否给了对方同等优化机会（Minara 笔记的滤网 2 同款问题）
  4. 新智元报道的转述层：数字全部来自项目页/论文，未独立验证；"每小时省 $8.75-13.5"的换算口径（什么任务密度？什么单价？）未给
  5. 韩松团队背书是真的，但"开源"范围：代码 MIT 开源了，但 535 环境与评测管线是否全开源待查——RSI 流水线的复现门槛可能远高于四个机制的使用门槛
