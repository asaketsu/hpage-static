# 100 万暴露 AI 服务：大规模安全扫描揭示基础设施盲区

> **来源**：The Hacker News · 2026-05-05
> **原文**：https://thehackernews.com/2026/05/we-scanned-1-million-exposed-ai.html
> **笔记ID**：sniff-20260601-exposed-ai
> **格式**：双格式(MD + HTML) · 含借鉴进化点 · RAG/wiki联动

## 摘要

安全研究者通过证书透明度日志扫描了 200 万+ 主机，发现约 100 万个暴露在公网的 AI 服务。其中约三分之一的 Ollama 实例没有任何密码保护。大量开源 LLM 前端和自托管 AI 基础设施使用宽松默认配置，缺乏认证和安全控制。DeepSeek 曾因暴露 ClickHouse 数据库引发重大安全事件。这是 AI 基础设施安全的一次系统性健康检查，揭示了从开发到生产的"安全债务"。

## 核心内容

### 扫描规模与发现

- 扫描对象：通过证书透明度日志发现 200 万+ 主机
- 暴露 AI 服务：约 100 万个（约 50% 的主机）
- Ollama 无密码：约 33% 的 Ollama 实例无认证
- 主要风险：配置错误、暴露端点、数据泄露

### 根本原因

1. **开源默认宽松**：Ollama、Open WebUI 等自托管工具默认无需认证，需手动配置
2. **快速部署压倒安全**：企业急于上线 AI 功能，安全配置被跳过
3. **缺乏 AI 安全标准**：传统 Web 安全（OWASP）未覆盖 LLM 推理端点
4. **影子 AI**：50-80% 员工使用未经授权的 AI 工具，安全团队看不到

### 重大事件

- **DeepSeek ClickHouse 暴露**：初创公司 DeepSeek 暴露了 ClickHouse 数据库
- **Claude Code 攻击墨西哥政府**：攻击者利用 Claude Code + GPT-4.1 入侵 9 个墨西哥政府机构，窃取 1.95 亿条记录
- **OpenAI Codex Security**：OpenAI 推出 Codex Security 研究预览版

## 关键概念

- **证书透明度日志（Certificate Transparency Logs）**：SSL/TLS 证书的公开审计日志，可用于发现暴露服务
- **Ollama**：流行的本地 LLM 运行工具，默认配置无认证
- **影子 AI（Shadow AI）**：员工未经 IT 部门批准使用的 AI 工具
- **LLM 推理端点**：大语言模型的 API 服务端口，传统安全工具不监控

## 能力边界

- 扫描仅覆盖使用 TLS 证书的服务，未覆盖纯 HTTP 暴露的 AI 服务
- 实际数字可能更高（有大量内网暴露未被统计）
- 未涉及商业 AI 服务（OpenAI/Anthropic API）的安全评估
- 扫描方法论未公开完整细节，可能存在统计偏差

## 最佳实践

1. 对所有自托管 AI 端点实施认证和访问控制
2. 将 LLM 推理端点纳入安全监控范围
3. 建立 AI 资产清单（AI Asset Inventory）
4. 对话日志和 Agent 接口视为敏感数据
5. 使用 VPN/零信任而非直接暴露 AI 服务到公网
