Agent 公司的终局：两种活法，其余一文不值

来源: 微信公众号 - 产品经理群
日期: 2026-08-01
标签: Agent 商业化 FDE SaaS 护城河 大模型 创业

核心结论

未来一两年，大部分 Agent 公司都将一文不值。

原因：模型每进一步，二次开发难度下降一层，Agent 公司封装的脚手架价值就萎缩一块。而大模型公司正在把 Agent 公司验证过的场景做成产品，进一步挤压市场空间。

但有两类公司大模型公司很难直接替代——它们是 Agent 创业的幸存者。

一、为什么大部分 Agent 公司将一文不值？

三个致命趋势

趋势 证据
模型变强，工程化废掉 某写作类 Agent 产品 2024 年做了大量工程化弥补模型缺陷，随模型进步全部废弃，已放弃原产品
头部客户开始自研 某年化数千万收入、续费率可观的 Agent 公司，头部客户开始放弃续费转自研
大模型公司直接做产品 Anthropic 发布 Claude Design → Figma 当日下跌 7.7%；OpenAI 发布 Presence（客服 Agent）→ 75% 来电无需人工

被淘汰的逻辑

Agent 公司最大的价值 = 把提示词、工作流编排等脚手架封装，减少客户二次开发。

模型每进一步：
- 二次开发难度 ↓ → 脚手架价值 ↓
- 大模型公司做成品 → Agent 公司市场 ↓

二、两种幸存者

幸存者 ①：把脏活累活做深的交付型公司

维度 说明
核心壁垒 不是"那层脚手架"，而是高效落地的能力
为什么大模型公司不做？ 与管理文化、盈利模型不匹配。脏活累活 = 重交付定制
OpenAI 的困境 Presence 不支持自助部署 → 专门成立实施公司 → 但企业 Agent 部署需高度定制
客户祛魅 去年客户要求不多，今年要求越来越多（深度集成等）
马化腾的判断 "重交付模式效率低、不透明，我们做被集成"——腾讯退出重交付定制

关键角色：FDE（Forward Deployed Engineer）

企业也可以自建 FDE 团队，但大多数企业 IT 团队是业务辅助部门，留不住高水平 FDE。

例子：华为在决定自研 ERP 之前，也没有长期维持一支高水平的 ERP 团队（Oracle 长期提供现场支持）。

幸存者 ②：从 SaaS 平台里长出来的 Agent

维度 说明
核心壁垒 大模型没有客户几十年积累的业务规则、历史数据和异常处理记录
业务上下文 指标口径、业务规则、系统权限——沉淀在 SaaS 系统里，不在大模型里
Snowflake 案例 SaaS 股价普跌 30%+（SAP/Salesforce），Snowflake 创 4 年新高
Cortex Code 不是独立 AI 编程工具，而是长在 Snowflake 数据管理 SaaS 上的编程工具
为什么赢？ 天生理解业务上下文：知道哪些字段需脱敏、数据口径怎么算、谁有权限

AI 越强，企业的业务上下文越重要。

三、护城河对比

维度 被淘汰型 交付型（FDE） SaaS 型
壁垒 脚手架封装 落地交付能力 业务上下文
被替代风险 极高（模型进步即废） 低（大模型公司不愿做脏活） 低（业务数据不在模型里）
代表 写作/客服 Agent 壳 OpenAI 实施公司 Snowflake Cortex Code
客户粘性 差 中（交付深度绑定） 高（数据+权限锁定）

四、关键信号

事件 信号
Claude Design 发布 → Figma -7.7% 投资人认真评估大模型绕过软件公司
OpenAI Presence → 75% 来电自动解决 大模型公司直接切 Agent 场景
Snowflake 营收 +30%、利润 +70% SaaS + AI > 独立 AI 工具
SAP/Salesforce 股价 -30% 纯 SaaS 不够，必须长出 Agent
腾讯退出重交付 "做被集成"，不做定制项目

五、一句话总结

Agent 公司只剩两种活法：把交付做深（FDE），或从 SaaS 里长出 Agent（业务上下文）。其余将一文不值。
