〇、定锚：我的现状与目标

科研与工程研究的瓶颈往往不是单点推理，而是检索、证据整理、代码实验、结果解释、写作与版本留痕之间不断断裂的上下文。现有 Hermes 工作流已具备检索、笔记、代码和验证能力，但必须继续压缩“手工搬运”环节，同时防止 AI 把看似完整的输出伪装成可信结论。

本篇的判断标尺不是“AI 能否替代科研人员”，而是：哪些环节可安全自动化，哪些必须由人承担最终科学责任，以及如何把自动化结果变成可复核资产。

一、内容整理：推文的六项能力与三项人类责任

1.1 推文的中心判断

作者提出：依赖人工逐篇检索、手抄数据、从零写分析脚本、反复制图排版的“古法科研”正接近淘汰；变化的对象是低价值机械流程，不是科研人员本身。这个判断是工作流层面的，不等于湿实验、科学判断或责任归属已被自动化。

“未来真正值钱的，不是你能不能熬夜把每一步都手搓完，而是你能不能提出好问题、设计好验证，并且第一时间发现 AI 什么时候在胡说。”

1.2 AI 已可承担的六类工作〔观点，2026〕

  1. 找课题：从文献中的结论分歧、性能矛盾、机制空白中提出候选问题，并初步评估可行性。
  2. 读文献：提取实验条件、逐图解释、横向比较证据与局限。
  3. 做综述：组织共识、争议与研究空白，而非摘要拼贴。
  4. 辅助实验：拆分技术路线、补全对照组、维护变量与失败记录；计算研究可直接编程和执行实验。
  5. 处理数据与论文：清洗、统计、绘图、逻辑检查、引用核对、模拟审稿与格式整理。
  6. 管理课题：把文献笔记、实验记录、研究想法与产物回写到可检索知识库。

1.3 不应外包的三项责任〔观点，2026〕

  • 判断问题是否值得做：价值函数、资源取舍与领域方向不能由模型默认偏好决定。
  • 解释异常数据：模型能列举原因，却未必理解仪器、样本、工艺或物理机制的真实边界。
  • 对最终结论负责：AI 不能承担科研诚信、实验安全和论证责任。

二、查询拓展：三项主张的原始证据与限定

2.1 The AI Scientist〔支持，2026〕

Nature 论文《Towards end-to-end automation of AI research》描述的系统覆盖创意生成、文献检索、实验规划与实现、结果分析、论文写作和自动审稿，聚焦机器学习研究，因为其主要实验可在计算环境中完成。推文对能力范围的转述基本吻合。

但限定同样关键：该系统不是“任何学科的自主科学家”。其端到端优势来自可计算实验、预设代码模板或可执行环境；湿实验、复杂仪器和开放世界数据仍需要人类与实验系统共同闭环。

  • 一手来源：Nature，DOI 页面 s41586-026-10265-5。
  • 核验结论：支持推文对 ML 研究自动化能力的描述；反对将其泛化为全学科自主科研。

2.2 Google DeepMind Co-Scientist〔支持，2026〕

DeepMind 于 2026-05-19 发布的 Co-Scientist 是 Gemini 驱动的异步多 Agent 系统：Generation Agent 产生假设，Proximity Agent 聚类保持多样性，后续角色对假设进行批评、排序和迭代。Nature 论文明确强调其默认约束包括合理性、新颖性、可测试性和安全性。

其关键启发不在“多 Agent 数量”，而在于把科研假设转化成一个可竞争、可批评、可分配算力的对象；这比单一聊天窗口的线性问答更接近科学论证。

  • 一手来源：Google DeepMind《Co-Scientist: A multi-agent AI partner to accelerate research》与 Nature 论文 s41586-026-10644-y。
  • 核验结论：支持“生成—辩论—迭代假设”的表述。

2.3 Claude Science〔支持，2026〕

Anthropic 的 Claude Science 将文献、多步研究、代码生成、图表与手稿迭代放进同一研究环境，并强调每项输出保留可审计历史。推文的“文献、数据、代码、算力、图片和手稿接进同一个工作台”是合理概括。

真正值得吸收的是“审计轨迹”而非界面整合本身：每个图、表和结论都应能回到数据、代码、提示词、运行配置与人工确认点。

  • 一手来源：Anthropic《Claude Science, an AI workbench for scientists》。
  • 核验结论：支持；“完整科研工作台”应理解为基础设施目标，不应误读为自动保证科研正确性。

三、归纳总结：科研 Agent 的正确分层

3.1 从“工具替人”转向“证据链编排”

推文的正确方向是消灭机械步骤，但容易被误读成“交给 Agent 就完成科研”。更可靠的架构应是四层分工：

  1. 证据层：原始论文、数据、实验日志、仪器/仿真输出；禁止用二手总结替代。
  2. 执行层：检索、数据处理、代码运行、图表和文稿草拟；每次运行留下版本与输入。
  3. 审查层：独立 Agent 或规则检查引用、数字、对照组、统计前提和结果可复现性。
  4. 责任层：研究者判断问题价值、异常原因、外推边界与最终发布。

3.2 三维护筛

  • 优点：将检索、整理、分析与写作串联，能显著降低上下文切换和机械劳动；Co-Scientist 证明“生成—反思—排序”比单轮生成更适合假设空间搜索。
  • 缺点：端到端展示容易掩盖输入数据质量、工具调用失败、代码错误与统计误用；自动审稿只是一种质量信号，不是科学真值。
  • 借鉴点：把“模型给出答案”升级为“模型产生可追溯候选，独立验证器检查候选，研究者签署结论”。

四、趋势判断

4.1 2026—2027：科研竞争将从模型能力转向研究操作系统

2026 年的 The AI Scientist、Co-Scientist 与 Claude Science 分别覆盖端到端计算研究、多 Agent 假设搜索和可审计工作台。共同方向说明竞争重点正从“更会回答”转到“能否管理证据、工具、算力和回写链路”。机会在于构建领域专用研究 OS；风险在于把漂亮工作流当成正确结论。

4.2 多 Agent 会分化为“有裁判”和“无裁判”两类

Co-Scientist 的生成、辩论、排名和可测试性约束表明，多 Agent 的有效性依赖明确评价函数。没有独立证据、可量化门槛和失败回退的“互相辩论”，只是更昂贵的文本循环。

4.3 人类价值向研究设计与反证能力上移

从 2024—2025 年的通用聊天/代码助手，到 2026 年的研究系统，自动化覆盖面已扩大；但真正稀缺的能力仍是提出可证伪问题、设计对照、识别异常和界定结论外推范围。研究者应把时间从排版与复制粘贴，迁移到这些高杠杆环节。

五、关联分析

5.1 与既有多 Agent 笔记的关系

本文与 Agent 协作与自我进化：双轮驱动的深度探索 互补：旧笔记讨论通用 MCP/A2A 与协作模式；本文以科研为具体场景，补上“证据链、实验可复现性、科学责任”三条硬约束。

5.2 与 Hermes 的实际工作流

Hermes 已具备研究检索、技能化流程、文件落盘和工具验证能力。可直接对齐的不是模仿大型平台，而是补齐每次研究任务的最小证据包：原始来源、提取内容、分析代码/参数、核验结果、人工结论与未决风险。

5.3 与飞机设计与工程研究的边界

在飞机设计、适航和工程试验语境，AI 可优先用于规范检索、需求追溯、试验数据清洗、方案对比和文档一致性检查；但合规解释、构型基线、失效机理和签署责任必须由具备授权的工程师掌握。计算研究的成功不能直接外推为安全关键工程的自动放行。

七、行动启示与回访

我的结论：保留 AI 承担检索、整理、代码与初稿等可验证劳动；放弃 将单次模型输出当作研究结论；改造现有研究任务，使每项核心主张都带有来源、版本、验证与责任人。

  • 行动 1：后续研究型笔记使用“主张—一手证据—限定—可执行动作”四段式。触发条件：出现论文、技术白皮书或可量化主张。验收标准：核心数字/能力均能回链一手来源，未核验项显式标记。
  • 行动 2：对复杂分析启用“生成者—核验者—归档者”三角色最小闭环。触发条件：任务涉及多源资料、代码或关键决策。验收标准：归档内同时有原始输入、结果、验证记录和失败/不确定性说明。

  • [ ] 行动 3：对安全关键工程研究，将“人类签署点”写入任务模板。触发条件：涉及适航、试验、真实硬件或对外结论。验收标准：AI 不绕过责任人和人工复核门。

  • 回访日期：2026-12-08。

  • 待验证假设/证伪条件：若新增自动化流程不能减少重复劳动，或其核验成本高于节省的时间，则应缩小自动化范围，而不是继续堆叠 Agent。

八、拓展应用推荐

  • 学术综述：用 Agent 建立“论点—证据—反例—缺口”索引，再由研究者裁定叙事主线。
  • 工程试验：用 Agent 汇总参数、日志和失败记录；用规则锁住单位、版本、阈值与签署节点。
  • 企业知识库：把项目会议、规范、仿真与决策记录接入可追溯链，避免只沉淀聊天摘要。

九、指南分析

这条推文最有价值的结构是“六件可交付工作 + 三件不可转交责任”：它避免把 AI 讨论落进抽象的替代论。要让这个结构可复用，必须额外加上证据来源、适用边界和验证门；没有这三项，“AI 科研工作流”会退化成无法审计的自动写作流水线。
