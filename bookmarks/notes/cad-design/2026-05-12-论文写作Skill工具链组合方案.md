## 摘要

文章推荐了 5 个外部 Claude Skill 仓库，按"题目—正文—交付"三个节点组合，覆盖论文写作全流程。核心思路是**用少量 Skill 组合覆盖大多数投稿场景**，而非每个环节都单独开发。

## 核心内容

### 工具链全景图

| 环节 | Skill | 仓库 | 星级 | 功能 |
|------|-------|------|------|------|
| 立项/开题 | research-proposal | luwill/research-skills | 426★ | Nature Reviews 风格模板，40+ 参考文献占坑 |
| 架构规划 | strategist | lishix520/academic-paper-skills | 172★ | 拆出 7 个评审节点，提示证据缺口 |
| 正文骨架 | composer | academic-paper-skills | - | 出论文骨架 |
| 正文润色 | scientific-writer | K-Dense-AI/claude-scientific-writer | 1.7万★ | 润色 + 术语统一 |
| 数据统计 | statistical-analysis | K-Dense-AI/claude-scientific-skills | - | pandas + statsmodels 工作流 |
| 排版交付 | docx/pptx/pdf/latex | 官方 + ndpvt-web/latex-document | - | Word/PPTX/PDF/LaTeX全覆盖 |
| 文献检索 | research-superpower | kthorn/research-superpower | - | PubMed/Semantic Scholar批量拉文献 |

### 两个高频 Workflow

**Workflow A：开题 + 文献综述**
1. research-proposal 填题目/语种/字数 → 输出 0.9 版开题稿
2. research-superpower 批量拉 PubMed/Semantic Scholar 文献
3. strategist 拆章节、标注证据缺口
4. 把 SUMMARY.md + 引文 JSON 扔给 composer → 可读草稿

**Workflow B：写作 + 交付**
1. composer 产出 Markdown
2. scientific-writer 润色 + 术语统一
3. docx skill 导出 Word 终稿
4. pdf skill 合并/压缩
5. paper-slide-deck 或 claude-office-skills 提取 PPTX
6. 官方 pptx skill 精修版式

### 安装注意事项

- K-Dense 技能包：`npx skills add https://github.com/K-Dense-AI/claude-scientific-skills --skill scientific-writing`
- LaTeX Document Skill：无 skills/ 文件夹，需保留整个仓库，运行 setup.sh + scripts/compile_latex.sh

## 🔍 借鉴点

- **端到端工作流编排** — 现有 paper-humanizer 只管文本处理，office-pipeline 只管多格式输出，缺少从立项→答辩的完整编排层
- **证据缺口标注** — strategist 的"7 个评审节点 + 证据位提示"思路值得吸收，可在 paper-humanizer 中增加"证据完整性检查"环节
- **双轨输出** — composer + scientific-writer 的分工模式（骨架→润色）可借鉴到 paper-humanizer 的 Step 4（长难句拆分）
- **文献链整合** — research-superpower 批量拉文献 → composer 的链路，可考虑在 scholar-assist 中增强

## 💡 启发

- 文章推荐的 5 个 Skill 中，**大部分是 Claude 生态的第三方 Skill**，而非 Hermes 体系。这说明 Claude 的 Skill 生态在学术写作领域已经比 Hermes 更成熟
- Hermes 的 paper-humanizer 在**文本处理深度**上更强（10步流水线、Burstiness、Semantic Chaining、Hedging 表格），但在**工具链广度**上落后
- 差距不在"能力"而在"生态" — Claude 有 1.7 万★ 的 scientific-writer，Hermes 需要自建或集成
- 建议：在 paper-humanizer 的 SKILL.md 中增加"外部工具链集成"章节，明确哪些环节可调用外部 Claude Skill

## 🔮 预判

- 学术写作 Skill 生态会继续向"编排层"演进 — 从单一工具到工作流组合
- Claude 生态的学术 Skill 会持续领先，Hermes 需要主动集成而非重复造轮子
- 证据管理（strategist 的证据缺口标注）是未来学术 AI 的核心需求，Turnitin 类工具会升级到"论证完整性检测"
