领域大模型 LoRA 到 vLLM 生产部署链

主题：领域大模型微调（CPT+SFT+LoRA/QLoRA）到生产推理部署（vLLM）的完整技术链路梳理。为 domain-llm-training 项目（2026-09-17 新建）补齐 04 评估→06 合并→07 量化→部署段的方法论依据。

生成日期 2026-09-18

内容整理

1. 全量微调的三堵墙与 LoRA 的数学根基

全量微调 7B 模型的显存账本：FP16 权重 14GB + 梯度 14GB + AdamW 优化器状态 28GB = 训练态 56GB 起；70B 模型至少 560GB（8×A100 80GB）。三堵墙：显存墙、存储墙（10 个下游任务 × 140GB = 1.4TB）、持续学习墙（小数据集全量微调常产出"退化版"而非"增强版"）。

LoRA 的理论支点不是拍脑袋：Aghajanyan et al. 2021 实测 RoBERTa-Large（355M 参数）的内在维度（intrinsic dimensionality）仅约 200——只调 200 个自由度即可达到全量微调 90% 以上性能。LoRA 公式 W = W0 + B@A，以 LLaMA-7B 注意力层为例（d=k=4096）：全量 16,777,216 参数 → LoRA r=16 时 131,072 参数，压缩 128 倍。

2. 三超参数实战配比（2026 共识）

超参数 推荐范围 实战建议
rank r 8-64 简单任务（格式/风格）r=8-16；领域知识/多步推理 r=32-64；r=128-256 须盯过拟合
alpha 16-128 惯例 alpha=2r（r=16→alpha=32）保持有效学习率稳定
target_modules q,k,v,o 或全部线性层 资源允许时注入 gate/up/down_proj 全线性层，代价是可训练参数翻倍但质量增益明显
学习率 1e-4~3e-4 比全量微调高 5-10 倍
dropout 0-0.1 小数据集用 0.05-0.1

3. QLoRA 三件套：NF4 + 双重量化 + 分页优化器

  • NF4（NormalFloat4）：按 N(0,1) 的 16 个等概率分位点量化，而非均匀 INT4 网格。原理是预训练权重近似零均值正态分布，等概率分桶使每桶权重数近似相等。实测量化误差比 INT4/FP4 低 10-30%。
  • 双重量化：每 64 个权重共享一个 FP32 量化常数，本身占 0.5 bit/参数开销；对常数再量化到 FP8 后降至 0.127 bit/参数，65B 模型省约 3GB。
  • 分页优化器：借用 NVIDIA Unified Memory，显存峰值时把优化器状态临时迁到 CPU。防 OOM，代价是轻微降速。
  • NeurIPS 2023 Oral 结论：QLoRA 微调与全精度全量微调无统计显著差异——即 1/4 显存换几乎等价质量。

4. 部署期 LoRA 两种服务策略（关键分叉点）

方案 A：合并部署（merge and deploy）——A×B 永久写回基座权重，单文件、零推理开销、服务与普通模型完全一致。适合单一用途模型。代价：失去换 adapter 的灵活性。

方案 B：热切换 adapter（vLLM 原生支持）——基座常驻显存（7B≈14GB），adapter 按请求动态加载（单文件 50-200MB）：

llm = LLM(model="meta-llama/Meta-Llama-3-8B-Instruct",
          enable_lora=True, max_lora_rank=64)
outputs = llm.generate(prompts, lora_request=LoRARequest(
    "customer_support_adapter", 1, "path/to/adapter"))

一个基座同时服务客服/代码/法务多个微调变体，规模化场景的显存/成本收益显著。代价：adapter 切换有轻微延迟开销 + 服务逻辑复杂化。

5. 推理量化格式选型

场景 推荐 理由
本地/CPU（Jetson 等） GGUF + llama.cpp 生态最成熟
生产 GPU 重质量 AWQ 4-bit 4-bit 中质量最佳
生产 GPU 重速度 GPTQ 或 AWQ 吞吐优先
质量至上不计成本 fp16 不量化 基线

vLLM 论坛实践补充：4-bit 微调模型可不合并直接部署——bitsandbytes QLoRA 路径（基座量化加载 + adapter 热挂），或 GPTQ+LoRA 走 vLLM 标准 LoRA API 动态选 adapter。

6. 安全发布：影子部署

新模型与旧模型并行跑真实流量：用户响应仍由旧模型出，新模型静默处理同一请求但输出只记日志对比。确认无回归后再切流。配合对基座模型的回归测试（防止领域微调把通用能力改坏）。

7. 关联补充：CPT 与 LoRA 的正交关系（2026-09-18）

千问分享会话「CPT训练：领域知识内化与任务对齐」的完整增补（概念正交对照 / LoRA vs 全参效果差距实证 / 选型决策框架 / domain-llm-training 项目校准）已按主题归档至 CPT继续预训练完整方法论 的 1.11 节——CPT 主题内容归 CPT 笔记。此处仅留要点：CPT 是"训练目标"、LoRA 是"参数更新方式"，两者正交可组合（LoRA-CPT 约达全参 80%-90%）；新知识注入场景 LoRA 落后全参 10%+，但通用能力保持反超。

查询拓展

  • QLoRA 训练后直接以 4-bit 服务（不反量化、不合并）的精度损失量化数据——论坛有案例但缺系统 benchmark
  • Unsloth 在 2026 版的 r>64 场景加速比是否仍保持 2-5x（meta-intelligence 指南未更新此点）
  • vLLM LoRARequest 多 adapter 并发时的 KV cache 隔离行为
  • GGUF 量化档位（Q4_K_M vs Q5_K_M）在领域术语密集语料上的召回差异

归纳总结

  1. LoRA 已是 2024-2026 事实标准：内存效率×多任务灵活性×微调质量三者平衡最优，"能不能做"的问题已死，剩下"怎么做得最有效"。
  2. 训练期量化（QLoRA）与推理期量化（AWQ/GPTQ/GGUF）是两套独立决策，不必绑定：QLoRA 训练后可合并回 fp16 再做推理量化。
  3. 部署分叉点 = 用途数量：单用途合并部署（零开销），多用途热切换（vLLM enable_lora）。domain-llm-training 项目当前是单领域单用途 → 合并部署是默认正解，热切换留作多领域扩展路径。
  4. 评估先行原则（Evaluation-First）：先建评估集再训练，微调后必须对基座做回归测试——领域能力↑与通用能力↓的平衡需要数据说话。
  5. 70B 级全量微调 560GB 的账本再次确认：个人/小团队走 QLoRA（16-24GB 单卡）是唯一现实路径。

趋势判断

  • LoRA 家族在 2026 的地位进一步固化，行业讨论重心已从"原理"转向"评估工作流+服务编排"——系统化评估能力成为 AI 工程团队的核心竞争力。
  • 热切换 adapter 服务（单基座多 adapter）随企业多场景微调需求增长，正在成为 vLLM/TGI 的标配能力；adapter 50-200MB vs 全模型 14GB 的存储经济学会重塑多租户推理架构。
  • 影子部署/金丝雀这类经典 SRE 手法与 LLM 评估结合（silent comparison + 自动回归打分）是生产化的下一个标配环节。
