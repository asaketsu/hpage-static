零、结论先行

核心事实：同一模型（DeepSeek V4 Flash）在四个 harness 下 BrowseComp Pass@1 从 10.5%（Claude Code）到 68.5%（OpenClaw）——58 个百分点的差距完全来自 harness 而非模型。 这是"模型排行榜不测量 harness"论的最强数字证据。但本文同时是自家产品发布的自评基准（Minara Harness 09-09 上线，次日发对比），需要六道滤网拆开读：哪些数字可信、哪些是营销结构、哪些方法学问题被自己点名了。

1.3 每基准用自己的指标，拒绝平均

"These metrics are not interchangeable, so we do not average them into an overall score."

好方法学（对比常见"总分第一"营销），但也要注意：不平均 = 无法回答"综合哪个好"——各有取舍。

三、Minara Harness 产品拆解（官网发布文交叉）

3.1 架构定位

金融垂直 harness：研究→回测→执行的同一工作区。通用能力（编码/浏览器/桌面/文档）+ 金融能力（市场数据/组合上下文）内嵌。

3.2 五个值得抄的设计（与我们的对照）

Minara 设计 我们已有的对应
Roundtable 多 agent 研究庭（成长论 vs 盈利质量辩论 + manager 裁决；失败研究保持可见） delegate_task 编排；"失败保持可见"我们没有——失败子任务直接丢弃
Data Studio 版本化（成功构建保留版本，失败修订不覆盖上次可用预览） 笔记幂等管线部分实现；代码层没有"失败不覆盖"惯例
"研究不授权交易"（Institution Mode 研究与执行强制分离，建议≠授权） agent-trading-safety skill 同原则——外部产品级印证
纸面部署先行（backtest 描述历史，不预测未来；paper → live 分离授权） walk-forward-validation + dry-run 铁律同构
Role Memory 默认 shadow mode（评估合格案例但不注入决策；晋升过评估门） "学习机制必须过评估门才晋升"——与我们 golden set 门禁同构，且他们默认不注入（更保守）

3.3 金融安全栈

Token 身份核验/仓位大小/敞口与滑点限制/交易上限/紧急停止——工具调用与控制决策留审计记录；自主运行需单独授权。

# 滤网 本文表现
1 谁是出题人 FinReportBench 自家——领先 9.6 分需打折；但 BrowseComp（OpenAI 系）/AgentDojo/SkillsBench 是第三方
2 是否给对手同等调优机会 未说明——各 harness 用默认配置还是有调优？这是最大黑洞
3 成本-延迟是否同报 ✅ 好样本：主动报自己"最贵 $0.2151"，且指出 OpenClaw 更便宜
4 样本与口径透明度 ⚠️ BrowseComp 用 200/1266 题样本；自己点名"两个 Hermes 数值保留原报告、分母待澄清"——罕见诚实
5 负结果是否公布 ✅ DeepSeek/Qwen 上被 OpenClaw 反超直接写出来（"Rankings reverse"一节）
6 指标不可比时如何汇总 ✅ 拒绝平均成总分——方法学加分

综合评级：营销结构与诚实方法学并存的自评基准里属于上游——负结果公布（滤网 5）与口径自我暴露（滤网 4）是两个诚实信号；出题人利益（滤网 1）与调优机会不明（滤网 2）是两个折扣项。可信度排序：BrowseComp 排名反转 > Spreadsheet 分差 > FinReportBench 领先幅度。

五、与我们体系的对接点

5.1 Hermes 被测的三个数据点（外部镜子）

基准 Hermes 数字 含义
FinReportBench DeepSeek 下落后 Minara 9.6 分；Qwen 下落后 7.6 分 金融报告类任务是我们弱项——符合预期（无金融专用工具链）
BrowseComp GPT 下 57.5%（第二，差 Minara 9 分） 搜索型任务我们其实不弱
SpreadsheetBench 2 DeepSeek 下 7.08%（垫底，分差 14.73 的低端） 电子表格是最痛的洞——与我们 xlsx 技能族的存在形成对照：有技能但 harness 层集成弱
Harness-Bench（第三方） 71.2 分（NanoBot 76.2 / Codex 80.4 之下） 独立口径下的中游位置

行动启发：SpreadsheetBench 的洞值得在周五 skill 审计里对 xlsx/xlsx-generator/officecli 做一次"为什么有技能没分数"的排查——嫌疑：结构化输出与公式验证链，不是技能有无。

5.2 "配对即性能单位"对我们选型的校准

我们的模型切换（model-switch）/fallback 链实践已隐含此认知（同模型不同网关表现不同），本文给出量化依据：选型必须报"模型×harness×基准"三元组，单独任何一项都误导。周论文候选增补：与《自进化 Harness》笔记的三种写连成"harness 时代"双篇。

5.3 金融 harness 的对照价值

Minara 的金融安全栈与我们 agent-trading-safety / quant 体系互为印证：研究执行分离、纸面先行、审计记录、默认不注入的学习——产品级的 agent-trading-safety 实现样本（我们的 skill 是原则宣言，他们给了工程结构）。

六、批判性审视

  1. FinReportBench 的循环性：自家基准上领先且该基准奖励"金融报告逻辑在 harness 里"——这正是 Minara 的卖点。结论方向可信（垂直 harness 在垂直基准领先是普遍规律），幅度不可信（9.6 分里多少是"按自己评分细则优化"）
  2. Claude Code 10.5% 的极端值：BrowseComp 10.5% 与其他三项差距过大——疑似 Claude Code 默认配置在长程搜索任务上有结构性劣势（如工具轮次上限/无搜索工具默认开启），这是"harness 决定工具面"的例证，但也提示对照组配置可能未对齐
  3. 四 harness 的选择偏差：为什么是 OpenClaw/Hermes/Claude Code？无选择理由——排除了 Codex/Cursor 等强对照（Harness-Bench 里 Codex 80.4 高于全部四家）
  4. Harness-Bench 的位置数据未被本文引用：Minara 在 Harness-Bench 的成绩缺席——只引第三方基准中对自己有利部分的风险
  5. 成本口径：$0.2151 是"highest reported cost"但其他家成本未全列——单价高的原因（更快=更多并行调用？）未拆解
  6. 样本 200/1266：BrowseComp 抽样的置信区间未报——58 分差远超噪声，但 1-2 分的对比（如对 Claude Code +1.0）在 200 题样本下不显著
