一、内容详细整理

1.1 一句话总纲（原文前言）

自部署 LLM 关心的指标：首字够不够快（TTFT）、字出来够不够连贯（TPOT/ITL）、并发多了吞吐掉不掉（系统吞吐）、显存装得下且留余量（VRAM + KV cache）、每百万 token 实际成本（cost per M tokens）。

1.2 延迟类指标

指标 定义 关键规律
Prefill Time 读完 prompt 到开始产出首字的内部耗时 Prefill=计算密集（算力跑满）；Decode=访存密集（算力常只用一小部分）
TTFT 请求发出→收到第一个输出 token TTFT = Prefill Time + 排队等待；70B 单卡 H100 短 prompt 几百 ms~2s；系统忙时 TTFT 大头是排队不是计算慢
TPOT/ITL 逐 token 间隔（稳态出字速度） H100 INT4 70B 常见 50~120 tok/s（8~20ms/token）；上下文越长出字越慢（KV cache 越大搬的数据越多）
端到端延迟 TTFT + 生成总时长 文件总结/代码生成更看这个
P95/P99 慢的 5%/1% 请求的最差延迟 生产看分位数不看均值；P99 远高于 P50=偶发抖动（GC/队列堵/OOM 重试）

1.3 吞吐类指标

指标 要点
TPS（三口径） 单流 decode/单流含 prefill/系统聚合——最容易混淆的指标；70B INT4 H100 decode 上限 ~100+ tok/s；7B 在 4090 可 200+（小模型计算占比高更吃算力）
QPS 交互场景一个 QPS 对应几十路并发对话；QPS×TPS 关系取决于并发度
连续批处理有效性 判定标准：同等显存下并发提升时吞吐是否线性增长；断崖有两种（无连续批处理 vs --max-num-seqs 槽位上限卡队列）——实测同一 8 并发：槽位卡住 104.9 tok/s 且 TTFT 涨 24 倍 vs 放开 167.9 tok/s，差别只在一个参数。看到断崖先查槽位再怀疑框架
多卡线性扩展效率 效率比 = 实测多卡吞吐 ÷（单卡×卡数）；实际 7~9 折；<0.7 = 并行策略或互联成瓶颈

1.4 资源类指标

VRAM 三件套：总显存 = 权重 + KV cache + 运行时碎片。
- 权重粗算：参数量(十亿) × 精度字节数（BF16=2B，INT4≈0.75B 含元数据）
- 经验法则：理论值 × 1.2 安全系数。70B INT4 单卡装得下但并发稍高就 KV cache 不足 OOM——"能安装但运行中挂"的根源

KV cache 公式：2 × 层数 × KV_head数 × head_dim × 精度字节 × token数
- Llama-3-70B（80 层/GQA 8 KV head/head_dim 128/BF16）：≈ 0.31 MB/token → 4K=1.3GB，128K=40GB
- 长上下文(≥32K)+多并发时 KV cache 可超权重本身成第一瓶颈 → KV 量化/CPU 卸载
- 反向错误更隐蔽：按最大上下文×最大并发开满 KV 池实际只用百分之几——实测超配 24 倍（池 109.8 万 token 实用 4.6 万，usage 4.2%）；调低后腾出 12GB 显存换更高聚合吞吐。--gpu-memory-utilization 配方通常是为"装得下"配的，不是为"跑得稳"配的——抄配方注意

利用率辨析：decode 阶段 GPU 利用率 30% 也可能正常（卡在带宽）；真正瓶颈指标是显存带宽——H100 SXM 3TB/s、H200 4.8TB/s、A100 2TB/s、4090 1TB/s。带宽差几倍出字速度就差几倍

量化损失：INT4（AWQ/GPTQ）对话类肉眼难辨，复杂推理/长链思考掉 1~5 个百分点——选 INT4 前必须实测自己业务题型的跌落（MMLU/GSM8K/HumanEval 量化前后对比）

1.5 服务质量与可靠性

  • /health 返回 200 不代表引擎在出字：健康检查探的是 API server，真正干活的是背后的引擎进程——两者可以分开死。存活探针要探真实生成（发 1 token 请求看回不回）
  • 判活不能用请求超时：满负载排队是正常的——用超时判活等于让流量高峰重启你的服务；看引擎是否在推进（Avg generation throughput 是否连续多周期为 0）
  • OOM 重试是 P99 抬头常见原因；99.9% 可用 ≈ 每月 <44 分钟不可用；开流式让感知延迟接近 TTFT

1.6 成本类

  • Cost per token / tokens per dollar / tokens per kWh（H100 SXM 700W vs 4090 450W——电力是长期账）
  • TCO = 硬件折旧(3~4 年) + 电费 + 机网 + 运维人力；月调用数十亿 token 级才回本；峰值波动大租云更灵活

1.7 进阶优化专属指标

优化 关键指标 实测/陷阱
投机解码 加速比 1.5~3×（解码瓶颈中低并发最明显）；接受率决定效果 统计陷阱：SSE chunk 数计速会系统性低估——被接受草稿 token 和验证 token 挤同一 chunk。实测把 41 tok/s 报成 20.5（几乎等于关掉投机采样的参考值，看起来完全可信）。正确：stream_options:{"include_usage":true} 读 completion_tokens。实测 MTP 接受率 65.4%、单次验证 1.65 token、上限 1.6×
Prefix Caching 命中率（Agent/RAG 场景 50%~70%）；TTFT 降 40%~90% 全不命中反略增开销；命中率低=场景前缀重复度低不划算
多卡并行 DP/TP/PP 选型 70B 以上基本多卡；NVLink 优于 PCIe

1.9 真机实测六坑（第九节精华，DGX Spark × Ling-3.0-Flash-INT4）

被测：Ling-3.0-Flash（124B MoE/仅激活 5.1B，KDA+MLA 混合注意力，价格 Qwen3.8-27B 的零头）；vLLM + CUDA Graphs + MTP 投机解码；--max-model-len 16384；统一按 usage.completion_tokens 计数。

# 坑 数字
1 TTFT 飙升先查排队 监控报警 TTFT 暴涨时先看并发队列与排队耗时，别盲目归咎算力
2 假性吞吐断崖 seqs=4 时 8 并发吞吐不涨延迟暴增——看似连续批处理失效，实为槽位限制；1→16 并发总吞吐 ×6.7（36.3→242.1）但单流 36.3→15.1 tok/s
3 KV cache 超配 24 倍 gpu-mem-util 0.80 分 21GiB 池（110 万 token）实用 4.6 万（4.2%）；调低释放 12GB 吞吐反升
4 长上下文 Decode 腰斩 prompt 300→15K：decode 39.0→18.2 tok/s（16K 窗口内已腰斩）；49K 时 7.1（慢 5.6×）。Prefill 恒定 2400+ tok/s（混合线性注意力优势）。测点放窗口中段 8K~16K，别只测首尾；别把 Prefill 不掉速当 Decode 不掉速
5 投机解码统计陷阱 chunk 数计速 20.5 tok/s 假数据 vs usage 口径 41 tok/s 真 2×
6 质量评测两盲区 ①思维链截断：IFEval 开思考模式 0.789→0.207，根因 max_tokens=2048 截断 CoT——表现为分数低而非报错；②FC 分层：BFCL-v3 综合 0.744 但单轮 0.887 vs 多轮自主循环仅 0.438——Agent 系统应由外层工作流编排驱动，不能全靠模型长链自主规划

三、归纳总结

  1. 指标分层的心智模型：延迟（用户感知）→ 吞吐（系统容量）→ 资源（硬件门槛）→ 质量（可靠性）→ 成本（钱）——五层各自独立又互相牵制，任何单指标优化都可能伤另一层
  2. "排队是 TTFT 的大头"是排障第一问：TTFT=Prefill+排队——监控报警先查队列再怪算力，这条纪律能省一半误诊
  3. KV cache 是双向陷阱：开小了并发 OOM，开大了挤占运行缓冲（24 倍超配实测）——--gpu-memory-utilization 的抄配方时代该结束了，要看 usage 实测调
  4. 带宽是 decode 的真瓶颈：GPU 利用率 30% 可能正常、显存带宽差几倍出字速度差几倍——选卡比算力更该看 GB/s
  5. 投机解码的统计陷阱具有普遍教训：计量口径错误产生的"看起来完全可信"的假数据（20.5 恰好等于关闭时的参考值）是最危险的——所有性能测量先审统计口径
  6. 质量评测的"低分≠模型差"：CoT 截断表现为掉分而非报错、FC 多轮弱必须靠外层编排补——评测配置错误会伪装成能力缺陷

四、趋势判断

  1. MoE 小激活大总参会成为端侧部署主流：124B 总参/5.1B 激活+统一内存机器——"大模型塞小机器"的性价比路线被跑通，价格是稠密 27B 的零头
  2. 混合线性注意力（KDA+MLA）解决长上下文降速：Prefill 恒定 2400+ tok/s 实测证明非全注意力架构的工程价值——Decode 端仍是 KV 搬运瓶颈，架构创新在两头分别发力
  3. "假性断崖"类排障知识会成为部署工程师的核心经验：一个参数（max-num-seqs）造成 24 倍 TTFT 差异——调优知识从"指标定义"下沉到"参数级手感"
  4. 评测配置审计会标准化：CoT 截断陷阱（0.789→0.207）这类"配置错误伪装能力缺陷"的案例会推动 eval harness 的配置校验成为标配
  5. 统一内存机器（DGX Spark 类）开辟新生态位：121GB CPU/GPU 共享空间让百亿级 MoE 单机可跑——大小厂的成本结构都会被重估
