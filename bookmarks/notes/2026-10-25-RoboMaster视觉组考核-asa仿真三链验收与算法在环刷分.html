两个反直觉点值得记：
1. 转速升高，命中率降但击杀时间几乎不变。射速 10Hz 提供冗余，决策层"提前减速+迎面宽角"把窗口损失吃掉了。
2. 7m 的瞄准误差 RMS 极小（0.001-0.008 rad）却打不中。这排除跟踪问题，把根因锁死在弹道残差（7m 下垂 0.33m，补偿后残余超半高容差）+ 远距角点可观测性。这是"指标正常但结果是零"的典型，只看 aim RMS 会误判算法好。

三、口径校正：三处"自己骗自己"的地方

这节是本次最该带走的东西。跑通之后回头审口径，发现三处表述站不住：

原表述 事实 为什么危险
"视觉自瞄闭环已在仿真跑通" 刷分器注入真值角点，YOLO 不在环 被追问漏检率/检测延迟时零材料，等于把"几何闭环"冒充"感知闭环"
"完整视觉 demo ✅" demo 读出的是 *.avi 离线录像 与仿真器无连接，"能跑 demo" ≠ "能接仿真"
"Gazebo 因无 GPU 排除" asa 有 AMD RX 6600；真因是 rmoss_gazebo 要 Jazzy + Gazebo Harmonic 论据错一次，后面所有选型判断都失去信用

方法沉淀：验收前先 grep -n VideoCapture tests/*.cpp 查 demo 的输入源。离线录像 / 真值注入 / 仿真渲染三种输入，对应的结论强度差一个数量级。数据表要给出去，就必须成对标注"检测理想化"。

四、算法在环刷分器的设计取舍

aim_loop_sim 挂同济测试框架，复用其 Solver/Tracker/Aimer 全部类，几何用 reproject_armor 生成像素角点——与实车解算 100% 同源。这是"零 sim2real 争议域"的关键：坐标系、内参、畸变、外参全走同一份 yaml。

三轮调试都是靠对照实验破局，不靠读代码猜：
- 前向轴假设错（云台前向 +x 不是 +z）→ sanity 投影爆 1e10
- pitch 符号反（同济约定世界系向上为负）→ 翻转对照 577 发 0 中 vs 12 发 9 中
- 弹道补偿缺失 + t_fly 用了旋转中心距离 → 打点打印 dz=+0.200 直接看出弹停在板前 0.2m

还有一个隐蔽坑：跨场景复用 solver/tracker/aimer 导致状态污染（EKF 时间戳/lock 残留），表现为"全表 d≥3 全灭但单场景正常"。修法是每场景重建三件套。

方案 关键事实 判定

选型的第一性约束不是"哪个引擎强"，而是版本能装进去（Humble vs Jazzy/Harmonic）+ 有没有 CUDA（决定 OpenVINO 路线）+ 磁盘余量（asa 已用 86%，64G）。

六、我的判断

  1. 考核要求本身已满足，不必为了"看起来很完整"去硬凑感知闭环——把三条链的边界讲清楚，比糊成一条"全闭环"更可信。
  2. bevy 值得投，但要先算账：装 rustup 1.95 + 首次编译（64 核约 8-15min）+ 图像桥，磁盘要 8-15G，而当前只剩 64G 且 86% 已用。这是唯一需要用户拍板的成本项。
  3. 7m 短板是算法问题不是仿真问题：瞄准 RMS 已经小到 0.001rad 量级，剩下的是弹道补偿与远距角点精度，该在算法侧改，不该改仿真参数。

七、可复用清单

  • 停栈必须用全栈清场脚本：pkill ros2 launch 只杀直接子进程，map_server/robot_state_publisher 挂到 ppid=1 变孤儿，同名节点在 DDS 里抢占 → 新 lifecycle_manager 打不到真 map_server → /map_server 永久 unconfigured。
  • loopback sim 必须发 /initialpose：否则不发布 map->odom，RViz 画不出车、代价地图刷 frame map does not exist。
  • RViz 看不到车先查产品配置：官方 nav2_default_view.rviz 里 RobotModel: Enabled: false + TopDownOrtho Scale: 160（小场地被放大到屏幕外）。
  • 换地图要改两处：nav2_params.yaml 的 yaml_filename 优先级高于 launch 的 map:=，且源码与 install 副本都要改（运行读 install）。
  • set -u 不能包裹 source ROS：/opt/ros/*/setup.bash 内部引用未定义变量，直接 unbound variable 静默退出。
