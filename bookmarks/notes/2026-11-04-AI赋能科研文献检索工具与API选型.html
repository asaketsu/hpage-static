一、内容整理

1.1 核心结论

工具搜不到，不代表论文不存在。用 AI 检索文献，最重要的不是找到一个“最强的工具”，而是知道你的工具能搜到哪里、搜不到哪里。

作者兔老师将课程“大数据和人工智能”中 AI 赋能科研部分系统梳理为系列，第一期只讲文献检索，难度由易到难，涉及工具包括 YILA、Grok Bot、Codex 和 WorkBuddy。文中明确划分两种更靠谱的方式：

  • 方式一：直接用接入论文数据库的 Agent，开箱即搜，适合大多数人
  • 方式二：自己给 Agent 接入论文 API，相当于给 Agent 装上手和脚，适合动手能力强、想掌控检索过程的人

1.2 常见坑：只靠开源检索 Skill

  • 网上开源论文检索 Skill 很多，安装方便，但多只连少数免费来源，如 arXiv 或不带 key 的免费接口
  • 免费接口搜几次就被限流，只出来十几篇
  • 最危险的不是搜得少，而是形成错觉：以为该方向论文就这么几篇
  • 误判研究空白，开题时才被导师问住“这篇你怎么没看”
  • 结论：想检索到权威高质量论文，不建议只靠一个 Skill

1.3 方式一：直接用接入论文库的 Agent（YILA 示例）

作者常用 YILA 做文献检索，接入 Google Scholar、Semantic Scholar、arXiv、Google 专利等数据库，论文和专利都能直接搜。五个可直接抄用的场景：

  • 场景一 写申报书/开题报告找立项依据：按“现状、影响机制、实践路径”检索近 5 年中英文代表性文献。示例中 YILA 同时检索万方、OpenAlex 和 Google Scholar，去重后留 57 篇，并诚实提示英文文献里直接研究中国思政课的很少，只适合作国际参照
  • 场景二 中英文文献一次搜齐：示例“短视频使用与大学生睡眠质量”近 5 年实证研究，中英文各列代表性文献并标注样本量与期刊等级，如 Frontiers in Psychology（JCR Q1）、Acta Psychologica（JCR Q2）；同时提醒现有研究多讲“成瘾或问题性使用”而非普通刷视频时长
  • 场景三 临床/药物方向研究进展：示例 SGLT2 抑制剂治疗心力衰竭，优先 RCT、系统综述和指南，按疗效/安全性/适用人群分类；结果命中 DELIVER（NEJM 2022）、EMPULSE（Nature Medicine 2022）、2023 年 ESC 指南更新，并提醒 DAPA-HF、EMPEROR 等奠基性试验在 5 年窗外需单独补
  • 场景四 新方向补经典文献：示例“社区韧性”，先给奠基经典再补近年代表性研究，形成阅读路径——概念奠基、社会资本与协同治理、中国情境应用；经典从 Norris 等（2007）、Aldrich & Meyer（2014）起读，并给出“只读三篇读哪三篇”的建议
  • 场景五 查技术相关专利：示例钙钛矿太阳能电池封装，检索近 5 年中国和全球专利，按 9 条技术路线分类，如有机/无机交替薄膜阻隔、专用封装胶膜、低温与光固化工艺、边缘密封、柔性超薄封装、封装设备等，列主要申请人如极电光能、天合光能、南开大学、华中科技大学、宁德时代、韩华、Jusung 等；同时声明边界：只是值得跟踪的申请人、非按数量排名，海外同族未核实完整，不能作 FTO 侵权判断

核验纪律：拿到结果后做两件事——随机抽几篇回到数据库核对论文真实存在；再看有没有漏掉已知重要论文。

1.4 方式二：给 Agent 接入论文 API

作者用过且推荐的三个 API，定位不同：

  • OpenAlex：覆盖面最广的“学术总目录”，收录 3.2 亿多篇作品，每天新增几万篇；作品含期刊/会议论文、书和章节、数据集、学位论文、预印本等；数据源最早接手微软学术（Microsoft Academic Graph，2021 年停止）及 Crossref（DOI 注册机构），另汇集 PubMed、DataCite、HAL 及大学/学科知识库；同一论文的 arXiv 预印本、正式版、学校知识库版本会尽量合并去重；可拿到题目、摘要、作者、机构、期刊、被引次数、参考文献、是否开放获取，有摘要约 1.7 亿篇，开放获取约 1.3 亿篇；对 6000 多万篇 OA 论文缓存全文 PDF 可直接下载，每天免费额度约够下 100 篇；中文作品约 590 万篇，中文核心期刊与国内学位论文仍需查知网、万方
  • OpenAlex 费用：关键词检索每天约 1000 次、每次最多 100 条；按条件筛选每天约 10000 次；用 DOI 查单篇不限次免费；官方参考是一天 20 次检索、200 次筛选、50 次单篇查询约花 0.04 美元；额度每天北京时间早上 8 点（UTC 零点）刷新；带 key 每秒最多 30 次、不带 key 每秒 10 次且每天额度只有十分之一；新账号第一笔 1 美元限速约 50 分钟后解除；遇 429 等一会儿再试不会额外扣费
  • Semantic Scholar：查引用关系最顺手，官方称 2.14 亿篇论文、24.9 亿条引用关系、7900 万位作者；特色是引用网络（引用谁/被谁引用）、TLDR 一句话 AI 摘要、相似论文推荐、开放获取 PDF 链接；注意摘要可能因版权缺失、关键词检索最多返回 1000 条相关度排序结果，更多需批量检索接口；不申请 key 可用但共享限速池，高峰易拒，申请 key 起步每秒 1 次
  • SerpApi：间接用上 Google Scholar，Google Scholar 本身无官方 API、官方帮助页明确不提供批量获取；SerpApi 第三方抓取 Scholar 结果页整理成结构化数据，能搜到期刊文章、学位论文、书、摘要、法院判例，来源含出版社、学会、在线知识库、大学网站；可拿到标题、作者、来源、片段（非完整摘要）、被引次数、“被谁引用”和“所有版本”链接，可按年份筛，拿不到全文；每次最多 20 条，按成功检索次数计费；每月 250 次免费，入门档 25 美元/月 1000 次，订阅制当月清零
  • 另外两个免费按需取用：PubMed（E-utilities）生物医学必备，收录 4000 多万条题录和摘要；arXiv API 面向物理、数学、计算机等预印本，可直接拿全文 PDF，官方要求每 3 秒最多 1 次，写代码记得加等待
  • 作者习惯组合：OpenAlex 打底，Semantic Scholar 顺引用链补充，SerpApi 留着补漏；API 搜到主要是论文信息不是全文，付费论文全文仍需学校图书馆权限下载

1.5 接入方式与 API key 安全

  • 接入不麻烦：找到 API 官方文档交给 Agent，让它自己写调用代码。官方文档入口：OpenAlex（https://developers.openalex.org/）、Semantic Scholar（https://api.semanticscholar.org/）、SerpApi（https://serpapi.com/google-scholar-api）、PubMed（https://www.ncbi.nlm.nih.gov/books/NBK25497/）、arXiv（https://info.arxiv.org/help/api/）
  • 不要把 API key 直接发给 Agent：key 相当于账户密码，粘贴在对话框里会留在聊天记录里不安全
  • 更稳妥做法：有专门填 key 输入框就填在框里；没有就把 key 写进项目文件夹 .env 文件，让程序从文件读取，并告诉它不要打开、不要显示该文件

1.6 三个工具分别怎么配置

  • Grok Bot 作者觉得最丝滑，三步：新建专用搜论文 Bot（如“论文搜索助理”）→ 只说一句话“我要通过 API key 搜索 OpenAlex 的论文，帮我去设置一下” → 它弹出填 key 输入框并提示 key 安全保存、Bot 本身看不到 → 保存后自动测试，用 “large language models peer review” 检索返回靠前论文和被引次数，提示本次查询花费 0.001 美元；按此价格每天 1 美元额度约 1000 次检索；追问“人工智能在媒体中相关应用比较火的论文”后按被引排序列出 2018 年以来引用最高论文
  • Codex：先说需求“我要搜索 OpenAlex 的论文，我一会儿可以给你一个 API key，帮我接入以后帮我去搜论文”；它提醒 key 是登录凭证不要写进代码或公开文件、优先放本地环境变量，并列出需准备内容：API key、检索主题、筛选条件（年份、期刊、引用量等）和结果格式；作者按原则不直接粘贴 key，而是写进 .env 再让它读环境变量；接着让它做本地检索网页，约 4 分钟做好：输入关键词可搜、可按年份/OA/文献类型筛选、结果可导出 CSV 或 BibTeX，key 在网页“API 设置”里填，以后打开网页即可不用每次和 Agent 对话
  • WorkBuddy：用法和 Codex 基本一样，把 API 文档交给它、key 放进 .env、让它写检索脚本，作者未重复截图

二、查询拓展

2.1 OpenAlex

OpenAlex 是开放学术图谱项目，定位“学术总目录”，由 Crossref、PubMed、DataCite 等多源汇聚，去重合并同一作品多版本。价值在于便宜的筛选统计：按年份、期刊、机构、作者、被引次数做趋势分析成本低，适合第一次摸清方向的 Agent 先扫全景。局限在中文核心期刊与国内学位论文覆盖弱，大陆语境必须补知网/万方。

2.2 Semantic Scholar

Semantic Scholar 由 Allen Institute for AI（AI2）运营，强项是引用图与 TLDR 摘要，适合“滚雪球”：从几篇核心论文出发，前向被引、后向引用、相似推荐三路扩散。注意 TLDR 并非每篇都有、摘要受版权缺失影响，API 返回条数上限与批量接口要分开看，高峰共享限速池时优先用 key。

2.3 SerpApi 与 Google Scholar

Google Scholar 无官方 API 且官方明确不支持批量获取，SerpApi 是合规边界上的第三方抓取转结构化服务。它适合补 OpenAlex/Semantic Scholar 搜不到的书、学位论文、小众会议、判例等长尾，但返回的是片段而非完整摘要、拿不到全文，且按检索次数订阅计费、月度清零，用量大前要算账。

2.4 PubMed E-utilities 与 arXiv API

PubMed E-utilities 是生物医学题录/摘要标准入口，4000 多万条，临床方向如 SGLT2 示例的证据链常从这里起。arXiv API 是预印本全文直达入口，但官方限每 3 秒 1 次，Agent 批量拉取时必须加等待与缓存，否则触发限速。

2.5 免费开源检索 Skill 的结构性短板

开源 Skill 的免费来源多为 arXiv、PubMed 等开放库或无 key 免费接口，天然三短板：来源窄（中文核心、专利、学位论文覆盖弱）、限速严（无 key 共享池易 429）、无去重合并（同一论文多版本重复计数）。把“搜出十几篇”误读为“没人做”正是检索策略失效而非方向空白。

三、归纳总结

3.1 框架：两条路线与三层组合

文献检索
├─ 方式一：现成 Agent（YILA 类）
│   └─ 零配置、开箱搜、适合申报书/开题/中英文/临床/新方向/专利
└─ 方式二：自接 API
    ├─ OpenAlex 打底（全景、趋势、筛选便宜）
    ├─ Semantic Scholar 滚雪球（引用链、TLDR、相似推荐）
    └─ SerpApi 补漏（书、学位论文、小众会议、判例）
        └─ 细分免费补强：PubMed（生物医学）、arXiv（预印本全文）

3.2 选型对照（非表格版）

  • 要全景摸方向、做近 5 年发文趋势统计：OpenAlex 优先，关键词每天约 1000 次、筛选每天约 10000 次、DOI 单篇不限，常规检索日耗约 0.04 美元
  • 已有核心论文想扩相关文献：Semantic Scholar，顺引用链前后滚雪球，注意摘要缺失与 1000 条上限
  • 专补书、学位论文、小众会议：SerpApi，每月 250 次免费，入门 25 美元/月 1000 次清零
  • 生物医学证据：PubMed E-utilities；物理/数学/CS 预印本全文：arXiv API，每 3 秒最多 1 次
  • 中文核心期刊、国内学位论文：知网、万方补查，OpenAlex 中文仅约 590 万篇比例偏低
  • 专利布局：YILA 专利助手类接入万方专利 + Google Patents，但结果仅“值得跟踪申请人”，不能作 FTO

3.3 成本量级

  • OpenAlex 一次测试检索约 0.001 美元，1 美元额度约 1000 次检索；20 检索 + 200 筛选 + 50 单篇查询日耗约 0.04 美元
  • Semantic Scholar 申请 key 起步每秒 1 次，免 key 共享池高峰易拒
  • SerpApi 订阅清零制，用量大再考虑

四、趋势判断

4.1 趋势一：检索从“搜关键词”转向“按研究任务组织证据”

依据：作者五个场景不是裸关键词，而是按立项依据三段式、疗效/安全性/适用人群、奠基经典阅读路径、技术路线分类等任务结构组织结果，并主动提示时间窗外奠基试验、国际参照边界、非排名非 FTO 等边界。未来 Agent 检索的竞争点是任务结构化与边界诚实，而非召回条数。

4.2 趋势二：组合检索成为默认，三源打底+滚雪球+补漏

依据：作者自用组合是 OpenAlex 打底、Semantic Scholar 补引用链、SerpApi 补长尾，单源必然漏中文核心、学位论文、书与小众会议。学术 Agent 的默认架构会从单 Skill 走向多源编排加去重合并。

4.3 趋势三：key 安全与本地化检索网页化

依据：Grok Bot 的专用填 key 框（Bot 本身看不到）、Codex 的 .env/环境变量路线、本地检索网页（关键词搜、年份/OA/类型筛选、导出 CSV/BibTeX）三条线索同指一向：凭证不出对话、检索能力沉淀为本地工具而非每次对话。检索正从“和 Agent 聊”变成“给自己装一个检索台”。

4.4 趋势四：免费限速倒逼“省着搜”

依据：OpenAlex 无 key 额度只有带 key 的十分之一、新账号首笔限速 50 分钟、arXiv 每 3 秒 1 次、Semantic Scholar 摘要缺失与 1000 条上限。会写低成本检索策略（先筛选统计、再 DOI 精查、批量接口分页、缓存全文）的人，单美元能搜的量明显更高。

五、关联分析

5.1 与本地论文检索笔记体系的关联

  • 已有笔记库中 2026-11-03《科研课题孵化器软件》、2026-10-20《飞机结构设计融入AI科研需求与使用流程策划》等与“AI 赋能科研”主题相邻；本篇补的是第一步文献检索的工具选型与成本账，可作为科研工作流系列的上游模块
  • 与本对话工具链的关联：本篇提取即用 fxtwitter article.content.blocks 解析 X 长文，说明“会检索”不止搜论文，也包括绕过平台墙拿全文——检索策略本身就是能力

5.2 与项目索引的关联

  • 项目 project/scholar-analyst（Scholar Analyst）描述为学术分析报告生成器，支持 arXiv/Semantic Scholar/PubMed 多源检索、MD+HTML 双格式输出，与本篇方式二高度同构：OpenAlex 打底 + Semantic Scholar 滚雪球 + PubMed/arXiv 补强的组合可直接映射到该项目的多源检索层
  • 项目 project/deep-research / project/deep-research-hermes 的深度研究链路同样依赖多源检索，本篇的“免费 Skill 只连少数来源”坑点与“10 万条/天量级但中文覆盖弱”的取舍，是评估这些项目召回可信度时的现成标尺：凡只报条数不报来源构成的检索结果，都应按本篇纪律回数据库抽查核对

5.3 与用户研究习惯的关联

  • 用户领域含飞机设计企业背景与适航/构型管理资料，专利布局场景（钙钛矿封装九路线、申请人清单、FTO 边界）对装备/材料方向的专利跟踪有直接迁移价值：先分类技术路线再列申请人、声明非排名非 FTO 的写法可照搬
  • 用户此前对数字精度零容忍、引用历史 PASS 前须交叉核对的铁律，与本篇“随机抽几篇回库核对 + 检查漏掉已知重要论文”的核验纪律同构，适合写入检索类任务的验收门

六、金句摘录

“最危险的不是搜得少，而是它会给你一个错觉：这个方向的论文就这么几篇。”——免费检索 Skill 的结构性坑点

“其实不是这个方向没人做，而是你的工具没有搜到。”——误判研究空白的根因

“工具搜不到，不代表论文不存在。用 AI 检索文献，最重要的不是找到一个‘最强的工具’，而是知道你的工具能搜到哪里、搜不到哪里。”——全篇收束命题

“它也老实告诉我：英文文献里直接研究中国思政课的很少，适合当作‘国际参照’来引用。这种提醒，比硬塞给你几篇不相关的英文文献有用多了。”——边界诚实比硬凑召回更有价值

七、行动启示

  • 检索前先写来源清单：OpenAlex 打底、Semantic Scholar 滚雪球、SerpApi 补漏、PubMed/arXiv 按学科补强、中文核心补知网万方，缺一类要在报告里声明
  • API key 一律不进对话：有专用填 key 框用框，没有写项目 .env 并声明不打开不显示
  • 每次检索结果两道核验：抽查回库核对真实存在、对照已知重要论文查漏
  • 成本先算账：按 20 检索 + 200 筛选 + 50 单篇约 0.04 美元/天估预算，arXiv 批量加 3 秒间隔、429 等待重试不重跑
  • 把检索沉淀成工具：按 Codex 模式做本地检索网页（筛选 + CSV/BibTeX 导出），而不是每次重复对话检索

八、拓展应用推荐

  • 申报书/开题报告立项依据：抄作者三段式提示词（现状、影响机制、实践路径），用 YILA 类 Agent 一次拿中英文代表文献 + Excel 候选池
  • 临床/药物综述：抄 SGLT2 提示词，按疗效、安全性、适用人群分类，优先 RCT 与指南，并主动补时间窗外奠基试验
  • 新方向入门：抄“社区韧性”提示词，先奠基经典后补近年研究，要求给阅读路径和“只读三篇”清单
  • 专利布局跟踪：抄钙钛矿提示词，按技术路线分类列申请人并写每类解决的问题，严格标注非排名、非 FTO
  • 飞机/装备方向技术调研：把上述专利与文献模板平移到材料、构型、适航相关主题，先 OpenAlex 全景筛年份与机构，再用引用链滚雪球，最后用 SerpApi 补学位论文与会议长尾
  • 本地检索台搭建：OpenAlex key 放 .env，照 Codex 路线做关键词 + 年份/OA/类型筛选 + CSV/BibTeX 导出的本地网页
