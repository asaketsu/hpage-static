# MoE + 多模态训练：视觉-语言 MoE 的路由策略特殊挑战

> 夜学深度笔记 | 覆盖 20+ 前沿论文，从 Med-MoE 到 AsyMoE、MoDES、AnyExperts、VisMMOE 等
> 日期：2026-05-27
> 主题：MoE + 多模态训练（视觉-语言 MoE 的路由策略特殊挑战）— P0 方向

---

## 核心发现

### 1. 模态不对称（Modal Asymmetry）是 VLM-MoE 的核心挑战

**AsyMoE（2025）** 首次系统揭示 VLM-MoE 的根本问题：视觉模态和语言模态的语义密度、信息熵、token 长度存在巨大差异，导致传统 MoE 路由策略在 VLM 上失效。

- **视觉 token 信息密度低**：一个 224×224 图像的 ViT 输出通常 196-576 个 visual tokens，但每个 token 的语义信息远少于一个语言 token
- **语言 token 信息密度高**：每个语言 token 携带更丰富的语义和语法信息
- **传统路由的"一刀切"问题**：固定 top-k 激活（如 top-2）在视觉和语言 token 上表现迥异——视觉 token 被过度路由到语言专家，语言 token 被过度路由到视觉专家
- **AsyMoE 解决方案**：引入模态感知的路由门控（modality-aware gating），为视觉和语言 token 分配不同的专家子集，通过模态不对称性增强专家特化

**与已有知识的关联**：
- [[2026-05-06-MoE混合专家模型]] → 已有 Token Choice / Expert Choice 路由知识，本次补充了**模态不对称**这一 VLM 特有维度
- [[2026-05-24-VLM强化学习RL训练]] → 视觉编码器冻结策略的深层原因：视觉 token 的信息密度低，导致梯度信号效率低，MoE 路由加剧了这个问题

### 2. 专家特化模式：视觉专家 vs 语言专家 vs 跨模态专家

**Q-MoE（ACM Multimedia 2024）** 和 **AnyExperts（arXiv 2025）** 揭示了 VLM-MoE 的三种专家类型：

| 专家类型 | 功能 | 路由策略 |
|---------|------|---------|
| 视觉专家（Visual Experts） | 处理图像特征提取、视觉推理 | 主要接收 visual tokens |
| 语言专家（Language Experts） | 处理文本生成、语言推理 | 主要接收 text tokens |
| 跨模态专家（Cross-modal Experts） | 处理视觉-语言对齐、多模态推理 | 接收混合 tokens |

**Q-MoE 的关键创新**：文本驱动的路由（Text-Driven Routing）
- 使用 LLM 的 hidden states 作为路由信号，而不是原始 tokens
- 通过文本先验知识预测哪些专家应该被激活
- 在 VQAv2 上提升 20%+，COCO Captioning 提升 30%+

**AnyExperts 的关键创新**：按需专家分配（On-Demand Expert Allocation）
- 打破固定 top-k 的刚性约束，根据任务需求动态分配专家数量
- 视觉任务激活更多视觉专家，语言任务激活更多语言专家
- 跨模态任务激活跨模态专家组合

### 3. 路由策略的三代演进

| 代际 | 代表工作 | 核心机制 | VLM 适配 |
|------|---------|---------|---------|
| 第一代 | Q-MoE (2024) | 文本驱动路由 | 用 LLM hidden states 预测路由 |
| 第二代 | AsyMoE (2025) | 模态感知路由 | 区分视觉/语言 token 的路由策略 |
| 第三代 | AnyExperts (2025) | 按需专家分配 | 动态专家数量 + 任务感知的专家选择 |

**与已有知识的关联**：
- [[2026-05-06-MoE混合专家模型]] → 已有 Token Choice → Expert Choice → Routing-Free 三代路由，本次补充了**模态感知**这一 VLM 专属维度
- [[2026-05-11-MoE蒸馏与压缩]] → 专家特化与蒸馏的关系：跨模态专家是最难蒸馏的

### 4. 推理优化：动态专家跳过与模型卸载

**MoDES（arXiv 2025）** 和 **VisMMOE（2026）** 针对 VLM-MoE 的推理瓶颈提出了两种优化方向：

**MoDES（Dynamic Expert Skipping）**：
- 核心问题：VLM-MoE 推理时，大量专家是冗余的
- 解决方案：动态跳过低贡献专家，减少计算开销
- 机制：基于 token 的专家贡献度评估，实时决定哪些专家可以跳过
- 效果：在保持精度的前提下显著降低推理延迟

**VisMMOE（Visual-Expert Affinity Offloading）**：
- 核心问题：VLM-MoE 模型太大，无法在内存受限设备上部署
- 解决方案：基于视觉-专家亲和性的卸载策略
- 关键发现：视觉专家可以被卸载到 CPU/边缘设备，而语言专家需要保留在 GPU
- 原因：视觉 token 的处理相对独立，可以异步执行

### 5. 领域特化：医疗、地理空间、人体运动

**Med-MoE（EMNLP 2024, 77 cit）**：
- 医疗 VLM 的 MoE 设计：按医学领域（放射学、病理学、眼科等）划分专家
- 轻量级设计：在医疗场景下，不需要通用 VLM 的全部能力
- 效果：在医疗分类和生成任务上超越通用 VLM

**SkyMoE（AAAI 2025, 7 cit）**：
- 地理空间 VLM：遥感图像理解
- 专家按地理领域划分（城市、农业、灾害、海洋等）
- 解决通用 VLM 在遥感任务上的 suboptimal 问题

**HMVLM（2025）**：
- 人体运动-视觉-语言 MoE
- 用 MoE LoRA 实现多模态指令微调
- 3D 人体运动语义与视觉-语言的对齐

### 6. 持续学习中的 MoE：漂移感知路由

**On Token's Dilemma（2026）**：
- 核心问题：VLM 持续学习时，新任务的视觉-语言分布与旧任务不同
- 解决方案：漂移感知（Drift-Aware）的 token 分配
- 机制：检测视觉-语言分布漂移，动态调整专家激活策略
- 与 [[2026-05-20-Active Data Selection]] 的关联：CPPO 的 completion 剪枝可以迁移到 VLM-MoE 的 token 剪枝

### 7. 测试时重路由：R2-T2（ICML 2025, 9 cit）

- 核心发现：VLM 的视觉感知能力通常不如 LLM 的推理能力
- 解决方案：测试时重路由（Re-Routing at Test-Time）
- 机制：在推理阶段动态调整专家激活策略，增强视觉感知弱的任务的专家激活
- 效果：在 challenging downstream tasks 上显著提升

## 技术原理解析

### 模态不对称的数学形式化

AsyMoE 提出模态不对称的量化指标：

$$A_{modality} = \frac{H_{text}}{H_{visual}} \times \frac{L_{text}}{L_{visual}}$$

其中：
- $H_{text}$ / $H_{visual}$：文本/视觉 token 的信息熵
- $L_{text}$ / $L_{visual}$：文本/视觉 token 的平均序列长度

**关键洞察**：
- 当 $A_{modality} > 1$（文本信息密度更高），传统路由会导致视觉专家过载
- 当 $A_{modality} < 1$（视觉信息密度更高），传统路由会导致语言专家过载

**模态感知路由门控**：

$$g_v = \sigma(W_v \cdot h_{visual} + b_v), \quad g_t = \sigma(W_t \cdot h_{text} + b_t)$$

$$P(e_i | x) = \text{softmax}(\alpha \cdot g_v \cdot W_{v,i} + (1-\alpha) \cdot g_t \cdot W_{t,i})$$

其中 $\alpha$ 是模态权重，由输入 token 的模态类型决定。

### 动态专家跳过的贡献度评估

MoDES 的专家贡献度评估：

$$C(e_i, x) = \frac{1}{|S_i|} \sum_{t \in S_i} \| \text{Attention}(t, e_i) \|_2$$

其中 $S_i$ 是专家 $e_i$ 处理的 token 集合。贡献度低于阈值 $\tau$ 的专家被跳过。

### 按需专家分配的优化目标

AnyExperts 的优化目标：

$$\min_{k} \mathcal{L}(y, f(x; \{e_i\}_{i=1}^k)) + \lambda \cdot k$$

其中 $k$ 是激活的专家数量，$\lambda$ 控制计算-精度权衡。

## Actionable Insights

### 1. 可落地的路由策略改进

**对现有 VLM 项目**：
- 在路由层加入模态感知门控（modality-aware gating），区分 visual tokens 和 text tokens
- 实现公式：$P(e_i | x) = \text{softmax}(\alpha \cdot g_v \cdot W_{v,i} + (1-\alpha) \cdot g_t \cdot W_{t,i})$
- 参数 $\alpha$ 可以通过输入 token 的模态类型（vision vs text）自动确定

### 2. 推理优化方向

**对 VLM-MoE 部署**：
- 视觉专家可以卸载到 CPU/边缘设备，语言专家保留在 GPU（VisMMOE 发现）
- 动态专家跳过（MoDES）可以在推理时减少 30-50% 的计算开销
- 测试时重路由（R2-T2）可以增强视觉感知弱任务的专家激活

### 3. 持续学习场景

**对 VLM 持续学习**：
- 漂移感知路由（On Token's Dilemma）可以缓解灾难性遗忘
- 结合 Active Data Selection（CPPO）的 token 剪枝，可以进一步优化计算效率

### 4. 领域特化

**对垂直领域 VLM**：
- 医疗 VLM：按医学领域划分专家（Med-MoE）
- 地理空间 VLM：按地理领域划分专家（SkyMoE）
- 人体运动 VLM：用 MoE LoRA 实现多模态对齐（HMVLM）
