## 核心观点

OpenClaw 不是对话工具，是**执行引擎**。它不是大脑，是双手。大多数人把 OpenClaw 当 ChatGPT 用，只发挥了不到 10% 的能力。

> "约束对人类是枷锁，对 Agent 是加速器。"

---

## 关键要点

| # | 实践 | 核心要点 |
|---|------|----------|
| 1 | **安全先行** | 沙盒模式启动，设预算上限，运行两周再提权限 |
| 2 | **技能安装顺序** | 基础 → 专业 → 进阶，别看到什么装什么 |
| 3 | **记忆系统** | 让 Agent 记住你的偏好，避免每次重复说明 |
| 4 | **Cron 定时任务** | 自动化重复工作，新闻/天气/汇报全自动 |
| 5 | **团队协作协议** | 明确角色边界，引入状态机思维，任务拆到原子级别 |
| 6 | **浏览器控制** | Playwright 自动化，填表/截图/数据提取 |
| 7 | **子 Agent 架构** | 多 Agent 协作的关键不在数量，在协作协议 |
| 8 | **Webhook 集成** | 接入 GitHub/GitLab 等外部服务 |
| 9 | **Prompt 工程** | System Prompt 是灵魂，花时间打磨 |
| 10 | **错误处理** | 自动重试 + 降级策略 + 告警通知 |
| 11 | **成本控制** | 免费模型处理日常，付费模型攻坚 |
| 12 | **知识库** | 本地 RAG + 外部搜索结合 |
| 13 | **多开模式** | 工作/生活分离，不同 Agent 不同配置 |
| 14 | **VPS 部署** | 别在主力电脑跑，安全隔离 |
| 15 | **社区资源** | Discord 社区、clawhub 技能市场 |

## 💡 对我们的价值分析

### ✅ 已在做的
- 记忆系统（三层架构 + WAL Protocol）✅
- Cron 定时任务（天气/新闻/记忆/保活）✅
- 多 Agent 团队（Dev/Content/Data/OPM）✅
- 技能按需安装 ✅
- VPS 部署 ✅

### ⚠️ 可改进的
- **错误处理**：缺少统一的自动重试+降级策略（watchdog 只监控 cron）
- **多开模式**：ubot 同时处理工作和生活，可考虑拆分
- **知识库**：本地 RAG 有 gap（相似度阈值过高，notes/ 未被索引）

### 🔥 重点行动
1. **完善错误处理链**：给关键 cron 加降级策略（如模型不可用 → 自动换 fallback）
2. **团队协作协议强化**：文章提到的"状态机思维"和"原子级任务拆解"值得借鉴，可融入 AGENTS.md
3. **浏览器控制能力**：已有 playwright-mcp，但实际使用率低，可探索自动化场景

## 延伸思考

文章强调 "工具是死的，人是活的"——这和我们 SOUL.md 的核心行为准则一致："灵活应对，方案 A 不行立刻换方案 B/C"。

最有价值的一点：**多 Agent 协作的关键不在数量，在协作协议**。这正是我们 OPM Meow 战略前置 + 数据闭环设计的初衷。
