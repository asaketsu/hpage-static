归纳总结

核心命题一句话：授权与安全不是取舍关系，而是用多层防线把"爆炸半径"压到最小之后，才敢真正给 AI 最大的执行权限。作者四个月迭代出一套 8 层防线的工作流（选型收敛 → 物理隔离 → 计划先行 → 测试分工 → 规范化出栈 → 秒级回退 → 生产守门员 → 三层文档记忆），让人类工程师只站在最后一道关口做决策与验收。

全文骨架可压缩为一个不等式：放手程度 ∝ 1 / 爆炸半径。每一层防线都在缩小"AI 写错时代价的上限"：worktree 让写炸的代价=两秒删目录；Plan 让跑偏的代价=重审 5 分钟；PR+对抗性 Review 让坏代码的代价=不合入；Feature Flag 让线上事故的代价=1-2 分钟关开关；部署看板让"幽灵版本"的代价=一屏看清。代价压到足够小后，"给不给 AI 权限"就不再是一个需要纠结的问题。

内容整理：八层防线逐层拆解

1. 选型收敛：Agent/Skill/MCP 都做减法

层 选择 理由
Agent 只用 Claude Code GPT 防御性编程、其他家 coding 差距明显
模型 生产=SOTA（Fable）或次优省心（Opus 5.5）；国模 DS-4.1 / GLM-5.3 非 flash 已"可用"但不进生产 省下的沟通/修补/重做时间 > 多花的钱
Skill 几乎只用 matt 一个 ①边界问题先问清敲定，减少落地跑偏 ②答案沉淀进 spec，大任务跨 session 状态维护
MCP 仅平台 MCP + Lark（读文档）+ meegle（需求单） 因人而异，按真实工作流接

关键动作：Claude 五时代后按 Anthropic 工程实践压缩全局配置/记忆/项目 Context，丢弃不用的 MCP 和 Skill——工具越多不是越强，是噪音。

2. 物理隔离：git worktree 是并发的前提

  • 改代码第一步永远是拉最新代码 + 独立 worktree（/private/tmp/-），绝不在主 IDE 工作区直接改。
  • 真实生产节奏同时派 2-6 个 Agent 并行，同一目录必然依赖冲突/分支打架。
  • 主 IDE 永远停在干净主集成分支，只做全局检索与最终核对；worktree 写炸了 rm -rf 两秒重置——消除"Agent 改坏本地代码"的心智负担。

3. 计划先行：前 5 分钟审计划，省 2 小时返工

稍大需求禁止直接改文件（大概率第 3 个文件就把架构写崩），强制先出 Plan，必含：

  1. 核心目的与影响面（下游模块/数据库字段/接口契约破坏性变更）
  2. 改动文件清单——计划外代码一行不准碰
  3. 边界与测试方案（正常流+极端异常兜底+单测写法）
  4. 跨天大需求：状态持久化文件（process.md/task.md）+ Checkpoint 勾选制，新 session 读一眼状态文件即无缝热启动

4. 终极测试分工：人不是 AI 的人肉测试机

反面模式：AI 写完代码，人开 Postman 手动拼参数测——这是把人变成廉价人肉测试机。正确分工：

  • 人类：只校验最终业务效果（体验页面功能）。
  • AI：代码自动部署 DEV 后拿到登录态和 API 权限，独立完成完整闭环——正常流（落库/返回结构）+ 异常流（非法参数/缺 token/并发竞争/超时 4xx/5xx），断言全绿才算"AI 维度的代码交付"。

5. 规范化出栈：PR 是人机之间最重要的防火墙

机制 做法
分支隔离 一切改动走 feature 分支，禁推集成分支
双语规范 gh pr create：Title=英文 Conventional Commit（喂 CHANGELOG），正文=中文动机/范围/验证证据，禁机械贴 diff
对抗性 Review chatgpt-codex-connector 当 Reviewer，gpt 挑不出毛病才准合入——"gpt 这德性很适合对抗性 review"，大合入常卡 20-30 轮
CI 自闭环 Actions 跑 Lint/类型/单测/镜像；CI 红了不用人翻报错，Agent 自己读日志定位堆栈、自己打补丁提交到全绿
防污染拦截 合并前自动核对是否夹带同事未发布提交

6. 极速回退防线：先有秒级刹车，才敢踩油门

  • 原则反转：没时间做繁重的线上结果校验 → 所以把精力放在保证能极速回退。
  • 核心改动默认包裹 PostHog Feature Flag，上线不全量暴露；异常时后台一键关 Flag，1-2 分钟止血，替代 10-30 分钟的回滚-重打包-重发布传统链路（那条链路走完"业务早就炸穿了"）。

7. 生产守门员：部署看板 + 全量日志巡检

每次合入 Prod 的固定动作，看板两个使命：

  1. 版本绝对透视：一屏看清每环境运行的镜像 SHA/代码版本——杜绝"以为发布了，线上其实跑着半个月前老版本"的幽灵问题。
  2. 全量日志异常巡检：穿透拉取所有环境全部服务最新业务日志，自动过滤聚类 Error。

血泪事故：同事本地自测通过但配置没对齐，服务后台疯狂报错、前端没崩无人察觉，发现时 error 日志已堆积几十万条。此后制度化：最近 5 分钟无新增未捕获 Traceback 和 5xx，线上才算通过验收。

8. 文档工程化：三层编排是唯一的长期记忆

"Agent 本质无状态，不沉淀规则它换个 session 犯同样的错；骂模型蠢没有意义，文档当代码治理，且文档是最重要的代码。"

层 载体 内容
L1 项目顶层约定 CLAUDE.md / AGENTS.md 启动/测试命令、Dev/Prod 地址、跨服务鉴权、红线规约
L2 规则与踩坑库 memories/ 或 docs/rules/ 按领域分层（engineering/、infra/），每条踩坑复盘用一句精准索引钩子命名，且和代码足够近
L3 任务级规约 specs/ + process.md PRD、接口定义、Checkpoint 进度，随 Git 跟踪

与已有笔记的接力：[[2026-06-20-LLM-Agent过度授权工具选择.md]] 从学术侧证明"过度授权扩大 blast radius"是 Agent 安全第一问题，本文给出工程侧的完整答案（不是少给权限，而是压小爆炸半径后多给权限）；[[2026-08-25-AI-Agent-IDE-Intent-SpecDriven多Agent协调.md]] 的 Augment Intent 把 worktree 隔离+spec 状态记忆产品化（Specialists 各自 worktree），本文是个人层面手工搭出同等能力的实操版。

差异点/我们不认同的：作者"几乎只用一个 matt skill"的极简路线，与我们"垂直 skill 库"路线相反——我们场景更宽（机器人/量化/飞书/研究），扁平化反而丢失程序性记忆；但对单一 coding 场景，工具收敛确实降低 Context 噪音，启发是定期做 skill 减法审计（skill-review 已有，需真跑）。

趋势判断

  1. "权限争论"正在被"半径工程"终结：从"该不该给 Agent 权限"（2025 主叙事，对应 06-20 论文的批判对象）转向"怎么把写错的代价压到两秒重置"（本文），问题从伦理题变成工程题。
  2. Skill 生态从堆量进入收敛期：作者从"热门 skill 都试"到"几乎只用一个"，与 Claude Code 官方 Context engineering 指南方向一致——2027 年 skill 竞争的胜负手是"减噪能力"不是"功能数量"。
  3. 测试人力正在被重新定义为"验收人力"：DEV 环境闭环自测把人从测试执行者挤到业务效果验收位，QA 角色的存续形态=写验收标准的人。
  4. 文档=代码将从口号变成治理制度：三层编排（顶层约定/踩坑规则库/任务 spec）与我们的三级记忆同构，说明"Agent 无状态→文档是唯一长期记忆"已是多方可复现的共识结构。
  5. 国模信号：DS-4.1/GLM-5.3 非 flash 被独立实践者评为"coding 可用但不进生产"——国模距生产级 coding 还差"省心度"（返工/沟通成本）最后一公里。

指南分析

若照搬这套工作流，按依赖顺序落地（每层独立可回退）：

  1. 第一周（零风险层）：所有改动走独立 worktree + 主分支只读——立即消除本地环境被改乱的风险，无任何工具依赖。
  2. 第二周（流程层）：大需求强制 Plan（影响面/文件清单/测试方案）+ process.md Checkpoint 制；PR Title 英文 Conventional Commit + 正文中文动机。
  3. 第三周（自动化层）：接对抗性 Reviewer + CI 红了 Agent 自修复循环；DEV 环境凭证下发，AI 自测全绿才交付。
  4. 第四周（止血层）：核心改动包 Feature Flag 上线；搭最小部署看板（镜像 SHA 透视 + Error 日志聚合），发布后 5 分钟无新增 5xx 才算过。
  5. 持续（记忆层）：踩坑即写规则（一句精准钩子命名），按领域归档，靠近代码存放。

失败回退：任何一层引入成本超过收益（如单人项目接 codex review 太重），降级为"该层只保留人工版"——防线是菜单不是教条。

拓展应用推荐

  • 给 Hermes 运维：把"部署看板+5 分钟无 5xx 才算验收"移植成 gateway 发布后的固定巡检动作（cluster-health-check 已有原料，缺制度化触发）
  • 给多 Agent 并行任务：delegate_task 并行写文件前默认开 worktree/独立目录，替代事后冲突检测
  • 给笔记/研究管线：spec 沉淀模式（边界问答→落盘→跨 session 热启动）正是我们高频笔记流的镜像，可反向把"用户纠偏→skill patch"的问答环节显式 spec 化
  • 给 DUCK 真机调试：「先保证秒级刹车才敢踩油门」= 我们"守卫红线提前介入"哲学的工程版表述，可引作文档论据
