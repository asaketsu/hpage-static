## 核心问题

Hermes Agent 内置记忆容量仅 **2,200 字符**（约三四句话），所有内容平铺无结构，撑满就得手动挤掉旧的。每次对话像重新认识。

**解法**：通过第三方记忆插件扩展，从"便利贴"升级为"图书馆检索系统"。

---

## 记忆两层架构

| 层级 | 模式 | 特点 |
|------|------|------|
| **内置记忆** | 2,200 字符纯文本，每次对话自动加载 | 简单直接，但极小，无结构 |
| **插件记忆** | 数据库存储，空间不限 | 支持语义搜索、结构化查询、信任评分 |

## 8 款记忆插件横向对比

### ★★★★★ Honcho（最强推理）

| 维度 | 内容 |
|------|------|
| 费用 | 免费/付费 |

|------|------|
| 费用 | 付费 |

| 亮点 | 自动提取关键信息、自动去重、开箱即用，GitHub 最火 |
| 缺点 | 云端付费，数据不在本地 |

### ★★★☆☆ Holographic（作者选择）⭐

|------|------|
| 费用 | **免费** |

## Holographic 配置（三行命令）

```bash
# 查看当前记忆状态
hermes memory status

# 设置记忆提供者
hermes config set memory.provider holographic

# 验证生效
hermes memory status
```

配置文件：
```yaml
memory:
  memory_enabled: true
  user_profile_enabled: true
  provider: holographic
```

数据库位置：`~/.hermes/memory_store.db`（SQLite）

## Holographic 工作机制

**三层检索**：
1. **FTS5 全文搜索** — 关键词匹配
2. **HRR 向量检索** — 语义相似性
3. **实体解析 + 信任评分** — 判断事实可靠性，低分自动遗忘

**9 种操作**：

| 操作 | 用途 |
|------|------|
| `add` | 添加事实 |
| `search` | 搜索事实 |
| `probe` | 查询实体 |
| `related` | 查关联 |
| `reason` | 多实体推理 |
| `contradict` | 矛盾检测 |
| `update` | 更新 |
| `remove` | 删除 |
| `list` | 列出所有 |

还有 `fact_feedback`（点赞/踩），踩多了自动遗忘——像人一样慢慢忘掉不重要的。

## 思考

文章的核心洞察——**记忆是 AI Agent 从"工具"到"助手"的分水岭**。我们当前使用 Hermes 内置记忆 + Memory Graph（MCP），已覆盖基本需求。Holographic 的 FTS5 + HRR 双层检索模式值得关注，特别是信任评分自动遗忘机制。但对于重度用户，Honcho 的多轮辩证推理可能是更强的选择。

**对我们系统的意义**：当前 Memory Graph 方案与 Holographic 思路类似（图谱 + 搜索），但缺少信任评分和自动遗忘。可作为未来优化方向参考。
