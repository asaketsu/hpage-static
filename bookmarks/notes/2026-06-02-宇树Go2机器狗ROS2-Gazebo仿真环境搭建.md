## 📌 一句话总结

宇树 Go2 机器狗的 ROS2 Humble + Gazebo 全量仿真环境搭建指南，涵盖裸机编译、Docker 部署、多传感器（D435i + VLP16 + L1 激光雷达）扩展，并配有键盘遥控与建图导航的完整链路。

### 2. 技术架构要点

**传感器配置（核心价值）**：

```
Go2 前置单目摄像头 → 模拟本体摄像头
前置 L1 激光雷达  → LaserScan + PointCloud2
外接 VLP16 雷达   → LaserScan + PointCloud2
D435i RGB-D（sensors:=true） → 深度 + RGB
Velodyne-IMU（sensors:=true）→ 惯性数据
```

**DDS 中间件**：使用 CycloneDDS（而非默认 FastDDS），通过 XML 配置文件优化通信，这是 ROS2 仿真中减少延迟的关键选型。

**构建系统**：`colcon build` + `CycloneDDS URI` 环境变量注入，标准 ROS2 工作空间模式。

### 3. 部署路径对比

| 方式 | 优点 | 缺点 |
|------|------|------|
| 裸机编译 | 性能最优，调试方便 | 依赖地狱，版本冲突风险 |
| Docker | 环境隔离，一键部署 | GPU 直通配置复杂，性能略损 |
| 飞书轻量版 | 适合新手快速上手 | 功能子集，不含 cafe 场景 |

### 4. 踩坑与解决方案

| 坑 | 解法 |
|----|------|
| 首次启动失败 | 场景资源下载未完成，再执行一次即可 |
| NVIDIA 驱动后亮度失控 | GRUB 添加 `acpi_backlight=vendor`（笔记本）或 `native` |
| Secure Boot MOK | 安装驱动时注册密钥 → 重启时 Enroll MOK |
| cafe 场景资源找不到 | `export GZ_SIM_RESOURCE_PATH=~/project/.../models` |

## 🔬 延伸思考

1. **仿真→实机迁移**：Gazebo 物理引擎与真实 Go2 的动力学差异（摩擦、延迟、传感器噪声），需要 domain randomization 弥补
2. **Jetson 部署路径**：仿真端（x86）训练策略 → ONNX/TensorRT → Jetson 实机推理，符合边缘 AI 部署范式
3. **多机协同**：Go2 的多机编队仿真可通过 ROS2 namespace + 多 launch 实现，具备研究价值
