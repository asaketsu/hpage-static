# Codex 驱动数字人视频全流程：8步流水线从选题到发布

> 来源：用户提供的工作流描述
> 主题：使用 Codex 作为唯一工具，完成数字人视频从选题到发布的全链路自动化
> 评分：⭐⭐⭐⭐⭐ (5/5) — 端到端数字人视频制作 SOP，可复现性极强

## 核心结论

**整条流水线全程在 Codex 中完成，不切换任何其他软件。** 8 个步骤覆盖从数字人形象生成到多平台发布的完整闭环，每个环节都有明确的工具选型和替代方案。核心设计思想：**Codex 作为统一编排层，通过 CLI/API 调用外部服务（TTS/视频生成/剪辑），而非人工切换工具**。

## 完整 8 步流水线

```
Step 1: 数字人形象生成（固定）
    ↓
Step 2: TTS 音色确定
    ↓
Step 3: 选题调研 + 口播文稿
    ↓
Step 4: 文稿→视频提示词 + B-roll 规划
    ↓
Step 5: 视频生成（数字人/B-roll）
    ↓
Step 6: 素材整合
    ↓
Step 7: 剪辑封装（ChatCut）
    ↓
Step 8: 封面+标题+发布元数据
```

### Step 1: 生成并固定数字人主播图片

| 维度 | 说明 |
|------|------|
| **目标** | 生成一个固定的数字人形象，后续所有视频中保持一致 |
| **关键** | "固定"——同一张人脸在所有视频中出现，建立品牌识别 |
| **工具** | Codex 内调用图像生成 API（DALL-E / Midjourney / SD 等） |
| **产出** | 一张固定的数字人主播肖像图 |

### Step 2: 确定音色（TTS 服务）

| 服务 | 特点 | 适用场景 |
|------|------|----------|
| **GeminiTTS** | Google 出品，多语言支持 | 需要中英混合的场景 |
| **ElevenLabs** | 业界标杆，音色自然度最高 | 高品质商业视频 |
| **其他** | MiniMax / F5-TTS / LuxTTS | 本地部署/成本控制 |

**关键决策**：选定音色后固定下来，和 Step 1 的形象绑定，形成数字人的"视觉+听觉"统一身份。

### Step 3: 调研选题 + 撰写口播文稿

| 维度 | 说明 |
|------|------|
| **风格** | 快节奏口播文稿——短视频黄金法则 |
| **流程** | 选题调研 → 素材搜集 → 文稿撰写，全在 Codex 内用 LLM 完成 |
| **要点** | 文稿是后续所有步骤的源头，决定了 TTS 时长、视频分镜数量、B-roll 需求 |

### Step 4: 文稿→视频提示词 + B-roll 规划

这一步是**整条流水线的核心转换层**：

| 输入 | 转换 | 输出 |
|------|------|------|
| 口播文稿（自然语言） | Codex 拆解 | 逐句视频生成提示词（每段口播对应的画面描述） |
| 同上 | 同上 | B-roll 规划（补充镜头/录屏/素材清单） |

**关键技术点**：文稿按语义分段，每段映射到一个镜头。Codex 同时规划哪些段落用数字人口播（Step 5 生成），哪些用 B-roll 补充画面。

### Step 5: 视频生成

| 后端 | 特点 | 调用方式 |
|------|------|----------|
| **FLOVA** | 数字人驱动（图片+音频→说话视频） | CLI/API |
| **即梦 / Dreamina** | 字节系 AI 视频生成 | CLI/API |
| **其他** | HeyGen / D-ID / Synthesia 等 | API |

**双轨生成**：
- 数字人片段：Step 1 固定形象 + Step 2 固定音色 → FLOVA 生成说话视频
- B-roll 片段：Step 4 的提示词 → 即梦/Dreamina 生成补充画面

### Step 6: 整合素材

| 素材类型 | 来源 |
|----------|------|
| 数字人片段 | Step 5 (FLOVA) |
| 录屏 | 手动/Codex 自动录屏 |
| B-roll | Step 5 (即梦/Dreamina) |

**拼接逻辑**：按 Step 4 的分镜规划，将数字人片段和 B-roll 交替排列，形成完整视频叙事线。

### Step 7: 剪辑封装（ChatCut）

| 处理项 | 说明 |
|--------|------|
| **音频** | 对齐 TTS 音轨与视频帧 |
| **动效** | 转场/字幕动画/关键帧 |
| **中英字幕** | 自动生成双语字幕（Whisper + 翻译） |
| **成片封装** | 最终输出标准化视频文件 |

**ChatCut** 是这条流水线的核心剪辑工具，作为 Codex 的 CLI 后端。

### Step 8: 封面 + 发布元数据

| 产出 | 规格 |
|------|------|
| **封面图** | 4:3 和 3:4 两种比例（适配横屏/竖屏平台） |
| **标题** | SEO 优化，含关键词 |
| **简介** | 视频描述 |
| **标签** | 平台标签体系 |

## 工具链全景

| 步骤 | 首选工具 | 替代方案 | 调用方式 |
|------|----------|----------|----------|
| 1. 形象生成 | 图像生成 API | DALL-E / Midjourney / SD | API |
| 2. TTS | GeminiTTS / ElevenLabs | MiniMax / F5-TTS / LuxTTS | API |
| 3. 文稿 | Codex + LLM | — | 内置 |
| 4. 提示词 | Codex + LLM | — | 内置 |
| 5. 视频生成 | FLOVA + 即梦 | HeyGen / D-ID | CLI/API |
| 6. 整合 | Codex 脚本 | FFmpeg | CLI |
| 7. 剪辑 | ChatCut | — | CLI |
| 8. 封面 | 图像生成 API | Canva API | API |

## 💡 对我们的借鉴分析

### ✅ 已有能力对照

| 流水线步骤 | Hermes 现有能力 | 差距 |
|------------|----------------|------|
| TTS | ✅ LuxTTS + F5-TTS（语音克隆） | 无差距 |
| 文稿 | ✅ LLM + 新闻聚合 skill | 无差距 |
| 视频生成 | ❌ 无 FLOVA / 即梦 API 集成 | **需开发** |
| 剪辑 | ❌ 无 ChatCut 集成 | **需开发** |
| 字幕 | ⚠️ 有 Whisper (STT)，但无字幕文件生成 | 需扩展 |
| 封面 | ⚠️ 有图像生成 skill，但无 4:3/3:4 自动适配 | 需扩展 |

### 🔥 关键启发

| 启发点 | 内容 |
|--------|------|
| **Codex 作为统一编排层** | 不切换软件，全部通过 CLI/API 调用——这和 Hermes 的 Agent 编排思路一致 |
| **形象+音色固定策略** | Step 1+2 的"固定"设计是数字人品牌化的关键 |
| **文稿→提示词的转换层** | Step 4 是最核心的 AI 能力——把自然语言文稿拆解为视频分镜 |
| **双轨视频生成** | 数字人片段 + B-roll 分开生成再拼接，比单一生成灵活 |
| **ChatCut 作为 CLI 后端** | 剪辑工具的 CLI 化是全流程自动化的关键一环 |
