摘要

传统观点认为投机解码（Speculative Decoding, SD）对 MoE 模型效果有限——EAGLE 原论文报告 Mixtral 8x7B 仅获得 1.5x 加速，而 Dense 模型可达 ~3x。然而 2025-2026 年的一系列研究彻底推翻了这一认知：MoESD（NeurIPS 2025 Spotlight）证明在中等 batch size 下，MoE 反而从 SD 中获益更多，最高达 2.29x 加速（Qwen2-57B-A14B）。核心原因在于 MoE 的低算术强度（arithmetic intensity = k/N，k 为激活专家数，N 为总专家数）使其在更大 batch 范围内保持 bandwidth-bound，而 SD 验证步骤在 bandwidth-bound 时几乎"免费"。随后 MoE-Spec、EVICT、Jakiro、SP-MoE 等论文分别从专家预算、自适应验证、Draft 多样性、预取流水线等角度优化，形成了 MoE 投机解码的完整方法论。本文系统梳理六大前沿方向，建立与已有知识（投机解码四代演进、MoE 路由机制、蒸馏压缩）的深度关联。

一、核心发现

1.1 反直觉的结论：MoE 比 Dense 从 SD 中获益更多

MoESD（NeurIPS 2025 Spotlight, arXiv:2505.19645）的核心贡献：

  • MoE 的低算术强度是其 SD 优势的根源。Dense 模型的算术强度约 50-100 FLOPS/byte，而 MoE 仅为 k/N × Dense（如 k=2, N=64 时仅约 3%）。这意味着 MoE 在更大的 batch size 范围内保持 bandwidth-bound
  • "目标效率"（Target Efficiency）新指标：传统 SD 优化只关注接受率 α，但 MoESD 引入 target efficiency = T_AR / T_SD，综合衡量 SD 对目标模型前向传递次数的节省。即使 α 很高，如果 target efficiency 低（验证步骤激活了太多专家），加速也会被抵消
  • 稀疏度越高，SD 收益范围越广：随着 MoE 设计趋势向更高稀疏度发展（如 DeepSeek-V3 的 256 专家选 8 个），SD 有效的 batch size 范围不断扩大
  • 实验数据：Qwen2-57B-A14B 在 A100 上实现 2.29x 加速（中等 batch size），验证了理论预测

1.2 专家路由时间相关性降低验证成本

Cohere 技术报告（2026-04）量化了三个关键因素：

  1. 专家路由时间相关性（Temporal Correlation）：连续 token 的路由路径高度相关，导致验证阶段多个 token 激活的专家联合（union）远小于 worst-case。实际加载的专家数 ≈ 单 token 激活数的 1.3-1.8 倍，而非理论的 K × batch_size
  2. 共享专家比例（Shared Expert Ratio f）：DeepSeek 系列的共享专家减少了 routed 部分的比例，在低 batch 时降低验证成本，但会提高有效 k/N，使模型更早进入 compute-bound
  3. 降低 k/N 的双重收益：更少的激活专家/总专家比，既保持低算术强度，又在高 batch 时仍保持 bandwidth-bound

1.3 MoE-Spec：Expert Budgeting 解耦投机深度与内存成本

MoE-Spec（arXiv:2602.16052）的关键创新：

  • 问题：SD 的 draft tree 越大，不同分支激活不同专家，验证时需要加载的专家联合急剧增长，导致内存压力和带宽消耗抵消加速收益
  • 方案：Training-free 的 expert budgeting——每层设置固定专家容量上限，只加载贡献最大的专家，丢弃长尾低频专家
  • 原理：利用了 MoE 验证中的"幂律特性"——top-4 专家通常覆盖 80-90% 的验证路径，剩余专家只贡献 10-20% 但占 50% 的加载开销
  • 效果：比 EAGLE-3 baseline 提升 10-30% throughput，且可以灵活调节精度/延迟权衡

1.4 EVICT：自适应 Draft Tree 截断

EVICT（arXiv:2605.00342）的无参数自适应方法：

  • 核心洞察：不是所有 draft token 都值得验证。随着 draft tree 变深，边际 token 的"性价比"（接受概率 × 节省的延迟 / 验证成本）递减
  • 方法：在验证前截断 draft tree，仅保留 cost-effective 的前缀。利用 draft model 的信号估计候选 token 的价值，结合离线 profile 的验证成本
  • 特点：Training-free、Hyperparameter-free、Lossless（不改变输出分布）
  • 效果：比自回归解码快 2.35x，比 EAGLE-3 平均快 1.21x
  • 兼容性：已集成到 SGLang 高性能图执行框架

1.5 Jakiro：用 MoE 增强 Draft Model 的多样性

Jakiro（arXiv:2502.06282）换个角度——不是优化目标 MoE 的验证，而是用 MoE 增强 draft model 本身：

  • 问题：传统 tree-based sampling 中，同一层级的候选 token 来自相同特征表示，导致候选之间高度相关，限制多样性
  • 方案：在 draft model 中引入 MoE 层，不同专家独立生成预测，解耦候选之间的相关性
  • 混合推理策略：前几个 token 用自回归解码（精度优先），后续 token 切换为并行解码 + 对比特征增强（速度优先）
  • 效果：在 MT-bench 上平均 2.84x 加速（对比 EAGLE-2 的 2.46x），树立了新的 SOTA

1.6 SP-MoE：投机解码 + 专家预取联合优化

SP-MoE（arXiv:2510.10302）针对 CPU-offloading 场景：

  • 问题：MoE + SD 的组合会放大 GPU 内存压力和 CPU-GPU 带宽竞争。验证时多 token 激活的专家联合远超单 token
  • 投机专家预取：利用 draft model 和 target model 的路由结构对应关系，在 draft 阶段预测验证时需要的专家，提前从 CPU 预取到 GPU
  • Cutoff-layer 策略：基于经验 profile 和解析延迟模型，限制每层预取深度，确保刚好及时可用而不浪费带宽
  • 异步流水线：预取线程 + 批量 I/O 隐藏加载延迟
  • 效果：TPOT 加速 1.07-3.5x（跨多数据集、环境和 MoE 模型）

二、技术原理解析

2.1 MoE 投机解码的理论基础

标准投机解码的加速比为：

Speedup = E[接受token数] / (1 + T_draft/T_target)

对于 Dense 模型，T_target 主要取决于 batch size。当 batch 增大到 compute-bound 时，验证的额外计算成为瓶颈，SD 收益递减。

对于 MoE 模型，关键区别在于：

  • 权重加载主导延迟：MoE 的总参数巨大但只激活少量专家，延迟瓶颈是加载 k 个专家的权重（bandwidth-bound）
  • 验证的"半免费"特性：验证 K 个 draft token 时，由于路由时间相关，实际只需加载少量额外专家（≈1.3-1.8x 单 token 的专家数），但验证了 K 个 token
  • 算术强度模型：MoE 的 roofline model 中，k/N 越小，bandwidth-bound 的区间越大，SD 验证的"免费"窗口越宽

MoESD 的理论模型引入 target efficiency η：

η = T_AR / T_SD = (f_batch × N_experts_per_token) / (f_batch × union_experts + overhead)

当 η > 1 时 SD 有效，MoE 的低 k/N 使 η > 1 的 batch 范围远大于 Dense。

2.2 专家预算机制（MoE-Spec）

Draft tree 的验证过程中，每个 token 激活 k 个专家，但 tree 的多个分支可能激活不同专家。假设 draft tree 有 D 层、每层 B 个分支：

最坏情况 union_experts = min(k × D × B, N)
实际 union_experts ≈ k × D^0.6（路由相关性）

MoE-Spec 的 budgeting 设定每层最多加载 C 个专家（C < N），按以下优先级选择：

  1. 统计当前 draft tree 中每个专家的覆盖路径数
  2. 按覆盖数降序排列
  3. 加载 top-C 个专家，其余路径的 token 用 fallback 策略（重新路由到已加载的最近专家）

关键：这种截断是 lossy 的，但实验显示 C = N/2 时精度损失 < 0.1%，而吞吐提升 20%+。

2.3 Draft Tree 截断机制（EVICT）

EVICT 的自适应截断基于 cost-benefit 分析：

对于 draft tree 中位置 k 的 token t:
  benefit(t) = P_accept(t) × (k - k_reject) × T_target_saving
  cost(t) = P_reach(t) × Δ_experts(t) × T_load_expert

保留条件: benefit(t) / cost(t) > threshold

其中：
- P_accept(t) 由 draft model 的置信度估计
- Δ_experts(t) 由离线 profile 得到（每个位置平均新增多少专家）
- threshold 自适应调整，确保整体不增加延迟

四、Actionable Insights

  1. vLLM/SGLang MoE 推理配置：当前 vLLM 已原生支持 EAGLE-3 + MoE 投机解码。Red Hat 实测 gpt-oss-120B MoE 模型用 EAGLE-3 在 vLLM 上降低 19.4% 的每百万输出 token 成本（SWE-bench 代码任务），200 并发仍有效。建议在我们自己的 MoE 推理服务中启用
  2. MoE-Spec 的 Expert Budgeting 思路：可以集成到 Hermes 的推理优化 skill 中。对 DeepSeek-V3 这类大 MoE，budgeting 设为 top-50% 专家即可获得显著吞吐提升
  3. Draft model 选择指南：对于 MoE 目标模型，draft model 应优先选择延迟低而非精度高。小型 Dense model（如 Qwen2.5-0.5B 为 Qwen2-57B-A14B 做 draft）比同系列小 MoE 更好——因为 Dense draft 的延迟更稳定
  4. 投机解码 + 量化 MoE 的组合：量化（INT4/FP8）使 MoE 更 bandwidth-bound → SD 收益可能更大。值得在 Qwen3-30B-A3B + AWQ 上实测验证
  5. 美团 LongCat 的启发：LongCat-Flash-Lite（685 亿参数，激活 29-45 亿）通过 N-gram 嵌入 + 推测解码协同，实现了 500-700 token/s。draft model 使用常规嵌入层规避 N-gram 查找开销，这种"非对称 draft"思路值得借鉴

五、待深入的问题清单

  1. Expert Choice 路由 vs Token Choice 路由对 SD 的影响：Token Choice 的路由时间相关性有利于 SD；Expert Choice 按专家选 token，时间相关性可能更弱
  2. 量化 MoE + SD 的精确收益：INT4 量化后 k/N 不变但权重加载带宽降 4x，是否使 SD 的"免费验证"窗口更大？
  3. Draft model 也是 MoE 的情况：如果 draft 和 target 都是 MoE，路由预测的准确度如何？Jakiro 方案的实际部署成本
  4. MLA（Multi-head Latent Attention）+ MoE SD：DeepSeek 的 MLA 已经压缩了 KV Cache，SD 对 MLA-MoE 的收益是否有变化
  5. 高并发（>200 batch）下 MoE SD 的收益衰减点：Cohere 报告的带宽-计算切换点在哪？对不同 GPU 架构（H100 vs A100）的差异
  6. MoE-Spec budgeting 与 Expert Parallelism 的交互：EP 下专家分布在不同 GPU，budgeting 可能减少跨卡通信
  7. SSD（异步投机-验证）+ MoE 的叠加效果：SSD 的 5x 加速是 Dense 上的结果，MoE 上能否保持
  8. 端侧 MoE 推理的投机解码：SMoLPU 的 122µJ/token 能耗数据是否可在其他端侧平台复现
