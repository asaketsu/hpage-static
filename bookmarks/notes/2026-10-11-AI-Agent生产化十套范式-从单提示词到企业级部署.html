一、内容整理

1.1 核心命题

Stripe 的编码 Agent 每周合并 1000+ PR；Uber 70% 的 PR 来自 Agent；Spotify 累计合并 250 万条自动化维护 PR——但没有一家公司用单一 Agent。每家公司都是一组 Agent，按任务分别设计。作者精读 70+ 篇 Stripe/Uber/DoorDash/Shopify/Meta/Microsoft/Cloudflare 工程博客，归纳出 10 套生产级 Agent 配置（setups）。

1.2 所有 Agent 的公共内核

  • OpenAI 三件套定义：Model（推理决策）+ Tools（可调用函数）+ Instructions（行为规则）
  • Anthropic 更短："Agent 通常只是基于环境反馈在循环中使用工具的 LLM"
  • 关键洞见：模型是最小的部分。公司真正花数月打磨的是周围的一切——harness：循环（调用→执行工具→回填结果→重复）/ 上下文与记忆 / 沙箱 / 工具访问（MCP 网关）/ 护栏（默认只读+花费上限+人工审批）/ 验证（测试、lint 或第二 Agent 检查）

1.3 Workflow vs Agent + 五种模式

  • Workflow：模型和工具跑在预定义代码路径上；Agent：模型自己决定步骤。生产中大多混用——Stripe 的 "blueprint" = 固定步骤（lint/push）夹 Agent 循环
  • 五模式：提示链 / 路由 / 并行化（同任务多次执行对比）/ 编排者-工人 / 评估者-优化者

1.4 单 Agent 还是多 Agent

微软 Azure SRE Agent 的教训：首版 100+ 窄工具 + 50+ 子 Agent，数据转移链超过 4 跳几乎必败。重组后只剩几个通用 Agent + 5 个核心工具，9 个月独立处理 35,000+ 事故。拇指法则：只有当第二个 Agent 做真正不同的事（如检查第一个的工作）时才拆分。

1.5 十套配置速览（建法 × 案例 × 数据）

# 配置 建法要点 案例（数据）
1 后台编码 Agent Slack/工单触发→预热沙箱→固定步骤夹 Agent 循环→验证器先跑→人审合并 Stripe Minions（1000+ PR/周）；Shopify River（1/8 PR 共著，30 天 3536 PR）；Spotify Honk（LLM judge 否决 1/4 越界会话）

5 安全 Agent 证据包先行（纯代码收集）→多专科并行→猎手与检查者用不同模型→引用代码级校验 Cloudflare（四专科+综合 Agent，禁取新内容只能用批准词表）；Figma（便宜模型路由+纠错回写 steering file，解决时间 -71%）；Shopify Dispatch（6 周 300+ 发现≈$40 万赏金等价，全扫 $50-300）
6 数据分析 Agent 知识层优先（表描述/指标定义/示例查询）→先检索后写 SQL→用户自身权限跑→真实问题 eval 集 DoorDash Vera（20 万数据集，eval 通过率 43%→90%，同模型 harness 加分 2.60 vs 2.16）；Notion Data Scout（数据团队请求 -80%）；OpenAI（6 层上下文，600PB）
7 客服 Agent 小模型路由→成本阶梯（代码/RAG/全 Agent）→专科子 Agent→每答案三查→LLM judge 日审采样 Lyft（新客服 Agent 建设 6 月→2 周）；DoorDash（幻觉 -90%，合规事故 -99%）；Coinbase CEEcil（确定性处理器秒答）
8 研究 Agent 主 Agent 存计划防长跑失忆→并行工人各管一角→压缩摘要→独立引用核对 pass Anthropic（Opus 主+Sonnet 子，内测胜单 Agent 90.2%，但 15× token——token 量解释了 80% 性能差）；Harvey（合同红线 53%→87%，延迟 +47%）；Perplexity（BrowseComp 40.7%→83.8%）
9 知识 Agent（第二大脑） 短结构化知识文件（~1000 token）→Agent 构建+批评者审→事实过期机制→错则自修补丁回放旧案 Meta 部落知识（4100 文件→59 个上下文文件，覆盖 5%→100%，工具调用 -40%）；Meta 组织二脑（每问题 token -80%）；Notion Lore（有记忆 102/149 vs 无 82/149）
10 定时自动化 Agent cron 起新会话→只读+vault 凭证→书签记忆断点→偏好/状态两分记忆→存在性检查防重发→单次预算封顶 Anthropic（每日简报 $5/run 上限）；GitHub Agentic Workflows（markdown 编译成 Actions，只读默认+安全输出）；微软（定时任务 4.5/5 分 vs 事故响应 1.7/5 分——窄而重复是 Agent 的甜点区）

1.6 十套配置的六条公共铁律

  1. 独立的检查者——干活的 Agent 永不自己评分（Spotify LLM judge / DoorDash 证伪 pass / Shopify 换模型验证）
  2. 模型之前先用代码——取数、跑检查、收证据全用普通代码，模型只做需要判断的部分
  3. 默认只读——改动真实世界的动作全走人工（draft PR/审批按钮/计划签字）
  4. 每个结论必须有证据——没有日志行/查询/来源支撑的结论直接丢弃（Meta 架构级强制引用）
  5. 按任务收窄权限——每个任务只给必需工具
  6. 真实测试用例——过往事故/问题/PR，每次变更后重放

二、查询拓展

2.1 与 Anthropic《Building effective agents》的同源与增量

本文的五模式（提示链/路由/并行/编排/评估者-优化者）直接继承 Anthropic 2024 年 12 月那篇经典，增量在于：每套配置配了 2025-2026 年的真实生产数据（成本/覆盖率/人工推翻率），把"模式"升级成了"带度量衡的配置模板"。Cloudflare $0.98/次审查、DoorDash $4.79/flag 这类数字此前散落在各博客，本文首次聚合。

2.2 "Token 量解释 80% 性能差"的深意

Anthropic 研究系统的数据（多 Agent 胜 90.2% 但 15× token）与业界 2026 年共识互证：多 Agent 系统的主要收益来自并行上下文容量，而非推理分工。这与本系统此前记录的 Orchestration Era 判断一致——上下文带宽是第一性约束。

三、归纳总结

3.1 一句话总结

模型是容易的部分，模型周围的 setup 才是让它工作的东西——这是十条配置、六条铁律、十家公司全部收敛的结论。

3.2 生产化成熟度光谱

玩具级      单提示 + 通用工具 + 乐观信任
           ↓
工程级      固定 workflow 夹 Agent 循环 + 验证器 + 人审
           ↓
生产级(本文) 六铁律全开: 独立检查者/代码先行/只读默认/
           证据强制/窄权限/真实用例重放 + 单位经济学度量

3.3 选型决策树（从"最烦的事"倒推）

  • 小工单淹没 → 后台编码；PR 审查积压 → 代码审查；一处改动×500 文件 → 迁移
  • 被告警吵醒 → 值班 SRE；每天同样的数据问题 → 数据分析；每天同样的客服问题 → 客服
  • 每天早上查五个工具 → 定时自动化。起步一律：窄、只读、带一个检查者。

四、趋势判断

趋势1：Agent 竞争单位从"模型能力"转向"harness 质量"

DoorDash Vera 的对照实验是铁证：同一模型，换 harness 后 eval 通过率 43%→90%。预测：2027 年企业采购 Agent 的评估表里，模型列会退化为占位符，harness 六件套（沙箱/记忆/网关/护栏/验证/度量）成为 RFP 主战场。

趋势2：多 Agent 泛滥后必然回摆到"少而通用"

微软从 50+ 子 Agent 砍到几个通用 Agent 的案例，加上"4 跳必败"的量化边界，标志着 2024-2025 年"多 Agent 编排热"的退潮。预测：子 Agent 数量会成为架构审查指标，超过个位数需要书面论证。

趋势3：知识层（第二大脑）是下一个挖坑方向

Meta 部落知识（覆盖率 5%→100%、工具调用 -40%）和 Notion Lore（102 vs 82/149）证明：给 Agent 喂结构化短知识文件，收益大于换更强模型，且成本是一次性的。预测：企业 AI 预算中"知识工程"科目将从零起步快速增长，与 eval 投入并列。

五、关联分析

5.1 与本系统六层 Harness 架构的对照

本文的 harness 六件套（循环/上下文记忆/沙箱/工具访问/护栏/验证）与本系统 harness-architecture skill 的分层几乎一一对应——互为东西方实践印证。差异点：本文补充了单位经济学度量（$0.98/审查）这一层，值得作为第七件套补进自有框架。

5.2 与 Cron 自动化实践的直接映射

Setup 10（定时自动化）的五要点——书签记忆断点/偏好状态两分/存在性检查防重发/单次预算封顶——与本系统 evolution-gate.sh 的 marker 封存、monitor 确定性输出、spend cap 实践完全同构。Anthropic 的"报告失败源也算交付"原则可直接吸收进 morning-briefing。

5.3 与 Agent-Omit/上下文省略谱系的呼应

研究 Agent 的"压缩：工人只返回短摘要而非全部阅读内容"与本系统记录的 Agent-Omit 上下文省略模式同源。Anthropic 15× token 成本结构提示：并行化收益与上下文成本是同一枚硬币的两面，路由决策要按问题价值定价。

5.4 与确定性护栏（deterministic-guardrails）的互证

"Code before the model"与 Cloudflare 安全 Agent 的"证据包先行"都是同一原则：确定性代码负责可确定性的事，模型只留给判断。这与本系统三条铁律（验证器输出纯确定性/LLM 唤醒必须被门禁）完全一致。

六、金句摘录

「The model is the easy part. The setup around it is what makes it work.」— 模型是容易的部分，周围的一切才让它工作

「The agent never decides it's done, the tests do.」— Agent 永不自己宣布完成，测试说了算（迁移 Agent 状态机）

「The goal is a compass, not an encyclopedia.」— 知识文件要的是指南针，不是百科全书（Meta 1000 token/文件）

「Narrow, recurring jobs are where agents shine.」— 窄而重复的工作才是 Agent 的闪光区（微软：定时 4.5/5 分 vs 事故 1.7/5 分）

七、行动启示

  • 直接可抄的六铁律清单：下次自建任何 Agent 前过一遍——独立检查者？代码先行？只读默认？证据强制？窄权限？真实用例？
  • 可立即安装的起步件（文中给出仓库）：claude-code-action（后台编码）、gstack /review（审查）、superpowers 迁移技能（worktree 并行）、trailofbits/skills（安全 42 插件）、gpt-researcher（研究）、anthropics daily-brief（定时）
  • 度量维度补课：给自己 Agent 补单位经济学（每次运行成本/中位时长/人工推翻率）——本文所有案例都用这三件套汇报
  • 子 Agent 数量纪律：新增子 Agent 前先问"它是否在做真正不同的事（如检查对方）"，否则合并

八、拓展应用推荐

  • 给团队赋能：十套配置表可直接当内部选型菜单——按"最烦的事"列匹配，一页纸决策
  • 给评测体系：六铁律可转成 Agent 生产化 checklist（CI 门禁化），与真实用例重放组成发布前双卡
  • 给知识管理：Meta "59 个上下文文件" 的压缩比（4100:59≈70:1）为团队知识库瘦身提供量化基准
  • 研究方向：Anthropic "token 量解释 80% 性能差" 的单变量归因值得深挖原论文，可能推出多 Agent 系统的成本-性能帕累托前沿

九、指南分析

作为一篇 70+ 信源的综述，写作范式三点：

  1. 配置模板化而非案例罗列：每套 setup 用统一骨架（做什么/怎么建/谁在用/从哪起步），10 套排下来模式自然浮现——比"十大案例"式文章多了可复用性
  2. 每个论断带度量衡：不给"大幅提升"，给"43%→90%""$0.98/次""0.6% 推翻率"——数字密度是综述可信度的来源
  3. 结尾降维打击：不劝你建十套，给"最烦的事→选一套"的决策树 + "窄/只读/带检查者"三词起步法——把信息量收敛成行动指令
