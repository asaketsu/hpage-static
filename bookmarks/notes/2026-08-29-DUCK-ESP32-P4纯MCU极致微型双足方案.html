1. 三大硬骨头与破局（源文档 §一 照录）

# 瓶颈 破局
1 算力断崖：双核 RISC-V 400MHz 比 RK3566 弱 10-20×，跑不动 ONNX/FP32 放弃 ONNX → ESP-DL + INT8 QAT；MLP <50KB，推理 5ms→<1ms
2 总线带宽：1Mbps 半双工轮询 15 舵机 >20ms 破 50Hz 红线 2Mbps + SyncWrite（~2.5ms）+ 关键帧抽样（每周期读 3-5 髋/膝/踝，其余分帧后台）
3 内存墙：768KB SRAM 捉襟见肘；PSRAM 延迟高 分区钉死：控制变量全在 SRAM；PSRAM 只放权重/日志/Wi-Fi 栈；推理张量绝不用 PSRAM（延迟 ×3-5）

2. 硬件（源文档 §2 照录）

BOM（~587g / ~¥400-450 / 峰值 26.5W）

模块 选型 重量 功耗
主控 ESP32-P4-WIFI6-DEV-KIT 裁切（P4+C6） ~15g ~1.5W
舵机 飞特 STS3215 ×15（金属齿轮） ~150g ~25W 堵转
IMU BMI270 / ICM-42688-P 双 SPI ~2g ~5mW
电源 2S LiPo + 双路 BEC ~120g -
结构 碳纤/3D 打印极简骨架 ~300g -

电源树关键点

  • 舵机轨 7.4V 直连 + 1000µF×2 吸堵转浪涌
  • 主控 5V/3A 独立高频降压（TPS5430 级），与舵机轨物理隔离共地不共正——防反电动势击穿 P4
  • P4 ADC 实时监测，<6.8V 触发安全降级
  • 电平：STS3215 TTL ↔ P4 3.3V，必须半双工收发器（74LVC1G125/FE-URT-1）
  • 关键优化：RMT 外设或 UART 硬件 RS485 模式做自动方向切换，消除软件切换微秒延迟

3. 软件架构（源文档 §三 照录，FreeRTOS 替代 Linux+Rust）

任务分配（双核 HP CPU）

核心 任务 优先级 周期 职责
Core 0 Task_ControlLoop 25 严格 20ms 读 IMU/关节 → ESP-DL 推理 → 安全过滤 → 批量下发；此核禁 Wi-Fi 中断
Core 1 Task_WiFi_RPC 10 事件 C6 SPI 数据 → JSON-RPC 意图 → 共享内存（互斥）
Core 1 Task_ServoRead 15 5ms 异步轮询非关键关节
Core 1 Task_SafetyMonitor 20 10ms 电压/温度/看门狗；Core 0 死锁 → 接管舵机阻尼趴下
LP Core DeepSleep_Wake - 中断 RTC 唤醒、低压优雅关机

控制环时序（20ms 预算）

1. SyncWrite 15 路（2.5ms @2Mbps）
2. 读 6 关键关节：位置+负载（3.5ms）
3. IMU SPI DMA（<0.5ms）
4. 观测拼接 + ESP-DL INT8 推理（<1ms）
5. 安全过滤（<0.2ms，纯 C 无除法）
→ vTaskDelayUntil 绝对唤醒
合计 ~7.5ms / 20ms（37.5%）—— 余量健康

ESP-DL 推理要点

  • PC 端 PyTorch → esp-dl 工具链 INT8 QAT 量化 → .cpp 数组烧 Flash/PSRAM
  • 推理张量 heap_caps_malloc(MALLOC_CAP_INTERNAL|MALLOC_CAP_8BIT) 钉死内部 SRAM
  • 多策略热切换：7 动作权重存 Flash/PSRAM，切换只传权重指针，不重建模型

硬件级安全（APM + TWDT）

  • APM（访问权限管理）：禁 Core 1（Wi-Fi）与 LP 核访问舵机 UART 寄存器——硬件层面保证"只有控制核能控电机"（robotd 特权隔离的 MCU 等价物）
  • TWDT：ControlLoop 50ms 超时 → SafetyMonitor 立即接管发"扭矩关闭/阻尼"

4. 风险与妥协（源文档 §六 照录）

风险 级别 对策
Sim2Real 难度剧增（STS3215 齿隙/摩擦更明显；P4 跑不动摩擦补偿网络） 🔴 MuJoCo 极精细建模 STS3215 物理特性；或 PID/摩擦前馈混合 RL
放弃高级视觉（CSI/ISP 有但跑不动 VLA/SLAM） 🟡 定位"运动控制底座"，视觉交外部主机 Wi-Fi 6 下发意图
开发门槛高（FreeRTOS/C + ESP-DL 量化 + 总线时序） 🟡 嵌入式功底要求极高；参考 references/esp32_port_guide.md
