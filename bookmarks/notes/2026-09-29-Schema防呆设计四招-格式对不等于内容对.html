一、事故开箱：格式对≠内容对

报销区间"3月15日到3月2日"（结束早 13 天）——Schema 校验全绿入库。校验器只证明两个字段都是合法日期字符串，不证明内容对。 填沟的办法不在校验层，在 Schema 设计本身。

四种"合法但离谱"（半年脏数据日志归纳）：

姿势 案例 为什么校验器瞎
①枚举外强转 priority 给"非常重要"/"P0"/"急!!!" string 类型合法，下游按三值分发直接懵
②数值范围离谱 金额 999999999；置信度自信写 1.5 number 合法，算钱时爆炸
③字段间自相矛盾 已取消订单：取消原因 null+支付金额 350 每字段单看都对，拼起来是谎言
④幻觉填充 不知道签署地就编"北京市" 格式完美内容虚构，长得跟正确答案一样

核心认知转变：Schema 不是"把字段类型写清楚"，是替模型预先挡枪——你写得越松，枪就越多。

二、防呆四招（往 Schema 里塞）

  1. 能枚举就别裸写：取值可预估一律 enum。实战细节：枚举值用英文小写比中文稳（模型对 "high" 的准确率明显高于"高"，中文枚举偶尔出变体）
  2. 数值必须戴镣铐：number 必带 minimum/maximum。写前自问"物理合理边界在哪"——置信度天生 0-1、金额不为负不上亿。"模型吹牛也得在牛圈里吹"
  3. 字段冗余自洽（最反直觉）：故意让关键字段多输出一份"理解说明"。日期区间加必填 nights——模型为填它必须自己算区间，负数被 minimum:0 拦下。用冗余换可校验性，交叉验证白捡一个抓手
  4. 必填要狠，禁填要更狠：required 之外，明确禁止编造——抽不到的字段输出 null（type 含 "null"）+description 写"禁止推测"。"不给模型体面的'我不知道'出口，它就编一条路"

三、Schema 之外垫一层自洽校验（L3）

跨字段业务逻辑 Schema 表达不了，十几行 Python 跑在"校验通过之后、入库之前"：日期倒挂/晚数不符/已取消有支付金额。作者线上 ~20 条规则，平均每周拦 3-4 条"合法但矛盾"——每一条进库都是事故。

三层防线各管各的，缺一层漏一类：

格式层(JSON Schema 语法) → 管语法
防呆层(enum/边界/锚点/null) → 管单字段合理性
自洽层(业务规则) → 管字段间逻辑

⚠️ 最大陷阱：上了 Schema 校验就宣布"结构化输出解决了"——半年后库里躺着一批绿灯放进来的脏数据。

四、账

Schema 从"字段+类型"升级到防呆版 <1 小时；之后三个月人工修脏数据工单从每周 5-6 个降到≈0。一小时换三个月清净。

定位：上游"三件套"（约束解码+自动修复）管"怎么输出合法 JSON"；本篇管"合法 JSON 内容怎么不跑偏"。

五、💡 对我们的价值分析

✅ 已在做的

  • 三层防线 ≈ 我们验证门禁分层（语法检查→语义检查→行为验收）的同构；"别把校验通过当质量合格" = "exit_code=0 且 tests>0 才算完成"
  • 枚举/边界约束实践：训练判据按家族定制（tag 防猜错）、iron-rules 14 条铁律=防呆层

六、内容整理（归纳总结与关联分析）

归纳总结：校验管格式、Schema 防呆管内容、自洽层管逻辑——三层各管各的。四招=enum 堵强转（英文小写稳）/min-max 戴镣铐（先问物理边界）/冗余锚点换可校验性（nights 让模型自己算）/null 出口治幻觉（禁止推测+体面的不知道）。ROI：<1h Schema 升级换 3 个月零工单。每周 3-4 条合法但矛盾的拦截率是真实生产数字。

关联分析：这是 9 月"显式契约化"元趋势（达索/ROSClaw/EBTO/Jev 四篇的归纳命题）在数据层的落点——enum/边界/锚点/null 就是数据契约的四件套，与 Jev 决策契约（state/rubric/逃生口/阈值）完全同构：都是把"什么算对"从运行时判断提前到设计时声明。航空领域映射：适航构型管理的数据项定义表（935/957）本质就是防呆 Schema——字段枚举/单位边界/必填禁填百年前就在做，LLM 工程在重新发明航空数据纪律。与 Harness Engineering 篇"规则编码两次"（GUIDE+CHECK）互证：description 是 GUIDE，enum/min-max 是 CHECK。

八、趋势判断

  1. "Schema 即提示词"成为共识：description 的措辞质量直接影响输出质量——Schema 设计与 prompt 工程合并为同一学科
  2. 冗余自洽锚点会标准化：类似 nights 的派生字段校验将成为 LLM 结构化输出库的内置模式（预测 API 层出现 cross-field validation 声明式支持）
  3. null 出口从技巧变规范："允许模型说不知道"会成为行业输出规范的一部分——与 Agent 领域 NOT_EVALUATED（ROSClaw）同源同构
  4. L3 自洽层是下一批创业切口：业务规则引擎×LLM 输出的组合（每周拦 3-4 条事故的量级在千级客户下=刚需）
