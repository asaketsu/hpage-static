一句话总纲

Qwen3-VL-2B（SigLIP-2 视觉编码器 + DeepStack 多层视觉注入 + 原生 256K 上下文）+ LLaMA-Factory（v0.9.4 起支持）= 12GB 显存跑 LoRA 多模态指令微调的完整流程：图文数据格式（images 字段+一问一答）→ YAML 一条命令训练 → 显存三板斧（max_pixels/cutoff_len/QLoRA）→ 三坑防御（没看图猜答案/幻觉/训练验证撞脸）。核心纪律：问题必须依赖图片信息，验证集按"来源"切分而非随机。

一、内容整理

1.1 选型

  • 模型：Qwen3-VL（2025-11 发布，原生多模态）——2B/4B/8B 三档；2B 档 12GB 显存可训（入门），8B 做产品
  • 框架：LLaMA-Factory——数据转换/LoRA 注入/训练循环全封装，配置文件即开训
  • 任务定位：指令微调（喂"图片+问题"学会按业务口径回答），不是教认新东西；LoRA 只更新小部分参数

1.2 数据格式

{
  "images": ["pics/menu.jpg"],
  "conversations": [
    {"from": "human", "value": "这张菜单有什么招牌菜？"},
    {"from": "gpt", "value": "招牌是酸菜鱼，中辣，推荐两人份。"}
  ]
}

要点：①问题必须依赖图片信息（纯文本可答=没教看图）②数据量参考 LLaVA 配方：对齐几十万图文对，指令微调几万~十几万条起步 ③图像预处理：统一短边/JPG/PNG/超大图降采样——动态分辨率下一张 4000px 长截图吃上千 token，混几张训练成本翻倍

1.3 训练配置（YAML 全文照抄）

model_name_or_path: Qwen/Qwen3-VL-2B-Instruct
template: qwen3_vl
finetuning_type: lora
lora_rank: 64
lora_alpha: 16
dataset: menu_qa
max_pixels: 51200        # 显存开关1：图像分辨率(token数)
cutoff_len: 2048         # 显存开关2：序列总长
per_device_train_batch_size: 2
gradient_accumulation_steps: 4
bf16: true
flash_attn: fa2
learning_rate: 2.0e-4
num_train_epochs: 3

llamafactory-cli train menu_vl.yaml 一条命令开训。2B 单卡 A100 一小时一轮。

视觉编码器冻结策略：默认冻结（只动语言模型+投影层）。解冻的两个场景：①图像域与训练分布差太远（如显微镜照片）②效果卡住且数据已确认没问题。取舍：先冻着跑基线，不足再解冻，一次只解一层找最小改动。

1.4 显存账本与三板斧

三板斧按性价比排序：降 max_pixels（一张高清图顶几十张低清）→ 降 cutoff_len/batch → 上 QLoRA（4-bit 量化+LoRA，8B 压回一张卡）。另加 freeze_vision_tower: true 再省一截（代价：图文对齐更新变慢）。

1.5 评测与三坑

坑 症状 防御
没看图猜答案 分数好看但图根本没看（问题模式雷同，答案背下来了） 挑训练没见过、答案藏在图里的样本人工过
幻觉 图上三把椅子答四把 单独攒"图上有什么/没什么"是非题逐条看
训练验证撞脸 同批照片拆两边，模型记得图→分数虚高 按"来源"切分：同文件夹/同批拍摄只进一边

评测双通道：公开基准（TextVQA/GQA）看大盘 + 人工看图抽检看质量——前者跌=方向错，后者错=细节糙，两个信号分开看。

二、查询拓展

2.1 与本机 08-19 Unsloth+LLaMA-Factory 笔记的衔接

08-19 笔记已覆盖 LLaMA-Factory 的文本微调路径（全方法流），本文补上多模态分支（template: qwen3_vl / images 字段 / freeze_vision_tower）——两篇合起来是 LLaMA-Factory 完整使用手册。

2.2 与 Jetson 的关系

Qwen3-VL-2B 的 12GB 起步要求 vs Jetson Orin 8GB 统一内存：直接训不行，QLoRA 压缩后边缘试探可行（与本机"不在 Jetson 跑重型训练"策略一致——管线就绪，实跑留待其他机器）。

2.3 与"小模型蒸馏"笔记的方法论呼应

同日蒸馏笔记的"数据门禁六项"与本文"三坑防御"同构：输入真实/输出正确/边界样本 ↔ 问题依赖图片/答案藏在图里/按来源切分——微调的成败都在数据，不在模型。

三、归纳总结：流程速查

① 选型：Qwen3-VL-2B + LLaMA-Factory（12GB 起步）
② 数据：images 字段+一问一答；问题必须依赖图；按来源切分
③ 配置：YAML 一条命令；max_pixels/cutoff_len 是显存总开关
④ 训练：LoRA 基线（视觉塔冻结）→ 不足再逐层解冻
⑤ 显存三板斧：max_pixels ↓ → cutoff_len/batch ↓ → QLoRA
⑥ 评测双通道：公开基准（方向）+ 人工看图（细节）
⑦ 三坑：猜答案（答案藏图里样本）/ 幻觉（是非题）/ 撞脸（按来源切）

四、趋势判断

趋势 1：多模态微调门槛降至消费级，垂直视觉场景将批量出现

依据：12GB 显存=一张入门卡/笔记本；LLaMA-Factory 全封装使流程"照抄可复现"——与 08-18 小模型 LoRA 实证（0.8B 生产级抽取）同一趋势：微调从大厂专属变成小团队/个人的常规武器，垂直视觉场景（票据/菜单/设备照片/医学影像）会像当年 RAG 一样批量落地。

趋势 2："图根本没看"将成为多模态微调的第一大坑，评测方法论先行者赢

依据：本文坑一是最深陷阱（分数与能力脱钩）——与评测三部曲"构造效度"问题同构：TextVQA 高分≠你的场景看图。自建"答案藏在图里"的验证集会从建议变成标配纪律，正如回测领域的样本外验证。

六、拓展应用推荐

  1. 飞机损伤照片识别（候选）：蒙皮裂纹/紧固件缺陷照片 + 检修口径问答——本文流程可直接套（视觉域与预训练分布差异大，需解冻视觉塔场景）
  2. 技术手册图理解：nativePDF-structurer 输出的 visual_regions + "图中设备编号含义"问答——与 08-25 nativePDF 笔记联动
  3. 票据/菜单类 MVP：文章原场景，12GB 卡可完整复现——练手首选
  4. Jetson 侧：训练不在本机跑（资源策略），推理部署（2B 量化后 Jetson 可载）是本机角色
