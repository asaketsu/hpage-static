DUCK-Pi_5：把 Microduck 类双足机器人移植到 Raspberry Pi 5（8GB）

来源：飞书 wiki 双文档（移植策划书 + robotd 深度解读）→ 已落地为完整工程项目。
项目落点：~/uclaw/project/DUCK-Pi_5/（Rust workspace + 配置 + 脚本 + 硬件 + 六篇文档）
一句话核心：最大挑战不是算力（50Hz 预算占用仅 ~25%），而是重量（+50g / +7%）与纯净供电；软件上"只换腿不换脑"——重写 ServoBus 硬件抽象层，上层全部保留。

1. 硬件方案

1.1 重量预算（第一优先级）

部件 重量
RK3566 核心板（原） ~20 g
Pi 5 裸板 ~48 g
主动散热器 ~25 g（薄铜片可省至 ~8g）
净增重 +45~55 g（+7%）

对策链：仿真先行（URDF 代入新质量，域随机化 ±10~15% 大概率覆盖 +7%）→ 安装位下移（骨盆最低处压重心）→ 减重散热 → 电池对冲（2S 2000→1500mAh）。

1.2 供电系统（第二优先级）

铁律：Pi 5 与舵机电源物理隔离——舵机堵转瞬间压降会直接复位 Pi 5。

2S/3S LiPo ─┬─ BEC 5V/6A（LC滤波+470µF+100µF）→ Pi 5
            └─ 舵机轨 6~7.4V 直供 15 舵机（共地不共正）
INA219 @ I2C → 电压 <6.4V 触发坐下/阻尼保护

续航：23W 总负载 / 11Wh（2S 1500mAh）→ 25~30 分钟（比原方案短 1/3，需明示预期）。

1.3 舵机总线（核心电路改造）

方案 延迟 推荐
A. 原生 UART + 74HC126/241 半双工 最低（15 路轮询 3~4ms） ⭐⭐⭐⭐⭐
B. USB 转 TTL +1~2ms 调试期可用
C. PCA9685 I2C PWM 低 总线舵机不适用

15 路大概率为 TTL 半双工串行总线舵机（Feetech STS 类，推断）。

2.1 robotd 的安全设计（源自 doc2 解读）

  • 唯一执行权威：只有 robotd 能控电机；padd/btd/手机/手柄只发"动作意图"（Unix Socket + JSON-RPC 2.0）
  • 控制面/数据面分离：上层崩溃/OTA 中断，robotd 仍维持安全姿态——这是 OTA 自动回滚的前提
  • Rust 选型理由：无 GC 抖动（20ms 周期不被打断）+ 零成本抽象 + 内存安全（不能崩溃的安全关键进程）+ Tokio async
  • 通信选型对照：共享内存（耦合高❌）/ ROS2 DDS（太重❌）/ gRPC（开销高❌）/ Unix Socket + JSON-RPC（✅ <1ms）

2.2 Sim2Real 工程亮点（面向部署的训练设计）

  • 舵机物理建模：Backlash 齿隙（双足站立抖动元凶→策略学会过冲补偿）+ 电压敏感（扭矩∝电压²，域随机化含电压变量）+ 位置控制模式（安全过滤在位置空间裁剪）
  • 多模态策略热切换：装轮子→另一套 RL 策略（切换连续性/安全约束差异/触发可靠性）
  • MuJoCo Warp：单卡并行数千环境，步长精度与传统 MuJoCo 一致

2.3 50Hz 实时预算（Pi 5 vs RK3566）

环节 RK3566 Pi 5（A76 ≈2.5×A55）
舵机反馈读取 3~5ms ~3ms
ONNX MLP 推理 2~5ms 0.5~1.5ms
安全过滤 <1ms <0.5ms
舵机写入 2~3ms ~2.5ms
合计 / 20ms 8~14ms ~7ms（35%）

7.5 硬件定案（2026-08-29 下午增补：STS3215 + FE-URT-1）

用户指定执行器与总线方案，本节为增量定案（非源文档内容），协议细节已对照权威源码核验。

定案内容

项 定案 关键理由
执行器 FEETech STS3215（12V 版，C047 类）× 15 FE-URT-1 板 9~12.6V 输入；7.4V 版 C001 接 3S 必烧
总线接口 FE-URT-1 驱动板（ST/SC 通用 TTL 转换） 板载自动收发方向 → 免 GPIO17 方向脚、免 74HC126/241 分立电路
供电 3S 锂电（9.9~12.6V）→ 板载 DC IN 统一供 15 舵机 动力+信号同板隔离；Pi 5 走独立 BEC 5V（共地不共正）
电平 板上跳线置 3.3V Pi 5 RP1 非 5V 容忍
预算变化 ¥900~1300 → ¥2000~2550（STS3215×15 为主增量） 协议确认 + 免方向电路 + 官方调试生态

协议核验（对照 huggingface/lerobot 源码，修正 3 处真 bug）

项 确认值 证据
帧头 FF FF lerobot feetech.py _broadcast_ping 收包匹配
校验 ~(ID+LEN+CMD+P) & 0xFF，无 +1 同上 L390（原 Rust 实现误用 Dynamixel 补码+1）
应答帧 含 ERROR 字节：FF FF ID LEN ERROR DATA CHK ping 应答 status_length=6
SyncWrite LEN 4+3N = 49 LEN 语义 = CMD+参数+CHK
寄存器 Torque=40 / Goal_Position=42 / 反馈区 56~63 lerobot tables.py STS_SMS_SERIES_CONTROL_TABLE
位置单位 0..4095 ↔ 0..360°（0.088°/step，中位 2048） tables.py sts3215 → 4096 分辨率

代码影响（全部完成并回归通过）
