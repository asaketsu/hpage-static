核心要点

1. 把 Claude 当独立工程师，别当结对伙伴 ⭐⭐⭐

  • 旧模式（4.6）：粗需求 → plan模式 → 边聊边补细节 → 结对编程
  • 新模式（4.7）：第一轮就把任务说透（意图+约束+验收标准+文件路径），一次到位
  • 原因：4.7 每轮用户输入都触发更多推理，多轮追加 = token浪费 + 质量下降
  • 借鉴到 Hermes：给 agent 的指令要一次给足上下文，不要分多轮补

2. xhigh = 新默认 effort level

  • 新增 xhigh 档位（high 与 max 之间），日常推荐
  • 各档位感受：
  • medium/low：CI/轻量agent任务，4.7低档比4.6同档更强
  • high：性价比之选，多session并发/预算紧时
  • xhigh：官方主推，设计API/写schema/迁移/review 等吃智力活
  • max：慎用，回报递减+易overthinking，留给极端复杂场景

3. Adaptive Thinking 替代固定思考预算

  • 4.7 不再支持手动 thinking budget
  • 模型自动判断：简单query直接答，复杂才深度推理
  • 手动调参用自然语言：
  • 多想："Think carefully and step-by-step; this problem is harder than it looks"
  • 快答："Prioritize responding quickly rather than thinking deeply"

4. 悄悄变的默认行为

行为 变化 影响
回复长度 挂钩任务复杂度，简单查询变短 需明说长度要求
工具调用 先推理再动手，频率下降 需在prompt中说明何时用工具
Subagent 更克制，默认少开 多文件并行需显式写规则

Subagent 规则（可直接抄进 CLAUDE.md）：

Do not spawn a subagent for work you can complete directly. Spawn multiple subagents in the same turn when fanning out across items or reading multiple files.

5. 长跑任务终于能跑

  • 跨多文件复杂修改、模糊线索debug、跨服务review、几十步收敛的agentic任务 → 可以放手让它跑
  • 建议：effort 保持 xhigh，看第一轮能走到哪一步

借鉴到 Hermes Agent 体系

  1. 指令质量：一次给足上下文的思路，直接适用于 delegate_task 的 context 写法
  2. Subagent 策略：我们的 delegate_task 已经在用类似的扇出模式，可以进一步优化 prompt
  3. Effort level 类比：不同任务用不同模型（重型→GLM-5.1，轻量→flash）已经是这个思路
  4. Auto mode：类似我们的 notify_on_complete + background=true 模式
