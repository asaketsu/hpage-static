步态奖励设计两篇：STL 时序逻辑规约与双足步态条件课程

内容整理

围绕 DUCK-Pi_5 下次训练的另一条修复路线：如何用结构化奖励打破"站立局部最优"。两篇论文分别给出规约驱动（STL）与课程驱动（gait-conditioned + multi-phase）两条互补路径。

论文一：Learning Gait-Aware Quadruped Locomotion with Temporal Logic Specifications（Google Barkour, arXiv:2607.00442, CoRL 投稿）

核心思想：把步态写成 Signal Temporal Logic (STL) 规约，用定量 robustness（满足裕度，正值=满足、负值=违反）直接作为 dense reward。相比手调加权奖励：可解释（每项对应一条人类可读的要求）、可诊断（失败 rollout 可归因到具体被违反的谓词）。

方法管线：
1. 三个速度档专家模型各收集 50 条轨迹（500 步、dt=0.02s、弃前 2s 暖机段）
2. 特征提取：跟踪误差、CoM/CoP、roll/pitch、足接触 c_ℓ(t)、步态周期 T 与占空比 DF（接触信号上升沿估计）、对角相位误差
3. PSTL 模板分三类：共享安全 φ_safe（力矩限制 S1、roll S2、pitch S3、CoM 高度 S4、支撑接触数 S5）+ 速度跟踪 φ_track（T1/T2）+ 步态结构 φ_gait
4. 参数从专家轨迹分位数拟合（99 分位给误差幅度上限，低分位给下限），避免过度惩罚短瞬态
5. 奖励 = 活动规约在窗口 H_g 上的 smooth robustness（walk H=30 步、trot/bound H=24 步，约一个完整步态周期）

关键工程细节：
- 模式切换用 Froude 数 定阈值：Fr = v²/(g·h)，{0.15, 0.74} 对应 Barkour 腿长 0.41m 的 0.7 m/s 与 1.7 m/s 换挡点
- 迟滞防抖：walk→trot 进入阈值 0.72、退出 0.65；trot→bound 进入 1.75、退出 1.45 —— 模式在边界附近抖动会引入奖励不连续、破坏学习
- 步态结构谓词示例：trot 要求窗口内 2 触地占比 ≥0.70 且对角纯度 ≥0.99；walk 要求 11 步窗口内必出现 ≥3 触地事件；bound 要求飞行占比 ≥0.04、前足单独支撑 ≥0.18、后足单独 ≥0.16、四足全触地限制在 [0.10, 0.30]
- 观测含 15 步（0.3s）本体感受历史 + 模式标志；动作为绝对关节位置 q_des = q_default + k_a·a
- 实测：MJX 并行 + 域随机化，STL 奖励比手调基线速度跟踪更紧、训练更稳

论文二：Gait-Conditioned RL with Multi-Phase Curriculum for Humanoid Locomotion（Unitree G1, arXiv:2505.20619）

核心思想：单一循环策略（LSTM actor + 非对称 critic）+ 步态 ID one-hot 条件化 + 奖励路由（reward routing）：gait mask 按当前步态 ID 选择性激活奖励项——走路激活摆动高度/直膝/拖脚惩罚，跑步激活蹬地/短触地，站立激活静止 bonus 并关闭步态项。消除多步态奖励互扰，单一策略内端到端学出站/走/跑/转换。

三阶段课程（仿人类运动发育）：
- Phase 1 只训 Walk：gait ID 固定，练出周期触地+足间隙+伸膝
- Phase 2 加 Stand 与 Walk→Stand（W2S）：‖v_c‖<0.1 进入 W2S，低速双支撑持续 1.5s 才切 Stand（迟滞防早切）
- Phase 3 加 Run 与 Run→Walk（R2W）：Froude 判据 Fr>0.5 切跑，减速后 R2W 持续 2.5s 完成平滑衰减
- 课程三轴：步态复杂度（走→站→跑→转换）、指令速度（低速到 4.0 m/s）、协调机制（路由/掩码/过渡混合渐进启用）

奖励系数表（照录关键项）：
- 共享：跟踪线速度 1.5 / 角速度 1.0、DOF 速度惩罚 -1e-3、碰撞 -10.0、动作变化率 -0.01、DOF 限位 -5.0、存活 bonus 0.15
- 手臂（仿生）：臂腿动量平衡 5.0（最大权重！抵消腿部角动量）、摆臂能量 0.3、肘相位跟踪 2.5、摆臂对称 2.0
- Walking：摆动高度惩罚 -15.0、触地 1.0、直膝 0.1、拖脚 -0.5
- Running：短触地 0.2、蹬地 1.0、前向速度 0.2、摆动高度 -25.0（比走路更狠）
- Standing：触地 2.5、基础运动 2.5、姿势上限 4.0、静止 bonus 2.0、足平贴 2.5
- W2S：摆动高度 -20.0、平滑减速 0.1；R2W：平滑减速 1.0、过渡到走速 0.5

真机验证：Unitree G1 上验证站立/行走/走↔站转换；仿真中跑与 R2W 成功。无需 MoCap、无 AMP、无蒸馏。

查询拓展

  • STL robustness 的 smooth 近似：softmin/softmax 温度参数选取、log-sum-exp 数值稳定性（原文 β 锐度：walk/trot 0.5、bound 0.1）
  • Froude 数换挡的生物学出处（Hildebrand；Alexander Jayes）与双足版本：人 walk-run 转换约 Fr≈0.5，与本文 G1 判据一致；DUCK-Pi_5 腿长约 0.14m 时对应 v≈0.83 m/s（若双足跑步需要）
  • reward routing 与 MultiCritic Actor Learning（单 actor 多 critic 头）的对比：mask 路由 vs 多 critic 分解，谁的 credit assignment 更干净
  • CPG/相位引导策略（phase-guided controller, Shao 2021）：与 gait ID 条件化的等价性——sin-cos 相位编码已含周期信息，gait ID 补充离散模式
  • rsl_rl 中实现 reward routing 的最小改动：reward 函数签名加 gait_id 参数、term mask 在 runner 层做

归纳总结

两篇论文对"打破站立局部最优"给出互补答案，共同点值得注意：

  1. 奖励必须含时序结构：单帧马尔可夫奖励（站得稳+能量低）天然偏向静止；STL 窗口语义（窗口内触地占比、相位误差、事件必现）与 gait-specific 奖励路由都在把"周期性运动"编码进学习信号
  2. 模式切换必须带迟滞：两篇独立采用 enter/exit 双阈值（STL 0.72/0.65、G1 1.5s/2.5s 持续时长）——模式抖动 = 奖励不连续 = 训练崩坏，这是工程铁律
  3. Froude 数是速度分档的普适锚：v²/(gh) 把不同体型机器人的换挡速度归一化，双足 0.5 分界与四足 0.15/0.74 都有生物学出处
  4. 专家轨迹的分位数拟合（STL 篇）把"调奖励系数"变成"从数据学系数"——50 条轨迹足够，这比手调可复现
  5. 单一策略多步态（两篇共同主张）优于多策略蒸馏：DUCK-Pi_5 当前"一个 velstand 策略"路线与之兼容，后续加站→走转换不需要推倒重来

趋势判断

  • 步态奖励设计正从"手调系数黑箱"向两个方向分化：形式化规约（STL/时序逻辑，可验证可诊断）与数据驱动拟合（专家轨迹分位数）；2026 年两者会合流为"模板 + 数据校准"
  • reward routing / gait mask 模式正在成为多步态单一策略的标准组件（与 MoE 化的 Perpetual Humanoid Control 路线竞争，胜在简单）
  • 仿生学奖励（直膝、摆臂动量平衡）证明：不追 MoCap 也能得到自然人形步态，reference-free 路线在真机 G1 上已闭环
  • STL 在 locomotion 的应用从导航/操作扩展到多步态控制，失败归因能力（违反了哪条谓词）对 sim2real 调试价值极高

关联分析

与 DUCK-Pi_5 的直接对接：
- 鸭子双足与 G1 人形同构：奖励路由 + 三阶段课程可平移——Phase 1 只训走（当前 velstand 等价物）、Phase 2 加站与走→站、Phase 3 按需扩展；gait ID 进观测 + 奖励项 mask 是最小侵入实现
- "站立奖励组"的存在（静止 bonus 2.0 + 姿势 4.0）反证：DUCK-Pi_5 白训的根因之一是没有给"走"独立的正奖励通道——速度跟踪项弱于能量惩罚项时，站立是必然解。STL 篇的触地占比谓词（窗口内 2 触地 ≥0.70）是可直接借用的"反站立"奖励：站着 = 触地占比 100% ≠ trot 目标 → robustness 为负
- Froude 数计算：鸭腿长约 0.14m，走跑分界 v = sqrt(0.5×9.8×0.14) ≈ 0.83 m/s；当前 velstand 目标速度若低于此值则纯走态即可，无需跑态奖励
- 迟滞双阈值直接可用于手柄速度指令的平滑（当前 duck_infer_pad_throttled.py 的 50Hz 节流场景）

与姊妹篇《RL熵坍缩修复三篇》互链：熵坍缩修复解决"探索死亡"（信号层），步态奖励设计解决"目标缺失"（奖励层）；DUCK-Pi_5 下次训练应两者并用——REPO 式 advantage 修正在前 1000 iter 保探索，STL/路由式步态奖励在后期塑形。

与 09-07 Transformer/MLP 等效性笔记互链：等效性成立的隐含前提是奖励结构能引导出目标行为；奖励本身有缺陷时，架构对比无意义——先把奖励修对，再谈架构。

拓展应用推荐

  1. DUCK-Pi_5 奖励重构（P0）：下次训练在 reward 配置中加窗口触地占比项（STL 篇 G4 谓词的简化版：滑动窗口内单双足交替触地占比 ≥ 阈值给正奖励）——这是打破站立局部最优的最直接杠杆，且与 mjlab reward 函数签名兼容
  2. gait ID + 奖励路由骨架（P1）：若后续要做站/走/转换多模式，G1 篇的 one-hot ID + reward mask 是最小侵入路径，Phase 1→2 课程先跑通站走切换
  3. Froude 换挡 + 迟滞指令平滑（P2）：真机部署脚本 duck_infer_pad_throttled.py 中给手柄速度指令加 enter/exit 迟滞（0.05 m/s 级），避免模式边界抖动
  4. STL 失败归因借鉴（P3）：训练日志中按谓词分解 robustness 曲线（哪条规约在违反），下次白训时可秒级定位"卡在哪个行为约束上"而不是只看总 reward

指南分析

奖励设计决策树（针对双足/小型机器人）：

  • 症状：reward 高但机器人不动（白训） → 奖励层修复优先：加触地交替占比项（STL 谓词式）或 gait 路由分离站立/行走奖励组；同时检查能量惩罚系数是否压倒速度跟踪（G1 表：跟踪 1.5 vs DOF 速度 -1e-3，量级差 1500 倍，能量项是形状修正不是主驱动）
  • 症状：多步态互扰、学出四不像 → gait ID 条件化 + reward mask 路由；模式切换迟滞双阈值
  • 症状：速度档位切换时策略崩 → Froude 数定换挡点 + enter/exit 迟滞；过渡期用 W2S/R2W 独立模式（持续 1.5~2.5s）平滑
  • 症状：步态不像自然步态（拖脚/蹲行） → 仿生奖励组：摆动高度惩罚（走路 -15、跑步 -25 的量级参考）、直膝支撑、动量平衡
  • 症状：训练能走但不稳 → 检查安全谓词权重（力矩/roll/pitch/CoM 高度），STL 篇的 robustness 曲线按谓词定位最紧的约束
  • 课程设计铁律：永远从单步态 Phase 1 开始；新增模式 = 新 Phase，不要一开始全模式混训（奖励冲突 + 探索不足双杀）
