## 一、内容详细整理

### 1.1 重要前置提醒

- **FP8 精度要求**：需要 **NVIDIA Ada Lovelace（RTX 4090/5090）或 Hopper（H100）及以上**架构。旧卡（RTX 3090）无法原生运行 FP8，需改用 BF16/FP16 权重
- **显存需求**：27B FP8 模型约需 **30-35GB 显存**。单张 RTX 4090（24GB）不够，需双卡或 A100/H100
- **依赖安装**：所有方法均需先安装对应库（原文命令使用本机 Scoop Python 路径，已泛化）

### 1.2 路线一：快速测试 / 对话推理（vLLM）

> vLLM 对 FP8 支持最完善，推理速度最快，适合部署 API 服务或批量测试。

**安装**：

```powershell
python -m pip install vllm
```

**完整代码**：

```python
from vllm import LLM, SamplingParams

# 指向本地下载目录
model_path = "./Qwen3.8-27B-FP8"

llm = LLM(
    model=model_path,
    quantization="fp8",          # 指定 FP8 量化
    tensor_parallel_size=2,      # 根据GPU数量修改，单卡设为1
    gpu_memory_utilization=0.9,
    trust_remote_code=True       # Qwen 模型必须开启
)

sampling_params = SamplingParams(temperature=0.7, max_tokens=512)

messages = [
    {"role": "user", "content": "请解释什么是量子纠缠，用通俗的语言。"}
]

outputs = llm.chat(messages, sampling_params=sampling_params)
print(outputs[0].outputs[0].text)
```

> ⚠️ 如果只有单张 24GB 显卡，vLLM 可能无法加载 27B FP8。此时建议换用 GPTQ/AWQ 4bit 量化版本，或使用 llama.cpp 方案。

### 1.3 路线二：研究 / 微调 / 自定义推理（Transformers + Accelerate）

> 适合需要修改模型结构、做 LoRA 微调、或集成到自定义 Pipeline 的场景。

**安装**：

```powershell
python -m pip install transformers accelerate torch
```

**推理完整代码**：

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_path = "./Qwen3.8-27B-FP8"

tokenizer = AutoTokenizer.from_pretrained(model_path, trust_remote_code=True)

# FP8 推理需要 CUDA 设备且支持 FP8
model = AutoModelForCausalLM.from_pretrained(
    model_path,
    torch_dtype=torch.float8_e4m3fn,   # FP8 数据类型
    device_map="auto",                  # 自动分配到多卡
    trust_remote_code=True
)

messages = [{"role": "user", "content": "写一首关于春天的五言绝句"}]
input_ids = tokenizer.apply_chat_template(messages, return_tensors="pt").to(model.device)

with torch.no_grad():
    output = model.generate(input_ids, max_new_tokens=256, do_sample=True, temperature=0.7)

response = tokenizer.decode(output[0][input_ids.shape[-1]:], skip_special_tokens=True)
print(response)
```

**LoRA 微调完整代码**：

```python
from peft import LoraConfig, get_peft_model, TaskType
from transformers import TrainingArguments, Trainer

# 在加载模型后添加 LoRA 适配器
lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=16, lora_alpha=32, lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"]
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()  # 通常 < 1% 参数可训练

# 后续使用 Trainer + Dataset 正常训练即可
```

> ⚠️ **微调注意**：FP8 权重本身不适合直接梯度更新。微调时建议将基座权重转为 BF16（`torch_dtype=torch.bfloat16`），仅 LoRA 部分参与训练。

### 1.4 路线三：消费级显卡 / CPU 混合推理（llama.cpp / Ollama）

> 如果显卡不支持 FP8 或显存不足，可将模型转换为 GGUF 格式，在消费级硬件上运行。

**步骤 1：转换为 GGUF**：

```bash
# 克隆 llama.cpp 并编译
git clone https://github.com/ggerganov/llama.cpp && cd llama.cpp
cmake -B build && cmake --build build --config Release

# 转换（FP8 → F16 → GGUF Q4_K_M）
python convert_hf_to_gguf.py ../Qwen3.8-27B-FP8 --outtype f16
./build/bin/quantize ../Qwen3.8-27B-FP8/model-f16.gguf \
    ../Qwen3.8-27B-FP8/model-Q4_K_M.gguf Q4_K_M
```

**步骤 2：Ollama 一键部署**：

创建 `Modelfile`：

```dockerfile
FROM ./Qwen3.8-27B-FP8/model-Q4_K_M.gguf
TEMPLATE "{{ .Prompt }}"
PARAMETER num_ctx 4096
```

运行：

```bash
ollama create qwen3.8 -f Modelfile
ollama run qwen3.8 "你好，介绍一下你自己"
```

### 1.6 最终建议（原文照录）

- **有 H100/A100/双4090** → 直接用 **vLLM** 跑 FP8，性能最优
- **要做微调或研究** → 用 **Transformers**，但微调时转 BF16
- **只有单张消费级显卡** → 放弃 FP8，转 **GGUF Q4/Q5** 用 Ollama 运行
- **验证完整性**：无论哪种方式，首次加载成功后检查 `config.json` 中的 `num_hidden_layers`、`vocab_size` 等参数是否与仓库页面一致，确保权重无遗漏

## 二、查询拓展

### 2.1 FP8 vs GGUF Q4：两种量化哲学

| 维度 | FP8 (E4M3) | GGUF Q4_K_M |
|------|------------|-------------|
| **量化方式** | 浮点 8 位（4位指数+3位尾数） | 整数量化 + K-quant 混合精度 |
| **精度损失** | 极小（几乎无损） | 轻微（Q4_K_M 是质量/体积平衡点） |
| **27B 模型体积** | ~27GB | ~16GB |
| **硬件要求** | Ada/Hopper+ 专用 FP8 单元 | CPU 亦可跑（AVX2/NEON） |
| **适用场景** | 数据中心/专业卡 | 消费级/边缘设备 |
| **生态支持** | vLLM/TensorRT-LLM | llama.cpp/Ollama/LM Studio |

**核心差异**：FP8 是"硬件原生支持的低精度浮点"（GPU 计算单元直接算），GGUF 是"软件层的整数量化"（CPU/GPU 都能算但效率不同）。

### 2.2 vLLM 参数深潜

- **`tensor_parallel_size=2`**：张量并行，把模型切到 2 张卡。27B FP8 (~27GB) 单张 4090 (24GB) 放不下，必须双卡
- **`gpu_memory_utilization=0.9`**：允许 vLLM 占用 90% 显存（剩余留给 KV cache 和激活值）
- **`trust_remote_code=True`**：Qwen 系列需要执行自定义 modeling 代码，必须开启（安全性考虑：只对可信来源开）
- **`quantization="fp8"`**：显式声明量化格式，vLLM 会加载对应的 FP8 kernel

### 2.3 torch.float8_e4m3fn 的含义

- **E4M3**：4 位指数 + 3 位尾数 + 1 位符号，动态范围小但精度高，适合前向推理
- **fn**：finite（不含 inf/nan 表示），推理场景够用
- PyTorch 2.1+ 原生支持此 dtype，但实际矩阵乘法仍依赖 CUDA 12+ 和 Ada/Hopper 硬件单元

## 三、归纳总结

### 3.1 决策树

```
你的硬件是什么？
├─ H100 / A100 / 双4090（30GB+ 显存）
│   ├─ 要部署 API 服务 → vLLM (FP8 直跑)
│   └─ 要微调/研究 → Transformers (微调时转 BF16)
├─ 单张 4090/5090（24GB）
│   ├─ 显存差一点 → vLLM + GPTQ/AWQ 4bit
│   └─ 稳妥方案 → llama.cpp GGUF Q4 + Ollama
└─ 30系及更早 / 更低显存（≤16GB）
    └─ llama.cpp GGUF Q4/Q5 + CPU/GPU 混合
```

### 3.2 显存需求速查表

| 模型版本 | 体积 | 最低显存 | 推荐路线 |
|----------|------|----------|----------|
| 27B FP8 | ~27GB | 30-35GB（双卡） | vLLM |
| 27B BF16 | ~54GB | 60GB+（A100 80G） | vLLM/Transformers |
| 27B GGUF Q4_K_M | ~16GB | 16GB 单卡 | Ollama |
| 27B GGUF Q5_K_M | ~20GB | 24GB 单卡 | Ollama/llama.cpp |

## 四、趋势判断

### 趋势 1：FP8 正在成为专业卡部署的标准格式

> 依据：vLLM 对 FP8 支持最完善 + NVIDIA Ada/Hopper 全面原生支持 + 27B FP8 相比 BF16 体积减半显存减半。数据中心场景 FP8 正在取代 FP16 成为默认选择（这与 snowboat 工程全景笔记 1.1.1 节的判断一致）。

### 趋势 2：消费级硬件的 27B 可用性持续改善

> 依据：GGUF Q4 让 16GB 显存可跑 27B；Ollama 一键部署把门槛降到 Modelfile 两行配置。随着量化算法改进（Q4_K_M → IQ4），消费级跑 27B 的质量损失在缩小。

## 六、拓展应用推荐

### 6.1 Jetson 场景适配（本机相关）

本机 Jetson Orin Nano（Ampere 架构，8GB 统一内存）**无法运行 27B 任何量化版本**：

- 27B GGUF Q4 需 16GB+，Jetson 8GB 远不够
- Jetson 的 Ampere GPU 也不支持 FP8（需 Ada/Hopper）
- **结论**：Jetson 只适合跑 Needle 2（14MB）这类端侧专用模型或更小的 Qwen（0.5B-3B Q4）——这与"不要在 Jetson 上跑重型 ML"的用户铁律一致

### 6.2 代码复用清单

- **vLLM 对话脚本**：可直接复用于任何 FP8 模型（改 model_path 即可）
- **Transformers 推理脚本**：chat_template 用法是标准范式，适用所有 Qwen 系列
- **LoRA 配置**：r=16/alpha=32/q_k_v_o_proj 是 Qwen 系列的标准配置，可直接套用
- **GGUF 转换命令**：FP8 → F16 → Q4_K_M 两步转换链适用于所有 FP8 发布的模型
- **Ollama Modelfile**：两行配置（FROM + PARAMETER num_ctx）是最小可部署单元

### 6.3 适合跟进学习
