ROS1 和 ROS2，对于新手哪个更适用于机械臂开发？

生成日期 2026-08-07

来源：微信公众号文章
发布日期：2026-08-07
核心结论：新手直接选 ROS2

一句话定义

2026 年 8 月时间点，ROS1 已于 2025 年 5 月 31 日 EOL，新手应直接选用 ROS2——从 Humble 或 Jazzy LTS 版本入手，配合 MoveIt 2 + ros2_control 进行机械臂开发。

内容整理

核心结论：新手应选 ROS2

基于以下关键事实：
- ROS1 Noetic 已于 2025 年 5 月 31 日终止生命周期（EOL）
- ROS2 生态已足够成熟，主流厂商全面支持
- 直接学 ROS2 避免未来迁移的技术债务

ROS1 与 ROS2 生命周期对比

ROS1 终止支持

ROS Noetic Ninjemys 是 ROS1 最后一个发行版，已于 2025 年 5 月 31 日正式 EOL。意味着：
- 不再接收安全更新和 Bug 修复
- 继续使用将带来技术债务和安全风险
- 遗留项目应制定迁移计划

ROS2 发行版支持周期

ROS2 采用偶数年 LTS、奇数年非 LTS 的发布策略：

发行版 发布日期 支持截止 类型 Ubuntu
Humble Hawksbill 2022.5 2027.5.31 LTS 22.04
Iron Irwini 2023.5 2024.12 非LTS 22.04
Jazzy Jalisco 2024.5 2029.5.31 LTS 24.04
Kilted Kaiju 2025.5 2026.12 非LTS 24.04
Lyrical Luth 2026.5 2031.5.31 LTS 26.04

LTS 提供 5 年官方支持，非 LTS 约 1.5 年。新手建议选 Humble（资源最丰富）或 Jazzy（支持至 2029）。

技术架构差异

通信中间件：DDS 取代 ROS1 自定义协议

特性 ROS1 ROS2
通信协议 自定义 TCPROS/UDPROS DDS（Fast DDS、Cyclone DDS 等）
发现机制 中央 Master 节点 分布式发现（多播/单播）
实时性 软实时 硬实时支持（需配置）
QoS 策略 无 丰富的 QoS 配置
安全性 无内置加密 SROS2 支持加密与认证

DDS 引入增加了学习复杂度，但带来了实时性、QoS 和安全性的本质提升。

MoveIt 2：机械臂运动规划演进

功能 MoveIt 1 MoveIt 2
运动规划 OMPL/CHOMP 同上，性能优化
实时伺服控制 有限支持 MoveIt Servo 完整支持
任务构造函数 实验性 成熟稳定
轨迹处理 基础 增强型时间参数化
笛卡尔路径规划 有限 完整支持

MoveIt Servo 是 MoveIt 2 的重要新特性，支持：
- 实时位姿伺服（150Hz+ 控制循环）
- 外部传感器集成（视觉伺服、力控）
- 拖动示教
- 手眼协调

这对需要手眼协调、视觉伺服或拖动示教的机械臂应用至关重要。

ros2_control：统一硬件接口框架

标准化硬件接口类型 + 典型控制器配置：

controller_manager:
  ros__parameters:
    joint_trajectory_controller:
      type: joint_trajectory_controller/JointTrajectoryController
      joints:
        - joint_1
        - joint_2
        - joint_3
        - joint_4
        - joint_5
        - joint_6
      command_interfaces:
        - position
      state_interfaces:
        - position
        - velocity

JointTrajectoryController 是机械臂轨迹执行的核心控制器。

学习曲线与入门路径

ROS2 学习难点

  • DDS 相关概念：QoS Profile、Discovery、Domain ID
  • 构建系统：colcon 替代 catkin
  • 启动文件：Python 替代 XML（更加灵活）

推荐入门路径

第一阶段：环境搭建（1-2 周）
- Ubuntu 系统准备
- ROS2 安装：wget http://fishros.com/install -O fishros && bash fishros
- 基础概念学习：Node、Topic、Service、Action

第二阶段：机械臂专项（2-4 周）
- ros2_control 学习（硬件接口标准）
- MoveIt 2 配置（Setup Assistant）
- 仿真环境搭建（Gazebo / Ignition / Mujoco ROS2）

第三阶段：实机操作（视硬件条件）

中文社区资源

  • 鱼香 ROS（FishROS）：一键安装 + 中文教程
  • 古月居（GuYueHome）：中文 ROS 教程社区
  • ROS2 官方中文文档

常见问题与解决方案

问题 原因 解决方案
节点无法互相发现 DDS Discovery 配置 检查 ROS_DOMAIN_ID；配置 CycloneDDS XML
QoS 不匹配导致消息丢失 发布者/订阅者 QoS Profile 不兼容 统一 QoS 策略（Reliable vs Best Effort）
colcon build 失败 依赖缺失/版本冲突 检查 package.xml 依赖；rosdep install
MoveIt 规划成功但不动作 控制器未启动/FollowJointTrajectory Action 未连接 检查 controller_manager 是否活跃

版本选择建议

场景 推荐版本 理由
追求稳定性 Humble 社区资源最丰富，问题解决方案多
追求新特性 Jazzy 支持至 2029，Ubuntu 24.04 原生支持
企业项目 Humble 或 Jazzy LTS 长期支持保障，避免技术债务

总结

ROS2 已成为机械臂开发的事实标准。对于新手，直接学习 ROS2 避免了未来迁移的技术债务，且当前 ROS2 生态已足够成熟。建议从 Humble 或 Jazzy LTS 入手，配合鱼香 ROS 和古月居的中文资源。

关键成功因素：
1. 选择 LTS 版本（Humble 或 Jazzy）
2. 从仿真开始（Gazebo/Ignition/Mujoco），再转实机
3. 掌握 ros2_control + MoveIt 2 两大核心框架
4. 善用中文社区资源（鱼香 ROS、古月居）

归纳总结

这是一篇面向新手的 ROS2 机械臂开发入门指南。核心价值在于：
1. 明确的版本推荐——Humble（稳）或 Jazzy（新），不要再用 ROS1
2. 三大核心框架——DDS（通信）+ MoveIt 2（运动规划）+ ros2_control（硬件接口）
3. 厂商支持全景——优傲/Franka/安川 + 国产遨博/节卡/艾利特
4. 可操作的入门路径——3 个阶段（环境搭建→机械臂专项→实机操作）

结合最新研究与技术变化

1. 与 OttoClaw 项目的关联

OttoClaw 使用 ESP32-S3 + FreeRTOS 控制舵机——是比 ROS2 更底层的嵌入式方案。ROS2 适合需要复杂运动规划（逆运动学、碰撞检测、轨迹优化）的多自由度机械臂，而 ESP32 方案适合 6 路舵机直接控制的简单场景。两者是不同层级的机器人控制栈。

2. 与 SO-ARM100 / servo-arm-control Skill 的关联

用户的 servo-arm-control Skill 涉及 6-DOF 机械臂的 DH 运动学和逆解。ROS2 + MoveIt 2 是这类机械臂的标准软件栈——如果要从纯 Python 运动学计算升级到工业级运动规划（含碰撞检测、轨迹优化、实时伺服），MoveIt 2 是必经之路。

3. 与具身智能方向的关联

具身智能（VLA/ActionHead/Gemini-Robotics）需要机器人执行物理动作。ROS2 是连接 AI 决策层和物理执行层的标准中间件——VLA 模型输出的动作指令通过 ROS2 Action/Topic 传递给 ros2_control 执行。

4. 2026 技术变化

  • ROS1 正式 EOL（2025.5.31）——迁移不再是选择题
  • MoveIt Servo 成熟——实时伺服控制成为标配
  • 国产机械臂全面支持 ROS2——遨博/节卡/艾利特
  • 仿真环境多元化——Gazebo / Ignition / Mujoco ROS2 三选一

趋势判断

  • ROS2 已成为机器人开发的事实标准——ROS1 EOL 后没有回头路
  • MoveIt Servo 实时控制是新焦点——从规划（离线）到伺服（在线）的范式转换
  • 国产协作机械臂生态成熟——遨博/节卡/艾利特全面 ROS2 支持，降低硬件门槛
  • DDS 是 ROS2 的核心复杂度来源——学习曲线陡峭但带来实时性/安全性本质提升
  • 仿真优先——先仿真后实机已成为标准学习路径

关联分析

  • 与 servo-arm-control Skill 的关联：DH 运动学 + 轨迹规划可以升级到 MoveIt 2
  • 与 dual-mcu-robot-architecture Skill 的关联：ESP32+STM32 双 MCU 架构可以扩展为 ESP32（底层舵机控制）+ ROS2（上层运动规划）的分工
  • 与 embodied-ai-control Skill 的关联：具身智能的 VLA 模型输出动作指令需要 ROS2 作为执行中间件
  • 与 OttoClaw 项目的关联：ESP32 是更轻量的方案，ROS2 适合复杂运动规划场景
