摘要

分析 HollowMan6/TinyML-ESP32 项目（黑胡桃实验室 TinyML 教程），包含 3 个 ESP32 端侧 AI 案例：姿态识别、语音唤醒、跳绳计数。核心发现是 3 个项目共享完全相同的训练→部署流水线。提取为通用 Python 训练框架，包含 IMU 预处理、音频 FFT 特征提取、Keras→TFLite→C 导出器，12 个单元测试全绿。

源项目三合一

项目 传感器 窗口 特征维度 类别 模型

统一流水线（3个项目完全一致）

数据采集(ESP32 串口→CSV) → 预处理(滑窗+展平) → Keras训练(Dense 2层)
    → TFLite转换 → xxd导出C数组 → ESP32 TFLite Micro推理(8KB arena)

5 个关键设计模式

  1. 加速度触发机制：|ax|+|ay|+|az| > 3.5g 才开始采集，极大降低功耗和误触发
  2. 统一 Dense 架构：2 层全连接足以处理简单分类，模型<4KB
  3. TFLite Micro 8KB arena：ESP32 上最小可行的推理环境
  4. xxd 导出：Linux 一行命令将二进制模型嵌入 C 代码
  5. 20% 随机切分验证：简单的 train/test split 防过拟合

💡 启发

  1. Dense 的力量：在特征维度足够低（<500维）时，2 层 Dense 比任何复杂架构都高效。嵌入式端侧推理不需要 CNN/Transformer，简单的全连接就够了。

  2. "3 个项目同一流水线"的价值：当 3 个不同任务（IMU/音频/计数）共享相同的架构，说明流水线本身是通用的。抽取为框架比复制粘贴更有长期价值。

  3. 加速度触发是嵌入式 AI 的核心模式：不要 24/7 跑推理，先用简单规则（加速度阈值）过滤大部分"无事发生"的帧，只在有事件时才启动 NN。

🔮 预判

  • 短期：此流水线可直接用于 Jetson + ESP32 协作场景（Jetson 训练→ESP32 部署）
  • 中期：加入 CNN/LSTM 选项提升时序分类精度，加入数据增强
  • 长期：量化感知训练(QAT) + 自动超参搜索 + ESP32-S3 双核加速
