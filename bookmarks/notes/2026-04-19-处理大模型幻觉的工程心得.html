问题场景

作者让大模型处理签证材料：分析家庭成员是否符合条件 + 填写签证申请表。结果：
- 只给出男主人分析，女主人和孩子被遗忘
- 识别不了申请表字段，或填错位置
- 结论：大模型对"值"的理解远优于对"结构/位置"的理解

核心痛点

1. 复杂文档破坏理解力

一份财务报告 = 8大章24节68小点 + 32张配图 + 10张表格。层级嵌套越多，AI 理解能力加速退化。

2. 长上下文 ≠ 长理解

"能容纳百万字"和"可理解百万字"是两码事。篇幅一长，模型顾头不顾尾。

3. 填表场景特别致命

内容填对但位置填错 → 手动修改比人工填还麻烦。

4. 不分模型

市面主流模型都有此问题，能力越差越明显。

根本原因（评论区补充）

观点 作者
LLM 注意力在长上下文中严重衰减，按语义边界切小块比 prompt 技巧都管用 teaguexiao
本质就是 Prompt Chaining + 反思模式（Reflection），当前 Agent 常用范式 easylee
可用 Embedding + 向量数据库做检索增强 Mantext1989

作者的解决方案：SnapFill

核心思路——将计就计，用工具补齐 LLM 短板：

  1. 树形结构拆分：按文档结构层级拆分章节（非按字数截断），保留源文档层级关系
  2. 区域识别隔离：把"工作经历""学习经历"等连续多行区域拆开，避免混淆
  3. 自动判断填充区域：根据用户画像判断哪些格子该填、哪些不用填
  4. 分批提交：每个章节独立提交 LLM 处理，避免理解力超载

效果：200个空格的用户信息表，1分钟填完，准确率 90%+，速度快 5-6 倍，节省大量 Token。

产品链接：https://www.gosnapfill.cn/

洞察与借鉴

对我们 Agent 系统的启发

  1. 结构化拆分是通用解法 — 不仅填表场景，所有长文档处理都适用
  2. 树形 > 平铺 — "按结构层级拆分"优于"按字数截断"
  3. 工具补短板 > 等模型进化 — Next Token Prediction 的底层范式不支持结构理解，工程手段比等 GPT-6 更靠谱
  4. Embedding + 向量库 是另一个方向 — 我们已有 hybrid-search skill

批判性思考

  • 文章本质是产品推广帖，但问题分析到位
  • 90% 准确率没有标注测试条件和样本量
  • "树形结构理解范式"具体实现未公开，技术细节不清
  • Embedding 方案（评论4）更通用，但需要额外基础设施
