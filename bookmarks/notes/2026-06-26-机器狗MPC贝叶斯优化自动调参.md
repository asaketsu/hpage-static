## 内容详细整理

### 核心问题

机器狗在陌生房间导航时，MPC（模型预测控制）控制器的权重参数（跟踪目标权重、控制输入权重、障碍物距离惩罚等）过去靠工程师**手动调参**。换到另一个房间，参数可能又不稳。

### 解决方案：贝叶斯优化自动调参

论文用**贝叶斯优化（Bayesian Optimization, BO）**在离线仿真中自动搜索 11 个 MPC 参数，替代人工调参。

### 硬件平台

| 组件 | 配置 |
|------|------|
| 机器狗 | Unitree Go2（定制） |
| 感知 | 3D LiDAR |
| 计算 | Jetson Orin Nano |
| 底层行走 | CHAMP 控制器（接收 /cmd_vel 速度命令） |
| 导航栈 | 完整运行在 Jetson Orin Nano 上 |

### 系统架构

```
LiDAR 点云 → 局部高斯占据栅格 → 导航图（拓扑连通关系）
                                    │
                                    ▼
A* 在滚动窗口生成局部路径 → 非线性 MPC → 速度命令 → CHAMP 控制器
                                    │
                                    ▼
              贝叶斯优化（离线仿真，TPE，11维参数空间）
```

### 11 个 MPC 参数

| 参数类别 | 具体参数 |
|---------|---------|
| 位置跟踪 | 位置跟踪权重 |
| 偏航跟踪 | 偏航跟踪权重 |
| 终端代价 | 终端代价权重 |
| 控制输入 | 控制输入权重 |
| Jerk 正则 | Jerk 正则化权重 |
| 障碍物权重 | 障碍物惩罚权重 |
| Sigmoid 形状 | Sigmoid 障碍函数形状参数 |

### 贝叶斯优化流程

```
1. 前 20 次：随机冷启动（Random Sampling）
2. 之后：TPE（Tree-structured Parzen Estimator）根据已有结果采样候选参数
3. 每次试验：启动完整 Gazebo 仿真，评估综合导航分数
4. 目标：找到一组参数 θ，让机器人在多种导航场景里的综合表现最好
5. 跨场景评分：不同场景的得分加权合成一个综合目标
```

### 核心公式（一句话）

> 找到一组 MPC 参数 θ，让机器人在多种导航场景里的综合表现最好。

### 关键结果

| 指标 | 手调 Baseline | BO 调参后 | 改善 |
|------|-------------|----------|------|
| 平均路径长度 | 33.84 m | 20.74 m | **-38.7%** |
| 到达时间 | 200.37 s | 94.25 s | **-53.0%** |
| 导航成功率 | 65.0% | 90.0% | **+25%** |
| 真实房间成功率 | 5/10 | 8/10 | **+30%** |

### E3 Warehouse 场景（未参与训练）

| 指标 | Baseline | BO 调参后 | 改善 |
|------|---------|----------|------|
| 路径长度 | 73.97 m | 41.07 m | **-44.5%** |
| MPC 求解时间 | 60.78 ms | 48.41 ms | **-20.4%** |

### 参数敏感性分析

使用 **Gaussian Process surrogate** 做参数敏感性分析：哪些参数一变，整体导航分数变化最快 → 这些参数就是最值得优先关注的旋钮。

### 局限性

1. **离线调参**：当前版本主要是离线调参，未来才会走向在线 BO
2. **参数空间边界**：BO 搜索只能在预设参数空间里找答案，如果真正好的控制器设计不在这个边界内，优化器也不会凭空发明出来
3. **环境表征**：当前版本主要是离线调参，未来需要更强的环境表征

## 查询拓展

### 相关技术

1. **MPC（模型预测控制）**：在滚动时间窗里同时考虑轨迹跟踪、控制输入和约束，不是只看下一步。对机器狗这种平台，动作不平滑会带来抖动、绕路甚至碰撞。

2. **贝叶斯优化（Bayesian Optimization）**：
   - **TPE（Tree-structured Parzen Estimator）**：BO 的核心采样算法，根据已有结果采样候选参数
   - **Gaussian Process surrogate**：用于参数敏感性分析
   - **Sample-efficient**：尽量少试几次，就找到足够好的参数

3. **CHAMP 控制器**：Unitree Go2 的底层行走控制器，接收 /cmd_vel 速度命令。

4. **高斯占据栅格**：局部窗口里用 LiDAR 构建占据栅格，表示环境中哪些位置被占据。

### 技术路线对比

| 方法 | 优点 | 缺点 |
|------|------|------|
| 手动调参 | 简单直接 | 换环境需要重新调，效率低 |
| 贝叶斯优化（本文） | 自动搜索，跨场景通用 | 需要仿真环境，离线调参 |
| 强化学习 | 端到端学习 | 训练成本高，安全性难保证 |
| 大模型端到端 | 泛化能力强 | 实时性差，不可解释 |

## 归纳总结

这篇论文的核心价值不是"贝叶斯优化有多新"，而是它抓住了机器人里很真实的一类问题：

> **很多系统不是没有理论控制器，而是理论控制器到了新环境，参数调不好就会变得很笨。**

如果以后机器人要走进更多陌生房间、仓库、园区和工厂，它们需要的不只是一个漂亮的 planner，也需要一种能把失败经验重新变成参数选择的方法。

### 关键洞察

1. **MPC 的痛点不在公式，而在权重**：跟踪目标要多重？控制输入要多省？离障碍物多近开始强烈惩罚？这些参数在一个房间里调好了，换到另一个房间可能又不稳。

2. **贝叶斯优化不是替代 MPC**：而是在离线仿真里反复试参数，找到一组跨场景通用的参数。

3. **跨场景评分是关键**：不是只在一个环境里把参数调到最好，而是把不同场景的得分加权合成一个综合目标。

4. **从仿真到真机的迁移**：真实房间实验从 5/10 提升到 8/10，说明仿真调参可以迁移到真实世界。

## 趋势判断

### 短期（1-2年）
- 贝叶斯优化在机器人控制参数调优中广泛应用
- 更多机器人平台（四足、轮式、机械臂）采用 BO 自动调参
- 仿真环境（Gazebo、Isaac Sim）与 BO 深度集成

### 中期（3-5年）
- 在线贝叶斯优化：机器人边运行边调参
- BO 与强化学习结合：BO 调参 + RL 策略学习
- 跨平台参数迁移：一个平台调好的参数迁移到另一个平台

### 长期（5-10年）
- 自调参机器人：机器人自动发现最优控制参数
- 与多模态大模型结合：大模型理解环境，BO 调参执行
- 从参数优化到架构优化：BO 不仅调参，还优化控制器结构
