## 核心论点

**Harness（执行系统）不会被模型吞掉，Memory（记忆）不是插件而是 Harness 的核心能力。谁控制 Harness，谁就控制 Memory；不拥有 Harness，就不真正拥有 Memory。**

---

## 五层论证结构

### 1. Harness 不会被模型完全吞掉

**背景变化**：Agent 构建方式从简单 RAG 链 → 复杂流程编排 → 完整 Agent Harness（Claude Code、OpenCode、Deep Agents 等）。

**常见误判**：模型越强，外部脚手架越少，最终被模型吸收。

**Chase 的反驳**：
- 2023 年需要的脚手架确实消失了，但被新的脚手架替代了
- Agent 的定义要求模型与工具、数据源、外部状态互动
- 只要互动存在，模型外就一定有系统负责调度、管理和约束
- Agent = 模型 + 工具 + 上下文 + 状态 + 执行环境 → 这个组合系统就是 Harness

### 2. Memory 不是插件，而是 Harness 的责任

**类比**：把 Memory 插到 Agent Harness 里，就像把"驾驶能力"插到汽车里一样。

**短期记忆**：对话消息、工具调用结果、大段上下文

**长期记忆**：跨会话偏好、历史行为、用户习惯、项目知识

**Harness 的设计问题**：
- 什么时候写入？
- 什么时候读取？
- 压缩后保留什么、丢弃什么？
- 如何暴露给模型？

**现状**：Memory 还很早期，很多 Agent MVP 甚至不做长期记忆（先求稳定完成任务）

**机会窗口**：早期抽象未稳定，谁掌握 Harness，谁更容易定义 Memory 形态

### 3. 闭源 Harness 会把 Memory 变成锁定

**三层风险**：

| 层级 | 情况 | 后果 |
|------|------|------|
| 轻 | 使用有状态 API，会话状态存在模型厂商服务器 | 换模型/供应商后，难以接续过去线程 |
| 中 | 使用闭源 Harness | 读写记忆、压缩上下文、存储中间产物的方式不透明 |
| 重 | 整个 Harness + 长期记忆藏在 API 后面 | 看不见 Harness，不拥有 Memory，不知道能否导出/迁移 |

**核心判断**：
> 过去切换模型相对容易，因为大多数模型 API 近似无状态。但一旦 Memory 进入系统，迁移成本完全不同——Memory 不是配置项，而是用户互动、偏好、语气、历史决策和业务上下文长期积累的数据资产。

### 4. Memory 是未来 Agent 的数据飞轮

**案例**：Chase 内部邮件助手被误删后，用同一模板重建，体验差很多——所有偏好需重新教。

**关键洞察**：
- 没有 Memory → Agent 容易被复制（同样的工具、模型、提示词即可）
- 有了 Memory → 积累用户交互和偏好的专有数据集 → Agent 越用越懂用户 → 产品越来越难被替代

**模型厂商动机**：
- 只靠模型本身未必能形成强锁定
- 但状态、压缩、长期记忆、用户偏好都留在平台内 → 锁定强得多

### 5. Open Memory，需要 Open Harness

**LangChain 推 Deep Agents 的原因**：
- 开源、模型无关
- 支持开放标准
- 可连接 Mongo、Postgres、Redis 等外部记忆存储
- 可自托管或部署在不同云上

**原则**：
- 模型可以替换
- 工具可以替换
- 数据库可以替换
- 但记忆不能轻易丢

## 深层含义

### 从"模型锁定"到"记忆锁定"

| 过去讨论的锁定 | 未来讨论的锁定 |
|----------------|----------------|
| 模型能力 | 状态 |
| 价格 | 记忆 |
| 接口 | 压缩摘要 |
| 上下文窗口 | 用户偏好 |
| | 跨会话连续性 |

### 分水岭判断

> 当 Agent 只是一次性工具时，Memory 不是核心问题。当 Agent 变成长期协作者时，Memory 就是产品本身的一部分。

### 真正含义

> 你要拥有的不只是调用模型的代码，而是 Agent 如何记住、如何忘记、如何迁移、如何持续学习的控制权。

---

## 与当前项目的关联

### 对 Hermes Agent 的启示

1. **Memory 系统是核心资产**：Hermes 的 memory 工具（MEMORY.md、USER.md）需要持续完善，这是长期竞争力
2. **Harness 控制权**：Hermes 是开源的，这本身就是优势——用户拥有自己的 Harness 和 Memory
3. **记忆迁移能力**：需要考虑跨实例/跨环境的记忆迁移方案，避免用户被锁定
4. **压缩摘要机制**：session_search 和 context-compressor skill 正在做这件事，需要持续优化

### 对 ESP32-S3 Smart Ambient Lamp 项目的启示

- 嵌入式场景下 Memory 形态不同（本地存储、设备偏好）
- 但原则一致：设备记忆（用户习惯、偏好设置）应属于用户，而非厂商云端
