一、内容整理

1. 核心思想：存图不存向量

对比 传统向量库（FAISS等） LEANN
存储策略 存下每个 embedding（768维 float32 ≈ 每条3KB） 只存剪枝后的图结构（CSR格式），查询时按需重算 embedding
核心技术 — graph-based selective recomputation（图选择性重计算）+ high-degree preserving pruning（保高度数剪枝）
存储（60M块 Wiki） 201 GB 6 GB（省 97%）
存储（400K 微信消息） 1.8 GB 64 MB
存储（780K 邮件） 2.4 GB 79 MB
存储（38K 浏览历史） 130 MB 6.4 MB
精度 基准 无损失（论文 claim）

为什么省：embedding 本体是大头，图结构很小；查询时只需要对候选路径上的少量节点重算 embedding（选择性重计算），而不是全库。高度数节点在图中保留（保高度数剪枝保证连通性/召回）。

2. 五大卖点

卖点 说明
🔒 隐私 数据不出本机，无云、无 OpenAI、无 ToS
🪶 轻量 图重计算消除 embedding 存储；CSR 格式压缩图存储
📦 可移植 整个知识库可拷贝/分享，个人 AI 记忆随身带
📈 可扩展 脏乱个人数据（传统向量库会崩的那种）轻松处理
✨ 无精度损失 同等检索质量

3. 项目示例使用说明（用户指定重点 ⭐）

LEANN 的杀手锏是 RAG on Everything——同一套 declarative API，十几种数据源开箱即用。全部示例在仓库 examples/ 与 apps/ 目录：

① 文档管理器（最简单入门，所有平台）

# data/ 默认带两篇论文+傲慢与偏见+华为LLM技术报告（中英混合）
python apps/paper_rag.py                    # 交互模式（不传 --query）
python apps/paper_rag.py --query "LEANN如何实现存储节省？"
  • 支持 .pdf / .txt / .md，任意目录直接指过去
  • 交互模式输入 quit 退出

② ColQwen 多模态 PDF（视觉语言模型检索）

# ColQwen2/ColPali 模型，文本+图表双通道理解，Apple Silicon MPS 加速
leann build --embed colqwen2 --source papers_dir
leann search --embed colqwen2 --query "架构图哪张讲了剪枝策略？"

适合含大量图表的论文/技术文档；详见 docs/COLQWEN_GUIDE.md

③ Apple Mail 邮件秘书（仅 macOS）
- 前置：系统设置→隐私与安全→完全磁盘访问权限授予终端
- 780K 邮件块 → 78MB；"像 Google 一样搜邮件"

④ Chrome 浏览历史时光机

python apps/google_rag.py --chrome-profile ~/Library/Application\ Support/Google/Chrome/Default
# Linux: ~/.config/google-chrome/Default

38K 条历史 → 6MB——浏览器历史变成个人搜索引擎

⑤ 微信聊天侦探

brew install sunnyyoung/tap/WeChatTweak-CLI   # 先装导出器
python apps/wechat_rag.py

40万条消息 → 64MB，跨语言搜多年聊天记录

⑥ ChatGPT / Claude 对话档案
- ChatGPT：Settings→导出数据（.zip/.html）→ 直接喂给 LEANN
- Claude：导出 .json/.zip → 同上
- "AI 对话史变成可检索知识库"

⑦ iMessage 历史档案（macOS）
- 数据源：~/Library/Messages/chat.db（SQLite）
- 需完全磁盘访问；或用备份库 --db-path 指定

⑧ MCP 实时数据源（Slack / Twitter 等）

npm install -g slack-mcp-server
python apps/slack_rag.py --mcp-server slack-mcp-server \
  --workspace-name myteam --channels general,eng --concatenate-conversations
# Twitter 书签同理：npm install -g twitter-mcp-server
  • 关键参数：--max-messages-per-channel / --max-retries / --retry-delay
  • 扩展新平台：照抄 apps/slack_data/slack_mcp_reader.py + apps/slack_rag.py 模式即可接任意 MCP server

⑨ Claude Code 代码库语义检索

pipx install leann --global   # MCP server 依赖全局 leann 命令
# 然后按 packages/leann-mcp/README.md 配置 Claude Code 的 MCP
  • Claude Code 原生只有 grep 式关键词搜索；LEANN 是 drop-in 语义搜索 MCP 服务，不改工作流直接升级
  • 含 agentic pipeline：自动 query 重写 + 语义搜索规划
  • 代码切块走 AST chunking（按语法树切，不按行数切）

⑩ CLI 速查（全局命令）

leann build    # 建索引
leann search   # 语义搜索
leann watch    # 监听目录变化增量索引（文件落盘 .leann/indexes/）
leann ask      # RAG 问答（接 LLM）
leann list     # 列索引
leann remove   # 删索引
leann build --help  # 完整参数

三、归纳总结

四、趋势判断

  1. "存储换计算"会成为端侧 AI 的标配权衡：个人设备磁盘贵、算力闲（NPU/GPU 大量空闲），LEANN 的 trade 正好打在端侧的软肋上——Jetson/手机/Mac 都适用
  2. 个人数据 RAG 是 2026 年爆发点：微信记录/邮件/浏览史/ChatGPT 史——数据全在本地但从未可检索；LEANN 类工具把"个人暗数据"点亮，与 agent memory 赛道（Mem0/Letta）正面相遇
  3. MCP 成为 RAG 数据源的统一插口：LEANN 把 MCP server 当数据采集器（Slack/Twitter），而非工具调用器——MCP 的第二种用法会扩散
  4. 向量库市场分化：服务端重查询场景（Milvus/Qdrant）与端侧重存储场景（LEANN）分道——"世界最小向量索引"是新品类的旗帜
  5. Claude Code 的 grep 短板被第三方补齐：语义检索 MCP 是 drop-in 升级，预示 IDE agent 的检索层会被专门产品占领（grep→semantic 是必然升级路径）
  6. 科研工程化的标杆：MLsys 论文+PyPI 包+uv+CI+devcontainer+投票问卷——2026 年系统论文的"发行包"标准正在抬高

七、指南分析

"存储-计算权衡"速查（何时选 LEANN 式架构）

存 embedding 成本（条数 × 维度 × 4B） > 重计算成本（查询频率 × 候选数 × 单次 embedding 计算）
→ 数据量大、查询频率低、算力便宜（端侧空闲 NPU）→ 选重计算（LEANN）
→ 数据量小、查询频率高、延迟敏感（在线服务）→ 选预计算（FAISS）

个人 RAG 落地三步法
1. 数据导出：每个平台都有导出口（微信 Tweak / ChatGPT zip / Chrome SQLite / 邮件 eml）——难点从来不是 RAG 是导出
2. 索引一次：leann build 全量建索引（6GB 可容 6000 万块）——之后 watch 增量
3. 查询接入：CLI 问答 / MCP 进 IDE / OpenAI 兼容 API 进任意 agent
