二、文章②核心：AI 理解 CAD 模型为什么这么难

2.1 四层困难

层次 困难 说明
格式封闭 CAD 文件不开放 SLDPRT/CATPart/PRT 各有私有格式，核心数据结构是黑盒
内容复杂 信息维度远超图像 数百面、数千边、上万顶点、多层嵌套特征、NURBS 曲面、BREP 拓扑
隐性知识 设计意图不在文件中 为什么倒角 2mm？为什么 3° 拔模？经验/标准/强度要求都不在 CAD 文件里
精度苛刻 0.1mm 差异 = 不同零件 图像识别可以模糊，CAD 不行

2.2 关键洞察：Cursor 的前车之鉴

Cursor 创始人 Michael Trun 团队最初搞的是 AI 机械 CAD，因难度太大转向 AI 编程。

这说明 AI 编程（代码是纯文本）和 AI 建模（几何+拓扑+语义）的难度差了一个量级。

2.3 CAD vs 图像的信息复杂度对比

维度 图像 CAD 模型
数据结构 2D 像素矩阵 (ARGB×4) 数学+拓扑+语义的多维对象
信息量 1080p ≈ 8M 像素 数百面+数千边+特征树
结构性 平面连续 树状离散（点之间无连续关系）
精度要求 模糊识别可接受 0.1mm 不可容忍
隐性知识 几乎不需要 大量工程经验

三、文章①核心：Codex 一句话建模的流量生意

3.1 热度来源

两个因素驱动了近期 Codex/Claude Code 操作 CAD/CAE 的热潮：

  1. 开源项目突破：text-to-cad、text-to-cae、Foam-Agent 跑通了 AI CAD/CAE 全流程
  2. MCP Server 涌现：GitHub 上出现了大量非官方 CAD/CAE MCP（很多是中国开发者）

3.2 三条技术路径

路径 原理 代表项目 局限
A. 直接生成 DXF Codex 生成 Python 代码调用 ezdxf — 不直观、不好修改
B. 原生 AI CAD NL→Python→build123d→OpenCASCADE text-to-cad, HiCAD, Zoo 不依附现有 CAD，但功能有限
C. MCP 连接 CAD NL→CAD 命令→软件执行 Fusion MCP, SolidWorks MCP 最合理，但大厂未开放官方 MCP

3.4 真实用户体验（泼冷水）

  • 消耗海量 Token
  • 模型大体看着像，细节错误很多，改不如重画
  • 提示词需要很长很精细，还不如直接动手快
  • 简单零件还行，复杂零件和装配体做不到

四、文章③核心：PTC Creo 13 AI Assistant — 企业级路径

4.1 三种模式

模式 成熟度 功能 面向
Advice（建议） 正式版 基于帮助文档和最佳实践，引导用户到正确工具 所有用户
Assist（协助） Beta 结合当前模型上下文，提取洞察，协助解决设计问题 扩展功能
Automate（自动化） Alpha 执行复杂几何操作和分析任务，结果供用户审阅 扩展功能

4.2 关键设计原则

  • 受控环境运行：Automate 模式在受控环境中执行，不会在用户不知情的情况下修改模型
  • 人工审批：执行结果提供给用户审阅和批准
  • 渐进式：从 Advice → Assist → Automate，逐步释放能力

五、各厂商 AI+CAD 进展汇总

厂商 AI 助手 MCP 状态 进展
PTC Creo AI Assistant (3模式) 未开放官方MCP Automate 模式 Alpha，可执行几何操作
Autodesk Fusion Assistant ✅ 官方MCP (本地+云端) 最开放，已对接 Claude
达索 虚拟伴侣 Leo 未开放 演示了 2D→3D 参数化建模，未上市
西门子 NX AI 未开放 投入中，细节未公开
第三方 各种插件 — 原理与 MCP 类似，功能有限

归纳总结

  1. AI+CAD 的核心矛盾：大模型擅长的是「概率推理下一个 token」，而 CAD 需要的是「精确的几何+拓扑+语义理解」。两者之间存在根本性的范式鸿沟。文章②说得精准——图像是涂色书，CAD 是工程教材。

  2. MCP 不是万能药：当前 Codex+MCP 的方案本质是「参数化命令的 API 调用」，大模型并没有真正理解几何和设计。它解决的是「工具连接」问题，不是「设计理解」问题。

  3. 企业级落地的正确姿势（文章③ PTC Creo 的三模式架构）：

  4. 先做软件答疑（Advice）→ 再做上下文洞察（Assist）→ 最后做受控执行（Automate）
  5. 核心原则是「人在回路」，AI 建议→人工审阅→批准执行

  6. 这与 LLM Agent 领域的 Human-in-the-Loop 模式完全一致

  7. 仿真比建模更接近落地：仿真工作流相对固定（前处理→求解→后处理），跨软件编排更容易标准化。Synera、安世亚太、雪浪糖等已在做基于 Workflow 编排的定制仿真 Agent。

  8. 流量泡沫规律：每一波 AI 新技术（GPT→Coze/Dify→OpenClaw→Codex）都会催生一批"卖课人"，利用信息差制造焦虑。判断技术是否真成熟，要看大厂的产品化进度，而不是 GitHub 上的 demo 项目。

趋势判断

时间维度 判断 置信度
短期（1年内） CAD AI 助手普及（Advice 模式），特定场景仿真 Agent 落地 90%
中期（2-3年） Automate 模式成熟，主流 CAD 厂商开放 API/MCP 70%
长期（5年+） 生成式设计在特定领域形成商业方案，通用方案仍远 50%
不会发生 Codex "一句话建模"取代工程师 99%

核心趋势：CAD/CAE 厂商从「卖软件」转向「卖 AI 增值服务」。AI 助手将成为 CAD 软件的标准配置，类似于 Copilot 之于 Office。
