一、核心范式转变

1.1 从 "Extract-Then-Store" 到 "Store-Then-On-demand-Extract"（STONE）

当前主流 Agent 记忆采用 "先提取再存储"（ETS）范式：LLM 从经验中提取"有用"信息并丢弃原始数据。问题在于——对未来不同任务有用的信息可能在当前提取时被丢弃。

STONE 范式（arXiv:2602.16192）提出直接存储原始经验，在检索时才按需提取：

维度 ETS（传统） STONE（新范式）
存储内容 提取后的结构化事实 原始经验（完整对话/日志）
信息损失 高（提取函数丢弃潜在有用信息） 零（保留全部原始上下文）
存储开销 看似更小，但多任务冗余累积 最小（Theorem 1 证明）
检索灵活度 低（锁定于提取时的任务视角） 高（任意任务维度检索）

核心定理：在"不丢失任何未来任务可能需要的信息"的约束下，STONE 实现了所有 ETS 范式中的最小记忆体积。因为 ETS 对同一原始经验按不同任务重复提取会产生冗余，累积后反而比原始数据更大。

1.2 更深层洞察发现

在随机环境中，单次经验回放会导致噪声驱动的行为不稳定。深层洞察发现聚合多条相关经验，通过统计方法提取潜在概率分布：

简单回放: M* = argmax Rel(M, T) → 提取单条最佳记忆 → 噪声敏感
深层发现: M_T = {M ∈ S | f_T(M) > 0} → 统计聚合多条相关记忆 → 抗噪声

1.3 经验记忆共享

多 Agent 共享记忆池 S = ∪M_i（i=1..K），实现集体学习加速。单个 Agent 不再依赖有限的自身试错轨迹，而是从整个群体的经验中受益。

二、2026 基准体系与评测标准

2.1 三大标准基准

基准 问题数 核心测试维度 规模
LoCoMo 1,540 单跳/多跳/开放域/时序记忆 多会话对话
LongMemEval 500 用户回忆/偏好/知识更新/时序推理/多会话 6 个子维度
BEAM - 1M/10M token 级超长上下文记忆 10 个子维度

2.2 五维评估框架

不再只看准确率，而是效用-效率-适应性-忠实性-治理五维平衡：

  1. Utility（效用）：记忆是否实际改善了下游任务结果？
  2. Efficiency（效率）：每单位效用增益的 token/延迟/存储成本
  3. Adaptivity（适应性）：能否从交互反馈增量更新，无需全量重训？
  4. Faithfulness（忠实性）：召回的信息是否准确且不过时？（陈旧/幻觉召回比无召回更糟）
  5. Governance（治理）：隐私合规、删除请求支持、组织策略遵循

三、架构演进：从图数据库到实体链接

3.1 核心变化

2024 年图记忆（Neo4j 等）是实验性的。2026 年的生产范式已转向内置实体链接：

  • 传统方式：外部图数据库存储实体关系，支持图遍历查询
  • 新方式：add() 时提取实体存入并行 {collection}_entities 集合，检索时通过实体匹配提升相关记忆排名
  • 代价：失去可遍历的图接口和 relations 字段，但大幅降低运维复杂度

3.2 Mem0 的混合检索策略

三路并行评分 + 融合：
1. 语义相似度：Dense Embedding 相似度搜索
2. BM25 关键词匹配：精确词频匹配，弥补语义搜索遗漏
3. 实体匹配：查询中的实体与记忆中的实体交叉提升

归一化后融合为单一分数。

3.3 单次 ADD-only 提取

新算法将 Agent 生成的事实（确认、推荐）提升为与用户陈述的事实同等权重的一等公民，关闭记忆覆盖缺口。

四、统一记忆分类体系（arXiv:2603.07670）

4.1 三轴分类法

时间范围: 工作记忆（Context Window） → 情景记忆（日志/轨迹） → 语义记忆（事实/知识） → 程序记忆（技能/代码）
表示载体: 文本 → 向量索引 → 结构化存储（SQL/KG） → 可执行代码
控制策略: 启发式规则 → Prompt 引导自管理 → RL 学习型管理

4.2 记忆作为 POMDP 的信念状态

Agent 在每一步的决策模型：

a_t = π_θ(x_t, R(M_t, x_t), g_t)   ← 策略（LLM）基于输入 + 记忆检索 + 目标
M_{t+1} = U(M_t, x_t, a_t, o_t, r_t) ← 记忆更新（写入/管理/去重/冲突解决/删除）

记忆 M_t 充当 POMDP 中的信念状态——对不可观测的真实世界状态的内部摘要。

4.3 记忆消融的关键发现

  • 去除反思组件：生成式 Agent 在 48 模拟小时内从连贯的多日计划退化为重复、无上下文的响应
  • 去除技能库：Voyager 的技术树里程碑进度速度下降 15.3 倍
  • 替换为长上下文：MemoryArena 多会话任务完成率从 >80% 降至 ~45%

五、多 Agent 记忆架构

5.1 四级作用域模型

Mem0 的多作用域记忆模型：

作用域 范围 典型用途
user_id 跨所有会话的特定用户 用户偏好、历史
agent_id 特定 Agent 实例 Agent 专属知识
run_id/session_id 单次对话 会话内上下文
app_id/org_id 组织级共享 团队知识库

检索时自动合并并按优先级排名（用户记忆 > 会话上下文）。

5.2 Hermes 三机协作的启示

Hermes jbot/ubot/abot 三机共享文件系统（NFS4），当前使用 JSONL 追加式经验池。可以借鉴：

  1. STONE 原则：存储原始会话片段而非仅提取的"经验卡片"，未来任务按需检索
  2. 深层洞察发现：对同一问题的多机经验做统计聚合，而非简单取最新一条
  3. 实体链接：在经验池中提取实体（项目名、错误类型、工具名），用实体匹配增强检索
  4. 多作用域：当前 exchange-protocol 只有全局级，应增加 user_id 级和 session_id 级

六、未解决的六大挑战

  1. 时序抽象规模化：如何在十亿级记忆条目中高效执行时序查询？
  2. 跨会话身份解析：同一用户在不同平台的身份如何合并？
  3. 应用级评估：记忆系统的价值最终要看端到端任务改善，而非中间指标
  4. 隐私与同意架构：GDPR "被遗忘权" 在分布式记忆系统中如何实现？
  5. 记忆陈旧性：如何自动检测和更新过时的记忆条目？
  6. 学习遗忘：Agent 何时应该主动删除不再相关的记忆？

七、对 Hermes 系统的具体影响

7.1 直接可落地的改进

  1. 记忆分层存储：当前 Hermes 的 MEMORY.md 是扁平的 ETS 模式。考虑引入 STONE 层——保存原始会话关键片段（而非仅提取的事实），配合按需提取
  2. 混合检索：当前 memory 工具只做语义搜索。可增加 BM25 关键词匹配层和实体链接层
  3. 多作用域：当前只有 user 和 memory 两个 target。可增加 session 级和 org 级
  4. 记忆消融测试：参考 Voyager 15.3x 的消融结果，对 Hermes 的 Skill 系统做消融实验，量化每个 Skill 的实际贡献

7.2 新方向评估

  • BEAM 10M 级别基准：48.6 分说明超长上下文记忆仍是开放问题。Hermes 的 session_search 本质上是一种检索增强记忆，应持续关注这一方向的进展
  • 记忆共享加速：三机经验池已具备基础，关键是引入统计聚合和深层洞察发现
