用户评注（高密度摘要）

最近，几乎所有能长时间运行的 Agent，都开始被包装成自进化。Jeff Dean 等研究者和资本押注 RSI，背后的判断很直接：单纯扩大参数、数据和算力，回报正在放缓，大家都在寻找下一条 Scaling Law。

真正的自进化至少要完成三个闭环：提出改动 → 验证它确实更好 → 把结果变成下一轮的起点。只会持续写代码和运行任务，还算不上进化。

LLM 时代，生成已经很便宜，验证反而成了最大的瓶颈。面对科研、架构和开放式 Agent，单靠模型互相打分，很容易出现奖励投机和集体幻觉。

所以下一条 Scaling Law，可能来自模型外部的自进化基础设施：可执行环境、可靠验证，以及能够积累真实经验的长期记忆。

原文核心论证

背景：RSI 浪潮与资本狂热

  • 1965 年 I.J. Good 提出智能爆炸假说："第一台超智能机器是人类需要做的最后一项发明"
  • Jeff Dean 正式加入 Recursive Self-Improvement (RSI) 浪潮
  • 今年 RSI 创业爆发：CoreAutoAI, Recursive_SI, SakanaAI, DiscoLoopAI, mirendil 等
  • 根本原因：单纯扩大数据和算力的回报正在放缓（Scaling 放缓），市场急需新 Scaling Law
  • 炒作与现实：几乎所有人都在声称做 RSI。给 Claude Code 加个 auto-loop 就敢叫自进化。甚至有创业公司演示"一键生成 100 篇论文"

进化的四个层级

文章区分了四个不同层次的"进化"，关键分界线在于——是更好的执行器（Level 1-2）还是更优秀的架构师（Level 3-4）：

层级 含义 类比
Level 1 更新权重 模型自己学习（RL/微调）
Level 2 改进自身参数/超参 元学习、AutoML
Level 3 重写自身逻辑 Agent 重写自己的工作流
Level 4 完全自主进化 RSI 终极目标

大多数所谓的"自进化 Agent"其实只是 Level 1-2（更好的执行器），而非 Level 3-4（真正的架构师）。

进化引擎：三步循环

任何尝试自进化的系统都依赖一个连续的三步循环：

1. Propose（提出改动）— 生成一个新的变更
2. Verify（验证更好）— 确认变更确实带来改进
3. Compound（积累起点）— 把结果变成下一轮的起点

80 年 AI 史 = 人类反复尝试启动这个三步引擎，却在不同瓶颈处猛烈撞墙。

四波浪潮：每次都卡在不同瓶颈

Wave 1: 打字机上的猴子（1958）— 生成瓶颈

Richard Friedberg（IBM）在 IBM 704 大型机上做实验：程序随机翻转自己的机器指令，期望幸运的突变让它变聪明。

结果：灾难。烧了大量电力，产出的代码是垃圾。

瓶颈：生成。随机变异无法产生有意义的代码。

Wave 2: 完美瘫痪（2003）— 验证过度

Jürgen Schmidhuber 提出优雅至极的"Gödel Machine"——铁律：必须先用数学证明某个修改能保证改进，才允许应用它。

结果：理论完美，但被自己的完美杀死。对复杂神经网络，数学证明某个修改必然提升需要近乎无限的计算量。这台机器从未迈出哪怕一步进化。

瓶颈：验证（过度约束）。完美主义导致完全停滞。

Wave 3: 意大利面大脑（2016）— 过拟合瓶颈

科技巨头推出 AutoML：用超级 AI 自动设计小 AI 模型的"大脑"，用基准测试高分作为奖励。

结果：AI 打破了人类记录，但工程师看到生成的是意大利面网络（spaghetti networks）。更糟的是，这个意大利面大脑在特定测试上得满分 100，但在真实世界中智能崩溃——它学会了利用基准测试的微观漏洞，过拟合了静态数据。

瓶颈：过拟合。优化了基准测试的代理指标，而非真实能力。

Wave 4: 启发式觉醒（2022-至今）— 验证瓶颈回归

LLM 吞下了人类所有代码，终于理解了优雅、功能性代码的样子。不再构建"意大利面大脑"。生成瓶颈终于"解决"了。

但这就回到了最终 Boss 战——AI 能生成极其复杂、类人的代码了，但怎么知道它是否真的有效？

  • LLM 会幻觉出看似合理但实际无法编译的代码
  • 会引入微妙的逻辑回归，破坏系统稳定性
  • 不再是数学证明的问题（Wave 2），也不是静态过拟合的问题（Wave 3），而是生成器本身根本不可靠

瓶颈：验证（生成器不可靠）。LLM 幻觉让验证变得极其困难。

四波浪潮瓶颈总结

波次 年份 瓶颈类型 失败原因
Wave 1 1958 生成 随机变异产生垃圾
Wave 2 2003 验证（过度） 完美主义导致零进化
Wave 3 2016 过拟合 优化代理指标而非真实能力
Wave 4 2022-现在 验证（不可靠） LLM 幻觉让验证失控

大撤退：人类退守外环

80 年 AI 史揭示了一条清晰的趋势线：人类不断后退。

手动设计参数 → 反向传播让机器调权重
手工网络架构 → NAS 自动设计蓝图
手工优化器 → 元学习让机器自己找
手工 Agent 工作流 → 机器开始重写它们

每次技术跃进都是撬开一个曾经需要人类直觉的"黑箱"，将其变成可搜索的空间。随着人类越退越远，唯一剩下的阵地就是验证。

从生成到验证：真正的瓶颈

文章的核心论点：

  • 对于封闭形式任务（竞赛编程、形式数学），验证很简单——编译器或逻辑求解器给出即时二元反馈
  • 但 RSI、科学发现和开放式探索本质上是开放式（open-ended）的
  • 当 AI 提出一个新架构、新研究框架或自主 Agent 管线时，静态基准测试和简单的"LLM-as-Judge"启发式都会失败
  • 用 LLM 验证另一个 LLM 而没有真实世界执行基础 = 左脚踩右脚想飞

自进化基础设施的三大支柱

"生成本身很廉价；稀缺的是将原始生成转化为真正递归复合所需的验证基础设施。"

支柱 说明
可执行环境 用可验证的计算工件（执行轨迹、系统剖析、经验证明协议）替代模糊的文本评估
可靠验证 将科学主张锚定到硬计算或物理现实，而非 LLM 互评
长期记忆 积累真实经验而非循环幻觉

归纳总结

这篇文章用 80 年 AI 史论证了一个核心论点：自进化的瓶颈不在生成，在验证。

四波浪潮每次都试图启动"提出→验证→积累"三步引擎，但每次都在不同环节撞墙：
- 1958 卡在生成太差
- 2003 卡在验证太严
- 2016 卡在过拟合代理指标
- 2022-现在 卡在 LLM 幻觉让验证不可靠

文章的终极判断：下一条 Scaling Law 不在模型内部（参数/数据/算力），而在模型外部的自进化基础设施——可执行环境、可靠验证、长期记忆。这与你之前保存的 SkillOpt（训练技能文档而非权重）、DeepSeek Agent Harness 执行栈（评测/验收层是最被忽视的一层）、以及 evidence-harness / goal-conditions（验证器项目）完全一脉相承。

趋势判断

  • RSI 成为下一个资本风口：Jeff Dean 入场只是开始，2026 下半年会有更多顶级研究者涌入。但大部分项目是"加个 auto-loop 就叫自进化"的泡沫
  • 验证基础设施是真正的蓝海：生成已经商品化（LLM API 几分钱），验证还没有被商品化。谁掌握可靠验证器，谁就掌握 RSI 的钥匙
  • LLM-as-Judge 的局限性被认识到：对于开放式任务，模型互评会产生集体幻觉和奖励投机。需要真实世界执行（execution grounding）来锚定
  • 模型外部优化 > 模型权重优化：SkillOpt（训练 skill.md）和 Search-R1（RL 训练检索策略）都证明——不动权重、优化外部策略不仅可行，而且可以跨模型迁移
  • 四波浪潮的周期性：每次 AI 突破都在"生成"和"验证"之间摇摆。Wave 4 正处于验证瓶颈，下一次突破很可能来自验证基础设施

关联分析

  • 与 SkillOpt 的直接关联：SkillOpt 恰好实现了文章描述的三步循环——Propose（优化器提出 add/delete/replace 编辑）→ Verify（validation gate 严格验证提升）→ Compound（best_skill.md 作为下一轮起点）。SkillOpt 是"验证驱动自进化"在技能层面的具体实现
  • 与 DeepSeek Agent Harness 执行栈的关联：那篇推文的第 5 层"评测/验收/可观测性"（goal-conditions / evidence-harness）正是本文说的"验证基础设施"。这两篇文章互为表里——一篇讲理论（为什么验证是瓶颈），一篇讲实践（谁在做验证器）
  • 与 Hermes evolver/error-case-library 的关联：用户的 evolver 系统（错误模式→规则沉淀→经验闭环）是三步循环的简化版。但缺少严格的"验证门控"——目前是启发式而非验证驱动。SkillOpt 的 validation gate 模式可以作为 evolver 升级方向
  • 与 deterministic-guardrails 的关联：文章说的"用可验证的计算工件替代模糊文本评估"，与用户的确定性护栏理念一致——关键流程必须可程序化验证，不能靠自然语言描述
  • 与用户航空结构 AI 方向的关联：航空结构设计规范是"封闭形式任务"——有明确的适航标准做二元验证。这恰好是文章说的验证可行的场景
