摘要

微信公众号"艾算立方AIX³"发布的一篇 Hermes Agent 功能全景指南。文章将 Hermes 的能力分为五大部分共 15 个功能点：初始设置（SOUL.md、MEMORY/USER.md、/insights、/snapshot）、飞行中实时控制（/branch、/rollback、/btw、/steer+/queue、/yolo+/fast+/reasoning）、供应商锁定破解（/model 切换、辅助模型分工）、多平台触达（17平台网关、/voice、Cron+Webhook）、以及技能扩展（斜杠命令）。核心论点是大多数用户只用了 Hermes 8% 的功能，把它当成了"稍微聪明一点的 ChatGPT"。文章价值在于系统性的功能清单，适合新手快速了解 Hermes 能力边界，也适合老用户查漏补缺。

核心内容

第一部分：你跳过的初始设置

1. /personality + SOUL.md
Hermes 启动时读取 SOUL.md，内容永久成为 Agent 的"灵魂"和语气。/personality 命令可随时切换预设人格。避免每次聊天重复写系统提示词，一次写入 SOUL.md 即可。

2. MEMORY.md + USER.md
两个持久化文件每次会话自动读取。MEMORY.md 是项目笔记本，USER.md 记录用户个人信息。通过 FTS5 + LLM 摘要索引，8 周前的记忆也能自动弹出，无需反复自我介绍。

3. /insights [天数]
跨会话分析仪表盘：token 消耗量、使用的模型分布、卡点位置、最常问的话题。/insights 30 可看过去一个月全貌。

4. /snapshot
高风险操作前的状态快照。出问题直接 /snapshot restore 回滚，Agent 版"时光机"。

第二部分：飞行中实时控制

5. /branch（别名 /fork）
类似 Git 的会话分支。尝试激进路径时不想污染当前上下文？直接分支，不行切回来。

6. /rollback
文件系统检查点。Agent 搞崩代码后无需 git，直接 /rollback 秒恢复。

7. /btw
临时旁白问题：只用当前上下文，不调工具，不存记录。快速确认类命令。

8. /steer 和 /queue
Agent 正在跑多个工具调用时，发现方向错了？不用杀进程，直接 /steer 加指令，下一条工具调用即生效，缓存仍然热。/queue 可排队下一轮指令而不中断当前流程。这是 Hermes 独有的"飞行中纠偏"能力。

9. /yolo、/fast、/reasoning
三个功率开关：/yolo 跳过危险命令审批，/fast 切换极速模型，/reasoning 调节推理深度。大多数人永远用默认设置然后抱怨慢。

第三部分：彻底摆脱供应商锁定

10. /model [--provider] [--global]
一条命令切换模型，无需重启。支持 Anthropic、OpenAI、OpenRouter、NVIDIA NIM、Kimi、Gemini、AWS Bedrock 等十几家供应商。重活用 Opus，轻活用 Kimi，状态无缝继承。这是 Hermes 相比 ChatGPT/Claude 原生客户端的核心优势——不绑定任何单一模型供应商。

11. 辅助模型
上下文压缩、会话摘要、标题生成、视觉任务等都可以单独指定不同模型。主脑用 Opus 4.7，压缩用 Haiku 4.5，标题用小模型。不为轻量任务付重量级模型的钱。这种"模型分工"思路在 Agent 领域越来越主流。

第四部分：你从未激活的超大触达

12. 17 平台网关
Telegram、Discord、Slack、WhatsApp、Signal、Email、SMS、Matrix、飞书、企业微信、钉钉、QQBot、Home Assistant……一个 Hermes 进程全部搞定。这是"写一次，到处跑"的消息层抽象。

13. /voice 实时语音
支持 CLI、Telegram、Discord 文字/语音频道。打字 /voice 即可语音交互，解放双手场景。

14. Cron + Webhook 订阅
内置定时任务支持自然语言描述："每周五下午 5 点，总结本周 GitHub 提交，发布到 Slack #standups"。配合 Webhook 可实现 GitHub、Vercel、Stripe 等事件零延迟推送。完全免费，替代 Zapier/IFTTT。

第五部分：把游客和真用户区分开的秘密

15. 技能 = 斜杠命令
100+ 内置技能，全部是 / 命令，输入 / 自动补全。用户可自写技能，写一次在任何会话、任何平台永久可用。文章作者举例自写了 /sage 技能用于发现领域异常值、追踪趋势、起草推文。游客一周用一次斜杠命令，真用户把整个工作流写成斜杠命令。

总结金句

"你花钱买了一个拥有持久记忆、100+ 技能、文件回滚、会话分支、飞行中纠偏、17 平台、实时语音、多模型路由、定时任务、Webhook 和自定义技能的超级 Agent……结果你只把它当成了一个稍微高级一点的 ChatGPT 机器人。工具没有辜负你，是你从来没有给它真正的指令。"

🔍 借鉴点

  • 辅助模型分工思路 → 我们已通过 Fallback 链实现模型路由，但可以更细化：标题生成、摘要压缩、视觉任务各指定不同模型，节省成本。当前我们的压缩模型是自动选择的，可考虑显式配置。
  • /steer 飞行中纠偏 → 长任务执行中用户介入调整方向，避免"一条路走到黑"。我们已在 steer-hook skill 中实现了类似机制，但实际使用频率低，可考虑在 OPM 层自动触发。
  • Cron + Webhook 替代 Zapier → 我们已有 25+ cron job + webhook 订阅 skill，但还没做到"自然语言描述→自动生成 cron"的程度。可以考虑用 AI 解析自然语言定时需求直接创建 cron job。
  • 技能=斜杠命令的扩展思路 → 我们的 200+ skill 已经是斜杠命令形式，但用户自写技能的门槛还可以降低。文章作者的 /sage 示例是个好参考——领域专属技能的自动化。

💡 启发

  • "8% vs 92%"的隐喻很有传播力 → 可以借鉴这种"你以为你都会了？其实你还差得远"的叙事框架来写我们自己的技术文章。
  • 飞行中纠偏是 Agent 区别于 Chatbot 的核心特征 → /steer 和 /queue 让 Agent 在执行中可被纠正，这对生产环境至关重要。传统 chatbot 只能重来。
  • 模型分工将成标配 → 不再是"一个模型搞定一切"，而是主脑+辅助模型的编排。这和我们的 Fallback 链思路一致，但更强调"不同任务用不同级别模型"的成本优化。

🔮 预判

  • 多模型路由会成为 Agent 框架的标配功能 → 目前只有 Hermes 和少数框架原生支持，未来一年内所有主流 Agent 框架都会跟进。
  • "技能商店"模式会兴起 → 类似 VS Code 插件市场，Agent 技能的可分享、可组合生态将形成。Hermes 的 SKILL.md 格式已经有了这个雏形。
  • Webhook + Cron 的"免费自动化"叙事会持续有效 → Zapier/IFTTT 的付费自动化市场会被 Agent 原生能力蚕食。
