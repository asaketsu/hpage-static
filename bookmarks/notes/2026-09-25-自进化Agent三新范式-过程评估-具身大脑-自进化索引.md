## 一、内容整理

> **一句话总览**：自进化 Agent 研究在 2026 年 9 月出现三层突破——**过程级评估基准**（不只看终点能力）、**具身大脑闭环架构**（不重训的部署后进化）、**检索索引自进化**（无人干预的索引诊断-修订-验证循环）。

### 1.1 EvoPathBench：自进化 Agent 的过程级评估（arXiv:2609.24663）

自进化 Agent 把交互反馈转化为持久工件（记忆/技能），工件在经验流中迭代更新。终点性能因此**不完整**——必须评估“目标能力何时涌现、后续更新是强化/保持还是削弱它”。

- **方法**：固定底座模型与工具，把演化中的工件在连续 checkpoint 处冻结，在 held-out episodes 上评估目标能力。
- **三能力测试**：未见任务泛化、无关学习后的保持（retention）、新证据下的规则适应（rule adaptation）。
- **领域**：公开交易数据 + 校准轨迹。
- **发现**：相似未见任务上的增益在分布漂移下常被削弱；保持损失集中在少数进化路径；**没有任何方法实现可靠的规则适应**；自进化能产出有 held-out 增益的候选工件，但被选中的更新总是实现不了这个潜力。

### 1.2 ME-Brain-1.0：进化具身智能的记忆-认知-行动大脑（arXiv:2609.24271）

突破“部署后能力冻结”的限制，围绕**行动执行→经验获取→经验进化→改进执行**闭环组织系统：

- **Evolvable Memory**：把多模态轨迹固结为分层可复用经验。
- **Cognitive Core**：把物理经验转化为可迁移技能（比最强对比模型在具身/agent 基准上高 8.2/9.6 分）。
- **Action Model**：事件驱动关键帧 + EventCell 局部世界预测 + 动作条件记忆调制，把算力聚焦决策关键时刻/区域/历史证据。
- RoboMME 47.88% 成功率（+3.26）；RoboDojo 21.51 Score（超 π0.5 达 10.10 分）；ME-RealBench 69.5 Score / 66.7% 成功率（超 DM0.5 达 12.8/11.7）。

### 1.3 SELF-INDEX：自进化搜索索引（arXiv:2609.19656）

检索质量高度依赖索引键如何暴露文档知识，而最优索引表示随检索环境变化。SELF-INDEX 让索引无人干预自进化：

- **Optimizer**：自主诊断检索短板 → 选择性修订责任索引键 → 验证每次修订后才更新。
- **Query Simulator**：主动探索额外需求，使索引进化超越已有查询覆盖。
- 跨语料与检索器一致提升，惠及下游搜索 agent 与 agent 记忆系统对历史交互的检索。

## 二、查询拓展

### 2.1 过程级评估 vs 终点评估

终点评估（endpoint eval）只看最终能力分数；过程级评估（process-level eval）追踪能力在工件演化轨迹上的出现/强化/削弱。这与软件工程中"CI 门禁 vs 发布验收"同构：DUCK 项目"每存档档位必须跑验收器"正是过程级评估的工程实践，本文把它形式化为基准。

### 2.2 记忆固结（Memory Consolidation）

源自认知科学的记忆巩固理论（海马→皮层固化）。ME-Brain 的 Evolvable Memory 把多模态轨迹固结为分层可复用经验，与 Hermes 的 memory-refiner（USER.md/MEMORY.md 精炼）、memory-consolidation skill（L1/L2/L3 记忆审计）直接同构——差别在 Hermes 是文本经验，ME-Brain 是多模态物理轨迹。

### 2.3 诊断-修订-验证闭环

SELF-INDEX 的 Optimizer 三步（诊断短板→修订→验证后更新）与 Hermes 递归自我进化循环（L1 信号扫描→L2 沉淀→L3 对账）结构相同。关键差异：SELF-INDEX 的"每次修订验证后才更新"是**机械门禁**，而 Hermes 的 L2 沉淀需用户拍板——工程可靠性更高但速度受限。

## 三、归纳总结

### 3.1 自进化系统三层架构对照

```
层        EvoPathBench      ME-Brain         SELF-INDEX       Hermes现状
评估      过程级checkpoint  基准分数提升      检索质量验证      cron验收器+哨兵
记忆      冻结工件快照      分层经验固结      索引键修订        MEMORY.md+skills
进化      无(评估框架)      认知核转技能      模拟查询探索      session-evolution-scan
```

### 3.2 共同信条

- **进化必须可验证**：SELF-INDEX 修订前验证；EvoPathBench 用 held-out 冻结快照；ME-Brain 用基准分数。三篇都拒绝"更新了就是进化了"。
- **进化有代价**：EvoPathBench 实锤"保持损失集中在少数进化路径"——进化不是免费午餐，错误的更新会削弱已有能力，需要选择性保留。
- **聚焦关键**：ME-Brain 事件驱动关键帧把算力聚焦决策关键时刻，与 attention 经济同构。

## 四、趋势判断

### 趋势1：Agent 自进化评估从"终点分数"转向"能力轨迹追踪"
依据：EvoPathBench 首次提出过程级评估基准并实锤"选中的更新实现不了候选潜力"——这是终点评估完全看不见的失效模式。

### 趋势2：具身智能从 train-and-freeze 转向 deploy-and-evolve
依据：ME-Brain 不重训底座模型即实现跨基准 SOTA 级提升，证明经验层进化（记忆+认知核）是比重训更廉价的进化路径。

### 趋势3：检索基础设施开始自进化
依据：SELF-INDEX 把索引优化从人工诊断-重处理自动化为无人干预循环，且收益外溢到下游 agent 记忆检索。

### 脚注：样本量 3 篇，趋势为方向性判断。

## 五、关联分析

### 5.1 与 Hermes 递归自我进化循环的关联（最强关联）

用户 09-21 明令"严格执行"的三层映射（L1 信号=session-evolution-scan 每日扫描 → L2 沉淀=用户拍板后 skill patch → L3 对账=evolution_log.jsonl 全量入账）与三篇论文对照：

- **EvoPathBench 的警示直接适用**：Hermes 的 skill patch（工件更新）从未做过"无关学习后的能力保持"测试——一次 patch 可能削弱既有能力而不自知。建议在 skill-ab-testing 中增加回归检查。
- **SELF-INDEX 的"修订前验证"**正是 Hermes launch_gate.sh（发射前 11 条死法检查）在索引域的镜像——验证机械门禁方向正确。
- **ME-Brain 的分层记忆**（轨迹→经验→技能）与 Hermes 四层落盘（memory+docs+skill references+PROGRESS）同构，可借鉴其"事件驱动"思想：只在决策关键时刻沉淀重记忆，降低记忆通胀。

### 5.2 与 DUCK 项目的关联

- DUCK 的 death_ledger.jsonl + launch_gate.sh + runtime_guard.sh = EvoPathBench 式过程级评估的工程雏形（每档验收 = checkpoint 冻结评估）。
- ME-Brain 的 EventCell 局部世界预测与 DUCK sim 部署的推机器人测试（write_root_velocity）同属"主动扰动验证"思想。

### 5.3 与量化交易系统的关联

EvoPathBench 用公开交易数据评估 agent 自进化——"规则适应"（新证据下更新交易规则）恰是 quant-evidence-governance skill 的核心场景，且其结论"没有方法实现可靠规则适应"提示：交易规则进化必须保留人工拍板（与用户 09-22 拍板纪律一致）。

## 六、金句摘录

> 「endpoint performance alone offers an incomplete view of self-evolution」— 终点分数看不见进化路径上的能力退化。

> 「the selected updates consistently fall short of realizing this potential」— 被选中的更新总是实现不了候选工件的潜力——进化系统的选择器是瓶颈。

## 八、拓展应用推荐

- **Hermes 自进化循环升级**：把 EvoPathBench 的三能力测试（泛化/保持/规则适应）改造成 Hermes skill patch 的机械门禁——patch 前后各跑一次场景回放，保持损失超阈值即回滚（对应 skill-ab-testing 现有框架的增强）。
- **DUCK 经验池进化**：death_ledger.jsonl 目前只追加不淘汰——可借鉴 ME-Brain 分层经验固结，把反复出现的死法模式固结为 launch_gate 规则（已做）+ 把过时死法降权（未做）。
- **量化策略进化治理**：quant-evidence-governance 已有"外源因子本地验证"，可加 EvoPathBench 式过程追踪——每次规则 patch 记录前后回测对比，形成策略能力轨迹档案。

## 九、指南分析

- **可抄度评估**：EvoPathBench 的冻结快照评估法（可抄度★★★，直接映射到 skill patch 前后对比测试）；SELF-INDEX 的诊断-修订-验证闭环（可抄度★★，需先有检索质量诊断手段）；ME-Brain 整体架构（可抄度★，工程量过大，只取思想）。
- **方法论质量**：三篇均有量化基准支撑；EvoPathBench 的"选中的更新实现不了候选潜力"发现最有工程价值——它指出进化系统的瓶颈在选择器而非生成器，直接指导 Hermes 把投入从"生成更多 skill 候选"转向"提高选择门槛"。
- **局限**：EvoPathBench 仅在交易数据域验证；ME-Brain 的基准提升是否来自记忆架构还是 prompt 工程未完全消融；SELF-INDEX 的 Query Simulator 生成的合成查询可能偏离真实分布。
