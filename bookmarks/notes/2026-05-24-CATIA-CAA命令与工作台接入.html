摘要

本文讲解 CAA（Component Application Architecture）开发中如何将自定义功能接入 CATIA V5 的交互界面——从命令类设计、状态机交互、资源文件管理到工作台/工具栏/菜单注册，再到 Add-in 解耦方案。核心观点：按钮不是命令，按钮是 CATCmdStarter；命令由三层组成（Starter → Header → Command Class）；CATStateCommand 是机械/几何 CAA 开发中最常用的命令类型，将交互建模为状态机。

核心内容

1. 命令三层架构

CAA 中一个可点击功能由三层组成，很多初学者会混淆：

层级 类 职责
第一层 CATCmdStarter 按钮本身，不执行逻辑，只启动命令
第二层 CATCommandHeader 知道加载哪个库、实例化哪个命令类
第三层 CATCommand / CATStateCommand 真正运行，接收交互事件并修改文档

调用链：用户点击按钮 → CATCmdStarter → CATCommandHeader → 加载模块 → 实例化命令类 → 接收交互

2. 命令类型选择

CAA 文档把用户可见命令分为三类，选择取决于用户是否需要继续交互：

CATStateCommand（最常用） — 把交互过程建模为状态机：
- 每个状态收集一类输入
- 输入满足条件后通过 transition 进入下一个状态并执行 action
- 典型流程：初始状态（选择对象）→ 第二状态（输入参数）→ 结束状态（创建特征）

3. State Command 骨架

头文件需要：
- 继承 CATStateCommand
- 声明资源文件（CmdDeclareResource）
- 覆盖 BuildGraph（核心：创建状态、创建 dialog agent、串联条件/动作）
- 实现生命周期函数：Activate / Desactivate / Cancel

class MyCompanyCreateMeasureCmd : public CATStateCommand {
    CmdDeclareResource(MyCompanyCreateMeasureCmd, CATStateCommand);
    CATBoolean CheckSelectedObject(void *data);
    CATBoolean StoreSelectedObject(void *data);
    CATBoolean CreateMeasureFeature(void *data);
    CATPathElementAgent *_selectionAgent;
    CATDialogAgent *_okAgent;
};

BuildGraph 是核心：

void MyCompanyCreateMeasureCmd::BuildGraph() {
    CATDialogState *selectState = GetInitialState("SelectInputState");
    _selectionAgent = new CATPathElementAgent("SelectInputAgent");
    selectState->AddDialogAgent(_selectionAgent);
    AddTransition(selectState, NULL,
        IsOutputSetCondition(_selectionAgent),
        Action((ActionMethod)&MyCompanyCreateMeasureCmd::StoreSelectedObject));
}

4. 命令头（Command Header）注册

命令类写好后，需要在工作台或 add-in 的 CreateCommands 中创建 command header：

#include "CATCommandHeader.h"
MacDeclareHeader(MyCompanyWorkbenchHeader);

void MyCompanyWorkbench::CreateCommands() {
    new MyCompanyWorkbenchHeader("MyCompanyCreateMeasureHdr",
        "MyCompanyCommands", "MyCompanyCreateMeasureCmd", (void*)NULL);
}

四个参数：Header 类名、Header 实例 ID、命令类名、参数指针（64 位环境用 CATINT32ToPtr 宏避免指针宽度问题）

5. 工作台与工具栏

Workbench — CATCmdWorkbench 容器，包含多个 toolbar
Toolbar — CATCmdContainer，包含多个 starter
Starter — CATCmdStarter，指向 command header

CATCmdWorkbench *MyCompanyWorkbench::CreateWorkbench() {
    NewAccess(CATCmdWorkbench, workbench, MyCompanyWorkbench);
    NewAccess(CATCmdContainer, measureToolbar, MyCompanyMeasureTlb);
    SetAccessChild(workbench, measureToolbar);
    AddToolbarView(measureToolbar, 1, Right);
    NewAccess(CATCmdStarter, createMeasureStarter, MyCompanyCreateMeasureStr);
    SetAccessCommand(createMeasureStarter, "MyCompanyCreateMeasureHdr");
    SetAccessChild(measureToolbar, createMeasureStarter);
    return workbench;
}

关键标识符区分：
- MyCompanyCreateMeasureCmd — 命令类（实现逻辑）
- MyCompanyCreateMeasureHdr — 命令头（注册入口）
- MyCompanyCreateMeasureStr — 启动器（按钮）

6. Add-in 解耦方案

如果不想修改已有 workbench，使用 Add-in：
- 目标 workbench 暴露 add-in interface
- 你实现这个接口，把工具栏和命令注册进去
- 适合增加工具栏和有限菜单入口，但不应该假设能任意重排目标 workbench 的菜单结构

class MyCompanyMeasureAddin : public CATBaseUnknown {
    CATDeclareClass;
    void CreateCommands();
    CATCmdContainer *CreateToolbars();
};

CATImplementClass(MyCompanyMeasureAddin, DataExtension,
    CATBaseUnknown, MyCompanyMeasureAddinComponent);
TIE_MyTargetWorkbenchAddin(MyCompanyMeasureAddin);

7. 资源文件管理

资源类型 文件名 用途
CATNls Header.CATNls 标题、帮助、短提示、分类（翻译资源）
CATRsc Header.CATRsc 图标、快捷键、助记键（非翻译资源）
命令类资源 Command.CATNls 状态提示、undo prompt、面板文案

CATNls 中常见 key：HeaderClassName.HeaderInstanceID.ResourceItem

8. 最佳实践

  1. 不要直接手写 StartUp 属性字符串 — 在 UI 代码中散落模型细节
  2. 使用 factory 模式 — 同一个 factory 可被命令、脚本、批处理或测试复用
  3. 命令可以同时在 toolbar 和 menu 中 — 指向同一个 command header，不需要写两份命令类
  4. 最小验证流程 — 先做成 one-shot（点击弹出消息或打印 trace），确认 header/library/class name 和资源链路没问题，再逐步加入 state graph 和业务逻辑

能力边界

适用：CATIA V5 CAA 二次开发、机械/几何特征创建、分析工具集成、批处理功能 UI 化
不适用：CATIA V6 / 3DEXPERIENCE（不同架构）、非 CAA 开发场景
难度：中等偏高，需要理解 CAA 对象模型、COM 接口、资源系统

最佳实践

  1. 命令类 → Header → Starter 三层分离，不要混在一起
  2. 优先用 CATStateCommand 建模交互流程
  3. 资源文件与代码用 CmdDeclareResource 关联
  4. 用 Add-in 解耦，不要直接修改目标 workbench
  5. 先 one-shot 验证，再逐步完善 state graph
  6. 64 位环境用 CATINT32ToPtr 避免指针宽度问题
