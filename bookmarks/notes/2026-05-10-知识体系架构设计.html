一、背景

基于一篇介绍 Karpathy llm-wiki 的公众号文章，从"学习这个工具"演变成"梳理整个知识体系"。最终完成了 Wiki 实例搭建、多领域隔离、双写机制、统一查询入口的全链路设计。

二、四套系统全景

系统对比

系统 数据源位置 存什么 怎么找 类比
Hermes Memory ~/.hermes/memories/ 偏好、事实、教训 精确匹配（token级别） 便利贴
Wiki ~/uclaw/wiki/ 实体/概念卡片（结构化） [[wikilink]] + 索引 百科全书
RAG ~/obs_notes/（Obsidian，1100+篇） 原始笔记全文 关键词 + 语义向量 图书馆检索
Hybrid Search / Notes ~/uclaw/bookmarks/notes/（Agent笔记，100+篇） 分析报告、学习笔记 BM25 + 向量融合 搜索引擎

核心区别

维度 RAG Wiki
内容形态 原文 chunks（碎片） 结构化卡片（完整）
增长方式 线性（越多越慢） 复利（越查越丰富）
检索方式 向量相似度 图遍历（链接跳转）
适合回答 "原文怎么说的？" "XX 是什么？跟谁有关？"
维护成本 自动（重建索引） 半自动（Agent 提取）

定位分工

用户问了一个问题
    ↓
① Memory（最快）— "用户偏好是什么？上次决定用什么方案？"
② Wiki（结构化）— "这个概念/人/工具是什么？"
③ RAG / Hybrid Search（全文）— "原文怎么说的？有没有提到过 XX？"
④ 笔记（阅读）— "这篇文章的完整分析是什么？"

三、Wiki 搭建过程

起点

从公众号文章"AI混子-俊"学习 llm-wiki 模式，决定搭建实例。

目录结构

~/uclaw/wiki/
├── README.md                 ← 总目录
├── ROUTER.md                 ← 路由配置（领域关键词匹配）
├── ai-tech/                  ← AI/技术领域（当前活跃）
│   ├── SCHEMA.md             ← 领域定义 + 标签体系 + 规则
│   ├── index.md              ← 内容目录（7页已索引）
│   ├── log.md                ← 操作日志
│   ├── raw/articles/         ← 原文存档（不可变）
│   ├── entities/             ← 实体页（karpathy, markitdown 等）
│   ├── concepts/             ← 概念页（llm-wiki 等）
│   ├── comparisons/          ← 对比分析
│   └── queries/              ← 查询记录
├── _legacy/                  ← 18个旧散装笔记（待 ingest）
├── finance/                  ← 预留
└── psychology/               ← 预留

关键决策

  1. 多 Wiki 实例方案（而非单 Wiki + 标签分区） — 因为每个领域的 SCHEMA.md 是定制的，混在一起标签体系会冲突
  2. 不新建 ingest skill — 已有的 research/llm-wiki skill v2.1.0 完整覆盖 6 步流程
  3. _legacy/ 暂存 — 18个旧散装笔记后续逐个 ingest 进对应领域

Ingest 6 步流程

  1. Capture — 抓取存档 + SHA256 校验
  2. Discuss — 确认要点
  3. Check — 搜索冲突
  4. Write — 创建/更新实体页和概念页
  5. Navigate — 更新 index.md + log.md
  6. Report — 报告变更

路由机制（ROUTER.md）

每次 ingest 新内容时自动判断归属领域：
- 读取 ROUTER.md 匹配关键词
- 不存在该领域 → 自动建域（复制模板 + 改配置）
- 跨领域用 [[wikilink]] 互引

四、双写机制

规则

每次执行分析/笔记写入时，同时自动执行 Wiki ingest，无需用户指示。

触发条件

情况 笔记 Wiki
文章分析/读书笔记 ✅ 完整笔记 ✅ 提取实体+概念
竞品分析 ✅ 分析报告 ✅ 提取公司/产品/方法论
纯问答（查天气/查单词） ❌ 不写 ❌ 不写
用户明确说"加入 wiki" 跳过 ✅ 直接 ingest

定位

  • 笔记 = 过程记录（我读了什么、想了什么）→ 给用户看的
  • Wiki = 知识沉淀（什么实体值得长期记住）→ 给系统用的

五、统一查询入口（knowledge-query）

设计动机

四套系统并存，用户不可能指定"去 wiki 查"还是"去 RAG 查"。需要一个统一入口，自动路由。

路由规则

问题类型 路由到 示例
用户偏好/历史决策 Memory "我之前说止损设多少？"
某个概念/实体是什么 Wiki → Memory "Karpathy 是谁？"
原文怎么说的 RAG → Notes "那篇文章怎么评价 llm-wiki？"
之前做过/分析过什么 session_search → Notes → Memory "我们上次分析的那个项目"
综合性/不确定 全部并行 "关于 XX 我们都知道什么？"

执行流程

  1. 分析问题意图 → 确定查询源
  2. 并行查询（最多3个源）
  3. 合并去重（冲突以 Memory 为准）
  4. 格式化返回

Skill 信息

  • 名称：knowledge-query
  • 路径：research/knowledge-query/SKILL.md
  • 类别：research

    └→ ④ Notes（分析笔记）
    ↓
合并去重 → 一句话回答你
