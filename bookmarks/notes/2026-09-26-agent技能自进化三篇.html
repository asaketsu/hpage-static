内容整理

SkillPivot：偏差点引导的技能自进化（2609.29154）

核心观察：失败轨迹极少整条全错——通常先有有价值的探索前缀（收集证据、缩小解空间），后在某点拐进错误后缀（重复无效调用/过早停止/误读观测）。整条轨迹当失败信号=把有用前缀一起清洗掉，产生过宽、过噪、过拟合单例的技能更新。

方法四步：

  1. 偏差点检测：定位学生 agent 从"有效解题"转向"错误行为"的那一步。
  2. 教师续跑：更强教师模型从同一前缀继续，产出成功后缀（最多 10 步，可重试 3 次）。
  3. 后缀对比：学生失败后缀 vs 教师成功后缀，从同一起点分叉——差异即技能缺口，生成最小化、条件化、可审计的技能增量（delta）。
  4. 回归门禁验证：检查更新是否保留原有用规则+新指导是否超出触发案例泛化，防有害更新。

实验：Qwen3-32B 学生 / Qwen3.5-397B-A17B 教师模块，ToolQA 六个不相交任务组。演进技能跨任务组泛化、跨多轮演进持续提升、跨模型迁移（GPT-4o mini / Gemini 3.1 Flash-Lite / DeepSeek-V4-Pro / Qwen3.5 / Qwen3-32B 全部正增益）——弱模型+演进技能可追上甚至反超强模型+原始技能。消融证明：后缀对比（vs 全轨迹反思）和 review 门禁（防长程退化）都是必要件。

Scope Before You Persist：记忆跨族干扰防护（2609.29144）

核心问题：持久记忆编辑有两个独立决策——更新是否被证据支持（whether）+ 更新应作用到哪（where）。单族内收集的证据可支持前者，但不能证明全局部署。

机制：跨族干扰（cross-family interference）——在一个任务族内认证有效的编辑，通过一个紧凑全局 skill 部署后，影响证据从未覆盖的族。8 个 12 轮流的实验里，每种全局更新方法都跌到 Static 基线以下。

数学骨架（命题 1）：有益提案概率 π、增益 G、有害损失 L、门禁接受率 α/β，期望部署变化 >0 当且仅当 παG > (1−π)βL。多证据通道 AND 门下有害接受率=各通道 β 之积（独立时）——但错误相关时加通道无效，边际验证器精度不够，证据的错误相关性才关键。

解法：族域检索（family-scoped retrieval）——固定输出的干预实验（只改检索范围，提案/门禁决策/程序/分数全不变），每条被接受的 skill 只在其来源族检索。结果：12 轮流保持局部认证增益 + 27 流随机序扩展中轨迹效用和有效更新数双升。ORC 门禁（Orthogonal Regression Control）= 执行接地（execution-grounded）的技能编辑门。

HEXIS：技能编译为扩展状态机（2609.30123）

核心问题：技能文档作为上下文供给时，「该执行哪个操作」由模型每步从指令+历史里推断——模型可能报告检查失败却不执行技能要求的修订（偏离概率 εt）。供给影响选择但不强制执行。

方法：把技能编译成扩展有限状态机（EFSM）：

  • 知识/控制流分离：任务知识+局部指令留在状态内供推理；操作顺序/数据依赖/分支/循环/终止由显式转移条件强制执行。
  • 追迹引导增量编译：从技能文档初始化机器 → 对齐执行迹复用或新增动作与转移 → 检查数据依赖与声明要求 → 重放复现新旧全部迹才提交更新。
  • 状态机记录执行进度与中间结果。

结果：qwen3.6-flash 执行编译出的机器，原样迁移到其他三个 backbone，16 设置中 15 个优于直接技能执行、11 个领先或并列；Qwen3.8-27B token 用量降 38.4~88.9%；与 SkillOpt 组合在 SpreadsheetBench 达 84.2%。

查询拓展

  • SkillsBench（Li et al. 2026）：策展技能把平均通过率 33.9%→50.5%（87 任务 8 域），HEXIS 引言的关键背景数字。
  • SkillOpt / SkillGen / SkillForge / SkillClaw / SkillAudit / Self-Harness：技能进化生态近期全家族（更新信号来源各异：执行反馈/成败迹/多用户聚合/有无技能对比/多失败汇总）。
  • StateFlow（Wu et al. 2024）：预定义状态机组织执行，HEXIS 的前身；区别在于 HEXIS 自动从技能编译而非手工设计。
  • Formal Skill / AFlow / TraceCompiler / Compile Then Page：程序化执行路线的并列工作。
  • Reflexion / ExpeL / Agent Workflow Memory：言语记忆与经验复用经典线。
  • Gödel Agent / Darwin Gödel Machine：自指 agent 与档案库式自改进，Scope 论文选的是部署谱系而非档案最优视角。

归纳总结

三篇论文拼出一个完整的技能系统可靠性工程图景：

  • SkillPivot 定位"改哪里"：失败→偏差点→后缀对比→最小 delta。信号颗粒度从"整条轨迹"细化到"分叉后缀"，与全轨迹反思相比降噪明显。教师续跑解决了"失败案例没有对照"的老问题——从同一前缀分叉构造对照，是受控实验思想在技能进化里的移植。
  • Scope 定位"存到哪"：局部认证≠全局安全。这个发现对所有持久记忆系统都是警告：证据域必须匹配部署域。AND 门数学（β 连乘）说明堆验证器不如降错误相关性。
  • HEXIS 定位"怎么执行"：自然语言技能→编译成可执行结构，把"模型 infer 下一步"换成"状态机转移条件强制"。知识留给模型、控制流交给机器，是 LLM 可靠性问题的经典解法（同 MC/DC 覆盖逻辑在航电中的角色）。
  • 共同元趋势：技能系统正从「文档检索增强」走向「工程化制品」——有编译、有门禁、有作用域、有回归测试。自然语言技能库=源代码，正在长出它的编译器和 CI。

趋势判断

  • 技能自进化研究的重心从"能不能进化"（SkillGen/Forge 阶段）转向"进化不伤人"（回归门禁/作用域/干扰防护）——2026 下半年密度最高的是安全阀设计，这是系统进入生产期的标志。
  • 跨模型迁移成为新的价值锚点：技能更新若只对生成它的模型有效=模型补丁；跨模型有效=执行知识蒸馏。SkillPivot 的五模型全正增益与 HEXIS 的零改动跨 backbone 是这一标准的确立性证据。
  • 「编译而非提示」路线（HEXIS/StateFlow/TraceCompiler）会在结构化领域（表格/审计/SOP）先落地，token 节省 38~89% 是硬经济账。
  • 部署谱系评估（deployed lineage, 全序列平均而非档案最优）会成为自改进系统的标准评估法——挑最好检查点报告=幸存者偏差。

关联分析

  • Hermes 的 session-evolution-scan（L1 信号层）正是 SkillPivot 的"偏差点检测"对应物：扫用户纠偏信号而非全量日志，Signal-to-noise 明显更优。SkillPivot 的"教师续跑构造对照"当前缺位——可以设想：同一任务用更强模型重跑分叉段，差分即技能缺口。
  • Hermes skill 的 category 分组 ≈ Scope 论文的任务族。跨族干扰在 Hermes 的实际形态：为 DUCK 训练写的 skill patch（如"发射后必验 60s"）若被泛化检索到量化/笔记任务=干扰。当前靠 description 写得窄来隐式防护，无显式 scope 声明。
  • HEXIS 对长流程 cron 链的启示：W5R 自治链（验收→续训→拉回→落盘）本质是状态机但靠 prompt+cron 隐式实现，orchestrator-handoff-pattern skill 已有 YAML 状态机思路——HEXIS 提供了「从技能文档自动编译状态机+重放验证」的完整算法可抄。
  • 用户「递归自我进化」明令（09-21/09-22）：三层映射（L1 信号扫描→L2 用户拍板沉淀→L3 evolution_log 对账）与 SkillPivot 的回归门禁哲学一致；Scope 论文的族域检索是 L2 层缺的一环——skill patch 应声明适用域，检索时只在域内生效。

拓展应用推荐

  1. 【P0·Hermes】skill frontmatter 加 scope 字段（声明适用任务域，如 scope: [duck-training, mjlab]），session-evolution-scan 产出的候选 patch 强制带 scope；防跨域污染（对应 Scope 论文核心发现）。工作量：frontmatter 约定+curator 简单校验。
  2. 【P1·Hermes】错误案例库引入"偏差点"字段：error-case 落盘时记录"从第几步开始错+之前哪些步骤有效"，而非只记根因——为后续对照构造提供结构。Data Meow 可在下次案例落盘时试点。
  3. 【P1·Hermes】长流程 cron 自治链（W5R 类）的 EFSM 化改造评估：把 launch_gate→runtime_guard→stand_eval→death_ledger 的转移条件显式化（现散在各脚本 if 判断里），重放验证机制照抄 HEXIS 的"复现全部历史迹才提交"。
  4. 【P2】跟踪 SkillsBench/SkillAudit 的评测方法，为 Hermes skill 库建"有无技能对照"的 A/B 基线（skill-ab-testing skill 已有雏形，缺对照执行记录结构）。

指南分析

落地 SOP（skill scope 字段，P0）：

  1. 定义 frontmatter schema：scope: [域列表]，缺省=[general]；curator 在 patch/merge 时校验 scope 合并结果（并集）并记录进 provenance。
  2. 检索侧改动：skills_list/skill_view 无需改（人肉检索）；session-evolution-scan 的候选生成时核对 scope——DUCK 纠偏只出 DUCK 域候选。
  3. 灰度：先对 robotics/quant/devops 三大类打 scope 标签（约 50 个 skill），观察两周跨域引用是否减少。
  4. 回归门禁：evolution_log.jsonl 已是审计底账，scope 违规（A 域证据 patch 到 B 域 skill）记为 gate FAIL 事件。

避坑：scope 粒度勿过细（按项目分）——族=任务模式非项目实例，DUCK 训练和 mujoco 调试是不同族；scope 缺省值必须是显式 general 而非空（空=全域检索=回到老问题）。
