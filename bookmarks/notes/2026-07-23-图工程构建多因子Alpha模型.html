核心结论

多因子投资是每个严肃对冲基金（AQR/Two Sigma/Bridgewater）产生回报的方式——他们不交易单一想法，他们堆叠因子。过去这需要 10 人研究团队，现在通过图工程（Graph Engineering），单个构建者就能运行一个自驱动的多因子 Alpha 模型。核心方法：每个因子变成图中的一个节点，用 Slate 运行整个图，每 24 小时自动执行。

一、Agent 演进四阶段

阶段 特征 持久性
Stage 1: Prompts 你就是循环——打字→等待→读输出→打字 关电脑即消失
Stage 2: Loops 脚本包裹 Prompt，按计划触发，持有状态 关电脑后存活
Stage 3: Swarms 循环扇出为多个专业化 Agent（生成信号→验证→执行） Python 胶水代码手动协调
Stage 4: Graphs 描述一次协调结构，图自动运行——知道何时并行/等待/重试/升级 不再碰胶水代码

图工程就是设计那个协调结构的实践。你定义节点，定义边，图自己运行。

为什么图 > 脚本？

脚本的失败模式 图的解法
一个 Agent 需要等另一个 → 脚本崩溃 并行是原生的
状态需要跨周期持久 → 脚本崩溃 状态是持久的
想要 6 个循环并行不同模型 → 脚本崩溃 原生支持
失败波及整个管道 失败限定在节点级，图的其余部分继续运行

二、七因子模型（2026 对冲基金标准）

基于 Fama-French 三因子（1993）→ Carhart 加动量（1997）→ 五因子（2015）的演进：

因子 含义
1. Market Beta 股票超额收益对市场超额收益的 60 月滚动回归
2. Size (SMB) 小盘股风险调整后跑赢大盘股
3. Value (HML) 高账面市值比长期跑赢低账面市值比
4. Momentum (MOM) 12 个月赢家继续赢 3-12 个月
5. Profitability (RMW) 稳健运营商跑赢弱势运营商
6. Investment (CMA) 保守资产增长跑赢激进扩张
7. Low Volatility 低波动股赚取比理论预测更高的风险调整收益

Alpha (α) 是模型无法解释的残差——那就是你猎取的目标。

三、11 节点多因子 Alpha 图

因子构建节点（7 个，并行运行）

节点 任务
Node 1: Market Beta Agent 60 月滚动回归，输出每只股票的 Beta
Node 2: Size Agent 按市值排序，计算小-大价差
Node 3: Value Agent 按账面市值比排序，计算高-低价差
Node 4: Momentum Agent 计算 12-1 月动量，从十分位价差构建 MOM
Node 5: Profitability Agent 计算毛利润率，构建 RMW
Node 6: Investment Agent 计算年度资产增长，构建 CMA
Node 7: Low Vol Agent 计算 60 日已实现波动率，从十分位价差构建低波

协调节点（4 个，顺序运行）

节点 任务 模型
Node 8: Validator Newey-West t 统计量 + 10,000 次 Bootstrap；杀死样本内外退化>30% 的因子 Opus（强推理）
Node 9: Regime Auditor 用 HMM 将 20 年历史分为 3 个制度；杀死只在一个制度有效的因子 Opus
Node 10: Portfolio Constructor 风险平价权重组合存活因子；强制行业/Beta/美元中性 Opus
Node 11: Risk Decomposer 对 7 因子+风格+宏观因子回归；报告残差 Alpha 和 t 统计 Opus

Maker never validates maker——制造者从不验证自己的工作。

只有残差 Alpha 在因子分解后存活的信号才是真正的新 Alpha，其他都是换了包装的风格因子。

四、Slate 工具：图的运行时

维度 说明
工具 Slate（by @wearerandomlabs）
形态 终端运行，npm 全局包
Programs 用 JavaScript 写的图，Slate 持续运行
交互方式 自然语言描述 → Slate 画图 → 你审图修改 → 运行
模型 自动拾取已有订阅（OpenAI Codex / GitHub Copilot / Random Labs 90 个模型）
调试 用自然语言描述故障 → Slate 修补节点

两个内置示例 Program

/goal——运行直到可验证完成

/goal implement a Newey-West adjusted t-statistic function in Python
and verify it matches the statsmodels implementation on ten random return series

图自动：写函数节点 → 写验证测试节点 → 运行两者 → 评分节点判断是否匹配 → 不匹配则带反馈循环回去。

/deepresearch——并行研究扇出

/deepresearch what does the latest academic research say about the
Fama-French five factor model out of sample performance in emerging
markets from 2015 to 2026

多个 Worker Agent 并行：读论文 / 查 arXiv / 拉 Kenneth French 数据 / 交叉引用引用 → 中央编排器综合。

五、11 步构建流程

步骤 操作
1 npm i -g @randomlabs/slate 安装
2 创建项目目录 ~/projects/multifactor-alpha
3 运行 slate
4 /providers 连接 Provider（Codex/Copilot）
5 /models 选两层模型：Sonnet（快速因子构建）+ Opus（验证/审计/分解）
6 用 /goal 和 /deepresearch 热身 30 分钟
7 用自然语言描述 11 节点图，Slate 起草
8 审查图示，提问（为什么用 Opus？超时怎么办？什么状态持久？）
9 slate run multifactor-alpha.js
10 /budget $30/run 设置预算
11 出错时用自然语言告诉 Slate，Slate 修补节点

核心设计规则

  • Sonnet 用于 7 个因子构建（快速层）
  • Opus 用于 4 个协调节点（强推理层）
  • Newey-West t 统计 > 2.5
  • Bootstrap 10,000 次迭代
  • 拒绝样本内外 Sharpe 退化 >30% 的因子
  • 文件系统作为记忆
  • 每 24 小时运行一次
  • 预算 $30/次

六、每 24 小时发生了什么

凌晨 3 点，图唤醒:

1. 7 个因子 Agent 并行触发 → 拉最新数据 → 更新因子时间序列
2. Validator: Newey-West t 检验 + 10,000 次 Bootstrap
   → 拒绝约 80% 看起来有前景的因子
3. Regime Auditor: HMM 分制度 → 重算每制度 Sharpe
   → 只在一个制度有效 = 那个制度的 Beta，不是 Alpha
4. Portfolio Constructor: 风险平价权重 + 中性约束
5. Risk Decomposer: 对全因子回归
   → 残差 Alpha t>2.5 → 信号存活
   → 否则记录为"今日无信号"

结果: 每天早上收到 Slack 消息
  要么有可交易信号
  要么有文档证据表明今天是噪音

两种结果都有用，都不需要你在键盘前。

七、七步蓝图总结

步骤 要点
1. 理解演进 Prompts → Loops → Swarms → Graphs
2. 了解因子 7 个因子，每个变成一个节点
3. 设计 11 节点 7 并行 + 4 顺序，先画图再写代码
4. 不同节点用不同模型 Sonnet 构建，Opus 验证，Maker 不验证 Maker
5. 强制硬规则 t>2.5 / Bootstrap 10K / HMM 三制度 / 残差 Alpha t>2.5
6. 用示例热身 /goal 和 /deepresearch 建立直觉
7. 让它复利 月1找 Bug，月2精炼因子，月3产生可交易信号

八、关键洞察

洞察 说明
图 ≠ 脚本 图原生支持并行/持久/节点级失败隔离
Maker-Checker 模式 制造者从不验证自己的工作
预算诚实 Slate 坦诚 $30/run 是建议性的而非硬中止——"这第三个声明是我信任这个工具的原因"
残差才是真 Alpha 因子分解后存活的残差才是新信息，其他都是换包装的风格
制度鲁棒性 只在一个市场制度有效 = 那个制度的 Beta，不是 Alpha
描述 > 编码 自然语言描述图 → 审图 → 运行，不写胶水代码
