Hermes Agent 记忆插件横评：8 款方案深度拆解

来源：微信公众号 · 荣哥 · 2026-05-26
标签：#Hermes #记忆系统 #AI Agent #Holographic #插件评测

核心问题

Hermes Agent 内置记忆容量仅 2,200 字符（约三四句话），所有内容平铺无结构，撑满就得手动挤掉旧的。每次对话像重新认识。

解法：通过第三方记忆插件扩展，从"便利贴"升级为"图书馆检索系统"。

记忆两层架构

层级 模式 特点
内置记忆 2,200 字符纯文本，每次对话自动加载 简单直接，但极小，无结构
插件记忆 数据库存储，空间不限 支持语义搜索、结构化查询、信任评分

8 款记忆插件横向对比

★★★★★ Honcho（最强推理）

维度 内容
费用 免费/付费
部署 云端或自部署
技术 多轮辩证推理
亮点 真正理解上下文推断意图，按目录/项目/会话隔离
缺点 配置复杂，需 API Key，新手劝退

★★★★☆ Mem0（最流行）

维度 内容
费用 付费
部署 云端
技术 LLM 事实提取 + 语义搜索
亮点 自动提取关键信息、自动去重、开箱即用，GitHub 最火
缺点 云端付费，数据不在本地

★★★☆☆ Holographic（作者选择）⭐

维度 内容
费用 免费
部署 本地 SQLite
技术 FTS5 全文搜索 + HRR 向量检索
亮点 纯本地零依赖，隐私最好，自带信任评分自动遗忘
缺点 无云端同步，无 Honcho 的多层推理

★★★★☆ RetainDB（最精准控制）

维度 内容
费用 $20/月
部署 云端
技术 向量 + BM25 + 重排混合搜索
亮点 7 种记忆类型，主动遗忘，控制力最强
缺点 最贵，个人项目心疼

Holographic 配置（三行命令）

# 查看当前记忆状态
hermes memory status

# 设置记忆提供者
hermes config set memory.provider holographic

# 验证生效
hermes memory status

配置文件：

memory:
  memory_enabled: true
  user_profile_enabled: true
  provider: holographic

数据库位置：~/.hermes/memory_store.db（SQLite）

Holographic 工作机制

三层检索：
1. FTS5 全文搜索 — 关键词匹配
2. HRR 向量检索 — 语义相似性
3. 实体解析 + 信任评分 — 判断事实可靠性，低分自动遗忘

9 种操作：

操作 用途
add 添加事实
search 搜索事实
probe 查询实体
related 查关联
reason 多实体推理
contradict 矛盾检测
update 更新
remove 删除
list 列出所有

还有 fact_feedback（点赞/踩），踩多了自动遗忘——像人一样慢慢忘掉不重要的。

使用体验

以前每次对话像新下载的 App，干干净净。现在像跟你共事三个月的同事——知道你偏好什么工作方式，手上有几条线在跑。

关键改变：不需要每次重复交代背景，Agent 自己记住并理解上下文。

思考

文章的核心洞察——记忆是 AI Agent 从"工具"到"助手"的分水岭。我们当前使用 Hermes 内置记忆 + Memory Graph（MCP），已覆盖基本需求。Holographic 的 FTS5 + HRR 双层检索模式值得关注，特别是信任评分自动遗忘机制。但对于重度用户，Honcho 的多轮辩证推理可能是更强的选择。

对我们系统的意义：当前 Memory Graph 方案与 Holographic 思路类似（图谱 + 搜索），但缺少信任评分和自动遗忘。可作为未来优化方向参考。
