根因分析

1. Gemini 3.x 系列全超时

  • 现象：gemini-3-flash、gemini-3.5-flash-low/extra-low、gemini-3.1-pro-high/low、gemini-3.1-flash-image 全部 6 秒超时
  • 根因：这些模型共享同一批 Gemini 账号池（8 个账号），根据 antigravity-model-failover 技能记录，当所有账号同时 QUOTA_EXHAUSTED 时，代理返回超时而非 503
  • 验证：执行 curl -s http://localhost:8045/api/accounts | jq '.accounts[] | {email, quota: .quota.models[] | select(.percentage >= 100)}' 可确认各账号配额状态

2. gemini-2.5-flash 400 错误

  • 现象：HTTP 400，错误信息为 safety_settings 中的 HARM_CATEGORY_CIVIC_INTEGRITY 不被接受
  • 根因：Gemini API 已弃用 HARM_CATEGORY_CIVIC_INTEGRITY（ civic integrity category），但 Antigravity 代理仍发送该 category
  • 修复：在 ~/.antigravity_tools/gui_config.json 的 proxy 配置中移除该 safety category，或等待上游修复

3. gemini-3-pro-image 404 错误

  • 现象：HTTP 502，上游返回 404 "Requested entity was not found"
  • 根因：当前 Gemini 账号池中的账号无 Imagen 3（gemini-3-pro-image）的 API 权限
  • 修复：添加支持 Imagen 3 的 Gemini 账号到池，或改用其他图像生成模型

后续行动

  1. 检查配额：运行 curl -s http://localhost:8045/api/accounts 确认各账号各模型配额
  2. 修复 gemini-2.5-flash：修改 Antigravity 配置移除 HARM_CATEGORY_CIVIC_INTEGRITY
  3. 添加 Imagen 3 账号：如需图像生成能力，添加支持 gemini-3-pro-image 的 Gemini 账号
  4. 启用主动配额探测：参考 antigravity-model-failover 技能，实现 /api/accounts 轮询避免超时
