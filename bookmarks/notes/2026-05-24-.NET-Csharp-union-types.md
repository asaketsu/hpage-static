## 核心内容

.NET 11 Preview 2 引入了 C# 15 的 union types 支持，这是社区请求多年的功能终于落地。Union types 允许一个类型表示多种不同的值，类似于 Rust 的 enum、TypeScript 的 union types 或 Haskell 的 algebraic data types。

### 基本语法

```csharp
[Union]
public union SupportedOS(string osName, int version);

// 使用
SupportedOS os = new SupportedOS("Windows", 11);
```

Union 声明列出可以包含的类型，编译器自动生成实现。

### 典型用例

#### Option 和 Result 类型

```csharp
[Union]
public union Result<TSuccess, TError>
{
    TSuccess Success;
    TError Error;
}

// 使用
Result<string, Exception> result = new Result<string, Exception>.Success("OK");
```

#### 多类型容器

```csharp
[Union]
public union IntOrBool(int i, bool b);

// 解构
if (value is int i) { ... }
else if (value is bool b) { ... }
```

## 技术实现

### 默认实现（带装箱）

默认情况下，union 类型实现 `IUnion` 接口，通过 `Value` 属性返回 `object`：

```csharp
public object Value => _isBool ? (object)_boolValue : (object)_intValue;
```

这会导致装箱（boxing）分配，在热路径中可能影响性能。

### 非装箱实现

通过实现 `TryGetValue` 模式避免装箱：

```csharp
[Union]
public struct IntOrBool : IUnion
{
    private readonly bool _isBool;
    private readonly int _value;

    public bool HasValue => true;
    
    public bool TryGetValue(out int value)
    {
        value = _value;
        return !_isBool;
    }
    
    public bool TryGetValue(out bool value)
    {
        value = _isBool && _value == 1;
        return _isBool;
    }
}
```

编译器在 switch 表达式中自动使用 `TryGetValue` 而非 `Value` 属性。

### Switch 表达式支持

```csharp
string str = unmatchedValue switch
{
    int _ => "integer",
    bool _ => "bool",
    _ => throw new InvalidOperationException()
};
```

## 未来特性

以下特性尚未包含在 .NET 11 中，但已规划：

1. **Union Member Providers** — 在 union 类型外部定义成员
2. **Closed Enums** — 不需要 catch-all 分支的 enum switch
3. **Closed Hierarchies** — 防止外部派生类的 sealed 类层次

## 借鉴进化点

1. **语言特性设计的渐进式策略** — .NET 团队采用"先可用，再完善"的策略：先提供基础 union 支持，后续迭代添加非装箱实现和更高级特性。这种 MVP 式语言特性发布模式值得其他语言团队参考。

2. **性能与便利性的权衡** — 默认实现简单但带装箱开销，高级用户可通过实现 `TryGetValue` 获得零开销。这种"默认够用，高级可选"的设计哲学平衡了易用性和性能。

3. **模式匹配的演进路径** — Union types 与 C# 的模式匹配（pattern matching）深度集成，展示了类型系统与语法特性的协同演进。语言设计应考虑特性间的组合效应。

4. **社区驱动的特性开发** — Union types 是社区长期请求的功能，.NET 团队通过 RFC 流程收集反馈、迭代设计。这种开放的语言设计流程值得借鉴。
