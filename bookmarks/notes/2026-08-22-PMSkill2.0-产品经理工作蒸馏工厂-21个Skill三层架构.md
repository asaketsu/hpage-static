## 一句话总纲

> **「说出你的产品问题，它给你调一支专家顾问团和执行团队」**——pm-master 总控分诊路由 + 13 个执行 Skill 消摩擦 + 7 个 Advisory Skill（Cagan/Torres/俞军/Mom Test 等）照盲区，链路模式下「交接摘要」接力全流程。

## 一、内容详细整理

### 1.1 三层能力架构（2.0 核心设计）

```
┌─ 全局总控 ────────────────────────────────────┐
│ pm-master：唯一入口                              │
│ 分诊问题 → 路由 Skill → 编排工作流链路            │
├─ 执行工具箱（13 个生产型 Skill：消摩擦）─────────┤
│ PRD / 评审 / 排序 / 路线图 / 数据分析 / 实验      │
│ 埋点 / 问卷 / 竞品 / 复盘 / 原型(3种)            │
├─ 专家顾问团（7 个 Advisory Skill：照盲区）───────┤
│ Cagan / Torres / 俞军（专家视角）                 │
│ Mom Test / Story Mapping / Build Trap（方法论）  │
│ pm-advisory-board（顾问团总控入口）              │
└──────────────────────────────────────────────┘
```

**创作来源的洞察**：产品经理工作的特点是"高度重复，但每次都感觉在从头开始"——

- 执行摩擦（写 PRD 的结构/排序框架/复盘格式每次都重想）→ 执行工具箱消掉
- 判断质量（该不该做/真需求还是客套话/为什么 outcome 没变）→ 顾问团把盲区照出来

### 1.2 执行工具箱：13 个 Skill 一句话

| Skill | 干什么 |
|-------|--------|
| `pm-master` | 全局总控：分诊 → 路由 → 编排链路 |
| `pm-prd-writer` | 模糊描述 → 可过评审的 PRD（含阶段零需求体检） |
| `pm-review-board` | 模拟 6 个角色同时喷你的需求（三档评审+意见质量红线） |
| `pm-prioritization-engine` | RICE/ICE/Kano 三模型同打分（敏感性分析+高分歧裁决） |
| `pm-roadmap-planner` | 目标+人力 → 带甘特图的路线图 |
| `pm-analytics` | 数据跌了→找原因→给建议一条龙 |
| `pm-experiment-designer` | 假设/分流/样本量/止损规则一次搞定 |
| `pm-tracking-spec-writer` | 用户链路 → 埋点事件 + QA 校验 SQL |
| `pm-survey-designer` | 调研目标 → 问卷题（每题对应一个假设） |
| `pm-competitor-deconstructor` | 四维拆解竞品（哪些能抄/不能抄） |
| `pm-postmortem-writer` | 5-Why 归因 + 强制分级行动项 |
| `pm-image2proto` | 截图 → 可运行 HTML 原型 |
| `pm-url2proto` / `pm-image2pencil` | 网址 → Next.js 项目 / 截图 → Pencil 设计稿 |

### 1.3 专家顾问团：7 个 Advisory Skill

| Skill | 类型 | 视角/方法 |
|-------|------|----------|
| `pm-advisory-board` | 总控入口 | 自动路由专家、组织多视角评审 |
| `pm-advisor-cagan` | 专家视角 | Marty Cagan 四大风险、赋能团队、discovery |
| `pm-advisor-torres` | 专家视角 | Teresa Torres 持续发现、机会解决方案树、假设验证 |
| `pm-advisor-yujun` | 专家视角 | 俞军用户价值公式、交易模型、决策效用 |
| `pm-method-mom-test` | 方法论 | 访谈问题改成能挖真实信号的问法 |
| `pm-method-story-mapping` | 方法论 | 需求拆故事地图，切可发布 MVP |
| `pm-method-build-trap` | 方法论 | 检查功能陷阱，把战略连回 outcome |

### 1.4 链路编排（最有特色的设计）

**判断链**（顾问团负责）：

```
Mom Test 取真信号 → Torres 挂进机会树 → 俞军算用户价值和替换成本
→ Story Mapping 切 MVP → Build Trap 连回 outcome → Cagan 复核四大风险
```

**执行链**（执行工具箱接力）：

```
pm-prd-writer 写 PRD → pm-review-board 预审 → pm-tracking-spec-writer 写埋点
→ pm-experiment-designer 设计实验 → pm-postmortem-writer 做复盘
```

**关键机制**：每个执行 Skill 声明**上游输入和下游交付**，链路模式下用「交接摘要」接力，不用每步重新解释上下文。

### 1.5 真实反馈（作者引用的用户声音）

- **pm-review-board 最能救命**：评审会被喷通常不是需求有大问题，而是某角色的顾虑没被提前考虑——会前全过一遍，会上只需确认
- **pm-experiment-designer 解决长期问题**：样本量/止损规则/判定标准前置——原来全靠经验，现在有检查清单
- **pm-prd-writer 价值在补漏不在写**：正文自己写不慢，慢的是被反复问"异常流程/埋点/非功能需求"——生成后自动补一遍
- **pm-advisory-board 让分歧提前出现**：方案缺的不是结论，是分歧地图——"它不替你拍板，但让你知道自己到底在赌什么"
- **pm-method-mom-test 适合所有访谈前**：把"你会不会用"改成"你上次怎么解决"——把想象拉回事实

### 1.6 使用方式

```bash
# 单个 Skill
~/.claude/skills/pm-prd-writer/
# 顾问团（7 个子目录或先只装总控）
~/.claude/skills/pm-advisory-board/
```

触发示例："帮我推进这个需求，从头到尾走一遍"（pm-master 编排）/ "用俞军的用户价值公式算算这个功能值不值得做" / "用 Mom Test 改一下这份访谈提纲"

## 二、查询拓展

### 2.1 Agent Skills Standard 兼容

仓库带 "Agent Skills Standard" 徽章——SKILL.md 格式遵循 Anthropy 的 Agent Skills 规范（name/description/triggers frontmatter），因此可跨运行时使用：Claude Code / Codex / Cursor / skills.sh 兼容 Runtime。这与 Hermes 的 skill 体系同源——理论上 pm-skills 可直接复制进 `~/.hermes/skills/` 使用。

### 2.2 "专家蒸馏"模式

pm-advisor-* 系列的思路是把**专家的书/方法论蒸馏成评审视角**：

- Cagan《Inspired》《Empowered》→ 四大风险（价值/可用性/可行性/商 viability）+ 赋能团队
- Teresa Torres《Continuous Discovery Habits》→ 机会解决方案树 + 每周访谈 + 假设地图
- 俞军《产品方法论》→ 用户价值 = 新体验 − 旧体验 − 替换成本
- Rob Fitzpatrick《Mom Test》→ 三原则（谈他们的人生不是你的点子/问过去不是将来/少说多听）
- Jeff Patton Story Mapping → 叙事主线 + 切片发布
- Melissa Perri《Escaping the Build Trap》→ 功能陷阱检查 + outcome 导向

这与本机的 persona-modeler skill（人物思维建模）同构——输入人名 → 调研 → 提炼决策模型 → 生成可复用 persona。

### 2.3 与同类 Skill 集合的生态位

- Anthropic 官方 skills（document-skills 等）：通用文档处理
- obra/superpowers：开发者工作流
- pm-skills：垂直职业（产品经理）全流程——**职业级 Skill 蒸馏工厂**的代表作，作者另有 career.skill 项目（输入任意职业自动拆 Skill 库）

## 三、归纳总结

### 3.1 架构亮点提炼

| 设计 | 机制 | 借鉴价值 |
|------|------|----------|
| **总控分诊** | pm-master 是唯一入口，用户不用知道用哪个 Skill | 降低 Skill 集合的认知负担 |
| **执行/判断分层** | 执行 Skill 消摩擦（快），Advisory Skill 照盲区（对） | 两类 Skill 的 KPI 不同：效率 vs 质量 |
| **上下游契约** | 每个 Skill 声明上游输入/下游交付 | 链路可编排，交接摘要接力 |
| **专家蒸馏** | 把书/方法论变成可调用的评审视角 | 知识资产化的范式 |
| **分歧地图** | 顾问团不替你拍板，让分歧提前出现 | 决策支持而非决策替代 |

### 3.2 与 Hermes 体系的映射

| pm-skills 设计 | Hermes 对应 | 差距/借鉴 |
|---------------|-------------|----------|
| pm-master 总控分诊 | jbot-meow（猫仔接单→评估→分配） | 已有同构；pm-master 的"链路编排"更显式 |
| 执行/Advisory 分层 | 四猫分工（Dev/OPM/Content/Data） | 四猫是职能分层，pm 是**效率/质量分层**——新维度 |
| 上下游契约+交接摘要 | context 一次性原则（AGENTS.md） | pm 的"交接摘要"是链式接力，本机是单次写透 |
| 专家蒸馏（Cagan/俞军） | persona-modeler skill | 同构！本机已有方法论，pm-skills 是现成样例 |
| 6 角色预审（review-board） | 执行/评判分离（Harness 准则） | pm 落到"评审会模拟"场景，更具体 |

## 四、趋势判断

### 趋势 1：职业级 Skill 工厂将成为 Agent 生态的垂直增长点

> 依据：pm-skills 915 Star + 作者的 career.skill（任意职业自动拆 Skill 库）。通用 Agent 能力趋同后，竞争转向垂直职业工作流的蒸馏深度。

### 趋势 2：「顾问团模式」成为 Agent 决策支持的主流形态

> 依据：pm-advisory-board 的核心价值是"分歧地图"而非结论——这规避了 AI 直接决策的责任问题，同时放大多视角价值。与 EnvHarness 的"goal predicate 不动"同理：AI 照亮盲区，人类保留拍板权。

### 趋势 3：Skill 间上下游契约将标准化

> 依据：pm-skills 全部 Skill 声明上游输入/下游交付 + 交接摘要接力。当 Skill 数量超过个人认知管理上限（本机已 400+），链路编排取代单点调用成为必然。

## 六、拓展应用推荐

### 6.1 可直接借鉴的 5 个设计

1. **总控分诊模式**：本机 Skill 检索可借鉴 pm-master——用户描述问题（而非点名 Skill）→ 总控分诊路由。knowledge-query 已是查询侧入口，可扩展到"工作流编排"侧
2. **上下游契约声明**：给高频协作的 Skill 组（如 note-dual-format + bookmark-reader + auto-md2html）显式声明输入/输出接口，链式调用时交接摘要接力
3. **评审会模拟**：重大决策（技术选型/架构改动）前跑"6 角色预审"——借鉴 pm-review-board，用 subagent 扮演不同关切方（安全/性能/运维/成本/用户/维护者）
4. **专家蒸馏范本**：pm-advisor-* 的 SKILL.md 是"书→评审视角"的蒸馏范本，本机 persona-modeler 可参考其结构（触发词/视角框架/输出格式）
5. **分歧地图输出**：多视角分析时不强求收敛结论，输出"分歧地图"（谁主张什么/赌注是什么/需要什么证据裁决）——适合 OPM 决策场景

### 6.2 安装试用建议

```bash

# 建议先装单个试用：pm-review-board（评审模拟）或 pm-method-mom-test（访谈改造）
```

## 七、指南分析

### 7.1 项目质量

- **问题定义精准**：'高度重复但每次都感觉在从头开始'一针见血；执行摩擦 vs 判断质量的两分法干净
- **架构克制**：不堆 21 个平级 Skill，而是三层（总控/执行/顾问）+ 链路契约
- **反馈真实**：引用的用户声音具体到场景（评审会/实验设计/访谈），非空洞好评
- **边界诚实**：结尾明确"AI 替代不了拍板/说服/最终决策"——工具定位清晰

### 7.2 局限

- 无量化效果数据（省了几小时/评审通过率变化）——README 是质性叙事
- 11 commits / 2026 新仓库，长期维护待观察
- 原型类 Skill（image2proto/url2proto）依赖前端生成质量，效果未验证
- 深度依赖中文产品圈语境（俞军方法论海外不通用）

## 八、金句摘录

> "每一个 Skill 都在回答同一个问题：这件事我每次都要重新想一遍，能不能让 AI 替我想？"

> "这些摩擦加起来，就是每天下班晚两个小时的原因。"

> "PRD 写得再完整，如果前面的机会、风险、用户价值和战略连接没想清楚，最后只是更高效地做错事。"

## 九、行动启示

- **本机 Skill 总控缺位是明确差距**：400+ Skill 已超个人认知管理上限，pm-master 的"描述问题→分诊→编排"模式值得做原型（P2，与 capability-patrol 同期评估）
- **上下游契约可先在笔记链路试点**：bookmark-reader → note-dual-format → auto-md2html → homepage 刷新四步链是最高频协作组，先给它声明接口
- **评审会模拟可立即用于重大决策**：下次架构选型/大改动前跑一次 6 角色预审（subagent 扮演），成本低于事后回滚
- **pm-skills 可直接复制试用**：Agent Skills Standard 兼容，`pm-review-board` 和 `pm-method-mom-test` 两个单体价值最高
