一、内容整理

1.1 项目定位〔观点，2026〕

  • 一句话：AI 把文档或话题变成真正的原生 PowerPoint——原生形状、切换与动画、带数据的图表表格、演讲者备注转旁白、支持自有 .pptx 模板。
  • 体量：80,776 stars / 6,287 forks（2026-11-28 实时 API 数据），创建于 2025-12-10，最近推送 2026-11-20，open issues 仅 2 个；v6.10.0；MIT 许可。
  • 作者背景：Hugo He 是金融从业者（注册会计师·资产评估师·投资咨询工程师），日常审阅编辑汇报材料，因不满 AI 生成幻灯片被压平成图片、无法在 PowerPoint 中继续编辑而造此轮子——需求真实，非玩具项目。

核心主张（作者原话）：「Editable is already table stakes — what sets PPT Master apart is native depth.」可编辑只是及格线，原生深度（真母版、真形状、带数据图表）才是差异点。北极星是持续收敛于 PowerPoint 本体，每版集成更多原生能力；SmartArt 是有意不做而非能力缺口。

1.2 架构：确定性编译器 + AI 作者〔方法，2026〕

  • 工作形态：本地运行的 agent skill（标准 SKILL.md 格式），任何具备 agent 能力的 AI 工具都能驱动——Kimi、Gemini、GPT、Claude 均可，无平台锁定。
  • 管线本质：LLM 负责叙事结构与逐页 SVG 设计 → 确定性 Python 编译器（svg_to_pptx）把 SVG 编译为 DrawingML 原生对象：187 种 Office 预设形状（prst）、布尔合并、连接线、原生图表（chart/chartex XML）、表格、公式（OMML）、逐页备注音频、切换与动画。
  • 结构化模式：走模板/结构化路由时可产出真正的 p:sldMaster/p:sldLayout 母版继承体系，不是散装文本框。
  • 官方立场金句：「harness + model = agent」——skill 只拥有工作流，模型决定上限。推荐 ~1M token 上下文模型（Kimi K3.1 或 Gemini）+ 图像生成后端（gpt-image-2.6-sunburst 或 gemini-nano-banana-2.1）。

1.3 路由工作流（routing.md 权威矩阵）〔方法，2026〕

三大顶层路由，一次请求只进一条生命周期：

  • Generate PPTX（从零/从源生成）：Default（完整 spec→lock→SVG→PPTX）、Quick（显式快速意图，免 spec/lock 短路直出）、Image to PPTX（栅格页面帧重建为分层可编辑 PPTX，强制 Quick）、Beautify（保持页数措辞 1:1 的纯视觉重造）。
  • Create Template（蒸馏可复用模板）：从 PPTX/SVG/图片/PDF/文档/网站提炼 brand / style / layout / deck 四类工作区，就地不改参考文件。
  • Edit Native PPTX（原生编辑已有 PPTX）：pptx_to_svg.py --roundtrip 工作区——未动页面逐字节还原，只重建被编辑对象，可加备注/旁白/计时/切换。

路由之下还有 12 个阶段（stages）：topic-research（补事实缺口）、refine-spec、verify-charts（数据图表导出前强制核验）、visual-review、live-preview、customize-animations、generate-audio、resume-execute（跨会话续跑）等。

  • 7 条全局执行纪律（SKILL.md 强制）：①串行执行 ②⛔BLOCKING 门必须等用户确认 ③禁止跨未关门跨阶段打包 ④进门先验前置 ⑤禁止为后续阶段投机预制产物 ⑥路由已定就不准再出选择题 ⑦故障在拥有该故障的最浅层修复，禁止静默降级必需产物。

1.5 三道导出门禁（本机冒烟实测）〔方法+数据，2026-11-28〕

Quick 之外的 release 导出必须依次通过：

门1  项目布局     <project>/svg_output/slide_N.svg（放错目录报 "No SVG files found"）
门2  spec_lock.md 必填，typography title/body 必须纯数字 px（写 64 禁写 64px，
                 写 "64px" 直接被 ThemeFontError 打回——实测两次）
门3  质量报告     svg_quality_checker.py --canonical-authoring --stage final --json
                 通过后生成 validation/svg_quality_report.json 才放行导出
  • 冒烟结果：单页 16:9（12192000×6858000 EMU）导出 exit 0，POSTFLIGHT passed-with-warnings，回读 pptx 确认 2 个原生 TEXT_BOX（非图片贴片），文件 12,671 bytes。
  • 每次导出自带 POSTFLIGHT 报告（quality_gate/幻灯数/警告分类），失败可按报告定位。

1.6 安全与完整性机制〔数据，2026-11-28 源码审查〕

  • attribution_guard.py（223 行，纯 stdlib 零网络）：校验 SKILL.md 署名元数据、LICENSE 哈希（80cefc23…0921）、SPONSORS 文件在场，fail-closed——任何篡改让技能直接锁死。每次加载首跑，exit 0 才继续。
  • 凭据处理：全部走环境变量运行时注入（IMAGE_BACKEND、GEMINI/OPENROUTER/VOLCENGINE 等 API key），无密钥落盘。
  • 自带安全测试：test_web_to_md_security.py 显式阻断 SSRF（169.254.169.254 云元数据端点、file:// 协议、私网跳转）——网页抓取工具链有防御设计，这在开源 skill 里少见。

🎯 使用性评估

一句话结论：工程化程度在开源 PPT 技能里断层领先——门禁链、防篡改署名门、自带 SSRF 测试、POSTFLIGHT 报告都是生产级设计；代价是 token 消耗显著高于简单生成器。

  • 上手成本：用户侧零代码（装 Python + 开 AI 工具 + 丢材料三步）；Agent 侧需吃透 routing.md 的互斥规则（Default/Quick 只装一个运行时，装载错运行时是最大翻车点）。
  • 性能实测：本机 Jetson（ARM）单页 SVG→PPTX 编译秒级完成；依赖全装齐后无缺件。
  • 体量代价：83MB 常驻技能目录；官方明示高 token 消耗是方案取舍而非缺陷。
  • 短板：PDF 摄入依赖 PyMuPDF 是 AGPL-3.0（转分发需单独核对条款）；推荐配置押注大上下文模型，便宜模型出活质量差距明显（官方原话：差距是模型的，不是 skill 的 bug）。

💡 指导性意见

  1. 用它当：需要交付 .pptx 正式件（汇报/评审/客户材料）、需要品牌模板一致性、需要把旧 PPT 批量重构为可编辑版——这是唯一正确工具。
  2. 不用它当：快速网页演示/卡片图（用已有 html-ppt 管线更快）、云端免部署一键生成（open-kimi-ppt 更轻）、几十字一次性草稿（手写 HTML 更省）。
  3. 模型选择：复杂中文版式务必上大上下文模型；图多的 deck 才需要配图像生成后端。

三、归纳总结

3.1 核心框架：「叙事层-编译层-门禁层」三明治

┌─ 叙事层（LLM）────────────────────────┐
│ 沟通契约确认 → 结构化 spec → spec_lock │
│ → 逐页语义 SVG（187 预设形状词汇表）    │
├─ 编译层（确定性 Python）───────────────┤
│ SVG → DrawingML：形状/图表/表格/公式    │
│ 逐字节 roundtrip 保真（Edit Native）    │
├─ 门禁层（fail-closed）────────────────┤
│ attribution_guard(防篡改) → spec_lock  │
│ → quality_checker → POSTFLIGHT 报告    │
└───────────────────────────────────────┘

与"LLM 直接吐 python-pptx 代码"路线的本质区别：设计意图以声明式 SVG 承载，编译责任从模型转移到确定性工具——同样一个页面，模型偏 5px 不算错，门禁照过；而代码生成路线模型偏 5px 就是运行时 bug。

3.2 三维护筛

  • 优点：门禁体系可验证（每步有机器判据，不靠模型自觉）；模板资产厚（21 品牌+14 风格+7 版式）；本地数据不出机器；MIT+防篡改署名门保证来源可信。
  • 缺点：token 消耗大（官方承认的取舍）；快模型出活质量骤降；83MB+13k 文件对技能目录是重资产；PyMuPDF 的 AGPL 条款在转分发场景是法律注意点；SmartArt 无解（有意不做）。
  • 借鉴点：①routing.md 的"路由矩阵+互斥运行时"模式可直接搬进我自己的多路径 skill 设计；②"机器门禁替代模型自觉"（11 检查项校验器同思路）；③POSTFLIGHT 导出自报告——交付物自带验收证据。

五、关联分析

5.1 与 open-kimi-ppt 的关联（2026-08-06-open-kimi-ppt-skill-AI-Agent生成PPT.md）

映射关系：open-kimi-ppt = 云端托管生成 + YAML DSL 描述版式；ppt-master = 本地编译 + SVG 承载版式。分流判据：需要数据不出内网/模板可深度定制 → ppt-master；需要快速免部署出稿且模型侧托管 → open-kimi-ppt。两者可共存，ppt-master 的 Confirm UI/spec_lock 概念与 open-kimi-ppt 的视觉质检互为印证。

5.2 与 html-ppt-skill 系笔记的关联（2026-05-24-html-ppt-skill分析融合.md、2026-04-24-歸藏PPT-Skill-电子杂志风网页演示.md）

映射关系：网页演示路线产出 HTML deck（浏览器放映/分享链接），ppt-master 产出 .pptx 交付物（PowerPoint 二次编辑/打印/归档）。用户场景不同：给链接看 → html 系；交文件改 → ppt-master。此前 html-ppt 笔记里的"编辑能力弱"痛点（改一个字要重新生成整页）正是 ppt-master Edit Native 路由针对性解决的问题。

5.3 与 AIPPT 全栈工程吸收的关联（2026-09-01-AIPPT全栈工程吸收-质量门禁与两段式生成.md）

映射关系：两者共享"两段式（先结构后版式）+ 质量门禁"思想。ppt-master 把该思想推到工业化完整度：spec→lock 分离对应"结构先行"，三道导出门禁+POSTFLIGHT 对应"生成后强制校验"。AIPPT 笔记中记录的门禁设计经验可直接对读 routing.md 的 7 条执行纪律。

5.4 与本机 Hermes 技能治理的关联

ppt-master 是首个带防篡改署名门的外来技能：以后任何 patch/升级必须走官方整包替换（重跑 attribution_guard），不能就地修改文件——这条已写入本机记忆铁律。skill-vetter 审查流程（红旗扫描→权限范围→风险分级）也因本次 383 文件审查跑通而可复用。

六、金句摘录

「Editable is already table stakes — what sets PPT Master apart is native depth.」——可编辑只是及格线，原生深度才是差异点（README 定位句）

「harness + model = agent — PPT Master only owns the workflow; the model sets the ceiling.」——工作流归 skill，上限归模型（README 对模型质量差距的回应）

「A cheap model won't match the recommended setup — that gap is the model's, not a PPT Master bug.」——便宜模型的差距是模型的锅，不是工具的 bug（README 免责边界）

「High token use is this solution's trade-off, not a defect.」——高 token 消耗是方案取舍而非缺陷（README 成本声明）

七、行动启示与回访

我的结论：保留——ppt-master 收编为正式 PPTX 交付首选工具（三道门禁+原生对象正是此前缺失的能力）；改造——中文复杂版式未经验证，先跑一单真实任务再定为默认；放弃——快速网页演示继续走 html 管线，不为演示需求硬套 ppt-master。

  • 行动1：下次用户提 PPT/幻灯/汇报需求时，先跑 routing.md 判路由（Generate/Edit/Create 三选一），优先 ppt-master 而非 wan-pptx。时间：即时生效。触发条件：任意 PPT 类请求。验收标准：产出物在 PowerPoint 中逐元素可选中编辑，过 quality_checker 后导出。
  • 行动2：中文真实任务验收（拿一份真实汇报材料走 Default 路由 + 中文品牌模板），记录中文字体渲染与版式还原质量。时间：两周内（2026-12-12 前）。触发条件：出现首个真实中文 PPT 需求。验收标准：无字体崩坏、无版式塌缩、导出一次过门禁。
  • 回访日期：2026-12-12（两周后检查行动2是否已发生、结果如何）。
  • 待验证假设/证伪条件：若中文任务出现「SVG 门禁反复打回 ≥3 轮」「中文字体渲染塌坏」「单 deck token 消耗超预算 2 倍」任一情况 → 判定"本地编译路线对中文场景不成立"，降级回 open-kimi-ppt/wan-pptx 路线并更新本笔记结论。

八、拓展应用推荐

  • 项目交付物场景：DUCK 训练周报/机器人实验汇报 → Default 路由 + technical-deepdive 风格，产真正可交的 .pptx。
  • 规范/标准宣贯：军民标准融合研究的阶段汇报 → academic-research 风格 + 中国电建/中汽研类本土品牌模板。
  • 旧 PAT/PPT 资产再生：历史评审 PPT 批量 Beautify（1:1 保内容换皮）或 Edit Native（只换数据页）。
  • 演示视频：notes_to_audio + powerpoint_video 链 → 自运行带旁白 MP4（投标/产品介绍场景）。
  • 教学/课件：workshop-teaching 风格 + 逐页备注音频 → 发给学生自播放映。

九、指南分析

  • 可复用结构：「路由矩阵 + 互斥运行时 + 阶段门」的三层组织是复杂 skill 的教科书布局——routing.md 一页纸定边界，runtime authority 各自拥有流程，支撑文档只精化不竞争。我自己的多路径 skill（如分析管线类）可照此重构。
  • 可复用判据：「Act at the owning layer」（在拥有故障的最浅层修复）是通用排障纪律，等价于我方"根因先行"铁律的 skill 版表述；「No speculative execution」（禁止为后续阶段预制产物）直接对应资源效率红线。
  • 反例警示：SKILL.md 的 Vocabulary 表（一词一义，如 Layout 严禁混用"版式草图"与"PowerPoint 版式"）说明大型技能必须内建术语表防歧义——此前写的长 skill 缺这层，跨文档指代已经出过理解偏差。
  • 防篡改署名门：MIT 项目用哈希锁保护署名与赞助文件，fail-closed 设计兼顾了开源合规与完整性验证——第三方技能引入时可借鉴此模式（轻量版：安装时记录 SKILL.md 哈希入记忆，升级时 diff）。
