## 核心发现

### 发现一：MCP 已成为 AI 连接层的「USB-C 标准」

2026 年 MCP 从 Anthropic 的内部协议演变为行业标准。关键标志：
- **Claude Desktop、ChatGPT、VS Code、Cursor** 等主流 AI 应用全部支持 MCP
- 官方提供了 **10 种语言的 SDK**：TypeScript、Python、Rust、Go、Java、Kotlin、C#、Swift、PHP、Ruby
- 类比精准：MCP = AI 应用的 USB-C 接口，一次构建、处处集成

### 发现二：架构双层模型 — 数据层 + 传输层

MCP 架构清晰分为两层：

**数据层（内层）**：
- 基于 JSON-RPC 2.0 协议
- 核心原语：Tools（工具）、Resources（资源）、Prompts（提示词）、Notifications（通知）
- 生命周期管理：Initialize → Capability Negotiation → Operation → Shutdown

**传输层（外层）**：
- **STDIO**：本地进程间通信，单客户端，适合本地 MCP server
- **Streamable HTTP**：远程 HTTP 通信，支持多客户端，适合云端部署

**关键参与者**：
- MCP Host（AI 应用，如 VS Code）→ 为每个 MCP Server 创建一个 MCP Client
- MCP Client（连接管理者）→ 维护与 MCP Server 的连接
- MCP Server（上下文提供者）→ 提供工具/资源/提示词

### 发现三：生态爆发 — 从 7 个参考实现到产业级基础设施

**官方参考 Server（7 个核心）**：
1. **Everything** — 测试/参考 server，演示全部 MCP 功能
2. **Fetch** — Web 内容获取与 LLM 友好格式转换
3. **Filesystem** — 安全文件操作，可配置访问控制
4. **Git** — Git 仓库读取/搜索/操作
5. **Memory** — 知识图谱持久化记忆系统
6. **Sequential Thinking** — 动态反思式问题求解
7. **Time** — 时区转换

**产业级框架（爆发式增长）**：
- **FastMCP** (TypeScript) — 快速构建 MCP server
- **mxcp** (Python) — 企业级 MCP server，YAML+SQL+Python，内置认证/监控/ETL
- **Spring AI MCP Server** — Java Spring Boot 自动配置
- **Quarkus MCP Server SDK** — Java 云原生
- **MCP Plexus** — 多租户、多用户 Python server 框架
- **Vercel MCP Adapter** — Next.js/Nuxt/Svelte 全支持
- **Higress MCP Server Hosting** — 阿里云基于 Envoy 的 wasm 插件方案

**管理工具生态**：
- **mcpm** — Homebrew 风格的 MCP server 包管理器
- **MCPProxy** — 智能发现 + 沙箱隔离 + 恶意工具自动隔离
- **ToolHive** — 容器化部署管理
- **MCPWatch** — 安全扫描器

**市场/注册中心**：
- **MCP Registry** (官方) — registry.modelcontextprotocol.io
- **Smithery.ai** — MCP server 注册与发现
- **Glama.ai** — 最大的第三方 MCP server 目录（17K+ servers）
- **mcp.run** — 托管注册中心 + 控制面

### 发现四：安全与治理成为焦点

- **MCPProxy** 提供沙箱隔离和恶意工具自动隔离
- **MCPWatch** 提供 MCP server 安全扫描
- **Webrix MCP Gateway** 提供企业级 SSO、RBAC、审计追踪、Token Vault
- 官方明确标注：参考实现**不是**生产就绪，开发者需自行评估安全需求
- **A2A-MCP Bridge** 出现：A2A (Agent-to-Agent) 协议与 MCP 的 Java 桥接

### 发现五：从工具调用到「Agent Skills」的演进

MCP 官方文档新增 **Agent Skills** 概念：
- Tools（被动调用）→ Resources（数据暴露）→ Prompts（模板）→ **Skills（主动能力）**
- Skills 允许 MCP Server 描述自己的完整能力，AI 应用可据此规划任务
- 这标志着 MCP 从「工具调用协议」向「Agent 能力发现协议」进化

### 本地 vs 远程 MCP Server 架构

```
┌─────────────────────────────────────────────────────┐
│ MCP Host (AI Application)                           │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐          │
│  │MCP Client│  │MCP Client│  │MCP Client│          │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘          │
│       │ STDIO        │ HTTP/SSE     │ HTTP/SSE       │
│  ┌────▼─────┐  ┌────▼─────┐  ┌────▼─────┐          │
│  │Local     │  │Remote    │  │Remote    │          │

│  │(Filesyst)│  │(Sentry)  │  │(Calendar)│          │
│  └──────────┘  └──────────┘  └──────────┘          │
└─────────────────────────────────────────────────────┘
```

### MCP Protocol 生命周期

```
1. Initialize (Client → Server)
   ← capabilities, serverInfo, version
   
2. Initialized (Server → Client notification)
   
3. Operation Phase:
   - tools/list → 发现可用工具
   - tools/call → 执行工具
   - resources/list → 发现资源
   - resources/read → 读取资源
   - notifications/tools/list_changed → 工具变更通知
   
4. Shutdown
```

## 实践启发

### 1. 对 Hermes Agent 的意义

Hermes 已有 `native-mcp` 和 `mcporter` skill，直接受益于 MCP 生态爆发：
- 可快速接入 Glama.ai 上 17K+ MCP server
- `mcpm` 包管理器简化了 MCP server 的安装和版本管理
- MCPProxy 的沙箱隔离解决了安全顾虑

### 2. 远程 MCP Server 是新趋势

本地 STDIO 模式适合个人助手，但企业场景需要远程 HTTP 模式：
- 多客户端共享同一 MCP Server
- 集中式权限管理
- 云端部署和弹性伸缩

### 3. MCP + A2A 双协议互补

MCP 解决 Agent↔工具连接，A2A 解决 Agent↔Agent 互操作。A2A-MCP Bridge 的出现标志着两个协议正在融合。
