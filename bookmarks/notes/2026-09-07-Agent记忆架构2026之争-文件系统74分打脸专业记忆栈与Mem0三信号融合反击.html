一句话总纲

2026 记忆战场两条战线的核心共识是"检索机制不如 Agent 用工具的能力重要"：Letta 用纯文件系统（grep+search_files）在 LoCoMo 拿 74.0% 超过 Mem0 当时图变体的 68.5%；Mem0 则以三信号融合（语义+BM25+实体）新算法反击到 92.5 分——但 1M→10M token 成绩从 64.1 跌到 48.6 暴露规模化的真正天花板在时间抽象而非检索。

一、内容整理

1.1 战场格局：三大基准与双方主张

基准 规模 考点 地位
LoCoMo 1540 题 多会话对话检索（单跳/多跳/开放域/时序） 最广泛引用
LongMemEval 500 题 知识更新/时序推理/多会话回溯 更严苛
BEAM 1M / 10M token 超大上下文（上下文窗口扩容无法解决） 最接近生产规模

评测五维度：BLEU / F1 / LLM-judge / token 消耗 / 延迟——后两者防止"高分但每次查询 2.6 万 token"的不可生产方案。

Letta 一方的核心实验：把 LoCoMo 对话历史直接塞进一个文件挂给 Letta agent（工具仅有 grep/search_files/open/close），GPT-4o mini 达 74.0%，高于 Mem0 当时自报的图变体 68.5%。且规则极简：agent 必须先 search_files 迭代检索、自行决定何时 answer_question 终止。

1.2 Letta 论点：为什么文件系统打赢专业记忆工具

  1. Agent 能力 > 工具精巧度：现代 agent 经海量代码任务后训练，对文件系统操作（训练数据里见得多）的调用能力远强于任何专有记忆 API——"简单工具更可能出现在训练分布里，因而更可能被有效使用"。
  2. 自主查询生成：agent 会把"Calvin 遇到挫折时如何保持动力？"改写成"Calvin motivation setbacks"再检索，并可迭代多轮直到找到——单跳检索设计的专业工具没有这个循环。
  3. 基准作弊争议：Mem0 曾宣称跑过 MemGPT on LoCoMo，Letta 团队（MemGPT 原班人马）公开表示无法复现其回填方法，Mem0 未回应澄清请求（GitHub issue #3004）——数字打架时先看谁的可复现性硬。
  4. 正确评估姿势：记忆效果 = 架构 × 工具 × 模型三者乘积，孤立比较记忆工具是苹果比橘子。Letta 的替代方案是固定框架比模型（Letta Leaderboard）或用 Terminal-Bench 这类长程任务整体评估（其 OSS 终端 agent 排名总榜第 4/OSS 第 1）。

1.3 Mem0 反击：三信号融合与 92.5 分

2026-04 新算法两大架构改动：

  • Single-pass ADD-only 抽取：agent 生成的事实（确认/推荐）与用户陈述的事实同权重入库——修复了"只记用户说的、丢掉 agent 推断的"覆盖缺口。
  • 三信号融合检索：语义相似 + BM25 关键词 + 实体匹配，三路并行打分归一化融合——"组合分数优于任何单一信号"。图记忆从外部图库（Neo4j）降级为内置实体链接：add() 时抽取实体存平行集合，查询时实体命中给记忆加分——牺牲可遍历的图接口换取零图库部署成本（明确的 tradeoff 声明）。

新战绩：LoCoMo 92.5 / LongMemEval 94.4 / BEAM-1M 64.1 / BEAM-10M 48.6，平均每次检索 ~6900 token（对照全上下文方案 ~26000 token/对话）。增益最大的是时序题（+29.6）与多跳（+23.1）。

1.4 生产化六件套与多作用域模型

生产环境真正需要的（过去 18 个月沉淀）：异步写默认（阻塞写是头号 footgun）/ rerank 二Pass / metadata 过滤（{"context":"healthcare"} 与语义解耦）/ 回填时间戳 / 项目级包含排除 prompt 配置 / 结构化异常。

四作用域 API 设计（已成为事实标准）：user_id（跨会话持久）/ agent_id / run_id|session_id / app_id|org_id——可组合，检索时自动合并并按 用户>会话>原始历史 排序。另有 actor-aware（群聊里用消息 name 字段区分"用户说的 vs agent 推断的"）与程序性记忆（怎么做，区别于 episodic 发生了什么 / semantic 知道什么）两个前瞻概念。

1.5 六大开放难题（Mem0 自认）

  • 时间抽象：BEAM 1M→10M 掉 25%（64.1→48.6）——上下文每 ×10，时序题最难
  • 跨会话结构：用户从纽约搬到旧金山应记为"演化"而非"覆盖替换"
  • 应用级评估：LoCoMo 92.5 分不能预测你的医疗/法律工作负载表现
  • 跨会话身份：匿名会话/多设备/混合登录流打破稳定 user_id 假设
  • 记忆腐化（staleness）：高频检索的"用户雇主"记忆在用户换工作后变成自信的错误——衰减机制只处理低相关记忆，高相关记忆的过期是更难的问题
  • 隐私与同意：谁能查看/保留多久/如何删除——监管将收紧

二、查询拓展：对 Hermes/猫仔自进化体系的直接适用性

背景对照：我方体系 = MEMORY.md（~8K 字符上限）+ USER.md（~3K）+ skills 库（程序性记忆）+ session DB（episodic）+ error-case-library——本质是文件系统记忆（Letta 路线）的野生实现，且已在压缩压力下运行（MEMORY 17%、USER 97% 满）。

2026 共识 我方现状对照 行动启示
简单工具+强 agent > 精巧检索栈 grep/read_file 直查 MD 文件，无向量库——路线正确 不必引入向量 DB，投资 agent 检索纪律
三信号融合（语义+关键词+实体） session_search 有 FTS5 关键词；缺语义路与实体路 低成本移植：给 knowledge-query 加实体抽取 boost（平行索引实体名，命中加分）
ADD-only：agent 推断同权重入库 memory-write 有实体链接；但"用户裁定"类高权重事实与普通陈述无区分 引入 provenance 字段（user-stated / agent-inferred / user-ruled）
四作用域（user/agent/run/org） 天然有 profile 层；缺 run_id 粒度的记忆隔离 跨机经验（exchange-protocol JSONL）正是 run 级记忆——补 scope 标注
记忆腐化：高相关记忆变自信错误 MEMORY.md 无过期机制；"1358g 实测"被 1831g 裁定推翻即活例 supercession 标记：新裁定写入时旧值不删、打 被09-05裁定取代 标签
程序性记忆=第三类型 skills 库就是程序性记忆，且是最强资产 印证 skills-first 架构；error-case-library 是其负样本集
token 效率是生死线（6.9K vs 26K） MEMORY 常驻 system prompt——每轮全量付费 维持压缩纪律；扩展记忆放文件按需读

边界诚实声明：Mem0 的 92.5 是其自报数字（Letta 已示范过 Mem0 基准数字的方法论问题），且两家各为自家产品辩护——结论应取"共识区"而非任何一方的最高分：多信号融合有效（+时序/多跳增益方向可信）、agent 工具能力是乘数（Letta 实验设计干净）、规模化天花板在时间抽象（BEAM 数据自洽）。

三、归纳总结

  1. 检索机制是乘法的小因子，agent 工具运用能力才是大因子：同一 agent 换记忆工具分数波动 < 换强模型/好 prompt 的波动——投资顺序应为 agent 纪律 > 检索算法。
  2. 训练分布决定工具上限：文件系统操作在代码语料里海量出现，专有记忆 API 几乎为零——自建工具接口应尽量伪装成熟悉的文件/CLI 形态，而非发明新交互。
  3. 融合优于单一信号，但融合可以很便宜：Mem0 的三信号（语义/关键词/实体）中，关键词+实体两路不需要向量库——纯文件体系也能做混合检索，这正是我方 hybrid-search skill 的理论依据。
  4. ADD-only 是覆盖缺口的补丁，腐化是删除策略的欠债：只加不删修好了"丢 agent 推断"，却让过期事实堆积——两个问题必须一起解（ADD+supercession 标记）。
  5. 基准分数与生产表现的换算率未知：BEAM 10M 掉到 48.6 说明规模每上一个数量级，架构假设就要重审——别用 1M 级结论设计 10M 级系统。
  6. 争议中最可靠的信号是可复现性：Mem0 对 MemGPT 基准的沉默 vs Letta 开源 benchmark 代码——评估框架开源与否是可信度的先行指标。

四、趋势判断

记忆正在从"组件"升格为"学科"，但重心已从检索转向时间：2024 争"向量 vs 图"，2025 争"LoCoMo 分数"，2026 的真问题变成 BEAM 上的时间抽象与跨会话演化——检索层基本饱和（92.5/94.4 已高），时间层刚破土（64.1→48.6 的悬崖）。判据：三大基准中 BEAM 成为"生产相关性"代言、新论文（MemRL/EverMemOS/Agentic Memory 2026-01 批次）全部围绕运行时演化与长程结构。

对我方体系的预测：文件系统路线在 ≤10M token 规模（约等于全部笔记+会话史）依然够用；真正的分水岭在记忆演化语义（新旧裁定如何链接）——这与 error-case-library 的"取代而非删除"设计前瞻吻合，值得继续深化而非推倒重来。

六、拓展应用推荐

  1. 实体 boost 移植（最低成本）：给 knowledge-query/RAG 索引加平行实体表——检索时查询实体命中给候选加分，无向量库也能逼近三信号融合。可与 rag-index-rebuild 的关键词+语义双路合并实施。
  2. MEMORY.md supercession 机制：写入新裁定时检索同主题旧条目，加 [被YYYY-MM-DD裁定取代] 前缀而非删除——直接回应"高相关记忆腐化"难题，防止压缩后旧值复活误导。
  3. provenance 字段进 memory-write：区分 user-stated / agent-inferred / user-ruled 三档——群聊多 agent 场景（jbot/ubot/abot 协作）的 actor-aware 最小实现。
  4. BEAM 式自评：用全部会话史（10M token 级）做一次"时序问答"抽样自测，量化我方文件记忆体系的时间推理天花板，为是否引入时序索引提供数据。

七、指南分析

质量：★★★★——双方均为一手工程团队、数字可交叉核验（Letta 开源 benchmark 代码 / Mem0 开源 eval 框架）；Mem0 报告对开放难题与自家 tradeoff（图接口回退）的诚实声明难得。
局限：①两家都有利益相关，最高分（92.5）来自自建基准自测，Letta 的 74.0 用的还是较弱模型（GPT-4o mini）故只构成下界证明；②LoCoMo/LongMemEval 是对话检索基准，对工具型 agent 的任务记忆（Terminal-Bench 类）代表性有限；③"文件系统够用"结论的前提是强 agent（工具调用纪律好）——弱模型上该结论未必成立；④BEAM 的 1M→10M 悬崖只有 Mem0 一家数据，缺独立复核。
