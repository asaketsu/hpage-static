一、内容整理

1.1 核心命题：能力转移不一定要动权重

传统蒸馏改弱模型参数（teacher forcing/on-policy distillation）。本文问：强模型能否直接给弱模型设计一套工作环境（Harness），不动权重实现能力转移？

关键洞察来自认知负荷视角：小模型失败往往不是"不会"，而是任务呈现方式施加了过高认知负荷——系统改进有两条路：让模型更强（蒸馏路线），或让任务对模型变简单（Harness 路线）。

1.2 实验设置

Builder（强模型）: GPT-5.5 / Claude Opus-4.7 / Gemini-3.1-Pro / Sonnet-4.6 / Grok-0.1 等
Target（弱模型）: GPT-5.4-mini（基线 0.488）/ Gemini-3.5-flash（基线 0.761，对照组）
平台: Cursor / Claude Code / GPT Codex（builder 自己跑的 agent 环境）
数据: 4 个 ToM（心理理论）基准各 1200 题，5% 做 builder 的验证集，95% 隐藏测试
约束: builder 看不到测试集；scaffold 必须跨样本泛化（防背题）

Scaffold 可包含：任务路由、prompt 模板、确定性求解器、few-shot、验证环节、格式强制——唯一要求是有个能跑未见样本的入口。

1.3 主结果

指标 数值
最佳 scaffold（GPT-5.5 @ Codex） GPT-5.4-mini：0.488 → 0.912（+0.423，87% 相对提升）
57 个 scaffolded runs 均值 0.763（+0.275），100% 超基线
11 个 builder 配置 全部正收益
最佳 scaffold vs 裸 GPT-5.4 四个基准全胜——给小模型装 harness 超过换大模型
vs 人工设计 UserHarness BigToM 反超（1.00 vs 0.95）；Hi-ToM/MMToM/MuMA 仍落后（0.80/0.84/0.88 vs 0.87/0.98/0.96）

推文核心："GPT-5.4-mini 原始平均准确率只有 48.8%，加入自动设计的 Harness 后最高达到 91.2%，甚至超过了裸跑的 GPT-5.4。强模型学到的能力可以被外化成 Prompt、代码、工具和工作流，再交给更便宜的小模型长期复用。"

1.4 机制解剖：钱花在哪才有效

论文对 72 个 runs 逐一读 scaffold 代码做 12 技术分类：

近乎普及的廉价可靠性控制：
- 格式强制（robust answer parsing）+ 贪心解码（temp=0）
- 基准路由 + 强制 CoT

真正拉开差距的（少数 scaffold 才有）：
- 确定性求解器（把推理编译成规则/代码）
- 结构化状态提取、极性逻辑（polarity logic）

关键发现——可编译性排序（per-benchmark 方法地图）：BigToM（观察/未观察的区分暴露在题面）几乎可全编译 → 近满分；MuMA-ToM（具身多智能体交互）几乎纯模型中介 → 规则化不动。收益不是来自更长推理或更多采样，而是结构外化+确定性卸载+格式强制。

1.5 五个反直觉细节

  1. 验证数据加码收益递减：5% 验证集已够，更多验证/采样/更长推理 ≠ 更好
  2. 稳定性：run 间 σ=0.036（比 +0.275 提升小一个量级）——可复现；但确定性求解器策略的 spread 大（一条规则逻辑错→整基准掉几十分）→ 建 2-3 个 scaffold 取验证最优是低成本上界捕获法
  3. Builder 推理努力单调有效：Opus-4.7 low→medium→high 的 scaffold 质量单调升
  4. 平台效应小于模型效应：Cursor/Claude Code/Codex 差异不大，选哪个 builder 模型更重要
  5. 过度脚手架反噬：对已强的 Gemini-3.5-flash，20 个匹配案例中 9 个在某基准上倒退（Hi-ToM 平均 -0.04）——目标接近天花板时，多余的路由/规则干扰正确行为的概率大于修复错误

二、查询拓展

2.1 与 ADAS / Meta-Harness / DSPy 谱系的关系

论文自定位在 harness-engineering 文献内但隔离出"强到弱转移"特定 regime：ADAS（meta-agent 发现 agent 系统）、Meta-Harness（在 harness 代码空间搜索）、DSPy（声明式编译 prompt）优化的是"系统本身"；本文测的是 builder 能力/推理努力/平台/验证预算/目标余量/可卸载性如何共同决定 harness 质量——把 harness 工程从手艺变成可测量的科学。

2.2 ToM 基准为何是好的试金石

嵌套信念追踪天然分层：BigToM（因果模板，规则可编译）→ Hi-ToM（递归深度 0-4，深度≥2 时 scaffold 也失效）→ MMToM-QA（贝叶斯逆规划）→ MuMA-ToM（具身多智能体）。难度梯度=可编译性梯度，恰好把"什么能外化、什么必须留在模型里"画出边界。

2.3 认知负荷理论的工程化

"失败=能力不足 or 呈现方式负荷过高"的二分可直接搬进日常排障：模型答错时先问"是题太难，还是我问的方式让它容易错"——后者改 prompt/格式/路由就能修，不用换模型。

三、归纳总结

3.1 可直接复用的设计原则（论文提炼）

  1. 确定性卸载优先：易错推理交给代码/规则，模型只做它擅长的（语义理解/歧义消解）
  2. 基准感知路由：先分类任务子类型再选处理策略
  3. 格式强制+贪心解码是免费午餐：防住格式错误和采样方差这两类无谓失分
  4. 定向分解优于暴力验证搜索：few-shot/self-consistency 投入产出比低
  5. 建 2-3 个候选取验证最优：捕获策略方差上界，成本仅线性增加
  6. 评估目标余量再决定 scaffold 强度：目标越强越要轻手（过约束反噬）

3.2 五要素实操区

✅ 功能清单（本范式能干什么）

  • 不训练提升弱模型 40+ 点（可编译任务上限 91%）
  • 小模型+harness 超越大模型裸跑（省 token 成本）
  • 强模型能力外化沉淀（prompt/代码/工具/工作流资产化）
  • 评估 builder 模型的新视角（"能为弱模型造多好的环境"）
  • 量化 harness 各组件的贡献归因

🎯 使用性评估

  • 适用域：结构可外化的任务（分类/路由/固定格式/规则密集）收益最大；纯语义任务（MuMA 类）收益薄
  • 成本：builder 一次构建（几十次验证集调用）+ 目标模型长期复用——摊销后极便宜
  • 风险：过约束反噬（强目标倒退）；确定性规则单点错误（spread 大）；验证集过拟合（5% 够用但别加码赌）
  • 当前边界：递归深度≥2 的嵌套信念与贝叶斯目标推断仍编译不动

💡 指导性意见（何时用/何时不用）

  1. 用：端侧/便宜模型做生产任务（0.8B 零件化思路的直接延伸）；benchmark 排查（"这模型真差还是 harness 差"）；能力资产沉淀
  2. 不用：目标已近天花板；任务不可编译（开放语义）；一次性任务（builder 成本收不回）
  3. 与微调的选择：任务规则稳定→scaffold（可解释可回滚）；需要泛化语义能力→蒸馏/微调

📌 案例（论文实测数据点）

  • Opus-4.7(high)@Cursor 三次重复：0.741/0.817/0.806——builder 间方差大于 run 间方差
  • Claude Code+Sonnet-4.6 第二次 run：0.870（同一配置最好与最差差 0.20）——"建多个取最优"策略的实证
  • Gemini-3.5-flash 组：BigToM +0.42（占宏观提升 96%）但 Hi-ToM -0.04——收益集中在"有余量且可编译"象限

🔧 使用方法借鉴（可直接抄的流程）

① 固定目标模型 M_tar + 任务基准 D，抽 5% 做验证集 V
② 让强模型（高推理档）在 agent 平台自主构建 scaffold：
   可用组件 = 路由/prompt模板/确定性求解器/few-shot/验证/格式强制
   约束 = 只见 V，必须对未见样本可执行
③ 重复构建 2-3 个候选，在 V 上选优
④ 部署：M_tar + scaffold 长期跑（权重冻结）
⑤ 归档 scaffold 为可复用资产（代码+规则+模板）

四、趋势判断

  1. "AI4AI"字面兑现：强模型优化弱模型的工作环境而非输出，harness 自演化从人驱动（Claude Code/Cursor 的工具设计）转向模型驱动——论文明确点出这是 agent harness 自演化的实证起点
  2. 基准分数语义被重写：@ManpreetBola 的评论方向会成主流——分数=harness×模型组合，模型卡不注明 harness 条件的裸分会失去意义
  3. 能力资产化：强模型的推理能力沉淀为确定性代码+规则库，弱模型即插即用——与 0.8B 零件化、Needle 2 极简引擎同一光谱，端侧 AI 的成本结构被改写
  4. 过度脚手架反噬会成新研究点：scaffold 强度与目标能力的匹配理论（何时该收手）目前空白
