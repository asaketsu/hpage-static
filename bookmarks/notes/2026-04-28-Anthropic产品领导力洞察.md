## 摘要

Anthropic 产品负责人 Cat Wu（负责 Claude Code & Cowork）分享了 AI Native 公司的产品方法论：**从点子到上线最快一天**，核心靠三大支柱——目标极简、流程可复用、PM 做框架而非做细节。文章重点讨论了 PM 角色在 AI 时代的质变：工程师与 PM 的边界正在消融，**产品品味（Product Taste）** 成为最稀缺技能。同时涵盖了 Claude Code 源码泄露事件复盘和 OpenClaw 限制的官方解释。

## 核心内容

### 1. 极速交付三大支柱

| 支柱 | 做法 | 示例 |
|------|------|------|
| 目标极简 | 一句话定义成功 | "让企业开发者零许可提示" |
| 流程可复用 | "Research Preview" 标签降低发布压力 | 快速迭代不背质量包袱 |
| PM 做框架 | 定义谁在何时介入，而非写 PRD 细节 | 搭建协作骨架 |

> **关键洞察**：速度不来自模型能力，来自**流程优化 + 团队赋能**。

### 2. PM 角色的质变

**招聘标准变迁**：
- **前 AI 时代**：PM 聚焦 6-12 个月路线图 + 对齐成本
- **AI Native**：PM 必须擅长缩短"想法→用户"距离，定义核心 out-of-box 体验

**PRD 方式**：
- 大多数功能：**一页纸文档**（目标 + 愉悦场景 + 当前失败模式）
- 重基础设施：才用完整 PRD
- 持续对齐：周度指标深挖 + Team Principles 文档

### 3. 产品品味（Product Taste）— 最稀缺技能

1. **定义下一代产品**（"1 个月后产品该长什么样？"）——最难，因模型/用户行为模糊
2. **产品品味**（决定做什么）——编码成本下降后，**判断做什么** 比怎么做更值钱
   - 工程背景帮助评估实现难度，做 tradeoff

> "产品品味仍然是一种非常稀缺的技能，只要我们觉得某人展现出了这种能力，我们几乎都会录用。"

### 4. 角色融合（Role Fusion）

| 传统角色 | Anthropic 实际行为 |
|----------|-------------------|
| PM | 写代码、调试 |
| 工程师 | 定义规格、做用户研究 |
| 设计师 | 做 PM 工作、提交代码 |

**招聘策略**：优先招**有产品品味的工程师**，减少沟通开销。

### 5. 团队结构与 Token 消耗

- PM 组织：5 个团队（Research PM / Developer Platform / Claude Code / Enterprise / Growth）→ **30-40 人**
- Token 消耗最高：① 工程团队 ② Applied AI 团队（客户 API 采纳、原型、会议准备）
- Token 限额存在但很少触发——基于**信任 + 社交问责**

### 6. Claude Code 源码泄露复盘

- **原因**：员工用 Claude 写 PR，经 2 轮人工审核仍未拦截
- **处理**：立即调查 → 加强防护 → **员工未被开除**（视为流程失败而非个人错误）
- **启示**："最重要的事情是从中吸取教训，增加更多防护栏"

### 7. OpenClaw/Claude 限制解释

- 订阅模式设计为**自有产品和 API 专用**，非第三方集成
- 优先级：自有产品 > 第三方工具
- 订阅者获得部分免费额度，但自有渠道优先

## 🔍 借鉴点

- **一页纸 PRD** → 适用于 Harness Engineering 中的"约束定义"层，简洁约束 > 冗长文档
- **Research Preview 标签** → 垂域 LLM 迭代时可用"实验性标签"降低用户期望管理成本
- **角色融合** → Agent 团队设计中，Dev Meow 和 Content Meow 的职责边界应更灵活，能跨界
- **产品品味优先** → 数据驱动 ≠ 品味驱动，关键决策仍需人的判断力
- **流程失败 ≠ 个人失败** → 自进化引擎（evolver skill）的理念一致——修系统不修人

## 💡 启发

- **Agent 架构启示**：Anthropic 的角色融合趋势意味着 AI Agent 设计不应过度专业化——Dev Meow 应能做产品判断，Data Meow 应能写内容。当前 AGENTS.md 的角色定义偏刚性，可考虑加入"跨界能力"维度。
- **约束即产品**：Anthropic 的"目标极简"本质上是一种约束工程——与其穷举所有需求，不如定义清晰的边界条件。这与 Harness Engineering 的约束层完全对齐。
- **速度来自流程而非模型**：Cat Wu 反复强调这一点。对垂域 LLM 的启示是：不要只追求模型能力提升，**交付流程的优化**（小批推进、Research Preview）同样关键。

## 🔮 预判

| 趋势 | 预判依据 | 可能的行动 |
|------|---------|-----------|
| PM 角色将逐步被 AI 吞噬 | 编码成本→0，PM 核心价值只剩"品味" | Agent 系统加入"品味评估"维度 |
| 一页纸 PRD 成为主流 | AI 降低实现成本，详细规格不再必要 | 简化 Harness 约束层模板 |
| 角色融合加速 | Anthropic 实践验证可行性 | Agent 团队架构重构为 T 型人才模型 |
