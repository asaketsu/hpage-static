归纳总结

一句话：下一代 AGI 进步的杠杆可能不是把 System-2（大模型/长推理/多智能体）堆得更大，而是给它配一个廉价的 System-1 预测器，在花钱之前判断哪些交互值得执行——把 scaling 的度量从"总算力"换成"有效算力"（informative compute）。

三层递进：
1. 问题：交互（推理 token / RL rollout / 工具调用 / 机器人动作）先付费后见货，边际收益递减；人类数据趋于耗尽、合成数据面临"哪些值得造"的选择、物理交互天然串行——瓶颈正从"能处理多少交互"转向"哪些交互值得成本"。
2. 方案：conditional interaction 闭环——Predict（System-1 打分）→ Gate（自适应阈值准入）→ Execute（System-2 只执行过闸者）→ Update（真实结果反训 System-1）。关键在协同设计而非级联：System-2 每次更新都改变什么有用，System-1 必须持续跟学（AlphaZero 的 policy-value 网络与树搜索互训是先例）。
3. 理论坐标：新增 scaling 第四坐标 ρᵤ（utility-relevant 交互密度）。理想筛选下执行算力下降趋近 1/ρᵤ；预测核心假设——ρᵤ 随系统变强而衰减（掌握的任务不再有教学价值），这可能是收益递减的一部分成因。

三条上山路（Era 划分）

Era 时段 杠杆 瓶颈
Era 1 2012–2020 扩模型容量 参数边际收益递减
Era 2 2020–2025 扩数据+算力 公开文本本 decade 内或耗尽
Era 3 2026+ System-1×System-2 协同设计 交互效率取代参数/数据成为主约束

浪费有多严重（RLVR 实例，公式已对论文核验）

GRPO 类方法靠同题多试的组内对比学习，全对或全错的组 advantage 为零、学不到东西。组内有教学价值的概率 = 1 − p^G − (1−p)^G（p=通过率，G=尝试数）：

通过率 p（G=8） 有教学价值组占比（公式复算）
50% 99.2%
90% 57.0%
95% 33.7%
99% 7.7%

模型越强 → 越多题 drift 向 100% 通过率 → 停止教学。这正是 System-1 该预测的东西。

框架五步（predict–gate–execute–update + 学习双时钟）

  • Represent：候选→紧凑 embedding（冻结 LM 编码器 / 任务结构图编码器）
  • Predict：小模型输出预测值+不确定性；等成本下按校准均值排序即最优
  • Gate：阈值由控制器微调以维持目标准入率；留小样本审计被拒者防漏检
  • Execute：System-2 只做过闸者
  • Learn：System-1 快时钟跟结果、System-2 慢时钟沿闸门采样的梯度爬升——双时钟分离是环路稳定的来源

三个协同设计接口：Knowledge（什么从 S2 蒸馏进 S1——常规解可直接下沉进 S1）、Representation（S1 看 S2 特征买精度但共享盲区）、Feedback（哪些结果监督 S1，决定它能看到自己哪类错误）。S1 天然是成本/不可逆性/安全约束的执行点。

一个闭环四个场景（只换"有用"与"成本"定义）

场景 候选 S1 预测 S2 执行 省下
训练推理模型 prompt 出混合组的概率 rollout 组 训练算力
训练机器人 任务/环境设定 适应后失败风险 sim/真机 episode 动作与仿真时间
测试时推理 再多想一步 继续想的价值 额外推理 推理算力+延迟
智能体用工具 search/run/ask 信息价值−成本 调用 延迟/钱/token/风险

数学结果（论文在声明假设下逐条证明）

  • 预算分配=背包问题：按单位成本价值降序准入。prompt 选择、任务采样、adaptive halting、工具 gating、模型路由全是这一条规则
  • 预筛成本只占"全跑再过滤"的 ρᵤ+r 比例 → 加速趋近 1/ρᵤ；假阳/漏检/预测成本各自拉低该上限
  • 零遗憾可达：S1 误差 < 最差该留者与最好该弃者的效用间隙一半时，选择与 oracle 完全一致
  • 候选池免费扩容：打分只需 embedding 不需 rollout，内存不随池规模涨
  • S1 应随 S2 一起长大：S2 越贵，最优 S1 尺寸永不缩水（定方向不定速率）
  • 可检验假设：ρᵤ 恒定时 gating 使 loss 曲线左移 ln(1/ρᵤ)；若 ρᵤ 衰减，曲线应对齐 informative compute 才对得齐，gating 甚至可能改 scaling 指数

九个落地工作（同组前作，说明框架非空想）

推理模型训练：MoPPS（KDD26，在线贝叶斯后验跟踪 prompt 成功率）、DPS（ICLR26，隐马尔可夫建模难度演化）、GPS（ICML26，单一泛化 prompt 预测器导引大模型 RL 后训）；智能体 RL：TRACE（EMNLP26，rollout 预算分配+树状信用回传）、树感知后验蒸馏；上下文：You Only Edit Once；测试时推理：Halo（MPC 式熵驱动双控制器，抑制过度规划崩溃）；机器人：MPTS（Nature Communications 2026，从优化历史学风险预测模型免评估找难尾任务）、PDTS（ICML26）、In-context MPTS（NeurIPS26）。

作者自评诚实边界：前作是例示框架而非验证框架；决定性实验是直接测量 ρᵤ。Premise（假设）/ Position（论证）/ Hypothesis（可测）/ Prediction（未测）四层声明清晰分开——测试时场景的前提尚未实测。

关联分析

  • 与库内笔记《人形机器人全身控制RL-MPPI-VLA三路线》：该篇指出 RL 先验+MPPI 修正与 System-1/2 范式同构（直觉生成+审核修正）。本篇给出更一般的抽象——S1 的本质不是"直觉生成"而是价值预测与准入控制，MPPI 的采样温度/候选数选择其实就是 gate 的阈值。两篇合读：分层协作是表象，廉价模块决定昂贵模块把钱花在哪才是共性。
  • 与我的 Hermes 架构：adaptive-inference-routing（按复杂度分配 token 预算）、model-dispatch（复杂度判定是否外派 GPT）本质上就是 conditional interaction 的手工版——但没有 Update 环（路由决策的结果没有反训判据）。本文指出的缺失环节：廉价判断器必须持续从昂贵结果中学习，否则难度分布漂移后 gating 质量 silently 退化。
  • 与 RL 训练线（DUCK）：ρᵤ 视角直接可用——课程学习中"已掌握任务停止教学"等价于 ρᵤ 衰减。MPTS 的"从优化历史预测任务风险、免评估找难尾"与我在 AutoDL 上跑的并行多线训练里"哪些 variant 值得继续烧"是同构决策。注意：用户停训判据（连续 3 档横盘=判死）已经是 ρᵤ 衰减的行为级检测。
  • 与 AlphaZero 传统：作者引用 AlphaZero 是策略网络+树搜索互训而非深搜单堆——这条论证线把"co-design"与"cascade"（静态路由训练一次用到底）区分开，判据是难度分布是否漂移。LLM 场景分布永远在漂（每次更新改变什么有用），所以 cascade 不够。
  • 信源分权：作者=论文一作本人的一手发布（非转述），可信度高；但属 Perspective/立场论文，核心 Prediction（ρᵤ 衰减）作者自认未测量——引用时应作"有理论支撑的假设"而非既证事实。

趋势判断

  • 方向可信：算力经济学从"堆总量"转向"省有效"是 2026 年明确趋势（推理成本优化、test-time compute 控制、agent 预算控制全是同一 family）。本文的贡献是给出统一数学骨架（ρᵤ + 背包 + 零遗憾条件），把散落的工作装进一个坐标系。
  • 风险：①ρᵤ 衰减是预测不是事实——若实测平坦，"informative compute 优于 total compute"的叙事强度大减；②gate 的探索-利用矛盾：闸门只从放行的样本学习，早期冷启动与分布外候选系统性漏检（作者承认 exploration 是 gate 失效场景）；③Perspective 论文的常见命运——框架被引用、坐标 ρᵤ 无人实测。
  • 对训练管线的近期影响：prompt/任务筛选（MoPPS 族）已是可复现的工程收益，RLVR 训练侧会先落地；test-time 与 agent 工具 gating 次之（论文自认前提未测）；机器人任务选择（MPTS）与我们的训练线最近。

指南分析

如何在本机/管线里应用这套框架（按成本递增）：

  1. 零成本：训练日志里加 ρᵤ 监控——对 RLVR 组按 u_adv 公式统计混合组占比，画 ρᵤ(t) 曲线。横盘=该数据源停止教学，触发换题/加难度（与用户"连续 3 档横盘判死"规则同源，可互相印证）。
  2. 低成本：agent 工具调用前加廉价预判（问题复杂度→是否需要真调用）——即把 model-dispatch 从"模型选择"扩到"动作选择"，并记录判定结果供事后校准（补 Update 环）。
  3. 中成本：DUCK 训练线引入任务风险预测（MPTS 思路）：用已完成 variant 的曲线特征预测新 variant 值不值得发射，替代"全都跑"。
  4. 不建议：现在就上完整 predict-gate-execute-update 闭环改造——本文的 test-time 前提未实测，先做 1-3 的观测性改造，等 ρᵤ 数据说话。
