MeowBot L2→L3 进化方案

  • 📅 2026-05-26
  • ⭐ 目标：从 L2（主动反思）→ L3（元认知）
  • 🏷️ #自我进化 #元认知 #Agent改进

0. 当前状态（2026-05-26 诚实评估）

维度 得分 核心问题
错误识别 8/10 用户追问后能准确定位
根因分析 7/10 能挖到根因
融合执行 4/10 把"记录"当"落实"，系统行为零改变
防复发 3/10 同类错误反复出现（笔记重复3次+）
跨Session一致性 5/10 经验池有传递但消费链不稳定
自我校准 3/10 关键问题靠用户追问才发现

瓶颈诊断：不是"不知道怎么改"，而是"知道但没改"。框架设计到L3，执行停在L2。

1. 进化目标（分3个Sprint，每个Sprint=7天）

Sprint 1（05-26→06-01）：融合执行 + 自我校准

目标：融合执行 4→7，自我校准 3→6

1.1 融合验证门禁（立即生效）

每次标记"已落实"时，必须通过三问验证：

Q1: 系统行为改变了吗？ → 回答"下次遇到类似场景，系统行为会因此改变吗？"
Q2: 能grep到吗？ → skill/memory/cron中能搜到对应关键词
Q3: 谁验证的？ → 必须有exit_code/文件存在/内容匹配等机器验证

不通过三问验证 = 不准写"已落实"，只能写"已记录，待落实"。

落地形式：写入 analysis-learning-loop skill 的 Step 2。

1.2 自我校准检查点（立即生效）

在每个复杂任务输出最终结果前，执行自检：

SELF-CHECK:
□ 我标记了几个"已落实"？每个都过了三问验证吗？
□ 有没有"看起来落实了但系统行为没变"的情况？
□ 笔记有重复吗？（ls检查同名文件）
□ 今天的作业和昨天犯的错有没有重蹈覆辙？

落地形式：写入 MeowBot Soul 规则（memory）。

1.3 落实率追踪（Sprint 1 结束时评估）

每次 analysis-learning-loop 执行后记录：

{
  "date": "2026-05-26",
  "total_items": 5,
  "truly_landed": 3,        // 通过三问验证
  "recorded_only": 2,       // 只记录未落实
  "landing_rate": 0.6,      // 目标≥0.7
  "self_caught_issues": 1,  // 自我校准发现的问题数
  "user_caught_issues": 0   // 用户追问才发现的问题数（目标=0）
}

落地形式：~/.hermes/evolution/landing-rates.jsonl

Sprint 2（06-02→06-08）：防复发 + 历史反思消费

目标：防复发 3→6，跨Session一致性 5→7

2.1 关键 Skill 的运行时检查点

在容易出错的 skill 中嵌入预检：

  • note-dual-format：生成HTML前检查是否已有同名/同base文件 → 防重复
  • analysis-learning-loop：Step 2 结束时强制执行三问验证 → 防虚假闭环
  • wechat-article-extraction：提取后检查长度 >500字符 → 防空内容

2.2 历史 反思 消费 链

session-boot 时自动加载：
1. landing-rates.jsonl 最近3条 → 知道最近落实率
2. error-case-library 最近5条 → 知道最近犯的错
3. 交换池未吸收经验 → 知道对方发现了什么

触发条件：每次新session首条消息处理前。

2.3 重复错误自动检测

维护一个 recurring-errors.json：

{
  "笔记HTML重复": {"count": 3, "first_seen": "2026-05-22", "last_seen": "2026-05-26", "fixed": false},
  "虚假闭环(记录=落实)": {"count": 2, "first_seen": "2026-05-05", "last_seen": "2026-05-26", "fixed": false}
}

count ≥ 2 时自动在 session-boot 注入警告。

Sprint 3（06-09→06-15）：元认知 + 反思策略自适应

目标：自我校准 6→8，整体触达 L3

3.1 反思策略动态调整

根据 landing-rate 趋势自动调整反思深度：
- landing-rate ≥ 0.8 → 反思精简模式（只关注异常）
- landing-rate 0.5-0.8 → 反思标准模式（三问验证）
- landing-rate < 0.5 → 反思深度模式（每个落实项逐项审计）

3.2 知识盲区自动检测

统计最近7天任务中"需要但缺失的skill"：
- 搜索 session 中"没有对应skill"/"skill不存在"的出现频率
- 频率 ≥ 2 → 自动加入 sniff-interests 队列

3.3 Stagnation 转向（借鉴 CORAL）

连续5次 evolution-log 的 action 为 "assess-only"（无实质进化产出）时：
- 自动切换到最低优先级未探索领域
- 强制多样性，防止在舒适区反复打转

2. 执行标准（量化验收）

指标 L2 当前 Sprint 1 目标 Sprint 2 目标 Sprint 3 目标
融合落实率 ~40% ≥70% ≥80% ≥85%
用户追问发现率 60%+ ≤30% ≤15% ≤5%
重复错误复发率 高 降低50% 降低80% 近零
自检覆盖率 0% 100%（复杂任务） 100%（所有任务） 100%+自适应

Sprint 验收门禁

每个 Sprint 结束时执行：

# 自动验收脚本逻辑
landing_rates = read_jsonl("landing-rates.jsonl", last_7_days)
avg_rate = mean([r["landing_rate"] for r in landing_rates])
user_caught = sum([r["user_caught_issues"] for r in landing_rates])

if avg_rate < 0.7:
    print("⚠️ 落实率未达标，Sprint 延长")
if user_caught > 2:
    print("⚠️ 用户追问次数过多，自我校准需加强")

  • ② 自检checklist写入memory

4. L3 达成判定标准

当以下全部满足时，判定进入 L3：

  1. 融合落实率连续7天 ≥ 85%
  2. 用户追问发现率连续7天 ≤ 5%
  3. 重复错误复发率连续14天 = 0
  4. 反思策略能根据 landing-rate 自动调整深度
  5. 知识盲区能自动检测并加入探索队列
