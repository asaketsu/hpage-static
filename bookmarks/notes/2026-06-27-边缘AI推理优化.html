一、PALUTE：存内计算 LUT 加速边缘 LLM 推理

出处：arXiv 2606.08891（UC San Diego，2026-06-08）

痛点

边缘 LLM 部署受功耗和面积严格约束。混合精度 GEMM 虽降低算术复杂度，但量化推理的计算瓶颈已转移到反量化（dequantization）和非线性算子上。

LUT 方法的本质

查找表（Lookup Table）通过预计算输出，用查表替代重复算术运算。但现有设计的容量开销和查表延迟都很高。

PALUTE 架构创新

  1. 基于单片 3D DRAM（Monolithic 3D DRAM）的存内 LUT 查询：利用 M3D DRAM 内存阵列 tile 的垂直组织，高并行 + 低面积开销。
  2. 近存 LUT 生成器：低延迟地为 GEMM 和逐元素一元非线性算子生成 LUT。
  3. 系统级分层与调度策略：最小化跨内存层的数据搬运。

对 Jetson 部署的启示

PALUTE 是专用硬件（M3D DRAM），Jetson Orin 暂无法直接复用。但其设计思想可迁移：
- 瓶颈已从 GEMM 转向反量化和非线性算子——这意味着 TensorRT FP16 引擎里，对 LayerNorm、Softmax、RoPE 等非线性算子的优化比单纯压 GEMM 更重要。
- 预计算 + 查表思想可用于固定形状输入的算子融合：把高频组合算子的输出预建表，推理时查表。

二、Breaking TinyML：量化神经网络的安全盲区

出处：arXiv 2606.14427（USC，2026-06-12）

问题

大多数 TinyML 硬件加速器专注于支持量化神经网络（QNN）以满足功耗和尺寸约束。但量化在 TinyML 硬件中的安全层面几乎未被探索。

现状与误区

  • 传统观点认为 QNN 对抗规避攻击的鲁棒性与全精度 DNN 相当甚至更强。
  • 但此前没有任何针对 TinyML 硬件定制的攻击策略。

贡献

提出两步攻击流水线，在 QNN 场景下超越当前 SOTA，证明 TinyML 硬件需要领域专属的安全分析。

对边缘部署项目的直接警示

本地 RT-DETR Jetson 部署、YOLOv26 姿态估计都使用 FP16/INT8 量化。这篇论文提醒：
- 不要假设量化=免费的安全加固。量化模型可能有未被发现的攻击面。
- 部署在公开环境（如监控系统、机器人感知）的量化模型，应做对抗样本鲁棒性测试。
- 硬件感知：攻击可能利用特定硬件的量化实现细节，不仅是模型权重。

三、嵌入式机器学习全流水线：工程决策手册

出处：arXiv 2606.18122（2026-06-16）

定位

这不是单点创新，而是面向 MCU 级边缘设备的系统工程综述。强调那些在通用 ML 教程中被隐藏的工程决策。

全流水线

数据采集 → 缓冲 → 特征提取(降维) → 类别不平衡下的验证 → 模型/运行时协同设计 → 流式部署

两个代表性信号族

  1. 惯性运动识别（IMU）：
  2. 2 秒、三轴加速度计窗口
  3. 原始样本 → RMS + 频谱特征 → 分类
  4. 关键词唤醒（KWS）：
  5. 音频采样 → 抗混叠 → MFCC（mel 频率倒谱系数） → 紧凑 1D 卷积网络

实战设计规则（可直接采用）

决策点 规则
数据策略 严格数据策展，质量优先于数量
特征工程 特征提取作为降维手段，降低模型复杂度
验证策略 类别不平衡下必须用合适的评估指标
量化 量化是标配，需配合阈值与调度
阈值设定 输出阈值化（非简单 argmax），低置信度拒绝
调度 多任务时间片调度，满足实时约束
现场监控 部署后持续监测漂移和性能退化

对 ESP32 平衡车 / XiaoZhi 项目的启发

  • 平衡车 IMU 处理：论文的 IMU 流程（窗口→RMS/频谱→分类）可直接用于姿态/运动模式识别扩展。
  • 阈值化输出：当前平衡车用 PID，若加入运动模式识别，应用阈值拒绝低置信度判断，避免误触发。
  • 现场监控：边缘设备部署后必须有数据漂移监测，否则模型静默退化。

四、边缘 AI 推理优化的实用行动建议

🟢 立即可做（关联本地项目）

  1. TensorRT 非线性算子优化：在 RT-DETR/YOLOv26 的 TensorRT 引擎上，用 trtexec --profilingVerbosity=detailed 定位是否非线性算子（LayerNorm/SiLU/Softmax）成为瓶颈，针对性做算子融合。PALUTE 揭示了这是当前量化推理的真正瓶颈。
  2. 量化模型对抗鲁棒性快速测试：对已部署的 INT8/FP16 检测模型，用简单的 FGSM/PGD 生成对抗扰动，测试是否在量化后鲁棒性下降。Breaking TinyML 警示这是盲区。

🟡 中期改进

  1. XiaoZhi 关键词唤醒复用 KWS 流程：参照论文的 KWS 流水线（MFCC + 1D CNN），评估是否比当前方案更省内存。
  2. 平衡车加运动模式识别：用 IMU 窗口特征 + 轻量分类器扩展功能（如跌倒检测、运动状态切换），配合阈值拒绝机制。

🔵 技术储备

  1. 跟踪存内计算 LUT 方向：PALUTE 代表的 M3D DRAM + LUT 是下一代边缘 AI 芯片趋势，关注是否有可在现成硬件上模拟的开源实现。
