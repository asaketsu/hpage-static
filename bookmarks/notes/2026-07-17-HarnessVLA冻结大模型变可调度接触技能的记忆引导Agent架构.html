一、内容整理

1.1 核心洞察

VLA（Vision-Language-Action）模型的强项和弱项高度不对称：局部接触动作很强（抓取/插入/操作铰链），但长程任务组织很弱（目标重绑定、位置交换、失败重试）。

Harness VLA 的核心判断：不要让 VLA 既负责理解任务，又负责空间定位，还负责低层接触。把接触交给冻结的 VLA，把组织任务交给 Agent planner。

1.2 架构设计：冻结 VLA = 一个可调用工具

Harness VLA 将冻结的 VLA 封装为一个特殊 primitive vla_act，放入固定的 primitive 库中：

Primitive 类型 功能 是否学习
vla_act 局部接触丰富动作（抓取/重新抓取/操作 fixture/双臂接触） ✅ 唯一的 learned primitive
move_to 目标定位、自由空间移动 ❌ 解析
rotate 姿态调整 ❌ 解析
set_gripper 夹爪控制 ❌ 解析
release 释放物体 ❌ 解析
navigate_to 导航到位置 ❌ 解析

双层记忆系统：
- 任务记忆：保存某个参考 seed 中成功的命令轨迹
- 全局记忆：保存可复用的成功规则和失败模型

1.3 关键设计原则：固定 primitive 词表

Harness VLA 反其道而行——不扩展技能库，而是固定 primitive 词表。Planner 不在部署时发明新技能，而是在有限工具中学习调用边界：
- 哪些步骤交给解析控制
- 哪些步骤需要 vla_act
- 失败后怎样重新摆位再试

1.4 实验结果

基准 Harness VLA 成功率 对比基线提升
LIBERO（标准） 96.0% 封装后无明显损伤
LIBERO-Pro（扰动） 82.4%（CC 版） +38.6 个百分点
RoboCasa365 55.4%（Codex 版） +25.4 个百分点（vs RLDX-1）
RoboTwin C2R 58.4%（CC 版） —

收益来源：不是换了更强底层 VLA，而是来自更清晰的高低层分工。

1.5 VLA 调用比例统计

基准 vla_act 占比 解析 primitive 占比
LIBERO（桌面任务） 15.8% 84.2%
RoboCasa365（厨房任务） 35.3% 64.7%
RoboTwin C2R（双臂任务） 47.4% 52.6%

桌面任务中大量移动和释放可以用解析控制完成；厨房和双臂任务更依赖学习到的接触动作。

1.6 适用边界与局限

  1. 仍依赖高层 planner 的可靠观察和判断
  2. 高层 planner 和低层 VLA 之间仍是开放反馈环路，缺少联合微调
  3. 高度杂乱、需要细粒度图像描述的任务中，结构化推理受限
  4. 更像"清晰系统架构"，而非一次性解决所有长程操作问题

二、查询拓展

2.1 VLA 的分层架构趋势

Harness VLA 代表了具身智能从"端到端大一统"向"分层专业分工"的范式转变。与 NVIDIA RoboTTT（前篇笔记）的思路形成对比：RoboTTT 通过扩展上下文长度让单一 VLA 记住长程历史；Harness VLA 则通过外部 planner + 记忆系统让冻结 VLA 专注于接触动作。两种路径代表了长程操作的不同解法——内化记忆 vs 外部编排。

2.2 Primitive 库设计 vs 端到端学习

固定 primitive 词表的设计与经典机器人操作中的"运动原语"（Motion Primitives）概念一脉相承。区别在于：传统运动原语全部手工设计，Harness VLA 保留了一个 learned primitive（vla_act）处理难以手工编码的接触动作，其余用解析控制。这种"1 个学习 + N 个解析"的混合策略在工程上极易维护和调试。

2.3 记忆引导的 Agent 架构

双层记忆（任务记忆 + 全局记忆）与 AI Agent 领域的 episodic memory + semantic memory 二分法对应。任务记忆 = 单次任务的成功轨迹（episodic），全局记忆 = 跨任务的可复用规则（semantic）。这与 Hermes Agent 的三级记忆架构（L1 常驻 + L2 短期 + L3 按需）在哲学上高度一致。

四、趋势判断

4.1 VLA 落地将从"更大模型"转向"更好分工"

依据：Harness VLA 证明冻结 VLA + 外部 planner 的分工架构在扰动场景下提升 25~38 个百分点，且不需要重训。这与软件工程中"单一职责原则"一致——让每个组件只做最擅长的事。

4.2 "冻结大模型 + 外部编排"将成为具身智能的主流范式

依据：Harness VLA 与 RoboTTT 代表两种路径，但 Harness 的工程优势更明显——不需要 GPU 推理长上下文（成本低）、不需要重训（部署快）、分工清晰（可调试）。预计 2026-2027 年更多系统将采用"冻结模型 + Agent 编排"架构。

4.3 机器人操作将从"端到端竞赛"转向"系统架构竞赛"

依据：Harness VLA 的收益不来自更强 VLA，而来自更清晰的接口设计。这意味着 VLA 模型层面的军备竞赛可能触顶，竞争将转向 planner 设计、记忆系统、primitive 库管理、失败恢复策略等系统层面。

五、关联分析

5.1 与 NVIDIA RoboTTT 笔记的关联

维度 RoboTTT Harness VLA
解决长程问题的方式 扩展上下文到 8000 步 外部 planner 编排
VLA 是否冻结 否（TTT 快速权重更新） 是（完全冻结）
记忆机制 TTT 快速权重 双层记忆（任务+全局）
推理延迟 恒定（TTT 保证） VLA 仅在需要时调用
适用场景 需要连续长程操作 接触动作 + 空间移动混合

两种方案互补：RoboTTT 适合连续长程操作（如十阶段组装），Harness VLA 适合接触动作与空间移动交替的任务（如厨房操作）。

5.2 与 Hermes Agent Skill 体系的深度关联

Harness VLA 的架构与 Hermes 的 Skill 系统高度同构：

Harness VLA Hermes Agent
vla_act（唯一的 learned primitive） 核心推理能力（LLM 本身）
move_to / rotate / release（解析 primitive） terminal / search_files / read_file（确定性工具）
Planner（决策何时用哪个 primitive） Agent 主循环（决策何时用哪个 Skill/工具）
任务记忆（成功轨迹） L2 短期记忆
全局记忆（可复用规则） L3 topics + Skill 库
固定 primitive 词表 固定工具集（不运行时发明新工具）

可借鉴的设计：Harness VLA 的"固定词表 + 学习调用边界"策略，正是 Hermes Skill 系统的最佳实践——不无限扩展 Skill 数量，而是让 Agent 学会在有限工具中做正确选择。

5.3 与双轮腿机器人 V2 项目的关联

Harness VLA 的架构可直接启发双轮腿机器人的控制架构设计：
- 平衡控制（LQR 1kHz）= 解析 primitive（类似 move_to）
- 步态生成（如果用学习方案）= learned primitive（类似 vla_act）
- 任务编排（导航/避障/上下楼梯切换）= planner
- 不需要让一个端到端模型同时负责平衡和步态和导航
