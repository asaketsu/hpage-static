# Jev Engineering：别用 LLM 做每一个决策

## 一、核心命题：新的分工三层

大多数 Agent 建在一个昂贵假设上——"每个智能决策都需要一次 LLM 调用"。路由/评分/验证/重试判断，没有一个需要一段文字，但常见做法是让生成模型写 prose→吐 JSON→等解析→祈祷 schema 活下来。**"这不是智能架构，是把聊天机器人当 switch 语句用。"**

Jev（TypeSafe AI，ChatGPT 联合发明人 Diogo Almeida 两年隐身之作，RLCD 训练，20-200x 快/40-400x 便宜）改变原语：不生成文本，读系统状态→评估类型化问题→返回软件可直接执行的概率。放弃开放字符串的能力，换来快得多的可组合决策层。

```
LLM  创造工作（turns context into new work）
JEV  类型化判断（turns state into typed judgment）
CODE 执行与强制（turns judgment into controlled action）
```

## 二、三个决策原语

| 原语 | 用途 | 输出 | 陷阱 |
|------|------|------|------|
| **Choice** | 恰一选项胜出（如下一个 worker） | 胜选项+全分布+置信度 | 菜单可能不全时必须带 none/other/escalate 逃生口，否则概率质量被强塞给最不错的答案 |
| **Score** | 有序 rubric 上的评分 | 可落在档间（1.6 ≠ "80%好"，只是你定义的描述之间的位置） | 别把序数 rubric 当精确测量 |
| **Noul** | 是/否概率 | ~1.0 likely yes / ~0.0 likely no / **~0.5 = 模型分不清（不是中等风险！）** | 要低中高三档就该用 Score |

## 三、决策契约（Decision Contract）——问题是程序的一部分

生产级问题不是随手 prompt，是决策契约：**state 字段 + question 指令 + 选项描述/rubric + fallback 出口 + 置信度阈值 + 允许的动作 + 升级路径 + 版本号**。

关键细节：**Jev 不会从你的内部字段名学到任务语义**——字段叫 `safe_to_publish` 不等于模型知道 safe 是什么，真正的规则必须写进 instructions 和 criteria。

## 四、置信度路由：三区运营

```
confidence ≥ 0.9 且低后果  → 自动执行该分支（选worker/排队列/排短名单）
中等置信度               → 改善状态再问：多抓一个源/问更强模型/跑确定性检查/收窄选项
低置信度 或 高后果        → 升级人工
```

**"没有不同下一步动作的置信度是装饰品"**——校准只有把不确定性路由到某处才有用。禁止系统用同样证据重复问同一个不确定问题；**重试必须花新证据，不只是花更多 token**。

## 五、放置位置：决策节点放在昂贵/危险的转换处

| 位置 | 模式 |
|------|------|
| 模型之前 | 路由：简单分类→Jev/代码；例行起草→快 LLM；含糊研究→强 LLM；高风险→人工。路由器要知道**当前可用**的模型菜单（别把昨天的模型表硬编码进永久 prompt） |
| 工具之前 | 门禁：LLM 提议工具调用→Jev 分类语义风险→**代码**决定放行/审查/拦截 |
| 工具之后 | 验证：HTTP 200 ≠ 目标达成。验证器查新证据（文件存在/章节齐全/引用有效/路径正确）→ pass/repair/escalate。建造者和验证器共享 artifact+rubric，不共享模糊的"完成了"感觉 |
| 检索周围 | 漏斗：确定性廉价过滤→embedding 短名单→Jev 相关性评分→小证据包→生成模型。trace 记录每项为何存活 |
| 动态菜单 | 浏览器 Agent 每次点击后可用动作都变了——**每次动作后从活状态重建选项集**，别用跑前写的静态清单 |

## 六、权限铁律与反模式

**最危险的错误：让置信度变成权限（confidence score ≠ permission）。Jev 只推荐，只有 harness 能授权。**

安全次序：`JEV 判断 → CODE 查策略 → 工具执行 → TRACE 记录`

十大反模式（节选）：选项消失/来源变了还用旧菜单；同样状态重试什么都没学到；**决策无收据**（只存胜出标签是不够的——要存契约版本+state 引用+完整分布+阈值+路由+实际动作）；**策略藏在分类器里**（问题说该允许什么，代码盲执行答案=把概率判断变成无界权限）。

## 七、上线清单（16 条）与推广顺序

16 条清单节选：是真语义决策而非生成/精确规则？state 紧凑/新鲜/基于证据？指令显式（不藏在问题 ID 里）？Choice 带逃生口？Score 是有序描述非假测量？置信度改变路由？阈值随后果分级？**代码保留权限/预算/副作用控制**？契约有版本？完整分布随动作落日志？影子模式跑过代表性样本？每次重试加了新证据？——**多个答"否"= 系统还没准备好更多自动化，只准备好更好的决策契约**。

推广顺序：先内部路由 → 再检索过滤/完成验证/模型选择/低危工具门禁 → 最后才是带显式策略和审批的重大动作。

**经济学**：单次调用便宜不是重点，**cost per completed task 才是**——便宜路由器把 worker 送错分支的代价可能超过省下的钱。跟踪：决策延迟/成本/分支准确率/下游工具成本/恢复成本/人工审查率/完成率。

## 八、💡 对我们的价值分析

### ✅ 已在做的（印证方向）
- **三层分工同构**：LLM/JEV/CODE ≈ 我们的 创造层/判断层/执行层——GrokBot 三层控制架构笔记（09-06）已提出同款"审批边界"，本文是该架构的工业级完整版
- **"SIMULATED ≠ REAL PERMIT"**（ROSClaw 笔记）与本文"confidence ≠ permission"完全同一条铁律——两个独立来源收敛，说明这是 Agent 安全的共识原则
- **决策收据** ≈ 我们的 evolution_log/error-case 台账思想；**重试必须花新证据** ≈ 训练止损器"iter 两次不变=挂起等拍板"

### ⚠️ 可改进的（差距）
- Hermes 的判断类调用没有"决策契约"概念——prompt 散落在各 cron job 里，无版本/无分布日志/无阈值分级，出问题无法复现"当时为什么这么判"
- 置信度路由缺失：所有判断都是"一刀切执行"，没有 auto/improve/escalate 三区——低置信度时既不补证据也不升级，直接赌
- 工具门禁是静态黑白名单，没有"语义风险分类→策略引擎"两级结构

### 🔥 重点行动
1. **决策契约模板落 skill**：把第七节清单做成 Hermes 判断类调用的标准前置模板（state/rubric/逃生口/阈值/版本），先用在 news-aggregator 的新闻筛选（高频+低危+可影子模式验证）
2. **与昨天笔记合流**：实现层（logprobs 单 token，本地 Jetson 可跑）+ 本篇架构层（契约/路由/权限）= Hermes 决策层升级的完整蓝图——Jev 上下篇已互链
3. **置信度三区引入 content-judge**：P≥0.9 自动过 / 0.6-0.9 补一次检索再判 / <0.6 标记人工——把"LLM 拿不准"从隐性变可路由

## 九、内容整理（归纳总结与关联分析）

**归纳总结**：Jev Engineering = 三层分工（LLM 创造/JEV 判断/CODE 强制）+ 三原语（Choice/Score/Noul，各带专属陷阱）+ 决策契约（8 要素，语义必须写进指令）+ 置信度三区路由（自动/改善状态/升级）+ 五个放置位（模型前路由/工具前门禁/工具后验证/检索漏斗/动态菜单）+ 权限铁律（confidence≠permission，CODE 查策略后才执行）+ 16 条上线清单 + 推广顺序（先内部路由后重大动作）。北极星指标：cost per completed task，非 cost per call。

**关联分析**：本文是 Jev 双篇的架构篇，[[2026-09-27-Jev式LLM单token概率传感器]] 是实现篇（logprobs 即免费 Jev 原语的本地替身）——两篇合起来构成"语义决策层"从理念到落地的完整链路；与 [[2026-09-06-GrokBot智能体操作系统三层控制架构]] 的 Harness-Loop-Graph-审批边界同构互证；"决策收据"思想可反哺 ROSClaw 笔记的 SimulationReceipt 概念——证据链思想在 LLM 决策层的对应物。三篇与达索/EBTO 笔记共同指向 9 月的元趋势：**工程知识的显式契约化**。

## 十一、趋势判断

1. **Agent 架构的"决策层"正在独立成层**：生成/判断/执行的分离将像 MVC 一样成为默认架构词汇——用一个大模型包打一切的"单层 Agent"会显得像 CGI 时代的网页
2. **置信度路由成为 Agent 可靠性的标准机制**：auto/improve/escalate 三区模式会被各大框架（LangGraph/autogen 系）原生吸收
3. **RLCD 类专用训练催生"决策专用小模型"品类**：通用 LLM 做判断是错位浪费——就像用 CPU 跑图形，专用决策模型（Jev/未来开源版）会拉走 Agent 内 80% 的非生成调用
4. **决策审计成为合规刚需**：契约版本+完整分布+路由+动作的"决策收据"会进入监管视野——与适航"构型管理可追溯"完全同构，用户的航空背景可直接迁移这层判断

## 十二、指南分析（怎么用这篇文章）

- 建 Agent 决策层：按第二~七节顺序走（原语→契约→路由→放置→权限→清单），第七节 16 条可直接当 PR review checklist
- 判断自己的 Agent 是否需要决策层：数 agent loop 里"隐藏的 yes/no/route/score 决策"数量——>10 个就该引入
- 说服团队：第一节"chatbot 当 switch 语句"是最强开题比喻；经济学段（cost per task）管 CFO
