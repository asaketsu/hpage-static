零、结论先行

OUI-1 的核心学习原理不是扩散模型也不是 DSL——是"输出可验证性驱动的自我教学循环"：parser 当裁判→幸存程序当训练集→模型当自己的老师→循环几轮把基座拉开 5.5 倍。 这个原理与我们体系四块拼图（gpu-lexer/S1-mini/正则调研/OUI-1）一致收敛到一条定律：当任务是窄的、输出是可判定的，小模型不仅能干好，还能靠"生成-验证-修复"循环自己变强。 对我们最深的增量：OUI-1 的 repair 流程"只修 parser 报的缺陷，拒绝任何重写或发明"——这是 SoL-Pi Evidence-Preserving Reducer 的训练版同构物（小模型初筛→原文核验→大模型只收证实信息），但用在了一个完全不同的领域（UI 生成 vs 日志归约）。两条线在"证据保留"原则上交汇。

二、三个选择各自的明确理由（原文忠实还原）

2.1 为什么是 DSL 而不是 HTML/JSON

openui-lang = 为 LLM 生成界面设计的紧凑行式语言。三个理由：

理由 机制
省 token JSON 里 "component"/"props"/"children" 键在每个元素上重复——openui-lang 紧凑位置语法，比 JSON 省 67% token → 直接降 API 成本和延迟
流式优先 行式语法（identifier = Expression）逐行可解析——每行到达，界面就多渲染一块，用户在模型生成完之前就看到界面开始出现
鲁棒 LLM 会幻觉组件名/产出非法结构——openui-lang 验证输出，只渲染合法部分

Reddit 问的好问题：普通 LLM 用 system prompt 就能写 OpenUI Lang，为什么要微调？答案=上下文开销：把整个 DSL 规范塞进 system prompt 吃掉大量上下文窗口——微调把这份开销移出窗口，留给真正的对话和工具调用。（与 Engram "把静态知识移出计算"同构！）

2.2 为什么是扩散模型而不是自回归

维度 自回归 DiffusionGemma
生成方式 一次一个 token 一次一个 256 token 的块
瓶颈 内存带宽 —
速度 慢 H100 >1000 token/s；RTX 5090 >700 token/s
可靠性 — 只有 13.0%（原始基座）

DiffusionGemma 有速度和硬件形态，但没有可靠性——这正是训练要解决的。

2.3 为什么可验证奖励是自我教学的钥匙（核心学习原理）

训练分两阶段：

阶段 1：监督微调（SFT）
  教 DiffusionGemma 写 openui-lang
  → 速度下降（多了结构约束）

阶段 2：self-distillation（自我蒸馏/自我改进）
  关键突破：openui-lang 有可验证的奖励
  → 模型可以当自己的老师

自我教学循环（逐步拆解）：

① 模型生成一批 openui-lang 程序
② parser 验证结构合法性
   ├─ 非法 → 指出精确的 schema/wiring 错误
   └─ 近乎通过 → 进入 repair 流程
③ repair 流程（最关键的设计）：
   - 只修 parser 报的缺陷
   - 拒绝任何重写或发明
   - 中位数修复只改一条语句
④ judge 检查每个幸存程序是否符合 brief（任务描述）
⑤ 幸存程序 → 下一轮的训练集
⑥ 500 步，一张 A100，1-2 小时
⑦ 生成的模型产下一批 → 循环继续

2.4 结果：跷跷板停止了

"以前每次运行都是两种错误此消彼长——self-distillation 同时改进了两者。"

指标 前 后
Benchmark 57.1% 71.7%
Schema 错误 292 76
Wiring 错误 971 484
生成时间（20 个 brief） 4.3s/输出 1.9s/输出（即使多了 28% token）

速度回来了 + 质量上去了——以前是跷跷板（质量上去速度下来），self-distillation 打破了跷跷板。

三、核心学习原理深挖（本笔记的核心增量）

3.1 "可验证奖励"的三个层次

层次 机制 OUI-1 对应
L1 结构合法性 parser 判对错 openui-lang parser
L2 精确定位缺陷 parser 指出"哪条语句错了" repair 只改那条
L3 任务符合度 judge 检查是否符合 brief 独立判官

关键洞察：L2 的"精确定位"是 repair 流程成立的前提——如果只能判"错了"但不能说"哪错了"，repair 无法限制在"只改一条"。这与我们 golden set 六项机检的"错误必须精确定位到文件/行"同构。

3.2 "只修缺陷，拒绝重写"的铁律

"repair 流程只修 parser 报的缺陷，拒绝任何重写或发明——中位数修复只改一条语句"

这是全文最值得深挖的设计决策。为什么禁止重写？

允许重写 禁止重写（OUI-1 选择）
模型可能"顺手"改了别的地方 训练数据干净：只有"修缺陷"的样本
引入新错误 每 条样本的 diff 可控
模型学到"改着改着就重写了" 模型学到"精确修补"的技能

与 SoL-Pi Evidence-Preserving Reducer 的同构：

OUI-1 repair SoL-Pi EPR
parser 报缺陷 小模型出诊断回执
只改缺陷不重写 逐条对照原文核验
judge 最后把关 只放行严丝合缝的
共同原则 证据保留：不发明不补充，只处理被验证的部分

3.3 自我教学循环 vs RSI

维度 OUI-1 SoL-Pi RSI
候选死亡率 未披露（但"一批"里幸存的才入训练集） 152→4（40:1）
优化目标 可验证奖励（parser+judge） token 效率（难作弊）
循环成本 一张 A100，1-2h/轮 535 个环境，更重
防作弊 judge 独立于 parser held-out 隔离验真
共同点 都用"生成-验证-修复"循环，且验证是确定性的 同

3.4 上下文开销移出窗口（与 Engram 同构）

OUI-1 微调把 DSL 规范移出 system prompt → 留窗口给对话。Engram 把静态知识移出前几层计算 → 留有效深度给推理。同一洞察的模型层（Engram）与 prompt 层（OUI-1）实现——"让便宜层干记住的活，贵层干思考"的两次落地。

五、与我们体系的全景对接

5.1 最深连接：三条线在"证据保留"交汇

线 表现
训练线（OUI-1） repair 只修 parser 报的缺陷，不重写——训练数据干净
推理线（SoL-Pi） 小模型出诊断回执，对照原文核验——推理只收证实信息
验证线（我们 golden set） 六项机检，错误精确定位到文件——门禁只放行确定性通过

三线交汇点："不发明不补充，只处理被验证的部分"——这是 2026 年 AI 可靠性工程的共同范式，从训练到推理到部署验证一以贯之。

5.2 对我们 skill 生态的启示

OUI-1 原理 对应
微调移出上下文开销 auto-skill 把工作流移出 prompt → SKILL.md 按需加载（同构）
自我教学循环 evolver/auto-skill 的"门禁后写入"（SoL-Pi 的 CODESKILL 实证 +9.69）
"只修缺陷不重写"铁律 skill patch 的最小 diff 原则——只改出问题的行，不重写整个 skill
judge 独立判官 执行/评判分离（AGENTS.md 准则 2）

5.3 周论文候选更新

今日学习原理深挖 + harness 簇七篇 + Engram = "证据保留范式"命题的证据链更厚了：训练（OUI-1 repair）→ 推理（SoL-Pi EPR）→ 验证（golden set）→ 记忆（Engram 查表）→ 自进化（mem0/SoL-Pi RSI）——五个层位同一原则。候选题从"验证器门控的自进化"升级为"证据保留：从训练到部署的可验证性范式"。

六、批判性审视

  1. "5.5 倍"的基座问题：DiffusionGemma 基座 13.0% 极低——5.5 倍只是"极差→中等"，绝对值 71.7% 仍有 28.3% 错误率。Qwen3.8 27B 的 78.8% 更高（虽然参数代价大）——OUI-1 的"无敌"限定在 4B active 及以下
  2. 训练成本被低估："一张 A100，1-2 小时"是每轮——自我教学循环跑了多少轮未明确（500 步是一轮的步数，不是总轮数）
  3. judge 的独立性：judge 是否也基于 openui-lang parser？如果是，那 L3"任务符合度"只是 L1 的超集而非独立维度——文章没说 judge 的实现
  4. "跷跷板停止"的机理未解释：为什么 self-distillation 能同时降两种错误——文章只描述了现象，没给机制（可能是 parser+judge 的联合信号比 SFT 单信号更丰富）
  5. openui-lang 生态绑定：DSL 是 OpenUI 自家的——用 OUI-1 = 用 OpenUI 生态，与 AGENTS.md 笔记的"own the handbook"精神有张力
