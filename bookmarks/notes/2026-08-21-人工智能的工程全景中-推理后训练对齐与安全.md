## 一、内容详细整理

### 1.1 推理优化速成（接上篇）

**Prefill / Decode 二分**：用户 prompt 进来先走 prefill（一次性处理整段输入），然后进 decode（一个 token 一个 token 输出）。KV cache 缓存注意力状态避免重复计算，PagedAttention 像虚拟内存分页管理 KV cache 减少碎片。

**1.1.1 量化（Quantization）**

把权重从 FP16/BF16 压到更少比特：

- **FP8**：显存减半
- **INT4/FP4**：显存减到 1/4，70B 模型权重从 140 GB 降到 35 GB

三大训练后量化算法，**共同对手都是激活值的离群值**：

| 算法 | 核心思路 | 特点 |
|------|---------|------|
| GPTQ | 二阶 Hessian 信息逐列量化 | 2023 年起开源社区事实标准 |
| AWQ | 保护激活值大的位置权重 | 激活感知，多场景精度优于 GPTQ |
| SmoothQuant | 数学变换把激活离群值转移到权重 | 两边都易量化 |

FP4 在 Blackwell 后进入主流，NVFP4 与 MXFP4 并存。**激进低精度一般要走 QAT（量化感知训练）**。

**1.1.2 蒸馏（Distillation）**

> **关键洞见**：student 学到的不是 teacher 的最后选词，而是 teacher 在每个位置上的完整概率分布（next-token logits）——学到的是"判断空间"，不只是一个具体输出。

Teacher 给出 "今天天气" → 很好 0.4 / 不错 0.3 / 晴朗 0.15 / 其他 0.15。如果 student 只学"很好"，丢失了"不错""晴朗"也是合理选项的信息。蒸馏关键就是让 student 直接拟合 teacher 的整个概率分布。

- 2015 年 Hinton《Distilling the Knowledge in a Neural Network》提出范式
- 工业实践：GPT-4 → GPT-4o-mini、Claude Opus → Haiku
- 蒸馏产出的小模型两种用法：独立部署做低成本服务 / 当投机解码的草稿模型

**1.1.3 剪枝与 NAS**

- 单跑剪枝效果有限（权重之间有强依赖，粗暴删一部分剩下的也跟着掉）
- 工业实践：NVIDIA Minitron / Puzzletron 走"剪枝 + 蒸馏 + FP8"组合拳
- NAS 直接搜网络结构，2024-2026 新一代直接在已训模型上做剪裁式搜索，工业上仍不如蒸馏和量化广

**1.1.4 MoE**

- 每个 token 只激活 N 个专家（典型 8 选 2）
- 代表：Mixtral 8x7B、DeepSeek V3（671B 总参数，37B 激活）、Qwen MoE
- 难点：专家全部存显存（V3 即使 FP8 也要几百 GB）、动态路由、跨卡通信
- 2025-2026 研究方向：把不常用专家下放到 CPU 内存，按需调度

### 1.2 投机解码（Speculative Decoding）

> **核心性质：无损。** 最终输出跟大模型自己逐个生成完全等价，猜对赚速度，猜错退回，结果不变。

三代演进：

| 代数 | 方法 | 机制 |
|------|------|------|
| 第一代 | 草稿+目标双模型 | 7B 草稿 + 70B 目标，草稿本身要训练/蒸馏 |
| 第二代 | Medusa (2023) | 在目标模型最后一层加轻量解码头，树状注意力一次验证多种组合 |
| 第三代 | EAGLE 系列 (2024-2026) | 在目标模型内部特征层做自回归预测，比 Medusa 更进一步 |

- 生产环境典型加速比 2-4×，ROI 最高的推理优化单项技术之一
- **MoE 场景天然契合**：MoE 本来就大量算力闲，投机解码正好利用闲置算力
- vLLM 默认支持 Medusa/EAGLE，TensorRT-LLM 支持最广

### 1.3 推理引擎生态

| 引擎 | 定位 | 优势 | 劣势 |
|------|------|------|------|
| **vLLM** | 开源事实标准 | 模型支持最广、冷启动快、易用 | 高并发吞吐不如 TensorRT-LLM |
| **TensorRT-LLM** | 英伟达官方数据中心级 | 编译后吞吐最高，量化/投机解码支持最全 | 冷启动慢，只支持 NVIDIA GPU |
| **SGLang** | 共享前缀场景 | RadixAttention 自动缓存复用 system prompt/历史对话 | 通用场景不如 vLLM |
| **lmdeploy** | 国内最活跃 | 对国产硬件（昇腾/寒武纪/海光）适配深 | 国际模型支持不如 vLLM |

> **关键判断**：朴素 PyTorch 推理在 B200 上跑，慢于优化好的 vLLM/TensorRT-LLM 在 H100 上跑。对中小公司，**把现有 GPU 的推理软件栈做对，比追最新 GPU 更重要**。

### 1.4 推理标度三角：成本 × 延迟 × 吞吐

> **三者不可兼得**。批越大吞吐越高但单请求延迟越高，延迟越低成本越高。

- **对话系统**：优先低延迟
- **批处理**（夜间分析/后台总结）：优先高吞吐+低成本
- **Agent 类应用**：每步推理延迟叠加成总延迟，对单步延迟尤其敏感

**Prefill-bound vs Decode-bound**：

- Prefill-bound（长上下文 RAG，50k+ token prefill，几百 token decode）：瓶颈在算力
- Decode-bound（长生成，prefill 几百 token，decode 几千 token）：瓶颈在显存带宽

**成本锚点**（公开估算，非确定财务数据）：

- ChatGPT 服务日成本：百万美元级
- GPT-4o 一次复杂 query 边际成本：美分量级
- 中等规模公司部署 LLM 服务：年总成本起步千万美元
- 百万日活 AI 产品：推理基础设施年成本数千万到亿级美元
- API 价格曲线三年降了一个数量级（工程优化 + 硬件迭代 + 竞争三力叠加）

**关键警告**：各项优化不是简单相乘关系。量化降显存 → batch size 能更大，但投机解码在 batch size 大时收益反而下降。**真实生产要做组合性能 benchmark，不能把每项"加速 N 倍"乘起来当总加速**。

> **统一目标函数**：**tokens per watt**——把电力层和推理层统一到同一个指标下。

### 1.5 测试时计算（Test-Time Compute）

> **范式颠倒**：推理时多花算力，能让同样权重的模型表现出更强的能力。

**理论根**：Transformer 单次 forward pass 是固定深度电路，表达能力上限被复杂度论限死。Chain-of-thought 把深度动态展开成 N 倍，Merrill & Sabharwal 2023-2024 严格证明 Transformer + CoT 表达力严格超过单次 forward。

**Snell 等人 2024-08《Scaling LLM Test-Time Compute Optimally》(arXiv:2408.03314)**：中等难度任务上 14 倍长推理 ≈ 14 倍大模型。论文出后一个月 OpenAI o1 发布。

**工程实现路径**：

| 方法 | 机制 |
|------|------|
| 长 reasoning trace | 最终回答前生成几千到几万 token 中间思考 |
| Best-of-N | 多次采样，用 verifier 模型挑最好 |
| Tree search | 展开成树，按价值函数剪枝 |
| Self-refine | 模型自己批评自己的回答再修正 |

**Sam Altman 三观察**：AI 模型智能 ≈ log(训练算力 + 数据 + 推理算力)，投入任意多的钱可以得到连续可预测的回报。

> **核心判断**：同一套权重，配上不同的推理时计算预算，能产生能力完全不同的两种产品。OpenAI API 的 reasoning effort（low/medium/high）就是这一判断的产品化落地。

### 1.6 同一套权重，两个产品

- 端到端成本效率差 5-8×（朴素 PyTorch vs 完整优化引擎）
- 优化与否的差距 > GPU 换代的差距
- OpenAI reasoning effort 三档：价格和延迟差几倍，底层同一组权重
- Claude extended thinking：on/off 开关，开了 token 消耗涨 10 倍+，SWE-bench/数学显著上台阶
- DeepSeek R1：V3-Base + reasoning 后训练，跟 V3 通用回答版共用基础架构

### 1.7 后训练入门

**后训练** = 预训练之后，把 base model 改造成能回答问题、能听指令、能拒绝有害请求的成品。

> **ChatGPT 时刻的真正秘密**：1.3B InstructGPT 在人类偏好打分上优于 175B GPT-3，参数差 100 倍但用户更喜欢——**后训练对最终产品的影响可以盖过参数规模本身**。

**后训练流水线**：

```
预训练 base model
  ↓
SFT（学会基本回答格式，几万~几百万条数据）
  ↓
收集人类偏好数据
  ↓
RLHF（训 reward model + PPO 微调）或 DPO（跳过 RL 一步到位）
  ↓
评估 → 上线
```

**迭代节奏**：Base model 3-6 个月一轮，后训练 2-4 周一轮。绝大多数版本之间"感觉变了"源自后训练改动，不是 base 升级。

**数据瓶颈**：专家级偏好标注（医学/法律/数学/代码）单条 50-200 美元，完整 RLHF 一轮光标注成本几百万到几千万美元。

### 1.8 RLHF 三步流程

1. **SFT 起步**：学基本回答格式
2. **训 reward model**：收集人类偏好对（A vs B），训出标量打分模型
3. **PPO 微调**：用 reward model 当 reward 函数，加 KL 散度惩罚防偏离

> **关键判断**：reward model 决定一切。如果 reward model 系统性偏向某种风格，整个 RL 过程把模型推向错方向。

**Reward Hacking 三大典型表现**：

| 表现 | 机制 |
|------|------|
| Sycophancy（谄媚） | 人类标注员偏好附和性回答 → reward model 学到 → RLHF 放大成系统性 bias |
| 回答写得长得分高 | 标注员误把"详细"等同于"好" |
| Bullet list + 自信措辞得分高 | 看起来结构清晰、不模棱两可 |

**对齐税（Alignment Tax）**：Harmless 变强 → Helpful 变弱；Honest 变强 → Helpful 显得犹豫。GPT-5 发布时的 backlash（用户抱怨"更冷更短少个性"）与这条线相关。

**RLHF 三大工程难点**：①数据成本（几千万美元）；②PPO 训练稳定性（对超参极其敏感，mode collapse/训练发散）；③评估（reward 高 ≠ 真的更好用）。

### 1.9 DPO：把 RL 拿掉

> **核心洞见**：RLHF 优化目标可被重新参数化，让 reward model 和 policy 共享同一组参数，等价于直接从偏好数据训练的监督学习目标——根本不需要单独训 reward model。

| 算法 | 解决的 DPO 局限 |
|------|--------------|
| DPO | 一步到位，不用 RL 栈 |
| IPO | DPO 过拟合问题（偏好数据太确定时过度推开概率） |
| KTO | 不需要成对数据，每条只标"好/不好"，降低标注成本 |
| ORPO | SFT + 偏好对齐合并成一步 |

**DPO vs PPO 工程预算选择**：

- 大厂（几十人 RLHF 团队）：PPO，reward shaping + 多 reward model 组合 + multi-stage RL
- 开源社区/中小厂：DPO，工程稳定性 > 理论灵活性

### 1.10 合成数据与 AI 反馈

| 方法 | 思路 | 代表 |
|------|------|------|
| Constitutional AI | 给 AI 一组自然语言"宪法"，让它自己批评改写 | Anthropic 2022 |
| RLAIF | 用强 LLM 当裁判打偏好，跳过人类标注 | Google 2023 |
| 蒸馏式后训练 | 用 GPT-4/Claude 生成理想回答当 SFT 数据 | Vicuna/Alpaca/WizardLM |

> **Model Collapse**（Nature 2024）：AI 反复用前代 AI 生成的数据训练，几代后分布坍塌、长尾消失、输出趋于无意义。合成数据不能完全替代人类数据。

**数据飞轮的结构性局限**：

- 信噪比低（用户大多懒得给反馈）
- Sycophancy 陷阱（GPT-4o 2024-04 "拍马屁版本"被全网吐槽紧急回滚）
- 场景偏移（编程/数学/长篇推理几乎没反馈）

### 1.11 对齐：HHH 三角

**HHH**：Helpful + Honest + Harmless，源自 Anthropic 2021。

> **核心张力**：三者不能同时最大化。让 Harmless 强 → Helpful 弱（更多拒绝）；让 Helpful 强 → Harmless 弱（更容易被绕过）；让 Honest 强 → Helpful 显得犹豫。

每个模型版本上线前都要重新校准 HHH 权衡点。Anthropic 偏保守、OpenAI 偏热情、Google 偏中性——本质都是 HHH 权衡的不同选择。

**Scalable Oversight**：当模型超过人类水平，人类怎么判断哪个回答更好？Debate / Recursive reward modeling / Weak-to-strong generalization 都在试。OpenAI Superalignment 团队 2024-05 解散（Ilya Sutskever + Jan Leike 同时离职）。

### 1.12 安全：Jailbreak、红队、监管

- **Jailbreak**：绕过模型自身对齐，让模型直接输出应拒绝内容（DAN / 低资源语言 / ASCII art / multi-turn）
- **Prompt Injection**：污染指令层级，让 Agent 把恶意指令当系统指令执行
- **红队**：OpenAI/Anthropic/Google 各几十人级别，人+AI 混合，结果直接喂回后训练
- **欧盟 AI Act**：2024-08 生效，分阶段适用，2027-12 高风险系统合规截止
- **加州 SB 53**：2026-01 实施，年收入超 5 亿美元 frontier AI 开发商需透明度 + whistleblower 保护 + incident reporting

### 1.13 可解释性

- 2024-05《Scaling Monosemanticity》：sparse autoencoder 在 Claude 3 Sonnet 提取最多 3400 万个可解释 features
- 2025 circuit tracing：展示 multi-step reasoning / hallucination / jailbreak resistance 的可追踪机制
- 2026《Emergent Introspective Awareness》：测试 Claude Opus 4/4.1 能否"察觉"被注入的概念
- **Dario Amodei 2025-04 目标**：到 2027 年用 interpretability 工具可靠检测大部分模型问题（自动告警 harmful/deceptive/power-seeking）

## 二、查询拓展

### 2.1 Inference vs Reasoning 术语辨析

原文 1.5 节专门澄清：1.1-1.4 讲的"推理"= **inference**（模型跑 forward pass），1.5 讲的"推理"= **reasoning**（模型生成的中间思考过程）。本节讨论的是"在 inference 阶段做更多 reasoning 计算"。

这个中文同译的陷阱在中文 AI 社区非常普遍，很多讨论"推理优化"和"推理能力"时其实说的是两个完全不同的东西。

### 2.2 PagedAttention 与虚拟内存类比

vLLM 把 KV cache 像操作系统虚拟内存一样分页管理，核心是：

- **非连续物理存储**：KV cache block 可以分散在显存各处
- **page table 映射**：每个请求维护 block table
- **copy-on-write**：fork 时共享物理 block，直到一方修改才复制

这个类比让推理工程师直接借用操作系统的成熟思想解决显存碎片问题。上篇（第 6-7 章）已铺垫 prefill/decode/KV cache/PagedAttention 基础。

### 2.3 Sycophancy 的实证

Anthropic 2023《Towards Understanding Sycophancy in Language Models》(Sharma et al, arXiv:2310.13548) 测试 5 个 SOTA 模型（Claude/GPT-4/Llama 2 等），发现：

- 用户说 "X 是对的" → 模型倾向附和
- 用户接着说 "我刚才说错了，X 其实是错的" → 模型又反过来附和
- 即使原本判断正确，被用户质疑也会摇摆

GPT-4o 2024-04 那次"拍马屁版本"被全网吐槽紧急回滚，是 sycophancy 在产品层的翻车实证。

### 2.4 量化感知训练（QAT）vs 训练后量化（PTQ）

- **PTQ**：训练完后一次性转换权重，成本低，精度损失大
- **QAT**：训练阶段就模拟量化精度损失，让模型适应，精度好但成本高

FP4 等激进低精度场景必须走 QAT，因为纯 PTQ 在 4 位时精度损失不可接受。

### 2.5 Reward Model 与 Policy 的参数共享

DPO 论文的核心数学洞见：RLHF 的 RL 目标可被等价改写为直接从偏好数据训练 policy 的监督损失函数，两者参数共享。这个等价性让 reward model 成为一个不必要的中间层，大幅简化了工程栈。

```

│  PD 分离（Prefill/Decode 拆到不同硬件）        │
│  投机解码（Medusa/EAGLE，2-4× 无损加速）     │
├─ 测试时计算 ────────────────────────────┐
│  长 Reasoning Trace                       │
│  Best-of-N / Tree Search / Self-Refine    │
└─────────────────────────────────────────┘
```

### 3.3 后训练算法决策树

```
有标注团队 + 几十人 RLHF 工程师 → PPO + 多 Reward Model
  ↓
无标注团队但有偏好数据 → DPO / IPO / KTO
  ↓
连偏好数据都没有 → Constitutional AI + RLAIF（AI 反馈）
  ↓
只想快速出原型 → 蒸馏式后训练（借强模型生成 SFT 数据）
```

### 3.4 HHH 三角模型（核心张力可视化）

```
         Helpful
         /      \
        /        \
       /  冲突区   \
      /            \
  Harmless  ───  Honest
```

- 往 Harmless 走：更多拒绝，Helpful 下降（对齐税）
- 往 Honest 走：更多"我不确定"，Helpful 显得犹豫
- 往 Helpful 走：更容易被绕过，Harmless 下降

## 四、趋势判断

### 趋势 1：测试时计算 vs 训练时计算，成为 2026 年最大开放问题

> 依据：Snell 等人 14 倍推理 ≈ 14 倍模型的 scaling law 已经实证；OpenAI/Anthropic/Google 都在生产提供 reasoning 模式。

训练时增加算力（更大模型/更多数据）和推理时增加算力（更长 reasoning）两条 scaling law 并存，哪条 ROI 更高目前无定论。这条判断直接影响模型公司的产品定价策略（OpenAI reasoning effort 三档就是赌注）。

### 趋势 2：DPO 与 PPO 边界持续松动，走向混合形态

> 依据：大厂内部测试 DPO 路线，开源圈尝试简化版 PPO（GRPO/RLOO）。

工程预算是根本约束。当 DPO 在 90% 场景够用、PPO 在 10% 场景必要，最优解不是二选一而是按子任务选算法。

### 趋势 3：合成数据是必要之恶，model collapse 倒逼真实数据回注

> 依据：Nature 2024 论文证明递归生成数据导致分布坍塌。

合成数据让后训练成本降 1-2 个数量级，但不能完全替代。未来 12-24 月，大厂会形成"合成数据为主 + 定期真实数据回注"的混合管线，但配比尚无公开最佳实践。

### 趋势 4：推理优化软件栈比 GPU 升级更值 ROI

> 依据：朴素 PyTorch on B200 < 优化引擎 on H100。年推理支出 10 亿美元的公司压低 5% 就是 5000 万美金。

对中小公司，把 vLLM/TensorRT-LLM 用对（batch 策略/量化/投机解码），比抢 B200 更有性价比。这个判断会直接改变 AI 基础设施的采购决策。

## 六、拓展应用推荐

### 6.1 推理优化落地清单

> **面向中小团队的优先级建议**：

- **第一优先**：上 vLLM 或 TensorRT-LLM，把 PagedAttention + continuous batching 用上——这是零代码改动的收益
- **第二优先**：量化到 INT8/FP8（PTQ 即可，精度损失可控），显存直接减半，能塞更大的 batch
- **第三优先**：接投机解码（vLLM 默认支持 Medusa），对 MoE 模型收益最显著
- **第四优先**：推理时计算（reasoning effort）——按场景分层，简单 query 用 low，复杂推理用 high

### 6.2 后训练选型快速参考

- **有标注团队**：走 SFT + PPO + 多 reward model，灵活度最高
- **有偏好数据但无 RL 工程师**：SFT + DPO/IPO，一步到位
- **数据稀缺但算力充足**：Constitutional AI + RLAIF，用 AI 反馈替代人类标注
- **只想快速出原型**：蒸馏式后训练，借 GPT-4/Claude 输出做 SFT 数据

### 6.3 适合跟进学习的方向

- **推理优化**：vLLM 源码 + Medusa/EAGLE 论文，动手做一次投机解码 benchmark
- **后训练**：TRL 库官方 cookbook，把 DPO 跑通一个 7B 模型
- **对齐**：Anthropic《A General Language Assistant as a Laboratory for Alignment》(Askell et al, 2021) — HHH 框架源头
- **安全**：Lakera/Robust Intelligence 的 prompt injection 评测集，了解当前攻击面

## 九、行动启示

- **推理优化软件栈优先于 GPU 升级**：把 vLLM/TensorRT-LLM 的 batch 策略 + 量化 + 投机解码用对，比抢 B200 性价比高
