## 摘要

歸藏（@op7418）开源了 `guizang-ppt-skill`——一个 Claude Code Skill，用单文件 HTML 生成「电子杂志 × 电子墨水」风格的横向翻页 PPT。核心理念是把十年设计经验压缩为规则写入 SKILL.md，让 AI 按规则自动执行，而非依赖审美天赋。项目 31 Stars，MIT 协议，含 10 种布局、5 套主题、WebGL 流体背景。

## 核心内容

### 1. 产品定位：单文件 HTML PPT

- **产物**：一个 `index.html`，双击浏览器打开，零依赖
- **交互**：横向左右翻页（键盘/滚轮/触屏/圆点跳转/ESC 缩略图）
- **视觉**：WebGL 流体背景 + 衬线标题 + 非衬线正文 + 等宽元数据
- **灵感**：Monocle / 卫报 / NYT 印刷排版 + Kindle 电子纸

### 2. 设计哲学：约束即美学

| 原则 | 具体做法 |
|------|---------|
| **字体三级分工** | 衬线→观点（大标题）、非衬线→信息（正文）、等宽→元数据（页码日期） |
| **色彩纪律** | 纸白+墨色+一个重点色，底色绝不是 #FFF，字色绝不是 #000 |
| **禁止自定义 hex** | 只能 5 套预设选一，「保护美学比给用户自由更重要」 |
| **节奏强制** | 连续 3 页同主题判 P0 错误，hero/non-hero 必须交替 |
| **固定网格** | 7:5 / 6:6 / 8:4 几套固定比例 |

### 3. Skill 工作流（6 步）

1. **需求澄清**（6 问清单：受众/时长/素材/图片/主题/硬约束）— 对齐前置，拦截 80% 返工
2. **拷贝模板** — `template.html` 已含 CSS + WebGL + 翻页 JS
3. **类名预检** — 先确认 `<style>` 里有对应类定义，再写 slide
4. **主题节奏规划** — 列出每页的 hero/light/dark，避免视觉疲劳
5. **填充内容** — 从 10 种布局骨架里挑、粘、改
6. **自检** — 对照 checklist.md，P0 必过

### 4. 技术架构

```
magazine-web-ppt/
├── SKILL.md           ← 工作流、原则、常见错误（264行）
├── assets/
│   └── template.html  ← 完整种子 HTML（CSS+WebGL+JS）
└── references/
    ├── components.md  ← 组件手册
    ├── layouts.md     ← 10 种布局骨架
    ├── themes.md      ← 5 套主题色
    └── checklist.md   ← 质量检查清单（P0-P3）
```

### 5. 5 套主题

| 主题 | 色调 | 场景 |
|------|------|------|
| 🖋 墨水经典 | 黑白灰 | 通用/商业发布 |
| 🌊 靛蓝瓷 | 蓝白 | 科技/AI/研究 |
| 🌿 森林墨 | 绿白 | 自然/可持续 |
| 🍂 牛皮纸 | 暖黄棕 | 怀旧/人文 |
| 🌙 沙丘 | 米金 | 艺术/创意 |

## 借鉴点（可执行）

1. **规则压缩为 Skill**：把领域专家经验结构化为 SKILL.md + checklist，让 AI 替人逐条执行——这正是我们 `note-dual-format`、`reading-notes` 等 skill 的思路，歸藏把它做到了极致
2. **「对齐前置」模式**：6 问澄清清单 + 大纲对齐后再动手，拦截 80% 返工——我们的 `writing-plans` skill 有类似思路，但缺少强制澄清步骤，值得补上
3. **约束即质量**：不允许自定义 hex、强制节奏交替、类名预检——对我们 html-slides skill 有启发，应该加更多硬约束
4. **Skill 安装体验**：README 里一段「给 AI 的安装 prompt」，复制粘贴给 Claude Code 即可自动安装——我们 Atlas 的 skill 注册可以借鉴这个 onboarding 体验

## 启发（超越原文）

1. **「十年经验的压缩包」这个比喻精准**：Skill 的本质不是代码，是决策树的编码。设计师做 1000 次「选字体」的决策，最终内化为「衬线→观点、非衬线→信息、等宽→元数据」三条规则。**每个 Skill 都应该是某个领域决策树的压缩**
2. **视觉节奏 > 视觉细节**：连续 3 页同主题判 P0 错误这条规则，本质上是在说「节奏比单页美感更重要」——这适用于所有内容创作（包括写作、代码、演讲）
3. **「保护美学比给自由更重要」**：这是一个反直觉但深刻的 UX 原则——在创意工具中，限制选项往往比增加选项更能产出好结果。类比：lint 规则越严，代码风格越统一

## 预判

- **趋势**：AI Skill 会从「功能型」（帮我做 X）向「审美型」（按 X 风格做）演进，歸藏这个 skill 是早期信号
- **行动**：已将此 skill 克隆到 `~/.hermes/skills/creative/magazine-web-ppt/`，可在 Hermes 中直接使用做杂志风 PPT
- **风险**：单文件 HTML 不适合需要动画/视频嵌入的复杂演示，仍需配合 ppt-generator skill
