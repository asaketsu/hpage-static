三、矛盾点（3 个，不调和，待裁决）

K1. 提示词工程的生死：「没死，在民主化」 vs 「光会写 Prompt 根本解决不了」

  • 2026-10-18-2小时从零看懂AI-企业内训同款认知体系.md：「提示词工程没死，在民主化+分层进化；范式从'一次写完美'转向'对话式共创'」
  • 2026-10-14-AI工程化真问题清单-跑通Demo之外的全部功夫.md：「单纯调用大模型 API 是未来最不值钱的 AI 能力」「光会写 Prompt 根本解决不了」

两边都不是空话：前者是 5 轮付费内训验证过的教学路线（初级市场确实在扩张），后者是一线交付的六难清单（生产环境确实不吃 prompt）。本周没有第三篇能给出"在什么分界线上 prompt 不再是瓶颈"的证据，所以不裁决。要裁决得有一个可测的分界（例如：任务需要几次工具调用/多少外部状态时，prompt 优化的边际收益归零）——这是我们自己该实测的东西。

K2. 通用物理推理模型会不会抽掉专用管线的底

  • 2026-10-16-Gemini4Argon-for-Robotics-Video到Sim到Real全栈工作流.md（官方博文）：「趋势2：单一通用物理推理模型压制专用管线……垂直场景公司（标注/遥操作/仿真咨询）的护城河被抽底」
  • 2026-10-13-解耦机器人学-对全栈机器人公司的反驳.md：「机器人学没有 GPT-3 时刻」「问题不是可行性，是存活性」——专业化是经济必然，全栈是被"协调陷阱"逼出来的临时解
  • 旁证反方向：2026-10-13-四足机器人开源项目全景图谱-五大流派与学习路线.md「RL+MPC 混合（非替代）是工业落地主流」

同一个模型（Gemini 4 Argon），一篇说它把垂直管线抹平，另两篇说具身领域根本还没有可抹平的通用层。注意证据等级不对等：压制论来自 Google 官方发布文+11 个官方案例（受益方自述），解耦论来自产业投资人（有立场但也给反例）。这不构成裁决，只构成立场对立——待裁决。

K3. AI 交付的最小作战单元：6 人 FDU 还是 1 人 + 5 Bot

  • 2026-10-14-FDE已死FDU登场-AI交付从单兵英雄到作战单元.md：「宣判'单兵超级英雄'FDE 模式的死亡」；拓扑=「人类在两端，智能体在中间」，6 人黄金角色 + 10-30 个数字员工
  • 2026-10-14-GrokBot五人自媒体团队-数字流水线的权限工程与验收闭环.md：一个创作者用多 Bot 搭「情报侦察员→选题策划师→内容主笔→事实编辑→人工发布→数据复盘师」，全流程跑通并给了验收标准

一篇说单兵已死、必须扩编到 FDU（企业交付场景），一篇给出单兵+多 Bot 现场可行的完整案例（内容生产场景）。可以辩称"场景不同"，但那样就把结论降级成"取决于场景"——而两篇原文都没给这个限定。这是本周最值得裁决的一条，因为它直接决定我们该不该继续扩猫队（现状：4 猫 + cron，介于两者之间）。

四、空白点（4 个候选深挖方向）

  1. MCP 的权限语义（高频零专文）——MCP 在本周 5 篇里出现，但全部是"工具层有两个项目"级别的提及，零专文。agent-security-governance/references/ 里有一份 MCP 供应链红队材料，但从未对任何实际 server 跑过。方向：拿本机已装 MCP server 做一次权限面审计（工具清单/凭据可见范围/跨会话残留），产出一张真实权限矩阵——这正好补 C5 的欠账。
  2. Jetson 自有实测（连续第二周空白）——Jetson 本周 6 篇提及、64 次频次，全是引用别人的数字（W40 已点过同样问题，本周未改善）。方向：本机 Orin 上跑一次 GraphRAG 的"抽取账单"实测（27B 本地模型的 token/s、每 100 chunk 耗时/成本），用自有读数替换文中外部数字——这是我们唯一能低成本拿到的差异化数据。
  3. Claude Opus 5.5 的独立实测（235 次提及、零自测）——本周所有 Opus 5.5 判断都来自转述（卡兹克的订阅体感、Gemini 实测的对比数字 WebDev #1 / Terminal-Bench 66.4%）。方向：用同一 brief 跑 Opus 5.5 / glm-5.3 / Gemini 4 Argon 三列对比（流程已有：codex exec 三列交叉验证），把"版本真神"从转述变成读数。
  4. "测量协议"怎么写（方法论空白）——VLA 篇点名「精度验收走向'测量协议化'」但没给协议模板；我们的 E 系门禁与 notes_eval_gate 各有一套指标，却没有一份通用的"测量协议"定义（容差怎么声明、准确度/重复性/成功率怎么分报）。方向：把两边抽象成一份模板（P7 分账原则的操作版）。

六、对体系的含义（一段收束）

本周最硬的一条不是"哪个模型更强"，而是"层"比"点"更值钱：Harness² 用实验、UHP 用协议、Codex 用额度账、20 个开源项目用栈清单，四路独立证明同一件事——把编排、验证、权限这三层搭对，弱模型也能跑出强结果；反之，最贵的模型拿去干杂活，额度再多也是白烧。这条对我们的价值是方向性省钱：效果差先查 skill/harness（免费），再动模型（烧额度/花钱）。

第二条同样扎人：我们所有的门禁都在报"系统级平均"（12ep 通过率、G 系全绿），而本周最扎实的一篇实测证明同一套系统在不同题型上一次赢一次输、均值毫无信息量。P7 已进判官范式，下一步该进的是 notes_eval_gate 与 E 系验收的报告格式——分题型/分科目报数，允许"某科目明确不合格"这种诚实读数存在。

三个矛盾点全部是"叙事 vs 账本"的性质（民主化叙事 vs 生产六难、官方自述 vs 产业立场、组织叙事 vs 单人实操），本周证据不足以裁决任何一条，如实挂账。判官不代替拍板。
