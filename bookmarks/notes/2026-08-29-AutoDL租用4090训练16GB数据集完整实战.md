# AutoDL 租 4090 训练 16GB 数据集：从配置机器到训练结束的完整实战

## 1. 平台核心规则（决定操作方式的 5 条）

| 规则 | 内容 | 对操作的影响 |
|------|------|-------------|
| 计费 | 开机计费/关机停费，按秒结算，整点+关机各扣一次 | 训练完**立即关机**，准备工作用无卡模式 |

## 3. 全流程九步（详细命令见项目 docs/01_full_playbook.md）

### Step 1-2 注册租卡 + SSH
- autodl.com 注册实名 → 充 ¥50 → 算力市场筛 4090（看内存档/单价）→ 镜像选 `PyTorch 2.3 + CUDA 12.1`
- `ssh -p 38xxx root@region-x.autodl.com`；VS Code Remote-SSH 或 JupyterLab 均可

### Step 3 传 16GB 数据（四路径对比）

| 路径 | 速度 | 结论 |
|------|------|------|
| **云盘中转（AutoPanel 授权阿里云盘/OSS）** | 5-20MB/s 稳定 | **首选**：本地→网盘→实例 |
| scp/rsync 直连 | 受本地宽带限制（100M 上行≈1.5MB/s→3h） | 小文件用 |
| JupyterLab 拖拽 | 1GB 内 | 代码/小配置用 |
| autodl-pub 公共数据 | 免传输 | 有现成数据集直接用 |

要点：**先压缩再传**（tar.zst）；下载固定到 `/root/autodl-tmp`；传完 `du -sh` 校验。
没有真实数据集？项目自带 `make_dataset_16g.py` 现场生成 16GB（100 类×8000 张，验证全链路）。

### Step 4 环境
```bash
source /etc/network_turbo && pip install timm && unset http_proxy https_proxy
python -c "import torch; print(torch.cuda.is_available())"   # 必须 True
```

### Step 5-6 tmux 长跑训练
```bash
tmux new -s train    # SSH 断线训练不死；Ctrl+B D 脱离
python train.py --data /root/autodl-tmp/data --epochs 20 --batch-size 256 --amp --workers 12
```
首 10 分钟盯三件事：GPU util>90%、显存 21/24GB（OOM 降 128）、loss 下降。
断点续训：同命令 + `--resume`（latest.pt 含 model/optimizer/scheduler/scaler 全状态）。

### Step 7 监控
`watch -n2 nvidia-smi` + train.log（每 20 step loss/lr，每 epoch val_acc+★best）。
异常速查：GPU 周期掉 0→DataLoader 饥饿加 workers；loss NaN→lr 减半查 AMP；OOM→降 bs。

### Step 8-9 成果回收 + 关机
```bash
tar -I zstd -cf results.tar.zst best.pt train.log
# AutoPanel 网盘上传 / scp 拉回 / 推 GitHub
# 控制台关机——按秒停费；数据盘保留但长期资产务必三备份
```

## 4. 常见坑速查表（10 条血泪）

| 坑 | 解 |
|----|-----|
| 数据放系统盘（30GB 满报 No space） | 一切放 `/root/autodl-tmp` |
| pip 装成 CPU 版 torch | 用平台官方镜像，不乱装 |
| network_turbo 忘关 | unset 两个代理变量 |
| tmux 外跑训练 | SSH 断=训练死，必开 tmux |
| 关机后原主机没卡 | 等待/迁移实例/无卡开机取数据 |
| 阿里云盘限速 | 三方权益包或换 OSS |
| 余额不足停机杀进程 | 长跑前充够 |
| 内存超限被 kill（无 swap） | workers 降 4 |
| best.pt 丢失 | 脚本已 best/双份 + resume 恢复 best_acc |
| 15 天不登录被回收 | 定期登录 + 余额>¥10 |

## 5. 120GB 内存与多卡（DDP 要点）

AutoDL 内存=每卡配额×卡数 → 120GB 档≈4×4090（¥7.5/时）。**先判断是内存墙还是算力墙**：
- 16GB 数据集 ImageFolder 流式读取：单卡 32GB 够，别为内存租 4 卡
- 真需多卡：`torchrun --nproc_per_node=4`，改动 ~25 行（DistributedSampler+set_epoch/DDP 包裹/rank0 存 ckpt/all_reduce 聚合/lr×world_size），坑表见 docs/02_ddp_notes.md

## 6. 已落地项目（四件套逐一展开）

项目路径：`~/uclaw/project/AutoDL-4090-Train/`——以下每项给出"是什么 + 怎么用 + 关键实现"。

### 6.1 `scripts/make_dataset_16g.py` — 现场合成 16GB 数据集

**是什么**：没有真实数据集时，在 AutoDL 实例上直接生成一个 16GB 的 ImageFolder 布局数据集，用于验证"16GB 数据训练"的完整工程链路（磁盘占用/DataLoader 吞吐/检查点体积/训练时长）。

**怎么用**（无卡模式 ¥0.1/时 下即可跑，不占 GPU 时长）：
```bash
pip install pillow numpy
python scripts/make_dataset_16g.py --out /root/autodl-tmp/data --target-gb 16
# 生成约 30-40 分钟（16 核并行）；完成后自动打印总体积校验
```

**关键实现**：
| 机制 | 说明 |
|------|------|
| 体积校准 | 先采样 50 张估平均单张体积（331×331 JPEG q90 ≈ 70KB），反推总张数（~80 万张/100 类） |
| 可学习设计 | 每类绑定独立 HSV 基色 + 条纹频率——是"结构化噪声"而非纯随机，训练能真收敛（精度无意义但 loss 曲线真实） |
| 断点续生成 | 已存在的文件跳过（`os.path.exists` 检查），中断后重跑同命令接着来 |
| 多进程 | `ProcessPoolExecutor` + chunksize=64，默认 `cpu_count()-2` 个 worker |

**注意**：输出布局严格遵循 `data/train/class_XXX/img.jpg` + `data/val/...`——torchvision `ImageFolder` 直接可读。

### 6.2 `scripts/train.py` — 生产级单卡训练脚本

**是什么**：完整可跑的分类训练脚本，把"tmux 长跑 + AMP + 断点续训 + 日志双写"四个生产要素全部内置。

**怎么用**：
```bash
tmux new -s train     # 先开 tmux！
python scripts/train.py --data /root/autodl-tmp/data \
    --epochs 20 --batch-size 256 --amp --workers 12
# 中断后续训（同命令 + --resume，自动从 runs/exp1/latest.pt 恢复）：
python scripts/train.py --data /root/autodl-tmp/data \
    --epochs 20 --batch-size 256 --amp --workers 12 --resume
# 常用参数：--img-size 331 / --lr 1e-3 / --out runs/exp1
```

**关键实现**：
| 机制 | 代码要点 | 为什么 |
|------|---------|--------|
| AMP 混合精度 | `autocast` + `GradScaler` | 显存减半→bs 翻倍→吞吐近翻倍；4090 Tensor Core 全开 |
| 双检查点 | `latest.pt`（model+optimizer+scheduler+scaler+epoch 全状态）/ `best.pt`（仅权重+精度） | latest 保证断点精确恢复；best 保证成果不被覆盖 |
| warmup + cosine | 前 2 epoch 线性升温，之后余弦衰减至 0.25 倍底 | 大 bs 训练初期防炸，后期细收敛 |
| 日志双写 | 终端 print + `runs/exp1/train.log` 追加 | tmux 断线后仍可 `tail -f` 追进度 |
| 数据加载 | `pin_memory + persistent_workers + prefetch_factor=4 + drop_last` | 消除 epoch 间 worker 重启开销，GPU 不等数据 |
| 模型 | timm `resnet50.a1_in1k` 预训练优先，无 timm 自动降级 torchvision | ImageNet 权重起步，20 epoch 内即可到高精度 |

**显存参考**（331px/AMP）：bs=128 ≈14GB 稳；bs=256 ≈21GB 贴 4090 上限，OOM 就降 128。
**预期耗时**：单 epoch 30-40 分钟（80 万张，吞吐 2500-3500 img/s），20 epoch ≈ 10-13h ≈ ¥19-25。

### 6.4 `docs/02_ddp_notes.md` — 4 卡 DDP 改造清单

**是什么**：当确认为算力墙（而非数据加载瓶颈）需要升级 4×4090（128GB 内存档）时，在单卡 train.py 基础上的**最小改动清单**。

**怎么用**：按清单 7 处改动逐条套用（约 25 行代码），启动命令换 `torchrun --nproc_per_node=4`。

**关键内容**：
| 改动点 | 代码 |
|--------|------|
| 初始化 | `dist.init_process_group("nccl")` + `LOCAL_RANK` 绑卡 |
| 数据 | `DistributedSampler`（shuffle=False）+ 每 epoch `sampler.set_epoch()` |
| 模型 | `DDP(model, device_ids=[local_rank])` |
| 存储 | 只 rank 0 写日志/检查点（否则体积 ×4） |
| 验证 | `all_reduce` 聚合各卡 correct |
| 学习率 | 有效 batch ×4 → lr 线性放大（或保守 ×2） |

**何时才需要 4 卡**（重要决策，勿为内存数字倒推）：
- ❌ 16GB 数据集 + ImageFolder 流式读取 → 单卡 32GB 内存足够
- ✅ 全数据 in-memory 缓存 / 7B+ 全参微调 / epoch 时长压到 1/4 有硬需求

附**多卡特有坑表**：NCCL hang（master_port 冲突/`NCCL_P2P_DISABLE=1`）、sampler 忘 set_epoch（每轮数据顺序相同精度差）、检查点 ×4、显存不均、计费 ×4（¥7.5/时）。
