一、内容整理

1.1 核心概念

OpenFugu 是一个开源的 模型调度器（Model Orchestrator），核心是一个仅 0.6B 参数的极小模型，不回答用户问题，只做一件事：

读问题 → 提取关键特征 → 判断哪个大模型最适合 → 派活
  • 调度成本：一次前向传播，约 0.01 秒
  • 调度准确率：95%（37 个测试用例）
  • 角色分配准确率：100%
  • 编排后比最佳单模型强 107%
  • 调度器可训练参数仅 19,500 个（vs 被指挥的几千亿参数大模型）

1.3 训练算法

不用梯度的进化策略 sep-CMA-ES（类似遗传算法）：
- 每次随机变异一点点
- 保留效果好的一代代进化
- 15 次纠正自己错误的日志（作者坦诚记录）

二、查询拓展

2.1 模型编排（Model Orchestration）趋势

"单一模型回答一切" → "多模型协作"，类比互联网从"一个网站做所有事"到"微服务架构"。

2.2 本地验证流程（4GB 显存即可）

git clone https://github.com/trotsky1997/OpenFugu.git
cd OpenFugu
pip install -r requirements.txt
python scripts/fetch_artifacts.py
python openfugu/mini.py --self-test  # 输出 95%/100%

2.3 自建智能路由

python openfugu/serve.py \
  --slot-models "openai/gpt-4o,anthropic/claude-sonnet-4,google/gemini-2.0-flash" \
  --port 8088

三、归纳总结

维度 内容
核心价值 让模型编排机制完全透明、可学习、可复现
性价比 简单问题走便宜模型，复杂问题调贵模型，按难度花钱
不绑死厂商 换模型池即可，对外接口不变
学习价值 代码几十文件，每个技术细节标证据来源，最佳学习材料

四、趋势判断

  1. 模型编排成主流：多模型协作替代单一模型，类似微服务架构
  2. 开源透明化：闭源技术被逆向开源，知识民主化
  3. 成本优化刚需：API 费用高昂，智能路由省成本
  4. 小模型调度大模型：19,500 参数调度几千亿参数，范式创新
