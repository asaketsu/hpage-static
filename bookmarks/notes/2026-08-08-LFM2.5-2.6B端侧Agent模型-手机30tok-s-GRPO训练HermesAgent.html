一句话定义

2.6B 参数的端侧 Agent 模型——手机 CPU 上 30 tok/s、M5 Max CPU 上 220 tok/s、H100 单卡高并发下近 15K tok/s（日均 ~13 亿 token）。在指令遵循和工具使用 benchmark 上超越 4 倍大小的模型（Gemma-4-E4B/Qwen3.5-4B），专为端侧 Agent 工作流设计：规划、工具调用、多步任务。

核心论点：去除 per-token 成本后，Agent 可以大规模并行运行在本地硬件上，24/7 运行后台任务烧掉数百万 token 零边际成本。当 token 花费不再是约束，Agent 可以无处不在。

四阶段后训练管线

LFM2.5-2.6B-Base
  │
  ├─ ① SFT（两轮：广覆盖 → 定向技能强化）
  │     └─ SFT 训练量是 LFM2.5-8B-A1B 的 7 倍
  │     └─ 侧重 agentic tasks：工具使用/Web 搜索/软件工程/Agent traces
  │
  ├─ ② Teacher Specialization（专家教师训练）
  │     └─ 从共享 SFT checkpoint 分出 6 个领域专家
  │     └─ 指令遵循/数学/知识(幻觉控制)/代码/工具使用/长上下文
  │     └─ 每个专家独立 SFT + RLVR
  │
  ├─ ③ MOPD（多领域 On-Policy 蒸馏）
  │     └─ Student 在自己的 policy 下 rollout
  │     └─ 每个 prompt 路由到对应领域的 Teacher
  │     └─ Teacher 提供 token 级反馈
  │     └─ 关键：Teacher 和 Student 从同一 SFT checkpoint 分支，分布接近
  │
  └─ ④ Agentic RL（真实 Agent 环境中的强化学习）
        └─ 多轮 agentic RL 通过真实 Agent harness
        └─ 任务：研究/写作/编码/数据分析/文档管理/工具使用/多步工作流
        └─ 优化算法：GRPO
        └─ 奖励：LLM-as-a-Judge rubric + 程序化检查 + 安全硬门禁
        └─ 训练环境：Hermes Agent / OpenClaw / 其他 harness

Agentic RL 训练架构

Training Engine (FSDP) ←→ RL Framework (verl) ←→ Rollout Engine (SGLang)
                                                        │
                                         Sandbox Service │
                                          ┌───────────────┘
                                          │
                                 Blackbox Harness
                                  (OpenClaw / Hermes Agent)
                                          │
                                  Harness Proxy
                                  (透明捕获 token 级轨迹)
                                          │
                                线性轨迹一致性检查
                                Token 不匹配检查
                                Rollout Routing Replay (R3)

关键设计：Harness Proxy 把 Agent harness 当作黑盒——不修改 harness 代码，同时透明捕获训练所需的 token 级轨迹。包括线性轨迹一致性、Token 不匹配检查、R3（Rollout Routing Replay）。

Hermes Agent 兼容性

Setting up your own local agent takes only two steps. First, serve LFM2.5-2.6B behind an OpenAI-compatible endpoint, then point your agent harness at it. It works out of the box with popular harnesses like Hermes Agent, OpenClaw, and Pi.

Liquid AI 官方提供了 Agent harness 集成指南，确认 Hermes Agent 是 LFM2.5-2.6B 的原生支持 harness。

结合最新研究与技术变化

1. 与 Hermes Agent 的直接关联

LFM2.5-2.6B 在 Agentic RL 阶段直接在 Hermes Agent 内训练——这是 Liquid AI 官方确认的。意味着这个模型对 Hermes 的工具格式、系统 prompt 和交互模式有原生优化。

端侧部署潜力：
- Jetson Orin Nano 有 8GB 内存，LFM2.5-2.6B 仅需 < 2.5GB → 可以同时跑模型 + LuxTTS + 其他服务
- 手机端 30 tok/s 意味着真正的端侧 Agent 成为可能
- 零 API 成本 → cron 任务可以 24/7 运行数百万 token

2. 与 Hands-On Modern RL 笔记的关联

LFM2.5-2.6B 的四阶段后训练管线是 Hands-On Modern RL 教程的工业级实现：
- SFT → Ch 7-8（SFT vs RL 决策）
- Teacher Specialization + MOPD → Ch 10（知识蒸馏）
- Agentic RL + GRPO → Ch 16（GRPO + RLVR）
- 真实 harness 训练 → Ch 20-21（Agentic RL）

3. 与 AI for Physics 五路线笔记的关联

LFM2.5-2.6B 的 MOPD 蒸馏是"化解→新能力连续谱"的典型案例——每个 Teacher 在各自领域的新能力（RLVR 获得），通过 on-policy 蒸馏整合到 Student 中。

4. 与自进化四波浪潮笔记的关联

Agentic RL 阶段的奖励设计（LLM-as-a-Judge rubric + 程序化检查 + 安全硬门禁）是"验证是最终瓶颈"的直接体现——程序化检查是确定性验证，LLM-as-a-Judge 是近似验证。

5. 与深入理解 AI Agent 笔记的关联

LFM2.5-2.6B 的 Agent = LLM + 上下文 + 工具公式中，这个模型同时优化了三个维度：2.6B 压缩了工具使用能力、128K 上下文处理长输入、GRPO 训练让模型在真实 Agent 环境中工作。

趋势判断

  1. 端侧 Agent 是下一个爆发点——2.6B 模型在手机上 30 tok/s，真正的隐私+低延迟+零成本的端侧 Agent 成为可能
  2. Token 零边际成本改变 Agent 设计——当 token 不花钱，Agent 可以 24/7 运行后台任务，大规模并行
  3. Hermes/OpenClaw 成为训练环境——LLM 不再只在学术 benchmark 上训练，而是直接在真实 Agent harness 中训练
  4. GRPO + 真实环境 RL 是 Agent 训练标配——SFT→蒸馏→Agentic RL 的四阶段管线正在标准化
  5. 小模型超越大模型——2.6B 在指令遵循和工具使用上超越 8B 的 Gemma，专用训练 > 通用扩大
  6. Harness Proxy 黑盒训练——不需要修改 harness 代码就能捕获训练轨迹，降低了 RL 训练的工程门槛
