## 一、原文核心内容（全流程总览）

### 1.1 问题与答案框架

**问题**：局域网有 8 块 A100，如何调用算力做训练/微调？
**答案骨架**（五步法，每步有配套脚本）：

```
体检(00) → 总线实测(01) → 显存核算(vram_calc) → 策略选择(决策树) → 一键启动(launch/*)
```

### 1.2 策略决策树（核心中的核心）

| 模型规模 | 40G×8 (320G) | 80G×8 (640G) | 启动模板 |
|----------|--------------|--------------|----------|
| ≤14B 行为调整 | LoRA-DDP | LoRA-DDP | train_lora_ddp.sh |
| ≤14B 灌知识 | ZeRO-3 全量 | ZeRO-3 全量 | train_full_zero3.sh |
| 14-30B | QLoRA / ZeRO-3(offload) | ZeRO-3 全量 | train_full_zero3.sh |
| 30-70B | QLoRA | ZeRO-3 全量 | train_full_zero3.sh |
| 70-120B | ❌ | QLoRA | train_lora_ddp.sh(qlora) |
| 多机无 IB | 一律 FSDP HYBRID_SHARD | 同左 | train_fsdp_hybrid.sh |

### 1.3 关键数字（实测锚点）

- LoRA 7B@8卡40G：**每卡仅 3.2GB**，余量 33.6GB——LoRA 的显存自由度极大
- QLoRA 70B@8卡80G：每卡 13.6GB ✅——大模型低成本试错的唯一路
- ZeRO-3 全量 14B@8卡40G：每卡 27GB ✅（余 9.8G，紧张但可行）
- ZeRO-3 全量公式：**12GB/每B参数总量**（权重2+梯度2+Adam8），再除卡数
- allreduce 总线档位：NVLink 90-140GB/s / PCIe 15-40 / 以太网≈网卡×0.7

### 2.2 使用性评估

**LoRA-DDP（80% 场景的选择）**：8 卡数据并行零心智负担，ZeRO-1 白拿优化器分片收益；rank16 对行为调整够用，灌知识升 rank64-128。
**ZeRO-3 全量**：表达力最强但最挑硬件——单机 NVLink 或双机 IB 才发挥；40G 卡训 14B 必须盯显存余量。
**FSDP HYBRID_SHARD**：无 IB 多机的救星——把通信锁在节点内 NVLink，跨机只同步梯度，25G 以太网也能全量。
**QLoRA**：大模型试错专用，速度慢 ~30% 但 40G×8 也能摸 70B。

### 2.3 指导性意见

- **先算后训**：任何任务先跑 `vram_calc.py`，OOM 在生产环境=灾难，在本计算器=一行红字
- **总线定策略**：allreduce <10GB/s（以太网级）→ 多机全量只认 HYBRID_SHARD；>80GB/s → ZeRO-3 随便
- **checkpoint 写本地 NVMe**：NFS 写 checkpoint 会随机卡死训练（铁律，见坑1）
- **有效 batch 锁定**：跨实验对比必须同有效 batch（卡数×per_device×grad_accum）
- **何时不用 8 卡**：模型 <3B 且数据 <10 万条——单卡+白天推理共享更划算（与 lan-llm-farm 时分共卡策略衔接）

### 2.4 案例可寻

- 本项目三模板即案例（7B-LoRA / 14B-ZeRO3 / 7B-FSDP 参数全给出）
- 姊妹案例：lan-llm-farm case1 Text-to-SQL（0.8B 零件锻造，gate 校验闭环）
- 工业参考：Spheron 2026 指南（NCCL 环境变量全表）、sumanthrh（HYBRID_SHARD 无 IB 实证）

### 2.5 使用方法借鉴（30 分钟快速开始）

```bash
# ① 体检（确认 40G/80G、NVLink 拓扑）
bash scripts/00_hardware_survey.sh | tee survey.txt
# ② 总线实测（NVLink 应 90-140GB/s）
NCCL_DEBUG=INFO torchrun --nproc_per_node=8 scripts/01_allreduce_bench.py
# ③ 核算（例：70B QLoRA 8×80G）
python3 tools/vram_calc.py --model 70 --mode qlora --gpus 8 --vram 80
# ④ 启动（环境变量自定义 MODEL/DATA/OUT）
MODEL=/data/models/Qwen3-7B DATA=/data/datasets/sft.jsonl bash scripts/launch/train_lora_ddp.sh
```

## 三、查询拓展（延伸事实）

1. **NCCL 环境变量速查**（Spheron 2026）：`NCCL_IB_DISABLE=0` 启用IB / `NCCL_IB_HCA=mlx5_0:1` 选HCA / `NCCL_SOCKET_IFNAME=eth0` 控制面网卡 / `NCCL_NET_GDR_READ=1` GPUDirect RDMA——日志看 `NET/IB` vs `NET/Socket` 判定实际走的通道
2. **通信量量级**：40B 模型 ZeRO-3 双机 8×A100，每步跨机通信 ~120GB——无 IB 时单步耗时秒级，这就是 HYBRID_SHARD 存在的理由
3. **ZeRO-3 与 LoRA 的坑**：stage3 分片与 `lora_target_modules ALL` 冲突会炸显存——**ZeRO-3 只配全量，LoRA 配 ZeRO-1/2**
4. **数据格式**：ms-swift 用 messages 格式 jsonl，混入 alpaca 格式**静默丢样本**——训练前日志核对样本数

## 五、趋势判断

1. **8×A100 的甜蜜区在 7-14B 全量 / ≤70B LoRA**——2026 主流开源模型（Qwen3/Llama4 系）恰好落在这个区间，这不是巧合而是硬件代际与模型代际的共振
2. **QLoRA 从"穷人的选择"变成"快速迭代标配"**：微调-评测-再微调循环里，QLoRA 慢 30% 换来的显存自由度，让 8 卡变成"可同时跑 3 个实验的试验台"
3. **HYBRID_SHARD 会成为以太网集群默认**：万兆/25G 普及但 IB 昂贵，"卡内分片+卡间复制"是通信预算约束下的工程最优解
4. **无公网不再是大障碍**：pip download 离线包 + hf-mirror + U 盘模型分发已成标准流程（本手册 §4），真正稀缺的是**把体检→基准→核算→策略→启动串成流水线的工程纪律**

## 六、归纳总结

**一句话**：8×A100 调用的本质是三道算术题——**总线带宽定策略上限、显存公式定模型上限、有效 batch 定实验可比性**；把体检/基准/核算做成训练前的固定仪式，OOM 和慢训都消灭在启动前。

**结构记忆**：
- 五步法：体检→总线→核算→决策树→模板启动
- 三档模板：LoRA-DDP（80%场景）/ ZeRO-3（有NVLink/IB）/ FSDP-HYBRID（以太网多机）
- 显存三公式：LoRA≈权重×1.15/卡 / 全量=12GB每B/卡 / QLoRA=权重×0.6/卡
- 五坑：NFS写ckpt卡死 / NCCL卡=网络 / ZeRO3×LoRA-ALL炸 / batch不齐不可比 / 数据格式静默丢
