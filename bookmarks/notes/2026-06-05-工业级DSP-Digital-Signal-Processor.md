## 一、什么是DSP

**数字信号处理器（DSP）** 是一种专用微处理器芯片，其架构针对数字信号处理的操作需求进行了优化。

> 目标：测量、滤波或压缩连续的实时模拟信号。

### DSP vs MCU vs CPU

| 维度 | MCU | CPU | DSP |
|------|-----|-----|-----|
| 核心设计 | 通用控制 | 通用计算 | 信号处理专用 |
| MAC 性能 | 弱 | 中等 | 极强（单周期 MAC） |
| 实时性 | 好 | 差（OS 延迟） | 最优（确定性延迟） |
| 功耗效率 | 高 | 低 | 高 |
| 典型应用 | 电机控制、IoT | PC、服务器 | 音频/雷达/通信/工业控制 |

### 为什么不用通用 CPU/MCU 做 DSP？

- 通用处理器 **无法持续实时** 执行 DSP 算法
- DSP 专用架构 **功耗更低**，适合便携/嵌入式设备
- DSP 算法有 **硬实时约束**（必须在固定时间内完成，不能批处理）

## 二、DSP 核心架构特征

### 2.1 软件架构

#### 指令集优化

DSP 指令集高度不规则，针对常见数学运算做了专用指令：

| 指令类型 | 用途 |
|----------|------|
| **MAC（乘累加）** | 矩阵运算、卷积、点积、多项式求值 |
| **FIR 滤波器指令** | 数字滤波核心 |
| **FFT 指令** | 频域分析 |
| **模运算寻址** | 环形缓冲区（无需边界检查） |
| **位反转寻址** | FFT 交叉引用 |
| **零开销循环** | 硬件循环缓冲区，消除循环开销 |

#### 关键特性

- **饱和算术**：溢出时停在寄存器最大值，而非回绕（避免信号失真）
- **定点运算**：比浮点更快，工业级 DSP 大量使用定点
- **单周期操作**：最大化流水线效率
- **手写汇编库**：关键算法仍用手写汇编，编译器优化无法完全替代

### 2.2 硬件架构

#### 内存架构

| 架构类型 | 说明 |
|----------|------|
| **哈佛架构** | 程序存储与数据存储分离，可并行访问 |
| **改进型哈佛** | 多总线（2 数据 + 1 程序），单周期内同时取 3 个值 |
| **多 DMA 通道** | 数据搬运不占用 CPU 周期 |

> DSP 通常 **无 MMU（内存管理单元）**，无虚拟内存，因为上下文切换延迟会破坏实时性。

#### 计算单元

- **高度并行 MAC 单元**：多个乘累加器并行工作
- **流水线架构**：取指、译码、执行、写回多段并行
- **硬件循环控制**：消除循环分支开销
- **FPU 集成**：现代 DSP 直接在数据通路中集成浮点单元

## 三、DSP 发展史

| 代际 | 时间 | 代表芯片 | 关键特征 |
|------|------|----------|----------|
| **第一代** | 1978-1983 | AMI S2811、TMS5100、μPD7720、TMS32010 | 硬件乘法器、哈佛架构、16-bit |
| **第二代** | 1985-1990 | AT&T DSP16A、Motorola 56000 | 3 存储器、24-bit、21ns MAC |
| **第三代** | 1990-1995 | TI TMS320C541、MC68356 | 专用加速单元、多核并行 |
| **第四代** | 1995+ | TI C6000、SHARC | VLIW、SIMD、超标量、3ns MAC |
| **现代** | 2010+ | C66x、C2000 Real-Time | 多核、GPU 加速、AI 扩展 |

### 里程碑

- **1978**：TMS5100（TI）— 首个 DSP，用于 Speak & Spell，首次用线性预测编码做语音合成
- **1978**：AMI S2811 — 首个专门为 DSP 设计的 IC，VMOS 工艺
- **1980**：NEC μPD7720 — 首个商用成功的 DSP
- **1983**：TMS32010 — TI 成为通用 DSP 市场领导者
- **2018**：SES-12/14 卫星 — 25% 容量用 DSP 替代模拟滤波器

## 四、工业级 DSP 主流厂商与产品线

### 4.1 Texas Instruments（TI）— 市场领导者

| 系列 | 定位 | 典型应用 |
|------|------|----------|
| **C2000** | 实时微控制器 | 电机控制、光伏逆变器、数字电源 |
| **C6000** | 高性能 DSP | 雷达、通信基站、图像处理 |
| **C66x** | 多核 DSP | 高端信号处理、AI 推理 |
| **Sitara** | ARM + DSP 异构 | 工业 HMI、网关、边缘计算 |

**C2000 系列特点**：
- 专为实时控制优化（电机 FOC、电源数字控制）
- 内置高精度 PWM、ADC、eQEP
- 浮点（C2000-FPU）和定点（C2000-Fixed）版本
- 主频 100-300MHz，单周期 MAC

**C6000 系列特点**：
- VLIW 架构，每时钟周期 8 个操作
- 主频 1.2GHz，8000 MIPS
- 8MB L2 缓存，64 个 EDMA 通道
- 用于通信、雷达、医疗成像

### 4.2 Analog Devices（ADI）

| 系列 | 定位 | 典型应用 |
|------|------|----------|
| **SHARC** | 高性能浮点 DSP | 音频处理、声纳、医疗 |
| **Blackfin** | 嵌入式 DSP+MCU | 工业控制、视频编码 |
| **DSP21xxx** | 定点 DSP | 通信、信号调理 |

**SHARC 特点**：
- 32-bit 浮点，双 MAC 单元
- 支持 SIMD 指令扩展
- 主频最高 1GHz，适合高带宽信号处理

### 4.3 其他厂商

| 厂商 | 产品线 | 特点 |
|------|--------|------|
| **NXP** | Qorivva MPC5xxx | 汽车级 DSP+MCU |
| **STMicro** | STDSP | 嵌入式信号处理 |
| **Infineon** | AURIX | 汽车安全级（ISO 26262 ASIL-D） |

## 五、工业级 DSP 核心应用场景

### 5.1 电机控制（C2000 主战场）

| 应用 | DSP 角色 | 关键指标 |
|------|----------|----------|
| **FOC（磁场定向控制）** | 实时电流环、速度环、位置环计算 | 控制周期 ≤10μs |
| **PMSM/BLDC 驱动** | 三相逆变、SVPWM 生成 | 开关频率 20-100kHz |
| **伺服驱动器** | 多轴协同、位置插补 | 多轴同步精度 <1μs |

### 5.2 数字电源

- **数字电源控制器**：电压/电流双环控制
- **PFC（功率因数校正）**：升压拓扑实时控制
- **UPS/逆变器**：SPWM 波形生成、并网同步
- 优势：参数在线可调、故障诊断、远程监控

### 5.3 雷达与通信

- **FMCW 雷达**：FFT 处理、CFAR 检测、多普勒分析
- **软件无线电（SDR）**：数字调制解调、信道编码
- **5G 基站**：波束赋形、MIMO 信号处理

### 5.4 工业检测与传感

- **超声波探伤**：脉冲回波信号处理
- **振动分析**：FFT 频谱分析、故障诊断
- **激光测距/雷达测速**：实时距离/速度计算

### 5.5 通信卫星

- **SES-12/14**：25% 转发器容量用 DSP 替代模拟滤波器
- 优势：重量↓、功耗↓、灵活性↑、可靠性↑

## 六、DSP 选型指南

### 6.1 选型决策树

```
需求类型？
├─ 实时控制（电机/电源） → C2000 / AURIX
├─ 高带宽信号处理（雷达/通信） → C6000 / SHARC
├─ 音频/语音 → SHARC / Blackfin
├─ 成本敏感/低功耗 → 定点 C2000 / Blackfin
└─ 需要 AI/ML → C66x（带 DSP 扩展）/ Sitara（ARM+DSP）
```

### 6.2 关键选型参数

| 参数 | 说明 | 典型范围 |
|------|------|----------|
| **主频** | 决定实时处理能力 | 100MHz - 1.2GHz |
| **MAC 性能** | 乘累加运算速度 | 1 MAC/cycle |
| **存储** | 片上 SRAM + 外部扩展 | 32KB - 8MB |
| **外设** | PWM/ADC/DMA/通信接口 | 取决于应用 |
| **功耗** | 工业级 vs 消费级 | 100mW - 10W |
| **温度范围** | 工业级 -40~85°C，车规 -40~125°C | 环境决定 |
| **认证** | ISO 26262 / IEC 61508 | 安全关键应用 |

## 七、DSP 编程关键要点

### 7.1 数据格式选择

| 格式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **定点（Fixed-point）** | 速度快、功耗低、成本低 | 动态范围小、需手动量化 | 电机控制、电源 |
| **浮点（Floating-point）** | 动态范围大、开发简单 | 速度慢、功耗高 | 雷达、通信、音频 |

### 7.2 性能优化策略

1. **手写关键路径汇编**：FFT、滤波器核心循环
2. **DMA 数据搬运**：ADC 采样→内存→CPU 处理，零拷贝
3. **零开销循环**：硬件循环缓冲区，消除分支预测
4. **流水线填充**：避免流水线气泡
5. **内存对齐**：多总线并行访问需 4/8 字节对齐

### 7.3 实时性保证

- 禁用操作系统（裸机）或使用 **RTOS**（FreeRTOS、RT-Thread）
- 中断优先级分层：ADC 采样 > 控制计算 > 通信
- 避免动态内存分配（malloc/free）
- 使用静态分配和对象池

## 八、DSP 与 MCU/FPGA 的边界

| 场景 | 首选 | 原因 |
|------|------|------|
| 简单控制 + 少量信号处理 | MCU | 成本低、生态成熟 |
| 复杂控制 + 中等信号处理 | DSP | 实时性 + 信号处理能力平衡 |
| 超高速信号处理（>100MSps） | FPGA | 并行流水线、确定性延迟 |
| 控制 + 信号处理 + 通信 + UI | SoC（ARM+DSP） | 异构计算，各司其职 |

> **趋势**：DSP 与 MCU 边界模糊化（C2000 本质是 DSP+MCU），FPGA 与 DSP 融合（SoC FPGA 如 Zynq）。

## 💡 启发与吸收

### 对我的提升

1. **架构选型思维**：不是"哪个更强"，而是"哪个最适合"——实时控制选 C2000，高带宽选 C6000/SHARC，成本敏感选定点
2. **定点 vs 浮点**：工业级 DSP 大量使用定点，因为速度 + 功耗优势明显，但开发难度更高（需手动量化分析）
3. **DMA 是实时系统的生命线**：数据搬运不占用 CPU，是保证控制周期确定性的关键
4. **手写汇编仍有价值**：在 DSP 领域，关键算法的手写汇编性能远超编译器优化

### 实施建议

- 电机控制/数字电源项目 → 优先评估 TI C2000（LaunchXL-F280049 开发板约 ¥200）
- 需要 FFT/滤波算法 → 学习 CMSIS-DSP（ARM）或 TI DSPLIB
- 实时性要求极高 → 裸机 + DMA + 中断分层，避免 RTOS 调度抖动
