## 核心发现

安全研究者在 Meta 智能眼镜伴侣应用 Stella（com.facebook.stella v273.0.0.21）中发现了一套完整的、处于休眠状态的人脸识别管道。这并非"Meta 正在秘密识别你看的人"，而是"完成此事的完整设备已组装完毕、功能正常，仅由 Meta 一端开关控制"。

## 技术细节

**三个端侧 AI 模型（~100 MB 总计）**：

1. SCRFD（3.4 MB）：人脸检测模型，基于 InsightFace/ICLR 2022
2. KPSAligner（117 KB）：关键点对齐模型，标准做法（MTCNN/dlib 同源）
3. SFace（96 MB）：人脸嵌入模型，输出 2048 维生物特征向量，远大于公开参考版本（~40 MB / 128-512 维）

**完整管道**：人脸检测 → 关键点对齐 → 2048维嵌入生成 → 本地向量索引（余弦相似度） → 匹配触发 Android 通知"Person Recognized"

**关键证据**：
  模型通过 Meta 的 NMLML 资产分发系统下载
  本地数据库 schema 包含生物特征记录的写入路径
  完整的通知 UI 界面已接线
  研究者用测试图片成功跑通端到端识别流程

**当前状态**：
  普通用户账户看不到相关 UI
  通知深链接的目标页面在构建中缺失
  未观察到 Meta 服务器向数据库推送身份数据

## 安全与隐私影响

1. 🎯 **预部署风险**：功能完整的生物识别管道预装在消费设备上，意味着一次服务器端开关或 OTA 更新即可激活，无需用户下载新组件
2. 🎯 **嵌入维度放大**：Meta 的 SFace 变体输出 2048 维（公开版 128-512 维），暗示更精细的识别能力或更大规模的底库
3. 🎯 **ExecuTorch 端侧推理**：全部模型通过 ExecuTorch 在设备端运行，数据不上传云端（但也意味着无法通过中间人检测）
4. 🎯 **法律灰色地带**：预装休眠的识别管道是否违反 GDPR/CCPA 生物数据保护条款？当前处于未激活状态，但管道的"就绪性"本身可能构成合规风险

## 借鉴进化点（3条）

1. 🔧 **Agent 系统的休眠能力设计**：Meta 的模式——完整管道预装、服务器端功能开关——可借鉴到 Agent 系统的功能灰度发布。对于 Hermes，可以在 agent 中预埋能力模块（如新的搜索降级链），通过配置开关控制激活，避免需要更新代码
2. 🔧 **端侧模型的逆向审计方法论**：研究者通过 APK 静态分析（拆解 .pte 模型文件、数据库 schema、通知通道）还原了完整管道。这套方法论可复用于任何移动端 AI 应用的隐私审计——检查模型文件、数据库表结构、Intent 过滤器
3. 🔧 **生物特征数据的架构防护**：2048 维嵌入向量存储在本地 SQLite 向量索引中。对于 Hermes 的记忆系统设计，敏感数据（如用户偏好嵌入）应考虑加密存储 + 访问审计，而非明文向量索引

## 深层思考

这起事件揭示了 AI 硬件产品的一个新范式：**能力预部署 + 云端激活**。硬件出厂时已具备全部 AI 能力，消费者购买的是一个"潜在功能"的载体。这种模式模糊了"设备能做什么"和"设备正在做什么"的界限，对监管框架提出了全新挑战。

对 AI Agent 社区而言，这提醒我们：能力边界不仅取决于代码逻辑，更取决于部署架构中的开关设计。一个"看起来无害"的休眠模块，可能只需一行配置变更就能变成完整的监控管道。
