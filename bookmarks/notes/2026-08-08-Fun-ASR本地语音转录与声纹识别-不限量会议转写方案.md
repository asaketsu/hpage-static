## 一句话定义

> 基于 Fun-ASR 的本地不限量语音转录方案——语音转文本 + 说话人分离（speaker diarization）+ **声纹识别自动标注发言人** + 大模型文本整理。声纹库越用越精准，形成正向循环。完全本地运行，替代飞书妙记的分钟限制。

## 完整原文核心内容

### 转录流程 Pipeline

```
1. 启动电脑录音
      ↓
2. Fun-ASR 转录文本（区分说话人 speaker 0, speaker 1...）
      ↓
3. 大模型文本整理：
   - 按对话主题聚合 + 对话轮次呈现
   - 还原对话真实信息
   - 生成 Final 文稿 + 摘要
      ↓
4. 说话人映射表（spk_id ↔ display_name）
   - 声纹识别自动建议 suggested_name + 匹配度 score
   - 人工确认/修正
   - 回灌声纹库（越用越准）
```

### 声纹识别工作流

#### 初始状态（无声纹库）

| spk_id | display_name | suggested_name | score | locked |
|--------|-------------|----------------|-------|--------|
| 0 | 发言者 0 | 赵二 | 0.337 | no |
| 1 | 发言者 1 | 张三 | 0.403 | no |
| 2 | 王五 | 李四 | 0.359 | yes |

> 匹配度都低于 0.5，系统给的建议不准，需要人工修正。

#### 人工修正 + 回灌声纹库

人工确认 spk_id=2 实际是"王五"后：
1. display_name 改为"王五"
2. locked 改为 yes
3. **回灌声纹库**——系统自动从录音中挑出王五的音频片段
4. 人工确认片段后，系统建立王五的声纹特征

#### 再次识别

| spk_id | display_name | suggested_name | score | locked |
|--------|-------------|----------------|-------|--------|
| 0 | 发言者 0 | 赵二 | 0.337 | no |
| 1 | 发言者 1 | 张三 | 0.403 | no |
| 2 | 王五 | **王五** | **1.000** | no |

> 王五的 score 达到 1.000，系统已能准确识别。

#### 成熟期

> 多场景语料交叉标注后，系统对音色特征越来越熟悉，不同会议中都能稳定识别，score 基本达到 **0.7-0.8**。

### 声纹库建立方式

| 方式 | 说明 | 实操难度 |
|------|------|---------|
| **单人音频注册** | 专门提供一段纯净单人音频注册声纹 | ⚠️ 难度高（需要专门录制） |
| **会议回灌** | 标注后的发言人映射关系回灌声纹库 | ✅ 推荐（自然积累） |

> 重点推荐**回灌声纹库**——人工确认后系统自动从录音提取该说话人音频片段建立声纹特征，无需专门录制。

### 声纹库的成长性

```
初次使用 → 匹配度低(<0.5) → 人工修正 → 回灌声纹库
    ↑                                              ↓
    └── 多场景交叉标注 ← score提升(0.7-0.8) ←────┘
    
    正向循环：越用越精准 → 越准越好用 → 越愿意用
```

## 结合最新研究与技术变化

### 1. 与 LuxTTS 的关联

LuxTTS（Jetson 上的语音克隆）和 Fun-ASR 的声纹识别是**同一技术栈的两个方向**——LuxTTS 从文本到语音（合成），Fun-ASR 从语音到文本+身份（识别）。两者的声纹特征提取技术是互通的。

### 2. 与 Whisper Skill 的关联

Hermes 有 `whisper` Skill（OpenAI 语音识别），但 Whisper 只做语音转文本，**不做说话人分离和声纹识别**。Fun-ASR 在中文场景下更强（专门优化中文识别），且自带说话人分离+声纹库。

### 3. 与本地 AI 七层堆栈的关联

Fun-ASR 对应七层堆栈中的：
- **模型层**：语音识别模型（ASR + 说话人分离 + 声纹识别）
- **记忆层**：声纹库（可累积可审计的成长性记忆）
- **工作流层**：录音→转录→整理→标注→回灌的闭环

### 4. 与数字人口播 Rachel Skill 的关联

Rachel 用 MiniMax 做声音克隆（voice clone），Fun-ASR 做声纹识别（voice identification）。一个是"从声纹特征生成语音"，另一个是"从语音提取声纹特征匹配身份"。

### 5. 与 Hermes STT 的关联

Hermes 的 STT 目前用 faster-whisper 做语音转文本。Fun-ASR 可以作为升级方案——增加说话人分离和声纹识别，让 Hermes 处理多人对话场景时知道"谁在说什么"。

1. **本地语音转录正在替代云端服务**——不限量+隐私+声纹成长性是核心优势
