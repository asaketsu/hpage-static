内容整理：MUSE-Autoskill 五阶段技能生命周期

1. 核心论点：技能是长期进化资产，不是单次生成产物

论文识别现有 AutoSkill 系统的四个实践空白：
- ①创建与使用不匹配：技能创建时无法访问 Agent 运行时上下文
- ②缺乏结构化逐技能记忆：无法跨任务积累自由形式经验
- ③静态且未经验证：缺单元测试驱动评估
- ④上下文处理差：扁平对话历史长任务截断/溢出

五阶段生命周期：创建 → 记忆 → 管理 → 评估 → 优化。技能打包遵循 Anthropic Agent Skills 格式（SKILL.md + scripts/ + resources/ + tests/），创建后必须在沙盒跑通 tests/ 全部单测才能注册入技能库；失败则检查错误栈调用 update_skill 修补重测。

2. 三级记忆架构（核心创新：技能级记忆）

  • 技能级记忆：每个技能目录挂 .memory.md 文件，跨任务积累该技能的笔记/经验/使用观测（已知故障模式、输入格式特性、性能注意事项）。加载技能时与 SKILL.md 接口一起注入——Agent 受益于先前经验无需重新推导。
  • 短期记忆：当前任务上下文，增长时自适应压缩中间步骤摘要。
  • 长期记忆：跨会话持久笔记，不压缩，存放环境特性等超越单一技能的一般经验。

3. 两级自适应上下文压缩

上下文维护为对话节点 DAG（每轮一节点，记录响应/工具调用/观测/token 用量）：
- 一级（单节点压缩）：只重写超阈值节点的负载为紧凑摘要，保留每轮边界与规划-行动-观测结构——破坏性小，后续轮次仍可按位置引用
- 二级（链压缩）：仅当一级不够时，合并连续中间节点为综合摘要节点，丢失每轮结构
- 原始节点永远保留在完整历史，活动链始终可恢复；每会话后全状态快照持久化，支持任务中断恢复

4. 实验结果（SkillsBench 51 任务，GPT-5.5 主干）

  • MUSE-Autoskill 68.40% 总体最优，超 Codex (67.3%) 和 Hermes (61.2%)
  • 比无技能基线 +15.21pp
  • 从自身成功轨迹创建技能后，35 个生成成功任务上准确率 87.94%，超越人类技能基线（约75%）——AI 生成的技能比人写的更好
  • 跨 Agent 迁移：MUSE 生成的技能注入 Hermes 后 +10.51pp，抹平 79% 与人类技能差距——证明生成的是"外部化知识资产"而非绑定单一运行时的行为

5. 技能库三种维护机制

  • 优化：技能失败时根据错误反馈修订或重新生成
  • 合并：重叠技能合并为更通用的单一技能
  • 剪枝：删除持续失败或长期未使用的技能

6. Hermes Learning Loop 对照（CSDN 实战拆解）

  • 记忆存储：SQLite FTS5 全文索引，importance 字段 + BM25 相关性综合排序取 Top-K 注入 system 上下文
  • Skill 自动创建：检测重复性任务模式 → 提议创建（fetch_issues_to_notion 式）
  • 使用中自改进：记录成功率/用户修正/执行时间，连续失败自动调整步骤或建议重建
  • 触发调度：trigger 规则（关键词/正则/语义匹配）+ Gateway 层路由，每 Skill 独立超时/重试/回退配置

查询拓展

  • MUSE 的技能级记忆(.memory.md) 与 Hermes 现有 skill references/ 目录的边界在哪：references 是静态知识，.memory.md 是动态使用经验——Hermes 的 experience-bank skill 已部分覆盖但未按技能目录挂载。
  • 跨 Agent 迁移的"79% 差距抹平"实验设计值得复刻：把 Hermes 生成的 skill 注入 Claude Code/OpenClaw 验证可移植性，是检验 skill 质量的硬标准。
  • 单测驱动技能验证在 Hermes 的落地成本：现有 skill_manage 无 tests/ 惯例，需评估为哪些高价值 skill 补测试（cron 类 skill 最容易——执行结果可断言）。

归纳总结

  • 技能系统的分水岭不在"能不能创建"而在五阶段是否闭环：创建-记忆-管理-评估-优化缺一段，技能库就会退化为僵尸堆积。Hermes 当前有创建(技能管理)+记忆(memory)+管理(skill-review)但评估与优化未机械化——skill_stress_test 存在但未强制门禁化。
  • 技能级记忆是被低估的关键设计：把使用经验挂在技能本体而非全局记忆，检索时随技能一起加载，解决"知识在库里但用时想不起"的经典失败。与 Hermes memorygraph 的实体链接互补。
  • AI 生成技能超越人类技能（87.94% vs 75%）的前提是单测过滤：只有跑通 tests/ 的技能才入库——质量门禁机械化再次被验证为自进化系统的必要条件，与用户"信任重建靠机械化门禁非口头承诺"的定调完全一致。
  • 上下文两级压缩（先节点后链）的保守策略哲学：破坏性小的先做，结构信息（每轮边界）尽量保留——与 harness-checkpoint 的断点恢复设计同构。

趋势判断

  • Agent Skill 正从"提示词封装"演进为"带测试、带记忆、带版本管理的软件资产"——Anthropic SKILL.md 格式成为事实标准后，生命周期管理（本次论文）是下一个竞争点。字节&RIT 的 MUSE 是首篇五阶段全覆盖的免训练方案。
  • 跨 Agent 技能迁移将成为 skill 质量的标准验收口径："生成的技能能否被别的 Agent 用"比"在自己的循环里得分"更有说服力。Hermes 作为被测 Agent 出现在论文实验里（61.2%），说明其 skill 机制已达学术基准测试覆盖度。
  • 技能评估的自动化（单测+运行时反馈）与 RL 策略的机械化门禁（12ep+三科目）是同一趋势在两个领域的投影：验收从人工目测走向程序化断言。

关联分析

  • 与 Hermes 的直接映射：MUSE 在 SkillsBench 上击败 Hermes (68.40% vs 61.2%)，差距来源按论文归因是——①Hermes 无技能级记忆（经验散在全局 memory）②无单测门禁（技能质量靠 review 惯例）③上下文压缩策略未公开但推断为截断式。这三点都是可落地补强项。
  • 与既有笔记的呼应：与 09-28《Agent即策略模型》《把经验教给AI的Skill制作方法论》构成技能进化三部曲——前者立"Agent=策略"本体论，方法论篇立"Skill=经验载体"，本篇补"生命周期闭环+质量门禁"，理论链条完整。
  • 与 evolver/skill-review 现有机制对照：优化/合并/剪枝三机制 Hermes 已有对应物（evolver 合并清理+skill-review 退化检测），缺失环节精确锁定在评估机械化——skill_stress_test 应升级为高价值 skill 的入库门禁。

拓展应用推荐

  • P0（Hermes）：为 cron 类 skill（执行结果可断言：文件产出/exit code/输出格式）试点单测门禁——入库/更新必须附 tests/ 并通过。首批候选：daily-paper-reading（笔记双格式可验）、a-stock-market-summary（飞书格式可验）。
  • P1（Hermes）：技能级记忆试点——在高频 skill 目录挂 .memory.md，由 experience-bank 自动追加使用经验，skill_view 时联动加载。候选：search-fallback-chain（每次降级路径都是宝贵经验）。
  • P2（Hermes）：两级上下文压缩策略对照——当前 compaction 是链式摘要（相当于直接二级），可借鉴"先单节点压缩"的保守策略，在大工具输出（terminal 长输出）场景先做节点级摘要，保结构信息。
  • P3（观察）：跟踪 MUSE-Autoskill 开源实现（github.com/Akshay2695/muse_autoskill），其 .memory.md 与 tests/ 惯例若被社区采纳，Hermes skill 格式应跟进兼容。

指南分析：技能生命周期五阶段自检清单（下次直接抄）

  1. 创建：技能创建时能否访问运行时上下文？（禁闭门造车式预生成）
  2. 记忆：该技能的使用经验存在哪？下次调用能否自动带出？
  3. 管理：技能库有无索引+定期 review（重叠合并/僵尸剪枝）？
  4. 评估：入库前有无程序化断言（单测/执行验证）？
  5. 优化：失败反馈能否自动触发修订而非只记 error-case？
  6. （迁移加分项）该技能拿到别的 Agent 里能否直接用？（SKILL.md 自包含度检验）
