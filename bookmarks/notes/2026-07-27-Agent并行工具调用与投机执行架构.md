# Agent 并行工具调用与投机执行 — 从 ReAct 串行到 3.7× 加速的架构跃迁

> **出处**: arXiv 2312.04511 (LLMCompiler, ICML 2024) / 2603.18897 (PASTE, 2026-03) / 2604.16469 (B-PASTE, 2026-04) / SimpleTool (2026-03) / Speculative Actions (2025-10, MIT+Cornell)
> **日期**: 2026-07-27
> **标签**: #AI-Agent #并行执行 #投机执行 #工具调用 #延迟优化 #LLMCompiler #PASTE #SimpleTool

## 一、核心问题：串行 ReAct 循环的延迟税

主流 Agent 架构（ReAct 式循环）本质是「思考→调用工具→等待→再思考」的串行管线。**工具执行占 Agent 总请求时间的 35-61%**，多步任务延迟线性叠加，5-15 次工具调用可轻易达到数十秒甚至分钟级。

延迟敏感场景更严重：
- 语音 Agent 需亚秒级响应
- 具身 AI 需 10+ Hz 控制频率
- 企业客服用户等待 15-30 秒即体验崩塌

**根本矛盾**：模型推理已经足够快，瓶颈在「管线工程」——调用编排、等待、序列化。

## 二、三层加速技术栈

| 层级 | 技术 | 优化目标 | 延迟收益 | 成熟度 |
|------|------|----------|----------|--------|
| **层 1：单步并行** | Parallel Tool Calling / LLMCompiler | 单轮内独立工具并发 | 1.5-3.7× | 生产就绪 |
| **层 2：跨步投机** | Speculative Actions / PASTE / B-PASTE | 预测下一步工具并预执行 | 1.4-2× | 研究到早期生产 |
| **层 3：token 级** | SimpleTool | 压缩函数调用生成 | 3-6×（单步内） | 需微调 |

三层可组合叠加，聚合效果可将 30 秒任务压缩到 5-8 秒。

### 2.1 Parallel Tool Calling — 低垂果实

**原理**：当 Agent 需要多个互相独立的信息时，一次性并发获取。三个 300ms 的串行 API 变成一个 300ms 的并行调用——3× 加速。

**关键约束**：依赖分析。只有真正无依赖（无共享状态突变、无顺序要求、无数据依赖）的操作才能安全并行。大多数框架采用保守策略：模型显式声明独立调用，编排器只并行化这些。

### 2.2 LLMCompiler（arXiv 2312.04511, ICML 2024）

借鉴经典编译器原理，三阶段架构：

```
问题输入 → [Planner] 分解+识别依赖 → [Task Fetching Unit] 准备输入 → [Executor] 并发执行
```

| 指标 | ReAct 基线 | LLMCompiler | 提升 |
|------|-----------|-------------|------|
| 延迟 | 1× | 最高 3.7× 加速 | 3.7× |
| 成本 | 1× | 最高 6.7× 节省 | 6.7× |
| 准确率 | 基线 | +~9% | 9% |

成本节省来自更少的 LLM 推理轮次——3 次工具调用一轮解决而非三轮。

### 2.3 Speculative Actions（MIT+Cornell, 2025-10）

**灵感**：直接借鉴 CPU 架构的投机执行。处理器预测分支并提前处理；如果预测正确，工作已完成；如果错误，丢弃重来。

**Agent 版本**：用一个更小的「草稿模型」预测主模型可能的下一步动作，在主模型还在思考时就预执行。

| 指标 | 数值 |
|------|------|
| 下一步动作预测准确率 | 最高 55% |
| 安全性 | **无损**（预测错误即丢弃，回退串行） |
| 适用环境 | 游戏、电商、网页搜索 |

**增强方向**：更强的草稿模型、top-K 多分支预测、多步推测（预测未来 2-3 步）、置信度感知投机。

### 2.4 PASTE（arXiv 2603.18897, SJTU+MSR, 2026-03）⭐ 重点

**核心洞察**：Agent 工具调用序列**不是随机的**，而是遵循重复模式。查看用户 profile 的 Agent 几乎总会接着检查权限；读文件的编码 Agent 通常接下来会编辑它。

**架构**：从执行 trace 中挖掘模式，构建「模式元组库」：上下文 + 预测工具 + 参数推导函数 + 经验成功率。

| 指标 | 数值 |
|------|------|
| 任务完成时间平均降低 | **43.5-48.5%** |
| 工具执行吞吐量提升 | 1.8× |
| p95/p99 尾延迟降低 | 48.6% / 61.9% |
| 预测命中率 | 93.8% |
| top-1 精确预测率 | 27.8%（精确预测哪个工具+什么参数） |

**生产级设计亮点**：
- **中间件模式**：Agent 和工具后端之间，无需修改 Agent 逻辑
- TypeScript 8000 行（Gemini-CLI）+ Python 4000 行（Qwen-DeepResearch/Virtual-Lab）
- 资源开销极低：每秒延迟降低仅需 0.02 core-s CPU、2.6MB 内存、0.9MB 网络
- 可作为 sidecar 容器运行

**安全策略**：策略定义投机资格——完全可投机 / dry-run 合格 / 禁止投机。实测在 20000+ 次投机执行中检测并阻止了 602 次潜在副作用操作，最终输出零偏差。

### 2.5 B-PASTE（arXiv 2604.16469, 2026-04）— 边缘部署优化

**改进**：从单工具投机提升到**有界分支假设（beam）投机**。

- 维护有界的未来执行子图 beam
- 按**预期关键路径缩短量**排序（而非原始执行概率）
- 显式建模 co-run 干扰、下游解锁价值、状态安全约束
- **边缘部署**：Thor-class 边缘环境测试达 1.4× 端到端加速

**核心价值**：资源受限场景（边缘/端侧）下投机执行不能抢夺延迟关键路径的权威执行资源。B-PASTE 在低争用下才利用安全并行，高争用时优先保证快路径。

### 2.6 SimpleTool（2026-03）— Token 级压缩

**洞察**：结构化函数调用输出含大量低熵冗余——JSON 分隔符、参数名、格式 token——高度可预测。

**方法**：引入特殊 token 压缩这些序列 4-6×，同时**并行生成函数名和参数**（二者因果依赖弱——知道调用 search_database 对查询字符串帮助不大）。

| 指标 | 数值 |
|------|------|
| 端到端加速 | 3-6×（最高 9.6×） |
| 并行化开销 | 仅 8.2% |
| 4B 模型 P50 延迟 | 61.2ms（消费级 GPU + 量化） |
| 可达控制频率 | 16 Hz（具身 AI 实时级） |

## 三、组合效应

一个 6 次工具调用的任务（其中 3 次为独立对）：

```
基线串行:   6 次串行 + 6 步 LLM 推理
+ 并行工具:  4 次有效调用（独立对合并）+ 4 步 LLM  → ~1.5× 加速
+ 投机执行:  2-3 次投机命中省掉完整往返           → 再叠加 1.5-2×
+ SimpleTool: 每步函数生成 3-6× 更快            → 再叠加 3-6×
```

**聚合效果**：30 秒 → 5-8 秒。对语音/具身 Agent，意味着从不可用到生产就绪。

## 四、实践权衡

| 维度 | 风险/成本 | 缓解 |
|------|----------|------|
| **计算成本** | 投机执行以算力换延迟，错误预测浪费 CPU/API | PASTE 开销极低（sidecar），高价值交互值得，批处理不值得 |
| **正确性保证** | 并行需严格依赖分析，错误分类导致竞态/错误结果 | 保守策略+自动依赖图（LLMCompiler） |
| **可观测性** | 投机执行使调试复杂化——结果来自预计算还是标准执行？ | 需追踪投机状态的分布式 tracing |
| **框架成熟度** | 并行调用已成主流；投机执行仍处研究→早期生产；SimpleTool 需模型微调 | 按场景选择 |

## 五、未来趋势

1. **模型原生投机**：未来 API 可能支持「投机工具提示」——模型元数据暗示下一步可能动作，编排层据此预执行
2. **多 Agent 跨 Agent 预取**：一个 Agent 预测另一个 Agent 的需求，实现跨 Agent 数据预取
3. **硬件感知调度**：投机策略与 GPU/TPU 调度紧密集成，进一步优化
4. **性能前沿转移**：从模型能力转向系统工程，管线优化成为核心竞争力

## 六、对 Hermes Agent 的实践启发

| 启发 | 具体应用 |
|------|----------|
| **并行工具调用已在 Hermes 中使用** | system prompt 鼓励 batch 独立 tool call，但可进一步审计哪些调用可并行而未并行 |
| **PASTE 模式库思路可移植** | 分析 Hermes 历史工具调用 trace，挖掘重复模式（如 read_file → patch → read_file → terminal），构建轻量投机层 |
| **B-PASTE 边缘思路适用 Jetson** | Jetson Orin 资源受限，B-PASTE 的资源感知投机调度直接适用本地推理场景 |
| **SimpleTool token 级压缩** | 若未来微调本地模型，可在 function calling 输出格式上应用类似压缩 |
