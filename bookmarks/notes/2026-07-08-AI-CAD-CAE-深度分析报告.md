# AI+CAD/CAE 深度研究报告：从「一句话建模仿真」的流量泡沫到企业级落地路径

**日期**: 2026-07-08  
**来源**: 微信公众号「AIE加速工业进化」系列文章  
**关联笔记**: 数字工业软件智能化转型、AI+CAD 技术路线分析

---

## 执行摘要

AI+CAD/CAE 正处于「流量狂欢」与「技术深水区」的断裂带：营销号鼓吹 Codex/Claude「一句话建模仿真」，但实际工程级应用距离通用作产品还极远。三篇文章揭示了一个核心矛盾——**让 AI 真正理解 CAD 模型的本质难度远超公众想象**，而企业级的落地路径已悄悄转向「AI 助手」模式（如 PTC Creo 13 的三模式 AI Assistant），而非公众幻想的「自然语言生成式建模」。

---

## 一、流量生意：谁在鼓吹「一句话建模仿真」

### 1.1 现象：Codex + CAD/CAE MCP 项目引爆话题

2026 年 5 月，多个开源项目跑通了 AI 驱动的 CAD/CAE 全流程：

| 项目 | 技术路径 | 状态 |
|------|----------|------|
| Cai-aa/text-to-cae | Codex → Abaqus 全流程（建模→物理设置→求解→后处理） | 跑通演示 |
| csml-rpi/Foam-Agent | OpenFoam AI 驱动 CFD | 跑通演示 |
| AuraFriday/Fusion-360-MCP-Server | Fusion 360 MCP Server | 开源 |
| eyfel/mcp-server-solidworks | SolidWorks MCP Server | 开源 |
| ATOI-Ming/FreeCAD-MCP | FreeCAD MCP Server | 开源 |
| wjc9011/COMSOL_Multiphysics_MCP | COMSOL MCP Server | 开源 |

### 1.2 三类技术路径

目前 AI CAD 的技术路径基本分为三类：

| 路径 | 方式 | 优劣 |
|------|------|------|
| ① 直接生成 DXF | Codex 生成 Python 代码调用 ezdxf/build123d | 不直观、难修改，非主流 |
| ② 联合大模型+CAD 内核 | 构建原生 AI CAD | 难度极高，大厂尚差很远 |
| ③ MCP 连接 CAD 软件 | 自然语言→CAD 命令→执行 | **当前最合理路径** |

### 1.3 两类鼓吹者画像

1. **流量号**：用「分分钟一句话就能建模」的耸人听闻风格蹭热度，内容甚至由 AI 创作
2. **卖课者**：制造「再不学 AI+CAD 就要落后」的恐慌，收割小白。不少曾是 GPT 提示词卖课者转型而来

### 1.4 用户体验的真实反馈

实际使用 Codex CAD/CAE 项目的用户反馈：

- ❌ 消耗海量 Token
- ❌ 产出模型大体看着像回事，细节错误很多，改起来还不如从头手画
- ❌ 提示词需要很长很精细，还不如直接动手快
- ❌ 简单零件还行，复杂零件和装配体做不到
- ❌ 稍微复杂一点就很耗时且易出错

## 二、技术深水区：为什么 AI 理解 CAD 模型这么难

### 2.1 四层递进式挑战

> 把图像比作一本涂色书，那么 CAD 模型就是一本工程教材。

| 层级 | 挑战 | 具体表现 |
|------|------|----------|
| **L1: 文件格式不开放** | SLDPRT/CATPart/PRT 等闭源格式，核心数据结构黑盒 | 需技术手段拆解（如 Hoops AI 工具集） |
| **L2: 内容复杂度** | 多层嵌套特征、参数化特征树、NURBS 曲面、BREP 拓扑关系 | 数学+拓扑+语义的「多维对象」 |
| **L3: 隐含信息缺失** | 设计意图（为什么倒角 2mm？）、几何相似性、产品功能特征 | CAD 文件不包含「为什么这么画」 |
| **L4: 精度要求苛刻** | 0.1mm 的差异即为完全不同零件，图像识别的容错不适用于 CAD | 10mm 孔 vs 12mm 孔在图像中几乎一样 |

### 2.2 核心矛盾

> 「要实现生成式建模（不是一个零件，而是一个产品），可能基础是让 AI 真正理解 CAD 模型。」——但这个过程远比想象的困难。

**案例佐证**：Cursor 团队创始人 Michael Tun 最初就是搞 AI 机械 CAD 的，后来因为难度大才转向了 AI 编程。

### 2.3 数据收集困境

从实际角度，收集大规模设计模型文件本身就已经很困难——企业 CAD 数据涉及核心知识产权，极少对外公开。

## 三、企业级真实路径：从「生成式设计」到「AI 助手」

### 3.1 大厂布局对比

| 厂商 | AI CAD 进展 | 状态 |
|------|-------------|------|
| **PTC** | Creo AI Assistant（Advice/Assist/Automate 三模式） | 已发布，Assist 测试版 |
| **Autodesk** | Fusion MCP Server + Assistant（可操作建模） | 已发布，早期测试 |
| **达索系统** | 虚拟伴侣 Leo（2D→3D 参数化模型） | 演示阶段，未上市 |
| **西门子** | AI+CAD 投入中 | 未开放官方 MCP |

### 3.2 PTC Creo 13 AI Assistant：三模式深度解析

2026 年 7 月最新发布的 Creo 13 将 AI Assistant 升级为三种模式：

#### ① Advice（建议模式）— 全员可用

- 与当前设计的模型**无关**
- 基于帮助文档和最佳实践提供软件使用指导
- 一步步引导用户到正确的工具和选项

#### ② Assist（协助模式 Beta）— 扩展功能

- 结合当前设计的模型信息提供协助
- 提取模型相关洞察，协助解决问题
- **直接从模型中提取信息，只需几秒钟，无需手动编译**

#### ③ Automate（自动化模式 Alpha）— 早期测试版

- 执行复杂的几何操作和分析任务
- 减少工程师繁琐手动任务时间
- **在受控环境中运行，结果需用户审阅批准**
- 不会在用户不知情的情况下对模型进行操作

### 3.3 第三方服务商

- **Synera**（国外）：仿真 Agent 平台
- **安世亚太、雪浪云、树为智能**（国内）：基于 Agent 开发平台的定制仿真 Agent
- 模式：Workflow 流程编排为主，探索 Skills 模式
- 可实现自动化仿真工作流创建，效果接近「一句话仿真」，但背后需要大量流程约束

## 四、综合研判：泡沫与真相

### 4.1 当前认知状态分级

| 声称 | 认识论状态 | 判断 |
|------|-----------|------|
| Codex 可以一句话建模 | **Contested**（存在矛盾证据） | 简单零件可演示，复杂零件和装配体做不到 |
| AI 将取代 CAD 设计师 | **Speculative**（推测） | 无直接证据，大厂仍投入 AI 助手而非替代方案 |
| MCP 是最佳路径 | **Supported**（有证据但未完全验证） | 在用户保有 CAD 软件的前提下合理，但功能有限 |
| 生成式设计是未来方向 | **Established**（已确认） | 达索/西门子/PTC 均在投入，但通用产品尚远 |
| AI 助手是当前最务实方案 | **Supported**（有证据） | PTC/Autodesk 均已发布，处于早期阶段 |

### 4.2 核心结论

**流量泡沫**：营销号将「演示级跑通」夸大为「工业级可用」，本质是利用信息差收割流量。

**技术真相**：AI+CAD 的核心瓶颈不在「连接软件」（MCP 已解决），而在「理解模型」（几何+拓扑+语义+意图的复合理解），这是目前所有大厂尚未攻克的根本难题。

**企业路径**：当前最务实的落地是「AI 助手」模式——不是让 AI 替代设计师画模型，而是辅助设计师操作软件、理解模型、自动化重复性任务。PTC Creo 13 的三模式架构（Advice→Assist→Automate）代表了这一演进方向。

### 4.3 趋势判断

1. **短期（1-2 年）**：AI 助手模式在 CAD 软件中普及，功能集中在软件答疑+简单建模指令
2. **中期（3-5 年）**：面向特定工作流的仿真 Agent 实现定制化企业级落地
3. **长期（5+ 年）**：通用生成式设计——需要解决「AI 理解 CAD 模型」的根本难题
