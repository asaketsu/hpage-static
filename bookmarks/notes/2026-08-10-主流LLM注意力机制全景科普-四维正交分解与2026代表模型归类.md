## 一句话定义

> **主流 LLM 注意力设计不是一条简单的"MHA→MQA→GQA→MLA→稀疏/线性"升级链。** 更准确的理解方式是把相关技术分成**四个可以组合的正交维度**：KV 缓存表示、注意力连接范围、线性/状态空间替代层、位置编码与稳定化技术。

---

## 完整原文核心内容

### 四维正交分解框架

| 维度 | 解决的问题 | 代表技术 |
|------|-----------|---------|
| **① KV 缓存表示** | 解码时的显存和带宽 | MHA → MQA → GQA → MLA |
| **② 注意力连接范围** | 长 序列的计算量 | Full / Sliding Window / Sparse |
| **③ 线性/SSM 替代** | 固定状态解码 | Linear Attention / Mamba / DeltaNet |
| **④ 位置编码与稳定化** | 位置信息 + 训练稳定 | RoPE / ALiBi / QK-Norm / iRoPE |

> **这些维度彼此正交**。例如：Qwen3.5 = GQA（维度①）+ 3:1 Gated DeltaNet/Attention 混合（维度②③）+ RoPE（维度④）。不能把 GQA、DSA 和 Hybrid 当作互斥的三类范式。

### 三个成本必须区分

| 成本 | 公式 | 说明 |
|------|------|------|
| **KV Cache 显存** | `≈ B × L × T × H_KV × (d_k+d_v) × s` | 自回归解码缓存每层的 K 和 V。MQA/GQA 减少 H_KV；MLA 缓存低维潜在表示 |
| **Prefill 计算** | `O(T²)` | 构造查询与所有键的关系。FlashAttention 减少中间显存但不改变二次阶数 |
| **单步解码计算** | `O(T)` | 生成新 Token 只需访问已有 T 个位置。但完整生成过程累计仍可能二次增长 |

> **GQA/MLA 主要缓解缓存与带宽；稀疏/局部/线性机制主要减少长序列计算。它们解决的不是同一个问题。**

### 维度①：KV 缓存表示

| 机制 | KV 组织方式 | KV Cache 特征 | 主要权衡 | 采用模型 |
|------|-----------|-------------|---------|---------|
| **MHA** | 每个查询头有独立 K/V | 最大 | 结构成熟，但缓存和带宽压力高 | 原始 Transformer |
| **MQA** | 所有查询头共享一组 K/V（H_KV=1） | 同维度比较下最小 | 效率高，共享过强时可能影响质量 | — |
| **GQA** | 每组查询头共享一组 K/V（1<H_KV<H_Q） | MHA 与 MQA 之间可调 | 工程折中良好 | **Llama 3, Qwen2.5, Mistral 7B, MiniMax M2** |
| **MLA** | 缓存低维联合潜在表示 + RoPE 解耦分量 | 取决于潜在维度和实现 | 压缩率高(~93%)，结构和内核更复杂 | **DeepSeek-V2/V3/R1** |

> MLA 不是"先缓存压缩向量再恢复完整 K/V"——K 的升维矩阵可吸收到查询投影中，V 的升维矩阵可吸收到输出投影中，无需真的构造完整高维 K/V。

### 维度②：注意力连接范围

| 机制 | 复杂度 | 说明 |
|------|--------|------|
| **Full Attention** | O(T²) prefill | 最直接的全局信息通路，基础设施最成熟 |
| **Sliding Window (SWA)** | O(Tw) | 每个位置只访问最近 w 个 Token。Mistral 7B / Gemma 3（5 局部+1 全局，窗口 1024） |
| **NSA (Native Sparse)** | — | DeepSeek 提出，三并行分支：压缩+选择+局部窗口，门控组合 |
| **DSA (DeepSeek Sparse)** | 主注意力 O(Tk)，索引器仍 O(T²) | DeepSeek-V3.2，MLA 上加入学习式稀疏选择 |
| **MoBA (Mixture of Block Attention)** | — | 把上下文划分成 Block，MoE 路由选择相关 Block |

### 维度③：线性注意力与混合架构

| 方案 | 说明 | 采用模型 |
|------|------|---------|
| **Gated DeltaNet** | delta rule 更新快速权重 + 数据相关遗忘门 | **Qwen3.5-27B**（3:1 Gated DeltaNet + Gated Attention，262K 上下文） |
| **KDA (Kimi Delta Attention)** | Gated DeltaNet 的通道级遗忘门 | **Kimi Linear**（3:1 KDA + MLA，KV Cache 降 75%，100 万 Token 解码吞吐 6x） |
| **Lightning Attention** | 线性注意力变体 | MiniMax-Text-01（**后续 M2 系列弃用，改回全注意力**） |
| **Mamba/SSM + Transformer 混合** | 大部分层用 SSM，少量全注意力层 | NVIDIA Nemotron-H |

> ⚠️ **重要提醒**：MiniMax M2/M2.5/M2.7 **不再使用** Lightning Attention，改为全层 Full Attention + GQA（48 Q 头/8 KV 头/192K 上下文）。技术报告明确说明：混合高效注意力在大规模推理/编码/Agent 任务上**尚未稳定达到全注意力的质量**。

### 维度④：位置编码与稳定化

| 技术 | 说明 |
|------|------|
| **RoPE** | 旋转 Q/K 的二维子空间编码相对位置。大量 LLM 使用，但未经调整不能可靠外推（需 PI/NTK/YaRN） |
| **ALiBi** | 注意力分数上加线性距离偏置。"没有额外位置嵌入"≠"没有位置编码" |
| **QK-Norm** | 归一化 Q/K 控制 Logit 尺度，减轻 Softmax 饱和。多种模型采用但非强制标准 |
| **iRoPE** | Llama 4：RoPE 层与 NoPE 层交替 + 推理时注意力温度缩放 |

### 2026 代表模型准确归类表

| 模型/系列 | KV 表示 | 连接或混合方式 | 备注 |
|---------|---------|-------------|------|
| 原始 Transformer | MHA | Full Attention | 标准基线 |
| **Llama 3** | GQA | Full Attention | GQA 降低 KV Cache |
| **Mistral 7B** | GQA | Sliding Window | 限制局部访问范围 |
| **Gemma 3** | GQA | 5 局部 + 1 全局 | 窗口 1024 Token |
| **DeepSeek-V2/V3/R1** | MLA | Full Attention | 低秩 KV 潜在表示 |
| **DeepSeek-V3.2** | MLA | DSA 稀疏选择 | 主注意力稀疏，索引器仍全序列评分 |
| **Qwen3.5-27B** | GQA（全注意力层） | 3 Gated DeltaNet + 1 Gated Attention | 线性—全注意力混合，**不是 KDA** |
| **Kimi Linear** | MLA（全局层） | 3 KDA + 1 MLA | 线性—全注意力混合 |
| **MiniMax-Text-01** | 依层而定 | Lightning + Softmax | 早期混合架构 |
| **MiniMax M2/M2.5/M2.7** | GQA | **全层 Full Attention** | 不使用 Lightning Attention 或 KDA |
| **Nemotron-H** | 依配置而定 | Mamba/SSM + Transformer | 仅代表 Nemotron-H 子系列 |

### 机制选择决策表

| 目标 | 更相关的机制 | 主要风险/代价 |
|------|-----------|-------------|
| **降低解码 KV 显存** | MQA, GQA, MLA, KV 量化 | 共享/压缩过强可能影响质量 |
| **降低长上下文 prefill 计算** | SWA, 块稀疏, Token 稀疏, 线性注意力 | 全局覆盖或精确检索可能受限 |
| **保留任意位置直接寻址** | Full Attention, 少量全局层 | 二次 prefill 成本 + 线性增长 KV Cache |
| **固定解码状态大小** | 纯线性注意力或 SSM | 有限状态容量；精确回看更困难 |
| **提高训练稳定性** | QK-Norm, 合适初始化 | 不是独立的效率方案 |
| **扩展 RoPE 上下文** | 位置插值, YaRN | 标称窗口≠有效检索长度，必须实测 |

### 2026 趋势判断（作者原文）

1. **组合式设计正在增加，但全注意力并未退出**——Qwen3.5/Kimi Linear/DeepSeek-V3.2 展示了不同混合路线；MiniMax M2 系列仍偏好全注意力
2. **KV 压缩与计算稀疏化继续共同演进**——GQA/MLA 解决缓存带宽，DSA/NSA/MoBA 减少主注意力访问范围，两者可叠加
3. **实际速度越来越依赖软硬件协同**——理论复杂度只是上限；Kernel/量化/prefix caching/speculative decoding/设备带宽决定真实吞吐
4. **长上下文长度不能只看模型卡数字**——原生窗口/外推窗口/有效检索长度/Agent 实际稳定性是不同概念
5. **MoE 与注意力机制是不同维度**——MoE 稀疏的是 FFN 专家计算；稀疏注意力减少的是 Token 连接

## 结合最新研究与技术变化

### 1. 与 LLMs-from-scratch 笔记的关联

LLMs-from-scratch 的 Ch3（Attention 机制）和 Ch4 Bonus（GQA/MLA/SWA/MoE）是本文的理论基础。本文是对 Bonus 内容的**2026 最新全景更新**——加入了 KDA、DSA、MoBA、Gated DeltaNet 等最新架构。

### 2. 与 MoE/MMoE 模型全解笔记的关联

snowboat84 的 MoE 综述讲的是 FFN 专家稀疏（MoE），本文讲的是 Token 连接稀疏（Sparse Attention）。两者是**不同维度的稀疏化**——本文最后一条趋势判断明确指出这一点。

### 3. 与 LLM 推理优化 Skill 的关联

PagedAttention/量化/推测解码等推理优化技术的选择，取决于模型用的注意力机制——GQA/MLA 影响 KV Cache 大小，稀疏/线性注意力影响 prefill 和解码计算量。

### 4. 与 LFM2.5-2.6B 的关联

LFM2.5 使用 Liquid AI 自有的 LFM 架构（非标准 Transformer），属于本文未覆盖的独立路线——混合了注意力与 SSM 的变体。

## 趋势判断

1. **混合架构是主流方向**——纯 MHA 或纯线性注意力都有局限，3:1 混合成为常见比例
2. **GQA 是 2026 的事实标准**——Llama 3/Qwen/Mistral/MiniMax M2 都用 GQA
3. **MLA 是 DeepSeek 的独有路线**——压缩率最高但内核最复杂
4. **高效注意力的理论优势不保证实践优势**——MiniMax M2 的回归是重要警示
5. **长上下文有效长度≠标称长度**——必须实测检索能力
