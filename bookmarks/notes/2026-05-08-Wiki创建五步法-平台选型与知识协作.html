摘要

文章介绍了 Wiki 的两层含义（协作系统 + 软件），并以五步法拆解 Wiki 创建流程：选平台、定部署、规划结构、创建内容与权限、推广维护。核心逻辑是"工具选型 → 架构设计 → 内容治理 → 持续运营"，适合团队从零搭建知识库时参考。

核心内容

1. Wiki 双重含义

  • 系统层：多人协作的写作/知识共享系统
  • 软件层：创建 Wiki 网站的工具（MediaWiki、DokuWiki、Confluence 等）
  • 代表案例：维基百科（Wikipedia）— 只是众多 Wiki 实现之一

2. 五步建站法

步骤 核心决策 关键选项
① 选平台 开源 vs 商业 MediaWiki（灵活）/ DokuWiki（轻量）/ Confluence（企业级）
② 定部署 云托管 vs 独立部署 云：快速、免维护；独立：控制性强、需技术基础
③ 规划结构 分类 + 模板 + 首页 按部门/项目/产品线组织；统一页面模板
④ 内容与权限 编辑 + 权限控制 + 版本追溯 查看权限分级、编辑审核、版本历史
⑤ 推广维护 协作文化 + 定期更新 指定维护人、收集反馈优化体验

3. 结构设计要点

  • 导航：分类 → 子分类，层级清晰
  • 模板：会议记录、产品文档等标准化模板
  • 首页：公告 + 最新更新 + 常用链接

4. 权限与治理

  • 分级权限：查看 / 编辑 / 审核
  • 版本控制：追溯每次修改历史
  • 内容质量依赖于权限设计

🔍 借鉴点

  • 模板标准化 → Hermes 的 note-dual-format skill 就是"统一模板"思想的具体落地，所有笔记遵循同一结构（📅⭐🏷️📰🔗 头部 + 固定板块）
  • 权限分级思路 → Agent 交换池的 registry.json 权限设计（644）是同一逻辑的最小化实现
  • 首页聚合 → index.md 就是笔记的"Wiki 首页"，汇总所有条目便于导航

💡 启发

  • Wiki 的核心价值不在工具本身，在协作文化 + 持续维护。技术选型是次要的，"谁负责更新"才是决定 Wiki 生死的问题。很多企业 Wiki 死亡不是因为工具差，是因为没人维护
  • 从 Wiki 到 AI Agent 知识库的演进路径：Wiki（人写人看）→ RAG（人写 AI 查）→ Agent 自主写入+查询。我们在 Hermes 上的 memory + skill + exchange-protocol 就是这条路的中间态

🔮 预判

  • Wiki 不会消亡但会进化 — 纯手动维护的 Wiki 会逐渐被 AI 辅助的"半自动知识库"取代（如自动摘要、自动分类、自动关联），但结构化编辑和权限控制的需求会保留
  • Agent-native 知识管理 → 未来知识库的第一用户不是人而是 Agent，Wiki 的编辑器会被 Agent API 替代（Hermes 的 skill 系统已经是这个方向）
