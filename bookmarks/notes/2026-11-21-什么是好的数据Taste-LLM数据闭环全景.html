内容整理：数据闭环五阶段全景

序：为什么"数据 Taste"没有标准答案

证据 关键内容
ACM 从业者调研（采访 219 位 LLM 从业者） 高质量数据 top3 特征：可靠性（来源可靠）> 相关性（对齐目标）> 准确性（无明细错误）；验证方式 top3：人工抽样、定量指标、数据可视化；三大难题：无统一数据处理流程、清洗到什么程度可 work 不可知、清洗后无法做指标量化
Chinchilla（DeepMind，arxiv 2203.15556） 固定算力下参数量 N 与 token 数 D 应近似按 C^0.5 同步增长；70B 参数 + 1.4T token 在近似算力下击败 280B + 300B 的 Gopher，且推理更便宜

作者的推论：数据规模扩大提升模型上限，且随架构演进"单位模型/算力能吃的数据越来越多"——基模公司的行动指令是"不要低估模型上限，赶紧找数据"。质量无标准答案 → 各家都在用自己的数据 Taste 解决问题，Taste 即竞争力。

阶段一：找到好的数据（4 来源）

来源 要点 关键证据
爬虫 良莠不齐，需大量清洗；经典管线 = 分类过滤 + 困惑度分层 CCNet（arxiv 1911.00359）：FastText 分类置信度过滤 + Wikipedia KenLM 困惑度分层；FineWeb（arxiv 2406.17557）反直觉发现：原始数据经严格 filter+dedup 后实验效果反而下降
开源数据集 HF 是 seed 首选（Kimi 等基模厂也这么干）；质量高于爬虫但有瑕疵（大量 dataset 是集合+合成，带 LLM rewrite 错误） 实操建议：①做 HuggingFace 监控日报盯自己领域新数据集；②先看来源是否知名公司/实验室（≈质量预打分）；③再分析覆盖度/有效性/格式/处理代码是否开源

阶段二：选择好的数据（Data Selection 之争）

争议背景：有 post 认为"Data Selection 方向消失了"——scale up 后过多 filter 导致样本分布偏离反而伤模型。作者反驳：对 startup 低成本初始化基模，选到关键数据是最重要的问题，没有之一；高质量数据挖尽后，跨领域数据和低质量数据的利用是必做题。

论文 机制 作者评注
DEITA（美团 24，arxiv 2312.15685） Complexity × Quality × Diversity 构造"进化序列"生成高质量对齐数据 7B/13B 实验结论，当前模型规模下未必成立
RDS+（25，arxiv 2503.01807） topK 等经典方法在百万/千万量级失效（数据有偏或过拟合 judge model 偏好）；改用 hidden states 表示数据特征打分 hidden states 每层表现不一，预计方法没那么稳定
ATLAS（Google，多语言 scaling law） ①跨语言迁移有方向性：西语→加泰罗尼亚语显著有帮助，反向不一定，要算源 token 对目标的边际贡献；②多语言有成本（互挤信息空间）但正迁移可抵消：语言数 K→2K，参数仅需 1.18x、数据 1.66x、计算 1.96x、原有数据保留 83% 即可维持 loss；③小众语言超 1 epoch 后重复数据有效收益速降 （作者作为 Data Selection 重要性的正面证据引用）

阶段三：合适的时机用合适的数据

三阶段分工：pretraining 用广泛多样数据建语言/知识/基础能力 → SFT 用高质量指令-回答示范教指令遵循/格式/典型任务 → RL 用反馈信号（模型/人类打标）提升对齐、激发 pretraining 潜力。

DeepSeek-R1 的教训（arxiv 2501.12948）：R1-Zero 纯 RL 出现可读性差 + 语言混杂 → 解法 = 精筛 + 模型判断 + 人为判断构造高质量 SFT 数据，再以 accuracy + format + length + language 多维 reward 强化 CoT 轨迹质量。

Nemotron（NVIDIA）工业细节（github NVIDIA-NeMo/Nemotron）——本篇信息密度最高段：
- 数据配比：Pre-Training 23.5T（web/代码/学术/多语言）→ SFT 1.5T（高质量/合成/STEM/教材）
- 长上下文：CPT 最长 512k 训练序列；SFT 平均 128k、上限 256k。配套可控合成任务五式：答案信息放很远位置 / 多文档分散证据 / 加无关干扰文档 / 要求跨文档多跳组合 / 保留可自动验证的标准答案
- Agent 能力放 SFT：pretraining 本质训 p(next token|previous tokens)，SFT 把 Agent/多轮/CoT 加上去，本质是训 P(action|state)
- Reasoning control 埋进训练数据（最反直觉细节）：~10% 样本去掉 reasoning（训练 on/off 开关能力）；~3% 推理轨迹截断到不同 token budget，推理达预算即插 </think> 要求模型基于不完整思考收束最终答案。结论：reasoning budget 不是纯推理端功能——模型必须提前见过四种形态：不思考直接答 / 短思考 / 长思考 / 思考中途被终止仍收束

反共识：脏数据也有价值（A Bitter Lesson for Data Filtering，arxiv 2605.19407）：①同规模模型下，精细过滤（语言/感叹词/去重）的数据学习充分度远不如全量数据；②注入打乱顺序的低质量数据，模型依旧能学到词语关联。作者保留意见：该论文建立在"高质量数据有限"前提上，而现实是所有人都在拼命创造高质量数据（含低质合成）。

阶段四：如何判断数据质量（小模型当裁判）

论文 机制 作者评注
DataDecide（25，arxiv 2504.11393） 用小模型低成本预测哪份 training data 更好：150M 模型排名预测 1B 排名，约 80% 数据对决策正确；小模型不看 Accuracy 而看 logits 里答案的 prob——MBPP/HumanEval 上小模型做不对但答案 likelihood 已含信号，预测准确率升至 ~80% 有道理：不可能每换一份数据就全量 pretraining 一遍，可靠 baseline 很重要
DataMan（阿里 25，arxiv 2502.19363） GPT-4 标注 3.57w 篇 doc 按 13 维度打分 → 微调 Qwen2-1.5B 得到 DataMan 打分模型 → LLaMA 实验证明只用 score=4/5 数据训练显著优于随机采样 微调一个私域评测模型是合理做法，Kimi 在 Data Pipeline 里也大量使用
DataRater（OpenReview） 50M 参数 transformer 做 meta-learned 打分器：以原模型 loss 为 label 训练，新数据过模型打分丢低分——本质选"给模型更大梯度"的数据 理想但问题大：大模型特性未必能转化为小模型 loss 表征；梯度大未必是好事

阶段五：合成数据（Agent 长程任务的主路)

Agent 场景互联网无公开数据集，长程任务基本靠合成：

案例 合成策略
Kimi K3（arxiv 2607.24653） 知识图谱法：从全互联网信息构建 Agent Task Graph，无限挖掘（带去重 + 概念合并）可能的 Task 与轨迹
Qwen-AgentWorld（arxiv 2606.24597） 种子数据 → 大量 Agent 轨迹合成
WeAgent-MMSearch（微信，arxiv 2608.28062） 逆向生成：先从互联网找到一个"必须由图片才能回答的问题"，再不断向前 Multi-Hop 合成并保证实际可执行性，产出长程轨迹，最后 reject sampling 取高质量子集

阶段六：如何评测数据（闭环的最后一环）

Google Research 调研（arxiv 2402.16611）：模型团队内不同角色关注点完全不同（训练团队看评测效果、产品看真实用户分布），但观察方式惊人一致且原始：
- eyeballing：肉眼观察 + 直觉结论——往往无代表性，且常因果颠倒（带着结论找证据）
- notebook：数据分析（分布等）——高度定制化，难形成共识、难标准化

作者结论：这是当前研发最痛的点，正解类比互联网产品的 A/B 实验体系——需要一个全面可靠的 A/B 实验平台作为模型迭代参考。

归纳总结

  • 核心命题：数据质量没有客观标准答案（219 人调研实证），"数据 Taste"= 围绕采集→筛选→使用→质量→评测五阶段闭环的经验决策力，是数据团队的核心竞争力。
  • 五阶段一句话：找数据（爬虫要粗滤勿精滤、HF 做 seed、合成四路）→ 选数据（startup 视角 Data Selection 是第一问题；topK 会失效、hidden states 更稳）→ 用数据（三阶段各司其职，能力要埋进对应阶段的数据形态）→ 判质量（小模型当私域裁判：看 logits 不看 Accuracy）→ 评测数据（eyeballing 原始性 = 全行业痛点，等 A/B 平台）。
  • 三条反直觉：①FineWeb：过度过滤反而降效果；②Bitter Lesson：脏数据也教词语关联，全量学习更充分；③Nemotron：reasoning on/off、思考截断收束这些"推理端功能"必须提前做进训练数据。
  • 作者立场坐标（引用其评注时注意）：startup 视角（低成本初始化基模优先）、对学术结论一律保留（规模外推/稳定性/前提条件三连问）、工业实践权重高于 paper 结论（Kimi/Nemotron 的用法当正面证据）。

趋势判断

  • "数据即模型"进入操作层竞争：共识期（数据重要）已过，各家比拼的是 Taste——本文 bookmarks 309 > likes 234 的收藏型信号说明从业者正在把这类框架当工具书囤。
  • Data Selection 方向没有消失，而是换了形态：从"外置 filter/topK"转向"hidden states/优化器感知/meta-learned"的内生表征打分（RDS+/OPUS/DataRater 同脉络），与"Data Selection 消失论"的分歧本身是 2026 年数据工程的路线之争。
  • 合成数据从补充变主路：Agent 长程任务（K3 知识图谱、WeAgent 逆向生成）已经 100% 合成；合成方法学的差异化（图谱挖掘 vs 逆向生成 vs 模态转换）正在成为基模厂的新护城河。
  • 控制能力前置进数据：Nemotron 的 reasoning control（10% 无推理 + 3% 截断轨迹）预示趋势——未来模型的"可控性旋钮"（思考预算/风格开关）越来越靠数据配方实现，而非推理端 prompt。
  • 评测是最后的洼地：五阶段里前四段都有论文弹药，唯独评测停留在 eyeballing + notebook——数据 A/B 实验平台是明显的空白机会（创业/开源皆可切入）。
