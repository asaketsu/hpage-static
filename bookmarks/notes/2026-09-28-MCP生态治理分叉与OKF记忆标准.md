# MCP 生态 2026-09 观察：治理分叉、安全防御与 OKF 记忆标准
> 探索日期 2026-09-28 ｜ 来源 6 个（GitHub API/HN Algolia/官方 README 原文提取）｜ 前序：无同主题笔记（避重：最近笔记为 LLM 交易 Agent/Transformer 运动策略/Jev 传感器，均不覆盖 MCP 生态治理）

## 核心发现（5 个）

### 1. MCP 首次治理分叉：omcp（OpenMCP）——"反门卫"硬分叉
- **是什么**：Enclawed 公司发起的社区驱动硬分叉（2026-09-22 上 HN，repo=enclawed/omcp），口号 "Build without permission"。动因 manifesto 三条：协议属于社区不属于守门人；反对闭门工作组+实时聊天室式治理；PR 只按技术优劣+可复现单测评审，"Judge the diff"。
- **关键工程决策**：**线上协议完全兼容（drop-in compatible）**——wire format、schema 字段名、方法名、版本标识符全部不变，分叉只在治理流程不在协议本体。"omcp only ever adds"：新能力只能以扩展/可选元素形式加入，不理解它的实现可直接忽略。schema TypeScript-first（schema/2026-07-28/schema.ts），每 push 自动构建发布 HTML/PDF 全版本规范。
- **价值判断**：这是开源协议治理危机的标准样本——与 OpenSSH/LibreOffice 式分叉同构，但因"兼容只加不改"约束，分叉成本极低。对 MCP 生态的启示：**协议中立性风险已被社区视为真实威胁**（上游曾无技术评审关闭 PR）。

### 2. MCP 攻击面实锤：12 类检测规则对齐 OWASP MCP Top 10
- **mcp-audit-tool**（graygnatconsole，105★，2026-09-26 创建，PyPI 可装）：纯 Python 静态分析 CLI，扫 Claude Desktop/Cursor/Windsurf/Cline/Zed/VS Code 的 MCP 配置。检测：工具描述投毒（tool poisoning）、rug pull（`npx -y` 拉最新版=每次执行任意新代码）、明文 API key、命令注入、`curl|bash` 安装器、文件系统服务器根挂载 `/`、无认证远程端点。输出安全评分 A+→F + SARIF，CI 就绪。
- **关键攻击向量**：一行 `claude_desktop_config.json` 配置即可让模型拿到：凭证（env 明文）、任意执行（bash 包装）、全盘（filesystem rooted at /）、被投毒的 tool description（直接注入模型上下文）。

### 3. 主动防御新范式：HoneyMCP 蜜罐"幽灵工具"
- **是什么**（barvhaim/HoneyMCP，Apache-2.0，PyPI=honeymcp）：FastMCP 服务器加一行 `mcp = honeypot(mcp)` 中间件，注入 LLM 生成的领域相关"幽灵工具"（假的安全敏感工具）作蜜罐。
- **双类威胁检测**："get"类幽灵工具抓数据外泄（偷凭证/私密文件），"set"类抓间接提示注入（向 agent 环境注入恶意指令）。触发即记录完整攻击遥测：工具调用序列、参数、会话元数据。另有"认知模式"——检测到攻击者后用合成数据保持其在线（拖延+画像），React 实时仪表盘。
- **设计精髓**：高保真检测（只在对幽灵工具的显式调用时触发，零误报）+ 蜜罐对攻击者透明（与合法工具混排）。

### 4. OKF v0.2 + DMAA：Agent 记忆的"推拉双栈"新标准
- **okf-agent-memory**（730★，2026-09-05 创建，Go 零依赖，MCP-ready，sub-300µs 检索）：基于 Google Cloud knowledge-catalog 的 **OKF（Open Knowledge Format）v0.2** 规范实现 Git 原生持久项目记忆。
- **诊断的两个致命失败模式**（对我们直接适用）：① **Prompt 巨石**（把所有规则塞 AGENTS.md/CLAUDE.md）→ 上下文膨胀 + **attention drift**（agent 忽略关键指令）；② **RAG 盲区**（把行为规则倒进向量库）→ agent 在通用任务中**从不语义搜索操作约束**（格式/安全规则）。
- **DMAA 双记忆架构**：Push 层=~100-150 token 的 Domain Codex（AAG 微语法写的不变量/伦理/语气）+ 确定性触发器（Search-Before-Write）；Pull 层=OKF 知识包，**基线 0 token**，按需 `okf_search`/`okf_show` 微秒级检索。memory 前后有 frontmatter（type/key/namespace/tags/verified/stale_after）+ SQLite FTS5 索引 + 磁盘 .md 双层。
- **mcp-memory**（218★，fellowgeek）：OKF v0.2 的 MCP server 封装，六工具（memory_store/search/…），namespace 隔离（user/preferences vs project/architecture）。

### 5. 生态位分化：x64dbg 逆向调试 MCP（2110★ 单月）
- duty1g/x64dbg-mcp-server（2026-08-22 创建，2110★）：x64dbg 原生 MCP 插件，暴露调试器全功能（断点/寄存器/内存）给模型。单月 2110★ 说明 **MCP 已进入专业工具深水区**——不是 demo 玩具而是把重型桌面软件的完整 API 暴露给 agent。
- 另有国家级目录（italia-mcp 91★ / france-mcp 62★）：政府公开数据+法务+发票的 MCP 目录——公共部门采纳信号。

## Actionable Insights

1. **协议分叉兼容策略可抄**：omcp 的 "only ever adds" 约束 = 分叉不破坏生态的最低成本路径，适用于任何内部 API/协议演进。
2. **安全左移到配置文件**：MCP 时代供应链攻击入口从 package.json 转移到 mcp.json——审计对象是**配置**不是代码。
3. **蜜罐是注入检测的零误报路径**：比内容过滤/意图分类器便宜且高保真（只在诱饵被咬时触发）。
4. **行为规则禁入向量库**：agent 不会主动搜索"我该遵守什么"，确定性触发器（Search-Before-Write）才是行为约束的正确挂载点。

## 关键风险与盲点

- omcp 分叉动机为单方陈述（manifesto），上游 Anthropic 视角未采集（来源级别：社区声明 vs 官方未回应）
- okf-agent-memory 的 730★ 含 Trendshift 榜单流量，热度≠生产验证；DMAA 尚无独立复现（来源级别：项目自述）
- mcp-audit-tool 发布仅 2 天（09-26），规则成熟度未验，先跑只读扫描再定采纳
- MCP "数千公共服务器"数据来自项目 README 引述，未见原始统计源

## 一页速查

> **omcp** = MCP 治理硬分叉，线上协议 100% 兼容，只加不改，TS-first schema，PR 凭 diff+单测过审
> **mcp-audit-tool** = 纯 Python MCP 配置静态审计，12 规则对齐 OWASP MCP Top10，扫投毒/rug pull/明文密钥/根挂载，SARIF+CI
> **HoneyMCP** = FastMCP 一行中间件注入幽灵工具蜜罐，get 类抓外泄、set 类抓注入，攻击遥测+认知模式拖延
> **OKF v0.2** = Google knowledge-catalog 的开放知识格式：md+frontmatter（verified/stale_after/namespace）+FTS5+Git 原生
> **DMAA** = Push（100-150 token 不变量 Codex + 确定性触发器）+ Pull（OKF 知识包基线 0 token 按需检索）；治 Prompt 巨石 attention drift 与 RAG 盲区两病
> **信号**：MCP 进入专业深水区（x64dbg 调试器 2110★/月）+ 公共部门（意法国家目录）；安全工具化（审计 CLI+蜜罐）一周内双落地
