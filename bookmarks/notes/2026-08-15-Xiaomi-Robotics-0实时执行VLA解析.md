## 一、内容整理：问题与方法全貌

VLA 参数量可达数十亿 → 推理延迟高 → 连续推理步之间**动作拼接不连续** → 产生分布外的抖动运动（OOD jerky motions），一步抖、步步错。这是实机部署的第一杀手，比成功率更先卡死落地。

Xiaomi-Robotics-0 的解法是**训练配方 + 部署策略双管齐下**：

| 层面 | 手段 |
|---|---|
| 模型 | 预训练 VLM（处理视觉+语言）+ DiT（flow-matching 生成动作 chunk），共 **4.7B 参数** |
| 预训练 | 大规模跨本体机器人轨迹 + 视觉-语言数据联合训练（防灾难性遗忘） |
| 后训练 | 异步执行专项技术（见下） |
| 部署 | 连续推理的动作 chunk 时间步对齐 |

## 二、方法细节

### 2.1 数据规模（照录）

| 数据类型 | 规模 |
|---|---|
| 机器人轨迹 | 开源（DROID、MolmoAct）+ 自采；自采两任务：Lego 拆卸 338 小时、折毛巾 400 小时；总计约 **200M timesteps** |
| 视觉-语言 | **80M+ 样本**，两类来源：通用 VL 数据集（保语义广度）+ 机器人数据衍生的 VL 数据（增强机器人视角图像感知） |

### 2.2 两阶段训练

**预训练（两步）**：
1. 第一步给 VLM 装上动作生成能力：训练其从观测图像+指令+本体状态预测动作 chunk。为处理轨迹多模态，采用 **Choice Policies**——同时预测 N 个动作 chunk 候选及各自得分
2. 第二步（衔接 DiT 生成路径，具体分工见报告 2.2 节）

**后训练（异步执行专项）——本文最核心的技术贡献**：
- 基础手法：**动作前缀条件化**（action prefixing）——上一次推理的动作作为下一次生成的前缀，保证 chunk 间连续性
- 但前缀有陷阱：后续时间步动作会利用"相邻动作相似"的时序相关性走**捷径**——直接抄前缀而不是看视觉/语言信号 → 策略退化、反应性下降
- 解法：后训练时把因果注意力掩码换成 **Λ（Lambda）形注意力掩码**，强制动作生成更多关注视觉/语言条件、抑制对动作前缀的过度依赖

### 2.3 部署：同步 vs 异步（照录全文逻辑）

**同步执行**：执行 chunk 前 T_e 步 → 停下 → 用最新观测推理下一个 chunk → 机器人空转等推理完成。简单但空转。

**异步执行**（核心）：
```
1. 推理得到 T 步 chunk，先执行前 T_e 步，然后触发下一次推理
2. 推理期间机器人不停——继续执行当前 chunk 剩余动作
3. 下一次推理以 [T_e, T_e+Δt_c-1] 区间的动作为前缀条件（噪声初始化）
4. 新 chunk 生成完毕后，从 Δt_inf 步开始执行（Δt_inf = 推理延迟）
5. 约束 Δt_c ≥ Δt_inf：前缀覆盖整个推理窗口
   → 推理全程始终有动作可执行，推理周期无缝衔接
```

**推理参数**：action chunk 从标准高斯采样初始化，**5 步 flow-matching** 积分 τ∈[0,1] 得到预测。**RTX 4090 上推理延迟 80ms**。
**传感器同步**：所有输入模态按时间戳重采样到统一 **30Hz** 时间线，每个时钟节拍聚合各传感器时间上最近的测量。

## 三、实验结果

### 3.1 仿真（三大 benchmark 全 SOTA）

| Benchmark | 成绩 |
|---|---|
| LIBERO（四 split 平均） | **98.7%**（对比 OpenVLA 76.5%、OpenVLA-OFT 更强） |
| SimplerEnv Google Robot | Visual Matching **85.5%** / Variant Aggregation 74.7% |
| SimplerEnv WidowX | **79.2%** |
| CALVIN ABC→D / ABCD→D | 5 连任务平均完成数 4.54→**4.75** / 4.67→**4.80** |

### 3.2 实机（双臂精细操作两任务）

**Lego 拆卸**（LA-5/10/20 单结构 + MA 34 块混合；指标=正确分拣率+吞吐）：
- 所有方法成功率接近；两个同步方法（π0.5、Xiaomi Sync）略优——异步方法反应性稍弱，抓取精度不足时砖块与夹指间高张力会弹飞
- **吞吐：Xiaomi-Robotics-0 全场最高**，超过同为异步部署的 Training RTC 变体

**折毛巾**（6 条毛巾 × 2 次 30 分钟连续 rollout；单次超 2 分钟记失败）：
- π0.5 / Sync / Training RTC 吞吐相当（1 pcs/min）
- **Xiaomi-Robotics-0：1.2 pcs/min 最高**

**失败模式分析（有价值）**：Training RTC 变体常卡死——甩毛巾时误抓多层，不去重新抓取纠正，而是陷入重复甩动的死循环。这印证**动作前缀机制在策略学习中引入捷径**：后续动作预测直接抄前缀而不看其他模态。Λ 形掩码版有效避免此类重复失败。

### 3.3 VLM 能力保持

预训练阶段 VL 数据 + 轨迹联合训练 → 在通用 VL benchmark 套件（通用 QA 到幻觉检测）上**追平底座 VLM**，含具身推理 benchmark ERQA。机器人训练不再以牺牲语义能力为代价。

## 五、工程借鉴（Jetson/端侧部署直接相关）

1. **80ms@RTX4090 的构成**：5 步 flow-matching（而非几十步扩散）是延迟主功臣——**推理步数砍到个位数**是 VLA 实时的第一杠杆
2. **异步执行协议**：Δt_c ≥ Δt_inf 约束 + 前缀覆盖推理窗口——推理慢不致命，**衔接断裂才致命**。这套时间对齐协议可直接移植到任何 chunk 式策略
3. **30Hz 时间戳重采样**：多传感器异步到达时按统一时间线聚合最近测量——比硬件级同步便宜得多，工程实用
4. **Λ 形注意力掩码**：任何用自回归前缀保证连续性的场景（语音流、机器人、流式生成）都可能踩"前缀捷径"坑——训练时约束注意力看向条件信号是通用修复
5. **联合训练保 VLM**：机器人微调时混入 VL 数据可防灾难性遗忘——对 Hermes 的多任务模型微调同样适用（技能执行能力与语义理解共存）

## 六、趋势判断

1. **VLA 竞赛的重心正从"benchmark 分数"转向"实机工程化"**：LIBERO 98.7% 已接近饱和（OpenVLA-OFT 97%+），下一个差异化战场是延迟、平滑性、吞吐——Xiaomi 这份报告本身就是一个信号：大厂愿意为 80ms 和 1.2 pcs/min 发一篇正式报告
2. **异步执行协议将成为 chunk 式策略的标配**：Δt_c ≥ Δt_inf 约束 + 前缀覆盖推理窗口的逻辑与具体模型无关，可平移到任何 flow-matching/diffusion 策略——预计一年内成为开源 VLA 框架的默认部署模式
3. **"前缀捷径"问题的曝光会带动注意力掩码设计的小高潮**：Λ 形掩码证明训练时约束注意力分配能修复策略退化——这类"训练-部署一致性"问题会在更多自回归+前缀场景（流式语音、视频生成）复现
4. **消费级 GPU 实时 + 开源 checkpoint 的组合在压缩商用 VLA 方案的空间**：4090 可跑意味着中小团队全套自建成为可能，VLA 落地门槛从"有一个机器人实验室"降到"有一张 4090"

## 七、归纳总结

Xiaomi-Robotics-0 是目前**消费级 GPU 实时 VLA 最完整的公开参考实现**：4.7B（Qwen3-VL 底座 + DiT flow-matching），预训练混入 80M VL 样本保语义能力，后训练用 Λ 形注意力掩码填平"动作前缀捷径"的坑，部署用异步执行协议（推理期间继续执行、前缀覆盖推理窗口、5 步 flow-matching）做到 RTX 4090 上 80ms 延迟。交付成绩：三大仿真 benchmark 全 SOTA（LIBERO 98.7%）、实机双臂任务吞吐全场最高（折毛巾 1.2 pcs/min）、VLM benchmark 追平底座。核心洞察一句话：**VLA 实时性的敌人不是推理慢，而是 chunk 衔接断裂**——训练侧防捷径、部署侧时间对齐，两手抓才能既快又顺。与 World Pilot 的对照给出下一阶段的开放问题：先验融合（每步多一次 WAM 前向）与实时执行（80ms 单模型）目前不可兼得。
