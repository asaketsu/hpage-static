## 第一部分：原文忠实摘要

### 1. 蒸馏在解决什么

大模型贵/慢/难部署，而客服问答/摘要/抽取/润色/补全等场景只要"小快便宜且任务内够好"。**蒸馏=把大模型里"对这个任务有用的能力"迁移到小模型**——Teacher→Student，让更小学生模仿更强教师。

小模型能学会的原理：**学不完所有能力，但可学到具体任务分布上的核心模式**（老医生不必把全部医学传给只学"看感冒"的学生）。

### 2. 蒸馏是一类方法（三分类×两模式）

| 维度 | 类型 | 学什么 | 适用 |
|------|------|--------|------|
| 方法 | **输出蒸馏** | 教师的概率分布（软标签）——"不同类别之间有什么关系"（猫，有点像狗/老虎，完全不像汽车） | 最经典，分类任务 |
| 方法 | **特征蒸馏** | 中间表示对齐（语义结构/实体关系/推理链状态）——"不仅答案接近，思考过程接近" | 小模型训练常见 |
| 方法 | **关系蒸馏** | 样本间相对关系（相似/相反/解释链）——"答案之间的结构" | 检索/推荐/语义匹配 |
| 模式 | **白盒** | 可访问 logits/概率分布/隐藏层/attention——上限最高 | 开源教师 |
| 模式 | **黑盒** | 只有输入输出→大模型生成数据+清洗+微调学生——"LLM 时代反而最常用" | 闭源 API 教师 |

经典损失：L = α·CE(硬标签) + (1-α)·T²·KL(教师软标签)，**温度 T 越高分布越平滑（类间关系越多），越低越接近教师的最终选择**，按任务实验调。

### 3. 工程六步 + 适用判断 + 四误区（原文工程精华）

六步：①定义学生目标（任务/硬件/延迟/成本定规模）→②选教师（**不是越大越好：任务上够强+输出风格稳定**）→③备数据（真实/公开/教师生成三类；教师生成必须清洗：幻觉/格式/矛盾/覆盖窄）→④训练（**最常见起点=已有小模型 SFT**，不从零）→⑤建评测集（常见/边界/长/短/歧义/拒答/幻觉七覆盖；指标除准确率还看格式稳定/延迟/成本/拒答/幻觉率）→⑥上线迭代（坏例回流=数据飞轮）。

适合蒸馏：任务明确/调用频高/延迟敏感/教师可覆盖/数据可积累。**不适合**：任务极开放+世界知识要求极高→RAG/工具调用/路由大模型更合适。

四误区：①蒸馏≠压缩（量化剪枝是工程手段，蒸馏是训练策略）②教师越强越好（太强学不会，风格乱学出乱）③数据多就够（**教师有幻觉→学生"非常自信地胡说八道"**）④蒸馏后必达教师水平（学生目标是任务内可接受+成本大降，别全押）。

现代做法五步：大模型生成问题（分难度分类型）→生成答案（可多模型交叉）→人工/规则清洗→SFM+偏好对齐→**上线按难度路由（混合系统比纯大/纯小都划算）**。

### 4. 蒸馏思想的四个"亲戚"——本月文献全都在讲蒸馏

把"能力从 A 载体迁移到 B 载体"定义为广义蒸馏，则本月阅读构成一个蒸馏家族图谱：

| 亲戚 | 载体迁移 | 与经典蒸馏的关系 |
|------|----------|------------------|
| **EXPO-FT 吸收回写**（09-28） | edit head 的改进 → 底座权重 | 自蒸馏（self-distillation）：学生发现的更好动作回灌教师 |
| **Harness-Zero**（DAIR 周榜第6） | 专用 harness 行为 → 模型权重（agent-as-harness 修正演示） | 行为蒸馏：环境逻辑→参数；去 harness 后 23.3%→44.3% |
| **Kev 微调闭环**（09-28） | Jev 决策能力 → Qwen 小模型 | 黑盒蒸馏的现代版：1 美元 H100 复刻决策层 |
| **dontbesilent 方法论**（09-28） | 人类专家判断 → Skill 规则 | 碳基蒸馏：纠偏四要素就是"软标签"（含"为什么错"的类间关系） |

**观察**：2026 年的蒸馏主战场已从"分类模型压缩"迁移到**Agent 能力的迁移**（决策/行为/经验），共同结构都是"强载体示范→弱载体模仿→差距回流"。

### 6. 航空领域深化（领域扩展，非原文内容）

**适航/构型管理视角的蒸馏映射**——航空业早就在做"能力蒸馏"，只是载体不同：

| 蒸馏概念 | 航空对应物 | 启示 |
|----------|-----------|------|
| Teacher→Student | **型号改装培训**：资深机长（Teacher）→副驾（Student），改装课程=蒸馏课程表 | 培训大纲的"重点课时分配"≈α 权重：核心科目（硬标签）与经验判断（软标签）的比例 |
| 软标签（类间关系） | 教员的**经验性鉴别诊断**："这个故障现象 70% 是 A 系统但 30% 别忽略 B"——机务排故手册里的"常见/罕见/排除"三段式就是概率分布的文本化 | 为什么老师傅带出的学生更强：学的不是结论是判断结构。型号资料 FIM（故障隔离手册）的价值正在于此 |
| 白盒/黑盒 | 白盒=设计方有全权限数学模型（适航取证时的工程数据包）；黑盒=仅能观察输入输出的运行经验（航司可靠性数据） | **MOC（符合性验证方法）的分级与蒸馏模式分级同构**：能拿到内部数据的验证深度天然更高 |
| 温度 T | 培训中的"泛化-聚焦"调节：T 高=举一反三（跨机型迁移），T 低=单机型精熟 | 改装培训的"差异训练"（difference training）就是低 T 蒸馏——只学增量 |
| 数据清洗铁律 | **适航指令（AD）/服务通告（SB）的经验筛选**：不是所有厂家建议都采纳，机队工程评估后择优 | "教师生成必须清洗"=OEM 文件也要经工程评估，防"非常自信地胡说八道"式照单全收 |
| 数据飞轮 | **持续适航**（Continuing Airworthiness）：运行中故障/失效数据回流设计改进（25.859 等） | 蒸馏闭环=持续适航的 AI 版：上线不是终点是数据起点 |

**领域综合判断**：航空培训体系百年演进出的"改装课程+差异训练+经验带飞+持续适航回流"，与蒸馏工程六步+数据飞轮**结构同构**。这印证一个命题：**蒸馏不是算法而是知识工程的组织形式**——凡"强载体向弱载体迁移能力且可验证"的场景，航空经验（构型管理/分层验证/数据回流）全部适用。适航背景做 AI 蒸馏项目有天然的方法论优势。

## 8. 内容整理（归纳总结与关联分析）

**归纳总结**：蒸馏=能力从大载体迁移到小载体的训练策略（非压缩工程）。三方法（输出/特征/关系）×两模式（白盒上限高/黑盒最常用）。工程六步（定义→选师→备数→训练→评测→迭代），教师选"任务够强+风格稳定"而非最大，数据质量>数量（教师幻觉→学生自信胡说），评测七覆盖，上线按难度路由。适用判据：任务明确+高频+延迟敏感；开放任务走 RAG/路由。

**关联分析**：本笔记把 9 月阅读的四个"能力迁移"案例（EXPO 吸收/Harness-Zero/Kev/经验沉淀）统一进广义蒸馏框架，发现 2026 蒸馏主战场已从模型压缩转向 Agent 能力迁移；航空领域深化显示改装培训/持续适航与蒸馏六步/数据飞轮结构同构——蒸馏本质是知识工程的组织形式而非算法，可验证性（评测集）是两类体系共同的成败关键。与 [[2026-09-28-把经验教给AI的Skill制作方法论]] 互补：那篇讲碳基蒸馏的采集端，本篇讲硅基蒸馏的全流程。

## 10. 趋势判断

1. **"黑盒蒸馏+路由"成为中型团队默认栈**：教师生成数据→小模型 SFT→难度路由的混合系统，比单押大或小都划算——原文现代做法一节已是行业标配描述
2. **Agent 能力蒸馏接棒模型蒸馏**：行为/决策/经验迁移（EXPO/Harness-Zero/Kev 路线）的研究热度将超过经典三分类
3. **评测集成为蒸馏项目的竞争壁垒**：数据人人能生成，七覆盖评测集+坏例回流机制才是护城河——与"决策收据"（Jev 篇）同属审计资产
4. **端侧小模型+蒸馏在 Jetson 类设备常态化**：0.8B-4B 学生模型跑决策层（Kev 路线）与我们 Jetson 部署能力天然契合
