  • 收录理由：把 RAG/Skill/Workflow/Evaluation 四件套按"知识参与执行的方式"重新分工——RAG 找信息、Skill 封装判断规则、Workflow 组织执行、Eval 验收质量——这是对本库既有四件套认知的本体层补位；且与我们自身体系（error-case-library / experience-bank / skills）完全同构，可直接对照。
  • 场景锚点：企业知识库立项前的一次"认知纠偏"（先问知识在哪，再问建什么系统）；核心员工离职风险盘点；Agent 化项目从"问答"升级到"执行"的分界决策。

内容整理：从"知识在哪"到"经验如何参与执行"

一、原文核心命题：企业搞错了知识库的对象

典型现状：几千份 PDF、几十万文档切片塞进向量库、套上 RAG，宣布"企业知识 AI 化"。原文判断：很多人从一开始就理解错了企业知识是什么——一家企业真正有价值的知识，很多时候根本不在文档里，而在具体的人脑子里：长期处理客户需求、解决复杂问题、经历业务失败之后形成的判断能力。

原文用一组对照说明差距：

对照维度 十年业务负责人 看完全部文档的新员工
面对客户需求 几分钟判断值不值得接 未必能做出同样判断
客户真正想解决什么 有直觉 靠猜
哪里容易交付失控 踩过坑 无感知
差距本质 不是信息数量，是对信息的理解、经验积累、处理不确定性的能力

这就是企业最容易忽视的隐性知识。

二、老问题的 Agent 时代新解法

隐性知识高度依附个人——核心员工离职，企业失去的不止一个岗位劳动力，还有多年积累的客户理解、异常处理经验和业务判断。过去没有系统化沉淀的手段；原文判断：Agent、RAG、Skill、Workflow 的真正价值之一，就是让企业第一次有机会系统化地沉淀这些经验。

但有一个关键技术区别：把知识存储下来 ≠ 让知识真正参与业务执行。四件套分工（原文原意）：

组件 解决的问题 知识形态
RAG 如何找到相关信息 显性文档知识
Skill 把一部分操作流程和判断规则封装起来 外化的经验规则
Workflow 组织执行顺序 流程知识
Evaluation 判断系统有没有按预期完成任务 验收标准知识

四个环节必须结合起来，缺一不可。

三、案例：内容审核专家的经验资产化两级跳

原文以内容审核专家为例（知道什么文章易出事实错误、哪些信源不能直接用、哪些表达违反品牌规范、哪些必须交人工）：

  • 第一级（存储）：整理成审核手册——知识被记录了，但员工仍需自己阅读、理解、执行。知识在场，不参与执行。
  • 第二级（参与执行）：把经验转换成规则 + 审核 Skill + 异常处理流程 + 真实测试案例，再通过 Agent 自动执行部分审核——企业才开始把个人经验转化为可复用的组织能力。

四、一次性沉淀不够：知识系统必须是活的

业务环境会变、模型会变，今天有效的判断可能过几个月失效。真正有价值的企业知识系统必须能：记录知识来源 → 追踪规则版本 → 发现错误 → 根据真实业务反馈持续更新。这是一个闭环，不是一个交付物。

五、诚实边界：不是所有隐性知识都能数字化

复杂的人际沟通、商业谈判、现场判断、责任承担，依然需要人。企业的正确目标不是"把所有员工经验复制进 AI"，而是优先识别那些能够表达、验证、复用的高价值判断，把它们逐渐沉淀成组织资产。

六、结论：竞争壁垒的转移

通用模型越来越易得、工作流越来越易复制时，企业间竞争壁垒反而转移到经验体系：别人可以调用和你一样的大模型、复制类似的 Agent 架构，但很难在短时间内复制你经过多年真实业务积累、持续验证和改进的经验体系。未来值得建设的不是"能回答所有问题的超级知识库"，而是一套能把经验转化成行动、把行动结果转化成新经验的组织系统。

归纳总结

原文论证链一表收拢：

# 论点 依赖的前提
1 企业知识库运动搞错了对象：价值知识在人脑不在文档 隐性知识 > 显性知识（对高价值判断而言）
2 RAG 只是四件套之一，只解决"找到" 知识存储 ≠ 知识参与执行
3 经验资产化路径：规则 + Skill + 流程 + 测试案例 + Agent 执行 经验必须"外化"成机器可执行形态
4 资产化不是一次性工程，是带版本与反馈的闭环 业务与模型都会漂移
5 部分隐性知识永不可数字化，人保留在场 沟通/谈判/担责不可编码
6 壁垒=经验体系，模型与架构终将平权 通用能力商品化速度 > 领域经验积累速度

一句话：知识库 AI 化的真命题不是"把文档做成可检索"，而是"把人的判断做成可执行、可验收、可演进的资产"。

趋势判断

  1. 与库内系列互证：本篇结论与《Agent 不是竞争力》（同作者）"组件平权后壁垒在交付侧"、《AI 时代领域知识才是真正护城河》（05-31 三篇）完全收敛——2026 年的共识正在形成：模型/框架/RAG 管线全部商品化，唯一慢变量是经验积累速度。
  2. 四件套分工被逐渐标准化：RAG→检索层、Skill→程序性知识层、Workflow→编排层、Eval→验收层，与 Anthropic Agent Skills 路线（skill = 把 SOP 写成机器可执行包）同构；预计"经验→Skill"会成为 2026-27 企业 AI 交付的标准动作，FDE 岗位的工作重心随之从"搭系统"转向"挖经验、写规则、配验收"。
  3. 隐性知识外化的 bottleneck 在可信度而非技术：经验写成规则不难，难的是验证规则在真实业务里不翻车——Eval 与真实反馈闭环（原文第四节）才是资产化的瓶颈，这与本库《什么是 Eval》的判断一致。
  4. 反向风险（原文未展开）：过度外化会产生"规则腐化"——被封装的判断在环境变化后变成错误规则且无人察觉，版本追踪（原文第四节）是唯一的保险丝，也是多数企业最容易省略的一环。

指南分析

企业经验资产化五步（原文逻辑 + 本库实施惯例合成，原文仅覆盖方向）：

步 动作 产出 验收判据
1 盘点：识别"能表达、验证、复用"的高价值判断（先业务负责人后全员） 判断清单 + 持有者 每条判断有真实案例支撑
2 外化：判断 → 显式规则 + 异常处理流程 + 边界条件（哪些必须交人工） 规则文档/Skill 包 规则可被非持有人执行出同等结果
3 固化：规则封装成 Skill，配 Workflow 编排 + 真实测试案例（Eval 集） 可执行 Skill + 回归集 Eval 通过率 + 人工抽检一致
4 上线：Agent 执行为主、人处理"不可数字化"例外（谈判/担责/现场） 人机分工表 例外路径有明确升级判据
5 闭环：记录知识来源、规则版本化、错误回流、按真实反馈更新 知识台账 + 版本链 规则腐化可追溯（谁/何时/依据什么改）

红线（原文明确）：跳过第 1 步直接建 RAG（文档≠知识）；跳过第 5 步交付一次性系统（规则会腐化）。
