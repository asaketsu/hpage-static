## 一、内容整理

### 0. 系统定位

> 一体化 A 股量化系统：抓取每日股票/ETF 数据 → 计算技术指标+筹码分布 → 识别 61 种 K 线形态 → 200+ 栏目综合选股 → 11 种内置策略 → 回测验证 → 自动交易（打新）。普通笔记本全流程 1 天数据 **4 分钟**跑完。

### 1. 功能全景（16 项能力）

| 模块 | 内容 | 关键数字 |
|---|---|---|
| 综合选股 | 股票范围/基本面/技术面/消息面/人气/行情 自由组合 | **200+ 信息栏目** |

### 2. 核心策略实现细节（照录 6 个）

**放量上涨**：①当日涨幅<2% 或收<开（排除） ②成交额≥2亿 ③量/5日均量≥2

**均线多头（MA30 向上）**：①30日前MA30 < 20日前MA30 < 10日前MA30 < 当日MA30 ②当日MA30/30日前MA30 > 1.2

**停机坪**：①最近15日有>9.5%放量上涨 ②次日必须高开收涨且与开盘差<3% ③之后2-3日同样高开收涨、差<3%、日振幅<5%

**回踩年线**：①前段（最近60日最高收盘价之前）从年线(250日)下方向上突破 ②后段在年线上运行，后段最低价日与最高价日相差10-50日 ③缩量回踩：最高量/最低量>2 且 最低价/最高价<0.8

**突破平台**：①60日内某日收≥60日均线>开 ②放量上涨 ③此前任意一天收盘与60日线偏离-5%~20%

**放量跌停（反向）**：①跌>9.5% ②成交额≥2亿 ③量≥5日均量×4（博弈超跌反弹）

**低ATR成长**：①上市≥250日 ②近10日最高收盘/最低收盘>1.1

**基本面选股**：0<PE≤20 且 PB≤10 且 ROE≥15

### 4. 架构要点（工程借鉴核心）

```
instock/
├── bin/run_job.sh          # 作业入口
├── config/proxy.txt        # 代理池（ip:port 或 user:pass@ip:port）
├── config/eastmoney_cookie.txt  # Cookie 注入
├── execute_daily_job.py    # 整体作业（4种时间模式）
├── basic_data_daily_job.py # 分功能作业（基础/指标/形态/策略/回测 各自独立）
└── ...
```

- **数据库自动建库建表** + 批量 upsert 封装 → 业务扩展只写逻辑
- **Web 视图字典**：新业务表配置字典即自动出现可视化界面（低代码思路）
- **部署**：Docker 镜像 + mariadb 容器编排（InStockService 网络），或 Windows 直装
- **日志三分**：stock_execute_job.log（抓取/处理）/ stock_web.log（Web）/ stock_trade.log（交易）

## 二、查询拓展

1. **筹码分布（CYQ）算法实现**：三角化分布 vs 均匀分布假设，210 日窗口的衰减权重怎么定？
2. **"停机坪"策略的胜率数据**：作者回测模块里该策略的历史成功率，与龙头战法中"分歧转一致"的对应关系
3. **人气指标数据源**：股吧人气排名/粉丝占比从哪个接口抓，反爬强度如何？
4. **talib CDL 形态在 A 股的适配性**：61 种形态基于美股 OHLC 定义，涨跌停板制度下（如一字板）形态信号是否失真？
5. **自动交易接口**：打新策略走哪个券商通道（QMT/PTrade/硬模拟），延迟与合规风险？

## 三、归纳总结

| 维度 | 要点 |
|---|---|
| 数据层 | 东方财富为主源，代理池+Cookie 双反爬；12 类日频数据全覆盖 A 股 |
| 计算层 | talib 32 指标+61 形态，公式刻意对齐国内软件（同花顺/通达信/东财）——本土化细节 |
| 策略层 | 11 种内置策略全部明文参数（阈值照录可复刻），策略模板可扩展 |
| 工程层 | 分功能作业脚本解耦、批量时间模式、视图字典低代码、日志三分——** amateur 数据到工程化产品的完整范本** |
| 性能层 | 多线程+单例共享，1 天全流程 4 分钟（普通笔记本） |
| 风险边界 | 自动交易只给打新+示例（涉钱不送策略）——作者明确的合规自觉 |

**一句话**：这是"数据抓取→因子计算→策略筛选→回测验证→自动化执行"五段全打通的 A 股单机量化参考实现，价值不在策略多强（多为经典技术分析），而在**工程骨架完整可抄**。

## 四、趋势判断

1. **单机全栈量化开源正在"消费级化"**：13.9k star 说明散户量化的需求规模——Docker 一键起、笔记本 4 分钟跑完，门槛已降到"会装软件就能跑"
2. **反爬是数据层的第一公民**：代理池+Cookie 注入直接做进 config 目录——数据源稳定性正在取代策略先进性成为开源量化项目的核心差异点（与我们 Tavily 降级链同构）
3. **形态/指标公式本土对齐是隐形壁垒**：talib 原生公式与国内软件有差异，该项目逐一对齐同花顺/通达信——海外轮子本土化的脏活累活构成护城河
4. **"涉钱不送策略"成为开源量化的默认伦理**：只送框架+打新（无风险套利），策略留白——与量化私募开源"框架不开源信号"的商业逻辑一致

### 对我们体系的直接借鉴（吸收+优化自我）

1. **批量时间作业模式**：`execute_daily_job.py 2022-01-01 2022-03-01`（区间/枚举/单日）——iron-rules 的 scan 脚本可加同款时间参数，历史复盘时一键回放任意时段
2. **策略参数全部明文常量**：每个策略的阈值（2亿成交额、5日均量×4、MA30比值1.2）直接可读可改——对照我们的 cycle-records.json，把铁律参数也显式化便于回测调参
3. **反爬双保险**：代理池文件+Cookie 文件外置到 config/，热加载——数据源故障时的降级思路与 search-fallback-chain 同构，可吸收进 akshare/tushare 抓取层
4. **回测自动补数**：回测时数据缺口自动填补到当前——减少我们手工对齐数据的环节
