## 一、内容整理

### 1.1 项目总纲与目标体系

项目以 RMUC（RoboMaster 大学赛）标准步兵为载体，16 周赛季周期，五组协同交付一辆可参赛的完整步兵机器人。目标体系拆为三个 OKR：

- **O1 自瞄闭环**：检测→解算→云台跟踪→发弹命中 3m 外固定装甲板。KR：检测率 ≥95%（误检 ≤2%）、自瞄收敛 ≤500ms、3m 命中率 ≥60%（静止靶 10 发）。
- **O2 底盘可控**：全向移动+小陀螺。KR：麦轮解算误差 <5%、小陀螺演示成功（底盘旋转+云台指向不变）。
- **O3 五组成建制**：各组交付物验收、完整整车+3 分钟演示视频、运营内容矩阵达标（B 站 5000 播放）。

### 1.2 系统架构（三层）

```
┌─ 上位机（Pi5/Jetson，视觉自瞄） ─ OpenVINO 加速可选
│    装甲板检测 → 敌方方位解算 → 弹道解算 → 目标角下发
├─ 主控 STM32F407（RM 开发板类型C / 自研板）
│    底盘：4×M3508+麦轮 CAN PID + 运动解算（全向）
│    云台：yaw/pitch 串级 PID（角度环+速度环，IMU 反馈）
│    发射：摩擦轮×2 转速环 + 拨弹盘 M2008 脉冲计数
│    遥控：SBUS/图传链路；电源：12V/24V 电池+降压+裁判系统
└─ 机械：底盘框架（U形槽铝/Carbon）+ 云台+ 弹仓+42/17mm 发射管
```

三层分工逻辑：上位机负责"看到谁、打哪里"（视觉+解算），主控负责"怎么动、怎么打"（电机控制环），机械负责"承载与约束"（结构+限位）。上位机与主控通过 UART 100Hz 串口通信，帧头 0xA5，传输目标偏航/俯仰角+开火指令。

### 1.3 五组任务与难度重排

原文千问页给出 RM 本尊的难度排序（视觉⭐5/雷达⭐4.5/电控⭐4/机械⭐3.5/运营⭐3），本项目在"约束场景"（固定场地、标准灯效、已知地图）下做了降维重排：

- **视觉组（降 ⭐4）**：装甲板灯条在标准灯效下特征极强，经典通道差分法可解释、免训练、部署成本为零。
- **雷达组（降 ⭐3.5）**：RM 赛场是已知固定地图（官方发布 CAD），定位问题从"SLAM 建图"降为"已知地图定位"。
- **电控组（降 ⭐3.5）**：M3508+C620 有官方文档+大量开源参考，从单电机环起步。
- **机械组（持平 ⭐3.5）**：全新设计无 DUCK 复用，但 U 形槽铝型材免加工方案降低了门槛。
- **运营组（持平 ⭐3）**：内容/VI/新媒体/赞助四件套不变。

降维核心手段是约束场景——训练载体的价值在于让新人快速打通链路，而非复刻全难度。

### 1.4 代码交付物与冒烟验证

两个可运行算法已落盘并通过本机冒烟（Jetson Orin, Python 3.11, numpy 2.4.3）：

**bullet_trajectory.py**（弹道解算）：
- 模型：抛体 + 空气阻力（线性近似 K_DRAG=0.08/m），迭代二分法解 pitch 补偿角
- 4 档弹速（15/18/22/30 m/s），3m 目标补偿角分别为 4.471°/3.101°/2.076°/1.119°
- 验证四项全过：单调性（弹速越高补偿越小）、回代误差 <1e-6、量级校验（>纯重力近似 2.60° 且 <5°）、重力对照

**armor_detect.py**（灯条检测）：
- 管线：通道差分(R-B/B-R) → 阈值 → 两遍连通（列投影切竖带+带内行行程切分）→ 灯条筛选（长宽比/高度）→ 平行配对（间距比/高度比）→ 装甲板中心输出
- 纯 numpy 无 cv2 依赖
- 验证：红/蓝双阵营合成帧 20/20 检测率 100%，中心误差 <6px，无灯条帧不误报

### 1.5 冒烟抓出并修复的三个问题

冒烟验证的价值在于"写完就跑"，三个问题全是文档推导发现不了的：

1. **弹道断言写反**：初版断言要求补偿角 <2.5°，但 18m/s 打 3m 的物理正确值是 3.10°（阻力要求比纯重力 2.60° 更大补偿）。修断言不修代码——代码的物理模型是对的。
2. **合成器灯条间距不真实**：初版 `bar_gap=30`（间距/高比 0.75），真实 RM 装甲板约 3.5-4（230mm/55mm 灯条间距/灯高），低于配对阈值 1.2-5.0，导致检测率仅 80%。修合成器参数为 `bar_gap=140`。
3. **检测端真 bug——列投影粘连**：纯列投影把 y 方向分离的绿色干扰块与灯条在重叠列粘连成 142px 假灯条，漏检 4/20。根因是列投影只看 x 方向连通，不区分 y 方向的不同块。修复为两遍连通：先列投影切竖带，带内再按行行程切分（`np.diff(rows) > 3` 分段），检测率回到 100%。

## 二、查询拓展

### 2.1 M3508+C620 CAN 协议与控制环

M3508 是大疆 RM 标准底盘电机（无刷减速直流），配套 C620 电调。C620 通过 CAN 总线接收电流指令（-16384~16384 对应 -20A~20A），内置转子机械角度传感器可读反馈。控制环典型结构：电流环（电调内嵌）→ 速度环（主控差分角度得速度，1kHz）→ 位置环（可选）。本项目起步值 Kp=10/Ki=0.5 是 RM 社区共识典型值，实车整定时先做阶跃响应观察超调与稳态误差。

### 2.2 麦轮全向运动解算

4 个 45° 斜置麦轮的全向底盘，逆解公式为 `w1..w4 = f(vx, vy, ω)`，其中 vx/vy 是底盘系速度分量、ω 是旋转角速度。45° 布局的标准矩阵：

```
w1 = vx - vy - ω*L    (左前)
w2 = vx + vy + ω*L    (右前)
w3 = vx + vy - ω*L    (左后)
w4 = vx - vy + ω*L    (右后)
```

L 是轮到中心距离（半轮距）。小陀螺模式是 ω≠0 且云台指向不变的特例——底盘转但云台 IMU 反馈补偿 yaw 角保持指向。

### 2.3 云台串级 PID 的必要性

直驱云台惯量大（枪管+相机+弹仓），负载变化快（发射反冲、俯仰重心位移）。单环 PID 会在角度误差收敛前引入振荡——外环还没收敛，内环已经抖。串级结构：外环角度（云台 IMU 欧拉角）→ 内环角速度（陀螺仪）→ 电流。快动力学问题留给内环（毫秒级响应），外环只处理参考轨迹跟踪（百毫秒级），抗扰与响应速度同时改善。

这与 DUCK 双足项目的同步读写控制环思想一致——都是"快环兜底层、慢环定目标"的分层控制。从 DUCK 的 50Hz 升到 RM 的 1kHz，FreeRTOS 任务划分是关键。

### 2.4 PnP 位姿解算

PnP（Perspective-n-Point）是从 3D 已知点+2D 像素点求解相机位姿的经典算法。装甲板灯条的 4 个角点在装甲板坐标系中有已知 3D 坐标（如 55mm 高、230mm 间距），相机检测到 2D 像素角点后，PnP 解出旋转向量+平移向量→装甲板在相机系的三维位置。这是从"检测到装甲板"到"知道装甲板在哪"的桥梁，直接决定自瞄精度。标定质量（相机内参棋盘格+云台外参与电控零位对齐）比算法复杂度更影响命中率。

### 2.5 AMCL 与 Nav2

AMCL（Adaptive Monte Carlo Localization）是 ROS2 Nav2 的标准定位组件，用粒子滤波在已知地图上做位姿估计。RM 赛场地图是官方 CAD 固定的——飞坡、环形高地、资源岛位置全部先验，AMCL 用激光/点云扫描与已知地图配准即可定位，不需要 SLAM 建图。这把"雷达组"的难度从⭐4.5 降到了⭐3.5。

### 3.3 上位机-主控通信契约

UART 115200-921600bps，100Hz，帧头 0xA5：

```c
typedef struct {
    uint8_t  sof;         // 0xA5
    float    yaw_deg;     // 目标偏航（云台系）
    float    pitch_deg;   // 目标俯仰
    uint8_t  fire_cmd;    // 0 停止 1 单发 2 连发
    uint8_t  checksum;
} aim_msg_t;
```

这个契约是视觉组与电控组联调的唯一接口——视觉组按此格式发、电控组按此格式收，两边独立开发、W11 联调。契约冻结后不应频繁改字段，checksum 保证帧完整性。

### 3.4 安全联锁铁律（四条）

1. **失控保护**：SBUS 丢控 >200ms → 电机怠速+发射停止
2. **摩擦轮使能**：物理开关+遥控双确认
3. **发射方向有人禁止使能**：测试场地管理
4. **电池保护**：电压 <20V 告警，<19V 强制停机

## 四、趋势判断

**趋势 1：竞赛机器人从"单车性能竞赛"转向"体系对抗"**
依据：RM 引入英雄/哨兵/无人机后，单车性能不再是胜负主因。本项目雷达组的"哨兵级导航成果直通"设计顺应此趋势——单做步兵是自满，做导航栈是积累可迁移资产。

**趋势 2：视觉自瞄走"经典法打底+CNN 补边角"双轨**
依据：装甲板灯条在标准灯效下特征极强，经典通道差分法免训练、可解释、部署成本为零。CNN 的价值在反甲识别、能量机关、复杂光环境——本项目 L1-L2 走经典法、L4 才上 OpenVINO CNN 的梯度设计符合此判断。先拿基线命中率，再花算力。

**趋势 3：弹道解算回归"实测标定"而非"参数泛化"**
依据：摩擦轮间隙、弹丸质量、出口速度三者都随批次与磨损漂移，K_DRAG=0.08 只是起点。PROGRESS 已列"实弹标定后更新"为已知问题——真实赛场数据是唯一可信来源。

**趋势 4：低成本桌面验证台成为竞赛入门标准动作**
依据：L0 桌面台 ¥3-5k 能验证 100% 视觉自瞄代码，L1/L2 无需重做。项目把 L0 显式纳入 BOM 拆解而非事后临时方案，是这一趋势的工程化体现。

### 8.1 可迁移到其它竞赛赛制

### 8.2 可迁移到非竞赛场景

- **弹道/抛射体解算**：滚珠抛射、水弹、高尔夫球初速与补偿角解算同构，大学物理实验可直接用 `bullet_trajectory.py`
- **桌面云台展示台**：L0 台改造为展厅交互装置（人脸/手势触发追踪拍摄）成本仅 ¥3-5k

### 8.3 可迁移到已有资产

`bullet_trajectory.py` 的迭代解 pitch 方法可复用于双足踢球弹道——`kick_trajectory.py` 的纯滚动模型可升级为抛体模型，处理踢出高度非零场景。
