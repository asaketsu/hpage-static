# 自进化 Agent 2026：三层进化矩阵、源码级重写与工作流编译

> **学习日期**: 2026-07-06
> **信息源**: Xinming Tu《The What & When of Self-Evolving Agents》(UW, 2026-06-08); Requesty《5 AI Agent Techniques That Just Dropped》(2026-05-23); MOSS/Ratchet; EvoScientist; "Compiling Agentic Workflows into LLM Weights"
> **核心命题**: 自进化已从"调 prompt"升级为**三层 × 三时**的完整矩阵——能改外部文件、能改 Harness 逻辑、甚至能改模型权重；关键不是"会不会变"，而是"变什么、何时持久化、如何防止退化"

---

## 一、范式升级：从静态编排到状态化进化

### 1.1 两大原始动机

| 动机 | 含义 | 衡量指标 |
|------|------|----------|
| **边际成本下降** | 相似任务越做越便宜，历史轨迹压缩成可复用资产 | 每"任务族"的 token 数、工具调用数、重试次数、人工干预次数 |
| **能力天花板抬升** | 不止变便宜，还能把以前做不了的长程任务纳入射程 | 可完成任务的最长 horizon、错误累积率、上下文衰减率 |

> 核心转变：**无状态编排（每次从零开始）→ 状态化进化（把经验带向未来）**。"学习"必须落地到某个可持久化的载体上。

### 1.2 核心问题拆成两问

1. **What evolves?** —— 到底什么在变？
2. **When does the update persist?** —— 这次更新何时固化、保留多久？

---

## 二、What Evolves：三层可塑载体（由表及里）

| 层 | 载体 | 典型实现 | 改动成本 | 持久度 |
|----|------|----------|----------|--------|
| **L1 External Files** | 笔记、文档、skill 库、用户记忆 | Voyager、Anthropic Agent Skills、OpenAI Codex Record & Replay | 低/即时/可逆 | 中 |
| **L2 Agent Harness** | prompt、工具、工作流、控制流、恢复逻辑 | Claude Code 动态工作流、LLM-as-Tool-Makers、DSPy/MIPRO 元编程、Recursive LM | 中 | 高 |
| **L3 Model Weights** | 模型 checkpoint 内化的知识与行为 | Cursor Tab 在线 RL、Test-Time Training、JitRL、Profile-to-PEFT、PERSOMA | 高/慢 | 极高 |

> **铁律：越靠核心，改动越贵越慢，但越"粘得住"。** 改 prompt 当天就能回滚；改权重一旦固化就难以撤销。这决定了自进化的"安全刹车"必须按层分级。

### 2.1 每层的代表性机制

- **L1 外部文件**：MemGPT / MEMENTO / Memory-as-Action（工作记忆与上下文分页）；Composio / ReasoningBank（集体知识与 Skill Commons）
- **L2 Harness**：Meta-Harness 元编程；Alita-G / Darwin Gödel Machine（Harness 飞轮与自动设计）；Anthropic Agent Skills / Voyager（持久技能）
- **L3 权重**：Test-Time Training / Learning to Discover at Test Time / JitRL（测试期快速权重）

---

## 三、When Updates Persist：三个时间尺度

| 时间尺度 | 场景 | 进化目标 |
|----------|------|----------|
| **单会话内（Online Adaptation）** | 一次任务执行中 | 在线适配当前任务 |
| **跨会话（Longitudinal Alignment）** | 同一用户多次交互 | 纵向对齐到该用户偏好 |
| **跨用户（Population-Level Evolution）** | 全体用户共享 | 群体级能力提升 |

三层 × 三时 = **3×3 进化矩阵**，每个格子对应一类系统。判断一个"自进化 Agent"时，先定位它在矩阵的哪个格子，再看它是否声称覆盖多个格子。

## 四、2026 五大突破技术（Requesty 5/23 盘点）

### 4.1 MOSS：源码级自我重写

这是**比 prompt tuning 和权重更新更激进**的新范式——Agent 直接修改自己的 Python/TypeScript 源码：

```
执行任务 → 识别自身逻辑弱点 → 重写特定模块 → 自动测试验证 → 部署改进版
```

> 不是"调参"，是"改代码"。每次任务执行都可能让系统为未来任务变得更好。

**配套：Ratchet** 提供"最小卫生配方"（minimal hygiene recipes），防止自重写后跌破历史基准分数——这是自进化的**安全护栏**。

### 4.2 Managed Agents（API 级托管）

Google Gemini API 的 Managed Agents 把编排从客户端搬到服务端：
- 服务端 24/7 运行 agent loop
- 状态自动跨会话持久化
- 无需活跃客户端连接即可主动行动

> 消除了"agent 托管"难题：不用维护 WebSocket 长连、不用自己做状态序列化、不用自建调度器。
> **代价**：状态留在供应商服务器 → 厂商锁定。**对策**：用 Gateway 路由 LLM 调用以保持可移植性。

### 4.3 工作流编译进权重（最高杠杆降本）

把多步 agent pipeline 蒸馏进单个微调模型：

| 指标 | 编译前（多步 pipeline） | 编译后（单模型） |
|------|------------------------|------------------|
| 成本 | $0.50 / 次 | $0.005 / 次（**降 100×**） |
| 延迟 | ~30 秒 | ~2 秒 |
| 质量 | 接近前沿 | 接近前沿（极小回退） |

**落地路径**：① 持续收集 agent 轨迹 → ② 识别常见输入-输出模式 → ③ 用这些模式微调小模型 → ④ 路由：简单请求走编译模型，复杂请求走完整 pipeline。

### 4.4 IdleSpec：空闲期推测规划

利用等待工具响应的"死时间"，提前为可能的结果生成多个候选下一步动作，结果回来后做匹配（命中率 60-80%），把多步工作流的感知延迟砍掉一半以上。

> **最佳场景**：工具输出可预测时；推测规划路由到便宜快速模型。

### 4.5 LCGuard：多 Agent 隐式通信护栏

防止被攻破/幻觉的 Agent 污染整个系统：在 Agent 间交接处加验证层，用快速模型检查输出是否违反安全约束，几乎不增加延迟。

> 编码 Agent 把子任务委托给专家 Agent 时，一个专家的幻觉会级联传播——LCGuard 式验证切断这种级联。

## 五、EvoScientist：持久记忆驱动的多 Agent 自进化（实证标杆）

EvoScientist 是"持续改进研究策略"的进化型多 Agent AI 科学家框架，三个专职 Agent：

| Agent | 职责 |
|-------|------|
| **Researcher Agent (RA)** | 科学想法生成 |
| **Engineer Agent (EA)** | 实验实现与执行 |
| **Evolution Manager Agent (EMA)** | 从历史交互蒸馏可复用知识 |

> 关键创新在 EMA：它把"过去交互的洞察"蒸馏成**可复用知识**，让系统不再依赖静态、手工设计的 pipeline。实验显示 EvoScientist 在想法生成的新颖性/可行性/相关性/清晰度上超越 7 个开源和商业 SOTA，且通过多 Agent 进化显著提升代码执行成功率——证明了**持久记忆对端到端科学发现的价值**。

## 六、对 Hermes Agent 系统的落地启示

| 现状能力 | 可引入的进化机制 | 对应层 |
|----------|------------------|--------|
| Skill 库（auto-skill/evolver） | ✅ 已有 L1；可加 Skill 质量回归基线（Ratchet 思想） | L1 |
| Cron 任务调度 | IdleSpec 式空闲推测：cron 等待期预生成候选 | L2 |
| 多 Agent 委派（dev/content/data/opm） | LCGuard 式交接验证，防幻觉级联 | L2 |
| 模型路由（free-model-apis/model-switch） | 工作流编译：高频 cron 模式蒸馏成小模型调用 | L3 |
| exchange-protocol 三机经验池 | EvoScientist EMA 思想：把交互蒸馏成可复用知识 | L1 |

### 🚨 关键缺口
1. **自进化的安全刹车缺失**：MOSS 式源码重写在 Hermes 上无 Ratchet 护栏，存在自退化风险。建议给 evolver/auto-skill 加"基准回归门禁"——patch 后必须通过代表性任务测试集才允许合并。
2. **进化矩阵定位不清**：当前自进化集中在 L1（外部文件/skill），L2（Harness 元编程）和 L3（权重）几乎空白。工作流编译（4.3）是降本最高杠杆的方向，值得优先探索。

---

## 七、核心要点速记

1. **自进化的本质是"经验落地"**——必须回答"变什么 + 何时固化"，否则只是 transcript 里的行为，不是架构属性。
2. **三层载体由表及里**：外部文件（便宜即时）→ Harness（中）→ 权重（贵但粘）。安全刹车按层分级。
3. **MOSS 源码重写是 2026 最激进方向**，但必须配 Ratchet 式基准护栏防退化。
4. **工作流编译进权重 = 100× 降本**，是高频固定流程的最佳归宿。
5. **IdleSpec + LCGuard** 分别解决"慢"和"乱"两个 Agent 痛点，实现成本低、收益明显。
