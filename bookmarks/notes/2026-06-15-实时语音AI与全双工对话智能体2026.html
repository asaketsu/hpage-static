摘要

实时语音 AI 在 2026 年迎来两个关键突破：一是双 Agent 预取架构将 RAG 延迟从 50-300ms 压缩到 <1ms 缓存命中；二是 GRPO 强化学习对齐使全双工语音模型在停顿处理、轮流接话、反向信道、打断响应四个维度全面优化。级联管线（ASR→LLM→TTS）平均端到端延迟已达 0.94 秒，而统一语音模型（Moshi 等）正在消除文本中间层，直奔音频到音频的零延迟目标。

一、核心问题：为什么语音 AI 这么难？

人类对话有一个硬约束：超过 200ms 延迟就会感到"卡顿"。但一个传统级联语音管线需要串行经过三步：

阶段 延迟范围 说明
ASR（语音识别） 30-80ms 将音频转为文本
LLM 首字延迟 150-300ms 推理生成第一个 token
TTS 首音延迟 50-100ms 文本转语音首个音频块
最低总和 ≥230ms 还不含网络/编码开销

更关键的是，RAG 检索还需要额外 50-300ms 向量数据库查询延迟，直接将总延迟推到不可接受的范围。

1.1 三种解决路径

路径 A：优化级联管线（2024-2025 主流）
  └─ 并行执行 + 句子级流式 + 量化压缩
  └─ 优势：模块可替换、调试容易
  └─ 天花板：~500ms（三段串行的固有开销）

路径 B：双 Agent 预取（2026 新方案）
  └─ 后台慢思考 + 前台快回答 + 语义缓存
  └─ 优势：级联架构不改动、RAG 延迟降到 <1ms
  └─ 天花板：缓存命中率决定（首次仍走全链路）

路径 C：统一端到端模型（2026 前沿）
  └─ 音频帧直接到音频帧、无文本中间层
  └─ 优势：理论最低延迟、原生全双工
  └─ 天花板：模型训练难度高、可控性低

二、VoiceAgentRAG：双 Agent 预取架构

来源：arXiv:2603.02206v2 — Salesforce AI Research

2.1 核心洞察

受 Kahneman 的 System 1/System 2 框架启发：在多轮对话中，用户的下一个问题往往可以从当前上下文预测。

2.2 双 Agent 协作

Agent 角色 时机
Slow Thinker（后台慢思考） 监听对话流，预测 3-5 个可能的后续话题，预取文档块到语义缓存 用户聆听当前回答时异步运行
Fast Talker（前台快回答） 先查语义缓存（<1ms 查找），缓存未命中才回退到向量数据库 关键延迟路径

2.3 语义缓存的关键设计

核心教训：缓存索引必须用文档嵌入而非查询嵌入。

"早期设计用预测查询的嵌入做索引，导致缓存'命中'返回了无关块——当预测'价格细节是什么？'会缓存定价块，但当用户实际问'年度账单有折扣吗？'，缓存返回的是通用定价信息而非折扣相关内容。"

参数调优：
- 查询到文档的余弦相似度系统性低于查询到查询的相似度
- 默认阈值 τ=0.40（查询到文档匹配通常在 0.30-0.55 之间）
- 近重复检测：余弦相似度 >0.95 时更新而非新增
- TTL 默认 300 秒 + LRU 淘汰策略

2.4 实际效果

指标 无预取 有预取
缓存命中率 ~0% 60-80%（多轮场景）
查询延迟 50-300ms <1ms（缓存命中时）
用户感知延迟 500ms-1s+ <200ms（缓存命中时）

三、低延迟级联管线实战

来源：arXiv:2508.04721v1 — NetoAI

3.1 流水线架构

音频输入 → [Streaming ASR] → 文本
                              ↓
                    [FAISS RAG 检索] → 上下文
                              ↓
              [4-bit 量化 LLM (2B)] → 句子级流式输出
                              ↓                    ↘
                    [Real-time TTS] ←── 消费句子队列 → 音频输出

3.2 五项关键优化

  1. 句子级流式传输：LLM 用正则检测标点，按句子切分放入线程安全队列，TTS 线程异步消费
  2. 4-bit 量化：2B 参数 LLM 在 H100 上仅需少量 VRAM，延迟降至 0.67s
  3. 并发模块执行：ASR、LLM、TTS 三模块通过生产者-消费者模式并行
  4. TTS 线程预加载：TTS 线程在 LLM 线程之前启动，预热参考音色减少抖动
  5. msgpack 二进制序列化：LLM 与 TTS 间用二进制而非 JSON，减少 0.8-1.0 秒

3.3 实测性能（500 条 RFC 语音）

指标 均值 最小 最大
ASR 0.049s 0.029s 0.069s
RAG 0.008s 0.008s 0.012s
LLM 0.670s 0.218s 1.706s
TTS 0.286s 0.106s 1.769s
总延迟 0.934s 0.417s 3.154s
LLM TTFT 0.106s 0.077s 0.181s
TTS TTFA 0.678s 0.412s 1.482s

结论：平均 0.94 秒已低于 1 秒交互阈值，但仍有优化空间——LLM 是最大瓶颈（占 72% 延迟）。

四、全双工语音模型的 RL 对齐

来源：arXiv:2606.11167v1 — Kyutai & Gradium

4.1 问题定义

全双工语音模型（如 Moshi、PersonaPlex）可以同时听和说，但监督学习的 token 级似然最大化不直接优化交互行为——模型不知道何时该沉默、何时该插话。

4.2 四维交互对齐

交互轴 目标 奖励函数
停顿处理 用户犹豫时保持沉默 R_pause = -1 如果有 >1s 的语音
轮流接话 用户让出发言权时迅速响应 R_turn = -d（d = 响应延迟）
反向信道 用户说话时给出简短反馈 R_bc = F1 分数（≤1s 的反馈词）
用户打断 被打断时让出并响应 R_int = -d（打断结束后的延迟）

4.3 GRPO 训练管线

每步训练：
  1. 随机选一个交互轴 ℓ ∈ {pause, turn, bc, int}
  2. 从该轴专用数据集抽取一个片段
  3. 当前策略 π_θ 采样 G=16 个补全
  4. 解码为波形，用轴专用奖励函数打分
  5. 优势估计：Â = (r - mean) / std（跨 16 个样本）
  6. 裁剪代理损失 + KL 惩罚（β=0.01）
  7. ⚠️ 损失只在文本 token 上计算（文本控制内容和时序）

关键设计：LLM Judge 奖励（Qwen3-235B 打分 1-3 分）防止语义退化，使用奖励解耦归一化（各组件独立标准化后等权求和）。

4.4 训练数据

数据集 时长 描述
Fisher 2,000h 随机配对电话对话
Seamless (Improvised) 1,300h 专业演员即兴对话
Seamless (Naturalistic) 2,700h 自然对话参与者

每轴最多提取 2,000 个交互片段，VAD 使用 Silero。

五、统一语音模型生态

5.1 级联 vs 统一模型对比

维度 级联管线 (ASR→LLM→TTS) 统一 S2S (Moshi 等)

全双工 ❌ 需额外 VAD 逻辑 ✅ 原生支持

可控性 ✅ 高（文本可审计） ❌ 低（黑盒音频）

六、对 Hermes 语音系统的启示

6.1 当前差距分析

能力层 当前 Hermes 2026 SOTA 差距
听得清（ASR） Whisper（离线批处理） Conformer-CTC 流式（<50ms） 缺流式
听得懂（理解） 文本→LLM 统一 S2S 或级联+预取 缺预取
做得对（推理） glm-5.1 + MCP 工具 双 Agent 架构（快+慢） 可改进
说得像人（TTS） F5-TTS（克隆） 实时 TTS + 情感控制 缺实时流式

6.2 可落地的改进

  1. 引入语义缓存预取层：借鉴 VoiceAgentRAG，在 Hermes Gateway 的语音交互路径上增加 Slow Thinker 异步预取
  2. 句子级流式 TTS：将 F5-TTS 从"整句生成"改为"句子流式"，减少首音延迟
  3. 全双工 VAD：用 Silero VAD 实现打断检测，用户说话时自动停止 TTS 播放
  4. RL 交互对齐评估：用四维交互指标（停顿/轮流/反馈/打断）评估当前语音 Agent 质量
