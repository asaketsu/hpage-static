## 一、Beyond Tokens：潜变量通信统一框架（18 方法系统化）

### 1.1 核心问题

当前 LLM 多 Agent 系统的通信协议是**自然语言**：Agent 逐 token 交换消息，将内部推理文字化。这带来三个结构性缺陷：

1. **推理成本高**：每次通信都要走完整的 LLM 生成流程
2. **信息损失不可逆**：连续表示→离散 token 的量化损失
3. **自然语言歧义/冗余**：同一语义多种表达方式

### 1.2 三轴分类框架

论文提出统一的**潜变量通信**分类法：

| 维度 | 问题 | 可选项 |
|------|------|--------|
| **WHAT**（传什么） | 通信的信息载体 | Embeddings / Hidden States / KV-Caches / 其他连续状态 |
| **WHICH**（怎么对齐） | 发送-接收对齐方式 | 潜空间对齐 + 层级对齐 |
| **HOW**（怎么融合） | 接收端如何利用信息 | Concatenation / Prepending / 数学运算 / Cross-Attention / Cache Restoration |

### 1.3 五大设计模式

从 2024-2026 年的 18 种代表性方法中提炼出五种模式：

1. **Embedding Bridge**：发送 Embedding，接收端通过投影层融合 — 最简单但信息密度低
2. **Hidden-State Tunnel**：直接传递中间层隐状态 — 信息保留最多但对齐难度大
3. **KV-Cache Sharing**：共享 KV 缓存，接收端直接恢复上下文 — 延迟最低
4. **Cross-Attention Fusion**：接收端用 Cross-Attention 处理发送端输出 — 最灵活但计算量大
5. **Cache Restoration**：将发送端 KV 缓存注入接收端 — 最高效的上下文传递

### 1.4 四大开放挑战

1. **跨架构对齐**：不同模型（GPT/Llama/Qwen）的潜空间如何对齐？
2. **潜变量通道安全**：恶意 Agent 可通过污染潜变量注入攻击
3. **边缘部署压缩**：潜变量通信在 Jetson 等设备上的带宽/计算限制
4. **潜变量 CoT 关系**：潜变量通信与潜变量思维链的交互机制

### 1.5 对 Hermes 的启示

- **三机协作**：jbot/ubot/abot 当前用 JSONL 文本交换经验。理论上可用 KV-Cache Sharing 模式加速上下文传递
- **安全性**：潜变量通道安全是 exchange-protocol 需要考虑的新维度
- **边缘优化**：Jetson Orin 上 KV-Cache Sharing 比 token 生成更高效

## 二、GARL：博弈论强化学习驱动的多 Agent 战略优先级

### 2.1 核心思路

多 Agent 系统中，性能不仅取决于个体能力，更取决于**交互策略**。GARL 将交互结构化为博弈论框架。

### 2.2 两阶段博弈模型

```
Stage 1: 竞争 Agent 在共享候选集上分配战略资源（注意力/权重）
Stage 2: 仲裁者根据竞争结果产出最终排名
```

博弈论效用函数 → 角色专用 RL 信号 → 策略优化

### 2.3 实验结果

- **小模型 + GARL 可匹敌大模型**：开源小模型在博弈论框架下竞争力接近闭源大模型
- **法律领域排序提升显著**：争议焦点排序任务中 GARL 全面优于单 Agent
- **通用战略决策提升**：不限于法律，任何需要优先级排序的多 Agent 场景

### 2.4 对 Agent 编排的影响

1. **Hermes 任务分配**：可将任务分配建模为博弈——多个 Agent 竞争任务，仲裁者选择最优分配
2. **优先级排序**：daily-paper-push、kanban 等场景可直接应用 GARL 框架
3. **小模型增强**：在智谱/GLM 等小模型上用 GARL 有望接近 GPT-4 级别的战略决策质量

## 三、CollabSim：CSCW 驱动的协作能力评估框架

### 3.1 关键发现

多 Agent 系统失败**不是因为个体能力不足，而是因为协作能力缺失**：

- 无法建立共同理解（Common Ground）
- 无法维持共享任务理解
- 无法平衡个体与集体激励
- 无法在交互中修复对齐偏差

### 3.2 四个协作能力维度

| 维度 | 定义 | 人类 CSCW 对照 |
|------|------|---------------|
| 共同基础建立 | 对任务/环境/角色达成一致 | 共享参考点、术语表 |
| 共享任务理解维护 | 随任务进展持续同步 | 看板、站会、状态更新 |
| 激励平衡 | 个体目标 vs 集体目标 | 绩效考核设计 |
| 对齐修复 | 发现并纠正理解偏差 | 回顾会议、事后复盘 |

### 3.3 评估框架

CollabSim 提供**可配置的模拟环境**：
- 理论驱动的协作能力定义
- 受控的交互条件操控
- 动作级别的内部状态探测

跨四个 LLM 的实验证明 CollabSim 能**分离模型性能模式**，揭示 Agent 设计的任务依赖效应。

### 3.4 对 Hermes 三机协作的启示

当前 Hermes jbot/ubot/abot 三机的协作协议（exchange-protocol）主要关注**数据交换**（经验池、公告），缺少**协作能力评估**。CollabSim 的四个维度可直接用于评估：

1. **共同基础**：三机对同一任务的理解是否一致？（目前靠经验池文本共享，无量化评估）
2. **任务理解**：cron 任务状态是否在三机间同步？（当前各机独立执行 cron）
3. **激励平衡**：各机 Skill 质量是否存在竞争退化？（无竞争机制）
4. **对齐修复**：当经验池信息矛盾时如何解决？（当前无冲突解决机制）

## 四、Agent-Orchestrated Adaptive RAG：自适应检索编排

### 4.1 核心方法

替代静态单步检索，引入三步自适应循环：
1. **动态查询分解**：将复杂查询拆分为子查询
2. **迭代检索**：多轮检索，逐步聚焦
3. **有界自反思评估**：Agent 自我评估检索质量，决定是否继续

### 4.2 关键发现（反直觉）

| 数据集 | 查询分解效果 | 反思机制效果 |
|--------|------------|------------|
| DevOps（结构化域） | ✅ 总分 +0.04, MRR +0.17 | ✅ 引用准确率提升 |
| MuSiQue（多跳推理） | ❅ 排名精度下降 | ⚠ 延迟大幅增加 |

**核心结论**：Agent 增强不是万能的——**必须根据查询和领域特征选择性应用**，而非一味追求更强的推理管线。

### 4.3 对 Hermes RAG 的影响

- **hybrid-search Skill**：当前是静态检索。可引入自适应查询分解（对复杂问题拆分搜索）
- **成本意识**：反思机制的延迟代价显著，需要"成本-收益"权衡（延迟预算控制）
- **场景路由**：结构化查询走分解增强，简单查询走直检

## 五、MARL + Model-Based Control：安全可行的多 Agent 协作

### 5.1 方法融合

- **MARL（多 Agent 强化学习）**：学习协作策略
- **Model-Based Control**：保证动作安全、动力学可行

### 5.2 价值

- 纯 MARL 可能学到不安全的协作策略
- 纯 Model-Based 缺乏适应性
- **融合**：MARL 学策略 + Model-Based 做安全约束 → 安全+自适应

## 六、跨论文共性洞察与趋势

### 6.1 从"通信效率"到"通信范式"

2024-2025 年关注"如何让 Agent 通信更高效"（压缩、缓存）。2026 年开始质疑**自然语言是否应该作为通信协议**本身。潜变量通信标志着从"优化现有协议"到"更换底层协议"的转变。

### 6.2 从"任务完成"到"协作质量"

CollabSim 代表了评估范式的转变：不再只看任务结果，而是**量化协作过程**。这与软件工程中从"代码产出"到"代码质量+团队协作"的演进一致。

### 6.3 从"通用增强"到"场景自适应"

Agent-Orchestrated Adaptive RAG 的反直觉结果表明：**更强的推理管线不一定更好**。2026 年的趋势是"自适应编排"——根据场景选择策略。

### 6.4 博弈论成为多 Agent 标准工具

GARL 表明博弈论不再是理论工具，而是**实用的多 Agent 策略优化框架**。小模型 + 博弈论 = 接近大模型性能，这对资源受限环境（Jetson）意义重大。

## 七、对 Hermes 系统/Skill 的改进建议

1. **agent-orchestration-pattern Skill**：需要 patch 追加潜变量通信的五大设计模式（当前缺少连续表示通信方案）
2. **exchange-protocol Skill**：三机经验交换应增加协作能力评估维度（参考 CollabSim 四维度）
3. **新建 `latent-communication` Skill**：研究 Hermes 三机之间 KV-Cache 共享的可行性
4. **agent-reflexion-workflow Skill**：反思机制的延迟代价需要量化控制（参考 Adaptive RAG 的成本-收益分析）
5. **mcp-integration Skill**：MCP 协议天然是 token 级通信，应评估潜变量通信在 MCP 层的可行性
