归纳总结

一句话总纲：Microduck 的"够用就好"选型哲学——RK3566 四核 A55 同时扛住 50Hz 动作推理 + 舵机通信 + 相机 + 音频（15022 周期仅漏 3 个，0.02%），证明小型双足不需要高价计算模组；真正的选型逻辑不是芯片跑分而是瑞芯微软件生态（RKAIQ/RKNN-Toolkit2/设备树现成路径）；动作策略与视觉实验是两套独立模型——RL 跑 CPU，YOLO11n 量化后跑 NPU，二者尚未闭环。

核心增量（库内已有 5 篇 Microduck 笔记未覆盖的部分）：
- 完整 BOM 级元器件清单（双 IMU 型号、ToF、音频编解码芯片具体型号）
- RK3566 选型逻辑的证据链分析（不是"用了什么"而是"为什么是它"）
- YOLO11n NPU 视觉实验全链（150 帧训练 / INT8 量化 / 25.7ms 实测延迟）——库内首次收录
- 信息边界诚实声明：哪些能确认、哪些仍缺（原理图/PCB/XL330 后缀均未公开）

内容整理：硬件 BOM 与两套模型

BOM 主表（官方公开配置）

模块 型号与厂商 实际作用
主控板 Radxa Zero 3W；Rockchip RK3566 运行 Linux、机器人服务、ONNX 动作策略与相机服务
执行器 15× DYNAMIXEL XL330；ROBOTIS 驱动关节并回报位置、速度、电流、电压、温度
机身 IMU LSM6DSV16X；ST 向动作策略提供角速度、加速度与机身姿态
第二枚 IMU BMI088；Bosch 位于 Robot HAT，当前主控制链尚未使用
前向摄像头 IMX219；Sony MIPI CSI 采集图像
距离传感器 VL53L8CX；ST 8×8 共 64 区 ToF 距离矩阵
音频编解码器 TLV320AIC3104；TI 麦克风 ADC 与播放端 DAC
电池 NP-F550 规格 2S 锂电 标称 2600 mAh，官方续航约 1 小时

关键结构事实：
- 整机 15 枚舵机 ≠ 策略 14 维输出：动作策略只控 14 关节，鸭嘴（第 15 枚）由上层程序单独控制
- 舵机 ID 分段：右腿 10–14，左腿 20–24，头/颈/嘴 30–34；imu_to_dxl v2 总线 ID=200
- 三板架构：Radxa Zero 3W（主控）+ imu_to_dxl v2（IMU 接入舵机总线）+ RPI Robot HAT（挂 BMI088/VL53L8CX/音频），后两块 Pollen 自研，原理图未公开
- 总线分工：15 舵机 + IMU 板共用 1 Mbps Dynamixel 总线；摄像头走 MIPI CSI；Robot HAT 经 I²C 管 ToF/BMI088/音频，音频数据另走 I²S
- 配置细节：Zero 3W 1GB 内存 + 32GB 存储；整机约 780g；XL330 具体后缀（M288-T 或 M077-T）未公开

为什么是 RK3566（选型逻辑证据链）

  1. 供应链事实：瑞芯微 → Radxa（Zero 3W 单板机）→ Pollen → Hugging Face（2025 收购）。无证据表明瑞芯微是 HF 直接供应商——文章纠正了这个常见误写
  2. 性价比档位：65×30mm、5V/2A 供电规格（注意：这是板卡输入要求≠实测功耗）、四核 Cortex-A55 足以同时承接 50Hz 推理 + 舵机通信 + 相机 + 音频 + 蓝牙 + 升级服务
  3. 决定性因素是软件生态：相机链路要 RKAIQ + GStreamer；YOLO 部署要 RKNN-Toolkit2 + RKNPU 驱动 + librknnrt.so——从模型转换、设备树、取流到 NPU 推理全有现成路径，换板 = 全部重新验证
  4. 供货保障：Radxa 官方承诺供货至 2030 年 9 月；系统用 Rockchip BSP 6.1 内核
  5. 实测背书：15022 个控制周期漏 3 个 = 50.0Hz 实测、漏周期率 0.02%
  6. 保留项：Pollen 更新系统文档把 Zero 3W 标为"阶段性目标"，量产主板仍可能调整

模型一：RL 动作策略（CPU 上跑）

项 配置
训练仓库 microduck_rl（mjlab/MuJoCo Warp + rsl_rl PPO）
并行环境 默认 4096 个；平地行走约 1–2 小时出可用步态
网络结构 三层 MLP actor，隐藏层 512/256/128
观测 61 维 3 陀螺仪 + 3 重力方向 + 14 关节位置 + 14 关节速度 + 上次 14 维动作 + 13 维速度/头部/身体指令
输出 14 关节动作（鸭嘴不在内）
奖励 奖励目标线速度/角速度/直立/目标姿态；惩罚滑脚/冲击/动作突变/多余力矩变化
任务族 坐下、起身、踢球、叼取、翻滚、滑轮各有独立配置与策略文件
域随机化 重心/质量/惯量/关节摩擦/电机增益/电池电压/负载压降/控制延迟/编码器偏差/IMU 安装误差/地面条件 + 带齿隙模型
部署 checkpoint → ONNX（观测归一化一并封装）→ 真机 50Hz ONNX Runtime → 缩放/低通/安全限幅 → 舵机目标位置

⚠️ 纠错点：动作策略当前跑在 CPU 上——NPU 不是行走的执行单元，不能混写。

模型二：YOLO11n 视觉实验（NPU 上跑）

项 配置
模型 YOLO11n，输入 320×320，单类别 duck
训练数据 3 次采集共 150 帧；留出 session 上 mAP50=0.976（样本极小，仅适用该实验集）
量化 INT8 量化后 3.9 MB .rknn
算力 RK3566 单核 0.8 TOPS NPU
预处理 CPU 把 1280×720 等比缩放补边到 320×320 → librknnrt.so 调 NPU → 解码边界框
实测延迟 推理+解码中位 25.7ms，P95 58.4ms（30 帧、3 轮、2Hz 基准）
边界 检测结果尚未接入 mediad 实时帧分支，机器人行为拿不到检测框——只能说"检测器已量化并在 NPU 测通"，不能写成已具备自主寻找/跟随/抓取的视觉闭环

仍未公开的拆解信息

XL330 具体后缀、NFC 控制芯片、麦克风/扬声器/功放型号、RAM 与 eMMC 颗粒、电池电芯、两块定制板原理图与 PCB。Alpha 版 MJCF/STL 可核对机械父子关系，但无法证明电子器件机内安装位置——这正是文章不画线缆走线的原因。

方法论借鉴（吸收层）

  1. "够用就好"的证据化表达：文章用"当前负载没有显示出必须使用高价机器人计算模组的理由"替代跑分对比——选型结论用实测漏周期率背书，比堆参数可信
  2. 供应链表述精确性："RK3566 经 Radxa 和 Pollen 进入 HF 旗下产品"≠"瑞芯微是 HF 供应商"——写 BOM 分析时这种间接链路措辞值得照抄
  3. 能力边界三段式：每项能力标注"已确认/未公开/不能写成"——视觉实验"检测器测通"与"视觉闭环"的区分是技术写作范本

查询拓展

  • microduck_rl 仓库的 DR 配置全表（齿隙模型具体参数）→ 对照我们 dp5 训练的 DR 覆盖缺口
  • mediad 实时帧分支接入检测框后的官方进展 → 视觉闭环何时真落地
  • XL330 M288-T vs M077-T 后缀差异（扭矩/减速比）→ 复刻选型刚需，等官方或社区披露
  • RK3566 NPU 0.8 TOPS 上跑更大检测模型（YOLO11s）的可行性边界
  • VL53L8CX 64 区 ToF 在步态落脚点选择中的应用潜力（与 push recovery 落脚点文献呼应）

趋势判断

  1. 小型双足的算力档位正在固化：RK3566 级（A55×4 + 0.8TOPS NPU）成为 $399 档事实标准——"CPU 跑策略 + NPU 跑视觉"双模型分工将成标配架构，单芯片大算力方案在该价位暂无必要
  2. NPU 视觉是大厂下一步必争：HF 收购 Pollen 后视觉实验先行铺路（YOLO + RKNN 全链测通），暗示后续"看到鸭子→走过去"的闭环产品化；检测器与行为解耦发布 = 迭代风险隔离的工程策略
  3. "生态锁定"效应显性化：选 Rockchip 不是选芯片而是选 RKAIQ+RKNN+设备树全家桶，换板成本=全链重验证——国产 SoC 进机器人市场的竞争维度从性能转向工具链完整度
  4. 开源硬件的"半透明"策略：代码/设备树/训练模型开放，但 CAD 可制造文件、原理图、PCB 闭源——生态开放度与商业护城河的平衡点正在被 HF 校准

指南分析

什么时候需要这篇笔记：
- 复刻/移植 Microduck 需要官方 BOM 对照清单时（直接查元器件表）
- DUCK-Pi_5 bring-up 验收需要漏周期率量化指标时（0.02% 基准）
- ASC/视觉项目需要 RKNN 量化部署链参考时（预处理→量化→延迟实测全流程）
- 写硬件选型报告需要"生态优先于性能"论证模板时
- 与人讨论 Microduck 时纠正两个高频错误：NPU 不跑行走策略；15 舵机≠14 维输出

风险提示：文章基于 2026-09 公开工程配置，量产版主板可能换（官方文档已把 Zero 3W 标为阶段性目标）；1GB 内存配置对自主任务扩展是潜在瓶颈。

拓展应用推荐

  1. DUCK-Pi_5 立即可做：把"漏周期率"加入 bring-up 验收脚本（count missed cycles / total cycles，对标 0.02%）
  2. ASC 项目移植：抄 YOLO11n INT8 量化链（320×320 输入 + 等比缩放补边预处理），若 ASC 后续换 RK3566 类主控可直接复用 .rknn 流程
  3. 训练线对照：官方 DR 含"编码器偏差 + IMU 安装误差 + 齿隙"三项，检查我们 dp5/mjlab 训练配置是否覆盖（未覆盖项是 sim2real gap 候选源）
  4. 舵机 ID 重映射工具：官方分段 ID（10/20/30 段）与我方线性 ID 的映射表应固化为脚本常量，防迁移配置时静默错位
