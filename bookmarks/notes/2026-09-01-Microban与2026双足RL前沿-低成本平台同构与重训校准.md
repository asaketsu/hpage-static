## 一、内容整理

### 1.1 Microban：与 DUCK-Pi_5 最同构的开源平台

Rhoban（法国波尔多机器人俱乐部，RoboCup 老牌强队）2026 年发布的全开源小人形，241 星 / 26 fork / 224 commits：

```
身高        30cm，桌面级
主控        Raspberry Pi Zero 2W（DUCK-Pi_5 是 Pi 5，同生态）
舵机        19 × Dynamixel XL330-M288-T（与 microduck 官方同款！）
扩展板      Pollen RPI Robot Hat（Pollen Robotics = microduck 母公司）
电池        2 × 18650 + BMS，USB-C 充电
结构件      ~30 个 3D 打印件（PLA，0.12mm 层高，15% 填充）
轴承        12 × 钢/POM 垫片（替代无空转法兰舵机的滚针轴承）
许可        双许可：软件 GPL v3 / 硬件与文档 CC BY-NC-SA 4.0（商用需授权）
```

**关键工程细节**：

- CAD 提供 STL + STEP 双格式 + Onshape 在线装配模型，**设计时显式标注 19 自由度的运动范围，并在结构中集成机械限位（stops）控制自碰撞**，走线也在 CAD 阶段预留——这是 RoboCup 级的硬件成熟度。
- 配套完整文档链：BOM（含采购链接）→ printing.md（打印取向指南）→ assembly.md → deployment.md → usage.md（键盘/手柄控制+自定义动作）。
- 当前软件栈是**演示/教育取向**（keyframe 动作驱动，非 RL 策略）——「first steps」视频是预编排步态。这与 microduck（RL 策略 ONNX 热插拔）形成互补：Microban 强在机械与文档，microduck 强在 RL 栈。

### 1.2 与 DUCK-Pi_5 的同构对照（为什么值得跟踪）

两者共享同一硬件基因：XL330 舵机 + Pollen 生态扩展板 + Raspberry Pi 主控 + 全 3D 打印结构。差异与可借鉴点：

- **19 DoF vs 15 DoF**：Microban 多出双臂（每臂 2 DoF）——DUCK-Pi_5 未来若加臂可参考其肩部结构。
- **机械限位进 CAD**：DUCK-Pi_5 的 3D 打印件设计清单里应对齐此项——RL 策略失控时机械限位是最后防线，比软件限位（NaN refuse/deadman）更底层。
- **垫片替代轴承**：XL330 无空转法兰版本需要钢/POM 垫片方案，DUCK-Pi_5 舵机选型（STS3215 替换）同样会遇到输出轴支撑问题。
- ** licenses 警示**：硬件 CC BY-NC-SA——若未来 DUCK-Pi_5 借鉴 Microban 结构件设计，非商用没问题，但衍生设计须同许可公开。

### 1.3 2026.01-02 双足 RL 论文精选（awesome-humanoid-robot-learning 时间线）

从 Ze（YanjieZe，福建开源机器人圈核心开发者）维护的 awesome 列表 2026 年条目中筛出与重训直接相关的：

**① Toward Reliable Sim-to-Real Predictability for MoE-based Robust Quadrupedal Locomotion（arXiv 2026.02）**

核心命题：sim2real 的**可预测性**（predictability）本身作为优化目标——不只是「迁移成功」，而是「仿真表现能在真机上被可靠预测」。MoE（混合专家）结构用于鲁棒运动。对重训的价值：+555g 增重场景下，仿真 reward 高≠真机好，把 sim2real gap 本身纳入训练目标是 2026 年的新共识。

**② FastStair: Learning to Run Up Stairs with Humanoid Robots（arXiv 2026.01）**

人形跑上楼梯——展示 2026 年 RL 步态已从平地走向垂直地形。方法参考价值有限（DUCK 是桌面鸭），但标志「动态步态天花板」持续抬高。

**③ AME-2: Agile and Generalized Legged Locomotion via Attention-Based Neural Map Encoding（arXiv 2026.01）**

注意力机制的神经地图编码替代传统高度图扫描——泛化到未见地形。对 obs 设计的启示：61D obs 契约中环境感知块未来可用 attention 编码压缩。

**④ RPL: Learning Robust Humanoid Perceptive Locomotion on Challenging Terrains（arXiv 2026.02）**

感知运动一体化（perceptive locomotion）在挑战地形的鲁棒学习——与 ④ 同主题的 STATE-NAV（2025.12，双足导航稳定性感知地形估计）共同指向：**感知不再只是 VLA 的事，运动策略本身开始吃感知输入**。

**⑤ LocoFormer: Generalist Locomotion via Long-Context Adaptation（arXiv 2025.09）**

Transformer 骨干 + 长上下文在线适应——泛化运动控制的通用模型路线。与 MLP 策略（microduck 现用）的对比：长上下文让策略在测试时「边走边适应」，等价于隐式 system identification。

### 1.4 综述校准：双足 DRL 两大流派的 2026 状态（arXiv 2404.17070 v7）

- **系统辨识派**：接受仿真永远不完美 → DR（域随机化）+ RMA 在线适应 + teacher-student 蒸馏。
- **先验知识派**：模型基先验 + RL 微调（feedforward 补偿 + 策略反馈调节），2026 年新证据（MDPI PFRL 框架，平行伸缩腿双足）显示**不用 DR、不用复杂 reward 也能 sim2real**——前馈运动补偿+策略网络反馈调节的协同机制足够。
- 层级控制（HL 决策 + LL 平衡/跟踪）仍是轮腿/复杂平台的主流架构。

## 二、查询拓展

### 2.1 Rhoban 与 Sigmaban 谱系

Microban 名字直接继承 Rhoban 的 RoboCup 人形 Sigmaban 系列（Sigmaban 3/4 是法系 RoboCup 冠军级平台）。Sigmaban 的 meta-bodi 软件框架（C++、Eigen、Rhoban 系 motion engine）是 Microban src/ 的基础。跟踪价值：RoboCup 人形的**keynote 步态引擎**（capture step / model predictive control）是 RL 之外的另一条成熟技术路线。

### 2.2 Pollen Robotics 生态位

Pollen（Reachy 机械臂母公司）的 RPI Robot Hat 是 microduck + Microban 共同的电源/总线枢纽。DUCK-Pi_5 已采用 Pollen 生态（XL330 BAM 电压模型），Microban 的 18650+BMS+USB-C 电源方案是比当前 BEC 方案更集成的参考（虽然 2S 锂电 7.4V 需升压到 5V，效率与浪涌要实测）。

### 2.3 Sim2Real gap 的三层分解（综述共识）

物理参数 gap（质量/摩擦/执行器延迟）→ 用 DR 覆盖；传感器 gap（噪声/延迟/丢帧）→ 用观测噪声注入+history 编码；任务语义 gap（地形/接触）→ 用课程学习。DUCK-Pi_5 的 +69% 增重属于第一层的**系统性偏移**而非分布覆盖问题——这是「重训」而非「微调」能解的根本原因（与 08-31 定案一致）。

## 三、归纳总结

### 3.1 2026 低成本双足平台技术栈收敛图

```
                    低成本双足/人形平台 2026 收敛栈
┌─────────────────────────────────────────────────┐
│ 主控   Raspberry Pi 系（Zero 2W ~ Pi 5）          │
│ 舵机   XL330 系（18-55g）或 STS3215（55g 扭矩型） │
│ 总线   单线半双工 TTL（500kbps-4Mbps）+ 扩展板    │
│ 电源   2S 锂电+BMS / BEC 5V，缓启动 MOSFET        │
│ 结构   全 3D 打印 PLA + 机械限位 + 垫片轴承       │
│ 软件   分野：keyframe 演示（Microban）            │
│         vs RL 策略热插拔（microduck ONNX 61D）    │
│ 训练   mjlab/IsaacLab + PPO + DR + teacher-stu.  │
└─────────────────────────────────────────────────┘
```

### 3.2 对 DUCK-Pi_5 重训计划的三点校准

- **校准1——DR 范围必须覆盖质量系统性偏移**：microduck 官方质量 DR 仅 ±5% 且只随机 trunk_base，这在同构复刻下够用；换 STS3215 后 +69% 是**分布外**，重训时质量 DR 范围应至少覆盖整机质量的 ±30%（含连杆分布），摩擦/延迟 DR 按综述标准配置。
- **校准2——先验知识派提供了降风险备选**：若纯 RL 重训首轮失败，PFRL 式「前馈补偿+策略反馈」混合路线是 fallback——用 nominal 模型算前馈力矩，RL 只学残差，样本效率和稳定性都更好。
- **校准3——sim2real 可预测性应写进验收标准**：不只看仿真 reward，W3 吊架首走前的 URDF+60g 回放（已在计划中）正是可预测性检查；可再加「仿真中注入实测舵机延迟/背隙后的性能衰减曲线」作为上电前 gate。

## 四、趋势判断

### 趋势1：低成本开源人形进入「文档与机械成熟度」竞争阶段

依据：Microban 把机械限位、走线、垫片轴承、打印取向全部工程化进 CAD 与文档链；soft Robotics 类平台（asimov-v0 781 星）同步在涨。RL 栈（microduck/mujoco playbook）趋于同质化后，**装配体验与可靠性设计**成为差异化。

### 趋势2：sim2real 从「迁移技巧」升级为「可预测性科学」

依据：2026.02 MoE 四足论文把 predictability 作为显式目标；LocoFormer 的长上下文在线适应本质是把 system identification 内化进策略。评测范式从「真机上走起来了」转向「仿真-真机性能相关性有多高」。

### 趋势3：XL330 级舵机平台与 STS3215 级平台将形成两档生态

依据：Microban/microduck 守 18-20g XL330 档（轻、贵、精度高）；DUCK-Pi_5 换 STS3215 后进入 55g 扭矩档（重、便宜、扭矩大）。两档平台的 obs/act 契约与 DR 配置不可直接互换——这正是上游无 .pt ckpt 必须重训的生态原因，也意味着重训产物对 STS3215 档其他 DIY 双足有复用价值。

### 趋势4：RoboCup 系 keyframe 引擎与 RL 策略将走向混合

依据：Microban（keyframe）与 microduck（RL）共享同一硬件生态，社区必然出现「RL 步态 + keyframe 手臂动作」的混合栈；DUCK-Pi_5 的 beak/tail 直接指令通道（61D/14 契约里走非 RL 路径）已经是这个方向的微缩实现。

## 七、行动启示

- **W0/W1 期间**：对照 Microban CAD 检查 DUCK-Pi_5 打印件机械限位覆盖度（15 关节全查），缺限位的关节在首上电前补打限位件——成本 1 小时，避免一次RL失控撞毁舵机（55g STS3215 惯量更大，碰撞损伤 > XL330）。
- **M3 重训配置**：质量 DR 扩到 ±30%（全连杆），摩擦 ±0.2，加入舵机背隙/延迟随机化；验收标准加「注入实测扰动后性能衰减 <30%」gate。
- **fallback 预案**：纯 RL 首轮失败 → 切 PFRL 残差学习路线（nominal 前馈 + RL 残差），样本需求更低。
- **跟踪清单**：Microban repo（watch releases，等 RL 栈）+ awesome-humanoid-robot-learning 月度 diff。

## 九、指南分析

**与 DUCK-Pi_5 时间线的对接（按周排）**：

- **W0/W1（当前）**：打印件限位覆盖度检查——对照 Microban CAD 的 stops 设计，逐关节核查 C047/C001 版本，缺口件补打（约 1 小时/关节，PLA 即可）。此项为一票否决级：STS3215 惯量大，无机械限位的首上电风险不可接受。
- **W2（标定联调期）**：实测采集舵机阶跃响应（延迟/超调/背隙），记录为重训 DR 参数的实测锚点——DR 范围不是拍脑袋，以实测值 ±margin 定。
- **W3（重训启动）**：M3 配置按本笔记校准 1-3 执行；URDF+60g 回放通过后，加跑「注入实测扰动」的衰减测试，衰减 <30% 才进吊架首走。
- **应急分支**：纯 RL 首轮 reward 不收敛或吊架首走失败 → 切 PFRL 残差路线（nominal 前馈 + RL 残差），训练预算砍半重试。

**资源边界提醒**：训练在 AutoDL 4090（已租），本机 Jetson 只做代码管线与推理冒烟——与既有铁律一致，勿在本机起训练进程。
