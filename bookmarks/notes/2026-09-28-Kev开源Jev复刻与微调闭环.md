## 一、它是什么

Kev = 建在 **Qwen3.5/Qwen3.8** 上的一族可自训自部署的 Jev 式决策模型，架构依据《Jev's Architecture Unmasked》。**API 与 TypeSafe System One 对齐**——TypeSafe Python SDK 直接指向本地 Kev 服务器，不用改代码。

- 一次请求同时问 noul（是否）/choice（多选）/score（评分），共享文本但**彼此读不到对方**
- 默认带校准概率：每个 checkpoint 附带留出数据上拟合的温度
- 四个尺寸：0.8B（笔记本）→ 4B → 9B → 27B（单张数据中心 GPU）
- 可在自己标注样本上微调；一条命令部署 HTTPS 端点，空闲缩容到零

## 二、与 Jev 正面对比（Brier 分数，开发/测试）

| 模型 | 基座 | 新数据源 | 已训数据源 |
|---|---|---|---|
| Kev-0.8B | Qwen3.5-0.8B-Base | 0.648 / 0.697 | 0.827 / 0.838 |
| Kev-4B | Qwen3.5-4B-Base | 0.817 / 0.838 | 0.873 / 0.865 |
| Kev-9B | Qwen3.5-9B-Base | 0.822 / 0.852 | 0.872 / 0.874 |
| Kev-27B | Qwen3.8-27B 后训练 | **0.848 / 0.896** | 0.866 / 0.870 |
| Jev | 托管闭源 | 0.857 / – | 0.845 / – |

- 「新数据源」= 训练时从未见过的数据集和策略规则——**最接近你自己问题的设置**
- 方法论三点：开发集挑 checkpoint、每模型只读一次测试集、Jev 只在开发集跑过；Brier 评**整个概率分布**非只评最高分
- 关键自我限制：**27B 与 Jev 差一个点内，但不知道 Jev 训练数据，所以不是受控比较**——没把"追平 Jev"说成已证明结论

## 三、微调闭环（全文最有价值部分）

三步：`npx skills add jaredpalmer/kev@kev-finetune` → 跟 agent 说"帮我在我的客服工单上微调 Kev" → 它自己做完全部。

Skill 七步工作流：**采访你 → 找到你代码里已在问 Jev/TypeSafe 的问题 → 转换已有标签（或用 LLM 生成足量数据测增益）→ Modal 上从已发布 checkpoint 微调 → 留出切片拟合温度 → 与未动模型对比打分 → 部署端点并拆干净**。
- 不需要本地 GPU、不用克隆仓库；Kev-4B 一次训练 H100 约 **$1**

**增益实测（含诚实的边界声明）**：
- 示例客服负载（3 问/1050 条/H100 15min）：4B 67.7%→**73.6%**，"5% 错误预算下可自动化决策比例" 34%→**48%**
- 真实数据（5219 条消费金融投诉 1 epoch）：未见投诉 0.804→**0.904**
- **但**："增益是分布内的——告诉你 Kev 学你的任务多好，不代表其他一切表现"；**400 条以下增益在噪声内**

## 四、验证与训练细节

- **问题隔离验证**：一起问 vs 分开问，fp32 概率差异 <4e-6——"问题互相隔离"设计是真的
- 每个 checkpoint 校准温度：0.8B T=2.41 / 4B T=2.14 / 9B T=2.30，存 head.pt，开箱即校准概率非原始 softmax
- decision-v7 训练套件：10,000 条公开记录（10 源×1000）+ 896 条 policy + 60 个规则结构 1680 条；2 epochs，LoRA rank 16，正确答案交叉熵；lr 0.8B=1e-4（OneCycle），4B/9B=5e-5；**未使用任何 Jev 输出**

## 五、💡 对我们的价值分析

### ✅ 已在做的（印证方向）
- Jev 三部曲前两篇（09-27 实现/09-28 架构）已把决策层蓝图立起来——本篇补上"开源可自训"这块拼图，且 Jetson 可跑 0.8B 档
- "七步微调 skill 从现有代码找问题而非从零想" ≈ 我们的 session-evolution-scan 从会话纠偏里找信号（同款"从已有工作流采信号"思想）

### ⚠️ 可改进的（差距）
- 我们还没有任何决策模型微调链路——若 news-aggregator/日志分诊试点跑出价值，下一阶就是"用积累的纠偏数据微调 Kev-4B"（H100 $1/次的成本完全可接受，AutoDL 4090 也能跑 4B LoRA）
- 校准温度实践缺失：我们 logprobs 实现篇提了校准但没落地——Kev 的 head.pt 模式（每 checkpoint 带温度）是可直接抄的工程方案

### 🔥 重点行动
1. **收藏 Kev 仓库**（github.com/jaredpalmer/kev）：Jev 试点验证后如需私有化/降本，4B 在 AutoDL 4090 上 LoRA 微调可行
2. **校准温度进 logprobs 试点**：本地 logprobs 读出后先在标注样本上拟合 T 再输出概率——Kev 证明这是标配而非可选项
3. **积累纠偏标注数据**：session-evolution-scan 的候选清单天然是"问题+人工裁决"对——存成 Kev 微调格式，未来一条龙（正好呼应 dontbesilent 篇的"经验→规则"，这里是"经验→数据→模型"）

## 六、内容整理（归纳总结与关联分析）

**归纳总结**：Kev = Jev 的 Apache-2.0 复刻（Qwen3.5/3.8 底座，0.8B-27B 四档，API 兼容 TypeSafe SDK），三件超越前人（OpenJev/von/Reflex 停在推理层）的事：①问题隔离经 4e-6 验证 ②每 checkpoint 自带校准温度 ③"采访→找现有问题→转标签→$1 微调→对比→部署"七步闭环。27B 新数据源 0.848 vs Jev 0.857（作者自认非受控比较）；微调增益实在（0.804→0.904）但明说分布内、<400 条是噪声。

**关联分析**：Jev 四部曲至此完整——①09-27 logprobs 实现篇（机制可 25 行复现）→②09-28 架构篇（决策契约/置信度路由）→③本篇 Kev（开源+微调闭环）→④dontbesilent 篇（规则/标注数据从人类经验来）。四篇构成决策层的完整价值链：**人的经验 → 标注数据 → 微调决策模型 → 架构化路由 → 廉价推理**。yibie 作为信源连续两天出现在 Jev 生态（09-27 博客转发+本篇），值得列为该领域观察哨。

## 八、趋势判断

1. **决策模型赛道进入"开源追平闭源"阶段**：27B 差一个点的开源实现 + $1 微调成本，意味着闭源 Jev 的溢价窗口在收窄——重演 LLM 赛道剧本
2. **微调 skill 化是 agent 时代的新分发形态**：`npx skills add` 一条命令把 ML 微调管线送达普通开发者——"skill 即模型分发渠道"
3. **诚实的评估文化成为开源项目的差异化竞争力**：主动交代"非受控比较/分布内增益/噪声边界"的项目赢得信任——与 benchmark-selfreport-audit 的六道滤网精神一致
4. **校准温度将成为决策模型标配**：从"输出原始 softmax"到"输出可被阈值路由的概率"，T 拟合是最后一公里

## 九、指南分析（怎么用这篇文章）

- 选型速查：Jetson/本地=Kev-0.8B；AutoDL 4090=4B/9B 微调；要最好效果=27B；不想管=直接 Jev API
- 微调前先估数据量：<400 条别训（噪声内）；1000+ 条再动手（1050 条案例有效）
- 部署最省事路径：Modal 账号+一条命令，不用克隆仓库
