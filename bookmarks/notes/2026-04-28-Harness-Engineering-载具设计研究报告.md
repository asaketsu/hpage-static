# Harness Engineering 驱动的垂域 LLM 在多领域载具设计中的应用研究

## 摘要

2026 年初，Anthropic 和 OpenAI 几乎同一周发布了关于 Harness Engineering 的实践文章，标志着 AI 工程从 Prompt Engineering → Context Engineering → Harness Engineering 的第三次范式跃迁。Harness Engineering 围绕 AI Agent 设计整个运行时环境，通过**约束（Constraints）、工具（Tools）、反馈（Feedback）**三层框架，使 Agent 在复杂环境中可靠运行。

本研究将 Harness Engineering 的三层框架系统性地映射到**航空、航天、无人机、运载火箭**等多领域载具设计的垂域 LLM 应用中。核心发现：

1. **约束层**：适航规章、物理定律、制造工艺限制等硬约束，可形式化为 Agent 的 Guides（前馈控制）
2. **工具层**：CAE 仿真、数字孪生、MBSE 工具链等工程软件栈，构成 Agent 可调用的工具集
3. **反馈层**：应力校验、收敛检测、多学科冲突仲裁等质量门禁，对应 Agent 的 Sensors（反馈控制）

研究表明，Harness 思维与航空领域的"适航认证"在本质上是**同构**的——两者都是给自主系统套上约束，使其在复杂环境中可靠运行。本文提出六种 Harness 架构模式在载具设计中的适配方案，并给出分阶段实施路线图。

**关键词**：Harness Engineering；垂域大模型；载具设计；多 Agent 协作；航空适航；物理增强 AI

## 第一章 引言

### 1.1 研究背景

载具设计（包括民用飞机、军用飞行器、航天器、运载火箭、无人机等）是工程领域最复杂、约束最严苛的系统性活动之一。一个现代商用飞机的设计涉及**数十万个零部件**、**数百个子系统**、横跨**结构、气动、动力、航电、飞控、隐身**等多个学科。设计周期长达 10-15 年，单次物理破坏性试验成本可达数百万至数千万元。

与此同时，大语言模型（LLM）正在从通用能力加速向**垂域化**演进。2025-2026 年的行业共识是：7B-70B 级别开源模型 + 行业知识微调/蒸馏，成为垂域模型的主流技术路线。在航空领域，NASA 已开展航空专用 LLM 的微调与评估研究 [NASA 2025]，IEEE SMC 发表了 LLM 推动商业航天技术创新智能化的专题论文 [IEEE 2025]。

然而，**垂域 LLM 在载具设计中的应用面临一个根本性挑战**：载具设计不是文本生成任务，而是一个受物理定律、安全标准、制造工艺三重约束的工程求解过程。通用 LLM 可以生成"看起来合理"的设计方案，但无法保证其物理可行性、适航合规性和可制造性。

### 1.2 问题定义

本研究聚焦以下核心问题：

> **如何将 Harness Engineering 的「约束—工具—反馈」三层框架融入垂域 LLM 系统，使其在多领域载具设计中可靠地发挥作用？**

具体拆解为三个子问题：

1. **约束如何形式化？** 适航规章（如 CCAR-25）、物理定律（如 Navier-Stokes）、制造工艺限制（如 3D 打印角度）如何编码为 Agent 可理解的约束？
2. **工具链如何编排？** CATIA/NX、Abaqus/Ansys、Nastran 等工程软件栈如何作为 Agent 工具集集成？
3. **反馈如何闭环？** 仿真结果校验、多学科冲突检测、适航合规审计如何构建自动化的质量门禁？

## 第二章 三层框架映射：约束·工具·反馈 → 载具设计场景

### 2.1 框架总览

Harness Engineering 的核心结构是 **Guides + Sensors** 的前馈-反馈控制闭环。在载具设计场景中，我们将这一结构细化为三层可操作的框架：

```
┌─────────────────────────────────────────────────────────────┐
│                    Harness for Vehicle Design                │
│                                                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐  │
│  │  约束层       │  │  工具层       │  │  反馈层           │  │
│  │  Constraints  │→│  Tools       │→│  Feedback         │  │
│  │  (Guides)     │  │  (Actions)   │  │  (Sensors)        │  │
│  │              │  │              │  │                  │  │
│  │ • 适航规章    │  │ • CAD/CAE    │  │ • 应力校验        │  │
│  │ • 物理定律    │  │ • 仿真求解器  │  │ • 收敛性检测      │  │
│  │ • 制造工艺    │  │ • 优化算法   │  │ • 合规性审计      │  │
│  │ • 材料极限    │  │ • 数字孪生   │  │ • 多学科冲突仲裁  │  │
│  └──────────────┘  └──────────────┘  └──────────────────┘  │
│         ↕                  ↕                  ↕             │
│  ┌──────────────────────────────────────────────────────┐   │
│  │           垂域 LLM（航空/航天专用模型）                │   │
│  │    7B-70B 开源基础 + 行业数据微调 + RAG 知识增强       │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 约束层（Constraints → Guides）

约束层是 Harness 的前馈控制组件，**在 Agent 行动之前引导它做对**。在载具设计中，约束来源可分为四个层次：

#### 2.2.1 法规级约束（Regulatory Constraints）

| 约束类型 | 典型规范 | 形式化方式 |
|----------|----------|------------|
| 适航标准 | CCAR-25（运输类飞机）、FAR-25、EASA CS-25 | 条款 → RAG 知识库 + 结构化规则引擎 |
| 航天标准 | NASA-STD-5009、ECSS-E-ST-32-08C | XML/JSON Schema 约束定义 |
| 军用标准 | GJB 系列、MIL-STD-1530D | 知识图谱节点 + 属性约束 |
| 环保法规 | ICAO Carbon Offsetting (CORSIA) | 排放计算公式嵌入 |

**实现路径**：将适航规章拆分为**原子条款**（每条有唯一编号、适用条件、合格判据），构建向量化的 RAG 知识库。Agent 在生成设计方案时，实时检索相关条款并校验合规性。

#### 2.2.2 物理级约束（Physical Constraints）

| 约束类型 | 物理方程 | 嵌入方式 |
|----------|----------|----------|
| 结构力学 | 弹性力学方程、von Mises 屈服准则 | Physics-Informed Neural Networks (PINNs) |
| 流体力学 | Navier-Stokes 方程 | PINNs + CFD 代理模型 |
| 热力学 | Fourier 导热方程、Stefan-Boltzmann 辐射 | 边界条件约束 |
| 动力学 | Newton-Euler 方程、Lagrange 方程 | 运动学约束嵌入 |
| 材料失效 | Paris 疲劳裂纹扩展、Tsai-Wu 准则 | 复合材料失效包络面 |

**关键洞察**：PINNs 在 2025-2026 年取得了突破性进展。NVIDIA GTC 2025 展示：25 亿单元仿真从 2048 CPU 核心×1 个月 → 320 GH200 芯片×6 小时。这使得将物理方程嵌入实时设计循环成为可能。

#### 2.2.3 制造级约束（Manufacturing Constraints）

- **3D 打印**：最小壁厚、悬垂角度（<45°）、支撑结构可达性
- **CNC 铣削**：刀具可达性、最小内角半径、装夹定位
- **复合材料铺放**：纤维路径连续性、铺层顺序约束、固化工艺窗口
- **焊接/铆接**：焊缝间距、热影响区宽度、紧固件边距

**实现路径**：将制造工艺约束编码为**几何规则集**，在 Agent 生成设计后自动执行 DFM（Design for Manufacturing）检查。

#### 2.2.4 运营级约束（Operational Constraints）

- 载荷包线（2.5g -1g 巡航载荷工况）
- 环境谱（温度循环、湿度、腐蚀环境）
- 维修可达性（检修口尺寸、工具操作空间）
- 全寿命成本目标（制造成本 + 运营成本 + 维修成本）

### 2.3 工具层（Tools → Actions）

工具层定义了 Agent 可以执行的动作空间。载具设计中，垂域 LLM Agent 的工具集可划分为五大类：

#### 2.3.1 几何建模工具

| 工具 | 功能 | API 接入方式 |
|------|------|-------------|
| CATIA/NX | 参数化三维建模 | Python scripting + CAA API |
| OpenSCAD/FreeCAD | 程序化几何生成 | CLI + Python API |
| Grasshopper | 拓扑优化 + 参数化设计 | Python 远程调用 |
| 生成式设计引擎 | AI 驱动的拓扑/形貌优化 | REST API + GPU 推理 |

#### 2.3.2 仿真分析工具

| 工具 | 功能 | Agent 调用方式 |
|------|------|---------------|
| Abaqus/Ansys | 有限元结构分析 | Python 脚本驱动，解析 .odb/.rst 结果文件 |
| Nastran/Patran | 模态/颤振/气动弹性 | DMAP 语言 + Python 包装层 |
| Fluent/OpenFOAM | CFD 气动分析 | 命令行 + Python API |
| LS-DYNA | 碰撞/坠撞仿真 | 关键字文件生成 + 结果解析 |

#### 2.3.3 优化算法工具

- **拓扑优化**：SIMP 方法、水平集法、扩散模型驱动的生成式设计
- **多学科优化（MDO）**：基于代理模型的优化框架（如 OpenMDAO）
- **多目标优化**：Pareto 前沿搜索 + 人类偏好引导

#### 2.3.4 知识检索工具

- **RAG 引擎**：向量数据库（Milvus/Weaviate）存储适航规章、设计手册、历史案例
- **知识图谱**：Neo4j 存储材料属性、失效模式、设计规则的关系网络
- **文献检索**：arXiv + Semantic Scholar API 获取最新研究成果

#### 2.3.5 数字孪生工具

- **实时状态监控**：传感器数据流 → 结构健康评估
- **寿命预测**：疲劳累积损伤模型 + 裂纹扩展预测
- **虚拟试验**：基于高置信度仿真替代部分物理试验

### 2.4 反馈层（Feedback → Sensors）

反馈层是 Harness 的反馈控制组件，**在 Agent 行动之后帮它自我纠正**。在载具设计中，反馈机制可分为五个层次：

#### 2.4.1 单点校验（Point Validation）

```
Agent 生成设计方案 → 运行有限元分析 → 检查最大应力 → 
  if σ_max > σ_allowable: 标记为「不合规」，反馈修改建议
  else: 通过，进入下一轮
```

#### 2.4.2 收敛性检测（Convergence Detection）

- 仿真求解收敛性：残差是否满足收敛判据
- 优化迭代收敛性：目标函数变化率 < 阈值
- Agent 行为收敛性：连续 N 轮迭代输出变化 < ε

#### 2.4.3 合规性审计（Compliance Audit）

自动化适航合规检查流程：
1. Agent 提交设计方案 →
2. 提取关键设计参数（材料、尺寸、载荷、安全系数）→
3. 自动匹配相关适航条款 →
4. 逐条校验合格/不合格/需补充分析 →
5. 生成合规性检查清单（Compliance Checklist）

#### 2.4.4 多学科冲突仲裁（Multi-disciplinary Conflict Resolution）

```
结构 Agent: 建议加厚蒙皮（减重优先级低）
气动 Agent: 反对加厚（影响气动外形）
隐身 Agent: 支持特定区域加厚（RCS 优化）
───────────────────────────────────────
仲裁 Agent: 综合权重决策 → 输出 Pareto 最优解集
```

#### 2.4.5 人类专家审查（Human Expert Review）

对于安全关键决策（如安全系数取值、材料替换、工艺变更），反馈层设置**人工确认门禁**：

- Agent 生成建议 + 置信度评分
- 置信度 > 95%：自动通过（低风险场景）
- 置信度 80-95%：自动通过但标记供后续审查
- 置信度 < 80%：必须经人类专家确认

### 2.5 三层框架的协同机制

三层不是线性流水线，而是**嵌套的闭环系统**：

```
约束层 ──定义──→ 工具层的可用动作空间
工具层 ──执行──→ 产生设计方案
反馈层 ──校验──→ 方案是否满足约束
反馈层 ──反哺──→ 修正约束层的规则（如发现新失效模式）
约束层 ──更新──→ 工具层的参数范围
```

这一协同机制的核心是：**约束定义了边界，工具在边界内探索，反馈验证探索结果并修正边界**。这与经典控制理论中的"模型预测控制"（MPC）思想高度一致。


## 第三章 多领域载具设计案例分析

本章将 Harness 三层框架应用于四种典型载具设计场景，展示框架的通用性和领域特异性。

### 3.1 民用飞机结构设计

#### 3.1.1 场景描述

设计某型窄体客机机翼与机身连接接头，7075-T651 铝合金，需满足 CCAR-25 部强度要求，X 方向极限载荷 50 吨，优先减重，可考虑 3D 打印制造。

#### 3.1.2 Harness 配置

| 层次 | 具体实现 |
|------|----------|
| **约束** | CCAR-25.305（强度与变形）、25.307（结构验证）；von Mises 屈服准则 σ_yield = 455 MPa；3D 打印最小壁厚 0.5mm、悬垂角 <45°；疲劳寿命 > 60000 飞行小时 |
| **工具** | 自然语言→CAD API（生成参数化接头几何）；Abaqus Python 驱动（自动网格划分 + 边界条件）；SIMP 拓扑优化器；CCAR-25 RAG 知识库 |
| **反馈** | 应力集中系数 Kt < 3.0 检查；疲劳损伤度 D < 1.0 验证；制造可行性 DFM 自动审计；人类强度专家审查（最终确认） |

#### 3.1.3 Agent 工作流

```
1. 工程师输入自然语言需求
2. LLM 解析需求 → 识别关键参数（材料、载荷、约束）
3. 检索 CCAR-25 相关条款 → 确定安全系数和合格判据
4. 调用拓扑优化 → 生成初始构型
5. 运行有限元分析 → 检查应力和变形
6. if 不合规: LLM 分析失败原因 → 修改参数 → 回到步骤4
7. 疲劳寿命评估 → 生成适航报告草稿
8. 人类专家审核 → 批准/修改
```

**关键创新**：步骤 2-7 完全由 Agent 自主完成，人类仅在步骤 1（定义需求）和步骤 8（最终审查）介入。设计周期从传统的 2-3 周压缩至 1-2 天。

### 3.2 航天器结构设计

#### 3.2.1 场景描述

设计某型低轨通信卫星的主承力结构（中心承力筒 + 舱板），需承受发射阶段的振动和噪声载荷，在轨运行 15 年，质量预算严格。

#### 3.2.2 Harness 配置

| 层次 | 具体实现 |
|------|----------|
| **约束** | ECSS-E-ST-32-08C（航天器结构设计）；准静态载荷包络（轴向 6g、横向 2g）；声振环境谱；热循环 -40°C ~ +80°C；辐射环境约束（材料退化系数）；质量预算 < 50 kg |
| **工具** | 蜂窝夹层结构设计工具；Nastran 模态分析；随机振动分析（PSD 输入）；热-结构耦合分析；ECSS 标准 RAG |
| **反馈** | 基频要求 > 30 Hz（一阶）检查；质量/面积比达标验证；疲劳累积损伤计算；热变形对天线指向精度影响评估 |

#### 3.2.3 特殊挑战

航天器设计的独特约束在于：
- **一次性使用**：发射阶段不可维修，任何结构失效意味着任务失败
- **极端环境耦合**：振动 + 声学 + 热循环 + 辐射 + 真空，多物理场同时作用
- **质量极度敏感**：每公斤发射成本约 $2,000-10,000（取决于轨道和火箭）

这些特性使得航天器结构设计的 Harness 需要**更严格的反馈门禁**和**更保守的安全裕度**。与航空的"损伤容限"设计理念不同，航天器更倾向于"安全寿命"设计。

### 3.3 无人机系统设计

#### 3.3.1 场景描述

设计某型中型固定翼无人机的机翼结构，碳纤维复合材料铺层，翼展 6m，需兼顾气动效率、结构效率和电磁隐身。

#### 3.3.2 Harness 配置

| 层次 | 具体实现 |
|------|----------|
| **约束** | 复合材料 Tsai-Wu 失效准则；铺层顺序约束（对称均衡）；最小铺层比例要求（0°/±45°/90°）；翼尖挠度 < 翼展 5%；RCS 截面积 < 阈值 |
| **工具** | 复合材料铺层优化器；XFLR5/OpenVSP 气动分析；FEKO 电磁仿真；多学科优化框架（OpenMDAO） |
| **反馈** | 层间剪切应力校验；气动弹性稳定性（颤振速度裕度）；RCS 热点检测；多目标 Pareto 前沿质量评估 |

#### 3.3.3 Agent 特化

无人机场景的 Agent 需要**三个特化子 Agent**并行协作：
- **结构 Agent**：优化铺层设计，最小化重量
- **气动 Agent**：保持翼型效率，防止失速
- **隐身 Agent**：优化外形和材料，降低 RCS

三个 Agent 通过**仲裁者 Agent**协调冲突，这正是 Harness Coordinator Mode 的典型应用。

### 3.4 运载火箭结构设计

#### 3.4.1 场景描述

设计某型液体运载火箭的级间段结构，铝锂合金焊接壳体，需承受最大动压点的轴压和弯矩，同时控制结构质量分数。

#### 3.4.2 Harness 配置

| 层次 | 具体实现 |
|------|----------|
| **约束** | 轴压屈曲临界载荷（Shell Buckling）；焊缝强度折减系数 0.85；热防护层厚度约束；级间分离行程和间隙要求；运输/起吊载荷工况 |
| **工具** | 壳体稳定性分析（Koiter 理论 + 非线性 FEA）；焊接工艺仿真；级间分离动力学仿真；载荷综合分析（风场/推力/气动） |
| **反馈** | 屈曲安全系数 > 1.5 校验；焊缝疲劳寿命评估；分离时序冲突检测；整体质量闭环验证 |

#### 3.4.3 独特约束

运载火箭设计有一个独特的 Harness 维度——**任务级约束**：
- 载荷-轨道耦合优化（结构质量每减 1 kg = 有效载荷增 1 kg）
- 发射窗口约束（影响热环境和风场设计工况）
- 多级火箭的级间质量传递链

这要求 Harness 的约束层不仅包含**局部结构约束**，还必须包含**任务级全局约束**。

## 3.5 军用战斗机/战斗攻击机设计

### 3.5.1 场景描述

设计第六代隐身战斗机（对标美国 F-47 NGAD / 中国歼-XX），需同时满足超音速巡航、全向隐身、高机动性和有人-无人协同作战能力。结构设计涉及隐身外形-气动-结构-电磁多学科深度耦合。

### 3.5.2 军机设计的独特约束维度

军机设计在 Harness 约束层中面临民用载具所不具备的**特殊约束集合**：

#### A. 隐身约束（Stealth Constraints）

| 约束类型 | 具体要求 | 形式化方式 |
|----------|----------|------------|
| RCS 控制指标 | 前向 RCS < -30 dBsm（VHF 波段）；侧向/后向有相应要求 | 电磁仿真代理模型 + RCS 预算分解 |
| 外形隐身规则 | 连续曲率外形；边缘对齐原则（平行边缘减少散射峰值）| 几何规则约束引擎 |
| 结构隐身 | 腔体屏蔽（进气道/座舱/喷管）；吸波结构一体化设计（RAS）| 多物理耦合仿真 |
| 红外隐身 | 热特征抑制；喷管红外辐射控制 | 热力学约束 |

**关键挑战**：隐身外形与气动效率之间存在根本性矛盾——棱角分明有利于雷达波偏转但不利于减阻和机动。传统设计需要数百轮迭代才能找到 Pareto 平衡。

**最新进展**：FibreCoat 2025 年推出新型柔性雷达吸波板（金属镀层玻璃纤维+玄武岩纤维+聚合物），可替代传统隐身涂料，大幅降低维护成本。这为 Agent 提供了新的材料工具选项。

#### B. 生存力约束（Survivability Constraints）

- **战伤容限**：结构在 12.7mm/23mm 弹击后仍能承受返回载荷（ limp-home 载荷）
- **冗余设计**：双余度/三余度传力路线，单一结构损伤不导致灾难性失效
- **燃油系统防护**：自密封油箱、惰性气体填充
- **弹射救生**：零-零弹射到高速弹射包线内的结构完整性

#### C. 作战效能约束（Combat Effectiveness Constraints）

- **武器舱容积**：内埋弹舱尺寸约束直接影响机身截面和结构布置
- **传感器融合布局**：分布式孔径系统（EODAS）的安装位置与结构开口
- **电子战集成**：内置干扰机、拖曳诱饵的空间和电磁兼容性

#### D. 保密与合规约束（Classification Constraints）

军机设计面临民用领域不存在的**信息分级约束**，这直接影响 Harness 的设计：

```
机密级约束:
├── 设计参数本身是保密的（外形尺寸、RCS 指标、性能包线）
├── 约束规则不能出现在公开 LLM 的训练数据中
├── Agent 必须在封闭网络中运行（物理隔离）
└── 反馈数据不能回传到外部服务
```

### 3.5.3 Harness 配置

| 层次 | 具体实现 |
|------|----------|
| **约束** | GJB 军用标准体系；RCS 预算分解（前向/侧向/后向/上下）；战伤容限载荷工况；内埋弹舱容积约束；飞行包线约束（9g 对称/5.5g 非对称）；保密数据分级管控 |
| **工具** | 隐身-气动联合优化器（RCS+CFD 耦合）；复合材料铺层优化（气弹剪裁）；电磁仿真（FEKO/CST）；弹击/战损仿真；内埋武器舱流场/结构联合分析；六代机有人-无人协同任务规划器 |
| **反馈** | RCS 热点自动检测与定位；全频段隐身-气动 Pareto 解集质量评估；战伤容限验证（剩余强度系数）；内埋武器舱流场品质评估；保密合规性审计（数据分级检查） |

### 3.5.4 Agent 工作流——以隐身外形优化为例

```
1. 总师 Agent 定义任务：优化进气道外形，前向 RCS < -30 dBsm，
   同时总压恢复系数 > 0.95，满足超音速巡航进气需求

2. 约束 Agent 检索相关 GJB 标准 + 历史隐身设计规则
   → 输出约束清单（RCS 预算、进气道流量比、畸变指数上限）

3. Generator Agent（隐身外形生成器）：
   a. 调用参数化进气道模型 → 生成候选外形
   b. 调用 CFD 代理模型 → 评估气动性能
   c. 调用 RCS 代理模型 → 评估隐身性能

4. Evaluator Agent（多学科评审器）：
   a. 检查 RCS 是否满足前向指标
   b. 检查总压恢复是否达标
   c. 检查进气道与机身融合过渡的几何连续性
   d. 评估 S-弯进气道对发动机进口流场畸变的影响

5. Sprint Contract 自动签署：
   - Sprint 1：概念探索（放宽约束，搜索设计空间）
   - Sprint 2：聚焦优化（收紧至设计目标）
   - Sprint 3：验证确认（全频段 RCS 精确仿真 + 高精度 CFD）

6. 人类隐身/气动专家审查最终方案
```

### 3.5.5 关键案例参考

#### 美国 F-47（NGAD 第六代战斗机）

2026 年 3 月，美国空军正式选定波音公司制造 F-47 第六代隐身战斗机。波音击败洛马的核心优势是其 **"数字优先"（Digital-First）设计方法**——与洛马的传统"先造原型再迭代"不同，波音提出构建**完全成熟的数字孪生体**，在虚拟环境中完成绝大部分设计和验证工作后再生产首架物理原型。

**Harness 映射**：
- F-47 的数字孪生 = **Repo-as-Truth 架构的军工实现**
- F-47 作为"空中指挥节点"控制 CCA（协同作战飞机）= **Coordinator Mode 的实战部署**
- F-47 的有人-无人协同 = 多层 Agent 系统的物理载体

#### 波音 T-7A Red Hawk（数字工程标杆）

T-7A 是**首个完整采用 MBSE + 数字孪生的军用飞机项目**，从笔记本电脑上的模型到首飞仅用 36 个月（传统流程需要 8-10 年）。

核心经验：
- **单一数据源（Single Source of Truth）**：所有设计、分析、制造数据共享同一数字主线
- **虚拟优先（Virtual First）**：在数字环境中完成 80%+ 的验证工作
- **开放架构**：数字控制系统支持快速演化

**这正好对应 Harness Engineering 的 Repo-as-Truth + Depth-First Working 模式。**

#### 中国歼-20/歼-35

截至 2025 年，中国已列装超 200 架第五代隐身战斗机，歼-20S（双座型）可控制多架无人机协同作战。在结构设计方面：
- **DSI 无附面层隔道进气道**：利用三维鼓包取代传统隔板，减重同时兼顾隐身
- **大面积复合材料应用**：机身蒙皮、机翼壁板广泛使用碳纤维复合材料
- **气弹剪裁**：通过复材铺层设计实现气动弹性主动控制

这些技术方向正是垂域 LLM Agent 在结构优化领域可以发挥作用的场景——将工程师的复材铺层经验编码为 Harness 约束，由 Agent 自动搜索最优铺层方案。

### 3.5.6 军机 vs 民机 Harness 对比

| 维度 | 民用飞机 | 军用战斗机 |
|------|----------|------------|
| **约束密度** | 适航规章（确定性条款）| 作战需求指标（模糊+迭代）|
| **设计理念** | 损伤容限（裂纹扩展安全）| 战伤容限（弹击后返回）|
| **隐身要求** | 无 | 全频段 RCS 控制（核心驱动）|
| **多学科耦合** | 结构-气动-动力 | 结构-气动-隐身-电磁-武器 |
| **保密等级** | 公开/商用 | 机密/绝密（物理隔离环境）|
| **LLM 部署** | 可用商用 API | 必须私有化部署（端侧推理）|
| **数字孪生** | 逐步引入 | F-47/T-7A 已作为核心方法 |
| **迭代速度** | 10-15 年 | T-7A 已证明 3 年可行 |
| **Harness 主架构** | Coordinator Mode | Repo-as-Truth + Generator-Evaluator |

**关键发现**：军机设计因为保密要求，**不能依赖商用云端 LLM**，必须采用 7B-70B 开源模型私有化部署方案。但同时，军机项目（如 T-7A、F-47）比民机更积极拥抱数字工程——因为军方对"颠覆性"新方法的容忍度更高，且不受民用适航审批流程的掣肘。

这意味着：**Harness + 垂域 LLM 在军机设计中可能比民机更早实现落地。**

## 3.6 军用运输机/特种飞机设计

### 3.6.1 场景描述

设计大型军用运输机（对标 C-17/Y-20），需实现大载荷/远航程/粗糙跑道起降。结构设计挑战集中在超大开口（尾跳板/侧门）对机身扭转刚度的削弱，以及货舱地板的高集中载荷。

### 3.6.2 独特约束

| 约束类型 | 具体要求 |
|----------|----------|
| 货舱容积 | 宽 × 高 × 长 ≥ 规定尺寸（容纳主战坦克/直升机）|
| 尾跳板开口 | 机身尾部超大开口，开口后扭转刚度损失 > 40%，需特殊补强 |
| 地板载荷 | 集中载荷达 50+ 吨（坦克单车轮压），分布式载荷 10+ 吨/米 |
| 粗糙跑道 | 起落架载荷系数 > 民机 2-3 倍，机身需承受高冲击载荷 |
| 空投/空降 | 货舱门开启时的气动载荷和压力分布突变 |
| 自部署能力 | 不依赖地面保障设备的快速检修和战损修理 |

### 3.6.3 Harness 配置

| 层次 | 具体实现 |
|------|----------|
| **约束** | GJB 运输机结构设计标准；货舱容积硬约束；地板集中载荷工况矩阵；粗糙跑道起降谱；空投/空降动态载荷 |
| **工具** | 大开口结构优化器（拓扑+尺寸组合）；起落架动态仿真；货舱流场/空投仿真；地板结构疲劳分析 |
| **反馈** | 开口区应力集中校验（应力比 > 1.5）；扭转刚度闭环验证；空投时序安全性检查 |

### 3.6.4 Agent 特化需求

军用运输机设计的 Agent 需要**三个特化子 Agent**：

- **机身结构 Agent**：优化大开口补强方案（桁架/框架/蜂窝夹层），在刚度和重量间取得平衡
- **货舱系统 Agent**：设计地板载荷传递路径，优化滚棒/导轨系统布局
- **任务系统 Agent**：规划空投/空降时序，确保重心变化在安全范围内

三个 Agent 通过 Coordinator Agent 协调——因为尾跳板开口直接影响机身扭转刚度，进而影响空投时飞机的姿态稳定性。

### 3.6.5 与民机货运型的差异

军用运输机与民航货运机（如 B777F）在 Harness 设计上有本质区别：

| 维度 | 民航货运 | 军用运输 |
|------|----------|----------|
| 载荷类型 | 标准集装箱/板 | 超大超重装备（坦克/直升机）|
| 装卸方式 | 侧门/鼻门 | 尾跳板（自驱驶入）|
| 跑道要求 | 铺装跑道 | 粗糙跑道/野战机场 |
| 生存力要求 | 无 | 战场生存力（防空火力/战损）|
| Harness 反馈重点 | 疲劳寿命 | 极限载荷/战损/冲击 |


### 3.7 多领域载具的对比分析

| 维度 | 民用飞机 | 军用战斗机 | 军用运输机 | 航天器 | 无人机 | 运载火箭 |
|------|----------|-----------|-----------|--------|--------|----------|
| **设计周期** | 10-15 年 | 3-5 年* | 5-8 年 | 3-5 年 | 1-2 年 | 2-4 年 |
| **安全理念** | 损伤容限 | 战伤容限 | 损伤容限+战伤 | 安全寿命 | 经济寿命 | 安全寿命 |
| **约束密度** | 极高（适航）| 极高（作战指标）| 高（军用标准）| 高（航天）| 中等 | 高（任务）|
| **反馈严格度** | 极高（取证）| 极高（实战验证）| 高 | 高（成败）| 中等 | 高 |
| **多学科耦合** | 结构-气动-动力 | 结构-气动-隐身-电磁-武器 | 结构-开口-空投 | 热-结构-EMC | 结构-气动-隐身 | 结构-气动-动力-控制 |
| **LLM 落地难度** | ★★★★★ | ★★★★★ | ★★★★ | ★★★★ | ★★★ | ★★★★ |
| **Harness 复杂度** | 极高 | 极高 | 高 | 高 | 中 | 高 |
| **LLM 部署方式** | 可用商用API | 必须私有化 | 私有化 | 私有化 | 灵活 | 私有化 |

**关键发现**：约束密度和安全要求越高，Harness 的 Guides 层越重要；多学科耦合度越高，Sensors 层的仲裁机制越关键。**军用战斗机**（隐身-气动-电磁-武器四重耦合）与**民用飞机**（适航合规极致要求）并列为 Harness 复杂度最高的场景。但军机因保密要求和数字工程先行优势，**可能比民机更早实现 Harness + 垂域 LLM 的全面落地**。


## 第四章 六大 Harness 架构模式在载具设计中的适配

基于 Anthropic、OpenAI、Cursor 的实践，以及载具设计的独特需求，本章提出六种 Harness 架构模式在载具设计中的适配方案。

### 4.1 Planner-Worker-Judge 三层分离

**来源**：Cursor 多 Agent 协作实践

**载具设计适配**：

```
┌──────────────────────────────────────┐
│  Planner Agent（总师 Agent）          │
│  • 解析设计需求，拆解为子任务          │
│  • 确定子任务依赖关系和执行顺序        │
│  • 分配学科（结构/气动/动力...）       │
│  • 全局约束管理（质量预算、进度）       │
└──────────────┬───────────────────────┘
               │ 派发任务
      ┌────────┼────────┐
      ▼        ▼        ▼
┌──────────┐┌──────────┐┌──────────┐
│ Worker 1 ││ Worker 2 ││ Worker N │
│ 结构设计  ││ 气动分析  ││ 系统集成  │
│ Agent    ││ Agent    ││ Agent    │
└────┬─────┘└────┬─────┘└────┬─────┘
     │           │           │
     └───────────┼───────────┘
                 ▼
┌──────────────────────────────────────┐
│  Judge Agent（评审 Agent）             │
│  • 多学科接口协调性检查                │
│  • 适航合规性综合评审                  │
│  • 质量预算闭环验证                    │
│  • 生成评审报告，建议修改              │
└──────────────────────────────────────┘
```

**实施要点**：
- Planner 掌握全局约束（质量预算、载荷分配），这是**不可逾越的硬约束**
- Worker 之间通过 Git 锁文件实现并发隔离（借鉴 Cursor 教训——20 Agent 并行时锁机制是关键）
- Judge 的评审标准必须**形式化**，不能依赖 LLM 的"直觉判断"

### 4.2 Generator-Evaluator 对抗（GAN-Style Loop）

**来源**：Anthropic 三篇 Harness 论文

**载具设计适配**：

```
┌─────────────────┐     ┌──────────────────────┐
│  Generator      │     │  Evaluator           │
│  (设计生成器)    │◄────│  (合规评审器)          │
│                 │     │                      │
│  • 读取设计需求  │────►│  • 检查物理可行性      │
│  • 调用工具生成  │反馈  │  • 校验适航合规性      │
│  • 输出设计方案  │     │  • 评估可制造性        │
│                 │     │  • 评分 + 修改建议     │
└─────────────────┘     └──────────────────────┘
```

**Anthropic V2 创新——Sprint Contract 在载具设计中的映射**：

每轮迭代前，Generator 和 Evaluator **自行协商验收标准**：

| 迭代轮次 | 验收标准（示例） | 评判依据 |
|----------|-----------------|----------|
| Sprint 1 | 最大应力 < 300 MPa | 初始估算，留裕度 |
| Sprint 2 | 疲劳寿命 > 40000 FH | 初步评估 |
| Sprint 3 | 疲劳寿命 > 60000 FH + Kt < 2.5 | 收紧至设计目标 |
| Sprint 4 | 全部适航条款通过 | 最终验收 |

**核心发现**：Agent 互相评估比自评估有效几个数量级（Anthropic 实验）。在载具设计中，这意味着"设计 Agent"和"审查 Agent"的对抗比单个 Agent 自检更可靠。

### 4.3 Coordinator Mode（主 Agent 当工头）

**来源**：Claude Code 的 Coordinator 架构

**载具设计适配**：

```
┌──────────────────────────────────────┐
│  Coordinator Agent（总师/PM Agent）    │
│  • 接收设计任务，分配给各学科 Worker    │
│  • 管理设计基线（当前有效的设计状态）    │
│  • 审批危险操作（材料替换、安全系数变更）│
└──────────────┬───────────────────────┘
               │ 通过"邮箱"请求/审批
      ┌────────┼────────┐
      ▼        ▼        ▼
  结构Agent  气动Agent  动力Agent
  (提交设计  (提交翼型  (提交推力
   变更请求)  修改请求)  分配方案)
```

**"邮箱"机制在载具设计中的含义**：
- 每个学科 Agent **不能直接修改**其他学科的设计参数
- 所有跨学科修改必须通过 Coordinator **审批**
- Coordinator 维护一个**设计冻结/释放**状态机

**现实映射**：这与航空企业的**工程更改控制流程（ECR/ECO）**高度一致。Harness Coordinator Mode 本质上是将企业的工程管理流程自动化。

### 4.4 Repo-as-Truth（环境管住认知）

**来源**：OpenAI Codex 团队——5 个月构建 100 万行代码生产系统

**载具设计适配**：

```
核心思想：不管理 Agent 行为，而是确保它感知的整个世界都是准确的
         ──────────────────────────────────────────────
         在载具设计中："世界"= 设计数据环境

┌─────────────────────────────────────────────────┐
│              Design-Repo-as-Truth                 │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐  │
│  │ 3D 模型库 │  │ 仿真数据库│  │ 适航知识库    │  │
│  │ (STEP/   │  │ (结果+    │  │ (条款+判据+  │  │
│  │  IGES)   │  │  元数据)  │  │  案例)       │  │
│  └──────────┘  └──────────┘  └──────────────┘  │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐  │
│  │ 材料数据库│  │ 工艺知识库│  │ 项目管理基线  │  │
│  │ (疲劳S-N │  │ (DFM规则 │  │ (需求+接口+  │  │
│  │  曲线等) │  │  + 约束)  │  │  更改记录)   │  │
│  └──────────┘  └──────────┘  └──────────────┘  │
│                                                  │
│  ↑ Agent 的所有感知都来源于这个统一的"真实世界"    │
└─────────────────────────────────────────────────┘
```

**关键原则**：
1. **单一数据源（Single Source of Truth）**：所有 Agent 共享同一个设计数据环境
2. **自动维护**：CI/CD 流水线自动更新模型、仿真结果、知识库
3. **可追溯性**：每次设计变更都有完整的审计日志

**OpenAI Codex 团队的核心洞察**：流程管住行为，**环境管住认知**。如果 Agent 感知到的环境是准确的，它的行为自然更可靠。在载具设计中，这意味着**投资建设高质量的设计数据环境比优化 Agent 本身更重要**。

### 4.5 Sprint Contract（冲刺合同）

**来源**：Anthropic V2 创新

**载具设计适配**：

在每个设计迭代"冲刺"开始前，Agent 自签验收合同：

```yaml
sprint_contract:
  sprint_id: "wing-root-fitting-v3"
  objective: "优化机翼-机身连接接头，目标减重 8%"
  
  # Agent 自协商的验收标准
  acceptance_criteria:
    - criterion: "最大 von Mises 应力"
      threshold: "< 380 MPa"
      basis: "CCAR-25.305 + 1.15 安全系数"
    - criterion: "疲劳寿命"
      threshold: "> 60000 FH"
      basis: "CCAR-25.571 损伤容限要求"
    - criterion: "质量"
      threshold: "< 12.5 kg"
      basis: "质量预算分配 WBS-3.2.1"
    - criterion: "可制造性"
      threshold: "DFM 检查零违规"
      basis: "3D 打印工艺规范"
  
  # 不满足验收标准的后果
  on_failure: "回滚至上一版本，Generator 重新分析失败原因"
  
  # 人类介入条件
  human_gate: "安全系数变更 > 0.1 或材料替换时触发"
```

**价值**：Sprint Contract 将隐性的设计要求显性化，使每次迭代都有**明确的完成定义（Definition of Done）**。

### 4.6 Depth-First Working（深度优先构建）

**来源**：OpenAI 实践——大目标拆小构件，逐个构建后解锁更复杂任务

**载具设计适配**：

```
Level 0: 全机级概念设计
  ├── Level 1: 机翼设计
  │     ├── Level 2: 机翼蒙皮（先完成）
  │     ├── Level 2: 机翼翼肋（先完成）
  │     └── Level 2: 机翼大梁（先完成）──→ 解锁 Level 1 验收
  ├── Level 1: 机身设计
  │     ├── Level 2: 机身框（先完成）
  │     └── Level 2: 机身蒙皮（先完成）──→ 解锁 Level 1 验收
  └── Level 1 全部完成 ──→ 解锁 Level 0 全机级多学科优化
```

**核心原则**：
- 自底向上构建，每个最小构件独立验证
- 上层任务只有在所有下层任务完成后才能开始
- 避免在未经验证的基础上构建复杂设计

### 4.7 架构模式选择矩阵

| 载具类型 | 推荐主架构 | 辅助架构 | 理由 |
|----------|-----------|----------|------|
| 民用飞机 | Coordinator Mode + Generator-Evaluator | Sprint Contract | 安全关键、多学科、需人工审批 |
| 军用战斗机 | Repo-as-Truth + Generator-Evaluator | Coordinator Mode | 隐身-气动对抗优化、数字孪生驱动、F-47/T-7A已验证 |
| 军用运输机 | Coordinator Mode + Depth-First | Sprint Contract | 大开口结构链式依赖、多系统协调 |
| 航天器 | Repo-as-Truth + Depth-First | Planner-Worker-Judge | 数据环境质量是核心、自底向上构建 |
| 无人机 | Planner-Worker-Judge | Generator-Evaluator | 迭代快、多目标、成本敏感 |
| 运载火箭 | Sprint Contract + Coordinator Mode | Repo-as-Truth | 任务级约束严格、一次性使用 |

## 第六章 结论与展望

### 6.1 核心结论

本研究系统性地将 Harness Engineering 的**约束-工具-反馈**三层框架映射到多领域载具设计的垂域 LLM 应用中，得出以下核心结论：

**结论一：Harness 思维与航空适航认证在本质上是同构的。**

适航认证是最古老的"工程 Harness"——它通过规章（约束）、测试方法（工具）、审查流程（反馈）来确保飞机的安全可靠性。AI Agent 的 Harness 通过架构约束（Guides）、工具调用（Tools）、评估闭环（Sensors）实现同样的目标。两者的映射是自然的、必然的。

**结论二：约束层是载具设计 Harness 的核心差异化因素。**

与软件工程中的 Harness（约束相对简单，主要是代码风格和测试覆盖率）不同，载具设计的约束是**物理的、法规的、制造的三重叠加**。约束的形式化质量直接决定了 Agent 的可靠性上限。投资建设高质量的约束知识库比优化模型本身更重要（呼应 OpenAI 的 Repo-as-Truth 理念）。

**结论三：反馈层需要多层次的闭环设计。**

从单点物理量校验到多学科冲突仲裁，再到人类专家审查，反馈层必须支持从自动到半自动到手动的渐进式介入。安全关键场景不能完全自动化，但可以通过 Harness 显著减少人工介入的频率和负担。

**结论四：架构模式的选择取决于载具类型和安全等级。**

没有一种架构模式适用于所有场景。民用飞机需要 Coordinator Mode + Sprint Contract 的严格管控；航天器需要 Repo-as-Truth 的数据环境优先；无人机需要 Planner-Worker-Judge 的快速迭代；运载火箭需要 Sprint Contract 的任务级约束。

**结论五：垂域 LLM 的价值不在于替代工程师，而在于重构设计流程。**

工程师的角色从"操作工具"转变为"定义约束、审核输出、承担决策责任"。核心竞争力的本质回归——对物理规律的深刻理解和对复杂系统的全局把控能力变得更加重要，而非更不重要。

### 6.2 理论贡献

1. **提出了载具设计 Harness 三层框架**（约束-工具-反馈），将 AI Agent 的 Harness Engineering 从软件领域拓展到物理工程设计
2. **建立了六种架构模式与四种载具类型的匹配矩阵**，为实际部署提供决策参考
3. **揭示了 Harness 思维与适航认证的同构性**，为 AI 系统通过适航审查提供了理论通道
4. **提出了 Sprint Contract 在工程设计中的形式化方案**（YAML 格式），实现了设计验收标准的机器可读化

### 6.3 实践意义

- **短期**：为航空/航天企业提供了垂域 LLM 应用的系统化实施路径
- **中期**：为多 Agent 协作在工程设计中的部署提供了架构指导
- **长期**：为适航认证范式的变革提供了技术可行性论证

### 6.4 局限性

1. **缺乏实证数据**：本研究为理论框架研究，尚未在真实载具设计项目中验证
2. **约束形式化难度被低估**：适航规章的自然语言歧义性远比预期严重，完全形式化可能需要 5-10 年
3. **多 Agent 并发效率**：Cursor 的经验表明，20+ Agent 共享设计时效率急剧下降，载具设计的并发规模可能更受限
4. **PINNs 的工程成熟度**：虽然学术进展显著，但 PINNs 在工业级复杂结构中的精度和鲁棒性仍需验证

### 6.5 未来研究方向

1. **约束形式化的自动化**：利用 LLM 将自然语言适航条款自动转化为可执行规则
2. **物理增强的 Agent 记忆**：将材料属性、失效案例、设计经验编码为持久化的 Agent 记忆
3. **多尺度 Harness**：从零件级到部件级到系统级到全机级的层级化约束管理
4. **Harness 的 Harness**：监控 Harness 本身的有效性，检测约束遗漏和反馈失灵
