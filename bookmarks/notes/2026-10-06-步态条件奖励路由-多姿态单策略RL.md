# 步态条件奖励路由：多姿态单策略 RL 的去干扰训练法

> 来源：arXiv 2505.20619 (UCL, Unitree G1 真机验证) + npj Robotics 自动跌倒恢复 + DUCK E28/E30 失败根因对照
> 日期：2026-10-06 · 领域：足式机器人 RL · 对现有训练线直接可用度：★★★★★

## 一、为什么这篇论文直击 DUCK E28 病根

E28（sit_flag 条件双态站/蹲）终裁 FAIL 的尸检结论：站组 z 落点 0.055-0.119 与蹲组 0.056-0.118 **完全交叉**，分离度 0.0177 < 0.02 门槛；E30 进一步确认「重技能在混合域被信号稀释」（趴 35% env 的混合训练里 recovery 悬赏全程到账 0.000-0.001 从未被吃，standup 专域同预算爬到 67%）。**这两个失败共享同一个教科书级病名：reward interference（奖励干扰）**——多姿态混训时，一个姿态的奖励梯度把另一个姿态的策略往回拉。

UCL 这篇论文的解法恰好就是这个问题的对症药：**gait-conditioned reward routing（步态条件奖励路由）**，在 Unitree G1 人形上单 recurrent 策略学会站立/行走/跑步/双向转换并真机落地。

## 二、核心机制拆解（可复制的三件套）

### 2.1 奖励路由：每步只让相关奖励项进梯度

- 完整奖励向量分两类：**共享项**（任务级 tracking + 调节项，如速度跟踪/能耗）+ **模式专属项**（站立用静止奖励/足对称，跑步用 push-off/短触地时长）。
- 训练时按当前步的 gait ID 施加 **gait mask**，把无关奖励项从学习目标中过滤掉——站立步不给跑步项梯度，反之亦然。
- 转换步态（walk-to-stand）可**继承或插值**相邻两个模式的奖励，行为平滑过渡不突变。
- 论文原文定位：*"each locomotion behavior is optimized independently while coexisting within a single recurrent policy"* ——单策略共享主干 + 独立信用分配，两头兼得。

### 2.2 观测设计：one-hot gait ID 进 obs

- obs 含 sin-cos 步态相位编码 + **one-hot gait ID**（站/走/跑/转换），同时喂 actor 和 critic——策略网络显式知道「我现在被要求做什么模式」。
- 这正是 E28 sit_flag 想做而没做到的事：sit_flag 在 obs[48:51] command 段里，但**没有配套的奖励路由**，sit/stand 两套 z 目标在标量总奖励里互相抵消，策略学到「趴中间值」的最优解。

### 2.3 课程：姿态渐进引入而非同时开训

三阶段课程（仿人类运动发育）：Phase1 低速行走（-~0.x m/s，节奏/足间隙/膝姿态）→ Phase2 加站立+走转站（双支撑/姿态稳定）→ Phase3 跑步（push-off/腾空相/短触地）。同时从三个维度渐进：姿态复杂度、指令速度范围、协调机制启用（路由/转换混合/减速平滑逐步打开）。

论文明确指出动机：**"Training all gaits simultaneously often leads to reward conflict and unstable exploration"**——这就是 E28 从第 0 步就 sit/stand 各 50% 混采的死因。

### 2.4 架构细节

- LSTM + MLP 的 recurrent actor-critic，**非对称结构**：actor 只看本体感受（可部署性），critic 额外拿特权信息（足接触状态/地面反力/摩擦系数/外扰力及其作用点）稳定价值估计。
- 输出 23 维关节位置偏移，PD 控制器固定增益跟踪——与 DUCK 的 offset 动作空间同构。
- 人类启发奖励（无需 MoCap）：直膝支撑、反相摆臂（对消腿引起的角动量）、残差角动量显式惩罚。

## 四、E31 处方：把奖励路由移植到 DUCK 双态线

按本篇论文机制重开 E31（E28 换配方，不是补丁）：

1. **obs 改造**：sit_flag 从 command 段析出为独立 one-hot 2 维段（[1,0]=站 [0,1]=蹲），与 cmd 并列。
2. **奖励路由**：站姿奖励（upright_while_tall@0.082 带单侧截止）只在 mask=站 时进总奖励；蹲姿奖励（z@0.046 带）只在 mask=蹲 时进；共享项（存活/action_rate/关节限位罚）恒开。
3. **课程渐进**：Phase1 纯站（复用 E20D/E23b 成熟配方 3000iter）→ Phase2 加蹲域（sit_prob 0.3→0.7 渐进）→ Phase3 混采+转换段。
4. **放弃条件**（沿用提案纪律）：m6000 时双态分离 <0.02 即停线，回退三件套架构（已定案，不推翻）。
5. **风险预算**：约 8000-10000iter（6-7h GPU），对齐 E20D 冷启动成功档位；禁热启 E28 ckpt（其条件响应从未建立，热启=继承病灶）。

与已定案架构的关系：三件套（E23b 站走推静 + E29 m12000 翻身 + 五段 skill 蹲起）是**已交付的保底**；E31 是「单模型双态」路线的最后一次对症尝试——若 reward routing 也救不动，则彻底坐实「DUCK 上分策略优于单策略」的结构性结论，反而把三件套从「权宜」升级为「终局架构」。

## 六、指南分析（怎么用这篇文献）

- 新双态/多姿态训练立项：直接抄「one-hot 模式 ID 进 obs + reward mask 路由 + 三阶段课程」三件套当配方骨架，禁只做 ID 注入不做奖励路由（E28 实证死法）。
- 给用户讲解：一句话版「让策略知道要做什么（obs ID）只完成一半，还必须只奖励做对了的事（reward mask），否则两个姿态的梯度互相打架，策略学出四不像」。
- 避坑速查：①转换段（站↔蹲）的奖励要继承/插值相邻模式，禁硬切换；②混训第一步就 50/50 采样=必翻车（论文原话 reward conflict and unstable exploration）；③热启带病灶 ckpt = 继承已固化的中间值策略，E31 必须冷启动。

## 七、拓展应用推荐

1. **E31 双态线**（本笔记主处方）：reward routing 重开 sit/stand，8000-10000iter 冷启动，分离度 <0.02 即停线回退三件套。
2. **E29 翻身线增强**：recovery 技能若要并入主策略（非独立模型），用 reward routing 给 recovery 段单独奖励通道，避免 E30 式「悬赏到账 0.000 从未被吃」。
3. **真机部署侧的 gait ID 映射**：duck_run 系脚本的 cmd13 行走指令与 sit_flag 可统一为模式 ID 总线，策略侧自然支持「站/走/蹲」运行时切换——比部署端硬切 ONNX 干净。
4. **周论文候选**：「单策略多姿态的奖励路由 vs 分策略专家切换：DUCK 五年尺度的架构决策边界」——E30（信号稀释失败）与 E31（路由法）构成天然对照实验。

## 八、趋势判断

1. **奖励路由成为多任务 loco RL 的默认配置**：2025-2026 论文（本篇+MultiCritic 系）独立收敛到「共享主干+条件化信用分配」，纯多任务标量奖励混训已被证伪。
2. **LSTM/时序记忆回归**：本篇 actor 用 LSTM 处理延迟接触效应与转换段，与 DUCK obs delay DR 思路互补——纯 MLP+DR 与 recurrent 策略的融合是下一步。
3. **恢复技能内建化**：npj Robotics 证明 fall recovery 可与行走共生同一策略，独立 recovery 模型（如 E29 专域）会逐步被路由式统一策略吸收——但前提是奖励不互斥。
4. **参考自由（reference-free）路线胜出**：AMP/MoCap 依赖被 biomechanics-inspired 奖励替代，小团队（无 MoCap 资源）的可行路径。

## 九、查询拓展

- MultiCritic Actor Learning (ICLR'22)：值函数解耦的原始出处，E31 备选方案 B。
- One Policy but Many Worlds (arXiv 2505.18780)：统一策略+AMP 式奖励的另一实现。
- GPO Growing Policy Optimization (arXiv 2601.20668)：渐进课程最新集成。
- Humanoid push-recovery 学习（emergentmind 综述页）：与 E22/E23b 抗推课程直接相关。
- MuJoCo/mjlab 侧实现参考：mask 实现即 reward 字典按 gait ID 索引取子集，mjlab 的 reward 管线天然支持（E23b 已用同款结构做静止单独通道）。

## 十、内容整理（归纳总结与关联分析）

**归纳总结**：多姿态单策略 RL 的成败分水岭在奖励路由而非网络表达——①one-hot 模式 ID 进 obs 让策略感知意图；②reward mask 让每个姿态的梯度只来自自己的奖励项（共享项恒开）；③课程渐进引入防早期梯度冲突；④转换段奖励插值保平滑。四件缺一即回退到「中间值策略」。Unitree G1 真机验证站/走/跑+双向转换，架构=LSTM actor（仅本体感受）+特权 critic。

**关联分析**：与 E28/E30 失败尸检构成完整因果链——E28 有 sit_flag（ID 注入）无路由（梯度互抵）→分离度 0.0177 FAIL；E30 混合域 recovery 悬赏被稀释（到账 0.000）→专域 67% vs 混域失败。本篇是两个失败的统一解法，也是「三件套 vs 单模型」架构之争的最后一块拼图：若路由法仍失败，「DUCK 上分策略优于单策略」从权宜升级为终局结论。与 [[2026-10-06-Agent记忆2026-自进化与基准]] 的交叉点：GLoW 的 Go-Explore 经验前沿思想同样适用于 RL 训练线的技能复用组织。

## 一句话结论

E28 死于奖励干扰而非表达能力：gait ID 进 obs 只解决「策略知道要做什么」，**reward mask 才解决「梯度只奖励做对了的事」**——两者必须配套，缺一即回到信号稀释老路。
