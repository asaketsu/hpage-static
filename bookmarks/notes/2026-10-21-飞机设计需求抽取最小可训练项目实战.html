内容整理

源方案核心（千问分享《飞机设计顶层需求梳理方案》）：模型训练只解决"非结构化文本→带引用的条目"这半件事，判定/冲突/裁决仍是人的事。路线=条款级知识库(RAG) + SFT 抽取模型 + 引用强制校验 + 人工评审基线；CPT 只在术语密度高时做；DPO 在幻觉率>2% 且错误系统性时上。红线：模型输出只能当候选清单，每条需求必须有人签署。

查询拓展

  • char-level 小模型生成精确 JSON 的能力边界：563K 参数在 val loss 1.79（perplexity≈6）时仍无法维持 300+ 字符结构化输出——真实任务必须 token-level 底座（Qwen 词表+预训练），这正是"为什么真训要换基座"的实证注脚。
  • DPO 在弱 SFT 上无法翻身（DPO 后评测仍全 0）：偏好对齐放大已有能力的相对优劣，不能无中生有——印证源方案"DPO 在 SFT 幻觉率>2% 时才上"的前置条件设计。
  • Jetson nv 定制 torch（2.5.0a0+nv24.08）所有 torch.optim.* 构造器在 dynamo→onnx→缺 onnxscript 链上崩（报"circular import"是误报）；stub onnxscript 无效，根治=手写纯 tensor AdamW。
  • 语义等价判定 _item_match：description 全等或"引用+数值+类型"三元组等——规则基线 75% "幻觉率"实为措辞不对齐被抓，说明匹配标准不靠措辞巧合放行。

归纳总结

  1. "最小可训练"的正确打开方式：真训练一个小到当天能跑完的模型，验证的是管线（数据/loss mask/校验/评测闭环）而非模型能力——两者必须分开陈述，评测数字如实呈现。
  2. 引用自洽是地基：伪造语料的第一铁律是金标准对校验器自身全过（description⊂原文、条款号在原文、数值三要素一致），否则评测无意义。生成顺序决定成败：先构造 desc，再由 desc 拼装原文。
  3. 评测体系的价值在判别力：门槛表不是给自己贴金的，是给后期真训定的验收线；tiny 全 0 + 基线部分过 = 评测在工作。
  4. Jetson 上做训练的三条铁律：GPU 前先看 free（统一内存 7.4G 常态只剩 1.2G）；nv torch 有 optimizer 坑（备手写 AdamW）；CPU 自回归生成 ~2s/百 token，BoN 预算按此算。
  5. 校验器也要被校验：check_unit 曾把换算系数当 SI 值（35000ft→0.3048 而非 10668m），范围检查从未生效——修复后 unit_err 0→2、基线召回 23.1%→15.4%，数字变严格才是修复生效的证据。
  6. DPO loss 恒等于 ln2 = 假训练：margin/acc 全 0 必查 mask 维度——mask[len-1:] 切的是 batch 维（大小 1，越界空切片），必须 mask[:, len-1:]。

趋势判断

  • 适航/需求工程领域的 LLM 落地范式正在从"通用问答"收敛到"抽取+强制溯源+人工签署"三件套：模型只负责候选条目化，引用校验器做硬门（引用失效整条退回），人保留终审——本项目的管线就是这个范式的最小完整实现。
  • 评测门槛表（召回≥90%/引用≥98%/幻觉≤1%）会成为领域标配：溯源是适航场景的死要求，幻觉率的可自动判定性（数值/条款号可在原文回查）使其成为少数能硬验收的 LLM 指标。
  • 真训成本曲线：本仓库最小版数据构造 1 天内完成；真训版（金标准 300-500 条 + SFT 1500-3000 条 + Qwen LoRA）按源方案估 2-3 人月——数据治理占大头，训练本身是零头。
