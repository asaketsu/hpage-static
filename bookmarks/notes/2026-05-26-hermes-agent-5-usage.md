# 让你的 Hermes Agent 发挥更大的价值：五个真正用法

> 来源：微信公众号 | 日期：2026-05-26

---

## 核心观点

> 真正的用法是：设计一套让 Agent 持续工作的流程，而不是把它当成一个高级搜索框。

装上去然后用一用，是一种答案。但那种用法很快就会遇到天花板，然后开始觉得"AI 也不过如此"。

---

## 用法一：用"元提示"让 /goal 发挥真实潜力

### 问题

很多人用 `/goal` 的方式是：`/goal 帮我写一个 App` → 效果比普通对话好不了多少。

**问题不在 `/goal` 本身，问题在于你给的提示太烂了。**

### 正确姿势

`/goal` 的设计逻辑是让 Agent 执行一个长时间运行的任务——跑过超过 10 小时没停的 `/goal`，持续构建、调整、迭代，最后交出来的东西完全不是普通对话能比的。**前提是你给它一个足够好的目标描述。**

### 解法：让 AI 替你写提示（元提示）

```
1. 先开一个普通对话，把你想做的事情描述给 AI 听
2. 告诉它：「我接下来要用 /goal 命令，请帮我生成一个适合 /goal 使用的详细提示词」
3. 拿到生成的提示，复制，粘贴进 /goal
```

**例子**：用 Godot 做一个第三人称射击游戏
- 直接输入 `/goal 帮我做一个第三人称射击游戏` → 效果一般
- 让 AI 先生成包含游戏机制、操控逻辑、场景结构、资产需求的完整提示词 → 结果差距是天壤之别

跑完之后得到一个可以在游戏里移动、射击、翻找尸体拾取弹药和绷带的游戏原型。不是最终产品，但框架是真实的，可以继续迭代。

> **/goal 的正确姿势：不要自己写提示，让 AI 帮你优化提示，再给 /goal。**

## 用法二：用看板把每天的任务真正分配出去

### 看板功能被严重低估

通过仪表盘进入：终端输入 `hermes dashboard` → 打开 URL → 点进 Kanban。

**功能本身**：往里面放任务，自动分配给 Agent 和子 Agent 执行。任务从「Triage（待分类）」→「To-do（待办）」→ 执行完成后归档。

### 晨间工作流

每天早上：
1. 拿出纸，把今天要做的事全部列出来
2. 打开看板，把所有"Hermes 能做的事"全部丢进去
   - 搜集最近三天 AI 领域的新工具，整理成报告
   - 起草三条关于 Hermes 用法的文章内容
3. 去做自己必须人工处理的事——打电话、付账单
4. 回来时，看板里那几个任务已经在跑了，有的甚至已经完成了

> 普通任务管理软件是提醒你自己去做，这个看板是真的把任务给做了。

## 用法三：用竞品拆解加速产品研究

### 以前的做法

打开 Chrome，开 DevTools，逐个看网络请求，翻 Console，猜框架，手动记录 → 半天没了，还不一定能看清楚。

### 现在让 Hermes 来做

```
打开浏览器，访问 [目标网站 URL]。
对该网站进行完整的技术调研和拆解：
- 使用了哪些技术栈？
- 有哪些核心功能？
- 前端框架是什么？
- 使用了哪些第三方服务和 API？
- 付费功能的定价逻辑是什么？
- 哪些功能值得参考？
最后整理成 Markdown 报告。
```

Hermes 会自己打开浏览器，去网站点来点去，看控制台，分析网络请求，然后给一份完整报告：技术概览、具体用到的库和框架、Analytics 收集了哪些事件、支付用的什么系统、定价逻辑……

> 拿到报告之后，可以直接扔给另一个 Agent，让它在自己的项目里参考实现。

**核心不是"抄"，而是"拆解学习"**。把行业里做得好的产品，系统性地研究清楚，比自己随便翻要高效得多。

## 用法四：用记忆 Wiki 让 Agent 有上下文可用

### 问题

用 Hermes 时间长了，很难直观看到以前聊过什么。

### 解法：让 Hermes 搭一个本地记忆 Wiki 网站

**搭建提示词**：
```
我想建一个记忆 Wiki 网站。
这个网站应该包含：
1. 我们讨论过的所有主题列表，可以点击查看详情
2. 每日工作日志，记录每天我们一起完成了什么
3. 每个条目都应该有对话记录和工作摘要
请帮我把这个站点构建出来。
```

### 两个价值

1. **对自己**：相当于一本自动维护的工作日记，随时能回来查"上次我搞那个 RAG 系统的时候遇到了什么问题""那个 Python 批处理脚本的逻辑我当时是怎么写的"
2. **对 Agent 本身**：告诉 Hermes 每次工作前先查一下记忆 Wiki，它就能带着上下文来工作，而不是每次从零开始

> 可以设定一个定时任务每天更新这个记忆 Wiki。

## 用法五：用晨间对话让 Agent 随时间变得更了解你

### 做法

给 Hermes 设置一条定时任务——每天早上 9 点，主动问一个问题：

```
每天早上 9:00，主动问我今天的第一优先级是什么。
然后根据我的回答：
1. 列出你能帮我做的相关任务
2. 更新你对我的记忆，包括我目前在做什么、我关注什么
```

### 积累效应

- 第一周回答时，了解很浅
- 第三个月，已经知道你在做什么项目、工作节奏、什么时候做产品什么时候写内容、最近遇到的瓶颈

这些信息在记忆里积累，会让工作建议越来越贴合实际情况，而不是泛泛的"我可以帮你完成任何任务"。

**实际例子**：如果连续两周都把"写文章"放在第一优先级，它会开始主动在看板里预留这类任务的模板，甚至会主动问"上次那篇文章还在进行中吗"。

## 五种用法总结

| 用法 | 核心 | 解决的问题 |
|------|------|-----------|
| 元提示 + /goal | 让 AI 帮你写提示，再给 /goal | 提示太烂导致 /goal 效果差 |
| 看板工作流 | 晨间列任务 → 丢看板 → 回来已完成 | 任务管理 vs 任务执行 |
| 竞品拆解 | 让 Hermes 自动调研竞品网站 | 手动分析竞品效率低 |
| 记忆 Wiki | 本地网站记录所有对话和工作 | 跨会话上下文丢失 |
| 晨间对话 | 定时主动问第一优先级，更新记忆 | Agent 不了解用户变化 |

---

## 进化点

1. **元提示模式** — "让 AI 帮你写提示，再给 /goal" 是一种通用模式，不仅限于 Hermes。任何需要结构化长提示的任务都可以用这个模式。值得在 Hermes Skill 设计中推广。
2. **看板 = 真正的 AI 员工** — 看板不是任务提醒，而是任务执行。这区分了"任务管理工具"和"AI Agent"的本质差异。Hermes 的看板功能值得更深入地集成到日常工作中。
3. **竞品拆解自动化** — 让 Agent 自动调研竞品网站并生成报告，这是产品研究的高效方式。可以封装成一个 Skill（类似 `competitor-analysis`），配合 browser 工具链使用。
4. **记忆 Wiki 的双向价值** — 既服务于人（工作日记），也服务于 Agent（上下文注入）。这与 Hermes 的三层记忆体系（会话/持久/技能）理念一致，但 Wiki 提供了更直观的可视化界面。
5. **晨间对话的积累效应** — 定时任务不仅是提醒，更是"主动学习用户"的机制。Agent 通过每天问一个问题，逐渐积累对用户的理解。这是从"被动工具"到"主动伙伴"的关键转变。
