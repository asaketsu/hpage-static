## 零、导读：这篇文的独特价值

推文引子先给了一个**认知框架**：

> "AI 比人思考的快，但人思考在前，AI 思考在后。也就是说 AI 的优势是后思考。"

这个"前思考/后思考"框架是全文的方法论钥匙：**人负责产生方向性想法（前思考），AI 负责快速验证与展开（后思考）**。作者自述"让 AI 代为验证了思路"成文——本文本身就是这个框架的产物。

正文回答一个朴素但关键的问题：**AI 会继续变强，而我的时间有限，接下来什么最值得投入？** 给出三条判断。这篇文的独特价值在于：作者不是观察者在预测，而是实践者在复盘（做了自动化项目、开源了视频平台和技能包之后的冷思考），且每条判断都锚定了具体行业事件（Anthropic computer use / Gemini Live / n8n AI Builder / Anthropic 记忆工具 / Claude Opus 4 统筹研究系统）。

**对 Hermes 用户的意义**：这是一份"个人 AI 工程化投入路线"的同行样本，可以直接对照自己的体系做差距检查——本笔记第三章做这件事。

## 一、原文三条判断忠实还原

### 判断一：桌面端格局已清，移动端值得更多注意力

- **2024-10 Anthropic computer use 开放测试**：AI 直接看屏幕、移鼠标、点击输入——当时笨拙但路径明确
- 沿此路径，桌面端工作方式已有轮廓：**人提目标 → AI 调工具操作软件 → 人查结果**。可靠性和效率问题仍多，但做应用的人已可据此设计产品
- 移动端信号：**2025-03 Google Gemini Live 摄像头+屏幕共享**（围绕眼前之物对话）；**Claude Code Remote Control**（任务在电脑跑，手机接着看和交互）
- 作者结论：手机作为 AI 入口的价值 = **现场信息 + 离开电脑后继续参与**。复杂任务留电脑执行，提需求/看进度/确认关键动作在手机完成
- 探索方向：**找那些发生在日常生活里、用手机处理更自然的需求**

### 判断二：最值得积累的是经过验证、能重复交付的 workflow，核心在"固化"

- 一次完成 ≠ 长期稳定可交。以视频制作为例：脚本→配音、画面对应、字幕检查、成片标准、**中断后知道从哪继续**——都要有明确安排
- 固化的定义：**把要求变成可执行、可检查、可复用的规则**。输入是什么、输出标准、哪里允许灵活、哪里必须停下确认
- 锚点：Anthropic 2024 底工程文章区分 **workflow（预定义路径，可预测一致）vs agent（模型动态决定步骤）**——任务明确的场景强调 workflow
- 但 AI 也能参与固化（n8n AI Workflow Builder 自然语言建流）→ **作者真正看重的是其中的业务经验和验证过程**
- "一个节点接到另一个节点，并不代表流程已经可用"——什么结果值得交付、哪些错误不能接受、例外怎么处理，需结合真实工作不断检验。**业务方定目标并对流程负责**
- 企业应用观：把一项具体工作做好→形成稳定交付→再扩大范围。**模型升级让执行更快更便宜，而积累的业务规则、验收标准、真实案例继续发挥作用**

### 判断三：记忆和多 Agent 围绕具体问题做，不把架构本身当目标

- **记忆**：记大量历史对话 ≠ 下次能做好。有些过时、有些只是当时讨论。**当前目标、已确认的决定、完成到哪一步**往往更值得留（锚点：2025-09 Anthropic 基于文件的记忆工具，上下文外保存+跨会话项目状态）
- 判据：能否**减少重复解释、避免丢关键约束**。解决不了这两问题的记忆设计不值得优先投入
- **多 Agent**：锚点 Anthropic 2025 研究系统——Opus 4 统筹 + Sonnet 4 执行，内部评测优于单 Agent；**但 token 消耗约为普通聊天 15 倍**
- 判据：工作能否真正拆开？各 Agent 任务是否明确？结果能否独立检查？**并行收益能否抵消沟通协调成本**？"如果一个 Agent 已经能把事情做好，就先把它做好。只有出现了明确的瓶颈，再增加分工"
- 收尾立场：先把跑通的流程做扎实，再找适合手机发起/接收的场景。记忆和多 Agent 在**能解决具体问题时**加入

## 二、批判性审视：三条判断的对与漏

### 2.1 站得住的部分（有证据支撑）

| 判断 | 支撑证据 | 评价 |
|------|---------|------|
| 桌面端格局已清 | computer use → 现有 Agent 产品形态确实收敛为"人提目标/AI 执行/人验收" | ✅ 描述准确 |
| workflow > 一次性 | Anthropic 官方 workflow vs agent 二分法 + 实践共识 | ✅ 与"Harness Engineering"准则同构 |
| 记忆要带目的 | "减少重复解释、不丢约束"两个判据干净利落 | ✅ 比多数"记忆万能论"清醒 |
| 多 Agent 算账 | 15× token 成本数字来自 Anthropic 官方 | ✅ 罕见的成本视角 |
| "AI 优势是后思考" | —— | ✅ 前思考定方向、后思考提效率的分工认知 |

### 2.2 需要补充/商榷的部分

1. **移动端判断漏了入口战争的关键变量**：作者看 Gemini Live 和 Remote Control，但 2026 年移动 AI 入口的真正变量是**系统级整合**（iOS/安卓把 AI 助手做进 OS 层）和**超级 App 内嵌**（微信/支付宝的 AI 能力）。第三方移动 AI 应用的窗口可能比预期短。"找手机上更自然的需求"方向对，但**谁拥有入口**决定生死
2. **"固化"漏了固化的对立面**：固化流程遇到需求变更时的**修改成本**未被讨论。过度固化的 workflow 会变成债——这正是 roadmap 笔记里"evals + 回归测试"存在的理由：固化必须配套**可验证**，否则固化的是错误。作者提到"结合真实工作不断检验"，但没有给出机械化检验手段
3. **多 Agent 15× 成本数字需要语境**：那是 Anthropic 内部**研究评测**场景（多源并行检索型任务）的观察值，不是通用系数。简单流水线型多 Agent（如本笔记体系里的笔记生产链）成本远低于此。拿 15× 一刀切吓退多 Agent 会错失真实收益场景
4. **"人思考在前"的边界**：前思考/后思考二分在**方向选择**上成立，但在**执行中的意外处理**上，AI 必须做"即时前思考"（无人值守任务里没有人在前）。作者的手机参与论（提需求/看进度/确认关键动作）其实已经隐含了这一点，但没展开成"人机介入点设计"这个更普适的概念

## 三、对照 Hermes 体系：一份现成的自检样本

这篇文最有价值的用法：作者的三条判断恰好是三面镜子，照出我们体系的成色。

| 判断 | 作者立场 | Hermes 体系现状 | 对照结论 |
|------|---------|----------------|---------|
| 一：移动端 | 手机=入口，找手机自然的需求 | **飞书 DM 即移动入口**——发链接→自动笔记→推送验证结果，已是"手机发起+接收"形态；cron 结果推送到飞书=异步进度查看 | ✅ 已在作者说的方向上，且比其更进一步（不只查进度，还能全流程托管） |
| 二：固化 workflow | 固化=可执行可检查可复用的规则 | **Skill=c固化的载体**（SKILL.md 就是"输入/输出标准/灵活点/确认点"）；本会话刚吸收 patent-disclosure-skill 的 validator 模式；笔记全链=典型固化 pipeline | ✅ 强项。但作者强调的"中断后从哪继续"（断点恢复）我们靠 PROGRESS.md + checkpoint，覆盖不均 |
| 三：记忆按需 | 留"当前目标/已确认决定/进度" | **TieredMemory 三级架构**（L1 铁律/L2 短期/L3 Topic）——L2/L3 的设计初衷正是"过时的淡出、项目的留下"；今天刚做过 USER.md 精练（89%→34%）就是这条判据的实践 | ✅ 对齐，且"减少重复解释"正是 L1 铁律存在的理由 |
| 三：多 Agent 按需 | 算账：拆得开+独立检查+收益>成本 | **delegate_task 默认单层**（max_depth=1）+ DAG verifier 模式刚在 roadmap 笔记里列为 P0 待落地——我们同样是"先做好单 Agent"派；15× 成本警觉与我们"智谱免费额度优先"的成本纪律同源 | ✅ 立场一致，且 verifier（独立检查）正是作者说的判据落地 |

**总体对照结论**：三条判断我们的体系全部"提前对齐"——不是因为巧合，而是双方都从实践出发走到了同一批结论（固化优先、按需架构、成本算账）。差异在于**作者的视角是"个人开发者选赛道"，我们的视角是"体系已经建成后的自我审计"**。对我们真正有增量的提醒是：

1. **移动端"自然需求"扫描**：现有飞书链路偏"工作流转发"，还没做过"哪些日常需求用手机发过来更自然"的主动盘点——值得做一次
2. **断点恢复的均匀覆盖**：长任务（视频渲染级）中断恢复在笔记链上有（sync 幂等），在其他链上无
3. **"业务方对流程负责"**：固化流程的验收标准来自业务方（用户）而非 AI 自评——这正是 evals 域（roadmap 笔记 P0-1）反复指向的同一短板，两个独立来源收敛到同一结论，优先级再加权
