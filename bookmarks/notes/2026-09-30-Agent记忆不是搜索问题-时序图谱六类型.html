一、锚点数字（含 yibie 的溯源订正）

微软《LLMs Get Lost in Multi-Turn Conversation》(arXiv:2505.06120)：15 模型×20 万+模拟对话，任务拆多轮平均损 39% 准确率——但拆开看：能力只掉 16%，不稳定性上升 112%（同指令最好最差运行差 50 个百分点）。
机制：模型在前几轮过早假设+过早给答案，然后过度依赖；拐错弯后不会恢复。
→ 结论修正："多轮更差"不准确，"模型没变笨，是变得不可靠"——而记忆系统每轮的上下文排布，正是在减少拐错弯的机会。

二、四代 Agent 记忆史（每代修上代的坑，引入新坑）

代 方案 崩点
1 整段对话塞 prompt 长度/成本崩；准确率在窗口填满前早就崩
2 滚动摘要 留要领丢细节——丢的恰是日期/ID/错误码/精确金额
3 分块 embed 检索"和问题相像的"≠"现在为真的"——新旧断言在向量空间几乎一样，两条都回来且无一条标有效
4 知识图谱 存的不再是文本是结构；同一份结构支持多种读取（顺边读=精确断言/聚节点=事物描述/看簇=没人写过的模式）

核心缺口："一种段落被要求回答每一种问题"。修法=同一份记忆多种形态取回，每种为不同问题而建。

三、认知心理学标签的问题（本文的独立批判）

语义/情景/程序记忆三分法按"记忆是关于什么"排序——只告诉题材，不告诉"怎么取回"。实践中标签什么都没做：标了三种，检索还是同一种方式。"标签从来不是检索路径"。

对照"测量"而非"描述"：长期记忆基准的五种能力——信息抽取/跨会话推理/知识更新（新事实取代旧事实）/时间推理（何时为真）/弃答（知道历史里没有）。

四、Zep 六种上下文类型（一次调用换 scope）

类型 是什么 回答什么问题 关键设计
① Facts 图谱边上的断言 "什么时候换的企业版？" 四时间戳：valid_at/invalid_at（现实世界起止）+ created_at/expired_at（系统何时得知）——三月结婚四月才知道，照样答对"三月结的吗"；升级不覆盖旧值而是关闭区间，无空隙无重叠，"上个季度什么为真"仍可答
② Entities 具名事物+随新事实再生的描述 "讲讲这条管道" 张力：实体摘要读着顺但无有效期；事实可核验但读着不像简报——只有摘要=流畅而错误，只有事实=正确而不连贯
③ Episodes 原始消息与派生物并排 "客户实际报了什么？" 真相来源层：逐字保留字段名/错误码/字节偏移，可引用而非转述
④ Thread summaries 覆盖单场对话的增量摘要 "那问题怎么解决的？" 保留两个不同结果：服务恢复了≠根因找到了
⑤ Observations 跨图谱的模式/决定/关系 "这些失败有什么共同点？" 连接只存在于记录关联方式里，没有任何一条消息陈述过；给"值得调查的序列"但不确立因果
⑥ User 用户画像 冷启动"嗨" 查询之前就要在场（无可检索）

Smart Context Assembly：跨六类型统一排名（不分开排）+字符预算内填块——形状跟着问题走（套餐变更问题偏重事实，冷启动偏重用户摘要）。

五、💡 对我们的价值分析

✅ 已在做的

  • 三级记忆+knowledge_graph+session DB 已是第四代形态的雏形；"决定分高下在选择不在存储"与我们的 memory 精练方向一致
  • "弃答"能力 = NOT_EVALUED（ROSClaw）与 null 出口（Schema 防呆）的同源物——体系三处独立收敛

⚠️ 可改进的（差距清单）

  • 无时间戳语义：knowledge_graph 的边没有 valid_at/invalid_at——"上次为真"类问题答不了（用户偏好变了/项目状态变了都靠人工更新）
  • 记忆取回单一形态：session_search 是"片段"型，缺"事实+区间"型——纠偏记录只存了"当时结论"没存"何时失效"
  • 多轮不可靠（112% 不稳定性）对我们直接适用：长会话后期决策质量下降是结构性的——重要决策应回读开头的任务定义（防拐弯）

🔥 重点行动

  1. knowledge_graph 边加四时间戳（valid_at/invalid_at/created_at/expired_at）——最小改动换"何时为真"能力，与既有 kg-auto-sync 兼容
  2. 纠偏沉淀带失效语义：session-evolution-scan 的规则入账时记 valid_at；被新纠偏取代时关闭区间而非覆盖（"上季度什么为真"可答）
  3. 长会话拐弯检测：>20 轮的会话在关键节点回读首条任务消息做对齐自检（112% 不稳定性的工程对策）

六、内容整理（归纳总结与关联分析）

归纳总结：记忆系统在模型调用之前工作，三约束（token 预算/无界历史/一条入站消息）下分高下的是"选择"不是"存储"。四代演进（全文→摘要→向量→图谱）每代修上代坑；认知三分类（语义/情景/程序）只分题材不给检索路径=标签无效。Zep 六类型（事实带四时间戳/实体/片段/会话摘要/观察/用户）+跨类型统一排名的 Smart Assembly。39% 多轮损失拆开=能力-16%+不稳定+112%（过早假设拐弯不恢复）。

关联分析：与昨日 [[2026-09-29-STB时空桥梁冥想法-注意力变焦训练]] 的镜像在此加倍——人脑变焦与模型上下文排布是同一问题的碳硅两版；与 [[2026-09-29-模型蒸馏方法论]] 的"评测七覆盖"互补：记忆基准五能力里的"弃答"正是蒸馏评测缺的那格。与 WFM（LLM Wiki 图式检索，DAIR 周榜）正面竞争关系：WFM 训专用检索模型，Zep/Graphiti 走显式图谱结构——隐式学习 vs 显式结构的路线之争，与 EBTO（显式约束）vs 端到端的对照同构，再次落在 9 月元趋势"显式契约化"上。

八、趋势判断

  1. 记忆系统从"检索问题"转向"排布问题"：39% 数字会把行业焦点从召回率拉到上下文组装质量——Smart Assembly 类跨形态排名成为标配
  2. 时序语义（valid_at）成为记忆层标配：覆盖式更新将被视为 bug——"上季度什么为真"是刚需且向量检索结构性答不了
  3. "拐弯不恢复"催生对齐检查点范式：长会话定期回读任务锚点会内建进框架（预测 LangGraph 类框架出 checkpoint-align 原语）
  4. 图谱显式结构 vs 专用检索模型（WFM）两年内分胜负：可解释/可编辑的显式路线在企业合规场景占优——与适航构型管理"可追溯"要求同向
