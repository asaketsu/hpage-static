## 一、VLA 是什么：不是"会聊天的机器人"，它直接决定下一步怎么动

**视觉—语言—动作模型（Vision-Language-Action Model，VLA）**：把视觉观测、语言指令和机器人状态映射成控制动作的模型。

基本数据流：

```
图像 + 语言 + 本体状态 → 动作序列
```

- **本体状态（proprioception）**：关节角、末端姿态、夹爪开合、底盘位置等。少了它，机器人像"只看后视镜开车"——知道外面发生了什么，却不清楚方向盘已经打到哪儿。
- **训练时额外输入**：人类示范或历史轨迹中的正确动作。Hugging Face 的 LeRobot 数据工具会把多相机视频、传感器状态和动作放进同一条时间线。
- **Xiaomi-Robotics-0 示例**：主摄像头、腕部摄像头、文字指令和 `proprio_state` 一起送入模型，输出未来若干步组成的 **action chunk**。

**VLA 真正难的地方**：不是认出杯子，而是把"杯子"翻译成一串不会摔杯子的动作。

### 统计学习视角

从统计学习角度看，VLA 仍是在有限示范中学习一个条件关系：

```
P（动作 | 图像、语言、本体状态、历史观测）
```

损失函数、参数估计、泛化与分布偏移，这些问题和经典统计学习一脉相承；变化在于：
- 输入：从人工设计的低维特征 → 图像、语言和长时序状态
- 输出：从一个标签 → 连续动作分布

### 历史坐标：RT-2 与动作 token

- **RT-2**：把机器人动作表示成类似文字的 token，让视觉语言模型已有的语义知识参与机器人控制——理解这条路线的重要坐标。
- **OpenVLA**：延续 RT-2 思路，把权重、训练和微调链路进一步开放。
- **动作 token 的代价**：逐个生成可能慢，离散化也会损失精度。
- **后续演进**：OpenVLA-OFT、π0、GR00T 等路线开始大量采用**动作分块（action chunking）、Diffusion 或 Flow Matching**，一次预测连续动作。

## 二、一张 VLA 里的三层工作

> 注意：这是三层**功能**，不是三个必须彼此独立的模型。同一个改造后的 VLM 可以同时承担视觉语言理解和动作 token 生成；另一类 VLA 则把连续动作生成拆给动作专家。

### 第一层：视觉语言理解（VLM）

**VLM 不是某个固定产品**，而是一类同时处理图像和语言的模型，在 VLA 中负责看懂场景、理解指令并形成语义特征。

- Qwen-VL 这类 VLM 以 **Transformer 为核心**，通常包含视觉编码器和视觉—语言连接模块：RGB 图像先变成视觉 token，再与文字 token 一起交给语言模型 Transformer 处理。
- **VLM 描述的是模型承担的功能，Transformer 描述的是它采用的网络架构，两者不在同一个层级。**

### 多相机接入的两种方式

| 方式 | 做法 | 特点 |
|------|------|------|
| 拼接 | 先拼成一张大图 | 简单 |
| 分别编码 | 每路图像分别编码，用输入顺序、相机标签或视角 embedding 区分 | 更灵活 |

**关键限制：多图语义融合 ≠ 几何对齐**。Transformer 可以学到"主视角里的杯子"和"腕部视角里的杯沿"有关，却不一定显式算出它们在同一个三维坐标系中的位置。

### 标定与分布偏移（原文重点展开）

很多 RGB 型 VLA 依靠固定相机和同步示范，学习隐式的"视角—状态—动作"统计关系。相机被重新安装、碰歪，或镜头参数改变后，原来的关系就会失准——这叫**标定变化带来的分布偏移**，夹爪便可能抓偏。

**术语精确定义**（原文强调）：
- **标定**：测量相机成像参数及其与外部参考坐标系几何关系的过程。
- **相机外参**：相机坐标系与指定参考坐标系之间的六自由度刚体变换（三维旋转 + 平移）；使用时必须明确参考坐标系和变换方向。
- **相机位姿** vs **投影外参**："相机在参考坐标系中处于哪里、朝向哪里" 与视觉投影公式里常表示的反方向"参考坐标如何变到相机坐标"，二者可能互为逆变换，不能只看矩阵名字。
- **腕部相机**：安装在机械臂末端、跟着夹爪移动；**外部相机**：固定在桌边或房间里。

### 手眼标定（hand–eye calibration）两种安装方式

| 方式 | 相机位置 | 标定对象 | 特点 |
|------|---------|---------|------|
| **眼在手上（Eye-in-Hand）** | 随机械臂运动 | 相机与末端执行器的固定关系 | 相机先估计物体在相机坐标中的三维位置，再通过变换计算物体相对夹爪/基座的位置。绝对三维位置还需要深度、双目、三角测量或其他测距信息 |
| **眼在手外（Eye-to-Hand）** | 固定在工作区 | 相机与机器人基座的关系 | 并非低配：外部相机视野大、画面稳定，适合全局定位和避障；腕部相机离目标近，适合精细抓取和插入 |

**工业实践**：外部相机看全局，腕部相机看细节，两者组合。

**机器人基座**：机器人身上的参考坐标系。固定机械臂指底座固定在桌面/地面/机架；机械臂装在轮式底盘、人形或四足机器人上时，基座坐标系随整机相对世界移动。

**标定 vs 定位的关键区分**：
- 标定求的是特定安装条件下**相对固定的几何参数**
- 定位和机器人运动学计算的是**运行时不断变化的位姿**
- 移动机器人使用 Eye-to-Hand：不是每走一步都重新标定，而是持续更新基座在世界中的位置（只靠里程计累加会产生漂移）；只有相机被碰歪或安装关系改变时才需要重新标定或在线估计外参
- **几何对齐**：借助标定结果、深度和运动学，把不同相机看到的三维点转换到共同的基座或世界坐标系。比 Transformer 中的语义关联更明确，但更依赖标定质量、时间同步和传感器精度

### 深度图与点云的三条接入路径

**VLM 不是所有传感器的总入口**：

1. 把深度映射成图像交给视觉编码器
2. 用独立的深度或 3D 编码器生成 token，再与 RGB 特征融合
3. 只在训练时用深度作空间监督，部署仍然只吃 RGB

通用 VLA 多以 RGB 作为语义主输入，不代表机器人很少使用深度；精密抓取、避障和导航中，深度常进入独立 3D 模块。**PointVLA** 就是把点云特征注入预训练动作专家的一种尝试。

### 本体状态（proprioception）的接入

关节角、末端姿态、夹爪开合这些本体状态是连续数值，一般先归一化，再由 **MLP 投影成状态 token**。之后既可以进入 VLM，也可以绕过 VLM 直接交给动作专家。**怎么接，并没有统一答案**：

| 模型 | 本体状态接入方式 |
|------|----------------|
| π0.5 | 当前状态量化成离散 token 放进 VLM 提示 |
| OpenVLA-OFT | 状态投影成连续嵌入 |
| GR00T N1 | 状态嵌入直接送给动作头 |

2026 年 8 月一项基于 π0.5 的受控实验比较了五种接口，发现不同任务偏好的入口并不相同。

### 第二层：动作生成

两类典型结构（不一定对应两个独立模型）：

| 结构 | 代表 | 机制 |
|------|------|------|
| **VLM 直接生成动作 token** | RT-2、原版 OpenVLA | 像续写文字一样，输出量化后的机器人动作 |
| **VLM + 连续动作专家** | π0、GR00T、OpenVLA-OFT | VLM 形成"目标是什么、物体在哪"的语义上下文，Flow Matching 或 Diffusion 动作模块再结合机器人状态，生成未来一段动作 |

**动作专家也常用 Transformer，但它不因此变成 VLM**——同一种网络结构，承担的是不同职责。

**"独立"不代表互不相干**：π0 里的 VLM 专家和动作专家会交换特征并联合训练，并不是 VLM 写完一句计划再调用一个毫无关系的模型。

### 第三层：底层控制器（经常被省略）

VLA 输出关节目标、末端增量或动作块；**逆运动学、插值、安全限制和电机闭环**再把目标变成真实运动。让 VLA 直接碰电机电流？多数系统不会这么莽。

**完整数据流两个分支**：

```
分支A：RGB、语言与状态条件 → 改造后的VLM → 动作token → 底层控制器
分支B：VLM语义特征＋状态条件 → 连续动作专家 → 动作块 → 底层控制器
```

### 隐藏的第四层：机器人数据与本体适配

它未必是一块独立网络，却决定前两层能否落到具体机器人上。不同机器人关节数不同、相机位置不同、坐标系也不同。同一句"向前"，落到双臂、人形和移动机械臂上，根本不是一回事。

**很多新模型骨架相似，真机效果却差得很远。差距藏在**：数据清洗、动作归一化、相机标定、控制频率，以及失败后有没有人接管并把修正过程重新喂回训练。

**国产 VLA 的真正投入点**：不是从 Transformer 另起炉灶，而是使用成熟的 VLM、连续动作生成和跨本体学习范式，把投入压在**真机轨迹、本体生态和部署工程**上。

## 三、主流模型地图：它们根本不在同一个货架

> 理解模型地图最容易犯的错：把论文模型、可下载模型、商业闭源系统和开发框架一起排成绩。

### 三个主干坐标

**① OpenVLA / OpenVLA-OFT——开源研究基线**
- 有预训练权重、LoRA 和全量微调、从头训练与评测说明
- 适合研究者理解"怎样把 VLM 训练成 VLA"
- OFT 补上连续动作、多图输入和高频双臂控制
- 不一定代表能力天花板，但是很好的透明参照物

**② π 系列——通用操作和泛化路线**

| 版本 | 重点 |
|------|------|
| π0.5 | 陌生环境中完成多阶段任务（公开可下载、可微调的核心版本） |
| π0.6 | 可靠性和吞吐 |
| π*0.6 | 从自主经验中强化专家策略 |
| π0.7（2026年4月） | 组合泛化：重新组合学过的技能，执行训练中没有直接出现的任务 |

**关键事实：π0.7 更新，却没有像 π0.5 那样开放公共权重。能力最新和开放程度最高，从来不是一回事。**

**③ GR00T N1.7——英伟达人形机器人与工具链路线**
- Early Access 版本提供 3B 基础权重、推理和微调代码
- 结构：VLM + Diffusion Transformer 动作头
- 与 Isaac 仿真、评测和部署生态连接
- 能下载、能后训练，但完整预训练数据并未全部公开，不能叫"从头可复现"

### 外圈模型（值得知道但不适合直接选型）

| 模型 | 定位 |
|------|------|
| Helix | Figure 的闭源快慢系统：低频语义理解 + 高频动作控制 |
| Gemini Robotics | Google DeepMind 闭源机器人模型：大模型推理、规划与控制结合 |
| GO-1 | 智元的跨本体数据和机器人生态路线；AgiBot World 数据覆盖超 100 万条轨迹、100 多台机器人、1000 多个任务场景 |
| Xiaomi-Robotics-0 | 4.7B 参数，强调实时异步执行，已开放权重、推理、评测和后训练代码 |
| LingBot-VLA | 大规模多本体真机数据训练通用策略；初代论文披露约 2 万小时、9 种双臂构型 |
| X-VLA | 用本体专属软提示解决不同本体的数据与动作空间差异 |
| UnifoLM-VLA-0 | 宇树：通用 VLM 继续训练成具身模型，公开训练、推理、权重以及 12 类 G1 操作数据 |

### 要移出"模型排行榜"的两个名字

- **LeRobot**：数据、训练、硬件与评测**工具链**
- **StarVLA**：可替换骨干和动作头的**模块化研究框架**

它们能承载模型，但不是和 π0.5 同层级的基础模型。

## 四、"开源"的六层拆解

具身智能里的"开源"很松，至少要拆成六层：

```
① 架构 → ② 推理代码 → ③ 模型权重 → ④ 微调代码 → ⑤ 预训练配方 → ⑥ 训练数据
```

| 开放层级 | 判断 |
|---------|------|
| 只给论文 | ≠ 能运行 |
| 只给权重 | ≠ 能微调 |
| 能微调 | ≠ 别人可以从头复现 |

**分级结论**：
- OpenVLA → 接近"**可复现型开放**"
- GR00T N1.7、π0.5、Xiaomi-Robotics-0 → "**开放权重且支持微调**"
- π0.7、Helix、Gemini Robotics → 主要是"**能力坐标**"

**许可证还要另看**：代码用 Apache 2.0，不代表权重和数据自动获得相同授权。

### 为什么不该给"2026 最强 VLA"结论

不同模型控制不同机器人、使用不同数据，在 LIBERO、ALOHA、家庭长任务或人形全身控制上接受不同考试。把这些数字并成一张总榜，表格很漂亮，判断会变薄。

### 判断新模型的正确顺序

看到一个新的机器人模型时，先别急着问它是不是"最强"。先看：
1. 它使用什么输入
2. 怎样生成动作
3. 控制什么机器人
4. 权重、训练链路和数据究竟开放到哪一层

**模型名字还会继续变，真正不容易过时的，是这套判断顺序。**

## 五、归纳：本文的知识框架图

```
VLA = P(动作 | 图像、语言、本体状态、历史观测)
│
├── 第一层：视觉语言理解（VLM）
│   ├── 视觉编码器 → 视觉 token
│   ├── 多相机：拼接 vs 分别编码（语义融合 ≠ 几何对齐）
│   ├── 标定体系：外参/位姿/Eye-in-Hand/Eye-to-Hand
│   ├── 深度/点云：三条接入路径（RGB映射/独立3D编码器/仅训练监督）
│   └── 本体状态：MLP→token，入口未统一（π0.5量化/OpenVLA-OFT连续/GR00T直连）
│
├── 第二层：动作生成
│   ├── 路线A：VLM直接生成动作token（RT-2、OpenVLA）——慢、离散损失精度
│   └── 路线B：VLM语义 + 连续动作专家（π0、GR00T、OFT）——Flow Matching/Diffusion
│
├── 第三层：底层控制器（IK、插值、安全限制、电机闭环）
│
└── 第四层（隐藏）：数据与本体适配（清洗、归一化、标定、频率、人在环修正）
    └── 国产VLA的主战场：真机轨迹 + 本体生态 + 部署工程
```
