数字孪生低代码可视化平台 — 独立项目方案

1. 项目概述与定位

1.1 项目名称

TwinLite — 轻量级数字孪生可视化搭建平台

1.2 一句话定位

面向中小团队和独立开发者，提供"拖拽搭大屏 + 3D场景 + 实时数据"的一站式开源方案，让数字孪生不再是头部企业的专属。

1.3 市场痛点

痛点 现状 我们的解法
商业平台贵 DataV 年费 5-50 万，ThingJS 按项目收费 完全开源 MIT，零授权费
技术门槛高 Three.js 学习曲线陡峭 低代码拖拽 + 预制组件
定制能力差 封闭平台只能用内置组件 插件机制，社区贡献组件
私有化部署难 SaaS 平台数据安全顾虑 Docker 一键私有部署
供应商锁定 一旦用上就很难迁移 标准化数据格式，可导出

1.4 目标用户

  • 主要用户：中小软件公司（5-30人团队），需要给客户交付数据可视化大屏
  • 次要用户：独立开发者/外包团队，接数字孪生项目但不想从零搭建
  • 边缘用户：企业 IT 部门，内部做监控看板/园区管理

1.5 核心差异化

不追求"零代码"（那是营销话术），而是追求低门槛高可控：
- 拖拽能搞定 80% 场景
- 剩下 20% 可以写代码扩展
- 全程数据格式透明，随时可以接手

2.2 竞品优劣分析

DataV（阿里云）
- ✅ 阿里云生态整合深，组件丰富，运维成熟
- ❌ 绑定阿里云、价格贵、无3D能力、不可定制

ThingJS（优锘）
- ✅ 3D能力强、零代码交付、行业模板多、培训体系完善
- ❌ 商业授权贵、引擎封闭、社区不活跃

Grafana
- ✅ 开源生态极强、数据源支持最多、社区活跃
- ❌ 无3D、仪表盘配置不直观、不适合"大屏交付"场景

CesiumJS
- ✅ GIS/地球可视化最强、开源、性能优秀
- ❌ 纯代码开发、学习曲线陡、不适合通用数字孪生场景

2.3 我们的定位空白

现有方案要么贵且封闭（DataV/ThingJS），要么功能不全（Grafana无3D、Cesium无低代码）。

TwinLite 填补的是：开源免费 + 3D可视化 + 低代码拖拽 + 私有部署 这个交叉领域。

3.2 技术选型

前端

模块 技术选型 理由
框架 React 18 + TypeScript 生态最大、类型安全、组件复用
3D引擎 Three.js + React Three Fiber Three.js生态最成熟，RFP提供React集成
图表库 ECharts 5 中文生态最好、图表类型最全、性能优秀

后端

模块 技术选型 理由

部署 Docker + docker-compose 一键部署、环境一致

3.3 核心设计原则

  1. 数据驱动渲染：编辑器产出的 JSON Schema 驱动最终渲染，编辑态和运行态共享渲染器
  2. 插件化一切：图表、3D组件、数据源、交互动作全部可插拔
  3. 离线优先：编辑器可纯本地运行，只同步到云端
  4. 性能预算：首屏 < 3s、3D场景 60fps、内存 < 500MB

4. 核心功能模块

4.1 模块架构

TwinLite
├── 📐 画布编辑器 (Canvas Editor)
├── 🧊 3D场景管理 (3D Scene Manager)
├── 📊 图表组件库 (Chart Components)
├── 🔌 数据源管理 (Data Source Manager)
├── ⚡ 事件交互引擎 (Event Engine)
├── 🧩 插件市场 (Plugin Marketplace)
└── 📦 导出部署 (Export & Deploy)

4.2 画布编辑器

MVP 功能：
- 自由画布拖拽（网格/自由两种模式）
- 组件属性面板（位置/尺寸/样式/数据绑定）
- 图层管理（z-index、锁定、隐藏、分组）
- 撤销/重做（操作历史栈）
- 多选对齐（左/右/居中/等距分布）

JSON Schema 示例：

{
  "canvas": {
    "width": 1920, "height": 1080,
    "background": "#0a1628",
    "components": [
      {
        "id": "chart_01", "type": "echarts-line",
        "position": {"x": 100, "y": 200, "w": 400, "h": 300},
        "props": {"title": "月度销售额", "smooth": true},
        "dataSource": "ws://api/sales/monthly"
      }
    ]
  }
}

4.3 3D场景管理

  • 模型导入：glTF/GLB 格式（Three.js 原生支持）
  • 场景编辑：拖拽模型、调整光照、相机视角、动画配置
  • 预置模型库：工业设备、建筑、管道等常用模型
  • 数据绑定：模型属性（颜色/位置/显隐）绑定实时数据
  • 地标/热点：3D模型上标注信息点，hover/click 弹出数据面板

4.4 图表组件库

基于 ECharts 封装，预置高频图表：
- 折线/柱状/饼图/仪表盘/雷达/热力图
- 地图（中国地图/世界地图）
- 数字翻牌器
- 进度条/水波球
- 装饰组件（边框/标题/动态背景）

每个图表组件统一接口：

interface ChartComponent {
  type: string;           // 图表类型
  props: Record<string, any>;  // ECharts option 扩展
  dataSource: string;     // 数据源ID或URL
  refreshInterval: number; // 刷新间隔(ms)
}

4.5 数据源管理

支持多种数据接入方式：

类型 协议 适用场景
静态数据 JSON文件 演示/原型
REST API HTTP GET/POST 常规业务数据
WebSocket WS 实时数据流
数据库直连 SQL（只读） 内部数据
MQTT 订阅Topic IoT设备数据
时序查询 InfluxQL 历史趋势分析

数据变换管道：
原始数据 → 过滤 → 映射 → 聚合 → 格式化 → 组件消费

4.6 事件交互引擎

支持组件间联动：
- 触发器：点击、hover、数据变化、定时器、条件满足
- 动作：显隐组件、跳转链接、弹窗、数据过滤、3D视角切换、发送指令
- 交互链示例：点击地图某省 → 过滤右侧图表数据 → 3D模型高亮对应区域

4.7 导出部署

  • 一键导出：将项目打包为独立 HTML（内嵌资源）
  • Docker 部署：docker-compose up 一键启动前后端
  • 嵌入模式：提供 iframe SDK，嵌入第三方系统
  • 截图/录像：定时截图、录制操作视频（用于汇报）

8. 差异化策略

8.1 vs 商业平台（DataV/ThingJS）

核心差异：开放透明
- 数据格式完全透明（JSON Schema），用户随时可以迁移
- MIT 协议，无授权限制
- 技术栈主流（React + Three.js），不绑定私有引擎

8.2 vs 开源方案（Grafana/Cesium）

核心差异：开箱即用的3D + 低代码
- Grafana 无3D能力 → 我们有
- Cesium 需纯代码 → 我们有拖拽编辑器
- 两者都不适合"交付型大屏" → 我们专门为此设计

8.3 独特卖点（USP）

  1. 3分钟 Demo：从安装到出第一个大屏 < 3分钟（Docker一键启动 + 预置模板）
  2. 插件5分钟开发：文档+脚手架，5分钟写出自定义图表插件
  3. 一键交付：编辑完直接导出独立HTML发给客户，无需部署
  4. 全中文优先：文档、社区、模板全部中文，降低国内开发者门槛
