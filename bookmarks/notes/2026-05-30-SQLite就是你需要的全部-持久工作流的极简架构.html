SQLite 就是你需要的全部：持久工作流的极简架构

来源：Obelisk Blog · 2026-05-29
原文：https://obeli.sk/blog/sqlite-is-all-you-need-for-durable-workflows/
评分：⭐4/5
标签：#SQLite #持久工作流 #Agent架构 #基础设施 #Litestream

摘要

Obelisk 团队提出一个务实观点：对于大量持久执行场景，SQLite 比 Postgres 更合适。核心论点是"持久的是工作流状态，不是基础设施"。SQLite 提供事务性持久状态而不需要额外数据库服务，结合 Litestream 异步备份到 S3，可以构成 AI Agent 场景下的极简持久层。

核心内容

1. 持久的本质是状态不是基础设施

持久执行（Durable Execution）常被讨论为需要持久基础设施，但实际关键的是工作流状态。计算可以保持廉价和可丢弃。Obelisk 方案中，工作流进度存于执行日志，工作流从持久历史重放，活动可重试。

2. SQLite 的天然适配

  • 无网络跳转，无额外控制面
  • 无新运维面仅为保护工作流进度
  • 本地数据库文件就是恰当的机制层级

3. Litestream 让 SQLite 可移植

  • 异步流式复制 SQLite 变更到 S3 兼容对象存储
  • 工作状态靠近运行时，同时外拷备份、迁移、检查
  • 注意：异步复制存在短暂数据丢失窗口

4. Agent 场景的最佳匹配

AI Agent 工作流的特点：突发性（bursty）、实验性、每个 Agent 独立状态更易理解。微 VM/容器舰队 + 各自 SQLite + 对象存储备份，比大型共享系统更合适。

5. 何时仍需 Postgres

需要更高可用性、更广泛的共享可扩展性、或同步复制时，Postgres 仍是正确选择。

关键概念

  • Durable Execution：工作流状态持久化，计算可丢弃
  • Execution Log：工作流进度记录，支持重放和重试
  • Litestream：SQLite 异步复制工具，备份到 S3
  • Fault Isolation：每个 Agent 独立 SQLite 文件，故障不扩散

能力边界

  • 异步复制意味着最新本地写入可能丢失
  • 不适合需要高可用共享数据库的场景
  • 多租户强一致性需求仍需 Postgres

最佳实践

  • 每个 Agent/租户一个 SQLite 文件，天然隔离
  • 本地开发用 SQLite，生产按需升 Postgres
  • 用 Litestream 异步备份，而非同步复制
  • 微 VM 舰队模型：小、廉价、可替换
