## 一、内容整理

### 1.1 SelectInfer：选择性神经元加载与计算（arXiv:2607.18081）

**核心思路**：不是所有神经元对每个任务都同等重要——只加载和计算最重要的子集。

**两阶段优化**：
1. **离线分析阶段**：LLM 分析器（Profiler）分析并识别任务特定（task-specific）和通用（general-purpose）神经元
2. **在线推理阶段**：
   - **选择性加载**（Selective Loading）：只加载离线阶段识别为最重要的神经元子集，减少内存占用
   - **选择性计算**（Selective Computation）：运行时只动态计算最相关的神经元

**关键区别**：与粗粒度剪枝/量化不同，SelectInfer 在神经元级别操作，不需要重训练或微调。离线分析后，推理时直接跳过不重要的神经元——既是内存优化（不加载）也是计算优化（不计算）。

**评估结果**：在多个数据集上显著减少内存占用和计算量，同时保持任务性能。

### 1.2 Forget to Improve：预算策划的端侧持续学习（arXiv:2606.25115）

**核心洞察**：端侧语言模型 Agent 通过积累经验到检索记忆中（而非更新权重）来改进。但这种记忆有三个约束——硬边界 RAM 占用、能耗暴露、以及通过薄弱上行链路到达对等节点。

> **"遗忘以改进"**：按净价值（net value）策展的记忆比保持所有条目更好。

**单一评分：净价值每字节（Net Value Per Byte）**
```
Score(entry) = Value(entry) - Harm(entry)  // 每字节归一化
```

一个评分统领三个决策：

- **KEEP（保留）**：在 RAM 和能耗预算下驱逐低价值字节
- **SHARE（共享）**：仅当洞察的价值超过上行链路成本时发送
- **TRUST（信任）**：按来源（provenance）门控对等条目

**实验环境**：真实异构 Jetson 测试平台，两个机械臂节点 + 一个中心节点。

**量化结果**：
- 记忆占用减少 2.7 倍
- 上行链路减少 2.4 倍
- 注入攻击成功率从 0.75 降至 0
- 在被投毒或过时记忆损坏的案例上准确率提升

> 关键结论：预算作为策展人。按净价值遗忘实际上**增强**而非削弱了 Agent。

### 1.3 EnerInfer：能量感知的端侧 LLM 推理（arXiv:2606.23001）

**核心发现**：端侧 LLM 推理有可利用的配置松弛（configuration slack）——适度降低 NPU 和内存频率可保持体验质量（QoE），同时显著提升能效并减少热量。

**三重挑战**：
1. **配置依赖性**：最高效的 NPU/DDR 频率设置随模型、推理引擎、平台和运行条件变化，没有稳定的排名
2. **传感器缺失**：商业设备缺乏组件级功耗传感
3. **热动态性**：外壳温度随请求到达、响应长度和热历史变化

**EnerInfer 方案**：
- **解耦预测**：用模型结构感知的预测替代逐模型分析，跨 NPU/DDR 频率设置预测吞吐量和功耗
- **排名驱动在线反馈**：选择满足 QoE 的高效配置
- **有限视界热预测**：在能量优化和热约束推理之间动态切换

**能效提升**：
- 手机：+65%
- 笔记本：+12%
- 开发板：+24%
- **全部无 QoE 违规**

### 1.4 Cascaded Multi-Granularity Pruning：工业 IoT 的级联剪枝（arXiv:2606.26861）

**粗到细级联框架**：按 Layer → Attention Head → FFN Channel 顺序逐级剪枝，在每级之间用轻量低秩恢复重新估计组件重要性。

**结构独立性假设（SIA）**：形式化为可检查的条件，预测逐组件剪枝标准对给定架构是否可靠：
- **满足 SIA**：MHA + GELU 架构 → 压缩比可达 13.8 倍
- **违反 SIA**：GQA + SwiGLU 架构 → ~74 个百分点的准确率塌缩

**实测**（轴承故障诊断，88M~6.25B 参数模型）：
- MHA+GELU：13.8 倍压缩，83.82% 准确率（+3.70pp）
- GQA+SwiGLU：压缩时准确率塌缩
- 推理延迟降低 67.2%，峰值内存降低 62.5%

> **关键洞察**：不是所有架构都能安全剪枝。注意力头类型和激活函数的组合决定了剪枝可靠性。

### 1.5 Edge AI 推理加速器：端侧模型适配（arXiv:2607.18101）

在资源受限硬件上实现端侧模型适配（lifelong personalization），但端到端反向传播的计算/功耗/内存限制使其困难。该工作提出专用推理加速器来支持边缘设备上的模型微调。

## 二、查询拓展

### 2.1 神经元重要性分析（Neuron Importance Analysis）

SelectInfer 的离线分析器本质上是确定每个神经元对特定任务的贡献度。这与「稀疏激活」（Sparse Activation）研究相关——大模型中只有一小部分神经元在任何给定输入下被激活。关键区别是 SelectInfer 在离线确定重要性后，推理时完全不加载/不计算不重要的神经元，而非运行时动态稀疏激活。

### 2.2 端侧持续学习 vs 云端微调

Forget to Improve 代表了一个重要路线选择——端侧 Agent 不通过权重更新来学习，而通过经验记忆积累。这避开了端侧微调的三大障碍：
1. **计算不可行**：Jetson Orin Nano 8GB 无法进行 7B 模型的反向传播
2. **灾难性遗忘**：持续微调导致旧任务性能退化
3. **安全风险**：可写权重 = 可投毒权重

但代价是：经验记忆占用 RAM、消耗能耗、通过薄弱上行链路暴露给对等节点。

### 2.3 NPU 频率-能效松弛（Frequency-Energy Slack）

EnerInfer 的核心洞见——适度降低 NPU/DDR 频率可在保持 QoE 的前提下大幅省电——这与 CPU DVFS（动态电压频率调节）理念一致但应用于 LLM 推理。关键区别是 LLM 推理的 QoE 不完全取决于延迟——用户对首 Token 延迟（TTFT）敏感，但对后续生成速度有容忍度，这创造了频率调节空间。

## 三、归纳总结

### 3.1 端侧 LLM 部署优化技术栈

```
模型层：量化(GGUF/INT8) → 剪枝(Cascaded) → 神经元选择(SelectInfer)
  ↓
推理层：选择性加载 + 选择性计算 → 内存/计算双减
  ↓
运行时层：频率调节(EnerInfer) → 能效优化 + 热管理
  ↓
经验层：预算策划记忆(Forget to Improve) → 持续学习 + 安全
```

### 3.2 五篇论文优化目标对比

- **SelectInfer**：内存占用 + 计算量（神经元级，离线分析 + 在线跳过）
- **Forget to Improve**：RAM + 能耗 + 上行链路 + 注入安全（净价值评分）
- **EnerInfer**：能耗 + 热量（NPU/DDR 频率调节）
- **Cascaded Pruning**：模型大小 + 延迟（级联 Layer→Head→Channel 剪枝）
- **Edge AI Accelerator**：端侧微调可行性（专用硬件）

### 3.3 Jetson Orin Nano 适用性评估

| 技术 | 适用性 | 理由 |
|------|--------|------|
| SelectInfer | ⭐⭐⭐ | 神经元级选择直接减少 Jetson 显存压力 |
| Forget to Improve | ⭐⭐⭐⭐⭐ | 已有 Jetson 测试床验证，机械臂场景与用户项目直接相关 |
| EnerInfer | ⭐⭐⭐ | Jetson 有 NPU，频率可调 |
| Cascaded Pruning | ⭐⭐ | MHA+GELU 限制较大，现代模型多用 GQA+SwiGLU |
| Edge Accelerator | ⭐ | 需专用硬件，不适用 |

## 四、趋势判断

### 趋势 1：端侧 Agent 学习从"权重更新"转向"经验记忆策展"
Forget to Improve 提供了强有力的证据：在资源受限设备上，按净价值策展经验记忆比微调权重更有效——记忆减少 2.7 倍、上行减少 2.4 倍、注入攻击降为零，同时准确率提升。这预示着端侧 Agent 的"持续学习"将更多采用检索增强+记忆管理的范式，而非传统 ML 的梯度下降。

### 趋势 2：能效优化成为端侧 LLM 的第一优先级
EnerInfer 首次系统性地证明：适度降频可省电 65% 而不影响 QoE。对于电池供电的边缘设备（机器人、可穿戴），这意味着续航从分钟级到小时级的质变。未来端侧推理框架的竞争将从"谁更快"转向"谁更省电"。

### 趋势 3：架构选择决定压缩天花板
Cascaded Pruning 揭示的 SIA 条件是一个重要警告——MHA+GELU 可安全压缩 13.8 倍，但 GQA+SwiGLU（Llama/Mistral/Qwen 等主流架构）在同等压缩比下准确率塌缩。这意味着现代主流 LLM 的端侧部署仍受限于量化（而非剪枝）路径。

### 趋势 4：安全与效率不再是对立面
Forget to Improve 最深刻的贡献是证明了"遗忘 = 防御 + 效率"——按净价值清理低质量记忆同时减少了注入攻击面和资源消耗。安全治理和资源优化通过"净价值评分"统一为一个目标。
