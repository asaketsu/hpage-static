为什么无图智驾不使用SLAM建立局部语义地图？

来源：微信公众号「智驾最前沿」（作者：陈云培）
原文链接：https://mp.weixin.qq.com/s/qo6bzxzYYv5wF3QmfoawDw
记录日期：2026-06-26

一、文章概要

自动驾驶领域正从"高度依赖高精地图"转向"无图智驾"（不依赖预设地图，实时感知理解环境）。在这个过程中，BEV + Occupancy + Transformer 组合成为主流，而曾经在机器人领域立下汗马功劳的 SLAM 方案却没有被智驾采用。文章系统回答了一个核心问题：为什么？

二、内容详细整理

2.1 为什么传统几何建图跟不上变化？

SLAM 的核心逻辑是基于几何约束：

  • 提取路边建筑边缘、交通标志转角等特征点
  • 通过数学公式计算这些点在三维空间的坐标
  • 在静态/刚性环境下非常精确

但在城市交通这种动态、非刚性环境下，几何逻辑遭遇严重挑战：

问题 机制 后果
拼图错位 相机角度微小偏移→几何投影错位 地图物体重影/位置漂移
算力消耗不均 环境复杂度↑→维护局部特征地图内存/时间↑ 系统过载
语义断层 必须先"看懂"物体才能"画进"地图 无法归类的物体（树枝、建筑垃圾、特种车辆）在地图中缺失

核心缺陷：语义地图要求系统先识别再建图 → 无法识别 = 感知盲区 → 对自动驾驶安全要求是巨大隐患。

2.2 Transformer 如何重塑空间感？

传统 2D→3D 转换依赖深度估计：猜每个像素距离→投射到3D。但"猜深度"极不稳定，受光影、雨雾干扰。

Transformer 引入"主动询问"机制：

BEV画布上每个位置（Query）→ 主动向所有摄像头画面打听：
  "你们视野里有没有哪个像素属于我这个地理位置？"

三大优势：

优势 说明
特征级融合（非结果级拼接） 在最底层特征阶段就把360°信息融为一体，而非各自算完再凑
全局注意力 利用道路整体轮廓推断被遮挡区域（"脑补"货车后方道路结构）
空间感涌现 通过大规模数据学习建立类人的空间直觉，不依赖精准深度计算

关键洞察：左侧相机看到车头 + 后侧相机看到车尾 → BEV画布上汇聚为同一物理实体。这种逻辑连贯性是传统SLAM难以企及的。

2.3 Occupancy 网络如何解决感知死角？

如果 BEV+Transformer 解决了"看清世界"的问题，那么 Occupancy Network 解决的是"叫不出名字的物体"问题。

核心范式转变：

维度 SLAM 语义地图 Occupancy 网络
识别逻辑 先分类再建图 只判断空间是否被占据
未知物体 识别不出→忽略→危险 不需要知道叫什么，只需知道被占据→避让
世界观 贴满标签的分类表 充满障碍物的物理空间

4D 时空连续性：
- 注入 Transformer 特征 → 存储过去几帧信息 → 形成带记忆的 4D 空间感知
- 即使障碍物瞬间被遮挡，系统仍记得该体素曾检测到物体 → 根据运动趋势预测当前位置

2.4 为什么这种组合成为必然选择？

BEV + Transformer + Occupancy 的本质是将感知统一到同一个坐标系和同一种数学语言下。

SLAM 失败的根本原因：

SLAM 试图在一个不断变动的世界里建立一套永恒不变的坐标，这在复杂城市环境中成本太高、容错率太低。

维度 SLAM BEV+Transformer+Occ
坐标系 永恒不变的绝对坐标 实时更新的相对BEV坐标
传感器兼容 强依赖特定配置 对安装位置/型号更强兼容
下游对接 飘忽的语义标签 + 散乱点云 高清实时含物理占用的3D鸟瞰图
路径规划 需要额外解读 像玩赛车游戏一样直观

BEV（Bird's Eye View）感知的里程碑论文和产品：

时间 里程碑 核心贡献

3.2 为什么 SLAM 在智驾"失败"但机器人大获成功

这是本文没有展开但关键的对比：

维度 机器人SLAM 自动驾驶
速度 低速（<2m/s） 高速（>10m/s）
环境 静态/半静态 高度动态
帧率要求 10-20Hz足够 需50Hz+实时
可接受延迟 100ms <20ms
地图有效期 分钟-小时级 秒级（环境秒变）
遮挡频率 低 极高（车辆/行人频繁遮挡）

SLAM 的"先建图再定位"范式适合环境变化慢于运动速度的场景。自动驾驶恰好相反——环境变化快于车辆运动，SLAM 的地图刚建好就过时了。

3.3 Occupancy Network 与 NeRF/3DGS 的关系

Occupancy Network 的体素思想与 NeRF/3D Gaussian Splatting 有深层联系：

  • Occupancy：离散体素，二值/概率占据 → 推理快，适合实时避障
  • NeRF：连续隐式表示 → 渲染质量高，但推理慢
  • 3DGS：半离散高斯基元 → 介于两者之间，渲染快质量高

自动驾驶选择 Occupancy 而非 NeRF/3DGS，核心是实时性 > 渲染精度。

3.4 "无图"不等于"无先验"

行业常说的"无图智驾"实际仍有先验信息：
- SD地图（标准导航地图）：道路拓扑、限速
- 车道级导航：粗粒度车道信息
- 道路经验：Tesla 的 fleet learning 积累的统计先验

"无图"指的是不依赖高精地图（HD Map）的厘米级精确几何信息，而非完全从零感知。

四、归纳总结

4.1 范式之争的本质：确定性建模 vs 数据驱动

SLAM（确定性建模）              BEV+Transformer+Occ（数据驱动）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
人工设计特征                      数据自动学习特征
几何约束优化                      端到端梯度优化
可解释性强                        可解释性弱
静态环境最优                      动态环境最优
边际场景需人工补丁                边际场景靠数据覆盖
低数据依赖                        高数据依赖

自动驾驶选择后者，因为城市交通的边际场景无穷多，人工设计特征的"打地鼠"游戏永远赢不了。

4.2 三层感知架构对比

层级 SLAM 方案 无图智驾方案
空间重构 深度估计→3D投影 Transformer BEV（主动Query）
物体理解 语义标签→分类建图 Occupancy体素→物理占据判断
时序记忆 回环检测→全局优化 4D时序注意力→短时记忆
下游输出 语义标签+点云 3D占用BEV图→直接路径规划

4.3 为什么"无法归类"是最大安全隐患

这是文章最深刻的洞察之一：

传统语义地图的致命假设是"世界上的物体都可以被分类"。但现实世界中存在大量长尾未知物体（洒落的建筑垃圾、特殊形态的施工围挡、侧翻的异形货车）。

  • SLAM方案：无法分类 → 不画进地图 → 系统不知道它存在 → 直接撞上去
  • Occupancy方案：不需要分类 → 只要空间被占据就避让 → 物理保底

这个差异是生死级别的安全差异。

五、趋势判断

5.1 端到端架构将统一感知与规控

BEV+Transformer+Occupancy 的下一步是端到端（E2E）：
- UniAD（CVPR 2023 最佳论文）已证明可行性
- Tesla FSD V12+ 实现了感知到控制的全程神经网络化
- 预测：2026-2027年主流车企将量产端到端架构

5.2 Occupancy 分辨率将大幅提升

当前 Occupancy 网络的体素分辨率约 0.5-1m，未来趋势：
- 多尺度体素：近处密集(0.1m) + 远处稀疏(1m)，类似LOD(Level of Detail)
- 神经辐射场增强：在关键区域用 NeRF 补充细节
- 预测：2027年实现 0.1m 级近场占用感知

5.3 SLAM 不会消亡但角色转变

SLAM 在自动驾驶中并非完全消失，而是退入幕后：
- 离线建图：仍用于停车场记忆、高精地图众包更新
- 多传感器标定：外参标定仍是SLAM技术
- 泊车场景：低速+静态环境，SLAM仍有优势（如记忆泊车）
- 预测：SLAM将成为自动驾驶的补充技术而非核心感知方案

5.4 "感知-建图"边界模糊化

传统SLAM的"建图"和"定位"是分离的两个阶段。BEV+Occ方案实际上在做隐式建图——每一帧BEV特征图本身就是一张局部地图，只是它不持久化、不复用。这标志着显式建图正在被隐式表征替代。

6.4 Occupancy 思想对机器人感知的启发

虽然本文讲的是自动驾驶，但 Occupancy 网络的"不需要分类，只需判断占据"思想对机器人感知有直接启发：
- 传统机器人导航：SLAM建图→语义分割→路径规划（三步串联，级联误差）
- 启发方案：直接用轻量 Occupancy 网络输出局部可通行性 → 跳过语义分割环节 → 降低延迟和算力

这与用户 ESP32 平衡小车项目的"物理安全兜底"理念高度一致。
