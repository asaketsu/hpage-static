一、核心发现：Agent 记忆的范式转移

2026 年 Agent 记忆研究经历了一次重大范式转移——从长上下文填充 (Long-Context Stuffing) 转向结构化双记忆系统。核心主张是：

冻结 LLM 参数 + 可进化的外部记忆 = 无灾难性遗忘的持续学习

这直接挑战了当前主流的 RAG 方案。RAG 只存储"是什么"(knowledge-oriented)，新框架同时关注"怎么做"(process-oriented)。

二、MIA 框架：Manager-Planner-Executor 三角架构

2.1 架构总览

角色 类型 职责 类比
Memory Manager 非参数化 压缩存储历史搜索轨迹 海马体（情景记忆）
Planner 参数化 根据经验生成搜索策略 前额叶（策略规划）
Executor 推理引擎 ReAct 循环执行工具调用 运动皮层（行动执行）

2.2 关键创新：双向转换环 (Bidirectional Conversion Loop)

非参数化记忆（外部轨迹）
        ↕ 压缩/内化
参数化记忆（模型权重）
  • 内化路径：成功的非参数化策略 → 微调 Planner → 写入参数
  • 外化路径：参数化知识 → 解析为可检索的非参数化条目
  • 这个环解决了"策略只存在上下文中，模型本身没有变"的问题

2.3 混合检索策略

MIA 的记忆打分不是纯语义相似度，而是三维加权：

维度 公式 含义
语义相似度 cosine(query, memory) 问过类似的问题？
价值奖励 s_i / (u_i + 1) 这条记忆以前管用吗？
频率奖励 1 / (u_i + 1) 这条记忆是否罕见？(鼓励探索)

其中 s_i = 成功次数，u_i = 使用次数。低频但成功的记忆会被优先检索，防止"高频但低质"记忆垄断。

2.4 两阶段交替强化学习

Stage 1: 固定 Planner → 训练 Executor（学会按计划执行）
Stage 2: 固定 Executor → 训练 Planner（学会制定好计划）
    ↻ 交替迭代直到收敛

这解决了 Planner 和 Executor "互相甩锅"的问题——如果 Planner 计划好但 Executor 执行不了（或反之），系统能检测到并针对性改进。

2.5 Test-Time Learning (TTL)

最关键的创新：Planner 在推理过程中实时进化，不需要中断：

  • 推理时自动收集 (query, plan, outcome) 三元组
  • 用成功/失败信号做在线梯度更新
  • 无监督判断机制：用 LLM 自评判断推理质量（不需要标注数据）
  • 与推理并行，不阻断用户请求

性能：在 11 个基准上，MIA 让 GPT-5.4 在 LiveVQA 上提升 9%、HotpotQA 上提升 6%。多模态 +5.5%、纯文本 +7.5%。

3.1 MemRL：形式化基础

记忆三元组 (z, e, Q)：
- z = 状态嵌入
- e = 原始经验
- Q = 效用值

更新规则：Q_j ← Q_j + α(r_t - Q_j)（EMA/Bellman）

理论保证：
- 局部收敛：E[Q_t - B] = (1-α)^t (Q_0 - B)
- 方差控制：lim sup Var(Q_t) ≤ ασ²/(2-α)

实证（ALFWorld 探索任务）：从 0.324 → 0.507 (+56% last accuracy)，CSR 从 0.456 → 0.697。

3.2 DMS：达尔文式记忆生态

生存值公式：S(m_i) = U(n_i) · D(Δt, n_i) · P(K_i)

  • 使用效用：U(n_i) = ln(1 + n_i) + v_new
  • 时间衰减：D(Δt, n_i) = 1 / (1 + exp[β(Δt - T_half(n_i))])
  • 可靠性：P(K_i) = 1 / (1 + γK_i)（K = 失败次数）

高适应度记忆存活，停滞记忆被"elbow method"剪枝。支持 ε-变异（随机探索新策略）和贝叶斯风险反馈。完全免训练。

3.3 MemSkill：记忆操作技能化

将静态记忆操作（增/删/改/查）替换为可学习的技能库：
- Controller 用 Gumbel-Top-K 选择每轮使用的技能组合
- PPO 训练技能参数
- Designer（LLM 驱动）从困难案例生成新技能

困难案例评分：d(q) = [1 - r(q)] · c(q)（低成功率 × 高复杂度）

  2. Skill 引入频率奖励：Skill 加载时加入 1/(u+1) 因子，避免高频低效 Skill 垄断上下文
  3. evolver 增加 TTL 模式：当前 evolver 在 session 结束后反思，可增加推理中的微反思+即时记忆更新

五、关键技术细节

5.1 注意力稀释问题 (Attention Dilution)

长上下文记忆的核心缺陷：当历史 > 10K tokens 时，LLM 的注意力被稀释，重要信号被噪声淹没。

MIA 的解法：不在上下文中堆叠记忆，而是：
1. Manager 压缩轨迹为结构化工作流
2. Planner 提取关键策略
3. 只将精炼后的指导注入上下文

5.2 无监督自进化机制

LLM 自评 → 置信度打分 → 高置信成功/失败 → 更新记忆 Q 值
                           低置信 → 人工/外部验证（可选）

这使得 MIA 在无标注数据的环境下仍能持续进化，关键是 LLM 自评的校准性。

5.3 编排→编舞的范式转移

MIA 的 Manager-Planner-Executor 是编排式（中心化调度）。2026 趋势是向编舞式（去中心化协作）转移：
- A2A Protocol：Agent 间直接通信
- CRDT 状态同步：多 Agent 记忆无冲突合并
- OACP/ACP：Agent 通信协议标准化

六、开放挑战

  1. 泛化受限：低相似度或对抗性领域中，高 Q 值但无关的记忆可能误导
  2. 超参数敏感：λ、K、学习率的固定调度在语义匹配和效用之间产生次优权衡
  3. 长期信用传播：当前仅单步 Q 传播，长程任务中不如完整 TD-learning
  4. 记忆无限增长：当前无有效压缩/蒸馏机制
  5. 检索策略局限：固定检索策略，缺少分层聚类或元学习
