# 小模型 LoRA 微调实证：Qwen3.5-0.8B 达生产级抽取精度 + 边缘端峰值内存压缩 26×

> 出处：arXiv 2606.08051《How Small Can You Go? LoRA Fine-Tuning 270M–8B Models for Merchant Information Extraction in Financial Transactions》（Mastercard 生产系统团队）
> arXiv 2606.19528《Techniques for Peak Memory Reduction for LoRA Fine-tuning of LLMs on Edge Devices》（Qualcomm AI Research）
> 标签：#LoRA #小模型 #Qwen3.5 #边缘部署 #微调 #量化

## 一、内容详细整理

### 1.1 论文一（2606.08051）：0.8B 能否扛起生产级信息抽取？

**任务背景**：Mastercard 生产系统用 LoRA 微调 LLaMA 3.1-8B 做银行交易字符串的商户信息抽取（一条噪声字符串拆出 10 个实体字段：商户名/州/市/街道/电话/邮编/国家/网站/中介/动态描述符），F1=96.95%。但 8B 模型半精度要 16+GB 显存、日处理数百万笔交易时推理吞吐和能耗都是问题——于是系统研究：**最小多大模型能维持生产级精度？**

**实验规模**：24 个模型变体 × 4 模型家族（Gemma 3: 270M/1B/4B；Qwen 3.5: 0.8B/2B/4B；Aya 3.35B；LLaMA 3.1-8B）× 2 种 prompt 策略（Free-Thinking 带思维链 / JSON-Only 直出）× 2 种训练模板（Think/Nothink）。数据集 8,015 条标注交易串（6,125 训练 / 668 验证 / 1,213 测试）。训练用 LLaMA-Factory，跑在 NVIDIA DGX Spark（GB10 Blackwell 芯片、128GB 统一内存）上，共 462 GPU 时训练 + 195 GPU 时评估。

**核心结果表**（F1 / 吞吐 samples per second，DGX Spark batch=4 确定性解码）：

| 模型 | 策略 | F1 | s/s | 备注 |
|---|---|---|---|---|
| LLaMA 3.1-8B | FT (rank32 生产基线) | .9695 | — | 生产现状 |
| LLaMA 3.1-8B | FT (rank8) | .9675 | 0.13 | rank8 仅差 0.20 |
| **Qwen 3.5 4B** | **JO** | **.9660** | **0.51** | **最佳 sub-8B，差 0.35** |
| Qwen 3.5 4B | JO NT | .9624 | 0.53 | Nothink 同分更快 |
| Aya 3.35B | FT | .9572 | 0.33 | 生产部署掉 3-5 分（唯一异类） |
| Qwen 3.5 2B | FT NT | .9518 | 0.98 | 2B 即上 95+ |
| **Qwen 3.5 0.8B** | **FT NT** | **.9475** | **1.32** | **0.8B 匹敌 2-4×大模型** |
| Gemma 3 1B | FT | .9393 | 2.16 | 传统架构 1B 落后 0.8B Qwen |
| Gemma 3 270M | FT | .8735 | 4.09 | 270M 已到 87 分 |

**五大硬结论**：

1. **LoRA rank 8 就够**：LLaMA 8B rank8 vs rank32 只差 0.20 F1；Aya 3.35B 上 rank32 (60.5M 可训练参数, 1.8%) vs rank8 差距在噪声内。rank8 适配器存储省 4×，版本管理更简单——生产直接可用。
2. **Qwen 3.5 0.8B 是异类**：0.8B 拿 94.75 F1，几乎追平自家 2B（95.18），还超过大 25% 的 Gemma 3 1B（93.93）。归因于 **hybrid Mamba-attention 混合架构**——线性时间序列建模 + 精确位置注意力，对「在噪声输入里定位特定子串」的结构化抽取特别有利。
3. **CoT 微调增益与模型大小反相关**：FT（带思维链指令）对多数模型 +0.18~+1.82 F1，小模型受益更大（Gemma 270M +1.82）；但 **Qwen 3.5 4B 反转**——JO 直出反而高 0.45 分，说明容量足够时混合架构能内化抽取逻辑，短 prompt 还能把更多窗口留给任务本身。
4. **Think/Nothink 几乎无差**：Qwen 3.5 全部 6 个配置 ΔF1 < 0.004。更有趣的是 SFT 后 Think 训练的模型推理时全部输出**空思考块**（`<think>\n\n</think>` 直接接 JSON）——模型自己学会了对结构化抽取任务推理无益。Nothink 推理快 1.0-2.9×。
5. **基准分能迁移到生产**：14 个 sub-8B 变体部署为 Databricks Model Serving 端点后重测，平均 F1 只掉 0.8 分；唯一例外是 Cohere2 架构的 Aya（掉 3-5 分）。**Pareto 头部**：LLaMA 8B FT（7.46s, 96.75）→ Qwen 3.5 4B JO（1.97s, 96.60），只让 0.15 分换 **3.8× 延迟降低**。

**训练配方**（可直接抄）：LoRA r=8, α=16（scaling α/r=2.0）、6 epoch（2298 步）、LR 1e-4 cosine、有效 batch 16（4×4 梯度累积）、每 200 步存 checkpoint（12 个/模型）。**峰值普遍出现在 step 1400-2000（epoch 3.7-5.2），之后轻度过拟合**——生产管线必须做系统性 checkpoint 选择。

**逐字段规律**：State（0.983-0.996）和 Zip（0.954-0.995）连 270M 都接近满分；Country 字段方差最大（0.700-1.000，因出现率仅 12.7%）；Merchant_Name 和 Street 在 1B 以下急剧劣化（0.834/0.754）。

### 1.2 论文二（2606.19528）：边缘设备 LoRA 微调峰值内存暴降 26-28×

**问题**：LoRA 只解决「可训练参数少」，但反向传播要存前向激活值，长上下文下 3B 模型微调照样 OOM。瓶颈在激活值而非权重。

**四件套技术**（叠加生效，Llama-3.2 3B 实测峰值内存，单位 GB，列为上下文长度）：

| 配置 | 1024 | 2048 | 4096 | 8192 | 16384 |
|---|---|---|---|---|---|
| FP32 基线 | 27.60 | 29.97 | 47.96 | OOM | OOM |
| + LoRA (r=16) | 19.10 | 26.20 | 40.41 | 68.83 | OOM |
| + 量化（QDQ 即时反量化） | 8.80 | 14.68 | 27.48 | 53.07 | OOM |
| + Checkpointing（选择性激活缓存+磁盘 offload） | 2.37 | 3.33 | 6.29 | 12.21 | 24.05 |
| + Softmax 近似（语义相关 token 子集） | 1.30 | 2.43 | 5.41 | 11.58 | 23.79 |
| + Logits 掩码（只在金标 token 上算损失） | **0.70** | **1.02** | **1.59** | **3.24** | **6.95** |

Qwen-2.5 3B 同样 26.20→1.01GB（28×）。**3B 模型 2048 上下文微调从 26GB 压到 1GB**——手机/Jetson 级设备直接可跑。

**四项技术各自原理**：
- **基座量化 + on-the-fly 反量化（QDQ）**：权重存量化形式，前向时动态反量化。省的是权重驻留内存。
- **记忆高效 checkpointing**：不是传统全部重算——选择性缓存部分激活 + 磁盘 offload。附录 B.3 证明比纯 gradient checkpointing（省 10× 但多 33% 计算）进一步大幅降峰值，代价是额外 I/O。
- **Softmax 近似**：不用层级 softmax/负采样，直接用预训练 LLM 学到的 token 相似度挑「语义相关 token 子集」算交叉熵——论文实验证明优于负采样。复杂度从 O(V) 降到 O(k)。
- **Logits 掩码**：只在金标 token 上计算损失（系统/用户 prompt token 掩为 -100），logits 张量从 V×L 缩到 V×k。文中 70B 模型也用 rank-16 LoRA + 梯度 checkpointing + device_map=auto 双卡跑通。

**与其他方法的关系**：与 QLoRA/LoRA-FA/HyC-LoRA 正交可叠加；与 Zero-Offload（优化器状态卸载到 CPU，边缘设备 CPU 内存也不够）和 NNTrainer（PyTorch 生态集成差）对比各有取舍。**框架无关，可直接集成进 PyTorch。**

**实验配置细节**：所有微调 rank-16 adapter 挂 Q/V 投影、α=16 无 dropout；上下文 2048 右 padding；Llama tokenize 时加 EOS、Qwen 不加；训练步数按数据集 500-2813 步（GSM8K 1000 / MATH 2813 / XSum 1000 / SQuAD 500）。

## 二、查询拓展

- Qwen 3.5 的 hybrid Mamba-attention 架构细节：0.8B 里 Mamba 层与 attention 层的比例是多少？长序列下 KV cache 占用是否也随 Mamba 占比下降？（对 Jetson 部署显存预算关键）
- LLaMA-Factory 的 `qwen3_5_nothink` 模板在 ms-swift 里的等价物（lan-llm-farm 用的是 ms-swift ≥3.10）
- DGX Spark（GB10, 128GB 统一内存）作为「实验与生产分离」工作流的性价比：论文算的 MSRP 几百到几千 GPU 时回本，对比租 A100
- 2606.19528 的 softmax 近似是否已开源？语义相关 token 子集的预计算脚本（余弦相似度 top-k 索引）能否套在中文词表上
- Mastercard 场景的「生产迁移验证」方法论：14 端点重测平均 -0.8 分——自己部署时是否也该建立「基准→服务」双测纪律
- Aya（Cohere2 架构）为何在生产 serving 掉 3-5 分：容器化/逐请求执行与批量推理的差异假设

## 三、归纳总结

1. **0.8B 零件的工程上限被正式标定**：结构化窄任务（可校验输出：JSON/SQL/bbox）上 0.8B LoRA 后达 94.75 F1，距 8B 基线仅 2.2 分，推理快 10×。这为「小模型当零件不当全能助手」提供了最硬的生产级数据支撑。
2. **适配器经济学**：rank8≈rank32（Δ<0.2），训练峰值在 epoch 3.7-5.2，checkpoint 选择必须制度化。LoRA 的成本大头不在训练而在「选哪个 checkpoint」。
3. **推理监督不是免费的但也不贵**：CoT 指令对 <4B 模型稳定 +0.3~1.8 分（即使输出不含推理），对足容量的混合架构反而负贡献——prompt 策略要按「模型容量×架构类型」选，不是越大越要 CoT。
4. **边缘微调的内存公式变了**：权重只占小头，激活值才是 boss。四件套（QDQ 量化 + 选择性 checkpointing + softmax 近似 + logits 掩码）把 3B/2048 从 26GB 压到 1GB，手机级设备可以本地个性化微调，隐私数据不出设备。
5. **两篇论文组合拳**：0.8B 小模型负责「精度够用」，内存四件套负责「哪里都能训」——端侧个性化（数据不出网）+ 局域网训练农场（A100 批量锻造）形成完整光谱。

## 四、趋势判断

- **sub-4B 生产部署将成为默认**：Pareto 数据（0.15 分换 3.8× 延迟）对任何日处理百万级请求的系统都是不可拒绝的交易。预计 2026 下半年更多生产系统把 8B 降到 2-4B 混合架构模型。
- **Mamba-attention 混合架构在端侧继续扩大份额**：Qwen 3.5 全系 hybrid 化且 0.8B 表现异常强，线性注意力对长上下文 KV cache 的节省正是端侧最痛的点。
- **on-device fine-tuning 从 demo 走向产品**：26× 内存压缩 + 手机 8-12GB RAM 的现实，意味着「本地个性化」在 2026-2027 成为隐私敏感场景（输入法/相册/健康）标配能力。
- **「实验-部署」两阶段工作流固化**：DGX Spark 类桌面工作站（统一内存大、无策略限制）做实验筛选 + 生产环境只收编最优适配器——中小团队不再需要云 GPU 蹲点。
- **评估纪律升级**：基准→生产 serving 必须双测（平均 -0.8 分但 Aya -5 分的教训），端到端验证成为部署 gate 的一部分。

## 五、关联分析

- **lan-llm-farm 项目（2026-08-16 笔记）**：四案例正是「0.8B 当零件」路线，本文给它的四问门禁第④条（0.8B 选型理由）补上了最硬的证据——case1 Text-to-SQL 与本文商户抽取同属结构化窄任务，本文 94.75 F1 直接可用作 gate 线参考（≥85% 的设定偏保守，可按字段难度分层）。训练配方（r=8, α=16, LR 1e-4, 峰值 epoch 3.7-5.2）可直接写进 generic_runner.py 的默认超参。
- **Jetson 端侧部署链**：lan-llm-farm 的 merge_and_quantize.sh 产出 Q4_K_M GGUF；本文内存四件套补上「训练侧」的端侧化——如果未来要做「Jetson 上就地微调」（比如巡检场景新类别当日适配），checkpointing+softmax 近似+logits 掩码是必抄组合。Orin Nano 8GB 跑 0.8B LoRA（估算 <2GB 峰值）完全可行。
- **Hermes 自身的小模型策略**：nexa-local-inference skill 用 Ollama 跑本地模型做轻量任务；本文提示可以在局域网 A100 用 LLaMA-Factory 批量锻造多个 rank8 适配器（每个仅几十 MB），按任务热插拔——「一个基座 + N 个零件适配器」比「N 个全量模型」省一个数量级存储。
- **DeepSeek-V4-Flash A100 部署笔记（2026-08-12）**：大模型推理优化与小模型锻造是互补而非替代——大模型做编排/复杂推理，0.8B 零件做批量结构化抽取，路由层按「输出可校验性」分流。
- **Agentic Context Engineering**：本文的 logits 掩码（只学 assistant token）与 context engineering 里「只对响应部分做梯度」的思想同源，训练侧和推理侧的上下文治理正在合流。
