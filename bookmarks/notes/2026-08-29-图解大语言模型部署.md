> 说明：原文正文不可达，以下按图中术语逐项展开——每项为该术语的通识定义与工程要点（非原文照录），保持与《LLM 推理部署检查清单》笔记互引。

### 3.1 显存与量化：显存怎么算

- **VRAM 组成**：模型权重 + KV Cache + 激活/缓冲区。自部署最常犯的错 = 只算权重忘了 KV Cache。
- **KV Cache**：与 batch × 序列长度 × 层数 × 2(K/V) × hidden × 精度字节成正比；长上下文/高并发场景 KV 显存常超权重本身。
- **量化 FP16→INT8→INT4**：权重体积近似减半再减半（16→2 字节），7B 模型 FP16 ≈14GB → INT4 ≈3.5GB；代价是精度损失与部分 kernel（如 Marlin/AWQ/GPTQ）的量化感知部署。

### 3.2 推理加速：速度从哪来

- **两阶段**：Prefill（并行吃 prompt，决定 TTFT）与 Decode（逐 token 自回归，决定 TPOT/ITL）——两者瓶颈不同，优化手段不同。
- **Prefix Cache**：相同系统提示词的 KV 复用，直接砍 Prefill 计算，TTFT 大幅下降（客服/Agent 场景刚需）。
- **Batching**：Continuous Batching 把多个请求的 Decode 拼批，吞吐（TPS）近线性提升，代价是单请求延迟略增。

### 3.3 扩展与选型：规模怎么撑

- **DP / TP / PP**：数据并行扩吞吐；张量并行切单层权重（需 NVLink 高带宽）；流水线并行切层（通信量小，适合跨机）。
- **MoE**：激活参数 << 总参数，同样的"能力预算"下推理显存/算力更省，但需要好的路由与负载均衡。
- **NVLink**：TP 的命脉——卡间带宽不足时 TP 效率急剧劣化（PCIe 上 TP>2 通常不划算）。

### 3.4 指标与成本：拿什么衡量

| 指标 | 含义 | 影响因素 |
|------|------|---------|
| TTFT | 首 token 延迟 | Prefill 速度 + Prefix Cache 命中 |
| TPOT / ITL | 每 token 生成时间 / token 间隔 | Decode 单步延迟 |
| 系统吞吐 TPS | 全系统 tokens/s | Batching + 并发调度 |
| P95/P99 | 尾延迟 | 调度抖动、batch 长尾请求 |
| 真实成本 | $/百万 token | 吞吐 ÷ 卡时成本 |

**铁律**（呼应前言）：先定 SLA（TTFT P95 < x s），再倒推显存/batch/并行策略——而不是反过来。
