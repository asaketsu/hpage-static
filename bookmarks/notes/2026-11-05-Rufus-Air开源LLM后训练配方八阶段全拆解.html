归纳总结

亚马逊团队把 GLM-4.5-Air-Base（106B-A12B MoE）的完整后训练配方开源成 48 页报告：八阶段串行流水线（SFT → Reasoning RL → Coding RL → IF RL → General Agent → Coding Agent → Search Agent → RLHF），全程零新人工标注、零自研蒸馏教师，SFT 数据 100% 来自 17 个公开数据集原样使用。同一底座换这套配方，IFBench 从 33.6 → 76.9，对官方 GLM-4.5-Air 在所有报告基准上领先（仅 Arena-Hard v2 创意写作一项落后）。

四个可迁移的核心结论：
1. SFT 是能力构建阶段不是热身——SFT 单独 checkpoint 已在 IFEval(+5.3)/IFBench(+24.2)/AIME 双年(+6.6/+3.5)反超官方完整后训练版；
2. 难度过滤把 prompt 锁在可学习带（pass 率 >0.8 丢弃、零成功丢弃，过滤即自动课程）；
3. 奖励可靠度决定阶段顺序（硬可验证奖励先训、易被 hack 的 judge/偏好奖励后训，RLHF 压轴；顺序按"被 hack 的暴露时间"排，不按奖励形式排）；
4. 基础设施是配方的一部分（token-in/token-out、chat template 全程一致、Firecracker microVM 沙箱、MoE 的 Rollout Routing Replay）。

算力经济学：SFT 是最大单项（约 832 节点·日）；Agent 阶段成本在 GPU 之外——沙箱服务约 1 万并发、约 $10K/月；BrowseComp 全量评估约 10⁵ 次搜索调用、数百美元。

四个值得单拎的工程细节：
- SFT 三轮 epoch 中第 1 轮就平台化——held-out 分数在 epoch 1 内走平，后续 epoch 只降 loss 不涨分，最终携带 ckpt 3799（平台区内）而非终点。"loss 在降"不等于"模型在变好"。
- Coding RL 64K→128K 中途扩响应预算：截断率 11–28% 压到 <0.1% 后奖励与 LCB 双双续涨；截断样本 loss-mask 掉（不惩罚被截断的）。
- IF RL 的 rubric 只写必要条件：加"可选 rubric"（约 10 条/实例）会让策略学会长文冗余覆盖；只保留必要条件，最终回复从 5.4K 缩到 3.6K token。奖励设计直接塑造输出风格。
- Search Agent 用 mean-only 优势（Dr. GRPO 变体）：judge 噪声下，除以组标准差会把 0.1 的部分分差放大成与真解同权（+3.75），成对消融 mean-only 全面领先（55.8–64.8 vs 49.7–58.7）。噪声奖励通道必须改优势估计器。

诚实边界（论文自述）：阶段顺序是"一个可行的顺序"非"最优顺序"（未探索多专家蒸馏合并）；Coding Agent 算力用尽未收敛；无单一基准套件全程跟踪（跨阶段归因有缺口）；创意写作输给官方版与 Nemotron（未试风格化 RM）。

指南分析

小团队照抄路径（按论文自身可复用性排序）：
1. 单阶段借用零门槛：论文明确支持"拿一个阶段或一个基础设施组件而不取其余"。最易迁移的是难度过滤三件套（正确性过滤用强教师跑一遍 + 可学习带 [0, 0.8] + 动态采样）——任何 RLVR 任务通用，零额外标注。
2. IF RL 合成法可整体复用：14K 多约束（教师增广 2-6 原子约束+每约束 Python 验证函数）+ 13K 对抗多轮（教师扮用户主动制造失败），两数据集合训 90 步就拿到 +24.7 的 Multi-challenge——性价比全表最高，且合成管线全可程序化。
3. 不要照抄的：阶段顺序未证明最优；RLHF 段的 HH-RLHF 原始标签在他们的设置里是负资产（直接训会掉编码/IF 能力，需过滤后仅取 prompt）。
4. 预算红线：Agent RL 的真实成本在沙箱与外部 API（$10K/月级），不在 GPU——规划 Agent 训练时按"每阶段单独预算"而非均值外推。
