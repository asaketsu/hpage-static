定锚

领域坐标：小型双足机器人 Sim2Real 的「表达层」首篇系统实现——把 LLM 创造力（情绪编舞）约束进物理可执行域（IK + RL 跟踪），是 microduck 赛道从"能走"迈向"有性格"的第一份公开方法论文档。

收录理由：用户 DUCK-Pi_5 恰好卡在同一个位置——行走/站立已验收、头颈解锁（E24）已拍板、且用户明确审美要求"头和脖子不能锁死，很不真实，也不好看"。本篇是这条需求的外部工程实证：情绪表达 ≠ 额外控制器，而是把情绪作为观测条件（one-hot）+ 板载参考播放器 + 跟踪式奖励，全部塞进同一个行走网络。

场景锚点：读者场景 = 已有一个能走的 RL 鸭子，想让它"活起来"——回答三个问题：情绪怎么进网络（122 维观测契约）、动作从哪来（LLM 编排→IK→DeepMimic 式跟踪）、值不值得抄（单 run 多情绪 vs 多策略硬切换的分岔）。

内容整理：S0/S1 分层架构与训练管线

3.1 一句话总纲

一个 122 维输入 / 15 维输出的单网络 S0（低层跟踪控制器），在 mjlab+MuJoCo Warp 上用单次 FlashSAC run（4096 并行鸭子）同时学会行走、转身、21 种情绪、头部和喙；上层 S1（LLM）只做两件事——选速度、选情绪——情绪切换对 S0 是一次调用。

3.2 核心架构：S0/S1 分层（本篇最大的方法论增量）

层 是什么 职责边界
S1（心智） LLM（作者写"Astra、Opus，随便什么跑鸭子心智的"） 只选 velocity + emotion 两个高层指令，不碰伺服
S0（低层控制器） 单网络，纯 RL，sim-to-real 把指令翻译成 15 个伺服目标位置，行走与情绪同网络输出
参考播放器（板载） 网络旁边的小模块 存 21 情绪编舞库，播选定情绪——给网络喂"现在+0.2s 后"的目标姿态

作者原话定位："S0 is not the emotional intelligence. That sits on top of it."——情绪智能在 S1，S0 只是让情绪物理上成立的执行层。这与库内《解耦机器人学》《走路用RL干活用Transformer》《System1预筛与System2协同》三篇的分层思想完全同向，但第一次给出鸭子体量的落地实例。

3.3 观测/动作契约（122→15）

网络输入 122 维（博客原述构成）：
- 本体感知：陀螺仪 + 重力投影 + 14 关节角 + 14 关节速度 + 上一步动作
- 速度指令：S1 下发的 velocity command
- 情绪条件：21 类 one-hot
- 参考段：播放器给的目标姿态（现在 + 0.2 s 超前），覆盖头/躯干/腿/喙

输出：15 个目标位置 = 14 关节 + 喙。注意一个真实增量：官方 xgoduck_runtime 的策略只输出 14 关节（嘴舵机单独控制，见 hardware 仓库表述），而本文 S0 把喙纳入网络输出——头颈+喙联动是情绪表达的关键通道，官方栈没做，作者做了。

诚实边界：博客未给 122 维的精确逐段分解（按原述组件粗算约 73 维，参考段约占 49 维），精确分解不可从原文核实，复现时需自行设计。

3.4 训练管线（五段式，全部可映射到现有工具链）

  1. 编舞（Choreography）：每个情绪 = 姿态（posture）+ 风格（style）+ 几个手势（gestures），由 Opus 生成——LLM 当编舞师，不当控制器
  2. 全身 IK：把编舞落到鸭子关节上，约束脚平贴地面（物理合理性第一道闸）
  3. DeepMimic 式跟踪奖励：作者明说"这些动作没有物理根据，所以训练必须有"——策略在仿真里学跟踪这些动作，学出来的=鸭子物理上做得到的版本（物理合理性第二道闸，也是核心）
  4. 单次 FlashSAC run：mjlab + MuJoCo Warp，4096 并行鸭子；BAM 伺服模型（力矩曲线 + 15 ms 延迟 + 齿隙 gear play）+ 随机推扰。行走/转身/21 情绪/头/喙全部出自这一次 run
  5. 上真机前双闸：先在独立 CPU MuJoCo（自带另一套伺服模型）里跑；再带鸭子 runtime 代码入环跑——两道检查过了才碰硬件

3.5 真机部署与诚实现状

  • S0 以 ONNX 跑在鸭子 runtime 里；切情绪 = 上层一次调用
  • 平静类情绪稳；弹跳类情绪和行走仍会偶发摔倒——兜底方案是原厂 get-up 控制器把它扶起来（不掩盖问题，明写现状——比多数项目发布诚实）
  • 浏览器可玩同一网络：MuJoCo 编译成 WebAssembly，W/S 行走、A/D 转向、Space 推它、Inputs 面板可视化网络实际看到的观测

归纳总结

  1. 分层胜过全能：S1（LLM 选目标）+ S0（RL 执行）+ 参考播放器（板载编舞）三件套，职责切得极干净——LLM 的创造力和 RL 的物理可靠性各就各位，中间用 IK 和跟踪奖励两道闸把前者约束进后者
  2. 情绪是观测条件，不是行为库：one-hot 进网络 + 参考段进观测，让"情绪"成为策略的条件变量而非硬切换的技能——这是与"7 技能硬切换"路线的本质分岔
  3. 单 run 多任务：行走+转身+21 情绪+头+喙一次训练全出——条件化策略的规模效应示范
  4. 物理诚实三连：IK 贴地约束（设计期）→ DeepMimic 跟踪（训练期）→ CPU 仿真+runtime 入环双闸（部署期）——每一层都在过滤"物理上做不到的姿态"
  5. 诚实的现状报告：弹跳情绪+行走仍摔、靠原厂起身兜底——表达层不是免费午餐，成熟度=平静情绪>弹跳情绪≈行走
  6. 平台增量：喙纳入网络输出（官方栈嘴是独立控制）——头颈+喙联动是表达力的关键通道

趋势判断

  • "表达层"成为小型双足的下一个竞争维度：Microduck 生态（Pollen 官方→Luwu 商业复刻→社区）已把"能走"变成 commodity；情绪/性格是差异化下一站——Luwu 硬件已带音视频模块+ToF，表达层硬件就位，缺的就是这类策略
  • LLM→编舞→IK→RL 跟踪有望成为表达层的标准管线：它把"生成动作"这个 LLM 不可靠环节外包给物理过滤，规避了 LLM 直接出控制信号的幻觉风险
  • 离策 RL 第二波成型：FastSAC（2512.01996）→ FlashSAC（RSS 2026）→ 本文真机应用，离策从论文走向"爱好者可用"——但官方生态默认仍是 PPO/rsl-rl，换栈窗口还没到临界
  • 浏览器 Wasm 仿真=新的"可玩性发布"形态：把部署网络直接放进网页让人玩，是低成本传播+众测验收的组合拳

指南分析：情绪层落到 DUCK-Pi_5 的分阶段方案

前提：零破坏原则——本节是立项级指导材料，未经用户拍板不动任何项目代码（与吸收分析纪律一致）。

阶段 0（当日可做，零成本）

  • 玩在线仿真：打开 anashoussaini.com/sims/xgoduck/，W/S 行走、A/D 转向、Space 推扰、切情绪看观感——这一步回答"这玩意到底值不值得追"（用户目测=唯一真值，与真机测试纪律同款）
  • 对照观察：平静情绪 vs 弹跳情绪的步态差异、切情绪瞬间有没有踉跄、被推后的恢复表现

阶段 1（若立项：情绪 MVP，3-5 情绪起）

  1. 情绪集：不抄 21 个，从 calm / happy / alert / sad 起步——平静类是已验证稳定区
  2. 编舞：LLM 生成每情绪的"姿态+风格+手势"关键帧序列 → 全身 IK 落关节（贴地约束）——用户运动学/CAD 背景直接对口
  3. 观测契约扩展：现 61 维 + 情绪 one-hot(4) + 参考段（建议先只做头颈+喙的 now+0.2s，约 10-20 维）——只加不改，保留 hot-swap 可能性评估后再定
  4. 奖励：velocity 族保持 + 新增 DeepMimic 式 pose 跟踪项（头颈/喙为主）；甩头惩罚单独设防（头部质量占比警示）
  5. 参考播放器：Pi5 板载 python 播放器，情绪切换=一次调用
  6. 验收门：沿用 12ep 采样+用户目测真值纪律；每情绪单独判，12/12 才算对齐

阶段 2（远期，带触发条件）

  • 全身情绪参考（腿+躯干+头颈+喙）并入——触发条件：阶段 1 单情绪 12/12 且弹跳类不摔
  • S1 接入（OH2P/asa 语音链选情绪）——触发条件：情绪集≥5 且切换延迟可接受
  • FlashSAC 离策栈评估——触发条件：FlashSAC 代码开源且与 mjlab 兼容性实测通过；当前 F04 栈已统一 rsl-rl，无实证收益不换栈

风险与不做项

  • ❌ 不做：现在就动 obs 契约（61 维契约是全家共享，动=全家重训，E 系列未收官）
  • ❌ 不做：直接对标本文数字（0.79kg/HLS1910/15ms 延迟均与用户硬件不同——吸收原则不吸收数字，跨平台数字禁直接对标）
  • ⚠️ 风险：单策略条件化与用户三模型拍板冲突——存档为对照路线，启动前须用户重新拍板
  • ⚠️ 成熟度提示：弹跳情绪+行走仍摔（作者自述）——表达层的"弹跳类"在源头项目就没过关，MVP 只做平静类是规避而非妥协

拓展应用推荐

  • OH2P 语音助手 → duck S1 心智：用户的语音链+LLM 就是现成 S1，鸭子当第三个语音终端——"说句话，鸭子用情绪回应"是表达层与语音链的自然合流
  • 浏览器 Wasm 仿真自托管：把 DUCK-Pi_5 的策略放进网页让用户手机直接玩——既是演示（用户"不要无头"的可视化要求同源）也是零成本众测

  • 发布形态借鉴：博客+在线可玩仿真+真机视频三件套，是个人机器人项目低成本获得传播的模板
