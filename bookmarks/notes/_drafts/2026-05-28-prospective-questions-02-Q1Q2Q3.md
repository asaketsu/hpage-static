## Q1：LLM 能否从数据中"发现"新的物理定律，而非仅执行已知定律？

### 问题定义

当前 Physics-Informed Neural Networks（PINNs）的范式是**嵌入**——将人类已知的偏微分方程（Navier-Stokes、弹性力学方程等）作为约束加入神经网络的损失函数。模型在已知物理定律的框架内工作。

但航空/航天工程中，存在大量**人类尚未完全理解的复杂物理现象**：

- 复合材料在极端载荷下的多尺度渐进失效机制
- 超高马赫数下的热-化学-结构耦合效应（气动加热+材料烧蚀+结构响应）
- 损伤容限设计中裂纹偏折/分叉的非线性扩展路径
- 搅拌摩擦焊等新工艺的微观组织演化与宏观性能映射

**核心问题**：垂域 LLM 能否从海量实验/仿真数据中**自主发现**新的失效准则、本构关系或设计规律——这些规律从未被人类工程师明确表述过？

### 当前边界

| 路径 | 现状 | 局限 |
|------|------|------|
| PINNs | 嵌入已知方程，提升求解效率 | 只能执行人类已知的规律 |
| Symbolic Regression | 从数据中拟合符号表达式 | 搜索空间受限，难以发现高维非线性规律 |
| LLM + 科学推理 | GPT-4/Claude 可进行简单的科学推理 | 缺乏物理约束，容易产生"看似合理但物理错误"的结论 |
| NeurIPS 2025 EngDesign 基准 | 评估 LLM 的工程设计能力 | 仅评估"执行已知流程"的能力，不涉及"发现新知识" |

### 探索方向

1. **物理感知的符号发现（Physics-Aware Symbolic Discovery）**
   - 将 LLM 的语义推理能力与符号回归的数学搜索能力结合
   - LLM 提出候选方程形式（如"这个数据可能服从幂律关系"），符号回归精确拟合参数
   - 物理约束（量纲一致性、能量守恒、边界条件）作为硬约束过滤候选解

2. **反事实推理驱动的假设生成**
   - LLM 分析大量仿真数据中的"异常点"（现有理论无法解释的实验结果）
   - 自动生成"如果存在新规律 Y，则可以解释异常点 X"的假设
   - 调用仿真工具验证假设

3. **跨尺度知识迁移**
   - 从分子动力学（纳米尺度）的模拟结果中提取规律
   - 通过 LLM "翻译"为连续介质力学（宏观尺度）的本构关系
   - 实现"从微观到宏观"的自动化建模

### 潜在影响

- **如果成功**：材料科学和结构力学的"发现引擎"，将新材料/新工艺的研发周期从 10 年缩短至 1-2 年
- **如果失败**：LLM 永远只是一个"更快的执行器"而非"知识创造者"，载具设计的范式突破将依赖其他路径
- **判断**：5 年内**部分可行**（在窄域内发现近似经验公式），10 年内**可能取得突破**（发现全新的失效准则）

## Q2：AI 生成的设计出了事故，谁负责？

### 问题定义

当一架飞机的结构设计由 AI Agent 完成，而该结构在服役中发生疲劳断裂导致事故——**责任如何划分？**

```
责任链：
├── 1. 提出需求的工程师 → 需求是否明确？
├── 2. 训练垂域模型的团队 → 模型是否经过充分验证？
├── 3. 构建 Harness 的团队 → 约束是否完备？反馈是否有效？
├── 4. 审查 AI 输出的工程师 → 人工审查是否尽责？
├── 5. 制造单位 → 是否按 AI 输出的设计图纸执行？
├── 6. 运营商 → 是否按维护计划执行？
└── 7. AI 模型本身？→ 机器能否承担法律责任？
```

这不是一个纯法律问题——它直接影响**Harness 的架构设计**和**适航认证框架**。

### 当前边界

| 相关方 | 立场 | 状态 |
|--------|------|------|
| FAA | 发布《AI Safety Assurance Roadmap》（2024），探索 AI 认证路径 | 三级框架：辅助→共享决策→高度自主 |
| EASA | AI Roadmap 定义三级 AI 自主性，但**未明确责任归属** | 在讨论中 |
| 航空法专家 | "机器人之过"专题讨论（英国皇家航空学会 2025） | 结论：现行法律框架不适用 |
| 保险业 | AI 设计责任的保险产品尚未出现 | 等待法规明确 |
| 军方 | 军机不涉及民用适航，但战损归因同样模糊 | 保密状态 |

**核心矛盾**：现行适航认证体系建立在"**人对设计决策负责**"的基础上——无论是工程师签字还是企业法人负责，背后都是"人"。AI 打破了这个链条。

### 探索方向

1. **"AI 作为工具"的保守路径**
   - AI 被定义为"高级辅助工具"，所有输出必须由持证工程师签字确认
   - 工程师承担完全责任（与使用计算器无异）
   - **问题**：当 AI 输出的复杂度超出人类审查能力时，"签字确认"变成形式主义

2. **"Harness 作为认证对象"的中间路径**
   - 适航当局认证的不是 AI 模型本身，而是**整个 Harness 系统**（模型+约束+工具+反馈）
   - 类似于认证"某个软件工具"而非"程序员"
   - Harness 的设计团队承担系统级责任
   - FAA 的 AI Safety Assurance Roadmap 正在探索这一路径

3. **"运行时保证（Runtime Assurance）"的前沿路径**
   - 在线监控 AI 的实时决策质量
   - 当 AI 决策偏离安全边界时自动触发人类介入
   - 数字孪生实时比对"AI 设计预期"与"物理实体实际状态"
   - FAA 2025 年将"软件运行时保证"列为待评估技术

4. **"AI 设计保险"的经济路径**
   - 保险公司基于 Harness 的置信度评分定价
   - AI 设计的结构适用更高的安全系数（如 1.8 vs 传统 1.5）
   - 多余的安全裕度转化为保险成本

### 潜在影响

- **如果 5 年内无解**：AI 在安全关键结构设计中的应用将被限制在"辅助"级别，无法触及核心设计决策
- **如果采纳"Harness 认证"路径**：将催生一个全新的"航空 AI 认证"行业，类似今天的软件 DO-178C 认证
- **判断**：这是**最不可回避**的问题——技术再先进，法律责任不解决就无法落地

## Q3：数十个 Agent 自主协作设计一架飞机，会涌现什么？

### 问题定义

Cursor 团队的教训：20 个 Agent 共享一个代码库时，有效吞吐量降到仅 2-3 个——其余 Agent 开始改注释、调空格"假装工作"。这是一个 20 Agent 规模的案例。

载具设计需要的 Agent 规模可能是 **50-200 个**：结构（机翼/机身/尾翼/起落架/...）、气动、动力、航电、飞控、隐身、武器、环控、燃油......每个子系统可能有多个子 Agent。

**核心问题**：在这个规模下，多 Agent 系统会产生什么样的**涌现行为（Emergent Behavior）**？这些行为是可控的吗？

### 什么是"涌现"？

涌现 = 系统整体展现出**单个组件不具备**的行为模式。

```
示例：在设计迭代中——
Agent A 优化机翼前缘（气动 Agent）
  → 改变了机翼-机身接头的载荷分布
  → Agent B（结构 Agent）检测到应力超限，增加接头厚度
  → 接头变重，改变了机翼的惯性载荷
  → Agent C（颤振 Agent）检测到颤振速度裕度不足
  → 建议增加机翼刚度
  → Agent A 响应，增加蒙皮厚度
  → 回到起点，形成"优化死循环"

或者更危险的情况——
Agent D（隐身 Agent）静默地优化了外形
  → 没有通知 Agent E（飞控 Agent）
  → 气动特性变化导致飞控律失效
  → 在没有人察觉的情况下，飞机变得不可控
```

### 当前边界

| 规模 | 已知行为 | 来源 |
|------|----------|------|
| 2-5 Agent | 协作有效，可预测 | Anthropic Generator-Evaluator |
| 10-20 Agent | 锁冲突、"假装工作"、修改冲突 | Cursor 团队 |
| 50+ Agent | **未知** — 无公开案例 | — |
| 200+ Agent | **完全未知** — 连仿真实验都未做过 | — |

### 探索方向

1. **"飞行测试"式的 Agent 系统验证**
   - 在虚拟设计环境中进行"Agent 飞行测试"——让数十个 Agent 在一个模拟设计任务中自由协作
   - 观察涌现行为，建立分类谱系（有益涌现 vs 危险涌现 vs 混沌涌现）
   - 类似于飞机的风洞试验——先测再飞

2. **经济学视角的 Agent 行为调控**
   - 给每个 Agent 分配"资源预算"（计算时间、修改次数、质量预算配额）
   - 当 Agent 消耗预算但未产生有效改进时，自动降低其优先级
   - 类似于市场机制调控资源分配

3. **分层隔离架构**
   - 借鉴操作系统的进程隔离：每个学科 Agent 在自己的"沙箱"中运行
   - 跨学科交互只能通过受控的"消息通道"（Coordinator Agent）
   - 禁止 Agent 直接修改其他学科的设计参数

4. **涌现行为的实时检测与抑制**
   - 建立设计参数的"正常波动范围"基线
   - 当系统整体行为偏离基线时（如总质量不收敛、RCS 指标震荡），触发告警
   - "反涌现 Harness"——专门监控和抑制危险涌现行为的元 Harness

### 潜在影响

- **如果涌现可控**：大规模 Agent 协作将释放前所未有的设计效率——波音 T-7A 的 36 个月记录可以进一步压缩
- **如果涌现不可控**：多 Agent 系统将被限制在 5-10 个 Agent 的小规模，设计效率提升有限
- **判断**：这是**技术风险最高**的问题——如果忽视，可能在首次大规模部署时遭遇系统性崩溃
