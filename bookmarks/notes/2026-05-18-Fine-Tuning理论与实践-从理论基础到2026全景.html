摘要

Fine-tuning 是 LLM 从"通用预训练"走向"下游任务可用"的必经之路。本文从理论基础（迁移学习 → 适配器 → LoRA → 强化学习对齐）梳理发展脉络，系统对比 SFT/RLHF/DPO/GRPO/ES 等训练范式，详解 LoRA/QLoRA/DoRA/PiSSA 等 PEFT 技术，提供从数据准备到工具链选型再到训练实践的完整实操指南。核心结论：2026 年，LoRA/QLoRA 是个人开发者的唯一现实选择，GRPO 是推理能力突破的关键，ES 是 RL 之外的全新范式。

一、Fine-Tuning 理论基础与发展脉络

1.1 核心定义与定位

Fine-tuning（微调）是预训练后的第二阶段训练，目标是将通用语言模型适配到特定任务、领域或风格。

预训练（Pre-training）→ 微调（Fine-tuning）→ 部署（Deployment）
    通用语言能力          任务/领域适配          推理服务

Fine-tuning vs 预训练的本质区别：

维度 预训练 Fine-tuning
数据 海量无标注语料（TB 级） 高质量标注数据（K~100K 级）
目标 学习语言表示和通用知识 任务对齐和领域适配
参数 全部参数更新 全部或部分参数更新
成本 千卡集群数周~数月 单卡数小时~数天
规模 万亿 token 百万~千万 token

     ↓

     ↓

     ↓

     ↓

     ↓

     ↓

     ↓
2026 GRPO+RLVR/DAPO 时代：可验证奖励，推理模型成熟

1.3 理论基石：为什么 Fine-tuning 有效？

迁移学习理论（Transfer Learning）：

  1. 特征复用：预训练模型在底层学习通用语言特征（语法、语义、常识），这些特征在多数下游任务中都有价值
  2. 表示空间对齐：微调将预训练模型的表示空间旋转到下游任务的最优位置
  3. 参数高效性：研究表明，大部分下游任务只需更新 <1% 的参数即可达到接近全量微调的效果

数学直觉：

预训练权重 $W_0$ 已经接近下游任务的局部最优解 $W^*$。微调本质上是寻找一个小的增量 $\Delta W$：

$$W = W_0 + \Delta W$$

其中 $\|\Delta W\| \ll \|W_0\|$，这就是 PEFT 的核心假设。

二、Fine-Tuning 方法全景

2.1 训练范式分类

Fine-tuning 按训练目标可分为三大类：

Fine-Tuning
├── 监督微调（SFT）— 学习"怎么做"
│   ├── Full Fine-tuning（全量）
│   └── PEFT（参数高效）
│       ├── LoRA / QLoRA
│       ├── DoRA / PiSSA / LoRA+
│       └── Adapter / Prompt Tuning
│
├── 偏好对齐（Preference Alignment）— 学习"什么更好"
│   ├── RLHF（PPO + Reward Model）
│   ├── DPO（直接偏好优化）
│   ├── RLAIF（AI 反馈）
│   └── ORPO（联合 SFT+ 偏好）
│
└── 推理强化（Reasoning RL）— 学习"如何推理"
    ├── GRPO（DeepSeek 组相对优化）
    ├── DAPO（DeepSeek 动态奖励）
    ├── RLVR（可验证奖励）
    └── ES（进化策略，2025 新范式）

2.2 监督微调（SFT）

目标：教会模型遵循指令、输出格式、领域知识。

数据格式（Instruction-Response 对）：

{
  "messages": [
    {"role": "system", "content": "你是一个专业的法律助手"},
    {"role": "user", "content": "什么是合同法中的要约？"},
    {"role": "assistant", "content": "合同法中的要约是指..."}
  ]
}

SFT 的局限：

  • 只能教会模型"模仿"数据中的行为，无法纠正偏好
  • 无法解决"有害输出"问题
  • 无法提升推理能力

2.3 全量微调 vs PEFT 对比

方法 可训练参数比例 显存需求（7B） 性能 适用场景
Full Fine-tuning 100% 120GB+（多卡） 基准 研究/超算
LoRA 0.1-1% 12-16GB 95-98% 个人/团队
QLoRA 0.1-1% 6-8GB 93-96% 单卡消费级
DoRA 0.1-1% 14-18GB 96-99% 追求极致
PiSSA 0.1-1% 12-16GB 95-98% 快速收敛
Adapter 1-5% 16-20GB 90-95% 多任务

2.4 LoRA 数学原理

核心公式：

$$W = W_0 + \Delta W = W_0 + BA$$

其中：
- $W_0 \in \mathbb{R}^{d \times k}$：预训练权重（冻结）
- $B \in \mathbb{R}^{d \times r}$：降维矩阵（可训练）
- $A \in \mathbb{R}^{r \times k}$：升维矩阵（可训练）
- $r \ll \min(d, k)$：秩（通常 8~64）

关键洞察：

  1. 低秩假设：任务特定的权重变化可以用低秩矩阵近似
  2. 参数效率：参数量从 $d \times k$ 降到 $r \times (d + k)$，减少 99%+
  3. 无推理延迟：训练时分离的 $BA$ 可以合并到 $W_0$ 中，推理时无额外计算

LoRA 的局限（NeurIPS 2025 发现）：

  • 侵入维度（Intruder Dimensions）：LoRA 会在权重矩阵中引入新的高秩奇异向量，这些维度是遗忘（catastrophic forgetting）的主要来源
  • 持续学习恶化：在连续微调场景中，LoRA 会逐步累积侵入维度，性能持续下降
  • 与 FullFT 不等价：虽然目标任务精度可能相同，但访问的是解空间的不同区域

2.5 LoRA 进阶变体（2024-2025）

变体 核心改进 适用场景
QLoRA 4-bit 量化权重 + LoRA 单卡消费级 GPU
DoRA 分解为幅度 + 方向更新，解耦 magnitude 和 direction 追求极致性能，逼近 FullFT
PiSSA 用 SVD 初始化 $A$ 和 $B$，快速收敛 数据量少、需要快速迭代
LoRA+ 非对称学习率（$B$ 用更大 LR） 大宽度模型
rsLoRA 随机缩放，稳定训练 大秩设置
AdaLoRA 动态秩分配，自动剪枝 多任务/资源受限
MoRA 矩阵低秩适配，更大容量 高容量需求
LoRA-FA 冻结 $A$，只训练 $B$ 进一步减少参数

2.6 偏好对齐范式演进

RLHF（2022）：四模型架构

1. SFT 模型（Actor）— 生成候选响应
2. Reward Model — 打分人类偏好
3. Critic/Value Model — 估计状态价值
4. Reference Model（冻结）— KL 约束

问题：需要训练 4 个模型，显存翻倍，训练不稳定。

DPO（2023）：二模型架构

$$\mathcal{L}_{DPO} = -\log \sigma\left(\beta \log \frac{\pi(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi(y_l|x)}{\pi_{ref}(y_l|x)}\right)$$

  • 消除 Reward Model 和 Critic
  • 直接用偏好对 $(y_w, y_l)$ 优化
  • 效果接近 RLHF，成本降低 60%

ORPO（2024）：单模型联合训练

  • SFT + 偏好对齐在同一个损失函数中完成
  • 只需一个模型，无需 Reference Model
  • 适合资源极度受限场景

2.7 GRPO 与推理强化（2024-2025）

GRPO（Group Relative Policy Optimization）：DeepSeek 推理模型的核心

核心创新：用组内统计替代 Critic

对于同一个 prompt，采样 G 个响应 → 计算每个的 reward → Z-score 标准化
advantage_i = (r_i - mean(r)) / std(r)

优势：
- 不需要训练 Value Model，显存减半
- 组内相对评价天然适合推理任务（数学题、代码等有标准答案）
- DeepSeek-R1 用 GRPO 实现了无需人类标注的推理能力涌现

RLVR（Reinforcement Learning with Verifiable Rewards）：

  • 用规则验证器替代 Reward Model
  • 数学题：检查答案是否正确
  • 代码题：运行测试用例
  • DeepSeek-R1 的核心训练方法

DAPO（DeepSeek Prover Optimizer）：

  • 动态奖励：根据任务难度调整奖励
  • 长上下文优化：处理长推理链
  • 解决 GRPO 的高方差梯度问题

2.8 进化策略（ES）：2025 新范式

核心思想：用随机扰动 + 选择替代梯度下降

1. 生成 N 个扰动版本：W + ε_i（ε_i 随机噪声）
2. 评估每个版本的 loss
3. 选择表现最好的方向更新权重

2025 突破（arXiv 2509.24372）：

  • 首次在 10 亿参数级别成功应用 ES 进行全参数微调
  • 无需反向传播，无需梯度
  • 与 GRPO 在推理任务上表现相当

意义：ES 是 RL 之外的全新后训练范式，尤其适合：
- 梯度不可导的场景
- 黑盒模型
- 需要探索性优化的任务

三、Fine-Tuning 实践指南

3.1 决策树：什么时候需要 Fine-tuning？

你的任务失败原因？
├── 模型不知道你的领域知识 → RAG（检索增强）
├── 模型不理解你的格式要求 → Prompt Engineering
├── 模型行为不符合你的偏好 → Fine-tuning
│   ├── 只需改格式/风格 → SFT（LoRA/QLoRA）
│   ├── 需要改偏好/价值观 → DPO/RLHF
│   └── 需要提升推理能力 → GRPO/RLVR
└── 模型太慢/太贵 → 蒸馏（Distillation）

2026 年黄金法则：Prompt → RAG → Fine-tune → Distill

3.2 数据准备（最关键环节）

数据质量 > 数据数量：

维度 高质量 低质量
准确性 100% 正确 存在事实错误
多样性 覆盖多种场景 单一模板
复杂度 由易到难 全部简单/全部复杂
一致性 格式/风格统一 格式混乱

数据量建议：

模型规模 最小有效量 推荐量 饱和点
1-3B 1K 5-10K 50K
7B 5K 20-50K 200K
14-30B 10K 50-100K 500K
70B+ 20K 100-300K 1M+

合成数据（Synthetic Data）：

教师模型（GPT-4/Claude）→ 生成指令+响应 → 质量过滤 → 学生模型微调

关键实践：
1. 用更强的模型生成数据（教师-学生蒸馏）
2. 多轮迭代：微调 → 评估 → 生成新数据 → 再微调
3. 质量过滤：用规则 + 模型双重过滤
4. 多样性增强：同义改写、场景扩展

3.5 Unsloth 实战示例

from unsloth import FastLanguageModel

# 加载模型（4-bit 量化）
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/llama-3-8b-bnb-4bit",
    max_seq_length=2048,
    load_in_4bit=True,
)

# 添加 LoRA
model = FastLanguageModel.get_peft_model(
    model,
    r=16,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_alpha=16,
    lora_dropout=0,
    bias="none",
)

# 训练
trainer = SFTTrainer(
    model=model,
    train_dataset=dataset,
    max_seq_length=2048,
    args=TrainingArguments(per_device_train_batch_size=2, gradient_accumulation_steps=4),
)
trainer.train()

# 合并并保存
model.save_pretrained("fine-tuned-model")

3.7 超参数调优指南

参数 推荐范围 说明
LoRA rank (r) 8~64 越大容量越大，但可能过拟合
LoRA alpha r~2r 通常设为 r 的 1-2 倍
Learning rate 1e-4 ~ 5e-4 LoRA 比全量微调用更大 LR
Batch size 1~8（单卡） 配合 gradient accumulation
Epochs 1~3 通常 1-2 个 epoch 足够
Warmup ratio 0.03~0.1 防止初期不稳定
Weight decay 0.01 防止过拟合

3.8 训练监控与评估

关键指标：

指标 含义 目标
Training loss 训练集损失 持续下降
Validation loss 验证集损失 不显著高于训练 loss
Perplexity 困惑度 越低越好
BLEU/ROUGE 生成质量 任务相关
Human eval 人工评估 金标准

过拟合信号：
- 训练 loss 持续下降，验证 loss 开始上升
- 模型在训练集上表现完美，在未见数据上退化
- 输出变得过于"模板化"

缓解过拟合：
- 减少 LoRA rank
- 增加 weight decay
- 减少训练 epoch
- 增加数据多样性

4.1 2026 年 Fine-tuning 格局

4.2 未来方向

  1. LoRA 的极限：NeurIPS 2025 的"侵入维度"研究推动下一代 PEFT 方法
  2. GRPO 的演进：DAPO、Dr. GRPO、GSPO 等变体解决高方差问题
  3. ES 的规模化：从 1B 到 70B+ 的 ES 微调正在验证
  4. 多模态微调：视觉-语言联合微调（如 LLaVA 系列）
  5. 持续学习：解决 LoRA 在连续微调中的累积退化问题
