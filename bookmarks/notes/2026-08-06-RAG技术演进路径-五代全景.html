一句话定义

从 2020 年的"无脑检索 top-k"到 2026 年的"RL 训练 Agent 自主找信息"，RAG 技术经历了五代演进——每一代都在解决上一代的痛点。

内容整理

① 2020 — 基础 RAG（解决"知识不在模型里"）

起点：Lewis 等人的 RAG 论文

组件 技术
检索 DPR（Dense Passage Retrieval）稠密检索
匹配 向量相似度
生成 LLM
  • 第一次让 LLM 能"外接知识库"
  • 缓解幻觉和时效性问题

痛点："无脑检索"——把所有文本切成 chunk 做向量索引，查询取 top-k 就完事。chunk 彼此孤立、检索粗糙、对复杂问题无力。

② 2022–2023 — 检索精度升级（更准）

技术 创新
ColBERTv2 "单向量"→token 级多向量 + MaxSim 延迟交互；残差压缩把存储降 6–10 倍。检索器从"粗"变"准"
Modular RAG RAG 不是固定管道，而是一堆可编排模块（检索/重排/生成），像乐高一样组合。架构开始"模块化"

③ 2023–2024 — 反思纠偏 + 结构增强（更准、更懂关系）

反思纠偏路线：给系统装"质检员"

技术 机制
Self-RAG 用反思 token 自己决定要不要检索、内容对不对
CRAG 用轻量评估器三路径纠正（正确用/错误重写或联网/模糊混合）

→ 解决了"检索到垃圾也不知道"的问题。

结构增强路线：

技术 机制
RAPTOR 用递归摘要树组织文档，适合全局性、多跳、总结类问题
GraphRAG (Microsoft) 把文本抽成实体–关系知识图谱，用 Leiden 社区摘要做多跳推理
LightRAG 轻量化图 RAG
HippoRAG / HippoRAG2 用个性化 PageRank 做多跳推理

→ "结构化知识"路线，但全量图谱构建很贵。

④ 2024–2025 — 路由与成本优化（更省）

技术 策略
Adaptive RAG 按查询复杂度动态路由——简单问题直接 LLM 答、复杂问题才走多步检索
LazyGraphRAG 把社区摘要延迟到查询时才算，索引成本降到 GraphRAG 的 0.1%
长上下文路由 2M token 窗口出现后，结论是"不替代 RAG，而是分工"——简单查走 RAG（几分钱），复杂多跳走长上下文，视觉文档走 ColPali
GraphRAG-Bench (ICLR 2026) 给出经验法则：图的价值随查询复杂度上升

⑤ 2025–2026 — 自主智能体 + 强化学习（更自主）

技术 创新 效果
Agentic RAG AI Agent 动态决定"用什么工具（向量库/网页/API/SQL）、查几轮、怎么合成" —
Search-R1 用 RL 端到端训练 LLM 学会"何时搜、搜什么" 在 Qwen2.5-7B 上比普通 RAG 提升 41%
DeepRetrieval 直接以检索指标（recall@k、NDCG）为奖励优化查询 —
DeepResearcher RL 训练深度研究能力 —
MCTS-RAG 把蒙特卡洛树搜索融进推理 —

→ 从"固定流程"走向"会自己找信息的智能体"。

查询拓展

  • Search-R1 的 RL 训练具体用什么奖励信号？检索 recall@k 还是最终答案准确率？
  • LazyGraphRAG 的 0.1% 索引成本具体怎么做到的？查询时计算社区摘要的延迟如何？
  • HippoRAG2 的个性化 PageRank 与 GraphRAG 的 Leiden 社区摘要相比，多跳推理精度差异？
  • ColPali 的视觉文档检索在什么场景下优于文本 RAG？
  • Agentic RAG 的工具选择决策（向量库/网页/API/SQL）是怎么实现的？路由器架构？

归纳总结

RAG 五代演进的底层逻辑可以用一条线串起来：

基础检索 → 精度提升 → 质量保障 → 成本优化 → 自主智能
   ↓          ↓          ↓          ↓          ↓
 解决有     解决准     解决对     解决贵     解决活

每一代解决的核心矛盾：
- ① 基础：知识不在模型里 → 解决"有没有"
- ② 精度：检索太粗糙 → 解决"准不准"
- ③ 反思+结构：检索到垃圾不知道 + 不懂关系 → 解决"对不对"
- ④ 路由：什么都全量检索太贵 → 解决"贵不贵"
- ⑤ Agentic+RL：固定流程不会自适应 → 解决"活不活"

当前最前沿在第⑤代——RL 训练 LLM 自主决策检索策略，代表项目 Search-R1 在 7B 模型上实现 41% 提升。

趋势判断

  • RAG 不会死，只会进化：长上下文（2M token）出现后有人喊"RAG 已死"，但实际结论是"分工"——简单走 RAG 省钱，复杂走长上下文
  • 图 RAG 成本断崖式下降：LazyGraphRAG 把索引成本降到 GraphRAG 的 0.1%，知识图谱路线的经济障碍被消除
  • RL + RAG 是下一个爆发点：Search-R1 证明 RL 端到端训练检索策略可行，7B 小模型也能大幅提升。这和 SkillOpt（训练技能文档）是同一思路——不动模型权重，优化外部策略
  • 查询复杂度决定技术选型：GraphRAG-Bench 的经验法则——简单查询用基础 RAG，复杂多跳用图 RAG，视觉文档用 ColPali
  • Agent 化是终局：从"固定管道"到"Agent 自主决定工具/轮次/合成策略"，RAG 正在变成 Agent 的一个能力维度而非独立系统

关联分析

  • 与 Hermes Agent 的直接关联：Hermes 有 rag-index-rebuild（重建 RAG 索引）和 hybrid-search（三路融合搜索 semantic+keyword+entity）Skill。这篇推文给出了 RAG 技术选型的完整路线图——Hermes 当前在第②~③代（ColBERTv2 级混合搜索），可以参考第④~⑤代的 Adaptive RAG 和 Agentic RAG 做升级
  • 与用户知识层体系的关联：用户有 knowledge-fusion（并行扫描5源+实时搜索+交叉验证）和 knowledge-query（统一知识查询入口）。Agentic RAG（第⑤代）正是 knowledge-query 的进化方向——Agent 动态决定用哪个数据源、查几轮、怎么合成
  • 与 AWS Context Ontology Accelerator 的关联：AWS 的语义上下文层是第③代"结构增强"路线的企业级实现——用形式化本体 + 知识图谱替代 GraphRAG 的自动抽取
  • 与 SkillOpt 的关联：SkillOpt + Search-R1 是同一范式——不动模型权重，用 RL 优化外部策略（Skill 文档 / 检索策略）。两者可以融合：用 Search-R1 的 RL 方法训练 Hermes 的知识查询 Skill
  • 与用户研究方向（航空结构AI）的关联：航空结构设计规范的多跳推理（规范条款→材料属性→载荷工况→适航符合性）天然需要图 RAG（第③代）或 Agentic RAG（第⑤代）
