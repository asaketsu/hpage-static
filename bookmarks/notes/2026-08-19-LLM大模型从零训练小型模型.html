一、核心概念（内容整理）

文章是"从理论走向实践"的一篇：在有限算力（Mac/MPS 亦可）下，从零手写一个 LLaMA 架构的 83M 小模型，跑通 预训练 → SFT 微调 → 推理 → 导出 的完整链路。核心命题：训练一个完美大模型不是目标，对 LLM 全流程建立直观而系统的认知才是。

三层链路认知框架：

阶段 数据 学到什么
Pre-training 序列猴子 10B token 通用语料 语言的统计规律与世界知识（续写能力）
SFT BelleGroup 350 万条中文对话 指令遵循、对话交互（"基础模型"→"可用助手"）
导出/推理 — HF 标准格式分发、生态对接

二、技术要点（指南分析）

2.1 LLaMA 架构五件套（与原始 Transformer 的差异）

组件 原始 Transformer LLaMA（本文实现） 为什么
归一化 LayerNorm（Post-Norm） RMSNorm（Pre-Norm） 去均值中心化省计算；前置归一化训练更稳、收敛更快
注意力 MHA GQA（16 Q / 8 KV，n_rep=2） KV Cache 显存减半；质量优于 MQA；提前熟悉推理优化主流方向
位置编码 正弦绝对位置 RoPE 旋转位置 只旋 Q/K；相对位置性质；外推性更好
前馈 2 层 MLP + ReLU SwiGLU 三矩阵门控 同参数量下表达力更强；hidden = 4/3×dim 对齐 64 倍数
输出层 独立矩阵 weight tying 词表 6144×dim 768 的参数直接省掉（与嵌入共享）

2.2 模型配置（82.59M 参数）

dim=768, n_layers=12, n_heads=16, n_kv_heads=8, vocab=6144, max_seq_len=512。
配置类继承 PretrainedConfig（model_type="My-LLM"）、模型类继承 PreTrainedModel——这两个继承是"能进 HuggingFace 生态"的关键（save_pretrained / AutoModelForCausalLM / push to hub）。

2.3 训练工程细节（文章最有价值部分）

  1. 数据集懒加载：预扫描 jsonl 逐行字节偏移量（f.tell()），__getitem__ 时 seek+readline——10B token 语料不用进内存；坏行重试 10 次。
  2. X/Y 错位：X=input[:-1], Y=input[1:]——next-token 的 shift 在 Dataset 做，模型 forward 不做。
  3. loss 双保险：模型内 cross_entropy(ignore_index=0, reduction='none') 逐 token + 训练循环 loss_mask 加权——padding 不计损失。
  4. 断点续训全状态：checkpoint 保存 model/optimizer/scaler/进度 + 三种 RNG 状态 + DataLoader shuffle 的 torch.Generator 状态——恢复后数据顺序与中断前一致。比"只存 model"的教程高一个工程等级。
  5. 原子保存：.tmp + os.replace；step 检查点滚动保留 5 个；latest 损坏自动回退。
  6. 混合精度：CUDA 走 autocast+GradScaler；MPS/CPU 用 nullcontext（MPS 对 autocast 支持不完整）。
  7. 梯度累积 8 步：有效 batch 48×8=384；顺序 unscale→clip(1.0)→step 不能乱。
  8. 余弦退火 LR：warmup 线性升 → 余弦衰减 → min_lr=lr/10 封底。
  9. DataParallel 诚实注释：DP 只适合 <1B 演示；真实训练 DDP/FSDP/DeepSpeed。

2.4 SFT 关键差异

  • 数据：apply_chat_template 编码多轮对话（system + user/assistant 交替）。
  • 损失掩码 generate_loss_mask：在 token 流里搜索 <|im_start|>assistant\n 子序列，从其后到首个 eos（含）标 1——只对回答计损失，用户输入不计。这是 SFT 的本质：教模型"怎么答"而非"复述问"。
  • 优化器 Adam→AdamW；init_model 先加载预训练权重（_orig_mod. 前缀兼容 torch.compile）。
  • 掩码实现是纯 Python 双指针子串匹配，慢但对任意 chat template 通用。

2.5 推理与导出

  • 推理态 forward 只投影最后位置（h[:, [-1], :]）——省算力技巧。
  • generate：温度采样 + top_k 截断（top_k 外 logits 填 -inf 再 softmax）；stop_id 提前终止。
  • 导出：register_for_auto_class → save_pretrained → HF 标准目录，trust_remote_code=True 直接加载。
  • 预训练 vs SFT 效果：预训练只会续写（给问题续出更多问题），SFT 以对话方式回应——"可用助手"的转变直观可见。

verify_structure.py（CPU，torch 2.13.0）：7 项断言全过——参数量 82.59M 与文章 83M 对齐、前向 shape、推理态单位置投影、因果遮挡一致性、RoPE 保范数、repeat_kv 形状、RMSNorm 统计、generate 产出。

文章代码为"展示格式"（缩进丢失、is not None 粘连），项目落盘版已修复为可运行代码，语义 100% 忠实。两处文章自身小瑕疵已记录：①模型 forward 不做 X/Y shift（由 Dataset 负责，与部分教程不同）；②inference.py 的 generate_super 是注册后别名，报错时改 generate。

四、可学到的点（归纳总结·续）

  1. "从零"的边界：从零 ≠ 从矩阵乘法写起，而是"不借助现成模型 checkpoint/训练框架，只依赖 torch+transformers 基础设施"。83M 级从零训练在消费级硬件完全可行。
  2. HF 生态对接的两个继承：PretrainedConfig + PreTrainedModel（含 register_for_auto_class）就是自定义模型进 HF 生态的全部门票。
  3. 断点续训的正确完整度：RNG 状态 + shuffle Generator 状态 + iter_per_epoch 校验——训练可复现性是这套教程的核心卖点。
  4. GQA/RoPE/SwiGLU 实现细节：repeat_kv 的 expand+reshape、RoPE 实虚部 stack、SwiGLU hidden_dim 4/3 规则——"知道"与"会写"的差距。
  5. SFT loss mask 的通用实现：模板子序列搜索法不依赖特定 tokenizer 结构，任意 chat template 通吃。
  6. 成本意识：Mac MPS 全程可跑；"跑通链路"的算力门槛已降到消费级——与 face-api.js 浏览器门禁（6.5MB 模型）共同印证"小模型工程学"趋势。
