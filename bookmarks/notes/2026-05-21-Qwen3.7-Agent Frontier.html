1|# Qwen3.7-Max: The Agent Frontier
 2|
 3|**来源**: qwen.ai | Hacker News #11 (620 pts, 249 comments)
 4|**日期**: 2026-05-21
 5|**URL**: https://qwen.ai/blog?id=qwen3.7
 6|
 7|## 摘要
 8|
 9|阿里云发布 Qwen3.7-Max，定位为"Agent Frontier"——面向 Agent 应用的前沿模型。该模型在 Artificial Analysis 的 Omniscience 评测中取得了 SOTA 的非幻觉率，优于 Opus 4.7、Gemini 3.1 Pro 和 GPT5.5。
10|
11|## 关键要点
12|
13|- **Agent 定位**: 模型明确定位为 Agent 应用场景，强调自主执行和工具调用能力
14|- **Omniscience SOTA**: 在 Artificial Analysis 的 Omniscience 评测中非幻觉率领先，但需注意该指标只统计错误答案，模型可以通过拒绝回答来降低幻觉率
15|- **Omniscience Index**: 引入了更全面的评测——同时奖励正确答案、惩罚幻觉、不奖励拒绝回答
16|- **中文模型表现分化**: 讨论提到 GLM 5.1 和 DeepSeek 4 Pro 在 Omniscience 指标上表现较差
17|- **幻觉检测仍是开放问题**: HN 讨论中普遍认为"模型知道自己不知道什么"仍是未解决的技术难题
18|
19|## 个人分析
20|
21|Qwen3.7-Max 的发布有几个值得关注的点：
22|
23|1. **"Agent Frontier"定位**: 这标志着模型设计从"对话助手"转向"自主代理"。Agent 场景对工具调用、多步推理、长期记忆的要求远超普通对话。
24|2. **Omniscience 指标的双刃剑**: 非幻觉率 SOTA 听起来很好，但正如 HN 评论指出的——一个永远说"我不知道"的模型也能达到 0% 幻觉率。Omniscience Index 的引入（同时惩罚拒绝回答）才是更健康的评估方式。
25|3. **中文模型竞争格局**: GLM 5.1 和 DeepSeek 4 Pro 的相对落后值得关注。作为 Hermes Agent 团队，这意味着在中文场景下可能需要考虑多模型路由策略。
26|4. **幻觉检测的困境**: HN 讨论揭示了一个根本问题——LLM 的训练数据决定了它"不知道"的东西无法被训练到。RL 训练教的是"答对"而不是"承认不知道"。
27|
28|## 行动建议
29|
30|- 考虑在 Agent 路由中增加 Qwen3.7-Max 作为中文 Agent 场景的备选
31|- 关注 Omniscience Index 的后续更新，作为模型评估的重要参考
32|- 幻觉检测仍是核心挑战，Agent 设计需要内置"不确定性表达"机制
33|- 多模型路由策略在中文场景可能成为必要
