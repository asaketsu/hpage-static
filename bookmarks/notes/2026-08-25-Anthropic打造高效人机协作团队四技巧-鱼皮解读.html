一句话总纲

清晰的目标+明确的角色分工+扎实的文档+统一的质量标准——这些本来就是好团队该有的，AI 不会拯救一个混乱的团队，它只会把团队原本的样子无限放大。 Anthropic 四技巧（写清楚协作信息/分好工/让 AI 主动/慢慢建立信任）与本机 AGENTS.md + Skills + 团队角色 + 人工确认的架构高度吻合，四技巧相当于对本机实践的一次外部框架验证。

一、内容整理

1.1 技巧一：写清楚协作信息

核心：对 AI 来说，没写下来的事情就等于没发生。口头共识/私聊/老员工脑中的业务背景 AI 看不到。

四个信息源：会议纪要（飞书妙记转写）→ 聊天记录总结（企业微信/腾讯元宝）→ 企业知识库（飞书/语雀/Notion）→ 项目配置文件（CLAUDE.md/AGENTS.md）

1.2 技巧二：给 AI 和人类分好工

共享工作空间：AI 和人类要共同维护同一套产物，避免重复劳动（"注册量" vs "激活量"的例子）。

Skills 技能文件 = 角色的"离职交接文档"——包含角色定位、干活步骤与规范、权限。可整体迁移给另一个 AI 复用。

知乎回答工作流案例：搜集问题 Agent + 撰写回答 Agent 两 Agent 协作，通过 Zhihu CLI 调用知乎数据。

1.3 技巧三：让 AI 主动

北极星目标：AI 不主动不是因为不聪明，是没告诉它终极目标。北极星必须由人类设定。

案例：团队把"让新用户容易上手"定成北极星 → AI 主动发现报错提示太难懂，提文案修改建议 → 第二周新用户明显增多。

1.4 技巧四：和 AI 慢慢建立信任

渐进式权限授予：从简单易检查任务开始 → 确认质量稳定 → 逐步授予更多权限。

AI 资讯推送案例：初期 AI 搜集→草稿→人工检查→编辑确认→发布；后期质量稳定后跳过大人工步骤。

1.5 核心洞见（文章最有价值的一句）

AI 不会拯救一个混乱的团队，它只会把团队原本的样子无限放大。

本机 AGENTS.md 已包含四技巧的全部要素：写清楚协作信息（上下文一次性原则）、分好工（四角色+Skills）、北极星目标（团队协作协议核心架构）、慢慢建立信任（三层权限模型+人工确认）。本文价值在于为本机实践提供了来自 Anthropic 官方的外部框架验证。

2.2 "Skills 即离职交接文档"的表述

本文把 Skills 文件比作"离职交接文档"——任何一个 AI 拿到同一份 Skill 文件就能复刻同款 Agent。这与本机 skill_view() 的复用机制（Skill 可被任何 Agent 加载）完全一致，但"离职交接文档"比"角色定位"更直观，可进 skill 文档作为心智模型。

三、趋势判断

趋势 1：AI 团队协作的"文档前置"将成为标准实践

依据：Anthropic 官方+鱼皮解读+本机 AGENTS.md 三重印证——"没写下来就等于没发生"正在从工程经验上升为团队协作规范。预期 AGENTS.md/CLAUDE.md 类文件将成为项目标配（类似 README/CHANGELOG），纳入团队文化而非仅限 AI 工具配置。

依据：本文第三技巧的"北极星"概念——不是任务层面的指令，而是团队层面的终极目标声明。这与本机 AGENTS.md 的"团队核心架构"同构，但多数 Agent 系统缺少这一层。预期有多 Agent 架构的团队会逐步把北极星声明写进根目录的 AGENTS.md 或系统提示的固定前缀。
