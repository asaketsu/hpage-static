2. 核心命题：信任曲线 + 验证瓶颈

2026.9.21 她发帖：「here's how i shipped 2,500 PRs last month to production」。她强调数字从来不是目标，信任才是——自己不在场时，agent 也能交出高质量的活。

两条关键判断（均本人原话）：

  • 「The bottleneck with agents is verification.」 agent 写代码很快，难的是确认它写对了。她做性能优化的起点：手工抓 Chrome DevTools trace 抓到自己都烦了，才想到「wait, we have agents. What am I doing?」→ 写验证类 skill，让 agent 自己跑应用、抓 trace、找热点、推性能。
  • 「Agents are like new hires in a constant state of amnesia and idiocy.」 记不住你说过什么，也不会真的学会新东西——只能靠 rules、skill、工具和长期记忆去近似。

信任曲线：她把用 agent 讲成一条往上爬的曲线。「一到五个」区间最难走出去（每个对话都要盯、不停纠偏、人一走就错），难在不知道从哪下手；从 5 跳不到 100 的原因就是还不信任它们的产出——不信任硬开 100 个子 agent = 一堆低质量 PR、回归和 bug。

3. 方法论核心：信任倒金字塔（越往上越该多花力气）

她 2026.10 帖子给出的四层结构（编号为层级序，原文即倒金字塔）：

层级 手段 要点
① 最上层 改代码库本身 更好的架构、更强的类型和不变量、清晰的边界。agent 爱照抄现有代码、爱走最短路径——那就让最省事的那条路正好是对的
② 静态分析 lint、测试、CI——在问题出现前拦住
③ 文字 注释、rules、AGENTS.md、skill——靠 agent 自己判断、无法强制，少用，但要用
④ 最下层 人工审查 最难扩展的一层；agent 合码速度太快不可能每个 PR 细看，人的精力应花在设计「让 agent 默认就做对的环境」

配套两条铁律：

  • 「every time you intervene and correct your agent, you should think about how to eliminate it entirely.」——每次人工纠偏都该想如何彻底消除这次干预。
  • 「your codebase is memory」——agent 反复犯的错不变成约束，就会像病毒一样一直复制下去。

4. 懒是实在的动力：Benny → Grok Bot → pstack

  • Benny（头像小狗）：她给自己做的 bot——睡觉时自动分拣 Slack bug 报告、复现并修掉确认 bug。动机原话：「I'm a fairly lazy person. … And I wanted to just fix them all.」
  • Grok Bot：团队作品；她最骄傲的是客户端架构——用自制 agent 友好框架（代号 Dune，目标=让上下文很少的 agent 也能默认写出高质量代码）重构了糙原型。
  • pstack（开源 skill 合集，她每天在用）：内置 benny 自动化包（默认不启用）；/create-verification-skill 生成验证 skill；/correct 把重复纠错提层固化；/automate-me 照工作记录起草个人 mode。
  • 现在的角色自述：「almost like a manager for my digital colleagues」——别人给 Grok Bot 提反馈，她的 bot 自动去修，她只 review 代码。

5. 普通人可照做的七条（作者提炼，人人可起步）

  1. 边学边公开——她进 EmberConf 靠的就是学 Ember 时写的博客推文；学到哪写到哪。
  2. 列害怕清单——「If you're not afraid, you're too comfortable.」挑一件因怕没做的事去试。
  3. 从最烦的重复活下手，先自己走一遍——Benny 和验证 skill 都诞生于她手工干烦之后；亲手走通才知道怎么算做对。
  4. 动手前先定义验证——做网页让 agent 打开页面截图，写脚本让它跑一遍贴结果。
  5. 少开几个，盯清楚——先 1-5 个，看它们具体在哪犯错，别急着堆数量。
  6. 同一个错，往上提一层修——第二次纠正同一问题时：能写成检查就写检查，能改结构就改结构，文字说明放最后。
  7. 每年问自己一次还兴奋吗——她当经理前就约定每年重估「这还是不是梦想中的工作」。

6. 作者自评（Mai Yang 个人增量，非 Lauren Tan 观点）

Mai Yang 自述其视频流水线（选题/字幕/初稿/封面均已 bot 化）对照信任曲线仍停在第一段：每个关键节点仍人工把关，部分是必要把关、部分是自己没给 bot 足够验证手段只好自己当验证器；倒金字塔也是反着用（同一问题第二次出现多半只在对话里再提醒，很少变成自动检查）。下一步=把「盯着看」逐条变成 bot 能自跑的验证。

归纳总结

  • 全文一句话：放手的本质不是勇气而是信任，信任不是感觉而是验证基建——用四层倒金字塔把「人盯 agent」升级为「环境保证 agent 做对」。
  • 深层结构：她的路径 = 三个反转。①职业反转：非 CS→金融→VBA→顶级前端→AI 工程师，每次跃迁的入口都是「公开发布的内容+社区里的人」；②工具反转：从「agent 写不了生产代码」的怀疑者到月产 2500 PR，转折点不是模型变强而是她把验证外包给了 skill；③管理反转：从管人（Netflix 经理）到管 digital colleagues，管理对象变了但方法论同构——设计环境而非逐案审查。
  • 倒金字塔的本质是控制论分层：强制约束（架构/类型/CI）优先于软约束（文字/rules），人工只兜底——与我们「确定性护栏优先、LLM 判断兜底」的排序完全一致。
  • 「agent=失忆新员工」是反浪漫化的清醒：不指望 agent「学会」，只靠外部结构近似记忆——这解释了为什么 skill/AGENTS.md/codebase 约束是长期资产而对话纠偏是易耗品。

趋势判断

  • 职业身份迁移：「manager for my digital colleagues」预示工程师角色重心从写码转向设计验证环境+审查——与「Agent Skills 才是关键抽象层」一脉相承：资产从代码变成「让 agent 做对的结构」。
  • verification 是下一代竞争点：模型能力趋同后，产出质量差距来自验证基建（谁能让 agent 自证正确，谁就能放量）。她从 5→100 agent 的瓶颈不是模型是信任，信任的载体是 skill 化验证。
  • 个人轨迹的普适信号：非 CS 出身+公开学习+社区节点，仍是进入 AI 一线的主通道——「边学边公开」的复利在她 20 年轨迹里反复兑现。
  • bot 化产品形态：Benny→Grok Bot 的路径（先给自己做 bot→产品化为「人人可定义自己的 bot」）是 AI 产品孵化的典型模板：自用自动化先行，验证后再泛化。

指南分析

倒金字塔的落地操作序（可直接抄）：

  1. 盘点你正在人工盯的每个 agent 环节，标记「必要把关」vs「我当验证器」两类。
  2. 对「我当验证器」类：先亲手走一遍流程（她强调：不亲手走通就不知道怎么算对），再写验证 skill（agent 自己跑、自己截图/贴结果/比对断言）。
  3. 同一错误第二次出现时强制提层：能写 lint/测试→写；能改结构/类型→改；只剩文字（rules/注释）→放最后并接受其不保证执行。
  4. 代码库本身是第一杠杆：让「最省事的路=对的路」——agent 爱照抄现有代码，所以现有代码的质量就是 agent 产出的上限（codebase is memory 的另一面）。
  5. 放量前置条件：只有当某类任务的验证 skill 齐备、错误不再复发，才把该类任务从 1-5 个 agent 放量——不信任时放量=低质量 PR 灾难。

拓展应用推荐

  • Hermes 侧直接可落的三件事：
  • 高频人工盯梢环节（如笔记 11 检查项、发版 grep 红线）逐条 skill 化为 agent 自跑验证——对标 /create-verification-skill。
  • error-case-library 加「提层」字段：每个案例标注是否已升级为 lint/门禁/结构约束，未提层的定期催办——对标 /correct。
  • cron/长任务验收先行定义验证物（判分表/回读证据），无验证物的任务不发射——对标「动手前先定义验证」。
  • 借鉴 Dune 思路：给低上下文子代理的任务模板默认携带验证标准（验收判据/禁做清单），降低「失忆新员工」出错率。
