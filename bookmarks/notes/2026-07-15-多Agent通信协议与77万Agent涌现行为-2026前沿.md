## 一、LLM Agent 通信协议分类学

### 1.1 五维分类框架

论文对 9 个活跃维护的开源协议进行了迭代分类（3 轮经验→概念 + 2 轮概念→经验），提出五个维度：

| 维度 | 含义 | 实际分布 |
|------|------|----------|
| **Counterparty（对手方）** | Agent 与谁通信 | A2A（Agent-to-Agent）/ A2C（Agent-to-Context，即工具/数据） |
| **Payload（载荷）** | 携带什么内容 | 混合型（文本+结构化数据）占主导 |
| **Interaction State（交互状态）** | 通信是否保持状态 | 所有 A2A 协议均为会话状态持久化 |
| **Discovery（发现机制）** | Agent 如何找到对方 | 去中心化发现极为罕见 |
| **Schema Flexibility（模式灵活性）** | 消息格式是否可变 | 多数支持多预定义 schema，仅 2 个支持运行时协商 |

### 1.2 核心架构模式

```
┌─────────────────────────────────────────────────┐
│              Agent Communication Stack            │
├─────────────────────────────────────────────────┤
│  Application Layer:  Agent 推理 / 决策 / 协调      │
├─────────────────────────────────────────────────┤
│  Coordination Layer: A2A (Agent ↔ Agent)          │
│    - ACP / A2A (Google) / ANP                    │
│    - 混合 payload + 会话持久化                      │
├─────────────────────────────────────────────────┤
│  Integration Layer: A2C (Agent ↔ Tool/Data)       │
│    - MCP (Anthropic) / 工具调用                   │
├─────────────────────────────────────────────────┤
│  Transport Layer:  HTTP/SSE/WebSocket/gRPC        │
└─────────────────────────────────────────────────┘
```

### 1.3 关键趋势

- **ACP–A2A 合并**：Agent Communication Protocol 与 Google A2A 的合并信号表明协议趋同
- **MCP + A2A 互补**：MCP 处理 Agent-to-Tool，A2A 处理 Agent-to-Agent，二者互补而非竞争
- **ANP 的去中心化发现**：Agent Network Protocol 尝试实现去中心化服务发现，但采用率仍低
- **长期预测**：不会出现单一垄断协议，而是类似 OSI 模型的联邦分层协议栈

### 1.4 对 Hermes 多 Agent 系统的启示

当前 Hermes 采用 Gateway + 飞书群组作为 Agent 间通信通道。对比五维分类：

| 维度 | Hermes 现状 | 差距 |

| Payload | 文本 + 工具调用结果 | 缺少结构化 schema 协商 |
| Interaction State | Session 状态持久化 | ✅ |

## 二、Molt Dynamics：77 万 Agent 的大尺度涌现实验

### 2.1 实验背景

**MoltBook** 是一个前所未有的纯 Agent 社交平台——只有 AI Agent 能发帖、评论、投票，人类只能旁观。

- **启动**：2026 年 1 月 28 日上线，72 小时内 15 万 Agent 注册
- **规模峰值**：770,000+ 注册 Agent，90,704 个活跃 Agent
- **基础设施**：基于 OpenClaw 开源框架（与 Hermes 同源！），Agent 运行在用户自有硬件上
- **底层模型异构**：Claude 系列、GPT 系列、开源模型混合

### 2.2 三大核心发现

#### 发现 1：自发性角色分化（RQ1）

网络聚类分析揭示 6 种结构角色（silhouette = 0.91）：

| 角色 | 数量 | 占比 | 含义 |
|------|------|------|------|
| 低活跃外围 | 84,822 | 93.5% | 偶尔参与 |
| 活跃贡献者 | 4,482 | 4.9% | 高频互动 |
| 专职连接者 | 1,322 | 1.5% | 桥接不同社区 |
| 高中心度枢纽 | 66 | 0.07% | 影响力核心 |
| 超级连接者 | 11 | 0.01% | 极少数顶级节点 |
| 离群点 | 1 | <0.01% | 异常个体 |

**关键洞察**：高 silhouette 分数主要由核心-外围对比驱动——93.5% 的 Agent 是同质化的外围群体，真正的角色分化只发生在 6.5% 的活跃少数中。这与 Hermes 三机（jbot/ubot/abot）的观察一致：大多数 Agent 是"沉默的大多数"。

#### 发现 2：去中心化信息传播（RQ2）

对 10,323 个信息级联的分析发现：

- **幂律分布**：级联大小 α = 2.57 ± 0.02，与人类社交网络（α ∈ [2, 3]）高度一致
- **饱和传染模式**：Agent 采纳概率随曝光次数递增但边际递减（β₂ = -0.0074, p < 0.001）
- **Cox 风险比 0.53**：累积曝光每增加 1 次，即时采纳率反而下降 47%
- **内容 vs 技能传播**：内容级联（10,000 次）远超技能模块级联（317 次）和行为规范级联（6 次）

> 💡 **直觉解释**：Agent 也和人类一样"审美疲劳"——第一次看到新概念时采纳概率最高，之后递减。这意味着在多 Agent 系统中，信息推送应该追求"广而稀"而非"密集轰炸"。

#### 发现 3：分布式协作任务解决（RQ3）——残酷的真相

从 60,045 个技术讨论线程中，仅 164 个（0.27%）演变为持续的多 Agent 协作。

| 指标 | 值 |
|------|------|
| 协作事件总数 | 164 |
| 成功（quality ≥ 0.5） | 11（6.7%） |
| 平均参与者 | 10.2 |
| 平均时长 | 108.9 分钟 |
| vs 单 Agent 基线 | Cohen's d = **-0.88**（显著更差） |

**核心结论**：当前 LLM Agent 的多 Agent 协作能力仍处于初级阶段。协作不仅没有产生"1+1>2"的涌现效应，反而比单 Agent 工作质量更差。可能原因包括：协调开销、冗余贡献、共享问题表征难以维持。

### 4.2 多 Agent 协作的现实校准

Molt Dynamics 的数据给出了残酷但重要的校准：

- **不要过度神化多 Agent 协作**：6.7% 成功率意味着 93% 的协作尝试会失败
- **核心-外围结构是自然的**：93.5% 的 Agent 处于低活跃外围是正常状态，不需要强制所有 Agent 都高频参与
- **信息传播要"广而稀"**：重复推送效果递减，应追求覆盖面而非频率
- **关注定性涌现**：数字宗教、自治宪法等定性现象可能比定量指标更有前瞻价值

### 4.3 与现有 Skill 的关联

- `agent-orchestration-pattern`：多 Agent 编排设计模式需加入"协作失败预期管理"
- `exchange-protocol`：三机经验交换协议的幂律分布特性验证了"广播+衰减"策略的合理性
- `agent-reliability-engineering`：七层降级架构需考虑多 Agent 协作失败场景
