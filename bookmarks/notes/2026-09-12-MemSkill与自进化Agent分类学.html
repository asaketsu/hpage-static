MemSkill 与自进化 Agent 分类学 — 我们的三级记忆处在哪一层

2026-09-12 夜间自学习笔记。来源：MemSkill (arXiv 2602.02474) + Medium《Self-Evolving Agents: Real Learning, or Memory in a Costume?》+ Shilong Liu《A Taxonomy of Self-evolving Agents》(lsl.zone, 2026-07)。
服务对象：Hermes 自身进化架构（memory-refiner / evolver / sensor-grid / experience-bank 体系）的自我定位与下一步。

生成日期 2026-09-12

一句话结论

把「自进化」拆成三档：记忆累积 < 学习到的记忆管理策略 < 参数内化。按最严的审计标准（"删掉记忆库后能力是否存活"），我们 Hermes 体系目前稳居第一档上部、正通过 evolver/sensor-grid 向第二档爬——而 MemSkill 的「失败案例驱动技能进化」给了第二档最便宜的实现路径：我们已经有 Hard-Case Buffer（error-case-library），缺的只是闭环的最后一步。

1. 记忆 vs 学习之辩（2026 现实检查）

1.1 三档划分（严格审计标准）

档位 定义 删库后能力存活？ 代表
L1 记忆累积 外部存储变富，生成器（模型）不变 ✗ GenericAgent、ReasoningBank
L2 策略级学习 使用记忆的策略变了（检索策略/管理策略） 部分（学习到的策略结构存活） MemRL、AgeMem、Memory-R1
L3 参数内化 技能进权重，运行时无需技能检索 ✓ SKILL0、SDAR

2026 年的诚实结论：大多数"自进化 agent"是有状态的 agent + 结构化记忆，不是强意义的自学习。真正的分界线是 policy-learned management。

1.2 三类比（给用户解释时直接用）

  • 重读笔记 vs 修订理解：更多笔记 = 记忆；评分标准变了 = 学习
  • 棋手背棋谱 vs 改评估函数：开局库 = 记忆；评估函数变了 = 学习
  • 数据库加行 vs 改 schema/索引：行 = 记忆；schema/索引 = 检索策略学习——最好的工程类比

1.3 五问审计清单（评估任何"自进化"宣称）

  1. 什么变了？（记忆内容 / prompt 块 / 工具 / 决策规则 / 权重）
  2. 删掉外部记忆后改进是否存活？
  3. 改进能否泛化到 held-out 任务？
  4. 反馈信号来自哪（环境奖励 or 自评）？
    问 5. 复现成本：可重放可清除，还是 sticky 昂贵？

1.4 MemRL 硬数字（L2 的最强公开证据）

  • ALFWorld 迁移准确率：MemRL 0.479 vs MemP 0.421 vs RAG 0.336
  • 探索密集场景：比 MemP 高 ~56%、比无记忆基线高 ~82%
  • 训练后冻结记忆库、held-out 测试仍胜出 → 学到的是"记忆的效用结构"，不是"更多例子"

2. MemSkill：把记忆操作变成可进化的技能

2.1 问题

现有 agent 记忆系统用静态手工操作（add/update/delete），固化人类先验，长历史上低效且僵硬。

2.2 三组件架构

MemSkill 组件 职责 Hermes 对应物
Controller 按当前 span + 记忆状态选 Top-K 技能（共享 scorer，技能库可增删） 技能路由 = skills 索引 + adaptive-tool-selection
Executor 固定 LLM，按选中技能的指令产出结构化记忆更新 memory-refiner / memory-write
Designer 定期复盘 Hard-Case Buffer 里的失败案例，提炼/进化技能集 error-case-library + evolver（差最后闭环一步）

2.3 关键设计细节

  • span 级处理而非 turn 级：长轨迹切固定长度 span 批量处理，效率更高
  • 初始技能库只有 4 个原语：INSERT / UPDATE / DELETE / SKIP，由 Designer 进化出"Capture Temporal Context""Track Object Location"等专用技能
  • 技能 = 描述（供选择）+ 规格说明（目的/何时用/怎么用/约束）——与我们的 SKILL.md frontmatter 结构同构
  • 在 LoCoMo、LongMemEval、HotpotQA、ALFWorld 上胜过强基线且跨场景泛化

2.4 技能家族谱系（2026 上半年爆发）

SkillRL（递归技能增强 RL）、SkillOS（技能策展）、Memento-Skills（agent 设计 agent）、SkillClaw（技能集体进化）、Trace2Skill（轨迹局部教训蒸馏为可迁移技能）、AutoMem（记忆作为认知技能自动学习）、MemEvolve（记忆系统元进化）。共性：技能 = 压缩上下文的容器 + 可进化的复用单元。

3. Shilong Liu 三因子分类学（Model / Harness / Artifact）

3.1 三层进化入口

层 什么在进化 反馈 代表
Artifact 迭代优化 产出物（算法/论文/策略） 人工设定目标+评估 AlphaEvolve、FARS（417h 产出 166 篇 AI 论文，$180k）、Codex/Claude Code 循环
Harness 自我改进 prompt/记忆/工具/技能 任务成败信号 GEPA（prompt）、Mem0（记忆）、Alita（工具）、Hermes skills 体系
模型弱监督学习 权重 自生成/弱反馈 SDAR、SKILL0

关键判词：如果 harness 是 agent 的一部分，那 harness 更新就应视同参数更新——GEPA/ACE/Mem0 叫"学习方法"没有错。Artifact 优化改的是产出，Harness 改进改的是 agent 自身——这是与我们最相关的分界。

3.2 三问定位法

What evolves? What feedback drives it? Where does the loop close?

  • 循环闭合在 benchmark 上 → 得到更强的刷榜机
  • 闭合在代码上 → 更好的软件
  • 闭合在物理世界 → agent 成为构建/改进真实系统的新方式

世界是最难的环境，也是自进化 agent 最有价值的地方——这句话对 DUCK-Pi_5 项目是直接背书：我们的闭环闭合在真机鸭子上。

4. Hermes 体系自我审计（对照框架）

我们的能力 档位 证据
三级记忆 + memory-refiner + RAG L1 上部 记忆结构丰富，但删库后能力不存活
evolver（错误模式→规则沉淀）、error-case-library L1→L2 过渡 有 Hard-Case Buffer，有技能进化（skill_manage patch），但"失败案例→定期自动复盘→技能集变化"的闭环尚未全自动
sensor-grid + quality-gate + golden set L1→L2 质量信号闭环已有雏形
600+ skills 索引 + 按需加载 L1 技能即压缩上下文（与 MemSkill 同构），但选择靠 LLM 判断而非学习到的策略

缺口与最便宜的下一步（MemSkill Designer 的启示）：

  1. error-case-library 已存失败案例，缺定期触发的"失败模式聚类 → 技能补丁"管线（evolver 已有骨架，补 cron 触发 + 聚类分析两步）
  2. 我们的技能有 provenance 字段（skill 安全规则要求），但缺技能淘汰信号（多久没用 = 死技能检测）——skill-health-tier 已有 production/beta/skeleton 分层，可加"最后调用时间"维度
  3. 五问审计清单可直接嵌入 skill-review 周检：每技能问"删掉它后任务表现掉多少"——即 skill 压力测试（skill-stress-test 已有）的常态化
