一、内容详细整理

1.1 核心命题

公开视频里人形机器人接到指令→走到桌边→拿物体，看似一个模型搞定一切。但拆开控制链路，理解语言、选择动作、维持平衡、跟踪关节、调节电流各自处理不同输入，能容忍的延迟相差极大。端到端训练可以连接它们，但不会让它们变成同一个问题。

文章将控制系统拆成 六个功能层 + 两项贯穿能力（状态估计、安全），底层伺服再拆为位置/速度环与电流/FOC 两块，最终看到七个执行模块。

架构铁律：上层给出的目标不能来回跳，下层执行要足够快、足够稳。上层不必每瞬间重新决定任务，下层不能用更高频率盯住位置/速度/电流。

1.2 频率分层概览

┌─────────────────────────────────────────────────────────┐
│  层级          │  典型频率      │  运行位置              │
├─────────────────────────────────────────────────────────┤
│  L1 任务理解    │  事件触发       │  中央控制器             │
│  L2 VLA/行为    │  5—30 Hz       │  中央控制器 (GPU)       │
│  L3 运动规划    │  数十 Hz       │  中央控制器             │
│  L4 全身控制    │  200—1000 Hz  │  中央控制器 (实时核)     │
│  L5 关节控制    │  500—1000 Hz │  中央/驱动器            │
│  L6a 位置/速度环│  1—8 kHz      │  关节驱动器             │
│  L6b 电流/FOC   │  8—20 kHz     │  关节驱动器 (MCU)       │
└─────────────────────────────────────────────────────────┘

图中频率是工程量级，非某款产品规格。中央控制器与关节驱动器通过 EtherCAT、CAN FD 等实时总线交换关节目标和反馈。

1.3 逐层拆解

L1 任务与交互层 — 处理目标、上下文和完成条件。分辨"蓝色箱子是哪一个""左侧货架在哪里"，决定失败时重试还是停机。输出抽象目标（移动到某区域、抓取某物体、按序完成接近→抓取→搬运→放置）。

L2 VLA / 行为策略层 — Vision-Language-Action 模型把视觉、语言和机器人状态接到动作上。核心问题："动作"可以指很多东西：
- 关节位置
- 末端执行器位姿（需经逆运动学变成关节命令）
- Action chunk（一次预测一段未来动作，更连贯但遇到新误差更难修正）

NVIDIA GR00T N1 把视觉语言推理和连续动作生成放进两个紧密耦合的系统，推理完成后动作仍要接入具体控制器。

公开频率参考：OpenVLA 两个 Franka 部署分别 5 Hz / 15 Hz；GR00T N1.7 约 12—36 Hz。Action chunk 弥补速度差：策略一次预测一段，下层在两个预测周期之间继续执行。

L3 技能、运动规划与轨迹层 — 把离散意图补成连续过程。碰撞检查、逆运动学、轨迹时间参数化在此完成。输出不再只是"去那里"，而是带时间顺序的末端位姿、质心轨迹、足端落点或关节参考。学习型系统可能缩小这层，但可达性、碰撞、速度限制、接触时序这些问题总得在系统某处解决。

L4 全身控制（WBC） — 人形机器人没有始终固定在地面的底座。右手前伸→质心变化；抬起一脚→另一脚成为唯一支撑。WBC 协调所有目标与约束，算出全身关节命令：
- 约束、操作任务、姿态分开处理，用优先级避免次要动作破坏接触条件或突破关节限位
- 可输出关节位置/速度，也可直接输出关节力矩

公开案例：状态估计和全身控制 500 Hz，电机命令 1000 Hz；ros2_control 示例给出 500 Hz 与 1000 Hz 硬件组件协同。平衡控制等不起上层模型的慢速推理。

L5 关节控制层 — 读取编码器、速度估计和力矩信息，比较当前状态与目标，计算新命令：
- 位置控制盯角度误差
- 速度控制盯转速误差
- 力矩/阻抗控制关心输出力与接触柔顺性

ros2_control 实时循环三动作：读硬件状态→更新控制器→写回命令。控制器和硬件组件可用不同更新率。上层隔几十毫秒才发新动作时，驱动器不停下来等。

速度差很要命：上层慢一拍可能只是顿一下；关节闭环一直慢一拍，跟踪误差和振荡就冒出来，严重时失稳。越靠近硬件，越受不了时延抖动。

L6 伺服驱动与电流环 — 典型级联结构：位置误差→速度目标→电流/力矩目标→电流环调节电压。ODrive 文档展示的正是这套结构。力矩控制模式下可绕过外侧位置环和速度环，只用内侧电流控制。

频率再往上：ODrive 原生控制循环 8 kHz；Microchip FOC 示例 20 kHz 快环 + 4 kHz 转矩慢环。

电流环为什么必须在底层？电机线圈、电流采样、功率器件状态变化太快，等不了视觉模型看完一张图，也承受不了不确定通信延迟。驱动器要据本地采样立刻纠偏，过流/过速/传感异常时及时限制输出。

1.4 命令向下走，状态一路回来

编码器→关节角度速度；IMU→角速度加速度；足底力传感器→接触判断；相机/触觉→环境信息；驱动器→电流温度故障。原始数据经时间同步、滤波、状态估计后，才成为各层用得上的信息。

越靠近内层反馈越直接：电流环看电流，关节环看位置速度。全身控制需要身体姿态、质心与接触状态；行为策略关心物体、机器人状态和动作结果；任务层最后判断箱子有没有放好。

它们不是拿同一份原始数据各自处理——看到的是同一台机器人，却在不同时间和空间尺度上理解它的状态。

1.5 一个大模型为什么还不够

三个硬约束：
- 实时性：语义推理依赖大模型+长上下文，电流控制需稳定快速本地闭环，计算节奏差太远
- 故障定位：失去平衡时要分清是状态估计出错、接触条件变了、WBC 无解、还是驱动器没跟上。全藏进黑盒，定位和降级都更难
- 失效边界：VLA 预测错一个动作不该直接变成无限制电机输出。关节限位、碰撞检测、电流限制、急停、看门狗要分布在控制链路不同位置

安全不是系统末端再补一个开关。急停和驱动保护靠近硬件，平衡与接触约束进入全身控制，任务超时和失败恢复留在上层。有些保护甚至应独立于运行大模型的通用计算机。

1.6 端到端会统一机器人控制吗

大概率不是"一个大模型吃掉所有模块"，而是更深的融合：
- 上层模型负责更长时间尺度的任务理解、动作生成、经验复用
- 下层控制继续负责高速闭环、稳定接触、硬件保护
- 中间边界变模糊，VLA↔运动规划↔全身控制之间出现更多学习型接口
- 但越靠近真实接触、平衡和电机执行，工程约束越不会消失

二、查询拓展

2.1 VLA（Vision-Language-Action）

视觉-语言-动作模型的统称。将视觉感知、自然语言理解和机器人动作生成统一到一个神经网络中。代表工作：NVIDIA GR00T 系列、OpenVLA、RT-2（Google）。核心设计选择在于"动作"的粒度——关节级、末端执行器级、还是 action chunk（动作序列块）。粒度越粗，连贯性越好但误差修正越滞后。

2.2 Action Chunk

VLA 策略一次预测一段未来动作序列（而非单个控制周期的动作），下层控制器在两次预测之间持续执行这段轨迹。本质是用时间冗余弥补策略推理频率（5—30 Hz）与控制频率（数百 Hz）之间的巨大落差。ACT（Action Chunking Transformer）首次系统化这一思想。

2.3 全身控制（Whole-Body Control, WBC）

经典方法源自 Sentis & Khatib（task-space / null-space projection）。核心思想：将浮动基座机器人的多任务多约束控制问题转化为一个带优先级的二次规划（QP）。高优先级任务（如平衡、接触保持）在 null space 之外求解，低优先级任务在 null space 内尽量满足，绝不破坏高优先级约束。

2.4 级联伺服控制（Cascaded PID）

ODrive 采用的标准结构：位置环（外环）→速度环（中环）→电流环/FOC（内环）。每一级将上一级的输出作为自己的目标。越内层频率越高、延迟容忍度越低。力矩模式可旁路外层两个环，直接控制电流——这对柔顺控制（impedance control）和外力估计至关重要。

2.5 EtherCAT / CAN FD

工业实时总线。EtherCAT（Ethernet for Control Automation Technology）使用"飞读"机制，数据帧穿过所有节点后回到主站，典型周期 100 μs—1 ms，抖动 <1 μs。CAN FD 是传统 CAN 的升级，数据段带宽从 1 Mbit/s 提升到 5—8 Mbit/s，单帧数据从 8 字节扩到 64 字节。人形机器人中 EtherCAT 更常见于高端平台。

三、归纳总结

3.1 人形机器人控制系统时间尺度分层模型

  时间尺度    层级           处理内容              关键约束
  ─────────────────────────────────────────────────────────
  秒级~分钟    L1 任务        目标分解/上下文/重试    语义正确性
  100ms级     L2 VLA         视觉推理→动作生成      泛化能力/动作连贯
  10ms级      L3 运动规划    碰撞检查/IK/轨迹        可达性/连续性
  1—5ms      L4 WBC         全身协调/平衡/QP        实时性/约束满足
  1ms        L5 关节控制    位置/速度/力矩闭环      跟踪精度/抗扰
  100μs      L6a 伺服环     位置PI/速度PI           带宽/稳定性
  50μs       L6b 电流/FOC   Park变换/SVPWM          开关损耗/采样噪声
  ─────────────────────────────────────────────────────────
                    ↓ 命令逐层细化     ↑ 状态逐层抽象 ↓

3.2 端到端 vs 分层控制的边界

维度 端到端 VLA 传统分层控制
延迟容忍 高（100ms+） 低（μs~ms）
可解释性 黑盒 模块可定位
安全边界 难嵌入 逐层分布式
泛化能力 强（跨任务） 弱（需手工设计）
失效模式 难预测 可分析
硬件耦合 间接 直接

结论：未来不是"端到端取代分层"，而是"模型能力渗透控制链路 + 实时性/安全性/可解释性反向约束模型边界"。

四、趋势判断

趋势1：VLA 与 WBC 之间将出现"学习型接口"

当前 VLA 输出（关节位置或末端位姿）和 WBC 输入（全身 QP 约束）之间仍有大量手工翻译。未来这一层（L2↔L3↔L4）会被可微的运动规划模块或学习型全身策略填充，使语义意图到力学执行之间的 gap 缩小，但不会完全消失，因为接触动力学的不连续性不可微。

依据：NVIDIA GR00T N1 已经将推理和动作生成分成两个紧密耦合系统，而非纯端到端。

趋势2：智能关节驱动器吸收更多控制层

随着 STS3025BL 等一体化关节模块的成熟，位置环、速度环甚至简单的力矩反馈将下沉到驱动器内部。中央控制器只需发送抽象关节目标（如 1 kHz），驱动器在内部 8 kHz 闭环。这简化总线负载但增加调试黑盒风险。

依据：ros2_control 已支持控制器和硬件组件使用不同更新率；ODrive 文档展示级联控制全部在驱动器内完成。

趋势3：安全将成为独立子系统而非最底层

文章明确反对把安全画成"第七层"。急停/看门狗必须在硬件层独立于通用计算机运行；任务级安全（超时/失败恢复）在上层独立监控。这种纵深防御思路与人形机器人产业化中功能安全认证（ISO 13849 / IEC 62061）的推进一致。

依据：ros2_control 提供控制器失败后停用与回退；ODrive 力矩模式默认设速度限制。

趋势4：实时总线成为差异化竞争点

EtherCAT 的 100 μs 周期和 <1 μs 抖动对 1000 Hz 全身控制是刚需，CAN FD 的性价比适合中低端。随着关节数增加（人形 28—40+ DOF），总线带宽和拓扑管理将成为系统瓶颈，催生专用实时通信芯片或基于 TSN（Time-Sensitive Networking）的新方案。

五、关联分析

5.1 与双轮腿机器人项目的直接映射

项目路径：~/uclaw/project/two-wheel-legged-robot/
硬件：STM32H743VIT6（大脑）+ ODrive 3.6（轮 FOC）+ STS3025BL（腿关节）+ Pixracer R15（IMU/EKF2）+ 2×AS5600 磁编码器 + 6S

本文的六层架构可直接映射到该项目的硬件分工：
- L4 全身控制 + L5 关节控制 → STM32H743（大脑）
- L6 电流/FOC（轮）→ ODrive 3.6（级联控制 + 力矩模式，文中引用的正是 ODrive 文档）
- L6 关节驱动（腿）→ STS3025BL（总线舵机，内部闭环）
- 状态估计 → Pixracer R15 + EKF2（IMU 融合）
- AS5600 → 关节编码器反馈（L5 关节控制读取）

关键启示：项目中 ODrive 和 STM32 之间的通信延迟（CAN 总线）是 L4↔L6 的跨层瓶颈，需要重点优化；EKF2 状态估计频率应 ≥ WBC 频率（500 Hz）。

5.2 与舵机臂项目的关节控制关联

项目路径：~/uclaw/project/servo-arm-pro/
