# 小模型 LoRA 微调数据质量：合成数据蒸馏与「形式而非事实」框架

> 2026-09-09 夜间自学习笔记
> 来源：arXiv 2601.03211（企业搜索相关性标注 SLM 蒸馏）、Fine-Tuning LLMs in 2026 行业实践博客
> 关联项目：AirCraft 航空知识问答（MiniCPM5-2B + LoRA，R3 已训完 1504 条，eval_loss 1.959，待质量提升）

## 核心结论（一句话版）

**微调解决"形式"问题，不解决"事实"问题；小模型 + 合成数据蒸馏管线可以追平教师 LLM，前提是先有 eval、答案格式与生产场景严格一致。**

---

## 1. 决策框架：什么问题该微调，什么问题该 RAG

2026 年行业共识的四象限判断法（按失败类型 × 信号稳定性切分）：

| 失败类型 | 信号稳定 | 信号易变 |
|---|---|---|
| **知识型**（"模型不知道我们的文档"） | 继续预训练（极罕见，如专业科学语料） | **RAG（正解，不要微调）** |
| **行为型**（schema/语气/格式/拒答） | **微调 LoRA/QLoRA（正解）** | Prompt 工程 + few-shot |

要点：
- 基座模型 2026 年已原生支持长上下文、工具调用、结构化输出，"prompt+RAG"覆盖面比两年前大得多；
- Ovadia et al.（arXiv 2312.05934）实证：**事实回忆 RAG 一致优于微调**，往权重里烤事实会产生过时、不可验证的答案并侵蚀通用能力（灾难性遗忘）；
- 正确顺序：**Prompt → RAG → Fine-tune → Distill**；
- 最高 ROI 模式：薄 LoRA/QLoRA 适配器叠在强基座上，**与检索配合而非取代检索**；
- 铁律：**训练前必须先有书面 eval**。"如果无法判断新 checkpoint 是否比旧的好，你面对的不是微调问题，是评估问题。"

### 检查清单（五项全 yes 才立项微调）

1. eval 已存在且 prompt+RAG 基线跑不过它
2. 失败是行为型而非缺知识
3. 至少几百条高质量样本，且格式与生产**严格一致**
4. 有 adapter 生命周期 owner（12 个月维度：季度复验、基座漂移检查、回滚方案）
5. 已估算持续运维成本且收益成立

## 2. arXiv 2601.03211：合成数据蒸馏管线详解

论文目标：企业搜索相关性标注（判断 query-document 相关度）。核心矛盾：人工标注贵、公开数据集与真实企业数据分布不符、LLM 直接标注吞吐低且贵。

### 2.1 五步合成数据管线（可复用模板）

| 步 | 操作 | 工具/方法 | 目的 |
|---|---|---|---|
| 1 | 种子文档选取 | 企业内部文档（邮件/聊天/知识库） | 锚定真实数据分布 |
| 2 | 合成 query 生成 | LLM 从种子文档生成"真实用户会问的问题" | 解决 query 稀缺 |
| 3 | 难负例挖掘 | **BM25 检索**相似但不对的文档 | 提升判别难度，逼模型学细粒度差异 |
| 4 | 教师打分 | GPT-4o 对 query-doc 对打分级相关性标签 | 生成训练信号 |
| 5 | 蒸馏进 SLM | LoRA 微调 Phi-3.5 Mini Instruct | 压缩能力到小模型 |

### 2.2 结果

| 指标 | 蒸馏后 SLM (Phi-3.5 Mini) | 教师 LLM (GPT-4o) |
|---|---|---|
| Human NDCG | **0.953** | 0.944 |
| Pairwise Accuracy | **63.81** | 62.58 |
| 吞吐 | **17×** | 1× |
| 成本 | **1/19** | 1× |

结论：923 对人工标注基准上，蒸馏 SLM 与人类判断的一致性**追平甚至超过**教师 LLM。小模型不是缩水版，在窄域判别任务上是合格替代品。

### 2.3 为什么有效（因果链）

1. 任务是**窄域判别**（不是开放生成），决策边界简单，2-3B 参数足够表达；
2. 难负例（BM25 top 但不相关）逼迫模型学"差在哪"而不是"像不像"，这是判别任务的核心信号；
3. 教师只负责打标签（一次性成本），推理时不需要教师——成本结构从"每次调用都贵"变成"训练一次、部署免费"。

## 3. 对 AirCraft 项目（MiniCPM5-2B 航空问答）的落地建议

当前状态回顾：R3 已训完 1504 条，eval_loss 1.959（R1 554条→2.151，R2 739条→2.145），Web UI 三模型对比就绪。已知瓶颈：答案均长 ~118 字、全单轮、49 条重复问题未清洗。

### 3.1 按四象限重新定位项目

本项目失败模式是什么？用户问航空结构材料知识，模型答得浅、答不对。这是**知识型 + 稳定信号**（航空材料知识不每周变）→ 按框架属于"继续预训练/RAG"象限，而非纯 SFT。但 2B 模型做不了像样的继续预训练，所以现实路径是**混合**：

| 方案 | 适用 | 对本项目的适配度 |
|---|---|---|
| 纯 SFT（现状） | 行为型失败 | ⚠️ 部分错位——目前把"注入知识"寄望于 SFT |
| SFT + RAG | 知识+行为混合 | ✅ 推荐：LoRA 管"领域语气/格式/术语"，检索管"事实" |
| 蒸馏管线升级 SFT | 缺标注数据 | ✅ 强烈推荐：参照 2601.03211 五步管线造 R4 数据 |

### 3.2 R4 数据管线具体建议（照抄论文五步）

1. **种子**：已有航空结构材料文档（领域语料即种子）
2. **query 扩写**：用 glm-5.2 从每篇种子文档生成 3-5 个真实工程师会问的问题（含模糊问法、缩写问法、上下文依赖问法——企业 query 的三大特征）
3. **答案扩写**：每问生成 300-500 字结构化答案（定义→机理→数据/牌号→应用场景→对比），替代现在 118 字的"百科词条"式短答案——这是已诊断的 50% 权重瓶颈
4. **去重清洗**：先解决 49 条重复问题，question 归一化（去空白/同义合并）
5. **教师质检**：glm-5.2 按"准确性/完整性/是否需要外部信息"三维打分 1-10，<7 分丢弃，**先筛 query 再生成答案**（论文明确：低质 query 过滤省算力）

### 3.3 eval 体系先行（当前最大缺口）

论文和行业博客共同强调：**没有 eval 就没有微调**。建议在 R4 训练前先建：

- 固定 100 题考试集（覆盖材料牌号/工艺/失效模式/适航条款四类，人工或教师模型出题）
- 每题参考答案 + 评分 rubric（正确性/深度/幻觉率三维）
- R3 先跑基线，R4 训完同卷对比——解决"效果很不好无法量化"的问题
- 加一项**幻觉率**指标：答案中不可溯源断言占比（领域问答的隐性杀手）

### 3.4 后续演进路径

- 数据到 3000+ 条且 eval 达标后，可考虑 DPO 偏好对（好答案/差答案对比）进一步校语气——按博客选型：有成对偏好→DPO，只有点赞点踩→KTO
- 多 adapter 服务模式（vLLM LoRA 路由）暂不需要，单领域单任务

## 4. 查询拓展：围绕本主题的延伸问题

### 4.1 答案长度对 SFT 效果的影响边界在哪？

AirCraft 实测答案均长 118 字是 50% 权重瓶颈。但答案不是越长越好——超出模型容量（2B/26M）后，长答案反而稀释监督信号、拉高幻觉率。合理区间：300-500 字结构化答案（定义→机理→数据→应用→对比），既提供推理链又不超载。这与 FineInstructions（arXiv 2601.22146）的发现一致：**答案必须"锚定在文档上"（grounded in the document）**，脱离源文档的长答案会引入幻觉。

### 4.2 难负例（hard negatives）对判别任务的通用性

arXiv 2601.03211 用 BM25 挖难负例做相关性标注。该模式可迁移到：
- **幻觉抑制**：训练模型判别"正确断言 vs 形似错误断言"（如相近牌号的材料属性混淆）
- **拒答能力**：构造"不可回答问题"（文档中无答案），教模型说"资料未覆盖"而不是编造
- AirCraft R4 数据中建议加入 10-15% 此类样本

### 4.3 什么时候该放弃 SFT 转向蒸馏？

按四象限框架：当失败模式是"知识型+稳定"（航空材料知识属于此类）且基座太小做不了继续预训练，蒸馏管线是正解——用大模型（glm-5.2）生成结构化 QA 对，小模型学格式和领域语气，事实部分交给 RAG。**2B 模型的正确角色是"领域交互界面"，不是"领域知识库"。**

### 4.4 eval 集规模与信噪比

100 题考试集是否足够？按论文 923 对人工标注基准的经验，百题量级可支撑 NDCG 类相对比较（判断 R3 vs R4 谁好），但不足以做绝对质量评估。建议分层：50 题核心知识（牌号/工艺）+ 30 题推理应用（失效分析）+ 20 题边界测试（幻觉诱饵/不可回答）。

## 5. 归纳总结

**一句话**：微调管"形式"（语气/格式/术语/schema），RAG 管"事实"；小模型窄域判别任务可蒸馏追平教师 LLM（NDCG 0.953 vs 0.944，吞吐 17×、成本 1/19），但前提是 eval 先行 + 数据格式与生产严格一致 + 答案长度匹配模型容量。

三层因果链：
1. **为什么 SFT 在知识注入上失效**：往权重烤事实 → 过时不可验证 + 灾难性遗忘 → 应改 RAG（Ovadia 2312.05934 实证）
2. **为什么合成数据蒸馏有效**：窄域判别决策边界简单（2-3B 参数够表达）+ 难负例逼出细粒度差异 + 教师成本一次性（打标签）而非每次调用
3. **为什么项目失败在数据不在训练**：训练格式与推理格式不匹配是"沉默杀手"——AirCraft 的 118 字短答案直接封顶输出能力，无论怎么训都是浅答

## 7. 关联分析

- **与本地 Qwen3.8/量化笔记（09-08）**：量化规律闭环——模型越大越耐压（2.4T@1.19bpw 可用）反向印证小模型（26M MiniMind）该用 Q8_0/F16。同理，**蒸馏管线也依赖"教师足够强"**——glm-5.2 作教师比 26M 模型自举生成质量高一档。
- **与 AirCraft 项目**：R3（eval_loss 1.959）已触及当前数据质量上限；R4 应照抄 2601.03211 五步管线（种子→query 扩写→难负例→教师打分→蒸馏），重点修 118 字短答案 + 49 条重复。
- **与 minimind-training-pipeline 项目**：7 阶段案例集覆盖 Pretrain→SFT→DPO/GRPO，本笔记的四象限决策框架可作为"该用哪阶段"的前置路由层。
- **与 knowledge-fusion/rag-index-rebuild 工作流**：若 AirCraft 转向 SFT+RAG 混合，RAG 索引重建技能直接复用（从领域文档建关键词+语义双索引）。

## 9. 指南分析：AirCraft R4 合成数据管线操作手册

> 本节为可直接执行的操作指南，整合 2601.03211 五步管线 + 本地约束（Jetson 不跑训练，AutoDL 执行）。

### 步骤 1：种子文档与存量数据清洗
```bash
# 在 Jetson 上（数据准备）
cd ~/uclaw/project/AirCraft/AM_MiniCPM5
# 去重：question 归一化（去空白/全半角/同义合并），目标消除 49 条重复
python3 -c "
import json
data = json.load(open('r3_data.json'))
seen, out = {}, []
for d in data:
    k = d['instruction'].strip().replace(' ', '')
    if k not in seen:
        seen[k] = 1; out.append(d)
json.dump(out, open('r3_dedup.json','w'), ensure_ascii=False, indent=2)
print(f'{len(data)} -> {len(out)}')"
```

### 步骤 2：query 扩写（教师模型）
- 输入：每篇种子文档
- prompt 要点：生成 3-5 个"真实工程师会问的问题"，覆盖模糊问法/缩写问法/上下文依赖问法（企业 query 三特征）
- 先筛 query 再生成答案（省算力）：清晰度/难度/是否需额外信息三维打分，<7 分丢弃

### 步骤 3：答案扩写（300-500 字结构化）
模板：定义→机理→数据/牌号→应用场景→对比。每答案必须锚定源文档，禁止教师自由发挥补充文档外断言。

### 步骤 4：难负例与边界样本（10-15%）
- 相近牌号混淆对（如 2024-T3 vs 7075-T6 的属性张冠李戴）
- 不可回答问题（答案=「资料未覆盖」标准回复）

### 步骤 5：AutoDL 训练（复用已验证脚本，铁律：禁手写）
```bash
# 在 AutoDL 上（~/uclaw/project/AirCraft/AM_MiniCPM5/ 同路径）
sed -e 's|round2_data|r4_data|g' -e 's|output_r2|output_r4|g' train.py > train_r4.py
# R3 用 537 步 12分42秒（RTX 4080），R4 预计 3000+ 条 → ~25min
/root/miniconda3/bin/python train_r4.py
```

### 步骤 6：eval 同卷对比
R3/R4 各跑 100 题考试集，对比正确率/深度分/幻觉率三维。**判据：幻觉率下降 + 核心知识正确率上升才算 R4 成功**——eval_loss 单指标不可信（R1→R3 loss 降但用户体感"效果很不好"即为证）。

### 回退方案
R4 不达标 → 保留 R3 权重，数据回滚 r3_dedup.json，检查教师打分分布（是否过松）。
