一、内容整理

0. 手眼标定解决什么

将机械臂末端、相机、棋盘格三者坐标系统一到一个坐标系下。两种场景：

场景 相机位置 不变的量（待求 X）
眼在手上（eye in hand） 装在机械臂末端 相机与末端的相对位置 T_cam2ee
眼在手外（eye to hand） 装在机械臂外固定处 相机与基座的相对位置 T_cam2base

核心思想一句话：手眼标定的原理就是在找相对位置固定不变的量。

1. 前置知识：齐次变换矩阵

  • 4×4 变换矩阵描述两坐标系相对关系 = 旋转 R + 平移 t
  • T 的作用：把 A 坐标系下的点转换到 B 坐标系；矩阵的逆反向转换
  • 关键认知：点还是那个点，客观存在——只是在不同坐标系下有不同坐标值，T 只做坐标系转换
  • 链式法则（变换复合，顺序从右往左）：T_C2A = T_B2A · T_C2B
  • 符号约定：上标=去哪（目标坐标系），下标=从哪来（源坐标系）

2. 眼在手上推导（AX=XB）

四个坐标系：base（基座）/ ee（末端）/ cam（相机）/ target（棋盘格）

已知/未知：
| 量 | 来源 |
|---|---|
| T_ee2base（每组不同） | 机械臂 SDK 读取，或 URDF+关节角正运动学算出 |
| T_cam2target（每组不同） | PnP 从图像解出（依赖内参标定） |
| T_cam2ee（固定，即 X） | 待求 |

推导路径：点 P 从棋盘格到基座的链路：target → cam → ee → base，等式两边 P 约掉得：

T_ee2base(1) · X · T_target2cam(1) = T_ee2base(2) · X · T_target2cam(2)
（两组姿态下 T_target2base 不变）

移项整理成经典 AX=XB。

实操铁律：
- 一组数据 = 机械臂末端位姿 + 同一时刻拍的棋盘格图片
- ⚠️ 棋盘格千万别动——保证 T_target2base 不变，方程组才能成立
- 需多组不同姿态的数据构建方程组

OpenCV 实现：

R_cam2ee, t_cam2ee = cv2.calibrateHandEye(
    R_ee2base_list, t_ee2base_list,   # 各姿态末端位姿
    R_target2cam_list, t_target2cam_list,  # 各姿态PnP结果
    method=method)  # 5种经典方法，差异在旋转/平移方程的解耦或联立

3. 眼在手外推导

关键差异：不变量是 T_cam2base（X）；棋盘格固定在机械臂末端上（不能动）

双路径等式：
- 路径 1：target → ee → base（棋盘格随末端动，经正运动学）
- 路径 2：target → cam → base（经相机观测）

两路径等式含两个未知量（X=T_cam2base 和 Y=T_target2ee），取两组姿态消去 Y 后移项得 AX=XB 标准形式——此处 A 的两个矩阵都是求逆过的（与眼在手上不同）。

OpenCV 实现（同一个接口，参数方向相反）：

R_cam2base, t_cam2base = cv2.calibrateHandEye(
    R_base2gripper_list, t_base2gripper_list,  # 注意：与眼在手上相反，求逆即可
    R_target2cam_list, t_target2cam_list,
    method=method)

4. 两种场景对照表（自行归纳）

待求 X T_cam2ee T_cam2base

二、查询拓展

  1. OpenCV 5 种 method 的差异：TSAI/PARK/HORAUD/DANIILIDIS/ANDREFF 各自如何解耦旋转平移——精度与鲁棒性对比
  2. AX=XB 的解存在性条件：旋转轴退化情形（两组姿态旋转轴平行时方程病态）——数据采集的姿态多样性要求
  3. 手眼标定精度评估：重投影误差之外的验证方法（已知距离测量/重复定位精度测试）
  4. 动态手眼标定：机器人运动过程中在线标定（不用停机采集）的研究进展
  5. 与 servo-arm-control 的 DH 参数关系：URDF 正运动学（T_ee2base 来源）与 DH 建模的一致性校验

三、归纳总结

维度 要点
一句话 手眼标定 = 找"相对位置固定不变的量"，两种场景统一为 AX=XB 齐次变换方程求解
数学核心 多组姿态数据构建方程组消元；眼在手外多一步消去棋盘格-末端关系 Y
最大坑 棋盘格必须绝对静止（眼在手上场景）——动了就全废
工程链路 内参标定 → PnP 解 T_target2cam → 机械臂 SDK 读 T_ee2base → calibrateHandEye 解 X
认知要点 点是客观存在，坐标值随坐标系变——变换矩阵只做坐标系转换，链式法则从右往左复合
接口统一 OpenCV 一个 calibrateHandEye 通吃两种场景，只差参数方向（求逆）

四、趋势判断

  1. 手眼标定从"专业操作"走向"开机自检"：协作臂厂商（UR/遨博）已把一键手眼标定内置——但理解 AX=XB 原理仍是诊断精度问题的唯一路径，"会调包"与"能排错"的分界线
  2. EiT 方案（眼在手外+固定相机）在工业检测中占比上升：全局视野稳定、标定一次长期有效——缺点是盲区，与 eye-in-hand 的局部高清互补，双相机融合方案渐成标配
  3. VLA 时代手眼标定依然不可替代：Harness VLA/OpenVLA 类系统的 RGB-D 输入、staging 状态判断全部建立在相机-基座坐标系统一之上——端到端模型消化不掉坐标系问题
  4. 标定自动化的"最后一公里"是姿态多样性自动规划：采集哪些姿态能让方程组病态性最低——主动标定（active calibration）研究将工程化落地
