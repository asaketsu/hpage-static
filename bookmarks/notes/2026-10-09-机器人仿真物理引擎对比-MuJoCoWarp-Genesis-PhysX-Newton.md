## 一、文章概要

同一场景、同一控制器的四引擎横评：**Isaac Sim 中的 PhysX、原生 MuJoCo（CPU）、Newton（MuJoCo-Warp，GPU）、Genesis**。核心发现一句话：**宏观任务结果（成功/失败）四引擎基本一致，但接触力峰值可差一个数量级、轨迹误差可达厘米级、柔性物体结果彻底分化**——只看任务成功率做策略评估会漏掉大量物理信息。

**四大结论**：
1. **刚体宏观行为一致，力学过程不同**：滑块停止距离差 0.05mm，但接触力峰值差 10 倍（MuJoCo 系 10.46N vs PhysX 1.06N）
2. **小间隙接触最能区分引擎**：插销装配（0.10mm 间隙）中硬接触的 PhysX 力过载停止，三款软接触引擎可完成
3. **柔性物体分歧最大**：参数/网格/动作全对齐，结果从稳定夹持到几何翻转不等，网格加密+步长减半也救不回来
4. **性能分水岭明确**：单环境 MuJoCo CPU 最快（0.17M steps/s）；8192 并行时 MuJoCo-Warp 吞吐 21.6M steps/s 领先

## 二、实验设计（方法论价值最高的部分）

| 引擎 | 执行路径 | 版本 | 接触模型 |
|------|---------|------|---------|
| PhysX | Isaac Sim · CPU TGS | 6.1.0.0 · float32 | **硬接触**（刚性约束） |
| Newton | MuJoCo-Warp · GPU | 1.5.2 · Warp 1.16.0 · float32 | 软接触 |
| MuJoCo | 原生 CPU | 3.11.0 · float64 | 软接触 |
| Genesis | 原生刚体求解器 · GPU | 1.4.1 · float64 | 软接触 |

- 统一 Franka Panda + 同一显式力矩控制器（非引擎内置驱动），1kHz 控制频率
- **资产校验协议**：导入后回读质量/质心/惯量/关节轴/限位，而非假设解析正确
- 每步动量平衡校验（5×10⁻⁶ N·s 容差）；步长减半做灵敏度对照
- **诚实声明**：多引擎一致 ≠ 贴近现实；本研究无物理真值

## 三、内容整理（关键数据）

### 3.1 基础刚体（表象一致、内里分化）

| 实验 | 一致的指标 | 分化的指标 |
|------|-----------|-----------|
| 滑块滑动 | 停止距离差 0.05mm | 力峰值 10.46N(MuJoCo系) vs 1.06N(PhysX)；质心上浮 1.12mm |
| 立方体坠落 | 接触时刻均 ~0.26s | 峰值力 253.86N(PhysX) vs 52.04N(MuJoCo系)；穿透 0 vs 7.8mm |
| 单铰链摆动 | 1ms 步长偏差 <0.084° | —（修掉 armature 导入坑后浮点级一致） |

**步长比引擎更敏感**：步长减半的影响 ≈ 引擎间差异的 10 倍（滑行距离变化 0.50mm vs 引擎差 0.05mm）；PhysX 步长减半峰值力翻倍（127→254N）但总冲量不变——**只对比峰值力会误导**。

### 3.2 多物体/机器人（任务一致、轨迹分化）

- **碰撞链**：球→立方体→棱柱，四引擎终点差 18.7-21.3mm（PhysX vs 其余），棱镜朝向差 34°
- **1mm 布局扰动敏感性**：MuJoCo CPU 轨迹变化 31.4mm vs PhysX 仅 2.4mm——**任务结果相同 ≠ 仿真鲁棒性相同**
- **偏心抓取释放**：落点偏移 PhysX 9.0mm / Genesis 6.9mm / Newton 1.1mm / MuJoCo CPU 0.3mm
- **插销装配（0.10mm 间隙+倾斜）**：软接触引擎停滞在 15.3-15.7mm，接触反馈控制器救活（达 19.9mm 目标深度）；PhysX 全部力过载（125.8N 超限）
- **密集扫掠（15 物体）**：Newton 同输入三次运行 11/8/7 入盘——**单引擎内部波动 ≈ 引擎间差异**

### 3.3 柔性物体（分歧最大、无解）

| 方案 | 1N 工况 | 2N 工况 |
|------|---------|---------|
| MuJoCo CPU | 1.345s 失效 | 完整周期，抬起 66mm |
| 原生 MuJoCo-Warp | 1.335s 失效 | 2.525s 失效（下放阶段） |
| PhysX GPU（未调通） | 0.066s 失效 | 1.536s 失效 |
| Genesis FEM/SAP | 数值跑完，抬不起来 | 同左 |
| Newton MJWarp+VBD | 丢球 | **全周期完成，抬起 69mm** |

同参数（E=20kPa, ν=0.3, μ=0.5）同网格（125顶点/384四面体），25 组数值对照证明：**网格加密+步长减半不能消除分歧**。

### 3.4 性能（RTX PRO 5000 + Ryzen 9900X）

| 并行数 | MuJoCo CPU | MuJoCo-Warp | Genesis |
|-------|-----------|-------------|---------|
| 1 | **0.17M/s** | 0.006 | 0.002 |
| 8192 | — | **21.6M/s** | 11.8 |
| 131072 | — | 35.2 | 26.4 |

单环境 CPU 快 28 倍；8192 并行 GPU 反超；批量再大差距缩小至 1.3 倍。

## 四、归纳总结（四条经验，原文提炼）

1. **先查导入数据，再怪引擎**：铰链测试中 Genesis 慢 51.4° 的"引擎差异"实为 armature 被导入成 0.1 kg·m²；全局阻尼设置不会覆盖几何体自带参数（Newton 形状阻尼 200 导致 1.92kN 假力尖峰）
2. **结果一致的表象下可能藏着完全不同的物理**：必须同时报告力数据、轨迹、失效严重度
3. **排名引擎前先测引擎内部波动**：GPU 同输入多次运行的离散度可以 ≈ 引擎间差异；不能笼统说 GPU 仿真非确定（取决于场景）
4. **柔性体必须每引擎单独验证**：对齐标称参数不保证结果一致

## 六、查询拓展

- **Newton 引擎**：NVIDIA 开源的 MuJoCo-Warp 后继，主打 GPU 并行 + VBD 柔性体；本文为少数第三方实测
- **硬接触 vs 软接触**：PhysX TGS 刚性约束（零穿透、力集中）vs MuJoCo solref/sol impedance 软弹簧（允许 mm 级穿透、力平滑）——DUCK 的 sim 用 MuJoCo 软接触，真机舵机是刚性减速器，落地瞬间力特性差异是 Sim2Real gap 的物理来源之一
- **VBD（Vertex Block Descent）**：柔性体求解器，刚柔耦合用独立求解器+代理反馈——Newton 全周期完成柔性抓取的关键
- **动量平衡校验**：每步 ΣF·dt = Δp，容差 5×10⁻⁶ N·s——比"看动画像不像"硬一个数量级的自洽性验证，可移植到我们的 eval 脚本
- **armature 陷阱**：MJCF 显式 armature=0 ≠ 导入后为 0；DUCK 的 XML 里 STS 舵机惯量参数同理需要回读校验

## 七、趋势判断

- **物理引擎竞争进入"接触保真度"阶段**：视觉保真（Isaac 的强项）已经过剩，下一步差异化在接触力/柔性体/紧配合——Newton 的出现本身就是这个方向的押注
- **跨引擎评估将成为 RL 策略验收标配**：本文预告的续篇（策略跨引擎迁移）直指 Sim2Real 之外的第二条鲁棒性轴线：**Sim2Sim2Real**
- **GPU 仿真确定性神话破灭**：Newton 同种子不同结果（碰撞链 4.4mm/扫掠 11vs7 入盘）说明"GPU=非确定"与"CPU=确定"都不成立，取决于场景实现
- **对具身智能基准测试的启示**：只报 success rate 的 leaderboard 会被"轨迹烂但碰巧成功"的策略污染，力/轨迹指标将进入评测协议
