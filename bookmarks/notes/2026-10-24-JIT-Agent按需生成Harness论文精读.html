归纳总结

一句话：把"Harness 设计"从人工 Ahead-of-Time 工程变成一个 27B 小模型按任务即时生成（Just-in-Time）的可学习产物——执行模型冻结不动，任务一变就现场生成一套新的四模块执行框架；实证同 backbone 下性能超 Claude Code/Codex 等 5 个成熟 harness 且 token 成本全场最低，是"换 harness 顶换模型"命题的学术级实锤（GLM-5.2+JIT 在 9 基准 8 个第一，均分 81.8 vs GPT-5.6 裸奔 74 左右）。

内容整理：如何生成 Harness（用户核心问题 ①）

生成流水线（推理时一次调用的完整解剖）

输入上下文 c_τ = 四元组：

输入 内容 类比
任务规范 τ 当前任务的描述 需求单
固定协议 Π 四模块的 schema、接口、生命周期、校验规则、共享执行语义 编译器目标平台的 ABI
能力注册表 C_τ 可调用工具/技能/API/MCP 清单（bash、web_search、crawl 等） 工具箱目录
参考上下文 E_τ 从 harness bank 检索的少量先前 harness（按任务类型匹配取 3 个） few-shot 样例

生成的产物不是自由文本，而是协议约束下的结构化模块代码——这是全篇最关键的工程设计：

  1. 四模块分解 h = (M, P, A, F)：Memory（历史→视图压缩）、Planning（视图→局部指令）、Action（控制更新+动作发射）、Capability orchestration（指令条件化的工具激活/隐藏）。运行时依赖序 M→P→F→A，每步：M 压历史 → P 出局部指令 → F 按指令挑工具 → A 发动作，走共享内核 Exec 执行。
  2. HarnessFactory 统一接口：先人工用这套接口重实现了 13 个代表性 scaffold（ReAct / Plan-and-Execute / ReSum / Flash-Searcher / GAM / MemoBrain / AggAgent / OAgent / AgentFold / HiAgent / DeepAgent / ROMA / AOrchestra），构成种子库 B₀。生成 = 在这些接口的约束空间里"选型+实例化+写出模块实现"，而非从零写任意 agent 程序——把无限生成空间收敛到可校验的 ℋ_Π^exec。
  3. Best-of-N 静态选择：并行生成 N 个候选（repo 默认 --rollouts 3），只执行选中的 1 个。本地 vLLM 服务用 logprob 选择器（靠 prompt_logprobs 打分，托管 API 不暴露此参数时降级用 judge 选择器让评审模型挑）。
  4. 验证+有界修复：生成后过协议校验（编译错误/接口不匹配/工具调用失败/运行时异常→结构化诊断 g），基于诊断做 ≤2 轮 patch 修复（修复能力是 Stage II 专门训出来的），两轮修不好就废弃。

训练配方三阶段（27B 生成器是怎么来的）：

阶段 教什么 数据/方法
I 定制 任务条件→协议合规 harness 的映射 更强 teacher（同协议）生成通过验证的样本做 SFT；同 backbone 同种子下"reward 升且延迟/成本不升（至少一项严格降）"的偏好对做加权 DPO
II 修复 执行反馈→小幅高杠杆修订 失败 harness+诊断→teacher 两轮内修好的轨迹做 teacher-forced 模仿，只保留"局部可恢复"的失败样本
III 进化 超越已有最优的能力（Evo-GDPO） 在线对局：G 个候选 vs bank 里的 reward 前沿，reward/latency/cost 三通道组内独立归一化再聚合（reward 权重占主导），clip-PPO + 对 Stage-II 的 token 级 KL

内容整理：能不能复用（用户核心问题 ②，答案分四层）

结论先行：复用的不是"成品 harness"，而是"经验与参考"。四层复用性完全不同，必须拆开说：

复用维度 能否 机制与证据
① 同一 harness 跨模型复用 ✅ 强复用，已实证 harness 与执行模型彻底解耦（协议只约定接口，wrap 任意 agentic LLM）。5.5 节：DeepSeek V4 / Qwen3.6 / Mimo-V2.5 三家族 6 个 backbone、4 基准，24/24 全胜 ReAct 基线，平均 +7.6 分。换执行模型不用重新生成
② 同一 harness 跨任务复用 ⚠️ 技术上可执行，设计上刻意不复用 协议兼容的 harness 任何任务都能跑（静态模式下就是一次性用完即弃），但论文核心主张正是"合适的 harness 不只 domain-dependent 更是 instance-dependent"——搜索任务要并行证据探索、终端任务要精简 ReAct、深度研究要工作记忆、批量文件迁移要阶段机+逐文件校验（附录 C 的 Gearbox/Pegboard/Abacus 等 10 个可视化案例全是任务形状决定的定制结构）。硬套旧 harness 正是它批评 AOT 方法的那个缺陷
③ 经验跨任务复用（harness bank） ✅ 显式设计，Streaming 模式的核心 每个任务执行后，(harness, task, reward, 延迟, 成本) 五元组按前沿保留规则（reward 匹配或超越现有前沿 且 至少一维严格改进）决定是否入 bank；后续任务生成前先 Retrieve(τ_{n+1}; B_{n+1}) 检索相似任务的旧 harness 作为参考上下文 E_τ。附录 B.1：Streaming > Static 在 3/3 数据流上成立——复用发生在"生成参考"层面（retrieve→regenerate），不是拿旧 harness 原样跑（retrieve→reuse）。生成器参数 θ 始终冻结，进化走 bank 不走权重
④ JIT 模型本身复用 ✅ 27B 权重开源在 HF，部署一次（vLLM TP=4）可服务所有任务类型；repo 支持不用本地权重、直接拿托管 API 当 meta-agent（--meta-model provider-model --selector judge）

复用性判定的实操口径：想把它接到自己系统——同任务族反复出现的场景应该攒 bank（走 streaming），一次性异构任务用 static 即可；换执行模型零成本，换任务要重新生成但可喂旧 harness 当参考。repo 还提供 --harness-refs {desc,code} 开关：参考上下文喂"设计描述"还是"采样源码"。

关联分析

  1. "换 harness 顶换模型"的学术实锤（对我们模型经济学的直接验证）：记忆里长期持有的命题"效果差先查 skill/prompt 再换模型；换 harness 顶换模型"，这篇论文给出了正名——标题级论断 harness intelligence is a trainable, transferable, and compounding dimension of agent capability orthogonal to model scaling**，且用 GLM-5.2+JIT（开源小模型+harness）压 GPT-5.6 裸奔做了定量背书。以后说服别人（或说服自己别乱换模型）直接引这篇。
  2. Hermes 被当成 baseline 打了（直接利益相关）：表 3 中 Hermes（Nous Research）在 DSQA 69.9/1157K，被 JIT 85.1/400K 全面超越——同 backbone 下差 15.2 分还花 2.9 倍 token。这不是坏消息而是路线图：差距来源不是模型而是 harness 的任务适配度。我们的多 profile/skill 体系已经是"harness 可组合"方向，缺的是 (a) 任务条件化的自动选型 (b) 执行反馈回流成 harness 资产的前沿保留规则。
  3. 与自有 agent-primitive-architecture 三原语的映射：论文四模块 (M,P,A,F) ≈ 我们的 Agents/Skills/Hooks 分层——Memory≈记忆系统、Planning≈编排层、Capability orchestration≈skill 路由、Action≈工具执行。论文证明这套分解足以把 13 个主流 scaffold 全部规范化成同一坐标系——印证"原语化分解是 harness 可学习的前提"。
  4. harness bank ≈ experience-bank / error-case-library 的学术同构：前沿保留规则（reward 不降+至少一维严格改进才入库）与我们"经验卡片带验收判据才沉淀"是同一思想；Stage II 的"失败+诊断→两轮内修复"轨迹正是 error-case-library 的训练化版本。我们已在实践这条路线的工程近似，论文给出的是可训练化版本。
  5. 与 AOT harness 优化路线（记忆里的 harness-architecture 六层等）的关系：不是替代而是时点之争——AOT 把 harness 当持久资产离线优化，JIT 把搜索成本摊销进训练好的生成器、部署时按例合成。Table 4 的范式对比表（AutoHarness/Meta-Harness/AHE/Adaptive AH/TTHE/RHI/Harness-R1 vs JIT）值得留存：全表中只有 Harness-R1 和 JIT 同时具备"实例合成+可学习修复"，JIT 独有"训练化在线进化"。

趋势判断

  • Harness 工程从"手艺"变成"可训练学科"：论文把 harness 形式化为 ℋ_Π（协议约束的可执行空间）并证明 27B 小模型就能在此空间内完成选型+实例化+修复+进化。2026 下半年可预期：各家 harness（Claude Code/Codex/Hermes/OpenClaw）会把"任务条件化生成"做成内置能力，静态单一 harness 会像"手工调 prompt"一样贬值。
  • "小模型+好 harness > 大模型裸奔"成为可引用的定量事实：token 成本降 36%（均值）而性能反超，推理经济学叙事从"蒸馏大模型"转向"摊销 harness 智能"——这与模型经济学里包月+错峰策略叠加（生成器 27B 可本地 vLLM 部署，执行模型继续用包月 API）是可落地的成本组合。
  • Agent 竞赛的第二轴线确立：模型厂商排行榜之外会出现 harness 智能排行榜（论文 leaderboard 已开先例）。对 Agent 框架作者：不暴露"可被 JIT 类生成器 wrap 的接口"的框架会被边缘化。

指南分析：什么场景该用 / 怎么接

场景 建议
同类任务高频重复（如固定格式深度调研、批量文档流水线） 值得接：走 streaming 模式攒 harness bank，token 省幅最大
任务高度异构、一次性 静态 best-of-N 即可；或直接用现成 HarnessFactory 11 个 seed 手选
想试但不想部署 27B repo 原生支持托管 API 当 meta-agent（--meta-model + judge selector），先零成本试效果再决定是否本地部署

硬件/实时场景（如真机控制） 不适用：论文域限 agentic LLM 任务（搜索/规划/办公），无实时性讨论；27B 生成器引入分钟级前置延迟

拓展应用推荐

  1. 给 Hermes 侧的 skill 路由加"任务条件化"层（低成本试点）：不引 JIT 模型，先用 HarnessFactory 的 11 个 seed 做成 skill 选型表——按任务形态（搜索型/规划型/办公型/递归研究型）先例化对应 scaffold 模板，仅此一步就接近论文里 seed harness 的上限水平。
  2. experience-bank 升级为前沿保留规则版：现有经验卡片入库加三条判据——reward 不降、延迟不升、成本不升（至少一项严格改进），对齐 Evo-GDPO 的 bank 更新逻辑，防经验库退化成杂物堆。
  3. 真机长任务之外的 Agent 流水线降本：多轮深搜/巡检类 cron 任务（盯盘扫描、论文日报）理论上最吃 token，可先用 JIT（托管 API meta-agent 模式）对一条流水线做 A/B，实测 36% 成本降幅是否迁移。
