一、范式转移：从静态模型到自进化 Agent

1.1 行业转折点

"It is not the most intellectual of the species that survives... but the species that is able best to adapt and adjust to the changing environment." — Darwin（paraphrased）

AI 领域正经历从 scaling static models 到 developing self-evolving agents 的根本范式转移：

  • 旧范式：训练 → 部署 → 冻结。模型部署后不再改变，除非人工重新训练
  • 新范式：Agent 在运行时自主修改内部组件，基于自身轨迹和反馈信号持续改进

1.2 与其他学习范式的区分

范式 运行时 动态 测试时 主动 自反思
Curriculum Learning ✗ ✗ ✗ ✗ ✗
Lifelong Learning ✗ ✓ ✗ ✗ ✗
Model Editing ✗ ✓ ✓ ✗ ✗
Self-evolving Agents ✓ ✓ ✓ ✓ ✓

自进化 Agent 是唯一同时满足全部五个条件的范式。

二、形式化定义：什么算"自进化"

2.1 操作性定义

一个自进化 Agent 需同时满足三条标准：

  1. 经验依赖性（Experience-dependent）：更新必须由 agent 自身轨迹、自生成数据或环境反馈驱动
  2. 持久策略改变（Persistent policy-changing）：更新必须产生持久的、改变策略的效果，而非暂态的 instruction-following
  3. 自主探索能力（Autonomous exploration）：系统必须具备自主探索或自发学习机制

2.2 形式化表达

Agent 工作流表示为 Γ（多 agent 拓扑），其中节点 i 包含：
- ψᵢ：模型（通常是 LLM）
- Cᵢ：上下文（prompt 和 memory）
- Wᵢ：工具集

静态 Agent：Γ₀ = Γ₁（部署后冻结）
自进化 Agent：Γ₀ → Γ₁ → Γ₂ → ...（持续演化）

三、进化什么？四大维度

3.1 模型进化（Model Evolution）

子类 代表工作 机制
Policy 进化 SCA, Self-Rewarding, TextGrad 将文本反馈视为可微分训练信号
经验驱动 AgentGen, Reflexion, AdaPlanner 通过交互构建/学习环境
奖励自驱 Self-Rewarding LM 内部自评判机制驱动改进

TextGrad 是关键创新：将整个计算图中的文本反馈视为"梯度"，反向传播到 prompt 和 workflow 的各个节点。

3.2 上下文/记忆进化（Context Evolution）

"Effective memory management is crucial for agent performance"

系统 机制
Mem0 两阶段管线：ADD → MERGE/UPDATE → DELETE
Memory-R1 RL 框架训练专用 Memory Manager
Agent Workflow Memory 记录常见子任务序列供复用

Prompt 优化方向：
- SPO（Self-Supervised Prompt Optimization）：完全自闭环，模型自生成训练数据
- DSPy：将整个工作流表示为图，联合优化子 prompt
- TextGrad：文本梯度在 workflow 中传播反馈

3.3 工具进化（Tool Evolution）

三个递进层次：

① 自主发现与创建
- Voyager：通过试错构建不断扩展的技能库（Minecraft 环境）
- CREATOR：将抽象工具创建与具体工具使用解耦
- SkillWeaver：分析成功轨迹来提出和合成新技能

② 精通（通过迭代精进）
- LearnAct：自纠错循环，从经验中学习
- From Exploration to Mastery：从反馈信号建立学习循环

③ 可扩展管理与选择
- ToolGen：将工具编码为 LM 词表中的唯一 token
- AgentSquare：元学习自动搜索模块化设计空间

3.4 架构进化（Architecture Evolution）

单 Agent 系统优化：
- TextGrad：文本梯度反向传播通过 workflow
- AgentSquare：进化算法搜索组件组合
- Darwin Gödel Machine：递归修改自身 Python 代码库 ← 最激进的自进化

多 Agent 系统优化：
- ADAS（Automated Design of Agentic Systems）：将系统设计定义为图灵完备空间中的搜索问题
- AFlow：用可复用算子 + MCTS 导航设计空间
- ReMA：多 agent RL 协作训练 meta-thinker 和 executor

四、何时进化？两类时间模式

4.1 Intra-Test-Time Self-Evolution（任务内进化）

在任务执行过程中发生的适应：

机制 代表 描述
In-Context Learning Reflexion, AdaPlanner 存储语言反思作为 episodic memory
Supervised Fine-Tuning SEAL 生成"self-edits"重构自身
Search-Based Tree of Thoughts, Buffer of Thoughts 搜索最优推理路径

4.2 Inter-Test-Time Self-Evolution（跨任务进化）

在多个任务之间积累和迁移经验：

  • 积累经验库（lessons learned）
  • 优化 prompt 策略（跨任务迁移）
  • 扩展工具/技能库
  • 重构记忆架构

五、代表性框架深度拆解

5.1 Darwin Gödel Machine — 最激进的自进化

  • 核心理念：递归修改自身 Python 代码库
  • 机制：Agent 读取自己的源码 → 提出改进 → 验证 → 部署
  • 意义：最接近"真正自我修改"的实现
  • 风险：需要严格的安全边界

5.2 EvoAgentX — 工程化进化工作流

  • 来源：EMNLP 2025 Demo
  • 能力：自动化框架用于进化 Agentic Workflow
  • 特点：开源、可部署，面向生产
  • 代码：github.com/EvoAgentX/EvoAgentX

5.3 STELLA — 生物医学自进化 Agent

  • 能力：自进化 LLM Agent 用于生物医学研究
  • 机制：动态发现和集成新工具
  • 价值：证明了领域自进化的可行性

5.4 SEAgent — 计算机使用自进化 Agent

  • 来源：arXiv 2508.04700（2025-08）
  • 能力：从经验中自主学习的计算机使用 Agent
  • 机制：记录操作轨迹 → 提取模式 → 优化策略

5.5 MASLab — 统一多 Agent 代码库

  • 来源：arXiv 2505.16988（2025-05）
  • 能力：统一、全面的 LLM 多 Agent 系统代码库
  • 价值：为多 Agent 研究提供标准化实验平台

7.2 差距与改进建议

P0 — 补齐 Intra-Test-Time 反思机制：
- 当前 Reflexion 式"任务内语言反思"主要靠 session 内 context，缺乏结构化的 episodic memory 存储
- 建议：引入类似 Reflexion 的"失败 → 语言反思 → 存入 episodic memory → 下次任务前检索"循环

P1 — 引入 TextGrad 式梯度传播：
- 当前 prompt 优化是独立的 skill（auto-prompt-optimization），未与 workflow 图结合
- 建议：将 Hermes 的 skill 调用链建模为计算图，引入文本梯度反向传播

P1 — 强化跨任务经验迁移（Inter-Test-Time）：
- experience-bank 已有雏形，但缺乏系统性的"经验抽象 → 模式提取 → 跨任务复用"管线
- 建议：参考 Agent Workflow Memory，自动提取成功轨迹中的子任务序列模式

P2 — 引入架构自搜索：
- 当前多 Agent 编排是人工设计的（OPM/Dev/Content/Data Meow）
- 建议：参考 AgentSquare/ADAS，用进化算法搜索最优 agent 组合

7.3 安全边界

自进化的核心风险：
1. 能力漂移：自进化可能偏离用户意图 → 需 alignment 锚点
2. 代码自修改风险：Darwin Gödel Machine 式自改代码需沙箱
3. 评估可信度：LLM-as-Judge 可能被 prompt injection 欺骗

Hermes 的 AGENTS.md 已有禁止操作表，但需增加"自进化操作的审批流程"。
