没有免费的检验器——机器人策略验证器 150 篇综述

内容整理

论文: No Free Checker: A Survey of Verifiers for Robot Policies (arXiv:2609.09250v2, 2026-09-13, cs.RO)

核心命题: 机器人学习中验证器（verifier）无处不在——过滤演示数据、提供奖励信号、推理时排序候选动作、评估策略。综述约 150 篇工作后得出总规律：可信度（credibility）随可用性（availability）上升而单调下降——verdict 越便宜、越早、越密集，高分越不能说明任务真的做好了。No free checker：想要便宜的检验必然牺牲可信度。

两轴评价框架:
- Availability（可用性）: 一次 verdict 的成本多高、在 rollout 中多早给出、能多频繁地询问。verdict 越便宜/越早/越密，可用性越高。
- Credibility（可信度）: 一个高分到底对任务说明了什么。判断越容易被博弈（gameable）、越自利（self-serving），可信度越低。

四大家族（按判断来源划分）:
1. 人类验证器：偏好比较（RoboArena 双盲对比聚合排名）、逐时间步打分（reward sketching，标注者画 0-1 进度曲线训练 reward model）、执行中介入（HG-DAgger 人类门控 / HACO）。
2. 规则与形式化验证器：STL（信号时序逻辑）satisfaction margin 打分——满足为正、违反为负、幅度=离边界多近；calibrated predictive runtime verification 用 conformal prediction 给预测器输出加校准误差带（95 分位 held-out 误差做区间），可提前几步预警规范即将被违反；鲁棒版处理校准/部署分布漂移。
3. 学习与预训练验证器：success detector、reward model、TOPReward 等。
4. 模型内在验证器：SAFE——在 VLA 策略内部表征上训轻量失败预测器（成功/失败在 latent space 可分离），functional conformal prediction 校准时变阈值；Sentinel 监控动作预测的时序不一致性 + 任务进度双通道。用于检测（执行中报警）与选择（执行前挑最可靠候选）。

Table 5 验证器错误如何随用途放大（关键洞见）:
验证器有四种用途，一个错误会同时污染全部四个：
- Curation（选数据进训练）与 Ranking（排名）：候选在未见评分的情况下产生 → 错误在语料上平均掉，只需平均准确率。
- Training reward（训练奖励）与 Runtime gate（运行时门禁）：候选由"搜索评分错误的输入区域"产生——一个罕见的评错区域就足以让评分完全不可用，因为优化会精确地找到它。

6.3 Reward hacking 的形式化: agreement rate（一致性基准）和 policy gain（训练增益）都是在"从未被搜索对抗过的验证器"上测的。用作训练奖励/运行时门禁的验证器多一条要求：不存在任何输入区域使评分以搜索可达的方式出错。Reward hacking 就是这条要求的失效。已知修复：信息论瓶颈、非负奖励构造。语言侧已有 scaling law（策略能被优化到多远才翻车）与 token 空间攻击（找出 top reward model 打最高分的应拒绝输入）；机器人侧的可利用性共享基准尚不存在——各 reward model 作者自报抗 hacking 性，无第三方审计。

6.1 一致性基准家族: TOPReward（130 任务×4 平台，与人类判断的一致性）、Robometer（语料为训练而生非审计）、RoboReward（为诊断验证器错误而生，当前一致性最低）、OpenGVL（用帧的真实时间序做参考，测跨具身泛化）、ASIMOV（安全场景）。

其他要点: Li et al. 论断——具身世界模型中 RL 的上限瓶颈是验证不可靠而非探索困难；一方法让策略/世界模型/reward model 互相迭代多轮自提升。

查询拓展

  • STL satisfaction margin 可否给 DUCK stand_eval 加"接近摔倒边界"的连续分数（现只有二值 tilt<45°）？
  • conformal 校准对 DUCK FELL 检测（0.5s 滑动均值+2s 学习期）是否有增量——把阈值从手工改成 held-out 误差分位数？
  • 语言侧 reward model scaling law（Gao et al. 41）在机器人侧的等价物什么时候出现；DUCK 的确定性 reward 项是否可视为"不可搜索欺骗"的极限形式？
  • SAFE 式内部表征失败预测器能否用 R9/R9T 的 value/entropy 轨迹复刻一个廉价的"倒前预警器"？

归纳总结

  1. 核心规律一句话: verdict 的便宜、早、密（availability↑）与高分含金量（credibility↓）是结构性权衡，不是工程不足——任何"又便宜又可信"的验证器宣称都违反本综述的经验规律。
  2. 错误放大机制取决于"候选是否由搜索产生": 未被搜索对抗的用途（curation/ranking）错误可平均；被搜索对抗的用途（training reward/runtime gate）单一错误区域会被优化精确命中并放大——这是 reward hacking 的统一解释，比"策略学会了作弊"的直觉表述更可操作。
  3. 验证器也要被验证，且验证方法分三层: 固定 rollout 集上的一致性 → 由它训练出的策略增益 → 被优化对抗下的稳健性。只报第一层是当前领域的普遍水分来源。
  4. conformal prediction 是把"手工阈值"换成"带覆盖率保证的分位数阈值"的通用技法，在 runtime verification 与内部表征失败预测器（SAFE）两处都出现——分布漂移时保证失效，需 robust 版本。

趋势判断

  • 验证器可靠性正成为机器人学习规模化后的下一主战场：Li et al. "瓶颈是验证而非探索"的论断若成立，RL in world models 的投入会从生成侧转向评分侧。
  • 机器人侧缺共享的可利用性基准（语言侧有 token 攻击+scaling law）——做出第一个"固定候选集 + 各验证器可利用性打分"的基准会是高影响力工作，与 DUCK 无关但与 Agent 自进化评估直接相关。
  • 模型内在验证器（读策略内部信号做失败预警）成本最低、可用性最高，按本综述规律其可信度最低——但 SAFE 的 conformal 校准路线说明"低成本+统计保证"的组合在挤压这个权衡边界。

关联分析

与 DUCK 验收体系的直接对照:
- stand_eval_v2 冤案（09-23 docs/98）= 6.3 的镜像案例: 一验收器（把 dones 当摔，不区分 time_out）在"未被搜索对抗"的评测用途下没暴露；它同时被用作完训验收门禁（runtime gate），错误（400 步封顶误判为摔倒→全系冤判 UNSTABLE）就被放大成整条训练链的判决。综述的框架把这个事故精确归类：gate 类用途对单一错误区域零容忍。
- "验收器先经已知好/坏模型交叉验证再上岗"的用户铁律 = 6.1 一致性基准的最小化版本: 已知好模型（W5R2 狂躁 4.5 真坏 / TRANS 冷静 0.11 半好）就是 held-out 参考判断。综述提供了理论包装：没有这层校准，验收器自己的 error rate 是未知数。
- DUCK 死法签名体系 vs reward hacking: DUCK 的躺平 farming（peak<0.05+ep_len>400+fell=0）就是"策略找到了 reward 评错区域"——alive_upright 工资在躺平态仍被支付。修法（air_time 挂 cmd 门 0.05 + jvel 罚）与综述所列"信息论瓶颈/非负奖励构造"同属"收窄错误区域"。
- S 系工资加浓实验（alive_upright 0.0236→0.048 精确 2 倍）可从综述视角再审：工资加倍 = 提高 reward 密度（availability↑），按规律其 credibility 风险同步上升——act_tail_mean 的监测（S2T 压到 1.8）正是在监控欺骗行为。

与已读论文关联:
- 与《RL 策略部署稳定性-约束式平滑与动态 EMA》（09-23）同属"部署前门禁"主题：前者管动作平滑性（运行时），本综述管评分可靠性（验收时）。
- 与《自进化 Agent 过程级评估 EvoPathBench》（09-23）互补：EvoPathBench 评 Agent 进化过程，本综述提供"评估器自身可信度"的审计框架——自进化系统里两者缺一不可，否则进化方向被有缺陷的验证器劫持。

指南分析

给 DUCK 验收链的三条可操作改进:
1. 验收器上岗协议固化: 任何新 eval 脚本先跑"已知好/坏模型对"（如 W5R2@18659 坏 vs H1YAW@13250 好双锚点），一致性 100% 才准上岗——这已是用户铁律，建议写进 launch_gate.sh 第 12 条（发射前 eval 脚本自检）。
2. runtime_gate 与 curation 用途分离: stand_eval 结果同时被用于"是否继续训"（ranking）与"是否上真机"（gate）。上真机门禁应加第二独立信号（如 act 有界性 + 末态 z 高度双指标），单评分器双用途时错误不平均反而放大。
3. 连续化摔倒边界: 参考 STL satisfaction margin，把 tilt<45° 二值判据升级为 margin = 45° - tilt 的分布报告（min/P10/median），完训验收看 margin 分布而非单点——W5R2"存活恒 400"冤案若有 margin 分布会更早暴露异常。

Hermes 自进化侧的镜鉴: 递归自进化循环（L1 信号扫描→L2 沉淀→L3 对账）的 L1 信号本身就是一个 verifier，且属于 availability 最高的"规则签名扫描"类——按本综述规律其 credibility 有限。现有的"进化准入门禁（session 证据+人工拍板）"正是对抗验证器不可靠的对的制度设计，值得在 evolution_log 审计时保留。

拓展应用推荐

  • P0（DUCK）: launch_gate.sh 增补第 12 条——eval 脚本签名自检（新/改验收脚本必须附最近一次好/坏锚点对拍记录，否则禁发射）。低成本，直接防 stand_eval 类冤案复发。
  • P1（DUCK）: stand_eval_v3 增加 margin 分布输出（tilt/z/act 三指标 P10/P50/min），验收判据从单阈值改为"margin>0 的 episode 占比 + 分布形态"，一周内可落地。
  • P2（Hermes 自进化）: session-evolution-scan 的候选清单增加"信号可信度"字段（规则签名命中 vs 用户明示纠偏分级），L2 沉淀优先采信高级别信号。
