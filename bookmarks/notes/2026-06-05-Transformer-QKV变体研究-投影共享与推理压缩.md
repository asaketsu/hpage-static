# Transformer 需要三个投影吗？QKV 变体系统性研究

> **来源**：arXiv 2606.04032 · 学术论文 · 2026-06-05
> **原文**：https://arxiv.org/abs/2606.04032
> **热度**：HN #15, 159 pts
> **格式**：双格式(MD + HTML) · 含借鉴进化点

## 摘要

论文系统评估了 Transformer 注意力机制中 QKV 三个投影的必要性，测试了三种投影共享约束：Q-K=V（共享 key-value）、Q=K-V（共享 query-key）、Q=K=V（单一投影）。在合成任务、视觉（MNIST/CIFAR/TinyImageNet）、语言建模（300M 和 1.2B 参数模型，10B tokens）上的实验表明，Q-K=V 可减少 50% KV cache，仅 3.1% 困惑度退化。结合 GQA-4 达到 87.5% cache 压缩，结合 MQA 达到 96.9%，使端侧推理成为可能。

## 核心内容

### 研究问题
Transformer 的 QKV 注意力是否真的需要三个独立投影矩阵？去掉一些会怎样？

### 三种投影共享方案

1. **Q-K=V（共享 Key-Value）**：Key 和 Value 使用同一投影，Query 独立
   - KV cache 减少 50%
   - 困惑度仅退化 3.1%
   - 原因：Key 和 Value 在表示空间中高度相似，注意力在低秩区域运行

2. **Q=K-V（共享 Query-Key）**：Query 和 Key 使用同一投影，Value 独立
   - 破坏了注意力的方向性
   - 性能显著下降

3. **Q=K=V（单一投影）**：三个投影合一
   - 产生对称注意力图
   - 需要非对称注意力修正（2D 位置编码）

### 关键发现
- Q-K=V 效果好是因为 Key 和 Value 占据相似的表示空间
- 注意力本质上在低秩机制中运行
- Q=K-V 破坏注意力方向性是根本缺陷
- 投影共享与头共享（GQA/MQA）是互补的，可叠加

### KV Cache 压缩效果

| 配置 | KV Cache 减少 | 困惑度退化 |
|------|-------------|-----------|
| 标准 QKV | 0% | 基线 |
| Q-K=V | 50% | 3.1% |
| Q-K=V + GQA-4 | 87.5% | ~5% |
| Q-K=V + MQA | 96.9% | ~7% |

## 关键概念

| 概念 | 定义 |
|------|------|
| 投影共享 | 多个注意力投影矩阵共享权重，减少参数和内存 |
| KV Cache | 推理时缓存 Key 和 Value 的中间结果，避免重复计算 |
| GQA | Grouped Query Attention，多组共享 Key/Value 头 |
| MQA | Multi-Query Attention，所有头共享一组 Key/Value |
| 低秩机制 | 注意力矩阵实际秩远低于理论值，冗余可压缩 |

## 能力边界

- 实验规模最大 1.2B 参数，未在超大模型验证
- 困惑度退化在长上下文场景下可能更显著
- 2D 位置编码作为对称注意力修正增加了实现复杂度
- 对推理质量敏感的任务（如代码生成）需要更谨慎评估

## 最佳实践

1. 端侧部署优先考虑 Q-K=V + MQA 组合（96.9% 压缩）
2. 云端推理用 Q-K=V + GQA-4 平衡质量和效率
3. 投影共享是权重绑定的一个被低估的实例，值得系统性探索
4. 2D 位置编码可以缓解对称注意力问题
