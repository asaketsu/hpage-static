归纳总结

一句话：模型参数冻结，Agent 通过修改外围 Harness（Prompt/Skill/脚本/工具规则/异常插件）持续改进做事能力，并把"改进的方法"沉淀为可跨任务复用的经验——对具身智能，这提出了"改进经验的迁移"这一比"技能迁移"更深的研究问题。

本篇与 10-18 笔记的分工：那篇回答"我们系统怎么吸收"（四分判定+两处已落地增强），本篇回答"对机器人/DUCK 意味着什么"（具身章节+新数据细节）。

内容整理：机制回顾与新增实证细节

核心机制（与 10-18 笔记互补的表述）

概念 论文表述 关键细节
八组件编辑 模型冻结在中央，外围 Prompt/Skill/脚本/工具规则/异常插件可编辑 "模型具备某项能力 ≠ Agent 能可靠使用该能力"——编程 Agent 把工具调用写成文字而不执行，改工具使用规则即 60→100（Figure 15）
Propose-Probe-Compose 提出修改→对照执行→组合改进 无标准答案时对照行为变化而非分数；系统全程看不到任何评分
双角色分离 执行 Agent 完成任务 + 改进 Agent 分析记录改 Harness 可用不同模型（主实验改进角色=Claude Opus 4.8），也可同模型自编辑
经验沉淀 保存完整 Harness（Skill/脚本/工具规则）+ 说明 每条经验附"什么现象表明需要改/改什么/哪些执行对照支持"；证据不足不入库
克制继承 新任务不继承上个任务的全部 Harness 从基础 Harness 出发，按当前问题选择性复用——特化规则跨任务可能失效

本篇新增的数据细节（10-18 笔记未覆盖）

  • 汇总排班/场地/人力/预算多文件生成项目方案案例（Figure 9）：原 Agent 从不检查产出文件、数据不跨文件核对 → 加通用校验脚本（强制重开检查）+ 专业对账 Skill（明确哪些数字必须跨文件核对）→ 事后评测 43.1→77.8
  • 并行探索预算扩大：GLM-5 从 64.2→75.7（k=1）→ 79.6（扩大并行预算）
  • JobBench 消融：不用历史经验 34.2 → 用经验 36.0（WorkBuddy 74.4→77.5 之外的第二基准验证）
  • 诚实披露的选择失误：被选中的交付物实际 55 分，被放弃的反而 95 分——无验证器环境下行为对比判断仍可能出错
  • 代价明示：每轮改进都要额外调模型+执行候选方案；论文证明的是"优化工作机制有实际价值"，不是"一定比训练模型便宜"

具身智能章节（本篇独有增量）

巡检机器人案例：已具备自主导航能力的机器人经常在某些设备附近定位失败——原因未必在导航模型，执行流程问题同样常见：
- 定位置信度下降时没有重新观察
- 原观察位置被遮挡时不会选新观察点
- 反复失败后没有及时切换恢复策略

这些不需要重训导航模型，可通过修改感知调用方式、导航 Skill、异常恢复流程解决。

两种迁移的区分（核心新知）：

类型 内容 约束
能力迁移 把已学会的动作策略迁移到其他机器人 要求本体/控制接口相似
改进经验迁移 把发现问题、调整工具、验证效果的方法迁移到其他机器人 不要求本体相同，但需按新传感器/环境/运动能力重新验证

物理世界约束：一次看似成功的改进，必须经过独立的物理验证和安全检查，才能用于真实机器人——软件任务的对照实验在物理域要加安全门禁。

分工定位：模型训练改变模型内部能力；Harness 改进改变模型外部能调用什么能力、如何组织使用。具身场景中前者=运动策略/感知模型，后者=技能组合/工具调用/异常恢复/任务执行。

关联分析

  • 与 DUCK 真机调试铁律同构：巡检机器人案例的三类失败（不重新观察/不换观察点/不切恢复策略）与我们"H1 乱蹬根因=起始姿态分布外+执行层带宽"的归因路径一致——先查执行流程再考虑重训策略，这正是 Harness² 的核心主张在机器人域的映射
  • 改进经验迁移=我们 skill 体系的手工版：duck-stand-squat / sim2real / servo-quirks 等 skill 就是"改进经验"——未来换本体（新舵机/新主控）时，rl-policy-transfer 判定"策略不可复用"但调参方法/坑表/校准协议可复用，这正是"改进经验迁移不要求本体相同"的实例
  • 与 evolver/经验池的对照（详见 10-18 笔记四分判定）：本篇补充的"证据不足不入库"与我们"单次成功 confidence 上限 0.5 需二次复现"已闭环；"克制继承"对应我们 skill 按需加载而非全量注入
  • 物理验证门禁：与我们真机守卫哲学（IMU>45° 终止/动作后复读关节角）一致——Harness² 把这从纪律上升为方法论要求
  • 与 ROSClaw 笔记（2026-09-21）衔接：文中点名 ROSClaw 是具身 Agent 运行时值得探索此方向的目标——两文合看=物理域 Harness 改进的落地路径

趋势判断

  1. 具身智能的第二增长曲线：VLA/运动策略研究饱和度上升后，"能力组织层"（Harness）的改进是下一个性价比高地——模型不动，Agent 变强，这对算力受限的端侧机器人（我们的 Jetson 场景）尤其友好
  2. "改进经验迁移"会成为新研究问题：技能迁移关注"会不会"，改进经验迁移关注"怎么学会得更快"——后者对机器人公司是真正的复利资产（本体换代不丢方法论）
  3. 无验证器改进+物理安全门禁的组合是具身域刚需：真机没有 ground-truth 分数，A/B 行为对比+物理验证是唯一闭环——与我们盯盘/真机测试的"证据链"纪律同源

指南分析

  • ✅ 可直接沿用：真机失败归因时先列"执行流程三查"（是否重新观察/是否换策略点/是否切换恢复），再考虑重训——零成本，写进真机调试 SOP
