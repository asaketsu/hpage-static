一、核心结论（先看这个）

  1. Agent 框架的范式正在从"预定义能力"转向"自进化"——LangGraph/CrewAI 们要求开发者预注册全部工具和流程，新一代框架让 Agent 自己长技能、记路径、从失败中学习。判断标准一句话：遇到新情况时，是谁在改代码？开发者 = 旧范式；Agent 自己 = 新范式。
  2. GenericAgent 用 3300 行种子代码实现 6× token 节省——核心机制是"技能结晶"：首次任务高成本探索→执行路径固化→复用近乎零成本。且 388 个 commit 全部由 Agent 自己提交（自进化最强实证）。
  3. Evolver 的"基因组进化协议"（GEP）把进化变成可审计工程——genes.json（原子进化模式）+ capsules.json（组合策略）+ events.jsonl（append-only 审计日志），与微调的本质区别：自进化改的是 Agent 行为方式，微调改的是模型知识，完全不同层面。
  4. Mem0 2026 新算法：LoCoMo 92.5 分 / LongMemEval 94.4 分，每查询仅 ~6900 token（全量上下文方案要 26000+）。两大增益来自：时间推理 +29.6 分、多跳推理 +23.1 分。架构关键 = 单遍 ADD-only 抽取 + 三信号并行检索（语义+关键词+实体）。
  5. 对本机 Hermes 的直接映射：Hermes 的 skill_manage/memorygraph/session_search 体系已具备 Evolver 式骨架，但缺 GenericAgent 的"技能结晶"自动化——目前 skill 沉淀靠 cron 触发 + Agent 主动判断，尚未形成"执行路径→结晶→直接复用"的闭环。

二、内容整理（功能清单：这些项目/报告提供了什么）

2.1 GenericAgent（github.com/lsdefine/GenericAgent，4.3K stars，日增 883）

  • 3300 行种子代码：9 个原子工具（代码执行/文件读写/浏览器控制等）+ ~100 行 agent loop + 5 层记忆
  • 技能结晶机制：新任务→自主探索→执行路径结晶→记忆存储→下次直接复用（6× token 节省来源）
  • 5 层记忆架构：
层 名称 职责
L0 Meta Rules 核心行为约束
L1 Insight Index 路由与召回索引（30K 上下文内精准取知识的关键）
L2 Global Facts 累积的稳定知识
L3 Task Skills/SOPs 可复用工作流
L4 Session Archive 会话日志长期回溯
  • 真实浏览器注入（保持登录态，非沙箱）、Android ADB 控制、多模型支持（Claude/Gemini/Kimi/MiniMax）
  • 自我证明：仓库 388 个 commit 无一人工终端输入

2.2 Evolver（github.com/EvoMap/evolver，4.7K stars，日增 866）

  • GEP 基因组进化协议三资产：
  • genes.json 原子进化模式（可复用改进单元）
  • capsules.json 复合进化策略（基因组合）
  • events.jsonl append-only 进化历史（可审计）
  • 进化工作流：信号检测（从运行日志提取错误模式）→ 基因选择（信号匹配评分）→ 变异生成（显式参数控制）→ Prompt 发射（协议化而非任意代码执行）→ 事件记录
  • 策略预设（生产环境用 harden 或 repair-only）：
EVOLVE_STRATEGY=balanced     node index.js --loop  # 50%创新/30%优化/20%修复
EVOLVE_STRATEGY=harden       node index.js --loop  # 20%创新/40%优化/40%修复
EVOLVE_STRATEGY=repair-only  node index.js --loop  # 0/20/80
  • 四重安全机制：信号去重（防递归修复循环）、停滞检测（防无限进化）、源文件保护（防覆盖核心代码）、验证门禁

2.3 Open Agents（github.com/vercel-labs/open-agents，3.1K stars，Vercel 出品）

  • 三层架构：Web(Next.js) → Durable Workflow → Sandbox VM
  • 关键设计：Agent 跑在沙箱外——沙箱可独立休眠/恢复、Agent 执行跨越单请求生命周期、模型与沙箱实现可独立替换
  • Durable Execution：基于 Vercel Workflow SDK，任务在服务器重启后存活（流式+取消+长任务状态管理）
  • 能力：文件读写/语义代码搜索/Shell/分支管理/自动 PR/会话只读分享/.agents/skills 技能系统
  • 定位：不是自进化 Agent，而是自进化 Agent 跑生产所需的基础设施

2.4 Mem0 State of AI Agent Memory 2026 报告

  • 三大标准基准：
  • LoCoMo：1540 题，单跳/多跳/开放域/时间记忆四类
  • LongMemEval：500 题六类，知识点更新+多会话最严格
  • BEAM：1M/10M token 规模（扩上下文窗口解决不了，最贴近生产）
  • 五维评估框架：BLEU + F1 + LLM judge + token 消耗 + 延迟（防止单轴优化）
  • 2026 新算法成绩：LoCoMo 92.5 / LongMemEval 94.4 / BEAM-1M 64.1 / BEAM-10M 48.6，每查询 ~6900 token
  • 架构两大变化：①单遍 ADD-only 抽取（Agent 生成的事实与用户陈述事实同权重存储）②三信号并行检索融合（语义相似度+关键词匹配+实体匹配，融合分超越任一单信号）
  • 生态：21 框架 + 20 向量库集成
  • 六大开放难题：跨会话身份解析、大规模时间抽象、应用级评估框架、隐私同意架构、跨设备身份、记忆过时处理（用户情况变化后旧记忆变错误）

三、使用性评估

项目/报告 好用点 局限
GenericAgent 种子极小（3300 行）验证了"少即是多"；30K 上下文够用靠 L1 路由；自建仓库是最硬核自证 本地优先，生产化弱；浏览器注入有安全面；单人口碑项目风险
Evolver 进化可审计可回滚（git-based + blast radius 计算）；不需要 GPU；策略预设覆盖生产/实验 生态早期；进化质量依赖基因库积累；Node.js 栈
Open Agents Durable Execution 解决自进化 Agent 的"重启存活"死穴；沙箱分离设计干净 不是自进化本体；绑定 Vercel 云；大参考应用非精简库
Mem0 报告 基准+评估框架全开源（github.com/mem0ai/memory-benchmarks）；数字可复现 厂商报告立场（自家算法第一）；BEAM 10M 才 48.6 分说明长规模仍是硬骨头

四、归纳总结：指导性意见（何时用/何时不用）

  1. 何时借鉴 GenericAgent：想降低重复任务 token 成本时——把"执行路径结晶"思路加到现有 skill 体系：不只记结论（SKILL.md），还记完整执行轨迹（哪些工具调用序列成功了），下次直接重放。
  2. 何时借鉴 Evolver：需要 Agent 行为的可审计变更时——本机已有 evolver skill，本次调研确认其方向正确，可补充 GEP 三资产结构（genes/capsules/events 分离）和策略预设概念。
  3. 何时不用：纯静态工作流（无重复性、无失败模式）不需要自进化；强合规环境慎用自动进化（即使有审计，变更频率本身是风险）。
  4. 记忆选型速查（2026 年现状）：drop-in 记忆层→Mem0；时间图记忆→Graphiti；memory-first 有状态 Agent→Letta；组织知识控制面→Cognee；LangGraph 生态→LangMem；文件透明记忆→ReMe。
  5. L1 Insight Index 是 30K 上下文跑赢 200K 竞品的钥匙——Hermes 的 skill 索引本质就是 L1，这个数据点支持"小上下文+强路由"路线，不必盲目追求大窗口模型。

五、案例可寻

  • GenericAgent 自建仓库：388 commits 全 Agent 完成——从 0 长出技能树的真实案例
  • 6× token 节省场景："外卖下单"首次探索（高成本）→ 二次调用结晶技能（低成本）——重复型任务收益模型
  • Evolver 生产策略：harden（40% 修复）/ repair-only（80% 修复）预设对应生产稳定优先——比默认 balanced 更适合已上线系统
  • Mem0 与自家对比：2025 论文（ECAI，arXiv:2504.19413）建立十方案基线 → 2026 算法在时间推理+29.6/多跳+23.1——增量改进路径清晰可循
  • 反面参照：OpenClaw 53 万行 vs GenericAgent 3300 行——代码量与能力不成正比，架构（记忆分层+结晶）才是关键变量

6.1 Mem0 三信号检索思路（伪代码，可移植到 memorygraph）

# 融合检索：语义 + 关键词 + 实体 三路并行打分
score = w1 * semantic_similarity(query, memory) \
      + w2 * keyword_overlap(query, memory) \
      + w3 * entity_match(query_entities, memory_entities)
# 融合分 > 任一单信号（Mem0 实测结论）

七、对我们体系的改进建议

优先级 建议 依据

九、趋势判断

  1. Agent 框架价值重心从"编排"转向"记忆与学习"：2024 编排框架（LangGraph/CrewAI）→ 2025 记忆层（Mem0/Letta）→ 2026 自进化闭环（GenericAgent/Evolver）。编排已成商品化底座，差异化在上层。
  2. 可审计进化将成为生产门槛：Evolver 的 events.jsonl + git 回滚模式会被主流框架吸收——没有审计日志的自动进化上不了生产，这与企业 Agent 治理（agent-security-governance skill 主题）合流。
  3. 记忆基准进入 1M+ token 时代：BEAM 10M 最佳成绩才 48.6 分，说明长规模记忆远未解决——谁先把 10M 规模做到 70+ 谁就定义下一代标准。
  4. 小上下文+强路由路线获得数据支撑：GenericAgent 30K 窗口跑赢 200K-1M 竞品、Mem0 每查询 6.9K token 拿 92.5 分——"检索质量 > 窗口大小"在 2026 年从观点变成可复现事实。
  5. 自进化 Agent 的基础设施需求显现：Open Agents 的 Durable Execution（重启存活）+ 沙箱分离预示下一批创业机会在"进化引擎的生产化托管"，而非另一个编排框架。
