摘要

OpenCLI 是一个将网站、Electron 应用、本地工具统一转化为确定性 CLI 接口的开源项目。核心创新：通过 CDP（Chrome DevTools Protocol）桥接浏览器会话，让 AI Agent 能直接操作已登录的网页——导航、点击、提取数据、截图——无需 LLM 消耗 token。90+ 预建 Adapter（B站、知乎、小红书、Twitter、Reddit 等），加上 Agent Skill 驱动的自定义 Adapter 编写流程，形成"人类用 CLI，Agent 用 Skill"的双层架构。

│  AI Agent    │────→│  opencli CLI     │────→│  Chrome Browser  │

技术栈

  • 运行时: Node.js ≥ 21 / Bun ≥ 1.0, ESM
  • CLI 框架: Commander.js
  • 浏览器: CDP (Chrome DevTools Protocol) + 浏览器扩展桥接
  • 构建: TypeScript → tsc → dist/
  • 测试: Vitest (unit/adapter/e2e)
  • 依赖极简: 核心仅 7 个 dep（commander, ws, js-yaml, undici 等）

关键设计决策

1. 零 LLM 成本

运行时不调用任何 LLM——所有操作都是确定性 CLI。LLM 只在 Agent 端（写 Adapter 时）使用。

2. 复用登录态

不存储凭据，直接复用 Chrome 已登录的 session。账户安全 + 零配置。

3. 确定性输出

同一命令同一输出 schema，支持 table/json/csv 格式，可管道、可脚本化。

4. Adapter 生命周期

侦察站点模式 → API发现(network/state/bundle/token/intercept 5层)
→ 字段解码 → init骨架 → verify验证 → 写入site memory

5. IPage 抽象

完整的浏览器操作类型安全接口（goto/click/type/snapshot/wait/network/frames/cdp），Adapter 只依赖此接口。

💡 对 Hermes Agent 的借鉴

P0: Manifest 快路径

  • 现状: Hermes Skill 加载是文件系统扫描
  • 借鉴: 预编译 skill-manifest.json，启动时零扫描
  • 行动: 在 auto-skill 或 skill-auto-inject 中加入 manifest 机制

P0: Strategy 路由

  • 现状: Agent 访问网站时统一用 browser_navigate，无策略区分
  • 借鉴: PUBLIC(直接curl) / COOKIE(带cookie) / INTERCEPT(拦截网络) 分层
  • 行动: 在 search-fallback-chain skill 中集成策略路由

P1: Site Memory

  • 现状: 每次抓取同一网站都从零开始
  • 借鉴: ~/.opencli/sites/ 模式，缓存已知的 endpoint 和字段映射
  • 行动: 创建 ~/.hermes/site-memory/ 持久化站点知识

P1: Adapter 决策树 Skill

  • 现状: 写新网站抓取器靠经验，无标准化流程
  • 借鉴: 30 分钟闭环决策树 + verify 验证
  • 行动: 将 wechat-article-extract 等 skill 升级为类似决策树结构

与垂域 LLM 的关联

OpenCLI 的 Adapter 模式 与 Harness Engineering 的"工具层"高度对齐：
- 约束层: Strategy 枚举 + Auth 策略 = 约束
- 工具层: IPage 抽象 + Browser primitives = 工具
- 反馈层: verify + site memory = 反馈闭环

在航空/航天载具设计中，可借鉴此模式：
- 将仿真软件（CATIA/ANSYS）封装为确定性 CLI Adapter
- Strategy 路由对应不同仿真类型的调用策略
- Site Memory 对应已验证的仿真参数映射
