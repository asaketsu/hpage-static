## 摘要

文章系统梳理了 Hermes Agent 的 8 个进阶机制：SOUL.md人格定义、三层Memory系统、AGENTS.md项目配置、Cron定时任务、Skill组合流水线、Subagent并行委派、Prompt Cache省钱技巧、多平台网关。额外覆盖了 OpenClaw 迁移和 LightRAG 知识图谱。核心理念：**Hermes 不是一个工具，而是一个会成长的系统**。

## 核心内容

### 一、SOUL.md：Agent 的灵魂
- 每次对话注入系统提示词
- 控制在 1KB 以内
- 写"反复需要纠正的行为规则"，不写泛泛的性格描述
- **反客服话术**：删掉"好问题""我很乐意帮你"，直接回答

### 二、三层 Memory 系统
- **Session Memory**：当前对话上下文，关了就没了
- **Persistent Memory**：MEMORY.md(2200字符) + USER.md(1375字符)，跨会话持久化
- **Skill Memory**：从经验中提炼的可复用工作流
- 关键操作：每次复杂任务后主动存经验；Heartbeat 周期做 Memory 维护复盘

### 三、AGENTS.md：项目级工作手册
- 根目录放核心规则（启动时加载）
- 子目录放分支规则（惰性发现，工具调用时才加载）
- 可复用 `.cursorrules` 和 `.cursor/rules/*.mdc`

### 四、Cron + Skill 组合
- 自然语言创建定时任务
- **Cron 可挂载 Skill**：带专业技能的 AI 在特定时间做决策
- **SILENT 模式**：健康时回复 `[SILENT]` 不打扰，只在异常时通知
- 多 Skill 同时挂载，产生组合效应

### 五、Skill 组合流水线（核心亮点）
**实战案例：5 个 Skill 串联 Twitter 自动化**
1. 克隆 → 采集推文，输出人格画像
2. 采集 → 按画像关注话题搜新闻素材
3. 创作 → 人格画像+素材生成推文，打分筛选
4. 配图 → 为通过筛选的推文生成视觉统一配图
5. 发布 → 批量发布，支持原创/引用/回复

**Skill 设计 5 原则：**
1. **单一职责** — 每个 Skill 只做一件事
2. **文件系统传递** — Skill 间通过文件交换数据，不用内存变量
3. **幂等性** — 重复运行同输入不产生副作用
4. **可观测** — 每步有日志和输出文件
5. **容错设计** — 单步失败不影响其他步骤

### 六、Subagent 并行委派
- `delegate_task` 派生独立子 Agent
- 并行处理：审查PR + 搜竞品 + 整理文档，3个10分钟→10分钟搞定
- 子 Agent 无主会话冗余历史，更专注更快
- 可给子 Agent 指定不同模型（便宜任务用便宜模型）

### 七、Prompt Cache 省钱
- 保持系统提示词稳定可命中缓存
- 不频繁切换模型
- 用 `/compress` 压缩过长历史
- 用 `/usage` 监控消耗

### 八、多平台网关
- Gateway 守护进程连接 Telegram/Discord/微信等十几个平台
- `/sethome` 设 Home Channel 统一接收通知
- Cron 输出直接推送到指定平台

## 🔍 借鉴点（对比我们的系统）

### ✅ 已到位
- SOUL.md 665字节，在1KB以内 ✅
- 三层 Memory 系统完整 ✅
- AGENTS.md 项目级配置 ✅
- 24个 Cron 任务运行中 ✅
- Subagent 委派能力 ✅
- 多平台网关（飞书+微信） ✅

### ⚠️ 需改进
- **SILENT 模式**：watchdog/auto-defender/health-check 等监控 cron 未用 SILENT，健康时仍有噪音
- **Skill 组合流水线**：有31个 skill 目录但未串联成自动化流水线
- **Skill 设计原则**：未系统性审查现有 skill 是否符合5原则（单一职责/文件传递/幂等/可观测/容错）
- **Prompt Cache**：未主动用 /compress 优化，未监控缓存命中率
- **Cron 挂载 Skill**：仅1个 cron（盯盘神探）挂了 skill，其他都是裸 prompt

### ❌ 缺失
- **LightRAG 知识图谱**：仍用朴素向量检索，未升级到实体关系图谱

## 💡 启发

- **"会成长的系统"这个定位极其精准** → 我们的自进化闭环（笔记→学习→Skill→Cron→监控）正是这个思路的实践，但还可以更激进
- **Skill 组合是下一个突破点** → 我们有31个 skill 但都是孤立的，串联成流水线后威力翻倍。比如：`blogwatcher` + `deep-analysis` + `note-dual-format` = 全自动深度研究流水线
- **SILENT 模式是极简主义的体现** → "只在出问题时通知"比"每次都汇报"更尊重用户注意力
- **文件系统传递 > 内存变量** → 这个设计原则解释了为什么基于文件的 skill 比基于 API 的插件更可靠、更可调试
- **Cron + Skill 组合 = 带专业技能的定时 AI** → 我们的 cron 大部分是裸 prompt，挂上 skill 后能力会上一个台阶
