> 嘉宾：Yann Dubois — OpenAI 后训练前沿（Post-training Frontiers）团队联合负责人，GPT-5.5 核心构建者

---

## 核心洞察

> "如果从非常广泛的意义上来看后训练，包括所有的强化学习以及对我们推理模型的训练，它其实就是把一个了解世界万物的东西，变成对人类真正有用的东西的过程。"

> "当模型基本上了解了世界的一切、拥有了我们所说的良好的世界先验知识（good priors）之后，强化学习突然就开始起作用了。"

---

## 一、AI 进步的本质：连续而非阶跃

**表面感受 vs 真实情况**：

很多人感觉 AI 是"阶跃式"变强的，但 Yann 认为所有进展实际上是**连续增长**的。之所以产生"跳跃感"，是因为模型的**可靠性突破了关键临界点** — 终于能让人类放心用它解决真实工作了。

> "大概在去年 12 月刚刚跨过了这个门槛，至少在 OpenAI 是这样。"

**三个加速因素**：
1. **可靠性跨越临界点** — 连续进步但主观感受为阶跃
2. **AI 自加速** — 优秀模型加速自身开发，特别是编程方面
3. **从竞赛转向实用性** — 从数学/编程竞赛的"可验证奖励"转向真实用户场景

---

## 二、GPT-5.5 内幕

### 发布过程中的"情绪过山车"

Yann 坦言每次前沿模型开发都经历相同循环：
1. 做出来 → 全员极度兴奋
2. 内部质疑涌现 → 预期降到低谷
3. 发布后外部反响好 → 重新高兴起来

GPT-5.5 的波动幅度尤其大。

### 两大成就

1. **效率翻倍** — 通过正交优化（研究团队 + 推理团队协同），测试时扩展曲线左移：思考更少 Token 达到更高性能
2. **公司协同一致** — 整个公司朝同一个"北极星"目标努力

### 架构：垂直 + 水平改进

- **垂直团队**：针对编程、计算机使用、科学研究等特定场景优化
- **水平团队（Yann 的团队）**：整合所有垂直改进 + 指令遵循、函数调用、思考时间控制等通用能力
- 两者可以**正交改进**，不同模型版本中不同团队的改进交替集成

---

## 三、后训练团队：模型最终能力的操盘手

Yann 领导的后训练前沿团队负责三件事：

| 职责 | 说明 |
|------|------|
| **决定训练内容** | 从众多垂直改进中选择什么进入最终训练 |
| **大规模整合** | 在海量 GPU 上运行，将所有改进融合到一起 |
| **水平改进** | 思考时间优化、指令遵循、函数调用、记忆功能等 |

---

## 四、强化学习：从"行不通"到核心引擎

### 历史转折

> "直到两年前，在学术界和研究界中那些不从事强化学习的人，大概率都认为强化学习根本行不通，太难以捉摸了，没法用。"

Yann 本人曾是 RL 怀疑者。ChatGPT 问世时，他认为"不用强化学习也能做出一样的东西"。转折点在于：**当预训练模型积累了足够的世界知识后，RL 突然变得有效了** — 不仅在 LLM 领域，机器人领域也是如此。

### 当前 RL 的两大挑战

1. **基础设施成本** — 需要大规模采样海量回答，极其昂贵
2. **Agent RL 的归因问题** — 在漫长的执行流程（roll out）结束后才知道对错，无法在 Token 层面归因"哪一步做对了"

### GRPO：开源世界的收敛点

> "GRPO 是一种非常简化的方法。在机器学习中，我们一再看到，能够通过算力不断扩大规模的最简单方法，往往最终效果最好。"

- **GRPO**（Group Relative Policy Optimization）— 对同一提示生成多个回答，组内相对奖励归一化
- **PPO** — 训练奖励模型 + 价值模型，限制更新幅度
- **DPO** — 无需奖励模型，直接用"好 vs 差"成对偏好数据优化

## 五、泛化的关键：横向能力而非领域

> "如果你拥有了这种横向能力，你就能泛化；但在很多情况下，我们现在并没有这种横向能力。这就是为什么大语言模型在各个领域都会产生幻觉的原因。"

**核心洞察**：泛化是基于**能力**而非**领域**发生的。

- 数学竞赛 → 编程竞赛：可以泛化（都需要逻辑推理）
- 竞赛 → 真实世界：难以泛化（竞赛定义清晰，真实世界混乱模糊）

**关键的横向能力**：
- 理解定义模糊的任务
- 应对混乱的现实世界
- 知道自己"不知道"
- 信息检索和上下文理解

**负迁移的例子**：显式指令遵循 vs 隐式指令遵循
- 极度擅长显式指令 → 会忠实执行包含错字的命令
- 人类 → 一眼就能看出打错了字

## 六、幻觉的根因：SFT 强迫模型编造

> "SFT 会迫使模型产生幻觉。"

Yann 引用 John Schulman（OpenAI 联合创始人）的观点：

**SFT 的问题**：如果模型不知道某篇论文的存在，但训练数据中标准答案引用了它 → 实际上在**优化模型编造不存在的引用**。

**RL 的优势**：从模型自身采样 → 模型恰好采样出它不知道但正确的答案的概率极低 → 永远不会奖励编造行为。

> "如果你有一个出色的强化学习流程，幻觉发生的频率不应该太高。"

---

## 七、评估：被低估的瓶颈

### 为什么评估越来越难

1. **任务越来越开放** — 从"找 Bug"到"帮我建网站"，最优解不唯一
2. **模型超越人类** — 能真正评估模型的人越来越少
3. **文化问题** — 大家都想提升模型，不愿投入评估

### 模型作为裁判（Model as Judge）

> "更优秀的模型会成为其他模型更好的老师" — 形成自我强化的能力飞轮。

关键洞察：**每次建立评估体系，实际上就是在建立训练数据集的方法** → 评估 → 训练数据 → 模型改进 → 评估过时 → 需要新评估。

---

## 八、未来方向

### 持续学习（Continual Learning）

> "模型在第 0 天往往比新员工更有用，但效用曲线是平的；而人类会持续学习、适应、变得更高产。"

Yann 对持续学习**极其兴奋**：
- 目前只有 Codex memories 等初级方案，远非终局
- 核心难点不在技术，而在合规、权限、隐私
- 三年前以为 OpenAI 六个月就能解决，三年过去了还没做到

### Agent Harness：短期权宜之计

> "如果把现有模型完全冻结，大家开足马力优化 Harness，每个单点领域都能感受到 AGI。"

但现实是模型不会冻结，Harness 会一直处于变动中。

### 初创公司建议

> "真正的瓶颈在'最后一公里'，确保模型能拥有正确的权限、能接入正确的连接器。"

大模型厂商专注底座通用能力 → 初创公司专注垂直领域最后一公里（权限、连接器、合规）→ 这个空间将永远存在。
