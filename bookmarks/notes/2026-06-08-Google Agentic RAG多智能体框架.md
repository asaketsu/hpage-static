# Google Agentic RAG：多智能体迭代检索框架

> 来源：微信公众号 | 2026-06-08
> 原文：https://mp.weixin.qq.com/s/8PdVIubBGWKtMMyCb0pc3g
> 参考：https://research.google/blog/unlocking-dependable-responses-with-gemini-enterprise-agent-platforms-agentic-rag/

## 核心问题

现有 RAG 系统"搜一次、生成一次"，信息找不全就凑合回答或直接说"没找到"。问题不是信息不存在，是系统没有**继续找**的能力。

## 框架架构：5 个角色

| 角色 | 职责 |
|------|------|
| **编排器** | 接收请求，判断是否需要多步完成，分配子任务 |
| **规划智能体** | 规划信息获取路径（如先查财务库、再查项目日志） |
| **查询改写器** | 将原始问题拆成多个可检索的子查询 |
| **搜索扇出智能体** | 将改写后的查询同时发送给多个数据源 |
| **LLM** | 汇总上下文，生成最终答案 |

## 核心创新：充分上下文智能体（Sufficient Context Agent）

位于流水线末端的"质检员"，做三件事：

1. **审查片段**：检查检索到的文本是否包含回答所需内容
2. **草稿验证**：对比原始问题、草稿答案和检索片段，判断信息是否全面可溯源
3. **精确反馈**：不只是说"信息不够"，而是指出**具体缺什么**，生成改进指令

### 迭代流程

```
编排 → 搜索 → 充分性检查 → (不充分→) 改写查询 → 再搜索 → (充分→) 合成答案
```

## 实验结果（FramesQA）

- 数据集：824 查询，2676 份 PDF
- **跨库检索准确率 90.1%**，接近单库水平
- 跨库比单库延迟仅增加 3%

| 方法 | 准确率 |
|------|--------|
| Vanilla RAG | ~56% |
| 单库 Agentic RAG | ~90% |
| 跨库 Agentic RAG | 90.1% |

## 可借鉴要点

1. **充分性检查机制**：回答前先判断信息是否足够，不够就精确描述缺什么再搜索——这个模式可以移植到任何 RAG 系统中
2. **迭代检索而非单次**：将"搜一次"升级为"搜到够为止"的闭环
3. **跨库路由低成本**：规划智能体判断去哪个库找，几乎不增加延迟
4. **可审计可溯源**：每步检索都有反馈日志，答案不是靠模型猜测填补
