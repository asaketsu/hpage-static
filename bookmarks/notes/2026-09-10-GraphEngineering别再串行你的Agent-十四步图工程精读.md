## 零、结论先行

百万浏览的爆文，讲一件事：**你写的多步 agent 几乎都是队列（queue），而工作的形状本来是图（graph）**——"粗看之下，一半的步骤根本没有任何东西需要等待"。

全文 14 步把单文件 agent 改造成"扇出到舰队、自检发现、落在单个 agent 永远装不下的结果上"的图。**它是《MultiAgent已死Multi-Agent-OS万岁》笔记（Anthropic DAG 协作）的操作手册版**——那篇讲为什么，这篇讲怎么干。

**三个最值钱的原则**（原文结语自选）：
1. **砍掉不携带数据的箭头**——"and then"不是依赖
2. **默认 pipeline() 而非 barrier**——"分开"不等于"同步"
3. **对见过的一切去重，而非只对确认的**——否则循环永远不干涸，机器永远付费重发现同样的死胡同

**与既有体系的关系**：这篇是今天方法论三部曲的收官——DAG OS（为什么）→ Meshy 数据驱动（训练系统层同构）→ 本文（Agent 编排层的具体手法）。第二章做合流分析。

## 一、十四步忠实还原

### 第 1 步：节点与边——"and then"不是依赖
- **节点 = 工作单元**（一个 agent、一个有界任务、一进一出）；**边 = 依赖**（这个节点的输出喂那个节点的输入）——全部定义就这些
- 几乎所有人犯的错：把"然后"当边。"总结这个文件**然后**告诉我天气"——天气不消费总结，两个无关节点被线性脚本毫无理由地链在一起
- **判据问题**：对每个"and then"问——下一步真的读上一步的输出吗？不读就没有边，等待纯属浪费

### 第 2 步：线性脚本已是退化图
- "A→B→C→D"就是画了最差的图：单链无分支，每节点一进一出。能跑，但慢且脆——链没有冗余，C 卡死则 D 永不发生，A 的产出堵在上游
- 第一技能：**重画链条**——走一遍每个箭头问第 1 步的问题，会发现两三个箭头根本不携带数据，只因"你恰好按那个顺序打字"。砍掉它们，链条向侧方塌缩成一片可并行的独立节点

### 第 3 步：每个节点有契约
- 无法推理的节点无法并行化。契约 = **有界输入、有界输出、恰好一个任务**
- 输入显式传入，绝不从共享上下文窗口"顺手拿"；输出是定义好的形状（最好带 schema 校验）——Claude 的 agent() 带 JSON schema 时，子代理被强制返回校验过的结构化数据，**校验发生在工具调用层，不匹配自动重试**而不是给你一段要"解析并祈祷"的自由文本

### 第 4 步：边也是数据契约
- 边不是"B 在 A 后"，是**关于什么跨过的承诺**：A 产这个形状，B 造来消费这个形状。**按数据命名边而不是按顺序**——立刻能看出边是否真实（数据真的跨过吗），且形状保持就能换掉任意一端的节点
- **边的实现是纯 JS**（flatten/dedupe/filter 就是代码）——**"人们烧模型 token 的巨量东西其实只是边，而边是免费的。把 agent 留给判断，别用于管道。每个边都是 agent 的图 = 给自己的接线付租金"**

### 第 5 步：parallel() 扇出
- N 个独立节点（N 个信源/文件/路由）不要串行——parallel() 收一个 thunk 数组，每 thunk 一个子代理并发跑完返回结果数组
- 两个健壮性细节：**parallel() 是 barrier**（等全部完成才返回，下一阶段见完整集）；**抛错的 thunk 解析为 null 而不是拖垮整批**——出来时永远 `.filter(Boolean)`
- 并发按核数封顶、超出排队——丢一百个 thunk 也会全部完成，只是分批
- **关键架构红利**：扇出活在 Claude 写的代码里而非模型对话里——**Claude 自己的上下文从不同时持有九个信源**，每个子代理带自己的上下文，只有最终答案回来。编排层零 token，因为脚本不是对话

### 第 6 步：barrier 汇聚——只在必须时
- fan in 是边汇聚的节点：一个 agent/一段代码同时看到全部上游结果，做真正需要全集的事（跨源去重/按影响排名/全空早退）
- **保持图快的规则**：只在阶段真正需要全部前置结果时用 barrier。仅 flatten 列表不是 barrier 是边——内联做
- 嗅探测试："parallel → transform → parallel 且中间 transform 无跨项依赖 → 该用 pipeline 跳过 barrier"

### 第 7 步：菱形——split/work/merge
- 扇出+扇入 = **一切严肃 agent 图的主力拓扑**：市场扫描/依赖审计/代码评审/研究报告都是这个形状（换信源换 prompt 同骨架复用）
- **值得背下来的规范形**：fan out（收广度）→ reduce（纯代码压缩）→ synthesize（末 agent 写答案）
- "看到菱形后，你不再问'怎么让 agent 多做几步'，开始问'**分裂点在哪、汇合点在哪**'——第二个问题才 scale"

### 第 8 步：运行时条件路由
- router 节点检查结果决定哪条下游路径触发（分类工单→分派处理器；diff 小→快审，diff 大→全面审计）
- 工作流里就是**对节点校验输出的 JS if/switch**——**"确定性在这里从限制变成特性：分类可以是 Claude 驱动的，路由是 Claude 写的代码，同样的分类永远同样地跑。节点拿到 Claude 的判断，边上拿到脚本的可靠。不存在'Claude 今天决定跳过审计'的涌现意外——跳过得写进图里，而图里没有"**

### 第 9 步：边上放验证器
- **图的真正杠杆不是更多 agent，是能包住它们产生置信度的结构**。验证器节点坐在边上，在结果被允许流向下游前，唯一工作是**试图杀死这个发现**——活下来才通过
- 三个模式：**对抗验证**（每发现 N 个独立怀疑者试图反驳，多数存活才保留）/ **视角多元验证**（每个验证器一个透镜：正确性/安全性/可复现——多样性抓到 N 个相同检查抓不到的失效）/ **评审团**（N 个不同角度生成，并行评委打分，赢者综合+嫁接落选者最佳片段）
- 实证：Bun 运行时移植就靠循环内建的对抗性代码审查

### 第 10 步：节点隔离，失败局部化
- 链中失败级联；图中失败应困在节点内。parallel 抛错→null 已是包含，`.filter(Boolean)` 就是围堵——**每个 fan in 都设计成容忍缺失输入而非假设全集**
- 更隐蔽的失败：节点互踩（并行写文件冲突）→ **git worktree 隔离**，各自沙箱干完干净合并。"只在该拓扑真需要时才用——特定拓扑的安全带，不是每次运行的默认税"

### 第 11 步：加环，但必须收敛
- 未知规模的发现任务（找到一个 bug 揭出三个）需要**环**——回到早前节点的受控边。危险显然：不收敛的环 = 无限循环刷 agent 直到预算烧光
- **收敛模式 = loop until dry**：持续生成 finder 直到 **K 连续轮无新发现**才停
- **几乎所有人第一次都搞错的细节**：去重对象——**对"见过的一切"去重，不是只对"确认的"**。否则被拒的发现每轮都回来，循环永不干涸，你造了台永远付费重发现同样死胡同的机器

### 第 12 步：节点间分层模型
- 图让这事在单 agent 里永远看不清的地方变得显然：**有界重复节点（抽取/分类）跑便宜模型，判断节点（综合/裁决）花贵 token**
- 工作流里子代理默认继承会话模型——**不覆盖则整个大跑全按会话档计费**。单次 agent() 的 model 选项只路由那个节点
- "大跑前查 /model，扇出的重复节点降档、合并节点保持顶档——**不动图的形状就把吞 token 的图变成经济的图**"

### 第 13 步：拓扑就是成本与延迟
- 图的形状不是装饰，是墙钟时间的最大杠杆。**所有人都绊倒的选择：parallel() vs pipeline()**
- parallel barrier = 全部等最慢节点；**pipeline() = 每项独立流过所有阶段无 barrier**——A 已在第 3 阶段时 B 还在第 1 阶段，快的先完成不等慢的
- **默认 pipeline()**。barrier 只在阶段真正需要全部前置结果时用（跨集去重/总量早退/一条发现对比所有其他的 prompt）。"'代码更干净''阶段感分开'不是理由。**barrier 延迟是真实、可测、浪费的时间。分开≠同步**"

### 第 14 步：让 Claude 画图
- 最后一步：无法预划的任务别手画图。dynamic workflows 里描述目标，Claude 自己写编排脚本：分解任务、选扇出、生成舰队、综合结果——**为这一次运行量身定制的图，而非你希望合身的固定图**
- 三个入口：prompt 里说 workflow；跑保存的（/deep-research 就是生产中的真图：scope→并行搜→fetch→对抗验证→synthesize，正是本文骨架）；**开 ultracode 每个实质任务自动规划 workflow，跑得好按 s 存进 .claude/workflows/——版本控制、按名重跑、clone 仓库的人都能启动**

### 六个本周值得建的图
安全扫描（每路由文件一个子代理+验证器）/ 引用报告（/deep-research）/ 模块移植（文件扇出+测试门+失败回环+对抗评审）/ diff 对抗评审（按大小路由：小→快审，大→多透镜并行审计+评审团）/ 生态定时扫描（存一次永远重跑）/ 未知规模发现（并行 finder+对全部见过去重+验证幸存者+两轮无新即停）

### 为什么这真的重要
- "你 agent 的天花板几乎从不是模型，是**你交给它的工作形状**"
- 链迫使一个上下文装一切、一个失败停一切、每个快步等最慢者；图把上下文摊到舰队、失败困在节点、给你能包置信度的结构（节点 schema、边验证器、每次同样跑的路由）
- **编排层是代码——十八个 agent 之间的协调零模型 token，因为脚本不是对话**
- 结语："A prompter asks a question. An architect draws a graph.（提问者问问题。架构师画图。）"

## 二、方法论合流：四篇笔记其实是同一篇

本文与今天系列笔记构成完整方法论闭环：

| 笔记 | 层次 | 核心命题 | 本文对应 |
|------|------|---------|---------|
| MultiAgent已死/DAG OS | 为什么 | 自由协作的多 agent 死了，DAG+验证器活了 | 第 7/9 步（菱形+边上验证器）= DAG OS 的实现细节 |
| Meshy 数据驱动 | 训练系统层 | 控制流由数据就绪驱动，编排进程消失 | 第 4 步（边=数据契约）+ 第 8 步（路由=对校验输出的代码分支）= 数据驱动的 Agent 版 |
| LLM-as-Judge 八模式 | 评估层 | 判官参与控制流 | 第 9 步三模式 = 判官模式 3/5/8 的图化落地（对抗验证=成对比较；评审团=多判官；边验证=判官进循环） |
| patent-docket 状态机 | 长流程治理 | phase 机校验+路径交接+轮次上限 | 第 11 步（环必须收敛+K 轮无新即停）= max_rounds=3 的同构；第 3 步节点契约 = 路径交接合同 |

**合流结论**：四个层次（协作架构/训练基建/评估门禁/流程治理）在 2026 年收敛到同一组原语——**契约（schema）、数据驱动（边）、验证（杀发现的边）、收敛上限（K 轮/3 轮）、免费编排（代码不是对话）**。这不是巧合，是 agent 工程的"结构力学"成型。

**可以直说的三条体系映射**：
1. **笔记链已是半个菱形**：抓取（扇出）→ 分析（单 agent）→ 发布（串行）。按第 13 步审视：发布链 convert→scan→sync 是 pipeline 而非 barrier（各自独立流过），当前实现恰好正确；但抓取多源时若串行 web_search 则违背第 5 步——本笔记的抓取已是并行调用 ✅
2. **L1 门禁 = 第 9 步的确定性版**：G1-G6 六项检查就是"试图杀死发现的验证器"，只是全用代码（模式 7）。对抗验证（三怀疑者多数决）是 L2 候选
3. **delegate_task 的改进方向**（与 DAG OS 笔记 P0-2 呼应）：当前 sub-agent 结果无独立验证——第 9 步的"对抗验证"给出了具体实现：每个关键产出 N 个独立怀疑者试图反驳。这是 verifier 角色的落地手法

## 三、批判性审视

1. **Claude Code 依赖**：14 步的 10 步绑在 Claude Code dynamic workflows 上（parallel()/pipeline()/worktree/.claude/workflows/）。思想普适，**实现是 Anthropic 生态的**——移植到 Hermes 需自己实现 parallel 池与 schema 校验层（delegate_task 的 tasks 数组已是雏形）
2. **作者背景存疑但内容自证**：bio 是"crypto//ai//polymarket, trading data not emotions"——非系统工程师人设。但全文技术细节扎实（Bun 移植/ultracode/s 键保存都是真实特性），百万浏览+991 收藏的社区背书。**爆文里少见的"细节可验证"**
3. **去重细节是全文最被低估的贡献**："对见过的去重而非确认的"——这条对错误案例库（error-case-library）同样成立：**去重应按"见过的问题"而非"修过的问题"**，否则同一死胡同的变体永远被当新案例
4. **无成本数字**：零 token 编排/便宜模型节点都定性正确，但全文无量化（一个 barrier 换 pipeline 实测省多少、对抗验证多花多少）——落地时要自测
5. 第 14 步"让 Claude 画图"与"人思考在前"（姜老师笔记）存在张力：动态画图适合探索性任务，**固化流程（笔记链）仍应人定拓扑**——两种模式按任务类型分治，不是替代关系
