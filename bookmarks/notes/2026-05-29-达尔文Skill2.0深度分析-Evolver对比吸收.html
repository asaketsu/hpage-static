达尔文 Skill 2.0 深度分析 — 与 Hermes Evolver 对比吸收

一、Darwin Skill 2.0 是什么

花叔（@AlchainHust）开源的 Agent Skill 自动优化系统，核心灵感来自 Karpathy 的 autoresearch——把模型训练的实验循环移植到 Skill 质量优化。

一句话定义：对 SKILL.md 做「评估→改进→实测→保留或回滚」的闭环优化，只保留分数上升的改动。

1.1 五阶段循环

Phase 0: 初始化（确认范围 + git 分支 + 测试 prompt 设计）
Phase 1: 基线评估（9 维 rubric 评分 + runtime 适配性审查）
Phase 2: 迭代改进（最多 N 轮 hill-climbing，每轮单文件编辑）
Phase 3: 实测验证（子 agent 带测试 prompt 跑一遍，对比 baseline）
Phase 4: Keep or Revert（分数上升→git commit；下降→回滚）

1.2 9 维评分 Rubric（总分 100）

# 维度 权重 类型
1 Frontmatter 质量 7 结构
2 工作流清晰度 12 结构
3 失败模式编码 12 结构
4 检查点设计 6 结构
5 可执行具体性 17 结构
6 资源整合度 4 结构
7 整体架构 12 效果
8 实测表现 23 效果
9 反例与黑名单 6 Meta-skill

关键设计：
- 结构 59 分 + 效果 35 分 + Meta 6 分，实测表现（dim8）单一维度权重最高 23 分
- 基于 Microsoft Research SkillLens（arXiv 2605.23899）的实证：LLM-as-judge 准确率仅 46.4%，加入 meta-skill 维度后升到 73.8%
- 融合 SkillOpt（arXiv 2605.23904）的 validation-gated 设计

1.3 五大设计原则

# 原则 含义
01 单一可编辑资产 每次只改一个 SKILL.md，控制变量
02 双重评估 静态结构分 + 动态实测分
03 棘轮机制 分数只升不降，回滚一切退步
04 独立评分 子 agent 评分，避免「自己改自己评」
05 人在回路 每个 skill 优化完暂停等用户确认

1.4 学术根基

  • SkillLens（arXiv 2605.23899）：Microsoft Research，发现 LLM-as-judge 评估 skill 质量准确率仅 46.4%，加入 meta-skill 后提升到 73.8%
  • SkillOpt（arXiv 2605.23904）：validation-gated 验证机制
  • autoresearch（Karpathy）：自主实验循环 → ratchet 只进不退

二、Hermes Evolver 现状

我们的 Evolver 是 7 阶段自进化引擎，v2026-05-29 已融合 Darwin Skill 2.0 的部分概念：

1. COLLECT → 收集显式错误信号
1.5. DISCOVERY → 主动发现隐式改进机会
2. IDENTIFY → 识别重复模式
3. GENERATE → 生成修复协议（SkillOpt 有界编辑）
4. VALIDATE → 三问门禁验证
5. TEST → 改进后自动执行验证
6. REVERT → 自动回滚机制
7. RECORD → 追踪进化历史

已有融合：DISCOVERY 阶段、TEST 阶段、REVERT 阶段已在 05-29 补丁中加入，但实现深度与 Darwin 原版有差距。

三、逐维度对比分析

3.1 评估体系

维度 Darwin Skill 2.0 Hermes Evolver 差距
评分框架 9 维 rubric，权重固定，总分 100 PRM 多数投票 + 五维度评分 + confidence 评分 ❌ Evolver 缺乏统一 rubric，PRM 评分维度与 Skill 质量评估不在同一层面
实测验证 dim8 权重 23%，必须跑测试 prompt 对比 baseline TEST 阶段仅做 dry-run + 24h 回归 ❌ Evolver 无 formal baseline 对比，dry-run 验证力度不足
独立评分 子 agent 盲评 执行/评判分离原则 ⚠️ Evolver 有原则但无强制执行机制
LLM-judge 偏差 SkillLens 实证处理（46.4%→73.8%） 未专门处理 ❌ 盲区：PRM 评分可能存在同向偏差

判断：Darwin 在评估科学性上显著领先。其 9 维 rubric 是目前 Skill 质量评估领域最系统的方案，有论文实证支撑。Evolver 的 PRM 更偏「会话质量评估」而非「Skill 质量评估」。

3.2 进化驱动

维度 Darwin Skill 2.0 Hermes Evolver 差距
触发信号 用户主动请求（"优化 skill"） 错误信号 + 用户纠正 + 主动发现 ✅ Evolver 领先：多源触发，不依赖人工启动
信号范围 Skill 文件本身 错误日志 + 反馈 + 记忆 + cron 产出 + 跨 skill 重复 ✅ Evolver 领先：信号覆盖远超 Darwin
DISCOVERY 无主动发现 有主动扫描（skill 使用频率、cron 质量趋势、pitfall 积累率） ✅ Evolver 独有
经验闭环 无 DECIDE→REVIEW→REFLECT→RETRIEVE 四步闭环 ✅ Evolver 独有

判断：Evolver 在进化驱动和信号广度上全面领先。Darwin 本质是「被动优化工具」——需要人触发；Evolver 是「主动自进化引擎」。

3.3 改进执行

维度 Darwin Skill 2.0 Hermes Evolver 差距
编辑范围 单个 SKILL.md Skill + Rule + Script + Memory ✅ Evolver 覆盖更广
编辑控制 每轮只改一个文件 有界编辑（ADD/DELETE/REPLACE，单次≤3 个） ⚠️ 各有侧重：Darwin 更严格单文件，Evolver 允许跨类型但控制数量
验证门禁 9 维分数严格上升 三问验证（行为改变？能 grep？谁验证？） ⚠️ Darwin 门禁更客观（数字驱动），Evolver 更偏逻辑验证
Rejected Buffer 无（未通过直接丢弃） 有（retry_count<3 可重试） ✅ Evolver 领先：不浪费被拒绝的编辑

3.4 回滚机制

维度 Darwin Skill 2.0 Hermes Evolver 差距
机制 git ratchet（git commit + 回滚） applied-edits.jsonl 快照 ⚠️ Darwin 的 git 方案更成熟可靠
触发 分数下降 TEST 失败 + 48h 内质量下降 + 用户反馈 ✅ Evolver 触发条件更丰富
防死循环 棘轮保证分数只升 同一编辑回滚≥2 次→abandoned ⚠️ 各有策略

3.5 架构哲学差异

维度 Darwin Skill 2.0 Hermes Evolver
定位 Skill 质量优化器 系统级自进化引擎
类比 模型训练的 hill-climbing 生物进化的自然选择
优化目标 SKILL.md 的 9 维分数 错误率↓ + 经验内化率↑ + 落实率↑
依赖 独立工具，任何 SKILL.md 生态可用 深度绑定 Hermes 架构
人介入 每个 skill 暂停等确认 仅高风险编辑需确认
生态兼容 50+ runtime（Claude Code/Codex/Cursor/OpenClaw/Hermes 等） Hermes 专用

四、可吸收的关键改进

P0 — 立即可吸收（性价比高，改动可控）

# 改进 来源 落地方式 预期效果
1 9 维 rubric 适配 Darwin dim1-9 提炼为 Evolver 的 Skill 质量评估模板，嵌入 VALIDATE 阶段 评估从「逻辑判断」升级为「量化打分」
2 测试 prompt baseline 对比 Darwin dim8 TEST 阶段增加：改进前后用相同 prompt 跑一遍，输出质量对比 消除 dry-run 验证的盲区
3 Runtime 适配性检查 Darwin gate 项 VALIDATE 阶段增加 grep 扫描 runtime-specific 硬编码 防止 skill 在不同 agent 生态中失效

P1 — 短期吸收（1-2 周内）

# 改进 来源 落地方式 预期效果
4 LLM-judge 偏差校准 SkillLens 论文 PRM 评分增加 meta-skill 维度（失败模式编码 + 反例黑名单），降低乐观偏差 PRM 评分可信度从 ~46% 提升到 ~74%（论文实证）
5 Git ratchet 回滚 Darwin 棘轮 用 git 管理 skill 修改（每次 GENERATE 应用前 git stash + commit），替代 applied-edits.jsonl 回滚从「字符串快照」升级为「完整版本控制」
6 degradation 自动检测 Darwin controlled study 对 evolver 修改的 skill，自动构造 4 类 degradation 测试 防止「改了 A 坏了 B」的隐性退化

P2 — 长期吸收（需架构调整）

# 改进 来源 落地方式 预期效果
7 子 agent 独立盲评 Darwin 原则 04 GENERATE 后用独立 subagent（不同模型）做盲评 消除自己改自己评的系统性偏差
8 diminishing returns 自动 break Darwin Phase 2 连续 2 轮改进分数差 < 3 分→自动停止该 skill 优化 避免在边际收益递减的 skill 上浪费 token

五、Evolver 独有优势（Darwin 不具备）

# 能力 说明
1 主动 DISCOVERY 扫描 skill 使用频率、cron 质量趋势、pitfall 积累率、用户隐性信号、跨 skill 重复
2 经验闭环 DECIDE→REVIEW→REFLECT→RETRIEVE，从错误中学习的四步闭环
3 辩证法记忆融合 黑格尔正-反-合，矛盾信息不简单追加而是融合
4 防复发三级注入 编译期 pitfalls + 运行期 pre-hook + 验证期 post-hook
5 跨类型基因 Rule + Skill + Script + Patch 四种输出类型
6 Auto-skill 联动 同一错误≥3 次自动触发 skill 创建
7 Rejected-Edit Buffer 被拒绝的编辑不丢弃，retry_count<3 可重试

六、结论

一句话：Darwin Skill 2.0 在「Skill 质量评估的科学性」上领先我们一个代际，但 Evolver 在「进化驱动的广度与主动性」上领先 Darwin。

核心洞察：两个系统是互补而非竞争关系。

  • Darwin 解决的问题：「这个 Skill 写得好不好？能不能更好？」 — 质量评估专家
  • Evolver 解决的问题：「系统哪里有问题？怎么持续进化？」 — 全身免疫系统

最佳策略：将 Darwin 的 9 维 rubric + baseline 对比 + git ratchet 吸收为 Evolver 的 VALIDATE/TEST 子模块，而非替换 Evolver 的进化管线。让 Evolver 在进化时使用 Darwin 的评分标准，但保持 Evolver 的主动发现和经验闭环能力。

风险提示：
1. 9 维 rubric 100 分制评分在 Hermes cron 环境中可能因 token 限制无法完整执行 → 需要简化版
2. git ratchet 依赖 git 操作，Hermes skill 目录已有 git 管理，可行性高
3. 子 agent 盲评需要 auxiliary provider（zai/glm-5.1 并发=1），需用其他 provider
