为什么 KV Cache 只存 K 和 V、从不存 Q？

1. 原推全文（逐字翻译照录）

问题：为什么 KV cache 存 K 和 V 向量，却从不存 Q？

LLM 是自回归的：每个 token 由它之前的所有 token 逐个预测出来。这一性质在模型内部有直接后果——

一次对 n 个 token 的前向传播产生 n 个隐状态，但只有最后一个被投影到 logits 并用于生成下一个 token。

要理解 KV cache 为什么只存 K/V，必须回溯最后一个隐状态是如何产生的。用 10-token prompt 走一遍：

1) Prefill（预填充）：全部 10 个 token 并行过一遍模型（因果掩码）——整个 prompt 是已知的。每一层、每个位置产生 q/k/v 三个向量，每个位置对所有前置位置做 attention。这一步计算密集，TTFT 主要就是 prefill。

2) 生成第 11 个 token：只需要第 10 个位置的隐状态 → 投影到 vocab 维 → logits → softmax 采样出 token 11。

3) 回溯隐状态：最后隐状态是 FFN 输出的最后一行；FFN 是逐位置（position-wise）的，所以该行只来自 attention 输出的最后一行。

4) Attention 矩阵：10-token prompt 的 QKᵀ 是 10×10 矩阵。第 i 行 = Qᵢ 与所有 K 的点积。第 10 行因此只含 Q₁₀：Q₁₀·K₁, Q₁₀·K₂, …, Q₁₀·K₁₀。Q₁~Q₉ 只属于第 1~9 行——而那些行的隐状态已被丢弃（从不需要）。attention 最后一行经 softmax 后乘以全部 V₁~V₁₀ 得到输出最后一行。

结论：最后隐状态只依赖三样东西——Q₁₀、全部 Key、全部 Value。

5) 生成 token 12：token 11 拼入后，需要第 11 行：Q₁₁ 对 K₁~K₁₁，乘 V₁~V₁₁。关键是：K₁~K₁₁ 和 V₁~V₁₁ 与 prefill+首 token 产生的逐位相同——因果掩码下，一个 token 的 K/V 只依赖它自己和之前的 token，永不依赖之后的内容，所以追加 token 11 不可能改变位置 3 的任何东西。

6) 缓存状态：每个解码步只需保留所有 K/V，只为新位置计算 Q、K、V。每步用一个 query 向量，用完即弃，永不复用——所以 Q 从不进缓存。

推文配图（四层缓存总览，视觉识别还原）：

KV CACHE       [K|V][K|V][K|V] →  ONE REQUEST      （请求内，精确匹配）
PREFIX CACHE   绿块 绿块 绿块  →  SHARED KV        （跨请求共享前缀）
PROMPT CACHE   紫块 紫块 紫块 + 文档($) → BILLED KV （服务商计费层）
SEMANTIC CACHE 查询💬 → 🔍 → ✓答案  ⚠️ FUZZY MATCH （跳过模型，模糊匹配）
──────────────────────────────
EXACT MATCH（前三层） vs FUZZY MATCH（第四层，有风险）

推文结尾：KV cache 只是 LLM serving 四层缓存之一，另外三层是服务端 prefix cache、按量计费的 prompt cache、完全跳过模型的 semantic cache——详见其 X Article。

2. 数学本质（领域补全，一张表说清）

量 依赖范围 生成后是否复用 缓存价值
Qᵢ 仅位置 i 的当前输入 当步算完 attention 即弃 ❌ 无
Kᵢ 位置 i 及之前所有 token（因果掩码） 之后每一步都要与最新 Q 点积 ✅ 必须
Vᵢ 同 Kᵢ 之后每一步 softmax 加权平均都要用 ✅ 必须

因果掩码是根本原因：K/V 是"只增不改"的累积量（append-only），Q 是"一次性"的消耗品。缓存的定义就是"未来还会用的东西"——Q 不满足定义。

复杂度账（L 层、d 维、n 个已生成 token）：
- 无缓存 decode：每步 O(n·d²) 重算全部历史 → 总 O(n²d²)
- 有缓存 decode：每步只算新位置 O(d²) + attention O(n·d) → 显存换计算的教科书案例
- 这正是 图解大语言模型部署 显存公式中 KV Cache 项的由来：2 × L × n × d × precision

3. 四层缓存体系对照（原文框架 + 补全）

层 作用域 匹配方式 生命周期 典型实现
1. KV cache 单请求内 精确（token 级） 请求结束即释放 vLLM PagedAttention、SGLang RadixAttention
2. Prefix cache 跨请求 精确（前缀哈希） 分钟级驻留 系统提示/多轮对话公共前缀复用
3. Prompt cache 服务商计费 精确 按策略 OpenAI/Anthropic 输入缓存折扣（缓存命中 token 计费 1/10 价）
4. Semantic cache 跨用户跨问题 模糊（语义相似度） 小时~天 GPTCache 等；⚠️ 相似≠相同，有答错风险

层级关系：1→2→3 是"精确匹配的扩大作用域"，4 是质变——不再匹配 token 而是匹配意图，收益最大（完全跳过模型）风险也最大（fuzzy match ⚠️）。

4. 值得记的三个点

  1. 面试答案的一句话版：因果掩码下 K/V 随序列只增不改（未来每步复用），Q 只在当步出现后即被丢弃——缓存"未来要用的"，所以只有 KV
  2. 推文的推导路径本身值得学：不自说自话，从"最后一个隐状态怎么来"回溯到 attention 矩阵行结构，每步都贴着矩阵形状走（10×10 的第 10 行只含 Q₁₀）——这是能写进教材的讲法
  3. 四层缓存框架的工程价值：把"KV cache 显存爆了"“为什么多轮对话越聊越快”“prompt cache 折扣怎么来的”"semantic cache 什么时候不能用"统一进一张图
