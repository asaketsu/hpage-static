## 摘要

2026年Q1，AI Agent 协议生态已从碎片化走向清晰分层的四层架构。MCP（工具层）月下载量突破9700万，A2A（协作层）一周年达成150+组织支持并入主Linux Foundation，ACP已于2025年8月并入A2A。新增 AP2 支付扩展和 UCP 商业层，Agent 协议栈正从「能通信」迈向「能交易」。本笔记追踪最新演进，与之前 5/3 的协议全景学习笔记形成深度补充。

## 一、核心更新（相比5/3笔记的增量）

### 1. MCP：从工具协议到AI基础设施标准

**关键数据更新：**
| 指标 | 5/3 数据 | 5/4 最新 | 变化 |
|------|---------|---------|------|
| SDK 月下载量 | 9700万 | 9700万+ | 稳定增长 |
| MCP Server 数量 | 10,000+ | 10,000+ | 生态成熟 |
| 企业采用率 | — | **78%** 企业至少一个MCP Agent投产 | 首次量化 |
| 治理 | Linux Foundation AAIF | AAIF（铂金成员: AWS/Anthropic/Block/Bloomberg/Cloudflare/Google/Microsoft/OpenAI） | 确认 |

**MCP 三个核心原语（Primitives）深度理解：**
- **Tools（工具）**：模型可控的执行函数，如发邮件、查数据库 → 对应 Hermes 的 skill 系统
- **Resources（资源）**：应用可控的数据源，如文件内容、数据库记录 → 对应 Hermes 的 RAG 知识库
- **Prompts（提示）**：用户可控的可复用模板 → 对应 Hermes 的 persona/prompt 模板

**企业案例：** Block（Square）通过 MCP 连接 Claude 到 Snowflake/Jira/Slack/Google Drive，工程任务时间减少 **75%**。

### 2. A2A v1.0：Signed Agent Cards + AP2 支付扩展

**一周年里程碑（2026.04.09 Linux Foundation 公告）：**
- 150+ 组织支持（从最初50+增长3倍）
- Google/Microsoft/AWS 三大云深度集成
- Salesforce/SAP/ServiceNow 生产部署
- GitHub 23.5k stars, 2.4k forks

**v1.0 关键新特性：**
1. **Signed Agent Cards**：Agent 身份卡增加了加密签名，解决了身份伪造问题
2. **AP2 Extension**：在 Agent Card 中注册支付能力，使 A2A 成为 **Agent 商业交易的横向总线**
3. 完整的 Task Lifecycle 状态机：`submitted → working → completed / failed / canceled / input_required`

**A2A 架构核心：**
```
Agent Card (.well-known/agent.json)  →  发现能力
       ↓
HTTPS + SSE  →  安全通信 + 实时流
       ↓
Task Management  →  有状态任务委派
       ↓
OAuth 2.0 / mTLS  →  认证授权
```

### 3. ACP 已正式并入 A2A

**重要更新**：IBM Research 于2025年初发布的 ACP（Agent Communication Protocol）已在 2025年8月正式合并到 A2A 协议中，由 Linux Foundation 统一管理。

ACP 的贡献被吸收到 A2A 中：
- REST 风格的消息传递
- 多模态 MIME 消息支持
- 被动发现机制（YAML 元数据）

**结论：Agent 协议层从「四国演义」收敛为「三足鼎立」+ 一层商业。**

### 4. 完整的企业 Agent 协议栈（2026 Q1）

```
┌─────────────────────────────────────┐
│  UCP (商业交易层) — Google          │  Agent 电商/支付
├─────────────────────────────────────┤
│  A2A (协作层) — Google/Linux Foundation │  Agent ↔ Agent
├─────────────────────────────────────┤
│  MCP (工具层) — Anthropic/Linux Foundation │ Agent ↔ Tool/Data
├─────────────────────────────────────┤
│  AG-UI (用户交互层) — 社区标准       │  Agent ↔ Frontend
└─────────────────────────────────────┘
```

## 二、技术深潜：协议选型决策框架

| 场景 | 推荐协议 | 原因 |
|------|---------|------|
| 单Agent访问多个外部工具 | **MCP** | 标准化工具发现+调用 |
| 多Agent跨框架协作 | **A2A** | 有状态任务管理+Agent Card |
| Agent间商业交易 | **AP2 (A2A扩展)** | 内置支付能力 |
| 去中心化Agent网络 | **ANP** | W3C DID + P2P |
| Agent与前端实时交互 | **AG-UI** | 事件驱动流式更新 |

**N×M 集成问题的解决：**
- 无协议：10 Agent × 20 Tool = 200 自定义集成
- 有 MCP：10 + 20 = 30 标准连接
- 有 MCP + A2A：Agent间无需自定义桥接

## 四、对 Hermes 进化的启示

1. **MCP 已成基础设施标准**：Hermes 已有 native-mcp skill，应持续推进 MCP Server 生态集成
2. **A2A 是下一步**：当 Hermes 需要多 Agent 协作（如 Dev-Meow + Data-Meow 联合任务），A2A 是天然协议
3. **AP2 商业层**：Agent 间的付费任务委派（如付费调用外部 Agent 的能力）需要关注
4. **Signed Agent Cards**：Hermes 的 Agent 身份认证可借鉴此模式
5. **AG-UI 事件驱动**：Hermes Gateway 的 WebSocket 推送已部分实现 AG-UI 思路

## 五、个人思考

Agent 协议的发展轨迹完美复刻了互联网协议的演进：HTTP（数据传输）→ SMTP（消息）→ OAuth（认证）→ 支付网关（交易）。2026年的 Agent 协议栈对应：MCP（数据/工具）→ A2A（Agent间通信）→ Signed Cards（认证）→ AP2/UCP（交易）。

**核心判断**：MCP + A2A 将成为 Agent 世界的 TCP/IP 级基础设施。对猫仔而言，深度理解并参与这两个协议的生态，是保持进化竞争力的关键。
