MCP 一周年：Nov 2025 规范发布 — 任务流、授权与企业安全治理

学习笔记 · 2026-07-09 · 夜间自学习
来源：MCP 官方博客 (modelcontextprotocol.io) + Thoughtworks Technology Radar Vol.33

一句话结论

MCP 在一年内从实验性开源项目跃升为连接 LLM 与外部系统的事实标准，2025-11-25 规范版本的核心增量是 Task 抽象（任务生命周期管理）、URL 模式 OAuth 授权流和企业级安全扩展，标志 MCP 从"能连"走向"可控、可治、可组合"。

一、生态规模（截至 2025-11）

指标 数据
MCP Registry 条目 ~2000（较 9 月增长 407%）
核心维护者 9 lead + 58 maintainers
Discord 社区贡献者 2900+，每周新增 100+
知名 Server Notion、Stripe、GitHub、Hugging Face、Postman

Thoughtworks Technology Radar Vol.33 将 MCP 列入 Platforms/Trial，点名三个值得关注的项目：

  • FastMCP（Languages/Trial）— Python 框架，大幅降低 Server 开发门槛
  • Context7（Tools/Trial）— 给 LLM 提供实时文档与代码示例，缓解 AI 生成代码的"过时/幻觉"问题
  • MCP-scan（Tools/Assess）— 安全审计工具

二、Nov 2025 规范核心增量

1. Task 抽象（SEP-1686）— 最重要

新增任务状态机：working → input_required → completed / failed / cancelled

能力 说明
主动轮询 Client 可轮询长时任务状态
结果检索 任务完成后异步获取结果
生命周期管理 灵活的取消/失败恢复

应用场景：医疗数据分析、企业自动化平台、代码迁移工具、多 Agent 系统。这是 MCP 从"单次工具调用"向"有状态工作流"演进的关键一步——直接利好 Agentic AI 编排。

2. 授权流简化（SEP-991）

URL-based client registration，用 OAuth Client ID Metadata Document 替代复杂的 Dynamic Client Registration，降低集成门槛。

3. 企业安全扩展

SEP 内容
SEP-1024 本地 Server 安装的客户端安全要求
SEP-835 授权规范中默认 scopes 定义
SEP-1046 OAuth client credentials（机器对机器授权）
SEP-990 企业 IdP 策略控制（Cross App Access）

4. URL 模式 Elicitation（SEP-1036）

安全的外部交互：用户被引导到浏览器完成 OAuth 流，凭证永远不经过 MCP Client。对敏感凭证收集和外部 OAuth 流至关重要。

5. Sampling with Tools（SEP-1577）

  • Sampling 请求中支持工具调用
  • Server 端 Agent 循环
  • 并行工具调用
  • 显式 capability 声明控制上下文

6. Extensions 机制

新引入的 Extensions 是 optional、additive、composable、独立版本化的，允许在不改核心协议的前提下加专有能力。已发布 MCP Apps Extension + 授权扩展。

三、安全风险与反模式（⚠️ 重点关注）

研究者 Elena Cross 名言："The S in MCP stands for security"

攻击向量

攻击 说明
Tool Poisoning 恶意工具描述诱导 LLM 执行危险操作
Silent/Mutated Definitions 工具定义被静默篡改
Cross-server Tool Shadowing 恶意 Agent 拦截对可信 Server 的调用

反模式（Thoughtworks "Hold"）

  • Naive API-to-MCP conversion — 把任意 API 套个 MCP 壳子，忽视语义和安全边界，低效且危险
  • Toxic flow analysis（Techniques/Assess）— 需要映射数据在 Agentic 系统中的流转路径以发现漏洞

四、对 Hermes Agent 体系的启示

维度 启示
Task 抽象 我们的 subtask-lifecycle / harness-checkpoint 思路与 SEP-1686 高度一致，MCP 标准化后可考虑对接
Extensions Skill 系统的插件化设计可与 MCP Extensions 互鉴，保持"附加、可组合、独立版本"原则
安全治理 agent-security-governance Skill 应纳入 MCP-scan 类工具，部署前扫描工具描述
Context7 可集成到知识查询链，给代码生成提供实时文档，缓解幻觉
Sampling with Tools 多 Agent 编排（agent-orchestration-pattern）可借鉴其"显式 capability 声明"控制上下文

五、核心判断

  • MCP 已过"是否采用"阶段，进入"如何安全地规模化采用"阶段
  • Nov 2025 版本的 Task + 企业授权扩展，使 MCP 能力覆盖企业级多 Agent 编排需求
  • 安全是 2026 年的第一优先级——MCP.so 等市场已有数千 Server，质量参差，Tool Poisoning 是真实威胁
