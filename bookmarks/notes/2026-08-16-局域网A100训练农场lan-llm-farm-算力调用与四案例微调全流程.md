## 二、架构与算力调度（一图流）

```
Jetson/PC 客户端 ──HTTP:8810──> 训练网关 ──┬─ subprocess ─> swift sft（夜间窗口）
  client_submit.py     ①四问门禁          │
                       ②SQLite任务队列      └─ HTTP:8811 ─> vLLM 推理（白天常驻）
                       ③GPU显存调度(76G预算)                  ├─ 评测批量生成
                       ④案例路由 cases/*                     └─ LoRA 热挂载试跑
                       ⑤产物登记(sha1+大小)
```

**显存预算（A100-80G 单卡）**：白天 vLLM ~8G + 评测复用；夜间 LoRA 训练 18G（文本）~34G（视觉 SFT）+ OCR 农场余量 12G。**与 lan-gpu-farm 单双日轮换**：双日 LLM 训练 / 单日 OCR 微调，两网关通过 `/gpu/status` 互查避让。

**四问门禁**（源笔记§四，网关强制）：提交任务必须带 answers.yaml，①错误能否自动发现 ②数据是否必须本地 ③任务能否微调收窄 ④0.8B 选型理由——**答不上两个直接 422 拒绝**。

## 三、完整操作流程

### A100 侧（一次性，4 步）

```bash
cd ~/uclaw/project/lan-llm-farm
bash server/setup/00_env_check.sh          # 体检（GPU/驱动/磁盘≥200G/端口8810,8811）
bash server/setup/01_install_train_env.sh  # 训练环境（无公网: OFFLINE_WHEELS=/data/wheels）
bash server/setup/02_install_vllm.sh       # vLLM 手动验证
sudo bash server/setup/03_systemd.sh       # systemd 常驻 + 夜训 timer
```

模型预置（无公网场景）：U 盘拷入 `Qwen3.5-0.8B` 到 `/data/llm-farm/models/`，或临时代理 `huggingface-cli download Qwen/Qwen3.5-0.8B --local-dir /data/llm-farm/models/Qwen3.5-0.8B`。

### 日常业务流（客户端两条命令）

```bash
# ① 提交训练任务（answers 四问回答可从各案例 config.yaml 的 answers 段抄）
python3 server/gateway/client_submit.py submit \
    --case case1_text2sql --config case1_text2sql/config.yaml \
    --gateway http://<A100_IP>:8810 --priority 1

# ② 轮询状态 + 取产物（gate 达标 → done；未达标 → failed(gate)）
python3 server/gateway/client_submit.py status --task-id <id> --gateway http://<A100_IP>:8810
python3 server/gateway/client_submit.py artifacts --task-id <id> --gateway http://<A100_IP>:8810
```

### 训练产物 → 端侧部署

```bash
# A100 上合并+量化（产出 merged/ bf16 + gguf/Q4_K_M ~600MB）
bash deploy/merge_and_quantize.sh /data/llm-farm/artifacts/case1/<task_id> case1

# Jetson 端侧注册（Ollama 自动生成 Modelfile）
bash deploy/serve_local.sh ollama /data/llm-farm/artifacts/case1/Qwen3.5-0.8B-case1-Q4_K_M.gguf
# 或局域网共享（A100 上全量 bf16）
bash deploy/serve_local.sh vllm /data/llm-farm/artifacts/case1/<task_id>/merged 8820
```

## 四、四案例明细（数据→校验器→达标线）

| 案例 | 训练数据 | 校验器（Gate） | 达标线 | 状态 |
|------|---------|---------------|--------|------|
| case1 Text-to-SQL | 3000 条模板生成（航空紧固件库存 schema） | SQLite 执行 + 结果集对比（执行准确率，非字符串比对） | ≥85% | mock 自测 1.0/注噪 0.5→gate 正确触发 |
| case2 手册问答 | 10 知识条目×多问法+同义增广 | **heldout 独立集**关键词≥2 或模糊≥0.75 | ≥70% | 判分逻辑单测通过 |
| case3 重排器 | 正例+易负例+**难负例**（同 topic 不同条目） | MRR / NDCG@10 / pair_acc | MRR≥0.35 | 金标 mock=1.0 自测通过 |
| case4 OVD/REC | 程序化合成场景图（拒绝采样防重叠）+bbox 真值 | IoU≥0.5 贪心匹配命中率 | ≥60% | 标注规范性单测通过（bbox∈[0,1]、x1<x2） |

**达线才算 done**——网关把评测报告挂任务记录，未达线标 `failed(gate)`，防"训练集表演"（case2 的 heldout 纪律即为此设计）。

### 关键设计决策（可直接借鉴）

1. **执行准确率 > 精确匹配**：等价 SQL（`ORDER BY` 次级键、ROUND 尾差）也算对，贴近业务真实可用性。实现坑：金标 SQL 的 `ORDER BY` 必须带确定性次级键（如 `, part_no`），否则并列值排序不稳定金标不可复现（实测 0.98→修后 1.0）。
2. **sqlite3 隐式事务坑**：`executemany` 后必须显式 `commit()`，否则评测器 `BEGIN` 撞未提交事务抛错（本次实测抓到的真 bug）。
3. **合成数据零标注成本**：case1 模板×槽位、case4 程序化画图+bbox 真值来自生成参数——IoU 天然可校验。真实落地只需替换数据源（真照片+标注），评测器不变。
4. **优先级抢占语义**：数字越小越优先；`decide_schedule` 在显存不足时找 priority 数字**更大**（更不重要）的可断点任务让位。
5. **夜训分时**：23:00 timer 把 vLLM 从 0.10 显存占用重启到 0.05（腾出训练显存），07:00 恢复——推理不断服，训练有空间。

## 五、使用性评估

| 维度 | 评价 |
|------|------|
| 好用吗 | ✅ 客户端零依赖（纯标准库）；四问门禁防拍脑袋立项；33 项纯函数回归无 GPU 可跑 |
| 适用场景 | 局域网单卡 A100/任意大显存 GPU + 小模型（0.8B~4B）LoRA 流水线；数据不出网的企业场景 |
| 不适用 | 多机分布式训练（当前单卡串行队列）；0.8B 独立承担开放域 Agent（TAU2 11.6 分的边界）；需要海量公网语料的预训练 |
| 成本 | 0.8B LoRA 全流程显存 ~18G（文本）/34G（视觉），A100 夜间窗口绰绰有余；单案例 3000 条 3 epoch 预计 <1h |

## 六、指导性意见（何时用/何时不用/替代方案）

- **用**：输出可规则校验的窄任务（SQL/JSON/分数/bbox）；手册/内部文档问答；检索重排降主模型 token；巡检开放词汇初筛（OVD 一类一训太贵，0.8B 临时类别按需问）。
- **不用**：复杂多轮 Agent、医疗法律结论、无人值守高风险控制（源笔记反面清单）。
- **替代方案**：更小内存（<300MB）看 Needle-2 风格极简模型；要更强推理换 2B（内存×2，先过四问第④条）；云端有公网时大模型 API 直接调（本项目价值恰在**无公网+数据不出局域网**）。
- **升级链**：0.8B 零件（端侧 Ollama）→ vLLM :8811 局域网共享 → 云端大模型 → 人工。
