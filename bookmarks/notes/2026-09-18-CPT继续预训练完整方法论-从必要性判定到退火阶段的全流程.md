## 一、内容整理

### 1.1 CPT 的本质定义

原文给出精确定义：**CPT（Continued Pre-Training，继续预训练）是在已有通用预训练模型（如 Qwen、Llama）基础上，用大规模无标注的领域文本继续做自回归语言建模训练（预测下一个 token），目标是把领域知识"写进"模型参数里。**

核心定位：解决通用模型在垂直领域的"知识层缺陷"——模型自注意力机制能解析问题，但参数里压根没有相关条文或参数，只能概率拼凑导致事实性错误。

### 1.2 CPT 与 SFT 的分工

这是原文最有价值的框架判断：

| 阶段 | 解决的问题 | 比喻 |
|------|-----------|------|
| CPT | "模型压根不知道"（补知识） | 打地基 |
| SFT | "模型知道但说不出来"（学做事） | 盖房子 |
| DPO/RLHF | 风格/安全对齐 | 精装修 |

**顺序不能颠倒**：先 CPT 再 SFT。如果颠倒，会出现"形式到位、内涵缺失"——模型学会了回答格式但回答内容空洞。

标准链路：CPT（领域内化）→ SFT（任务对齐）→ DPO/RLHF（风格对齐）。CPT 只是第一步，后面必须接任务微调，否则模型只会"懂领域语言"不会"按指令办事"。

### 1.3 必要性判定（先评估再做）

原文给出了清晰的决策树：

| 症状 | 诊断 | 处方 |
|------|------|------|
| 回答方向基本正确，表述不够专业/格式不对 | 能力层不足 | **直接 SFT，不需要 CPT** |
| 回答出现大量事实性错误/术语混淆/关键参数偏差 | 知识层缺失 | **需要 CPT** |

**先验证 RAG**：原文最省钱建议——"如果你在做垂域 LLM 落在，可以先用'通用模型+检索'验证八成问题能否解决，再决定是否上 CPT，这是最容易被忽视的省钱点。"

三条判定路径：
1. 检索命中 + 回答准确 → RAG 解决
2. 检索没命中（文档里确实没有）→ 知识盲区，补文档
3. 检索命中了但模型理解错/格式错/推理错 → 能力问题，标记为需要微调

### 1.4 数据准备

| 维度 | 要点 |
|------|------|
| 数据来源 | 企业内部文档（工单日志/操作规程/技术方案）、行业白皮书、专利文本、专业论文、标准规范 |
| 数据配比 | 领域语料 20%-40%，通用语料 ≥60%（防灾难性遗忘） |
| 数据清洗 | 去 HTML 标签、MinHash 去重、过滤低质量、删敏感信息 |
| 数据量门槛 | 高质量行业语料至少几亿 token，低于这个量级效果容易被淹没 |
| 数据格式 | JSONL，每行一个 JSON 对象，核心字段 text |

### 1.5 算力估算

以 7B 模型、10B token 为例：
- 8×A100 理想训练约 4 天，实际按 5-7 天估计
- 70B 模型 + 100B token 计算量是前者的 100 倍，普通团队很难在合理时间内完成

### 1.6 训练超参

| 参数 | 推荐值 | 理由 |
|------|--------|------|
| 学习率 | 1e-5 量级（全参训练） | 远小于原始预训练，否则一步冲掉通用知识 |
| 循环次数 | <1万条数据 3-5 epoch；>1万条 1-2 epoch | 小数据多轮，大数据少轮 |
| 序列长度 | 模型支持的最大值 | 长序列捕获更多上下文 |
| 退火阶段 | 训练末期学习率降到极小 + 数据换成人工精选高质量种子 | 模型收敛质量明显跃升 |

### 1.7 防遗忘与评估

**回放（rehearsal）**：保留一定比例通用样本混进训练（通用占比 ≥60%）。

**双轨评测**：领域基准 + 通用基准一起看。只盯领域涨点是陷阱——通用基准不掉才算适配成功。

### 1.8 四大误区

| 误区 | 内容 |
|------|------|
| 一 | 一上来就烧算力做 CPT，结果领域语料不大，通用模型+检索就能解决，纯属浪费 |
| 二 | 只做 CPT 不做 SFT，模型只会"懂领域语言"不会"按指令办事" |
| 三 | 领域语料占比过高（>50%），导致通用能力严重退化 |
| 四 | 忽略词表扩展，领域专有术语在原词表里被拆成子词，信息损失严重，训练初期损失居高不下 |

### 1.9 三方案对比

| 方案 | 开发周期 | 算力成本 | 团队要求 |
|------|---------|---------|---------|
| RAG | 1-2 周 | 几乎为零（API 调用费） | 1-2 个后端工程师 |
| SFT | 2-4 周 | 几万到几十万 | AI 工程师+标注团队 |
| CPT | 1-3 个月 | 几十万到上百万 | 专门训练团队+大量算力 |

### 1.10 CPT 的硬需求场景

原文给出两种"必须做 CPT"的场景：

1. **行业有独特语言体系**：古文、医学拉丁文、法律条款引用方式——通用模型的 tokenizer 拆词就拆错了，检索回来的片段模型也读不懂。
2. **需要深度内化的推理能力**：多跳逻辑、因果链条、复杂决策——RAG 只能给片段，给不了"思维方式"。

### 1.11 千问交叉验证：CPT vs LoRA 的正交关系（2026-09-18 增补）

> 来源：千问分享会话「CPT训练：领域知识内化与任务对齐」· 2026-09-18 · [分享链接](https://qianwen.my.cn/share/chat/a44cf652a9de478aad481060f97e4bcf)（两轮追问：CPT 和 LoRA 是不是一回事 / 垂域产出上是否等效）

**核心论断：CPT 是"训练目标"（继续预训练补领域知识），LoRA 是"参数更新方式"（低秩适配节省算力）——两者是正交概念，可组合为 LoRA-CPT，不是二选一。**

**1.11.1 概念正交对照**

| 维度 | CPT | LoRA |
|------|-----|------|
| 本质 | 训练阶段/目标 | 参数更新方法 |
| 解决的问题 | "模型不懂领域知识" | "全参数训练太贵" |
| 参数更新 | 通常全参数 | 仅低秩矩阵（0.1%-1%） |
| 数据 | 大规模无标注领域文本 | 任意（CPT/SFT/DPO 均可挂） |
| 成本 | 高（全参数） | 极低（消费级显卡可跑） |

LoRA 是"外挂适配器"，可挂任何训练阶段：LoRA+CPT（省钱版 CPT）/ LoRA+SFT（最常见）/ LoRA+DPO（偏好对齐）。

**1.11.2 效果差距实证（2024-2026 多项实验）——对垂域产出"是否等效"的直接回答**

| 任务类型 | LoRA vs 全参数差距 | 说明 |
|---------|------------------|------|
| 指令跟随/对话风格 | -0%~-2% | 基本无差别，偶有反超 |
| 领域问答（有 RAG 兜底） | -1%~-3% | 差距可被检索补齐 |
| 数学/代码推理 | -3%~-8% | 需要高 rank 缩小差距 |
| **新知识注入（CPT 场景）** | **-10% 以上** | **不建议纯 LoRA，应做全参数 CPT** |
| 通用能力保持（MMLU） | LoRA 优于全参 | LoRA 掉 0-2 点，全参常掉 3-8 点 |

**结论：垂域产出上不等效。** LoRA-CPT 只能达到全参数 CPT 约 80%-90% 的效果，无法承载复杂知识体系（复杂推理能力弱，只能注入原子事实和浅层逻辑）。

**1.11.3 为什么很多团队觉得"差不多"（三个假象源）**

1. 任务本身不需要深度知识注入（客服话术/格式调整/术语替换类，LoRA 够用且抗遗忘更优）
2. 评测维度不够深——只测领域基准不测通用基准，掩盖了全参 CPT 的灾难性遗忘代价
3. 数据量没到 LoRA 容量上限——Thinking Machines Lab 2025 实证：数据信息量在 LoRA A/B 矩阵容量内时性能与全参完全相当，超出即衰减

**1.11.4 选型决策框架（与 1.3/1.9 的判定链衔接）**

- **选全参数 CPT**：行业语料几十亿 token+、百万级预算、有分布式经验、知识差异大（核电运维/法律判决/医学病历）、追求深度内化——对应 1.10 的两类硬需求场景
- **选 LoRA-CPT**：数据几亿 token 内、十万级预算、单机多卡、需频繁迭代数据版本、"保通用前提下增强垂类"
- **折中两阶段**："先 LoRA 后全参数"——LoRA 跑通数据流程验证配比与评估，方案确认后全参数出最终版

**1.11.5 对本笔记体系的增量**

- 与 1.2（CPT/SFT 分工）互补：补上了"参数更新方式"这个正交维度，形成 训练目标（CPT/SFT/DPO）× 更新方式（全参/LoRA）的完整选型矩阵
- 与 1.7（防遗忘）互证：LoRA 冻结主干天然抗遗忘（MMLU 掉 0-2 vs 全参 3-8 点）——预算受限时 LoRA-CPT 是"不伤原能力"的赢家
- domain-llm-training 项目校准：1GB 语料 ≈ 1.5 亿 token 级 + 单机 4090 = 落在 LoRA-CPT 区间（1.11.4 第二档），与项目现行 CPT+LoRA-SFT 双阶段设计互为印证；若语料扩到十亿 token 级应重评全参数 CPT

## 二、查询拓展

### 2.1 "先 RAG 再 CPT"的决策逻辑

原文最重要的方法论贡献不是 CPT 怎么训练，而是**做 CPT 之前的决策树**：先用通用模型+检索验证 80% 的问题能否解决。这与本地 08-19《LLM 技术选型决策指南-RAG-SFT-DPO-RL-Distillation》的分层路线完全一致——RAG 是第一道筛，筛不掉的才上微调。

原文的三条诊断路径（检索命中+回答准确→RAG 解决；检索没命中→补文档；检索命中但回答错→微调）是一个可操作的分流框架，可直接作为领域落地的 SOP。

### 2.2 "退火阶段"的工程价值

原文提到的退火阶段（训练末期学习率降到极小 + 数据换成人工精选高质量种子）是本篇最值得记录的细节。这对应预训练中的 **cooldown / annealing** 阶段——Chinchilla 论文和 Llama 2/3 的训练报告中都有提到，但工程实操中常被忽略。

退火的本质：训练后期模型已接近收敛，大学习率只会让权重在最优点附近震荡；降到极小学习率 + 切换到最高质量数据，让模型在"最干净的梯度方向"上做最后的精细调整——收敛质量跃升的来源是这个。

### 2.3 词表扩展的必要性

原文误区四指出"领域专有术语在原词表里被拆成子词"——这在航空/医疗/法律领域是真实痛点。例如"翼肋"在 Qwen tokenizer 中可能被拆成 ["翼", "肋"]（2 token），而扩展词表后变成 ["翼肋"]（1 token）。

影响链：拆词 → 训练初期 loss 居高不下（模型要先学重新组合碎片）→ 有效训练步数减少 → 同等算力下领域知识注入不足。

### 2.4 灾难性遗忘的量化

原文给出配比"通用 ≥60%"，但这个数字与上一篇（domain-llm-training 项目）的"通用 10-15%"有差异。差异来源：

- 本篇千问原文的配比可能针对更大规模 CPT（几亿 token 级别），此时通用比例需更高
- domain-llm-training 项目的配比针对小规模 CPT（200-300MB），此时通用比例可低
- 通用比例与领域数据量成正比反方向变化：领域数据越大，通用比例需要越高来对抗遗忘

这是一个需要在实际训练中用双轨评测动态调整的参数，不是固定值。

## 三、归纳总结

### 3.1 领域大模型落地的三层决策

```
1G 领域文档
├── 第一步：RAG 验证（1-2 周，~¥0）
│   ├── 80% 问题解决 → 停在这层，不需要训练
│   └── 解决不了 → 第二步
├── 第二步：微调路线选择
│   ├── 回答方向对但格式/表述差 → SFT only
│   └── 回答事实性错误/术语混淆 → CPT + SFT
└── 第三步：CPT + SFT 全链路（1-3 个月）
    ├── CPT（补知识）→ SFT（学做事）→ DPO（精装修）
    └── 双轨评测：领域↑ + 通用不掉
```

### 3.2 CPT 的四阶段工程流程

| 阶段 | 做什么 | 关键参数 |
|------|--------|---------|
| 数据准备 | 清洗+去重+混合通用 60% | 几亿 token 门槛 |
| 训练 | 低学习率全参训练 | lr=1e-5, bf16, DeepSpeed |
| 退火 | 末期降学习率+换高质量种子 | cooldown |
| 后接 SFT | 把知识转化为任务执行 | LoRA SFT |

### 3.3 与 domain-llm-training 项目的互补关系

| 维度 | 本篇（CPT 方法论） | 上篇（domain-llm-training 项目） |
|------|-------------------|-------------------------------|
| 视角 | 决策树+理论框架 | 可执行代码+配置文件 |
| 数据配比 | 通用 ≥60% | 通用 10-15% |
| 基座 | Qwen/Llama 通用 | Qwen2.5-7B-Base |
| 硬件 | 8×A100 为主 | 4×A100 L2 标准档 |
| 独特贡献 | 退火阶段+词表扩展+必要性判定 | 数据预处理脚本+DeepSpeed 配置+量化部署链 |

**两篇合在一起** = 完整的 CPT 落地方案：本篇给决策依据和理论框架，上篇给可跑的代码和配置。

## 四、趋势判断

**趋势 1：CPT 的门槛在下降**
依据：原文提到 PEFT 库做 LoRA/QLoRA 继续预训练，单卡 24G 显存就能跑 7B 模型。含义：CPT 从"百万元团队"向"单人单卡验证"下沉，验证阶段不再需要全参训练。

**趋势 2：退火阶段将从"可选"变为"标配"**
依据：原文明确提到"模型收敛质量会明显跃升"。含义：在数据量有限的领域 CPT 场景，退火阶段的 ROI 极高（几乎不增加成本但显著提升最终质量）。

**趋势 3：RAG→SFT→CPT 的决策树将成为领域落地 SOP**
依据：原文给出三条诊断路径 + 三方案成本对比表。含义：不做 RAG 验证就直接上 CPT 将被视为工程失误。

**趋势 4：词表扩展在中文领域场景将成为必选项**
依据：原文误区四专门提到"信息损失严重，训练初期损失居高不下"。含义：航空/医疗/法律等术语密集领域的 CPT，不扩词表等于白训。

**趋势 5：通用数据配比将从经验值走向动态调整**
依据：原文 60% vs 上篇 10-15% 的差异说明这不是固定值。含义：未来工具会支持"遗忘率监控→自动调整通用配比"的闭环。

### 5.5 与 AutoDL 训练经验的关联

本地 DUCK 训练在 AutoDL 上跑（4×A100 4080S），与本篇 CPT 的硬件需求同构——AutoDL 的按量计费模式适合 CPT 的 3-7 天训练周期。但 DUCK 是 RL 训练（rsl_rl），不是 CPT——两者的 GPU 利用模式不同（RL 是 env+policy 交替，CPT 是纯前向+反向）。

## 六、金句摘录

> 「CPT 解决"模型压根不知道"的问题（补知识），SFT 解决"模型知道但说不出来"的问题（学做事）。顺序不能颠倒，否则会出现"形式到位、内涵缺失"的尴尬局面。」

> 「如果你在做垂域 LLM 落在，可以先用"通用模型+检索"验证八成问题能否解决，再决定是否上 CPT，这是最容易被忽视的省钱点。」

> 「领域语料占比过高（>50%），导致通用能力严重退化。」

> 「训练末期把学习率降到极小，数据换成人工精选的高质量种子，模型收敛质量会明显跃升。」

> 「只盯领域涨点是陷阱，通用基准不掉才算适配成功。」

> 「一上来就烧算力做 CPT，结果领域语料并不大，通用模型加检索就能解决，纯属浪费。」

> 「RAG 只能给片段，给不了"思维方式"。」

### 8.1 可落地为 CPT 决策 SOP

本篇的三条诊断路径 + 三方案对比表可直接作为组织内部"领域大模型立项"的评审 SOP：先 RAG 验证 → 评估命中率 → 决定是否上 CPT → 双轨评测验收。

在投入 CPT 算力前，先跑 100 道领域题的 RAG 基线——命中率 >80% 不启动 CPT，<60% 才启动。这是最省钱的工程实践。
