内容整理：三幕剧方法谱系

一句话定义

同一模型，推理时多想几步、多试几条路，答对率上去——算力不必全花在训练上，留一部分到答题现场。quality = f(C_train, C_test)，总预算固定时，难题把预算往 C_test 挪。

上期衔接（第 29 期 RL，已核验）

R1 不靠教师示范，直接基座上跑 GRPO，AIME 2024 pass@1 从 15.6% → 71.0%（R1 论文原文数字，多数投票再升至 86.7%）。训练再强，一步想错全错 → 引出本期：算力留一部分到答题现场。

代价与边界

  • 推理时算力不免费：N 翻倍，延迟与成本翻倍；简单题多想无用（已经会了）。
  • 最优分配 = 简单题少想、难题多想（compute-optimal 的核心）。
  • OpenAI o1 公告原话：o1 性能随训练时 RL 与推理时"想的时间"一起提升——两个旋钮不互斥。

归纳总结

  1. 双旋钮模型是本期最有迁移价值的框架：任何"预算固定"的系统（模型算力、Agent token、人的时间）都存在 train-side 与 test-side 的分配问题，难题应向 test-side 倾斜。
  2. 三条方法是一条谱系：只在解码层投票（自洽性）→ 引入外部打分器（BoN）→ 打分器深入到中间步骤（PRM 树搜索）。打分粒度越细，算力效率越高，但打分器本身成为新的单点风险（reward hacking 从 RL 迁移到推理侧）。
  3. 边际递减 + 难度自适应是省钱的两把刀：o1 从 64→1000 采样只多赚 ~10pp；Snell 证明按难度分配预算比无脑 BoN 省 4 倍。
  4. 能力放大器不是能力发生器：小模型能赢 14 倍大模型的前提是"本来就有一定成功率"——零基础的题，推理时算力救不了，预训练赢。

查询拓展

  • 难度估计器从哪来：Snell 的 compute-optimal 需要先知道题难不难——论文用模型自身迭代难度估计（value model 对候选打分），这个前置环节是工程落地最脆的一环，值得单读。
  • o1 的 test-time compute 内部到底是什么：OpenAI 未公开（CoT 长度自适应？树搜索？自洽性？），公开侧只能从阶梯数字反推——1000 采样重排 93% 说明上限受排序模型质量约束。
  • reward hacking 在验证器上的具体形态：分高但错的答案长什么样（迎合奖励模型的表面特征），与 RL 训练侧的 reward hacking 是否同构。
  • cons@64 vs maj@64 记法差异：o1 附录用 cons@64，R1 论文用 cons@64=86.7（majority voting）——口径相同，跨论文对比时注意 pass@1 的单采样设定。

趋势判断

  • 按想的时间计费已是现实：o1 阶梯数字（9.3→93.0 跨 10 倍）本质是"准确率商品化"——同一模型按预算卖不同准确率，reasoning API 的 thinking token 计费是它的产品化形态。
  • 难度自适应将从论文走向 serving 层标配：静态 N（固定采样数）在成本上不可持续，路由/调度层按题难度动态分配推理预算是明确方向（与我们库内 AI4AI-at-TestTime、RATIO 量化推理优化同向）。
  • 验证器质量成为新瓶颈：训练侧 scaling 红利收窄后，竞争点转向打分器——谁的过程奖励模型准，谁的 BoN/树搜索就有效；reward hacking 研究会从训练侧向推理侧迁移。

拓展应用推荐

  • 对我们（Agent 系统）：① 关键决策（不可逆操作前的判断）可用轻量 BoN——采样 3-5 个方案 + 显式判据打分，比单次生成显著降错；② 难度自适应已有雏形（adaptive-inference-routing 按任务复杂度分配 token 上限），Snell 的"难度→预算"映射函数可直接吸收；③ self-consistency 零成本可试——对数学/结构化抽取类任务多数投票，不改任何配置。
  • 对量化研究：多模型预测分歧度 = self-consistency 的票数分布，可作信号置信度代理（票数集中≠对，但分散=必弃）。
  • 对选型：小模型+推理时算力 vs 大模型单次的决策表——先测小模型在该任务的成功率基线，非零基线且 FLOPs 敏感时优先前者。

指南分析

什么时候用哪条（决策表）：

前提条件 首选方法 理由
答案可离散验证、无验证器 自洽性投票 零改造成本，+11~18pp 免费拿
有可靠验证器、预算中等 BoN（N=8~16） 1→16 收益最陡，16 之后边际塌缩
中间步骤可打分、预算充足 PRM 树搜索 算力效率最高，但验证器工程量大
简单题/已高准确率任务 单次推理 多想无用，纯烧钱
小模型成功率≈0 的题 换大模型/预训练 推理时算力放大不了不存在的能力

红线：验证器未经验证前，BoN 的 N 不宜大——N 放大的是打分器的偏差，不是答案的正确性。

行动与回访

  • 把 Snell 的"难度→预算"映射吸收进 adaptive-inference-routing 的判据（简单查询 CoT=off，难题自动升档）——行动项。
  • 在一个结构化抽取任务上实测 self-consistency（N=5 投票 vs 单次），拿真实增量数字。
  • 回访条件：若后续复现/文献显示小模型胜 14 倍大模型的结论不可泛化（仅限特定 benchmark），本笔记该条降权；证伪信号=多任务上 FLOPs 对齐后大模型反超。
  • 待验证：o1 的 93.0% 依赖"学习排序模型"——我们场景里排序器用什么（规则判据/LLM-as-judge）尚无实测，首次落地 BoN 时须对比。
