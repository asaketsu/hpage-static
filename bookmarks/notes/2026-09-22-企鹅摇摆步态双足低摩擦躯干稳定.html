查询拓展

DUCK 在真机部署遇两类地形痛点：低摩擦地面（瓷砖/光滑桌面演示）与支撑面摩擦系数不确知。本文用 5-DOF 企鹅形态双足机器人"Pengu"+ MuJoCo v3.8 仿真 + 硬件实测双轨，系统回答一个 DUCK 部署层正需要的问题：躯干侧倾策略（rolling, Gait R）与直立躯干策略（upright, Gait U）谁更适合低摩擦地面？什么条件下该"走得像企鹅"？ 这不是 RL 策略研究，而是形态学+开环控制的最小化对照实验——恰好补上 DUCK 全 RL 路线之外"控制策略本体论"的知识盲区。

内容整理

C3 Gait U 1.31 企鹅 COM（Macaroni 企鹅形态）

硬件平台：54cm 高、髋高 15cm、总质量 2.29kg、Dynamixel XM430-W350-T×5、Arduino MKR+BNO055 IMU、3D 打印 PLA 结构、椭球曲脚（非同心曲率中心提供被动侧向稳定）。COM 比率 = 整机 COM 高/髋轴高（中立站姿），钛钢配重块改变 COM 位置。

核心数据（Table II，硬件实测 10-20 次试验均值±SD）

低摩擦 μ=0.12（UHMW 聚乙烯板）：
- C1（U, 1.05）：速度 0.145 m/s，侧向脚速 0.037，COT 6.41
- C3（U, 1.31）：速度 0.227，侧向脚速 0.088（最差），COT 4.55
- C4（R, 1.05）：速度 0.199，侧向脚速 0.0.041，COT 5.14
- C6（R, 1.31）：速度 0.0.261（最快），侧向脚速 0.0.032（最小），COT 3.56（最低）——全指标冠军

高摩擦 μ=0.45（橡胶地）趋势反转：
- 低 COM 组（C1/C4）速度 0.107/0.108，COT 8.95/7.85
- 高 COM 组（C3/C6）速度 0.043-0.044，COT 23.6/24.6（高 COM 在高摩擦下崩坏）
- Gait R 在高摩擦下仍降低侧向脚速（0.035→0.024 / 0.018→0.009）

关键机制发现

  1. 低摩擦 + 高 COM + 躯干滚向支撑腿 = 最优组合：速度+80%（vs C1）、COT -44%、侧滑最小。机制=企鹅式侧摆实现机械能交换（Griffin & Kram 2000 Nature：企鹅摇摆不浪费能量），且长单支撑相+短双支撑过渡降低打滑窗口。
  2. 高摩擦下趋势反转：高 COM 配置速度暴跌 4 倍、COT 恶化 3 倍——"企鹅策略"不是普适最优，是条件最优。高摩擦下低 COM 的贴地稳定更划算。
  3. 仿真-硬件方向一致（μ=0.1 仿真 vs μ=0.12 硬件，Gait R 更快、成功控制器区域更大），但仿真成功域大于硬件实测——摩擦感知的 sim2real gap 仍存在，作者诚实标注未做硬件鲁棒域估计。
  4. 成功判据工程化定义值得抄：不倒+前进速度>0.05 m/s+航向偏差<90°+伺服速度<354°/s 占比≥3/4 步态周期+排除腾空相。鲁棒性=参数网格邻域成功（步频±0.05Hz、髋相位±10°）。
    4'. 开环正弦位置控制（p_i = A_i·sin(ωt+φ_i)+θ_i）五执行器，躯干 DOF 闭环 IMU 反馈——最小控制实现稳定双足行走，无 RL、无 MPC。

归纳总结

  1. "企鹅式摇摆"是被硬件实测验证的低摩擦最优步态本体——不是民间智慧而是数据结论，且适用条件明确（低摩擦+高 COM）。
  2. COM 高度是比步态策略更强的变量——COM 效应（4 倍速度差）> 步态策略效应（速度差 ~40%）。形态设计（配重位置）的杠杆大于控制策略切换。
  3. 条件最优而非普适最优——高摩擦下同配置崩坏，说明部署时地面摩擦感知/自适应策略切换是必要的，单一策略打天下不成立。
  4. 开环+被动稳定形态足以稳定行走——椭球曲脚非同心曲率中心提供被动侧向稳定，这是 DUCK 平脚设计之外的被动稳定方案。
  5. 仿真方向预测正确但幅度乐观——Gait R 优势的方向仿真硬件一致，成功域大小仿真>硬件（经典 sim2real gap）。

趋势判断

  • 短期：DUCK 演示场景多为光滑桌面/玻璃台面（μ 估计 0.1-0.3），正处于"企鹅策略"优势区。当前 RL 策略在低摩擦下表现未系统测试——值得增加低摩擦 DR（domain randomization）覆盖或部署层摩擦自适应。
  • 中期：形态-控制联合设计（morphology-control co-design）在小型双足平台是性价比路线：COM 高度这类"免费参数"（配重块）比改奖励函数更直接。
  • 长期：低摩擦步态本体（躯干滚向支撑腿）可否作为 RL 策略的参考轨迹/模仿目标，与 RL 弹性结合——本文开环版本已证明可行，RL 版本是自然延伸。

拓展应用推荐

  1. P0·DUCK 低摩擦演示守则：演示地面 μ<0.3 时优先测试当前策略表现；若侧滑/摔倒，参照本文 C6 配置逻辑——部署层添加侧向重心主动配平（DUCK 无躯干 roll DOF，可用 hip_yaw 侧摆近似），或干脆选粗糙垫演示。
  2. P1·摩擦 DR 补强：当前 W5/h1xr 系训练 DR 含 friction 0.5-1.5，低摩擦端（<0.3）覆盖不足。若演示需要低摩擦，训练侧补 μ∈[0.1,0.4] 域随机化，成本=一次变体训练。
  3. DR 覆盖检查命令级操作：variants 配置里 grep friction 区间，对照本文 μ∈{0.1,0.3,0.5,0.2} 扫描网格设计，把低摩擦端纳入。
  4. P2·被动稳定形态改造：DUCK 脚掌若换椭球曲脚（非同心曲率中心），获得被动侧向稳定——硬件改造项，需用户拍板，非 Agent 自主可执行。
  5. 成功判据抄用：本文"鲁棒性=参数邻域成功"定义可直接用于 DUCK 策略评估脚本——对超参邻域（步频/相位扰动）扫描而非单点验收。

指南分析

对 DUCK 项目的落地指南：
- 部署层（立即可用）：低摩擦地面演示前先测当前策略；侧滑症状出现时，先查地面 μ 再怪模型。本文数据给出明确的"μ<0.3 → 企鹅式策略优势区"分界。
- 训练层（下个变体可用）：DR 摩擦区间下界从 0.5 扩到 0.1-0.2，与现役 W5/h1xr 系配方兼容（单参数改动）。
- 形态层（长期）：椭球曲脚改造是被动稳定路线，与 RL 策略正交可叠加。
- 方法论层：本文是"最小控制平台 + 系统参数扫描"的典范——2×3 配置×4 摩擦×网格扫描的实验设计密度远超单点验证，DUCK 的版本谱系矩阵（docs/67-69）应向这种密度看齐。
