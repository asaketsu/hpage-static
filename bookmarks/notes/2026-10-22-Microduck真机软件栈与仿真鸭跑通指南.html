归纳总结

一句话：从仿真训出的策略到真机跑起来，中间差的不是再训一次，而是把宿主从 Python 推理脚本换成真机守护进程。文章给出一条零硬件路径——把官方 Rust 固件栈原样拉起，仅将舵机总线替换为 MuJoCo 仿真身体（TCP 7801），再通过 policy load 槽位热替换装入自训 ONNX，全程守护进程一行不改。

三个最有价值的知识点：

  1. 缝的架构：真机软件栈与仿真身体的接缝在舵机总线——缝以上（Rust robotd/configd/tofd/updaterd）是真机原封不动的固件，缝以下是 Python duck-body 仿真。守护进程分不清接的是真舵机还是仿真，因为 50Hz 回路的协议（发目标角/收传感读数）完全一致。
  2. 槽位与技能两套机制：槽位（slot）是固件写死的 7 个常驻模式（walk/stand/sitstand/ground_pick/kick_left/kick_right/roulade），换文件=换一类行为且热替换；技能（skill）是配置表里可增删的短动作（0.5~1s），临时触发跑完自收尾。policy load 装槽位、policy add 装技能，两套独立。
  3. 腿式运动两个动力系统概念解释"鸭子不走"：命令速度低于策略训练速度 → 极限环（limit cycle）塌缩，净位移为零（甩跳绳太慢转不圆）；完全对称静止起点+纯前进指令 → 落在零速循环的吸引区（basin of attraction）中心，不破对称永远走不出来，需要外部扰动越界。

内容整理：架构、命令与实测数据

三层架构与两个仓库

层 实现 来源仓库 职责
身体 Python duck-body（仅仿真存在） pollen-robotics/microduck_rl MuJoCo 物理，复用训练仓机器人模型（场景XML/执行器模型），TCP 7801 对接
守护进程 Rust robotd/configd/tofd/updaterd pollen-robotics/microduck 50Hz 控制回路、策略推理、安全检查、摔倒检测、运动学、里程计、槽位热替换
遥控器 robotctl（仿真走 scripts/duck-sim ctl 包装） 同上 下指令/看状态/装策略/读日志

替身放训练仓而非固件仓的原因：仿真和训练必须共用同一套机器人模型，sim2real 才对得上。

关键命令链（作者 Intel Mac 实测，构建耗时 2 分 59 秒）

# 准备
git clone https://github.com/pollen-robotics/microduck
git clone https://github.com/pollen-robotics/microduck_rl
cd microduck_rl && uv sync          # CPU 即可，无需显卡
cd microduck && cargo build -p robotd -p robotctl -p tof -p sounds -p configd -p updater

# 起栈（--sim 127.0.0.1:7801 把舵机总线换成 TCP）
DUCK_SIM_VIEWER=0 DUCK_SIM_RL=<训练仓路径> scripts/duck-sim

# 确认活着
scripts/duck-sim status / ctl health / realtime / ctl monitor --json

# 装自己的策略并行走（默认 0.15 不够，0.3 才迈开步）
scripts/duck-sim ctl policy load walk <output_baseline.onnx>
scripts/duck-sim drive 0.3

起栈成功三标志：== standing up → healthy → trunk 0.116 m（站立高度）。刚起那瞬回路掉到 37Hz 属正常，几秒回 50Hz。

健康报告口径（仿真里也有电池/电机温度——证明缝以上全是真代码）

  • loop 49.9 of 50.0 Hz · 6531 ticks · 11 missed：漏几轮是正常的，不是故障
  • battery 7.40 V (50%) / motors 32 °C：属于守护进程报告口径，仿真照报
  • 实时倍率 <1.0 = 真问题：策略在驱动一个"比它以为动得少"的身体，站不稳；表现不是肉眼变慢而是回路跌破 45Hz 闸门报不健康

monitor --json：控制回路每轮快照（真栈独有层）

Rust 示例 policy-rehearsal 只做"观测进→动作出"；真机守护进程中间多了策略槽位自动切换、动作安全闸门、移动限制——monitor 是看这些层的唯一窗口。每行一个 JSON 对应一轮循环（50Hz → 行间隔约 0.02s）。

move 三分量记账法（本篇最值得抄的设计）：

字段 含义 实测
requested 遥控器要的 0.3
applied 安全层放行、真发给电机的 起步 0.177 → 0.268 → 0.289 → 0.300（半秒多爬满，闸门逐步放开，非 bug）
limited_by 谁拦的 未使能时 ["deadman"]

行走成功五标志：装载不报错（形状 61 维观测进/14 路动作出，不对在加载前就拒，失败不动在跑的）；policy 从 stand 变 walk；applied 从 0 爬满 0.3；关节周期性摆动（左膝 -0.19~0.39 rad，摆程 33°）；里程计真挪了（8.7 秒净位移 0.83 米）——前四条证明链路活着，最后一条才回答机身挪没挪。

弧线行走的根因（官方 alpha 策略实测）

直走命令、转向分量全程 0，鸭子却走出左弯弧线（航向转 49°）：61 维观测里没有航向项（策略不知道自己偏了）+ 训练没开镜像对称约束（只要走得快就算赢） → 左膝每步摆约 73°、右膝只摆约 35°，左髋摆右髋几乎不动，每步往同一边蹭。换一次训练，偏向哪边是碰运气。

仿真验不了硬件

舵机总线驱动、蓝牙、摄像头成像管线、NPU、硬件编码器不是被简化，而是根本没有——这些硬件身上的毛病只有真机才看得见。

与我们 DUCK 项目部署链的对照（我们的链：AutoDL 训 → 本地导 ONNX → scp asa → headless_test.py 自建推理）：

维度 官方真机栈 我们的链 差距/启发

趋势判断

  1. "缝"的工程模式正在成为 sim2real 中间件的标准形态：以总线协议为接缝、守护进程不感知身体真假，等价于硬件在环（HIL）测试的机器人版。预测官方栈会沿这条缝扩展更多替身（不同动力学保真度的 body），训练仓与固件仓共用模型是关键设计约束。
  2. 策略交付物从"权重文件"走向"槽位生态"：7 个固件写死槽位 + 可增删技能 + 社区策略仓库（policy search 走 Hugging Face）——策略像 App 一样可搜索、可安装、可热替换的分发形态已现雏形，形状检查是唯一的安装门禁（行为质量无门禁，"好不好只有跑起来才知道"）。
  3. 动力系统语言（极限环/吸引区）从理论课下沉到部署调试手册：教程用"碗底小球""甩跳绳"讲清两个卡死模式，说明 sim2real 调试的经验正在被形式化——预测后续会有标准化的"步态可达性"预检工具（给定策略+起点，判极限环是否可达）。
  4. 官方 alpha 基线策略自身就走弧线（无航向观测+无对称约束），印证当前开源腿式 RL 基线的"能走但走不直"仍是普遍水位，航向/对称约束是下一步标配。

指南分析

适用场景：无真机时验证部署链完整性；策略交付前的宿主环境冒烟测试；学习官方安全层设计。

操作要点（按文内实测提炼）：

  1. 环境只需 CPU；Intel Mac 需按前文专节绕 PyTorch/MuJoCo-Warp 无 x86 包问题；需预装 ONNX Runtime 动态库
  2. 起栈后等几秒再看健康（首瞬 37Hz→50Hz）；== down 是收旧栈属正常
  3. socket/日志在 ~/.cache/duck-sim（真机在 /run）；默认策略集首次自动下载约 8MB——这下载的不是你训的 ONNX，自训策略必须 policy load 才生效
  4. 走不起来先查两件事：速度是否 ≥ 训练速度（drive 0.3）；起点是否完全对称（需扰动破对称）
  5. 判"真走了"的唯一硬指标是 odom 位移，不是关节在动（原地踩踏也是关节在动）
  6. 多鸭/多摄像头会压实时倍率，解法优先级：减鸭 > 减摄像头 > 无窗口
  7. 社区策略（policy add）形状检查会过但行为无保证，网络不通整节跳过不影响主链

风险与边界：此仿真只替身体层，硬件驱动链（总线/蓝牙/摄像头/NPU/编码器）完全缺席——跑通仿真鸭 ≠ 真机会好，硬件层问题（如我们踩过的舵机带宽、EEPROM 限位、IMU 符号）在此栈中不可见。

拓展应用推荐

  1. 抄 move 三分量记账法进真机守卫：守卫日志把"请求指令/实际下发/拦截原因"分列记录，事后判"是策略不行还是安全层拦了"一翻便知——与我们"每跑必记录关节角+震动"的守卫哲学直接互补
  2. 给部署链加形状预检门禁：ONNX 进真机前先验 obs/act 维度（官方 61/14 口径），加载失败不碰现役文件——比我们 sim 对拍更前置的一道廉价闸门
  3. 起步破对称写进真机 SOP：我们的鸭子归 0 姿态若接近左右对称+零速，纯前进指令可能落在吸引区中心——起走前给一次横向扰动或非对称起始角（与我们"起始姿态分布外"诊断互为印证，方向相反的两种病同一类根因）
