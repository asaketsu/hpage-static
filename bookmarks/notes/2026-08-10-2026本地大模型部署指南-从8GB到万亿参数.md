> **2026 年本地部署大模型的核心瓶颈已从 GPU 算力转向显存容量和内存带宽。** Kimi K3（2.78T 参数）在 8.24GB 内存上跑通（每 Token 等 32.69 秒），DeepSeek V4 Flash（284B）在 128GB Mac/DGX Spark 上接近可用。MoE 稀疏激活 + 权重流式加载 + 低比特量化正在把万亿模型搬上个人桌面。

## 完整原文核心内容

### Kimi K3 是怎么在 8GB 跑起来的

**kimi-k3-in-c 项目**：不到 200KB 的 C 语言代码完成 Kimi K3 的 CPU 推理。无 PyTorch、无 CUDA，只依赖编译器 + OpenMP + 系统数学库。

**内存压缩四层递进**：

| 层级 | 大小 | 说明 |
|------|------|------|
| BF16 全参数 | 5.56TB | 所有参数半精度的理论体积 |
| MXFP4 权重 | 1.56TB | 官方发布的 4-bit 量化权重 |
| 稠密主干 | 113.49GB | 专家留磁盘后，需持续参与计算的部分（注意力/路由器/共享专家/Embedding/输出层） |
| **峰值内存** | **8.24GB** | 稠密主干也改成逐层读取后的实测峰值 |

**技术原理**：

1. **MoE 稀疏激活**：Kimi K3 共 2.8T 参数，每 Token 仅激活 ~104B（3.7%）。每层 896 个专家中只用 16 个
2. **专家权重留磁盘**：根据路由结果从硬盘读取需要的 16 个专家
3. **稠密主干流式加载**：93 层稠密权重重新整理为 109GB 连续文件，循环缓冲区逐层读取
4. **KDA 固定状态**：69 个 KDA 层不需为每个历史 Token 保存 KV Cache，只维护固定大小递归状态
5. **MLA 压缩**：24 个 MLA 层通过低维表示压缩注意力缓存

**代价**：

| 指标 | 数据 |
|------|------|
| 每 Token 磁盘读取 | ~25.83GB 专家 + ~108.81GB 主干 = **~130GB+** |
| Token 速度 | 0.03 Token/s（32.69 秒/Token） |
| 完整存储要求 | **1.7TB NVMe** |
| 测试环境 | 双路 AMD EPYC 7763（124 核/228GB RAM/3.2TB NVMe + 4×L40 未用） |

> 8GB 是通过 Linux cgroup 限制进程内存测得的峰值 RSS。不是普通 8GB 笔记本实测。"One CPU"更准确理解为 CPU-only。

**内存阶梯测试**：从 8GB 增加到 224GB，内存扩大 28 倍，速度只提高约 1.7 倍。约 4-6 成时间在等硬盘。**关键硬件已从 GPU 转向 NVMe。**

### 显存选型指南

#### 显存计算公式

```
模型权重(GB) ≈ 参数量(B) × 量化位数 ÷ 8 × 1.15
总内存需求 ≈ 模型权重 + KV Cache + 1~3GB 运行缓冲
```

| 量化 | 每 1B 参数显存 |
|------|-------------|
| FP16（半精度无损） | ~2GB |
| INT8（8-bit） | ~1GB |
| **INT4/Q4_K_M（主流）** | **~0.5-0.6GB** |

> MoE 模型注意：虽然每 Token 只激活部分专家，但**全部专家权重都必须完整加载到内存/显存**。

#### 显存 vs 模型规模对照（Q4 量化，8K-16K 上下文）

| 显存 | 可运行模型 | 代表模型 | 显卡推荐 |
|------|-----------|---------|---------|
| **8GB** | 4B-7B | Phi-4 Mini 3.8B, Qwen3.5 4B | — |
| **16GB** | 9B-14B | Qwen3.5 9B, Gemma 4 12B | RTX 5060 Ti 16GB（¥5100-5300） |
| **24GB** | 24B-27B | Devstral Small 2 24B, Qwen3.8 27B | 二手 RTX 3090（¥5000-8000） |
| **32GB** | 35B MoE | Qwen3.5-35B-A3B（激活 3B） | — |
| **80-128GB** | 120B+ | gpt-oss-120b | 大容量统一内存工作站 |

#### 系统配置建议

| 显卡 | 建议系统内存 | CPU |
|------|------------|-----|
| 8-16GB 显卡 | 32GB | 6-8 核够用 |
| 24-32GB 显卡 | 64GB | 6-8 核 |
| 混合卸载 70B | 128GB | 更多核心 |

> 硬盘从 1TB NVMe 起步，长期推荐 2TB。

### "能跑≠能用≠值得部署"三层判断

| 层级 | 含义 |
|------|------|
| **能跑** | 权重可装进显存，或从硬盘逐层读取 |
| **能用** | 速度/上下文/模型能力足以完成任务 |
| **值得部署** | 省下的 API 费用或获得的隐私/稳定性/控制权覆盖硬件+电费+维护成本 |

> DeepSeek V4 Flash 的出现让这三者开始重合——接近前沿模型能力 + 量化后 110-168GB 可运行 + Mac/DGX Spark 可触及。

## 结合最新研究与技术变化

### 1. 与本地 AI 七层堆栈笔记的关联

本文是七层堆栈中**硬件层（第一层）和运行时层（第二层）**的 2026 实战选型指南。Kimi K3 的 8GB 实验证明了"能跑"的下限，DeepSeek V4 Flash 的量化方案展示了"值得部署"的上限。

### 2. 与 LFM2.5-2.6B 的关联

LFM2.5-2.6B（< 2.5GB 内存）对应本文的"8GB 能跑 4B-7B"档位——但 LFM2.5 专门优化了 Agent 工作流，手机 CPU 30 tok/s，是"能跑且能用"的代表。

### 3. 与注意力机制全景笔记的关联

Kimi K3 的 69 KDA 层 + 24 MLA 层正是上一篇注意力机制笔记中的"3:1 KDA+MLA 混合"架构——KDA 的固定状态特性让 Kimi K3 的 KV Cache 不随生成长度失控，这是 8GB 能跑的关键前提。

### 4. 与 ADB 本地算力机笔记的关联

ADB 方案的 AIPC（Mini PC）运行本地模型正是本文讨论的场景。结合本文的选型指南，AIPC 的硬件选择有了明确参考。

### 5. 与 Jetson Orin 平台的关联

Jetson Orin Nano 8GB 属于本文的"8GB"档位——可以跑 4B-7B 模型（如 LFM2.5-2.6B/Qwen3.5-4B），适合端侧 Agent 任务。

## 趋势判断

1. **MoE + 量化 + 流式加载 = 万亿模型上桌面**——三技术叠加持续降低部署门槛
2. **NVMe 成为新的关键硬件**——从 GPU 瓶颈转向存储带宽瓶颈
3. **DeepSeek V4 Flash 正在填平"能跑/能用/值得部署"三角**——接近前沿能力 + 可量化 + 个人设备可达
4. **统一内存设备（Mac/DGX Spark）成为本地部署主力**——不需要专业计算卡
5. **DGX Spark 涨价验证市场需求**——$3999→$4699，苹果 Mac 涨价断货
6. **KDA/MLA 等注意力创新直接降低 KV Cache**——架构创新和部署优化协同
7. **Ollama cloud 标记需警惕**——不是所有"本地"模型都在本地跑
