摘要

本文介绍了一种利用 Visual Studio「复制现有项目」功能，快速配置 NX（Siemens NX）二次开发环境的方法。核心技巧是用一条 CMD 命令批量导出 UGOPEN 目录下所有 .lib 依赖库文件名，避免手动逐一输入，整个过程两分钟内完成。

核心步骤

1. 复制现有项目

在 Visual Studio 中通过「新建项目 → 复制现有项目」快速继承已有配置，而非从零搭建。

2. 修改路径

配置项 说明
附加库目录 指向 NX 安装目录下的 UGOPEN 文件夹
输出文件路径 .dll 或 .so 的生成位置

3. 添加附加依赖库

不同 NX 版本的依赖库有变化，库文件通常位于：

NX安装目录\UGOPEN\

快速获取依赖库清单

痛点：手动逐个输入 .lib 文件名容易遗漏且效率极低。

解决方案——一条 CMD 命令搞定：

cd /d "C:\Program Files\Siemens\NX{版本号}\UGOPEN"
dir /d *.lib > libs.txt
参数 含义
dir 列出目录文件
/d 精简输出，仅文件名（宽列格式）
*.lib 只筛选 .lib 结尾的文件
> libs.txt 输出重定向到文本文件

操作流程：
1. 执行上述命令生成 libs.txt
2. 打开 libs.txt，复制全部库文件名
3. 粘贴到 VS 项目属性 → 链接器 → 输入 → 附加依赖项

适用范围

  • ✅ 适用于多个 NX 版本（NX10/11/12/1872/2007/2206/2306 等）
  • ✅ Visual Studio 2015/2017/2019/2022
  • ✅ NX Open C++ / NX Open C 开发

🔍 借鉴点

  • CMD 批量导出技巧 → dir /d *.lib > libs.txt 这个模式可推广到任何需要批量收集文件名的场景（如 Java JAR 依赖、Python 包列表等）
  • 复制现有项目 → 对所有大型 IDE（VS/Eclipse/Qt Creator）都适用，比从模板新建更可靠，因为已有的编译选项/宏定义直接继承

💡 启发

  • NX 二次开发入门的最大门槛不是 API 本身，而是环境配置。这篇方法把配置时间从 30 分钟压缩到 2 分钟
  • UGOPEN 目录下的 lib 分为几类：libufun（UF 函数库）、libnxopen（NX Open C++）、libinternal（内部接口）等，按需添加即可，不必全部链接

⚠️ 注意：链接所有 lib 可能导致冲突。实际开发中按需添加，常用核心库是 libufun.lib 和 libnxopen.lib。
