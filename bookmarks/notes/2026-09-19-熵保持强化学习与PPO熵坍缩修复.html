内容整理：核心问题

PPO/GRPO 类 policy gradient 算法在训练中系统性消灭策略熵——分布锐化锁死在已高分轨迹上，探索能力丧失，性能平台化甚至倒退。论文证明这不是调参不当，而是算法数学结构内生的：

  • 熵变化由 advantage 与（均值中心化）log-probability 的相关性驱动（Theorem 1）：ΔH ≈ -α·E[A·L·u⊤u′]，给高概率动作赋正 advantage → 分布锐化 → 熵减
  • 有限 MDP 最优解本就是确定性策略，但优化途中的景观需要探索/利用平衡——熵轨迹（journey）比终点熵更能预测最终性能："it's not the destination, it's the journey"
  • 全程低熵轨迹的 run 最终性能更差；仅在最后几步分叉的熵轨迹性能几乎不受影响

内容整理：方法详解

1. 理论层——各算法的熵动力学

  • PPO：多次 off-policy 复用轨迹放大熵坍缩；但 clipping 恰当时可保护熵（Theorem 2：(1-ε_low)·H_old ≤ H_new ≤ (1+ε_high)·H_old，clip 阈值直接限制每 token 熵变化幅度）
  • DAPO 非对称裁剪：ε_low=0.2 < ε_high=0.28 → 允许更大幅度熵增、限制熵减 → 隐式熵保持
  • GSPO 序列级裁剪：轨迹级 trust region，熵界与轨迹长度 |τ| 相关；|τ|<600 token 时比 DAPO 更紧
  • RLOO 严格 on-policy：不放大坍缩但仍受 Corollary 1 支配——base model 与 reward 强预校准时相关性为正，熵照样掉

2. 实证层——数值精度是隐藏杀手（Theorem 3）

BF16 量化导致 importance ratio 系统性向上偏置：
- 上 clip（A>0, r>1）：r_observed 更早触顶 → 概率上升被提前截断
- 下 clip（A<0, r<1）：向上偏置把 r 拉向 1 → 下 clip 约束变松
- 净效果 = 等效 ε_low > ε_high 的反向非对称裁剪——与 DAPO 的熵保持方向完全相反！
- 修复：模型输出全程 FP32 计算 ratio；训练用 FP16（mantissa 位多）替代 BF16。仅数值修复就拿到 AppWorld SOTA（79% TN / 71% TC）

3. 显式控制层——REPO 与 ADAPO

REPO（Regulated Entropy Policy Optimization）：改造 advantage：A_REPO = A - β_s·L(s,a)
- REPO-D（Decorrelate）：β ∝ -ΔH，逐 token 中和熵变，让 ΔH→0
- REPO-R（Rescale）：β = ζ·|A|——上调稀有正确解的权重，平均下调稀有错误解的惩罚，只用采样 token 的 log-prob 即可估计（CCE 兼容，零额外显存），且充当控制变量降低梯度方差
- 自适应控制器：ζ 初始 1e-3，熵低于初值 ×2、高于 ÷2，双向调压，ζ∈[1e-3,10]（REPO-D）/ [1e-4,0.05]（REPO-R）

ADAPO（自适应非对称裁剪）：ε_low=0.2 固定，ε_high∈[0.2,0.32] 按熵动态调（熵低→×1.05 放开熵增，熵高→×0.95 收紧），双向控制

关键实验结果

  • GRPO 训练全程熵掉 ~90%；RLOO 明显少；DAPO/GSPO 保留更多但 DAPO 可失控上冲
  • REPO-R/ADAPO 全面超越 off-policy 基线且熵平稳
  • 累计熵与最终测试精度正相关；探索密集型任务（AppWorld）收益 > 已锐化的数学任务（AIME）
  • 顺序训练实验（先 AIME 后 AppWorld）：GRPO 因熵坍缩第二阶段几乎丧失再训练能力；DAPO/REPO 保有熵和探索力
  • 数值精度实验：BF16→FP16+logπ 全精度修复后，DAPO 的熵动力学从"坍缩"翻转为"上升"——部分历史熵坍缩是数值伪影而非算法本质
  • Qwen2.5-32B 初始成功率 40% vs Qwen3 <10%（冗长 thinking blocks 拖累）——base model 特性主导熵动力学，与算法无关

查询拓展

  • 与 mode collapse 研究线的关系：arXiv 2601.21669 证明期望回报目标下 outcome-level mode collapse 不可避免，熵正则/KL 约束只能"软化"不能消除——与本文 Theorem 1 的"相关性驱动熵减"互补
  • RLVR overtraining 视角（2606.15455）：n=8 rollouts 下最小非零成功已饱和 advantage 信号 → 自强化锐化偏置
  • 连续控制域映射：DUCK H1F（MLP 高斯策略，rsl_rl PPO）熵 -1.83→-1.99 单调下坠 = Theorem 1 相关性机制的连续控制实例；action_symmetry -0.27→-1.41 同步恶化 = 熵坍缩把策略锁死在不对称步态吸引子
  • KL-regularized RL is Designed to Mode Collapse（2025）：KL 正则本身即推向 mode collapse 的数学结构

归纳总结

  1. 熵坍缩是 policy gradient 的内生数学性质（advantage×log-prob 相关性），不是工程 bug——但可以被 clip 结构、数值精度、显式控制器三层调控
  2. 监控指标升级：从"终点熵"改为"熵轨迹"——中途持续低熵才是性能杀手
  3. 数值精度（BF16 ratio 偏置）可制造与算法设计方向相反的等效裁剪，FP16+FP32 ratio 计算是零成本必修项
  4. 非对称裁剪（升多降少）+ 自适应控制器 = 通用熵保持配方，可叠加到任意 PPO 变体
  5. 熵保持的深层价值是可训练性（trainability）：保住探索储备，为顺序任务/新环境微调留活口

趋势判断

  • 熵轨迹监控将从"可选"变"标配"——论文已证明累计熵与最终性能强相关，训练框架会内置 entropy trajectory dashboard + 自动告警
  • ADAPO 式自适应超参（按观测熵双向调 clip）是"超参自动化"大趋势在 RL 后训练的落点
  • 数值精度审计（BF16 vs FP16 ratio 计算）会成为 RL 训练 stack 的标准 checklist 项——DUCK 项目可立即受益
  • LLM 后训练熵坍缩研究正在与连续控制域（机器人 RL）合流：同一套 Theorem 1 框架两边通用

拓展应用推荐

对 DUCK-Pi_5（最高优先级，今晚 H1F 拍板直接可用）：
- P0：H1F 熵坍缩处置按论文理论升级——单纯加 entropy_coef 是"固定 β 补熵"（论文明示其缺陷：不适应动态）；更优解是 ADAPO 思路的自适应熵控制：给 rsl_rl PPO clip 加非对称 ε（ε_low=0.2, ε_high=0.28），一行配置级改动
- P0：训练日志审计——H1F 的 ratio 计算若走 BF16 会叠加反向偏置；4080 上 FP16 训练 + log-prob FP32 是零成本修复
- P1：15min 守护 cron 的熵阈值改为轨迹型判据：不只看当前值，看 3 点滑动趋势（连续 2 窗下降且斜率超阈 → 预警），比单点 <-2.5 提前 1-2 小时捕获
- P2：REPO-R 的 β=ζ|A| 重缩放思想可移植到 rsl_rl（改 advantage 传入前处理），但需等 H1T2/H2 完训后做 A/B

对 Hermes Agent：
- 顺序训练实验结论直接映射 Agent 技能迭代：用坍缩过的模型做二阶段 RL ≈ 用僵化技能库做新领域——保持"探索熵"（技能多样性）是连续进化的前提，佐证 skill-review 的防僵尸化机制
- 数值精度审计思路可推广到任一训练管线 checklist

对量化交易：
- 熵坍缩 ≈ 过拟合的单模型版本；累计熵-性能正相关 ≈ 多样性-鲁棒性正相关。多因子集成时监控"因子相关性熵"，单一因子信号锐化（IC 集中）是组合熵坍缩前兆

指南分析：落地步骤清单

若在 rsl_rl 中落实非对称 clip（ADAPO 静态版）：
1. rsl_rl/modules/actor_critic.py 或 ppo.py 的 clip 计算处，把对称 clip(range, 1-ε, 1+ε) 改为 clip(range, 1-0.2, 1+0.28)
2. 配置项命名 clip_eps_low/high，default 保持对称（不破坏旧 run 复现）
3. 验证门禁：重启后 500 iter 内熵不下穿 -0.5（对照 H1T 判死线 -0.69）；六点采样熵轨迹无单调下坠
4. 回归验证：G 系列任一已完训 run 用新 clip 重放前 500 iter，对比 reward 曲线形状不失真
5. 坑点：rsl_rl 的 ratio = exp(logp_new - logp_old) 在 AMP 混合精度下可能走 BF16——验证时先 .float() 再作差
