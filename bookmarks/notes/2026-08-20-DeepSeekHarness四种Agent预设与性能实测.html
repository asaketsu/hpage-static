一、核心概念（内容整理）

DeepSeek Harness 是 DeepSeek 官方开源的 AI Agent 运行环境，对标 Claude Code / Codex，核心理念「一切皆插件」。

Agent 预设 = AI 在一次会话中能用哪些工具 + 遵守什么系统提示词 + 以什么方式工作的整套配置。官方内置四种预设，通过对话框上方的模式选择器切换。

四种内置模式对比（全文核心表）

模式 工具数 系统提示词 特点 定位
标准模式 20+（文件读写/终端/联网/规划/Skills/子Agent/待办） 完整 Agent 人设 覆盖面广，"国产版 Codex" 日常全能
极简模式 2（持续终端 + 文件编辑器） 一句话："You are a helpful software engineer assistant" 上下文占用少 10 倍 跑模型基准测试（V4 Pro 官方跑分框架）
PTC 模式 同标准 20+（只差一行配置） 同标准 Programmatic Tool Call：生成 TypeScript 代码串联多步工具，一次执行 步骤多但逻辑清晰的批处理
创造模式 标准 + Cordis 插件系统专属工具 同标准 + 高权限 AI 可检查/试验/自创插件和预设 改造 Harness 自身（权限≈Shell，按需切换）

关键机制：
- 工具多 → 每步选工具占推理能力 + 工具说明书塞进上下文摊薄注意力。标准模式说句「你好」就占 1 万+ tokens；极简模式只占 1000+ tokens（10 倍差距）
- PTC 与标准模式配置只差一行：工具呈现模式 native → code
- 极简模式没有：联网搜索、上下文压缩、任务规划、Skills、子 Agent

二、技术要点（指南分析）

2.1 3D 射击游戏任务实测（同一任务三模式对比）

指标 标准模式 极简模式 PTC 模式
耗时 33 分钟 23 分钟（快 10 分钟） 26 分钟（快 7 分钟）
交互轮次 多轮 多轮 1 轮 18 步
输入 tokens 520 万 — 150 万（不到标准 1/3）
成品质量 好 差别不大但高要求易掉链子 三模式中最好

结论一句话（鱼皮原话）："图快就用极简模式，图稳就用标准模式，步骤多的自动化任务试试 PTC 模式"——对应标题"性能提升 40%"（33→23 分钟）。

2.2 PTC 模式的批量重命名例子

  • 标准模式：重命名工具一次处理一张，128 张照片 = 128 次来回交互
  • PTC 模式：AI 写 5 行 TypeScript 循环脚本，1 次交互全部完成
  • 本质：把「多轮工具调用」编译成「一段代码」，交互轮次从 N → 1

2.3 自定义 Agent 预设工作流（复刻 Cursor Debug 模式实例）

步骤：
1. 切换到创造模式
2. 提示词模板（照录）：

基于标准模式创建一个自定义 Agent 预设，名称为「Debug 模式」。
要求复刻 Cursor IDE 的 Debug 模式工作方式。
必须参考 Cursor 官方文档来设计：https://cursor.com/docs/agent/debug-mode
  1. AI 自动加载编辑预设的技能 → 终端抓取 Cursor 官方文档 → 提取核心工作流
  2. 修改两个文件：preset.yml（名称/描述）+ agent.cordis.yml（工具和角色人设）
  3. Debug 模式六步工作流写入：假设 → 插桩 → 复现 → 分析 → 修复 → 清理
  4. 完成后模式选择器出现自定义模式，疑难 Bug 排查专用

2.4 可复刻的专用模式清单

模式 职责边界
代码审查模式 只审查不修改，安全性/性能/可读性逐项检查，输出报告
文档模式 专注注释/API 文档/README

三、复现验证（归纳总结）

  • 本机未安装 DeepSeek Harness，实测数据均引自鱼皮原文（同一 3D 射击游戏任务）
  • 可交叉验证的部分：极简模式=官方跑分框架，与 DeepSeek V4 Pro 跑分图脚注"V4-Pro 使用 DeepSeek Harness 极简模式作为框架进行测试"互证
  • 热评第一（131 赞）提供另一种解读："表面：一切皆插件；实际想表达的：你们自己去捣鼓吧别打扰 AGI 训练"——社区对"极简跑分"的调侃视角

四、可学到的点（Hermes 借鉴）

  1. 上下文经济学：工具说明书是隐性成本——"你好"占 1 万 vs 1 千 tokens 的 10 倍差距，与 Hermes 的 adaptive-tool-selection（BRANE 动态工具选择）、deferred tool catalog（按需 tool_search）完全同构。模式切换 = 工具预算的粗粒度版本
  2. PTC = 工具调用的"批处理编译"：N 次交互编译成 1 次代码执行，Hermes 的 execute_code（Python 编排多工具）就是同款思路——本文实测数据（150万 vs 520万 tokens）为这个方向提供了量化证据
  3. 预设即 SOP 沉淀：自定义预设把最佳实践固化为可切换模式，与 Hermes skill 体系等价；「假设→插桩→复现→分析→修复→清理」六步可直接吸收进 systematic-debugging skill
  4. 跑分环境的极简主义：公平比较模型本身就要剥掉环境噪声——评测一个模型能力时，Agent 环境的工具数量是混淆变量
  5. 权限分级：创造模式"像对待 Shell 访问一样对待"，按需开启不常驻——与 Hermes 生产部署二次确认铁律一致

五、趋势判断（拓展应用）

  1. 模式切换会成为 Agent 产品标配：Cursor（Agent/Ask/Plan）、DeepSeek Harness（四预设）已验证用户心智，未来差异化在预设的自动路由——按任务类型自动选模式，而不是让用户手切
  2. PTC/代码编排是 token 效率主战场：520万→150万的 3.5 倍压缩，比换更便宜的模型收益更直接；预计各 Agent 框架都会加"代码编排工具调用"路径
  3. 自定义预设生态：像 skill 市场一样，会出现预设分享生态（Debug 模式/审查模式/重构模式模板流通）
  4. 跑分与实战分层：极简模式跑分、标准模式干活——"模型能力"与"Agent 系统增益"的分离评测会越来越重要，Harness 本身成了评测标准件
