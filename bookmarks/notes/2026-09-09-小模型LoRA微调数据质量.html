小模型 LoRA 微调数据质量：合成数据蒸馏与「形式而非事实」框架

2026-09-09 夜间自学习笔记
来源：arXiv 2601.03211（企业搜索相关性标注 SLM 蒸馏）、Fine-Tuning LLMs in 2026 行业实践博客
关联项目：AirCraft 航空知识问答（MiniCPM5-2B + LoRA，R3 已训完 1504 条，eval_loss 1.959，待质量提升）

生成日期 2026-09-09

核心结论（一句话版）

微调解决"形式"问题，不解决"事实"问题；小模型 + 合成数据蒸馏管线可以追平教师 LLM，前提是先有 eval、答案格式与生产场景严格一致。

1. 决策框架：什么问题该微调，什么问题该 RAG

2026 年行业共识的四象限判断法（按失败类型 × 信号稳定性切分）：

失败类型 信号稳定 信号易变
知识型（"模型不知道我们的文档"） 继续预训练（极罕见，如专业科学语料） RAG（正解，不要微调）
行为型（schema/语气/格式/拒答） 微调 LoRA/QLoRA（正解） Prompt 工程 + few-shot

要点：
- 基座模型 2026 年已原生支持长上下文、工具调用、结构化输出，"prompt+RAG"覆盖面比两年前大得多；
- Ovadia et al.（arXiv 2312.05934）实证：事实回忆 RAG 一致优于微调，往权重里烤事实会产生过时、不可验证的答案并侵蚀通用能力（灾难性遗忘）；
- 正确顺序：Prompt → RAG → Fine-tune → Distill；
- 最高 ROI 模式：薄 LoRA/QLoRA 适配器叠在强基座上，与检索配合而非取代检索；
- 铁律：训练前必须先有书面 eval。"如果无法判断新 checkpoint 是否比旧的好，你面对的不是微调问题，是评估问题。"

检查清单（五项全 yes 才立项微调）

  1. eval 已存在且 prompt+RAG 基线跑不过它
  2. 失败是行为型而非缺知识
  3. 至少几百条高质量样本，且格式与生产严格一致
  4. 有 adapter 生命周期 owner（12 个月维度：季度复验、基座漂移检查、回滚方案）
  5. 已估算持续运维成本且收益成立

2. arXiv 2601.03211：合成数据蒸馏管线详解

论文目标：企业搜索相关性标注（判断 query-document 相关度）。核心矛盾：人工标注贵、公开数据集与真实企业数据分布不符、LLM 直接标注吞吐低且贵。

2.1 五步合成数据管线（可复用模板）

步 操作 工具/方法 目的
1 种子文档选取 企业内部文档（邮件/聊天/知识库） 锚定真实数据分布
2 合成 query 生成 LLM 从种子文档生成"真实用户会问的问题" 解决 query 稀缺
3 难负例挖掘 BM25 检索相似但不对的文档 提升判别难度，逼模型学细粒度差异
4 教师打分 GPT-4o 对 query-doc 对打分级相关性标签 生成训练信号
5 蒸馏进 SLM LoRA 微调 Phi-3.5 Mini Instruct 压缩能力到小模型

2.2 结果

指标 蒸馏后 SLM (Phi-3.5 Mini) 教师 LLM (GPT-4o)
Human NDCG 0.953 0.944
Pairwise Accuracy 63.81 62.58
吞吐 17× 1×
成本 1/19 1×

结论：923 对人工标注基准上，蒸馏 SLM 与人类判断的一致性追平甚至超过教师 LLM。小模型不是缩水版，在窄域判别任务上是合格替代品。

2.3 为什么有效（因果链）

  1. 任务是窄域判别（不是开放生成），决策边界简单，2-3B 参数足够表达；
  2. 难负例（BM25 top 但不相关）逼迫模型学"差在哪"而不是"像不像"，这是判别任务的核心信号；
  3. 教师只负责打标签（一次性成本），推理时不需要教师——成本结构从"每次调用都贵"变成"训练一次、部署免费"。

3. 对 AirCraft 项目（MiniCPM5-2B 航空问答）的落地建议

当前状态回顾：R3 已训完 1504 条，eval_loss 1.959（R1 554条→2.151，R2 739条→2.145），Web UI 三模型对比就绪。已知瓶颈：答案均长 ~118 字、全单轮、49 条重复问题未清洗。

3.1 按四象限重新定位项目

本项目失败模式是什么？用户问航空结构材料知识，模型答得浅、答不对。这是知识型 + 稳定信号（航空材料知识不每周变）→ 按框架属于"继续预训练/RAG"象限，而非纯 SFT。但 2B 模型做不了像样的继续预训练，所以现实路径是混合：

方案 适用 对本项目的适配度
纯 SFT（现状） 行为型失败 ⚠️ 部分错位——目前把"注入知识"寄望于 SFT
SFT + RAG 知识+行为混合 ✅ 推荐：LoRA 管"领域语气/格式/术语"，检索管"事实"
蒸馏管线升级 SFT 缺标注数据 ✅ 强烈推荐：参照 2601.03211 五步管线造 R4 数据

3.2 R4 数据管线具体建议（照抄论文五步）

  1. 种子：已有航空结构材料文档（领域语料即种子）
  2. query 扩写：用 glm-5.2 从每篇种子文档生成 3-5 个真实工程师会问的问题（含模糊问法、缩写问法、上下文依赖问法——企业 query 的三大特征）
  3. 答案扩写：每问生成 300-500 字结构化答案（定义→机理→数据/牌号→应用场景→对比），替代现在 118 字的"百科词条"式短答案——这是已诊断的 50% 权重瓶颈
  4. 去重清洗：先解决 49 条重复问题，question 归一化（去空白/同义合并）
  5. 教师质检：glm-5.2 按"准确性/完整性/是否需要外部信息"三维打分 1-10，<7 分丢弃，先筛 query 再生成答案（论文明确：低质 query 过滤省算力）

3.3 eval 体系先行（当前最大缺口）

论文和行业博客共同强调：没有 eval 就没有微调。建议在 R4 训练前先建：

  • 固定 100 题考试集（覆盖材料牌号/工艺/失效模式/适航条款四类，人工或教师模型出题）
  • 每题参考答案 + 评分 rubric（正确性/深度/幻觉率三维）
  • R3 先跑基线，R4 训完同卷对比——解决"效果很不好无法量化"的问题
  • 加一项幻觉率指标：答案中不可溯源断言占比（领域问答的隐性杀手）

3.4 后续演进路径

  • 数据到 3000+ 条且 eval 达标后，可考虑 DPO 偏好对（好答案/差答案对比）进一步校语气——按博客选型：有成对偏好→DPO，只有点赞点踩→KTO
  • 多 adapter 服务模式（vLLM LoRA 路由）暂不需要，单领域单任务
