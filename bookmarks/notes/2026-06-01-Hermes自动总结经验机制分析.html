一、文章核心架构

文章揭示了 Hermes Agent 的五层长期记忆系统和后台 Review Fork 机制：

Tool Calling（即时解决）→ Experience Accumulation（下次更好）
    ↓
┌─────────────────────────────────┐
│  Memory    — 用户偏好、稳定事实    │
│  Skill     — 可复用流程/工作流     │
│  Diary     — 日记，情感上下文      │
│  Self-Ref  — 深层行为模式反思      │
└─────────────────────────────────┘
         ↑
    Review Fork（后台自省 Agent）

1.1 Tool Calling vs Experience Accumulation

维度 Tool Calling（这一次） Experience Accumulation（下一次）
目标 解决当前问题 让下次更好
机制 临时拼凑 长期系统化
产出 任务完成 Memory/Skill/Diary/Reflection
风险 无积累，重复犯错 越用越强

1.2 五大长期系统

系统 作用 内容示例
Memory 稳定事实+用户偏好 写作风格、环境约束、关系边界
Skill 可复用方法论 微信草稿流程、代码审查步骤、图片质量检查
Diary 主观生活轨迹 情感基调、关系动态、日常事件
Self-Reflection 深层行为模式 偏见、成长领域、重复错误
(隐含) Curator 垃圾回收 过期/冗余 Skill 清理

1.3 Review Fork 机制（核心创新）

[用户交互] → [任务完成 & 回复已发送]
                      │
                      └→ [Fork Review Agent（后台）]
                            ├── 继承环境 & 配置
                            ├── 仅限 Memory/Skill 工具（白名单）
                            └── 静默保存更新

关键护栏：
- 隔离性：在最终回复送达后创建，不干扰主任务
- 白名单工具：只能用 skill_view、skill_manage、memory，不能终端/搜索/发消息
- 环境一致性：继承主会话的模型和运行时配置
- 隐私保护：Review prompt 不泄露到外部 Memory Provider
- 来源追踪：自动区分用户创建 / 显式请求 / 后台生成的 Skill

1.4 触发条件

触发节奏 条件
Memory 节奏 设定轮次后评估用户偏好、长期身份、纠正
Skill 节奏 工具迭代次数超过配置阈值（通常 ≥5）
复杂任务 涉及多个工具组合
用户纠正 Agent 的方法/风格/质量被用户修正
错误修复 工具/工作流先失败后成功解决
Skill 过时 发现现有 Skill 不完整/过时/不准确

二、差距对标：文章 vs 当前 jbot 实际状态

文章描述 jbot 当前状态 评估

2.3 📊 总体评估

覆盖度：7/10（核心机制有，缺少 Diary 和 Review Fork）
深度  ：9/10（已有的部分远超文章描述）
自动化：6/10（evolver 靠 cron，非会话内自动触发）

三、可吸收的关键模式

模式 1：Review Fork（会话后自动自省）

当前痛点：evolver 只在 cron（04:00）跑，白天复杂任务的经验无法即时沉淀。

吸收方案：不新增 Fork Agent（Jetson 资源受限），改为在 SOUL.md 中强化"任务完成后主动 self-improve"行为：
- 工具调用 ≥5 的任务 → 完成后主动评估是否值得创建/更新 Skill
- 用户纠正 → 立即执行 memory(action='add')
- 资源消耗：0（利用现有 memory/skill_manage 工具）

模式 2：Diary 日记系统

价值：长期情感建模、关系管理、个性化服务的基础。

最小化吸收：在 Memory L2（short-term）中增加 diary/ 子目录：
- 格式：YYYY-MM-DD.md，每条一行摘要
- 内容：关键对话主题、用户情绪标记、重要决策记录
- 自动降级：7天后压缩为 memory 条目

模式 3：Provenance 标记

吸收方案：在 SKILL.md frontmatter 增加 provenance 字段：

provenance: user_created | explicit_request | auto_generated | cron_evolved
