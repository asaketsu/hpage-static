2. v1.0 关键特性

  • Signed Agent Cards：密码学身份验证的代理名片（防伪造能力声明）
  • 多协议支持 + 企业级多租户 + 现代化安全流（Web 对齐架构，兼容现有负载均衡/安全模式）
  • 早期采用者的明确迁移路径
  • LangGraph / CrewAI 上的异构代理已能互派子任务、协同工作流，无需共享内部记忆（保持 opacity）

3. 与 MCP 的分工（官方定调）

  • MCP = 代理 ↔ 工具/数据（对内）；A2A = 代理 ↔ 代理（跨组织边界）；互补而非替代

4. ACP 四层架构（arXiv:2602.15055）

  1. Transport 层：默认 gRPC（低延迟），支持 WebSocket（浏览器代理）/HTTPS（遗留系统），TLS 1.3
  2. Semantic 层："意图本体论"——高层目标 → 标准化 JSON-LD；通用动作 schema（QUERY / EXECUTE / DELEGATE / NEGOTIATE）
  3. Negotiation 层：Agent Cards 交换 + 动态 SLA（工作范围/资源上限/成本/错误处理协议）
  4. Governance 层：零信任——DID（去中心化身份）验证身份，VC（可验证凭证）证明权限；每条消息密码学签名

5. Agent Card 结构与谈判生命周期

字段 内容 示例
Identity 唯一 DID did:acp:123456789
Capabilities 支持的语义意图 [data_analysis, web_search, code_gen]
Constraints 运行约束 max_latency: 500ms, data_residency: EU
Trust Score 对等声誉聚合 0.98（1.2k 次交互）
Interface 端点+协议 grpc://agent.example.com:50051

四阶段：Inquiry（PROBE）→ Proposal（BID：资源+ETA）→ Agreement（COMMIT：任务参数哈希=软合约）→ Execution & Settlement（执行证明+声誉回写）

6. 联邦发现：混合模型

  • 本地：私有网内广播发现（mDNS 式）；全局：DHT（联盟区块链背书）——避免中心化注册表单点故障

归纳总结

  • A2A 的"语法层"已收敛（v1.0 稳定+三大云原生集成+150 组织），下一个战场是"语义层+经济层"：编排、谈判、支付、声誉
  • Cisco 工程师原话承认："A2A 是句法层……还有巨大机会构建更丰富的语义与交互模型"——连推动者也承认语义层未解决
  • ACP 论文的价值在设计（四层架构+Agent Card+谈判生命周期），实验数字仅供参考
  • MCP/A2A 分工定型：对内工具 vs 跨组织代理，双协议栈并存将是常态

趋势判断

  • 2026 内 A2A 成为企业多代理事实标准（三大云已原生支持，迁移成本趋零）
  • AP2（代理支付）是下一个值得盯的变量：代理经济闭环一旦跑通，声誉/信任基础设施加速——对量化/交易类 Agent 直接相关
  • 深度防御方向：Signed Agent Cards + Proof-of-Intent 会成为代理安全的标配词汇，安全审计类 skill 会需要这些概念

关联分析（与 Hermes 生态的落地映射）

指南分析：A2A 概念速查（下次直接抄）
