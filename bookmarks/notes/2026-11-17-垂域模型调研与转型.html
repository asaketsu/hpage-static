五大发展方向（调研篇）

  1. 从"会回答专业问题"到"能完成行业工作流"：垂域模型 Agent 化——调用工具、操作软件、多步骤流程，嵌入业务闭环（工业质检全流程、金融风控决策、医疗辅助诊疗）
  2. 小而精+混合架构：7B–30B 是性价比甜点，准确率达大通用模型 90%+ 而成本低很多；标准组合=开源基座+垂域数据微调+RAG+行业知识图谱+Agent框架；边缘/私有化部署因隐私合规低延迟越来越重要
  3. 数据与 Know-how 才是真壁垒：模型同质化后，差距在高质量行业标注数据、真实业务反馈闭环、领域专家持续对齐、与企业系统集成深度
  4. 覆盖面从头部场景向长尾渗透：医疗/金融/法律/工业/交通/气象之后，能源、农业、建筑、港口、出版、教育跟进
  5. 商业模式从卖 API 转向效果付费与行业操作系统：按任务完成度、业务结果（降本提效增收）收费

主要挑战

  • 高质量垂域数据获取难、标注贵、更新慢
  • 专业场景容错率极低（幻觉在医疗法律代价巨大）
  • 合规与可解释性要求高
  • 中小企业自养模型成本高，更依赖平台/SaaS

内容整理：范式转型（转型篇）

核心命题：旧路线已死

"收集行业语料 + 开源底座继续预训练（CPT）+ 指令微调（SFT）= 垂域大模型"的旧路线，在通用大模型+RAG 面前已基本失效甚至成为负资产。

根因：通用大模型已把"语言理解+通用知识记忆"做到极高水准且边际成本极低；在小模型里塞行业百科既打不过 RAG 武装的千亿通用模型，还导致灾难性遗忘。

研究范式四大转向

# 转向 旧范式 新范式
1 静态知识注入 → 领域推理范式对齐 喂教材法条让模型背（更新慢、易幻觉，不如外挂 RAG） 行业壁垒在特有逻辑推演与决策树（鉴别诊断路径/要件审判逻辑/风控归因链路）；构建可验证环境（Verifiable Environments）+ 过程奖励模型（PRM），用 RL（o1/R1 范式）训练约束下的慢思考与多步推理
2 纯文本 → 非自然语言模态 文本语料为主 领域原生基础模型：工业传感时序/设备震动频谱、蛋白质结构/基因序列/病理切片/3D影像、3D CAD 拓扑/流体力学仿真加速/EDA 芯片设计——通用大模型几乎无法接管，是真正护城河
3 大而全 → 极致 SLM 卷参数规模 千亿通用模型的推理能力蒸馏到 1B–8B 垂域小模型，窄任务（单据抽取/意图路由/端侧代码补全/车载语音）上超越大模型+极低幻觉率，支撑毫秒级延迟
4 流畅优先 → 确定性与校准 "讨好型人格"（不确定也流利地编） 不确定性量化+拒答机制（Abstention）+强约束解码，输出严格置信度与可追溯证据链，"宁可不答，绝不瞎答"

应用策略：复合 AI 系统（Compound AI Systems）

企业不该"从零炼一个替代 GPT 的行业大模型"，而是做"路由调度 + 通用大模型 + 垂域小模型 + 确定性工具"的组合体：

  • 复杂开放性规划/推理 → 外部最强通用模型（或 DeepSeek/Qwen 大尺寸私有化）
  • 高频/标准/低延迟/高敏感任务 → 垂域小模型（原文例子：90% 常规工单分类、实体抽取、脱敏清洗交本地 3B 模型，成本仅为 API 的 1/50）
  • 精确计算与合规校验 → 传统软件/规则引擎/仿真求解器/SQL（不要让大模型做算术或硬背规则）

三个配套抓手：

  1. Agent 化绑定工作流：通用模型"两手空空"进不去 ERP/MES/HIS；护城河不是"懂多少行业知识"而是"能在多大程度上端到端把活干完"
  2. 私有过程数据飞轮：通用模型公司爬尽公开数据，但永远拿不到①私有实时状态数据（客户沟通/产线状态/审批流）②业务结果反馈数据（Outcome Data：诊疗后康复情况、文案转化率、风控坏账率）——用业务成败当 RLHF/DPO 信号持续迭代
  3. 物理隔离与成本刚需市场：军工/政务/核心金融/核心研发源码/大病历要求 100% 断网私有化；私有化千亿模型硬件成本过高，深度优化的 14B–32B"中等身材强垂域模型"仍是性价比最优解；端侧场景（机器人本体/智能座舱/矿山井下/移动医疗仪器）须脱离网络独立运行

旧 vs 新总对比（转型篇原表）

维度 过去的垂域模型（即将淘汰） 未来的垂域模型（转型方向）

一句话结论（原文）：通用大模型越强越像"水电煤/CPU"，垂域者的机会是用这些廉价智力打造"行业专用机床"。通用解决"能用"，垂域解决"好用、敢用、愿意持续付钱用"。

领域化扩展：航空制造业视角（领域扩展，非原文）

本段为结合飞机设计企业背景（适航 CCAR/构型管理/型号资料）的领域扩展，非两篇原文内容。

  • 确定性/拒答机制 ↔ 适航逻辑同构：航空软件验证的 DO-178C 核心是"每条输出可追溯到需求与验证用例"。转型篇的"可追溯证据链+拒答机制"实质是把这套适航思维搬进模型输出——AI 辅助设计/审查类工具要进航空主流程，强约束解码+置信度输出不是加分项而是准入门槛
  • 构型管理 = 私有实时状态数据的典型富矿：型号资料/EBOM/更改单流转/有效性管理正是"通用模型公司永远拿不到"的数据；FMEA/FTA 分析结果与实际故障闭环是 Outcome Data 的航空形态。垂域价值锚点在构型受控的数据闭环，不在让模型背 CCAR 条文（条文本身更新快、引用错更危险——典型该走 RAG 而非 CPT 的场景）
  • 非文本模态与本机实践对位：转型篇点名的"3D CAD 拓扑结构"方向，与本机已落地的 CATIA CAA 二次开发（StructGen 从需求到 CATIA 模型的自动建模）是同一命题的两端——CAD 原生表征模型 vs 现有 API 工具链编排，后者正是"复合 AI 系统用确定性工具"路线的实例
  • 仿真加速是航空最现实的垂域赛道：气动/结构/系统仿真占型号周期大头，"流体力学仿真加速模型"类代理模型（本机已有飞机结构数字孪生×SHM×代理模型研究线）比文本问答类垂域更贴合"领域原生基础模型"定义

归纳总结

  • 两篇合并的主线：垂域模型的价值锚点已从"知识占有"迁移到"工作流占有"。知识层被"通用模型+RAG"拉平，剩下三层壁垒——业务结果数据飞轮、非文本原生模态、低幻觉确定性——全部指向工程系统而非模型本体
  • 范式判断本质是一组替换：CPT+SFT → 领域 RL+蒸馏；静态语料 → 过程数据；单模型 → 复合系统；语料规模壁垒 → ROI 可衡量的工作流嵌入
  • 商业模式判断与范式判断自洽：效果付费之所以成立，正因为壁垒从模型层移到了系统层——模型可替换，嵌进业务的系统与数据飞轮不可替换

趋势判断

  • "7B–30B 甜点 + 1B–8B 蒸馏"的双层结构会成为垂域标配（离线分析用中等模型、在线高频用 SLM），与通用模型的多尺寸分层并存
  • 可验证环境/PRM 是下一个军备竞赛点：谁能为行业构建高保真可验证环境（仿真器+规则引擎+业务沙箱），谁就握住领域 RL 的入场券——这与通用侧 o1/R1 后的走势同构
  • 信源折扣提醒：本组观点来自 AI 生成综述，其"旧路线已死"的断言偏激进——CPT+SFT 在数据极私有、任务极窄的场景（如特定单据格式抽取）仍是有效起手式，"失效"更准确说是"不再是差异化壁垒"。采纳其方向判断，折扣其激进程度
  • 中期看，"垂域模型公司"会大量转型为"垂域 Agent/系统公司"，模型本身变成可替换组件——与调研篇"效果付费"预判收束于同一终点

拓展应用推荐

  • 模型经济学决策表更新：接到垂域/私有化需求时，按"路由+通用+SLM+确定性工具"四层出方案，而非默认"微调一个模型"——旧路线默认值应废弃

  • 蒸馏路线备用：端侧/离线场景（nxaa 本地推理）可探索从包月大模型蒸馏任务专用小模型的流水线

指南分析

  • 可操作原则一：先问"这层该不该是模型"——精确计算、规则校验、条文引用交给工具/RAG/规则引擎，模型只做路由与推理；判定标准=输出是否需要可追溯证据链
  • 可操作原则二：垂域项目立项三问——①私有过程数据（状态+结果）是否拿得到？②能否构建可验证环境（仿真器/沙箱/规则引擎）？③ROI 是否可衡量？三问有一个否，项目实质是套壳 RAG，不该按"训模型"立项
  • 可操作原则三：尺寸选型——离线分析 14B–32B 中等模型私有化，在线高频 1B–8B 蒸馏 SLM，开放规划走外部最强通用模型；不要在单一模型上求全
  • 反模式清单：CPT 塞百科、让大模型做算术/背规则、按 Token 付费采购垂域能力、指望单微调模型解决行业问题
