各论文技术细节

1. HyperSkill（超图技能记忆）

问题定义：经验记忆设计必须同时回答三问——存什么、如何结构与检索、如何进化。现有系统只各答一问：把轨迹/洞察/工作流存成孤立条目，丢掉了子任务与可复用技能之间的组合关系；用平坦 embedding 相似度检索，忽略关系信号；维护记忆时不利用其关系结构。

核心设计：
- 记忆表示为超图（hypergraph），两类节点：子任务步骤 + 可复用技能；每条超边链接"单次轨迹产出的子任务与技能"——保留组合关系；
- 双路检索：同时查子任务层和轨迹层，按技能在检索到的轨迹中的共现度排序；
- 周期性结构知情维护：修剪低效用节点 + 通过质量加权传播合并冗余技能。

实测：xBench/GAIA/WebWalkerQA 上用 GPT-4o 与 Qwen3-30B-A3B，胜过十个记忆基线，GAIA 最高 +11.51，WebWalkerQA 最高 +11.18。

2. Evo-Harness（上下文→Harness 技能编译）

问题定义：现实中 agent 不断遇到新任务，往往只有一次机会从执行中学习；这些执行产出丰富但高噪声的上下文——普遍有用的教训与任务特定杂质纠缠。此前工作很少在复杂真实任务上验证，也没隔离改进的驱动因素。

核心设计：
- 提出在线 harness 学习（online harness learning）：冻结的 agent（模型参数不动）通过跨序贯任务持续更新结构化 harness 来进步；
- 核心机制 context-to-harness skill compilation：把噪声单次执行蒸馏成可复用的技能 harness，支持跨域与主题级适配；
- 五个真实基准验证：TerminalBench2、SWE-bench、CL-Bench、-bench、WebArena-Infinity。

价值：这是对我们"Hermes skill 体系"最直接的学术映射——skill 就是 harness 的实例，每次会话结束后提炼 skill 的过程就是 context-to-harness compilation。

3. LycheeMemory V2（语义分段级固化）

问题定义：现有记忆系统靠急切固化（eager consolidation）——每轮交互后调 LLM 提取/总结/更新记忆。对话越长构建成本越高；粗 summarization 省 token 但丢细粒度证据；加大检索上下文或多跳推理又把开销转嫁到查询时。

核心设计：
- 用语义分段级固化替代逐轮固化：多轮交互攒成段，段完结时编码成"上下文无关的类型化记忆记录"；
- 语义边界检测（vs 固定窗口）保留连贯的事件级与时序证据；
- 轻量结构化索引支持"查询规划式"证据检索。

实测（GPT-4.1-Mini）：LoCoMo 89.22%、LongMemEval-S 92.20% SOTA；对比 A-Mem 构建阶段 token 省 86.0%（LoCoMo）/ 75.9%（LongMemEval-S），且不增加查询时 token。核心论点：记忆的精度-成本权衡不仅取决于保留什么信息，还取决于以什么粒度固化。

4. RippleMem（关联式回忆）

问题定义：长期记忆的瓶颈不是存，是取——当相关证据分散在多次交互中时，现有方法取不回完整证据集。全上下文方法要在噪声长上下文里搜；平坦检索返回孤立不完整记录；图记忆建图贵且压缩掉丰富事件上下文。

核心设计：
- 灵感来自认知科学的线索依赖情节检索（cue-dependent episodic retrieval）与联想补全（associative completion）；
- 交互历史存为"线索丰富的情节记忆单元"，组织成事件中心记忆图；
- 查询时：先通过混合线索回忆相关记忆锚点，再沿语义与结构关联从锚点扩散，找回缺失的支持证据——最初召回的记忆既是答案上下文，也是补全证据所需答案的线索（涟漪效应）。

实测：LoCoMo 与 LongMemEval-S 最佳综合表现，LLM-as-Judge 准确率 LoCoMo +3.95%、LongMemEval-S 最高 +11.87%，建图成本降约 30 倍。

5. Harness the Memory（记忆基底大评测）

问题定义：记忆正成为长程 agent 的核心基础设施，但"该用什么记忆基底（memory substrate，记忆表示与存储的底层介质）"缺乏系统证据。

核心设计：统一 harness 下受控评测七类基底——稠密/稀疏索引、文本记录、结构化存储、层级存储、精炼式记忆、参数化更新、激活兼容上下文机制；三个骨干模型 × 四个基准套件（用户中心 QA + agent 中心决策），26 个性能与效率指标。

关键发现：
- 没有单一基底全能：宽检索利于长上下文事实 QA，但过度检索会伤害序贯决策——把注意力从行动关键上下文上移开；
- 可扩展性引入路由轴：中等历史长度下表现好的基底，在更长视野下可能变贵或变脆；
- 结论：基底路由（substrate routing）是自适应 agent 记忆系统的必要组件。

6. JERP（规则池×策略联合学习）

问题定义：积累的交互经验有两种用法被割裂——存在模型外当自然语言规则（好解释但会与演进中的策略脱节），或更新模型参数（提升广但稀疏奖励下对局部错误修正有限）。

核心设计：
- 同一批交互轨迹同时更新长期经验规则池与策略；
- 决策时检索任务相关规则，与交互历史一起作为条件；
- 每集结束后，用轨迹优化策略的同时，对比当前 rollout 与参考成功轨迹来修订规则池；
- 耦合保持规则池与演进策略对齐，稳定有效的行为逐渐被模型本身吸收。

实测：AlfWorld 与 WebShop 上一致的决策性能提升。

归纳总结：三条主线收敛

主线一：记忆系统的三问统一求解（HyperSkill + LycheeMemory + RippleMem）

2026 年 8 月这三篇同时出现不是巧合：孤立研究"存储/检索/维护"单点优化的阶段结束了。HyperSkill 用超图把三问统一在一个数据结构里；LycheeMemory 用"固化粒度"这一个杠杆同时压成本和保精度；RippleMem 把检索从"一次查询"变成"锚点扩散过程"。共同信号：记忆设计从组件优化转向系统协同。

主线二：Harness 即记忆的载体（Evo-Harness + JERP）

Evo-Harness 的"在线 harness 学习"和 JERP 的"规则池-策略联合学习"本质是同一件事的两种表述：把经验固化成模型外结构（skill/规则），并让这个结构与模型行为保持同步。JERP 特别指出了脱节风险——规则池如果不同步更新，会从资产变成负债（过时规则误导决策）。这对 Hermes skill 体系的直接警示：skill 不维护就贬值（skill-review 机制的存在意义获得了学术背书）。

主线三：成本意识进入记忆设计核心（LycheeMemory + Harness the Memory）

LycheeMemory 的 86% token 节省与 Harness the Memory 的 26 指标评测共同宣告：记忆系统不能只比准确率。建图成本（RippleMem 降 30 倍）、构建 token（分段固化省 86%）、检索开销对决策的伤害（过度检索转移注意力）都进入设计空间。"基底路由"概念——按任务 regime 动态选择记忆介质——是下一阶段的方向。

趋势判断

  1. "冻结模型 + 进化 harness"成为主流自进化范式。Evo-Harness 与 JERP 都不动模型参数，只进化外部结构。这与"模型能力商品化、差异化在 harness 层"的产业判断一致——Hermes 的 skill 体系押注正确。
  2. 记忆的固化粒度是新的设计轴。LycheeMemory 证明逐轮固化 vs 分段固化的差异是 86% token——粒度选择比"存什么"对成本影响更大。
  3. 检索过度会伤害行动。Harness the Memory 的反直觉发现：宽检索利于 QA 但伤决策——agent 场景的记忆检索要窄而准，不是宽而全。这解释了为什么"全量记忆注入"的 agent 反而变笨。
  4. 认知科学概念持续输血。RippleMem 的线索依赖检索/联想补全、TrustTrade 的认识论启发——2026 年的 agent 记忆论文大量借用 40 年前的认知心理学概念，且都有效。
  5. 评测基准收敛。LoCoMo/LongMemEval 成为记忆系统标配基准（四篇中三篇用），GAIA 成为 agent 能力标配——后续跟进这两个基准的论文即可。

拓展应用：可落地清单

  1. MEMORY 固化改分段批处理（LycheeMemory 思想）：目前 MEMORY.md 每会话末压缩；可改为"攒 N 个会话→语义分段→一次固化"，预期砍掉大部分压缩调用 token。配合现有的 8000 字符上限机制。
  2. 技能组合关系图谱（HyperSkill 思想）：给 skill 加 composes_with/depends_on frontmatter 字段，构建任务时按图检索技能链而非单点匹配。先在量化域试点（iron-rules ← backtester ← param-lab 已是事实上的技能链）。
  3. skill-review 加"行为脱节检测"（JERP 思想）：回顾时不只看 skill 是否过时，还看"最近会话的实际做法是否已偏离 skill 描述"——偏离即触发修订。可复用 session_search 做偏差检测。
  4. memorygraph 加锚点扩散检索（RippleMem 思想）：现有 recall 是向量检索 + 一跳关系；可加二跳扩散——从命中的记忆沿关系边扩一圈，找回相关联的分散证据。数据结构已备，只差查询逻辑。
  5. 不做参数化更新路线（Harness the Memory 结论）：确认继续走"冻结模型+外部结构进化"路线，不引入需要训练的记忆机制——与 Jetson 资源约束一致。

查询拓展：未覆盖的延伸方向

  • HyperSkill 的技能粒度定义：摘要未说明"可复用技能"如何从轨迹中切分（步骤级/模式级/工作流级），细节需读正文——影响 skill 图谱设计的最小单元选择。
  • Evo-Harness 的 harness 具体格式：五基准验证但摘要未给 harness 的结构定义（YAML/代码/自然语言？），跟进 github.com/A-EVO-Lab/a-evolve 源码确认。
  • LycheeMemory 语义边界检测算法：分段边界的判定标准（话题转移/时间间隔/语义相似度阈值）未披露，这是复现的关键。
  • 记忆基准与 agent 基准的交叉验证缺失：四篇记忆论文均未在"真实长程工作流"（如多日项目开发）上验证，LoCoMo/LongMemEval 仍是对话 QA 型基准——与 Hermes 的运维型记忆需求有差距。
  • A-Mem/MemGPT 等前代基线对比：本批论文的基线多为 2025 年系统，Hermes 所用的 memorygraph（属性图+关系）与 HyperSkill 超图的工程权衡差异值得单独研究。

关联分析：与既有笔记/体系的联动

  • 与 Hermes skill 体系直接映射：Evo-Harness 的"在线 harness 学习"就是 auto-skill/evolver 机制的学术表述——本笔记验证了 skill 路线的正确性，同时指出缺口（单次执行的噪声过滤）。
  • 与 SKILL 增量队列问题的呼应：JERP 的"规则池与行为脱节会从资产变负债"，正是 read-gate 死锁导致 SKILL.md 指针长期积压的学术版警示——积压的增量指针就是脱节的规则。
  • 与 evolver/experience-bank 机制对照：HyperSkill 的超图组合关系 vs 现有 experience-bank 的平面卡片组织——可学到的点第 2 条（组合关系图谱）是直接改进方向。
  • 与 memory-consolidation skill 的关系：LycheeMemory 分段固化思想可注入该 skill 的 L1/L2/L3 审计流程——"攒段再固化"替代"每会话压缩"。
  • 与 quant 笔记的交叉：EvoTS-Agent（金融变点检测自进化）横跨两篇笔记——其三算子模式在 Agent 记忆笔记的 Evo-Harness 与量化笔记的 param-lab 中都有对应改进建议，是两主题的交汇点。

指南分析：方法论收获

  • 一次执行也要能学习：Evo-Harness 的核心约束是"one-shot opportunity"——不是所有环境都给你重试。Hermes 的 skill 提炼也应假设"这个会话只发生一次"，从中提取的教训必须立即结构化。
  • 噪声与信号分离是编译核心：context-to-harness 编译最难的不是提取，而是把"普遍教训"从"任务特定杂质"中分离。实践中可用"这个教训适用于 ≥2 个不同任务吗"作为过滤判据。
  • 评测要按 regime 分层报告：Harness the Memory 的教训——平均分掩盖 regime 差异，"哪种基底在哪种场景赢"比"谁平均分高"有用。任何对比实验（如策略参数对比）都应分 regime 报告。
  • 认知科学是设计模式库：遇到记忆/检索/遗忘问题，先查认知心理学的对应机制（情节记忆/工作记忆/间隔重复/线索回忆），大概率有现成设计可借鉴。

可学到的点

  1. 记忆三问（存什么/怎么取/怎么进化）必须联答（HyperSkill：单点优化会被另外两问吃掉收益）
  2. 固化粒度是被低估的成本杠杆（LycheeMemory：分段固化省 86% token 且不掉点）
  3. 检索要窄而准，宽检索伤决策（Harness the Memory：注意力是稀缺资源）
  4. 规则/harness 与行为脱节会从资产变负债（JERP：同步更新是硬需求）
  5. 锚点扩散找回分散证据（RippleMem：最初召回的记忆是进一步检索的线索）
  6. 冻结模型+进化 harness 是资源受限下的正确路线（Evo-Harness：五基准验证，模型参数不动）
