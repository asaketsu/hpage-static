# AI Agent 自进化架构前沿（2026-06）

> 三篇 arXiv 最新论文精读，揭示自进化 Agent 从「自动执行」到「自我改进」的关键架构跃迁。核心洞察：**进化不能只进化 Agent 本身，必须同步进化评估器和监督信号**。

## 一、AgentX：生产级自进化开发引擎

**出处**：arXiv 2606.26859（腾讯推荐系统团队，2026-06-25）

### 问题定义

推荐算法迭代正从「工匠式人工流程」转向「工业化研究循环」，但存在结构性瓶颈：idea→launch 周期仍依赖人类工程师完成假设生成、生产代码修改、A/B 实验上线、效果归因。**创新因此与团队规模线性增长，而非与算力、证据、累积知识复利增长**。

### 架构：四阶段闭环

```
Brainstorm Agent → Developing Agent → Evaluation Agent → Harness Evolution (SGPO)
     ↑                                                              ↓
     └──────────────────── 知识资产回流 ←─────────────────────────────┘
```

1. **Brainstorm Agent（头脑风暴）**：融合历史实验、系统架构、数据分析、外部研究，生成可执行的排序提案。
2. **Developing Agent（开发）**：通过仓库感知代码生成（repository-grounded generation）将提案转为生产级代码，并做多维可靠性验证。
3. **Evaluation Agent（评估）**：安全灰度上线 + 护栏否决式 A/B 判定，**成功和失败都转为结构化知识资产**。
4. **Harness Evolution 层（SGPO）**：将执行轨迹蒸馏为语义梯度更新（semantic-gradient updates），持续磨砺 Agent 自身——使系统不仅自动化，而是**自我改进**。

### 关键创新点

- **Harness Evolution（SGPO）**：不是简单记录成功/失败，而是把**完整执行轨迹**提炼为对 Agent 提示/参数的梯度方向更新，类似「让 Agent 从自己的执行历史中学习」。
- **护栏否决（guardrail-vetoed）**：A/B 判定有安全护栏一票否决权，避免自进化系统为追求指标而做出危险变更。
- **失败即资产**：失败实验同样进入知识库，这与传统「只学成功」的范式根本不同。

### 对 Hermes Evolver 的直接启发

当前 Evolver 是「错误模式→规则沉淀」的单向链路。AgentX 揭示了三个缺失环节：
- **缺少 Evaluation 闭环**：Evolver 沉淀经验后，没有自动验证「新规则是否真的改善了后续任务」。
- **缺少 Harness Evolution 层**：没有把执行轨迹蒸馏为对 Skill 提示的语义更新。
- **护栏否决机制**：自进化必须有安全闸门，防止 Skill 退化。

## 二、Red Queen Gödel Machine：Agent 与评估器协同进化

**出处**：arXiv 2606.26294（2026-06-24）

### 核心洞察

> 自改进 Agent 普遍假设评估标准是静止的——固定的验证器、固定的 benchmark、固定的标注集。但这忽略了进化的核心特征：**物种随环境改变而适应**。

论文标题借用「红皇后假说」（爱丽丝梦游仙境）：你必须不断奔跑才能留在原地——评估标准必须随 Agent 能力提升而进化。

### RQGM 框架

**受控效用进化（Controlled Utility Evolution）**：
- 搜索组织为**纪元（epoch）**，每个纪元内评估标准固定，自改进保证在纪元内成立。
- 在纪元边界，**效用函数（utility）可被更新**，于是自改进在目标演化过程中分纪元保持有效。

### 实验结果

| 场景 | 提升 |
|------|------|
| 可验证编码任务 | 测试通过率超 SOTA，且 token 用量减少 1.35-1.72x（agent-as-judge 信号更便宜） |
| 科研论文写作/评审 | 协同进化的写手接受率达 1.78-1.86x，协同进化的评审者准确率高 9% |
| AI 论文过度接受问题 | 最强基线评审者对 AI 生成论文的接受率是人类 1.91x；RQGM 引入对抗目标后纠正 |

### 最关键教训

基线评审者**过度接受 AI 生成论文（人类率的 1.91 倍）**。这意味着：**如果评估器不进化，自改进的 Agent 会学会钻评估器的空子**——产出看似高分实则低质的内容。RQGM 用对抗目标迫使评审者对 AI 和人类工作一视同仁。

### 对 Skill 审查体系的警示

当前 Hermes 的 Skill 审查/质量门禁如果长期不变，自进化的 Skill 会逐步「过拟合」审查规则——产出形式合规但实际无价值的内容。对策：**定期更新审查标准，引入对抗性测试用例**。

## 三、OPID：在线策略技能蒸馏

**出处**：arXiv 2606.26790（2026-06-25），代码开源 https://github.com/jinyangwu/OPID

### 问题

基于结果的强化学习（outcome-based RL）提供稳定优化骨架，但**稀疏的轨迹级奖励**无法指导中间决策该强化还是抑制。在线自蒸馏提供密集的 token 级监督，但现有技能条件变体依赖外部技能记忆库或检索式特权上下文，维护成本高且与当前策略的状态分布不匹配。

### OPID 双层技能表示

```
完整在线轨迹
    ↓ 提取
┌─────────────────────────────────┐
│ Episode-level skills（全局）      │ → 工作流模式 / 失败规避规则
│ Step-level skills（局部）         │ → 关键时间步的局部决策知识
└─────────────────────────────────┘
    ↓ 路由
Critical-first routing：
  检测到关键决策 → 用 step-level
  否则 → 回退 episode-level（默认）
    ↓ 注入交互历史
  在原始 + 技能增强 两种上下文下重新评分同一采样响应
    ↓ log-prob 差
  Token 级自蒸馏优势 + outcome 优势 → 策略优化
```

### 关键创新

- **不依赖外部技能库**：技能直接从**已完成的在线轨迹**中提取，避免维护成本和分布不匹配。
- **关键优先路由（critical-first routing）**：只在检测到关键决策点时调用细粒度的 step-level 技能，否则用粗粒度 episode-level，平衡精度与开销。
- **保留 RL 为主目标**：自蒸馏只是补充密集监督，不取代 outcome RL，保证训练稳定性。

### 实验验证

ALFWorld（具身 household）、WebShop（网购）、Search-based QA 三大基准上，OPID 在性能、样本效率、鲁棒性上普遍优于纯 outcome RL 和已有技能蒸馏基线。

## 四、对 Hermes 自进化体系的综合改进建议

### 🟢 P0（高价值、低成本）

1. **给 Evolver 补「Evaluation 闭环」**：每条沉淀的经验/规则，在后续任务中自动追踪「是否真正减少了同类错误」。用日志统计 before/after 错误率，规则无效则自动标记降级。
2. **Skill 审查标准定期对抗更新**：参照 RQGM，每月引入一批「对抗性测试用例」（故意写差的 Skill、形式合规但无价值的 Skill），检查审查机制能否拦截。

### 🟡 P1（中价值、中成本）

3. **双层技能记忆**：借鉴 OPID，将 Skill 库分为 episode-level（项目级工作流）和 step-level（单步关键决策），并实现 critical-first 路由，避免每次都检索全部技能。
4. **失败即知识**：参照 AgentX，明确把失败任务/失败实验也结构化入库，目前 Evolver 主要从错误沉淀，但「成功路径上的失败分支」信息未被利用。

### 🔵 P2（探索性）

5. **Harness Evolution 原型**：尝试把一段时间的执行轨迹蒸馏为对 Skill 提示词的语义梯度更新，作为 Evolver 的下一代能力。
