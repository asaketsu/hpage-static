内容整理

1.1 核心问题：记忆是死的，技能是活的

现有 Agent 记忆系统（事实记忆/experiential 记忆）检索到的历史轨迹只是被动上下文——Agent 每次都要重新推理一遍。典型症状：

  • 重复装同一个插件 N 次，每次都重新摸索 manifest 检查→依赖解析→注册→reload→可用性验证的流程
  • 反复探索同一个仓库，每次仍要重新 ls 找测试/配置/构建脚本的位置，token 白烧
  • 直接从原始轨迹蒸馏技能又不行：轨迹充满失败尝试、盲区探索、环境特异性噪声，且终局反馈稀疏延迟，步骤级 credit assignment 不确定——蒸出来的技能脆弱、过拟合、在不该触发的场景乱触发

MSCE 的答案：不做轨迹→技能的直接蒸馏，插入一个受治理的三层记忆中间层，技能只能从记忆中"晋升"出来。

1.2 三层记忆架构（核心贡献一）

层级 存储内容 形式化 角色
L1 Trace Memory 步骤级接地决策单元 f⁽¹⁾=(s,a,o,ρ,V)——语义状态/动作/观察/自反思/轨迹价值 证据层：所有上层记忆和技能必须保留指向 L1 的链接，可追溯
L2 Policy Memory 跨 episode 归纳的可复用程序性策略 f⁽²⁾=(ϕ,π,κ,B,{f⁽¹⁾})——触发条件/自然语言流程/验证回退规则/适用边界/支撑证据集 程序层：可修订的内部抽象
L3 Environmental Cognition 环境级声明式认知 f⁽³⁾=(E,I,C,{f⁽²⁾})——实体结构事实/动作-响应规律/环境约束 环境层：描述环境如何组织（如"这个仓库是 npm 项目"）

关键设计：
- L1 不持久化无界原始观察——只存归一化证据（截断状态文本/动作文本/结构化工具调用元数据/限长输入输出），上层只存 evidence id 不复制原文 → 控制存储 + 降隐私风险
- L2 归纳有门槛：同一确定性模式签名桶内至少 n_min 个不同 episode 的证据才触发归纳，杜绝单例过拟合
- L3 抽象的 prompt 禁止祈使句程序性指令（Πenv 强制 declarative only），保证 L3 是"环境认知"而非"技能副本"；证据走弱时降低置信度与检索优先级，低置信认知保留审计但排除出默认检索

1.3 技能结晶与调用（核心贡献二）

技能 k=(ϕ,π,κ,B,A,D,η) 继承 L2 的触发/流程/验证/边界，新增证据锚点 A、决策指导 D（preferences+anti-patterns）、可靠性 η。

晋升双门槛：
1. 正增益：G(f⁽²⁾) = V̄_with − V̄_blend(S_without) > θ_G（|S_with|≥3 时用 softmax 加权均值，否则算术均值；without 侧向基线收缩）
2. 稳定性：近期证据与当前 ϕ/π/B 吻合，而非强迫大幅改写

确定性校验器（技能入库前）：schema 校验（名称/前置条件/有序步骤/示例/工具清单/决策指导字段）→ 证据接地（引用的 evidence id 必须在支撑集内，声明的工具必须在证据观察到的白名单内）→ 覆盖测试（不得发明未支撑的命令、不得偏离保留的轨迹证据）。任何一条不过 = 丢弃，绝不入库。

部署后可靠性：η = (n_pass+1)/(n_trial+2)（Laplace 平滑成功率）。用户纠错/拒绝 → η 降 + 边界 B 收缩；连续成功 → η 升。高 η 进主动检索，低 η 留察或归档。调用时 L3 认知做参数实例化（如装依赖技能根据 L3 判断是 Alpine/Debian/macOS 选不同包管理器命令），技能失败则回退 L1 检索。

1.4 反思加权价值回填（核心贡献三）

不更新基座 LLM，只更新外部认知状态 C=(M⁽¹⁾,M⁽²⁾,M⁽³⁾,K)。双信号：
- 稠密步级自反思 ρ（每步都有，但可能噪声/不忠实）
- 稀疏终局反馈 R（episode 结束才有，文本反馈先量化为标量）

回填把稀疏终局值沿轨迹传播，用每步反思做加权校准 → 得到证据校准的轨迹值 V，统一驱动检索/策略归纳/环境抽象/技能晋升/后续修订。

1.5 实验结论

EvoAgentBench + LoCoMo 双基准 SOTA，超过 skill-augmented 与 memory-driven 两类基线；展现跨域迁移与终身进化增益（lifelong-evolution）。

查询拓展

2.1 与并发工作的差异化定位

系统 思路 与 MSCE 差异
MemSkill 把记忆操作本身重构为技能 MSCE 分离记忆与技能，用证据锚点+价值信号链接，晋升成为受治理问题
ProcMEM 技能池即程序性记忆 同上——"什么成为技能/何时适用/如何修订退役"是显式治理流程
直接蒸馏系（SkillFlow/EvoSkill/SkillRL/SAGE） 轨迹→技能蒸馏 + RL 优化 未经治理的噪声轨迹蒸出脆弱过程；MSCE 先治理记忆再晋升

2.2 与本机 Hermes 体系的同构映射（最高价值部分）

MSCE 概念 本机对应物 差距
L1 trace（带 V 值的接地单元） error-case-library（EC 案例）+ session 历史_raw EC 无价值标注 V；session trace 未归一化
L2 policy（ϕ/π/κ/B+证据集） experience-bank 经验卡片 经验卡缺 κ 验证规则与 B 适用边界字段
L3 environmental cognition MEMORY.md / USER.md 已有雏形，但无"证据弱→降置信"衰减机制
Skill 结晶 + 确定性校验器 skill_manage + curator adopt curator 已有人工门禁；缺自动 schema/证据接地/工具白名单三重校验
可靠性 η 平滑成功率 无 全缺——skill 无成功/失败计数与降级退休
反思加权价值回填 agent-reflection（双轨反思） 有反思无价值传播回填

归纳总结

MSCE 一句话：记忆管证据，技能管执行，晋升靠双门槛（正增益+稳定性），入库过三验
（schema/证据接地/工具白名单），退役靠 η 平滑成功率。

治理公式：噪声轨迹 → L1 接地(带V) → L2 归纳(≥n_min跨episode) → 双门槛 → 校验器
→ Skill(带A/D/η) → 部署反馈 → η 升降 → 检索/降级/归档

三个最可抄的设计：① 证据锚点链（任何上层抽象可回溯到 L1 具体交互）② 工具白名单校验（技能声明的工具必须在证据里出现过，防幻觉命令）③ η=(pass+1)/(trial+2) 的平滑退役机制。

趋势判断

趋势：Agent 记忆研究从"存取效率"转向"记忆→能力转化治理"

依据：TMLR 2602.06052（Agent Memory in the Second Half 综述）把 self-evolving/long-horizon 定为"下半场"主题；MSCE/MemSkill/ProcMEM 三个并发工作同时收敛到 memory-skill 融合；ICML 2026 有 5 篇 agentic memory 论文。检索增强（怎么取）已是存量竞争，能力转化（怎么变成可调用资产）是增量方向。

趋势：training-free 是工程落地主航道

MSCE 全程不更新基座 LLM，只治理外部认知状态——与本机 Hermes 的 skill/memory/cron 外挂体系同一哲学：进化发生在模型外围，可控可审计可回滚。

拓展应用推荐

  1. experience-bank 补字段（P1，低成本）：经验卡片 schema 增加 verification（κ）、boundary（B）、evidence_ids（A）、reliability（η 四则运算）四字段，写入时强制
  2. error-case-library 价值标注：EC 条目增加复盘结论 V（该案例带来的修复是否复用成功），用于排序而非全量检索
  3. skill 退休机制：为 curator 增加 η 计数器——连续 3 次调用失败自动降级为 probation 并提示人工审查，替代纯人工回顾
  4. 本 cron（夜间自学习）的闭环校准：学习笔记如果 7 天内无引用/无关联，降低该主题的再嗅探优先级（L3 置信衰减的直接应用）

指南分析

质量：★★★★★——形式化干净（每层记忆/技能/增益都有元组定义与公式）、治理机制可操作（阈值+校验器+η 全部可实现）、诚实标注 G 是启发式信号而非因果效应估计。局限：实验仅 EvoAgentBench/LoCoMo 两基准；η 冷启动依赖初始调用次数；文本反馈量化为标量的机制在附录，鲁棒性未充分讨论。
