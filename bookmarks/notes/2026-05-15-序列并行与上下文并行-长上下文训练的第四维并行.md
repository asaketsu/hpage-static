## 摘要

序列并行（Sequence Parallelism / Context Parallelism）是继 DP/TP/PP 三维并行之后的第四维并行策略，专门解决长上下文训练中注意力 O(n²) 计算和显存瓶颈。本文深入分析六大前沿方法：Ring Attention（环形块状计算，无限序列长度）、DeepSpeed Ulysses（注意力头并行，all-to-all 通信）、USP 统一框架（混合 Ulysses + Ring）、StarTrail（同心环多维并行，GPT 模型提速 77.12%）、TSP 折叠并行（同时分片权重和序列，2.6x 吞吐）、以及 AutoSP（编译器自动化 SP）。还覆盖了 ZeCO（线性注意力零通信开销）、Untied Ulysses/UPipe（逐头分块省 87.5% 显存）和 HelixPipe（注意力并行流水线）等重要工作。长上下文模型（DeepSeek-V3 128K、Gemini 2M）已将序列并行从可选优化变为训练必需基础设施。

## 核心内容

### 一、问题根源：为什么需要第四维并行

标准 Transformer 注意力计算复杂度 O(L²·d)，其中 L 是序列长度。随着上下文从 4K（GPT-3.5）→ 128K（Llama 3）→ 1M（Gemini 1.5 Pro / Qwen 2.5-1M）→ 2M（Gemini 2.5 Pro），注意力显存和计算量呈二次增长：

- 70B 模型 128K 序列：单层注意力需要 ~128GB 显存（KV cache + attention matrix）
- 1M token 训练：超出任何单卡 H100 80GB 的承载能力

传统的三维并行（DP + TP + PP）无法解决：
- **DP**：每卡持有完整序列，序列太长直接 OOM
- **TP**：切分权重，但不切分序列长度（激活值仍然完整）
- **PP**：按层切分，每层的注意力仍然是完整序列

因此需要在**序列维度**上进行切分，这就是序列并行/上下文并行的核心动机。

### 二、两大基础范式：Ring Attention vs DeepSpeed Ulysses

#### 2.1 Ring Attention — 环形块状计算

论文：*Ring Attention with Blockwise Transformers for Near-Infinite Context*（Liu et al., 2023）

核心思想：将长度为 L 的序列均分到 N 张 GPU，每张持有 L/N 的 Q、K、V 片段。GPU 排成逻辑环（Ring），通过 N 轮迭代完成完整注意力计算。

工作机制（以 4 张 GPU 为例）：
1. 初始：GPU_i 持有 Q_i, K_i, V_i（各 1/4 序列）
2. 每轮：GPU_i 用本地 Q_i 与当前持有的 K、V 计算局部注意力，同时将 K、V 传递给下一 GPU
3. 经过 4 轮迭代，每张 GPU 都看到了全部 K、V，得到正确的注意力输出

关键技术：利用 FlashAttention 的 online softmax 数值稳定性技巧：
```
l_{j+1} = l_j · e^{m_j - m_{j+1}} + Σ_k e^{q_x · k^{(j+1)}/√d - m_{j+1}}
O_{j+1} = (O_j · l_j · e^{m_j - m_{j+1}} + Σ_k e^{...} · v_k^{(j+1)}) / l_{j+1}
```

优势：序列长度无理论上限（只需更多 GPU）；通信与计算可重叠
劣势：P2P 通信量与 GPU 数 N 和序列长度 L 成正比，跨节点带宽瓶颈严重

#### 2.2 DeepSpeed Ulysses — 注意力头并行

论文：*DeepSpeed Ulysses: System Optimizations for Enabling Training of Extreme Long Sequence Transformer Models*（Jacobs et al., 2024）

核心思想：沿**注意力头（attention heads）维度**切分。每张 GPU 持有完整序列但只有 H/N 个注意力头。

工作机制：
1. 初始：GPU_i 持有完整的 Q、K、V，但只有第 i 组注意力头
2. 通过 all-to-all 通信交换序列分片 → 变为每卡持有 L/N 的序列但拥有全部注意力头
3. 本地计算注意力（每头独立，无需通信）
4. 再次 all-to-all 通信恢复原始分布

通信模式：两次 all-to-all（不是环形 P2P）
通信量：4·L·d_model（与 GPU 数无关！）

优势：通信量不随 GPU 数增长；实现简单
劣势：**受注意力头数限制** — GPU 数不能超过注意力头数 H。Llama 3 8B 有 32 头，最多 32 张 GPU 做序列并行

### 三、USP 统一框架 — 混合两全其美

论文：*USP: A Unified Sequence Parallelism Approach for Long Context Generative AI*（Fang & Zhao, 2024, arXiv:2405.07719）

核心贡献：将 Ulysses 和 Ring Attention 统一到同一框架。用记号 U_xR_y 表示：
- x = Ulysses 组大小（头维度切分数）
- y = Ring 组大小（序列维度环大小）
- 总 GPU 数 P = x × y

配置示例：
- U_4R_1 = 纯 Ulysses（4 头并行，无环）
- U_1R_4 = 纯 Ring Attention
- U_2R_2 = 混合（2 组头并行 × 2 节点环形）

工程价值：一个框架覆盖所有配置，根据硬件拓扑（NVLink 节点内 + 跨节点网络带宽）选择最优组合。已在 HuggingFace Accelerate、TRL SFTTrainer 中集成。

### 四、StarTrail — 同心环多维并行（NeurIPS 2025）

论文：*StarTrail: Concentric Ring Sequence Parallelism for Efficient Near-Infinite-Context Transformer Model Training*（NeurIPS 2025 Poster）

核心创新：引入额外并行维度 C（team size），将 P2P 通信拆成子环，大幅降低跨节点通信。

工作原理：
- C 张 GPU 组成一个"团队"，团队内部用 Ulysses 式 all-to-all
- 团队之间用 Ring Attention 式 P2P，但每个 GPU 只与 P/C² 个其他 GPU 通信
- P2P 通信量减少约 C 倍

实测性能：
- **GPT 模型：提速 77.12%**
- **DiT（Diffusion Transformer）：提速 114.33%**
- 覆盖 NLP 和 CV 任务，适用性广
- 不受注意力头数限制（克服 Ulysses 短板）

### 五、TSP — 折叠张量与序列并行（Zyphra, 2026）

论文：*Folding Tensor and Sequence Parallelism for Memory-Efficient Transformer Training & Inference*（arXiv:2604.26294, April 2026）

核心创新：**将 TP 和 SP 折叠到同一设备轴**。每个 GPU 同时持有权重分片和序列分片，单一设备轴实现 1/D 的参数显存 + 1/D 的激活显存。

关键突破：
- 之前：TP 减参数但不减激活，SP 减激活但不减参数。TP+SP 需要二维设备布局（不同轴分别负责）
- TSP：一个轴同时负责，每个 rank 持有权重分片 + 序列分片
- 是唯一在单一设备轴上同时降低权重显存和激活显存的方案

实测数据（1024 × AMD MI300X）：
- **128K 序列长度，D=8：TSP 173M tokens/sec vs TP+SP 66M tokens/sec → 2.6x 吞吐**
- 显存：TSP 38.8 GB/GPU vs TP+SP 85-140 GB/GPU（128K 序列）
- 支持 16K~128K 各种序列长度，显存优势一致

适用场景：长上下文 + 显存受限（如 AMD MI300X 192GB HBM3 虽大但模型也大）

### 六、AutoSP — 编译器自动化序列并行（PyTorch 官方, 2026）

论文：*AutoSP: Unlocking Long-Context LLM Training Via Compiler-Based Sequence Parallelism*（arXiv:2604.27089, April 2026）

核心贡献：**全自动将普通训练代码转为序列并行代码**，用户只需 import + compile。

技术路线：
- 在 Torch IR 层面实现编译器 pass
- 自动识别注意力层，插入序列并行通信原语
- 自动生成长上下文友好的 activation checkpointing 策略
- 集成 DeepSpeed，兼容 ZeRO

实测性能：
- **NVIDIA GPU：可训练上下文长度提升 2.7x**
- **AMD GPU：提升 2.5x**
- 运行时开销极小（negligible throughput loss）

工程价值：降低了 SP 的工程门槛。之前需要手写 Ulysses/Ring Attention 通信逻辑，现在编译器自动完成。

### 七、其他重要工作

#### ZeCO — 线性注意力零通信开销（NeurIPS 2025）
- 专为线性注意力模型设计（非标准 softmax attention）
- 通信量：D·e（仅与设备数和元素大小有关，不随序列长度增长！）
- 对比：Ulysses 需要 4LD，Megatron CP 需要 2PLD
- 适用场景：Mamba/RWKV/RetNet 等线性注意力架构

#### Untied Ulysses / UPipe — 逐头分块省显存（arXiv:2602.21196, Feb 2026）
- 在注意力头维度上做更细粒度的分块（headwise chunking）
- 中间张量显存减少 **87.5%**（32B Transformer）
- Llama3-8B 单节点 8×H100 可训练 **5M token 上下文**（比之前方法提升 25%+）
- 速度与现有方法持平

#### HelixPipe — 注意力并行流水线（arXiv:2507.00394, Jul 2025）
- 将序列并行与流水线并行结合
- 注意力并行分区：不同 micro-batch 的注意力计算跨流水线阶段并行
- 二折 FILO micro-batch 调度：平衡显存 + 通信计算重叠
- 解决长序列下 PP 气泡和显存膨胀问题

## 关键概念

- **Sequence Parallelism (SP)**：序列并行，将序列维度切分到多个 GPU。Megatron SP 只切非矩阵乘法操作（LayerNorm、Dropout），与 TP 配合使用
- **Context Parallelism (CP)**：上下文并行，将所有层的序列维度切分（包括注意力），通信与计算重叠。Megatron-LM 和 NeMo 框架中的叫法
- **Blockwise FlashAttention**：分块计算注意力，将 O(L²) 显存降为 O(L)，是 Ring Attention 的数学基础
- **Online Softmax**：逐块累积 softmax 归一化常数，避免一次性加载全部注意力矩阵
- **All-to-All Communication**：全互联通信，每对 GPU 之间交换数据。Ulysses 的核心通信原语
- **NVLink vs 跨节点网络**：NVLink 节点内带宽 900 GB/s，跨节点 InfiniBand 通常 50-100 GB/s。SP 方案设计必须考虑这个差距

## 能力边界

1. **Ring Attention 跨节点瓶颈**：P2P 通信在跨节点场景下延迟高，低带宽环境下性能退化严重
2. **Ulysses 头数限制**：32 头的模型最多 32 张 GPU 做序列并行，对超大规模训练不够灵活
3. **TSP 通信开销**：折叠策略增加了通信量，在通信带宽充足的 NVLink 节点内表现最好
4. **AutoSP 覆盖范围**：编译器 pass 目前支持标准 Transformer 架构，自定义注意力变体可能不兼容
5. **ZeCO 仅限线性注意力**：标准 softmax attention 模型无法使用
6. **所有方案都需要足够 GPU 数量**：序列并行度 = GPU 数量，128K 训练通常至少需要 8 卡

## 最佳实践

1. **混合配置优先**：用 USP 框架的 U_xR_y 配置，节点内 Ulysses（NVLink 高带宽 all-to-all），跨节点 Ring（减少跨节点通信量）
2. **与 TP/PP/DP 正交组合**：SP 是独立维度，与三维并行无冲突。典型 4D 并行：TP=4(节点内) + CP=2(跨节点序列) + PP=2 + DP=剩余
3. **Activation Checkpointing + SP**：长上下文训练中两者配合使用效果最佳，AutoSP 已自动处理
4. **GQA/MQA 减少通信**：分组查询注意力（GQA）和多头查询注意力（MQA）减少 KV 头数，Ring Attention 通信量相应降低
5. **先 profiling 后选方案**：不同硬件拓扑（NVLink/IB 数量、带宽比例）下最优 SP 配置差异大
