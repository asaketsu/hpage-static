## 一、核心发现

### 发现 1: 多 Agent 系统的时序-结构信用归因统一框架

**论文**: "Unifying Temporal and Structural Credit Assignment in LLM-Based Multi-Agent Prompt Optimization" (arXiv:2605.30227, 2026-05-28)

**核心问题**: 多智能体系统 (MAS) 的优化面临两个根本挑战——离散不可微的计算图和稀疏的全局监督信号。现有黑盒优化器无法将轨迹级失败归因到特定局部组件，导致低效、高方差探索。

**创新方案**: 提出**时序信用归因 + 结构信用归因**双轴分解：

- **时序信用 (Temporal Credit)**: 使用状态空间瓶颈 (State-Space Bottlenecks) 识别关键轮次。核心思想是：不是所有对话轮次同等重要，某些轮次是"转折点"，错误在这里发生会导致后续全部失败
- **结构信用 (Structural Credit)**: 使用平稳角色策略 (Stationary Role Policies) 隔离各 Agent 贡献。通过固定其他 Agent 的策略，单独评估一个 Agent 改变后的影响

**算法**: 离散化语言化块坐标下降 (Discrete Verbalized Block Coordinate Descent)
- 不做全局更新，而是交替优化"角色 prompt"和"聚合协议"
- 使用 LLM 生成的"代理梯度"(Proxy Gradients) 精准定位薄弱环节
- 显著降低查询复杂度同时提升性能

**与 Hermes Agent 的映射**:
- Hermes 的 Skill 系统本质上是"角色策略"
- Skill 的 patch/edit 操作类似于"块坐标下降"——每次只修改一个 Skill
- 当前的"进化日志"是朴素的信用归因（记录哪个 Skill 改了什么），但缺乏时序维度的分析

### 发现 2: Agent 自进化基准 — PTCG-Bench 的启示

**论文**: "PTCG-Bench: Can LLM Agents Master Pokémon Trading Card Game?" (arXiv:2605.29653, 2026-05-28)

**核心发现**:
- LLM Agent 在复杂策略环境中能达到"非平凡"的游戏表现
- 但**持续稳定的自进化仍然是一个开放问题**
- Agent 性能高度敏感于 **Harness 设计**（即 Agent 与环境交互的接口层）

**Harness 感知 (Harness-Aware)**:
- 论文引入"模块化 Harness 消融"(Modular Harness Ablation) 来分离 Agent 能力和接口设计的影响
- 同一 Agent 在不同 Harness 下性能差异显著
- 这验证了 AGENTS.md 中的 Harness Engineering 准则的必要性

**对 Hermes 的启示**:
- Skill 的"触发条件"定义就是 Harness 设计
- 触发条件过于宽泛 → Agent 在不合适的场景被激活
- 触发条件过于狭窄 → Agent 无法在需要时被调用
- 需要像 PTCG-Bench 那样做"Skill 消融实验"——逐个禁用 Skill 看系统整体性能变化

### 发现 3: 金融 LLM 合规检测 — FinGuard

**论文**: "FinGuard: Detecting Financial Regulatory Non-Compliance in LLM Interactions" (arXiv:2605.29427, 2026-05-28)

**核心贡献**:
- 基于 Qwen3-8B 通过 SFT + 自博弈 RL 训练的金融合规检测模型
- 在 FinGuard-Bench 上**大幅超越所有基线**，包括 Qwen3.5-397B-A17B 和 GPT-5.1
- 证明：小模型 + 领域特定 RL > 大模型通用安全能力

**技术细节**:
- 管线直接基于监管文档，诱导金融合规风险分类体系
- 合成基于监管的训练数据，无需预定义违规类别
- 自博弈 RL：让模型生成对抗样本并自我进化

**量化交易相关性**:
- 金融 AI 系统的合规性是实际部署的硬性要求
- FinGuard 的"监管文档 → 分类体系 → 合成数据 → SFT+RL"流水线可作为量化交易系统的合规层模板

### 发现 4: LLM 交易 Agent 的知识污染与评估陷阱

**论文**: "From Knowing to Doing: A Memory-Controlled Benchmark for LLM Trading Agents on Stock Markets" (arXiv:2605.28359, 2026-05-27)

**核心问题**:
1. **知识截断污染**: 长回测区间与前沿 LLM 的知识截止日期重叠，允许模型用"记住的"价格和事件替代投资推理
2. **原始回报率是噪声代理**: 股票选择能力的真正度量需要控制市场 beta、行业暴露、风险因子

**解决方案**: Memory-Controlled Benchmark
- 控制 LLM 的记忆访问（限制其使用训练数据中的价格信息）
- 使用因子调整后的 Alpha 而非原始回报率评估

**关键洞察**: 当控制了知识污染后，LLM 交易 Agent 的表现大幅下降——说明当前很多"LLM 能交易"的结论可能是幻觉

### 发现 5: 时序增强 LLM 统一预测与推理 — StockR1

**论文**: "Reasoning through Verifiable Forecast Actions: Consistency-Grounded RL for Financial LLMs" (arXiv:2605.21975, 2026-05-21)

**核心创新**: StockR1 — 时序增强 LLM，统一股票预测和推理

**解决的矛盾**:
- 现有方法要么将时序数据抽象为文本（丢失数值精度）
- 要么将预测与语言推理解耦（定性推理与定量结果不匹配）

**技术方案**:
- 引入**可验证预测动作 (Verifiable Forecast Actions)**: LLM 输出结构化预测，用一致性约束的 RL 训练
- 统一框架：定性分析 → 定量预测 → 可验证回报信号 → RL 优化
- 处理金融市场的极端非平稳性、低信噪比、外部信息依赖

**与 GRPO 的联系**: 这种"可验证动作 + RL"的范式与 RLVR (Reinforcement Learning with Verifiable Rewards) 高度一致，但将验证器从"数学对错"扩展到"金融预测是否被市场验证"

### 2.1 多 Agent 信用归因 — 代理梯度算法

# 双轴信用归因伪代码
class DualCreditAssignment:
    def __init__(self, mas_system):
        self.agents = mas_system.agents  # 角色 Agent 列表
        self.rounds = mas_system.rounds  # 对话轮次历史
    
    def temporal_credit(self, trajectory):
        """识别关键转折轮次"""
        # 1. 计算每轮的状态变化量（信息熵差异）
        state_deltas = []
        for i, round_state in enumerate(trajectory.states):
            if i == 0:
                continue
            delta = entropy(trajectory.states[i]) - entropy(trajectory.states[i-1])
            state_deltas.append(delta)
        
        # 2. 找到瓶颈轮次（状态变化最大的转折点）
        bottleneck_rounds = identify_bottlenecks(state_deltas, threshold=0.8)
        return bottleneck_rounds
    
    def structural_credit(self, trajectory, target_agent):
        """隔离目标 Agent 的贡献"""
        # 1. 固定其他 Agent 策略
        other_agents = [a for a in self.agents if a != target_agent]
        fixed_policies = {a: a.freeze_policy() for a in other_agents}
        
        # 2. 反事实推理：如果目标 Agent 用不同策略会怎样
        counterfactual = run_with_modified_policy(
            target_agent, trajectory, alternative_policies
        )
        
        # 3. 计算目标 Agent 的边际贡献
        credit = evaluate(counterfactual) - evaluate(trajectory)
        return credit
    
    def proxy_gradient(self, weak_links):
        """LLM 生成代理梯度"""
        prompt = f"""
        在多 Agent 系统中，以下环节被识别为薄弱点:
        {weak_links}
        
        请为每个薄弱环节生成具体的改进建议（类似梯度的方向和幅度）
        """
        suggestions = llm.generate(prompt)
        return parse_gradient(suggestions)

### 2.2 StockR1 可验证预测动作

```python
# StockR1 风格的可验证预测框架
class VerifiableForecastAction:
    def __init__(self):
        self.prediction_schema = {
            "symbol": str,
            "direction": "up|down|neutral",
            "magnitude": float,  # 预测涨跌幅
            "horizon": int,      # 预测天数
            "confidence": float,
            "reasoning": str     # 自然语言推理链
        }
    
    def verify(self, prediction, actual_return):
        """验证预测是否被市场证实"""
        # 方向正确性
        direction_correct = (
            (prediction["direction"] == "up" and actual_return > 0) or
            (prediction["direction"] == "down" and actual_return < 0) or
            (prediction["direction"] == "neutral" and abs(actual_return) < 0.005)
        )
        
        # 幅度准确性
        magnitude_error = abs(prediction["magnitude"] - actual_return)
        
        # 综合奖励信号
        reward = (
            1.0 * direction_correct +          # 方向奖励
            0.5 * max(0, 1 - magnitude_error)   # 幅度奖励
        )
        return reward
    
    def consistency_loss(self, predictions_for_same_stock):
        """一致性约束：对同一股票的多次预测应该一致"""
        directions = [p["direction"] for p in predictions_for_same_stock]
        # 惩罚自相矛盾的预测
        consistency = len(set(directions)) / len(directions)
        return consistency
```

## 三、实践启发

### 3.1 对 Hermes 多 Agent 编排的改进

**当前问题**: Hermes 的 `delegate_task` 是"发射后不管"(Fire-and-Forget)，子任务成功/失败的归因粒度不够细

**改进建议**:
1. **引入时序瓶颈检测**: 在子 Agent 的多轮工具调用中，自动识别"关键轮次"——即错误最可能发生的步骤
2. **结构信用归因**: 当编排多个 Agent 完成任务时，分别评估每个 Agent 的边际贡献
3. **代理梯度反馈**: 当任务失败时，不只记录"失败"，而是用 LLM 分析"最可能是哪个环节出了问题"

### 3.2 对量化交易 LLM 应用的启示

1. **知识截断是真实威胁**: 在用 LLM 做历史回测时，必须控制知识泄漏。使用未来数据在 LLM 训练集中出现过的股票/时间段要特别小心
2. **小模型 + 领域 RL 优于大模型通用能力**: FinGuard 证明 8B 模型 + 领域 RL 可以超越 397B 模型。量化交易场景同理——专用的交易 LLM > 通用 LLM
3. **可验证预测动作**: 交易决策必须结构化输出（方向、幅度、置信度、推理链），且可以被事后验证

### 3.3 Harness 设计的教训

**从 PTCG-Bench 和 Hermes 实践中总结**:
- Skill 的触发条件是 Harness 的核心设计
- Harness 消融实验：定期禁用单个 Skill，观察系统整体性能变化
- 当发现禁用某 Skill 后系统性能无明显变化时，该 Skill 可能是僵尸 Skill

## 四、知识缺口

1. **时序-结构信用归因的实时计算成本**: 论文未报告代理梯度生成的延迟，在生产系统中是否可行？
2. **StockR1 的一致性约束如何处理市场 Regime 切换**: 当市场从牛市切换到熊市时，"一致性"要求可能是有害的
3. **多 Agent 信用归因在非对称信息场景下的表现**: 金融交易中，不同 Agent 可能有不同的信息访问权限
