## 一、内容详细整理

### 0. 核心论点

**连续数据只有在窗口、通道、时间、单位、标签和来源都被固定后，才成为可训练、可部署和可追溯的模型样本。** 传感器持续输出数据流，神经网络要求固定形状输入张量——工程关键是从连续流中截取时间窗口，同时保持采样间隔、通道顺序和标签时间范围一致。

### 1. 数据层级（最易混淆处）

| 层级 | 定义 | 示例 |
|------|------|------|
| 数据点 | 单轴传感器一个时刻一个值 | 加速度 x 一个读数 |
| 帧 | 同一时刻多通道值集合 | 六轴 IMU 一帧 = 6 通道 |
| 时间窗口 | 连续 N 帧 | 1s / 100 帧 |
| 样本 | 窗口 + 标签 + 元数据 | 可训练单元 |
| 批次 | 多样本组成（仅训练用） | MCU 单推理 = 1 样本 |

- 混淆层级的后果：样本数量算错、通道错位、训练与 MCU 输入形状不一致。
- **批次维只用于训练计算；导出模型前必须明确输入形状是否含批次维。**

### 2. 一个可训练样本的最小定义（表1）

| 字段 | 示例 | 作用 |
|------|------|------|
| 窗口 | 1 s / 100帧 | 确定物理时长和输入尺寸 |
| 通道 | ax, ay, az, gx, gy, gz | 固定排列与含义 |
| 时间 | 起止时间戳 | 检查丢点和标签对齐 |
| 标签 | 周期振动 | 定义学习目标 |
| 来源 | 设备03 / 会话17 | 支持分组划分和追溯 |

### 3. 启动与断流处理

- 启动阶段缓冲区未满：**不能把未初始化内存送入模型**。三种策略：
  - 等待填满（推荐，实时状态识别默认；有启动延迟但不造假数据）
  - 补零（需训练时也出现同样边界）
  - 复制边界（可能产生平坦片段）
- 断流/时间戳跳变 → 当前窗口**失效**（清空重开）。
- 采样点数稳定的前提：传感器有抖动时**保留时间戳并在预处理重采样**，不能假设"收到第 N 个点=时间等间隔"。

### 4. 输入契约：通道、单位、布局

- `[时间, 通道]` 与 `[通道, 时间]` 数值相同但内存排列不同——**训练脚本、模型输入、C 数组填充必须同一布局**。
- 单位固定：加速度统一 m/s² 或 g，禁止跨文件混用。
- **黄金样本**：保存原始帧 + 预处理后张量 + 模型输出。部署代码变更后做回归测试，快速发现布局错误。

### 5. 窗口数量公式与重叠

```
窗口数 = floor((L-N)/H) + 1   （L≥N）
例：L=1000, N=100, H=50 → 19 个窗口
```

- 窗口重叠提高判断频率，**不增加独立信息量**（相邻样本共享大量采样点）。
- **防数据泄漏铁律：先按设备或会话分组划分训练/测试集，再在各组内部切窗**——否则共享片段同时落入训练与测试两侧。

### 6. 时间连续性 ≠ 形状完整

- 长度 N=100 只证明窗口有 100 行数据，**不证明覆盖连续 1 秒**——中间停顿 300ms 后 shape 仍是 100×6，但时间模式被压缩。
- 窗口生成器必须检查相邻时间戳，间隔超容差即清空/重开。

### 7. 窗口生成器四类元数据

| 类别 | 示例字段 | 用途 |
|------|----------|------|
| 张量 | N×C、dtype、布局 | 模型输入 |
| 时间 | start/end/fs/gap_count | 连续性检查 |
| 来源 | device/session/file | 分组划分与追溯 |
| 版本 | firmware/preprocess/config | 复现与回归 |

- 元数据与张量可分开存储，但必须通过**稳定样本 ID** 关联。
- 元数据最少含：设备编号、传感器编号、采集时间、工况、固件版本、标签来源。

### 8. 离线/在线切窗一致性

- 离线训练用数组切片，在线固件用环形缓冲区——最易在**窗口起点、通道交错、步长触发、边界点是否包含**出现一位偏差。
- 验证方法：准备 0,1,2…编号短序列，直接观察每个窗口包含哪些点。
- 多通道布局：训练框架常用 `[time, channel]`，DMA 可能得到交错一维缓冲——固件写入输入张量时**明确索引公式 + 已知递增序列验证**。

### 9. 可直接抄的代码

**C：环形缓冲区形成固定长度六轴样本**：

```c
#define WINDOW_FRAMES 100
#define CHANNELS 6

static float ring[WINDOW_FRAMES][CHANNELS];
static uint32_t write_index;
static uint32_t valid_frames;

void push_frame(const float frame[CHANNELS])
{
    memcpy(ring[write_index], frame, sizeof(ring[0]));
    write_index = (write_index + 1U) % WINDOW_FRAMES;
    if (valid_frames < WINDOW_FRAMES) valid_frames++;
}

bool sample_ready(void)
{
    return valid_frames == WINDOW_FRAMES;
}
```

**Python：带时间连续性检查的在线窗口生成器**（0.1s 周期，第 13 点前插 0.5s 断点，N=8, H=4，发现断点清空缓存不产生伪连续样本）：

```python
from collections import deque

N = 8
H = 4
PERIOD = 0.1
MAX_GAP = PERIOD * 1.5

stream = []
time_s = 0.0
for index in range(24):
    if index == 13:
        time_s += 0.5  # 模拟采集断流
    stream.append({"t": round(time_s, 3), "value": index})
    time_s += PERIOD

buffer = deque(maxlen=N)
since_emit = 0
last_t = None
windows = []

for point in stream:
    if last_t is not None and point["t"] - last_t > MAX_GAP:
        print("GAP detected before", point)
        buffer.clear()
        since_emit = 0
    last_t = point["t"]
    buffer.append(point)
    since_emit += 1
    if len(buffer) == N and (not windows or since_emit >= H):
        window = list(buffer)
        windows.append({
            "start": window[0]["t"],
            "end": window[-1]["t"],
            "values": [p["value"] for p in window],
        })
        since_emit = 0

for index, window in enumerate(windows):
    print(index, window)
```

### 10. 切窗典型错误排查表

| 现象 | 原因 | 检查 |
|------|------|------|
| 首个窗口少一个点 | 起止索引定义不一致 | 用递增序列打印完整窗口 |
| 窗口间隔偶尔变化 | 步长按回调次数而非有效点计数 | 丢点时重置计数并记录时间 |
| PC 与 MCU 通道错位 | 布局转换索引错误 | 每通道不同常数的黄金输入 |

### 11. 迁移到真实 MCU 项目

- ISR 中只写采样点与时间戳，窗口完成后发布只读缓冲给任务。
- 无锁环形队列需证明生产者/消费者索引更新的原子性。
- 离线切窗测试用递增序号+每通道不同常量，MCU 输出窗口串口导回，与 Python 逐元素比对（起点/终点/布局/断点行为）。
- 断点窗口应标记为无效或单独状态，**不能默默补齐后送入普通分类**。

## 二、查询拓展

1. ** TinyML 官方 person_detection / magic_wand 示例**：官方例程均为"满窗才推理"的简单实现，不含 gap 检测和元数据绑定——本文工程规范高于官方示例水平，是实战补课材料。
2. **数据泄漏的会话级划分**：对应时序数据 Cross-Session Validation 思想（HAR 领域 leave-one-subject-out 是标准做法），与本文"按设备/会话分组再切窗"一致。sklearn 的 `GroupShuffleSplit`/`GroupKFold` 可直接实现分组划分。
3. **时间戳重采样**：文中"保留时间戳并在预处理重采样"对应 `scipy.signal.resample_poly` 或 pandas `resample().interpolate()` 流水线；MCU 侧则应记录 `gap_count` 元数据供训练侧对齐。
4. **无锁环形队列原子性**：单生产者单消费者（SPSC）环形队列在 32 位平台上索引读写各自只需一条 store 指令，天然原子；论文级依据是 Herlihy Shavit《The Art of Multiprocessor Programming》SPSC 章节。

## 三、归纳总结

### 因果链

连续传感器流（无天然样本边界）→ 切窗规则（N/H + gap 检测）固定形状 → 输入契约（布局/单位/通道序）保证训练=部署 → 元数据（来源/版本/时间）保证可追溯可复现 → 分组划分防泄漏 → 才是"可训练、可部署、可追溯"的样本。

### 核心认知增量

| 直觉做法 | 工程规范 |
|----------|----------|
| 收满 N 个点就当窗口 | 必须检查时间戳间隔，断流即失效 |
| 训练切窗和固件切窗各写各的 | 递增序列+黄金样本逐元素比对 |
| 随机划分训练/测试集 | 先按设备/会话分组再组内切窗 |
| 只存浮点数组 | 样本 ID 关联元数据（设备/固件/标签来源） |
| 启动时立即推理 | 等待完整窗口，或训练时见过同款边界 |
| `[时间,通道]`/`[通道,时间]` 随手选 | 训练、模型、C 填充三方锁死同一布局 |

### 一句话

**shape 完整 ≠ 时间连续；窗口重叠 ≠ 信息增加；样本 = 窗口 × 契约 × 元数据，三者缺一就不是可信样本。**

## 四、趋势判断

1. **传感器数据工程化是 TinyML 落地的主要瓶颈**：模型侧 TFLM 已高度标准化，差异化的失败点集中在数据侧（切窗/泄漏/布局错位）——本文系列把重心放在数据管线而非模型，反映了 2026 年 TinyML 教程从"跑通 demo"向"工程可信"的成熟化转向。
2. **元数据驱动的可追溯数据集会成为边缘 AI 交付标配**：设备/固件/预处理版本随样本入库，是 OTA 后模型回归测试的前提——与 MLOps 的数据版本控制（DVC 类）在端侧的投影一致。
3. **端侧数据质量监控会前移到采集层**：gap_count、丢点率作为元数据入库，训练侧可自动降权/剔除问题会话，"采集即质检"取代"训练前才发现数据脏"。
