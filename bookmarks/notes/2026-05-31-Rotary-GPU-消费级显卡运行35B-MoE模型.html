Rotary GPU：消费级显卡运行 35B MoE 模型的本地执行探索

摘要

论文提出 Rotary GPU 执行方案，探索在消费级硬件上运行大型 MoE 模型的可行性。作者使用 Qwen3.6-35B-A3B 类 MoE 模型，在 RTX 4060 Laptop GPU（8GB VRAM）上实现了本地执行：生成 2048 tokens 时仅使用约 6.3GB VRAM，解码吞吐量 21.06 tokens/s。核心理念是"旋转式加速器驻留"（rotary-based accelerator residency），让大模型在有限显存环境中通过智能调度实现本地化部署。这不是要替代数据中心，而是探索大模型能力向资源受限环境的延伸。

核心内容

1. 研究动机

大模型的能力已通过扩展实现，但部署可及性（deployment accessibility）可能和能力本身一样重要。许多组织受硬件、预算、安全或封闭网络约束，无法访问大型加速器集群。问题不是"如何训练更大的模型"，而是"现有大模型能否在更小硬件上变得可访问"。

2. Rotary GPU 方案

核心技术：旋转式加速器驻留概念（rotary-based accelerator residency）
让模型参数在 GPU 和系统内存之间"旋转"调度
MoE 架构天然适合此方案：每次推理只激活部分专家，不必全部常驻 VRAM
非活跃专家可在系统内存等待，活跃专家轮换进入 GPU

3. 实验结果

硬件：RTX 4060 Laptop GPU（8GB VRAM）
模型：Qwen3.6-35B-A3B 类 MoE
VRAM 使用：~6.3GB（峰值在 8GB 限制内）
解码吞吐量：21.06 tokens/s
输出长度：2048 tokens

4. MoE 的天然优势

MoE 模型总参数量大（35B），但每次推理只激活一小部分（~3B）。这种稀疏激活特性意味着：
不需要所有参数同时驻留 GPU
可以按需加载活跃专家，卸载非活跃专家
本地部署的 VRAM 需求远小于同等能力的稠密模型

关键概念

旋转式驻留（Rotary Residency）：模型参数在 GPU-系统内存间轮换，类似 CPU 缓存层级机制
MoE 稀疏激活：每次推理仅激活总参数的一小部分，天然适配有限 VRAM 场景
部署可及性（Deployment Accessibility）：模型在资源受限环境中运行的能力，与模型能力同等重要
消费级 GPU 推理：在非数据中心硬件上实现生产级推理吞吐量

能力边界

探索性研究而非确定性结论
仅测试了单类 MoE 模型，对稠密模型不适用
21.06 tok/s 的吞吐量对交互场景足够，对批量推理不足
预填充（prefill）阶段性能未详细报告
与韩国专利 KR 10-2026-0070380 相关，部分技术细节可能受限

最佳实践

MoE 模型是本地部署的最佳选择：大参数量+稀疏激活=低 VRAM 需求
VRAM 预算应按激活参数量规划，而非总参数量
消费级 GPU 可作为边缘推理节点，降低对云 API 的依赖
