AgentSkills自进化与安全治理-CoEvoSkills共进化验证与技能库相变

生成日期 2026-08-29

一句话总纲

Agent Skills 领域 2026 上半年两项关键进展：CoEvoSkills 证明机器自进化技能首次全面碾压人工技能（71.1% vs 53.5%，Finance 域领先人工 +56.9pp），而三项并发安全实证揭露社区技能 26.1% 含漏洞——技能生态同时迎来质量跃迁与信任危机，治理框架（G1-G4 门禁/T1-T4 信任分层）与规模上限（技能库相变）成为新的核心命题。

二、内容整理

2.1 背景：tool-skill gap 与人机认知错位

Anthropic 于 2025-10 提出 Agent Skills，2025-12 开放为标准。核心区别：

维度 Tool Skill
形态 单一自包含函数 多文件结构化包（SKILL.md + scripts + references + assets）
作用 执行并返回结果 改造 agent 的准备状态——注入程序性知识、修改执行上下文、预授权工具
加载 配置时 触发时渐进式披露（L1 元数据→L2 正文→L3 资源）

两个痛点驱动自进化研究：

  1. 人工编写劳动密集且质量不稳：SkillsBench 显示人工技能在 11 个域中增益高度不均，Natural Science 域甚至出现负增益——人类专家直觉设计的工作流与 LLM 处理上下文、推理、执行的方式天然错位（human–machine cognitive misalignment）。
  2. 现有自进化方法只能生成"工具"不能生成"技能"：Voyager/SkillRL/Alzubi 等方法面向一次性生成简单自包含函数，无法产出协调"指令+脚本+领域参考"的多文件包；且部分方法（Alzubi 2026）依赖 ground-truth 监督做失败诊断，真实世界不可得。

2.2 CoEvoSkills 框架（arXiv 2604.01687）

任务形式化：POMDP

任务环境 M=⟨X,A,T,O,Ω,R⟩：状态空间 X 是完整文件系统与进程；动作 A 是终端命令与文件编辑；转移 T 确定性；奖励 R(x_T)∈[0,1] 由隐藏的 ground-truth 测试评估输出文件。agent 只见部分观测，永远不知道隐藏测试检查什么——这是问题的根本难度。

双组件共进化

Skill Generator（技能生成器）
- 维护持久对话上下文 C，初始化为 (任务指令 I, meta-skill S_meta)
- 每轮读取当前技能版本 S(i) + 累积验证反馈 F(i,j)，产出改进版：S(i+1) ~ π(·|S(i), C(i)⊕F(i,j))
- 反馈 F 含失败测试用例、根因分析、可执行的修订建议

Surrogate Verifier（代理验证器）——信息隔离是关键设计
- 运行在完全独立的 LLM 会话，只看任务指令 I 和输出文件 x(i)，对生成器的推理、代码、技能内容全盲
- 目的：防止自验证的确认偏误——验证器测试生成与生成器内部状态条件独立
- 产出确定性断言套件 V={e1..e|V|}，代理奖励 R̃(x,V) = Σ1[e_k(x)]/|V| ∈ [0,1]

双通道交替优化（算法核心）

通道1（技能修订）：R̃ < 1 时，V 固定，失败诊断 F 驱动技能修订
通道2（测试升级）：R̃ = 1 但 oracle 失败时，验证器独立升级测试套件
                  （生成更多样、更全面、更具挑战性的用例）
终止：oracle 在全新环境 E' 重执行技能，通过 → 部署到目标 agent

关键洞见：ground-truth oracle 只返回一个不透明的 pass/fail 位（不给测试内容），正是为了防止生成器对 held-out 测试过拟合；而代理验证器提供密集的可操作反馈弥补 oracle 的稀疏性。两者职责严格分离。

域级分析（增益分布）

  • 9/11 域自进化 > 人工策划，最大差距：Finance +56.9pp、Cybersecurity +23.2pp
  • 人工技能已强的域（Energy、Robotics）自进化收益递减；人工无益的域自进化收益最大
  • 结论 3：人工技能的价值集中在"人类直觉恰好对齐 LLM 需求"的域，其余域应交给机器自进化

演化动力学

  • Round 0（无验证单次生成）≈ 裸基线；Round 2 达 44%；Round 3（63%）超越人工；Round 5 收敛 75%
  • 平均每个任务需 4.1 个验证周期、2.4 轮进化迭代即收敛——进化成本实用

⚠️ 技能库相变（Li 2026，对本地 499-skill 库的直接警示）

多 agent 系统"编译"为单 agent 技能库可大幅降 token 与延迟且精度不损——但压缩存在相变：超过临界库规模后，技能选择准确率急剧退化。这是技能库管理的基本限制：单个 agent 能有效管理的技能数量存在硬上限。Advanced Tool Use 的 Tool Search 只是部分缓解，根本的 scaling 问题未解。

2.5 安全实证三连与治理框架

三项并发实证（2025-10 ~ 2026-02）

研究 规模 核心发现
Schmotz et al. 2025 概念验证 SKILL.md 长文中嵌入恶意指令可"trivially simple"地实现 prompt 注入；良性任务的"Don't ask again"授权会顺延到相关有害动作
Liu et al. 2026a 42,447 社区技能（SkillScan 分析 31,132） 26.1% 含至少一个漏洞，14 种模式 4 大类；数据外泄 13.3%、提权 11.8%；捆绑可执行脚本的技能漏洞率高 2.12×（OR=2.12, p<0.001）；5.2% 高危疑似恶意
Liu et al. 2026b 98,380 技能行为学验证 确认 157 个恶意技能/632 漏洞；两大原型：Data Thieves（供应链窃取凭证）、Agent Hijackers（指令操纵劫持决策）；单一产业化作坊占确认案例 54.1%（模板化品牌冒充）

Skill Trust and Lifecycle Governance Framework（综述提出）

四道验证门（G1-G4）纵深防御：
- G1 静态分析：模式匹配+依赖扫描
- G2 LLM 语义分类：检测声明用途与实际指令的意图错位（针对间接注入）
- G3 行为沙箱：执行检测静态分析看不见的副作用（恶意技能平均 4.03 漏洞跨 3 个 kill-chain 阶段）
- G4 权限清单校验：声明能力（工具/路径/网络）vs G3 观测行为比对

四级信任分层（T1-T4）+ 最小特权：
- T1 未审查社区技能：仅指令级访问+完全工具隔离（永不授予脚本执行——直接回应 2.12× 结论）
- T4 厂商认证：全能力
- 与渐进披露逐级映射：T1 只见 L1 元数据；L2 指令需 T2+；L3 可执行脚本需 T3+
- 生命周期：运行时监控异常（意外工具调用/权限边界探测）→ 降级或吊销；干净历史可晋升——类似包管理生态的信誉系统

2.6 部署面速览（CUA 栈）

  • OSWorld-V 上专有 agent 达 72.6% vs 人类基线 72.36%（2025-12）——窄切片开始饱和，但 ScreenSpot-Pro/OS-Marathon/CoAct-1 混合 GUI-代码工作流仍差距显著
  • 7B 模型经 RL 自进化训练在 ScreenSpot-Pro 达 47.3%，反超 72B UI-TARS 24.2pp，仅用 3000 训练样本（Yuan et al.）——小模型+自进化 RL 是效率方向
  • OpenCUA-72B 开源最强 45.0%（OSWorld-Verified），AgentNet 数据集跨 3 OS/200+ 应用

三、查询拓展

3.1 "技能质量"评测方法论

SkillsBench 是唯一 purpose-built 的技能评测基准（87 任务/确定性验证器/二元 pass-fail，无主观人类判断）。对照本地实践：cron-verifier 的 rc=0/1/2 分层与"机器可验证事实取代 AI 主观判断"（AGENTS.md 完成定义）与该理念同构——确定性验证器是技能生态可复现性的基石。

3.2 共进化验证与 GAN 的结构同源性

CoEvoSkills 的 Generator-Verifier 交替优化（式 5/6：技能在固定测试压力下改进；测试在代理通过但 oracle 失败时升级）在机制上就是对抗式共存：验证器是"可学习的判别器"，技能是"可改进的生成器"。差异在于信息隔离的方向——验证器看不到生成器内部状态，且 oracle 只给 1-bit 信号防过拟合，等价于给"判别器泄漏"上了双重锁。

3.3 与 MemSkill/MSCE 的谱系关系

本地 8-25/8-27 笔记已覆盖 MemSkill（记忆技能自进化）与 MSCE（技能晋升治理）。CoEvoSkills 与它们正交：MemSkill 进化的是"记忆操作技能"，MSCE 管的是"技能晋升证据链"，CoEvoSkills 解决的是"多文件技能包的无人监督生成质量"。三者拼合即为完整自进化技能栈：生成（CoEvo）→ 存储（MemSkill）→ 晋升治理（MSCE）。

四、归纳总结

  1. 自进化 > 人工策展已成实证事实（9/11 域），但前提是共进化验证循环——纯 prompt 工程的技能生成（含官方 skill-creator）与裸 agent 统计不可区分。
  2. 信息隔离的代理验证是无人监督下的反馈引擎：验证器全盲于生成器 + oracle 只回 1-bit，双保险防确认偏误与过拟合。平均 2.4 轮收敛证明成本可控。
  3. 技能是跨模型可移植资产：5 家公司 6 个模型 +36~44pp，技能编码任务结构而非模型特性——技能库值得作为独立资产管理。
  4. 安全是技能生态的阿喀琉斯之踵：26.1% 漏洞率 + 54.1% 案例出自单一产业化作坊，说明攻击已工业化；带脚本的技能风险高 2.12× 应成为准入分级依据。
  5. 技能库存在相变规模上限：超临界规模后选择准确率急剧退化——技能库不是越大越好，治理（合并/归档/分层）是刚需而非锦上添花。

五、趋势判断

  1. 技能治理将复制包管理生态的演化路径（npm/PyPI 的前车之鉴）：G1-G4 门禁+T1-T4 分层+信誉升降级的框架会被 agent 平台（含 Hermes 类系统）逐步内置，2026 下半年出现首批生产级 skill registry。
  2. "人工写技能"将退守两个阵地：安全关键域（需人类责任链）与人工恰好擅长的域（Energy/Robotics 类）；其余域转向"人定验收标准+机器共进化生成"。
  3. 技能库规模相变将催生"技能路由"子领域：Tool Search/语义索引/分层加载（本地 skill-health-tier 的 production/beta/skeleton 三级即原始形态）从运维实践上升为研究问题。
  4. 验证器经济：Surrogate Verifier 的独立会话模式（执行/评判分离）会与 multi-agent 评审、LLM-as-Judge 融合，"被隔离的批评者"成为自进化系统的标准组件。

六、关联分析

  • 本地 499 skills / 30% production 现状：Li 2026 的相变发现直接支持现有 skill-health-tier 巡检路线，并给出新判据——问题不只是"质量分层"，而是总量是否已过临界点。可对 499 库做技能选择准确率回测（用历史任务 vs 技能触发的匹配记录）量化本库的相变位置。
  • evolver/experience-bank 闭环：CoEvoSkills 的平均 2.4 轮收敛 + 4.1 验证周期，为本机"错误模式→规则沉淀"的循环提供了可借鉴的终止条件与轮次预算参考。
  • 安全现状自查：本地大量社区导入技能（openclaw-imports 等）恰处 T1 层——26.1% 漏洞率意味着 skill-vetter 的每次导入前扫描不是过度防御，与 G1-G2 门禁对齐。
  • 与前序笔记互引：MemSkill（08-25）→ MSCE（08-27）→ 本篇构成"技能自进化三部曲"；Skills 工程化入门（08-22 Miles 长文）是工程视角前传，本篇补学术-实证视角。
