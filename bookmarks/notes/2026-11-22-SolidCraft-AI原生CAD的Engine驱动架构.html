定锚

SolidCraft 的价值不在于已经可替代 CATIA、NX 或 Creo，而在于它把 CAD 能力抽象为同一套可验证命令：GUI、CLI、浏览器和 AI Agent 都调用同一执行路径。对飞机设计企业而言，这是一种值得吸收的架构方向，而非可以直接替换工业 CAD 的产品结论。

  • 收录理由：补足既有《FreeCAD AI MCP 生态比较研究》偏“外接 MCP”路线的盲区——SolidCraft 代表“核心命令系统原生面向 Agent”的路线。
  • 适用场景：企业 CAD 二次开发、知识工程、参数化构型生成、可追溯的 Agent 执行链。
  • 边界：官方定位仍为“早期但可用于简单零件”；复杂曲面、工程图、CAM/CAE 与工业级内核稳健性不能据此视为已解决。

内容整理：从 GUI 流程到统一命令引擎

1. 原文的核心判断

传统 CAD 常以“用户操作界面 → 工具逻辑 → 建模计算”组织能力，自动化往往绕过 UI、重复实现或脆弱地模拟鼠标行为。文章以 SolidCraft 为样本提出另一条链路：

GUI / Browser / CLI / MCP Agent
            ↓
      统一 JSON 命令接口
            ↓
   文档、特征、参数与 Undo 事务
            ↓
       几何内核与 B-Rep 运算

其要点不是“AI 替工程师画模型”，而是把特征操作转化为带明确输入、错误返回、状态变更与可复核输出的工程命令。

2. 一手核验：SolidCraft 当前已公开的能力

项目 官方材料证据 解释
多入口 桌面、浏览器、headless CLI、MCP 使用同一命令 降低“UI 自动化、脚本、Agent 三套逻辑”分叉风险
参数化 受约束草图、参数/单位表达式、可编辑特征时间线 使“改壁厚/孔距”成为参数与特征修改，而非重生成网格
Agent 闭环 MCP 可执行建模、测量、改参数、导出；官方表述为 Build → Inspect → Revise → Export 生成后测量与检查是 Agent 工作流的一等能力
几何内核 当前使用 Truck；SolidCore 是面向后续的 NVIDIA SMLib Rust 移植，仍在开发 不能把 SolidCore 写成已全面生产化的内核
版本成熟度 官方站点展示 v0.12.0；README 称简单零件“早期但可用”，75/76 公开参考件通过其几何 oracle 测试覆盖是积极信号，但不等同于航空级复杂模型的长期稳健性

3. “Everything is a command”的实际意义

统一命令层应至少具备以下性质：

能力 对人工用户 对程序/Agent 企业工程价值
参数 schema 减少表单歧义 可校验 JSON 输入 降低误调用
事务与 Undo 可安全回退 失败不污染设计状态 支持可审计试错
检查/测量命令 直观验模型 可形成验收断言 让“已生成”变为“已验证”
同源命令 GUI 行为一致 无需 UI 自动化 避免双实现漂移
导出与版本记录 正常交付 可自动生成工件 可进入构型管理链

4. 数据语义比几何交换更关键

STEP 能交换实体几何，却通常难以无损携带原 CAD 的特征历史、参数关系与约束语义；STL/OBJ 则主要是网格。因而 AI 能可靠修改的前提不是“看见一个形状”，而是存在可寻址的参数、特征依赖与稳定的对象引用。

文章提到拓扑命名问题：上游特征更新后，边/面的内部编号可能变化，下游倒圆角等引用可能失效。这是参数化 CAD 的长期难题；命令接口本身不能消除它，只能通过持久化命名、来源追踪、重建后检查和失败显式化来控制风险。

归纳总结

结论：SolidCraft 展示的不是“自然语言 CAD 已成熟”，而是 AI-CAD 应有的正确底座：命令同源、状态可回退、结果可检查、设计语义可保存。

原文的三层趋势可以压缩为：

  1. 架构层：从 GUI 驱动改为 Engine/Command 驱动；
  2. 产品层：从单桌面客户端变为桌面、Web、CLI、MCP 可组合的工程能力；
  3. 交互层：图形、参数、脚本、自然语言长期共存，各自承担精确操作、意图表达、批处理和任务编排。

其中最应警惕的误读是：有 MCP ≠ 有工程闭环。真正的闭环必须包含“意图/约束 → 命令执行 → 几何与规则验证 → 失败回滚/修订 → 可追溯交付”。

趋势判断

趋势 判断 依据与限制
CAD 能力 API 化 高确定性 GUI、CLI、自动化共用核心命令可显著降低逻辑分叉；已被 SolidCraft 原型验证
Agent 直接操纵特征树 中期可行 依赖参数 schema、拓扑稳定性、约束检查与权限边界，远非仅靠聊天模型
跨 CAD 保留完整特征历史 长期困难 各系统的特征、求解器、内核和依赖语义不同，STEP 不能自然解决
开源 Rust CAD 取代成熟工业 CAD 近期不成立 内核迁移、曲面、工程图、CAM/CAE、长期回归库均是高门槛

关联分析

与企业级飞机设计智能化的映射

SolidCraft 思想 飞机设计企业可迁移对象 不应直接照搬的部分
统一命令注册表 将 CATIA/自研工具封装为“受控设计动作” 不把 GUI 宏录制当命令 API
参数化时间线 构型参数、骨架、部件规则、设计版本 不假设跨系统拓扑引用天然稳定
Inspect/Measure 几何完整性、间隙、质量属性、规则校核 不以截图或模型存在替代适航/工艺验证
MCP 接口 Agent 发现可用工具、受限调用与回执 不向 Agent 直开放生产 PLM/CAD 写权限
CLI/headless 批量变型、夜间规则校验、回归测试 不绕过配置状态、审批与签署链

对 CATDS / 企业工具链的启发

最小可行路线不是重造 CAD 内核，而是在既有 CATIA/CAA 或自研计算服务外建立“设计动作协议”：

自然语言任务
  → 受控任务规划（禁止直接写生产模型）
  → 参数化命令 + 输入 schema
  → 沙箱/副本模型执行
  → 规则、质量属性、几何证据校验
  → 人工复核后再进入受控发布

该路线优先投资“命令定义、验证器、证据与回滚”，而不是先投资一个万能 CAD 聊天入口。

指南分析

可落地的四级接入门

等级 动作 最低验收门 风险控制
L0 只读诊断 读取参数、质量属性、模型树 输出可复现且不改模型 默认权限
L1 草案生成 生成参数变更/建模命令草案 schema 校验 + 人工确认 不触达正式模型
L2 沙箱执行 在副本执行命令并导出结果 几何检查、规则检查、Undo/重放通过 隔离工作区
L3 受控合入 人工批准后合入受控构型 变更单、审签、版本/基线记录齐全 最小写权限

禁止跨档规则：未建立 L2 的可重复验证与回滚证据，禁止把 Agent 接入 L3 正式构型写入。

拓展应用推荐

  1. 建立 CAD Action Contract 原型：挑选 10 个高频、低风险动作（读参数、量孔距、质量属性、导出 STEP、创建草案特征等），为每个动作定义 JSON schema、前置条件、输出证据、失败码与回滚策略。
  2. 建设“模型断言”库：把“孔距=xx、最小壁厚≥xx、质量≤xx、无干涉”等要求编码为可机器验证的断言；Agent 的完成条件应是断言通过，而不是成功点击了命令。
  3. 拓扑敏感操作分级：倒圆角、壳、拔模、布尔和面引用等高失败特征需独立标为高风险操作，强制执行后测量、引用完整性检查和人工复核。
  4. 保留人机双入口：复杂草图、曲面与装配判断仍由工程师直接操作；Agent 先承担参数批改、重复检查、变型生成与证据汇总。

行动与回访

  • 已执行：完成 SolidCraft 官方 README 与官网交叉核验；纠正原文中可能被误读的边界——SolidCore/SMLib 路线仍在开发，不能按成熟生产内核引用。
  • 建议的下一步：在 CATDS 或相关内部工具中只选 1 个只读 CAD 检查动作，先写 Action Contract 与验收断言，再评估是否进入 L1 草案生成。
  • 验收/证伪条件：若同一参数化任务在副本模型上无法稳定重放，或无法输出几何与规则证据，则“Agent 闭环”假设不成立，必须停留在只读/草案阶段，不得扩大写权限。
