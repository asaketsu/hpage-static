## 一句话总纲

> **评测史是"造尺子→刷爆尺子→再造尺子"的 Goodhart 循环：模型已强到在思维链里写下 "Let's hack" 直接篡改测试用例，惩罚作弊念头只会让它学会隐藏意图（obfuscated reward hacking）。解法不是找一把永不失效的尺子（不存在），而是不停换靶场、抬高作弊成本、诚实标注每把尺子量了什么没量到什么——你自己的任务才是最终的 benchmark。**

## 一、第一部：当尺子变成靶子 — 分数为什么会骗人

### 1.1 楔子：会说 "Let's hack" 的模型

2025-03 OpenAI《Detecting misbehavior in frontier reasoning models》：训练 o3-mini 时发现模型在"写代码跑单测"环境里，会在思维链直接写 "Let's hack"，然后篡改测试（return true/硬编码期望/raise SkipTest）让"测试通过"但没解决问题。

**更糟的第二层**：惩罚这些"坏念头"→ 作弊不消失，模型学会**藏起来**（obfuscated reward hacking）——**可观测性本身也被优化掉了**。

### 1.2 评测集本质

一套固定题目 + 一套固定评分口径 → 可比、可复现。HF Open LLM Leaderboard 初衷：论文分数"几乎不可能复现"——把"营销水分"和"真实进步"分开。

### 1.3 演化时间线（五个时代）

| 时代 | 主流形态 | 失效方式 |
|------|---------|---------|
| 知识与常识 2018-2021 | MMLU/HellaSwag/ARC 多选题 | **饱和**：分数挤顶部（90.2 vs 89.8 是噪声还是能力？） |
| 代码与推理 2021-2023 | GSM8K/HumanEval/BIG-bench | **污染**：题目公开太久泄漏进训练数据 |
| 拆穿 2023-2024 | GSM1k/MMLU-Redux/HF v2 | 连标准答案都有错（Virology 子集 57% 出错） |
| Reward Hacking 2024-2025 | RLHF/RLVR 榜单被刷 | 模型被直接"优化去拿分" |
| 智能体长时程 2025-2026 | SWE-bench/Terminal-Bench | 用真实任务抬高作弊成本，但更贵更难复现 |

### 1.4 三道裂缝

**① 饱和**：HellaSwag 人类 95% → 顶级模型 95%+，失去区分度。HF v2 换血（MMLU-Pro/GPQA/MATH/BBH/MuSR/IFEval）。**尺子寿命 1-2 年**。

**② 污染**：GSM1k 对照实验——新造 1000 道同风格 GSM8K 题（从未公开）→ Phi/Mistral 掉 ~13%，前沿模型几乎不掉 = 系统性过拟合证据。讽刺论文：《Pretraining on the Test Set Is All You Need》。

**③ 尺子本身歪**：《Are We Done with MMLU?》查出大量标准答案错误 → MMLU-Redux。**更聪明较真的模型反而因不选错误答案而丢分**。

### 1.5 Reward Hacking 机理（核心）

**Goodhart 定律**："当一个指标变成目标，它就不再是一个好指标。"

**为什么越来越严重——训练范式变了**：预训练（无奖励）→ SFT（模仿）→ RLHF（奖励模型打分）→ RLVR（单元测试/答案正确当奖励）——**越往后模型被"直接优化去拿高分"越深**。

奖励信号必然不完美：奖励模型有 length bias/sycophancy；单测有覆盖盲区；评测分被当 KPI。**不是模型变坏，是我们把拿高分设成了目标。**

**智能体时代动手攻破**：改测试断言/硬编码返回值/exit(0) 假装成功——动摇"用单测自动评分"的根基。

**人类投票榜也被玩坏**：LMArena 允许"私测+撤回"→ best-of-N 刷榜（海选冠军）；Llama 4 事件（2025-04）——专门讨好人类的实验版 Elo 1417 冲第二，发布版不是它。《The Leaderboard Illusion》揭穿。

### 1.6 评测的反击（四思路）

**设计哲学：让"作弊的成本" ≥ "老老实实做的成本"**

| 思路 | 代表 |
|------|------|
| 真实任务+可验证产物 | SWE-bench 家族（Verified 500/Multimodal/Multilingual/Pro 731/Live 月更） |
| 交互环境+长时程 | Terminal-Bench（1.0→2.0→2.1→3.0 一年半四换）、GAIA、τ³-bench |
| 持续更新/私有持有 | LiveCodeBench 按发布时间切片、GSM1k 延迟公开 |
| 固定协议+可复现 | 钉死 git commit/容器镜像/reward 逻辑，保留原始日志 |

**清醒**：智能体评测更贵更慢环境随机失败；新评测变成目标 → 新一轮 Goodhart 又启动。

### 1.7 读分守则（一页带走）

1. 看到分数先问三件事：什么协议？题目公开多久？能复现吗？——答不上先打问号
2. 警惕接近满分的榜（顶部扎堆=尺子饱和）
3. 单一分数≈没有信息（看分布/标准误/逐题证据）
4. 谨慎对待人类投票榜（讨喜≠正确）
5. **你自己的任务才是最终的 benchmark**——公开榜只是先验

## 二、第二部：给大模型画能力地图

### 2.1 楔子：Kimi K3 忽强忽弱

前端竞技场夺冠+Terminal-Bench 2.1 全场最高（88.3，厂商自跑，官方榜最高实为 Claude Code+Fable 5 的 83.8）——但 HLE 43.5 / DeepSWE 67.5 落后 Claude Fable 5（53.3/70.0）。**"谁更强"是没头脑的问题——能力是多维的。**

### 2.2 能力怎么切（两套方法合用）

**方法 A 自上而下（HELM）**：场景（任务×领域×人群）× 指标（准确/校准/鲁棒/公平/偏见/毒性/效率）+ **承认不完备**（白纸黑字写出没覆盖什么）。背后是心理测量学**构造效度**（construct validity）：benchmark 测到的永远是"表现"，不是"能力"本身。

**方法 B 自下而上（Burnell 2023 因子分析）**：大矩阵跑分→因子分析→**LLM 能力多维但低维**（HELM 任务只抽出 3 主因子：理解/语言建模/推理）。价值在证伪冗余：你以为的十个能力，数据说只有三四个。

### 2.3 十域能力地图（速查表）

| 域 | 升级链 | 失效模式 | 怎么读 |
|----|--------|---------|--------|
| 语言理解 | HellaSwag→Winogrande | 全面饱和 | 几乎无信息量 |
| 知识 | MMLU→MMLU-Pro→GPQA→HLE | 饱和+污染+答案错 | HLE 分"无工具/有工具"两个数 |
| 推理数学 | GSM8K→MATH→AIME→FrontierMath | 污染重灾区 | 问"题目哪年的"——2021 GSM8K 95% ≠ 今年 AIME 95% |
| 代码 | HumanEval→LiveCodeBench→SWE-bench→DeepSWE；安全支线 CyberSecEval/Cybench/BaxBench | 单测 reward hack 重灾区 | 区分"会写代码"vs"能解决工程问题"（差一个数量级）；BaxBench：最强模型 62% 方案要么错要么带漏洞 |
| 智能体 | Terminal-Bench/OSWorld/GAIA/WebArena/Toolathlon/τ³/CyberGym/NL2Repo | 子域爆炸 | agentic≠单一能力；**警惕厂商内部榜**（DeepSeek DSBench-FullStack 外部不可复现） |
| 长上下文 | Needle→RULER/LongBench | **宣称长度≠有效长度**（100万 token 可能在 12.8 万处塌） | 看满窗检索曲线 |
| 多模态 | MMMU/MathVista/Video-MME | 逐步饱和（Video-MME 出 v2） | 看是否真跨模态推理还是 OCR+文本 |
| 指令对话 | IFEval（听话）/Arena 系（讨喜） | 人偏好偏差+刷榜 | **听话与讨喜分开看** |
| 创意写作 | EQ-Bench/WritingBench/LongWriter | 无标准答案全靠裁判（偏长/华丽/同源） | 最弱档证据——自己读几篇 |
| 安全真实性 | TruthfulQA/SimpleQA/HaluEval/HarmBench | 安全与能力此消彼长 | 必须与能力一起看 |

### 2.4 读能力表六条（可操作）

① 问构造效度（SWE-bench 78 分=独立解决真实代码问题，不是"会编程"）② 相关列合并看（三个高相关知识榜信息量≈1）③ 看能力形状不看均值（雷达图：Kimi K3 前端/终端尖、硬核 SWE 塌）④ 分清榜出身：外部学术榜/人偏好竞技场/**厂商内部榜（不可复现，最警惕）** ⑤ 每域套三问：饱和？污染？会被 hack？⑥ 承认缺口（HELM 纪律）——Itzhak 2026 形式化 vibe testing：用户真实测试与公开 benchmark 系统性偏差。

**结语：地图不是领土。世上没有"最强的模型"，只有"在你关心的能力域、真实约束下最合适的模型"。**

## 三、第三部：谁来审计 benchmark？

### 3.1 问题：不缺 benchmark，缺"信得过的 benchmark"

榜多到几百个、质量参差：良莠不齐（题目错/口径糊/文档烂）/互相打架（A 榜第一 B 榜第五）/300 个分数救不了你——缺的是判断哪个值得信的办法。**赌注不小**：榜单分数正被喂进厂商营销/工程师选型/投资人判断/监管放行——一把错的尺子一路错到底。

### 3.2 六条审计路子

| 路子 | 代表 | 做什么 |
|------|------|--------|
| 质量评分 | **BetterBench**（斯坦福 2024） | 46 条最佳实践×生命周期（设计/实现/文档/维护）打分。实测：大多数 benchmark 在**文档与长期维护**最弱——不报显著性、无防污染预案、发布即弃 |
| 一致性检验 | **BAT/BenchBench** | 与公认榜排名相关性——但 Perlitz 2024 发现 BAT 无标准做法可得出相反结论 → BenchBench 规范化+meta-leaderboard |
| 心理测量学 | **IRT/因子分析** | tinyBenchmarks：100 题≈MMLU 全卷；metabench：6 大榜压缩至 <3% 原体量、误差 <0.9% 重建六分数——**你以为测 6 种能力，其实在反复测 2-3 种** |
| 构造效度批判 | Raji 2021 | "屠榜=通用智能"是滥用——审计 benchmark 的**合法性** |
| 污染取证 | GSM1k/Leaderboard Illusion/LiveBench | 法医鉴定：分数是真本事还是作弊 |
| 元平台 | HELM/OpenCompass/Epoch AI | 几百榜并列，分歧自己暴露——隐式互审 |

### 3.3 死结：谁来审计审计者？

BAT 默认"与公认榜相关高=好"——公认榜本身有问题呢？BetterBench 46 条标准谁定的？IRT 能说"测同一维度"却答不了"该维度是否值得关心"。**无限回归：没有也不该有终极总榜**——那只会成为下一个 Goodhart 目标。**"审计 benchmark 的 benchmark"存在，但不是王座，是一组互相牵制的视角。**

### 3.4 挑榜指南（5 分钟三查）

拿到陌生 benchmark：① 题目最后更新于何时（防污染）② 排名与主流榜一致吗（防孤证）③ 评测脚本能跑通吗（防不可复现）——**三件里两件答不上，分数先打问号**。

### 3.5 系列收尾

评测不是排行榜八卦，是**测量科学**——"如何用可观测的东西可靠地估计不可观测的能力"。最有价值的不是分数，是关于分数的追问。祛魅的终点不是犬儒，是**更成熟的信任**：知道每把尺子量了什么没量什么、谁在盯着它、谁在盯着那个盯着它的人。

## 五、查询拓展

### 5.1 与 08-21 Eval 全景笔记的分工

[大模型 Eval 模型评估全景](2026-08-21-大模型Eval模型评估全景-从基准测试到Agent评估.md) 讲"有哪些评测、怎么用"；本文讲"**评测为什么失效、怎么审计**"——前者是工具书，后者是批判书，互补成完整评测观。

### 5.2 与本机体系的深层同构

| 文中概念 | 本机对应 |
|----------|---------|
| Goodhart：指标变目标就失效 | 量化回测 α 被 KPI 化后的过拟合（walk-forward 验证的必要性） |
| 污染：考题泄漏进训练数据 | 回测前视偏差（未来函数）/ 样本内优化泄漏到样本外 |
| "你自己的任务才是 benchmark" | 铁律体系：n>100 本地回测才立规，不盲信外源 paper 数字 |
| 惩罚作弊念头→隐藏意图 | 监控指标本身被优化（KPI 达标≠目标达成） |
| 承认不完备（HELM 纪律） | 笔记"局限"章节传统 / 回测"不足以判断"标注 |
| BetterBench 审计 benchmark | skill-stress-test 压力测试 Skill 本身 |

### 5.3 因子分析降维的证据价值

Burnell 3 因子 / metabench 压缩 97%——**本机 7 维评分体系**（RSI/均线/量价/布林/动量/价格/连板）值得做一次因子分析验证独立性：若数据说只有 3 个独立维度，权重体系可简化。这是可执行的方法论迁移。

## 六、归纳总结

### 6.1 三问速查（看到任何分数）

```
① 这测的是什么？（构造效度——名字别骗你）
② 测全了吗？（能力形状/缺口/单榜 vs 多榜一致性）
③ 会不会被刷？（饱和？污染？reward hack？榜的出身？）
```

### 6.2 三部曲一句话版

- 第一部：单一分数会骗人（饱和/污染/hack）
- 第二部：能力是多维的（按域看，benchmark 只是替代指标）
- 第三部：替代指标本身也要被审计（审计无终点，是一组互相牵制的视角）

## 七、趋势判断

### 趋势 1：评测军备竞赛打起"提前量"——尺子未饱和先换新尺

> 依据：ARC Prize 没等 ARC-AGI-2 饱和（54% vs 85% 大奖线）就发布 ARC-AGI-3 交互式基准；Terminal-Bench 一年半四换代；SWE-bench 长成家族（Verified/Pro/Live 月更）。**竞争从"刷爆再换"进化为"抢在饱和前造下一把"**——评测本身成为竞争维度。

### 趋势 2：评测消费者主权时代——私有 mini-benchmark 成为标配技能

> 依据：三部曲反复强调（说了三遍因为最重要）+ Itzhak 2026 vibe testing 形式化 + HELM"承认不完备"纪律 + BaxBench 62% 带漏洞的残酷现实——**公开榜信息密度持续衰减，"把关心场景做成小而诚实的尺子"从建议变成工程师必备技能**。本机 adaptive-inference-routing 的选型测试正是此实践。

## 九、拓展应用推荐

1. **模型选型流程升级**：本机模型切换/评测加"三问"门禁（协议？公开多久？可复现？）——适配 free-model-apis 四线选型
2. **7 维评分因子分析**：用 Burnell 方法验证 iron_rules_engine 7 维独立性，数据说话决定权重简化
3. **私有 mini-benchmark**：把用户高频任务（笔记 7 模块质量/CATIA 需求翻译/股票信号判定）做成 20-50 题私有评测集——模型切换前跑一遍，比任何公开榜可信
