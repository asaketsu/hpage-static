## 核心结论

把大模型搬到机器人本地（Ollama + Jetson/工控机），实现零网络延迟、数据不出本机。得益于 **OpenAI 兼容接口**，云端→本地切换只需改 `base_url`，上层代码一行不用动。Jetson Orin NX 16GB 上 7B INT4 模型总延迟 0.8 秒，已优于云端 API 的 1.1 秒。

## 一、云端 API 的三个瓶颈

| 瓶颈 | 表现 | 场景 |
|------|------|------|
| **延迟** | 端到端 300-2700ms，多步任务 10 秒+ 等待 | "去厨房"单步勉强可接受，五步任务 >10s |
| **网络依赖** | 网络一断机器人失联 | 工厂巡检、地下管廊、灾害救援 |
| **数据隐私** | 敏感数据不能传云 | 医院（患者信息）、工厂（配方）、金融 |

### 本地部署目标

| 指标 | 目标 |
|------|------|
| 延迟 | 端到端 <500ms（单轮推理） |
| 离线 | 完全不需要外网 |
| 隐私 | 数据不出本机 |
| 兼容 | 与桥接节点接口一致，改配置即可切换 |
| 资源 | 在边缘设备（Jetson/工控机）上可运行 |

## 二、三种本地部署方案对比

| 特性 | Ollama | vLLM | llama.cpp |
|------|--------|------|-----------|
| **定位** | 个人/边缘设备 | 服务端高吞吐 | 极致低资源 |
| **安装** | 低（一行命令） | 中（需GPU） | 中（需编译） |
| **OpenAI兼容** | ✅ 内置 | ✅ 内置 | 需配合 server |
| **GPU** | 可选（支持CPU） | 必须 | 可选（支持CPU） |
| **量化** | 自动（GGUF） | AWQ/GPTQ | GGUF（INT2-INT8） |
| **并发** | 单请求为主 | 连续批处理（高并发） | 单请求为主 |
| **适用** | **机器人边缘部署** | 多机器人共享服务器 | 无GPU极限设备 |

### 选型决策树

```
你的场景?
├── 单台机器人，有GPU（Jetson/工控机）→ Ollama
├── 多台机器人共享GPU服务器 → vLLM
├── 无GPU（树莓派/低功耗）→ llama.cpp
└── 混合架构 → 边缘Ollama + 中心vLLM
```

## 三、硬件平台与显存

### 3.1 平台对比

| 平台 | 算力 | 内存/显存 | 功耗 | 可跑模型 | 价格 |
|------|------|---------|------|---------|------|
| Jetson Orin Nano 8GB | 40 TOPS | 8GB 统一 | 7-15W | 7B INT4 | ~$250 |
| Jetson Orin NX 16GB | 100 TOPS | 16GB 统一 | 10-25W | 7B INT8 / 14B INT4 | ~$600 |
| Jetson AGX Orin 64GB | 275 TOPS | 64GB 统一 | 15-60W | 32B INT4 / 14B INT8 | ~$2000 |
| 树莓派5 + Hailo-8L | 13 TOPS | 8GB | 5-8W | 7B INT4（慢） | ~$120 |
| 工控机 + RTX 4060 | 15 TFLOPS | 8GB | 100-200W | 7B FP16 / 14B INT4 | ~$800 |
| 工控机 + RTX 4090 | 82 TFLOPS | 24GB | 200-450W | 32B INT4 / 14B FP16 | ~$2500 |

### 3.2 显存估算公式

```
显存(GB) ≈ 参数量(B) × 量化位数(bit) / 8 × 1.2（含KV Cache）

示例:
  Qwen2.5-7B  INT4:  7 × 4 / 8 × 1.2  ≈ 4.2GB  → 8GB设备
  Qwen2.5-7B  INT8:  7 × 8 / 8 × 1.2  ≈ 8.4GB  → 16GB设备
  Qwen2.5-14B INT4:  14 × 4 / 8 × 1.2 ≈ 8.4GB  → 16GB设备
  Qwen2.5-32B INT4:  32 × 4 / 8 × 1.2 ≈ 19.2GB → 24GB设备
```

## 四、Ollama 部署流程

### 4.1 安装

```bash
# x86 工控机
curl -fsSL https://ollama.com/install.sh | sh

# Jetson Orin (ARM)
curl -fsSL https://ollama.com/install.sh | sh
# 如未正确检测，手动安装 ARM64 版本 + 创建 systemd 服务
# 关键: OLLAMA_HOST=0.0.0.0:11434 (允许外部访问)
```

### 4.2 拉取模型

```bash
ollama pull qwen2.5:7b    # INT4, ~4.7GB
ollama pull qwen2.5:14b   # INT4, ~8.9GB
ollama list               # 查看已下载
```

### 4.3 OpenAI 兼容接口（核心）

```bash
# Ollama 提供 /v1/chat/completions，与 OpenAI API 格式完全一致
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "qwen2.5:7b", "messages": [{"role": "user", "content": "去厨房"}]}'
```

> **这意味着用 openai Python 库直接调用，只需改 base_url。**

### 4.4 Python 调用

```python
from openai import OpenAI

client = OpenAI(
    api_key="ollama",                      # 占位符，Ollama 不验证
    base_url="http://localhost:11434/v1",   # 指向本地
)

response = client.chat.completions.create(
    model="qwen2.5:7b",
    messages=[{"role": "user", "content": "去厨房"}],
    tools=[{...}],  # Function Calling 也支持
)
```

## 五、云端 vs 本地无缝切换

### 切换原理

```bash
# 云端
export OPENAI_BASE_URL="https://api.openai.com/v1"
export OPENAI_API_KEY="sk-xxx"

# 本地 (只需改两行)
export OPENAI_BASE_URL="http://localhost:11434/v1"
export OPENAI_API_KEY="ollama"
```

### 统一桥接节点

通过 `backend` 参数切换：

```python
if backend == "cloud":
    base_url = cloud_base_url      # https://api.openai.com/v1
    model = cloud_model            # gpt-4o-mini
else:
    base_url = local_base_url      # http://localhost:11434/v1
    model = local_model            # qwen2.5:7b

self.llm_client = OpenAI(api_key=api_key, base_url=base_url)
# 上层调用代码完全相同
```

## 六、三级模型选择策略

| 复杂度 | 典型任务 | 推荐模型 | 预期延迟 |
|--------|---------|---------|---------|
| **simple** | 单步指令（"去厨房"） | 7B INT4 | 200-500ms |
| **medium** | 多步规划（"去厨房拿苹果到客厅"） | 14B INT4 | 500-1500ms |
| **complex** | 复杂推理（异常诊断） | 32B INT4 | 1-4s |

### 自动选择逻辑

- 输入 >500 字符 → complex
- 关键词匹配（规划/分析/诊断/异常/故障）→ complex
- 关键词（找到/拿/放/导航/移动）→ medium
- 默认 → simple
- 显存不足自动降级：32B → 14B → 7B

## 七、实测数据

### 推理延迟对比（指令："去厨房拿苹果到客厅"）

| 硬件 | 模型 | 量化 | 首Token | 总延迟 | Token/s |
|------|------|------|---------|--------|---------|
| Jetson Orin Nano 8GB | 7B | INT4 | 380ms | 1.2s | 28 |
| Jetson Orin NX 16GB | 7B | INT4 | 220ms | **0.8s** | 42 |
| Jetson Orin NX 16GB | 14B | INT4 | 520ms | 2.1s | 22 |
| Jetson AGX Orin 64GB | 32B | INT4 | 680ms | 2.8s | 24 |
| 树莓派5 8GB | 7B | INT4 | 2100ms | **8.5s** | 5 |
| 工控机 RTX4060 | 7B | INT4 | 95ms | **0.4s** | 85 |
| 工控机 RTX4090 | 32B | INT4 | 320ms | 1.3s | 52 |

### 云端 vs 本地延迟

| 方案 | 首Token | 总延迟 | 网络 |
|------|---------|--------|------|
| 云端 GPT-4o-mini | 350ms | 1.1s | 需外网 |
| 云端 DeepSeek-Chat | 280ms | 0.9s | 需外网 |
| **本地 7B (NX 16GB)** | **220ms** | **0.8s** | **不需要** |
| 本地 7B (RTX4060) | 95ms | 0.4s | 不需要 |

> **结论**：7B 本地模型在 Jetson NX 上延迟已优于云端 API（省了网络往返）。

## 八、性能优化

### 量化精度选择

| 精度 | 显存(7B) | 速度 | 质量 | 适用 |
|------|---------|------|------|------|
| FP16 | 14.0GB | 1.0x | 最好 | 充足显存 |
| INT8 | 7.5GB | 1.5x | 几乎无损 | 显存中等 |
| **INT4(Q4_K_M)** | **4.7GB** | **2.0x** | **轻微下降** | **边缘首选** |
| INT2 | 2.8GB | 2.5x | 明显下降 | 仅测试 |

### 上下文窗口管理

| 长度 | 首Token延迟 | 适用 |
|------|------------|------|
| 512 | 180ms | 短对话 |
| 2048 | 420ms | 多步任务 |
| 4096 | 780ms | RAG |
| 8192 | 1450ms | 长上下文 |

### 其他优化

- **上下文裁剪**：超出 max_tokens 时从最早消息裁剪 + 摘要
- **模型预热**：启动时预加载，避免首次调用延迟
- **批处理**：多请求合并（vLLM 连续批处理优势）

## 九、常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| Ollama 不启动 | 端口占用/磁盘不足 | 改端口/清理空间 |
| 模型加载失败 | 显存不足 | 换 INT4 或更小模型 |
| 推理变慢 | 模型切换/过热降频 | `ollama ps` 检查/散热 |
| Function Calling 不触发 | 模型不支持/Prompt 不明确 | 用 Qwen2.5 7B+/强调"必须用函数调用" |
| 中文质量下降 | 量化损失 | 用 Q4_K_M（非 Q4_0）/ INT8 / Qwen 系列 |
| Jetson 不识别 GPU | CUDA 环境/版本 | v0.3.0+，检查 CUDA_HOME |
