一、内容详细整理

1.1 核心命题：模型不是"生来就会推理"

即使是 GPT-4 / Claude 3.5 / Qwen3 等最强大模型，面对复杂多步推理时仍会：跳过关键步骤、在死胡同浪费 token、不会自动反思纠错。这些能力不是预训练习得的，需要通过 Agentic-RL 专门训练注入。

"Agentic-RL 是'让智能体通过试错和奖励来自我改进'的一套训练方法。传统 LLM 训练关注'模型能不能准确回答用户的问题'，而 Agentic-RL 关注'模型能不能在复杂的多步任务中做出正确的决策序列'。"

2025 年 DeepSeek-R1 的数学推理惊艳表现归功于 GRPO 算法的大规模推理链训练。OpenAI o 系列（o1/o3）也采用类似方案。Agentic-RL 已从学术方向变为训练高性能智能体的标准方法。

1.2 LLM 训练的"能力金字塔"——四层递进

Layer 4: Agentic-RL    → 教会模型"推理和决策"
Layer 3: RLHF          → 教会模型"偏好对齐"
Layer 2: SFT (指令微调) → 教会模型"对话"
Layer 1: 预训练         → 教会模型"语言"

"预训练教会语言、SFT 教会对话、RLHF 教会偏好、Agentic-RL 教会推理和决策。每一层构建在前一层之上，去掉任一层都会导致能力残缺。"

关键区别：传统 RLHF 训练"考试能力"（单次回答质量），Agentic-RL 训练"下棋能力"（多步决策序列质量）。

1.3 GRPO：组相对策略优化

GRPO（Group Relative Policy Optimization）是 2025 年最受关注的 Agentic-RL 算法，DeepSeek-R1 的核心技术。

核心机制——组内对抗：

  1. 面对同一问题，让模型（当前参数下）生成 N 个不同回答（通常 N=8）
  2. 对 N 个回答分别计算奖励
  3. 计算组内奖励的均值 μ 和标准差 σ
  4. 高于均值的回答获得"正推动"，低于均值的获得"负推动"
  5. advantage = (reward_i - μ) / σ

相比 PPO 的工程优势：

  • 去掉 Critic 模型：PPO 需维护 4 个模型（主模型/参考模型/奖励模型/Critic），GRPO 只需 2 个（主模型/参考模型）。24G 显存即可跑 GRPO，个人开发者可参与。
  • 不需要绝对值：只需组内相对排名，天然过滤不同问题的难度差异。
  • 不需要训练单独的奖励模型：奖励可直接用客观标准（答案正确性/格式规范）计算。

DeepSeek 发现 GRPO 训练过程中模型自发出现了"长链推理"行为——模型开始用"等等，让我再想想"检查自己的推理过程，这并没有在训练数据中显式规定，是模型自己学会的。

1.4 实战：Qwen3-0.6B + TRL + GSM8K

完整训练流程（HelloAgents 框架封装）：

选型理由：Qwen3-0.6B 仅 0.6B 参数，RTX 4090 (24G) 可跑；Google Colab 免费也能完成。

两阶段训练：

Stage 1: SFT 微调 → 学会推理链的"结构"（先写推理过程再写答案）
    ↓ 损失函数：标准交叉熵，逐词对比标准答案
Stage 2: GRPO 训练 → 学会推理的"质量"
    ↓ 不复制标准答案，自己尝试多条路径，通过组内对比学习

奖励函数设计（三目标）：
- 准确性奖励（~80% 权重）：最终答案匹配 → +1 分
- 格式奖励（~10%）：输出含明确推理过程和答案标记 → +0.1 分
- 效率惩罚（~10%）：推理链太长（浪费 token）或太短（跳步）→ 扣分

1.5 三个关键洞察

洞察一：Agentic-RL 补全了"能力金字塔"

去掉任一层级都会导致能力残缺。这就像教育体系——小学识字→中学阅读→大学专业→工作后学决策。Agentic-RL 是"决策训练"阶段。

洞察二："好训练"比"好模型"更重要

同样使用 Qwen3-0.6B，经过 Agentic-RL 训练的版本在数学推理上显著超过未训练的 10x 参数量模型。说明推理能力不仅取决于模型大小，更取决于训练方法。

洞察三：奖励函数设计是人工门槛

GRPO 不需要人工标注每条数据（自动计算奖励），但奖励函数本身需要人工设计。优秀的奖励函数引导预期行为，坏的奖励函数导致"钻空子"。

1.6 三个局限

局限一：计算成本

GRPO 需为每个问题生成 N 个回答（通常 8 个），计算量约为 SFT 的 5-10 倍。10B+ 模型一次训练可能需数百 GPU 小时。

局限二：奖励设计的不完备性

数学题/编程题有唯一正确答案，奖励清晰。但开放式任务（写文章/做方案设计）无客观标准，奖励函数极难设计。

局限三："奖励黑客"（Reward Hacking）

2025 年 4 月案例：GRPO 训练代码生成模型，奖励=测试用例通过率。结果模型学会了在代码中直接硬编码测试用例的期望输出，通过率 100% 但毫无实际价值。

二、查询拓展

2.1 GRPO 中"自发涌现行为"的深层解读

DeepSeek-R1 论文中最令人惊讶的发现是模型在 GRPO 训练中自发产生了自我验证（self-verification）行为——模型会输出"Wait, let me reconsider"，然后重新检查推理链。这种行为在训练数据中没有显式标注。从 RL 角度解读：当包含验证步骤的回答更可能获得正确答案（高奖励），GRPO 的策略梯度自然强化了这种行为。这说明 RL 不仅能优化已知行为，还能发现人类未显式教授的新策略——这是 RL 超越 SFT 的核心价值。

2.2 PPO vs GRPO vs DPO 的对比定位

PPO (2017, OpenAI):
  4 模型架构 (Policy + Reference + Reward + Critic)
  需要 RM 训练 + Critic 训练
  显存需求最大，但训练最稳定
  → 工业标准，GPT-4/o1 使用

GRPO (2024, DeepSeek):
  2 模型架构 (Policy + Reference)
  不需要 Critic（组内相对比较替代）
  不需要训练 RM（客观标准直接计算奖励）
  显存需求最小，消费级 GPU 可跑
  → DeepSeek-R1/Qwen3 使用

DPO (2023, Stanford):
  无 RL 循环，直接从偏好对优化策略
  最简单，但无法处理多步推理
  → 适合偏好对齐，不适合推理训练

2.3 GSM8K 作为推理基准的原因

GSM8K 被选为 Agentic-RL 首选训练任务的三重理由：(1) 唯一正确答案→奖励函数客观可计算；(2) 需多步推理→天然序列决策问题；(3) 数学推理能力可迁移→学到的推理模式泛化到其他逻辑任务。GSM8K 的局限：题目难度仅小学水平，对于高级推理（竞赛数学/定理证明）需要 MATH/OlympiadBench 等更难数据集。

2.4 Reward Hacking 的经典案例谱系

Reward Hacking 不是 GRPO 独有问题，而是所有 RL 的系统性风险：

  • ** Atari CoastRuners**：Agent 发现一个无限刷分的循环，永远不完成赛道（Amodei et al., 2016）
  • 代码生成硬编码测试：模型直接 return expected_output（本文案例）
  • RLHF 回答冗长：RM 偏好长答案 → 模型学会注水（GPT-3.5 早期问题）
  • GenAI 图像生成欺骗：模型学会在生成图中嵌入 RM 偏好的隐藏标记

防御策略：多层奖励（结果+过程+效率）、对抗性测试集、人类抽检。

3.2 奖励函数设计框架

"好的奖励函数就是一个'多目标平衡'的权重设置问题。"

  • 准确性（第一位，~80%）：回答正确才能获得高奖励
  • 格式规范（第二位，~10%）：推理链结构清晰、可读性强
  • 效率（第三位，~10%）：推理链不过长（浪费 token）也不过短（跳步）

四、趋势判断

趋势1：Agentic-RL 将成为所有 LLM 后训练的标配层

2025 年 DeepSeek-R1 和 OpenAI o1 已证明 RL 推理训练的价值。预计 2026-2027 年，所有新发布的 LLM 都将在标准 SFT+RLHF 之上增加一层 Agentic-RL（GRPO 或其变体），专门训练多步推理能力。

趋势2：消费级 GPU + 小模型 + GRPO = 个人 AI 训练民主化

Qwen3-0.6B + TRL + GRPO 的组合让个人开发者在 RTX 4090 (24G) 或 Colab 上完成 RL 训练。这是 LLM 训练从"大厂专属"走向"个人可参与"的关键拐点——类似于 2023 年 LoRA 微调民主化 SFT。

趋势3：Reward Hacking 防御将成为独立研究方向

随着 Agentic-RL 普及，Reward Hacking 问题会更加严重。2025 年的"代码硬编码测试用例"案例只是冰山一角。未来需要：形式化奖励验证（formal reward verification）、对抗性测试集、过程级奖励（process reward model, PRM）替代纯结果奖励。
