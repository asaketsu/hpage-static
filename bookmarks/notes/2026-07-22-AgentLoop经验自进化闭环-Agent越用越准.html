AgentLoop 经验自进化闭环：让 Agent 越用越准、成本越来越低

出处: 微信公众号 - 马云雷（阿里妹）
日期: 2026-07-22
标签: #AI-Agent #经验自进化 #AgentLoop #Trace分析 #阿里 #质量优化 #成本优化
核心内容 (conf=0.95): 阿里 AgentLoop 构建"模型外经验层"——从 Agent 真实运行 Trace 中清洗出标准化 Trajectory（压缩至原始数据 4-6%），跨轨迹挖掘有效路径/失败模式/恢复策略，形成结构化经验库，在运行时通过 Recall Skill+CLI 注入上下文。不修改模型权重，仅靠经验召回提高成功率+稳定性+降低单位成功成本。

一、核心架构：经验自进化飞轮

观测 → Trace清洗 → Trajectory组装 → 跨轨迹挖掘 → 结构化经验
    ↑                                                    ↓
  再运行 ← 召回注入 ← Recall Skill ← 经验库 ←──────┘
阶段 做什么 关键产出
Trace 清洗 去除基础设施 Span、重复消息、无关日志 高价值 Trajectory（原始 Trace 的 4-6%）
Trajectory 组装 保留任务目标、行动步骤、工具调用、观察结果、错误、恢复过程、最终结果 标准化决策序列
经验挖掘 跨多条轨迹比较，识别反复出现的有效动作和高风险路径 结构化经验卡片
运行时召回 根据当前任务/工具/进度/错误状态，召回少量适用经验 注入 Agent 上下文

二、五类结构化经验

经验类型 说明 Hermes 对应
工具选择和调用顺序 哪个入口最有效、什么顺序最优 Skill 加载优先级
参数规则与前置条件 工具调用的参数约束、数据范围 Skill Pitfall 章节
反模式（Anti-pattern） 容易导致失败的错误路径 error-case-library
错误恢复策略 遇到错误后如何绕行/恢复 evolver 自动修复规则
结果验证规则 什么才算真正完成 verification-gate skill

四、与现有能力层的差异定位

能力 解决什么 如何生效
Memory 用户/会话历史 检索事实和偏好
RAG/知识库 业务事实和规则 外部知识检索
Workflow/SOP 标准流程 人工定义步骤

一句话：Memory 让 Agent 记得过去，RAG 让 Agent 找到知识，Skill 让 Agent 获得能力，经验自进化让 Agent 在当前任务中复用真实验证过的方法。

六、🔥 借鉴分析：Hermes 可落地的改进点

当前 Hermes 已有的"半成品经验闭环"

Hermes 组件 对应 AgentLoop 概念 差距
evolver skill 经验挖掘 + 反模式 ❌ 只从错误学，不从成功轨迹学
error-case-library 反模式库 ✅ 已有，但无自动召回
session-distill Trajectory 提取 ❌ 只做摘要，不做跨轨迹比较
Skills (Pitfall/Verification) 参数规则/验证规则 ✅ 有，但人工维护
exchange-protocol 多 Agent 共享 ✅ 三机经验池已有
Memory (L1/L2/L3) Memory 层 ✅ 已分层

可落地的 5 个改进方向

1. 🔴 成功轨迹经验挖掘（evolver 升级）

现状：evolver 只从错误学（error-case-library）。
改进：成功 cron/任务执行后，自动提取"有效路径"存入经验库。
实现：cron 成功执行后，检查 agent.log 的工具调用序列，与历史失败轨迹对比，差异部分即为"有效经验"。

2. 🟡 Trace→Trajectory 压缩

现状：session-distill 只做文本摘要。
改进：提取结构化 Trajectory（目标→步骤→工具→结果→恢复），压缩至原始 4-6%。
实现：扩展 session-distill 脚本，输出 JSON 格式的 Trajectory 而非散文摘要。

3. 🟡 运行时经验召回

现状：error-case-library 需要人工或 evolver 主动查。
改进：任务启动时自动召回相似历史经验注入上下文。
实现：新增 session-boot hook，根据任务关键词自动从 error-case-library + evolver 经验池召回 Top-3 经验卡片。

4. 🟢 质量度量仪表盘

现状：observability-dashboard 有工具调用统计，缺成功率/稳定性维度。
改进：增加"同类任务多次执行成功率"、"首次完成率"、"失败模式集中度"指标。
实现：扩展 watchdog 统计逻辑，按 session title 聚类计算。

5. 🟢 单位成功成本追踪

现状：有 token 统计（ccusage），但无"每成功任务成本"。
改进：用 token / 任务成功标志 计算真实单位成本。
实现：cron 执行记录已有 ok/error 标记，结合 session token 消耗即可计算。
