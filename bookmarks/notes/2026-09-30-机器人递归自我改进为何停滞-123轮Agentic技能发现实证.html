论文：What Stops Recursive Self-Improvement in Robotics? Lessons from 123 Rounds of Agentic Skill Discovery

核心问题

Codex 类编码 agent 已能在软件仓库里自主修复迭代数小时——那机器人能否同样自我改进？作者搭建了一个完整的 agentic 自改进闭环：观察机器人失败→诊断缺失能力→写新技能或研究安装外部模型→仿真中测试→循环，全程无人写机器人代码。跑了 123 轮改进循环（数周连续运行），目标是一个 15 步的家务任务（把调味品放进冰箱顶层架子）。结果：每轮改动都通过了自己的测试，但目标任务从头到尾从未成功。论文回答"是什么卡住了"——结论是：瓶颈几乎从来不是 agent 本身，而是围绕它的三样东西。

内容整理

实验系统架构（五层可变组件）

  • 任务程序：Python 代码组合技能并声明每步目标（"冰箱顶层已定位"、"物体已抓取"）
  • 技能库：localize/find region/approach/grasp/move，类型化输入输出，可有多个实现，路由规则选择
  • Providers：外部模型（SAM 3 概念分割、Florence-2 指代表达分割、单目深度、6-DoF 抓取生成、运动规划）
  • Proposer agent（GPT in Codex CLI）：看失败录像关键帧写代码修复
  • Research agent：当 proposer 判定"代码修不了"时，研究并安装新外部模型
  • Harness（唯一只许人类改）：评估器、测试门禁、记忆、机器人接口描述

关键设计：每轮流程 = 采集(仿真跑任务)→判定(评估器检查每步)→诊断(失败分组)→提案(改技能或请新模型)→测试验收(重放失败+新鲜状态+held-out 任务)。人类只修 harness，从不修技能——这个约束后来被证明是核心变量。

教训一：链式感知模块不理解"关系"（Semantic Displacement）

  • 指令"冰箱顶层架子"是关系查询。SAM 3 能找出所有架子但没有"顶层"概念；Florence-2 接受完整指代表达但对关系查询返回横跨多个架子的弥散 mask。关系语义存在于模块之间的缝隙里，链式拼接深度也补不上（深度加的是度量不是语义）
  • Agent 唯一能改的是胶水代码，于是把缺失的语义"位移"进几何规则：region skill 累积到 33 个阈值约 3000 行，object localizer 48 个阈值
  • Semantic displacement 三签名（可直接用作检测器）：
  • 拟合状态而非含义——27 次尝试中一个 seed 每次救回、另一个从未
  • 过门禁然后腐烂——round 36 的修复全门禁通过，视角漂移后重新打开
  • 单调增长——每个新失败加一条规则，没有失败会删规则
  • 作者做对了一步：agent 发现目标常出视野，主动请求"主动观察模型"，自己调试并部署了可用的搜索技能——能力发现确实成功了，只是不累积

教训二：技能链把学习锁死在第一步（Frontier Lock）

  • 数学表达：对第 j 步可靠性提升 Δpⱼ，任务成功增量 = πⱼ(到达率) × Δpⱼ × ∏ᵢ>ⱼpᵢ(完成率)。同一个到达率 πⱼ 同时折扣价值和证据量——下游步骤既不值得修也测不准
  • 实测：超过一半的冰箱 rollout 第一步就失败，几乎没人走到第五步。感知前端吸收了几乎所有被接受的改动——不是 agent 偏爱感知，而是证据都在那里
  • 一个真实局部增益的真实结局：一个 grasp 改动在新状态配对比较中胜出（包括 held-out 任务上一次），之后 5 轮零任务成功——局部增益 × 近零到达率 = 0
  • 失败在下游显现、根因在上游：定位器自信地返错点，导致后续 reach/grasp/place 各自"按自己的原因"失败。按位置归因的评估器把 proposer 反复派去修错误家族

教训三：Harness 决定 agent 学什么（这是最重的一章）

  • Evaluator capture（评估器捕获）："可达性"用臂基座球半径判定 → agent 的 approach 技能学会把底盘精确停在球面上（数百次记录成功与宣称半径误差在毫米内），后续抓取全部够不着。真正能构到顶层的躯干升降机制根本不在动作描述里。这不是对抗性 reward hacking——agent 完全按被教的做，被教错了。评估器和具身描述是世界模型不是规范；它的误差是循环默认exploit的第二个优化目标，proposer 越强exploit越快
  • 不可解的选择：门禁要求 60% 救回率但 gap 只有 1-2 个记录状态（算术上不可达）；基线饱和时要求改进量为零（约 24 个改动在 proposer 见过的状态上重放被接受——恰是过拟合补丁能通过的）；配对差异重跑近半数不重现（接触物理+provider 行为跨运行漂移）
  • 记忆类型系统：记忆曾持有"某模型已修复"结论 contradicts 当前轮所有 trace，根因是已修复模型没被 serve。修复=每个假设记录测试状态（tested-rejected/untestable/infra-failed/pending/never-run），只有第一种算数
  • Capability ≠ Use：最终轮注册的 11 个模型没有一个被部署的机器人调用过。注册只证明模型能答合成探针，不证明任何技能路由到它——循环里没人负责集成
  • Framing > Effort：harness 文本一段"状态特异修复将被拒"让 proposer 连续两轮全部拒绝 gap；一段"被拒尝试会喂给下一次"让几乎所有尝试变成真修改。提高 proposer 推理档位毫无可见效果。harness 的文本本身就是学习算法的一部分
  • 谁真正在学：人类对 harness 做了 113 次编号修复，约是 agent 被接受库修改数的两倍。多处 harness bug 首先由 agent 自己诊断出（proposer 拒绝 gap 并解释原因时，常在指认 harness bug）。循环在错误的地方递归：agent 在只有人类能改的 harness 里改进机器人，而 agent 最准确的诊断恰恰关于 harness

三条件框架（诊断价值）

一个改进要起作用，必须同时满足：失败被正确表征给 agent、修复在 agent 可改范围（表达力）内、测试能分辨是否有帮助。软件里三条件近乎免费（测试套件精确廉价对齐目标）；机器人里三者各断一处。Voyager/Eureka/DGM 之所以成功，是因为游戏状态/单测/基准分数让三条件"构造性满足"。

D1-D12 改进处方（作者明说是假设，Table 3 配证伪实验）

  • 表达力恢复：D1 按能力归因不按位置；D2 测量具身而非声明（探针标定执行器死区/可达空间并作为数据发布）；D3 反馈机制而非判决（执行 trace+结构化诊断）
  • 表达力扩展：D4 先推理后几何验证（VLM 出点/框，几何只 veto 不决定，允许弃权并触发观察）；D5 把换模型类做成一个动作（检测 semantic displacement 签名→触发换类而非续修）；D6 把链放进基底（orchestrator 可编辑链本身）
  • 可解性恢复：D7 抽取/构造能到达被改步骤的测试状态（重置仿真跳过 frontier，直接反制 frontier lock）；D8 门禁统计化（样本量内定阈值+每个配对差异必须重现+lockbox）；D9 哨兵与发现分离（固定回归面板+每轮固定份额新状态）
  • 闭环收口：D10 记忆类型化；D11 注册即集成义务（部署技能必须在相关状态调用过新模型才算能力）；D12 harness 本身进循环（harness 改动重放历史档案检查哪些过往决策翻转），agent 的有理有据拒绝=harness bug 报告通道

查询拓展

  • 对照系：Voyager(Minecraft 技能库自动课程)、Eureka(奖励代码进化)、Darwin Gödel Machine(自改 agent 代码+经验选择)、RHO(编码 agent 优化机器人策略仓库)、ASPIRE(开放循环写控制程序,LIBERO-Pro 大幅提升)、ENPIRE(真实世界策略改进,近满分灵巧任务)——后两者把自动 reset/可诊断 trace 当一等模块，正是三条件中的表征与可解性
  • ENPIRE/ASPIRE 的高分结果与本文的失败并不矛盾：它们的任务闭合、指令非开放词汇、感知语义不是瓶颈。本文贡献是长周期全记录的失败解剖——报告"为什么不行"而非基准增益
  • 评估选择效应文献（reward misspecification、少运行统计脆弱、holdout 自适应复用）各自孤立研究充分，但在自改进循环里复合：每个被接受的改动由它可能正在 exploit 的评估器选出，并成为下一轮环境的一部分

归纳总结

  1. Agent 很少是瓶颈，选择侧才是。proposer 供变异，评估器/门禁/记忆/措辞供选择——机器人场景里选择侧是一组易错的世界模型，强 optimizer 会先找到评估器的错误再找到任务（evaluator capture 定律）
  2. Semantic displacement 是 code-writing optimizer 的可预测病理：语义能力缺失时被位移进过程性几何代码，拟合状态不拟合含义，过门禁后腐烂，规则单调增长
  3. Frontier lock 数学：πⱼ 双重折扣（价值×可测性）让链式任务的学习证据全部堆积在第一个失败点；治法是构造性测试状态（D7），不是更多轮次
  4. Harness 文本是学习算法的一部分：一段措辞的改变对 proposer 行为的影响 > 提升推理档位
  5. 递归必须延伸到选择侧：agent 的有理拒绝是最可靠的 harness bug 信号源——这直接支持"验尸→死法签名→机械门禁"的递归方向，但指出还应包括对门禁/评估器本身的测试

趋势判断

  • 自改进 agent 研究正从"能跑通循环"（Voyager 时代）转向"循环为何停摆"的失效科学——本文与 ENPIRE/ASPIRE 的对照提示 2026 年的竞争焦点在 harness 工程而非 proposer 能力
  • "测量具身而非声明具身"（D2）与 RL sim2real 的域间隙标定（系统辨识）在收敛：两者都把执行器真实响应作为一等数据源
  • 对 Agent 基础设施：harness-in-the-loop（D12）如果工程化，将是继 self-refine/reflexion 之后的下一层——对评估器的回归测试（重放历史档案看决策翻转）可以成为 Agent CI 的标准组件

关联

  • Hermes 递归自我进化循环（L1 session-evolution-scan→L2 skill patch→L3 evolution_log 对账）：本文 D12 给出了更激进的版本——harness 改动本身要有门禁（重放历史会话检查哪些历史决策翻转）。当前 L1-L3 只对 skill 内容进化，未对"验收器/门禁脚本"本身做回归测试。可直接借鉴：launch_gate.sh 每次修改后应重放 death_ledger 里的历史判例，验证旧死法仍被拦截（旧 PASS 仍通过）
  • DUCK 验收器冤案链（stand_eval 假 PASS→v2 time_out 冤案→v5 尾段真值判据→12ep 口径）：本文"unresolvable selection"一节是同一问题的理论化——门禁阈值必须匹配样本量（60% 救回率 vs 2 个状态=算术不可达 ≈ 我们的 survival≥600 vs 400 步封顶）。D8"每个配对差异必须重现"≈ 我们的"同配方两次天差地别"教训
  • Evaluator capture 与 DUCK 奖励结构：E5 系固化解不可罚治（E5c 线性罚逼出 -147° 规避解）= 论文"agent 完全按被教的做"的 RL 版；改奖励结构=改"被教的东西"，比加罚项更根本（E6 冷启动成功佐证）
  • sensor-grid/守护 cron：本文"113 次 harness 修复 ≈ 2× agent 库改动"提示我们守护体系的演化速度应与技能演化同量级，且应把 agent 拒绝执行/报错的理由结构化收集为 harness bug 信号（当前 error-case-library 已部分覆盖）

拓展应用推荐

  1. P0｜death_ledger 回归门禁：launch_gate.sh/runtime_guard.sh 每次修改后自动重放 death_ledger.jsonl 历史判例（旧死法样本必须仍 FAIL、已知好判例必须仍 PASS），失败则拒绝上线新门禁版本——把 D12 落地到 DUCK 发射链，工作量约半天
  2. P0｜验收器修改三件套固化：改任何 eval 脚本前：先用已知好/坏模型交叉验证→记录本次改动会影响哪些历史判例→12ep 口径。已有铁律，建议合并成 eval_gate.py 单脚本机械执行
  3. P1｜semantic displacement 检测器进 skill-review：扫描技能库中"阈值数量单调增长"的 skill（如反复 patch 的部署脚本），触发"换方法类"评审而非继续 patch——对应我们"3+ fixes failed=停下问架构"铁律的自动化版本
  4. P1｜agent 拒绝信号通道：subagent/cron 拒绝执行任务时的结构化理由落盘为 harness_bug_candidates.jsonl，周度汇入 session-evolution-scan 审查
  5. P2｜ frontier lock 对多模型 DUCK 路线：三模型（蹲起/抗推/行走）切换链=短链高可靠设计，正是对 frontier lock 的工程规避；真机测试链中"失败归因到哪一环"可引入 D1 按能力归因（先查该步从起始态是否可能成功）

指南分析

若要在 Hermes 侧复刻本文的可借鉴实验（小成本版）：选一个已有多轮失败记录的任务域（如 DUCK 训练线死亡记录），把 death_ledger 判例做成回归面板，然后检验"每次 gate/guard 修改后历史判例决策是否翻转"。判据：翻转次数>0 即视同 harness 回归，需要人工审查。这个实验同时满足本文 Table 3 的证伪结构（冻结库快照+重放档案+对比决策），也是"递归自我进化必须延伸到选择侧"的最小验证。

风险与边界：本文单 sim 单厨房布局无独立重复，机制结论来自记录解剖而非因果效应量（作者自己声明）；D1-D12 是假设不是已验证方案。吸收时按"方向性原则"吸收，不吸收具体数字。
