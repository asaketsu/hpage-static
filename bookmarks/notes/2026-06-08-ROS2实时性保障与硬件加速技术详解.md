## 0. 引言

机器人系统中实时性决定生死：自动驾驶 80km/h 下 100ms 延迟 = 2.2m 额外制动距离；手术机器人 1ms 延迟可能导致不可逆组织损伤。

原生 ROS2 在默认 Linux 调度下消息传输延迟抖动达**毫秒级**，对需要微秒级响应的控制系统不可接受。

---

## 1. ROS2 执行模型

### 1.1 执行器类型

| 类型 | 特点 |
|------|------|
| `SingleThreadedExecutor` | 单线程顺序执行，简单但并发有限 |
| `MultiThreadedExecutor` | 线程池并行，吞吐高但调度复杂 |
| `StaticSingleThreadedExecutor` | 针对固定订阅优化的单线程 |

### 1.2 默认执行器核心问题

- **无优先级区分** — 紧急停止和普通日志同等对待
- **轮询调度** — 按到达顺序处理，非按重要性
- **资源分配不确定**

## 2. 回调机制优化

### 2.1 回调延迟分解

端到端延迟 = 消息发布 + DDS 传输 + 队列等待 + 调度延迟 + 回调执行

### 2.2 回调组策略

| 回调组类型 | 适用场景 |
|-----------|---------|
| `MutuallyExclusive` | 高优先级控制，保护共享资源，串行执行 |
| `Reentrant` | 低优先级数据/日志，可并行执行 |

---

## 3. 高级执行器配置

### 3.1 多线程执行器优化三要素

1. **线程数量** — 匹配 CPU 核心数
2. **CPU 亲和性** — `pthread_setaffinity_np()` 绑核，减少缓存失效
3. **调度优先级** — `SCHED_FIFO` + `sched_priority`，需 root/CAP_SYS_NICE

### 3.2 专用执行器模式

为不同优先级创建独立执行器：
- **高优先级** (priority=99, CPU0) → `SingleThreadedExecutor` — 实时控制
- **中优先级** (priority=50, CPU1) → `MultiThreadedExecutor` — 数据处理
- **低优先级** (default) → `SingleThreadedExecutor` — 后台任务

关键配置：
```c
mlockall(MCL_CURRENT | MCL_FUTURE);  // 锁定内存防页面交换
pthread_setschedparam(pthread_self(), SCHED_FIFO, &sch_params);
pthread_setaffinity_np(...);  // CPU 绑核
```

## 4. 优先级调度 — PiCAS 框架

PiCAS（Priority-driven Chain-Aware Scheduling）核心思想：将回调组织成**处理链**，按链优先级调度。

自定义优先级调度器关键实现：
- 优先级队列（`std::priority_queue`），数值越小优先级越高
- 同优先级 FIFO
- 优先级订阅封装：`create_priority_subscription(topic, qos, callback, priority)`

典型优先级分配：
| 回调类型 | 优先级 |
|---------|--------|
| 紧急停止 | 1（最高）|
| 运动控制 | 10 |
| 状态监控 | 50 |
| 数据记录 | 100（最低）|

## 5. 系统级实时性配置

### 5.1 PREEMPT_RT 内核

标准 Linux → 打 RT 补丁 → 完全可抢占内核。

构建步骤：
```bash
# 下载内核 + RT 补丁
wget linux-5.4.78.tar.xz && wget patch-5.4.78-rt44.patch.xz
# 应用补丁
xzcat patch-*.patch.xz | patch -p1
# menuconfig → Fully Preemptible Kernel (RT)
make -j$(nproc) && sudo make install
```

### 5.2 系统配置清单

| 配置项 | 命令/设置 |
|--------|----------|
| 实时优先级权限 | `/etc/security/limits.conf`: `rtprio 99`, `memlock unlimited` |
| CPU 性能模式 | `cpupower frequency-set -g performance` |
| 禁用透明大页 | `echo never > /sys/kernel/mm/transparent_hugepage/enabled` |
| 网络队列优化 | `tc qdisc add dev eth0 root fq_codel` |

### 5.3 DDS QoS 配置

| 消息类型 | QoS 策略 |
|---------|---------|
| 控制命令 | `reliable()` + `deadline(10ms)` + `lifespan(50ms)` |
| 传感器数据 | `best_effort()` + `deadline(33ms)` — 减少延迟 |
| 状态监控 | `reliable()` + `transient_local()` — 保留最新值 |

## 6. 实时性能监控

### 6.1 自定义监控组件

- 记录每个回调的 min/max/avg 延迟和调用次数
- 超阈值告警（emergency 1ms, control 5ms, other 10ms）

### 6.2 ROS2 Tracing

```bash
ros2 trace -k -u "ros2:*" --duration 10
ros2 trace-analysis analyze trace/
```

配合 Python + pandas 做延迟分布分析。

## 7. 硬件加速

### 7.1 核心思路

"让专业芯片干专业的事" — GPU/FPGA/NPU 数量级提升。

### 7.2 NVIDIA Isaac ROS (GPU)

- **NITROS**（NVIDIA Isaac Transport for ROS）实现零拷贝数据传输
- CUDA 流式处理：`cudaMemcpyAsync` + kernel launch + 异步回拷
- 性能测量：`cudaEventRecord` 精确计时

GPU 图像处理关键步骤：
1. CUDA 初始化 + 显存分配
2. Host→Device 异步拷贝
3. CUDA kernel 并行处理
4. Device→Host 异步回拷
5. 事件同步 + 发布结果

## 核心要点总结

| 层级 | 优化手段 | 效果 |
|------|---------|------|
| 应用层 | 回调分组 + 专用执行器 | 任务隔离，避免阻塞 |
| 调度层 | SCHED_FIFO + CPU 绑核 + mlockall | 确定性调度 |
| 框架层 | PiCAS 优先级调度 | 关键回调优先执行 |
| 内核层 | PREEMPT_RT | 微秒级抢占延迟 |
| 中间件层 | DDS QoS 优化 | 减少传输延迟 |
| 硬件层 | GPU/NPU/FPGA 加速 | 数量级性能提升 |
