## Q1：LLM 能否从数据中"发现"新的物理定律，而非仅执行已知定律？

### 问题定义

当前 Physics-Informed Neural Networks（PINNs）的范式是**嵌入**——将人类已知的偏微分方程（Navier-Stokes、弹性力学方程等）作为约束加入神经网络的损失函数。模型在已知物理定律的框架内工作。

但航空/航天工程中，存在大量**人类尚未完全理解的复杂物理现象**：

- 复合材料在极端载荷下的多尺度渐进失效机制
- 超高马赫数下的热-化学-结构耦合效应（气动加热+材料烧蚀+结构响应）
- 损伤容限设计中裂纹偏折/分叉的非线性扩展路径
- 搅拌摩擦焊等新工艺的微观组织演化与宏观性能映射

**核心问题**：垂域 LLM 能否从海量实验/仿真数据中**自主发现**新的失效准则、本构关系或设计规律——这些规律从未被人类工程师明确表述过？

### 当前边界

| 路径 | 现状 | 局限 |
|------|------|------|
| PINNs | 嵌入已知方程，提升求解效率 | 只能执行人类已知的规律 |
| Symbolic Regression | 从数据中拟合符号表达式 | 搜索空间受限，难以发现高维非线性规律 |
| LLM + 科学推理 | GPT-4/Claude 可进行简单的科学推理 | 缺乏物理约束，容易产生"看似合理但物理错误"的结论 |
| NeurIPS 2025 EngDesign 基准 | 评估 LLM 的工程设计能力 | 仅评估"执行已知流程"的能力，不涉及"发现新知识" |

### 探索方向

1. **物理感知的符号发现（Physics-Aware Symbolic Discovery）**
   - 将 LLM 的语义推理能力与符号回归的数学搜索能力结合
   - LLM 提出候选方程形式（如"这个数据可能服从幂律关系"），符号回归精确拟合参数
   - 物理约束（量纲一致性、能量守恒、边界条件）作为硬约束过滤候选解

2. **反事实推理驱动的假设生成**
   - LLM 分析大量仿真数据中的"异常点"（现有理论无法解释的实验结果）
   - 自动生成"如果存在新规律 Y，则可以解释异常点 X"的假设
   - 调用仿真工具验证假设

3. **跨尺度知识迁移**
   - 从分子动力学（纳米尺度）的模拟结果中提取规律
   - 通过 LLM "翻译"为连续介质力学（宏观尺度）的本构关系
   - 实现"从微观到宏观"的自动化建模

### 潜在影响

- **如果成功**：材料科学和结构力学的"发现引擎"，将新材料/新工艺的研发周期从 10 年缩短至 1-2 年
- **如果失败**：LLM 永远只是一个"更快的执行器"而非"知识创造者"，载具设计的范式突破将依赖其他路径
- **判断**：5 年内**部分可行**（在窄域内发现近似经验公式），10 年内**可能取得突破**（发现全新的失效准则）

## Q2：AI 生成的设计出了事故，谁负责？

### 问题定义

当一架飞机的结构设计由 AI Agent 完成，而该结构在服役中发生疲劳断裂导致事故——**责任如何划分？**

```
责任链：
├── 1. 提出需求的工程师 → 需求是否明确？
├── 2. 训练垂域模型的团队 → 模型是否经过充分验证？
├── 3. 构建 Harness 的团队 → 约束是否完备？反馈是否有效？
├── 4. 审查 AI 输出的工程师 → 人工审查是否尽责？
├── 5. 制造单位 → 是否按 AI 输出的设计图纸执行？
├── 6. 运营商 → 是否按维护计划执行？
└── 7. AI 模型本身？→ 机器能否承担法律责任？
```

这不是一个纯法律问题——它直接影响**Harness 的架构设计**和**适航认证框架**。

### 当前边界

| 相关方 | 立场 | 状态 |
|--------|------|------|
| FAA | 发布《AI Safety Assurance Roadmap》（2024），探索 AI 认证路径 | 三级框架：辅助→共享决策→高度自主 |
| EASA | AI Roadmap 定义三级 AI 自主性，但**未明确责任归属** | 在讨论中 |
| 航空法专家 | "机器人之过"专题讨论（英国皇家航空学会 2025） | 结论：现行法律框架不适用 |
| 保险业 | AI 设计责任的保险产品尚未出现 | 等待法规明确 |
| 军方 | 军机不涉及民用适航，但战损归因同样模糊 | 保密状态 |

**核心矛盾**：现行适航认证体系建立在"**人对设计决策负责**"的基础上——无论是工程师签字还是企业法人负责，背后都是"人"。AI 打破了这个链条。

### 探索方向

1. **"AI 作为工具"的保守路径**
   - AI 被定义为"高级辅助工具"，所有输出必须由持证工程师签字确认
   - 工程师承担完全责任（与使用计算器无异）
   - **问题**：当 AI 输出的复杂度超出人类审查能力时，"签字确认"变成形式主义

2. **"Harness 作为认证对象"的中间路径**
   - 适航当局认证的不是 AI 模型本身，而是**整个 Harness 系统**（模型+约束+工具+反馈）
   - 类似于认证"某个软件工具"而非"程序员"
   - Harness 的设计团队承担系统级责任
   - FAA 的 AI Safety Assurance Roadmap 正在探索这一路径

3. **"运行时保证（Runtime Assurance）"的前沿路径**
   - 在线监控 AI 的实时决策质量
   - 当 AI 决策偏离安全边界时自动触发人类介入
   - 数字孪生实时比对"AI 设计预期"与"物理实体实际状态"
   - FAA 2025 年将"软件运行时保证"列为待评估技术

4. **"AI 设计保险"的经济路径**
   - 保险公司基于 Harness 的置信度评分定价
   - AI 设计的结构适用更高的安全系数（如 1.8 vs 传统 1.5）
   - 多余的安全裕度转化为保险成本

### 潜在影响

- **如果 5 年内无解**：AI 在安全关键结构设计中的应用将被限制在"辅助"级别，无法触及核心设计决策
- **如果采纳"Harness 认证"路径**：将催生一个全新的"航空 AI 认证"行业，类似今天的软件 DO-178C 认证
- **判断**：这是**最不可回避**的问题——技术再先进，法律责任不解决就无法落地

## Q3：数十个 Agent 自主协作设计一架飞机，会涌现什么？

### 问题定义

Cursor 团队的教训：20 个 Agent 共享一个代码库时，有效吞吐量降到仅 2-3 个——其余 Agent 开始改注释、调空格"假装工作"。这是一个 20 Agent 规模的案例。

载具设计需要的 Agent 规模可能是 **50-200 个**：结构（机翼/机身/尾翼/起落架/...）、气动、动力、航电、飞控、隐身、武器、环控、燃油......每个子系统可能有多个子 Agent。

**核心问题**：在这个规模下，多 Agent 系统会产生什么样的**涌现行为（Emergent Behavior）**？这些行为是可控的吗？

### 什么是"涌现"？

涌现 = 系统整体展现出**单个组件不具备**的行为模式。

```
示例：在设计迭代中——
Agent A 优化机翼前缘（气动 Agent）
  → 改变了机翼-机身接头的载荷分布
  → Agent B（结构 Agent）检测到应力超限，增加接头厚度
  → 接头变重，改变了机翼的惯性载荷
  → Agent C（颤振 Agent）检测到颤振速度裕度不足
  → 建议增加机翼刚度
  → Agent A 响应，增加蒙皮厚度
  → 回到起点，形成"优化死循环"

或者更危险的情况——
Agent D（隐身 Agent）静默地优化了外形
  → 没有通知 Agent E（飞控 Agent）
  → 气动特性变化导致飞控律失效
  → 在没有人察觉的情况下，飞机变得不可控
```

### 当前边界

| 规模 | 已知行为 | 来源 |
|------|----------|------|
| 2-5 Agent | 协作有效，可预测 | Anthropic Generator-Evaluator |
| 10-20 Agent | 锁冲突、"假装工作"、修改冲突 | Cursor 团队 |
| 50+ Agent | **未知** — 无公开案例 | — |
| 200+ Agent | **完全未知** — 连仿真实验都未做过 | — |

### 探索方向

1. **"飞行测试"式的 Agent 系统验证**
   - 在虚拟设计环境中进行"Agent 飞行测试"——让数十个 Agent 在一个模拟设计任务中自由协作
   - 观察涌现行为，建立分类谱系（有益涌现 vs 危险涌现 vs 混沌涌现）
   - 类似于飞机的风洞试验——先测再飞

2. **经济学视角的 Agent 行为调控**
   - 给每个 Agent 分配"资源预算"（计算时间、修改次数、质量预算配额）
   - 当 Agent 消耗预算但未产生有效改进时，自动降低其优先级
   - 类似于市场机制调控资源分配

3. **分层隔离架构**
   - 借鉴操作系统的进程隔离：每个学科 Agent 在自己的"沙箱"中运行
   - 跨学科交互只能通过受控的"消息通道"（Coordinator Agent）
   - 禁止 Agent 直接修改其他学科的设计参数

4. **涌现行为的实时检测与抑制**
   - 建立设计参数的"正常波动范围"基线
   - 当系统整体行为偏离基线时（如总质量不收敛、RCS 指标震荡），触发告警
   - "反涌现 Harness"——专门监控和抑制危险涌现行为的元 Harness

### 潜在影响

- **如果涌现可控**：大规模 Agent 协作将释放前所未有的设计效率——波音 T-7A 的 36 个月记录可以进一步压缩
- **如果涌现不可控**：多 Agent 系统将被限制在 5-10 个 Agent 的小规模，设计效率提升有限
- **判断**：这是**技术风险最高**的问题——如果忽视，可能在首次大规模部署时遭遇系统性崩溃


## Q4：载具能否成为"自我设计的实体"——在服役中持续进化自身的设计？

### 问题定义

当前载具的设计和服役是**两个完全分离的阶段**：设计阶段（10 年）→ 制造 → 服役（30-50 年）→ 退役。服役过程中发现的问题反馈到下一代设计中。

数字孪生技术正在模糊这个界限：每架飞机都可以有一个实时更新的结构健康模型。但目前的数字孪生仍是**被动**的——它告诉你"这里有问题"，但不会自动修改设计。

**核心问题**：能否构建一个闭环系统，让载具在服役过程中**自主发现设计缺陷、生成改进方案、并将改进"遗传"到后续批次甚至同型机队**？

```
愿景：
服役数据流 → 诊断 Agent → 发现设计缺陷
  → 设计 Agent → 生成改进方案
  → 验证 Agent → 仿真验证
  → 适航 Agent → 快速合规评估
  → 制造 Agent → 修订工艺文件
  → 同型机队 → 远程推送"设计补丁"

  ← 持续循环，载具在服役中"进化"
```

### 为什么这不仅是"持续学习"？

普通持续学习（Continual Learning）解决的是"模型如何不遗忘旧知识地学习新知识"。而"自我设计"面临更根本的挑战：

1. **设计变更的级联效应**：改一个零件尺寸可能影响整个子系统
2. **适航认证的连续性**：每次设计变更是否需要重新取证？
3. **批次异构性的管理**：同型飞机的不同批次可能有不同设计，维修体系如何适应？
4. **"进化方向"的约束**：谁来定义"什么是更好的设计"？

### 当前边界

| 技术要素 | 现状 | 距"自我设计"的差距 |
|----------|------|-------------------|
| 数字孪生 | 结构健康实时监控 | 只诊断，不修改设计 |
| 增量学习 | LLM 领域已有进展 | 尚未应用于工程设计 |
| 快速适航审批 | A320neo 的衍生认证耗时 3 年 | 需要"天级"而非"年级" |
| OTA 更新 | 软件可远程更新（F-35 已实现） | 硬件/结构不可远程更新 |
| 自适应结构 | 变体机翼（NASA ACTE 项目）验证了概念 | 仅限气动面，不涉及结构主体 |

### 探索方向

1. **"设计 DNA"与版本控制**
   - 将载具的完整设计模型编码为"设计基因组"——每个零件、材料、工艺是一个"基因"
   - 设计变更 = "基因突变"
   - 利用版本控制（类似 Git）追踪每架飞机的"设计基因型"
   - 同型机队可以有不同的"设计版本"，但都有完整的追溯链

2. **"可进化约束"的 Harness**
   - 传统 Harness 的约束是固定的（适航规章不变）
   - 自我设计需要约束本身也能"进化"——根据服役数据更新安全裕度
   - 例如：某区域实测应力长期低于设计值的 60%，Agent 可建议降低该区域安全系数（减重），但需要通过专用审批通道

3. **"设计补丁"的分级推送**
   - Level 1（信息级）：诊断报告，供工程师参考
   - Level 2（建议级）：设计修改方案，工程师一键审批
   - Level 3（自动级）：仿真已验证、合规已通过的小幅修改，自动下发到维修基地

### 潜在影响

- **如果实现**：载具设计从"一次性"变为"持续迭代"，服役数据直接驱动设计进化。机队寿命可延长 20-30%，全寿命成本降低 15-25%
- **风险**："设计蠕变"——累积的小修改可能在不经意间偏离原始设计意图
- **判断**：这是**最远期但最具颠覆性**的方向。Level 1-2 在 5-7 年内可实现；Level 3 需要 10+ 年和适航认证范式的根本变革

## Q5：军工保密与 AI 大数据需求之间的悖论如何破解？

### 问题定义

垂域 LLM 的性能依赖于**大规模、高质量的训练数据**。通用 LLM 训练使用数万亿 token 的公开数据。

但军用载具设计数据——隐身外形参数、RCS 测试数据、战伤容限试验结果、先进复合材料配方——是**最高密级的国家机密**。这些数据：
- 不能放在云端
- 不能跨单位共享
- 不能让模型训练后的梯度信息泄露设计参数
- 连模型推理的中间结果都不能暴露

**核心问题**：如何在数据极度隔离的条件下，训练出足够强大的垂域 LLM？

这不是一个简单的"用开源模型私有化部署"就能解决的问题——**没有足够的数据，模型就不可能足够强**。

### 悖论的结构

```
    高性能模型 ←──── 需要大量数据 ←──── 数据共享
         ↑                                      ↑
         │                                      │
    军工需求                              保密要求
         │                                      │
         ↓                                      ↓
    强大的垂域LLM ←─── 需要隔离部署 ←──── 数据封闭
    
    → 矛盾：模型要强就需要数据，数据要保密就不能共享
```

### 当前边界

| 技术方案 | 原理 | 局限 |
|----------|------|------|
| 私有化部署 | 开源模型在本单位机房运行 | 模型能力受限于开源基座 |
| 联邦学习 | 各方训练本地模型，只共享梯度 | 仍有梯度泄露风险 |
| 合成数据 | 用仿真生成训练数据 | 仿真的精度瓶颈 |
| 迁移学习 | 在公开航空数据上预训练，少量保密数据微调 | 领域差距可能导致"负迁移" |
| 差分隐私 | 在梯度中添加噪声保护原始数据 | 噪声降低模型精度 |

### 探索方向

1. **"数据不动模型动"的联邦微调**
   - 以一个在公开航空数据上预训练的基座模型为起点
   - 各军工单位各自在本地保密数据上微调
   - **只共享微调后的 LoRA 适配器**（而非原始数据或完整模型）
   - 中央服务器聚合多个 LoRA 适配器，输出统一增强版模型
   - 关键创新：即使逆向 LoRA 适配器，也无法还原训练数据

2. **"影子模型"蒸馏**
   - 在保密环境中训练一个强大的"教师模型"（有权限访问所有数据）
   - 教师模型生成大量"影子输出"（标准化的设计建议、分析报告）
   - 影子输出脱密后在更广泛的环境中用于训练"学生模型"
   - 学生模型学到的是"设计能力"而非"设计数据"

3. **分层密级的 Harness**
   - 将 Harness 按保密等级分层：
     - **公开层**：适航规章、公开标准、教科书知识
     - **内部层**：企业专有工艺规范、材料数据
     - **机密层**：武器系统参数、隐身设计规则
   - 不同密级的 Agent 运行在不同的安全域中
   - 跨域信息传递经过严格的脱密审查

4. **"零样本"物理推理**
   - 终极目标：模型不需要看过保密数据，仅凭物理定律的编码就能进行有效的载具设计推理
   - 类比：物理学家不需要看过所有实验数据就能预测新现象——因为他掌握了底层的物理定律
   - 这需要 LLM 的物理推理能力达到"专家级"

### 潜在影响

- **如果联邦 LoRA 路径可行**：中国各大军工集团可以在不共享原始数据的前提下联合提升垂域模型能力——这可能是**中美 AI 军工竞争的关键差异化因素**
- **如果零样本物理推理突破**：保密与性能的矛盾将彻底消失
- **判断**：联邦 LoRA 路径 2-3 年内可验证；零样本物理推理是 10 年级别的长期目标

## Q6：老工程师的"直觉"可以被 AI 蒸馏吗？

### 问题定义

航空结构设计中存在大量**不可言传的隐性知识**：

- 老强度师看到图纸就能"感觉"到应力集中点在哪里
- 资深复材工程师用手摸一下铺层就能判断质量
- 总设计师凭经验在多个冲突方案中"直觉"选择最优解

这些"直觉"从未被写进教科书，也难以形式化为规则。但它们是**数十年试错和实战经验的结晶**，价值远超任何显性知识库。

**核心问题**：垂域 LLM 能否通过学习工程师的设计决策历史，将这种"直觉"蒸馏为可复用的模型能力？

### 为什么这比普通知识蒸馏难？

```
普通知识蒸馏：
  教师 LLM（大） → 学生 LLM（小）
  输入-输出对是明确的

工程师直觉蒸馏：
  教师 = 人类工程师（不可查询内部状态）
  输入-输出对是模糊的（工程师自己也说不清为什么这么选）
  决策过程包含：
  ├── 可表述的推理（30%）→ 可以文档化
  ├── 模式识别（40%）→ "我见过类似的" → 可从历史数据中学习
  └── 直觉（30%）→ "说不清为什么，就是感觉这样更好" → 最难蒸馏
```

### 当前边界

| 方法 | 尝试 | 效果 |
|------|------|------|
| 行为克隆（Behavior Cloning） | 记录工程师的操作序列训练模型 | 只学到"做什么"，不知道"为什么" |
| 偏好学习（Preference Learning） | 让工程师在多方案中选择偏好 | 可以学到价值函数，但样本效率低 |
| RLHF（人类反馈强化学习） | 工程师对模型输出打分 | 适用但成本极高，每个领域需要大量专家时间 |
| Persona Modeling | 用 LLM 建模特定专家的思维风格 | 可复现表达风格，但无法复现深层次专业判断 |

### 探索方向

1. **"影子学徒"系统**
   - 工程师日常设计工作中，系统在后台静默记录所有决策（CAD 操作、参数选择、方案比选）
   - 系统同时记录决策的**上下文**（当时的设计阶段、约束条件、可用方案集）
   - 通过大量决策-上下文对训练模型，使其在类似场景下能复现工程师的决策模式
   - **关键**：不追问"为什么"，而是从大量"做了什么"中学习模式

2. **对抗式直觉评估**
   - 训练一个"直觉 Agent"，在相同设计任务中与老工程师并行给出方案
   - 对比两者的差异，由工程师解释"AI 的方案为什么不如我的"
   - 工程师的解释成为新的训练数据
   - 迭代直到直觉 Agent 的方案与工程师方案的差异收敛

3. **"设计 DNA"的谱系分析**
   - 收集同一工程师数十年的设计作品
   - 分析其设计风格的"基因特征"（如安全系数取值偏好、材料选择倾向、局部细节处理习惯）
   - 将这些特征编码为可复用的"设计 DNA"
   - 新项目可以"继承"特定工程师的设计 DNA

4. **退役前的"知识冲刺"**
   - 当资深工程师接近退休时，组织密集的"知识提取冲刺"
   - 不是让他写文档（他写不出隐性知识），而是让他**评价大量 AI 生成的设计方案**
   - 工程师的评价（接受/拒绝/修改）成为高价值的训练数据
   - 几千个评价样本可能比几十篇技术报告更有用

### 潜在影响

- **如果成功**：航空工业面临的老龄化危机将得到根本性缓解——退休专家的"直觉"以模型形式永久保存
- **如果部分成功**：即使只能蒸馏 50% 的隐性知识，也足以大幅降低新工程师的成长曲线
- **风险**：蒸馏出的"直觉"可能包含**过时的偏见**（如"我们一直这么做"但不代表最优）——需要与物理仿真验证结合
- **判断**：这是**最有温度**的问题。技术价值之外，它关乎工业文明中人类经验的传承方式


## 六个问题的关联与优先级

### 问题关联图

六个问题不是孤立的——它们之间存在深层的逻辑依赖：

```
                    Q2: 谁负责？
                   ╱            ╲
                  ╱              ╲
    Q1: 发现新物理 ────── Q3: 涌现行为
         │    ╲              ╱    │
         │     ╲            ╱     │
         │      Q6: 蒸馏直觉      │
         │          │              │
         │          ↓              │
    Q5: 保密悖论 ←─ Q4: 自我设计
```

**解读**：
- **Q2（责任）是中枢**：几乎所有其他问题的落地都受制于责任归属
- **Q1→Q6**：发现新物理定律的能力越强，蒸馏直觉的需求越迫切（但也更有希望）
- **Q3→Q4**：自我设计系统必然是大规模多 Agent 系统，涌现问题必须先解决
- **Q5 独立于其他问题**：保密悖论是军工场景的独有约束，但解决后将释放 Q1/Q6 的军工数据价值

### 优先级矩阵

| 问题 | 紧迫度 | 解决难度 | 影响范围 | 推荐研究时序 |
|------|--------|----------|----------|-------------|
| **Q2 谁负责** | ★★★★★ | ★★★ | ★★★★★ | **立即启动**（法规制定周期 3-5 年）|
| **Q5 保密悖论** | ★★★★★ | ★★★★ | ★★★★ | **立即启动**（军工 AI 竞争窗口）|
| **Q6 蒸馏直觉** | ★★★★ | ★★★ | ★★★★ | 1-2 年内启动（老龄化紧迫）|
| **Q3 涌现行为** | ★★★ | ★★★★★ | ★★★★★ | 2-3 年内（Agent 规模扩大前必须解决）|
| **Q1 发现物理** | ★★★ | ★★★★★ | ★★★★★ | 持续跟踪（基础研究，非工程可控）|
| **Q4 自我设计** | ★★ | ★★★★★ | ★★★★ | 5 年后（依赖其他问题进展）|

## 结语：问题的价值

> **"提出一个好问题，等于解决了一半。"** ——爱因斯坦

这六个问题的真正价值不在于它们能否被回答，而在于：

1. **它们定义了技术发展的边界**——不触碰这些边界的创新都是增量式的
2. **它们暴露了跨学科协作的必需性**——AI 工程师单靠自己无法解决任何一个
3. **它们重塑了人才需求**——未来最稀缺的不是"会用 AI 的人"，而是"能定义 AI 该回答什么问题"的人

航空/航天工业正在进入一个前所未有的窗口期：AI 的能力在飞速提升，但**应用的方向比能力的提升更重要**。这六个前瞻性问题的探索，将决定垂域 LLM 是成为载具设计的"真正的伙伴"，还是仅仅是一个"更快的工具"。
