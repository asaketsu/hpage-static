## 二、QuantaAlpha：轨迹级进化框架

### 2.1 核心理念

> **将每次端到端的因子挖掘视为一条"轨迹"，通过轨迹级变异和交叉来进化因子——而非依赖无约束的重新生成。**

这借鉴了 SE-Agent（Self-Evolution trajectory optimization）的思想：显式进化轨迹本身，而非仅进化最终输出。

### 2.2 四阶段工作流

```
┌──────────────────────────────────────────────────────────┐
│                    QuantaAlpha Pipeline                    │
├──────────────────────────────────────────────────────────┤
│                                                            │
│  (A) Diversified Planning Initialization                   │
│      ↓ 生成 N_init 个互补假设（信号源/时间尺度/机制类型）   │
│                                                            │
│  (B) Factor Realization（约束门控）                         │
│      假设 h → 语义描述 d → 符号表达式 f → AST → 可执行代码 c │
│      ↕ 一致性验证 / 复杂度控制 / 冗余过滤                   │
│                                                            │
│  (C) Self-Evolution                                        │
│      Mutation: 自反思→定位失败步骤→定点重写                  │
│      Crossover: 从高奖励父轨迹重组互补片段                   │
│                                                            │
│  (D) Final Factor Pool                                     │
│      合并验证有效的因子                                     │
│                                                            │
└──────────────────────────────────────────────────────────┘
```

### 2.3 关键机制详解

#### 机制 1：可控因子构造（Controllable Factor Construction）

直接生成因子代码容易出错（语法错误、依赖不匹配、语义漂移）。QuantaAlpha 引入中间表示：

1. **假设 h** → 结构化语义描述 d（形式化市场机制为离散算子）
2. **语义描述 d** → 符号表达式 f（基于标准化算子库 O）
3. **符号表达式 f** → AST（抽象语法树，叶节点绑定原始特征，内部节点对应算子实例）
4. **AST** → 可执行代码 c（编译失败时触发 LLM 修复）

#### 机制 2：三重生成约束

| 约束 | 公式/方法 | 作用 |
|------|-----------|------|
| **语义一致性** | LLM 验证 h↔d↔f↔c 对齐 | 防止生成漂移 |
| **复杂度控制** | C(f) = α₁·SL(f) + α₂·PC(f) + α₃·log(1+|F_f|) | 防止过度工程 |
| **冗余控制** | AST 最大公共同构子树 S(f) = max s(f,φ) | 防止因子拥挤 |

#### 机制 3：轨迹级变异（Mutation）

```
τ = (s₀, a₀, s₁, a₁, ..., sₙ)
         ↑ 自反思定位最差步骤 k

τ_child = (s₀, a₀, ..., sₖ, Refine(aₖ), s'ₖ₊₁, a'ₖ₊₁, ..., s'ₙ)
                                    ↑ 仅重写失败步骤，冻结前缀
```

变异只修改局部，保留已验证的轨迹前缀，避免从头开始的探索浪费。

#### 机制 4：轨迹级交叉（Crossover）

从多个高奖励父轨迹中提取互补的高性能片段（假设模板、构造模式、修复策略），合并为新的子轨迹。

## 三、CogAlpha：认知 Alpha 挖掘

### 3.1 核心理念

> **将 LLM 从"模式复制器"进化为"认知思考者"。**

CogAlpha 将 Alpha 表示为代码（而非公式），通过 LLM 驱动的推理和进化搜索迭代优化。

### 3.2 关键架构

- **代码级 Alpha 表示**：每个因子是一段可执行代码，而非数学公式
- **七级 Agent 层次**：多阶段 prompt 驱动深度推理
- **多 Agent 质量检查器**：独立的质量评估 Agent
- **思维进化**：迭代优化推理路径本身

### 3.3 与 QuantaAlpha 的对比

| 维度 | QuantaAlpha | CogAlpha |
|------|-------------|----------|
| 因子表示 | 符号表达式 + AST | 可执行代码 |
| 进化单元 | 端到端轨迹 | 代码级 |
| 质量控制 | 三重约束（一致性/复杂度/冗余） | 多 Agent 检查 |
| 推理深度 | 轨迹级自反思 | 七级层次化推理 |
| 验证范围 | CSI 300 + 迁移 | 5 市场 3 国家 |
