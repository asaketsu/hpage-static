# OpenAI ChatGPT Memory Dreaming 架构分析与借鉴

> 来源：https://openai.com/index/chatgpt-memory-dreaming/
> 日期：2026-06-07

## 核心架构

OpenAI 的 **Dreaming** 是一个后台记忆合成系统，用于自动从用户历史对话中提取、更新和维护个性化记忆。

### 三代演进

| 代际 | 时间 | 名称 | 特点 |
|------|------|------|------|
| V1 | 2024-04 | Saved Memories | 仅显式写入（用户说"记住X"），类似手动笔记 |
| V2 | 2025-04 | + Dreaming V0 | 后台补充合成历史对话，但不够独立 |
| V3 | 2026-06 | Dreaming V3 | 独立运行，5x 算力压缩，覆盖 Free 用户 |

### 三大目标

1. **上下文延续**：告诉 ChatGPT 一次，后续自动记住（如相机设备信息）
2. **偏好跟随**：自动学习偏好（如素食、喜欢野生动物摄影），无需显式指令
3. **时效性维护**：记忆随时间自动更新（"计划去新加坡"→"去了新加坡"）

### 关键技术特点

- **隐式学习**：从自然对话中提取偏好，不依赖显式"记住X"指令
- **后台合成**：独立于对话的后台进程持续整合记忆
- **时态自动转换**：将来时→过去时、当前状态→历史状态
- **算力优化**：V3 相比之前减少约 5x 计算量
- **用户可见**：Memory Summary Page 让用户查看/编辑合成后的记忆
- **评估框架**：三个维度评估（上下文延续/偏好跟随/时效性）

## 与 Hermes 记忆系统对比

| 维度 | OpenAI Dreaming | Hermes |
|------|----------------|--------|
| 记忆层级 | 单层（统一合成） | 三层（L1铁律/L2短期/L3长期） |
| 触发方式 | 实时后台进程 | 30min cron 批量扫描 |
| 隐式学习 | ✅ 核心能力 | ⚠️ 已落地 Phase 2.3 |
| 时效刷新 | ✅ 自动时态转换 | ⚠️ 已落地 Phase 2.4 |
| 用户可见性 | Memory Summary Page | MEMORY.md 直接编辑 |
| 进化驱动 | 无（纯记忆） | evolver 错误驱动进化 |
| 适用规模 | 数亿用户 | 单用户/小团队 |

## 借鉴学习进化点

### 已落实

1. **隐式记忆提取**（Phase 2.3）：从对话自动提取偏好/约束，写入 memory
2. **时效性自动刷新**（Phase 2.4）：检测过时记忆自动转换时态

### 差距与未来方向

- **实时性**：Dreaming 是实时后台进程，Hermes 是批量扫描。短期不可弥合（架构限制）
- **隐式偏好置信度**：Dreaming 有数亿用户数据训练的评估模型，Hermes 靠规则匹配

## 启发

1. 记忆系统的核心价值不仅是"记住"，而是**自动从交互中学习**——用户不需要知道"记忆"功能的存在
2. 时效性是记忆系统的致命问题——不刷新的记忆比没有记忆更危险（错误推荐）
3. 5x 算力压缩表明：记忆合成的效率是可规模化的关键瓶颈
4. 评估驱动设计：三个明确的评估维度（延续/偏好/时效）指导系统优化方向
