## 二、核心发现

### 发现1：投机解码四代演进，从串行到并行突破6.5x加速

投机解码是2026年推理加速最重大的技术突破方向。四代方法演进如下：

#### 第一代：EAGLE — 特征级自回归（2.7-3.5x）

EAGLE的核心洞察是**在特征层（倒数第二层）做自回归比在token层更直接**：
- 使用target model的top-layer features作为draft model的输入
- 通过引入一个时间步的token序列解决特征预测的不确定性
- LLaMA2-Chat 70B上实现2.7-3.5x延迟加速，吞吐量翻倍
- **关键限制**：特征预测约束了性能上限

#### 第二代：EAGLE-2 — 上下文感知动态草稿树（3.05-4.26x）

EAGLE-2发现**draft token的接受率不仅取决于位置，还取决于上下文**：
- 引入context-aware dynamic draft tree
- draft model的置信度分数近似接受率（误差很小）
- 比EAGLE-1快20%-40%，达到3.05-4.26x加速
- **关键创新**：动态调整草稿树结构，而非静态

#### 第三代：EAGLE-3 — 直接Token预测 + 多层特征融合（最高6.5x）

EAGLE-3彻底放弃特征预测，转向**直接token预测**：
- 用multi-layer feature fusion替代top-layer features依赖
- 引入"training-time test"技术
- 在SGLang框架中batch size=64时实现1.38x吞吐提升
- 最高6.5x加速，比EAGLE-2再提升约1.4x
- **关键突破**：draft model可以充分利用训练数据scaling

#### 第四代：P-EAGLE — 并行草稿（1.10-1.36x over EAGLE-3）

P-EAGLE将EAGLE从自回归改为**并行多token预测**：
- 使用可学习的共享hidden state实现并行draft
- 解决长上下文训练的二次方复杂度问题
- 在vLLM中实现：GPT-OSS 120B/20B、Qwen3-Coder 30B上1.10-1.36x over EAGLE-3
- **关键意义**：并行draft消除了"投机越多、draft越慢"的瓶颈

#### 方法选择决策树（vLLM官方）

```
GPU利用率 < 50% AND 平均响应长度 > 100 tokens AND draft模型能放入显存
  → 开启投机解码
  → 优先EAGLE-3（最高加速），长上下文用P-EAGLE
GPU利用率 > 80% OR 内存压力大
  → 先优化批处理，不开投机解码
  → 用n-gram或suffix decoding轻量加速
```

### 发现2：KV Cache剪枝四篇最新论文，从均匀分配到自适应

arXiv:2603.20397的综述将KV Cache优化归纳为五大方向，本次重点深入**Cache Pruning（剪枝）**的最新进展：

#### Ada-KV（arXiv:2407.11550）— 首个逐头自适应预算分配

- **核心问题**：现有方法对所有attention head统一分配压缩预算，忽略每个head独特的attention pattern
- **理论贡献**：建立了剪枝前后attention输出的理论损失上界，解释了先前方法的优化目标
- **创新**：首个head-wise adaptive budget allocation策略
- **效果**：Ruler 13个数据集 + LongBench 16个数据集，question-aware和question-agnostic场景下均显著超越现有方法
- **优势**：plug-and-play，可与任何现有剪枝方法无缝集成

#### DefensiveKV（arXiv:2510.13334）— 防御性聚合对抗稳定性假设脆弱性

- **核心问题**：现有方法基于"稳定假设"（固定子集始终重要）用mean aggregation，但该假设在极端情况下脆弱
- **创新**：两步线性时间防御性聚合策略，控制worst-case风险
- **效果**：在20%缓存大小下，生成质量损失比最强baseline降低2.3x（DefensiveKV）和4.3x（Layer-DefensiveKV）
- **意义**：开创了通过worst-case风险管理优化缓存剪枝的新方向

#### DepthKV（arXiv:2604.24647）— 层依赖剪枝框架

- **核心问题**：现有方法对所有层应用统一剪枝比例，假设所有层对性能贡献相同
- **发现**：不同层对剪枝的敏感度差异巨大
- **创新**：基于层敏感度在全局KV预算内分配预算，而非均匀分配
- **效果**：多个模型和任务上，相同全局剪枝比例下持续超越均匀剪枝

#### PagedEviction（arXiv:2509.04377）— 面向PagedAttention的分块剪枝

- **核心问题**：现有方法依赖attention-based token重要性或跨vLLM page的token驱逐
- **创新**：针对paged memory布局的高效block-wise eviction算法
- **优势**：与PagedAttention无缝集成，无需修改CUDA attention kernels
- **效果**：Llama-3.1-8B/3.2-1B/3.2-3B在LongBench上内存使用改善且精度优于baseline

#### 剪枝方法对比矩阵

| 方法 | 创新点 | 适用场景 | 集成难度 |
|------|--------|---------|---------|
| Ada-KV | 逐头自适应预算 | 长上下文、多任务 | 低（plug-and-play） |
| DefensiveKV | 防御性聚合 | 极端长上下文 | 中 |
| DepthKV | 层依赖预算 | 深度模型（>64层） | 中 |
| PagedEviction | 分块剪枝 | vLLM生产环境 | 低（与PagedAttention集成） |

### 发现3：连续批处理23x吞吐提升 — Orca迭代级调度 + vLLM PagedAttention

#### 问题根源：传统静态批处理的GPU浪费

静态批处理（static batching）中，batch size固定直到所有请求完成。问题在于：
- 不同序列的生成长度不同，短序列完成后GPU闲置
- 在A100 40GB上，13B模型约26GB参数，剩余14GB可存约14k tokens
- 如果限制序列长度512，最多28个序列/批，但实际中序列长度差异巨大
- 一个序列2048 tokens时，batch size被限制到7个

#### Orca的突破：迭代级调度（iteration-level scheduling）

OSDI 2022的Orca首次提出**迭代级调度**：
- 不再等待整个batch完成，而是每个iteration动态决定batch size
- 一旦某个序列完成，立即插入新序列
- 解决prefill和generation计算模式不同的问题（通过waiting_served_ratio参数）

#### vLLM PagedAttention：近零浪费的KV Cache管理

PagedAttention（arXiv:2309.06180）受操作系统虚拟内存分页启发：
- **核心机制**：将KV cache分成固定大小的block，非连续存储
- **优势1**：近零浪费（near-zero waste）— 消除内存碎片
- **优势2**：灵活共享 — 同一prefix的KV cache可在请求间共享
- **效果**：相比FasterTransformer和Orca，吞吐提升2-4x
- **长序列效果更显著**：模型越大、序列越长、解码算法越复杂，提升越大

#### 连续批处理性能数据（Anyscale基准）

| 系统 | 相对naive batching吞吐提升 |
|------|--------------------------|
| vLLM + 连续批处理 + 内存优化 | **23x** |
| Ray Serve + 连续批处理 | 8x |
| HuggingFace TGI + 连续批处理 | 8x |
| NVIDIA FasterTransformer优化 | 4x |

### 发现4：投机解码 + KV Cache剪枝 + 连续批处理的组合拳效应

三者不是独立优化，而是**协同增强**：

1. **投机解码降低内存带宽压力**：减少decode阶段forward pass次数 → 降低HBM读取次数
2. **KV Cache剪枝增加batch容纳量**：剪枝后每个请求KV cache更小 → 连续批处理能容纳更多请求
3. **连续批处理放大投机解码收益**：高并发下投机解码收益下降 → 但配合KV Cache剪枝后batch增大，总吞吐提升更大

**最佳组合策略**：

| 场景 | 推荐组合 | 预期提升 |
|------|---------|---------|
| 低并发（QPS<10）+ 长响应 | P-EAGLE + Ada-KV | 4-6x |
| 高并发（QPS>50）+ 短响应 | 连续批处理 + PagedEviction | 8-12x |
| 中等并发 + 长上下文 | EAGLE-3 + DepthKV + 连续批处理 | 5-8x |
| 边缘设备（内存受限） | EAGLE-3 + DefensiveKV + 小batch | 2-3x |

## 三、技术原理解析

### 投机解码的数学本质

投机解码的核心是**rejection sampling**：

```
1. Draft model 生成 k 个候选 token: y_1, y_2, ..., y_k
2. Target model 并行验证这 k 个 token
3. 找到第一个不匹配的 token 位置 j
4. 保留 y_1, ..., y_{j-1}，在 y_j 处重新采样
5. 期望接受长度 E[L] = Σ P(accept at position i)
```

**加速比** = 1 + E[L] / (1 + overhead)

关键洞察：EAGLE系列通过**特征级自回归**和**动态草稿树**最大化E[L]，P-EAGLE通过**并行draft**降低overhead。

### KV Cache剪枝的数学约束

给定KV cache预算B，剪枝问题可以形式化为：

```
minimize ||A_post - A_pre||_2
subject to |KV_post| ≤ B

其中 A = softmax(QK^T / √d)V 是attention输出
```

- **Ada-KV**：为每个attention head i分配预算b_i，Σb_i = B，通过理论损失上界优化b_i
- **DefensiveKV**：不假设重要性稳定，用防御性聚合（类似min-max）控制worst-case损失
- **DepthKV**：为每层l分配预算b_l，Σb_l = B，通过层敏感度优化b_l

### PagedAttention的分页机制

```
传统KV cache: [seq1: block0, block1, block2, ...] [seq2: block0, block1, ...]
              ↑ 连续存储，固定大小，易碎片化

PagedAttention: [block0: seq1-pos0-16, seq2-pos5-16, ...]
                [block1: seq1-pos16-32, seq3-pos0-16, ...]
                ↑ 非连续存储，动态分配，block可跨请求共享
```

**block table**：每个请求维护一个block table，记录每个position对应的physical block ID。
