归纳总结

一句话：把 Agent Harness（围绕 LLM 的 prompt/工具/控制流的可执行代码）建模为 Python 类层级，用继承/重写/多态做自动演化，执行模型完全冻结——三基准全 SOTA，OOD 场景靠 Base 类安全兜底碾压全局演化方法。

论文攻击的是当前 harness 优化的两难：

路线 代表方法 死法
一统全局单体 Meta-Harness、AHE 场景增多后规则冲突+上下文膨胀：为财务表格优化的指令干扰代码生成任务
每域复制专用代码 手工复制 版本间零复用、难维护；遇 OOD 新任务专用脚本崩溃且无法回退

OO-Harness 的答案是 40 年前的软件工程智慧：OOP 的继承、封装与多态天然解决复用、特化与隔离。子类继承 Base 的通用控制力，只重写 targeted 方法；路由不确定时回退 Base，永远有下限。

内容整理：机制与数据

三角色架构

角色 模型 职责
演化 Agent Claude Opus 4.8（≤40 iter） 剖析 base 执行失败日志 → 按共享执行需求聚任务簇 → 写子类（继承既有类，重写/新增方法）
执行器 M gemini-3.5-flash（完全冻结） 被各类 harness 包裹执行任务，一个参数不调
路由器 Claude Sonnet 5 任务描述 + base 轨迹证据 + routing lessons → 选特化子类或复用 Base 结果

关键机制细节：
- 类层级与任务簇分离：簇组织证据，层级组织可复用代码；子类可在任意已有类上派生（父类不必是当前簇的 Hc）
- 候选评估只跑目标簇，不重跑全量发现集——省 API 成本，是训练效率优势的来源
- 两类教训冻结沉淀：design lessons（什么改法有效/失败）供改代码，routing lessons（何时该用哪个类）供路由；部署后全部冻结
- 多态执行：路由选中一个完整类，其方法在单实例内执行；方法可依据运行时证据（重复工具报错、产物未完成）条件化行为

对比方法全景（ AutomationBench Mean ）：test-time scaling 平行 K=5 反而掉分（60.24）；Meta-Harness 63.92 / AHE 64.18（全局演化小幅增益）；AAH（git 分支特化，并发工作）75.40；OO-Harness 77.41 唯一全面最优。核心结论之一：纯堆推理（best-of-K/self-refine）不保证增益——学对任务合适的 harness 才是杠杆。

消融：两个组件各自值多少分

  1. 路由证据（同一冻结 harness 目录）：task-only → task+轨迹，AutomationBench +12.64、Toolathlon PASS +4.37，但 Workspace 仅 +0.53。解释：Workspace 的聚类天然对齐任务类型（文档写作/表格编辑），任务描述本身就是好线索；另两个基准的簇按执行失败形态聚类（写入不完整/未 finalize），必须看到 base 轨迹才知道该故障是否发生——路由增益取决于演化时怎么聚类，不是免费的。
  2. 层级结构（Workspace Lite-100）：OO 继承 40.56% > Flat 平铺拷贝 +4.96 > Base-reset 从零加改。Flat 也携带演化代码仍输给 OO——组织方式本身（而非仅代码复用）贡献近 5 分。
  3. Base 复用案例（300 任务实测）：44.7% 任务直接复用 Base（其原 Base 成绩 77.15），55.3% 走特化（原 Base 成绩仅 44.40）——路由把特化精确导向弱任务，强任务不折腾，这是"下限稳固"的量化证据。

OOD 实验（5.3 节）

254 个 Toolathlon-GYM 训练 → 49 个 Toolathlon 测试，应用家族完全不相交。Meta-Harness 把全局学到的 harness 硬套新应用，PASS 掉至 44.90%；OO-Harness 路由器识破陌生场景、全体复用 Base，保住 59.18%（两数字来自 Figure 7 图内，正文仅定性——引用时标注）。特化的代价由继承兜底机制免除。

关联分析

与我们体系的映射（这是本篇对我们最大的价值）：

OO-Harness 概念 Hermes/我们体系中的对应物 差距/启发
Harness 类层级 Skills 目录树 + SKILL.md 我们是文档型 harness（自然语言程序），论文是可执行型（真 Python 类）——执行确定性与可测试性差一个量级
Base 类安全兜底 fallback chain / 默认 profile 哲学同构：不确定时回退基线而非硬套。但我们缺"路由置信度"这一层的显式实现
Routing lessons error-case-library + skill trigger 描述 我们有教训库但没有结构化的"何时用何 skill"路由教训，trigger 是人写的静态描述
演化 Agent 改代码 evolver / session-evolution-scan 我们已有 L1 检测层，但改动最终落在 Markdown 而非可执行代码
任务簇 skills 的 category 子目录 我们按领域手工分类，论文按执行失败形态自动聚类（commit-gate=写入缺失、compute-verify=算术推导错）——失败形态聚类可能是更本质的切面
每 profile 独立 skills multi-profile 隔离 这正是论文证明次优的 Flat 模式（+4.96 分差距）——跨 profile 复用值得重审

与同作者前作的关系：[[2026-09-28-Agent即策略模型-四层解剖与跨体系验证.md]] 提出"Agent=嵌在控制循环里的 transformer 策略模型"，并指出 model-native 方向（o1/R1 把规划内化进参数）。本篇是镜像论证：模型侧冻结（gemini-3.5-flash 不动），把全部智能压进脚手架代码的演化。两篇合起来框定了光谱两端——智能放参数里（RL 内化）vs 智能放 harness 里（OOP 演化）——而现实最优解大概率是混合：模型足够强则 harness 趋薄，模型冻结则 harness 吃满工程红利。

与 harness 演化研究谱系的定位：GEPA（prompt 反思优化）→ ReasoningBank（经验蒸馏为记忆）→ Meta-Harness/AHE（全局代码演化）→ OO-Harness（层级化代码演化+路由）；并发工作 AAH 用 git 分支做特化共享（工程派），NOOA 提"agent 即原生 Python 对象"编程模型（语言派）。OO-Harness 的增量在于：继承链既是代码复用机制也是安全降级路径（父类永远可用）——这是 git 分支模型没有的性质。

趋势判断

  1. Harness 工程正在从"写 prompt"变成"演化代码"：2026 年 Meta-Harness/AHE/AAH/OO-Harness 密集出现，benchmark 也专门化（HarnessDev/EvoHarnessBench）——脚手架本身成为研究对象是 Agent 工业化的标志信号。
  2. 冻结模型、演化环境侧成为一条务实路线：不改参数意味着无 GPU 训练成本、无对齐漂移、即插即换底层模型——对企业落地（Google Cloud 主场）诱惑极大。与 model-native 路线形成资本级路线之争。
  3. OOP 只是第一步：类层级是最古老的复用机制，后续可预期组件化/依赖注入/设计模式库进入 harness 演化（论文 NOOA 引用已现端倪）。
  4. 路由 = 新的瓶颈资产：三基准中路由质量差异巨大（+12.64 vs +0.53），"怎么聚类决定怎么路由"意味着演化阶段的聚类策略是被低估的研究点。

指南分析

如果要把 OO-Harness 思想落地到自己的 Agent 系统（按侵入性从低到高）：

  1. 零成本移植——路由教训结构化：给 error-case-library 增加 routing_lesson 字段（什么症状→该用/不该用哪个 skill），并让 skill trigger 描述从"我能做什么"改写为"什么执行故障出现时该找我"。
  2. 低成本移植——Base 兜底显式化：所有自动选择逻辑（模型 fallback、skill 匹配）加"置信度阈值 + 回退默认链"两行，杜绝低置信度硬套。
  3. 中等成本——执行失败形态聚类：把历史失败日志按故障模式（而非业务领域）重新聚类，据此重组 skill 边界——Workspace-Bench 消融证明任务类型聚类天然存在，但故障形态聚类才是跨领域特化的来源。
  4. 完整移植——可执行 skill 层：给关键 skill 配 scripts/ 可执行入口，SKILL.md 退化为类文档（docstring），演化直接改代码。Hermes 的 skill 结构（SKILL.md + scripts/ + references/）其实已经半只脚在这个方向上。

拓展应用推荐

  1. Hermes skill 体系重构评估：用 Flat vs OO 消融思路审视 multi-profile 的 skills 复制——能否引入"基 skill + profile 覆盖层"继承式结构（配置化 override 而非整目录复制）。
  2. Duck 训练发射链的 harness 化：AutoDL 发射脚本家族（各 variant 的 relaunch 脚本）正在手工膨胀成 Flat 模式——套 OO-Harness 的"基类+子类重写参数方法"可消重。
  3. 量化工作流的 routing lessons：盯盘/选股/回测三类任务的入口路由目前靠关键词触发，可积累"任务特征→正确工作流"的教训表。
  4. 论文选题：「文档型 skill（自然语言程序）vs 可执行型 harness（代码程序）的等价性与转化条件」——我们体系天然是前者的活样本，与本文对照可成一篇方法论文。
