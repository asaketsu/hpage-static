## 一、内容整理

### 1.1 千问页原文：战队五组难度排序

原文对 RoboMaster 战队五个组别做了难度排序与任务拆解，是本次项目策划的输入：

- **算法-视觉组（⭐5，最难）**：装甲板识别、能量机关识别、自瞄弹道计算、抗光扰优化、辅助导航。技术栈 OpenVINO/ROS2/工业相机。
- **算法-雷达组（⭐4.5）**：点云处理、SLAM、多机通信、哨兵导航。技术栈 Ubuntu/ROS2/Livox/Go2。
- **电控组（⭐4）**：STM32 控制、电机驱动、传感器融合、通信协议。技术栈 STM32/C/FreeRTOS。
- **机械组（⭐3.5）**：SolidWorks 建模、底盘/云台/发射机构、弹仓。技术栈 SolidWorks/CAD。
- **运营组（⭐3）**：内容创作、视觉设计、新媒体运维、综合事务（招新/赞助/报销/后勤）。

难度排序的逻辑：视觉与雷达决定"能不能打赢"（信息获取与打击精度），电控决定"能不能动"，机械是承载与约束，运营是弹药（经费）与人员（人力）供给。前两者是算法密集型且强耦合硬件，调参链路最长，故排最前。

### 1.2 第一轮方案：双足踢球载体（后转为备胎）

首个方案以"双足机器人踢球"为载体，理由是 DUCK-Pi_5 双足平台现成（15×STS3215 舵机 + Pi5 + CSI 相机），机械与电控零起步成本。增量预算仅 ¥375，12 周周期，五组任务与 RM 高度同构。

**可行性判定的关键纠偏**：RoboMaster 正式赛（RMUC/RMUL）的机器人制式是轮式底盘 + 云台 + 发射机构的步兵/英雄/哨兵/工程/无人机，**没有双足机器人赛项**。因此双足踢球的正确定位是"五组协同训练载体 + 招新展示项目"，远期对口 RoboCup 类人组，而非 RM 分区赛直通车。

项目已交付（保留有效）：方案文档 8 篇、BOM ¥375、4 个可运行算法（踢球弹道解算、球检测、踢球序列帧协议、场地拟合定位），全部本机冒烟通过。

### 1.3 第二轮方案：标准步兵（现役方案）

用户拍板"改成轮式底盘+云台+发射机构的步兵模式"后重建。新项目 `rm-infantry-standard`，16 周赛季制周期，对齐 RM 年度节奏（10 月新规→寒假整车→5 月分区赛）。

三档配置：

- **L0 桌面自瞄台（¥3,000-5,000）**：云台+摩擦轮发射+相机，无底盘，桌面固定。视觉自瞄全链可验证，代码 100% 迁移 L1。
- **L1 标准步兵（¥8,000-12,000）**：完整步兵（麦轮底盘+云台+17mm 发射）。可参赛最小口径，默认推荐。BOM 小计 ¥10,829（弹丸另计）。
- **L2 赛队强化（¥15,000-25,000）**：L1 + Carbon 轻量化 + 双相机 + 能量机关 + 备件体系。

系统架构：上位机（Pi5/Jetson，视觉自瞄）解算目标角 → UART 100Hz 下发 → 主控 STM32F407 → CAN1 驱动 4×M3508+C620（底盘）、云台串级 PID（yaw/pitch，IMU 反馈）、摩擦轮转速环 + M2008 拨弹脉冲控制 → 图传/遥控器 SBUS 回路。

### 1.4 冒烟验证抓出的三个问题

代码"写完就跑"策略在两个项目中各抓到三类问题，说明验证门禁比文档完备性更关键：

- **弹道补偿角断言写反**：18m/s 打 3m 补偿角 3.10°，纯重力近似 2.60°。阻力要求更大补偿是物理正确，断言窗口写成了小于重力近似值——修断言不修代码。
- **装甲板合成器不真实**：初版灯条间距/灯高比 0.75，真实 RM 装甲板约 3.5-4（230mm/55mm），低于配对阈值导致检测率 80%。修合成器参数。
- **灯条检测端真 bug**：纯列投影把 y 方向分离的干扰色块与灯条在重叠列粘连成 142px 假灯条，漏检 4/20。改为两遍连通（先列投影切竖带，带内按行行程切分），检测率回到 100%。
- **踢球序列帧物理不可行**（双足项目）：校准低速档 200 step/s 下 200ms 摆 60° 需 3413 step/s，超出可达。改为 SWING 高速档分档（2000/3000/4000，均 <4095 满速）+ 时长按舵机能力反解，并标注"首次必须悬空验证"。

## 二、查询拓展

### 2.1 RMUC 赛制结构

RoboMaster 大学赛（RMUC）核心兵种：步兵（数量最多，可自瞄对射）、英雄机器人（高血量高功率，1:3 换人比高价值）、哨兵（自主导航，雷达站）、工程机器人（部署道具）、无人机与飞镖机器人（规则演进新增）。步兵是入门兵种——结构简单、单台成本可控、对抗反馈直接，且五组任务覆盖度最高（自瞄链是视觉+电控+机械+雷达的综合体）。

### 2.2 17mm 弹丸与弹道

当年规则限制弹丸直径（17mm 主流）与出口速度上限。摩擦轮发射的出口速度受两因素约束：摩擦轮转速（电控转速环决定）与摩擦轮间隙（机械 16.8-17.2mm 可调）。弹道解算在小射程内（<5m）可用直线+重力补偿近似，阻力项（k≈0.05-0.1/m）在中射程（3m+）影响显著——本次实测 18m/s 打 3m 时阻力把补偿角从 2.60° 抬到 3.10%，抬升约 19%，不可忽略。

### 2.3 装甲板检测经典法

RM 装甲板 = 两条竖直灯条 + 中间数字。传统通道差分法（R-B / B-R）在标准灯效下仍是主流：灯条高亮特征极强，差分后背景噪声大幅压制。管线为通道差分 → 阈值 → 连通域 → 灯条筛选（长宽比/高度）→ 平行配对（间距比/高度比）→ 四边形 → PnP 解算位姿。PnP 是"从像素点到真实空间位姿"的桥梁，直接决定自瞄精度，标定质量（相机内参+云台外参对齐电控零位）比算法复杂度更影响命中率。

### 2.4 云台串级 PID 的必要性

直驱云台惯量大、负载变化快（枪管反冲、俯仰重心位移），单环 PID 会在角度误差收敛前引入振荡。串级结构（外环角度/内环角速度/电流）把快速动力学问题留给内环，外环只处理参考轨迹跟踪，抗扰与响应速度同时改善。这与双足项目 DUCK 的同步读写控制环思想一致——都是"快环兜底层、慢环定目标"的分层控制。

## 三、归纳总结

### 3.1 载体选型框架（三轴决策）

```
                  赛制对齐度
                      ▲
                      │        ★ L1 标准步兵
                      │        （目标=正式赛）
        ───── L2 强化 ─┼─────────────────→ 增量预算
                      │
        L0 桌面台      │   ○ 双足踢球
       （链路验证）    │    （目标=训练/招新）
                      │
                      ▼
              可复用度（本地已有资产）
```

- **赛制对齐度**（最高权重）：目标若含"参赛"，载体必须对齐赛项，否则整个方案的价值主张崩塌。这是本轮转向的唯一决定因素。
- **增量预算**：¥375 vs ¥8-12k 是 20 倍差距，必须显式对账而非默认接受。
- **可复用度**：双足项目机械/电控 100% 复用 DUCK，步兵几乎全新——转向的代价正是"可复用度"换"赛制对齐度"。

### 3.2 五组与 RM 本尊任务映射

```
千问页任务                    本项目交付（L1）
─────────────────────────────────────────────
装甲板识别/自瞄弹道        → armor_detect.py + bullet_trajectory.py ✅已验证
能量机关识别               → L4 路线（CNN，待定标）
点云处理/SLAM/哨兵导航     → docs/04（L1 视觉地标→L2 Nav2→L3 Livox）
底盘/云台/发射/弹仓建模    → docs/01（RMUC 尺寸重量约束）
STM32/M3508/串级 PID      → docs/02（4 电机 CAN + 云台串级 + 安全联锁）
内容/海报/新媒体/赞助      → docs/05（4 vlog + 4 推文 + 赞助包 + 纪录片）
```

五组任务 100% 覆盖，无遗漏；每条都标注了对应的可验证交付物而非描述性目标。

### 3.3 关键路径与风险框架

- **关键路径**：视觉（自瞄链）+ 电控（串级 PID）——两者是赛季成败的决定因素，且都可在硬件到货前离线开发（合成数据/单机位）。
- **可对冲风险**：预算不足（降 L0 先跑视觉链路）、规则变动（机械终版冻结放在新规发布后）、电控新人无 CAN 经验（从单电机环起步）、摩擦轮间隙（可调座设计）。
- **不可对冲风险**：人力——10 人配置在学期中难保证出勤，是最大单点风险。

## 四、趋势判断

**趋势 1：竞赛机器人正从"单一兵种竞赛"转向"体系对抗"**
依据：RM 引入英雄/哨兵/无人机后，单车性能不再是胜负主因，传感器融合与决策层权重上升。本项目雷达组的"哨兵级导航成果直通"设计正是顺应此趋势——单做步兵是自满，做导航栈是积累可迁移资产。

**趋势 2：视觉自瞄正从 CNN 单轨走向"经典法打底 + CNN 补边角"**
依据：装甲板灯条在标准灯效下特征极强，经典通道差分法可解释、免训练、部署成本为零；CNN 的价值在反甲识别、能量机关、复杂光环境等经典法失效场景。本项目 L1-L2 走经典法、L4 才上 OpenVINO CNN 的梯度设计符合此判断——先拿到基线命中率，再花算力。

**趋势 3：低成本桌面验证台将成为竞赛入门标准动作**
依据：L0 桌面台（¥3-5k）能验证 100% 视觉自瞄代码，L1/L2 无需重做。这使"先桌面后整车"成为理性选择，尤其适合经费未批复的团队。本项目把 L0 显式纳入 BOM 拆解（仅 8 项 ≈ ¥3.2-4.5k）而非事后临时方案，是这一趋势的工程化体现。

**趋势 4：弹道解算将回归"实测标定"而非"参数泛化"**
依据：摩擦轮间隙、弹丸质量、出口速度三者都随批次与磨损漂移，K_DRAG=0.08 这类经验值只是起点。本项目 PROGRESS 已列"实弹标定后更新"为已知问题——真实赛场数据是唯一可信来源。

## 九、指南分析

### 9.1 本项目作为"五组协同训练载体"的合格性评估

- **任务覆盖度**：五组 100% 覆盖，且每组任务与 RM 本尊一一对应（非类比映射）——合格。
- **可验证交付物**：每组有明确交付清单与时点，4 个门禁（G1 单组打通/G2 整车通电/G3 全链演示/G4 演示视频）——合格。
- **可降级路径**：L0/L1/L2 三档 BOM 显式拆解，经费不足可保视觉链路——合格。
- **风险暴露完整性**：预算/规则/人力/反光/加工五类风险已列对策，但人力风险无对策（唯一不可对冲项）——**待补**：招新前置到 W3 而非 W2。

### 9.2 与千问页难度排序的偏差

本项目给五组重排了难度：视觉⭐4（降 1，纯色球/灯条场景比 RM 全场景简单）、雷达⭐3.5（降 1，已知固定地图定位从 SLAM 降维）、电控⭐3.5（降 0.5，有 M3508 官方文档支撑）、机械⭐3.5（持平）、运营⭐3（持平）。降维的核心手段是**约束场景**（固定场地/标准灯效/已知地图）——训练载体的价值在于让新人快速打通链路，而非复刻全难度。

### 9.3 后续执行建议（P0 三项）

1. **10 月新规发布后立即复核 BOM**：弹速上限、尺寸重量、弹仓容量三处最可能变动，PROGRESS 已列门禁。
2. **W3 前启动招新**：人力是唯一不可对冲风险，招新周期 4-6 周，倒推必须提前。
3. **视觉组用合成数据先跑**：`armor_detect.py` 已有合成帧生成器，不等硬件即可产出检测率基线报告。
