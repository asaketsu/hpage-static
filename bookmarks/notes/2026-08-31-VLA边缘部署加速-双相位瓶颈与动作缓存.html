一、内容整理

1.1 VLA-XPU 表征论文（arXiv 2604.24447，上海交大）核心发现

Finding #1：模型大小 ≠ 推理频率的预测器。 反直觉实测：Diffusion Policy（小模型，Small Consumer）推理频率反而低于 π0（大模型，Big Consumer）——原因是扩散动作专家的迭代步数：Diffusion Policy 需要 100 步去噪，π0 只需 4 步。去噪步数比参数量更决定延迟。

Finding #2：CET（Cost/Energy/Time）三维排行榜颠覆「旗舰卡最优」直觉。

硬件 BF16/FP16 算力 显存 带宽 π0 得分场景
RTX 4090 330 TFLOP/s 24 GB 1000 GB/s 延迟优先（动态任务）最优
Jetson Thor 258 TFLOP/s 128 GB 273 GB/s 能耗优先最优（电池机器人）
AGX Orin 42 TFLOP/s 64 GB 204 GB/s SmolVLA 等小模型的 Cost-Energy 最优
Intel B60 Pro 90 TFLOP/s 24 GB 456 GB/s 成本优先（规模化部署）最优
Ascend 310P 88 TFLOP/s 48 GB 204.8 GB/s 重负载（Gr00t/π0）CE 场景占优

π0 实测一行：4090 跑出 102.3ms/86 分；Thor 246ms；Orin 920.6ms；B60 306.5ms。7B 的 OpenVLA 塞不进 12GB 的 Ascend 310B；强行用 CPU swap 跑，磁盘 I/O 把推理拖到 <1Hz，实际不可用——显存容量是与延迟门并列的硬可行性约束。

Finding #3：双相位计算失衡（本文最有价值的系统级洞察）。 用 Nsight Systems 对 π0 做细粒度画像：

  • VLM backbone = 计算受限阶段：SM 利用率 >90%
  • Action Expert = 访存受限阶段：SM 利用率仅 20-40%
  • VLM 利用率是 Action Expert 的 3 倍，但 Action Expert 延迟是 VLM 的 2 倍
  • 两阶段串行依赖 → 高性能算力单元在 Action Expert 阶段大量空转，这解释了「峰值算力规格」与「实际控制频率」之间的落差

配套加速方案：DP-Cache（扩散过程内部冗余削减，π0 上 1.29× 加速、成功率仅降 0.6%）+ V-AEFusion（VLM 与 Action Expert 异步流水线并行，1.3×）→ 组合在 GPU 上最高 2.9×，边缘 NPU 上 6×。

部署三步法（论文给的可复用决策流程）：① 在排行榜选目标模型查全部硬件画像 → ② 可行性过滤（显存容量 OOM 检查 + 控制频率门限）→ ③ 按场景优先级排序（延迟/成本/能耗）。

1.2 ActionCache（arXiv 2607.06370）：免训练的动作级缓存

问题：flow matching 类 VLA（π0.5/GR00T-N1.6）的动作头迭代采样占端到端延迟 36-65%+，实时控制瓶颈。

方案：把「过去成功生成的动作块」变成可复用计算。

设计点 实现
缓存键 VLM 输出嵌入（backbone 前向的副产物，零额外计算）→ 固定稀疏三值随机投影矩阵 R∈{-1,0,1}^(d×D) 压到 d=500 维（非零密度 p=0.01），免训练免拟合
缓存值 动作块本身（不是 KV cache/内部状态/视觉 token）→ 定义在动作空间，与 backbone 架构解耦
命中规则 Top-1 余弦相似度 > T_hit 才算命中（π0.5: 0.85；GR00T: 0.65），未命中回退纯高斯噪声全步生成——保守回退保住泛化能力
提交策略 miss 时暂存 (key, τ=(N-N_hit)Δτ 处的中间噪声动作) 到 pending buffer，episode 成功才提交，失败即丢弃
替换策略 容量 3000 条，LRU 起步；容量受限时 LFU 更优（防缓存污染）
预热 T_hit=1（绝不误命中）填满缓存后再降到目标阈值

实测数据（VLABench）：

模型 方法 NFE 成功率 延迟 加速比
π0.5 Base (NFE=10) 10 38.8% 18.8ms 1.0×
π0.5 Base 直降到 NFE=1 1 6.8% (-32.0) 2.5ms 7.52×
π0.5 ActionCache 1 32.4% (-6.4) 3.6ms 5.22×
π0.5 ActionCache 0 32.9% (-5.9) 1.6ms 11.75×
GR00T-N1.6 ActionCache 0 22.3% (-11.7) 0.7ms 34.43×
π0.5 EfficientVLA（对比） 1 2.3% (-36.5) 5.1ms 3.69×

关键结论：NFE=0（完全跳过去噪、直接复用缓存动作）在 π0.5 上成功率只掉 5.9 个点——相似视觉语境下历史动作可以不修改直接复用。键投影+查表开销 <2ms，可忽略。真机验证：SO-101 机械臂 pick-and-place，LeRobot 框架微调 100 episodes。

局限（论文自述）：只加速动作头，不动 VLM backbone，可与 VLM 侧免训练加速叠加；替换策略（LRU/LFU/FIFO）还能继续优化。

1.3 LiteVLA（arXiv 2511.05642）：树莓派 4 上的量化实测——Pi 级硬件的真实天花板

这篇是「低端硬件能跑 VLA 吗」的最直接证据：

配置 单次推理延迟 换算
SmolVLM-256 baseline FP32（Pi 4 CPU） ~11 s 0.09 Hz
LiteVLA 未量化 FP32（Pi 4 CPU） ~18 分钟 完全不可用
LiteVLA 4-bit NF4（投影头保 FP32） ~2 分钟 9× 改善但仍非实时
量化投影头 严重退化 输出不稳定/幻觉

架构策略：Action Chunking + ROS 2 异步分层——VLA 以 0.09Hz 低频出「动作块」，底层运动控制器高频执行，高层推理慢不阻塞底层控制。这是 Pi 级 CPU 跑 VLA 的唯一可行姿势。
另一铁律：投影头（projection head）绝不能量化，保 FP32；只量化主干。

1.4 SmolVLA 公开基准补充

  • GPU 上 SmolVLA 平均推理 ~87ms（learnopencv 实测），峰值显存 ~908MB
  • 基准达到 OpenVLA 成功率的 60-75%，参数量只有 1/14；单任务微调（200+ demonstrations）差距缩到 5-10%
  • 真机 SO-101 pick-and-place（SmolVLA 论文）：分布内 90% vs π0.5 70%；分布外 50% vs 40%
  • 定位：LeRobot 生态、消费级 GPU 可训、Jetson Orin NX（$499）可部署——比 AGX 便宜 4 倍的推理位

三、归纳总结

  1. 延迟的真正决定因素是迭代步数而非参数量。100 步去噪的小模型比 4 步去噪的 3B 模型慢——选型时先看动作头类型与 NFE，再看 backbone 大小。
  2. VLA 推理存在结构性「双相位失衡」：VLM 阶段计算受限（SM>90%）、Action Expert 阶段访存受限（SM 20-40%）。任何单一硬件都只能喂饱其中一个阶段——这为「大小核异构/异步流水线」提供了理论依据。
  3. 免训练加速的性价比天花板在动作头：ActionCache 证明「历史成功动作 + 语境相似度检索」可以在不动任何权重的前提下拿到 11.75×-34.43× 动作头加速，代价是个位数成功率损失。本质是把 LLM 推理里的 KV cache/prompt cache 思想移植到动作空间。
  4. Pi 级 CPU 跑完整 VLA 仍是禁区（18 分钟/次 FP32、2 分钟/次 NF4），唯一可行架构是「低频 VLA 出动作块 + 高频底层控制器执行」的异步分层；而 Pi 5 级跑 SmolVLA 处于两者之间，必须依赖动作分块。
  5. 「成功率-延迟」是可控滑杆：NFE 从 10 降到 1，base 掉 32 个点，ActionCache 只掉 6 个点——缓存热启动把滑杆的代价压掉 80%。

四、趋势判断

  1. 双系统（dual-system）架构已成主流共识：Hi-robot、π0/π0.5、Gr00t 全部走向「VLM 慢思考 + Action Expert 快控制」解耦。2026 年的增量在系统层：怎么让两个相位在廉价硬件上并行/流水线化（V-AEFusion 方向）。
  2. 动作缓存会成为 VLA 推理引擎标配，正如 prompt cache 之于 LLM serving。可预期的演进：缓存键从 VLM 嵌入扩展到「视觉+语言+机器人状态」联合键（GR00T 已是如此）；替换策略从 LRU/LFU 走向学习型。
  3. 边缘 XPU 生态多元化：评测已覆盖 Ascend 310B/310P、Intel Arc B60、Jetson Thor/Orin。中国产 NPU 在 CE（成本-能耗）维度对 NVIDIA 形成实质竞争，机器人厂商选型将从「无脑 NVIDIA」转向 CET 三维决策。
  4. 1B 参数是 Small/Big Consumer 分界线（该论文的分层），与「SmolVLA 类小模型 + 动作分块」路线在低端硬件（Pi 5/Jetson Orin NX/$10k 人形）形成完整生态位。
  5. 量化与缓存的组合是下一步：LiteVLA 证明 NF4 量化在 CPU 上拿 9×，ActionCache 在 GPU 上拿 11.75×——两者正交，Pi 5 + 量化 SmolVLA + 动作缓存的理论叠加空间值得验证。

六、拓展应用推荐

  1. P0｜DUCK-Pi_5 增加 ActionCache 式动作缓存原型：在现有 microduck_sim 仿真里，对解析控制器/PPO 策略的输出动作块按「观测嵌入相似度」建缓存（观测可用低维状态向量直接做键，无需 VLM 嵌入），命中则跳过策略前向。行走场景周期性强，预期命中率可观。工作量：仿真内 ~100 行 Python。
  2. P0｜Pi 5 部署前强制做「延迟预算表」：按论文三步法，先测 SmolVLA 在 Pi 5（CPU/NPU）的实际单次延迟 → 定动作块长度 H → 定控制频率。不做这步直接上真机会踩 LiteVLA 的坑（分钟级延迟）。
  3. P1｜量化留投影头：若对 SmolVLA 做 INT4/NF4 量化，投影头保 FP32（LiteVLA 铁律），预期在 Pi 5 上拿到数倍改善。
  4. P1｜Jetson 侧对比评测：本机 AGX Orin 可跑 SmolVLA 推理基准（论文称 Orin 是 SmolVLA CE 最优），为 DUCK-Pi_5 提供「Pi 5 vs Orin」的实测决策数据。注意遵守本机不跑重型 ML 的约束——仅轻量推理基准，训练留 AutoDL。
  5. P2｜关注 VLA-XPU 排行榜（vla-leaderboard-01.vercel.app）：持续更新的模型-硬件配对数据，后续选型直接查表。

七、指南分析

对「低端主控跑 VLA」的可操作决策树（综合三篇论文）：

目标：机器人上跑 VLA
→ 显存/内存装得下模型吗？（7B OpenVLA 需 >12GB；SmolVLA ~1GB 级）
  → 装不下 → 换小模型（SmolVLA/ACT 级）或云端推理
  → 装得下 → 实测单次推理延迟
    → <200ms → 可近实时闭环（GPU/Thor 级）
    → 200ms-2s → 动作分块（预测 10-50 步，底层 50Hz 执行）
    → >2s（Pi 级 CPU）→ 异步分层 + 量化（投影头保 FP32）
        + 动作缓存（周期性任务命中率高）
        + 考虑降级到「解析控制器 + VLA 仅做高层指令」

加速方法四家族选型（VLA-XPU 分类法）：
1. 冗余削减（Cache-VLA/DeeR/ActionCache）：免训练，动动作头，性价比最高
2. 架构压缩（TinyVLA/蒸馏/一致性模型）：需重训，上限高
3. 推测推理（Spec-VLA/TS-DP）：需配套小模型
4. 系统流水线（Real-Time Chunking/V-AEFusion）：不动模型，动调度

工程铁律三条：投影头不量化；episode 成功才提交缓存；命中率阈值先 1 后降（预热防误命中）。
