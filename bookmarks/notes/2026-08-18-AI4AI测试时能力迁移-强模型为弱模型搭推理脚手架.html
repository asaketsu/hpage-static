一、内容整理

0. 论文核心主张（推主点评 + 论文原文）

推主："对 agent 落地场景，这意味着测试时改造对外行为可能比更新内部参数更省成本"
论文："能力不是通过模型权重转移，而是通过塑造弱模型如何接收、推理、响应的 harness 转移"

1. 问题设定

传统范式 vs 本文范式：
| | 数据蒸馏 / On-policy 蒸馏 | Strong-to-Weak Scaffolding（本文） |
|---|---|---|
| 改什么 | 弱模型的参数（训练） | 弱模型周围的推理环境（harness） |
| 前提 | 缩小差距需要额外训练 | 失败可能源于任务呈现方式造成的认知负荷过载，而非能力不足 |
| 转移载体 | 权重 | 可复用的任务结构 |

设定细节：强 builder 构建脚手架（任务路由/提示模板/确定性求解器/少样本示例/验证检查/格式强制），作用于固定弱 target，在隐藏测试集上评估。builder 看不到完整测试集——成功的脚手架必须捕获可复用技能与任务结构而非记忆实例答案。

2. 核心实验结果

发现 数据
效应量 最佳脚手架把 GPT-5.4-mini 从宏观平均 0.49 拉到 0.91（绝对 +0.42）；所有 builder 配置均正增益
增益来源 不是更多验证数据/更多采样/更长思考，而是结构外化、确定性卸载、严格格式强制
Benchmark 分化 BigToM 上最佳脚手架把任务"编译"成可执行技能与规则（benchmark 变相被破解）；其它 benchmark 是真实的推理负担减少
残余误差 集中在最难区域：Hi-ToM 递归深度≥2 的高阶心智、贝叶斯目标推断子类
Builder 推理努力 努力层级单调提升脚手架质量（low→med→high→x-high 稳定上升）
平台效应 Claude Code vs Cursor 的平台差异 modest（相对 builder 模型本身的差异）
Target 依赖 弱的 GPT-5.4-mini 获益 > 已较强的 Gemini-3.5-flash（弱者获益最大）

3. 可操作设计原则（论文明示）

  1. 确定性卸载（deterministic offloading）：把脆弱的认知工作移进外部工具/代码/可校验表示
  2. Benchmark 感知路由：按任务子类型分流
  3. 格式控制：强制严格答案格式
  4. 定向分解：目标性拆解，优于暴力验证搜索

5. 双重价值（论文展望）

  • 部署视角：不改权重就能提升弱/便宜模型——与"自动 agent-harness 自进化"动机吻合
  • 评估视角：新评测问题——"模型多能构建让弱模型解决任务的条件？"脚手架质量成为 builder 外化推理能力的度量

二、查询拓展

  1. BigToM"被编译"现象的泛化：哪些 benchmark 可被脚手架结构性破解？评测污染的新形态（scaffold overfitting）如何检测？
  2. Hi-ToM 递归≥2 为何顽固：脚手架无法外化的"真心智推理"边界在哪——符号程序追不上递归信念追踪的根本原因？
  3. Builder 推理努力的成本收益曲线：x-high 的脚手架质量提升 vs 推理成本，ROI 在哪一档拐头？
  4. 与我们 skill 体系的映射：Hermes 的 skill 本质就是"强模型（写 skill 的我）给弱执行环境搭的脚手架"——本文的 4 设计原则可否作为 skill 审计标准？
  5. Harness-Bench / Meta-Harness / ADAS 谱系：自动化脚手架搜索的三个流派差异与融合趋势

三、归纳总结

维度 要点
一句话 强模型搭台、弱模型唱戏：能力经 harness 而非权重转移，0.49→0.91
核心机制 结构外化 + 确定性卸载 + 格式强制 + 定向分流（反对"鼓励多思考"）
关键规律 builder 推理努力↗脚手架质量单调↗；target 越弱获益越大；平台效应<模型效应
边界 高阶递归 ToM、贝叶斯目标推断仍是硬骨头；部分 benchmark 存在结构性破解
落地含义 弱模型+好脚手架 ≈ 强模型裸奔——agent 落地时 harness 投入优先级应高于换更大的模型

四、趋势判断

  1. "Harness 即能力"从口号变成实证科学：本文提供了效应量/稳定性/机制的系统性测量——harness 工程从手艺走向可比较的学科（我们 harness-architecture skill 的方向被验证）
  2. 能力迁移的三层路线图成型：权重层（蒸馏/SEAL）→ 上下文层（RAG/长上下文）→ 环境层（scaffold/harness）——第三层成本最低、迭代最快，将成为落地首选
  3. 评测范式转向"条件构建力"：从"模型能否解题"到"模型能否构建让别的模型解题的条件"——builder 能力的新基准，也预示 benchmark 污染的新战场
  4. 弱模型价值重估：小模型+强脚手架的组合在成本敏感的 agent 落地中挤压中档模型空间——"模型大小"与"harness 厚度"的预算分配是新的架构决策
