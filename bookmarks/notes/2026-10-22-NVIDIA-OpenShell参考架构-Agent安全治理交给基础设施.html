归纳总结

核心主张一句话：Agent 管不了自己（An agent cannot govern itself），安全与治理必须放在 Agent 碰不到的基础设施里。

推理论链：长时运行 Agent 的风险是复利的——它会自己下载代码、搭建新工具、申请更多权限，且执行路径是边推理边决定的（不可预先审计）。Agent 目标导向、不天然优先安全 → 所以治理不能依赖 Agent 自觉，必须外置。NVIDIA 给出的答案是三层参考架构：

层 组件 职能 隔离级别
第一层 OpenShell（开源运行时） 确定性治理：权限边界、凭据代管、形式化验证 软件
第二层 Vera CPU Agent 循环的算力底座：高并发+快核+大带宽 硬件（算力）
第三层 BlueField-4 DPU + Sentry 可选硬件防线：独立信任域监控、芯片级毫秒隔离 芯片

三层各自独立成防线，第三层可选——软件治理是基线，硬件隔离是增强。

内容整理：四组件、Vera 数据与硬件信任域

OpenShell 四组件（软件治理层）

组件 角色 关键点
Gateway 控制平面 管沙箱生命周期与策略；拦截器可接身份/授权/数据保护/审计等企业既有系统
Supervisor 独立检查者 完全独立于沙箱运行，按策略检查所有出站请求，代管凭据（Agent 永不直接持有密钥）
Sandbox 隔离工作负载 限制文件系统与进程访问；Agent 全程被视为不可信对象
Policy Prover 形式化验证 最有特点的一点：数学证明某条策略的权限不会超出组织设定的上限（ceiling）

设计原则：最小权限按需授予（access what it needs, when it needs it）。扩展有两条路——Supervisor 中间件可检查/拦截/改写网络内容；Gateway 拦截器接企业治理系统，不改 Gateway 本体。

Vera CPU 算力层（已核验数字）

Agent 循环（推理→调工具→执行代码→查数据）是串行依赖步，同时 AI 工厂要跑数千并发循环 → CPU 需求五维：多核+快核、高带宽互联/内存、大 I/O、硬件安全、每瓦性能。

指标 数值 口径
Olympus 核心 88 个（10-wide 前端/神经分支预测/深乱序） NVIDIA
关键 Agent 负载性能 最高 2x vs x86 NVIDIA
内存带宽 LPDDR5X 最高 1.2 TB/s；loaded 延迟比 chiplet 设计低 40% NVIDIA
互联 第二代 SCF：核间带宽最高 3x、核间延迟比 x86 低 50%；96 lanes PCIe Gen 6 NVIDIA
每瓦性能 2x vs x86；LPDDR5X 内存子系统功耗比 DDR5 竞品低一个数量级 NVIDIA
沙箱启动 >3x 快于 x86 CoreWeave 实测
Terminal Bench 20 个真实 agent 任务几何平均 1.8x，最高 2x（cobol-modernization/fix-git/db-wal-recovery/openssl-selfsigned-cert） CoreWeave 实测
单机柜密度 >11,000 并发 Agent 环境 CoreWeave 实测

BlueField-4 + Sentry（硬件信任域）

DPU 卡在 Agent（Vera 上）与模型之间的 I/O 路径上，形成 Agent 够不到的硬件信任域。Sentry（基于 DOCA）在该域内：监控请求响应/网络/文件活动、核验身份与委托权限、分析选定主机内存——不依赖 Agent 自我汇报。发现违规时 BlueField-4 在芯片层面执行策略，毫秒级隔离 Agent。

整体栈 = Vera Rubin 平台（跑 LLM）+ OpenShell（软件治理）+ Sentry on BlueField-4（硬件防线），三支柱构成 OpenShell 参考架构。

趋势判断

  1. Agent 安全从"提示词约束"迁移到"基础设施强制"：2025 年主流是 system prompt 里写"不要做危险的事"，2026 转向沙箱+形式化验证+芯片隔离——约束层从模型内移到模型外，这与"Agent 管不了自己"的共识形成相辅相成。
  2. 算力厂商开始为 Agent 定制 CPU：Vera 把"Agent 循环串行依赖步"当第一性设计约束（快单核+多核+大内存带宽），预告 Agent 工作负载将成为继训练/推理之后的第三类一级负载。x86 通用核在这条赛道失去默认地位。
  3. 硬件信任域成新战场：BlueField/Sentry 的卖点是"不依赖 Agent 自我汇报"——隐含判断是软件层监控可被攻陷的 Agent 绕过，只有 I/O 路径上的独立硅片可信。DPU 从网络加速卡演化为 AI 安全执行点。
  4. 形式化验证进入 Agent 治理：Policy Prover 把"权限天花板可数学证明"做成组件，预示 Agent 权限策略将从配置文件演化为可验证规约（企业采购 Agent 平台时大概率会要求这类保证）。
  5. 风险信号：整套数字无第三方复测，且深度绑定 NVIDIA 全家桶（CPU+DPU+软件），厂商锁定动机明显；参考架构的"开放"仅到软件层（OpenShell 开源），硬件层封闭。

指南分析

若要借鉴（非采购 NVIDIA 硬件场景），可落地的分层清单：

  1. 立即可做（软件层）：试用 OpenShell 开源仓库的 Sandbox+Supervisor 模式管理高危 Agent 任务；把密钥从 Agent 可读路径迁到代管层（Supervisor 模式）；出站请求加独立审查中间件。
  2. 中期可做（策略层）：为 Agent 权限写组织级 ceiling 规约，先用简单 linter 验证策略不越界，形式化工具（如 TLA+/Dafny）做关键策略验证——Policy Prover 思路的廉价版。
  3. 架构启示（不可采购场景）：任何长时运行 Agent 系统设计审查清单加三条——凭据 Agent 是否可直接持有？出站请求是否有独立于 Agent 的检查点？策略上限是否可被机器验证？
  4. 警惕项：不要把"Agent 自我汇报的状态"当安全依据（Sentry 的存在就是对这个的反证）；不要用监控代替隔离。

拓展应用推荐

  • Hermes 自身治理升级候选项：对照四组件审视——我们已有 Sandbox 式隔离（容器），Gateway 角色（策略生命周期管理）散落在各 skill 里，Supervisor（出站审查+凭据代管）与 Policy Prover（可验证权限上限）是明确缺口，可进 Harness 演化 backlog。
  • 机器人任务场景：DUCK 真机指令链是"高权限长时 Agent"（可发运动命令），OpenShell 的"需要时给所需权限"模式可迁移为任务级令牌：真机命令按任务签发、过期即失效，替代长期持有。
  • 企业咨询素材：飞机设计企业（适航/构型管理背景）引入 Agent 时，"治理放基础设施+权限上限可验证"与适航审定思路（独立性+可证明性）同构，是向这类企业讲 Agent 安全的最佳翻译桥梁。
