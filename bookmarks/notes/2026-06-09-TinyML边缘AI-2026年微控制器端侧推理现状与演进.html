一、2026 年微控制器端侧 AI 的核心趋势

1.1 从实验走向生产

TinyML 已跨过"demo 阶段"，进入真正的产品化部署。Shawn Hymel 的年度总结指出：专业工具链、工作流和设计模式已成熟，嵌入式行业正在稳步而非爆发式地采用 ML 解决实际问题。

关键约束（与 LLM 云端范式完全相反）：

维度 微控制器 典型值
RAM 几十到几百 KB 64KB - 512KB
Flash 有限存储 256KB - 2MB
GPU 无 N/A
运行环境 裸机或小型 RTOS FreeRTOS/Zephyr
模型规模 窄域、任务特定 <100K 参数

1.2 硅厂商纵向整合加速

2025 年的收购浪潮标志着一个清晰趋势：硅厂商买下端到端工作流层，使边缘 AI 成为芯片平台的一部分而非外部依赖。

平台 收购方 时间 定位
Edge Impulse Qualcomm 2025 最广泛使用的端到端嵌入式 ML 平台
Neuton.AI Nordic 2025 全自动 TinyML 工作流 + 超小模型
Imagimob Infineon 2023 端到端边缘 AI 平台

对工程师的影响：这些平台仍提供可移植运行时和导出格式，但最优路径将越来越多地偏向拥有公司的芯片。

二、推理运行时生态 2026

2.1 三大开放运行时现状

运行时 状态 特点
Google LiteRT for Microcontrollers ✅ 活跃，最广泛使用 裸机/RTOS 兼容，静态内存分配，支持 CMSIS-NN 加速
Microsoft ONNX Runtime ⚠️ 无官方 MCU 裸机版 边缘设备优秀但需 OS 支持，MCU 需大量移植
Apache microTVM ❌ 已停止活跃维护 编译器驱动的 ML 部署思路可行，但不再出现在 TVM 主线

2.2 硅厂商框架

每个主要 MCU 供应商都建立了自己的 AI 框架：

  • STMicroelectronics：STM32Cube.AI + NanoEdge AI Studio → 优化 C 代码生成 + 异常检测
  • NXP：eIQ ML 开发环境 → 覆盖 NXP 处理器系列
  • Renesas：Reality AI Tools + RUHMI Framework → Ethos 加速器优化
  • Nordic：Edge AI Add-on for nRF Connect SDK → nRF54 系列专用优化

三、硬件加速器演进

3.1 Ethos-U 的微控制器化

2025 年，ARM Ethos-U 神经处理单元开始出现在高端微控制器和跨界设备中（ST、NXP、Renesas）。关键洞察：

  • 范围窄但效率高：支持有限的算子/数据类型/内存布局，匹配时性能/功耗收益显著
  • 混合设计是常态：不匹配时回退到优化 CPU/DSP 执行
  • 配套软件栈绑定：不作为通用加速器暴露，而是通过厂商专用工具链

3.2 代表性芯片 2025-2026

芯片 厂商 特点
STM32N6 ST 集成神经加速器，保持 MCU 编程模型
i.MX RT 系列 NXP 跨界 MCU，Cortex-M + DSP/ML 加速
RA/RZ 系列 Renesas MCU + 可选 AI 加速块
nRF54 系列 Nordic 高效 DSP + Neuton 超小模型集成

3.3 软件级加速持续进步

CMSIS-NN 和厂商内核利用 SIMD 指令 + 缓存感知内存访问模式，使"普通"Cortex-M 设备无需专用 AI 硬件也能高效运行许多工作负载。

四、前沿研究方向

4.1 TinyNav：ESP32 上的端到端自主导航（arXiv:2603.11071）

核心突破：在 ESP32 微控制器上实现实时自主导航。

指标 值
模型参数 23K
推理延迟 30ms
架构 2D CNN（避免 3D 卷积和循环层）
输入 20 帧深度数据滑窗
输出 转向 + 油门命令
验证 Grad-CAM 验证空间感知和避障行为

对 Jetson Orin 的启示：23K 参数模型在 ESP32 上 30ms，在 Jetson 上可轻松实现亚毫秒推理。但 Jetson 的价值在于处理更复杂的传感器融合（多摄像头 + LiDAR + 语音），而非简单的 2D 深度导航。

4.2 能效软硬件协同设计（arXiv:2603.23668）

从毫瓦级 TinyML 到 LLM 数据中心，能效已成为可持续 AI 的主要约束。关键发现：

  1. 性能和能效越来越多地受数据移动和内存系统行为限制，而非算术吞吐量
  2. 共同的设计杠杆：加速器架构（ASIC/FPGA 数据流、存算一体）、系统级技术（分区、量化、调度、运行时自适应）
  3. 持续存在的差距：跨平台泛化有限、协同设计搜索空间大且昂贵、基准测试不一致

4.3 神经网络量化综述（arXiv:2508.15008）

面向 MCU 的量化全面综述，关键要点：

  • 核心权衡：模型性能 vs MCU 硬件能力（内存层次、数值表示、加速器支持）
  • 硬件视角：ARM 和 RISC-V 设计、集成 NPU 的低精度推理 MCU
  • 部署挑战：量化感知训练 (QAT) vs 训练后量化 (PTQ) 的选择取决于目标硬件

4.4 TinyML → TinyDL 演进（arXiv:2506.18927）

范式转变：从简单推理任务到在严重资源受限硬件上部署深度学习模型。

维度 TinyML（传统） TinyDL（新范式）
任务 简单分类/检测 深度学习推理
模型 浅层 CNN 复杂架构 + NAS
学习 离线训练 端上学习
方向 神经形态计算、联邦 TinyDL、边缘原生基础模型

五、与 Jetson Orin 平台的关联

5.1 分层部署架构

云端/服务器: 大模型训练 + 复杂推理
  ↓
Jetson Orin: 中等模型推理（LLM 量化、多传感器融合、TTS）
  ↓
ESP32/MCU: 超轻量模型（关键词检测、异常检测、简单分类）
  ↓
传感器: 原始数据采集

5.2 实际可借鉴的技术

  1. LiteRT 集成：Jetson 可以运行 LiteRT 模型作为快速预处理管道，将复杂任务卸载到 GPU
  2. CMSIS-NN 思路：Jetson 的 CUDA 核心可以做类似的"软件级加速"——用 TensorRT 优化算子替代通用实现
  3. TinyNav 的 CNN 架构：23K 参数的 2D CNN 可直接迁移到 Jetson 作为低延迟安全监控层
  4. 存算一体 (CIM) 趋势：关注 RRAM/SRAM-based CIM 设计，下一代边缘 AI 芯片可能采用

六、未解决挑战

  1. 跨平台泛化：每个硅厂商的优化路径不同，模型移植成本高
  2. 端上学习：目前仍以推理为主，在 MCU 上实现增量学习是开放问题
  3. 基准测试标准化：不同工作负载和部署设置下的评估方法不一致
  4. Transformer 在 MCU 上的部署：attention 机制对内存的需求与 MCU 约束存在根本矛盾
  5. 安全与隐私：边缘 AI 的安全推理和模型保护尚未成为主流关注
