Meta Hyperagents：让 AI 自己改写自己"大脑"的框架

来源：公众号「AI侦探小猪」| 论文：Towards Human-Level Agentic Web Manipulation (Meta FAIR)
日期：2026-04-30 | 关联：2026-04-30-Harness-Engineering即控制论 垂域模型

摘要

Meta FAIR 提出 Hyperagents 框架，核心创新是让 AI Agent 在执行任务过程中动态修改自己的 prompt 和代码，实现"在执行中学习适应"。实验显示样本效率提升 8.6 倍，WebArena 成功率 94.7%（+26.6pp），分布外泛化能力显著优于基线方法。

核心问题

现有 AI Agent 面对训练数据中没见过的网站、表单、验证规则时，成功率断崖式下跌。根本原因：靠更多训练数据解决不了所有未见场景，这是一个范式层面的问题。

架构设计

Hyperagents 的核心架构包含四个关键组件：

1. Context Memory（上下文记忆） — 结构化的可执行知识存储。每次执行后生成"反思总结"：当前状态特征 + 针对性策略 + 执行结果。记忆是"可执行的"而非"可检索的"——每条记忆都能直接用于生成新策略。

2. Adaptation Code（适应代码） — 遇到未知场景时，AI 动态生成专门针对当前环境的 prompt 或脚本，而非使用通用指令。这是"生成函数的函数"（meta-programming 思路）。

3. Shared Knowledge Base（共享知识库） — 多个 Hyperagent 共享适应策略，遇到新网站时生成的策略同步更新到知识库，实现群体学习。

4. Constraint Validation（约束验证） — 沙盒环境中先验证新生成代码的输出是否符合约束（如"不能跳转页面"、"不能提交空表单"），验证通过才真正执行并写回记忆。

工作流程

情境检测 → 判断是否在已知范围内
  → 已知：直接检索历史策略执行
  → 未知：策略检索 → 代码生成 → 沙盒验证 → 执行 → 更新记忆

这个过程是递归的——生成的代码可以进一步生成新代码，形成自我改进的循环。

与强化学习的本质区别

维度 强化学习 Hyperagents
学什么 静态策略网络 生成策略的能力
泛化方式 依赖训练数据分布 依赖执行中适应
样本效率 20000+ 次交互达 70% 8.6 倍效率提升
本质 固定函数 可生成函数的函数

实验结果

  • WebArena：94.7%（+26.6pp vs 前最佳）
  • MiniWob++：99.1%
  • 分布外测试：性能下降幅度远小于基线，证明学到的是"适应能力"而非特定操作记忆

借鉴点（对我们体系的映射）

Hyperagents 我们的体系 升级方向
Context Memory M-Flow + Skill 体系 从"描述性记忆"升级为"可执行记忆"
Adaptation Code Evolver（当前仅修 bug） 增加"主动适应"：遇到新场景自动生成策略
Constraint Validation Sensor-Grid + auto-defense 加强为"新生成代码必须先过沙盒测试"
Shared Knowledge Base 笔记索引 + RAG 已有，保持

关键启发：我们的记忆系统目前记录的是"发生了什么"（描述性），Hyperagents 的 Context Memory 记录的是"下次怎么做"（可执行性）。这个升级方向值得探索——让每条经验记忆都附带一个可直接执行的策略脚本。

行业预判

  1. 如果"在执行中学习适应"被验证成立，AI Agent 能力上限将取决于适应速度而非训练数据量
  2. Meta 开源策略意味着 Hyperagents 可能成为 Llama 生态 Agent 化的基础设施
  3. 下一步关键问题：能否泛化到网页操作之外（机器人控制、科学发现、代码生成）
  4. 与我们 2026-04-30-Harness-Engineering即控制论 中 Harness Engine 的"感知-决策-执行"框架高度呼应——Hyperagents 本质上就是一个 Harness Engine 的实例化
