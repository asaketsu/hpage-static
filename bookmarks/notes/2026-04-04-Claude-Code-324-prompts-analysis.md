# Claude Code 324 条提示词：9 个炸裂发现
> **来源**：微信公众号「小高AI探索实践」
> **日期**：2026-04-04
> **标签**：Claude Code、Prompt Engineering、AI Agent 设计、Anthropic
> **评分**：⭐⭐⭐⭐⭐ (5/5) — 对我们的系统设计有直接指导价值

---

## 核心观点
Claude Code 的 324 条提示词不是工具说明书，而是「写给 AI 的职场行为准则」。核心精神：克制、诚实、谨慎、自驱。

## 9 个关键发现

### 发现一：克制 — 别多管闲事
- 不添加超出要求的新功能/重构/改进
- 不为不可能发生的场景加错误处理
- 三行相似代码 > 过早出现的抽象
- **「克制比热情重要一百倍」**

### 发现二：注释极简主义
- 默认不写注释，只在「为什么」不明显时才写
- 不要解释「做了什么」（命名应承担此职责）
- **绝不删除现有注释**（可能记录历史 bug 教训）

### 发现三：不粉饰，不自贬
- 目标是准确汇报，不是防御式汇报
- 失败就直说，不要制造表面绿色结果
- 通过了也不要加免责声明弱化

### 发现四：高风险操作分级管控
- 授权只覆盖明确范围，不能外推
- 破坏性操作先调查再删除（可能是用户进行中的工作）
- 暂停确认成本很低，误操作代价极高

### 发现五：标点符号级 UX 执念
- 工具调用前用句号不用冒号（工具调用可能不显示给用户）
- 假设用户冷启动也能接上（对方刚离开又回来了）

### 发现六：闲着就睡，醒了就干
- 没事做就 sleep，不要浪费 token 回复状态
- 用户不在时偏向自主行动，用户在时偏向协作
- 犹豫时选一个先做，随时修正

### 发现七：独立验证协议
- 实现完成后必须独立对抗性验证
- 自己的检查不能替代独立验证
- PASS 后还要抽查 2-3 条命令确认

### 发现八：三层持久化
| 层 | 用途 | 生命周期 |
|---|---|---|
| 记忆 Memory | 跨对话有价值的信息 | 持久 |
| 计划 Plan | 就实现方法与用户达成一致 | 当前任务 |
| 任务 Task | 当前对话的离散步骤 + 进度追踪 | 当次会话 |

### 发现九：Fork/Team 协作
- 向子 Agent 说明任务时要像对刚进门的聪明同事做简报
- **绝不要委托理解本身** — 你必须证明自己已理解
- 综合判断的责任在你身上，不能甩给子智能体

## 💡 对我们的对照分析

### ✅ 我们已经在做的
1. **克制原则** — SOUL.md "先做后报，能自主验证的就不等审核" ✅
2. **准确汇报** — Verification Gate（Hook 2）✅ 但还需强化"不自贬"
3. **授权范围** — /approve 只覆盖单次命令 ✅
4. **三层记忆** — L1永久/L2今日/L3会话 ✅ 完全对标 Claude Code 的 Memory/Plan/Task
5. **冷启动友好** — 九段自检 ✅

### ⚠️ 可以改进的
1. **注释极简主义** — 我们生成代码时需要遵守：不写废话注释，不删现有注释
2. **独立验证协议** — 我们的 Verification Gate 是自检，缺少"独立对抗性验证"概念。可以借鉴：spawn 一个 subagent 做验证者
3. **用户在/不在的模态切换** — Claude Code 有 Focused/Unfocused 概念。我们可以用 heartbeat 检测用户活跃度来切换模式
4. **委托理解原则** — 分派任务给 Dev/Content 时，必须自己先理解问题，不能把"根据你的发现修复"甩出去

### 🔥 重点行动
1. 在 SOUL.md 补充「代码注释纪律」规则
2. 升级 Verification Gate：对复杂任务 spawn 独立验证 subagent
3. 团队分派纪律强化：分派时必须包含自己已理解的问题描述
